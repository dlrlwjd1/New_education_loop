# Case Study

## 개요

- **코스 전반부를 마무리하는 종합 case study**
- 과제: **하이파이(hi-fi) 장비 도매업체**의 핵심 비즈니스 프로세스 모델링
- 범위: **물품 입고부터 고객 주문 이행까지 전체 흐름**

## 내용

### 과제

지금까지 배운 **BPMN 요소 전체**를 사용해 도매업체의 core business process를 모델링한다. 완성 후 **token simulator(`processcamp.io/profile/links`)로 기술적 유효성과 토큰 흐름을 검증**한다.

> 강사의 안내: **이 단계에서는 접근 방식에 자유도가 크기 때문에 여러분의 프로세스는 강사의 것과 다르게 생겼을 가능성이 높고, 그것은 전혀 문제없다. 다만 token simulator로 기술적으로 정확한지만 확인하라.**

### 강사의 해설

**1. 시작** — 고객이 **회계부서(accounting department)에 주문을 보내면서** 흐름이 촉발된다

**2. 주문 검증** — 회계부서가 주문을 검증한다

**3. Parallel gateway** — 주문이 정확하면 토큰을 복제해 **두 작업을 동시에** 진행한다

| 회계 | 창고 |
|---|---|
| **송장 생성** | **주문 품목의 재고 확인** |

**4. 재고가 없는 경우**

- **창고가 공급업체에 부족 품목을 주문**한다
- 그동안 **회계팀은 송장을 완성하고 토큰은 parallel gateway에서 대기**한다
- 창고는 **고객에게 지연을 알린다**
- **부족 품목이 도착할 때까지 토큰이 대기**한다
- **품목이 도착하면 message event가 활성화**되어 다음 task를 알린다

**5. 배송 통보 — 두 가지 방식 모두 유효하다**

> **여기서 throwing message event는 선택 사항이다.** 소포가 발송되었음을 강조하는 역할을 한다.
>
> 창고는 **직접 message flow로 알리거나, 또 다른 throwing message event로** 고객에게 배송을 통보한다. **두 접근 모두 유효한 BPMN 스타일이다.**

**6. 병합과 종료**

- **창고와 회계팀이 모두 끝나면 parallel gateway가 토큰을 병합**한다
- **송장이 고객에게 발송**된다
- **회계팀이 고객의 결제를 기다린다**
- **결제가 접수되면 절차가 종료되고 케이스가 닫힌다**

## 예시

```text
하이파이 도매업체 핵심 프로세스

(✉ 고객 주문 수신)
        ↓
   [주문 검증]  ← 회계
        ↓
   ◇ 주문이 정확한가? ── yes
        ↓
        ⊕  ← parallel: 회계와 창고 동시 진행
   ┌────┴────────────────┐
   │                     │
[송장 생성]          [재고 확인]  ← 창고
   │                     ↓
   │              ◇ 재고가 있는가?
   │               ├─ yes ────────────┐
   │               │                  │
   │               └─ no              │
   │                  ↓               │
   │           [공급업체에 주문]        │
   │                  ↓               │
   │           [고객에게 지연 통보]     │
   │                  ↓               │
   │           (✉ 품목 도착 대기)      │
   │                  ↓               │
   │                  └───────────────┤
   │                                  ↓
   │                             [포장·발송]
   │                                  ↓
   │                        (✉ 배송 통보) ← 선택 사항
   │                                  │
   └────────────┬─────────────────────┘
                ⊕  ← 두 토큰 병합
                ↓
        [고객에게 송장 발송]
                ↓
        (✉ 결제 대기)
                ↓
           (◎ 케이스 종료)
```

## 요약

- **같은 요구사항이라도 정답 모델은 하나가 아니다.** 기술적으로 정확하면 된다
- **parallel gateway로 회계와 창고를 동시 진행**시키고, 느린 쪽(재고 부족 시 공급업체 대기)을 **closing gateway가 기다린다**
- **throwing message event는 선택 사항**이다. message flow로 직접 그려도 유효하다
- 이 case study로 **BPMN 기초(fundamentals)를 완주**했다
