# Process Scoping

## 개요

- 프로세스의 **범위를 어디까지 잡을 것인가**에 대한 규칙
- 핵심 규칙: **15 task rule** — 한 프로세스에 task 15개를 넘기지 않는다
- 더 근본적인 질문: **이 프로세스 모델의 목적이 무엇인가**

## 내용

### 프로세스를 가치 있게 만들려면 — 다른 사람이 이해해야 한다

> **나만 따라갈 수 있는 프로세스를 만들면 조직의 누구도 관심을 갖지 않는다.**

그래서 프로세스는 두 가지를 동시에 만족해야 한다.

| 목표 | 의미 |
|---|---|
| **Accessible(접근 가능)** | 사용자가 **파악할 수 있을 만큼 명확하게** 설계되었다 |
| **Expressive(표현력 있음)** | 내용이 **의미 있고 비즈니스 과제 해결에 도움**이 된다 |

### 시작 질문

> 모델링을 시작하기 전에 스스로에게 물어야 할 한 가지 — **내 프로세스는 얼마나 복잡해야 하는가?**

앞서 본 우주선 프로세스는 상당히 크지만 **task가 10개뿐이라 여전히 관리 가능**했다.

### 비법 공식 — 15 task rule

> **한 프로세스에 task 15개를 넘게 쓰지 마라.**

강사의 경험상 **task가 15개를 넘는 프로세스는 압도적이어서 이해하기 어렵고 영향력이 떨어진다.**

**왜 중요한가**: 앞서 만난 매장 직원 Max를 생각하면 된다. Max는 **필요한 정보를 즉시 이해해야 하고, 미로처럼 보이는 프로세스를 분석할 시간도 인내심도 없다.**

Max 같은 **비즈니스 사용자**에게 15 task rule은 프로세스를 **접근 가능하고 영향력 있게** 만든다.

### 예외 — 기술 사용자 대상인 경우

> 프로세스가 **더 기술적인 사용자**를 위한 것이라면? 예를 들어 프로세스로 **SAP 시스템의 요구사항을 정의**하는 경우.
>
> **15개를 넘어도 전혀 문제없다. 단, 모든 이해관계자가 BPMN에 숙련되어 있고 자신 있을 때만이다.**

### 가장 중요한 질문 — 목적이 무엇인가

두 가지 매우 다른 시나리오를 봤다.

1. Max 같은 **비즈니스 사용자가 가치 있는 업무 정보를 얻도록** 돕는 경우
2. **매우 복잡한 IT 시스템의 요구사항을 정의**하는 경우

> **이 프로세스 모델의 목적은 무엇인가?**
>
> - 가치 있는 **비즈니스 정보를 표현**하는가?
> - **IT 시스템의 동작을 정의**하는가?
> - **감사(audit)를 위한** 프로세스를 만드는가?
>
> 이 질문에 답하면 프로세스의 범위를 효과적으로 설정하고 의도한 목적에 부합하게 만들 수 있다.

### 비즈니스 사용자인데 15개가 넘어야 한다면?

> **task를 그냥 지워서 규칙에 맞출 수는 없다.**

다음 강의들에서 **아무리 복잡한 프로세스라도 효과적으로 구조화하고 단순화하는 두 가지 방법**을 배운다. (→ sub-process와 call activity, Module 8)

## 예시

```text
Scoping 판단 흐름

  이 모델을 누가 읽는가?
        │
   ┌────┴─────────────────┐
   │                      │
비즈니스 사용자        기술 사용자
(Max 같은)             (SAP 요구사항 정의 등)
   │                      │
15 task 이하로 유지     15개 초과 허용
   │                      (단, 모든 이해관계자가
   │                       BPMN에 숙련된 경우만)
   │
15개가 넘는다면?
   → task를 삭제하지 말고
     sub-process / call activity로 구조화한다
```

## 요약

- **나만 이해하는 프로세스는 가치가 없다.** accessible + expressive를 동시에 만족해야 한다
- **15 task rule** — 한 프로세스에 task 15개를 넘기지 않는다
- **기술 사용자 대상이면 초과해도 되지만**, 모든 이해관계자가 BPMN에 숙련된 경우에 한한다
- **범위 설정의 핵심 질문은 "이 모델의 목적이 무엇인가"** 다 — 비즈니스 정보 전달 / IT 요구사항 정의 / 감사
- 15개가 넘으면 **삭제가 아니라 구조화**로 해결한다
