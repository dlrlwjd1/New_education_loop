# Process Collaboration

## 개요

- 서로 다른 프로세스 참여자 간의 **협업을 올바르게 표현하는 법**
- 강사가 **많은 학생들이 어려워하는 주제**라고 짚는 부분
- 한 문장 규칙: **같은 pool 안이면 sequence flow, pool 사이면 message event**

## 내용

### 흔한 실수 — 조직 내부 인계에 message event를 쓰는 것

우주선 프로세스의 단순화 버전을 보자. **기획팀이 생산 계획을 작성한 뒤 품질보증(QA)에 인계**한다. 이메일로 보낸다고 가정하자.

**이것을 message event로 그리는 것이 맞는가?**

> **아니다. 틀렸다.**
>
> **한 조직 내부의 인계(handover)에는 message event를 사용하면 안 된다. 이것이 흔한 실수다.**
>
> **message event는 외부 당사자와의 커뮤니케이션 전용으로 예약되어 있다.**

**올바른 방법**: **lane을 가로지르는 sequence flow**로 인계를 표현한다. 내부 커뮤니케이션에는 이것으로 **충분하고 정확하다**.

> 이것은 Module 2에서 배운 "lane 경계를 가로지르는 sequence flow가 곧 인계"라는 원칙과 같다.

### 외부 참여자와의 협업 — 이때는 message event가 맞다

Bookworm 서점 프로세스를 다시 보자. 서점은 **조직의 일부가 아닌 고객**과 소통한다.

> **이 경우에는 message event와 message flow를 사용하는 것이 100% 옳다.**

### 기억할 규칙

> **한 pool 안에서의 협업 → sequence flow를 사용한다**
>
> **pool과 pool 사이의 협업 → message event를 사용한다**

## 예시

```text
✗ 잘못된 사용 — 같은 조직 내부에 message event

┌─ Pool: Space Z ────────────────────────────┐
│  ├─ Lane: 기획팀                            │
│  │   [생산 계획 수립] → (✉ 계획 발송)  ← ✗   │
│  │                          ┊              │
│  ├─ Lane: QA                ┊              │
│  │              (✉ 계획 수신) ← ✗           │
│  │                    ↓                    │
│  │              [계획 평가]                 │
└────────────────────────────────────────────┘


✓ 올바른 사용 — lane을 가로지르는 sequence flow

┌─ Pool: Space Z ────────────────────────────┐
│  ├─ Lane: 기획팀                            │
│  │   [생산 계획 수립] ─┐                     │
│  │                     │  ← 화살표 하나면 충분 │
│  ├─ Lane: QA ──────────┼───────────────────┤
│  │                     ↓                    │
│  │              [계획 평가]                  │
└────────────────────────────────────────────┘


✓ 올바른 사용 — pool 사이에는 message event

┌─ Pool: Bookworm 서점 ──────────────────────┐
│  (✉ 주문 수신) → [주문 처리] → (✉ 배송 통보) │
└──────┊──────────────────────────┊──────────┘
       ┊  message flow            ┊
┌──────┸──────────────────────────┸──────────┐
│  Pool: 고객 (외부, collapsed)                │
└────────────────────────────────────────────┘
```

## 요약

- **한 pool 안(같은 조직) → sequence flow**
- **pool 사이(외부 당사자) → message event + message flow**
- **조직 내부 인계에 message event를 쓰는 것이 가장 흔한 실수**다. 이메일로 보내더라도 마찬가지다
- 판단 기준은 **"매체가 무엇인가"가 아니라 "같은 pool인가 다른 pool인가"** 다
