# Summary

## 개요

- 두 함정의 **결정적 차이**와 모델에 미치는 영향을 정리한다

## 내용

### Multi-merge vs Deadlock — 심각도가 다르다

| | **Multi-merge** | **Deadlock** |
|---|---|---|
| 기술적 정확성 | **기술적으로는 맞다(technically correct)** | **기술적으로 틀렸다(technically incorrect)** |
| 프로세스 완료 | 완료는 된다 | **토큰이 갇혀 프로세스를 완료할 수 없다(incompletable)** |
| 문제 | 모델의 **표현력(expressiveness)을 훼손**해 다른 사람이 이해하기 어렵게 만든다 | 프로세스 자체가 **작동하지 않는다** |
| 성격 | **의사소통의 문제** | **논리의 문제** |

### 핵심 지침

> **여는 gateway와 닫는 gateway의 짝짓기(pairing)에 항상 세심하게 주의를 기울여** 두 함정 어느 쪽에도 빠지지 않도록 한다.

## 예시

```text
점검 체크리스트

□ 여는 gateway를 찾는다
□ 그에 대응하는 닫는 gateway를 찾는다
□ 두 gateway의 타입이 같은가?

   같다  → ✓ 정상
   ◇ → ⊕ → ✗ Deadlock    (프로세스가 멈춘다. 반드시 고친다)
   ⊕ → ◇ → ✗ Multi-merge (돌아가긴 하지만 오해를 부른다. 고친다)

□ 확신이 없으면 token simulator로 토큰 흐름을 확인한다
```

## 요약

- **Deadlock이 더 심각하다.** 기술적으로 틀렸고 프로세스를 완료할 수 없게 만든다
- **Multi-merge는 기술적으로는 맞지만** 모델의 표현력을 해쳐 다른 사람이 오해하게 만든다
- 두 함정 모두 **여는/닫는 gateway 짝짓기**만 확인하면 예방할 수 있다
- BPMN 모델을 검토할 때 **gateway 짝의 타입 일치 여부**를 가장 먼저 본다
