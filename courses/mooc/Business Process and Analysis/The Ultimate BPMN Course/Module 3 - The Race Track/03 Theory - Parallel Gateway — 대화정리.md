# Theory - Parallel Gateway — 대화정리

## 개요

- 학습일: 2026-09-08
- 원본: [03 Theory - Parallel Gateway](03%20Theory%20-%20Parallel%20Gateway.md)
- 병렬 게이트웨이(parallel gateway)의 토큰 복제와 동기화(synchronization)를 문답으로 확인했다.

## 내용

### 분기에서는 모든 경로로 보낸다

사용자는 경로가 세 개일 때 토큰이 “3개로 동시에 나가지”라고 설명했다. 병렬 게이트웨이는 조건으로 하나를 선택하지 않고 토큰을 복제해 모든 나가는 경로에 하나씩 보낸다.

### 합류에서는 모두 기다린다

두 작업이 끝나고 하나가 진행 중인 상황에 대해 “대기하고 그리고 나서 하나로 합쳐지지”라고 답했다. 닫는 병렬 게이트웨이는 필요한 토큰이 모두 도착하면 하나로 합쳐 다음 단계로 진행한다. 한 경로에서 토큰이 아예 오지 않으면 계속 기다려 다음으로 진행하지 못한다.

### 배타적 게이트웨이와 비교

사용자는 배타적 게이트웨이에서는 구슬 하나가 선택적으로 가고, 병렬 게이트웨이를 지날 때는 복사된다고 정리했다. 배타적 게이트웨이는 선택된 한 경로만, 병렬 게이트웨이는 모든 나가는 경로를 활성화한다.

### 교정한 표현 — 동시에 만난다는 뜻

사용자의 정리에는 “닫힌 게이트웨이에서 동시에 만나”라는 표현이 있었다. 이를 반드시 같은 시각에 도착해야 한다는 뜻으로 이해하지 않도록 구분했다.

- 먼저 도착한 토큰은 나머지를 기다린다.
- 늦게 도착해도 결국 모두 모이면 진행할 수 있다.
- 사용자는 이 상황에서 “진행 가능하지”라고 확인했다.

동기화는 ‘동시에 도착하기’가 아니라 ‘모두 도착할 때까지 기다리기’다.

## 예시

강의의 세 경로 예시를 바탕으로 확인한 상황:

```text
토큰 1개 → 여는 병렬 게이트웨이 → A, B, C에 토큰 하나씩
A, B 완료 / C 진행 중 → 닫는 병렬 게이트웨이에서 대기
C도 완료하고 토큰 도착 → 토큰 하나로 합쳐 다음 단계 진행
```

## 요약

- 병렬 게이트웨이는 + 기호로 표시하며 모든 나가는 경로를 활성화한다.
- 분기에서는 토큰을 경로 수만큼 복제한다.
- 합류에서는 필요한 토큰이 모두 도착할 때까지 기다린다.
- 도착 시각은 달라도 된다.
