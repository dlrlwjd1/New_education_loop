# Practical – Process of Manual Tasks in the Retail Industry (Part 2)

## 개요

- 조직이 **성장하거나 변화할 때** BPMN이 어떻게 대응하는지 보여주는 강의
- 핵심 주제: **Lane을 추가해 새로운 역할의 책임을 표현하는 법**
- 자주 하는 오해 하나를 바로잡는다

## 내용

### 프로세스 관리의 가장 큰 장점 — 역할별 절차를 명확히 전달한다

이 명확성은 조직이 **성장**하거나 **기술적으로 발전**해 변화를 겪을 때 특히 가치가 커진다.

### 시나리오 1 — 인원이 늘어난다

신발 매장이 빠르게 성장해 Max 외에 **매장 직원 3명을 추가 채용**했다고 하자. 아무도 "사이즈 없음" 같은 상황을 다뤄본 경험이 없다.

- **구조화된 프로세스가 없다면** → 관리자가 같은 내용을 수백 번 반복 설명해야 한다
- **BPMN 다이어그램이 있다면** → 직원을 **knowledge base**로 안내하기만 하면 된다. 다이어그램이 업무 수행 방법을 그대로 보여준다

### 시나리오 2 — 역할이 새로 생긴다

성장은 **프로세스 최적화**로도 이어진다. 예를 들어 매장이 재고 관리를 개선하기 위해 **warehouse manager(창고 관리자)** 를 새로 채용한다. 그러면 새 역할을 반영하도록 기존 프로세스를 갱신해야 한다.

**BPMN에서의 처리 방법:**

1. 다이어그램에 **lane을 하나 더 추가**한다
2. **"창고에서 신발 꺼내기" task의 책임을 shop assistant에서 warehouse manager로 옮긴다**

pool과 lane이 프로세스 내 **책임(responsibilities)** 을 나타낸다는 원칙이 그대로 적용된다.

### 흔한 오해 — 역할 간 인계 task가 필요하다?

> **오해**: 역할 사이의 인계(handover)를 명시하려면 별도의 task를 추가해야 한다. 예를 들어 "Max에게 알린다" 또는 "창고 관리자에게 언제 움직일지 알린다" 같은 task.

> **사실**: BPMN에서는 **필요 없다.** **lane 경계를 가로지르는 sequence flow 하나만으로** 한 역할이 다른 역할에게 프로세스를 넘긴다는 의미가 충분히 전달된다.

이 방식이 모델을 **깔끔하고 직관적으로(clean and intuitive)** 유지한다.

## 예시

```text
[Pool: 신발 매장]
 ┌─ Lane: Shop Assistant ────────────────────────────────┐
 │  (○ 사이즈 없음) → [매장 창고 확인] → ◇ 있는가?         │
 │                                        │ yes           │
 │                                        │               │
 │                              ┌─────────┘               │
 │                              │  ← lane 경계를 가로지르는 │
 │                              │     sequence flow 하나가 │
 ├─ Lane: Warehouse Manager ────┼─── 인계를 의미한다 ──────┤
 │                              ↓                         │
 │                    [창고에서 신발 꺼내기]                │
 │                              │                         │
 ├─ Lane: Shop Assistant ───────┼─────────────────────────┤
 │                              ↓                         │
 │                       [고객에게 판매] → (◎ End)         │
 └────────────────────────────────────────────────────────┘
```

**별도의 "인계 알림" task는 그리지 않는다.** 화살표가 lane을 넘어가는 것 자체가 인계다.

## 요약

- BPMN 다이어그램은 **반복 교육을 대체하는 knowledge base** 역할을 한다
- 새로운 역할이 생기면 **lane을 추가하고 해당 task를 그 lane으로 옮긴다**
- **lane 경계를 가로지르는 sequence flow가 곧 역할 간 인계**다. 별도의 인계 task를 그리지 않는다
- 이 원칙이 모델을 불필요한 요소 없이 깔끔하게 유지한다
