## 내용

### 사람이 늘어날 때 — 그림이 반복 교육을 대신한다

매장 직원 3명을 새로 뽑았는데 아무도 "사이즈 없음" 상황을 겪어본 적이 없다면?

- **그림이 없으면** 새로 온 사람이 전부 Max에게 물어봐야 한다. 관리자가 같은 설명을 수백 번 반복한다.
- **그림이 있으면** 누가 되었든 그 절차대로 하면 된다. 강의 표현으로는 다이어그램이 **knowledge base** 역할을 하고, 신입을 거기로 안내하기만 하면 된다.

### 새 역할이 생길 때 — lane을 추가하고 task를 옮긴다

성장은 인원 증가만이 아니라 **프로세스 최적화**로도 이어진다. 재고 관리를 개선하려고 **warehouse manager(창고 관리자)** 를 새로 뽑았다고 하자.

고칠 것은 두 가지뿐이다.

1. **lane을 하나 더 추가한다.** 같은 회사 안에서 생긴 역할이므로 pool을 새로 만들지 않는다. pool은 그대로 두고 그 안에 lane을 늘린다.
2. **"창고에서 신발 꺼내기" task를 shop assistant lane에서 warehouse manager lane으로 옮긴다.**

바탕에 깔린 원칙은 02강과 같다 — **pool과 lane은 프로세스 안의 책임(responsibility)을 나타낸다.** 책임이 새로 생겼으니 그 책임을 그림 위에 그리는 것이다.

### 인계는 화살표가 lane을 넘는 것으로 끝난다

이 강의가 바로잡는 흔한 오해다.

- **오해**: 역할이 넘어가는 지점에 "창고 관리자에게 알린다" 같은 인계용 task를 하나 그려야 한다.
- **사실**: BPMN에서는 필요 없다. **lane 경계를 가로지르는 sequence flow 하나**가 곧 인계다.

lane이 5개인 프로세스에서 A→B→C→D→E로 넘어간다면 인계 task만 네 개가 더 붙는다. 그런데 화살표는 이미 A의 lane에서 B의 lane으로 건너가 있다. 그 사실만으로 인계가 표현되므로 상자를 더 그리는 것은 중복이다. 강의는 이것이 모델을 **깔끔하고 직관적으로(clean and intuitive)** 유지하는 방법이라고 말한다.

## 예시

```text
[Pool: 신발 매장]
 ┌─ Lane: Shop Assistant ────────────────────────────────┐
 │  (○ 사이즈 없음) → [매장 창고 확인] → ◇ 있는가?         │
 │                                        │ yes           │
 │                              ┌─────────┘               │
 │                              │  ← 이 화살표가 lane 경계를│
 │                              │     넘는 순간이 곧 인계   │
 ├─ Lane: Warehouse Manager ────┼─────────────────────────┤
 │                              ↓                         │
 │                    [창고에서 신발 꺼내기]                │
 │                              │                         │
 ├─ Lane: Shop Assistant ───────┼─────────────────────────┤
 │                              ↓                         │
 │                       [고객에게 판매] → (◎ End)         │
 └────────────────────────────────────────────────────────┘
```

"창고 관리자에게 알린다" 같은 상자는 어디에도 없다.

## 오해했다가 바로잡은 지점

**"요청한다"를 task로 그려야 한다고 생각했다.**

- 처음 생각: shop assistant가 창고 관리자에게 요청을 하는 것이니, 그림에도 "요청한다 / 알린다" task를 하나 넣어야 한다.
- 실제: 넣지 않는다. lane 경계를 넘어가는 sequence flow가 이미 그 요청·인계를 의미한다. 인계마다 task를 그리면 lane이 늘어날수록 중복 상자만 쌓인다.
- 계기가 된 반례: lane 5개 프로세스에서 A→B→C→D→E로 넘어갈 때 인계 task 4개를 더 그리게 되는데, 화살표는 이미 lane을 넘어가 있다.

## 요약

- BPMN 다이어그램은 **반복 교육을 대체하는 knowledge base**다. 사람이 늘어도 그림만 보면 절차를 따를 수 있다.
- 새 역할이 생기면 **같은 pool 안에 lane을 추가하고, 해당 task를 그 lane으로 옮긴다.** pool을 새로 만들지 않는다.
- **lane 경계를 가로지르는 sequence flow가 곧 역할 간 인계**다. 별도의 인계 task를 그리지 않는다.
