# Loop Types

## 개요

- **Loop task(루프 작업)** — **정의된 조건이 충족될 때까지 여러 번 실행되는 activity**
- 목적: **gateway로 만든 투박한 루프 구조를 하나의 기호로 대체**한다

## 내용

### 문제 — gateway로 만든 루프는 투박하다

Space Z의 샘플 생산 프로세스를 보자. **exclusive gateway 두 개로 "샘플 생산이 끝났는가"를 판단하는 구조**를 만들면

- **토큰이 exclusive gateway의 조건이 충족될 때까지 계속 돌게 된다**
- 즉 **task를 반복(looping)하는 것이다**
- 본질적으로 **루프를 구성한 것**이지만, **다이어그램이 지저분하다**

### 해결 — Loop task

**gateway 두 개를 없애고 task에 작은 loop 기호를 추가**한다.

> **이렇게 하면 프로세스 다이어그램이 훨씬 깔끔해지고, 투박한 gateway 구조보다 더 명시적이다.**

**조건은 어떻게 하는가?**

> **필요하면 task에 note로 루프의 조건을 적을 수 있다. 그러면 gateway를 없애도 아무 정보도 잃지 않는다.**

**토큰 흐름**

> **토큰 흐름은 이전과 정확히 같다.** 다만 **모든 샘플이 생산될 때까지 토큰이 loop task 안에 머문다**는 점이 다르다. 다시 말해 **task의 모든 입력을 반복 처리한 뒤 토큰이 다시 풀려난다.**

## 예시

```text
✗ Gateway로 만든 루프 (투박함)

(●) → ◇ ←─────────────┐
      ↓               │
  [샘플 생산]          │
      ↓               │
      ◇ 다 만들었나? ──┘ no
      ↓ yes
     (◎)


✓ Loop task (깔끔함)

(●) → [샘플 생산 ↻] → (◎)
           │
           └─ note: "필요한 샘플 수만큼"

토큰은 모든 샘플이 생산될 때까지
loop task 안에 머문다


기호

[Task ↻]   loop 기호 = 조건이 충족될 때까지 반복
```

## 요약

- **Loop task는 조건이 충족될 때까지 activity를 반복 실행**한다
- **gateway 두 개로 만든 루프 구조를 기호 하나로 대체**해 다이어그램을 깔끔하게 만든다
- **조건은 task에 note로 적으면** 정보 손실이 없다
- **토큰은 반복이 끝날 때까지 task 안에 머문다**
