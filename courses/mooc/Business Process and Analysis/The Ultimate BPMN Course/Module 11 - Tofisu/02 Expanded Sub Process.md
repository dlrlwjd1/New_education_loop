# Expanded Sub Process

## 개요

- **Expanded sub-process(펼친 하위 프로세스)** — 하위 프로세스의 **모든 요소를 감추지 않고 직접 표시**한다
- 용도: **여러 task에 event나 loop를 한꺼번에 적용**하고 싶을 때
- **프로세스 흐름 자체는 일반 sub-process와 동일하다.** 순전히 **표현 방식의 문제**다

## 내용

### 일반 sub-process 복습

Bookworm 온라인 서점의 주문 프로세스는 **끝에 일반 sub-process가 있어 물품 배송 방법을 명시**한다. 그 task/sub-process에 도달하면 **아래 프로세스의 실행이 촉발**된다.

### Expanded sub-process의 동작

일반 sub-process처럼 **부모 프로세스에 링크만 하는 대신, 부모 프로세스에 직접 통합**한다.

> **프로세스 흐름 자체는 이것에 영향받지 않는다. 순전히 프로세스 흐름을 어떻게 표현하느냐의 문제다.**

**토큰 관점**

1. **토큰이 expanded sub-process의 경계에 도달하면 그것을 촉발**한다
2. **sub-process 내부의 토큰이 생성**되어 그 안을 흐른다
3. **내부 토큰이 소비되면**, 즉 **sub-process가 완료되면**
4. **부모 토큰이 잠금 해제되어 앞으로 전달**된다

> **본질적으로 expanded sub-process는 collapsed(일반) sub-process와 똑같이 작동한다.**

- 항상 **plain start event로 시작**한다 (똑똑한 모델러를 쓰면 자동 처리된다)

### 둘 중 무엇을 쓸 것인가 — 비교

| | **Collapsed (일반)** | **Expanded (펼친)** |
|---|---|---|
| 장점 | **정보를 두 프로세스로 효과적으로 분할**해 **부모 프로세스를 깔끔하게** 유지한다 | **모든 프로세스 정보를 한곳에 유지**해 **부모와 하위 프로세스 간 의존관계를 더 잘 시각화**할 수 있다 |
| 단점 | 의존관계가 한눈에 안 보인다 | **두 프로세스를 하나에 담아 다이어그램을 과도하게 복잡하게** 만들 수 있다 |

### 가장 중요한 차이 — event와 loop를 통째로 적용할 수 있다

> **expanded sub-process에서는 하위 프로세스 전체나 그 안의 여러 task에 attached event나 process loop를 적용할 수 있다.**

**예시**: sub-process에 **고객이 주문을 취소할 때 촉발되는 event를 부착**한다.

- 그러면 **하위 프로세스 전체가 취소**된다
- 다시 말해 **주문이 취소되면 물품 배송과 관련된 모든 activity가 취소된다**

> **이 경우 expanded sub-process는 activity들을 그룹으로 묶어, attached event 하나로 함께 제어할 수 있게 해 준다.**

### Best practice 규칙

> **일반적으로는 collapsed sub-process를 쓰는 것이 타당하다.**
>
> **하지만 의존관계를 표현하거나, 방금 본 것처럼 event나 loop type으로 이 activity들을 함께 제어하기 위해 모든 정보가 한 다이어그램에 필요하다면 expanded를 쓴다.**

## 예시

```text
Collapsed sub-process (일반)

Level 1: (○) → [주문 처리] → [물품 배송 ⊞] → (◎)
                                   │
Level 2:              (○) → [재고확인] → [포장] → [발송] → (◎)
         ← 별도 다이어그램. 부모가 깔끔하다


Expanded sub-process (펼친)

┌──────────────────────────────────────────────────────┐
│ (○) → [주문 처리] →                                   │
│   ┌─ 물품 배송 (expanded) ─────────────────────┐      │
│   │  (○) → [재고확인] → [포장] → [발송] → (◎)   │      │
│   └──────────────────(✉)──────────────────────┘      │
│                       ↑                       → (◎)  │
│              부착 event: "고객이 주문 취소"            │
│              → 하위 프로세스 전체가 취소된다            │
└──────────────────────────────────────────────────────┘
   ← 한 다이어그램. event 하나로 그룹 전체를 제어


선택 기준

  하위 프로세스 전체에 event나 loop를 걸어야 하는가?
  또는 부모-자식 의존관계를 보여줘야 하는가?
        │
   ┌────┴────┐
  예         아니오
   │           │
Expanded    Collapsed (기본값)
```

## 요약

- **Expanded sub-process는 하위 프로세스를 부모 안에 펼쳐서 보여준다.** 흐름은 collapsed와 동일하고 **표현만 다르다**
- **토큰은 경계에서 내부 토큰을 만들고, 내부가 끝나면 부모 토큰이 풀린다** (collapsed와 같음)
- **기본값은 collapsed**다. 부모를 깔끔하게 유지하기 때문이다
- **expanded를 쓰는 이유는 두 가지** — **의존관계 시각화**, 그리고 무엇보다 **하위 프로세스 전체에 attached event나 loop를 적용**하기 위해
- 이것이 **여러 activity를 하나의 event로 함께 취소**할 수 있게 해 준다
