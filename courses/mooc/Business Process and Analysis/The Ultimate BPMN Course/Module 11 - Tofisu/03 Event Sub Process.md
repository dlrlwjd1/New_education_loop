# Event Sub Process

## 개요

- **Event sub-process(이벤트 하위 프로세스)** — **예외(exception)를 처리**하는 하위 프로세스
- **부모 프로세스나 다른 하위 프로세스 안에 내장(embedded)** 될 수 있다
- **두 종류**가 있고, **start event의 선 모양(점선/실선)으로 구분**한다

## 내용

### 두 종류 — 점선과 실선

| 종류 | Start event 모양 | 동작 |
|---|---|---|
| **Non-canceling(비취소형)** | **점선(dashed)** | 촉발되어도 **바깥 하위 프로세스가 계속 진행**된다 |
| **Canceling(취소형)** | **실선(solid)** | 촉발되면 **바깥 하위 프로세스를 취소**한다 |

### 시나리오 1 — 비취소형 (고객이 주문 상태를 문의)

배송 하위 프로세스가 실행되는 도중 **임의의 시점에**(예: 품목 가용성을 확인하는 중) **고객이 주문 상태를 물어볼 수 있다.**

1. 이것이 **첫 번째 event sub-process를 촉발**한다
2. **두 토큰** — 부모 하위 프로세스의 토큰과 촉발된 event sub-process의 토큰 — 이 **서로 독립적으로 각자의 프로세스를 흘러간다**

> **왜 비취소형인가? 고객이 주문 상태를 물어본다는 이유만으로 주문 배송을 취소할 이유가 없기 때문이다.**

### 시나리오 2 — 취소형 (고객이 주문을 취소)

이번에는 **고객이 실제로 주문을 취소하려고 전화**한다.

1. **취소 프로세스를 촉발하면 바깥 하위 프로세스의 토큰이 죽는다(killed)** — 즉 취소된다
2. **고객이 더 이상 원하지 않으므로 물품 배송을 중단**한다
3. 이 동작은 **event sub-process의 start event가 점선이 아니라 실선인 것으로 알 수 있다**

### 전체 프로세스에 미치는 영향

고객이 주문을 취소하면:

1. **하위 프로세스의 토큰이 죽고, 이는 하위 프로세스의 완료로 이어진다**
2. **하위 프로세스 완료를 기다리던 부모 프로세스의 토큰이 풀려나 전달**된다
3. **하지만 경리부(bookkeeping)도 영향을 받는다.** 고객이 주문을 취소했으므로 **더 이상 송장을 보낼 필요가 없다**
4. 이를 위해 **하위 프로세스에 직접 부착된 canceling event**가 있고, **주문 취소 시 촉발**된다

> **이 attached event는 event sub-process의 canceling event와 정확히 같게 동작한다.** 하위 프로세스의 토큰이 죽고, 대기 중이던 부모 프로세스의 토큰이 풀려나 전달된다.

5. 그리고 **케이스가 종료**된다

### 반드시 기억할 것

> **event sub-process의 start event가 점선이면, 그것이 내장된 하위 프로세스는 정상적인 진행을 계속한다.**
>
> **하지만 event sub-process에 일반(실선) start event가 있으면, 부모 프로세스를 취소하거나 중단시킨다.**

## 요약

- **Event sub-process는 예외를 처리**하며 부모 프로세스나 하위 프로세스에 내장된다
- **점선 start event = non-canceling** — 예외 처리와 원래 작업이 **독립적으로 병렬 진행**된다
- **실선 start event = canceling** — **바깥 하위 프로세스의 토큰을 죽인다**
- 판단 기준은 **"이 예외 때문에 원래 작업을 멈춰야 하는가"** 다
  - 주문 상태 문의 → 배송을 멈출 이유가 없다 → **점선**
  - 주문 취소 → 배송을 멈춰야 한다 → **실선**
- **하위 프로세스에 부착된 canceling event도 event sub-process의 취소형과 동일하게 동작**한다
