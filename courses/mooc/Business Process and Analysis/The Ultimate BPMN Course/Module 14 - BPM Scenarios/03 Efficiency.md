# Efficiency

## 개요

- BPMN이 크게 기여하는 두 번째 비즈니스 시나리오 — **효율성**
- **BPM의 핵심 개념인 as-is 프로세스와 to-be 프로세스**가 여기서 정식으로 소개된다
- 사례: Fast Fore 컨설팅의 혼란스러운 채용 프로세스

## 내용

### 효율성 개선의 세 단계

1. **현재 상태 이해** — **조직에서 일이 어떻게 돌아가는지, 잠재적 비효율이 어디에 있는지 먼저 파악**한다
2. **간소화(streamlining)** — 파악했으면 **프로세스와 비효율을 간소화**한다
3. **자동화(automating)** — 마지막으로 **프로세스 단계를 자동화**해 **반복 작업을 더 빠르고, 더 싸고, 오류가 덜 나게** 만든다

> **효율성 측면에서는 이 세 차원 모두를 BPMN으로 다룰 수 있다.**

### 사례 — Fast Fore 컨설팅

**문제**: 채용 프로세스가 **매우 수동적이고 혼란스러웠다**

**1. 이해하기**

> **이 문제를 이해하는 데 BPMN 프로세스가 완벽하게 적합하다. 사용 가능하다면 말이다. BPMN 프로세스를 들여다보고 동료들과 그것에 대해 이야기하는 것만으로도 이미 문제가 되는 단계들이 드러나기 때문이다.**

**2~3. 간소화하고 자동화하기**

이 사례에서는 **HR 총괄이 이 혼란의 해법을 찾도록 도왔다.** 즉 **프로세스를 간소화하고 자동화 준비를 갖추게 했다.**

### 핵심 개념 — As-is 프로세스와 To-be 프로세스

> 시작은 **순수한 혼돈(pure chaos)** 이었다. **거기 보이는 것은 사실 BPMN이 아니지만, BPMN을 사용해 현재 상태를 더 잘 이해할 수 있다.**
>
> **이것이 business process management의 매우 중요한 개념으로 이어진다.**

| 용어 | 의미 |
|---|---|
| **As-is process** | **현재 상태(current state)를 나타내는 프로세스.** **오늘 실제로 실행되고 돌아가는 프로세스** |
| **To-be process** | **목표 상태(target state).** **미래에 달성하고 싶은 프로세스** |

### As-is에서 To-be로 가는 방법

> **as-is 프로세스에서 to-be 프로세스로 가려면 당연히 무언가를 해야 한다. 어떤 여정이든 A에서 B로 가려면 그 거리를 걸어야 하는 것과 같다.**
>
> **효율성 향상을 이야기할 때, 이 as-is에서 개선된 to-be 프로세스로 가는 한 가지 방법이 간소화(streamlining)다.**
>
> **간소화란 이 혼란스러운 상태에서 더 질서 있고 효율적인 상태로 가는 것을 뜻한다.**

### 간소화에 대한 강사의 조언

> **일반적으로 간소화 노력에는 은탄환(silver bullet)이 없다.**
>
> **하지만 내가 강력히 권하는 것은, 가능한 한 많은 이해관계자와 협업해 간소화를 진행하라는 것이다. 프로세스를 개선할 수 있는 방법에 대한 모든 통찰과 모든 관점을 확보하기 위해서다.**

## 예시

```text
효율성 개선의 세 단계

① 이해     현재 어떻게 돌아가는가? 비효율은 어디인가?
   ↓        → BPMN으로 as-is를 그린다
   ↓        → 그리고 동료와 이야기하는 것만으로 문제가 드러난다

② 간소화   혼란 → 질서 있고 효율적인 상태
   ↓        → 이해관계자를 최대한 많이 참여시킨다

③ 자동화   반복 작업을 더 빠르게 · 더 싸게 · 오류를 줄여서
            → Module 10의 task type이 이 단계의 도구


As-is → To-be

┌─ As-is process ─────────┐        ┌─ To-be process ─────────┐
│ 오늘 실제로 돌아가는 것   │  ───→  │ 미래에 달성하고 싶은 것   │
│                          │ 간소화 │                          │
│  ╱╲ ╱╲  혼란스러움       │  자동화│  (○)→[A]→[B]→(◎)       │
│ ╱  ╳  ╲                 │        │  질서 있고 효율적          │
└──────────────────────────┘        └──────────────────────────┘
        ↑                                      ↑
  Fast Fore의 채용 프로세스              간소화 + 자동화 준비 완료
  (수동적이고 혼란스러움)


중요: as-is를 정직하게 그려야 한다
  → Module 10의 원칙과 연결
    "애매하면 덜 자동화된 task type을 선택한다.
     as-is를 문서화해 자동화 잠재력을 드러내는 것이 목적이기 때문"
```

## 요약

- **효율성 개선은 이해 → 간소화 → 자동화** 세 단계이고, **BPMN이 세 단계 모두에 기여**한다
- **As-is process = 오늘 실제로 돌아가는 프로세스**, **To-be process = 목표 상태**
- **BPMN 프로세스를 놓고 동료들과 이야기하는 것만으로 문제 단계가 드러난다** — 그림 자체가 대화의 도구다
- **간소화에는 은탄환이 없다.** 대신 **가능한 한 많은 이해관계자를 참여**시켜 모든 관점을 확보한다
- 이 as-is/to-be 개념은 **Module 10의 "애매하면 덜 자동화된 task type을 고른다"** 는 원칙과 직결된다
