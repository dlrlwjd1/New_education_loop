# Visa Process Part 3

## 개요

- **Call activity의 존재 이유를 확정하는 강의**
- 완전히 무관한 두 프로세스가 **같은 블랙리스트 등재 프로세스를 각자 촉발**하는 것을 보여준다

## 내용

### 다른 신청자의 사례

이번에는 비자 프로세스로 돌아가 **다른 사람의 신청**을 따라간다. **심각한 범죄 경력이 있는 사람** — **Dream Island로 도피하려는 은행 강도**다.

### 처리 흐름

이 시나리오에서 주 프로세스(main process)는 다음과 같이 처리한다.

1. back office가 **경찰 기록을 불승인(disapproves)** 한다
2. **신청자에게 거절(reject)을 보낸다**
3. **해당 개인을 블랙리스트에 등재한다**

> **이 행동이 앞서 본 것과 동일한 블랙리스트 등재 프로세스를 촉발한다. 다만 이번에는 overstay 프로세스가 아니라 비자 프로세스가 활성화한 것이다.**

### 대사관이 블랙리스트 등재를 실행하는 두 가지 상황

> 실제로 대사관이 blacklisting 프로세스를 실행하는 상황은 **딱 두 가지**다.
>
> 1. **관광객 등의 비자 초과 체류(overstay visa)**
> 2. **비자 신청자의 범죄 경력 조회(criminal background check)**

### 결론

> **비자 프로세스와 overstay 프로세스는 완전히 무관하지만, call activity로 정의되어 있기 때문에 둘 다 독립적으로 블랙리스트 등재 프로세스를 촉발할 수 있다.**

이것이 **call activity가 존재하는 이유**를 보여주는 완결된 사례다.

## 예시

```text
하나의 전역 프로세스, 두 개의 무관한 호출자

프로세스 A: 비자 신청 (은행 강도의 경우)
(✉ 비자 서류) → [서류 확인] → [경찰 기록 요청] → [기록 평가]
                                                      ↓
                                            ◇ 승인되었는가? ── no
                                                      ↓
                                    [신청자에게 거절 통보]
                                                      ↓
                                    [블랙리스트 등재 ⊞] ━━┓
                                                          ┃
프로세스 B: Overstay (초과 체류의 경우)                    ┃
(✉ 국경통제 통보) → ... → 3차 독촉 후                      ┃
                                    [블랙리스트 등재 ⊞] ━━┫
                                                          ┃
                                                          ↓
                    ┌─────────────────────────────────────────┐
                    │ 전역 정의 프로세스: 블랙리스트 등재        │
                    │ (○) → [DB 조회] → [항목 생성] →          │
                    │       [상태 '차단' 설정] → (◎)           │
                    └─────────────────────────────────────────┘

두 프로세스는 서로 아무 관계가 없다.
그런데도 같은 절차를 필요로 한다.
→ call activity가 정확히 이 문제를 푼다.
```

## 요약

- **완전히 무관한 두 프로세스가 같은 절차를 필요로 할 때 call activity를 쓴다**
- 여기서는 **비자 신청(범죄 경력 불승인)** 과 **overstay(3차 독촉 후)** 두 경로가 같은 블랙리스트 등재를 촉발한다
- 만약 call activity가 아니었다면 **같은 절차를 두 곳에 중복 작성**해야 했고, 한쪽만 고치면 불일치가 생겼을 것이다
- 이것이 Module 8의 `Theory – Call Activity`에서 말한 **"중복 없는 일관성과 효율성"** 의 구체적 사례다
