# Theory – Data Object

## 개요

- **Data object(데이터 객체)** — 프로세스를 흐르는 **모든 종류의 데이터**를 나타낸다
- 예: 업무 문서(business documents), 이메일, 편지
- **핵심 원칙: 사용은 항상 선택 사항(optional)이다**

## 내용

### 읽기와 쓰기 — 화살표 방향이 의미를 결정한다

Bookworm 서점 프로세스의 두 가지 data object를 보자.

**1. 주문 확인 템플릿(order confirmation template) — task가 읽는다**

- 영업 관리자가 사용하는 **Word 문서**
- 관리자가 고객·제품 데이터를 템플릿에 복사·붙여넣기 한다
- 이 템플릿으로 **"주문 확인 발송" task를 완료**한다
- → **task가 data object를 읽는다(reads)**

**2. 송장(invoice) — task가 쓴다**

- **"송장 생성(generate the invoice)" task가 만들어 낸다**
- → **task가 data object를 쓴다(writes).** 그래서 **화살표가 task에서 object 쪽을 향한다**
- 이후 다른 task가 **후속 활동에 필요하므로 이 송장을 읽는다**

### 매우 중요한 원칙 — 항상 선택 사항이다

> **data object의 사용은 항상 선택 사항이다. 데이터를 소비하거나 생성하는 모든 task에 data object를 붙일 필요는 없다.**
>
> 포함 여부는 **use case에 달려 있다** — **프로세스에 명확성을 더하는가, 아닌가.**

### 언제 쓰는 것이 좋은가

**쓰는 것이 타당한 경우**

Bookworm 서점 관리자가 **새로운 문서 관리 시스템(document management system)을 도입**하려 한다고 하자.

- 매장에서 사용되는 **모든 문서가 시스템에 반영**되어야 한다
- IT 부서가 **어떤 문서가 언제 어떻게 사용되는지 알아야 한다**
- → **이런 시나리오에서는 data object를 쓰는 것이 완벽하게 타당하다**

**피해야 하는 경우**

> **큰 프로세스에서는 data object가 너무 많으면 다이어그램을 어지럽히고 표현력을 떨어뜨린다.**

**그래서 스스로에게 물어야 한다.**

> - **이 프로세스에 정말 data object가 필요한가?**
> - **그것이 내 프로세스의 명확성을 개선하는가, 방해하는가?**

## 예시

```text
Data object — 읽기와 쓰기

           📄 주문 확인 템플릿
                  │
                  ↓  (읽기: object → task)
(○) → [주문 접수] → [주문 확인 발송] → [송장 생성] → [송장 발송] → (◎)
                                            │             ↑
                                            ↓ (쓰기)      │ (읽기)
                                         📄 송장 ─────────┘


화살표 방향의 의미

📄 ──→ [Task]   task가 data object를 읽는다 (reads)
[Task] ──→ 📄   task가 data object를 쓴다 (writes)


사용 판단

  이 data object가 프로세스의 명확성을 높이는가?
        │
   ┌────┴────┐
  예         아니오
   │           │
 넣는다      넣지 않는다
   │
 전형적 사례:
 문서 관리 시스템 도입 —
 IT가 어떤 문서를 언제 어떻게 쓰는지 알아야 할 때
```

## 요약

- **Data object는 프로세스를 흐르는 데이터**(문서·이메일·편지 등)를 나타낸다
- **화살표 방향이 읽기/쓰기를 결정한다** — object→task는 읽기, task→object는 쓰기
- **사용은 항상 선택 사항이다.** 데이터를 다루는 모든 task에 붙일 필요가 없다
- **판단 기준은 "명확성을 높이는가"** 다. 너무 많으면 오히려 다이어그램을 어지럽힌다
- 문서 관리 시스템 요구사항 정의처럼 **문서 추적이 목적일 때 특히 유용**하다
