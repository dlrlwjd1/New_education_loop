# Theory – Data Store

## 개요

- **Data store(데이터 저장소)** — 프로세스가 **데이터를 읽거나 쓸 수 있는 장소**를 정의한다
- Data object와의 결정적 차이: **프로세스 인스턴스의 수명을 넘어 데이터가 지속된다(persists)**

## 내용

### 개념

데이터를 **생성하고 소비하는 것**에 더해, 우리는 종종 **데이터를 저장(store)** 해야 한다. BPMN은 이를 위해 **data store 요소**를 제공한다.

> **data store는 프로세스가 데이터를 읽거나 쓸 수 있는 장소를 단순히 정의한다.**

### Data object와의 결정적 차이 — 지속성(persistence)

> **data object와 달리, data store는 프로세스 인스턴스의 수명을 넘어 데이터를 지속시킨다. 즉 프로세스와 독립적으로 존재한다.**

| | **Data object** | **Data store** |
|---|---|---|
| 수명 | **프로세스 인스턴스와 함께 끝난다** | **프로세스와 독립적으로 존재한다** |
| 성격 | 프로세스를 흐르는 데이터 | 데이터를 담아두는 **장소** |
| 예 | 송장, 주문 확인 템플릿 | 고객 관리 시스템, 데이터베이스 |

### 사례

Bookworm 프로세스에 **영업 관리자가 고객 관리 시스템(customer management system)에 고객 항목을 생성**하는 task를 추가했다.

- 이 task는 **data store에 데이터를 쓴다**
- → **화살표가 activity에서 store 쪽을 향한다**
- 이 동작은 **activity가 저장할 데이터를 쓰는 data object의 경우와 매우 유사**하다

## 예시

```text
Data store — 프로세스 밖에 지속되는 저장소

(○) → [주문 접수] → [고객 항목 생성] → [주문 처리] → (◎)
                           │
                           ↓ (쓰기)
                    ▤ 고객 관리 시스템
                      (data store)
                      ↑
                프로세스가 끝나도 데이터가 남는다
                다른 프로세스 인스턴스도 이것을 읽는다


Data object vs Data store — 수명

Data object 📄
  프로세스 시작 ──────────────── 프로세스 종료
              [생성]      [소비]    ✗ 사라진다

Data store ▤
  프로세스 시작 ──────────────── 프로세스 종료
              [쓰기]                  │
  ────────────────────────────────────┴─────→ 계속 존재
  다른 프로세스, 다른 인스턴스도 접근 가능
```

## 요약

- **Data store는 프로세스가 데이터를 읽고 쓰는 "장소"** 다
- **data object와의 핵심 차이는 지속성**이다 — data store의 데이터는 **프로세스 인스턴스가 끝나도 남는다**
- 화살표 방향의 의미는 data object와 동일하다 (activity→store는 쓰기)
- 전형적인 예: 고객 관리 시스템, 데이터베이스 같은 **영속 저장소**
