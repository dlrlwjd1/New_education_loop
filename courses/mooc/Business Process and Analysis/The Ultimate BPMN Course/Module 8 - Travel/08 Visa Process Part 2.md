# Visa Process Part 2

## 개요

- 비자 초과 체류(overstay) 프로세스
- 사용 요소: **event based gateway**, **data store**, **call activity**
- 블랙리스트 등재(blacklisting) 프로세스가 **call activity**로 정의되는 이유를 보여준다

## 내용

### 상황

섬에서 지내다 시간 가는 줄 모르고 **실수로 비자 기간을 초과 체류**했다. 국경 통제(border control)는 귀국은 허용하지만 **결과가 있을 수 있다고 경고**한다. 이미 **overstay 프로세스가 촉발**되었기 때문이다.

### Overstay 프로세스

**1. 통보와 평가** — 국경 통제가 대사관에 사건을 알린다. 대사관 back office가 상황을 평가하고 **심각한지 판단**한다

**2. Event based gateway — 세 가지 event 대기**

이 시점에서 세 가지 event가 발생할 수 있다.

- **벌금 납부가 접수됨**
- **최종 독촉장(final dunning letter)이 발송됨**
- **7일이 경과함**

**3. 독촉 루프**

**7일이 경과했다고 가정**하면 → **독촉장(dunning letter) 발송**으로 이어진다.

- 첫 독촉장 발송 후 **event based gateway가 다음 event를 기다린다**
- **또 7일이 납부 없이 경과**하면 → **두 번째 독촉장 발송**
- **세 번째로 같은 일이 반복**되면 → **conditional event가 촉발되어 블랙리스트 등재(blacklisting)로 이어진다**

### 블랙리스트 등재 프로세스 — data store의 실제 사용

**1. 조회(읽기)** — IT 부서가 **그 사람이 데이터베이스에 기록되어 있는지 확인**한다

> **데이터베이스 항목을 읽는다. 화살표가 data store에서 task 쪽을 향하는 것으로 표시된다.**

**2. 생성(쓰기)** — **항목이 없으면 IT 부서가 새 블랙리스트 항목을 생성**한다

> **화살표가 task에서 data storage 쪽을 향하는 것으로 표시된다.**

**3. 상태 설정** — 마지막으로 그 사람의 상태를 **차단(blocked)** 으로 설정한다

이제 그 사람은 **Dream Island 데이터베이스에 공식적으로 차단 상태로 등록**된다.

### 핵심 — 블랙리스트 프로세스는 call activity다

> **blacklisting 프로세스는 call activity다. 즉 무관한 어떤 다른 프로세스에서도 접근할 수 있다.**

## 예시

```text
Overstay 프로세스

(✉ 국경통제가 대사관에 통보)
        ↓
   [상황 평가 · 심각도 판단]
        ↓
        ⬡  ← event based gateway
     ┌──┼──────────┐
 (💰 벌금    (⏱ 7일    (✉ 최종
  납부됨)     경과)      독촉장 발송)
     │        ↓
     │   [1차 독촉장 발송]
     │        ↓
     │        ⬡ ← 다시 대기
     │        ↓ (또 7일 경과)
     │   [2차 독촉장 발송]
     │        ↓
     │        ⬡ ← 다시 대기
     │        ↓ (세 번째)
     │   (◇ conditional event 촉발)
     │        ↓
     │   [블랙리스트 등재 ⊞]  ← call activity (굵은 테두리)
     ↓        ↓
  (◎ 종료) (◎ 차단됨)


블랙리스트 등재 프로세스 (전역 정의)

(○) → [DB에 기록되어 있는지 확인]
             ↑ (읽기)
          ▤ 블랙리스트 DB
             ↓
        ◇ 항목이 있는가? ── no → [새 항목 생성]
                                      ↓ (쓰기)
                                   ▤ 블랙리스트 DB
                                      ↓
                              [상태를 '차단'으로 설정]
                                      ↓
                                   (◎ 등재 완료)
```

## 요약

- **Event based gateway로 "납부 vs 시간 경과" 경쟁**을 표현하고, **독촉 루프**를 만든다
- **Data store의 읽기/쓰기 화살표 방향**은 data object와 동일한 규칙을 따른다
- **블랙리스트 등재가 call activity로 정의된 이유**는 다음 강의에서 밝혀진다 — 다른 프로세스도 이것을 필요로 하기 때문이다
