# Theory – Collapsed Pools

## 개요

- **Collapsed pool(접힌 풀)** — 내부 프로세스를 보여주지 않는 pool
- 핵심 개념: **black box(블랙박스)**
- 중요한 사용 규칙이 하나 있다

## 내용

### 일반 pool과의 차이

pool은 프로세스의 **참여자(participant)** 를 나타낸다. collapsed pool도 같은 역할을 하지만 **한 가지 결정적 차이**가 있다.

> **collapsed pool은 참여자의 상세한 프로세스 흐름을 보여주지 않는다.**

pool 내부의 프로세스는 **black box**로 취급된다. 안에서 뭔가 일어나고 있지만,

- 우리가 그 구체적인 내용을 **모르거나**
- 그것을 **포함시킬 필요가 없다**

### 언제 쓰는가 — 외부 참여자

collapsed pool은 **프로세스의 외부 참여자(external participants)** 를 표현하는 데 적합하다.

**예시**: 고객(customer)과 일하는 경우

→ collapsed pool을 사용해 **우리 행동과 고객 사이의 접점(touching point)** 만 보여주고, **고객의 내부 프로세스는 파고들지 않는다.**

### 중요한 규칙 — 외부 당사자에만 쓴다

> **collapsed pool은 오직 외부 당사자(external parties)에게만 사용해야 한다.**

**같은 조직 내 다른 부서를 모델링하는 경우라면?**

→ collapsed pool이 아니라 **같은 pool 안에 lane을 추가**하는 것이 옳다.

> **다른 부서가 뭘 하는지 잘 모른다는 이유로 collapsed pool을 쓰는 것은 올바른 모델링 관행이 아니다.**

## 예시

```text
올바른 사용 — 외부 참여자

┌─ Pool: 우리 회사 ──────────────────────────┐
│  ┌─ Lane: 영업 ──────────────────────────┐ │
│  │  (○) → [주문 접수] → [송장 발행] → (◎) │ │
│  └───────────────────────────────────────┘ │
└────────────────┬───────────────────────────┘
                 │  ← 접점(touching point)만 표현
┌────────────────┴───────────────────────────┐
│  Pool: 고객  (collapsed / black box)        │  ← 내부 흐름 없음
└────────────────────────────────────────────┘


잘못된 사용 — 같은 조직의 다른 부서

✗ ┌─ Pool: 회계팀 (collapsed) ─┐   "회계팀이 뭘 하는지 몰라서 접었다"
  └───────────────────────────┘

✓ ┌─ Pool: 우리 회사 ──────────┐
  │  ├─ Lane: 영업            │   같은 pool 안에 lane을 추가한다
  │  ├─ Lane: 회계            │
  │  └─ Lane: 물류            │
  └───────────────────────────┘
```

## 요약

- **Collapsed pool은 내부 프로세스를 보여주지 않는 black box**다
- **외부 참여자(고객, 협력사 등)** 를 표현하고 **접점만 드러낼 때** 사용한다
- **같은 조직 내 다른 부서에는 쓰지 않는다.** 대신 **같은 pool에 lane을 추가**한다
- "그 부서가 뭘 하는지 모르겠다"는 collapsed pool을 쓸 정당한 이유가 되지 않는다
