# Theory - Message Event — 대화정리

## 개요

- 학습일: 2026-09-08
- 원본: [04 Theory - Message Event](04%20Theory%20-%20Message%20Event.md)
- 메시지 이벤트는 외부 당사자와의 상호작용을 표현한다. 프로세스의 단계와 메시지 방향으로 네 종류를 구분했다.

## 내용

### 사용자가 정리한 흐름

고객의 요청을 받아 프로세스를 시작하고, 진행 중에 메시지를 보내거나 추가 요청을 받는다. 완료 통보를 보내며 끝낼 수도 있다. 사용자는 중간 수신이 새 프로세스를 시작하는 것이 아니라 기존 프로세스를 이어가는 것임을 확인했다.

| 단계 | 방향 | 이벤트 |
|---|---|---|
| 시작 | 수신 | 시작 메시지 이벤트(start message event) |
| 중간 | 수신 | 중간 수신 메시지 이벤트(catching intermediate message event) |
| 중간 | 발신 | 중간 발신 메시지 이벤트(throwing intermediate message event) |
| 종료 | 발신 | 종료 메시지 이벤트(end message event) |

### 태스크와 이벤트

- “책과 송장을 보낸다”는 수행할 행동이므로 태스크(task)다.
- “책과 송장이 발송되었다”는 일이 일어났다는 사실을 나타내는 이벤트(event)다.

### 메시지의 매체

사용자는 디지털 메시지만이 아니라 고객과 소통하는 여러 채널을 표현할 수 있다고 설명했다. 강의는 이메일뿐 아니라 계좌 이체와 실물 소포도 예로 든다. 대상은 고객을 포함한 외부 당사자다.

### 헷갈렸다가 교정한 지점

- 시작 메시지 이벤트를 쓰는 이유를 처음에는 고객의 대기 가능성과 연결했다. 핵심은 주문 수신이 프로세스의 시작 조건이라는 점이다.
- 완료 통보를 “발신형”이라고 답했다. 방향은 맞지만, 보내고 계속 진행하는 중간 발신과 보내면서 끝나는 종료 메시지 이벤트를 구분했다.
- 방향을 “발신·송신”이라고 정리했다. 두 단어는 모두 보내는 뜻이며, 구분해야 할 방향은 “발신·수신”이다.
- 단계를 “시작·중간·결과”로 표현했다가 표기 용어를 “시작·중간·종료”로 다듬었다.
- 시작 수신과 중간 수신의 차이를 다시 확인했다. 전자는 새 프로세스를 시작하고 후자는 이미 진행 중인 프로세스를 이어간다.

## 예시

대화에서 사용한 서점 상황:

- 고객 주문이 도착해야 주문 처리가 시작된다 → 시작 메시지 이벤트.
- 주문 처리 도중 고객의 추가 답변을 받는다 → 중간 수신 메시지 이벤트.
- 주문 처리 도중 배송 안내를 보내고 다음 단계로 진행한다 → 중간 발신 메시지 이벤트.
- 완료 통보를 보내면서 프로세스를 끝낸다 → 종료 메시지 이벤트.

## 요약

- 메시지 이벤트는 언제 주고받는지와 받는지·보내는지로 구분한다.
- 같은 수신이라도 프로세스를 시작하는지, 기존 프로세스를 이어가는지가 다르다.
- 같은 발신이라도 이후 계속 진행하는지, 프로세스를 끝내는지가 다르다.
- 태스크는 행동, 이벤트는 발생한 사실을 나타낸다.
