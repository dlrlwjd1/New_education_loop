# Practical – Beauty Process (Part 2)

## 개요

- inclusive gateway의 **가장 복잡한 사례**를 다룬다
- 사례: **gold 등급 고객이 샘플을 요청한 경우**
- 학생들이 가장 많이 질문하는 두 가지 오해를 정면으로 다룬다

## 내용

### 시나리오 — gold 등급 고객

Susan이 **사은품 세 개를 모두 선택**한다 → **토큰 3개 발행**

- closing gateway는 처음에 **토큰 3개를 기대**한다

**그런데 Susan이 디지털 바우처를 보내기로 하면?**

→ **closing gateway가 갱신되어 기대치를 2개로 줄인다**

### 여기서 생기는 상황 — 토큰 2개가 동시에 흐른다

샤워젤 토큰과 아이라이너 토큰이 다시 병합된 뒤에도, **여전히 토큰 2개가 순환하며 각각 별개의 event로 향한다.**

### 오해 1 — "토큰이 여러 개 동시에 흘러도 되나?"

> **학생들이 항상 묻는 질문이다. 답은 간단하다 — 그렇다, 허용된다.**

### 오해 2 — "첫 번째 end event가 활성화되면 프로세스가 끝나는 것 아닌가?"

> **아니다. 이것은 토큰 경주(token race)가 아니다.**

**프로세스가 완료되려면 모든 토큰이 각자의 end event에 도착해야 한다.**

이 사례에서는 고객이 **소포도 받고 이메일도 받는다**는 뜻이다.

### 왜 end event를 두 개로 나누는가?

> **두 end event가 서로 다른 상황을 정의하고, 그 상황들이 서로 다른 후속 활동(follow-up activities)으로 이어지기 때문이다.**

| End event | 후속 활동 |
|---|---|
| **사은품 배송** | 배송업체에 비용 지불, 소포 추적(tracking) 등이 뒤따른다 |
| **이메일 발송** | 위와 같은 활동이 **전혀 필요 없다** |

> **한 문장으로: end event를 두 개 두는 이유는 각각이 완전히 다른 후속 활동을 촉발하기 때문이다.**

## 예시

```text
Gold 등급 고객 시나리오

        ◎  ← inclusive gateway: 사은품 3개 모두 선택 → 토큰 3개
        │
   ┌────┼────────────┐
   │    │            │
[바우처] [샤워젤]  [아이라이너]
   │    │            │
   ◇    │            │
 디지털 선택          │
   │    │            │
   │    └─────┬──────┘
   │          ◎  ← closing: 기대치가 3 → 2로 갱신됨
   │          │
   │          ●  (샤워젤+아이라이너 병합 토큰)
   │          ↓
   ●     [포장 준비] → [배송]
   ↓          ↓
(◍ 이메일   (◍ 사은품
   발송)       배송됨)
   │            │
   │            └→ 후속: 배송비 지불, 소포 추적
   └─────────────→ 후속: 없음

두 토큰이 각자의 end event에 모두 도착해야 프로세스 완료.
먼저 도착한 쪽이 이기는 경주가 아니다.
```

## 요약

- **토큰이 여러 개 동시에 흐르는 것은 정상이며 허용된다**
- **프로세스는 첫 end event에서 끝나지 않는다.** 토큰 경주가 아니다 — **모든 토큰이 도착해야** 완료된다
- **end event를 나누는 기준은 "후속 활동이 다른가"** 다
  - 배송 → 배송비 지불·추적이 뒤따른다
  - 이메일 → 아무것도 뒤따르지 않는다
  - 따라서 두 개로 나눈다
- 이 기준은 Module 2 실습에서 본 "결과가 다르면 end event를 나눈다"는 원칙의 연장선이다
