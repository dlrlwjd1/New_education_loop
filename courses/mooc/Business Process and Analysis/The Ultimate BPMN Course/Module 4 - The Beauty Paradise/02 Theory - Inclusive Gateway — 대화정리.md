# Theory - Inclusive Gateway — 대화정리

## 개요

- 학습일: 2026-09-08
- 원본: [02 Theory - Inclusive Gateway](02%20Theory%20-%20Inclusive%20Gateway.md)
- 사용자 정리: 배타적 게이트웨이는 여러 갈림길 중 하나만 보내고, 병렬은 다 보내고, 포함 게이트웨이는 선택적으로 복수로 보낼 수 있다.
- 게이트웨이 학습에서 출발해 AI 네이티브 회사의 업무 설계, 워크플로 엔진, Hermes를 통한 구현과 코드 호출까지 질문했다.

## 내용

### 강의 핵심 — 선택한 경로만 활성화하고 기다린다

포함 게이트웨이(inclusive gateway)는 가운데 원(O)으로 표시한다. 조건에 따라 하나, 여러 개 또는 모든 경로를 활성화할 수 있다.

세 길 중 2번과 3번만 선택하면 토큰 두 개가 각 길로 간다. 합류에서는 그 두 토큰을 기다린다. 사용자는 “이미 보내지도 않은 거를 기다릴 필요가 없지”라고 설명했고, 3번 토큰이 오는 중이라면 도착할 때까지 기다린다고 답했다.

### 구분을 명확히 한 부분

사용자의 “닫힌 게이트웨이에서 구슬이 다 올 때까지 기다린다”는 정리에서 ‘다’의 범위를 확인했다. 병렬은 모든 경로를 활성화하고 기다리지만, 이 강의의 포함 합류 예시는 선택된 경로의 토큰만 기다린다. 세 길 중 두 길을 선택하면 두 개가 모였을 때 진행한다.

고객마다 필요한 조회가 다르면 무엇을 쓰느냐는 질문에는 처음에 배타적이라고 답했다. 질문 자체가 한 고객당 한 조회인지 여러 조회인지 불명확했다. 주문과 배송 조회가 둘 다 필요할 수도 있다는 조건을 명시하자 사용자는 포함 게이트웨이라고 답했다. 이를 단순한 사용자 오개념으로 기록하지 않는다.

### 대화 확장 — AI 네이티브 회사와 구현

이 절은 강의 원문 내용이 아니라 사용자의 추가 질문에 답하며 다룬 구현 예시다.

- BPMN은 회사 업무에서 무엇을 실행하고 어떤 결과를 기다릴지 설계하는 데 연결된다.
- 고객 문의를 읽고 필요한 조회를 선택한 뒤, 선택한 조회 결과가 모이면 답변을 만드는 예시를 사용했다.
- 워크플로 엔진은 실행 순서와 진행 상태를 관리하는 프로그램으로 설명했다. Camunda는 BPMN 모델과 작업 코드를 연결하고, LangGraph는 코드로 에이전트 흐름을 구성하는 도구의 예로 소개했다. 어느 제품이 시장에서 더 일반적인지는 자료만으로 단정하지 않았다.
- Hermes·OpenClaw처럼 기본 실행 기능이 있는 에이전트를 기반으로 회사 지침과 도구를 연결할 수 있다. ‘완성형 에이전트’는 대화 중 사용한 설명용 표현이며 정식 분류명이 아니다.
- 스킬의 자연어 지침과 코드가 강제하는 완료·승인 조건은 구분한다. 설치만으로 회사 업무 규칙이나 엄격한 실행 보장이 생기지는 않는다.

### 대화 확장 — Hermes에서 게이트웨이 규칙 구현

- 배타적: 문의 유형에 따라 `if / elif`로 하나의 작업만 실행하는 구조.
- 병렬: `delegate_task`의 작업 목록으로 여러 하위 에이전트에게 위임하고 결과를 모으는 방식. 단순 조회라면 코드에서 병렬 실행과 대기를 구현할 수도 있다.
- 포함: 각 조건을 별도로 검사해 필요한 작업 목록을 만들고, 선택한 작업들만 실행하고 기다리는 구조.
- 위 설명은 BPMN 엔진과 완전히 같은 실행 의미를 자동 보장한다는 뜻이 아니다. 실패한 작업을 성공으로 간주하지 않고 결과 상태를 확인하는 규칙도 구성해야 한다.

공식 자료를 확인해 설명한 기능이며, 이 세션에서 Hermes를 설치하거나 실제로 실행해 검증하지는 않았다.

### 교정한 오해 — 인터프리터 언어여야 하는가

사용자는 “코드는 인터프리터의 특징을 가져야겠네”라고 추론했다. 호출 가능한 실행 방법이 있다면 인터프리터 언어에 한정되지 않는다고 설명했다.

- Python: `python lookup_order.py`
- JavaScript: `node lookup_order.js`
- 미리 컴파일한 실행 파일: `./lookup_order`

필요한 것은 명확한 입력·출력과 실행 방법이다. 실행 환경과 접근 권한은 갖춰져 있어야 한다. 사용자는 이후 이해했다고 확인했다.

## 예시

강의의 포함 게이트웨이 예시:

```text
세 경로 중 2번·3번 선택
→ 토큰 두 개로 나눠 각각 전송
→ 2번만 도착하면 대기
→ 3번도 도착하면 합류 후 진행
→ 선택하지 않은 1번은 기다리지 않음
```

대화에서 사용한 고객 문의 적용 예시:

- 주문 정보만 필요하면 주문 조회만 실행한다.
- 주문과 배송 정보가 모두 필요하면 둘 다 실행한다.
- 답변 작성은 선택한 조회 결과가 모두 모인 뒤 진행한다.

## 요약

- 배타적은 하나, 병렬은 전부, 포함은 조건에 맞는 경로 조합이다.
- 포함 합류는 선택한 경로의 토큰만 기다린다.
- BPMN으로 설계한 분기·대기 규칙은 에이전트 지침과 코드로 구현할 수 있다.
- 코드 호출에 인터프리터 언어가 필수인 것은 아니다.
