# Non Interrupting Attached Events

## 개요

- **Non-interrupting attached event(비중단 부착 이벤트)**
- 일반 attached event와의 차이: **촉발되어도 원래 task의 실행이 계속된다**
- 토큰 관점: **원래 토큰이 죽지 않고, 추가 토큰이 생성된다**

## 내용

### 복습 — 일반(interrupting) attached event

- **부착된 message event가 촉발되면** → 그 event를 지닌 **task가 중단되고 취소(interrupted and canceled)** 된다
- **대체 task가 실행**된다
- 토큰 관점: **원래 task의 토큰이 죽고(killed), 대체 경로를 위한 새 토큰이 생성**된다

### Non-interrupting attached event

- **부착된 event가 촉발되면** → **대체 task를 촉발하는 추가 토큰이 생성**된다
- **원래 task는 계속 활성 상태로 남는다.** 즉 **원래 토큰이 죽지 않는다**

### 사례 — Deluxe 주문 프로세스

**기본 구조**: 물품을 포장·배송하면서 **송장 처리를 병렬로** 진행하는 전형적인 주문 프로세스

**추가한 것**: **`부족 품목 조달(procure missing items)` task에 non-interrupting timer event를 부착**했다. **이 event는 task가 3일 이상 걸리면 촉발**된다. 공급업체에 공급망 중단이 있으면 쉽게 촉발될 수 있다.

### 토큰 흐름으로 따라가기

1. **주문 확인**부터 시작한다. 주문에 문제가 없으면
2. **parallel gateway로 토큰을 복제**해 **배송과 송장 처리를 병렬 실행**한다
3. **경리부(bookkeeping)는 송장 생성**을 진행하고, **창고는 주문 품목의 가용성을 확인**한다
4. **하나 이상의 품목이 없으면 부족 부품 조달을 시작**한다
5. **며칠이 지난다.** 경리부는 송장을 진작에 끝냈지만 **조달 쪽에서는 아무 일도 일어나지 않는다**
6. **조달 3일째, timer event가 촉발**되어 **`고객에게 배송 지연 통보` task가 실행**된다

> **이 경우 우리는 당연히 품목 조달을 취소하고 싶지 않다. 다만 기다리는 동안 병렬로 고객에게 알려서 배송 지연을 예상할 수 있게 하려는 것이다.**

7. 언젠가 **부족 물품을 받고 배송할 수 있게 되어 모두가 만족**한다

## 예시

```text
Interrupting vs Non-interrupting

✗ Interrupting (일반 attached event) — 실선 테두리

        ┌────────────────────┐
(●) →   │  [부족 품목 조달]   │ ──→ 정상 완료 → ...
        │  ← 토큰이 죽는다 ✗  │
        └────────(✉)─────────┘
                  ↓
           [대체 task] (●) ← 새 토큰
           조달은 취소된다


✓ Non-interrupting — 점선 테두리

        ┌────────────────────┐
(●) →   │  [부족 품목 조달]   │ ──→ 정상 완료 → [배송] → ...
        │  ← 토큰이 살아있다 ✓ │
        └────────(⏱)─────────┘
                  ┊ 3일 경과 시
                  ↓
        [고객에게 지연 통보] (●) ← 추가 토큰
        조달은 계속 진행된다


Deluxe 주문 프로세스 전체

(○) → [주문 확인] → ⊕
                   ┌─┴──────────────────────────┐
                   │                            │
            [송장 생성]              [재고 확인] → ◇ 없음
             (경리부)                              ↓
                   │           ┌────────────────────┐
                   │           │ [부족 품목 조달]     │
                   │           └────────(⏱ 3일)─────┘
                   │                     ┊
                   │            [고객에게 지연 통보]
                   │                     │
                   │           [물품 수령] → [배송]
                   │                     │
                   └──────────┬──────────┘
                              ⊕
                              ↓
                            (◎)
```

## 요약

- **Non-interrupting attached event는 원래 task를 중단시키지 않는다**
- **추가 토큰이 생성**되어 대체 경로가 **병렬로** 실행된다
- 전형적 용도: **"기다리는 동안 뭔가를 함께 한다"** — 지연 통보, 에스컬레이션, 알림
- 판단 기준: **원래 작업을 취소해야 하는가, 계속하면서 뭔가를 추가로 해야 하는가**
  - 취소해야 한다 → **interrupting** (실선)
  - 계속해야 한다 → **non-interrupting** (점선)
