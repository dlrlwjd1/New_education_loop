# 1.3: How Process Mining Relates to Data Mining

## 개요
- 프로세스 마이닝을 **"슈퍼 글루(super glue)"** 로 규정한다 — 데이터와 프로세스, 비즈니스와 IT, BI와 BPM, 성능과 컴플라이언스를 잇는다.
- **욕망의 길(desire lines)** 비유가 이 강의의 핵심 이미지다.
- 데이터 마이닝의 기본 어휘(지도학습/비지도학습, 응답변수/예측변수)를 정리한다.

## 내용

### 프로세스 마이닝은 무엇을 잇는가
- **데이터**와 **프로세스**
- **현업 사람들**과 **IT 사람들**
- **비즈니스 인텔리전스(BI)** 와 **비즈니스 프로세스 관리(BPM)**
- **성능**과 **컴플라이언스**
- 그리고 이것을 **런타임에도, 설계 시점에도** 할 수 있다

### 왜 BI만으로는 부족한가 — Anscombe's Quartet
고전적 BI 도구는 스프레드시트, 계기판, 그래프로 **현실을 숫자 집합으로 포착**하려 한다. 그것으로는 부족하다.

**Anscombe's Quartet**: 각 11개 원소로 이뤄진 **네 개의 데이터셋**이 있다. 그림으로 보면 **완전히 다르게 생겼는데**, 통계적 성질은 거의 같다.
- x의 평균 = 9, 분산 = 11 (네 경우 모두)
- y도 마찬가지
- **선형 회귀를 적용해도 네 데이터셋 모두 정확히 같은 결과**

> BI 도구가 숫자만 보여준다면 그것으로 충분하지 않다. **숫자 뒤를 봐야 한다.**

### 욕망의 길(desire lines)
강의자가 베이징 칭화대 캠퍼스에서 찍은 사진. 잔디밭에 사람들이 다녀서 생긴 **오솔길**이 있고, 동료가 그 위를 걷고 있다.

| 현실의 것 | 프로세스 마이닝에서 |
|---|---|
| **잔디밭의 오솔길** | **이벤트 데이터** — 사람들이 실제로 하는 것 |
| **"여기로 다니지 마시오" 표지판** | **프로세스 모델** — 공식적으로 해야 하는 것 |

또 다른 사진: 자전거를 공원에 못 들어오게 막는 문(gate)이 있는데, **욕망의 길이 그 옆으로 나 있다.** 즉 **문이 의도한 대로 작동하지 않는다는 것을 데이터가 보여준다.**

### 프로세스 발견 = 예시로 언어를 배우기
아이가 엄마의 말을 듣고 언어를 배우는 것에 비유한다.

| 엄마가 말한 것 | 아이가 추론한 언어(모델) |
|---|---|
| `abc` | `abc`가 전부인 언어 |
| `abd` | 끝에 c와 d 중 **선택**이 있구나 |
| `ad` | `ad`이거나, `ab` 다음에 c나 d가 오는 것 |
| `abbc` | **b의 개수가 가변이구나** (0개 이상) — 학습에서 도약이 일어난 순간 |

| 언어 학습 | 프로세스 마이닝 |
|---|---|
| 문장(sentence) | 이벤트 로그의 **트레이스** |
| 언어(language) | **프로세스 모델** |

### 적합성 검사 = 맞춤법 검사
맞춤법 검사기는 **언어의 모델**을 갖고 있고, 입력한 텍스트가 그 언어에 맞는지 검사한다.

프로세스 마이닝의 적합성 검사에서 나오는 진단도 같다:
- 일어났지만 **일어나면 안 됐던** 활동
- 그 반대(일어나야 했는데 안 일어난 것)
- **너무 늦게, 너무 일찍**, 또는 **잘못된 사람**이 실행한 활동

### 데이터 마이닝의 기본 어휘

**데이터의 형태**: 표에서 각 **행 = 인스턴스**, 각 **열 = 변수**(속성/특성/데이터 요소).

| 변수 유형 | 정의 | 예 |
|---|---|---|
| **수치형(numerical)** | 숫자를 값으로 갖는다 | 나이, 몸무게 |
| **범주형(categorical)** | 작은 집합에서 값을 취한다 | cum laude/pass/fail, true/false |
| ↳ **순서형(ordinal)** | 순서가 **있는** 범주형 | 성적 등급 |
| ↳ **명목형(nominal)** | 순서가 **없는** 범주형 | true/false, 성별 |

**두 종류의 학습**

| | **지도학습(supervised)** | **비지도학습(unsupervised)** |
|---|---|---|
| 데이터 | **레이블이 있다(labeled)** | 레이블이 없다 |
| 변수 | **응답변수(response, 종속변수)** 를 **예측변수(predictor, 독립변수)** 로 설명 | 응답변수 없음 |
| 기법 | **분류**(의사결정 트리) — 응답변수가 범주형일 때 · **회귀** — 응답변수가 수치형일 때 | **군집화(clustering)**, **패턴 발견** |
| 목적 | 클래스나 값을 예측 | 동질적 집단을 찾기 |

### 프로세스 마이닝 vs 데이터 마이닝

| | 공통 | 차이 |
|---|---|---|
| 출발점 | 둘 다 **데이터에서 시작** | — |
| 관점 | — | 데이터 마이닝은 **프로세스 중심이 아니다.** 고립된 결정을 본다 |
| 할 수 없는 것 | — | 프로세스 발견, 적합성 검사, 병목 분석은 **전통적 데이터 마이닝으로 불가능**하다 |
| 핵심 개념 | — | **엔드투엔드 프로세스 모델**이 결정적이고, 그러려면 **동시성(concurrency)** 을 다뤄야 한다 |
| 데이터 형태 | — | 프로세스 마이닝은 **타임스탬프가 있고 케이스를 가리키는 이벤트**를 가정한다. 결정적 차이 |

> 다만 둘은 **함께 쓰여** 매우 고급 질문에 답한다.

## 요약
- 프로세스 마이닝은 데이터↔프로세스, 현업↔IT, BI↔BPM, 성능↔컴플라이언스를 잇는 **슈퍼 글루**다.
- **Anscombe's Quartet** — 통계값이 같아도 실제 모습은 완전히 다를 수 있다. 숫자 뒤를 봐야 한다.
- **욕망의 길** — 이벤트 데이터는 "실제로 하는 것", 프로세스 모델은 "해야 하는 것". 그 차이를 드러내는 것이 프로세스 마이닝이다.
- 발견은 **예시로 언어를 배우는 것**, 적합성 검사는 **맞춤법 검사**에 해당한다.
- 데이터 마이닝과의 결정적 차이는 **이벤트에 타임스탬프와 케이스 ID가 있다**는 것, 그리고 **엔드투엔드와 동시성**을 다룬다는 것이다.
