# 1.8: Evaluating Mining Results

## 개요
- 마이닝 결과의 **품질을 재는 방법** — 혼동 행렬과 그 파생 지표들.
- **과대적합·과소적합**을 피하기 위한 **교차 검증(cross-validation)**.
- 프로세스 마이닝에도 그대로 적용되는 개념들과, 프로세스 마이닝 고유의 어려움.

## 내용

### 혼동 행렬(confusion matrix)
**실제 클래스 × 예측 클래스**를 표로 놓는다. 초록은 정답, 빨강은 문제이며 **빨강 숫자가 클수록 문제가 크다.**

**예 1 — 학생 성적**: 실제로는 통과했는데(actual) 낙제로 예측된(predicted) 학생이 21명 → 오답.

**예 2 — 레스토랑 식중독**: 실제로 심하게 아팠던 고객은 **전부 정확히 예측**됐다. 반면 메스꺼웠던 **300명 이상은 한 번도 nauseous로 예측되지 않았다.**

### 이진 분류의 네 칸

| | 실제 양성 | 실제 음성 |
|---|---|---|
| **양성 예측** | **TP**(true positive) ✅ | **FP**(false positive) ❌ |
| **음성 예측** | **FN**(false negative) ❌ | **TN**(true negative) ✅ |

레스토랑 예: TP = 아픈 고객을 아플 것으로 예측. **FN = 아픈 고객을 안 아플 것으로 예측**(놓친 경우).

### 지표들

| 지표 | 공식 | 의미 |
|---|---|---|
| **오류율(error rate)** | (FP + FN) / 전체 | 문제가 있는 경우의 비율 |
| **정확도(accuracy)** | (TP + TN) / 전체 | 올바른 예측의 비율 |
| **정밀도(precision)** | TP / (TP + FP) | 양성이라 예측한 것 중 실제 양성 비율 |
| **재현율(recall)** | TP / (TP + FN) | 실제 양성 중 잡아낸 비율 |
| **F1-score** | 정밀도와 재현율의 **조화 평균** | 둘의 균형 |

정밀도와 재현율은 **1에 가까울수록 좋다.**

**계산 예 — 흡연/음주 데이터**

| 트리 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| 분할 전 (모두 young으로 예측) | 0.63 (63%가 실제로 젊어서 죽음) | **1** (아무도 old로 예측 안 하니까) | 0.77 |
| smoker·drinker로 분할 후 | **개선됨** | 약간 감소 (old로 예측했지만 젊어 죽은 2명 때문) | **개선됨** |

> 이것이 두 의사결정 트리를 **객관적으로 비교하는 수단**이다.

### 과대적합과 과소적합

**직관적 예시**: 가장 친한 친구 10명을 두고, **생일과 눈 색깔로 키를 정확히 예측하는** 의사결정 트리를 만든다고 하자. 10명뿐이면 그런 트리를 만들기 쉽고 그 10명에 대해서는 완벽히 작동한다. **그런데 새 친구가 생기면 틀린 값을 낼 가능성이 매우 높다.**

| | 정의 | 예 |
|---|---|---|
| **과대적합(overfitting)** | 모델이 **사용한 데이터셋에 지나치게 특화**돼 새 인스턴스에서 매우 나쁘게 작동한다 | "특정 생일 + 특정 눈 색깔 → 특정 키" |
| **과소적합(underfitting)** | 결론이 너무 일반적이어서 별 말을 하지 않고 **데이터를 실제로 쓰지 않는다** | "남자면 키가 1m보다 크다" — 자주 참이지만 배운 게 없다 |

### 교차 검증(cross-validation)
**기본 형태**: 데이터셋을 **훈련 세트(training set)** 와 **테스트 세트(test set)** 로 나눈다 → 훈련 세트로 학습해 모델(예: 의사결정 트리)을 만든다 → **테스트 세트를 그 모델에 적용** → 성능 측정.

> 핵심은 **보지 않은 데이터(unseen data)로 모델을 테스트**하는 것이다.

**k-겹 교차 검증**: 위 방식은 학습에 모든 데이터를 쓰지 못해 데이터를 최적으로 활용하지 못한다. 그래서 데이터를 **K개로 분할**하고, **K−1개로 학습하고 1개로 테스트**한다. 이 실험을 **K번 반복**하면 모든 데이터를 학습과 테스트 양쪽에 쓰게 된다.

### 평가를 어렵게 하는 것들

**1. 컨셉 드리프트(concept drift)** — 시간이 지나며 **기저 프로세스의 특성 자체가 바뀐다.**

**2. 음성 예시가 없다** — 레스토랑 예에서 우리는 **나중에 불평한 아픈 고객만 안다.** 실제로 불평하지 않은 고객에 대해서는 아무것도 모른다. 음성 예시 없이 **불균형한 집합**으로 학습하는 경우가 흔하다.

> **프로세스 마이닝에서도 이 문제가 상당하다** — 우리는 **일어난 트레이스만 볼 수 있고, 일어날 수 없었던 트레이스는 볼 수 없다.**

### 왜 데이터 마이닝을 먼저 배웠는가
이 코스의 초점은 명확히 프로세스 마이닝이지만, 기본 데이터 마이닝 기법을 먼저 배워야 하는 이유:
- 데이터 마이닝의 **아이디어를 프로세스 마이닝에 차용**할 수 있다
- 프로세스 마이닝 맥락에서 **국소적으로 데이터 마이닝 기법을 쓴다**

예: 프로세스 모델을 학습했고 그 안에 선택(choice)이 있다면, **제어 흐름을 학습한 뒤 의사결정 트리 학습으로 무엇이 그 결정에 영향을 주는지** 볼 수 있다. **단, 프로세스 모델을 먼저 발견해야만 가능하다.**

## 요약
- **혼동 행렬**에서 정밀도·재현율·F1이 나오고, 이것이 두 모델을 객관적으로 비교하는 수단이다.
- **과대적합**(데이터셋에 지나치게 특화)과 **과소적합**(너무 일반적이라 배운 게 없음) 사이의 균형이 목표다.
- **교차 검증**은 보지 않은 데이터로 테스트하는 것이고, **k-겹**으로 하면 모든 데이터를 학습·테스트 양쪽에 활용한다.
- 평가를 어렵게 하는 두 가지: **컨셉 드리프트**와 **음성 예시의 부재**. 후자는 프로세스 마이닝에서도 그대로 문제가 된다 — **일어난 트레이스만 보이고 일어날 수 없었던 트레이스는 안 보인다.**
- 프로세스 마이닝은 프로세스 모델을 전혀 고려하지 않는 고전적 데이터 분석을 훨씬 넘어서며, **고전적 데이터 분석과 고전적 프로세스 분석 사이의 다리**다.
