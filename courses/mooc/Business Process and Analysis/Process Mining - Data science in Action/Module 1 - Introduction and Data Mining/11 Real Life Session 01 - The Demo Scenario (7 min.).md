# Real Life Session 01: The Demo Scenario

## 개요
- Disco를 이용한 8부작 실전 세션의 첫 번째. **구매(purchasing) 프로세스**를 예제로 쓴다.
- 프로세스 마이닝 프로젝트의 **4단계 로드맵**과 **데이터 3요건**을 정리한다.

## 내용

### 시나리오
누군가 새 컴퓨터를 사려고 한다.

1. **요청자**가 돈을 쓸 수 있도록 **관리자 승인**을 받는다
2. 요청이 **구매 부서**로 가고, 최선의 선택지를 찾는다
3. 컴퓨터를 **주문**하고 **공급업체**가 납품한다
4. **송장(invoice)** 이 발송되고 **재무 부서**를 통해 지급된다

단순화를 위해 전 과정이 **하나의 시스템(예: SAP 같은 ERP)** 에서 처리된다고 가정한다.

### 관리자가 가진 세 가지 문제

| 문제 | 내용 |
|---|---|
| **효율** | 프로세스를 더 효율적으로 만들 방법을 찾고 있다. 어떻게 할지는 모르지만 **개선 여지가 있다는 느낌**은 있다 |
| **컴플라이언스** | 프로세스가 **구매 지침을 준수한다는 것을 증명**하라는 요구를 받았다. 그렇다고 생각하지만 **증거**가 필요하다 |
| **소요 시간** | 최근 **너무 오래 걸린다는 불만**을 받았다. 정말 문제인가? **SLA는 21일**이다 |

### 그래서 분석 목표 셋

1. 프로세스가 **실제로 어떻게 생겼는지** 이해한다
2. **지급 지침에서 벗어난 사례**가 있는지 분석한다
3. **성능 목표(21일 이내)** 를 통제한다

### 프로세스 마이닝 프로젝트의 4단계 로드맵

| 단계 | 내용 |
|---|---|
| **1. 스코핑(scoping)** | 질문이 무엇인지, 프로세스가 **어디서 시작하고 어디서 끝나는지**, 어떤 IT 시스템이 관여하는지 이해한다 |
| **2. 데이터 추출** | |
| **3. 데이터 분석** | 프로세스를 분석하고 질문에 답한다 |
| **4. 결과 발표** | |

> 이 시나리오에서는 이미 질문이 있다. **이 세 질문이 프로세스 마이닝 분석을 이끈다.**

### 데이터 요건은 단 세 가지
프로세스 마이닝은 데이터 분석 기법이므로 데이터가 필요하다. **다행히 요건이 정말 단순하다.** IT 시스템에서 **세 가지**만 찾으면 된다.

| 요건 | 뜻 | 예 |
|---|---|---|
| **Case ID** | 프로세스의 **한 번의 실행**을 식별하는 인스턴스 식별자 | 병원 진단·치료 프로세스 → **환자 ID** · 콜센터 → **서비스 요청 번호** · 구매 → **구매 주문 번호** |
| **Activity name** | 프로세스에서 수행된 **단계**. 상태 변경(status change)이나 트랜잭션명이어도 된다 | |
| **Timestamp** | 순서를 잡기 위한 시각. **최소 하나** | |

### 프로세스 마이닝 도구 안에서 벌어지는 일

원시 데이터를 넣으면 도구가:

1. **케이스별로 분리**한다
   - 케이스 1: A(고객 주문) → B(결제) → C(배송)
   - 케이스 2: A → **C → B** — 이미 아는 고객이라 결제 전에 먼저 배송했을 수 있다
   - 케이스 3: 활동 D 주변에 **반복(loop)** — 오류 때문에 송장을 두 번 보냈을 수 있다
2. 이것들이 현실에서 일어나는 **같은 프로세스의 서로 다른 변형(variant)** 이다
3. 도구는 **모든 케이스, 모든 변형에 걸친 프로세스**를 하나로 보여준다
   - 케이스 1만 있으면 단순한 순차 프로세스
   - 케이스 2를 넣으면 **분기 변형**이 나타난다
   - 케이스 3을 넣으면 D 주변의 **작은 루프**가 나타난다

> 원시 데이터에서 **직접 프로세스 시각화를 도출**하고, 그 모델은 **실제로 일어나고 있는 프로세스**를 보여준다. 이것이 핵심이다.

### 실무 팁 — IT 부서에 무엇을 요청할까
보통 **직접 IT 시스템에서 데이터를 추출하지 않고 IT 부서에 도움을 요청**한다. 그러려면 어떤 데이터가 필요한지 말할 수 있어야 한다.

이 구매 프로세스라면 ERP 관리자에게 이렇게 요청한다:
> **구매 주문 번호 · 활동명 · 각 단계의 타임스탬프**를 CSV 파일로 주세요.

## 요약
- 프로세스 마이닝 프로젝트는 **스코핑 → 데이터 추출 → 데이터 분석 → 결과 발표** 4단계다.
- **데이터 요건은 Case ID · Activity · Timestamp 셋뿐**이다. 이 단순함이 프로세스 마이닝을 가볍게 만든다.
- 도구는 케이스를 분리하고, 변형(variant)을 찾아내고, 전체를 하나의 프로세스 맵으로 합친다.
- **분석은 질문에서 시작한다** — 이 예제의 세 질문(실제 모습 / 컴플라이언스 / 21일 SLA)이 이후 세션 전체를 이끈다.
