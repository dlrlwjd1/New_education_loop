# 5.2: Mining Decision Points

## 개요
- **강화(enhancement)** 의 첫 유형인 **확장(extension)** — 모델에 **데이터 관점**을 붙인다.
- **의사결정 지점(decision point)** 에서 왜 어떤 케이스는 왼쪽, 어떤 케이스는 오른쪽으로 가는지 학습한다.
- **정렬(alignment)** 이 전제 조건이고, **의사결정 트리 학습**이 도구다.

## 내용

### 강화의 두 유형

| 유형 | 내용 |
|---|---|
| **확장(extension)** | 이벤트 데이터로 프로세스 모델에 **요소를 추가**한다 |
| **수리(repair)** | 이벤트 데이터로 **기존 모델을 고친다** |

> 둘 다 **새로운 모델을 산출**한다는 공통점이 있다. **적합성 검사와 다르다** — 적합성 검사는 현실과 모델의 맞음새에 대한 **진단을 생성**할 뿐이다.

**확장의 종류**: **가드(guard)와 데이터** 관련 / **시간** 관련 / **자원** 관련. 이 강의는 **데이터**를 다룬다.

### 필요한 것
1. **이벤트 로그**
2. **프로세스 모델** (발견했든 손으로 만들었든)
3. **정렬(alignment)** — 현실에서 본 트레이스를 모델 위에서 재생할 수 있어야 한다

> **정렬 덕분에 완벽히 맞지 않아도(move on model / move on log 문제가 있어도) 현실을 모델에 밀어 넣을 수 있다.** 그래서 이 강의의 나머지에서는 **부적합을 걱정하지 않는다** — 정렬이 처리해 준다.

### 의사결정 지점의 종류

| 표기 | 의사결정 지점 |
|---|---|
| **페트리 넷** | **출력 호가 여러 개인 자리**가 선택을 모델링한다 |
| **BPMN** | **XOR-split 게이트웨이**, **OR-split 게이트웨이**, **이벤트 기반 XOR-split**(지연된 선택) |

**XOR-split** — 두 활동 중 **하나**를 고른다(예: 청구 승인 vs 거절).
**OR-split** — 대안 중 **여러 개를 동시에** 고를 수 있다(예: 항공권만 예약할 수도, 항공권과 호텔을 함께 예약할 수도).

### 가드(guard)의 예
**빨간 케이스**는 `a → (b, c 어떤 순서로든) → d` 경로를 타고 e는 실행하지 않는다. **파란 케이스**는 b, c 대신 **e를 실행**한다.

> 이 정보를 하나의 프로세스 모델에 담으려면 **가드**가 필요하다. 가드는 **빨간 케이스가 타는 경로와 파란 케이스가 타는 경로**를 말해 준다.

### 분류 문제로 만들기
> **의사결정 지점 분석은 데이터 마이닝과 프로세스 마이닝을 결합해야 하는 분석의 예다.**

| 요소 | 내용 |
|---|---|
| **응답 변수(response)** | **b를 골랐는가 c를 골랐는가** |
| **예측 변수(predictor)** | 그 선택의 맥락에서 우리가 아는 모든 것 |

예: **활동 a가 선택 전에 실행됐다** → 선택이 **a를 실행한 사람**에 좌우될 수 있다. 고객 유형, 고객 나이 등도 예측 변수가 된다.

선택이 이뤄진 모든 시점에 대해 **(예측 변수 집합, 응답 변수)** 인스턴스를 만들면 **자연스럽게 의사결정 트리 문제**가 된다.

## 예시 — 가드 학습

**XOR-split**: 데이터를 보면 이런 가드가 나온다.
> **골드 고객이고 청구 금액이 500유로 미만이면 항상 y를 탄다. 나머지 고객은 z를 탄다.**
>
> 확인: **남부 지역의 실버 고객이 500유로 초과를 청구** → z가 실행됐다 → **가드와 일치한다.** ✅

**OR-split**: 이 경우 y만, z만, **또는 둘 다** 가능하다. 학습된 두 가드가 **겹친다(overlapping)** — 그래서 y와 z를 둘 다 타는 경우가 생긴다.
> 확인: **서부 지역 실버 고객이 500유로 미만 청구** → **y와 z가 둘 다 실행**됐다 → BPMN 조각과 일치한다. ✅

### 예측 변수로 무엇을 쓸 수 있나

| 범위 | 내용 |
|---|---|
| **케이스 변수** | 특정 이벤트에 의존하지 않고 **케이스 생애 동안 변하지 않는** 것. 예: 고객이 처음부터 끝까지 골드 고객 |
| **직전 이벤트의 속성** | 선택 직전에 실행된 이벤트 e의 속성 — **누가 e를 실행했는가**, e에 연결된 데이터 |
| **선택 전 모든 이벤트** | 직전만이 아니라 **선택 전에 실행된 모든 이벤트** |
| **미래의 이벤트까지** | 중간의 결정을 **나중의 결과와 연결**할 수 있다 — 이 케이스가 **너무 늦어질까? 거절될까?** |
| **더 넓은 맥락** | **실행 중인 케이스 수**(바쁘면 활동을 건너뛰는 경향?), **자원의 업무 부하**, 가용 자원 수, 심지어 **요일이나 날씨** |

### 주의 — 차원의 저주(curse of dimensionality)
> **변수를 많이 넣을수록 조합이 많아지고, 조합당 관측치가 적어진다.** 데이터가 극도로 희소해지고 **과적합의 위험**이 생긴다. **어떤 변수를 포함할지 신중히 생각해야** 한다.

### 응답 변수를 바꾸면 응용이 훨씬 넓어진다
지금까지 응답 변수는 **다음 활동**이었다. 그런데 대신 이런 것을 넣을 수 있다:
> **남은 처리 시간, 서비스 수준, 비용, 위험, 부정(fraud), 사고(incident)** 등.
>
> 예: 병원에서 **프로세스의 편차가 사고나 더 높은 비용으로 이어지는지** 알고 싶다면, **정확히 같은 원리**로 이해할 수 있다.

## 요약
- **강화 = 확장 + 수리**. 이 강의는 **데이터 관점 확장**이다.
- **전제 조건은 정렬** — 완벽히 맞지 않아도 현실을 모델 경로에 대응시킨다.
- 의사결정 지점을 **분류 문제**로 바꾼다: **응답 변수 = 어느 활동을 골랐나**, **예측 변수 = 그 시점에 아는 모든 것**.
- 예측 변수는 **케이스 속성 → 직전 이벤트 → 이전 모든 이벤트 → 미래 → 맥락(업무량, 요일, 날씨)** 까지 확장 가능하지만 **차원의 저주**를 조심해야 한다.
- **응답 변수를 바꾸면(남은 시간, 비용, 위험, 부정) 같은 기법이 훨씬 넓게 쓰인다.**
