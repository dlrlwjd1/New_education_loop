# 5.1: About the Last Two Weeks of This Course

## 개요
- 앞의 4주는 **제어 흐름(control-flow)** 만 다뤘다. 남은 2주는 **다른 관점들** — 시간, 자원, 데이터.
- 코스의 성격이 바뀐다: **강의가 짧아지고 덜 기술적이며 실무 지향적**이 된다.
- 세 번째 프로세스 마이닝 유형인 **강화(enhancement)** 가 중심이 된다.

## 내용

### 지금까지와 앞으로

| | 지금까지 | 앞으로 |
|---|---|---|
| **유형** | 발견(discovery), 적합성 검사(conformance) | + **강화(enhancement)** — 로그와 초기 모델로 **모델을 수리하거나 풍부하게** 만든다 |
| **관점** | 제어 흐름만 | **시간, 자원, 데이터**까지 |
| **차용 기법** | — | **데이터 마이닝**(의사결정 마이닝), **소셜 네트워크 분석**(자원 행동), **운영 연구**(시뮬레이션, 대기 행렬) |

### 다룰 주제들
- **의사결정 지점 마이닝** — 왜 어떤 케이스는 이 경로로, 다른 케이스는 저 경로로 가는가
- **병목 마이닝** — 병목이 어디에, 왜 있는가
- **소셜 네트워크 마이닝**, 자원 행동 — 누가 함께 일하는가? 사람들은 언제 가장 효율적인가? **일이 많아지면 더 빨리 일하는가?**
- **프로세스 비교** — 골드 고객과 실버 고객의 프로세스 차이는? **통과한 학생과 실패한 학생의 학습 행동 차이는?** → **비교 프로세스 마이닝**
- **운영 지원(operational support)** — 지금까지는 전부 오프라인이었다. **온라인 환경**으로 가서 **편차를 사후가 아니라 발생 시점에 탐지**한다
- **예측** — 특정 케이스의 남은 처리 시간은?
- **권고(recommendation)** — 이력과 현재 상태를 근거로 **다음에 실행할 최선의 활동이나 최적의 담당자**를 추천
- **데이터 추출** — 데이터를 이벤트 로그로 어떻게 바꾸는가
- **로깅 가이드라인** — 새 시스템을 설계한다면 **무엇을 기록해야** 프로세스 마이닝이 가능한가
- **프로세스 마이닝 프로젝트 수행법**

### 라자냐 프로세스 vs 스파게티 프로세스

| | **라자냐(lasagna) 프로세스** | **스파게티(spaghetti) 프로세스** |
|---|---|---|
| 성격 | **구조화된** 프로세스 | **매우 비구조적** |
| 발견의 가치 | 낮다 — **이미 어떻게 생겼는지 안다** | **매우 높다** — 발견 자체가 이미 가치 있다 |
| 관심사 | **어떻게 개선할 것인가** — 병목 분석, 어느 시점에 어떤 자원이 최선인지 | 먼저 **통찰을 제공**해야 한다. 내일 무슨 일이 일어날지 예측하는 건 의미가 없다 |

### 실습 자료 찾기
> 강의가 짧아진 이유는 **소프트웨어(ProM/Disco)와 데이터셋으로 직접 해 볼 시간**을 주기 위해서다. **제공된 데이터셋 너머로 생각해 보라.**

- **processmining.org** — 많은 데이터셋
- **BPI 챌린지** — 실제 이벤트 로그로 하는 대회
- **공개 데이터 마이닝 데이터셋** — 상당수가 어떤 식으로든 이벤트를 기술하므로 **이벤트 로그로 변환** 가능
- **오픈 데이터 운동** — 많은 정부가 시민에게 데이터를 제공하며 새 가능성을 만든다
- **소셜 미디어** — Twitter, Facebook, Google 모두 **오픈 API**를 제공한다

## 요약
- 남은 2주는 **제어 흐름 너머** — 시간·자원·데이터 관점과 **강화(enhancement)**.
- 데이터 마이닝, 소셜 네트워크 분석, 운영 연구의 기법을 프로세스 마이닝과 결합한다.
- **오프라인에서 온라인(운영 지원)** 으로 — 탐지, 예측, 권고.
- **라자냐(구조적) vs 스파게티(비구조적)** 프로세스는 **접근 자체가 달라야** 한다.
- 강의는 짧아지고 **직접 해 보는 것**이 중심이 된다. 데이터는 도처에 있다.
