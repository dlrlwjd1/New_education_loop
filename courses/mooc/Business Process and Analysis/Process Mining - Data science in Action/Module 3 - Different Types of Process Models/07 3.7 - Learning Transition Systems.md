# 3.7: Learning Transition Systems

## 개요
- **영역(region) 기반 발견의 1단계** — 이벤트 로그에서 **전이 시스템**을 만든다.
- 핵심은 **상태(state)를 무엇으로 정의할 것인가** — **과거 / 미래 / 둘 다**, 그리고 **추상화(abstraction)** 의 선택.
- 이 선택이 **일반화 정도를 조절하는 손잡이**가 된다.

## 내용

### 두 단계 접근
1. **이벤트 로그 → 전이 시스템** (이 강의)
2. **전이 시스템 → 페트리 넷** (동시성 탐지, **상태 기반 영역**을 이용, 다음 강의)

> 기본 아이디어: **전이 시스템의 상태 집합 하나가 페트리 넷의 자리 하나에 대응**한다.

### 상태를 어떻게 정의할까
트레이스의 **어떤 위치**(예: e와 f 사이)에서 그 케이스가 어떤 상태에 있다고 할 것인가?

| 기준 | 설명 |
|---|---|
| **과거(past)** | 이전에 일어난 **모든 활동과 그 순서** |
| **미래(future)** | 이상하게 들리지만, **완전한 트레이스**라면 그 위치에서 **미래에 무엇이 일어날지 안다.** 다음 단계는 f, 그다음은 a … |
| **둘 다** | 과거에 일어난 것과 미래에 일어날 것을 결합 |

> 상태를 잡고 나면 **전이를 붙이는 것은 매우 쉽다.**

### 추상화가 필요한 이유
> 추상화를 쓰지 않으면 **상태가 너무 많아지고**, 거의 모든 상태가 유일하거나 매우 드물게만 방문된다.

**추상화의 종류**

| 추상화 | 담는 것 | 잃는 것 |
|---|---|---|
| **없음(전체 시퀀스)** | 순서와 빈도 모두 | — |
| **집합(set)** | 과거에 **일어난 활동들** | **순서와 횟수** (c, d가 두 번 실행된 것을 알 수 없다) |
| **다중집합(multiset)** | 각 활동이 **몇 번 실행됐는지** | **순서** |
| **시간 창 / k-tail** | 최근 **k개 이벤트** (예: k=4 → `d c d e`) | 그 이전 |
| **창 + 집합** | 최근 k개의 활동 종류 | d가 두 번 일어난 것과 순서 |
| **창 + 다중집합** | 최근 k개의 **활동별 횟수** (d 2회, c 1회, e 1회) | 순서 — **같은 다중집합의 다른 순서는 같은 상태로 매핑** |
| **미래 k개** | 다음 k개 이벤트 (순서 무시하면 "다음 두 단계에 a와 f") | 순서 |

### 예시 — 같은 로그, 다른 전이 시스템
로그: `a,b,c,d` / `a,c,b,d` / `a,e,d`

| 추상화 | 결과 |
|---|---|
| **완전한 접두사(prefix)** — 과거, 순서 중요 | **접두사 오토마톤(prefix automaton)**. 빈 접두사 → `a` → `a,b` → … 로 성장. **자주 쓰는 추상화** |
| **미래** | 그 위치에서 앞으로 일어날 이벤트로 상태를 기술 |
| **과거 + 다중집합** | 순서는 모르고 **어떤 활동이 몇 번** 일어났는지만 안다. 상태 `{a,b,c}`는 **b가 먼저인지 c가 먼저인지 구분하지 않고 같은 상태로 매핑** |
| **마지막 이벤트만** | 각 상태를 **마지막에 실행된 이벤트**로 기술. 매우 강한 추상화 |
| **다음 이벤트만** | 각 상태를 **다음 단계가 무엇인지**로 기술. 초기 상태에서는 항상 a |

### 활동 외의 속성 활용
이벤트에는 **자원(resource), 위치, 비용** 등 다른 속성이 있을 수 있고, 전이 시스템을 만들 때 쓸 수 있다.
> 예: **상태가 활동이 아니라 자원(사람)에 대응**할 수 있다. 전이의 레이블도 활동이 아니라 **자원이나 고객 유형**일 수 있다.

### 후처리(post-processing)

| 기법 | 목적 | 주의 |
|---|---|---|
| **드문 경로·활동 가지치기** | 노이즈 제거 | 로그를 전이 시스템 위에서 재생하고 자주 안 가는 경로를 뺀다 |
| **셀프 루프 제거** | 가독성 | **적합도를 해칠 수 있다.** 이전에 완벽히 맞던 로그가 더는 안 맞을 수 있다 |
| **다이아몬드 구조 개선** | **나중에 동시성을 발견할 수 있게** | a와 b 중 선택이 있는데 a를 한 뒤에도 b를 할 수 있다면, **a와 b가 동시적인데 `b 다음 a` 인터리빙을 못 봤을 뿐**이라고 가정하는 것이 합리적이다 |
| **입력이 비슷한 상태 병합 / 출력이 비슷한 상태 병합** | **과적합 방지** | 행동을 일반화하는 방법들 |

### ProM에서
로그를 가져와 전이 시스템을 만들 수 있고, 위에서 말한 **모든 설정 선택**이 실제로 가능하다. 대부분의 파라미터에서 **결과 전이 시스템이 로그를 처음부터 끝까지 재생할 수 있음이 보장**된다.

## 요약
- 영역 기반 발견의 1단계는 **로그 → 전이 시스템**이고, 핵심 선택은 **상태의 정의**다.
- 상태는 **과거 · 미래 · 둘 다**로 정의할 수 있고, **집합 / 다중집합 / 시퀀스** 추상화와 **시간 창(k-tail)** 을 조합한다.
- 가장 흔한 것은 **접두사 오토마톤**(과거 전체 시퀀스)이지만, **추상화를 강하게 할수록 상태가 줄고 일반화된다.**
- **활동이 아닌 속성**(자원 등)으로도 상태와 전이를 정의할 수 있다.
- 후처리로 **가지치기, 셀프 루프 제거, 다이아몬드 구조 개선, 상태 병합**을 하는데, **다이아몬드 구조 개선은 다음 단계의 동시성 발견을 돕는다.**
