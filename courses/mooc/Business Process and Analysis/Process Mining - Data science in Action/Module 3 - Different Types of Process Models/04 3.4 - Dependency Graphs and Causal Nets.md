# 3.4: Dependency Graphs and Causal Nets

## 개요
- **휴리스틱 마이너(Heuristic Miner)** 가 기반으로 쓰는 두 표현을 다룬다.
- **의존 그래프(dependency graph)** — 실행 의미론이 없는, 인과성만 담은 그래프.
- **인과 넷(causal net, C-net)** — 의존 그래프 + **입력·출력 바인딩**. **선언적 의미론**을 갖는다.

## 내용

### 의존 그래프
> 노드 = 활동, 호(arc) = **인과 의존성**. 인과 의존성이란 **방향이 있는 관계로, 하나가 다른 하나를 촉발하거나 활성화**하는 것이다. 호에는 **빈도**나 **신뢰도**(그 인과가 얼마나 확실한지)를 나타내는 숫자가 붙는다.

**만들 때의 도전**: **동시성을 다뤄야 한다.** 활동은 여러 방식으로 인터리브될 수 있는데, **그것이 인과적 의존을 뜻하지는 않는다.**

**실행 의미론이 없다**:
> 페트리 넷처럼 "이 모델에 따라 가능한 트레이스 집합이 명확히 정해진다"가 아니다. **들어오고 나가는 호가 여럿이어도 AND인지 XOR인지 명확한 의미가 없다.** 입력·출력 행동을 **명확한 의미론 없는 OR-join/OR-split의 퍼지한 버전**으로 생각하면 된다. 어떤 때는 입력 하나, 어떤 때는 둘이 필요하다. **매우 느슨하게 해석한다.**

**다른 표현과의 관계**:
| 출발 | 의존 그래프로 |
|---|---|
| **인과 발자국(causal footprint)** | 행렬의 **화살표가 곧 의존 그래프의 호** |
| **페트리 넷** | **자리(place)를 모두 제거하고** 활동을 직접 연결하면 의존 그래프가 된다. 대신 **의미론을 많이 잃는다** |

**왜 중요한가**: 온갖 마이닝 알고리즘이 **이 표현에서 출발**한다. 첫 단계로 쓰거나 최종 산출물로 보여준다.
> **Disco의 퍼지 모델도 의존 그래프로 생각할 수 있다.** 정확한 의미론이 없고, 만드는 방법이 여러 가지이며 **대개 휴리스틱에 기반**한다.

### 인과 넷(C-net)
> C-net = **의존 그래프에 입력·출력 바인딩을 주석으로 붙인 것**. 실행 의미론을 부여하지 않으면서 **가능성을 스케치**한다.

**왜 C-net을 쓰는가**:
- **노이즈와 고급 개념을 다룰 수 있는 많은 프로세스 마이닝 알고리즘이 C-net과 매우 유사한 표현을 쓴다.** 대표적으로 **휴리스틱 마이너**
- 주류 언어와 잘 맞는다 — 페트리 넷이나 전이 시스템보다 **OR와 AND를 더 풍부하게** 이야기한다
- **XOR, AND, 그리고 무엇보다 OR를 모델링**할 수 있으면서 **묵음 전이나 중복 전이 같은 추가 요소가 필요 없다**
- **건전하지 않은 모델을 피하기 위해** 쓴다 — 의미론이 **교착을 만들지 않도록** 돼 있다

**느슨한 의미론**:
> **선택의 순간이 고정되지 않는다.** 그저 **사후에** 본다 — "이 트레이스가 이 모델에 맞는가? 이 모델에 따른 가능한 설명이 있는가?"

### 바인딩의 규칙 — 의무(obligation)로 이해하기

**핵심 직관**: **출력 바인딩은 의무를 만들고, 입력 바인딩은 의무를 제거한다.** 의무는 **토큰과 같다.**

한 번의 실행 예:
1. 시작 활동 **a**는 **첫 위치에서만** 일어날 수 있다. a에 출력 바인딩이 둘 있다면 — `{b, d}` 또는 `{c, d}` — 하나를 고른다
2. `{b, d}`를 골랐다면 **미래에 b와 d가 일어나야 한다는 의무**가 생긴다
3. **b가 일어나면** a→b 의무가 제거되고, **b→e 의무가 생긴다**
4. **d가 일어나면** 들어오는 쪽 의무를 제거하고 나가는 쪽 의무를 만든다
5. **e를 실행하면 의무 두 개를 제거**한다 — **AND-join 같지만 들어오는 세 호 전부가 아니라 둘에서만** 제거한다. **OR로 생각하면 된다**
6. 마지막에 **끝 활동**을 실행하고 의무를 제거한다

**게임의 규칙**:
| 규칙 |
|---|
| 항상 **시작 활동**으로 시작하고 **한 번만** 일어난다 |
| 끝에는 항상 **지정된 끝 활동**이 있다 |
| 중간 활동은 시작·끝 활동일 수 없다 |
| **의무는 토큰과 같다** — 입력 바인딩이 소비하려면 있어야 한다 |
| **끝에 남은 의무가 없어야** 한다 |
| **선택의 순간은 고정되지 않는다.** 사후에 이 성질들을 만족하는 설명을 찾으면 된다 |

**바인딩 조합**: 활동 x에 입력 바인딩 2개, 출력 바인딩 3개가 있으면 → **가능한 바인딩은 2 × 3 = 6개.**

> **유효한 바인딩 시퀀스(valid binding sequence)** 만 고려한다 — 처음부터 끝까지 가고, 입력 바인딩을 택할 때마다 **의무가 모두 존재**하며, 끝에는 **남은 의무가 없는** 실행. **이렇게 해서 교착 이야기를 아예 피한다.**

### 워크플로 넷과의 관계
**변환**: C-net → 페트리 넷은 간단하다. **모든 출력 바인딩과 입력 바인딩을 묵음(silent) 전이로 바꾸고**, 한 전이의 출력 바인딩과 다른 전이의 입력 바인딩을 잇는 **자리를 추가**한다.

| 방향 | 관계 |
|---|---|
| C-net → 워크플로 넷 | 모든 **유효 바인딩 시퀀스**는 초기 마킹에서 최종 마킹으로 가는 **유효 발화 시퀀스**에 대응 |
| 워크플로 넷 → C-net | 초기에서 최종까지 가는 모든 실행은 유효 바인딩 시퀀스에 대응. **그러나 워크플로 넷에는 교착에 빠지거나 최종 상태에 도달하지 못해 유효 바인딩 시퀀스에 대응하지 않는 실행이 많을 수 있다** |

> **워크플로 넷은 건전할 필요가 있지만, C-net에는 그런 건전성이 요구되지 않는다** — **선언적 의미론만** 쓰기 때문이다.

### C-net의 표현력
> C-net은 **의미론 해석이 다르다는 것만으로 놀랍게 표현력이 높다.**
>
> 예: **b, c, d가 무한히 많은 횟수 일어날 수 있는데(백만 번도 가능)**, 모델이 **모두 정확히 같은 횟수로 일어나도록** 보장하고 **순서도 보존**한다. b를 4번 했으면 c를 5번 먼저 할 수 없다. **이것은 고전적 페트리 넷으로 표현할 수 없다.**

## 요약
- **의존 그래프** = 노드(활동) + 호(인과 의존성) + 숫자(빈도·신뢰도). **실행 의미론이 없다.** Disco의 퍼지 모델이 여기 해당한다.
- **C-net** = 의존 그래프 + **입력·출력 바인딩**. **묵음·중복 전이 없이도** XOR/AND/**OR**를 표현한다.
- 핵심 직관: **출력 바인딩이 의무를 만들고 입력 바인딩이 의무를 제거한다.** 의무는 토큰과 같고 **끝에 남으면 안 된다.**
- **유효 바인딩 시퀀스만 고려**하므로 **교착을 아예 논하지 않는다** — 발견 기법이 계속 나쁜 모델을 만들어내는 것을 피하기 위한 설계다.
- C-net은 **선언적 의미론** 덕에 페트리 넷으로 표현 불가능한 행동(예: 여러 활동이 정확히 같은 횟수)도 표현한다.
