# 2.6: Alpha Algorithm — A Process Discovery Algorithm

## 개요
- 이 코스 최초의 구체적 발견 기법 **알파 알고리즘(Alpha algorithm)**.
- **동시성을 발견할 수 있었던 최초의 알고리즘** 중 하나.
- 핵심은 **네 가지 순서 관계**와 **발자국(footprint) 행렬**, 그리고 **8줄짜리 알고리즘**.

## 내용

### 입력 — 무엇을 버리고 무엇을 쓰는가
알파 알고리즘은 **제어 흐름만** 본다. 따라서 **버리는 것**:
- 자원(resource)과 기타 데이터 요소
- 이벤트가 일어난 **실제 타임스탬프** — **순서만** 신경 쓴다
- 케이스 ID와 케이스 속성

남는 것은 **케이스 안의 활동 순서**뿐이다. 그래서 이벤트 로그를 **트레이스의 다중집합(multiset)** 으로 변환한다.

> 이벤트 로그 = **트레이스의 다중집합**(같은 트레이스가 여러 번 나올 수 있으므로). 트레이스 = **활동명의 시퀀스**.

예: 로그 L1은 6개 트레이스를 담고, `a, b, c, d` 시퀀스가 **3번** 실행됐다.

### 네 가지 순서 관계

| 관계 | 기호 | 정의 |
|---|---|---|
| **직접 후속(direct succession)** | x > y | x 다음에 y가 **바로 온 케이스가 최소 하나** 있다 |
| **인과(causality)** | x → y | **x > y이고 y > x가 아니다** — x 다음에 y가 오지만 y 다음에 x는 절대 안 온다 |
| **병렬(parallel)** | x ‖ y | **x > y이고 y > x** — 양방향으로 직접 후속이 성립 |
| **선택(choice)** | x # y | **x > y도 아니고 y > x도 아니다** — 서로 절대 직접 뒤따르지 않는다 |

### 관계에서 패턴으로

| 관찰한 관계 | 학습하는 페트리 넷 패턴 |
|---|---|
| a → b | **순차(sequence)** |
| a → b, a → c, **b # c** | **XOR-split** — a 다음에 b 또는 c 중 선택 |
| b → d, c → d, **b # c** | **XOR-join** |
| a → b, a → c, **b ‖ c** | **AND-split** — a 다음에 b와 c를 어떤 순서로든 |
| b → d, c → d, **b ‖ c** | **AND-join** |

> 이 패턴들 위에서 토큰 게임을 재생해 보면 **실제로 그런 관계가 성립함**을 확인할 수 있다.

### 발자국(footprint) 행렬
이벤트 로그에서 **모든 활동 쌍에 대해 네 관계 중 하나**를 채운 행렬이다. **가능한 것은 이 넷뿐**이다 — 한 방향 인과, 반대 방향 인과, 서로 안 따름(#), 양방향(‖).

> **핵심 관찰**: 이벤트 로그의 발자국과 발견된 프로세스 모델의 발자국이 **정확히 같다.** 모델의 모든 가능한 트레이스로 발자국을 만들어도 같은 행렬이 나온다. **모델과 로그가 행동 관점에서 공통점을 갖는다는 뜻**이고, 이것이 알파 알고리즘의 출발점이다.

## 예시 — 8줄 알고리즘

> **8줄뿐인데 처음 보면 무섭게 생겼다.** 그런데 이렇게 단순한 알고리즘으로 **동시성, 루프, 선택을 가진 광범위한 프로세스를 발견할 수 있다는 것이 놀랍다.**

| 줄 | 하는 일 |
|---|---|
| **1** | 로그를 훑어 **등장하는 활동 집합 T**를 찾는다 (각각이 전이가 된다) |
| **2** | **T_I** — 트레이스의 **첫 위치**에 오는 활동들 (초기 전이) |
| **3** | **T_O** — 트레이스의 **끝**에 오는 활동들 (최종 활동) |
| **4** | **핵심 단계 — 자리(place) 발견.** 아래 참조 |
| **5** | X 중 **극대(maximal)** 인 것만 남겨 **Y**를 만든다 |
| **6** | **PL**(자리 집합) = Y의 극대 쌍들 + **초기 자리 I** + **최종 자리 O** |
| **7** | **호(arc)** 를 만든다 — I에서 모든 T_I로, 모든 T_O에서 O로, 그리고 내부 자리들의 A·B 연결 |
| **8** | 자리 P, 전이 T, 호 F를 가진 **페트리 넷을 반환** |

**4번 줄의 직관** — 두 활동 집합 **A**와 **B**를 찾는데:
1. **A 안의 두 활동은 서로 절대 뒤따르지 않는다**(자기 자신도 포함)
2. **B 안의 두 활동도 서로 절대 뒤따르지 않는다**
3. **A의 임의의 원소와 B의 임의의 원소 사이에는 항상 인과 관계가 있다** — 로그에 A의 원소 다음에 B의 원소가 오는 위치가 최소 하나 있어야 하고, **모든 조합에 대해** 그래야 한다

> **프로세스 발견을 페트리 넷으로 생각하면 결국 자리를 발견하는 일이 전부다.** A는 그 자리의 **입력 전이**, B는 **출력 전이**가 된다.

**5번 줄이 필요한 이유** — A와 B에서 노드나 호를 **제거해도 위 성질이 그대로 성립**한다. 즉 **A·B 관계의 어떤 부분집합도 자동으로 요건을 만족**한다. 그러면 **자리가 너무 많이 생긴다.** 그래서 **극대인 것만 남긴다.**

> 진짜 흥미로운 부분은 **4번과 5번**이다. 나머지는 이미 찾은 전이와 자리를 연결하는 단순한 일이다.

## 요약
- 알파 알고리즘은 **동시성을 발견할 수 있었던 최초의 알고리즘** 중 하나다.
- 입력은 **활동 순서만** — 타임스탬프의 실제 값, 자원, 케이스 속성은 모두 버린다.
- 네 관계: **직접 후속(>) · 인과(→) · 병렬(‖) · 선택(#)**. 이것이 **발자국 행렬**을 만든다.
- **로그의 발자국과 모델의 발자국이 일치**하는 것이 이 알고리즘의 근거다.
- 알고리즘의 본질은 **4~5번 줄** — 조건을 만족하는 **극대 집합 쌍 (A, B)** 를 찾아 그것을 **자리**로 삼는다.
- 발견 품질에는 네 가지 경쟁하는 기준이 있지만(비행기를 띄우려면 여러 힘이 필요한 것처럼), **이 강의는 적합도(fitness) — 관찰된 행동을 재생하는 능력 — 에만 집중**한다. 나머지는 뒤에서 다룬다.
