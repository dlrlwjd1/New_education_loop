# 2.5: Workflow Nets and Soundness

## 개요
- **워크플로 넷(WorkFlow net)** = 시작 자리와 끝 자리가 명확한 페트리 넷.
- **건전성(soundness)** 의 네 가지 조건이 이 강의의 핵심이다.
- BPM(비즈니스 프로세스 관리)의 맥락과, **모델 기반 분석의 근본적 한계**.

## 내용

### BPM 배경
> **BPM = IT와 경영과학을 잇는 연결 고리.** 주 목적은 **효율**이다.

역사:
- **18세기 Adam Smith** — **분업(division of labor)** 으로 프로세스를 더 효율적이고 저렴하게
- **Taylor** — 과학적 관리(scientific management)
- **Henry Ford** — 대량 생산(T형 포드)
- **1950년대** — 정보 시스템과 컴퓨터가 보편화되며 가장 큰 돌파구
- **현재** — 막대한 데이터가 있다. **데이터가 새로운 석유**인 다음 단계로 BPM을 끌어올릴 수 있다

**BPM 생애주기**: 설계/재설계 → 정보 시스템 구현·구성 → 실행(필요하면 즉석 조정) → 다시 설계.
- **모델 기반 분석**은 주로 **설계/재설계** 단계에서 쓴다
- **프로세스 마이닝**은 **프로세스가 실행되는 동안 배우는 것**에 초점을 둔다

**프로세스 모델의 용도**: 책임과 병목을 논의 · 컴플라이언스 분석 · 시뮬레이션으로 미래 문제 예측 · **정보 시스템 구성**(워크플로/BPM 기술).

### 언어는 많지만 차이는 작다
**바벨탑** 그림으로 표현한다 — 언어가 너무 많아 혼란스럽다.

| 표기법 | 맥락 |
|---|---|
| **BPMN**(Business Process Model and Notation) | 가장 널리 쓰인다 |
| **EPC**(Event-Driven Process Chain) | **SAP** 같은 시스템에서 쓰는 표기 |
| **페트리 넷 / 워크플로 넷** | 이 코스의 중심 |

> **표현은 달라 보이지만 모두 같은 현상을 표현하려 하고, 결국 모두 이벤트의 트레이스를 생성한다.** 이 코스에서 여러 언어를 보겠지만 **언어 간 차이는 미미하다. 모두 같은 개념에 기반한다.**

### 워크플로 넷의 정의
> **워크플로 넷** = **시작 자리 하나, 끝 자리 하나**를 갖고, **모든 전이와 자리가 시작에서 끝까지의 경로 위에 있는** 페트리 넷.

로그의 트레이스는 **초기 상태에서 최종 상태까지** 가야 한다. 프로세스 마이닝뿐 아니라 **워크플로 관리와 BPM 영역에서 널리 쓰이는** 모델 클래스다.

### 나쁜 모델의 예들

| 문제 | 내용 |
|---|---|
| **교착 가능** | 루프를 돌아 나오면 c3에만 토큰이 남는 상태 = 교착에 빠질 수 있다 |
| **AND-split에 대응하는 AND-join이 없음** | 도달가능성 그래프를 그리면 기대한 행동이 아니다 |
| **죽은(dead) 전이** | `pay compensation` 전이가 **절대 발화할 수 없다.** 두 입력 자리가 동시에 마킹되는 상태에 도달할 수 없다 |

### 건전성(soundness)의 네 조건
> **워크플로 넷이 건전(sound)하다 ⟺ 다음 네 성질이 모두 성립한다.**

| # | 성질 | 내용 |
|---|---|---|
| 1 | **안전성(safeness)** | 어느 시점에도 자리에 토큰이 **최대 하나** |
| 2 | **적절한 완료(proper completion)** | 끝 자리에 토큰을 놓는 순간 **다른 모든 자리는 비어 있어야** 한다 |
| 3 | **완료 가능성(option to complete)** | 무엇을 하든, **끝 자리에만 토큰이 있는 마킹에 항상 도달할 수 있어야** 한다 |
| 4 | **죽은 부분 없음(no dead parts)** | 프로세스 모델의 **모든 부분이 잠재적으로 활성화**될 수 있어야 한다 |

> 이 넷이 어떤 워크플로 넷이든 만족해야 할 **최소 요건**이다.

### 조건들 사이의 논리적 관계

> **완료 가능성(3)은 적절한 완료(2)를 함의한다.**

이유: 적절한 완료가 성립하지 않는다는 것은 최종 자리에 토큰이 있는데 프로세스 안에 무언가 남아 있다는 뜻이다. 그런데 **중간에 남은 토큰이 사라지는 유일한 방법은 최종 자리로 가는 것**인데, 그러면 최종 자리에 토큰이 **두 개**가 된다. 따라서 완료 가능성도 성립하지 않는다.

> 즉 **모델을 검사할 때 적절한 완료는 볼 필요가 없다.** 자동으로 성립한다.

### 앞선 성질들과의 연결 — 단락(short-circuit)
워크플로 넷의 **끝에서 시작으로 전이를 추가**해 순환시킨다. 이것을 **단락 워크플로 넷(short-circuited WorkFlow net)** 이라 한다.

> **워크플로 넷이 건전하다 ⟺ 대응하는 단락 페트리 넷이 활성(live)이고 유계(bounded)이다.**

안전성(첫 번째 조건)까지 원하면 **안전**해야 한다. 유계성만으로도 **나머지 세 성질에는 충분**하다.

### 모델 기반 분석의 근본적 한계

**두 가지 주요 분석 유형**:
- **검증(verification)** — 방금 논의한 건전성 검사 같은 것
- **성능 분석** — 시뮬레이션, 마르코프 분석 등

> **그런데 모델만 보는 것으로는 충분하지 않다.** 이 모든 분석 기법은 **모델의 품질에 의존**한다. **모델이 현실을 제대로 표현하지 못하면 어떤 분석 결과도 가치가 없다.**
>
> 실무에서는 **사람이 손으로 만든 모델이 현실과 잘 맞지 않는 경우가 흔해** 결론을 매우 신뢰하기 어렵다.
>
> **프로세스 마이닝은 모델과 실제 이벤트 데이터 사이에 매우 긴밀한 연결을 만들어** 이 문제를 해결하려는 것이다.

## 요약
- **워크플로 넷** = 시작 자리 하나 + 끝 자리 하나 + 모든 노드가 그 경로 위에 있는 페트리 넷.
- **건전성의 네 조건**: 안전성 · 적절한 완료 · **완료 가능성** · 죽은 부분 없음. 이 중 **완료 가능성이 적절한 완료를 함의**하므로 실제로 확인할 것은 셋이다.
- **단락 넷이 활성이고 유계 ⟺ 원래 워크플로 넷이 건전** — 앞 강의의 성질들과 정확히 연결된다.
- **이 강의의 결론**: 모델 기반 분석(검증, 시뮬레이션)은 **모델의 품질에 전적으로 의존**한다. 손으로 만든 모델은 현실과 어긋나기 쉽고, **그래서 프로세스 마이닝이 필요하다.**
- 다음 강의부터 실제 발견 알고리즘인 **알파 알고리즘**을 다룬다 — 이벤트 로그에서 **워크플로 넷을 발견**하는 것이 목표다.
