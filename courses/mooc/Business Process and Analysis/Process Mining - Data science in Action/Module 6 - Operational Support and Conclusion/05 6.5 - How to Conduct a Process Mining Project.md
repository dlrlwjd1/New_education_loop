# 6.5: How to Conduct a Process Mining Project

## 개요
- 프로세스 마이닝 프로젝트의 단계를 정의한 **L* 생애주기 모델(L\* lifecycle model)**.
- 프로젝트를 **유스 케이스의 모음**으로 보는 관점 — **목표 + 행동(action)**.
- 세 가지 프로젝트 유형: **데이터 주도 · 질문 주도 · 목표 주도**.

## 내용

### 유스 케이스 = 목표 + 행동

**목표(goal)** — 대개 **KPI를 개선**하려는 것이다(시간, 비용, 위험, 품질 …).
> 시간에 집중한다면: **평균 처리 시간·대기 시간·응답 시간 최소화**. 또는 평균이 아니라 **서비스 수준(합의된 기간 내 처리 비율) 최대화**.

**행동(action)** — **분석 자체를 위해 프로세스 마이닝을 하는 것이 아니다.** **실행 가능한(actionable) 정보**, 즉 **실제로 프로세스를 개선하는 데 쓸 수 있는 정보**를 원한다.

| 행동 수준 | 내용 |
|---|---|
| **재설계(redesign)** | 통찰에 기반한 프로세스의 **구조적 변경** |
| **조정(adjustment)** | **비구조적 변경** — 파라미터 변경 등. 예: **케이스 물량이 변동하면 일시적으로 자원을 몇 명 추가** |
| **개입(intervene)** | **개별 케이스나 개별 자원 수준**에서 개입 |
| **운영 지원** | 가장 정교한 형태 — **현재 이벤트 데이터로 특정 시점의 최선의 활동이나 자원을 체계적으로 권고** |

예시 유스 케이스: **"처리 시간을 30% 줄이려면 프로세스에서 무엇을 바꿔야 하는가?"**

### L* 생애주기 모델
> 프로세스 마이닝 프로젝트의 여러 단계를 기술하는 모델. **이상적인 프로세스 마이닝 프로젝트**를 그린 것이고, **라자냐 프로세스(고도로 구조화된 프로세스)** 를 겨냥한다.
>
> 데이터 마이닝·BI 맥락의 기존 생애주기 모델(**CRISP-DM, SEMMA**)과 관련 있지만, 그것들은 **프로세스 마이닝 특화가 아니고 상당히 고수준**이다. **L*는 훨씬 상세하고 프로세스 마이닝의 필요에 맞춰져 있다.**

| 단계 | 이름 | 내용 |
|---|---|---|
| **0** | **계획과 정당화(plan and justify)** | 분석을 정당화할 **비즈니스 케이스**를 갖는 것이 결정적일 때가 많다 |
| **1** | **데이터 추출** | 이벤트 데이터를 **찾고, 추출하고, 변환**한다. **비자명한 과제**다. 이벤트 데이터만이 아니라 **기존 모델**(규범적 모델과 적합성 검사를 하려면 미리 수집해야 한다)과 **다른 유용한 산출물**도 모은다. **목표와 답하고 싶은 질문**을 생각하고, **사람들 머릿속의 도메인 지식을 최대한 활용**한다 |
| **2** | **제어 흐름 모델 생성 + 로그 연결** | **제어 흐름이 모든 프로세스의 중추**다. 적합한 제어 흐름 모델을 만들고 **정렬(alignment)** 로 이벤트 데이터에 연결한다. **매우 반복적(iterative)** 이며, 이 단계는 특히 **여러 번의 반복**이 필요하다 |
| **3** | **다른 관점으로 확장** | 이벤트 데이터를 모델 위에서 재생하고 **다른 관점으로 모델을 확장**한다. 결과는 **모든 관점을 담은 통합 모델** |
| **4** | **운영 지원** | 이력이 아니라 **실시간·온라인**으로 쓴다 — **탐지, 예측, 권고**. **단, 라자냐 프로세스에서만 도달 가능하다** — 반복적이고 안정적 구조를 가진 프로세스여야 한다 |

### 세 가지 프로젝트 유형
> **시작 전에 이 맥락적 요인을 보고 이해하는 것이 매우 중요하다.**

| 유형 | 동기 |
|---|---|
| **데이터 주도(data-driven)** | **데이터의 가용성**이 이끈다. "데이터가 넘쳐나는데 뭘 해야 할지 모르겠다. 다만 우리가 가진 정보에 가치가 있고 아직 활용하지 못한다고 확신한다" |
| **질문 주도(question-driven)** | 프로세스의 **특정 영역에 왜 문제가 있는지 이해**하고 싶다 |
| **목표 주도(goal-driven)** | 단순히 **특정 KPI를 개선**하는 것이 목표다 |

### 정교화된 프레임워크와의 연결

| L* 단계 | 대응하는 프로세스 마이닝 활동 |
|---|---|
| **단계 2** | **discover, check(적합성 검사), compare, promote, explore** |
| **단계 3** | **enhance** — 로그를 모델 위에서 재생해 모델을 확장 |
| **단계 4** | **predict, recommend, detect** |

## 요약
- 프로세스 마이닝 프로젝트 = **목표(KPI 개선) + 행동(재설계·조정·개입·운영 지원)** 으로 이뤄진 유스 케이스의 모음.
- **L* 생애주기 5단계**: **0 계획·정당화 → 1 데이터 추출 → 2 제어 흐름 + 정렬 → 3 다른 관점 확장 → 4 운영 지원**.
- **매우 반복적**이다 — 나중 단계의 통찰이 앞 단계의 변경으로 이어질 수 있다.
- **단계 4(운영 지원)는 라자냐 프로세스에서만 도달 가능**하다.
- 프로젝트 유형(**데이터 주도 / 질문 주도 / 목표 주도**)을 시작 전에 파악해야 한다.
- **가장 중요한 두 가지**: ① **필요한 이벤트 데이터를 확보**할 것 ② **비즈니스 케이스를 항상 생각할 것** — **분석 자체가 목표가 아니다.**
