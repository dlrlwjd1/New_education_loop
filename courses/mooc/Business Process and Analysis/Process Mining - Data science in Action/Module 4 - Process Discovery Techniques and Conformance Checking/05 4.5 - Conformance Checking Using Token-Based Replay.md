# 4.5: Conformance Checking Using Token-Based Replay

## 개요
- 적합성 검사 기법 2 — **토큰 기반 재생(token-based replay)**.
- **누락 토큰(missing)** 과 **잔여 토큰(remaining)** 을 세어 **0~1 사이의 적합도**를 계산한다.
- 발자국과 달리 **실제 행동과 빈도를 본다.**

## 내용

### 왜 트레이스 단위 판정으로는 부족한가
트레이스 `a b e g`가 모델에 맞지 않는다고 하자.
> **완전한 트레이스 수준**에서만 적합도를 보면 이 트레이스의 적합도는 **0**이다. 그런데 이런 답은 별로 쓸모없다.
>
> **긴 트레이스**를 다루면 **어떤 트레이스도 맞지 않는 로그**가 생길 수 있고, 그러면 적합도가 0이 나오는데 이는 **매우 오해를 부르는 숫자**다.
>
> 그래서 **이벤트 수준**에서 — **맞는 이벤트의 비율과 맞지 않는 이벤트의 비율** — 을 봐야 한다.

### 네 개의 카운터

| 카운터 | 뜻 |
|---|---|
| **p** (produced) | 생산된 토큰 수 |
| **c** (consumed) | 소비된 토큰 수 |
| **m** (missing) | **없는데 소비된** 토큰 — 강제로 추가해야 했던 것 |
| **r** (remaining) | 끝에 **소비되지 않고 남은** 토큰 |

**불변식(invariant)**:
- 재생 중 자리의 토큰 수 = **p + m − c** 이고 **항상 양수**여야 한다(음수 토큰은 없으므로)
- 따라서 **p + m ≥ c**
- **c ≥ m** — 소비에 필요하지 않으면 누락 토큰을 추가하지 않으므로
- 끝에 **r = p + m − c**

> 이 수식들은 **개별 자리 수준에서도, 프로세스 모델의 모든 자리 수준에서도** 성립한다.

### 시작과 끝의 특별 처리
> **시작**: 환경(environment)이 **소스 자리에 토큰을 생산**해야 한다.
> **끝**: 환경이 **싱크 자리에서 토큰을 소비**해야 한다.
>
> **중요**: 트레이스 끝에 최종 자리에 토큰이 없어도 **소비는 해야 한다.** 없으면 **누락 토큰이 하나 추가**된다. 이렇게 해서 **트레이스가 원하는 최종 상태에서 끝났는지**를 실제로 검사한다.

### 적합도 공식
```
fitness = ½ · (1 − m/c) + ½ · (1 − r/p)
```
- **0** = 가능한 최악, **1** = 완벽 (문제없이 재생됨)

## 예시 — 손으로 계산하기

**예 1 — 완벽히 맞는 트레이스**
1. 환경이 소스 자리에 토큰 생산 → **p = 1**
2. **a** 실행 → 토큰 1 소비, 2 생산 → p = 3
3. **c** 실행 → 1 소비, 1 생산
4. **d** 실행 → 1 소비, 1 생산
5. **e** 실행 → **2 소비, 1 생산** → c = 5
6. **h** 실행 → end 자리에 토큰
7. 환경이 그 토큰을 소비

**결과**: p = 7, c = 7, m = 0, r = 0 → **적합도 = 1** ✅

**예 2 — 맞지 않는 트레이스** (a 다음에 d가 오는데 모델상 b나 c가 먼저여야 함)
1. 환경이 생산 → p = 1
2. **a** 실행 → 소비 1, 생산 2
3. **d** — **불가능하다.** **누락 토큰 기록 → m = 1**, 토큰을 추가하고 진행 (p = 3, c = 2)
4. **c** 실행 → 소비 1, 생산 1
5. **e** 실행 → 소비 1, 생산 1
6. **h** 실행 → 소비 1, 생산 1
7. 환경이 최종 자리 토큰 소비 (토큰이 있으므로 문제없음) → p = c = 6
8. **p2에 토큰이 남아 있다 → r = 1**

**결과**: p = 6, c = 6, m = 1, r = 1 → **적합도 = 0.83**

**예 3 — 앞서 본 `a b e g`**: 생산 6, 소비 6, 누락 1, 잔여 1 → **0.83**

### 로그 전체로 확장
> 개별 트레이스의 m, c, r, p를 **모든 트레이스에 걸쳐 합산**한다. **같은 트레이스가 여러 번 나올 수 있으므로(다중집합)** 빈도를 곱해 합한다. 공식은 인상적으로 보이지만 **개별 트레이스와 똑같은 것을 로그 수준으로 올린 것**뿐이다.

### 네 모델 비교 — 발자국과 다른 결과

| 모델 | 재생 적합도 |
|---|---|
| 알파 알고리즘 결과 | **1** |
| 모델 2 | 0.95 |
| 모델 3 | (더 낮음) |
| **꽃 모델** | **1** |

> **꽃 모델의 적합도가 1이다.** 너무 일반적이지만 **적합도 관점에서는 문제없다** — 본 모든 행동을 허용하기 때문이다.
> **이 모델이 로그를 잘 표현하지 못한다는 사실을 담으려면 정밀도(precision)를 봐야 한다.**

### 상세 진단
재생을 통해 **정교하고 상세한 진단**을 얻는다.
- 활동(페트리 넷의 전이)이 **몇 번 실행됐는지**
- **특정 호를 토큰이 몇 번 흘렀는지**
- 예: 모델 2의 진단은 **b, c와 d의 순서에 문제**가 있음을 보여준다. **c와 b가 d와 동시적이어야 하는데 순차로 돼 있어**, **d가 b나 c보다 먼저 일어난 모든 트레이스가 잘 맞지 않는다**

## 요약
- **토큰 기반 재생**은 **누락(m)과 잔여(r) 토큰**을 세어 적합도를 계산한다. 공식은 **½(1−m/c) + ½(1−r/p)**.
- **트레이스 단위 판정(맞다/안 맞다)이 아니라 이벤트 수준**으로 보는 것이 핵심이다 — 긴 트레이스에서는 트레이스 단위 적합도가 오해를 부른다.
- **시작과 끝의 환경 생산·소비**가 중요하다. 최종 자리에 토큰이 없어도 소비를 강제해야 **올바른 최종 상태에서 끝났는지** 검사할 수 있다.
- **꽃 모델의 적합도는 1**이다 — 적합도만으로는 나쁜 모델을 잡을 수 없고, **정밀도가 필요**하다.
- 발자국과 달리 **실제 행동과 빈도를 보고, 어느 자리에서 문제가 났는지 상세 진단**을 준다.
