# 4.7: Aligning Observed and Modeled Behavior

## 개요
- 적합성 검사의 **가장 발전된 접근 — 정렬(alignment)**.
- **비용 함수(cost function)** 로 **최적 정렬**을 정의하고, 그것으로 적합도를 계산한다.
- 정렬의 진짜 가치는 **다른 모든 분석의 전제 조건**이라는 데 있다.

## 내용

### 이전 기법들의 한계를 넘기 위한 요구사항
1. **프로세스 모델 표기법에 제약을 두지 않아야** 한다 — 워크플로 넷에 국한되면 안 되고, **같은 레이블의 전이가 둘 있거나 묵음 단계가 있는 모델**(OR-split/join 모델링용)도 다뤄야 한다
2. **모델을 통과하는 가장 가까운 경로**를 봐야 한다 — 현실에서 본 것을 **모델의 유효한 경로와 연결**해야 한다

> **왜 필요한가**: **성능 분석**(현실을 모델 위에서 재생해 병목을 찾는 것)과, **정밀도·일반화 같은 더 정교한 적합성 개념**, 더 진전된 진단을 위해서다. **먼저 현실을 모델의 경로에 연결해야** 한다. 즉 **다른 온갖 분석의 활성화 조건(enabler)** 이다.

### 정렬의 구조

| 이동 | 윗줄(로그) | 아랫줄(모델) | 뜻 |
|---|---|---|---|
| **로그에서만 이동** | 활동 레이블 | **≫** | 현실에서 일어났는데 **모델이 흉내 낼 수 없었다** |
| **모델에서만 이동** | **≫** | 활동 레이블 | 모델이 이동해야 했는데 **현실이 흉내 내지 않았다** |
| **동기 이동(synchronous)** | 활동 레이블 | 같은 레이블 | 둘 다 동시에 이동 — **일치** |

> 이 개념과 분석 기법은 **프로세스 모델 표기법과 무관**하다. 페트리 넷, BPMN, 전이 시스템 무엇이든 된다.

**예시**: 트레이스 `a, d, e, g, h`의 두 문제
1. **b나 c가 빠졌다** — d와 동시에 실행돼야 했는데
2. 끝에 **g와 h가 둘 다** 있다 — 둘 중 하나만 있어야 한다

정렬은 이를 명확히 보여준다 — **모델이 b 이동을 해야 했는데 현실이 흉내 내지 않았고**, 끝에 g와 h 중 **하나는 무시돼야** 했다.

### 최적 정렬과 비용 함수
> 현실을 모델의 경로와 연결하는 방법이 여러 개이고 **모델을 통과하는 경로도 여러 개**일 수 있다. **어느 경로를 고를 것인가?**
> **현실에서 본 것에 가장 가까운 경로**를 고른다.

**표준 비용 함수**:
| 이동 | 비용 |
|---|---|
| **동기 이동** | **0** |
| **로그에서만 이동** | **1** |
| **모델에서만 이동** | **1** |
| **두 활동이 불일치** | **무한대**(또는 절대 선택되지 않을 만큼 높은 값) |

**계산 예**:
| 정렬 | 비용 |
|---|---|
| 완벽히 일치 | **0** ← **최적** |
| a와 b가 뒤바뀐 설명 (로그 이동 1 + 모델 이동 1) | **2** |
| e1, e2, e3를 d1, d2, d3에 대응시킨 설명 (≫ 기호 10개) | **10** |

> **최적 정렬** = **더 낮은 비용의 정렬이 존재하지 않는** 정렬.

### 최적 정렬은 여러 개일 수 있다

**예시 1 — 비용 2인 두 설명**
- **설명 A**: 현실에서 e와 f가 일어났지만 **무시한다.** 루프를 돌지 않고 프로세스를 한 번만 통과한다 → 비용 2
- **설명 B**: **반복을 한 번 돈다.** f를 실행해야 함을 받아들이되, 그러려면 **현실에서 일어나지 않은 이벤트 두 개(d와 b)를 추가**해 시나리오를 설명한다 → 비용 2

**예시 2 — 최적 정렬 9개**
> 앞서 본 두 정렬에서 **b(모델에서만 이동)를 c로 바꿀 수 있다** → **3가지 변형**.
> 게다가 **d가 b, c와 동시적**이므로 **d 이동과 b·c 이동의 순서를 바꿀 수 있다.**
> 모든 조합을 세면 **최적 정렬이 9개**다.

### 비용 함수는 자유롭게 설계할 수 있다
표준 비용 함수 외에 **이벤트의 다른 속성과 성질**을 반영할 수 있다.

| 반영할 것 | 방법 |
|---|---|
| **활동의 유사도** | 로그의 이벤트와 모델의 전이가 **비슷하면 비용을 낮게** |
| **권한 위반** | John이 이 활동을 실행할 권한이 없다면 **벌점** |
| **마감 위반** | 3주 안에 해야 하는데 4주 걸렸다면 **너무 늦은 것에 벌점** |
| **데이터** | 특정 경로가 **특정 고객 유형이나 주문 규모**에만 허용된다면 반영 |
| **위험, 맥락 정보** | 무엇이든 추가 가능 |

> **무엇을 넣어도 여전히 최적 정렬을 제공하고, 다른 관점까지 고려한 차이를 진단할 수 있다.**

### 적합도 계산 — 최악 시나리오 기준
0~1 사이 숫자로 적합도를 내려면 **최악 시나리오의 비용**이 필요하다.

> **최악 시나리오** = **로그의 모든 이벤트를 "로그에서만 이동"으로** 처리하고, **모델의 최단 경로를 "모델에서만 이동"으로** 처리하는 것.

**계산 예 1**:
- 최적 정렬 비용 = **2**
- 트레이스 길이 = **7**, 최단 경로 길이 = **5**
- → **적합도 = 0.83**

**계산 예 2**:
- 최적 정렬 비용 = **2**
- 최악 시나리오 비용 = **6 + 6 = 12**
- → **적합도 = 0.833** (우연히 같은 값)

## 요약

**정렬의 장점**
1. **관찰된 행동을 모델 자체와 직접 연결**한다 — 매우 중요하다
2. **매우 유연하다** — 마감 미준수, 잘못된 사람의 실행 등에 **임의의 비용 함수**를 쓸 수 있다
3. **매우 상세한 진단**을 준다 — 이벤트를 정교한 수준에서 비교한다
4. **정렬 후 모델을 통과하는 경로**를 얻으므로 **온갖 다른 분석이 가능해진다**

**두 가지 용도**
- **편차 진단** — 어디서, 왜 벗어났는지
- **현실을 모델에 밀어 넣기(squeeze)** — 완벽히 맞지 않아도 **성능 분석 등 모델과 이벤트 데이터를 동시에 써야 하는 분석**에 결정적이다

**드릴다운**: 트레이스를 **맞는 것과 안 맞는 것으로 분리**해 따로 분석하면, **벗어난 케이스와 벗어나지 않은 케이스의 차이**를 이해할 수 있다.
