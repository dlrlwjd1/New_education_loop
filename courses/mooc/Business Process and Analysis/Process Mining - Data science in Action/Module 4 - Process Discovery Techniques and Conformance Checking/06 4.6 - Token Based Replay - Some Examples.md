# 4.6: Token Based Replay — Some Examples

## 개요
- 토큰 기반 재생의 **손 계산 예제 세 개**.
- 마지막에 **이 접근의 단순화 가정과 한계**를 정리하고, 다음 강의의 **정렬(alignment)** 을 예고한다.

## 예시

### 예제 1 — 35개 케이스, 적합도 0.96
트레이스 **`acd`** (1회) 재생:
1. 소스 자리 생산
2. **a** — 1 소비, 2 생산
3. **c** — 가능. 소비·생산
4. **d** — **p3에 토큰이 없어 활성화되지 않는다** → **누락 토큰 추가** 후 실행 (2 소비, 1 생산)
5. 최종 자리에서 소비
6. **p1에 토큰 1개가 남는다**

**결과**: p = 5, c = 5, **m = 1, r = 1**

전체 로그는 **스프레드시트**로 계산한다. 각 트레이스의 p·c·m·r을 구하고 **빈도를 곱한** 뒤 모두 합산해 공식에 넣는다.
> 예: 완벽히 맞는 첫 트레이스는 m = r = 0이고 **10번** 일어났으므로 10을 곱한다.

**전체 적합도 = 0.96**

### 예제 2 — 최악의 경우, 적합도 0
케이스 하나, 이벤트 하나(**e**)만 있는 로그.
1. 소스 자리 생산 → p = 1
2. **e** — **p1과 p2 모두 비어 있다** → **누락 토큰 2개** 기록. 그 뒤 2 소비, 2 생산
3. 트레이스 종료. 환경이 end 자리에서 소비해야 하는데 **토큰이 없다** → **누락 토큰 1개 더**
4. 최종 상태에 **소스 자리, p3, p4에 토큰이 남아 있다**

**결과**: p = 3, c = 3, **m = 3, r = 3** → **적합도 = 0**

> **생산된 토큰 중 실제로 쓰인 것이 하나도 없고, 소비된 토큰 중 실제로 있던 것이 하나도 없다.** 상상할 수 있는 최악의 적합도다.

### 예제 3 — 33개 케이스, 적합도 약 0.9
트레이스 **`ace`**(5회)를 재생하면 **잔여 1, 누락 1**이 나온다. 5번 일어났으므로 **잔여 5, 누락 5**. 모든 행에 대해 같은 계산을 하고 합산하면 **0.9에 조금 못 미치는 적합도**가 나온다.

### 예제 4 — 20개 케이스, 적합도 0.8
합계: **생산 200, 소비 200, 잔여 40, 누락 40** → **0.8**

> ProM의 진단도 손 계산과 **정확히 같은 값**을 보여준다. **음수 앞에 붙은 숫자가 누락 토큰**, **양수가 재생 중 소비되지 않은 토큰**이다.
> (참고: 이 화면은 ProM 6가 아니라 **ProM 5.2** 것이다. ProM 6는 다음 강의에서 다룰 더 발전된 기법을 제공한다.)

## 내용 — 이 접근의 한계

**단순화 가정 1 — 유일하고 보이는 레이블**
> 모든 예제에서 **전이의 레이블이 유일하고 보인다(visible)** 고 가정했다. **같은 레이블의 전이가 여럿이거나 레이블 없는(보이지 않는) 전이**가 있는 모델에 적용하려면 **휴리스틱**이 필요하고, 그러면 **진단이 오해를 부를 수 있다** — 재생 중 **같은 레이블의 두 전이 중 어느 쪽을 실행할지 추측**해야 하기 때문이다.

**한계 2 — 적합도 값이 너무 낙관적일 수 있다**
> 문제가 많으면 **토큰이 누락될 때마다 그냥 추가**하므로 **넷이 토큰으로 넘쳐난다.** 결국 **토큰이 너무 많아져 무엇이든 실행할 수 있게 된다.**

**한계 3 — 국소적 결정이 오해를 부르는 진단을 만든다**

**예시**: 트레이스 `a, c1, c2, e1, e2, e3`.
> 문제는 **처음의 a 실행이 e1, e2, e3의 실행과 맞물릴 수 없다**는 것이다. 그런데 재생은 **순진하게 처음부터** 시작한다.
1. 소스 생산 → **a** 실행 (1 소비, 2 생산)
2. c1, c2 — 문제없음
3. **e1** — **입력 자리 중 하나에 토큰이 없다** → 누락 토큰 기록
4. 끝까지 진행 → 최종 자리에서 소비 → **잔여 토큰 하나**

> **진단이 오해를 부른다.** 처음에 **a를 통과하는 경로를 골랐지만**, 자세히 보면 **b를 통과하는 경로가 더 나았을 것**이다.
>
> 적합도 숫자는 나오지만 **진단이 문제다.** **모델을 통과하는 대응 경로를 제공하지 못한다** — 지금 재생된 경로는 **실제로는 불가능한 경로**이기 때문이다.
>
> **정말 보고 싶은 것은 현실에서 관찰한 트레이스에 가장 가까운 경로**다. 이 경우라면 **`b, c1, c2, e1, e2, e3`** 였을 것이다.

## 예시 — 정렬(alignment)의 예고

**정렬의 구조**: 두 줄로 이뤄진다.
- **윗줄** = 이벤트 로그의 트레이스
- **아랫줄** = **모델을 통과하는 실제 경로**

**세 가지 이동(move)**:
| 이동 | 뜻 |
|---|---|
| **로그에서만 이동(move in log only)** | **현실에서 일어났는데 모델이 흉내 낼 수 없었다** |
| **모델에서만 이동(move in model only)** | **모델에 따르면 필요한데 현실에서 일어나지 않았다** |
| **동기 이동(synchronous move / move in both)** | 모델과 로그가 **무엇이 일어나야 하는지에 동의**한다 |

**≫ 기호**가 **이동 없음(no move)** 을 나타낸다.

> 정렬을 보면 **처음의 a와 b에 문제가 있었다는 것이 명확히 드러난다.** 단순 토큰 재생보다 **훨씬 나은 진단**이다.

## 요약
- 손 계산 예제들: **0.96**(35케이스), **0**(이벤트 하나짜리 최악), **약 0.9**(33케이스), **0.8**(20케이스).
- 계산 방식은 항상 같다 — **트레이스별 p·c·m·r을 구하고 빈도를 곱해 합산**한 뒤 공식에 넣는다.
- 세 가지 한계:
  1. **유일·가시 레이블 가정** — 중복·묵음 전이에는 휴리스틱이 필요하고 진단이 흐려진다
  2. **너무 낙관적일 수 있다** — 누락 토큰을 계속 추가하면 넷이 토큰으로 넘친다
  3. **국소적 결정** — 초반에 잘못된 경로를 골라도 되돌리지 않아 **진단이 오해를 부르고, 유효한 모델 경로를 제공하지 못한다**
- 해법이 다음 강의의 **정렬(alignment)** 이다 — **관찰된 트레이스에 가장 가까운 모델 경로**를 찾아 준다.
