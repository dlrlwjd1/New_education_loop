# 4.2: Alternative Process Discovery Techniques

## 개요
- 프로세스 발견의 마지막 강의. 지금까지 본 것 외에 **세 가지 기법**을 더 소개한다.
- **언어 기반 영역(language-based regions) · 유전 프로세스 마이닝 · 귀납적 마이닝(inductive mining)**.
- 통합 관점: **프로세스 발견 = 자리(place)를 찾는 문제**.

## 내용

### 발견 기법을 고를 때 볼 것
- **적합도·단순성·정밀도·일반화의 균형**
- **속도** — 얼마나 빨리 결과가 나오는가
- **메모리 사용량**
- **표현** — 어떤 표현을 쓰는가
- **유연성** — 관련 문제도 탐색할 수 있는가

> **알고리즘의 구현(빠르거나 느릴 수 있다)과 접근법 자체를 늘 구분**해야 한다.

### 통합 관점 — 행동을 더하고 빼기

| 행동을 **더하는** 연산 | 행동을 **빼는** 연산 |
|---|---|
| **전이 추가** — 새 트레이스가 가능해진다 | **전이 제거** |
| **자리 제거** — a와 b 사이 자리를 없애면 `b,a,c,d`가 가능해진다 | **자리 추가** — b 다음에 c가 오도록 강제한다 |
| **자리→전이 호 제거** (제약 제거) | **전이→자리 호 제거** |
| **전이→자리 호 추가** | **자리→전이 호 추가** |

> **자리를 더하거나 빼는 것이 행동의 양을 좌우한다.** 그래서 **프로세스 발견을 자리를 찾는 문제로 볼 수 있다.**
>
> - **알파 알고리즘** — 로그에서 본 행동으로 제약하기 위해 자리를 발견
> - **상태 기반 영역** — 전이 시스템을 만들고 상태 집합을 자리로 묶는다
> - **언어 기반 영역** — 전이 시스템을 만들지 않고 **트레이스에서 직접** 시작한다

### 기법 1 — 언어 기반 영역
**부등식 체계(system of inequations)** 를 푸는 문제다.

> **핵심 의미는 단순하다: 로그를 재생하는 동안 어떤 자리도 토큰 수가 음수가 되면 안 된다.**

**구성 요소**:
| 기호 | 뜻 |
|---|---|
| **c** | 발견하려는 자리의 **초기 토큰 수** |
| **A** | 로그의 **비어 있지 않은 접두사**마다 각 전이가 몇 번 발화했는지의 행렬 |
| **A′** | 같은 것이되 **마지막 단계를 무시**한 행렬 |
| **x_a, x_b** | **전이 → 자리** 방향의 호 개수 (미지수) |
| **y_a, y_b** | **자리 → 전이** 방향의 호 개수 (미지수) |

**부등식 체계의 세 부분**: **초기화**(초기 토큰) + **생산**(A′ 기반) + **소비**(A 기반, 음수 부호). 결과는 **항상 양수**여야 한다.

> **이 부등식 체계의 어떤 해도 하나의 자리**이며, **본 행동을 제거하지 않고 추가할 수 있는 자리**다.

**강점 — 제약을 추가하기 쉽다**:
- "끝에 자리가 비어 있어야 한다" → 제약 추가
- "자리의 입력이나 출력 전이가 2개를 넘지 않아야 한다" → 제약 추가
- 네트워크 구조에 대한 온갖 제약을 부등식으로 표현

> 모든 자리에 관심 있는 게 아니라 **행동을 가장 많이 제한하는 자리**에 관심이 있으므로 **목적 함수(goal function)** 를 쓴다. 그러면 **ILP(정수 선형 계획) 기법으로 풀 수 있는 표준 최적화 문제**가 된다.

### 기법 2 — 유전 프로세스 마이닝
**진화(evolution)로 모델을 반복적으로 개선**한다.

1. 이벤트 로그에서 **무작위로 프로세스 모델들을 생성**한다 (첫 세대)
2. **품질을 측정**한다. 충분히 좋으면 멈춘다(대개 그렇지 않다)
3. **가장 좋은 후보들이 다음 라운드**로 간다
4. **교차(cross over) 연산자**로 여러 후보를 재조합해 새 모델을 만든다
5. **돌연변이(mutation)** 로 모델을 조금 바꿔 개선을 기대한다
6. **새 세대**가 나온다. 한 세대에 **모델이 수천 개**일 수 있다
7. 적합성 검사로 품질을 측정하고 다시 최선을 고른다
8. **수백~수천 번 반복** 후 좋은 품질의 모델을 반환한다

| 특성 | 내용 |
|---|---|
| **속도** | 실제 로그에서는 **극도로 느리다.** 큰 세대와 많은 세대가 필요하다 |
| **유연성** | **극도로 유연하다.** 네 힘 외에 **새로운 힘을 쉽게 추가**할 수 있다 — 참조 모델과의 편집 거리, 비용 정보, 위험 정보 등에 가중치를 줄 수 있다 |
| **용도** | **새 문제를 만났는데 효율적인 해법이 없을 때 실험용**으로 쓴다. 그 경험에서 **훨씬 빠른 발견 기법의 아이디어**를 얻는 경우가 많다 |

### 기법 3 — 귀납적 마이닝
**로그를 재귀적으로 분해(decompose)** 한다.

**절차 예시** (트레이스 `abdef` 등):
1. 레이블 집합을 **두 집합으로 분할** — `{a,b,c,d}`와 `{e,f,g}`
2. 로그를 두 집합에 **투영(project)** 한다 → `abdef`가 `abd`와 `ef`로 나뉜다
3. **순차(sequence) 연산자**로 이어 붙이면 원래 트레이스가 복원된다
4. 첫 부분에서 모두 a로 시작하므로 **다시 순차 연산자로 분할** → `a` → `bd` → `e` `f`
5. `ef`/`eg` 열도 **순차 연산자로 분할**
6. 이제 순차로는 더 못 나눈다. **다른 연산자를 시도**한다
7. 마지막 열의 f와 g — **XOR 연산자**로 분할한다. **f와 g가 서로 다른 열에 있고 동시에 둘 다 있는 경우가 없기 때문**
8. 두 번째 열 — 순차가 안 되므로 **병렬(parallel/AND) 연산자**가 자연스럽다
9. 다시 b와 c가 남으면 **XOR 연산자**로 분할

> 더 분해할 수 없을 때까지 로그를 쪼개면 그 결과를 **트리로 표현**할 수 있다 — 이것이 **프로세스 트리(process tree)** 다. **AND, XOR, 순차, 그리고 루프** 같은 연산자로 분해한다.
>
> 프로세스 트리는 **구조화된 프로세스 모델로 쉽게 변환**된다 — 페트리 넷이나 BPMN으로.

**ProM에서의 귀납적 마이너**:
- 케이스가 **애니메이션**된다 (퍼지 마이너, Disco와 마찬가지)
- 밑에 깔린 표현은 **프로세스 트리**이고 **페트리 넷/BPMN으로 자동 변환**된다
- **슬라이더**로 추상화 수준을 고를 수 있다 — 빈번한 활동만 남기면 더 단순한 모델
- **편차 표시**, **빈번·비빈번 경로 확인** 등 기능이 많다

## 요약
- **프로세스 발견 = 자리를 찾는 문제**로 통합해 볼 수 있다. 자리 추가는 제약 추가, 자리 제거는 행동 확대다.
- **언어 기반 영역**: "토큰이 음수가 되면 안 된다"는 부등식 체계를 푼다. **제약과 목적 함수를 추가하기 쉬워** ILP로 풀린다.
- **유전 마이닝**: 느리지만 **극도로 유연**하다. **새 품질 차원을 자유롭게 추가**할 수 있어 새 문제 탐색용으로 좋다.
- **귀납적 마이닝**: 로그를 **순차/XOR/AND/루프 연산자로 재귀 분해**해 **프로세스 트리**를 만든다. **구조화된 모델이 보장**되고 슬라이더로 단순화된다.
