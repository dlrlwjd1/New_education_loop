# Wait-For Graphs

## 개요
- 교착 상태(deadlock)를 탐지하기 위한 대기 그래프(wait-for graph)를 다룬다.
- 두 트랜잭션이 서로가 잠근 자원을 기다리는 상황을 그래프의 사이클(cycle)로 표현하고 탐지한다.
- 분산 데이터베이스에서는 각 사이트별 지역(local) 대기 그래프와 전역(global) 대기 그래프를 함께 사용해야 한다.

## 내용

### 교착 상태와 대기 그래프의 기본 개념
- 트랜잭션 T1은 트랜잭션 T2가 잠근 자원을 기다리고, 동시에 트랜잭션 T2는 T1이 잠근 자원을 기다리는 상황을 가정한다.
- 이 경우 두 트랜잭션은 교착 상태(deadlock)에 빠져 무한정 대기(wait indefinitely)하게 된다.
- 이를 해결하는 한 가지 방법이 대기 그래프(wait-for graph)를 만드는 것이다.
- 중앙집중식(central) 시스템이든 분산(distributed) 시스템이든, 각 트랜잭션이 무엇을 기다리고 있는지 추적하면 사이클(cycle)이 존재하는지 탐지할 수 있다.
- 예: T1이 T2를 기다리고, T2가 T1을 기다리면 두 노드(node) 사이에 사이클이 있는 그래프가 만들어진다.
- 그래프에서 사이클 탐지(cycle detection)는 비교적 쉬운 작업이다.
- 사이클이 탐지되면 시스템은 즉시 개입하여 교착 상태를 해결할 수 있다. 트랜잭션 하나를 중단(abort)하거나, 필요하면 둘 다 중단하는 선택지가 있다.

### 분산 환경에서의 어려움 — 지역 그래프와 전역 그래프
- 여러 사이트(site)를 다루는 경우 문제가 더 복잡해진다.
- 예: 트랜잭션 T1, T2는 사이트 1에서, 트랜잭션 T3, T4는 사이트 2에서 관리된다고 하자.
- 각 사이트는 자신만의 지역 대기 그래프(local wait-for graph)를 만든다.
  - 사이트 1: T1이 T2를 기다린다.
  - 사이트 2: T3이 T4를 기다린다.
- 그러나 사이트를 넘나드는 관계도 존재한다. T4는 T1을 기다리고, T2는 T3을 기다린다.
- 결과적으로 전체 엔터프라이즈(enterprise) 관점에서는 사이클이 존재하지만, 각 사이트의 지역 그래프만 보면 사이클이 전혀 존재하지 않는다.
- 따라서 전역 대기 그래프(global wait-for graph)를 만들어 사이클(즉, 전역 교착 상태(global deadlock))이 있는지 판단해야 한다.

### 계층적 교착 상태 탐지(hierarchical deadlock detection) 관리 방식
- 교착 상태 탐지와 해결을 여러 계층(level)에서 수행할 수 있다.
- 사이트 1, 사이트 2, 사이트 3, 사이트 4가 각각 자신의 지역 대기 그래프와, 사이클을 탐지해 교착 상태를 처리하는 알고리즘을 갖는다.
- 하위 계층에서 사이트 1은 사이트 1과 사이트 2를 아우르는 전역 그래프를 호스팅(host)할 수 있다.
  - 사이트 1과 사이트 2 각각에서 사이클이 탐지되지 않더라도, 두 지역 그래프를 합쳐 사이트 1과 사이트 2 사이의 교착 상태를 사이트 1에서 처리할 수 있다.
- 마찬가지로 사이트 4는 사이트 3과 사이트 4를 아우르는 전역 그래프를 호스팅하여 두 사이트 사이의 교착 상태를 처리할 수 있다.
- 그럼에도 궁극적으로는 엔터프라이즈 전체(enterprise-wide)의 교착 상태 사이클을 고려해야 한다.
- 이를 위해 사이트 3에서 모든 지역 대기 그래프를 종합한 진정한 의미의 전역 대기 그래프(really global wait-for graph)를 호스팅하여 처리할 수 있다.
- 이것이 분산 시스템에서 계층적으로 교착 상태를 탐지하는 한 가지 방식이다.

## 요약
- 대기 그래프(wait-for graph)는 트랜잭션 간 대기 관계를 그래프의 노드와 간선으로 표현하고, 사이클 탐지로 교착 상태 여부를 판단하는 기법이다.
- 사이클이 발견되면 시스템은 트랜잭션 하나 또는 둘 다를 중단하여 교착 상태를 해결할 수 있다.
- 분산 시스템에서는 사이트별 지역 대기 그래프만으로는 사이클이 안 보일 수 있으며(사이트 간 교차 의존), 전역 대기 그래프가 필요하다.
- 해결책으로 여러 사이트가 계층적으로 부분 전역 그래프를 나누어 호스팅하다가, 최종적으로 한 사이트가 전체를 종합한 진정한 전역 그래프를 관리하는 계층적 탐지 방식을 사용할 수 있다.
