# Distributed Two Phase Locking

## 개요
- 분산 환경에서의 2단계 잠금(distributed two-phase locking) 방식들을 다룬다.
- 잠금 관리자(lock manager, LM)를 아키텍처에 추가하며, 잠금 관리자를 어디에 두느냐에 따라 여러 방식으로 나뉜다.
- 중앙집중(primary site) → 주 사본(primary copy) → 완전 분산(distributed) 순으로 살펴본다.

## 내용

### 기본 분산 트랜잭션 아키텍처 복습
- 분산 실행 모니터(distributed execution monitor)가 기업 전반에 퍼져 있으며 트랜잭션 관리자(transaction manager)와 스케줄러(scheduler)를 포함한다.
- 연산은 트랜잭션 관리자로 전송되고, 트랜잭션 관리자는 올바른 스케줄러를 찾아 연산을 보낸다.
- 스케줄러는 데이터베이스 프로세서(database processor)에서 연산을 시작하고, 결과는 다시 스케줄러와 트랜잭션 관리자를 거쳐 애플리케이션으로 전달된다.
- 분산 2단계 잠금에서는 여기에 잠금 관리자(lock manager)를 추가한다.

### 중앙집중식 / 주 사이트 2단계 잠금(Centralized / Primary Site 2PL)
- 한 사이트가 잠금 관리자를 호스팅하도록 지정되고, 한 사이트가 트랜잭션 관리자를 호스팅하도록 지정된다.
- 연산 순서:
  1. 트랜잭션 관리자가 연산 요청을 받는다.
  2. 트랜잭션 관리자가 잠금 관리자에게 잠금 요청(lock request)을 보낸다.
  3. 잠금 관리자가 잠금 승인(lock granted) 메시지로 응답한다.
  4. 트랜잭션 관리자가 데이터 프로세서에 연산을 보낸다.
  5. 데이터 프로세서가 연산을 처리하고 종료 메시지를 트랜잭션 관리자에게 보낸다.
  6. 트랜잭션 관리자가 잠금 관리자에게 잠금 해제(release) 메시지를 보낸다.
- 잠금 관리자는 프로세서와 직접 상호작용하지 않으며, 트랜잭션 관리자가 모든 메시징 조정 부담을 진다.
- 단점: 중앙집중식 잠금 관리자는 시스템의 병목(bottleneck)을 유발한다. 잠금 관리자 사이트나 유일한 트랜잭션 관리자가 다운되면 전체 시스템이 마비된다.

### 주 사본 2단계 잠금(Primary Copy 2PL)
- 중앙집중식 방식과 연산 순서는 동일하지만, 잠금 관리자가 기업 전반에 분산되어 있다.
- 각 잠금 관리자는 특정 자원 X를 담당한다. 시스템에 X의 사본(copy)이 여러 개 있을 수 있지만, 어떤 잠금 관리자가 X의 주 위치(primary location)를 관리한다.
- 순서:
  1. 트랜잭션 관리자가 값을 갱신·수정해야 하면 해당(주 위치를 관리하는) 잠금 관리자에게 잠금 요청을 보낸다.
  2. 잠금 관리자가 잠금을 승인한다.
  3. 연산이 X가 위치한 여러 데이터 프로세서로 전송된다.
  4. 연산 종료 응답이 트랜잭션 관리자로 전송된다.
  5. 트랜잭션 관리자가 잠금을 해제한다.
- 장점: 중앙 잠금 관리자 사이트의 부하를 줄이며, 트랜잭션 관리자와 잠금 관리자 사이의 추가 통신도 크게 늘지 않는다.

### 분산 2단계 잠금(Distributed 2PL)
- 잠금 관리자를 각 사이트에 분산 배치한다.
- 데이터가 복제(replicate)되지 않으면 앞의 주 사본 2단계 잠금으로 사실상 축소(degenerate)된다.
- 데이터가 복제되면 read-once, write-all 방식을 구현한다: 읽기는 복제된 데이터 사이트 중 아무 곳에서나 읽고, 쓰기는 모든 사이트에 써야 한다.
- 이 방식에서 잠금 관리자는 데이터 메시지를 전달(pass on)하는 역할도 한다.
  - 트랜잭션 관리자가 잠금을 요청하면, 잠금 관리자는 잠금을 승인하되 트랜잭션 관리자에게 알리지 않고 곧바로 데이터 프로세서에 연산 메시지를 보낸다.
  - 데이터 프로세서가 끝나면 트랜잭션 관리자에게 메시지를 보내고, 트랜잭션 관리자가 잠금 관리자로부터 잠금을 해제한다.

### 잠금 관리자에게 더 위임하기
- 한 단계 더 나아가 모든 연산을 잠금 관리자에게 신뢰(trust)하여 맡길 수 있다.
- 트랜잭션 관리자가 잠금 요청과 함께 연산을 요청하면 잠금 관리자에게 메시지를 보낸다.
- 잠금 관리자가 직접 데이터 프로세서에서 연산을 수행한다.
- 연산이 끝나면 데이터 프로세서가 잠금 관리자에게 잠금 해제를 알리고, 잠금 관리자가 트랜잭션 관리자에게 해제 사실을 알린다.

## 요약
- 분산 2단계 잠금은 잠금 관리자(lock manager)의 위치와 역할에 따라 여러 방식으로 나뉜다.
- 중앙집중/주 사이트 방식: 잠금 관리자가 한 곳에만 있어 병목과 단일 장애점(single point of failure)이 된다.
- 주 사본 방식: 각 자원의 주 위치를 담당하는 잠금 관리자가 분산되어 중앙 부하를 줄인다.
- 완전 분산 방식: 각 사이트에 잠금 관리자를 두며, 데이터가 복제되면 read-once/write-all을 사용한다.
- 각 방식은 제어력 대 병목, 통신량 사이의 트레이드오프가 있으며, 올바른 선택은 분산 데이터베이스 시스템의 특성과 사용 패턴에 달려 있다.
