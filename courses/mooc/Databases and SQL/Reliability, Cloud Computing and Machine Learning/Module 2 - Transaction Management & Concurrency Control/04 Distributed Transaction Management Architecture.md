# Distributed Transaction Management Architecture

## 개요
- 분산 데이터베이스 시스템(distributed database system)에서 트랜잭션을 관리하는 아키텍처를 다룬다.
- 핵심 구성 요소는 분산 실행 모니터(Distributed Execution Monitor)이며, 그 안에 트랜잭션 관리자(Transaction Manager, TM)와 스케줄러(Scheduler, SC)가 들어 있다.
- 각 데이터베이스마다 하나의 분산 실행 모니터가 연결되어 있다고 상상하면 된다.

## 내용

### 분산 실행 모니터(Distributed Execution Monitor)
- 분산 데이터베이스 시스템의 각 데이터베이스마다 하나씩 연결된다.
- 내부에는 트랜잭션 관리자(TM)와 스케줄러(SC)가 존재한다.
- BEGIN, READ, WRITE, COMMIT, IMPORT 같은 연산을 받아 처리한다.

### 연산 처리 흐름
- BEGIN / READ / WRITE / COMMIT / IMPORT 중 하나의 연산이 들어오면 그 정보가 트랜잭션 관리자(TM)로 전달된다.
- 트랜잭션 관리자는 필요한 스케줄러들과 통신한다.
- 스케줄러는 연산을 순서대로 정렬(line up)하여 데이터 프로세서(data processor)로 내려보낸다.
- 데이터 프로세서가 처리한 결과는 다시 트랜잭션 관리자로 전달된다.

### 병렬 스케줄러 간 협력
- 분산 실행 모니터는 자기 자신의 데이터 프로세서에 연산을 스케줄링하는 것으로 시작한다.
- 동시에, 다른 데이터베이스에 연결된 병렬 스케줄러(parallel scheduler)들에게도 자신이 수행할 스케줄링 활동을 알린다.
- 잠재적으로 모든 분산 데이터베이스의 모든 스케줄러와 접촉할 수 있다.
- 스케줄러는 자신의 트랜잭션 관리자로부터도, 다른 분산 실행 모니터에 속한 분산 트랜잭션 관리자로부터도 명령을 받을 수 있다.
- 결과값은 다른 분산 실행 모니터의 트랜잭션 관리자에게 되돌려 보내지며, 최종적으로 호출한 애플리케이션(calling application)으로 전달된다.

### 중앙집중식 시스템과의 비교
- 분산 데이터베이스 시스템의 트랜잭션 관리는 중앙집중식(centralized) 시스템과 유사하다.
- 다만 분산 실행 모니터는 이제 다수의 트랜잭션과 다수의 스케줄러를 제어(control)해야 한다는 점이 다르다.
- 이 부분에 대한 상세 내용은 다음 모듈에서 다룬다.

## 요약
- 트랜잭션 관리자 아키텍처를 논한다는 것은 곧 분산 실행 모니터(Distributed Execution Monitor)를 논하는 것이다.
- 분산 실행 모니터 = 트랜잭션 관리자(TM) + 스케줄러(SC)이며, 각 분산 데이터베이스마다 하나씩 존재할 수 있다.
- 트랜잭션 관리자는 스케줄러들과 통신하고, 스케줄러는 데이터 프로세서에 연산을 내려보낸 뒤 결과를 되돌린다.
- 분산 환경에서는 다수의 트랜잭션과 다수의 스케줄러를 제어해야 한다는 점이 중앙집중식과의 핵심 차이다.
