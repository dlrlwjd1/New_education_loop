# Formal Transaction Definition

## 개요
- 트랜잭션 관리 논의 전반에서 사용할 트랜잭션의 형식적 정의(formal definition)와 표기법을 소개한다.
- 트랜잭션 T_i는 그 연산들(reads/writes)과 종료 조건(termination: commit 또는 abort)의 부분 순서(partial ordering)로 정의된다.
- 충돌하는 연산 사이에는 순서가 필요하지만, 충돌하지 않는 연산 사이의 순서는 자유롭다.

## 내용

### 트랜잭션의 정의
- 트랜잭션 T_i는 그 모든 연산과 종료 조건의 **부분 순서(partial ordering)** 로 정의된다. 트랜잭션이 세 개면 T1, T2, T3처럼 쓴다.
- 소프트웨어 안에서는 많은 연산이 일어나지만, 우리가 관심 있는 연산은 **읽기(read)와 쓰기(write)** 뿐이다.
- 종료 조건(termination)은 **커밋(commit)** 또는 **어보트(abort)** 다.
- 시그마(sigma)는 이 부분 순서에 포함된 연산들의 집합으로, 스케줄의 모든 연산과 종료 조건의 합집합이다.
- 곡선 형태의 부등호(curvy less-than)는 부분 순서를 의미한다. 일반 부등호(<)가 순서(ordering)를 뜻하듯, 곡선 부등호는 "부분적인" 순서를 뜻한다.

### 부분 순서의 직관: 양말과 신발
- 오른쪽 양말 → 왼쪽 양말 → 오른쪽 신발 → 왼쪽 신발, 또는 오른쪽 양말 → 오른쪽 신발 → 왼쪽 양말 → 왼쪽 신발 등 여러 순서가 가능하다.
- 양말끼리는 어느 쪽을 먼저 신어도 되지만, **오른쪽 양말은 오른쪽 신발보다 먼저**, **왼쪽 양말은 왼쪽 신발보다 먼저** 신어야 한다. 바로 직전일 필요는 없고 그 이전 어느 시점이면 된다.
- 부분 순서는 반드시 지켜야 할 순서만 정의하고, 지킬 필요 없는 순서는 열어 둔다.

### 부분 순서의 성질
- **비반사적(not reflective)**: A가 B보다 앞선다고 해서 B가 A보다 앞서지는 않는다.
- **추이적(transitive)**: A가 B보다 앞서고 B가 C보다 앞서면, A는 C보다 앞선다.

### 충돌(conflict) 규칙
- 읽기와 읽기(read-read) 사이에는 충돌이 없다.
- 충돌은 **읽기와 쓰기(read-write)**, **쓰기와 쓰기(write-write)** 사이에만 존재한다.
- 트랜잭션 T_i 안의 임의의 두 연산 O_{i,j}, O_{i,k}에서, O_{i,j}는 read 또는 write이고 O_{i,k}가 write이면 두 연산 사이에 순서가 있어야 한다.
- 모든 연산은 종료 조건보다 먼저 일어나야 한다는 부분 순서가 존재한다.

### DAG 표현
- 트랜잭션은 방향 비순환 그래프(directed acyclic graph, DAG)로 표현할 수 있다.
- 예: X를 읽고, X와 Y를 더해 새 X를 만들고, 새 X를 쓰고 커밋하는 트랜잭션에서 관심 있는 연산은 read/write/commit뿐이며, 덧셈 연산 자체는 표기하지 않는다.
- Read(X)와 Read(Y)는 서로 어느 순서로 해도 되지만, 둘 다 Write(X)보다 먼저 일어나야 한다. 하나는 쓰기 전에 읽고 다른 하나는 쓰기 후에 읽으면 의미가 없다.
- Write(X)와 Commit 사이에는 엄격한 순서(strict ordering)가 있다.

## 예시
간단한 트랜잭션: X를 읽고, Y를 읽고, X ← X + Y를 계산해 X를 쓰고 커밋.

- 연산 집합(sigma): `R(X), R(Y), W(X), C`
- 명시된 부분 순서:
  - `R(X) < W(X)`
  - `W(X) < C`
  - `R(X) < C`
  - `R(Y) < C`
- 추이성을 이용하면 `R(X) < C`는 `R(X) < W(X)`와 `W(X) < C`에서 유도되고, `R(Y) < C`도 `R(Y) < W(X)`와 `W(X) < C`에서 유도된다.
- 따라서 훨씬 간단하게 표현할 수 있다: **{R(X), R(Y)} < W(X) < C** — 두 읽기는 어떤 순서든 쓰기보다 먼저, 쓰기는 커밋보다 먼저.
- 읽기끼리는 충돌하지 않으므로 두 읽기의 순서를 서로 바꿔도 데이터베이스에 동일한 효과를 남기는 동일한 트랜잭션이 된다.

## 요약
- 트랜잭션 T_i = 연산(reads/writes)과 종료 조건(commit/abort)의 부분 순서(partial ordering).
- 부분 순서는 비반사적이고 추이적이며, 반드시 지켜야 할 순서만 규정한다.
- 충돌은 read-write와 write-write 사이에만 있으며, 충돌하는 연산 사이에는 순서가 필요하다.
- 트랜잭션은 DAG로 표현할 수 있고, 추이성을 이용해 부분 순서를 간결하게 축약할 수 있다.
- 충돌하지 않는 연산(예: 두 읽기)의 순서를 바꿔도 데이터베이스에 남는 효과는 동일하다.
