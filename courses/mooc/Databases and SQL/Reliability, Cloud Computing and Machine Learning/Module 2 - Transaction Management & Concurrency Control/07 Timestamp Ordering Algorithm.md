# Timestamp Ordering Algorithm

## 개요
- 잠금(lock)이 아니라 타임스탬프(timestamp)에 기반한 동시성 제어 알고리즘인 타임스탬프 순서화(timestamp ordering) 알고리즘을 다룬다.
- 오래된(older) 트랜잭션이 새로운(newer) 트랜잭션보다 먼저 실행된 것처럼 보여야 한다는 원칙에 기반한다.
- 스케줄러는 연산을 뒤섞어 스케줄링할 수 있으며, 충돌(conflict)이 발생하면 알고리즘이 트랜잭션을 중단·재시작(abort and restart)시킨다.
- 읽기 2가지 + 쓰기 3가지, 총 5단계(5 steps)의 결정으로 구성된다.

## 내용

### 기본 전제
- 이 설명에서 T1이 T2보다 오래되었다고 가정한다. 타임스탬프가 더 오래되었으므로 T1이 T2보다 먼저 실행되는 것처럼 보여야 한다.
- 스케줄러가 충돌하지 않는 한 T2의 일부 연산을 T1보다 먼저 스케줄링해도 괜찮다.
- 충돌이 생기면 알고리즘이 멈추게 하고, 트랜잭션을 중단시킨 뒤 더 새로운 타임스탬프로 재시작한다.

### 읽기 규칙 1 — 오래된 트랜잭션이 새 트랜잭션이 쓴 값을 읽으려 할 때 (중단)
- T1(오래됨)이 객체 X를 읽으려 한다. 그런데 T2(새로움)가 이미 X에 값을 썼다.
- 원래 T2의 쓰기는 T1이 X를 읽은 후에 일어났어야 하는데, 스케줄러가 T2의 쓰기를 T1의 읽기보다 앞에 배치했다.
- 판정: T1 연산(트랜잭션)의 타임스탬프가 쓰기 타임스탬프(write timestamp)보다 작으면, 더 새로운 연산이 이미 이 값을 썼다는 뜻이다.
- 이 경우 T1이 잘못된 값을 읽는 것처럼 보이므로, **T1은 중단하고 훨씬 더 새로운 타임스탬프로 재시작**한다.

### 읽기 규칙 2 — 새 트랜잭션이 오래된 트랜잭션이 쓴 값을 읽을 때 (정상)
- 이번엔 T1이 T2보다 새롭다(T2가 오래됨). T2가 먼저 실행되는 것처럼 보여야 한다.
- 오래된 T2가 이미 값을 썼고, 새로운 T1이 그 값을 읽으려 한다.
- 오래된 트랜잭션이 수정한 값을 읽는 것이므로 **정상적으로 계속 진행**된다.

### 쓰기 규칙 1 — 오래된 트랜잭션이 새 트랜잭션이 이미 읽은 값을 쓰려 할 때 (중단)
- T1(오래됨)이 값을 쓰려 하는데, T2(새로움)가 이미 그 값을 읽었다.
- 원래 T2는 오래된 T1이 쓴 값을 읽었어야 하는데, T2가 먼저 읽어버려(jumped the gun) T1보다 더 오래된 어떤 트랜잭션이 쓴 값을 읽었다.
- 판정: T1이 지금 쓰면 이미 값을 읽은 새 트랜잭션 T2를 망치게 된다. 가장 최근의 읽기(most recent read)와 충돌하므로 **T1을 중단**한다.

### 쓰기 규칙 2 — Thomas의 쓰기 규칙(Thomas's Write Rule) (쓰기 무시)
- T1이 T2보다 오래되어 T1의 쓰기가 T2의 쓰기보다 먼저 일어나야 한다.
- 그러나 T2는 어떤 값도 읽지 않았다. 이전 값에 대한 지식 없이 그냥 어떤 값을 데이터베이스에 강제로 써 넣는다.
- 스케줄러가 T2의 쓰기를 T1의 쓰기보다 먼저 배치했다. T2가 이미 값을 썼고, 이제 T1이 쓰기를 시도한다.
- 판정: T2가 읽기를 전혀 시도하지 않았으므로, T1이 지금 무엇을 쓰든 어차피 T2에 의해 덮어쓰였을 것이다. 따라서 **T1은 자신의 쓰기를 무시(ignore)하고 트랜잭션을 계속** 진행한다. 이것이 Thomas의 쓰기 규칙(Thomas's write rule)이다.

### 쓰기 규칙 3 — 새 트랜잭션이 오래된 트랜잭션의 읽기·쓰기 뒤에 쓸 때 (정상)
- T2(오래됨)가 값을 읽고 썼고, T1(새로움)이 뒤이어 쓰기를 수행하려 한다.
- 새로운 트랜잭션이므로 **정상적으로 쓸 수 있다**.

## 예시

### Thomas의 쓰기 규칙 상세 예시
- T1은 오래된 트랜잭션, T2는 새로운 트랜잭션. 원래 순서라면 T1이 먼저, T2가 나중에 실행되어야 한다.
- 스케줄러가 연산을 뒤섞는다:
  - T1: 어떤 값을 읽고(read) → 값을 쓰려(write) 한다.
  - T2: T1의 쓰기보다 먼저 자신의 쓰기를 수행한다. T2는 오래된 트랜잭션이 쓴 값을 읽은 적이 없으며, 일방적으로(unilaterally) 데이터베이스의 값을 덮어썼다.
- 이제 T1이 값을 쓰려 하면: "새로운 트랜잭션 T2가 이미 일방적 쓰기를 했으니, 내 쓰기는 어차피 T2에 의해 대체될 것이다"라고 판단하고 자신의 쓰기를 무시한다.

## 요약
- 타임스탬프 순서화 알고리즘은 잠금이 아니라 타임스탬프로 동시성을 제어한다. 오래된 트랜잭션이 먼저 실행된 것처럼 보여야 한다.
- 읽기 2가지, 쓰기 3가지로 총 5단계 결정을 한다.
- 읽기: 오래된 T가 새 T의 쓰기 값을 읽으려 하면 중단; 새 T가 오래된 T의 값을 읽으면 정상.
- 쓰기: 오래된 T가 새 T가 읽은 값을 쓰려 하면 중단; T2가 읽지 않고 덮어쓴 경우 Thomas의 쓰기 규칙으로 쓰기 무시; 새 T가 오래된 T 뒤에 쓰면 정상.
- 충돌 시 트랜잭션을 중단하고 더 새로운 타임스탬프로 재시작한다.
