# Role-playing Dimensions and USERELATIONSHIP

## 개요
- 하나의 디멘션이 여러 의미로 팩트와 연결되는 역할 수행 디멘션과 비활성 관계를 계산에 사용하는 방법을 다룬다.

## 내용

### 역할 수행 디멘션
- 하나의 디멘션이 동일한 팩트에서 여러 역할을 맡는 구조다.
- 대표적으로 날짜 디멘션 하나가 주문일, 배송일, 결제일을 모두 설명할 수 있다.
- Power BI에서는 두 테이블 사이의 여러 관계 중 하나만 기본 활성 관계로 사용할 수 있고 나머지는 비활성 관계가 된다.

### 활성·비활성 관계
- 활성 관계는 일반 분석, 보고서, 시각화에서 기본 필터 경로로 사용된다.
- 비활성 관계도 유효한 연결이지만 명시적으로 활성화하기 전에는 필터 전파에 사용되지 않는다.
- 역할마다 디멘션을 복제하지 않고도 모델 크기와 관리 중복을 줄일 수 있다.

### USERELATIONSHIP
- `CALCULATE` 안에서 지정한 비활성 관계를 현재 측정값에만 사용한다.
- 모델의 기본 활성 관계를 영구적으로 바꾸지 않으므로 주문일 기반 분석과 배송일 기반 분석을 나란히 제공할 수 있다.

## 예시
```DAX
Sales by Shipping Date =
CALCULATE(
    SUM(Sales[SalesAmount]),
    USERELATIONSHIP(Sales[ShippingDate], Date[Date])
)
```

## 요약
- 역할 수행 디멘션은 하나의 차원을 여러 비즈니스 의미로 재사용한다.
- `USERELATIONSHIP`은 특정 계산에서만 비활성 관계를 켜서 기본 모델을 유지하면서 다른 관점의 분석을 가능하게 한다.
