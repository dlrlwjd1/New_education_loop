# Building a Snowflake Schema in Power BI

## 개요
- 디멘션 테이블을 정규화해 계층을 만드는 스노우플레이크 스키마를 Power BI에서 구성하고 스타 스키마와 비교한다.

## 내용

### 스노우플레이크 구조
- 중앙 팩트에 디멘션을 직접 연결하는 스타 스키마에서 한 단계 더 나아가, 큰 디멘션을 여러 관련 테이블로 분리한다.
- 예를 들어 제품 정보를 `Category → Subcategory → Product → Sales` 계층으로 구성한다.
- 각 단계는 일대다 관계로 연결되며 상위 범주의 필터가 하위 테이블을 거쳐 판매 팩트까지 전파된다.

### 장점과 비용
- 중복 데이터를 줄여 저장 효율과 데이터 무결성을 높인다.
- 명시적인 계층은 데이터 거버넌스와 확장성에 도움이 된다.
- 관계와 필터 경로가 늘어 모델·쿼리·유지보수가 스타 스키마보다 복잡해질 수 있다.

### Power BI 구성 절차
1. 관계 자동 검색을 끄고 `Category`, `Subcategory`, `Products`, `Region`, `Sales`, `Salespersons`를 적재한다.
2. 기본 키와 외래 키를 이용해 팩트와 디멘션 관계를 만든다.
3. 제품 관련 테이블을 `Category`, `Subcategory`, `Products` 관계로 연결해 계층을 구성한다.
4. 기존 스타 스키마를 변환할 때는 Power Query나 DAX 새 테이블을 이용해 큰 디멘션의 반복 속성을 분리하고 관계를 다시 설정한다.

## 예시
- 제품 범주를 선택하면 해당 필터가 하위 범주와 제품을 거쳐 판매 팩트까지 전달된다. 이를 통해 범주·하위 범주·개별 제품 수준의 분석을 하나의 계층으로 수행한다.

## 요약
- 스노우플레이크 스키마는 디멘션을 정규화해 중복을 줄이고 계층을 명확히 한다.
- 데이터 무결성과 거버넌스에는 유리하지만 관계 복잡성과 쿼리 비용을 고려해야 한다.
