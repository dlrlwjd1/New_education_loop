# Data Schema Types

## 개요
- Power BI 데이터 모델의 논리 구조인 스키마와 플랫·스타·스노우플레이크 스키마의 장단점을 비교한다.

## 내용

### 스키마
- 스키마는 데이터셋 안에서 테이블이 어떻게 조직되고 연결되는지 나타내는 논리 구조다.
- 잘 설계된 스키마는 데이터 무결성, 쿼리 성능, 탐색 가능성을 높인다.

### 플랫 스키마
- 한 비즈니스 엔터티와 관련된 필드가 하나의 넓은 테이블에 저장된다.
- 구조가 단순해 작은 데이터셋의 조회·시각화에는 편리하다.
- 데이터가 커지면 중복과 불일치가 늘고 유지보수와 쿼리 성능이 나빠질 수 있다.

### 스타 스키마
- 중앙 팩트 테이블이 여러 디멘션 테이블과 직접 연결된다.
- 관계 구조가 단순하고 이해하기 쉬우며, 중복을 줄이고 쿼리 성능을 개선한다.
- 판매 팩트 주위에 고객·제품·날짜 디멘션을 두는 형태가 대표적이다.

### 스노우플레이크 스키마
- 스타 스키마의 디멘션을 다시 정규화하여 여러 관련 테이블로 분리한다.
- 중복을 더 줄이고 계층, 무결성, 확장성을 명확하게 표현한다.
- 조인과 관계가 많아져 모델 이해와 쿼리 작성이 복잡해질 수 있다.

### 스키마 검증
- 열의 데이터 형식과 표시 형식을 확인한다.
- 테이블·열에 명확한 이름과 설명을 부여한다.
- 테이블 및 열 속성과 관계가 의도대로 설정됐는지 검증한다.

## 예시
- 제품 테이블의 범주와 하위 범주를 그대로 두면 스타 스키마이고, `Product Category`와 `Product Subcategory` 테이블로 분리해 계층을 만들면 스노우플레이크 스키마가 된다.

## 요약
- 플랫 스키마는 단순성, 스타 스키마는 분석 성능과 이해 용이성, 스노우플레이크 스키마는 정규화와 계층 표현에 강점이 있다.
- 데이터 규모, 분석 요구, 유지보수 비용을 기준으로 스키마를 선택한다.
