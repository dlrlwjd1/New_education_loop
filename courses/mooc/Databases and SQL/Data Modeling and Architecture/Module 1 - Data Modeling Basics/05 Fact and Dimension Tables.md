# Fact and Dimension Tables

## 개요
- 분석 스키마의 핵심 구성 요소인 팩트·디멘션 테이블과 정규화·비정규화의 트레이드오프를 이해한다.

## 내용

### 팩트 테이블
- 판매액, 수량, 매출처럼 집계할 수 있는 수치와 비즈니스 사건을 저장한다.
- 각 거래의 디멘션 키를 보유하며 합계·평균·건수 같은 계산의 중심이 된다.

### 디멘션 테이블
- 제품명, 날짜, 고객 인구통계처럼 팩트에 맥락을 제공하는 설명 데이터를 저장한다.
- 범주·기간·고객군별로 팩트를 필터링하고 나누어 볼 수 있게 한다.
- 스타 스키마에서는 디멘션이 팩트와 직접 연결되고, 스노우플레이크 스키마에서는 디멘션이 더 작은 관련 테이블로 분해된다.

### 정규화
- 데이터를 목적별 테이블로 분리하고 기본 키·외래 키로 연결해 중복을 줄인다.
- 데이터 무결성, 저장 효율, 논리적 가독성이 좋아지는 대신 관계와 조인이 복잡해진다.

### 비정규화
- 관련 정보를 한 테이블에 합쳐 조인을 줄이고 읽기·보고 성능을 높인다.
- 쿼리와 접근은 단순해지지만 데이터 중복, 저장 공간, 변경 일관성 관리 비용이 증가한다.
- Power Query의 테이블 분리·병합 기능으로 두 방향의 변환을 수행할 수 있다.

## 예시
- 정규화 모델에서는 `Sales(ProductID, SalesTotal)`가 `Product(ProductID, Name, Description)`를 참조한다.
- 비정규화 모델에서는 판매 행마다 `ProductName`과 `ProductDescription`을 함께 저장하여 조인을 없애지만 제품 정보가 반복된다.

## 요약
- 팩트는 측정할 사건과 수치를, 디멘션은 그 사건을 설명할 맥락을 담는다.
- 정규화는 무결성과 중복 제거에, 비정규화는 읽기 성능과 단순성에 유리하다.
- 분석 요구, 모델 크기, 데이터 원본, 성능 목표를 함께 고려해 균형을 선택한다.
