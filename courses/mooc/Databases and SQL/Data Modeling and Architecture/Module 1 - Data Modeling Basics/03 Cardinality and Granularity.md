# Cardinality and Granularity

## 개요
- 테이블 관계의 카디널리티와 데이터 세분성(granularity)이 Power BI 분석 정확도에 미치는 영향을 다룬다.

## 내용

### 카디널리티
- 카디널리티는 두 테이블의 레코드가 서로 연결되는 방식을 정의한다.
- 설정이 실제 데이터의 고유성과 반복 구조를 반영하지 않으면 중복 집계나 누락된 필터 결과가 발생할 수 있다.

### 관계 유형
- **일대일(1:1)**: 양쪽 테이블의 각 값이 하나씩만 대응한다. 예: 고객 ID와 고객별 고유 세금 ID.
- **일대다(1:N)**: 한쪽의 고유 레코드가 다른 쪽의 여러 레코드와 연결된다. 예: 한 매장과 여러 직원. 관계를 어느 방향에서 읽는지에 따라 다대일이라고도 한다.
- **다대다(N:M)**: 양쪽의 여러 레코드가 서로 연결된다. 예: 여러 판매원이 여러 제품을 판매하는 관계.

### 세분성
- 세분성은 데이터가 표현하는 상세 수준이다.
- 높은 세분성은 개별 거래·매장·제품처럼 상세한 분석을 지원하지만 데이터량과 모델 복잡도가 커진다.
- 낮은 세분성은 월별·지역별 합계처럼 빠른 요약 분석에 적합하지만 세부 패턴을 잃을 수 있다.
- 모델의 세분성은 답하려는 비즈니스 질문과 맞아야 하며, 카디널리티와 교차 필터 방향을 설계할 때 함께 고려해야 한다.

## 예시
- 특정 지역에서 어떤 자전거 모델이 잘 팔리는지 분석하려면 제품·매장·거래 수준의 높은 세분성이 필요하다. 전체 월매출 추세만 필요하다면 월 단위 집계 데이터로도 충분하다.

## 요약
- 카디널리티는 테이블 연결 규칙이고 세분성은 데이터의 상세 수준이다.
- 관계 유형과 세분성을 실제 비즈니스 질문에 맞춰야 정확한 필터링과 집계가 가능하다.
