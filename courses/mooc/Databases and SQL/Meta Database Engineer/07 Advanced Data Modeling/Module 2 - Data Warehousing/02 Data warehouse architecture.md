# Data warehouse architecture

## 개요

- 데이터 웨어하우스 아키텍처의 구성 요소(데이터 소스 → 스테이징 → 저장 → 데이터 마트 → 분석·보고)와 설계 모범 사례

## 내용

### 아키텍처의 목적

- 여러 소스로부터의 **데이터 흐름을 통제**하고, 데이터를 처리해 **일관된 형식으로 통합**해, 사용자가 분석으로 인사이트를 뽑을 수 있게 한다.

### 구성 요소

1. **데이터 소스(data sources)**
   - 외부 소스: 온라인 설문, 소셜 미디어 데이터
   - 내부 소스: 사내 데이터베이스의 고객·상품 정보
   - 운영 데이터: 고객 주문 등 일상 업무에서 생성
   - 플랫 파일(flat file): 내부 구조가 없는 파일 (온라인 행동 로그 등)
   - 소스의 **정확성**을 확보해야 부실한 분석을 피할 수 있다
2. **데이터 스테이징(data staging)** — **ETL**(Extract, Transform, Load) 파이프라인 프로세스 집합
3. **데이터 저장(data storage)** — 웨어하우스의 기반이 되는 중앙 저장소, 관계형 데이터베이스로 조직
   - **메타데이터 저장소** 포함 — 데이터의 "목차": 출처, 데이터 특징, 저장 테이블·속성, 파일 생성 시점·생성자 등. 소스 시스템·방법·프로세스의 변경 추적에 사용
4. **데이터 마트(data marts)** — 특정 사용자 그룹의 요구에 맞춘 **주제 지향 데이터베이스**. 부서·업무 기능별 데이터 부분집합으로 집중 분석 수행
5. **데이터 분석·표현** — 데이터 마이닝 등 기법으로 분석 후 보고서(인터랙티브·분석·정적 리포트)로 표현

### 모범 사례

- 분석 연산과 트랜잭션 연산을 분리
- 확장 가능한(scalable) 솔루션 사용 — 데이터 증가 대응
- 새 기능을 수용할 수 있는 유연한 아키텍처
- 데이터 보안 기능 포함
- 다양한 데이터 형식을 다루는 단순·유연한 구조
- 이해·구현·사용·관리가 쉬운 웨어하우스
- 개발 과정 문서화 — 기능 추가가 쉬워짐

## 요약

- 아키텍처는 소스 → ETL 스테이징 → 중앙 저장(+메타데이터) → 데이터 마트 → 분석·보고 흐름으로 구성된다.
- 데이터 마트는 부서별 집중 분석용 부분집합, 메타데이터는 데이터의 목차 역할이다.
- 분리·확장성·유연성·보안·문서화가 설계의 핵심 원칙이다.
