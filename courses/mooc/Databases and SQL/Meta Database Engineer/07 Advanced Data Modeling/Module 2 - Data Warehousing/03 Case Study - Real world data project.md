# Case Study: Real world data project

## 개요

- Meta 소프트웨어 엔지니어(Moxxy Herrera)가 실무 관점에서 ETL 파이프라인의 목적·설계 판단·운영 과제를 설명하는 사례 강의

## 내용

### ETL 파이프라인이 필요한 이유

- 초대형 데이터베이스에서는 데이터를 직접 꺼내기 어렵다 — ETL 파이프라인이 제품(소비자)들이 필요한 데이터에 더 빨리 접근하게 하는 핵심 수단.
- 구조: 데이터 소스 → 스테이징 영역 → 데이터 소비자(consumer).
- 소비자를 분리하면 (1) 원시 데이터를 웨어하우스에 백업 보관하고 (2) 사용 시점에 필요한 형태로 변환해 적재할 수 있다.

### ETL 각 단계

- **Extract** — 여러 데이터 소스를 한데 모음
- **Transform** — 데이터 검증(validation), 스크러빙·클리닝, 필요하면 암호화
- **Load** — 최종 소비자가 실제로 데이터를 가져가는 단계

### 설계 판단

- 목적은 서로 다른 시스템에서 만들어진 소스들을 특정 소비자가 쓸 수 있는 하나의 시스템으로 모으는 것 — **병렬화(parallelization)** 가 가능해진다.
- 설계 질문: 최종 소비자에게 무엇이 필요한가? 데이터를 어디서 가져오는가? 어떻게 조직해야 가장 성능이 좋은가?

### 운영 과제

- 가장 흔한 문제는 **데이터 볼륨** 처리 — 파이프라인이 최신 상태인지, 사용 시점에 필요한 데이터가 실제로 있는지 보장하기 어렵다.
- **지연(delay)** 을 이해해야 소비자가 아직 없는 데이터를 기대하지 않게 된다.
- 데이터베이스 변경은 파이프라인 변경을 촉발할 수 있다 — 파이프라인의 목표에 대한 이해와 이해관계자의 **강한 오너십**이 필요하다.

## 요약

- ETL(추출·변환·적재)은 빅데이터·클라우드 시대의 근본 프로세스로, 다양한 소스를 소비자 중심 시스템으로 통합한다.
- 설계는 소비자 요구·소스·성능을 중심으로 결정하고, 볼륨·지연·상류 변경에 대응하는 오너십이 운영의 핵심이다.
