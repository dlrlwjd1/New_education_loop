# Fundamentals of dimensional data modeling

## 개요

- 데이터 웨어하우스 분석용 모델인 차원 데이터 모델(dimensional data model)의 핵심 개념(차원·팩트)과 스타/스노플레이크 스키마

## 내용

### 차원 데이터 모델이란

- ER·객체지향 모델은 실시간 트랜잭션용 — 웨어하우스·분석에는 **특정 분석을 위한 데이터 접근·질의 최적화** 모델이 필요.
- 두 핵심 개념: **차원(dimension)** 과 **팩트(fact)**.

### 차원과 팩트

- **차원** — 데이터의 요소들로, 측정값의 맥락(perspective)을 정의. 예: 시간, 위치 — 매출을 시간·위치 맥락에서 측정
- **팩트** — 정량화 가능한 데이터. 예: 판매 수량, 이익
- 팩트 테이블의 측정값 2종:
  - **저장 측정값(stored measures)** — 소스에서 적재되어 저장된 집계값 (매출 데이터, 상품 가격)
  - **계산 측정값(calculated measures)** — 다른 측정값에서 계산 (이익 = 판매가 − 원가). 웨어하우스에 프로그래밍된 계산 규칙 기반 질의로 수행

### 구조

- **차원 테이블** — 차원 요소를 담고 **계층(hierarchy)** 으로 구조화 가능 → 여러 수준의 분석 지원
- **팩트 테이블** — 측정값 데이터 보유
- 계층을 따라 **드릴다운(drill down)/롤업(roll up)**: 연도·도시별 평균 매출 → 월별 → 주·일별로 내려가며 탐색

### 설계 모범 사례

- 분석할 비즈니스 활동을 먼저 명확히 하고, 가장 의미 있는 맥락을 주는 차원을 파악한다.
- 이해·접근·질의가 쉬운 방식으로 데이터를 조직한다.

### 스타 스키마 (star schema)

- 가장 널리 쓰이는 스키마 — 팩트·차원 테이블을 **별 모양**으로 배치한 단순 모델.
- 하나 이상의 팩트 테이블이 중앙에, 차원 테이블들이 주위에 연결. 예: 중앙 sales 팩트 ↔ suppliers, customer, product, time, location 차원

### 스노플레이크 스키마 (snowflake schema)

- 다이어그램이 눈송이를 닮은 스키마 — **차원 테이블을 정규화**해 중복 제거.
- 차원 데이터를 여러 단순 하위 차원(sub-dimension) 테이블로 분리. 예: product 차원 → products·subcategory·category 3개 테이블
- 단점: 차원 테이블·외래 키가 늘고, 분석 시 조인 질의가 복잡해진다.

## 요약

- 차원 모델은 차원(맥락)과 팩트(측정값)로 분석용 데이터베이스를 설계한다.
- 측정값은 저장형과 계산형이 있고, 차원 계층으로 드릴다운/롤업 분석을 한다.
- 스타 스키마는 단순·비정규형, 스노플레이크 스키마는 정규화로 중복을 줄이는 대신 조인이 복잡해진다.
