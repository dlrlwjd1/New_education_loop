# How is data modeling used at Meta?

## 개요

- Meta 엔지니어 Moxxy가 들려주는 실무 데이터 모델링 — 상황별 프로세스, 책임 있는 데이터 사용, 대규모 조율

## 내용

### 모델링에는 만능 프로세스가 없다

- 신제품의 새 데이터 모델 개발과, 구제품에 새 기능·규제 준수를 위해 개조(retrofit)하는 것은 **완전히 다른 프로세스** — 상황의 요구에 맞춰 조정해야 한다.
- 주도자도 맥락에 따라 다르다: 신제품이면 리드 엔지니어가 제품의 고수준 요구를 논의하며 주도, 사용자 프라이버시·특정 기능 때문이라면 담당 엔지니어나 규제 프로세스 관련자가 주도.
- Meta의 특징: **모든 엔지니어가 논의에 참여하고 바꿀 권한이 있다** — 첫 모델은 리드가 설계해도 모두가 개선 의견을 내놓을 것이 기대된다.

### 책임 있는 데이터 사용

- 접근 가능한 데이터가 많기에 **필요한 데이터만, 승인을 받아** 사용하는 것이 큰 도전이다.
- 데이터의 출처, 사용 방식, 저장 방식, **보관 기간**까지 정당화해야 하며, 그 회의에 철저히 준비되어야 한다.

### 대규모 변경 관리

- 데이터베이스 변경 관리에는 보안 저장·신뢰성·폴백 등 고려사항이 많고, 코드·데이터베이스 변경의 배포를 관리하는 **전담 팀들이 다수** 존재한다.
- 수십억 사용자의 시스템은 한 사람이 유지할 수 없다 — 데이터베이스는 모든 제품의 공통 지점이므로 변경에 신중하고 여러 팀과 조율해야 한다.

### 조언

- 데이터를 **왜 얻고, 어떻게 저장하고, 어떻게 보호할지** 깊이 생각하라 — 특히 사용자 정보라면 맡겨진 신뢰를 생각해야 한다.
- 어려운 질문과 트레이드오프를 다뤄야 하며, 모델은 한 사람이 설계해도 성공적인 데이터베이스는 수많은 기술·비기술 파트너와의 조율로 만들어진다.

## 요약

- 데이터 모델링 프로세스는 신규 개발이냐 개조냐에 따라 다르고, 주도자도 맥락에 따라 달라진다.
- 데이터의 출처·사용·저장·보관을 정당화하는 책임성이 핵심이며, 대규모 시스템은 다팀 조율로 유지된다.
- 데이터베이스 연동은 거의 모든 직무에 필요한 기본기다.
