# Types of data models

## 개요

- 데이터 모델 5유형(관계형·엔터티 관계·계층적·객체지향·차원)의 특징과 장단점 비교

## 내용

### 관계형(relational) 모델

- 데이터베이스를 **릴레이션(테이블)의 모음**으로 표현 — 행·열 저장.
- 장점: 다른 모델보다 단순, 빠른 식별·접근 / 단점: 복잡한 시스템에서 관계 탐색이 어려워지고 분석에는 별도 구조화가 필요할 수 있다.

### 엔터티 관계(ER) 모델

- 관계형과 유사하나 **각 테이블을 고유 속성을 가진 별도 엔터티**로 표현.
- 1:1, 1:N, M:N 등 다양한 관계를 다룬다. 예: clients-orders를 client ID로 잇는 1:N.

### 계층적(hierarchical) 모델

- **트리(부모-자식) 구조** — 각 레코드는 부모 노드를 갖고 자식 노드를 가질 수 있다.
- 단점: **1:N 관계만 기록 가능** — 자식 노드는 부모를 하나만 가질 수 있다. 예: 루트에 클라이언트, 그 아래 주문 노드들.

### 객체지향(object-oriented) 모델

- 객체를 특성·행동을 정의하는 **클래스로 번역.**
- 장점: 집약(aggregation)·합성(composition)·**상속** 등 다양한 연관 정의 가능 — 객체지향 접근이 필요한 복잡한 프로젝트에 적합.
- 상속 활용 예: PersonEntity 부모 클래스의 속성·연산을 Staff·Client 클래스가 물려받음. 단, OOP 원리와 프로그래밍 역량이 필요하다.

### 차원(dimensional) 모델

- 두 핵심 개념: **사실(fact)** = 프로세스에서 얻는 측정값(예: 판매 수량), **차원(dimension)** = 측정의 맥락(예: 판매 기간).
- 장점: **빠른 데이터 검색에 최적화**되고 효율적 분석을 위한 재구조화 — 이후 강의에서 상세히 다룬다.

## 요약

- 모델 선택은 비즈니스의 데이터 요구에 달렸다: 단순·범용은 관계형/ER, 트리형 1:N은 계층적, 복잡한 객체 연관은 객체지향, 분석·검색 최적화는 차원 모델이다.
