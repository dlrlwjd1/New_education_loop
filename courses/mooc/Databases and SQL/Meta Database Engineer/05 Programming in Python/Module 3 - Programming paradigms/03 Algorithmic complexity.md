# Algorithmic complexity

## 개요

- 리팩터링(refactoring)과 코드 성능 측정 — 시간(time)과 공간(space)
- Big O 표기법의 5가지 시간 복잡도: 상수·선형·로그·이차·지수

## 내용

### 왜 복잡도를 재는가

- 리팩터링(코드를 관리하기 쉽고 효율적으로 재작성)은 개발 주기의 표준 단계다.
- 더 빠르고 성능 좋게 만들려면 **측정**이 필요하다 — 코드는 **시간(얼마나 걸리나)과 공간(메모리를 얼마나 쓰나)** 으로 측정한다.
- **Big O 표기법**은 시간·공간 효율을 "최악부터 최상까지" 범주로 나눠 측정한다.

### 5가지 시간 복잡도

1. **상수 시간(constant time)** — 크기와 무관하게 항상 같은 시간·공간. 예: 딕셔너리 — 키가 값을 직접 가리키므로 반복 탐색이 필요 없다.
2. **선형 시간(linear time)** — 입력 크기에 비례해 증가. 범위 100 배열은 빠르지만 100만이면 훨씬 오래 걸린다.
3. **로그 시간(logarithmic time)** — 입력 대비 연산 수의 비율. 예: 100개 중 97 찾기 — 선형은 96회 반복, **이진 탐색(binary search)** 은 목록을 절반씩 갈라 검사해 약 7회 만에 찾는다.
4. **이차 시간(quadratic time)** — 입력 각각에 대한 선형 연산의 제곱 — 대개 **중첩 루프**. 바깥 10회 × 안쪽 10회 = 총 100회 반복.
5. **지수 시간(exponential time)** — 반복마다 두 배로 증가. 피보나치 수열이 대표 사례.

## 예시

```python
# 상수: 딕셔너리 키 조회
d = {'a': 1}; d['a']

# 선형: 리스트 전체 순회
for x in numbers: ...

# 이차: 중첩 루프 (10 × 10 = 100회)
for i in range(10):
    for j in range(10): ...
```

## 요약

- 코드 성능은 시간·공간으로 측정하고 Big O로 범주화한다.
- 상수(딕셔너리) < 로그(이진 탐색) < 선형(단일 루프) < 이차(중첩 루프) < 지수(피보나치) 순으로 비용이 커진다.
- 복잡도 이해가 리팩터링·최적화의 기초다.
