# What is procedural programming?

## 개요

- 절차적 프로그래밍(procedural programming) — 코드를 절차(프로시저/서브루틴)로 구조화하는 패러다임
- DRY 원칙과 절차적 접근의 장단점

## 내용

### 프로그래밍 모델(패러다임)

- Python은 **객체지향·절차적·함수형** 모델을 모두 허용한다.
- 모델의 목적은 **코드의 구조화** — 갱신과 기능 추가를 쉽게 만든다. 완벽한 단일 모델은 없으며 **조합이 최선**일 때도 있다.

### 절차적 프로그래밍이란

- 코드를 **프로시저(서브루틴, 기능 단위 코드 구역)** 로 구조화 — 특정 과업을 완수하는 논리적 단계들로 코드가 구성된다.
- 예: 5+10을 더하는 코드를 그대로 두고 8+4용 코드를 또 만들면 비효율 → **함수 sum(a, b)** 로 바꾸면 어떤 숫자 쌍에도 재사용된다.

### DRY 원칙

- **Don't Repeat Yourself** — 코드 중복 줄이기. 애플리케이션 전반에서 재사용할 함수를 만드는 것이 지침이다.

### 계산서 예제 — 프로시저의 상호 재사용

- bill_total(청구 항목을 순회해 합계 반환) → calculate_tax(비율·합계를 받아 세금 반환, 소수 2자리 반올림) → food_bill(고객 청구 데이터) → 마지막에 두 함수를 호출해 합계·세금·총액 출력.
- 코드 발자국이 줄어드는 구조: tax_total은 food_total을, food_total은 bill_total과 food_bill을, calculate_tax는 bill_total을 재사용한다.

### 장단점

- **장점**: 초보자가 배우기 쉽다 / 프로시저를 다른 코드가 재사용 / 프로시저가 과업별로 나뉘어 이해 쉬움
- **단점**: 유지보수·확장이 어려울 수 있다 / 실세계 객체와 잘 대응되지 않는 경우가 있다 / **데이터가 프로그램 전체에 노출**된다

## 요약

- 절차적 프로그래밍은 과업을 프로시저로 나눠 단계적으로 실행하는 구조로, 객체지향으로 가는 디딤돌이다.
- DRY 원칙에 따라 재사용 가능한 함수를 만들면 코드 중복이 준다.
- 배우기 쉽고 이해가 쉬운 반면, 유지보수·데이터 노출 측면의 한계가 있다.
