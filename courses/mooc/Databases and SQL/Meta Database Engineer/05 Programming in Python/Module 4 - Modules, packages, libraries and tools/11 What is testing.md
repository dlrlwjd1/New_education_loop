# What is testing?

## 개요

- 소프트웨어 테스팅의 정의와 필요성, 좋은 테스트의 관행, 테스팅 생애주기와 종료 판단 기준

## 내용

### 테스팅이란

- **성능·정확성·완전성 측면에서 소프트웨어를 평가·검증하는 과정** — 버그, 제품의 공백, 결함, 누락된 요구사항을 찾아낸다.
- 역사: 초기에는 디버깅에 의존 → 1980년대 이후 소프트웨어가 커지며 다양한 테스트 유형이 발전 → 과거엔 후반 단계에서만 하던 테스트가 이제 **초기 단계부터 통합**된다.
- 이상적 시나리오: **가장 적은 테스트로 가장 많은 결함을 찾는 것.** 웹사이트 트래픽 폭주(확장성)나 폼 데이터 검증(금융·은행에서 특히 중요) 같은 실패를 예방한다.

### 테스팅이 돕는 것

- 나쁜 설계 감지, 비효율적 흐름·기능 변경, 확장성 우려 해결, 보안 취약점 발견
- A/B 테스트로 최적안 선택, 플랫폼·기기 호환성 대응, 이해관계자 안심, 최종 사용자 경험 향상

### 좋은 관행

- 테스트 코드의 **재사용성** 확보 / 테스트는 요구사항으로 **추적 가능**해야 / **목적 지향적·효율적·반복 가능**하게 작성

### 생애주기와 테스트 케이스

- 큰 흐름: **계획 → 준비 → 실행 → 보고** — 스크립트·테스트 케이스 작성, 결과 수집, 결함 수정, 보고서 생성.
- **테스트 케이스** = 특정 목적을 위해 단계·데이터·사전/사후 조건을 담은 동작 집합. 잘 쓰면 커버리지·재사용성·UX 향상과 비용 절감을 가져온다.

### 분류와 종료 기준

- 내부 구현을 아는 정도에 따라 **블랙박스/화이트박스** 테스트로 구분. 호환성·애드혹·사용성·회귀(regression) 테스트 등 다양한 유형이 있고 **만능 해법은 없다** (웹페이지와 Android 게임의 테스트 요구가 다르듯).
- **언제 멈출지**도 중요 — 100% 완벽한 애플리케이션은 없다. 기준(메트릭): 테스트 사이클 수, 테스트 케이스 통과율, 시간 기한, 연속 실패 사이의 간격.

## 요약

- 테스팅은 성능·정확성·완전성을 검증해 결함을 찾는 품질 보증의 핵심이다.
- 계획→준비→실행→보고의 주기로 진행하며, 재사용·추적 가능·목적 지향의 원칙을 따른다.
- 상황별 테스트 유형을 고르고, 통과율·사이클 수 같은 메트릭으로 종료를 판단한다.
