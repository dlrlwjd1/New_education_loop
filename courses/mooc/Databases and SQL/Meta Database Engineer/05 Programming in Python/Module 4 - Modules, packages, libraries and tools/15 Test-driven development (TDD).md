# Test-driven development (TDD)

## 개요

- 테스트 주도 개발(TDD) — 테스트를 먼저 쓰고 그 테스트를 통과하도록 코드를 쓰는 방식
- 레드-그린-리팩터 사이클과 TDD의 이점

## 내용

### 왜 TDD인가

- 관행적으로 테스트는 코드 작성 후 남는 시간에 밀려 들어가 충분치 못했고, 그 결과 버그가 남는다.
- TDD는 반대로 **테스트를 먼저 작성**하고 코드는 테스트를 통과하도록 쓴다. 반복적(iterative) 접근이며, 팀의 기능·테스트 계획이 선행된다.

### 표준 5단계 (레드-그린-리팩터 사이클)

1. 실패할 기능 테스트를 작성한다
2. 테스트에 맞춰 코드를 작성한다
3. 실패를 예상하며 테스트를 실행한다
4. 오류를 평가하고 코드를 리팩터링한다
5. 프로세스를 재실행한다
- **레드 = 실패한 테스트, 그린 = 리팩터링 후 통과.** 더 이상 재실행이 필요 없이 모두 그린이면 기능 완성이다.
- 자동화가 중요해지면 Pytest 활용 — unittest는 클래스가 필요하지만 **Pytest는 함수만으로 되어** 더 쉽다.

### 이점

- 테스트를 먼저 쓰므로 **테스트가 코드를 확실히 커버**한다.
- 특정 기능·결과를 염두에 두고 테스트를 쓰게 되어 **처음부터 명확성** 확보.
- 기존 컴포넌트에 맞춰 새 기능·인터페이스를 통합하는 **예측성** 제공.
- 사이클 반복이 리팩터링 자신감을 길러 준다.
- 더 작은 코드, 이른 버그 수정, 확장성, 쉬운 디버깅.

### 전통적 테스트와의 차이·변형

- 핵심 차이: TDD는 **요구사항과 표준이 처음부터 부각**되어 목적이 분명하다. 현대 개발은 단계에 따라 두 방식을 혼용한다.
- 변형: 행위 주도(BDD), 인수 테스트 주도(ATDD), 스케일링 TDD, 개발자 TDD 등.

## 요약

- TDD는 테스트 → 코드 → 실패 → 리팩터 → 재실행의 레드-그린-리팩터 사이클로 진행된다.
- 커버리지·명확성·통합 예측성·리팩터링 자신감이 핵심 이점이다.
- Pytest가 함수 기반이라 TDD 자동화에 손쉽고, 실무에서는 전통 방식과 혼용된다.
