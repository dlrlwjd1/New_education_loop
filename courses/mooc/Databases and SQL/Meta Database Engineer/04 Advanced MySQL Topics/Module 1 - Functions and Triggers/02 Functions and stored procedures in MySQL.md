# Functions and stored procedures in MySQL

## 개요

- 함수와 저장 프로시저의 기본 복습, 이점, 그리고 둘의 핵심 차이(매개변수·반환값·용도)

## 내용

### 공통 목적과 이점

- 두 방법 모두 코드를 함수/프로시저의 본문(body)으로 **감싸(encapsulate)** 식별자 이름 호출만으로 특정 연산을 수행하게 한다.
- 이점: 코드의 **일관성**, **조직화**, **재사용성** — 사용·유지보수가 쉬워진다.

### 복습 예

- **저장 프로시저**: CREATE PROCEDURE로 만들고 CALL로 호출 (Lucky Shrub의 재고 확인 쿼리). 테이블에 데이터가 없으면 NULL 반환.
- **함수**: MOD(7, 5)처럼 SELECT 문 안에서 식별자 이름으로 호출 → 결과 2. **함수는 항상 값을 반환한다** (예: M&G의 고객별 평균 지출 계산).

### 핵심 차이

| | 함수 | 저장 프로시저 |
|---|---|---|
| 매개변수 | **입력(input)만** 가능 | **입력과 출력(output) 모두** 가능 |
| 반환 | 항상 값을 반환 | 출력 매개변수로 값을 되돌릴 수 있음 |
| 적합한 용도 | SQL 문 안이나 다른 함수 안에서 **특정 값 하나를 반환**할 때 | 데이터의 **처리·조작·수정** 작업 |

- 함수·프로시저는 필요한 만큼 만들 수 있으며, 언제 무엇을 쓸지 아는 것이 중요하다.

## 요약

- 함수와 프로시저는 반복 코드를 캡슐화해 재사용하는 수단이다.
- 함수는 입력 매개변수만 받고 항상 값을 반환하며 값 하나가 필요한 곳에 적합하다.
- 프로시저는 입·출력 매개변수를 모두 가질 수 있고 데이터 처리·조작·수정에 적합하다.
