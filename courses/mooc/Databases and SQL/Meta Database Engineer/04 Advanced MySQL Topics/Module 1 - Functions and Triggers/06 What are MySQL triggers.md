# What are MySQL triggers?

## 개요

- 트리거(trigger) — 특정 이벤트(삽입·갱신·삭제) 발생 시 자동으로 호출되는 저장 프로그램 형태의 동작 집합
- CREATE TRIGGER·DROP TRIGGER 기본 문법과 트리거의 이점

## 내용

### 트리거란

- **특정 이벤트가 일어나면 자동으로 호출되는 동작들의 집합(저장 프로그램).** 대표 이벤트: 테이블에 데이터 삽입·갱신·삭제.
- 매번 코드를 다시 쓰지 않고 자동으로 조치가 일어나게 한다.

### 생성 문법

1. `CREATE TRIGGER 트리거이름` — 이름은 사용자 정의, **데이터베이스 내에서 유일**해야 함
2. **트리거 유형 정의** — INSERT/UPDATE/DELETE 중 무엇에, BEFORE/AFTER 언제 실행할지
3. **대상 테이블 지정**과 적용 방식
4. **로직 정의** — 삽입·갱신·삭제 또는 이들의 조합. 여러 문장이면 **BEGIN...END 블록**으로 감싼다

### 삭제 문법

- `DROP TRIGGER IF EXISTS 스키마.트리거이름;`
  - **IF EXISTS** — 트리거가 있을 때만 삭제 (없는 트리거를 그냥 삭제하면 에러)
  - **점 표기법으로 스키마 지정** — 지정한 스키마에서만 삭제되도록
- **테이블을 삭제하면 그 테이블에 연결된 모든 트리거가 자동 제거**된다.

### 활용 예와 이점

- Lucky Shrub: 25% 초과 할인이 입력되면 관리자 승인 요청을 자동 발생 — `AFTER UPDATE` 유형의 approval_request 트리거로 갱신 후 로직 실행.
- 이점:
  1. **감사 추적(audit trail)** — 변경이 있을 때마다 기록을 삽입해 로그 유지
  2. **제약조건의 대안** — 데이터가 요구대로 갱신되도록 무결성 유지
  3. 지정한 동작에 대한 **작업 자동화**

## 요약

- 트리거는 삽입·갱신·삭제 이벤트에 자동 반응하는 저장 프로그램이다.
- CREATE TRIGGER(이름 → 유형(BEFORE/AFTER + 이벤트) → 테이블 → 로직)로 만들고 DROP TRIGGER IF EXISTS로 지운다.
- 감사 로그, 무결성 유지, 자동화에 유용하며, 테이블 삭제 시 관련 트리거도 함께 사라진다.
