# Database engineering at Meta

## 개요

- Meta 소프트웨어 엔지니어 Moxxy Herrera(기부 제품 담당)가 들려주는 데이터베이스 설계 철학 — 프라이버시, 확장성, 마이그레이션

## 내용

### 데이터 유효성과 신뢰

- 담당 업무: 누가 어떤 모금·자선단체에 기부했는지 추적 — 잘못되면 안 되는 데이터.
- 핵심 원칙: **올바른 데이터를 저장하고, 특정 사용자가 봐야 할 데이터만 그 사용자에게 보여준다** — 데이터 유효성(validity)과 접근 통제.
- 데이터베이스의 무결성·품질·설계가 **데이터 보호와 사용자 신뢰의 첫걸음**이다.

### 설계 프로세스

1. 제품이 동작하는 데 필요한 **핵심 데이터 모델**을 먼저 세운다 — 제품 관점에서 데이터 접근을 개념화하기 가장 쉽기 때문.
2. 초기 모델 위에 **프라이버시·검증 세부사항**을 파고든다 — 어떤 데이터를 암호화할지, 특정 서버에서만 접근하게 할지 등.
3. 저장하는 데이터 유형(신용카드·사용자 정보 등)에 따라 추가 점검을 설계에 통합한다.

### Meta의 핵심 고려사항

- **사용자 프라이버시·안전 최우선** — 사용자는 자기 데이터의 위치·접근을 알고, 불편한 제품에 쓰이지 않음을 알아야 한다.
- **확장성** — 아무리 잘 설계돼도 수십억 사용자 규모로 확장되지 않으면 소용없다.

### 현실적 도전 — 변경과 마이그레이션

- 어려움은 최초 구축보다 **변화** — 관계 개념이 세워진 뒤 무언가가 그것을 바꾼다.
- 사용자 볼륨뿐 아니라 **제품 유형의 변화**에도 대비해 미래의 변경 가능성을 미리 생각해야 한다.
- 기존 데이터베이스 수정(낡은 데이터 모델의 개편·데이터 마이그레이션)이 데이터베이스 업무의 대부분이며, 큰 계획과 시간이 필요하다. 상호의존적인 변경은 트래픽이 가장 적은 새벽에 릴리스해야 했던 일화도.

### 책임

- 데이터베이스 엔지니어는 많은 데이터에 접근한다 — 사소해 보이는 데이터라도 **사용자 신뢰가 걸려 있다는 책임감**을 가져야 한다.

## 요약

- 데이터베이스 설계는 제품 경험과 사용자 신뢰의 핵심이다.
- 핵심 모델 → 프라이버시·검증 → 데이터 유형별 점검 순으로 설계하고, 프라이버시와 확장성을 최우선으로 둔다.
- 실무의 대부분은 기존 모델의 변경·마이그레이션이므로 미래 변화를 미리 설계에 반영한다.
