# A quick review of stored procedures

## 개요

- 저장 프로시저 복습(생성·호출·삭제, 함수와의 차이)과 Python 애플리케이션 성능에 주는 이점

## 내용

### 복습 — 저장 프로시저

- **데이터베이스에 저장하는 미리 준비된 쿼리 블록**으로 CALL로 호출한다.
- 함수와의 핵심 차이: **함수는 입력 매개변수만, 프로시저는 입력·출력 매개변수 모두** 가능.
- 3단계: 생성 → 호출 → 삭제
  - `CREATE PROCEDURE 이름(매개변수)` + 로직
  - `CALL 이름();` (괄호 포함)
  - `DROP PROCEDURE 이름;` (괄호 불필요)
- 이점: 일관성(호출마다 같은 코드), 재사용성, 사용·유지보수 용이(하나의 블록으로 호출·수정·삭제).

### 활용 예 (Little Lemon)

- 매일 아침 그날 방문 고객 목록을 뽑는 코드를 반복 작성하는 대신 **daily_customer_details 프로시저**를 만들어 CALL 한 번으로 추출.

### Python과의 관계

- 저장 프로시저는 **Python 애플리케이션의 성능을 높이고 앱-데이터베이스 간 트래픽을 줄인다** — 큰 SQL 블록 대신 **프로시저 이름과 매개변수만 전송**하면 되기 때문.

## 요약

- 저장 프로시저는 CREATE/CALL/DROP으로 관리하는 재사용 쿼리 블록이며, 함수와 달리 출력 매개변수를 가진다.
- Python 앱에서는 이름+매개변수만 보내면 되어 트래픽 감소·성능 향상 효과가 있다.
