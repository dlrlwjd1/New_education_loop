# First normal form 1NF

## 개요

- 제1정규형(1NF)의 두 규칙: 데이터 원자성(atomicity) 강제와 불필요한 반복 그룹 제거
- 대학 course 테이블을 1NF로 재설계하는 과정

## 내용

### 정규화의 3가지 기본 형태

- 정규화를 달성하려면 **1NF → 2NF → 3NF** 세 기본 정규형을 수행해야 한다. 이 강의는 1NF를 다룬다.

### 1NF의 규칙

1. **데이터 원자성(data atomicity)**: 테이블의 어떤 필드에도 컬럼 속성의 값이 **하나만** 있어야 한다 — 필드당 값 하나.
2. **반복 그룹 제거**: 불필요하게 반복되는 데이터 그룹을 없앤다 — 반복 데이터는 중복(redundancy)과 불일치(inconsistency)를 낳는다.

### 원자성 위반과 잘못된 해결책 (course 테이블 예제)

- 문제: contact number 컬럼 한 필드에 튜터의 휴대폰 + 유선전화 **두 값**이 들어 있음 → 원자성 위반, 1NF 아님.
- 시도 1 — 번호마다 새 행 생성: 원자성은 해결되지만 **기본 키(course ID)가 더 이상 유일하지 않게 됨**.
- 시도 2 — 휴대폰/유선 컬럼 분리: 원자성과 기본 키는 지켜지지만 **반복 그룹 문제가 남는다** — 튜터 Mary Evans가 두 과목을 맡아 이름·연락처가 두 번 나타나고, 과목이 늘수록 반복도 늘어난다. 정보가 바뀌면 나타나는 모든 곳을 갱신해야 하고 하나라도 놓치면 불일치가 생긴다.

### 올바른 1NF 재설계

1. **반복 그룹 식별** — 튜터 이름과 연락처
2. **엔터티 식별** — course와 tutor
3. **엔터티별로 테이블 분리** — 과목 정보를 담는 Course 테이블, 튜터 이름·연락처를 담는 Tutor 테이블
4. Tutor 테이블에 **기본 키(tutor ID) 지정**
5. Course 테이블에 tutor ID 컬럼을 추가해 **외래 키로 두 테이블 연결**

## 예시

```text
-- 1NF 위반 (한 필드에 두 전화번호, 튜터 정보 반복)
Course(course_id PK, course_name, tutor_name, contact_numbers)

-- 1NF 재설계
Tutor(tutor_id PK, tutor_name, cell_phone, landline)
Course(course_id PK, course_name, tutor_id FK → Tutor)
```

## 요약

- 1NF는 필드당 하나의 값(원자성)과 반복 그룹 제거를 요구한다.
- 행 복제는 기본 키 유일성을 깨고, 컬럼 분리만으로는 반복 그룹이 남는다.
- 반복 그룹과 엔터티를 식별해 테이블을 분리하고 외래 키로 연결하는 것이 올바른 1NF 설계다.
