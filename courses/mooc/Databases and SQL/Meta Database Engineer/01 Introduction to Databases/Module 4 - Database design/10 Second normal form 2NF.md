# Second normal form 2NF

## 개요

- 제2정규형(2NF)의 조건과 함수 종속(functional dependency)·부분 종속(partial dependency) 개념
- 병원 백신 접종 테이블을 2NF로 재설계하는 과정

## 내용

### 전제

- 정규화는 **점진적(progressive) 프로세스**다 — 2NF를 구현하려면 먼저 1NF여야 한다.
- 목적: 중복을 줄이는 올바른 구조로 정확한 데이터 분석·검색을 가능하게 하는 것.

### 함수 종속(Functional Dependency)

- **테이블 안 두 속성 간의 관계** — 한 컬럼의 유일한 값이 다른 컬럼의 값을 결정한다.
- 관계 R에서 X가 유일 값(기본 키), Y가 비유일 값(비키 컬럼)이면, **Y는 X에 함수적으로 종속**된다.
- 예: student 테이블(학생 ID, 이름, 생년월일) — 이름은 Tony 중복, 생년월일도 중복이라 특정 학생을 못 찾는다. 유일한 값을 가진 학생 ID(기본 키)로만 특정 데이터를 반환할 수 있다 → **모든 컬럼이 학생 ID에 함수적으로 종속**.

### 부분 종속(Partial Dependency)

- **복합 기본 키**를 가진 테이블에서 나타난다.
- 예: 병원 백신 접종 테이블 — 환자 ID, 환자명, 백신 ID, 백신명, 접종 상태. 어떤 단일 컬럼도 유일하지 않아 **환자 ID + 백신 ID를 복합 기본 키**로 삼는다.
- **2NF 조건: 모든 비키 속성이 기본 키 전체에 종속**해야 하며, 키의 일부에만 종속하면(부분 종속) 위반이다.
  - 접종 상태(status): 특정 환자가 특정 백신을 맞았는지는 두 키 값을 **조합해야만** 알 수 있음 → 완전 종속 ✓
  - 백신명: **백신 ID만으로** 알 수 있음 → 부분 종속 ✗
  - 환자명: **환자 ID만으로** 알 수 있음 → 부분 종속 ✗

### 2NF로 업그레이드

1. 모든 비키 컬럼이 기본 키의 **모든 구성요소**에 종속되도록 만든다.
2. 테이블 안의 엔터티 식별 — 접종 상태(status), 백신(백신 ID·백신명), 환자(환자 ID·환자명)
3. 세 테이블로 분리: **Patient, Vaccine, VaccinationStatus**
- 이제 각 테이블에서 비키 속성이 자기 기본 키에만 종속되고, 백신명·환자명의 불필요한 반복이 사라진다.

## 예시

```text
-- 2NF 위반 (복합 PK 일부에 종속하는 컬럼 존재)
Vaccination(patient_id + vaccine_id PK, patient_name, vaccine_name, status)

-- 2NF 재설계
Patient(patient_id PK, patient_name)
Vaccine(vaccine_id PK, vaccine_name)
VaccinationStatus(patient_id + vaccine_id PK, status)
```

## 요약

- 함수 종속은 유일 값 컬럼(키)이 다른 컬럼 값을 결정하는 관계다.
- 부분 종속은 복합 키의 일부만으로 비키 속성이 결정되는 상태로, 2NF 위반이다.
- 엔터티별로 테이블을 분리해 모든 비키 속성이 키 전체에 종속되게 하면 2NF가 된다.
