# Foreign key

## 개요

- 외래 키(foreign key)의 목적 — 두 테이블을 연결해 교차 참조(cross-referencing)를 만드는 하나 이상의 컬럼
- 부모(parent)·자식(child) 테이블 개념과 다중 외래 키 시나리오

## 내용

### 외래 키란

- **두 테이블을 연결하기 위해 사용하는 하나 이상의 컬럼**. "foreign"은 "외부(external)"를 뜻한다 — 한 테이블의 외래 키는 다른 테이블의 외부 컬럼을 참조한다.
- 예: 서점 데이터베이스에서 어느 고객이 어떤 주문을 했는지 알려면 Order 테이블에 customer ID 컬럼을 외래 키로 추가한다. 주문 처리·배송·수정·취소를 올바른 고객과 연결해 수행할 수 있게 된다.

### 동작 원리 (T1 → T2)

- 참조하는 테이블 T1의 외래 키는 참조되는 테이블 T2의 관련 컬럼을 가리킨다.
- **T1의 외래 키 값은 T2 참조 컬럼에 존재하는 값과 일치해야 한다.**
- T2의 참조 컬럼은 각 행에서 유일해야 한다 — 대개 T2의 **기본 키**다.
- 용어: 참조되는(referenced) T2 = **부모 테이블**, 참조하는(referencing) T1 = **자식 테이블**.

### 부모-자식 관계의 성질 (Customer–Order 예)

- Customer와 Order는 **1:N** — 한 고객은 여러 주문을 할 수 있지만 각 주문은 정확히 한 고객을 가리킨다.
- **주문이 생기려면 고객 레코드가 먼저 존재해야** 하지만, 새 고객이 생겼다고 주문이 있어야 하는 것은 아니다.
- 즉 **부모는 자식 없이 존재할 수 있지만, 자식은 부모 없이 존재할 수 없다.**
- Order의 customer ID로 특정 고객 레코드를 가져와 송장 발행, 주소 배송 등에 쓴다.

### 다중 외래 키

- 한 테이블은 **여러 외래 키**를 가질 수 있다 — 자식 하나에 부모 여럿.
- 예: Order 테이블에 Product 테이블을 추가하면 외래 키 2개 — customer ID(→Customer), product ID(→Product).
- Order-Product는 각 주문이 특정 상품 레코드와 연결되지만, 상품은 아직 주문이 없을 수도 있다(신규 입고 상품).
- 이 구조에서 부모는 Customer와 Product 둘, 자식은 Order 하나다.

## 예시

```text
Customer(customer_id PK, name, address)     ← 부모
Product(product_id PK, ...)                 ← 부모
Order(order_id PK,
      customer_id FK → Customer,
      product_id  FK → Product,
      order_date, status)                   ← 자식 (부모 둘)
```

## 요약

- 외래 키는 자식 테이블에서 부모 테이블의 유일 컬럼(대개 기본 키)을 참조해 관계를 만든다.
- 외래 키 값은 부모의 참조 컬럼에 존재해야 하며, 자식은 부모 없이 존재할 수 없다.
- 한 테이블에 여러 외래 키를 두어 여러 부모와 연결할 수 있다.
