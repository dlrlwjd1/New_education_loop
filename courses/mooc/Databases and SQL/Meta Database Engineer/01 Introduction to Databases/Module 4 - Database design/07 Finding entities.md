# Finding entities

## 개요

- 데이터베이스에 어떤 테이블을 넣고 뺄지 결정하는 기준 — 데이터를 유지할 가치가 있는 엔터티(entity) 식별
- 속성(attribute)의 6가지 유형 구분

## 내용

### 엔터티란

- **자신의 특징을 정의하는 속성들을 가진 객체**. 장소·사람 등 데이터베이스에서 단일 대상을 나타내는 모든 것이 될 수 있다.
- 프로젝트에서 관심 있는 각각의 대상(예: 고객)이 엔터티가 된다.
- 테이블에서는 테이블 이름이 엔터티 이름(예: deliveries), 각 컬럼이 엔터티 관련 속성(ID, 이름, 배송 상태), 각 행이 엔터티의 인스턴스 레코드다.

### 속성의 6가지 유형 (student 테이블 예제)

1. **단순 속성(simple attribute)** — 더 이상 분류(분해)할 수 없는 속성. 예: 성적(grade) 값
2. **복합 속성(composite attribute)** — 여러 구성요소로 나눌 수 있는 속성. 예: 이름 → 이름(first)/성(last)
3. **단일값 속성(single-valued attribute)** — 값 하나만 저장. 예: 생년월일(학생당 한 값)
4. **다중값 속성(multi-valued attribute)** — 한 필드에 여러 값 저장 가능. 예: 이메일 컬럼에 학교 이메일 + 개인 이메일. **관계형 데이터베이스에서는 피해야 한다.**
5. **파생 속성(derived attribute)** — 다른 속성에서 계산되는 값. 예: 생년월일에서 나이 도출
6. **키 속성(key attribute)** — 유일한 값으로 엔터티 레코드를 식별. 예: 학생 ID

### 설계 원칙

- **프로젝트에서 쓰이지 않을 엔터티·속성은 고려할 필요가 없다.** 시스템 사용자가 작업을 완수하는 데 도움이 되는 데이터만 담는다.

## 요약

- 엔터티는 속성을 가진 객체이며, 테이블 = 엔터티, 컬럼 = 속성, 행 = 인스턴스다.
- 속성은 단순·복합·단일값·다중값·파생·키의 6유형이고, 다중값 속성은 관계형 설계에서 피한다.
- 실제로 사용될 데이터만 데이터베이스에 담는 것이 설계의 기본이다.
