# What is database normalization?

## 개요

- 정규화(normalization)의 정의 — 중복을 줄이고 수정 문제를 피하며 질의를 단순화하도록 테이블을 구조화하는 프로세스
- 삽입·갱신·삭제 이상(anomaly)을 대학 수강신청(enrollment) 테이블 예제로 이해

## 내용

### 다목적 테이블의 문제

- 예제: 대학 Enrollment 테이블 하나가 학생·과목·학과 목록, 셋 사이의 관계, 학과장 이름·연락처까지 **여러 목적**을 동시에 수행한다.
- 이런 다목적 테이블은 세 가지 대표적 문제를 일으킨다.

### 삽입 이상 (Insert Anomaly)

- **새 데이터를 넣으려는데 관련 없는 추가 데이터 입력이 강제되는 문제.**
- 예: 학생 ID가 기본 키인데, 새 과목명을 추가하려 해도 새 학생을 등록(ID 부여)하지 않으면 레코드를 만들 수 없다 — 기본 키 컬럼은 비워둘 수 없기 때문.

### 갱신 이상 (Update Anomaly)

- **한 레코드를 갱신하면 테이블 전반에 연쇄 갱신이 필요한 문제.**
- 예: 과목·학과 정보가 수강생마다 중복 저장되어 있는데, 컴퓨팅 학과장 Dr. Jones가 교체되면 테이블의 모든 Dr. Jones 인스턴스와 해당 학과 전체 학생 레코드를 갱신해야 한다. 하나라도 놓치면 데이터가 불일치한다.

### 삭제 이상 (Deletion Anomaly)

- **한 레코드를 삭제하면 필요한 다른 데이터까지 함께 사라지는 문제.**
- 예: ID 4번 학생 Rose가 자퇴해 데이터를 지우면, 디자인 학과의 레코드가 Rose의 행에만 존재했기 때문에 학과 정보 자체가 사라진다.

### 해법 — 정규화

- **각 테이블이 단일 목적(single purpose)을 갖도록** 설계를 최적화한다.
- Enrollment 테이블은 세 가지 목적을 가지므로 셋으로 분리:
  - **Student 테이블** — 학생 정보
  - **Course 테이블** — 과목 레코드
  - **Department 테이블** — 학과 정보
- 분리하면 이상 문제가 해결되고, 검색·정렬·분석용 SQL 질의 작성도 쉬워진다.

## 요약

- 정규화는 중복 감소·수정 문제 방지·질의 단순화를 위한 테이블 구조화 프로세스다.
- 다목적 테이블은 삽입(불필요한 추가 입력 강제), 갱신(연쇄 갱신), 삭제(연관 데이터 소실) 이상을 낳는다.
- 테이블마다 하나의 목적만 갖도록 분리하는 것이 정규화의 핵심이다.
