# Types of database schema

## 개요

- 논리적(logical) 스키마와 물리적(physical) 스키마의 구분
- ER 모델링으로 논리 스키마를, SQL 코드로 물리 스키마를 표현하는 방식

## 내용

### 논리적 데이터베이스 스키마

- **데이터가 테이블 관점에서 어떻게 조직되는지** — 어떤 테이블이 있어야 하고, 서로 다른 테이블의 속성이 어떻게 연결되는지 보여준다.
- 데이터 구성요소 간 관계를 그리는 작업이 곧 **ER 모델링(entity relationship modeling)**이며, 엔터티 타입 간 관계를 명세한다.
- 예: 주문 애플리케이션의 ER 모델 — Order(주문), Shipment(배송), Courier(배송기사) 엔터티의 관계.
  - 각 엔터티의 ID 속성이 기본 키(각 행의 유일 식별자).
  - Order 엔터티의 shipment ID·courier ID는 **외래 키**이면서 동시에 각각 Shipment·Courier 엔터티의 기본 키다 — 이것이 엔터티들과 Order 테이블 사이의 관계를 만든다.

### 물리적 데이터베이스 스키마

- **데이터가 디스크에 저장되는 방식** — 코드로 데이터베이스의 실제 구조를 만드는 것.
- MySQL 등 관계형 데이터베이스에서는 SQL로 테이블과 기타 객체를 생성한다.
- 예: 온라인 상점의 물리 스키마 — 고객·상품·거래 테이블을 만드는 SQL 문 작성.
- 물리 스키마 생성 방식은 데이터베이스 시스템마다 조금씩 다를 수 있다.

## 요약

- 논리 스키마는 테이블 조직과 관계(ER 모델)를, 물리 스키마는 디스크 저장 구조(SQL 코드)를 다룬다.
- 스키마는 데이터베이스 생성의 핵심이자 애플리케이션의 기반이다.
