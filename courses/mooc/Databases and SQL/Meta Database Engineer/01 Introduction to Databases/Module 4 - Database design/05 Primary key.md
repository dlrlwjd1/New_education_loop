# Primary key

## 개요

- 기본 키(primary key)의 목적 — 중복될 수 있는 데이터 속에서 특정 레코드를 유일하게 식별
- 후보 키에서 단순(simple) 기본 키를 고르는 과정과 복합(composite) 기본 키가 필요한 경우

## 내용

### 왜 기본 키가 필요한가 — 학생 테이블 예제

- 테이블(ID, 이름, 생년월일, 이메일, 성적)에서 2행의 Mary에게 성적을 입력하려면 Mary의 레코드를 유일하게 식별해야 한다.
- **이름은 못 쓴다** — Mary라는 학생이 두 명. **생년월일도 못 쓴다** — Dan이 같은 생일. 두 컬럼 모두 Mary에게 유일하지 않다.

### 후보 키 → 기본 키 선택

- 해법은 **후보 키(candidate key)** 찾기: **모든 행에서 유일하고 NULL이 될 수 없는(비어 있을 수 없는) 속성**.
- 예제에서는 학생 ID와 이메일이 후보 키 — 둘 다 각 학생마다 유일한 값이므로 어느 쪽이든 기본 키가 될 수 있다.
- 학생 ID를 기본 키로 지정하면, **선택되지 않은 후보 키(이메일)는 대체 키(alternate/secondary key)**가 된다.

### 복합 기본 키(Composite Primary Key)

- 테이블 어디에도 유일한 값을 가진 단일 컬럼이 없을 때, **두 개 이상의 속성을 조합**해 만든다.
- 예: 온라인 상점 배송(delivery) 테이블 — 어떤 단일 컬럼도 유일하지 않음 → **고객 ID + 제품 코드**를 조합하면 레코드마다 유일한 값이 되어 "어느 고객이 무슨 상품을 주문했는지" 식별하고 배송 상태를 추적할 수 있다.

## 예시

| 상황 | 선택 |
|---|---|
| 유일 컬럼이 존재 (ID, 이메일) | 하나를 기본 키로, 나머지는 대체 키 |
| 유일 단일 컬럼 없음 | 복합 기본 키 (예: 고객 ID + 제품 코드) |

## 요약

- 기본 키는 중복 방지와 레코드 유일 식별 수단이다.
- 후보 키는 유일하며 NULL 불가인 속성이고, 그중 선택받지 못한 키는 대체 키가 된다.
- 단일 유일 컬럼이 없으면 속성 조합으로 복합 기본 키를 만든다.
