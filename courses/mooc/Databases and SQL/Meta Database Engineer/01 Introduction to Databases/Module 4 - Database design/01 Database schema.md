# Database schema

## 개요

- 데이터베이스 스키마(schema)의 개념 — 데이터가 어떻게 저장될지 그리는 청사진(blueprint)
- 데이터베이스 시스템별로 다른 스키마의 의미와 스키마의 장점

## 내용

### 스키마란

- 개발 전에 데이터를 어떻게 조직할지 세우는 계획으로, **정보의 조직/그룹화와 그들 간의 관계**를 뜻한다.
- 시스템에 상관없이 핵심 개념은 두 가지다:
  1. **테이블 형태의 조직화된 데이터**
  2. **테이블 간의 관계**

### 시스템별 스키마의 의미

- **MySQL**: 데이터 구조의 모음, 데이터 저장 방식의 추상적 설계. **schema와 database가 사실상 동의어**다.
- **SQL Server**: 테이블·필드·데이터 타입·키 같은 여러 구성요소의 모음.
- **PostgreSQL**: 뷰(view)·인덱스·함수 같은 이름 있는 데이터베이스 객체를 담는 **네임스페이스(namespace)**.
- **Oracle**: **사용자마다 하나의 스키마**를 할당하고 스키마 이름도 해당 사용자 이름을 따른다.

### 스키마의 구성요소

- 스키마 객체(schema objects): 테이블, 컬럼, 관계, 데이터 타입, 키.
- 예: 음악 데이터베이스 — 아티스트, 앨범, 장르가 별도 테이블에 저장되지만 여러 키를 통해 서로 관련된다.
- 정리하면 스키마는 **중요한 데이터와 그 관계들, 모든 항목의 유일 키, 각 컬럼의 이름과 데이터 타입**으로 이루어진다.

### 스키마의 장점

1. 데이터베이스 객체에 대한 **논리적 그룹화** 제공
2. 객체에 대한 **접근·조작이 더 쉬움**
3. **보안 강화** — 사용자 접근 권한에 따라 객체를 분리·보호하는 권한 부여 가능
4. 스키마와 그 객체의 **소유권을 사용자·다른 스키마 간에 이전** 가능

## 요약

- 스키마는 데이터 저장 구조를 나타내는 청사진으로, 테이블과 테이블 간 관계가 핵심이다.
- MySQL(=database), SQL Server(구성요소 모음), PostgreSQL(네임스페이스), Oracle(사용자별 스키마)처럼 시스템마다 정의가 다르다.
- 논리적 그룹화, 접근 편의, 보안, 소유권 이전이 스키마의 장점이다.
