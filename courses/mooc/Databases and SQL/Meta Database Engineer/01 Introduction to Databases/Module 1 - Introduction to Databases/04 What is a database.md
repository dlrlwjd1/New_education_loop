# What is a database?

## 개요

- 데이터와 데이터베이스의 개념적 정의, 데이터가 데이터베이스 안에서 조직되는 방식
- 엔터티(entity)·속성(attribute)·테이블 구조와 관계형 외의 데이터베이스 유형(객체지향·그래프·문서)
- 온프레미스 vs 클라우드 호스팅

## 내용

### 데이터란

- **데이터 = 어떤 대상에 관한 사실과 수치(facts and figures)**.
- 예: 사람에 대한 데이터라면 이름, 나이, 이메일, 생년월일. 온라인 구매라면 주문 번호, 설명, 수량, 날짜, 고객 이메일.

### 데이터베이스란

- **데이터를 체계적으로(systematically) 조직해 저장하는 전자적 저장소**. 데이터를 전자적으로 저장·조작해 더 관리하기 쉽고 효율적이며 안전하게 만든다.
- 실사용 예: 은행(고객·계좌·거래), 병원(환자·직원·검사 데이터).

### 데이터는 어떻게 조직되는가

- 데이터베이스의 모습은 **스프레드시트/테이블 형태**의 체계적 조직이다.
- 모든 데이터는 식별 가능한 요소와 **속성(attribute)**을 가진다 (예: 사람은 나이·키·머리색).
- 데이터는 요소를 대표하는 **엔터티(entity)** 단위로 분리 저장된다. 엔터티는 행과 열이 있는 테이블과 같다.
  - 물리적 엔터티: 직원, 고객, 상품
  - 개념적 엔터티: 주문, 송장(invoice), 견적(quotation)
- 예: 온라인 상점은 Customer 엔터티(이름, 성, 생년월일, 이메일)와 Product 엔터티(상품 코드, 설명, 가격, 재고)를 가진다.
- 관계형 데이터베이스 세계에서 엔터티는 **릴레이션(relation) 또는 테이블**, 속성은 **컬럼**, 각 행은 그 엔터티의 **인스턴스**다.
- 두 엔터티를 결합해 주문 테이블(고유 주문 번호, 고객명, 주문 상품, 가격)처럼 만들 수 있다.

### 관계형 외의 데이터베이스 유형

- **객체지향 데이터베이스(object-oriented database)**: 테이블 대신 **객체**로 저장. 예: 온라인 서점에서 저자·고객·책·출판사를 클래스(class)로 만들고, 그 인스턴스(객체)가 실제 데이터를 담는다.
- **그래프 데이터베이스(graph database)**: 데이터를 **노드(node)**로, 관계를 **엣지(edge)**로 저장. 고객·주문·상품이 노드가 된다.
- **문서 데이터베이스(document database)**: 데이터를 **JSON(JavaScript Object Notation) 문서**로 저장. 테이블과 비슷한 컬렉션(collection) 안에 JSON 문서가 들어간다. 예: customer 컬렉션에 고객 문서, order/product 컬렉션에 주문·상품 문서.

### 데이터베이스는 어디에 있나

- 조직 구내의 전용 머신(온프레미스) 또는 **클라우드**에 호스팅.
- 현재는 클라우드 데이터베이스가 더 인기다 — 인터넷으로 데이터를 저장·관리·검색할 수 있고 **더 저렴한 비용**으로 데이터를 관리할 수 있다.

## 요약

- 데이터는 사실과 수치이고, 데이터베이스는 이를 체계적으로 조직한 전자 저장소다.
- 데이터는 엔터티(테이블)의 속성(컬럼)에 대해 행(인스턴스) 단위로 저장된다.
- 관계형 외에도 객체지향(객체), 그래프(노드·엣지), 문서(JSON) 데이터베이스가 있다.
- 호스팅은 온프레미스와 클라우드가 있으며, 비용 등의 이유로 클라우드가 대세다.
