# What are tables in databases?

## 개요

- 테이블의 개념적 구조: 컬럼(필드)·행(레코드)·데이터 타입·도메인(domain)·기본 키
- 테이블·엔터티·객체가 같은 개념을 가리킨다는 관점

## 내용

### 테이블 = 릴레이션 = 엔터티 = 객체

- 테이블은 데이터를 담는 행과 열로 구성되며, 하나의 데이터베이스는 여러 테이블을 담는다.
- 테이블들은 서로 관련되므로 **릴레이션(relation)**이라 부른다.
- 개념적·논리적 의미에서 테이블은 **엔터티(entity)**로도 불리고, 객체지향 데이터베이스(OODB)에서는 속성을 가진 **객체(object)**에 해당한다 — 본질적으로 테이블·엔터티·객체는 같은 개념이다.

### 컬럼(필드)과 데이터 타입

- 각 컬럼(필드/속성)은 **고유한 이름과 데이터 타입**을 가진다.
- 데이터 타입은 그 컬럼이 담을 수 있는 값의 종류(정수, 문자, 날짜·시간 등)를 정의한다. 어떤 타입을 쓸지는 개발자가 결정하며, SQL이 물리적으로 저장된 데이터와 상호작용하는 지침이 된다.
- 데이터 타입은 데이터베이스 시스템(MySQL, SQL Server, Access 등)마다 다를 수 있으므로 **해당 시스템의 문서를 항상 참조**한다.
- 일반적으로 모든 시스템이 지원하는 타입:
  - **문자열(string)** — 문자와 문자열 저장
  - **숫자(numeric)** — 정수·정확한 수·근사값
  - **날짜·시간(date and time)**
  - **바이너리(binary)** — 이미지, 파일 등

### 행(레코드)

- 컬럼(필드)들의 집합이 행을 이룬다. 관계형 용어로 행은 **레코드(record)**다.
- 예: Employee 테이블에서 각 행은 직원 한 명의 레코드다.

### 도메인(Domain)

- **한 속성에 할당할 수 있는 적법한 값들의 집합**. 필드가 담을 수 있는 값을 잘 정의하는 것.
- 예: 숫자 도메인에는 숫자만, 문자열 도메인에는 문자(열)만 넣을 수 있다. 도메인에는 길이 값 등 기능을 정의하는 규칙이 포함되어야 한다.

### 기본 키

- 각 행(레코드)은 **기본 키(primary key)**로 유일하게 식별된다.
- 유일한 값을 갖는 컬럼이 기본 키가 된다. 예: Employee 테이블의 ID (이름·직무는 중복될 수 있으므로).
- 단일 컬럼이 유일하지 않으면 **컬럼 조합**이 기본 키가 될 수도 있다.

## 예시

```text
Employee 테이블
  ID (숫자, PK) | Name (문자열) | Role (문자열)
  1             | ...           | ...
  각 행 = 직원 1명의 레코드
```

## 요약

- 테이블은 행(레코드)과 열(필드)로 데이터를 논리적으로 저장하며, 릴레이션·엔터티·객체와 같은 개념이다.
- 각 컬럼은 고유 이름과 데이터 타입(문자열·숫자·날짜시간·바이너리)을 가지며 시스템별 차이는 문서로 확인한다.
- 도메인은 속성이 가질 수 있는 적법한 값의 집합이다.
- 기본 키(단일 컬럼 또는 조합)가 각 레코드를 유일하게 식별한다.
