# Types of keys in a database table

## 개요

- 관계형 모델의 두 축(엔터티=테이블, 릴레이션=테이블 간 연결)과 테이블 관계를 성립시키는 키의 종류
- 키 속성(key attribute), 후보 키, 복합 키, 기본 키, 대체 키, 외래 키를 스포츠 리그·교직원 테이블 예제로 설명

## 내용

### 관계형 모델과 속성

- 관계형 모델의 두 핵심 개념: **엔터티(테이블)**와 관련 테이블을 잇는 **릴레이션(relation)**.
- 예: 스포츠 리그 데이터베이스 — League(순위, 팀명, 주), Teams(팀명, 주장, 코치), Points(순위, 팀명, 시즌 득점) 세 테이블. Teams의 팀명은 League에도 존재 → 관계의 단서.
- 속성 유형:
  - **단순(simple) 속성** — 행마다 단일 값 (예: 교직원 이름)
  - **다중값(multi-valued) 속성** — 여러 값(예: 담당 과목 목록). **관계형 설계에서는 피해야 한다.**

### 키의 종류 (Staff 테이블 예제)

- **키 속성(key attribute)**: 테이블의 개별 레코드를 유일하게 식별하는 값. 예: StaffID — 모든 행에서 유일.
- **후보 키(candidate key)**: 각 행에서 유일한 값을 갖는 **모든** 속성. 예: StaffID와 ContactNumber 둘 다 후보 키. 반복 값을 가질 수 있는 나머지 컬럼은 **비키(non-key) 속성**.
- **복합 키(composite key)**: 두 개 이상의 속성을 합쳐 행마다 유일한 값을 만드는 키. 예: 이름+직함 조합(같은 조합이 또 없다는 가정하에). 단일 속성 키를 찾을 수 없을 때 고려한다.
- **기본 키(primary key)**: 관계형 데이터베이스에 반드시 있어야 하는 키. 예: StaffID.
- **대체 키(alternate key, 2차 키 secondary key)**: 기본 키로 **선택되지 않은 후보 키**. 역시 각 필드에서 유일한 값을 갖는다. 예: ContactNumber.
- **외래 키(foreign key)**: **다른 테이블의 유일 키(보통 기본 키)를 참조**하는 속성. 예: StaffID는 college 데이터베이스의 다른 테이블들에서 외래 키가 될 수 있다.

## 예시

Staff 테이블 기준 키 분류:

| 키 종류 | 예 |
|---|---|
| 후보 키 | StaffID, ContactNumber |
| 기본 키 | StaffID (후보 키 중 선택) |
| 대체(2차) 키 | ContactNumber (선택받지 못한 후보 키) |
| 복합 키 | StaffName + StaffTitle (조합이 유일할 때) |
| 외래 키 | 다른 테이블에 있는 StaffID |

## 요약

- 관계형 모델은 엔터티(테이블)와 릴레이션(연결)으로 구성되고, 연결은 키로 성립한다.
- 유일한 값을 갖는 모든 속성이 후보 키이고, 그중 하나가 기본 키, 나머지는 대체 키가 된다.
- 단일 키가 없으면 복합 키를 쓰고, 다른 테이블의 기본 키를 참조하는 속성이 외래 키다.
- 다중값 속성은 관계형 설계에서 피한다.
