# A day in the Life of a Database Engineer

## 개요

- Meta 소프트웨어 엔지니어 Daniel Bloomfield Ramagem(2017년 입사, 워싱턴 DC 오피스)이 들려주는 데이터베이스 엔지니어의 일상과 커리어 조언
- 기술은 결국 인간의 문제를 해결하는 수단이라는 관점

## 내용

### 데이터베이스를 보는 눈

- 어머니의 나선형 노트 레시피북 — 페이지마다 번호가 있고 앞에 색인이 있어 원하는 레시피를 바로 찾는다 — 이것이 곧 데이터베이스다.
- **구조화된 방식으로 데이터를 저장하면 쉽게 검색할 수 있다**는 원리는 레시피북부터, 전 세계 친구가 즉시 보는 Facebook 사진까지 동일하며, 그 중심에 데이터베이스 인프라가 있다.

### 데이터베이스 엔지니어의 영향력

- **데이터는 모든 애플리케이션의 심장**이다. 빠르고 정확한 응답을 주는 효과적인 데이터 계층(data layer)을 만드는 능력이 결정적이다.
- 데이터 계층의 모델링·저장·검색 방식은 UI, 클라이언트, API 등 **테크 스택 전체에 영향을 미친다** — 데이터베이스 엔지니어는 애플리케이션 개발에서 매우 큰 영향력을 가진다.

### 매일 쓰는 기술

- **하드 스킬**: 웹 표준 프로그래밍 언어로 코딩, 데이터를 추출·변환·적재(extract, transform, load)하는 **파이프라인** 구축
- **소프트 스킬**: 커뮤니케이션과 조직력. "코드가 왕(code is king)"이라 생각했지만, 기술적으로 뛰어난 사람 중에서도 **자신이 만드는 것을 팀 내부와 사용자에게 설명할 수 있는 사람**이 더 크게 성장하더라는 교훈.

### 커리어 조언

1. **"완벽은 좋음의 적이다"** — 데이터 모델링에서 모든 변형·엣지 케이스를 다 담으려 하면 유지보수 어렵고 성능 나쁜 복잡한 스키마가 된다. **지금 여기의 데이터 요구에 집중**하고, 막연한 대규모 확장성 요구를 경계하라. 작게 시작해 자주 반복(iterate)하라.
2. **더 자주 써라(write more often)** — 결과물은 코드·SQL 쿼리만이 아니다. 문서화, 위키 갱신, 상태 공유 글이 나머지 20%다. 동료의 "done done?"(코드 체크인 + 문서 + 위키 + 공유 글까지 끝났는가?) 질문처럼, 코드 80%에 커뮤니케이션 20%를 더해야 완성이다. 불완전해도 일단 써서 공유하는 습관을 들여라.
3. **배운 것을 실생활 문제에 연결하라** — 레시피북, 어릴 적 모은 야구 카드나 만화책 정리처럼 작은 문제라도 기술을 적용해 보라.

## 요약

- 데이터베이스 엔지니어는 데이터 계층을 통해 테크 스택 전체에 영향을 미치는 역할이다.
- 일상 업무는 코딩과 ETL 파이프라인 구축, 그리고 그만큼 중요한 커뮤니케이션이다.
- 과설계를 피하고 작게 시작해 반복하며, 코드와 함께 글(문서·공유)을 쓰는 습관이 성장의 열쇠다.
