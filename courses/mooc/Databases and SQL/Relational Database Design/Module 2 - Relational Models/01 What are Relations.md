# What are Relations? (릴레이션이란?)

> 강좌: Relational Database Design (MOOC, 강사 Di Wu) · 모듈 2: Relational Models

## 개요
- 개념 모델(ERD)을 구현 가능한 물리 DB로 잇는 **중간 단계인 관계형 모델(relational model)**과, 그 기본 단위인 **릴레이션(relation)**의 속성·용어·도메인을 다룬다.

## 내용

### 모듈 2 학습 목표
- 관계형 모델이 무엇인지, 그 속성을 이해·설명한다.
- 각 릴레이션에 적절한 **키(key)**를 선택한다.
- **관계형 스키마(relational schema)**로 관계형 모델을 표현한다.
- **ERD를 관계형 모델로 변환**한다.

### 관계형 모델 (relational model)
- 테이블(릴레이션)들이 어떻게 연결되는지 기술하는 모델. 데이터를 **2차원 테이블(열·행)**로 조직.
- 포함 요소: **릴레이션(relations), 튜플(tuples), 속성(attributes), 키(keys), 외래 키(foreign keys)**. 표현은 **관계형 스키마 집합**으로.

### 릴레이션의 속성
릴레이션 = 열·행을 가진 테이블. 예: `Stores`(store ID, street, city, zip / 7개 행):
- **이름(name)** — 릴레이션(테이블) 이름.
- **차수(degree)** — **열(속성)의 수**.
- **카디널리티(cardinality)** — **행(튜플)의 수**.
- **속성(attributes)** — 열 이름들.

### 용어 정리
- **릴레이션(relation)** = 열·행이 있는 테이블. **속성(attribute)** = 열 이름. **튜플(tuple)** = 행.
- **도메인(domain)** = 하나 이상 속성에 대해 **허용되는 값의 집합**.
- **차수** = 속성(열) 수, **카디널리티** = 튜플(행) 수.
- **관계형 데이터베이스** = 고유한 이름을 가진 **정규화된(normalized) 릴레이션들의 모음**.

### 도메인 (domain)
- 각 속성의 허용 값을 제한. 예: employee ID = "특수문자 1 + 숫자 5자리" 형식으로 도메인 지정.
- **도메인이 제한적일수록 데이터가 정확해짐** — 오타·누락·잘못된 값 입력을 걸러냄.
  - 예: department 도메인을 (HR, Marketing, Sales, IT)로 제한하면 "Sale"(오타) 같은 무효 값을 막아, 이후 "Sales 직원 조회" 쿼리에서 누락을 예방.
  - 이름 길이 제한 등도 도메인의 예. (단 20399↔28399 같은 유효 범위 내 오타는 도메인으로 못 막음.)

## 예시
```text
Employee(EmployeeID, Name, Department)
차수=3, 카디널리티=저장된 직원 행 수
Department 도메인={HR, Marketing, Sales, IT}
```

## 요약
- 관계형 모델은 개념(ERD)과 물리 DB 사이의 중간 단계로, 데이터를 **릴레이션(테이블)**로 조직한다.
- 릴레이션 속성: **이름·차수(열 수)·카디널리티(행 수)·속성**. 용어: 릴레이션=테이블, 속성=열, 튜플=행.
- **도메인**은 속성의 허용 값 집합으로, 제한적일수록 데이터 정확도가 높아진다.
