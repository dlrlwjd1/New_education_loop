# Data Stored in DBMS (DBMS에 저장되는 데이터)

> 강좌: Relational Database Design (MOOC, 강사 Di Wu) · 모듈 1: Introduction to DBMS and Entity Relational Models

## 개요
- DBMS가 실제로 담는 네 가지 데이터 — **사용자 데이터, 메타데이터, 인덱스, 애플리케이션 메타데이터**를 다룬다.

## 내용

### 사용자 데이터 (user data)
- 사용자가 직접 입력·갱신·조회하는 실제 데이터.
- 보통 **테이블(table)**과 테이블 간 관계로 저장 → 이것이 "관계형(relational)" DB라는 이름의 유래.
- 각 테이블은 **열(column)과 행(row)**으로 구성. 열은 값을 기록할 구조, 한 건의 레코드는 하나의 행.

### 메타데이터 (metadata)
- "데이터에 대한 데이터" — 이름, 데이터 타입, 길이, 기본 키(primary key) 등 **데이터 구조**를 기술.
- **시스템 테이블/시스템 카탈로그(system catalog)**에 저장되며 직접 보이지 않고, 높은 권한의 사용자만 수정 가능.

### 인덱스 (indexes)
- 삽입·삭제·갱신 시 큰 정보를 옮기는 대신, **짧은 바이트로 대표**하는 인덱스만 이동해 효율↑.
- 전체 테이블을 훑지 않고 특정 위치로 빠르게 점프 → **저장·정렬·검색 가속**.
- 수동 또는 자동 생성. 데이터 갱신 시 **인덱스도 갱신** 필요(추가 단계·메모리·저장), 그러나 이점이 이를 능가.

### 애플리케이션 메타데이터 (application metadata)
- 사용자 편의 기능 — **폼(forms)**(입력 쉽게), **리포트(reports)**(요약 보기) 등 애플리케이션 구성요소.
- Access 같은 개발 프로그램의 Documenter 도구로 쿼리·폼·리포트의 메타데이터를 확인 가능.

## 예시
```text
사용자 데이터: Employee 행
메타데이터: EmployeeID는 정수·기본키
인덱스: EmployeeID -> 저장 위치
애플리케이션 메타데이터: 직원 입력 폼·급여 리포트
```

## 요약
- DBMS는 **사용자 데이터(테이블·행·열)** 외에 **메타데이터(구조, 시스템 카탈로그)**, **인덱스(빠른 접근)**, **애플리케이션 메타데이터(폼·리포트)**를 함께 저장한다.
- 실제 데이터 외의 정보를 저장하기 때문에 파일 크기가 커지지만, 그만큼 효율·기능을 제공한다.
