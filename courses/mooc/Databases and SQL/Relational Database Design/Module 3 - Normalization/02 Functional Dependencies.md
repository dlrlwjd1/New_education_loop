# Functional Dependencies

## 개요
- 한 릴레이션 안에서 속성 값 사이의 결정 관계를 함수 종속성으로 표현한다.

## 내용

### 정의와 표기
- 같은 릴레이션에서 `A`의 값이 정해질 때 `B`의 값이 유일하게 정해지면 `A → B`라 쓴다. A와 B는 각각 하나 이상의 속성일 수 있다.
- 왼쪽 A는 결정자(determinant), 오른쪽 B는 A에 함수적으로 종속된 속성이다.
- 기본키는 한 행을 유일하게 식별하므로 그 릴레이션의 모든 비키 속성을 결정한다.

### 표본 데이터의 한계
- 현재 표에 우연히 같은 값이 없다고 해서 함수 종속성이 성립하는 것은 아니다.
- 함수 종속성은 가능한 모든 유효 데이터에서 항상 성립해야 한다. 따라서 데이터 표본뿐 아니라 업무 규칙과 도메인 지식으로 확인해야 한다.

## 예시
```text
Employee(EmployeeID, FirstName, LastName, Position)
EmployeeID -> FirstName, LastName, Position
```
- `FirstName → EmployeeID`는 동명이인이 존재할 수 있어 성립하지 않는다. 표본에서 이름이 유일해 보여도 업무 전체에서는 보장되지 않는다.

## 요약
- 함수 종속성은 반드시 한 릴레이션 내부의 결정 관계다.
- 표본의 우연한 유일성과 업무 규칙상 항상 성립하는 종속성을 구분해야 한다.
