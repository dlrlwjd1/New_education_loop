# Build the Entity Relationship Model

## 개요
- 고객 인터뷰 결과를 서술형 업무 규칙과 ER 모델로 바꾸는 단계다.

## 내용

### 모델 작성 원칙
- 고객, 반려동물, 직원, 방문을 우선 엔티티 후보로 식별하고 각 엔티티의 속성과 식별자를 정한다.
- 업무 문장을 “한 A는 몇 개의 B와 관계할 수 있는가” 형식으로 양방향 작성한다.
- 명시되지 않은 규칙은 임의의 사실로 확정하지 않고 설계 가정으로 기록해 고객에게 검증받는다.

### 산출물
- 엔티티별 속성·식별자 목록
- 관계 이름, 차수, 최소·최대 카디널리티, 참여 제약
- 불확실한 규칙과 설계자가 채택한 가정 목록

## 예시
```text
Customer는 0개 이상의 Pet을 소유할 수 있다.
Pet은 정확히 1명의 Customer에게 속한다.
```

## 요약
- 인터뷰 내용을 검증 가능한 서술형 규칙으로 정리한 뒤 ERD의 입력으로 사용한다.
- 설계 가정을 별도로 남겨 요구사항과 설계자의 판단을 구분한다.
