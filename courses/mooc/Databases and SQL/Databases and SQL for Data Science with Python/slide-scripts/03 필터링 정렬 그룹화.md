# 03 필터링, 정렬, 그룹화

## 영상 목표

- `LIKE`, `BETWEEN`, `IN`으로 조건식을 확장한다.
- `ORDER BY`로 결과를 정렬한다.
- `GROUP BY`와 집계 함수로 그룹별 분석을 수행한다.
- `HAVING`과 `WHERE`의 차이를 설명한다.

권장 길이: 60-65분

---

## Slide 1. 오늘의 주제

### 슬라이드 문구

분석 쿼리의 기본기

- Pattern: `LIKE`
- Range: `BETWEEN`
- Set: `IN`
- Sort: `ORDER BY`
- Group: `GROUP BY`
- Group Filter: `HAVING`

### 스크립트

이번 영상에서는 SQL 조회를 분석 쿼리답게 만드는 핵심 문법을 다룹니다.

단순히 특정 값과 같은 행을 찾는 수준을 넘어서, 문자열 패턴을 찾고, 범위를 지정하고, 여러 값 중 하나에 해당하는 행을 찾습니다.

그리고 결과를 정렬하고, 그룹별로 집계하고, 집계 결과에 조건을 거는 방법까지 살펴봅니다.

## Slide 2. 기본 SELECT 복습

### 슬라이드 문구

기본 구조

```sql
SELECT column1, column2
FROM table_name
WHERE condition;
```

확장 방향:
- 조건을 더 풍부하게
- 결과 순서를 제어
- 그룹별로 요약

### 스크립트

출발점은 여전히 `SELECT`, `FROM`, `WHERE`입니다.

이번 영상에서 배우는 문법은 이 기본 구조를 확장합니다.

`WHERE`의 조건 표현을 더 다양하게 만들고, `ORDER BY`로 결과 순서를 제어하고, `GROUP BY`로 여러 행을 그룹 단위로 요약합니다.

## Slide 3. LIKE와 와일드카드

### 슬라이드 문구

문자열 패턴 검색

```sql
SELECT *
FROM AUTHOR
WHERE LASTNAME LIKE 'S%';
```

`%`
- 0개 이상의 문자

### 스크립트

`LIKE`는 문자열 패턴을 검색할 때 사용합니다.

예를 들어 성이 S로 시작하는 저자를 찾고 싶다면 `LIKE 'S%'`를 사용할 수 있습니다.

여기서 `%`는 0개 이상의 문자를 의미합니다. 따라서 S로 시작하기만 하면 뒤에 어떤 문자가 와도 조건에 맞습니다.

---

## Slide 4. BETWEEN

### 슬라이드 문구

범위 조건

```sql
SELECT *
FROM BOOK
WHERE PRICE BETWEEN 10 AND 25;
```

포함 범위:
`10 <= PRICE <= 25`

### 스크립트

`BETWEEN`은 값이 특정 범위 안에 있는지 확인할 때 사용합니다.

책 가격이 10 이상 25 이하인 행을 찾고 싶다면 `BETWEEN 10 AND 25`를 쓸 수 있습니다.

중요한 점은 양 끝 값이 포함된다는 것입니다. 즉 10과 25도 결과에 포함됩니다.

---

## Slide 5. IN

### 슬라이드 문구

집합 조건

```sql
SELECT *
FROM AUTHOR
WHERE COUNTRY IN ('Australia', 'Canada', 'India');
```

여러 `OR` 조건을 간결하게 표현

### 스크립트

`IN`은 여러 값 중 하나에 해당하는지 확인할 때 사용합니다.

예를 들어 국가가 Australia, Canada, India 중 하나인 저자를 조회할 수 있습니다.

이는 여러 개의 `OR` 조건을 쓰는 것보다 읽기 쉽고 간결합니다.

---

## Slide 6. ORDER BY

### 슬라이드 문구

결과 정렬

```sql
SELECT TITLE, PRICE
FROM BOOK
ORDER BY PRICE ASC;
```

정렬 방향:
- `ASC`: 오름차순
- `DESC`: 내림차순

### 스크립트

`ORDER BY`는 조회 결과의 순서를 정합니다.

가격이 낮은 순서로 보고 싶으면 `ASC`, 높은 순서로 보고 싶으면 `DESC`를 사용합니다.

정렬 기준은 하나일 수도 있고 여러 개일 수도 있습니다. 예를 들어 부서별로 정렬한 뒤, 같은 부서 안에서는 급여 내림차순으로 정렬할 수 있습니다.

---

## Slide 7. ORDER BY 주의점

### 슬라이드 문구

주의할 점

- 정렬하지 않으면 행 순서는 보장되지 않는다
- 컬럼 번호로 정렬할 수 있지만 가독성이 떨어진다
- 여러 컬럼 정렬은 왼쪽부터 적용된다

### 스크립트

SQL 결과는 `ORDER BY`를 쓰지 않으면 순서가 보장되지 않는다고 생각하는 것이 좋습니다.

가끔 `ORDER BY 2`처럼 컬럼 순서 번호를 사용해 정렬할 수 있지만, 쿼리를 읽기 어려워집니다.

가능하면 컬럼 이름을 명시하는 편이 유지보수에 좋습니다.

---

## Slide 8. DISTINCT와 GROUP BY

### 슬라이드 문구

중복 제거와 그룹화

```sql
SELECT DISTINCT COUNTRY
FROM AUTHOR;
```

```sql
SELECT COUNTRY, COUNT(*)
FROM AUTHOR
GROUP BY COUNTRY;
```

### 스크립트

`DISTINCT`는 중복을 제거한 값 목록을 보고 싶을 때 사용합니다.

반면 `GROUP BY`는 같은 값을 가진 행들을 그룹으로 묶고, 그룹별 집계를 할 때 사용합니다.

국가 목록만 보고 싶으면 `DISTINCT COUNTRY`가 적합하고, 국가별 저자 수를 보고 싶으면 `GROUP BY COUNTRY`와 `COUNT(*)`를 함께 사용합니다.

---

## Slide 9. 집계 함수

### 슬라이드 문구

자주 쓰는 집계 함수

- `COUNT`: 행 수
- `SUM`: 합계
- `AVG`: 평균
- `MIN`: 최솟값
- `MAX`: 최댓값

### 스크립트

그룹별 분석에서는 집계 함수가 핵심입니다.

`COUNT`는 행 수를 세고, `SUM`은 합계를 구합니다. `AVG`는 평균, `MIN`과 `MAX`는 최솟값과 최댓값을 구합니다.

집계 함수는 전체 테이블에 적용할 수도 있고, `GROUP BY`와 함께 그룹별로 적용할 수도 있습니다.

---

## Slide 10. AS로 별칭 붙이기

### 슬라이드 문구

결과 컬럼 이름 지정

```sql
SELECT COUNTRY, COUNT(*) AS author_count
FROM AUTHOR
GROUP BY COUNTRY;
```

### 스크립트

집계 함수 결과는 컬럼 이름이 길거나 알아보기 어렵게 나올 수 있습니다.

이때 `AS`를 사용해 별칭을 붙입니다. 예를 들어 `COUNT(*) AS author_count`라고 하면 결과 컬럼 이름이 `author_count`로 표시됩니다.

분석 결과를 다른 사람에게 보여주거나 Pandas로 가져올 때 별칭을 잘 붙이면 훨씬 읽기 좋습니다.

---

## Slide 11. HAVING

### 슬라이드 문구

그룹 결과 필터링

```sql
SELECT COUNTRY, COUNT(*) AS author_count
FROM AUTHOR
GROUP BY COUNTRY
HAVING COUNT(*) >= 2;
```

### 스크립트

`HAVING`은 그룹화된 결과에 조건을 걸 때 사용합니다.

예를 들어 국가별 저자 수를 구한 뒤, 저자가 2명 이상인 국가만 보고 싶다면 `HAVING COUNT(*) >= 2`를 사용합니다.

`WHERE`는 그룹화 전에 개별 행을 필터링하고, `HAVING`은 그룹화 후 집계 결과를 필터링합니다.

---

## Slide 12. WHERE vs HAVING

### 슬라이드 문구

차이점

`WHERE`
- 그룹화 전
- 개별 행 필터링
- 집계 함수 직접 사용 불가

`HAVING`
- 그룹화 후
- 그룹 결과 필터링
- 집계 함수 사용 가능

### 스크립트

`WHERE`와 `HAVING`의 차이는 SQL 초보자가 자주 헷갈리는 부분입니다.

`WHERE`는 원본 행을 대상으로 조건을 적용합니다. `GROUP BY` 전에 실행됩니다.

`HAVING`은 그룹화와 집계가 끝난 뒤 결과 그룹을 대상으로 조건을 적용합니다.

따라서 `COUNT(*) >= 2` 같은 조건은 `WHERE`가 아니라 `HAVING`에 적어야 합니다.

---

## Slide 13. SQL 실행 순서

### 슬라이드 문구

논리적 실행 순서

1. `FROM`
2. `WHERE`
3. `GROUP BY`
4. 집계 함수
5. `HAVING`
6. `SELECT`
7. `ORDER BY`
8. `LIMIT`

### 스크립트

SQL을 읽을 때는 작성 순서와 실행 순서가 다르다는 점을 알아야 합니다.

논리적으로는 먼저 `FROM`에서 테이블을 정하고, `WHERE`로 행을 필터링합니다. 그 다음 `GROUP BY`로 그룹을 만들고, 집계를 계산합니다.

그 뒤 `HAVING`으로 그룹 결과를 필터링하고, `SELECT`로 보여줄 열을 정하고, 마지막에 정렬과 제한을 적용합니다.

이 순서를 이해하면 `WHERE`와 `HAVING`의 차이도 자연스럽게 이해됩니다.

## Slide 14. 실습 데모: 분석 쿼리

### 슬라이드 문구

데모 쿼리

```sql
SELECT COUNTRY, COUNT(*) AS cnt
FROM AUTHOR
WHERE LASTNAME LIKE 'S%'
GROUP BY COUNTRY
HAVING COUNT(*) >= 1
ORDER BY cnt DESC;
```

### 스크립트

이 데모 쿼리는 이번 영상의 문법을 한 번에 연결합니다.

먼저 AUTHOR 테이블에서 성이 S로 시작하는 행만 남깁니다. 그 다음 국가별로 그룹화하고, 국가별 저자 수를 계산합니다.

마지막으로 집계 결과를 내림차순으로 정렬합니다.

이 쿼리를 실행하면서 SQL이 어떤 순서로 결과를 만드는지 단계별로 설명하겠습니다.

다섯 번째는 `HAVING`이 필요한 문제입니다. 집계 결과에 조건을 걸어야 하므로 `WHERE`가 아니라 `HAVING`을 사용해야 합니다.
