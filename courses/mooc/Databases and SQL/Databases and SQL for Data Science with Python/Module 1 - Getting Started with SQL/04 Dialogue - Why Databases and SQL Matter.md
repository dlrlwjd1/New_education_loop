# Dialogue: Why Databases and SQL Matter

> 이 파일은 다이얼로그(Dialogue) 형식의 학습 세션을 정리한 내용입니다.

## 다루는 주제

1. **데이터베이스 이해** - 데이터베이스란 무엇인지, 왜 조직이 데이터를 저장하는 데 사용하는지, 다른 저장 방식과 어떻게 다른지
2. **실제 데이터베이스 사례** - 일상에서 데이터베이스가 사용되는 예시, 구조화된 데이터 저장이 비즈니스에 왜 중요한지
3. **SQL 소개** - SQL의 약자와 목적, 데이터 전문가에게 SQL이 왜 필수인지
4. **학습 동기와 커리어 연관성** - SQL 학습이 커리어 목표에 어떤 가치를 갖는지

## 1. 데이터베이스 이해

### 핵심 특성

조직이 대량의 데이터를 관리할 때 데이터베이스를 선택하는 이유:

| 특성 | 설명 |
|------|------|
| **안정적인 저장** | 데이터가 손실되거나 손상되지 않고 안전하게 보존됨 |
| **빠른 조회·업데이트** | 필요한 데이터를 빠르게 검색하고 수정 가능 |
| **엄격한 데이터 관리** | 잘못된 값이 들어가지 않도록 제약 조건으로 데이터 무결성 보장 |

### 스프레드시트(Excel)와의 차이

거대한 Excel 파일로 고객 정보를 관리하려 하면:

- 파일 크기가 커질수록 속도가 느려짐
- 여러 사람이 동시에 수정하면 충돌 발생
- 잘못된 값 입력을 막을 수단이 부족
- 서비스 중단 없이 24/7 안정적으로 운영하기 어려움

→ **데이터베이스는 서비스의 안정적인 운영을 뒷받침하는 기반**

---

## 2. 실제 데이터베이스 사례

### 쇼핑몰 (e-Commerce)

- 수많은 상품 정보, 구매 이력, 고객 계정, 결제 정보가 서로 연결되어야 함
- 상품 페이지와 구매 페이지 간의 관계를 데이터베이스가 관리
- 대규모 트래픽에서도 안정적으로 재고와 주문을 처리

### 은행 (Banking)

- 금융 데이터는 구조화가 필수 — 잘못된 값이 들어가면 큰 사고로 이어짐
- 계좌 잔액, 송금 기록, 고객 정보가 정확하게 유지되어야 함
- 데이터 무결성(Data Integrity)이 특히 중요한 영역

> **핵심**: 데이터베이스는 단순 저장을 넘어, 비즈니스 운영 자체를 지탱하는 인프라

---

## 3. SQL 소개

### SQL이란?

**SQL (Structured Query Language, 구조화된 질의 언어)**

- 데이터베이스와 "대화"하기 위한 전용 언어
- 원하는 데이터를 요청(Query)하거나, 데이터를 추가·수정·삭제하는 데 사용

### 왜 SQL이 필요한가?

데이터베이스는 구조화된 방식으로 데이터를 저장하기 때문에, 그 구조를 이해하고 정확하게 요청할 수 있는 언어가 필요하다. SQL은 그 역할을 하는 표준 언어.

### 데이터 전문가에게 SQL이 중요한 이유

- 데이터 과학자, 데이터 분석가, 데이터 엔지니어 모두 SQL을 일상적으로 사용
- 수백만 건의 데이터 중에서 원하는 정보만 필터링하고 조합하는 핵심 도구
- 다양한 데이터베이스 시스템(MySQL, PostgreSQL, Oracle 등)에서 공통으로 통용되는 언어

---

## 4. 학습 동기와 커리어 연관성

### SQL 학습이 가치 있는 이유

- SQL을 알면 데이터에서 인사이트를 직접 끌어낼 수 있음
- 데이터를 다루는 대부분의 직무에서 기본 역량으로 요구됨
- 데이터 설계, 분석, 엔지니어링 모두의 출발점

### 데이터 설계 관점에서의 SQL

잘 설계된 데이터베이스는:
- 데이터를 효율적으로 저장하고
- 빠르게 조회할 수 있게 하며
- 분석 결과의 신뢰성을 높임

→ SQL을 잘 이해하는 것이 좋은 데이터베이스를 설계하는 첫걸음
