# Module 6 Quiz

## Q1. SQL의 View(뷰)에 대한 올바른 설명은?

**정답: 뷰를 정의하면 뷰의 정의만 저장되며, 뷰가 나타내는 데이터는 저장되지 않는다**

| 선택지 | 정답 여부 | 설명 |
|--------|-----------|------|
| 뷰를 통해 기본 테이블의 데이터를 변경할 수 없다 | ❌ | 업데이트 가능한(updatable) 뷰는 기본 테이블 데이터 변경 가능 |
| 뷰는 단일 테이블 구조의 독립적인 복사본이다 | ❌ | 뷰는 복사본이 아닌 정의만 저장되는 가상 테이블 |
| 뷰는 단일 테이블의 데이터만 나타낼 수 있다 | ❌ | 뷰는 여러 테이블을 JOIN한 결과도 표현 가능 |
| **뷰 정의만 저장되며 데이터는 저장되지 않는다** | ✅ | 뷰는 가상 테이블로, 쿼리 정의만 저장하고 조회 시 실시간으로 데이터를 가져옴 |

## Q2. 급여 범위가 50,000~100,000인 직업의 이름과 급여 범위를 표시하는 뷰를 생성하는 올바른 SQL은?

**정답:**

```sql
CREATE VIEW JobSalaryRanges(Job, StartingSalary, MaximumSalary)
AS SELECT JOB_TITLE, MIN_SALARY, MAX_SALARY
FROM JOBS
WHERE MIN_SALARY >= 50000 AND MAX_SALARY <= 100000;
```

| 오답 | 이유 |
|------|------|
| `WHERE SALARY > 50000 AND SALARY < 100000` | `SALARY` 컬럼이 없음, `MIN_SALARY`/`MAX_SALARY`로 조건을 나눠야 함 |
| `FROM JOBS WHERE ...` (`AS SELECT` 없음) | `AS SELECT` 절이 없어 문법 오류 |
| `CREATE VIEW` 뒤 뷰 이름 없음 | 뷰 이름이 없어 문법 오류 |
| `>` / `<` 사용 | 경계값(50,000 / 100,000) 포함이 요구사항이므로 `>=` / `<=` 사용이 맞음 |

## Q3. 저장 프로시저의 장점으로 올바른 것은?

**정답: All are valid benefits (모두 해당)**

| 장점 | 설명 |
|------|------|
| 성능 향상 | 데이터가 있는 서버에서 직접 처리, 최종 결과만 클라이언트로 전달 |
| 코드 재사용 | 여러 애플리케이션이 동일한 프로시저 공유 |
| 네트워크 트래픽 감소 | 여러 SQL 문을 하나의 호출로 실행 |

## Q4. 저장 프로시저에서 사용할 수 있는 파라미터는?

**정답: Input and output parameters (입력 및 출력 파라미터 모두)**

| 파라미터 종류 | 설명 |
|---------------|------|
| `IN` (입력) | 프로시저에 값을 전달 |
| `OUT` (출력) | 프로시저에서 결과를 반환 |
| `INOUT` | 입력과 출력 모두 사용 |

## Q5. ACID의 약자는?

**정답: Atomic, Consistent, Isolated, Durable**

| 속성 | 의미 |
|------|------|
| **A**tomic (원자성) | 트랜잭션의 모든 작업이 전부 성공하거나 전부 실패해야 함 |
| **C**onsistent (일관성) | 트랜잭션 전후로 데이터베이스가 일관된 상태를 유지해야 함 |
| **I**solated (격리성) | 동시에 실행되는 트랜잭션이 서로에게 영향을 주지 않아야 함 |
| **D**urable (지속성) | 커밋된 트랜잭션의 결과는 시스템 오류 후에도 유지되어야 함 |
