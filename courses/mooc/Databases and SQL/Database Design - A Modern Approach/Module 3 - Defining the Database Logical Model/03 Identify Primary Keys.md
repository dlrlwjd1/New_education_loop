# Identify Primary Keys (기본 키 식별)

> 강좌: Database Design: A Modern Approach (Logical Operations, MOOC) · 모듈 3: Defining the Database Logical Model · 토픽 3B

## 개요
- 각 테이블에 **기본 키(primary key)**를 정의하고, 적절한 키를 선택하는 기준을 다룬다.

## 내용

### 기본 키(primary key)란
- 각 행을 **고유하게 식별**하는 열 또는 열의 조합. 예: `Customers` 테이블의 `customer_id`.
- 역할·성질:
  - 값이 **고유(unique)** → 중복 행이 없음. 특정 행을 식별·조회하는 데 사용(전화번호로 특정인에게 연락하듯).
  - 값이 **바뀌면 안 됨**(전화번호를 자주 바꾸면 혼란).
  - **NULL(누락·미지)이면 안 됨**. NULL은 0이나 공백과 다르며, "아무것도 저장되지 않은 상태".

### 기본 키 선택
- 먼저 **고유 값을 가진 단일 열**을 찾음(예: 재활용되지 않는 `OrderID`). = **자연 키(natural key)**.
- 적절한 단일 열이 없으면 **새 열을 만들어** 고유 번호 저장(변경될 수 있는 코딩 체계 지양 — 이름 기반 고객번호는 이름이 바뀌면 문제). 일부 DBMS는 고유 번호 자동 생성 기능·타입 제공.

### 복합 키 (compound key)
- 단일 속성으로 안 되면, 여러 열을 조합한 **복합 키**(= composite key, multi-column key) 사용. NULL이 없고 변하지 않으며 고유해야 하며, **가능한 최소 열** 수 사용.

### 기본 키 선택 가이드라인 (유용·적절한 키의 조건)
- **Unique(고유)** — 현재뿐 아니라 미래에도 고유. 산업 표준 식별자(UPC, ISBN)가 좋은 후보.
- **Stable(안정적)** — 시간이 지나도 변하지 않음. 이름은 변하고 고유하지 않아 부적합. (단 UPC 12→13자리 변경처럼 표준 갱신은 있을 수 있음.)
- **Valid(유효)** — 외부 소스 없이 값이 올바른 형식인지 판단 가능(예: 12-32-2017은 잘못된 날짜).
- **Familiar(친숙)** — 사용자에게 의미 있어 입력값이 합리적인지 판단 가능(사용자 유형에 따라 다름).
- **Brief(간결)** — 값이 짧을수록 타이핑·전달 오류가 적음.
- **Simple(단순)** — 공백·특수문자·대소문자 혼용이 없는 값. 복합 키보다 **단일 열 키 선호**.
- **Efficient(효율)** — **정수(integer)**가 가장 효율적, 다음이 고정 길이 문자, 가변 길이 문자는 처리 부담이 큼.
- **Verifiable(검증 가능)** — 키가 나타내는 정체성을 확인 가능(직원 ID를 HR 기록과 대조).
- **Secure(안전)** — 민감 데이터(예: 주민번호/SSN)를 키로 쓰지 말 것. SSN은 고유·안정적이지도 않고(복수 SSN·중복 사례·미발급자 존재) 보안 위험.

## 예시 — 활동 3-4 (Canal House Books)
- `Personnel`에 `last_name`+`first_name` 복합 키? → **부적합**. 동명이인(Susan Smith) 가능, 이름은 변할 수 있음. **`employee_id`**를 고유하게 강제하는 것이 좋은 키.
- `Products`에 `model_number` 키? → 제조사마다 같은 모델 번호가 있을 수 있어 부적합. **`manufacturer`+`model_number` 복합 키**로 해결하거나, 더 나은 방법은 그 자체로 고유한 **UPC**(기존 `product_id`)를 단일 열 키로 사용. 단일 열 키가 복합 키보다 선호됨.
- 다이어그램에서 각 테이블의 기본 키 열 앞에 **별표(\*)** 표시. 이미 고유 ID가 제공된 테이블은 그것을 효과적인 기본 키로 사용.

## 요약
- 기본 키는 각 행을 고유 식별하는 열(들). **고유·비변경·비NULL**이 핵심.
- 단일 자연 키 > 복합 키 > 새로 만든 대리 키 순으로 고려.
- 좋은 키 기준: **Unique·Stable·Valid·Familiar·Brief·Simple·Efficient·Verifiable·Secure**. 정수 키가 가장 효율적, 민감 데이터(SSN)는 키로 부적합.
