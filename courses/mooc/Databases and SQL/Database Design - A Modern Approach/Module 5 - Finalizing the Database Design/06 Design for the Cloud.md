# Design for the Cloud (클라우드를 위한 설계)

> 강좌: Database Design: A Modern Approach (Logical Operations, MOOC) · 모듈 5: Finalizing the Database Design · 토픽 5E

## 개요
- 클라우드에 DB를 배포할 때의 특별한 고려사항 — 클라우드 컴퓨팅의 개념, 과제, 운영 전략, 전통적 설계와의 차이, 비정규화를 다룬다.

## 내용

### 클라우드 컴퓨팅
- Google·Amazon 같은 서비스는 전통적 DB 아키텍처의 한계를 넘는 규모(웹 인덱싱, 대량 전자상거래)를 처리하려고 새 하드웨어·소프트웨어 아키텍처를 발명.
- 핵심 개념 = **가상화(virtualization)** — 다수 컴퓨터·저장장치를 필요 시 호출(provision)하고 수요가 줄면 반납(deprovision). 자원이 구름처럼 계속 이동·변화 → **클라우드 컴퓨팅**.
- 이 플랫폼을 타사에 임대 → **AWS, Google Cloud Platform, Microsoft Azure**. 미리 DBMS가 설치된 머신 이미지를 쓰거나 직접 설치·구성 가능.

### 클라우드 DB의 과제
- 다수 동시 사용자(연산·통신 자원), 장거리로 인한 **네트워크 지연(network latency)**, 이미지·영상·오디오 등 대용량.
- 관계형 DB는 원래 로컬/기업 네트워크·단일 컴퓨터용이라, 클라우드 모델에 맞게 여러 적응·설계 전략이 필요.

### 클라우드 운영 전략
- **샤딩(sharding)** — 큰 DB를 여러 작은 DB로 분할(작은 DB가 빠름). 필요한 곳 가까이 배치해 통신 시간 단축. 관계형 DB의 클라우드 확장에 널리 쓰임.
- **캐싱(caching)** — 최근 접근 데이터의 사본을 각 지역에 보관해 가까운 캐시에서 빠르게 읽음. 성능 체감↑, 그러나 최신성이 보장되지 않는 등 복잡성·타협.
- **NoSQL** — 관계형이 아닌 기술. 고정 스키마·조인 같은 전제를 버려 고성능·확장성을 얻되, 모든 서버의 데이터가 변경 시점에 알려진 상태임을 보장하는 능력 등은 상실.

### 전통 vs 클라우드 DB 차이
- 종종 **비관계형(NoSQL)** 사용, **비정형(문서 등)** 저장, **확장성**(대량 처리 자원을 필요 시 증감), 서버에 **물리적 접근 불가**·제한적 소프트웨어 접근.

### 클라우드 DB 설계 프로세스
- 동일한 프로세스(목적·요구사항 → 개념 → 논리 → 물리). **개념·논리 모델은 물리 기술과 독립**적이어야 하며 ER 다이어그램으로 객관적 결정. **물리 모델 단계**에서 클라우드에 맞게 매우 다른 물리 모델을 결정할 수 있음.

### 데이터 비정규화 (denormalization)
- 보통 정규화가 목표지만, 비정규화가 적절한 경우도 있음. **빅데이터 분석**용 클라우드 DB는 의도적으로 **플랫 테이블**(여러 관련 테이블 대신 하나)에 저장 → 조인 없이 빠르고 단순한 조회.
- 대신 갱신은 훨씬 오래 걸림(정규화 DB는 한 행만 고치면 되지만, 비정규화는 반복된 값을 모든 행에서 수정). → **거의 추가·갱신 없이 자주 조회하는 고성능** 상황에 적합.

### 클라우드 DB 설계 가이드라인
- **애플리케이션 기능이 아닌 비즈니스 개념을 모델링**(앱 변경마다 재설계 방지).
- **확장성 주시** — 자원 증감, 데이터를 사용자 가까이, 작은 DB 여럿 사용.
- **보안·거버넌스를 설계에 내장** — 공개 인터넷 노출로 위험 증대, 요구사항 단계부터 앱 개발자·법무팀과 협업.
- **쓰레기·중복 제거** — 저장 비용이 운영비에 직결.
- **관계형 대안(NoSQL) 사용 여부 고려**.

## 예시 — 활동 5-7 (Woodworkers Wheelhouse)
데이터 유형별 저장 위치 판단:
- **카탈로그 데이터**(자주 조회·드물게 수정, 대용량) → **NoSQL** 또는 웹 서버 파일 저장.
- **재고·급여**(민감·트랜잭션 지향) → **관계형 DB**.
- **제품 시트·매뉴얼(PDF)·계획서(PDF)·프로젝트 영상** → **웹 서버 파일 저장**.
- **커뮤니티(블로그·게시판)**(비트랜잭션·비시급성, 게시 후 빠른 로딩 기대) → **NoSQL**.

## 요약
- 클라우드의 핵심은 **가상화**(자원 provision/deprovision) → 확장성. 과제는 동시 사용자·**네트워크 지연**·대용량.
- 전략: **샤딩·캐싱·NoSQL**. 전통 DB와 달리 비관계형·비정형·확장·물리 접근 불가가 흔함.
- 고성능 조회 위주면 **비정규화(플랫 테이블)**가 적절. 설계는 비즈니스 개념 모델링·확장성·보안·중복 제거·NoSQL 고려를 따른다.
