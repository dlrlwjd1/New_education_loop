# Ensure Data Integrity at the Column Level (열 수준 데이터 무결성 보장)

> 강좌: Database Design: A Modern Approach (Logical Operations, MOOC) · 모듈 5: Finalizing the Database Design · 토픽 5C

## 개요
- **열 수준(column level)**에서 값에 제약(constraint)을 걸어 데이터 무결성을 보호하는 통제들을 다룬다.

## 내용

### 열 속성 (column properties)
각 열에 제약을 부여해 무결성을 강제:
- 허용 **데이터 타입**, **입력·편집 제약**(NULL·중복 허용 여부), **기본값(default)**, 허용 **값 목록**, 허용 **값 범위**.

### 누락 데이터와 NULL
- **NULL** = 값이 입력되지 않음(미지). 0·공백·빈 문자열과 다름. "모름"과 "알지만 존재하지 않음"을 구분.
- 열을 **NOT NULL**로 지정하면 항상 값이 있어야 행이 저장됨 → 무결성 유지. **특별한 이유가 없으면 NULL을 금지**하라.

### 입력·편집 제약
- 열을 **필수(required)**로 = NULL 불허와 동일. **중복 허용 여부**도 지정(보통 인덱스와 함께). 기본 키 열은 이 제약을 자동으로 가짐.
- **입력 마스크(input mask)/picture** — 날짜(06/30/02 vs 30-Jun-2002)·SSN 대시·고객번호 패턴 등 일관된 입력 유도.
- 입력 후 값 **편집 금지**도 가능.

### 기타 데이터 검증 기법
- **기본값(default value)** — 덮어쓰지 않으면 들어가는 값(예: `OrderQuantity`의 기본 1).
- **값 목록(value list)** — 허용 값의 도메인 정의(예: 4개 주에만 배송 → 그 주들만). 목록이 짧을 때 열 수준에 적합(길면 lookup/validation 테이블 — 다음 토픽).
- **값 범위(range)** — 예: 5%~20% → `>=.05 AND <=.20`.

## 예시 — 활동 5-4
- `Books`의 `isbn` 형식 보장 → **Format 속성/입력 마스크**.
- `upc` 데이터 타입 → 앞자리 0이 있고 계산이 불필요하므로 **텍스트/영숫자**.
- `discount_amount` 5%~20% 규칙 → **허용 값 범위** 설정.

## 요약
- 열 수준 무결성 통제: **데이터 타입·NULL 여부·중복 여부·기본값·값 목록·값 범위·입력 마스크·편집 금지**.
- **NULL**은 "미지"를 뜻하며 0/공백과 다름 — 이유가 없으면 금지. 짧은 도메인은 값 목록, 길면 lookup 테이블.
