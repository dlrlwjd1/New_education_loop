# Identify Entity Relationships (엔티티 관계 식별)

> 강좌: Database Design: A Modern Approach (Logical Operations, MOOC) · 모듈 2: Defining the Database Conceptual Model · 토픽 2B

## 개요
- 주요 엔티티를 식별한 뒤, 그 엔티티들이 **어떻게 관련되는지** 분석·문서화하기 시작한다.

## 내용

### 엔티티 관계 (entity relationships)
- 주요 엔티티 타입을 어느 정도 식별했으면, 엔티티 타입 간 **모든 관계**를 파악. 고려할 질문 예:
  - 강좌 없는 강의실이 있어도 되나? 강의실 없는 강좌 개설이 있어도 되나?
  - 강좌는 강사가 정확히 1명이어야 하나? 여러 명일 수 있나? 강사가 여러 강좌를 가르칠 수 있나?
- 관계의 **논리 분석은 논리 모델링 단계로 미루고**, 개념 단계에서는 관계가 존재하는 위치를 단순히 매핑:
  - 문장으로: "Courses are delivered by Instructors.", "Courses take place in Classrooms."
  - 또는 ER 다이어그램에 **선을 긋고 동사로 라벨**.
- 관계는 **양방향**으로 발생할 수 있고, 각 엔티티는 여러 다른 엔티티와 관계 가능. 관계를 생각하면 **누락된 엔티티를 발견**하거나 기존 엔티티를 조정하게 됨.
  - 예: 강사가 다른 강좌를 학생으로 들을 수 있나? 강사·학생의 속성이 비슷한가? → 둘 다 "예"면 `Instructors`·`Students`를 없애고 **`Participants` 하나로** 통합(역할은 맥락에 따라 결정 — 같은 ID가 한 강좌에선 강사, 다른 강좌에선 학생 목록에).
- 이 단계에서 관계를 성립시킬 **속성 이름**을 미리 생각해두면 유용.

### 엔티티 관계 식별 가이드라인
- **명백한 관계에 집중** — 연속 패스로 점차 정교화.
- **누락된 엔티티 점검** — 예: 강사와 강의실은 직접 관련이 아니라, 강사가 특정 강의실에서 열리는 **강좌(Course)**에 배정될 때만 연결됨 → `Course` 엔티티가 없다면 추가하게 됨.
- **속성 생각 시작** — 관계를 성립시킬 속성 이름을 식별.

## 예시 — 활동 2-2 (Canal House Books)
- 개념 모델에서 엔티티 상자 사이에 **관계 선**을 긋고, 관계를 성립시킬 **속성 이름**을 상자에 기입.
- 하나의 설계 문제에 **여러 정답**이 있을 수 있으므로, 예시와 정확히 일치하지 않아도 괜찮다. 프로세스를 진행하고 설계를 테스트하면서 **추가 테이블의 필요**가 드러날 수 있다.

## 요약
- 엔티티 식별 후 **엔티티 간 관계를 매핑**(문장 또는 ER 다이어그램의 라벨 선).
- 관계 분석은 **누락 엔티티 발견·엔티티 조정**(예: `Participants` 통합)에 도움.
- 상세 논리(카디널리티 등)는 논리 모델링에서, 개념 단계는 관계의 **존재**를 문서화하는 데 초점.
