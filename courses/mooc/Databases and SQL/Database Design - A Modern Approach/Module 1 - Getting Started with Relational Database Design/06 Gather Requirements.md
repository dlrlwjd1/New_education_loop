# Gather Requirements (요구사항 수집)

> 강좌: Database Design: A Modern Approach (Logical Operations, MOOC) · 모듈 1: Getting Started with Relational Database Design · 토픽 1D

## 개요
- 설계를 시작하기 위해 필요한 정보·자원을 모으는 **요구사항 수집** 단계를 다룬다.

## 내용

### 정보 수집 (information gathering)
설계 첫 단계는 **DB의 목적 식별**. 다음 질문에 답할 정보를 수집:
- **목적(purpose)** — 고객이 왜 이 시스템이 필요한가?
- **기능(functionality)** — 시스템이 무엇을 해야 하는가?
- **사용자와 동작(users and actions)** — 누가 쓰고 어떤 작업을 하는가?
- **결과(outcomes)** — 고객의 장기 기대는?

### 범위와 결과 (scope and outcomes)
- 모든 이해관계자가 **프로젝트 범위와 기대 결과**를 (중요도 순으로) 동일하게 이해하도록. **목적 진술문(statement of purpose)**을 써서 승인받으면 유용. (예: "Orders DB는 고객·주문·주문 상세 정보를 담고, 주문 입력과 월별 매출 리포트에 사용된다.")
- 설계 초기는 **사람 집약적(people-intensive)** — 질문을 많이 하고, 명확한 소통이 필수. **반복적**으로 재확인·추가 정보를 얻는다. 사용자·유스케이스로 지원할 작업을 명확히.

### 데이터 소스 (data sources)
- 기존 데이터 소스를 분석하면 포함할 데이터를 식별하는 데 도움. 데이터가 최종적으로 DB에 **어떻게 유입될지**도 결정해야 함.

### 데이터 소유권 (data ownership)
- 데이터를 현재 누가 "소유"하는지 식별. 같은/유사 기능의 다른 DB가 있는지 확인. 부서별 중복 DB가 있으면 새 데이터 소스 구현·유지 및 **동기화**가 어려워진다.

### 보안과 프라이버시 (security and privacy)
- 고객·직원의 **개인정보**가 있으면 적절한 보호를 제공할 법적 책임이 따를 수 있다. 개인정보 노출은 재정적 결과와 회복 불가한 평판 손상을 초래.
- 규제는 지역·업종별로 다르며, 적용 규제를 이해할 책임은 설계자에게 있다(법무팀 자문 활용).

### 요구사항 수집 가이드라인
1. **주제 전문가(SME) 식별** — 이해관계자와 업무 전문가부터.
2. **각 SME 인터뷰** — 각 프로세스의 단계, 특히 각 단계의 **입력(inputs)과 출력(outputs)** 데이터 값에 집중(→ 포함할 열 식별). 관련 데이터 소스·문서·리포트 접근 확보.
3. **관련 프로세스 문서화** — 다이어그램·플로차트·서술 등으로 데이터와 주요 단계를 모델링, 각 단계의 입출력 기록.
4. **인터뷰이가 문서 검증** — 리포트·폼·스크린샷에서 만든 문서를 검토시키고, 특히 **누락된 데이터**에 주의.
5. **필요 시 수정** — 4~5단계 반복.

## 예시 — 활동 1-4 (Canal House Books)
매장 관리자·소유주가 제공한 기존 자원과 각 자원에서 던질 질문:
- **신규 재고 입력 폼(종이)** → 이 폼에 없는 다른 제품 유형이 있는지?
- **재고 스프레드시트** → 각 제품의 **공급업체(supplier)**를 식별하는 다른 소스가 있는지(재주문 정보)?
- **고객 영수증** → 매출이 현재 어떻게 기록되는지, 각 판매에 필요한 상세, **할인 코드·할인 계산 방식**은?
- **월별 매출 리포트(수작업)** → 할인 계산 방식·할인 유형?
- **행사 일정(데스크 캘린더)** → 웹사이트에 표시할 정보(날짜·시간·밴드/저자명 외), **리마인더 알림**이 어떻게 작동하고 무엇이 트리거인지?

## 요약
- 요구사항 수집 = **목적·기능·사용자/동작·결과** 파악 + 데이터 소스·소유권·보안/프라이버시 고려.
- 방법: **SME 식별 → 인터뷰(입출력 집중) → 문서화 → 검증 → 반복**. 초기 단계는 사람 집약적·반복적이며 명확한 소통이 핵심.
