# Identify Database Components (데이터베이스 구성 요소 식별)

> 강좌: Database Design: A Modern Approach (Logical Operations, MOOC) · 모듈 1: Getting Started with Relational Database Design · 토픽 1A

## 개요
- 데이터베이스를 설계하기 전에 알아야 할 **DBMS의 구성 요소(components)**와 그것들이 어떻게 함께 작동하는지 식별·설명한다.

## 내용

### 데이터베이스(database)란
- 데이터를 **유용한 작업(조회·갱신·정렬·검색)**을 수행할 수 있도록 구조화한 데이터 모음.
- 어떤 DB는 **트랜잭션 처리**(온라인 뱅킹·쇼핑) 중심, 어떤 DB는 **데이터 수집·분석**(과학·제조) 중심. 하나의 소프트웨어가 여러 DB에 접근하기도 한다.
- 오늘날 대부분의 비즈니스가 웹사이트·모바일·데스크톱 앱에 의존하며, 그 콘텐츠는 DB에 저장된다.

### 데이터베이스 구조 (structure)
- DB는 데이터를 담는 **컨테이너**들로 조직된다: **테이블(table) → 행(row) → 열(column)**. 열에는 데이터 값이 들어간다.
- 이 근본 요소를 정의하면 DB의 **모델/패턴 = 스키마(schema)**가 만들어지고, 담을 수 있는 데이터 종류와 조작 규칙·제약이 정해진다.
- 스키마는 데이터 적재 후에도 어느 정도 수정 가능하지만, 보통 **설계자가 사전에 계획**한다. 스키마 설계는 DB 설계자의 핵심 역할.

### DBMS 소프트웨어
- **DBMS(database management system)** = DB 기능을 제공하는 소프트웨어.
  - 단일 사용자/소규모: Microsoft Access, FileMaker Pro.
  - 다중 동시 사용자: Oracle Database, Microsoft SQL Server, MySQL, IBM DB2/Informix, SAP Sybase, Teradata.
- 대규모 시스템은 설정·관리에 전문성이 필요해 **DBA(데이터베이스 관리자)**를 두며, 자체 캠퍼스 또는 **클라우드 데이터센터**에 설치된다.

### DBMS의 기본 기능
1. **구조 정의** — CLI 또는 시각적 도구(드래그앤드롭)로 테이블·열 정의.
2. **데이터 입력·수정·삭제** — 폼/테이블 편집기, CLI, 외부 소스(텍스트·스프레드시트) 가져오기.
3. **데이터 검색** — 논리적 관계 기반 쿼리로 정렬·검색·필터.
4. **접근 제한** — 네트워크 보안 위에 DB 전용 사용자/비밀번호·권한 부여.

### 아키텍처
- 규모: 단일 컴퓨터·단일 사용자부터 여러 시스템·지역에 분산까지. 클라우드 DB는 전 세계 데이터센터에 분산.
- **클라이언트-서버(2-tier)**: 클라이언트 계층(사용자용 표현), 서버 계층(DB 직접 관리). 구성 요소 — DB 서버, 네트워크, 클라이언트(기기), 클라이언트 애플리케이션(내부적으로 SQL로 서버와 통신), 사용자(권한별 차등 접근).
- **3-tier/n-tier**: 비즈니스 로직 계층, 프레젠테이션 계층을 추가. 웹 애플리케이션 서버가 DB의 동적 데이터에 정적 웹 콘텐츠(HTML·그래픽)를 더해 브라우저로 표현.
- **서비스 지향 아키텍처(SOA)**: 컴퓨터가 사람이 아닌 **다른 컴퓨터와 데이터 공유**. XML/JSON 기반 메시징(SOAP, REST). 읽기뿐 아니라 수정·추가도 지원.
- **클라우드 기반 서버**: 제3자 인터넷 호스팅. 인터넷에서 서버를 빌려 쓰는 소프트웨어 = **SaaS(software as a service)**. 장점 — 설치·유지 비용 절감, 전 세계 접근, 대용량 저장·처리(AWS·Google Cloud).

### SQL
- 최종 사용자는 보통 DB와 직접 상호작용하지 않고, 앱/웹의 폼을 통해 접근. 반면 DBA·개발자·분석가는 **SQL(Structured Query Language)**로 직접 통신.
- 발음: "ess queue ell"(ANSI 1986 공식) 또는 "sequel"(원래 명칭 SEQUEL, 상표 충돌로 SQL로 변경). 이 강좌는 일반적으로 "ess queue ell", Microsoft SQL Server 제품 지칭 시 "sequel".
- SQL은 DB·테이블 생성·관리 및 데이터 조회·삭제·수정 명령으로 구성된 **표준 언어**. 구현체(Oracle vs SQL Server)마다 미묘한 차이가 있으나 매우 유사.

### 관계형 데이터베이스 (relational database)
- 초기 DB는 **플랫 파일(flat file)** — 단일 파일에 저장, 순차 검색만 가능(2차원: 레코드·필드).
- 1960년대 말 IBM의 **Dr. Edgar F. Codd**가 **관계 대수(relational algebra)** 기반의 논리적 토대를 마련 → 현대 관계형 DB.
- 데이터는 **여러 테이블에 분산**되고, 각 테이블은 다른 테이블이 특정 행으로 빠르게 이동할 수 있는 열을 가진다. 설계 규칙을 지키면 **데이터 중복 최소화·효율·고성능**을 얻는다.

## 예시 — 활동 1-1 (전문 조직 회원 DB)
- 회원 연락처·회비 납부·위원회 정보를 추적하는 샘플 DB.
- **Members 테이블**(memberID, first/last name 등) + **Payments 테이블**(memberID, 금액, 날짜 등).
- 두 테이블 모두 **MemberID**를 포함해 관계를 맺음. Payments에 MemberID만 저장하면, Members를 참조해 회원의 상세 정보를 조회 가능 → Payments에 이름 등을 중복 저장할 필요 없음.
- 이런 **고유 ID**가 서로 다른 테이블의 데이터를 연결하는 "접착제(glue)" 역할.

## 요약
- DB의 근본 요소: **테이블·행·열** → 이를 정의한 패턴이 **스키마**.
- **DBMS**가 구조 정의·데이터 CRUD·검색·접근 제한 기능을 제공.
- 아키텍처: 클라이언트-서버(2-tier), 3/n-tier, SOA(SOAP/REST), 클라우드(SaaS).
- **SQL**로 DB와 직접 통신. **관계형 DB**(Codd, 관계 대수)는 데이터를 여러 테이블로 나누고 **고유 ID**로 연결해 중복을 최소화한다.
