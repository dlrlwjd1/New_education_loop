# Lecture: Mail Archive

## 개요
- Mbox(메일박스) 이메일 아카이브 형식을 소개하고, 이를 크롤링·정제해 데이터베이스에 적재하는 `gmane.py` 예제의 배경과 설계 철학을 설명하는 강의

## 내용
### Mbox 형식
- Mbox 파일은 `From `(공백 포함, 실제 발신자와 무관한 구분자)으로 각 메일 메시지가 시작된다. 이어서 `키: 값` 형태의 헤더들이 여러 줄 나오고, 빈 줄 이후에 메시지 본문이 이어진다. 본문 안에 `From`이라는 단어가 줄 앞에 나오면 새 메시지로 오인될 수 있어 이스케이프 처리가 필요하다.

### 크롤러이자 스크래치 스토리지로서의 데이터베이스
- 이 예제는 웹 크롤러와 비슷하게, 데이터베이스를 크롤링 진행 상태를 기록하는 임시 저장소로도 활용한다 — 중단했다가 이어서 재개할 수 있고, 서버 문제 발생 시 멈췄다가 원인을 파악한 뒤 다시 시작할 수 있다.

### 실제 데이터의 지저분함과 점진적으로 발전한 코드
- 실제 이메일 서버들은 헤더 형식·주소 표기·날짜/시간대 형식이 조금씩 다르다. `gmane.py`는 정규 표현식으로 이런 편차를 흡수해 이메일 주소·날짜·제목·헤더·본문을 일관된 형태로 뽑아내는 코드다.
- 강사는 이 코드가 몇 시간이 아니라 몇 주에 걸쳐, 실제 서버와 주고받으며 겪은 오류들을 하나씩 처리하며 발전시킨 결과물이라고 강조한다 — 외부 데이터 소스와 통신하는 코드는 예상 못 한 문제(속도 제한, 데이터 불일치, 서버 불안정 등)에 맞춰 "진화적으로" 작성될 수밖에 없다는 실무적 교훈을 준다.
- 처음부터 모든 예외 처리를 완벽히 갖출 필요는 없으며, 기본 동작이 되는 코드를 먼저 만들고 문제가 발견될 때마다 점진적으로 보강하는 것이 현실적인 접근이라고 조언한다.

## 요약
- Mbox 형식은 `From ` 구분자와 헤더/빈 줄/본문 구조로 이루어져 있다.
- 실전 데이터 수집 코드는 처음부터 완벽할 필요 없이, 실제 서버와 상호작용하며 발견되는 문제(형식 편차, 속도 제한 등)에 맞춰 점진적으로 발전시키는 것이 현실적이다.
