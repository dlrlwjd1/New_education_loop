# Demonstration: Mail Archive 1/3

## 개요
- `gmane.py`를 실제로 실행해 Sakai 프로젝트 메일링 리스트를 크롤링하고, 재시작 가능(resumable)한 크롤러 설계와 `myutils.py` 헬퍼 함수를 살펴보는 실습 강의

## 내용
### 실행과 재시작 가능한 크롤링
- `messages` 테이블이 없는 상태에서 `python gmane.py`를 실행하면 몇 개를 가져올지 묻고, 순서대로 메시지 번호(예: 3 → 4)를 늘려가며 한 번에 한 메시지씩 요청한다. 50건마다 커밋한다.
- 이미 데이터가 있는 상태에서 다시 실행하면, DB에 저장된 마지막 메시지 번호(예: 400)를 확인해 401부터 이어서 요청한다 — 이 재시작 가능성이 이 크롤러 설계의 핵심이다. 처음부터 다시 시작하려면 `messages` 테이블을 직접 삭제해야 한다.

### myutils.py: 반복되는 패턴을 헬퍼 함수로
- "쿼리 결과에서 값 하나만 필요한" 경우가 매우 흔하기 때문에, `myutils.py`에 `query_value` 같은 헬퍼 함수를 만들어 8~9줄의 반복 코드를 한 줄로 줄인다. 이 함수는 결과가 없으면 `None`을 반환한다.

### 오류 처리와 재시도 가능성
- `try/except`로 네트워크 타임아웃(30초), HTTPS 인증서 문제(만료된 인증서 우회), Control-C 중단 시의 정리(commit 후 종료) 등을 처리한다.
- 강사는 이 모든 예외 처리가 처음부터 있었던 게 아니라 실제로 여러 번 발생한 문제를 하나씩 해결하며 추가된 것이라고 재확인한다. 처음 코드를 작성할 때부터 이렇게 복잡할 필요는 없다는 점을 강조한다.

## 예시
```python
from myutils import query_value

last_id = query_value(cur, "SELECT MAX(id) FROM messages")
start = (last_id or 0) + 1
```

## 요약
- 크롤러는 DB에 저장된 마지막 진행 상태를 조회해 이어서 시작하도록 설계하면 중단·재개가 자유로워진다.
- 반복되는 "값 하나만 조회" 패턴은 헬퍼 함수로 추출해두면 코드가 훨씬 간결해진다.
- 실전 크롤링 코드의 예외 처리는 실제 운영 경험을 통해 점진적으로 쌓이는 것이 자연스럽다.
