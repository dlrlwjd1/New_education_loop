# Building a Natural Language Index with SQL

## 개요
- 자연어의 특성을 활용해 역방향 인덱스를 더 작고 정확하게 만드는 세 가지 최적화 — 소문자 통일, 불용어(stop word) 제거, 어간 추출(stemming) — 을 소개하는 강의

## 내용
### 소문자 통일(case folding)
- 대문자로 시작하든 소문자로 시작하든 의미가 같은 경우가 많다(예: "Teacher"와 "teacher"). 인덱싱 전에 모든 단어를 소문자로 변환하면 인덱스 크기가 줄고 검색 정확도가 높아진다.

### 불용어(stop word) 제거
- "and", "for", "who" 같은 단어는 문장 구조에는 필요하지만 검색어의 의미에는 거의 기여하지 않는다. 이런 단어를 통상 "stop word"라 부르는데, 강사는 "무시해도 되는 단어"라는 뜻이 더 정확하다고 언급한다.
- 실제로 불용어를 제거하지 않고 색인을 만들면, 검색어와 무관한 단어(and, is 등)가 우연히 포함된 문서까지 걸려 위양성(false positive)이 늘어나는 문제를 실험으로 미리 보여준다.

### 어간 추출(stemming)
- "car"와 "cars"처럼 같은 개념을 가리키는 단어들을 하나의 어간(stem/어휘, lexeme)으로 매핑해 인덱싱하면, 인덱스는 작아지고 검색 시에는 오히려 더 많은(의미상 관련된) 문서를 찾아낼 수 있다.
- 이번 모듈에서는 불용어 테이블과 "단어→어간" 매핑 테이블을 직접 만들어, 인덱스를 만들 때와 검색할 때 모두 이 매핑을 적용하는 수작업 구현을 실습할 예정이라고 안내한다.

### 언어별 사전 설정
- 불용어와 어간 추출 규칙은 언어마다 크게 다르므로, 실제 PostgreSQL 내장 기능을 쓸 때는 어떤 언어(예: 영어)를 사용할지 지정하는 것이 중요하다. `SELECT cfgname FROM pg_ts_config;`로 PostgreSQL에 기본 내장된 언어별 텍스트 검색(text search) 설정 목록을 확인할 수 있다 — 이는 각 언어에 대해 이미 계산된 불용어 목록과 어간 추출 규칙을 포함한다.

## 예시
```sql
-- 불용어 제거 전: 무관한 문서까지 걸리는 문제 예시
SELECT DISTINCT id FROM docs_gin WHERE keyword IN ('is', 'and');  -- 의미 없는 매칭

-- PostgreSQL이 내장 지원하는 언어별 텍스트 검색 설정 목록
SELECT cfgname FROM pg_ts_config;
```

## 요약
- 자연어 검색 정확도를 높이려면 소문자 통일, 불용어 제거, 어간 추출 세 가지 최적화가 필요하다.
- 불용어를 제거하지 않으면 의미 없는 단어 때문에 위양성이 늘어나고, 어간 추출을 하지 않으면 같은 개념의 단어들이 따로 인덱싱되어 검색을 놓칠 수 있다.
- 이 규칙들은 언어마다 다르므로, PostgreSQL 내장 텍스트 검색 기능을 쓸 때는 언어 설정이 중요하다.
