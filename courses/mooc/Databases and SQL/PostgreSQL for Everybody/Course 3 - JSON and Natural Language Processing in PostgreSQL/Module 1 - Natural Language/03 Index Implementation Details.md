# Index Implementation Details

## 개요
- 인덱스의 본질(키→블록 힌트)과, B-트리·BRIN 같은 순방향(forward) 인덱스, 그리고 GIN 같은 역방향(inverted) 인덱스의 차이를 설명하는 강의

## 내용
### 인덱스는 "키 → 블록" 힌트
- 논리적/기본 키의 실제 값과 그 값이 들어있는 블록 번호만 작은 테이블로 저장해두면, 원하는 값을 즉시 특정 블록으로 찾아갈 수 있다. WHERE 절은 본질적으로 모든 행에 "이 조건이 참인가?"를 묻는 것과 같은데, 인덱스는 이 과정에서 디스크로부터 가져와야 할 데이터양을 최소화해주는 "치트 시트"다.

### 순방향 인덱스: B-트리와 BRIN
- **B-트리(B-tree)** : 균형 트리(balanced tree) 구조로 트리의 깊이를 최소화해, 아무리 레코드가 많아도 몇 번의 블록 읽기(보통 1~3회)만으로 원하는 블록에 도달한다. 문자열·숫자·날짜 키 모두에 적합하고 삽입·갱신 비용과 조회 성능의 균형이 좋아 "확신이 없으면 B-트리"가 기본 선택이다. 트리는 삽입 시 항목을 밀어내며(재구성) 균형을 유지하고, 필요하면 깊이가 늘어난다.
- **BRIN(Block Range Index)** : PostgreSQL 고유의 인덱스로, 각 블록(또는 블록 범위)의 최솟값·최댓값만 기록하는 매우 작고 빠른 인덱스다. 순차적으로 증가하는 데이터(날짜, 자동 증가 기본 키 등)에 적합하다. 범위가 겹치면 여러 블록을 읽어야 할 수 있지만, 인덱스 자체가 매우 작고 새 데이터가 끝에 추가될 때 인덱스 갱신 비용이 거의 없다는 장점이 있다.

### 역방향 인덱스(Inverted Index): GIN, GiST, SP-GiST
- 순방향 인덱스는 "하나의 키 → 하나의(또는 소수의) 행"을 찾는 데 쓰이지만, 열에 배열이나 여러 단어로 이루어진 문서처럼 "여러 개의 값"이 들어있는 경우에는 다른 접근이 필요하다.
- 역방향 인덱스는 문서를 여러 조각(단어 등)으로 쪼갠 뒤, 각 조각(키워드)이 어떤 행(블록)에 있는지 추적한다 — `%SQL%` 같은 와일드카드 검색을 효율적으로 처리하는 방법이다.
- PostgreSQL의 역방향 인덱스 종류: `GIN`(일반화된 역방향 인덱스, Generalized Inverted Index), `GiST`(해싱 지향), `SP-GiST`(공간적 특성 — 위도/경도, 3차원 점 등에 적합). 역방향 인덱스의 대표적 활용 사례는 텍스트 검색(풀텍스트 검색)이다.

## 요약
- 인덱스는 본질적으로 "키 값 → 블록 번호"를 알려주는 작은 힌트 테이블이다.
- 순방향 인덱스(B-트리, BRIN)는 단일 키로 행을 찾을 때, 역방향 인덱스(GIN, GiST, SP-GiST)는 배열·텍스트처럼 한 열에 여러 값이 들어있을 때 사용한다.
- 확신이 서지 않으면 B-트리를 기본으로 선택하고, 순차 증가 데이터에는 BRIN이 매우 효율적인 대안이 될 수 있다.
