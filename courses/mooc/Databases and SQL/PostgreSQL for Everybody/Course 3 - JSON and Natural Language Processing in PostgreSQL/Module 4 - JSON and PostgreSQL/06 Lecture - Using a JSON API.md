## 내용
### 이메일 크롤링과의 차이
- 이전 이메일 아카이브 예제는 메시지 번호가 순차적(1, 2, 3...)이라 단순했지만, 이번에는 문서를 읽고 그 안에 담긴 링크(다른 문서의 URL)를 따라가야 하는 진짜 스파이더링(spidering) 작업이다 — 어떤 데이터가 있을지 미리 알 수 없다.

### 할 일 목록(URL 큐) 기반 설계
- 이 애플리케이션의 핵심 테이블은 기본 키, JSON 본문, 검색된 URL, 검색 상태(성공 여부), `created_at`/`updated_at`으로 구성된다.
- 프로그램은 몇 개의 알려진 URL(예: 영화 1편)을 시드로 삽입하며 시작해, 문서를 하나씩 가져올 때마다 그 안의 링크를 "할 일 목록"에 추가한다. 이 목록은 처음엔 늘어나다가(새 링크 발견) 점점 줄어드는(모두 검색 완료) 패턴을 보인다.
- 이 방식도 Course 3 앞부분의 이메일 크롤러처럼 재시작 가능(resumable)하게 설계되어, 실행을 중단했다가 다시 실행하면 이어서 검색을 재개한다.
