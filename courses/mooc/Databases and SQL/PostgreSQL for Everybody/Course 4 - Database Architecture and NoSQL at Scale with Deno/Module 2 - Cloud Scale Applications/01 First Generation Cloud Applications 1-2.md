# First Generation Cloud Applications 1/2

## 개요
- 2002년 대학들이 각자 4만 달러짜리 서버를 사서 개별 관계형 데이터베이스를 운영하던 "가짜 클라우드" 방식에서, Google 검색·Gmail 같은 진짜 1세대 클라우드 스케일 애플리케이션으로 넘어가는 배경을 다루는 강의

## 내용
### 2002년의 "가짜 클라우드"
- 대학이나 기업들은 업무마다 별도의 고가 서버를 사서 각각 수직 확장하는 방식으로 운영했다. 일부는 이런 서버들을 한곳(예: Amazon 데이터센터)에 몰아넣고 이를 "클라우드"라 불렀지만, 실제로는 개별 건물을 한 건물로 모은 것에 불과했다고 지적한다.

### Google 검색과 Gmail: 진짜 1세대 클라우드
- Google 검색은 웹을 크롤링해 사본을 만들고 색인화하는 작업이라 관계형 데이터처럼 보이지만, 규모 때문에 전통적인 방식으로는 처리할 수 없었다.
- Gmail(2009년 기준)은 읽기/쓰기가 활발한 애플리케이션이지만, 각 사용자의 메일함이 서로 통신할 필요가 없는 독립된 "작은 데이터 사일로"라는 특성 덕분에 최종적 일관성(eventual consistency)이 잘 들어맞았다 — 사용자는 자신의 메일함에만 영향을 미치므로, 전체 시스템 차원의 즉각적 일관성이 필요 없었다.
- 초기 Gmail은 사용자의 물리적 위치에 따라 데이터를 가까운 서버로 마이그레이션하기도 했다(예: 유럽 여행 중 데이터가 유럽 서버로 이동).

### 샤딩(Sharding)의 개념
- 이메일 주소를 해시해 특정 폴더/서버에 배정하는 방식으로, 데이터를 여러 서버에 "분할"해 저장하는 것이 샤딩이다. 이는 "어떤 쿼리든 갈 수 있는" 읽기 전용 복제본과 달리, 데이터가 정확히 하나의 서버(샤드)에만 존재하는 방식이다.
- 각 사용자당 하나의 데이터베이스라면 SQLite 같은 단순한 단일 파일 DB도 충분할 수 있다는 점도 언급된다.

### Marissa Mayer의 Google I/O 2008 발표
- 강사는 이 발표를 실제로 청중석에서 들었으며, "수집/분산(scatter/gather)" 기법 — 백만 달러짜리 컴퓨터 한 대 대신 천 달러짜리 컴퓨터 수천 대를 병렬로 활용하는 방식 — 이 당시 혁명적이었다고 회고한다. 이것이 저비용 검색과 무료 서비스 제공을 가능케 한 핵심 기술이었다.
- 2009년 이후 Google·Facebook·Twitter·Amazon 등이 에너지 효율성과 하드웨어 폐기 주기에 대한 우려를 계기로 모범 사례를 공유하기 시작했다는 배경도 짚는다.

## 요약
- 2002년의 "클라우드"는 사실 여러 개의 독립된 서버를 한곳에 모은 것에 불과했다.
- Google 검색과 Gmail은 진짜 1세대 클라우드 스케일 애플리케이션으로, "작은 데이터 사일로"와 최종적 일관성 덕분에 확장이 가능했다.
- 샤딩(데이터를 특정 서버에 배정)과 "수집/분산" 기법이 저비용 대규모 서비스의 핵심 기술이었다.
