# Data Types in PostgreSQL

## 개요
- 테이블 스키마를 정의할 때 사용할 수 있는 PostgreSQL의 주요 데이터 타입(문자열, 숫자, 날짜/시간 등)을 설명하는 강의

## 내용
### 문자열 타입: VARCHAR, CHAR, TEXT
- `VARCHAR(n)` : 가변 길이 문자열. 실제 저장된 길이만큼만 공간을 차지하므로 효율적이며, 길이가 정확히 고정되어 있다고 확신할 수 없는 한 기본적으로 이 타입을 사용한다.
- `CHAR(n)` : 고정 길이 문자열. GUID(전역 고유 식별자)나 특정 길이의 해시(hash)값처럼 항상 정확히 n자를 채우는 데이터에 적합하다 — 채워지지 않으면 오히려 비효율적이다.
- `TEXT` : 길이를 미리 정하지 않는 텍스트 필드. 블로그 게시물, 댓글, 웹페이지 전체처럼 길이가 가변적인 긴 텍스트에 적합하다. 단, 인덱싱·정렬(ORDER BY, 일반 WHERE)에는 적합하지 않고 LIKE 검색 정도에만 활용한다. (다른 DB는 TEXT 종류가 여러 개지만 PostgreSQL은 이 하나로 단순하다.)
- 문자 집합(character set): 서구권 문자(Latin-1/ASCII)는 8비트(1바이트)로 충분하지만, 아시아 문자나 세딜리아(cedilla) 등은 8비트를 넘어 16~32비트가 필요할 수 있다. 문자 집합은 인덱싱·정렬·최종 사용자 입력 처리에 중요한 영향을 준다.
- `GUID` : A-F와 숫자로 구성된 문자열(예: UUID)을 저장할 때 사용.
- `BYTEA` : 문자 집합과 무관한 바이너리 데이터(이미지 등)를 저장할 때 사용.

### 숫자 타입
- 정수(integer): 일반적으로 쓰는 32비트 정수(약 ±20억 범위), 공간 절약이 필요할 때의 소정수(small integer), 더 큰 범위가 필요할 때의 대정수(big integer)가 있다. 대부분의 경우 그냥 INTEGER를 쓴다.
- 부동소수점(floating point): `REAL`은 32비트·유효자릿수 7자리의 근사치 계산용(예: 장기간 평균 기온), `DOUBLE PRECISION`은 64비트로 정밀도가 더 필요한 과학 계산(예: 항성 시뮬레이션)에 쓰인다.
- 두 타입 모두 2의 거듭제곱 분모의 분수만 정확히 표현할 수 있어 0.01(1/100) 같은 값은 정확히 표현되지 않는다. 그래서 화폐(돈)를 다룰 때는 `NUMERIC(전체자릿수, 소수점자릿수)`(예: `NUMERIC(14,2)`)를 사용해 정확한 값을 유지해야 한다.

### 날짜/시간 타입
- `TIMESTAMP` : 기원전 4713년부터 아주 먼 미래까지의 시각을 64비트 정수로 표현한다.
- 과거 유닉스 시간(1970년 1월 1일 기준 초, 32비트)은 2038년에 오버플로우(overflow)되는 문제(이른바 "2038년 문제")가 있었으나, PostgreSQL은 타임스탬프를 64비트로 처리해 약 서기 300,000년까지 문제없이 다룰 수 있다.

## 예시
```sql
CREATE TABLE example (
    id SERIAL PRIMARY KEY,
    short_code CHAR(64),          -- 항상 정확히 64자인 해시/GUID
    name VARCHAR(128),            -- 가변 길이 문자열
    bio TEXT,                     -- 길이 제한 없는 긴 텍스트
    views INTEGER,
    price NUMERIC(14,2),          -- 화폐: 부동소수점 오차 방지
    created_at TIMESTAMP
);
```

## 요약
- 문자열은 길이가 고정이면 CHAR, 가변이면 VARCHAR, 아주 길면 TEXT를 사용한다.
- 부동소수점(REAL, DOUBLE PRECISION)은 근사치 계산용이며, 정확한 값이 필요한 화폐 계산에는 NUMERIC을 사용해야 한다.
- PostgreSQL의 TIMESTAMP는 64비트로 설계되어 2038년 문제에서 자유롭다.
