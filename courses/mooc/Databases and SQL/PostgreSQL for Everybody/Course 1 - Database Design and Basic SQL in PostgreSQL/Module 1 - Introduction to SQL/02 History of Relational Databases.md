# History of Relational Databases

## 개요
- 관계형 데이터베이스가 등장하기 이전 자기 테이프(magnetic tape) 기반 순차 처리 방식과, 디스크 드라이브 등장 이후 관계형 데이터베이스와 SQL이 왜 필요해졌는지 설명하는 역사 강의

## 내용
### 테이프 시대: 순차 마스터 업데이트(sequential master update)
- 예전에는 회전식 디스크가 없어 조직의 모든 데이터를 자기 테이프에 저장했다. 테이프는 선형(linear) 매체라 임의의 위치로 즉시 이동할 수 없고, 처음부터 끝까지 이동하는 데만 한 시간 가까이 걸렸다.
- 은행 거래를 예로 들면, 계좌번호 순으로 정렬된 어제 자정 기준 잔액 테이프와, 카드 분류기(card sorter)로 정렬한 오늘의 거래 카드를 준비한다.
- 밤에 테이프(마스터 데이터)와 카드(거래 데이터)를 각각 한 레코드씩 순서대로 비교하며 병합(merge)해 새로운 테이프를 만드는 방식 — 이것이 순차 마스터 업데이트다.
- 이 방식에서는 특정 순간에 메모리에 올려야 하는 데이터가 딱 "현재 비교 중인 거래 한 건"뿐이었다. 다만 실시간 조회·수정은 불가능했고, 다음날 아침까지 기다려야 갱신된 결과를 볼 수 있었다.

### 디스크 드라이브의 등장과 관계형 데이터베이스
- 디스크 드라이브(그리고 이후 SSD)가 보급되며 데이터의 물리적 위치와 상관없이 어느 지점이든 수십~수백 분의 1초 만에 접근할 수 있게 되었다. 즉 데이터 간 이동 비용이 "동일"해졌다.
- 이 변화 덕분에 굳이 순차적으로 정렬해 병합할 필요 없이, 데이터를 임의 접근(random access)으로 탐색하는 새로운 소프트웨어, 즉 관계형 데이터베이스(relational database)가 1960~1970년대에 걸쳐 발전했다.
- 관계형 데이터베이스는 수학적 기반(관계 이론)을 두고 있으며, 이론 쪽 용어(관계 relation, 튜플 tuple, 속성 attribute)와 프로그래머 쪽 용어(테이블 table, 행 row, 열 column)가 같은 개념을 가리킨다.
- 강사는 프로그래머 관점에서 테이블을 "스프레드시트"에 비유한다 — 첫 행이 열 이름(메타데이터)을 담고, 나머지 행이 실제 데이터를 담는 구조. 데이터베이스에서 이 메타데이터 구조를 스키마(schema)라고 부른다.

### SQL 표준화의 배경
- 1960~70년대 IBM, Burroughs 등 여러 벤더가 각자 다른 데이터 모델(계층형, 네트워크형 등)로 데이터베이스를 만들었고, 벤더 간 호환성이 없었다.
- 이에 미국 표준 기구(현재 ANSI/INCITS)가 나서서 "구현 방법은 관여하지 않지만, 서로 대화하는 방식(언어)은 표준화하겠다"는 접근으로 SQL(Structured Query Language, 초기 이름은 Simple Query Language)을 표준화했다.
- SQL의 핵심 특징은 비절차적(non-procedural)이라는 점 — "어떻게" 데이터를 조합할지가 아니라 "무엇"을 원하는지만 선언하면, 데이터베이스 엔진이 내부적으로 최적화해 처리한다. 이 덕분에 벤더들은 SQL이라는 공통 인터페이스 위에서 자유롭게 내부 구현을 경쟁할 수 있었다.
- 강좌의 핵심 개념은 CRUD(Create, Read, Update, Delete) — 데이터를 저장하는 어떤 시스템이든 이 네 가지 기본 동작을 지원해야 한다.

## 요약
- 테이프 시대에는 순차 마스터 업데이트 방식으로만 데이터를 갱신할 수 있어 실시간 처리가 불가능했다.
- 디스크 드라이브의 등장으로 임의 접근이 가능해지며 관계형 데이터베이스가 발전했다.
- SQL은 벤더 간 호환성을 위해 표준화된, 비절차적(선언적) 데이터베이스 질의 언어다.
- 관계(relation)=테이블, 튜플(tuple)=행, 속성(attribute)=열이며, CRUD가 데이터베이스의 핵심 동작이다.
