# Keys

## 개요
- 기본 키(primary key), 논리적 키(logical key), 외래 키(foreign key) 세 종류의 키 개념과 명명 규칙(naming convention)을 정리하는 강의

## 내용
### 세 가지 키
- **기본 키(primary key)** : 각 행에 부여되는 고유 정수(예: AC/DC 행 = 42번, Led Zeppelin 행 = 75번). 사용자에게 별 의미 없는 내부 식별자이며, URL 등 외부에 노출될 수는 있지만 그 자체로 정보를 담고 있지는 않다.
- **논리적 키(logical key)** : 사용자나 외부 세계가 실제로 알고 검색에 사용하는 값(이메일 주소, 트랙 제목, 앨범 제목 등). 검색창에 입력하는 값이 곧 논리적 키다.
- **외래 키(foreign key)** : 한 테이블의 정수 열이 다른("외부") 테이블의 행(기본 키)을 가리키는 것.

### 명명 규칙(naming convention)
- 강사가 사용하는 관례: 모든 테이블의 기본 키 열 이름은 `id`로 통일한다.
- 외래 키는 `테이블이름_id` 형식으로 짓는다 (예: `artist_id`는 artist 테이블의 행을 가리킴).
- 조직마다 규칙은 다를 수 있지만, 중요한 것은 어떤 규칙을 선택하느냐가 아니라 그 규칙을 조직 내에서 일관되게 지키는 것이다.

### 기본 키로 문자열(예: 이메일)을 쓰면 안 되는 이유
- 이메일 주소처럼 논리적 키를 기본 키로 그대로 쓰자는 제안도 있지만 권장하지 않는다 — 문자열은 숫자보다 비교·인덱싱 비용이 크고, 이메일 주소는 결혼·개명 등으로 실제로 바뀔 수 있다.
- 한 시스템 안에서 잘 설계되어 있다면 논리적 키(이메일)는 정확히 한 테이블(예: 사용자 테이블)에만 저장되므로, 값이 바뀌어도 그 한 곳만 수정하면 된다. 반면 여러 시스템에 걸쳐 있다면 시스템마다 각각 수정해야 한다.
- GUID(전역 고유 식별자) 같은 긴 임의 문자열을 기본 키로 쓰는 경우도 있지만 정수보다 효율이 떨어진다. 원칙적으로 기본 키·외래 키는 정수, 논리적 키는 문자열로 두는 것이 가장 효율적이다.

## 예시
```sql
-- 명명 규칙 예시
CREATE TABLE artist (
    id SERIAL PRIMARY KEY,      -- 기본 키
    name VARCHAR(128) UNIQUE    -- 논리적 키
);

CREATE TABLE album (
    id SERIAL PRIMARY KEY,
    title VARCHAR(128) UNIQUE,  -- 논리적 키
    artist_id INTEGER           -- 외래 키: artist 테이블을 가리킴
);
```

## 요약
- 기본 키는 각 행을 가리키는 내부용 정수, 논리적 키는 사용자가 실제 검색에 쓰는 값, 외래 키는 다른 테이블의 기본 키를 가리키는 정수 열이다.
- `id` / `테이블이름_id` 같은 명명 규칙을 일관되게 지키는 것이 규칙 자체의 선택보다 중요하다.
- 이메일처럼 바뀔 수 있는 논리적 키를 기본 키로 사용하는 것은 비효율적이며, 기본 키·외래 키는 정수로 두는 것이 표준적인 방식이다.
