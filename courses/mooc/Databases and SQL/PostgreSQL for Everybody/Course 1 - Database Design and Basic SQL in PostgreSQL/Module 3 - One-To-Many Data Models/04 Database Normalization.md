# Database Normalization

## 개요
- 논리적 데이터 모델(다이어그램)을 실제 테이블 구조(물리적 모델)로 바꾸는 정규화(normalization)의 기계적 절차를 설명하는 강의

## 내용
### 정규화의 실용적 핵심
- 데이터베이스 정규화 이론은 매우 방대하지만, 실무적으로는 간단하다: 문자열 데이터를 복제하지 말고 참조(정수 키)하라는 것이 전부다.
- 각 테이블에 기본 키(정수) 열을 추가하고, 논리적 키가 필요한 열을 구분해 표시한다. 예: Led Zeppelin=1, AC/DC=2로 한 번 삽입되면, 이후 이 문자열이 필요한 모든 곳에서는 문자열 대신 이 숫자를 사용한다.

### 다이어그램의 화살표 → 실제 열로 변환하는 절차
1. 각 테이블에 기본 키 열(`id`, SERIAL)을 추가한다.
2. 논리적 키가 될 열을 정하고 표시한다 (검색·정렬에 자주 쓰이므로 인덱스를 만들어야 한다는 신호).
3. 다이어그램의 화살표(관계)마다, 화살표가 "많은 쪽(many)"에 있는 테이블에 외래 키 열을 추가한다. 예: 앨범 한 개에 트랙이 여러 개(다대일 관계)이므로, "많은 쪽"인 트랙 테이블에 `album_id`를 추가한다.
- 이 과정은 상당히 기계적(mechanical)인 절차다 — 그림을 그린 다음, 그 화살표를 그대로 외래 키 열로 옮기기만 하면 된다.
- 예제(트랙-앨범-아티스트-장르)에서는 화살표가 3개이므로 외래 키가 3개 생기고, 테이블마다 기본 키 1개와 논리적 키 1개씩이 생겨 총 4개의 완성된 테이블이 나온다.

## 예시
- 화살표 → 외래 키 변환 규칙:
  - `트랙 → 앨범` 관계(다대일) ⇒ 트랙 테이블에 `album_id` 추가
  - `앨범 → 아티스트` 관계(다대일) ⇒ 앨범 테이블에 `artist_id` 추가
  - `트랙 → 장르` 관계(다대일) ⇒ 트랙 테이블에 `genre_id` 추가

## 요약
- 정규화의 실무적 핵심은 "문자열을 복제하지 말고 정수 키로 참조하라"는 원칙 하나로 요약된다.
- 각 테이블에 기본 키를 추가하고, 논리적 키를 표시하고, 다이어그램의 화살표를 외래 키 열로 옮기는 것이 정규화의 기계적 절차다.
- 다음 강의에서 이 구조를 실제 `CREATE TABLE` SQL 문으로 구현한다.
