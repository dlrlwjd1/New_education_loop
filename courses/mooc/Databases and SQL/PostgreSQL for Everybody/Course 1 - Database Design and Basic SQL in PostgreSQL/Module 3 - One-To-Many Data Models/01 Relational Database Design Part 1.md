# Relational Database Design Part 1

## 개요
- 데이터베이스 설계는 이론보다 경험으로 느는 "기예(art)"에 가깝다는 점을 짚고, 데이터 모델링의 가장 핵심 원칙인 "문자열 데이터의 수직 복제 금지"를 소개하는 강의

## 내용
### 데이터베이스 설계는 그림 그리기다
- 데이터베이스 설계 결과물은 결국 테이블(상자)들과 그 사이를 잇는 선(외래 키, foreign key)으로 이루어진 다이어그램으로 귀결된다. 큰 프로젝트일수록 이 데이터 모델 다이어그램이 응용 프로그램의 핵심 그 자체가 된다.
- 좋은 데이터 모델을 짜는 감각은 경험과 협업(다른 사람과 화이트보드에 그려보는 것)을 통해 길러진다.

### 왜 CSV/스프레드시트로는 부족한가
- 스프레드시트나 CSV 파일은 작은 데이터(수백 건)에서는 빠르지만, 수백만~수억 건으로 커지면 느려진다. 반면 관계형 데이터베이스는 수억 건이라도 빠르게 유지될 수 있다.
- 음악 라이브러리를 스프레드시트에 직접 입력하면 트랙마다 아티스트·앨범·장르 이름을 반복 입력하게 되는데, 이를 "수직 복제(vertical duplication)"라고 부른다. 오타 하나가 생기면 복제된 모든 곳을 일일이 찾아 고쳐야 하는 문제가 생긴다.

### 핵심 원칙: 문자열을 반복 저장하지 말고 숫자로 참조하라
- 데이터 모델링에서 가장 중요한 단일 개념: 같은 문자열 데이터를 데이터베이스에 두 번 이상 저장하지 않는다. 대신 문자열을 한 번만 저장하고, 그것을 가리키는 정수 키(숫자)를 다른 곳에서 재사용한다.
- 예: MOOC는 사용자의 이메일 주소 대신 가입 시 부여된 사용자 번호(예: 116421)를 게시글·댓글 작성자 표시 등 내부적으로 사용한다. "블랙 사바스(Black Sabbath)"라는 문자열도 한 테이블에만 저장하고, 이를 참조해야 하는 곳에서는 그 행을 가리키는 번호(예: 42)만 사용한다 — 오타를 고칠 때 한 곳만 고치면 모든 참조에 자동 반영된다.

### 사용자 인터페이스와 데이터 모델은 분리해서 생각한다
- 사용자 인터페이스(UI)에는 여전히 수직 복제된 것처럼 보이는 화면(정렬·검색이 편한 스프레드시트 형태)이 필요할 수 있다. 이는 UI 요구사항으로 그대로 수용하고, 대신 내부 데이터 모델은 압축된(문자열을 반복하지 않는) 구조로 만든 뒤, 필요할 때 다시 조합해 UI에 보여주는 방식으로 접근한다.
- 즉 각 문자열/데이터 종류를 어떤 테이블에 넣을지 결정하고, 필요하면 새 테이블을 만들고, 테이블 사이에 연결선(관계)을 그리는 것이 데이터 모델링의 핵심 작업이다.

## 요약
- 데이터베이스 설계의 결과물은 테이블과 외래 키로 이루어진 다이어그램이다.
- 핵심 원칙은 "문자열 데이터의 수직 복제 금지" — 같은 문자열을 여러 곳에 반복 저장하지 않고, 정수 키로 참조한다.
- 사용자 인터페이스의 요구사항(수직 복제처럼 보이는 화면)과 내부 데이터 모델(압축된 구조)은 분리해서 설계하고, 필요시 조합해서 보여준다.
