# Altering Table Schema

## 개요
- `CREATE TABLE` 이후 스키마를 수정해야 할 때 사용하는 `ALTER TABLE` 명령과, 파일에 저장된 SQL을 일괄 실행하는 방법을 다루는 강의

## 내용
### 스키마는 나중에 바꿀 수 있다
- 테이블을 처음 만들 때 완벽할 필요는 없다 — 열 길이를 너무 짧게 잡거나(예: 블로그 본문을 `VARCHAR(1000)`으로 만들었는데 더 긴 글이 들어오는 경우), 열 타입을 깜빡 잘못 지정하는 실수는 흔히 일어난다.
- 대부분의 실용적인 데이터베이스는 `ALTER TABLE`을 지원하며, 스키마를 바꾸면 기존 데이터가 자동으로 새 스키마에 맞게 변환된다. 심지어 서비스가 살아있는(live) 상태에서도 실행할 수 있다.
- 단, 열을 삭제(drop)하는 경우 애플리케이션이 그 열에 여전히 데이터를 쓰려고 하면 데이터가 유실될 수 있으므로 주의가 필요하다.

### 주요 ALTER TABLE 작업
- 열 타입 변경: 예를 들어 `content` 열을 `VARCHAR(1024)`에서 텍스트(길이 무제한)로 바꾸는 경우.
- 열 추가/삭제: 복사-붙여넣기 과정에서 빠뜨린 열(예: 정수형 `favorites`)을 나중에 추가할 수 있다.
- 제약 조건(constraint) 변경: 외래 키 관계나 UNIQUE 제약이 잘못된 경우, 기존 제약을 삭제하고 새 제약(예: 두 열의 조합을 고유하게)을 추가해야 할 수 있다. Stack Overflow 검색이 실용적인 참고 자료로 언급된다.

### 파일에서 SQL 일괄 실행
- 수백~수천 개의 INSERT 문이 담긴 SQL 파일을 `\i 파일명`으로 한 번에 실행할 수 있다. 이때 psql을 실행 중인 폴더에 해당 파일을 받아두어야 한다.

## 예시
```sql
ALTER TABLE post ALTER COLUMN content TYPE TEXT;
ALTER TABLE post ADD COLUMN favorites INTEGER;
ALTER TABLE post DROP COLUMN oops;
```
```
\i lesson.sql
```

## 요약
- `ALTER TABLE`로 스키마 실수를 수정하거나 스키마를 진화시킬 수 있으며, 살아있는 데이터베이스에서도 실행 가능하다.
- 열 타입 변경, 열 추가/삭제, 제약 조건 변경이 대표적인 사용 사례다.
- 대량의 SQL 명령은 파일로 저장해두고 `\i` 명령으로 일괄 실행하는 것이 효율적이다.
