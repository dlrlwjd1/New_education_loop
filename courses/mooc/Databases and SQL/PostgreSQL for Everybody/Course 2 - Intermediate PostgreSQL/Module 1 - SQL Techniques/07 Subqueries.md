# Subqueries

## 개요
- 하나의 쿼리 결과를 다른 쿼리의 입력으로 사용하는 서브쿼리(subquery/subselect)의 개념과, 데이터베이스 관리자들이 온라인 서비스에서 서브쿼리를 꺼리는 이유(최적화 방해)를 다루는 강의

## 내용
### 서브쿼리란
- 쿼리 안에 또 다른 SELECT 문(괄호로 감싼)을 넣어, 그 결과값(또는 결과 집합)을 바깥 쿼리의 조건으로 사용하는 기법이다.
- 예: 이메일로 계정 id를 찾아 그 값을 다른 쿼리의 조건에 수동으로 복사·붙여넣기 하는 대신, 그 SELECT 문 자체를 괄호로 묶어 바로 조건 안에 넣을 수 있다.
- 서브쿼리가 여러 행을 반환할 수 있는 경우에는 `=` 대신 `IN`을 사용해, 반환된 값 집합 안에 포함되는지 확인한다.

### 왜 데이터베이스 관리자(DBA)는 서브쿼리를 싫어하는가
- 서브쿼리는 내부적으로 안쪽 SELECT를 먼저 완전히 실행해 임시 테이블처럼 만든 뒤, 바깥쪽 SELECT가 그 결과를 읽는 방식으로 처리된다(강사는 이를 손으로 그린 다이어그램에 비유해 설명한다).
- 이렇게 "먼저 이걸 하고, 그 다음에 이걸 하라"고 절차적으로 지시하면, 데이터베이스 옵티마이저(optimizer)가 전체 쿼리를 하나로 보고 자유롭게 재구성·최적화할 여지가 줄어든다 — 즉 서브쿼리는 최적화 가능성을 스스로 제한하는 셈이다.
- 데이터 마이닝처럼 한 번만 실행하고 성능이 크게 중요하지 않은 경우에는 서브쿼리가 표현력 면에서 매우 유용하지만, 초당 수천 건씩 실행되는 온라인 서비스 쿼리에서는 이 성능 손실이 누적되어 문제가 된다.

## 예시
```sql
-- 수동으로 두 단계에 걸쳐 하던 것을
SELECT id FROM account WHERE email = 'ed@umich.edu';  -- 결과: 7
SELECT content FROM comment WHERE account_id = 7;

-- 서브쿼리로 한 문장에 결합
SELECT content FROM comment
WHERE account_id = (SELECT id FROM account WHERE email = 'ed@umich.edu');

-- 여러 행이 반환될 수 있는 경우 IN 사용
SELECT content FROM comment
WHERE account_id IN (SELECT id FROM account WHERE ...);
```

## 요약
- 서브쿼리는 두 번의 쿼리를 하나의 문장으로 결합해 표현력을 높여준다.
- 다만 안쪽 쿼리를 먼저 완전히 실행해야 하므로, 데이터베이스가 전체를 하나로 최적화할 여지가 줄어들어 온라인 서비스 성능 관점에서는 기피된다.
- 데이터 마이닝처럼 실행 빈도가 낮고 편의성이 더 중요한 경우에는 서브쿼리가 충분히 실용적인 선택이다.
