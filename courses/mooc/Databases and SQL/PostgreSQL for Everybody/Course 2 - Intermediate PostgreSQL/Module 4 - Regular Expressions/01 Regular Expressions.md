# Regular Expressions

## 개요
- 정규 표현식(regular expression)의 배경과 기본 문법(`^`, `$`, `.`, `*`, `+`, `[...]`, `(...)`), 그리고 PostgreSQL에서 정규식 매칭에 쓰는 `~`, `~*`, `!~`, `!~*` 연산자를 다루는 강의

## 내용
### 정규 표현식이란
- 1960~70년대 형식 언어(formal language) 연구에서 비롯된, 문자열을 매칭·파싱하기 위한 작은 "프로그래밍 언어"다. Linux의 `grep`(Global Regular Expression Print) 등 여러 도구·언어에 구현되어 있으며, 핵심 문법은 공통적이지만 언어마다 세부 기능에 차이가 있다. PostgreSQL은 비교적 보수적인 정규식 구현을 채택했다고 언급된다.

### 기본 문법(퀵 가이드)
- `^` : 줄의 시작과 일치.
- `$` : 줄의 끝과 일치.
- `.` : 임의의 한 문자(다른 와일드카드 시스템의 `*`에 해당하는 역할).
- `*` : 바로 앞 문자를 0번 이상 반복.
- `+` : 바로 앞 문자를 1번 이상 반복.
- `[aeiou]` : 대괄호 안 문자 중 하나(문자 집합, 한 글자로 취급). `[^XYZ]`처럼 맨 앞에 `^`를 넣으면 부정(그 문자들이 아닌 것).
- `[a-z0-9]` : 범위 지정.
- `(...)` : 괄호로 감싼 부분은 "추출(캡처)하고 싶은 부분"을 표시한다.

### PostgreSQL의 정규식 매칭 연산자
- `~` : 정규식과 일치하는지(대소문자 구분).
- `~*` : 대소문자 구분 없이 일치하는지.
- `!~` : 일치하지 않는지.
- `!~*` : 대소문자 구분 없이 일치하지 않는지.
- `LIKE`와의 차이: `LIKE`는 표준 SQL이라 전체 문자열을 매칭 대상으로 하므로 부분 일치를 위해 앞뒤에 `%`를 붙여야 하지만(`LIKE '%UMSI%'`), 정규식 매칭(`~`)은 애초에 문자열 전체를 훑으며 부분 문자열이라도 일치하는 곳을 찾는(암묵적 반복) 방식이라 별도의 와일드카드를 앞뒤에 붙이지 않아도 된다.

## 예시
```sql
SELECT * FROM account WHERE email ~ 'umsi';         -- 어디든 'umsi' 포함
SELECT * FROM account WHERE email ~ '^c';           -- c로 시작
SELECT * FROM account WHERE email ~ 'm$';           -- m으로 끝남
SELECT * FROM account WHERE email ~ 'edu$';         -- edu로 끝남
SELECT * FROM account WHERE email ~ '^[gnt]';       -- g, n, t 중 하나로 시작
SELECT * FROM account WHERE email ~ '[0-9]';        -- 숫자 하나 이상 포함
SELECT * FROM account WHERE email ~ '[0-9][0-9]';   -- 연속된 두 자리 숫자 포함
```

## 요약
- 정규 표현식은 `^`(시작), `$`(끝), `.`(임의 문자), `*`/`+`(반복), `[...]`(문자 집합), `(...)`(추출 대상 표시) 등의 문법으로 문자열 패턴을 표현하는 별도의 작은 언어다.
- PostgreSQL은 `~`/`~*`/`!~`/`!~*`로 정규식 매칭 여부를 검사하며, LIKE와 달리 암묵적으로 문자열 전체를 훑으며 부분 일치를 찾는다.
- 정규 표현식은 Postgres 문서와 Stack Overflow 등에서 배우고 참고하며 익히는 것이 실용적이다.
