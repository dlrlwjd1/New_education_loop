# Index Choices and Index Techniques

## 개요
- 가상의 웹 크롤러(web crawler) 사례를 통해, 긴 텍스트(URL) 열을 인덱싱하는 세 가지 전략(직접 인덱스, MD5 기반 B-트리, 해시 인덱스)의 공간·속도 트레이드오프를 실측 비교하는 강의

## 내용
### 문제 상황: 긴 URL을 어떻게 유니크하게 관리할까
- 웹 크롤러는 이미 방문한 URL을 추적해야 재크롤링을 피할 수 있다. 이때 URL 열에 `VARCHAR(128)`처럼 길이를 임의로 제한하면, 실제로는 그보다 긴 URL이 들어올 때 오류가 발생한다 — URL 길이가 고정되어 있다고 가정할 수 없으므로 `TEXT`(길이 제한 없음)로 저장하는 것이 현실적이다.

### 전략 1: 텍스트 열 자체에 UNIQUE 인덱스
- `CREATE UNIQUE INDEX ON 테이블(url);`처럼 URL 열 자체에 B-트리 인덱스를 걸면, 인덱스 안에 URL 문자열 전체가 복제되어 저장된다. URL이 길수록(예: 4000자) 인덱스 크기가 원본 데이터 크기에 육박하거나 초과할 수 있다.

### 전략 2: MD5 해시 값을 별도 열로 만들어 B-트리 인덱스
- URL을 MD5로 변환해 인덱스 표현식으로 사용(`CREATE UNIQUE INDEX ON 테이블((md5(url)))`)하거나, 아예 MD5 결과를 저장하는 `UUID` 타입 열(예: `url_md5`)을 추가로 만들어 그 위에 인덱스를 건다.
- MD5는 고정 길이(128비트)이므로 원본 URL이 아무리 길어도 인덱스 크기가 일정하게 유지된다. 조회할 때도 `WHERE url_md5 = md5('...')::UUID`처럼 검색어를 MD5로 변환해 비교하면 인덱스를 그대로 활용해 빠르게 조회된다.
- 단, 검색 조건을 인덱스 표현식과 다르게 작성하면(예: `url_md5` 대신 원본 `url` 열로 비교) 인덱스가 적용되지 않고 전체 테이블 스캔이 발생한다는 점을 실험으로 보여준다 — 인덱스를 만들 때 쓴 표현식과 WHERE 절의 표현식이 일치해야 한다.

### 전략 3: PostgreSQL 내장 해시 인덱스
- `CREATE INDEX ... USING HASH (url);`로 PostgreSQL이 자체적으로(MD5든 SHA-256이든 내부 구현은 몰라도 됨) 해시 인덱스를 만들도록 할 수 있다. 이 방식이 실험에서 가장 작은 인덱스 크기를 보였다.
- 해시 인덱스의 한계: 정확히 일치(`=`)하는 조회에만 유용하며, 정렬이나 범위·접두사 검색(`<`, `>`, `LIKE '접두사%'`)에는 전혀 도움이 되지 않는다 — 이런 조건이 필요하면 B-트리를 선택해야 한다.

### 성능 실측 요약
- 인덱스 없음(원본 URL 그대로): 관계 크기 5MB, 조회 1.7ms.
- MD5 값을 직접 계산해 별도 열 + B-트리: 관계 크기는 다소 커지지만(추가 열 때문) 조회는 약 10배 빠름.
- PostgreSQL 내장 해시 인덱스: 인덱스 크기가 가장 작고, 조회 속도도 매우 빠름(단, 이 강의를 촬영한 PostgreSQL 11 버전 기준으로는 수동 MD5+B-트리 방식보다 약간 느린 경우도 있었다고 언급).

## 예시
```sql
-- 전략 1: 원본 URL에 직접 UNIQUE 인덱스 (긴 URL이면 인덱스가 커짐)
CREATE UNIQUE INDEX cr2_url ON cr2(url);

-- 전략 2: MD5를 저장하는 별도 열 + B-트리 인덱스
ALTER TABLE cr2 ADD COLUMN url_md5 UUID;
UPDATE cr2 SET url_md5 = md5(url)::UUID;
CREATE UNIQUE INDEX cr2_md5 ON cr2(url_md5);
SELECT * FROM cr2 WHERE url_md5 = md5('lemon')::UUID;  -- 인덱스 활용

-- 전략 3: PostgreSQL 내장 해시 인덱스
CREATE INDEX cr4_hash ON cr2 USING HASH (url);
SELECT * FROM cr2 WHERE url = 'lemon';  -- 정확 일치만 지원
```

## 요약
- 긴 텍스트 열을 그대로 인덱싱하면 인덱스가 원본 데이터만큼 커질 수 있으므로, 해시 값을 이용해 인덱스 크기를 줄이는 전략이 유용하다.
- MD5 등 해시를 별도 열로 저장해 B-트리 인덱스를 걸거나, PostgreSQL 내장 해시 인덱스(`USING HASH`)를 사용하는 두 가지 방법이 있다.
- 해시 인덱스는 정확 일치 조회에만 유용하며 정렬·범위·접두사 검색에는 쓸 수 없다는 한계를 반드시 고려해야 한다.
