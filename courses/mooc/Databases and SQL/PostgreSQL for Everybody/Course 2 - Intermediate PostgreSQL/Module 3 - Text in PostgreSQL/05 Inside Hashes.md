# Inside Hashes

## 개요
- 해시 함수(hash function)의 원리(결정성·민감성·균등분포·단방향성), 비트 연산(shift, XOR, mask)을 이용한 간단한 해시 구현, 그리고 MD5·SHA-256의 배경과 한계를 다루는 강의

## 내용
### 해시 함수란 무엇인가
- 임의 길이의 데이터를 입력받아 고정 길이(예: 64/128/256비트)의 결과를 내놓는 함수이며, 같은 입력에는 항상 같은 출력을 내는 결정론적(deterministic) 함수다.
- 용도: 네트워크 전송 오류를 감지하는 체크섬(checksum, 이더넷·Wi-Fi 등 저수준 프로토콜에서 흔히 사용), 그리고 더 엄격한 기준이 요구되는 암호화 해시(cryptographic hash, 서명 검증 등). 해시는 Python 딕셔너리, 데이터베이스 인덱스에도 핵심적으로 쓰인다.

### 좋은 해시 함수의 조건
- 결정론적(deterministic): 같은 입력 → 항상 같은 출력.
- 민감함(sensitive): 입력이 한 글자만 바뀌어도 출력이 크게 달라져야 한다.
- 균등 분포(uniform distribution): 가능한 모든 출력 비트 조합이 고르게 사용되어야 한다(특정 값에 몰리면 안 됨).
- 단방향(one-way): 출력만 보고 입력을 역산할 수 없어야 한다. 다만 입력이 매우 짧은 경우(예: 비밀번호)에는 무차별 대입으로 역산이 가능해질 수 있다 — 긴 비밀번호를 권장하는 이유 중 하나다.

### 간단한 해시 함수 직접 구현
- 문자열의 각 문자를 순회하며 "이전 해시 값을 왼쪽으로 시프트(shift) → 현재 문자의 아스키 값과 배타적 OR(XOR)로 병합(merge) → 특정 비트 수로 마스킹(mask, AND 연산)"하는 과정을 반복해 고정 크기 해시 값을 만드는 예제를 직접 실행해 보여준다.
- 이 단순한 구현으로도 "Hello"와 "hello"(대소문자 하나 차이), 그리고 문자 순서를 바꾼 문자열이 서로 다른 해시 값을 낸다는 민감성을 확인한다. 다만 강사는 이 예제 자체는 "형편없는 해시 함수"이며 실제로 두 개의 다른 입력이 같은 해시(충돌, collision)를 내는 경우를 쉽게 찾을 수 있다고 밝힌다.

### NIST 공모전과 MD5/SHA-256
- 실제 안전한 해시 알고리즘 설계는 매우 어려운 작업으로, 미국 NIST(국립표준기술연구소)가 여러 해에 걸친 공개 공모전을 통해 여러 팀이 서로의 알고리즘을 공격하며 검증하는 과정으로 표준을 선정한다.
- MD5(128비트)는 초기에 널리 쓰였으나, 이후 암호학적으로 여러 결함이 발견되었다(의도적으로 같은 해시를 내는 문서 조작이 가능해짐 — 서명 위조 위험). 다만 단순 중복 문서 탐지처럼 암호학적 안전성이 필요 없는 용도에는 여전히 쓸 수 있다.
- 비밀번호를 MD5로 해시해 저장하는 방식도, 흔한 비밀번호들을 미리 계산해둔 레인보우 테이블(rainbow table)을 이용하면 사실상 역산이 가능해지는 문제가 있다.
- 이후 등장한 SHA-2 계열(SHA-256 등, 2001년 이후)은 더 길고 견고한 해시를 제공하며, PostgreSQL에는 `MD5()`, `SHA-256` 등의 내장 함수가 있다.

## 예시
```sql
SELECT MD5('hello world');
```

## 요약
- 좋은 해시 함수는 결정론적·민감함·균등 분포·단방향성을 만족해야 하며, 이는 shift·XOR·mask 같은 비트 연산의 반복으로 구현된다.
- MD5는 널리 쓰였지만 암호학적 결함(충돌, 레인보우 테이블)이 발견되어 보안 용도로는 SHA-256 등 더 안전한 해시로 대체되었다.
- 실제 안전한 해시 알고리즘은 NIST의 공개 공모·검증 과정을 통해 선정된다.
