# Character Sets in Python

## 개요
- Python(및 데이터베이스 커넥터)이 유니코드(내부 표현)와 UTF-8(외부 저장/전송 형식) 사이를 어떻게 자동으로 인코딩/디코딩하는지 설명하는 강의

## 내용
### Python 2 → 3 전환과 유니코드
- Python 2의 문자열 내부 표현은 8비트 ASCII 기반이었지만, Python 3는 모든 문자열을 유니코드로 통일했다. 이는 Python 2→3 전환에서 가장 큰 변화 중 하나였다.
- 유니코드는 문자당 32비트라 용량은 크지만, 몇 번째 문자로도 즉시 점프할 수 있어(예: 1000번째 문자는 4000바이트 지점) 메모리 내 처리에는 매우 효율적이다.
- 반면 디스크 저장, 네트워크 전송, 파일 저장 시에는 UTF-8로 변환해야 한다 — 다른 언어(PHP, R 등)와의 상호운용성을 위해서다.

### 인코딩/디코딩을 압축·압축 해제에 비유
- 외부(UTF-8) → 내부(유니코드): 디코딩(decode) — "압축을 푸는" 과정.
- 내부(유니코드) → 외부(UTF-8): 인코딩(encode) — "압축하는" 과정.
- Python의 `open()` 함수는 `encoding` 매개변수의 기본값이 사실상 UTF-8로 동작하는 경우가 대부분이라 명시하지 않아도 잘 작동한다. ASCII 파일은 UTF-8의 부분집합이므로 특별한 처리 없이도 호환된다.
- 텍스트가 아닌 원시 바이너리로 읽고 싶을 때는 바이너리 모드로 열면 디코딩 없이 바이트 그대로 다룰 수 있다.

### 네트워크와 데이터베이스에서의 자동 변환
- 파일 읽기는 대부분 자동으로 디코딩되지만, 저수준 소켓(socket)을 직접 다루는 경우에는 수동으로 디코딩해야 할 수 있다.
- 데이터베이스 커넥터(connector)는 데이터베이스 자체의 문자 집합(레거시 문자 집합이든 UTF-8이든)을 알고 있어, 데이터를 가져올 때 자동으로 유니코드로 변환해준다 — 개발자가 별도로 신경 쓰지 않아도 되는 경우가 대부분이다.
- 결론적으로 파일·네트워크·데이터베이스 작업은 대체로 자동으로 인코딩/디코딩이 처리되지만, 특정 문자가 깨져 보이는 문제가 생기면 인코딩/디코딩 단계를 의심해봐야 한다.

## 요약
- Python 3의 문자열은 내부적으로 유니코드이며, 파일·네트워크·데이터베이스와 주고받을 때는 UTF-8로 인코딩/디코딩된다.
- 이 과정은 대부분 자동으로 처리되지만, 저수준 네트워크 처리 시에는 수동 디코딩이 필요할 수 있다.
- 문자가 깨져 보이는 문제의 상당수는 인코딩/디코딩 단계의 불일치에서 비롯된다.
