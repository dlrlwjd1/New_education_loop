# Cascading Revokes

## 개요
- 권한 부여(grant)와 회수(revoke)가 사용자 간에 전이될 때 발생하는 연쇄 회수(cascading revoke)를 다룬다.
- 권한 부여 관계를 방향 접근 그래프(directed access graph)로 표현하고, 회수 시 그래프에서 어떤 노드가 권한을 잃는지 판단한다.
- 다른 부여자로부터 권한을 별도로 받은 경우, 순환(cycle)이 생긴 경우, 최초 부여자(initial grantor)가 얽힌 경우 등 여러 상황을 예시로 설명한다.

## 내용

### 기본 개념
- 대상 객체(object)는 테이블, 뷰(view), 열(column), 행(row)이 될 수 있으나 여기서는 주로 테이블/뷰를 예로 든다.
- A가 B에게 권한을 부여할 때, grant 권한까지 함께 주면 B는 그 권한을 다시 제3자에게 부여할 수 있다.
- 방향 접근 그래프에서 화살표는 "부여자 → 피부여자" 관계를 나타낸다.

### 예시 1 — 단순 연쇄 (A → B → C)
- A가 B에게, B가 다시 C에게 권한을 부여한 상태.
- A가 B에게서 권한을 회수하면, B의 권한 자체가 A로부터 온 것이므로 B는 C에게서도 권한을 회수해야 한다.
- 즉 A의 회수는 "B와, B가 부여한 모든 대상"의 권한을 없애는 것을 의미한다.

### 예시 2 — 다른 부여자가 있는 경우 (A→B→C, A→D→C)
- A→B→C, 그리고 A→D, D→C 로 C는 B와 D 두 경로에서 권한을 받는다.
- A가 B에게서 권한을 회수하면 B는 C에게서 회수하지만, C는 D로부터도 권한을 받았고 A가 D는 회수하지 않았으므로 C는 권한을 유지한다.
- 최종 그래프: A, D, C는 연결 유지, B만 제외된다.

### 예시 3 — 순환 (A→B→C→B)
- A→B→C 상태에서 C가 다시 B에게 권한을 부여한다.
- A가 B에게서 회수할 때, 단순히 A-B 화살표만 지우고 B-C 순환을 유지하면 안 된다. B는 실제로 다른 독립적 부여자로부터 권한을 받은 것이 아니기 때문이다.
- **순환 탐지(cycle detection)** 로 B와 C가 (의도했든 아니든) 서로 순환하고 있음을 식별하고 그 순환을 제거해야 한다.
- 최종 그래프: A는 유지, B와 C는 권한을 잃는다.
- 변형: 만약 DBA가 C에게도 권한을 부여했다면, C는 다른 사람으로부터 권한을 받은 것이므로 C→B 권한이 유지된다.

### 예시 4 — 최초 부여자가 순환에 포함된 경우 (A→B, A→C, C→A)
- A가 B와 C에게 부여하고, C가 다시 A에게 부여한다.
- B가 C에게서 권한을 회수할 때, 순환 탐지로 A→B, B→C, C→A 전체 순환을 지워야 할 것처럼 보이지만, A는 다른 곳에서 권한을 얻었으므로 A는 권한을 유지한다.
- A는 최초 부여자이므로 자기 자신이 실수로 권한을 잃게 만들 수 없다.

## 요약
- 회수는 연쇄적으로 전파되어, 회수당한 사용자가 부여한 모든 하위 권한까지 회수된다.
- 다른 독립적 부여자로부터 별도로 권한을 받았다면 회수 후에도 권한을 유지한다.
- 서로 권한을 주고받는 순환은 순환 탐지로 식별해 제거해야 하며, 단순한 순환은 회수 시 함께 사라진다.
- 최초 부여자는 자신이 시작한 부여 사슬 때문에 스스로 권한을 잃지 않는다.
