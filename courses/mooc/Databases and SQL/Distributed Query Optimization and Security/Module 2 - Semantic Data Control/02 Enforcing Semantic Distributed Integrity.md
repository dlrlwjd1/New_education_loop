# Enforcing Semantic Distributed Integrity

## 개요
- 분산 환경에서 의미적 무결성 제약(semantic integrity constraint)을 어떻게 정의하고 강제하는지 다룬다.
- 제약은 세 가지 유형 — 개별 단정(individual assertion), 집합 지향 단정(set-oriented assertion), 다중 관계 제약(multi-relation constraint) — 으로 나뉜다.
- 조각(fragment)의 정의 술어(predicate)와 실제 데이터 양쪽에 대해 검사하며, 한 사이트라도 위반하면 전역적으로 거부한다.

## 내용

### 개별 단정(individual assertion)
- 하나의 테이블 또는 그 테이블의 조각들과 함께 식별되는 단정으로, 각 조각이 있는 사이트로 전송된다.
- 검사는 두 가지 대상에 대해 수행된다.
  - 조각 술어(fragment predicate): 조각이 어떻게 정의되었는가.
  - 데이터: 실제 데이터가 단정과 일관되는가.
- 전제: 이미 존재하는 데이터베이스에 나중에 제약(단정)을 정의하는 상황이다.
- 한 사이트에서 술어가 거짓이거나 데이터가 맞지 않으면, 전역적으로(globally) 단정을 거부하고 그 제약은 존재하지 않는 것으로 처리한다.

### 개별 단정 예시 — Employee 조각
- 조각 정의:
  - Employee1: 사번(employee number) 0 ~ 300
  - Employee2: 사번 300 ~ 600
  - Employee3: 사번 > 600
- 정의하려는 제약: 사번 < 400
- 조각별 검사 결과:
  - Employee1: 정의(0~300)와 모순 없음 → 데이터도 일관되면 수용.
  - Employee2: 정의(300~600)와 부분적으로 겹침. 400 이상 사번이 실제 데이터에 **없으면** 수용, **있으면** 단정 거부.
  - Employee3: 조각 정의 자체가 사번 > 600 이므로 제약(< 400)과 정면 모순 → 전역 거부(globally reject).

### 집합 지향 단정(set-oriented assertion)
- 다중 관계(multi-relational)이며 최소 하나의 조인 술어(join predicate)를 포함한다.
- 단일 관계와 함께 저장되므로, 그 관계 조각을 저장하는 모든 사이트에 저장된다.
- 술어만으로는 검사가 불가능하고 데이터에 대해서만 검사 가능하며, 많은 경우 실제 조인을 수행해야 참/거짓을 판정할 수 있다.

### 집합 지향 단정 예시 — Assignment/Project
- 제약: 대응하는 project 행이 있어야만 새 assignment 행을 삽입할 수 있다.
- 세미조인 조각화(semi-join fragmentation) / 유도 조각화(derived fragmentation)를 이용:
  - Assignment를 Project의 조각에 맞춰 조각화하여, 각 assignment 조각이 대응하는 project 조각과 같은 사이트에 있게 한다.
  - 삽입 시 한 사이트만 검사하면 되고, **통신이 필요 없다**.
- Project가 두 술어로 수평 조각화된 경우(예: project 번호 < 300, project 번호 ≥ 300):
  - 각 새 튜플은 두 project 조각 중 하나와 비교되므로 새 튜플당 **최대 1회 통신** 발생.
- Project가 조인 기준과 무관한 술어(예: project 이름)로 조각화된 경우:
  - 각 새 assignment를 모든 사이트의 모든 project 행과 비교해야 하므로 매우 비용이 큰 검사가 된다.

### 무결성 제약 강제 방법
- **개별 단정**: 갱신이 유발한 차등 관계(differential relation) R+(삽입), R−(삭제)가 해당 사이트의 모든 단정을 만족하면 그 사이트가 갱신을 수용, 하나라도 거부하면 거부.
- **집합 지향(단일 관계, 튜플 변수 사용)**: 예 — 두 신규 사원의 사번이 같으면 이름도 같아야 하고, 기존 테이블의 사번과 같은 사번이면 이름도 같아야 한다. R+, R−를 각 사이트에 보내 각 사이트가 검증하며, 한 사이트라도 거부하면 거부.
- **다중 관계 제약(multi-relation constraint)**: 여러 관계가 얽히고 보통 집계(aggregate)를 포함한다. 각 사이트에서 실패할 레코드를 조회하고, 하나라도 실패하면 거부.

### 다중 관계 제약 및 집계 예시
- 예: `select new *, new assignments and projects` 형태로, 새 project에 대응하는 project가 존재하는지 보장하려 한다.
- `count` 같은 집계 연산이 개입한다.
- 모든 신규 튜플을 project 조각을 가진 각 사이트로 보내고 중앙 관리자(central manager)로 되돌려야 한다.
- 하나라도 거부하거나 전부 거부하면 제약 위반으로 삽입을 거부, 아니면 수용.
- 집계(aggregation)는 다중 관계 제약과 유사하게 복잡하며, `count` 연산 때문에 검사가 특히 복잡해진다.

## 요약
- 개별 단정은 조각 술어와 데이터 양쪽을 검사하고, 한 사이트라도 위반하면 전역 거부한다.
- 조각 정의가 제약과 정면 모순이면 즉시 전역 거부한다(예: 사번 > 600 조각 vs 사번 < 400 제약).
- 유도 조각화로 assignment를 project에 맞춰 조각화하면 무결성 검사에 통신이 필요 없다.
- 조인 기준과 무관하게 조각화되면 모든 사이트의 모든 행과 비교해야 하므로 비용이 급증한다.
- 무결성 검사 비용은 집계의 복잡도와 동시에 검사하는 조각 간 관계 수에 따라 단순 ~ 복잡으로 변한다.
