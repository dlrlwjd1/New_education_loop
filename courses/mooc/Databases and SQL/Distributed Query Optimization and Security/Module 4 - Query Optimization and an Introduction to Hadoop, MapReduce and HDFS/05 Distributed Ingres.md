# Distributed Ingres

## 개요
- 분산 데이터베이스(fragmented database)에서는 각 쿼리 단계마다 프래그먼트를 어느 사이트로 이동시킬지 전략을 결정해야 한다.
- 중앙 집중식 Ingres와 동일하게 분리(detachment)와 대입(substitution)을 사용하지만, 분산 환경에서는 프래그먼트를 어느 사이트로, 어떤 순서로 이동시킬지에 따라 여러 옵션이 생기고 복잡도가 훨씬 높아진다.
- 통신 시간(communication time)이 분산 데이터베이스 시스템에서 매우 중요한 비용 요소이므로, 이를 최소화하는 전략을 선택해야 한다. 네트워크 아키텍처(점대점 vs. 브로드캐스트)에 따라 최선의 전략이 달라진다.

## 내용

### 분산 환경에서 조인 전략의 다양성
- 예시 분산 구성: site 1에는 project 테이블과 assignment 테이블의 프래그먼트 1(assignment1)이 있고, site 2에는 employee 테이블과 assignment 테이블의 프래그먼트 2(assignment2)가 있다.
- Ingres의 분리(detachment) 1단계와 동일하게, project 테이블에서 조건을 적용해 임시 테이블 P_new를 만든다.
- 2단계에서는 분산 환경이라 여러 옵션이 가능하다. 예시로 다음 세 가지가 제시된다.
  1. **옵션 1**: P_new를 site 2로 복제 이동시켜, site 1에서는 P_new와 assignment1을 조인하고, site 2에서는 P_new와 assignment2를 조인한 뒤, site 1의 조인 결과를 site 2로 보내 두 결과를 union한다.
  2. **옵션 2**: assignment2를 site 1로 이동시켜 assignment1과 union한 뒤, 통합된 assignment 테이블과 P_new를 조인하고, 그 결과를 site 2로 전송한다.
  3. **옵션 3**: P_new와 assignment1을 site 2로 이동시켜 assignment1과 assignment2를 union한 뒤, P_new와 통합된 assignment 테이블을 조인한다.
- 각 옵션마다 이동시켜야 하는 테이블/프래그먼트가 다르므로, 통신 비용을 최소화하는 방향으로 전략을 선택해야 한다.

### 네트워크 아키텍처에 따른 전송 비용 비교
- 예시 상황: 4개 사이트(site 1~4)가 있고, project 테이블은 4개 사이트 모두에 프래그먼트가 분산되어 있으며(총 3,000행이 site 3 이외의 세 사이트에 있다고 가정), assignment 테이블은 site 3에만 존재(2,000행)한다.
- **점대점(point-to-point) 아키텍처**: 각 사이트가 개별 통신 경로로 연결되어 있어, 여러 사이트로 데이터를 보내려면 각각 개별적으로 전송해야 한다.
  - project의 나머지 프래그먼트(site 1, 2, 4에 있는 3,000행)를 site 3(assignment가 있는 곳)으로 보내는 비용: 약 `3,000 × (튜플 전송 비용)`
  - 반대로 assignment(2,000행)를 site 1, 2, 4 각각에 개별적으로 보내는 비용: `2,000 × 3 × (튜플 전송 비용)` = `6,000 × (튜플 전송 비용)`
  - 따라서 점대점 아키텍처에서는 **project 프래그먼트를 assignment가 있는 site 3으로 보내는 것**이 더 저렴한 전략이다.
- **브로드캐스트(broadcast) 아키텍처**: 한 번 전송하면 모든 사이트가 동시에 수신할 수 있어, 여러 사이트로 보낼 때마다 별도 비용이 들지 않는다.
  - assignment(2,000행)를 각 사이트로 브로드캐스트하는 비용: `2,000 × (튜플 전송 비용)` (한 번만 전송)
  - project 프래그먼트(3,000행)를 site 3으로 보내는 비용: `3,000 × (튜플 전송 비용)`
  - 따라서 브로드캐스트 아키텍처에서는 **assignment 테이블을 각 site로 보내는 것**이 더 저렴한 전략이다.

## 요약
- 분산 Ingres는 중앙 집중식 Ingres의 분리(detachment)/대입(substitution) 개념을 그대로 사용하되, 프래그먼트를 어느 사이트로 옮길지에 따라 여러 실행 전략이 존재하며 통신 비용이 핵심 고려 요소가 된다.
- 네트워크 아키텍처가 **점대점(point-to-point)**이면 여러 사이트로 보낼 때마다 비용이 누적되므로, 데이터 양이 적은 쪽(예: 흩어진 project 프래그먼트, 총 3,000행)을 데이터가 몰려 있는 사이트(assignment, site 3)로 이동시키는 것이 유리하다.
- 네트워크 아키텍처가 **브로드캐스트(broadcast)**이면 한 번의 전송으로 여러 사이트에 도달하므로, 더 적은 총 행 수(assignment의 2,000행)를 브로드캐스트하는 것이 유리하다. 즉 최선의 전략은 네트워크 아키텍처 유형에 따라 달라진다.
