# Query Operations Costs

## 개요
- 관계형 데이터베이스의 주요 연산(선택, 사영, 그룹화, 조인)을 구현하는 여러 방법과 그 계산 복잡도(computational complexity)를 빅오(big O) 표기로 정리한다.
- 인덱스 유무(인덱스 없음, B+ 트리 인덱스, 해시 인덱스)에 따른 선택 비용 차이를 설명한다.
- 조인 구현 방식(교차곱, 인덱스 이용, 정렬된 테이블 병합)의 비용을 비교한다.

## 내용

### 인덱스 없는 선택 (selection, no index)
- n개 행을 순차 탐색해야 하며, 일치를 찾으려면 최악의 경우 n개 행을 모두 읽는다.
- 평균적으로 테이블의 절반(n/2)을 읽지만, 빅오에서는 상수를 제거하므로 **O(n)** — 선형 시간(linear time) 연산.

### B+ 트리 인덱스를 이용한 선택
- 대부분의 관계형 DB는 B+ 트리(B plus tree)로 인덱싱한다. 키 값 기준으로 균형 잡힌 트리(balanced tree)에 행을 저장하며, 리프(leaf)에는 인덱스 값과 원본 행 위치 포인터가 담긴다.
- B+ 트리의 장점은 항상 균형이 유지된다는 것. 한쪽 분기가 너무 깊어지면 분할(split)해 트리 전체를 재구성한다. 따라서 트리의 최하단 깊이는 항상 **log n**.
- 검색은 **O(log n)** 읽기로 행을 찾는다. n번 읽는 인덱스 없는 방식보다 훨씬 빠르다.
- 실제 B+ 트리는 이진(binary)이 아니라 노드당 수천 개 분기를 가질 수 있어 매우 짧다.
- 리프는 정렬(sorted)되어 있고 순방향(때로는 역방향) 포인터로 연결되므로, 같은 값(예: 여러 Harry)을 찾을 때 첫 번째를 찾은 뒤 인접 리프를 이어 읽어 각 후속 읽기는 **O(1)**. 총 검색 시간은 **O(log n)**.

### 해시 인덱스 (hash index)
- 검색 키에 해시 함수(hash function)를 적용해 얻은 값으로 해시 인덱스 항목을 찾고 포인터를 따라 행에 접근. **O(1)** 연산으로 매우 빠르다.
- 한계: 행 수가 매우 커지면 서로 다른 값이 같은 해시 값으로 충돌(collision)해, 인덱스 항목이 여러 행을 담는 버킷 체인(bucket chain)을 가리키게 된다. 체인 안 각 원소를 확인해야 하므로, 해시 인덱스가 작고 행이 많으면 검색이 **O(n)** 에 근접할 수 있다.
- 이 수업에서는 항상 공간이 충분한 희소 해시 인덱스(sparse hash index)를 가정하며, 해시 인덱스 읽기 비용은 **O(1)** 로 본다.

### 중복 제거 사영 (project with duplicate elimination)
- 레코드 검색은 O(n)이지만, 중복 제거를 위한 정렬(sorting)은 본질적으로 **O(n log n)** — 최선의 정렬 알고리즘도 n log n임이 증명되어 있다.
- 총 비용 O(n log n) + O(n) 중 더 큰 항을 취해 **O(n log n)**.

### 그룹화 (grouping)
- 레코드를 그룹화하려면 정렬이 필요하므로 **O(n log n)**.
- 초기 테이블이 이미 정렬되어 있으면 정렬이 불필요해 검색만 **O(n)**.

### 교차곱 / 카테시안 곱 (Cartesian product)
- 인덱스가 없다고 가정. 테이블 A의 각 행마다 테이블 B의 모든 행을 순회하므로 n × n = **O(n²)** — 매우 비싸다. 가능한 한 피한다.

### 인덱스를 이용한 조인 (iterating with an index)
- A(n행), B(n행), B가 인덱싱됨. A의 각 행마다 B의 인덱스에서 log n 깊이 탐색으로 대응 행을 즉시 찾는다.
- 총 비용 **O(n log n)** — 교차곱 O(n²)보다 훨씬 빠르다.

### 정렬된 테이블의 병합 조인 (merge join on sorted tables)
- 가능한 최선의 조인. 두 테이블이 조인 필드로 정렬되어 있다고 가정.
- 각 테이블에 현재 포인터(current pointer)를 두고, 정렬되어 있으므로 포인터를 순차적으로 아래로만 이동. 어느 포인터도 위로 되돌릴 필요가 없다.
- A와 B를 각각 한 번씩 읽으므로 2n 읽기, 상수를 제거하면 **O(n)**.

## 예시
연산별 복잡도 요약:
```
선택 (인덱스 없음)        : O(n)
선택 (B+ 트리 인덱스)     : O(log n)
선택 (해시 인덱스, 희소)  : O(1)
중복 제거 사영            : O(n log n)
그룹화                   : O(n log n)  (이미 정렬 시 O(n))
교차곱                   : O(n²)
인덱스 이용 조인          : O(n log n)
정렬 테이블 병합 조인     : O(n)
```

## 요약
- 선택 비용은 인덱스에 따라 O(n)(없음), O(log n)(B+ 트리), O(1)(희소 해시)로 크게 달라진다.
- B+ 트리는 항상 균형을 유지해 log n 깊이를 보장하며, 정렬된 리프 연결로 같은 값 다중 조회가 빠르다.
- 해시 인덱스는 O(1)이지만 충돌로 버킷 체인이 길어지면 O(n)에 근접할 수 있다.
- 정렬(및 그에 의존하는 중복 제거 사영·그룹화)은 O(n log n), 교차곱은 O(n²)로 피해야 하며, 인덱스 조인(O(n log n))과 정렬 병합 조인(O(n))이 효율적이다.
