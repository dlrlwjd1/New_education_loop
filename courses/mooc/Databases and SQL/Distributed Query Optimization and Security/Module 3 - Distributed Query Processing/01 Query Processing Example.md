# Query Processing Example

## 개요
- 간단한 조인 쿼리 하나를 여러 관계 대수(relational algebra) 표현으로 바꿔가며, 논리적으로 동일해도 실행 비용이 크게 다름을 보인다.
- 중앙 집중식(centralized)과 분산(distributed) 데이터베이스에서 쿼리 최적화 문제가 왜 지수적(exponential)으로 어려운지 설명한다.
- 조각화된 분산 DB에서 두 실행 전략의 자원 비용(resource cost)과 응답 시간(response time)을 통계 기반으로 정량 비교한다.

## 내용

### 예시 쿼리
- Employee와 Assignment 테이블을 조인하고, responsibility가 manager인 행을 골라 employee name을 조회하는 단순 쿼리.

### 관계 대수 표현의 세 가지 형태
- 표현 1(가장 단순): Employee × Assignment 교차곱(cross product) → 사번 일치 선택 → responsibility='manager' 선택 → employee name 사영(projection).
- 표현 2: `responsibility='manager'` 선택을 Assignment 테이블 쪽으로 밀어넣어(push down) Assignment를 먼저 축소한 뒤 교차곱. responsibility 열은 Assignment에만 있으므로 가능. 결과는 동일하나 더 작은 테이블로 교차곱하므로 성능이 낫다는 감(sense)을 준다.
- 표현 3(가장 효율적): 선택을 Assignment로 밀어넣어 축소한 뒤 Employee와 **자연 조인(natural join)** 수행 → employee name 사영. 자연 조인이 전체 교차곱 후 필터링보다 효율적이다.
- 세 표현은 대수 법칙(laws of query algebra)에 따라 모두 동등하며 같은 결과를 낸다. 다만 쿼리 계획(query plan)으로 보면 표현 3 > 표현 2 > 표현 1 순으로 효율적이다.

### 중앙 집중식 vs 분산 시스템
- 중앙 집중식: 최적의 관계 대수 표현을 찾는 문제로, 일반적으로 난해(intractable)하다. 쿼리가 복잡해질수록 표현 수가 지수적으로 늘어나므로 휴리스틱(heuristic)으로 가망 없는 것을 걸러낸다.
- 분산: 사이트 간 데이터 교환의 통신 시간(communication time), 테이블/조각의 위치, 복제 데이터의 사이트 선택까지 고려해야 해 더 복잡하다. 병렬 처리(parallel processing)의 이점이 있지만 해 공간(solution space)은 여전히 지수적이며 중앙 집중식보다 엄격히 더 크다.

### 조각화 제약과 두 전략
- 조각 배치:
  - Employee1 → 사이트 3, Employee2 → 사이트 4
  - Assignment1 → 사이트 1, Assignment2 → 사이트 2
  - 결과는 사이트 5로 전송
- **전략 1**: 사이트 1, 2에서 각 Assignment 조각을 읽어 manager 행만 필터링 → 사이트 3, 4로 전송 → 각 사이트에서 Employee 조각과 자연 조인 → 사이트 5에서 결과 합집합(union).
- **전략 2**: 모든 조각을 사이트 5로 보내고 모든 연산을 사이트 5에서 수행. Assignment 조각들을 union 후 selection 적용, Employee 조각들을 union 후 자연 조인.

### 비용 계산용 통계와 측정 단위
- 튜플 접근(tuple access) = 1 단위 시간, 데이터 전송(transfer) = 10 단위 시간.
- Employee 400 튜플 → 조각당 약 200 튜플.
- Assignment 1,000 튜플 → 조각당 약 500 튜플.
- manager는 20명 → 조각당 약 10명.
- 정확한 통계는 오버헤드가 크고 필수도 아니며, 좋은 추정치(good estimate)만으로 충분하다.

### 전략 1 — 자원 비용
- Assignment 읽기: (500 + 500) × 1 = 1000
- manager 전송: (10 + 10) × 10 = 200
- Assignment' 쓰기: (10 + 10) × 1 = 20
- Employee' 조인 생성(인덱스 가정, 튜플당 2회 읽기): (20 + 20) × 1 = 40
- 사이트 5로 전송: (10 + 10) × 10 = 200
- Employee 행 쓰기: (10 + 10) × 1 = 20
- union 결과 읽기: (10 + 10) × 1 = 20
- 합계: 1500 단위

### 전략 1 — 응답 시간 (병렬 실행 가정)
- 병렬이므로 같은 단계는 한쪽 비용만 계산.
- Assignment 읽기: 500 × 1 = 500
- 전송: 10 × 10 = 100
- 쓰기: 10 × 1 = 10
- 조인 읽기: 20 × 1 = 20
- 전송: 10 × 10 = 100
- 쓰기: 10 × 1 = 10
- union 읽기: (10 + 10) × 1 = 20
- 합계: 760 단위
- (참고: 분산 시스템에서 실제로 병렬 실행을 얻기는 매우 어려우므로 이는 최선의 경우 분석이다.)

### 전략 2 — 자원 비용
- Employee/Assignment 읽기: 400 + 1000 = 1400
- 사이트 5로 전송: (400 + 1000) × 10 = 14000
- 사이트 5에 쓰기: 1400 × 1 = 1400
- Assignment 선택 후 Employee와 조인(인덱스 없음): 1000 읽기 + (400 × 20) = 8000
- 합계: 25800 단위 (매우 비쌈)

### 전략 2 — 응답 시간
- 병렬 전송 최대값: 조각당 max(200, 500) × 1 = 500
- 사이트 5로 전송: 500 × 10 = 5000
- 쓰기: 500 × 1 = 500
- Assignment 선택(1000 접근) 후 인덱스 없는 Employee와 조인: 400 × 20 = 8000
- 합계: 15000 단위

### 결론
- 자원 비용: 전략 1 = 1500 vs 전략 2 = 25800
- 응답 시간: 전략 1 = 760 vs 전략 2 = 15000
- 자원 비용이든 응답 시간이든 전략 1이 압도적으로 우수하다. 데이터베이스 구조와 통계를 알면 실제 분석으로 더 나은 쿼리 계획을 예측하고 나쁜 계획을 제거할 수 있다.

## 예시
비용 계산 파라미터:
```
튜플 접근 = 1 단위, 전송 = 10 단위
Employee = 400 튜플 (조각당 ~200)
Assignment = 1000 튜플 (조각당 ~500)
manager = 20명 (조각당 ~10)

전략 1: 자원비용 1500,  응답시간 760
전략 2: 자원비용 25800, 응답시간 15000
```

## 요약
- 논리적으로 동일한 관계 대수 표현도 실행 계획으로는 비용이 크게 다르며, 선택/사영을 아래로 밀어넣고 교차곱 대신 자연 조인을 쓰는 표현이 유리하다.
- 최적 표현 탐색은 중앙 집중식에서 난해하고, 분산에서는 통신 비용·위치·복제 때문에 더 어렵다.
- 통계(테이블 크기, 조각 크기, 값 분포)는 전략 비용을 예측하는 데 필수이며 정확치보다 좋은 추정치가 실용적이다.
- 필터링을 사이트에서 먼저 수행하는 전략 1이 모든 데이터를 한 사이트로 모으는 전략 2보다 자원 비용·응답 시간 모두에서 훨씬 우수하다.
