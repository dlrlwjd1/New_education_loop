# Database Architecture Categories

## 개요

- 분산 DB 아키텍처를 자율성(autonomy), 분산 정도(distribution), 이질성(heterogeneity)의 세 축으로 분류한다.
- client-server, peer-to-peer와 통합 수준의 트레이드오프를 설명한다.

## 내용

### 자율성

긴밀한 통합은 하나의 DB처럼 동작한다. 반자율 시스템은 각 DB가 공유할 데이터를 정하고, 완전 격리는 로컬 설계·실행을 독립적으로 유지한다. 설계, 통신, 실행의 자율성을 따로 볼 수도 있다.

### 분산과 이질성

분산 정도는 단일 시스템, client-server, 완전한 peer-to-peer로 나눌 수 있다. 이질성은 하드웨어, 데이터 모델, 질의 언어와 트랜잭션 모델이 얼마나 다른지를 뜻한다.

### 처리 책임의 위치

client-server에서는 서버가 의미 검증, 최적화, 트랜잭션과 복구를 담당한다. peer-to-peer 분산 DBMS는 전역 스키마와 디렉터리로 질의를 나눈 뒤 각 로컬 서버에 부분 질의를 보낸다.

## 예시

| 구성 | 자율성 | 분산 | 이질성 |
|---|---|---|---|
| 통합 동종 DB | 낮음 | peer-to-peer | 낮음 |
| 연합 DB | 중간 | 여러 사이트 | 높을 수 있음 |
| 독립 DB 통합 | 높음 | 여러 사이트 | 높음 |

## 요약

- 세 축은 독립적이므로 요구사항에 맞춰 조합한다.
- 자율성이 높을수록 중앙 통제와 최적화 정보는 줄어든다.
- 이질성이 높을수록 스키마·언어·트랜잭션 변환 비용이 커진다.
