# Multi-Database Management System

## 개요

- 기존의 독립 DB들을 사후에 통합하는 다중 데이터베이스 관리 시스템(multi-DBMS)을 설명한다.
- 처음부터 설계하는 분산 DBMS의 top-down 방식과 기존 시스템을 묶는 bottom-up 방식의 차이를 다룬다.

## 내용

### 로컬 자율성 보존

각 로컬 DB에는 기존 스키마와 사용자 공동체가 있다. 통합 이후에도 로컬 외부 뷰와 애플리케이션은 그대로 동작해야 하며, 공유할 데이터만 전역 계층에 노출할 수 있다.

### 전역 개념 스키마

전역 개념 스키마(GCS)가 있으면 공유되는 로컬 데이터의 의미와 매핑을 한곳에서 제공한다. GCS가 없으면 전역 사용자가 각 로컬 스키마와 조인 관계를 직접 알아야 하므로 부담이 커진다.

### 질의 언어

unilingual 방식은 전역 질의 언어 하나를 강제한다. multilingual 방식은 여러 로컬 질의 언어를 받아 변환하지만 통합 계층의 구현이 훨씬 복잡하다.

## 예시

```text
기존 CRM DB ─┐
             ├─ Global Conceptual Schema ─ Global analytics view
기존 ERP DB ─┘

CRM·ERP의 기존 로컬 애플리케이션은 각 로컬 스키마를 계속 사용
```

## 요약

- multi-DBMS는 이미 존재하는 자율 DB를 bottom-up으로 통합한다.
- GCS는 공유 데이터와 의미 매핑의 범위를 정의한다.
- 로컬 호환성을 지키면서 전역 사용자 요구를 추가해야 한다.
