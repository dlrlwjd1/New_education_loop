# Problems This Course Addresses

## 개요

- 분산 DB 설계가 해결해야 하는 fragment·복제, 질의 계획, 디렉터리, 동시성·교착 상태와 복구 문제를 개괄한다.
- 정확한 최적해가 지나치게 비싼 문제에는 휴리스틱을 적용한다.

## 내용

### 설계와 질의 처리

테이블 전체를 모든 사이트에 복제하면 저장·갱신 비용이 커진다. 행 또는 열을 fragment로 나누고 필요한 위치에 배치하면 지역성을 높일 수 있다. 분산 조인 순서와 데이터 이동 계획도 경우의 수가 매우 많으므로 통신 비용과 병렬성을 고려한 휴리스틱이 필요하다.

### 메타데이터와 운영 정확성

전역 개념 스키마, 사이트별 논리 스키마와 물리 스키마의 디렉터리를 중앙화할지 분산할지 결정한다. 동시 갱신은 pessimistic·optimistic 제어, lock·timestamp 등을 통해 충돌을 막는다.

### 교착 상태와 장애 복구

분산 자원을 서로 기다리는 교착 상태에는 예방, 회피 또는 탐지·복구 전략이 필요하다. 커밋된 데이터는 장애 후에도 남아야 하므로 로그 기반 복구와 분산 commit protocol이 필요하다.

## 예시

```text
설계 문제: Customer를 지역별 행 fragment로 나눌 것인가?
질의 문제: 원격 Order를 이동할 것인가, Customer fragment를 이동할 것인가?
정확성 문제: 두 사이트 갱신 중 한 사이트가 실패하면 전체를 commit할 것인가?
```

## 요약

- fragment와 복제 배치는 이후 질의 비용을 좌우한다.
- 네트워크 데이터 이동량이 분산 질의의 핵심 비용이다.
- 동시성, 교착 상태와 복구는 분산 환경에서 사이트 간 합의 문제로 확장된다.
