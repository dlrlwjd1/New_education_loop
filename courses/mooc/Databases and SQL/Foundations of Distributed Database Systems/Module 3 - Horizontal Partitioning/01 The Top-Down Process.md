# The Top-Down Process

## 개요

- 새 분산 DB를 요구사항에서 시작해 전역·로컬 설계로 내려가는 top-down 과정을 설명한다.
- 개념 설계와 사용자 view 설계를 함께 분산 배치 결정에 사용한다.

## 내용

### 요구사항 분석

저장할 데이터와 관계뿐 아니라 누가, 어디에서, 어떤 질의를 얼마나 자주 실행하는지 조사한다. 분산 설계에는 데이터 요구와 접근 위치가 모두 필요하다.

### 두 설계 입력

개념 설계는 전체 엔터티와 관계를 표현하는 전역 개념 스키마와 ERD를 만든다. view 설계는 사용자·애플리케이션마다 필요한 외부 스키마와 접근 패턴을 만든다.

### 분산·로컬·물리 설계

전역 스키마와 view 사용 정보를 바탕으로 fragment와 사이트 배치를 결정한다. 이후 각 사이트의 로컬 개념 스키마와 물리 저장 구조를 설계한다. 운영 통계를 다시 요구사항에 반영해 반복 개선한다.

## 예시

```text
요구사항
 ├─ 개념 설계 → Global ERD
 └─ View 설계 → 사이트별 query/access frequency
          ↓
   분산 fragment·배치 설계
          ↓
   로컬 스키마·물리 설계
          ↓
   운영 통계 feedback
```

## 요약

- 데이터 구조와 사용자 접근 위치를 함께 수집한다.
- 전역 개념 스키마와 외부 view가 분산 설계의 입력이다.
- 실제 사용 패턴으로 fragment와 배치를 지속해서 조정한다.
