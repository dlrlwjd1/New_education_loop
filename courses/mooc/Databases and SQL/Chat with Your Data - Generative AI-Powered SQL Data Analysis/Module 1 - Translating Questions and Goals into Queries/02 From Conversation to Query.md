# From Conversation to Query

## 개요
- 질문을 SQL 쿼리로 변환하는 가장 기본적인 실습을 통해, **AI에게 데이터베이스 맥락(context)을 주는 것의 중요성**과 **AI가 만드는 가정(assumption)/환각(hallucination)의 위험성**을 다루는 강의.

## 내용
### 기본 실습 — 비디오 대여 테이블로 쿼리 생성하기
- 비디오 대여점의 간단한 테이블을 예시로 사용.
- 프롬프트: "이 MySQL 9.2.0 테이블을 기반으로, 가장 인기 있는 대여 항목을 알려주는 쿼리를 작성해줘." — 이때 **테이블 설계를 스크린샷으로 첨부**해 컨텍스트를 제공.
- 결과: 쿼리가 실행되고 결과가 나오지만, **영화 제목(title) 대신 inventory_id만** 나와서 원하는 정보가 아니었음.

### 대화를 이어가며 쿼리 개선하기 — "새 대화로 시작하지 마라"
- 원하는 결과가 아니라고 해서 대화를 버리고 새로 시작하지 않는다. **"데이터와 채팅한다"는 것은 대화를 계속 이어가며 맥락을 쌓아가는 것**을 의미.
- 후속 프롬프트: "제목(title)도 필요해."
- AI의 반응이 이 강좌 전체에서 중요하게 다룰 핵심 현상을 보여줌: **AI는 (내가 알려주지 않은) 데이터베이스 구조에 대해 스스로 "가정(assumption)"을 한다.**
  - "다음과 같은 스키마 구조를 가정하겠습니다"라고 말하며 스스로 추측한 스키마를 기반으로 쿼리를 다시 작성.
  - 이번 사례에서는 그 가정이 우연히 맞아서 올바른 결과가 나왔다.

### 가정이 틀렸을 때 벌어지는 일 — "연체 대여(late rentals)" 사례
- 프롬프트: "이 MySQL 9.2.0 테이블 기반으로, 연체된 모든 대여를 찾는 SQL 쿼리를 작성해줘."
- 쿼리를 실행하니 **결과가 0건** — 뭔가 잘못됨.
- 후속 프롬프트: "0건이 나왔어. 문제를 진단할 수 있는 간단한 SELECT문을 작성해줘."
- 진단 쿼리 실행 결과를 다시 AI에게 보여주니, AI가 문제를 정확히 짚어냄: **"rental_date가 2025년인데 return_date가 2005년이라 계산이 큰 음수가 된다"** — 즉 **데이터 품질 문제(data quality problem)**였다는 것.

### 핵심 교훈 — AI는 데이터베이스 "구조"는 가정할 수 있어도 실제 "값"은 볼 수 없다
- AI는 컬럼명이나 테이블 구조에 대해서는 그럴듯한 가정을 할 수 있지만, **데이터베이스 안의 실제 데이터 값(예: 특정 행의 날짜 오류)까지는 볼 수 없다.**
- 실제 데이터베이스에는 이런 데이터 품질 문제가 흔하게 존재하며, 이를 사람이 부지런히 검증(diligent)해야 한다.

### 좋은 쿼리를 위해 필요한 맥락(context)의 종류
1. **데이터베이스/테이블 구조**: 어떤 테이블, 어떤 컬럼, 어떤 타입인지.
2. **실제 데이터 값에 대한 정보**: 데이터 자체의 특이사항(품질 문제 등).
3. **비즈니스적 정의(business context)**: 예를 들어 "연체 대여"라는 용어를 AI는 임의로 "48시간 초과"로 정의했지만, 실제 비즈니스에서는 "72시간 초과"가 기준일 수도 있다 — **용어의 정의 자체가 맥락에 따라 달라진다.**

### 이 강좌의 진행 방향
- 먼저 최소한의 정보로 빠르게 쿼리를 생성하는 법을 배우고("bare minimum으로 bang for your buck"),
- 이후 **더 깊이 있게, 고품질의 쿼리를 만들기 위한 정교한 기법들**을 다룰 예정.

## 예시
```
1) 초기 쿼리 요청: "Based on this MySQL 9.2.0 table [스크린샷 첨부], tell me the query for the most popular rentals."
2) 개선 요청: "I need the title, too."
3) 진단 요청: "I'm getting zero results. Write a simple select to help diagnose the issue."
4) 결과 공유 후 원인 파악: AI가 rental_date/return_date의 데이터 오류를 짚어냄.
```

## 요약
- AI에게 데이터베이스 컨텍스트(테이블 구조 등)를 주면 꽤 정확한 쿼리를 생성할 수 있지만, **AI는 알려주지 않은 부분에 대해 스스로 가정(assumption)을 하며, 이 가정이 항상 맞는 것은 아니다.**
- 원하는 결과가 아닐 때는 새 대화를 시작하지 말고 **같은 대화를 이어가며 맥락을 계속 쌓아가야** 한다.
- AI는 데이터베이스 구조는 추측할 수 있어도 **실제 데이터 값의 품질 문제(예: 날짜 오류)까지는 볼 수 없으므로**, 결과가 이상하면 진단 쿼리로 직접 데이터를 확인하고 그 결과를 다시 AI와 공유해야 한다.
- 좋은 쿼리를 위해서는 구조적 정보뿐 아니라 **비즈니스 용어의 정의(예: "연체"의 기준)**까지 명확히 전달하는 것이 중요하다.
