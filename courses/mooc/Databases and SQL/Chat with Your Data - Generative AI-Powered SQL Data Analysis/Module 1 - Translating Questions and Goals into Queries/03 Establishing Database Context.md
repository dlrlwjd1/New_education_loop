# Establishing Database Context

## 개요
- 생성형 AI의 "창의성"이 데이터베이스/SQL 작업에서는 **환각(hallucination)**으로 나타날 수 있다는 점을 설명하고, 이를 막기 위한 **"데이터베이스 컨텍스트(database context) 확립"**의 구체적 항목들을 다루는 강의.

## 내용
### 창의성 = 때로는 환각(hallucination)
- 생성형 AI의 창의성(레시피 제안, 동화 창작 등)은 장점이지만, 데이터베이스/SQL 작업에서는 **정보가 부족할 때 그럴듯하게 "지어내는" 위험한 습성**으로 나타난다.
- 비유: **정보가 부족한 학생이 시험에서 부분 점수라도 받으려고 그럴듯하게 답을 지어내는 것**과 같다. AI도 정보가 부족하면 "그럴듯해 보이는" 답을 만들어낸다.
- SQL/DB 맥락에서는 존재하지 않는 컬럼을 지어내거나, 잘못된 구조의 쿼리를 만드는 형태로 나타난다.

### 실전 사례 — Postgres 클라이언트 환각
- 상황: 엑셀 파일들의 데이터를 Postgres 데이터베이스로 옮기기 위한 SQL 스크립트 생성을 요청.
- 프롬프트: "다운로드해서 임포트할 수 있는 SQL 파일을 만들어줘." → 길고 상세한 SQL 스크립트를 받음.
- 문제: 스크립트를 실행하니 **오류 발생**. 원인은 저자가 **"Postgres를 쓴다"고만 말했지, 어떤 클라이언트로 실행할지는 말하지 않았기 때문**.
- 오류 메시지를 다시 AI에게 보여주자, AI가 원인을 설명: `\c dbname`은 **PSQL(Postgres 커맨드라인 도구)의 메타커맨드**이지 표준 SQL이 아니므로, SQL만 지원하는 클라이언트(DB 클라이언트, JDBC 등)에서는 실패한다는 것.
- 핵심: AI는 "Postgres를 쓴다"는 말만 듣고 **"PSQL 클라이언트로 접속할 것"이라고 스스로 가정(assumption)**했고, 그 가정 하에서는 유효한(valid) 답을 준 것 — 하지만 그 가정 자체가 틀렸다.

### 왜 이런 환각이 생기는가
- AI가 어떤 세부사항이 없으면, **가장 흔한(common) 경우를 추측**해서 답한다. 하지만 사용자의 실제 상황이 "가장 흔한 경우"와 조금이라도 다르면 그 추측이 틀리게 된다.
- 목표: AI가 **추측할 필요가 없도록** 처음부터 충분한 정보를 줘서, 정확하게 추론할 수 있게 만드는 것.

### 데이터베이스 컨텍스트에 포함해야 할 핵심 정보 (기초 체크리스트)
1. **데이터베이스 종류(type)**: MySQL인지, Postgres인지, 다른 것인지.
2. **데이터베이스 버전(version)**: 버전에 따라 문법이 다를 수 있음.
3. **접속에 사용하는 클라이언트(client)와 그 버전**: PSQL 내장 클라이언트인지, 서드파티 범용 SQL 클라이언트인지 등.
4. **작업 대상 데이터베이스/테이블 이름**.
5. **각 테이블에 대한 완전한 설명**: 컬럼, 타입 등.
6. **테이블 간 관계(relationships)**.
7. **실제 데이터 샘플(sample data)**: 단순히 컬럼 설명만으로는 부족하다.

### 왜 "데이터 샘플"까지 필요한가 — 예: state 컬럼
- 예를 들어 `state`라는 컬럼이 있을 때, 값이 "Tennessee"처럼 전체 이름인지 "TN"처럼 약어인지 AI는 알 수 없다.
- 이걸 모르면 "테네시 주에 대한 쿼리를 만들어줘"라는 요청에도 정확한 쿼리를 만들지 못한다.
- 만약 데이터 안에 "Tennessee"와 "TN"이 **혼재**되어 있다면, 그건 애초에 데이터 입력 방식 자체의 문제이기도 하지만, 이 사실을 AI에게 샘플로 보여주면 **모든 변형(variation)을 아우르는 쿼리**를 만들어낼 수 있다.

### 핵심 비유 — "인턴에게 일을 맡길 때"
- 인턴에게 업무를 맡길 때 충분한 정보를 주지 않으면 제대로 못 하듯, AI에게도 **동일한 수준의 완전한 정보**를 제공해야 효과적인 쿼리·분석·설계를 얻을 수 있다.

## 예시
```
좋은 컨텍스트 제공 예:
- DB 종류/버전: "PostgreSQL 16"
- 접속 클라이언트: "DBeaver(범용 SQL 클라이언트)를 통해 접속, PSQL 커맨드라인 아님"
- 테이블 구조: 컬럼명, 타입, 관계
- 데이터 샘플: state 컬럼에 "TN", "Tennessee" 등 실제 값 예시 포함
```

## 요약
- AI의 창의성은 데이터베이스 작업에서 **정보 부족 시 그럴듯한 답을 지어내는 환각**으로 나타날 수 있다 — 시험에서 부분 점수를 노리고 답을 지어내는 학생과 비슷하다.
- 환각을 막으려면 **데이터베이스 종류/버전, 접속 클라이언트, 테이블 구조, 관계, 그리고 실제 데이터 샘플**까지 충분한 컨텍스트를 제공해야 한다.
- 특히 컬럼 설명만으로는 부족하고, **실제 데이터가 어떻게 생겼는지(예: 약어 vs. 전체 이름)까지 보여주는 샘플 데이터**가 정확한 쿼리 생성에 결정적이다.
