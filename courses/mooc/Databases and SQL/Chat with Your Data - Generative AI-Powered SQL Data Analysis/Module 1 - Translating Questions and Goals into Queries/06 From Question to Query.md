# From Question to Query

## 개요
- 좋은 질문을 확보한 뒤, 이를 **정확하고 복잡한 SQL 쿼리로 변환하는 실전 기법 — "실험적 쿼리 생성(experimental query generation)"**을 다루는 핵심 강의.

## 내용
### 흔한 실수 — "쿼리 생성해줘" → 바로 실행 → 실패 또는 은근한 오류
- 많은 사람들이 "이 질문으로 쿼리를 만들어줘"라고 요청하고 바로 실행하지만, 이는 실패하거나 **겉보기엔 맞아 보이지만 은근히 틀린(subtly flawed)** 결과를 낳기 쉽다.
- 원인: AI가 데이터를 실제로 보지 못한 채 **잘못된 가정**을 하기 때문 — 데이터를 미리 봤다면 다른(더 나은) 판단을 했을 것.

### 해결책 — "먼저 샘플 데이터를 확인한 뒤 쿼리를 생성하라"는 프롬프트
```
Whenever I ask you to create a query, I want you to first understand the data in the table, not just the schema.
You will first show me a series of simple select queries to gather samples from all tables you're going to use in the query.
Once you have the sample data and understand it, you will then generate the correct query for me.
```
- 이 프롬프트는 **복잡한 쿼리 생성에 최적화**되어 있으며, 문제를 여러 개의 작은 실험(작은 SELECT 쿼리들)으로 쪼개고, 각 실험의 결과를 피드백 받아가며 최종적으로 더 정확한 쿼리를 조립하게 한다.

### 실전 진행 — "고객이 어떤 장르를 볼 때 연체를 많이 하는가?" 질문 예시
1. (이미 데이터베이스 컨텍스트가 확립된 대화에서 시작 — 이전 대화를 문서로 저장해뒀다가 다시 첨부하거나, 같은 대화를 이어가는 방식 권장)
2. 프롬프트 적용 후 질문: "연체가 가장 잦은 고객들을, 그들이 보는 영화 장르를 기준으로 프로파일링해줘."
3. AI가 **문제 해결 접근법**을 먼저 설명: "① 연체가 가장 많은 고객 식별 → ② 대여 기록을 영화·장르와 연결 → ③ 장르별로 연체 데이터를 그룹화·분석."
   - **이 설명을 반드시 읽고, 예상과 다르면 "문제 해결 과정을 단계별로 설명해줘"라고 되물어야 한다.**
4. AI가 여러 개의 **샘플 조회 쿼리(sample queries)**를 제시 → 사용자가 각각 실행해서 결과를 수집.
5. 사용자가 각 쿼리의 결과를 **"쿼리 1: (결과 데이터)", "쿼리 2: (결과 데이터)"** 형식으로 정리해 AI에게 되돌려줌 (프롬프트가 상당히 길어지지만 괜찮음).
6. AI가 이 모든 샘플 데이터를 바탕으로 **최종 복잡한 쿼리(final query)**를 생성.

### 왜 이 방식이 정확도를 높이는가
- 복잡한 쿼리를 첫 시도에 정확히 생성하는 능력은 **실제 데이터의 값 형태, 컬럼 간 관계 등에 대한 지식에 크게 의존**한다.
- 작은 샘플 쿼리들을 미리 실행해봄으로써, AI는 (1) 자신의 쿼리가 예상대로 동작하는지, (2) 컬럼 간 관계가 실제로 생각한 대로인지, (3) 데이터 형식이 예상과 같은지를 **미리 검증**할 수 있다.
- 즉, "작은 실험을 실행하게 하고 그 결과를 알려주는 것"이야말로 **가장 풍부한 컨텍스트를 제공하는 방법** 중 하나다.

### 쿼리를 받은 후에도 끝이 아니다 — 검증(verification)의 중요성
- 최종 쿼리를 받으면 AI가 보통 그 쿼리가 무엇을 하는지 설명해주지만, 그렇지 않다면 **직접 설명해달라고 요청**해서 이해해야 한다.
- SQL을 잘 읽을 수 있다면 눈으로 검토하고, 그렇지 않다면 **정확성을 검증할 다른 방법을 고민**해야 한다.
- 이는 사람이 직접 쿼리를 짤 때도 마찬가지: 쿼리를 실행하고 결과를 보며 "이게 맞나?"를 항상 스스로 검토해야 한다.
- **사람도 실수하고, AI도 실수하고, 사람과 AI 사이의 커뮤니케이션 오류도 있을 수 있다.** 따라서 결과가 최소한 "말이 되는지(ballpark)" 확인할 수 있는 통계적/기본적인 검증 방법을 항상 고려해야 한다.

## 예시
```
프롬프트: "Whenever I ask you to create a query, first show me sample SELECT queries for the tables involved.
Once you understand the sample data, generate the correct final query."

질문: "Create a profile of customers that return movies late most often by the genres of movies they watch."

흐름:
1. AI: 접근 방식 설명 (연체 고객 식별 → 장르 연결 → 그룹 분석)
2. AI: 샘플 쿼리 여러 개 제시
3. 사용자: 각 샘플 쿼리 실행 → 결과를 "쿼리 1: ..., 쿼리 2: ..." 형식으로 정리해 전달
4. AI: 최종 복잡한 쿼리 생성 + 설명
```

## 요약
- 복잡한 쿼리를 한 번에 요청하면 은근한 오류가 생기기 쉽다 — 대신 **"먼저 샘플 데이터를 확인한 뒤 쿼리를 생성하라"**는 프롬프트로 문제를 작은 실험 단위로 쪼갠다.
- AI가 제시하는 샘플 쿼리들을 실행하고 그 결과를 돌려주면, AI는 실제 데이터의 형태와 관계를 검증한 뒤 훨씬 정확한 최종 쿼리를 생성할 수 있다.
- 쿼리를 받은 뒤에도 끝이 아니다 — **AI의 설명을 읽고, 필요하면 검증 방법을 스스로 고민**해야 한다. 사람도, AI도, 둘 사이의 소통도 실수할 수 있기 때문이다.
