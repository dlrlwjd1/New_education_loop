# Collaborative Debugging of SQL Queries with Generative AI

## 개요
- 이 강좌의 마지막 강의. SQL 쿼리의 오류를 생성형 AI와 함께 **디버깅(debugging)**하는 방법을 다루며, **문제의 성격에 따라 필요한 컨텍스트의 양이 다르다**는 것을 단계적으로 보여준다.

## 내용
### 디버깅에 필요한 컨텍스트의 3단계 스펙트럼

#### 1단계 — 컨텍스트 독립적(context-independent) 오류: 최소 정보로도 해결 가능
- 예: SQL 문법 자체의 실수 (콤마 누락 등).
- 프롬프트: "이건 방금 실행한 쿼리야(쿼리 붙여넣기). 에러가 발생했어. 뭐가 문제야?"
- 결과: "CTE의 `fc.categoryid` 줄에서 `fc.categoryid`와 `c.name as genre` 사이에 콤마가 빠졌습니다."라며 수정된 쿼리까지 제시.
- 이런 오류는 **데이터베이스와 무관한 순수 SQL 구조 문제**라 별다른 컨텍스트 없이도 해결 가능.

#### 2단계 — 어느 정도 유추 가능하지만, 명시적 정보가 있으면 더 정확해지는 오류
- 예: 컬럼명 오타 (`r.returnDate` vs. 실제 컬럼명 `r.return_date`).
- 이번엔 **에러 메시지 자체도 함께 제공**해야 한다 (스크린샷으로 줘도 되고, 텍스트로 복사해도 됨) — "쿼리를 실행했더니 이런 에러가 났어: `SQL error, unknown column r.returnDate`. 뭐가 문제야?"
- 결과: "오타로 인해 `r.returnDate`를 참조했지만, 실제 컬럼명은 아마도(likely) `r.return_date`일 것입니다."
- 왜 "아마도(likely)"라고 하는가 — **데이터베이스 컨텍스트를 주지 않았기 때문**에, 다른 컬럼들이 언더스코어(`_`) 형식을 쓰는 패턴을 보고 추측한 것. 만약 데이터베이스 컨텍스트가 확립된 대화였다면 "그건 틀린 컬럼명입니다"라고 **확정적으로** 답할 수 있었을 것.

#### 3단계 — 미묘한(subtle) 오류: 풍부한 컨텍스트가 반드시 필요
- 예 1: Postgres 17에서 `\c dbname`(PSQL 메타커맨드)을 표준 SQL 클라이언트에서 실행해 발생하는 오류. → **DB 종류(Postgres 17)와 실행 맥락**을 알려줘야 진단 가능.
- 예 2: **Postico**(특정 Postgres 클라이언트)에서 `CREATE DATABASE cannot run inside a transaction block` 오류 발생.
  - 프롬프트에 "나는 Postico를 쓰고 있고, 이런 에러가 났어"라고 **구체적 클라이언트 정보**를 제공.
  - 결과: "Postgres에서 `CREATE DATABASE`는 트랜잭션 밖에서 실행되어야 하는데, Postico 같은 일부 툴은 쿼리를 자동으로 트랜잭션으로 감싸서 이 문제가 발생합니다. 첫 줄만 따로 실행하세요."
  - 만약 "Postico를 쓴다"는 정보가 없었다면, AI는 이 원인을 알아낼 수 없었을 것.

### 핵심 원칙 — "AI가 디버깅을 못하면, 컨텍스트가 부족한 건 아닌지 먼저 점검하라"
- 사람들이 자주 저지르는 실수: 디버깅 도움을 요청하면서 **충분한 컨텍스트를 주지 않는 것.**
- 순수 SQL 구조 문제처럼 아주 단순한 것이 아니라면, 대부분의 실제 오류는 **DB 종류, 버전, 클라이언트 등 충분한 컨텍스트가 있어야 정확히 진단**된다.
- 디버깅에 어려움을 겪고 있다면: "내가 이 대화에 디버깅에 필요한 모든 정보를 충분히 제공했는가?"를 먼저 자문해야 한다.

### 추가 기법 — "진단용 쿼리를 만들어달라고 요청하기"
- 데이터베이스 컨텍스트를 확립할 때 썼던 것과 동일한 기법을 디버깅에도 적용할 수 있다: **"이 쿼리를 디버깅하는 데 도움이 될 일련의 SQL 진단 쿼리들을 생성해줘. 그 결과를 너에게 다시 줄게."**

## 예시
```
1) 문법 오류 (컨텍스트 불필요): "Here's the query I just ran [쿼리]. It produced an error. What is wrong?"

2) 컬럼명 오류 (에러 메시지 필요): "It produced this error: SQL error, unknown column r.returnDate. What is wrong?"

3) 클라이언트 특이적 오류 (풍부한 컨텍스트 필요): "I'm using Postico and getting this error:
   create database cannot run inside a transaction block. What's going on?"
```

## 요약
- SQL 디버깅에 필요한 컨텍스트의 양은 오류의 성격에 따라 다르다: **순수 문법 오류는 컨텍스트가 거의 불필요**하지만, **컬럼명/스키마 오류는 에러 메시지가 필요**하고, **클라이언트/DB 버전 특이적 오류는 풍부한 컨텍스트가 필수**다.
- AI가 디버깅에 실패하면, 먼저 **"충분한 컨텍스트(DB 종류, 버전, 클라이언트, 에러 메시지 전문)를 제공했는가"**를 점검해야 한다.
- 필요하다면 앞서 배운 기법처럼 **"진단용 쿼리를 만들어달라"**고 요청해 추가 정보를 수집하며 디버깅을 진행할 수 있다.
