# Boyce-Codd Normal Form

## 개요

- BCNF(Boyce-Codd Normal Form)의 조건과 3NF와의 관계, 위반 종속성을 분해하는 감산(subtraction) 알고리즘
- 다중값 종속(multi-valued dependency, MVD)과 4NF의 조건·변환 절차
- 4NF 이상의 정규형이 실무에서 갖는 위상 — 3NF면 비즈니스 트랜잭션에 충분

## 내용

### BCNF 조건

- 관계가 BCNF이려면: **모든 결정자(determinant)가 후보 키**여야 한다.
- 테이블에 **후보 키가 하나뿐이면** 3NF와 BCNF는 동일하다 — BCNF는 **3NF의 특수한(강화된) 형태**다.
- BCNF 위반은 테이블에 **후보 키가 둘 이상** 있을 때만 발생할 수 있다.
- 위반 신호: **비프라임(non-prime) 속성이 후보 키의 일부(프라임 속성)를 결정**하는 비자명(nontrivial) 종속성.

### BCNF 변환 — 감산 알고리즘

위반 FD `X → A`가 있는 관계 R에 대해:

1. **R1 = (X, A)** — 위반 FD의 결정자와 종속자를 합쳐 새 관계 생성. X가 R1의 후보 키가 된다.
2. **R2 = R − A** — 원래 관계에서 **종속자 A를 제거**한 나머지.
3. 분해된 R1, R2가 BCNF인지(각각 후보 키 하나로 모든 속성이 완전 종속하는지) 검증하고, 아니면 **반복**한다.

### 4NF와 다중값 종속(MVD)

- **MVD 표기**: `A ↠ B` (이중 화살표) — A의 **한 값에 대해 B의 여러 값**이 존재. 예: A1에 대해 B1, B2가 있으면 (A1, B1), (A1, B2) 두 행이 반복된다.
- MVD가 문제가 되려면 테이블에 **최소 3개 컬럼**이 필요하다. 2컬럼 관계(A, B)에서는 새 행을 넣는 것만으로 위반이 자연 해소되지만, C가 추가되면 불필요한 반복이 발생한다.
- 3컬럼 관계 R(A, B, C)에서 A ↠ B가 있으면 **B와 C는 서로 독립**이어야 한다.
- **4NF 조건**: (1) BCNF여야 하고 (2) 모든 비자명 MVD `A ↠ B`에서 **A가 후보 키**여야 하며, 다중 MVD 집합이 없어야 한다.

### 4NF 이상에 대한 실무적 관점

- 4NF·5NF는 **대체로 학술적(academic)이고 비실용적**이다. 모든 속성이 기본 키에 종속되고 서로 독립인 상황에 도달하면 이미 대부분 조건이 해소되어 있다.
- **비즈니스 트랜잭션용 데이터베이스는 3NF면 충분한 정규화**다. 더 높은 정규형이 항상 바람직한 것은 아니다.
- 이 강좌에서 5NF 이상은 다루지 않는다.

## 예시

### 예제 1 — BCNF 변환

R(A, B, C, D, E), FD: `BC → ADE`, `D → B`

1. 폐포 알고리즘으로 후보 키 식별 → **BC** (BC가 나머지 전 속성을 완전 결정)
2. `D → B` 검사: 비프라임 D가 프라임 속성 B를 결정하는 비자명 종속 → **BCNF 위반**
3. 감산 알고리즘 적용:
   - **R1(D, B)** — D가 후보 키, B는 D에 종속
   - **R2(D, C, A, E)** — 원본에서 B를 빼고, 키에서 B의 자리를 D가 대신함 → 후보 키 **DC**, A와 E는 DC에 완전 종속
4. 두 관계 모두 모든 결정자가 후보 키 → BCNF 충족.

### 예제 2 — 4NF 변환

R(A, B, C, G, H, I), MVD: `A ↠ B`, `B ↠ HI`, `CG ↠ H`. 후보 키(슈퍼 키)는 **ACG**.

1. `A ↠ B`에서 A는 슈퍼 키가 아님 → 4NF 위반 → **R1(A, B)** 분리 (A는 후보 키의 일부이므로 R1은 4NF). 원본에는 A의 복사본을 남기고 B 제거 → **R2(A, C, G, H, I)**
2. R2에서 `CG ↠ H` 위반 → **R3(C, G, H)** 분리 (CG는 후보 키의 일부 → 4NF). CG 복사본을 남기고 H 제거 → **R4(A, C, G, I)**
3. R4 검사: `A ↠ B`, `B ↠ HI`에서 이행적으로 **A ↠ I** 도출(H는 R4에 없으므로 I만 해당) → 위반 → **R5(A, I)** 분리, I 제거 → **R6(A, C, G)**
4. 최종: R1(A,B), R3(C,G,H), R5(A,I), R6(A,C,G) 모두 4NF.

분해할 때마다 **기본(후보) 키의 복사본은 원본에 남긴다**는 원칙은 여기서도 동일하다.

## 요약

- BCNF는 모든 결정자가 후보 키인 상태로, 후보 키가 하나뿐인 3NF 테이블은 자동으로 BCNF다.
- 위반 FD `X → A`는 R1(X, A)와 R2(R − A)로 감산 분해하고, 모든 관계가 조건을 만족할 때까지 반복한다.
- MVD(`A ↠ B`)는 한 값에 여러 값이 대응하는 종속으로, 3컬럼 이상에서 문제가 되며 4NF는 BCNF + "모든 비자명 MVD의 결정자가 후보 키"를 요구한다.
- 실무 데이터베이스는 3NF면 충분하고, 4NF 이상은 주로 학술적 의미를 가진다.
