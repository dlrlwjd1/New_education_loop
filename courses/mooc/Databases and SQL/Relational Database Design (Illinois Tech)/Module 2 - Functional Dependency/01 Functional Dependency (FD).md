# Functional Dependency (FD)

## 개요

- 함수 종속성(functional dependency, FD)의 형식적 정의와 결정자(determinant)·종속자(dependent) 개념
- 완전(full)·부분(partial)·이행(transitive) 함수 종속성의 구분
- 주어진 관계(relation)의 실제 데이터에서 성립하는 FD를 찾는 방법

## 내용

### 함수 종속성이 필요한 이유

- 관계의 **키(key)를 찾는 데** 사용한다.
- 관계가 **좋은 형태(good form)**인지 — 데이터가 중복 저장되지 않는지 — 검사한다.
- 제약을 강제해 데이터 무결성을 지키고, 삽입(insertion)·삭제(deletion)·갱신(update) 연산에서 생기는 **데이터 이상(anomaly)**을 제거한다.
- 속성 간의 관계를 표현하는 규칙 집합을 제공한다.

### 결정자와 종속자

- 표기: `A → B` (화살표는 항상 오른쪽을 향함) — "A가 B를 함수적으로 결정한다(A functionally determines B)" 또는 "B는 A에 함수적으로 종속된다(B is functionally dependent on A)"
- **결정자(determinant)**: 화살표 **왼쪽**의 속성 집합. 종속자의 값을 유일하게 결정한다. 속성 하나 이상일 수 있다.
- **종속자(dependent)**: 화살표 **오른쪽**의 속성 집합. 역시 둘 이상일 수 있다.
- 핵심 전제: 결정자 → 종속자 매핑은 **to-one 매핑**이어야 한다. 결정자의 한 값이 종속자의 두 값 이상을 가리키면(to-many) FD가 성립하지 않는다.

### 형식적 정의

관계 스키마 R에서 α, β ⊆ R일 때, `α → β`가 성립(hold)하려면: 어떤 적법한(legal) 관계에서든 두 튜플 t1, t2가 **α 값에서 일치하면 β 값에서도 반드시 일치**해야 한다.

예: R(A, B)에 튜플 (1,4), (1,5), (3,7)이 있을 때

- `A → B`: t1, t2가 A=1로 일치하지만 B는 4 vs 5로 불일치 → **성립하지 않음** (1이 두 값을 가리키는 to-many 매핑)
- `B → A`: B 값(4, 5, 7)이 모두 유일하고 각각 하나의 A만 가리키는 to-one 매핑 → **성립**

### FD와 키

- 속성 집합 X가 R의 튜플을 유일하게 식별하고(`X → R`), X의 **어떤 부분집합도 같은 일을 할 수 없으면** X는 **후보 키(candidate key)**다.
- 후보 키에 속한 속성을 **프라임 속성(prime attribute)**이라 한다.
- 후보 키 중 하나를 **기본 키(primary key)**로 선택하며, 기본 키는 다른 테이블에서 참조 대상이 된다.

### 완전 함수 종속(Full Functional Dependency)

- 결정자에서 **어떤 속성을 하나라도 제거하면 종속성이 깨지는** 경우 — 결정자의 모든 속성이 필요하다.
- 예: `AB → C`에서 A와 B 둘 다 필요하면 "C는 AB에 완전 종속" (C is fully dependent on AB)

### 부분 함수 종속(Partial Functional Dependency)

- 결정자에서 **일부 속성을 제거해도 종속성이 유지되는** 경우 — 결정자의 모든 속성이 필요하지는 않다.
- 예: `AB → C`에서 A를 제거해도 `B → C`가 성립하면 "C는 키(AB)의 **일부에만** 종속" → 부분 종속

### 이행 함수 종속(Transitive Dependency)

- 속성 간 FD가 **다른 속성을 거쳐 간접적으로** 이어지는 경우.
- `A → B`이고 `B → C`이면 A는 B를 **경유해(transitively)** C를 결정한다.
- 이때 A는 프라임 속성(후보 키의 일부), B는 **비프라임(non-prime) 속성**이다. **비프라임 속성이 결정자가 되는 FD의 존재가 이행 종속의 신호**다.

## 예시

관계 R(A, B, C, D, E)의 데이터에서 FD 성립 여부 판정:

- `C → E` 검사: C=3인 두 튜플이 E에서 서로 다른 값을 가리킴(3→2와 3→3) → to-many 매핑 → **성립 안 함**
- `E → C` 검사: E의 각 값(0, 2, 3)이 C의 한 값씩만 가리킴(0→5, 2→3, 3→3) → to-one 매핑 → **성립**
- `A → B` 검사: 1→4, 3→4로 각 A 값이 B의 한 값만 가리킴 → **성립**
- `B → C` 검사: B=4가 C의 5와 3을 모두 가리킴 → to-many → **성립 안 함**
- D: 모든 값이 유일 → **후보 키**(유일한 후보 키라면 기본 키). 기본 키는 다른 모든 속성(A, B, C, E)과 그 어떤 부분집합도 결정한다.
- DE: 후보 키 D에 어떤 속성을 덧붙여도 여전히 유일 식별자이므로 D와 같은 결정 능력을 가진다.

판정 요령: 결정자 값이 반복되는 튜플들을 찾고, 그 튜플들이 종속자 값에서도 일치하는지 확인한다. 한 값이라도 두 개 이상을 가리키면 성립하지 않는다.

## 요약

- FD `α → β`는 α 값이 같은 튜플은 β 값도 같아야 성립하며, 본질은 to-one 매핑이다.
- 결정자는 화살표 왼쪽, 종속자는 오른쪽이며 둘 다 속성 집합일 수 있다.
- 후보 키는 관계 전체를 결정하는 최소 속성 집합이고, 그 구성 속성이 프라임 속성이다.
- 완전 종속은 결정자 전체가 필요, 부분 종속은 키의 일부만으로 결정, 이행 종속은 비프라임 속성을 경유하는 간접 결정이다.
- 데이터 표본에서 FD를 판정할 때는 결정자 값이 겹치는 튜플 쌍의 종속자 값 일치를 확인한다.
- 다음 강의는 속성 폐포(attribute closure)와 후보 키 찾기다.
