# Entity - Relationship (ER) Model

## 개요

- 데이터베이스 설계 프로세스 5단계 개관과 ER 모델의 핵심 구성요소를 다루는 강의
- 3대 ER 표기법(Chen, UML, Crow's Foot) 비교 — 이 강좌는 이후 UML 표기법 중심으로 진행
- 관계(relationship)·다중성(multiplicity)·속성(attribute) 유형·키(key) 개념과 대학(college) 데이터베이스 개념 설계 예시

## 내용

### 관계형 데이터베이스 설계가 중요한 이유

- 데이터 중심 시대에는 효율적 저장, 빠른 검색, 쉬운 관리를 위해 데이터를 조직화해야 한다.
- 잘 설계된 데이터베이스는 조직의 모든 애플리케이션의 근간(backbone)이다.
- "Garbage in, garbage out" — 잘못 설계된 데이터베이스를 구현하면 사용자·개발자 모두 많은 문제를 겪는다.

### 설계 프로세스 5단계

1. **요구사항 수집·분석(Requirement Collection and Analysis)** — 사용자·실제 조직으로부터 데이터베이스 요구사항을 수집
2. **개념 설계(Conceptual Design)** — 요구사항을 ER 모델·ERD 같은 고수준 다이어그램으로 표현해 개념 스키마(conceptual schema)를 도출. 이 스키마는 기업의 모든 기능적 요구사항을 포함해야 한다.
3. **논리 설계(Logical Design)** = 데이터 모델 매핑(Data Model Mapping) — 개념 스키마를 특정 데이터베이스 시스템의 데이터 모델로 변환. 데이터 무결성을 유지하는 좋은 관계 집합(정규화)을 확보한다.
4. **물리 설계(Physical Design)** — 디스크 상의 물리적 배치: 파일 조직(file organization), 인덱싱 전략, 레코드 배치
5. **구현(Implementation)** — 데이터베이스를 테스트·구현·배포

### ER 모델의 두 축: 엔터티와 관계

- **엔터티(entity)**: 독립적으로 존재하며 다른 엔터티와 구별 가능한 실세계의 사물·객체. 서술에서 **명사(noun)**로 골라낸다. 예: author, book
- **관계(relationship)**: 엔터티 간의 연관. 서술의 **동사(verb)**로 골라내며, 항상 **양방향(bi-directional)**이다.
  - 예: "An author *writes* books" / "Each book is *written by* one author" — `writes`, `written by`가 관계 이름

### 3대 ER 표기법

| 표기법 | 엔터티 | 관계 | 속성 | 카디널리티 |
|---|---|---|---|---|
| Chen | 직사각형 | 다이아몬드 | 타원(oval) | 숫자 (1, M/N) |
| UML | 이름이 든 직사각형 | 선(line) | 직사각형 내부에 나열 | `1`, `*`(any/many), `0`(옵션) |
| Crow's Foot | 직사각형 | 까마귀발 기호가 달린 선 | 직사각형 내부에 나열 | 파이프( \| , \|\| )·까마귀발 |

같은 비즈니스 규칙을 세 표기법으로 표현하는 연습:

- **1:N** — "한 저자는 여러 책을 쓸 수 있고, 각 책은 한 저자가 쓴다" (Chen: 1—M, UML: `1..1` ↔ `1..*`)
- **M:N** — "한 배우는 여러 영화에 출연하고, 한 영화에는 여러 배우가 나온다" (Chen: M—N)
- **1:1** — "각 사용자는 하나의 프로필을 갖고, 프로필은 정확히 한 사용자에 속한다" (양쪽 모두 `1..1`)

이 강좌가 **UML을 채택하는 이유**: (1) 컴퓨팅·소프트웨어 공학에서 널리 쓰이고 (2) 비즈니스 규칙의 세부사항을 구체적으로 전달할 수 있어서다. 예: `*` 대신 "최대 5명(at most 5)", "최소 5(at least 5)"처럼 구체적 수를 표기할 수 있다 (과학 논문의 저자 수 제한 같은 규칙).

### 다중성(Multiplicity) = 참여(Participation) + 카디널리티(Cardinality)

- 표기: `X..Y` — 첫 숫자 X는 **참여(최소값)**, 둘째 숫자 Y는 **카디널리티(최대값)**
- **참여(participation)**: 관계에 참여하는 최소 인스턴스 수. `1` = 필수(mandatory, 모든 인스턴스가 참여), `0` = 선택(optional)
- **카디널리티(cardinality)**: 한 엔터티의 인스턴스가 상대 엔터티 인스턴스와 관계 맺는 **최대** 수 — to-one 또는 to-many
- 사용 가능한 기호: `0`, `1`, `*`(many/any number)
- 관계 유형(1:1, 1:N, M:N)은 양쪽의 카디널리티(최대값)를 읽어 판별하며, **외래 키는 many 쪽에 둔다** — one 쪽의 기본 키를 many 쪽으로 옮겨 외래 키로 삼는다.

### 속성(Attribute) 유형

- **단일값 속성(single-valued/simple attribute)** — 하나의 값. 예: author name = "JK Rowling"
- **복합 속성(composite attribute)** — 속성의 계층 구조(상위 속성 아래 구성요소). 구현 시 단일값 속성들로 분해해야 한다.
- **다중값 속성(multi-valued attribute)** — 한 엔터티에 값의 집합. 예: 저자의 연락처(전화번호 1, 2). 중괄호 `{ }`로 표기.
- **파생 속성(derived attribute)** — 기존 속성에서 계산. 예: birth date로부터 age 계산.

구현 시 주의: 복합·다중값 속성은 관계 스키마(relational schema)에서 다르게 처리해야 하고, **파생 속성은 시간 변화(time variation) 문제 때문에 관계 스키마에 포함하지 않는다**.

### 키(Key)

- **기본 키(primary key, PK)**: 엔터티의 고유 식별자. 행을 유일하게 식별하며 **NULL이 될 수 없다**. UML에서는 속성 옆에 `PK`로 표기. → **엔터티 무결성(entity integrity)** 보장(테이블 내 레코드 중복 금지)
- **복합 키(composite key)**: 두 개 이상 속성의 조합. 예: student number + last name. 단일 속성이 적절한 기본 키가 못 될 때 사용.
- **대리 키(surrogate key)**: 식별 목적으로 생성한 번호로, 의미를 가질 필요가 없다. 예: AuthorID = 89471
- **외래 키(foreign key, FK)**: 다른 테이블의 기본 키를 참조하는 속성. 기본 키와 **같은 타입**이어야 하고, 매칭되는 한 NULL도 허용. → **참조 무결성(referential integrity)** 보장. 부모 엔터티(author)와 자식 엔터티(book) 간 행의 대응은 외래 키(AuthorID)를 통해 이루어진다.

## 예시

대학(college) 데이터베이스의 개념 설계(UML ERD) — 학생, 교수, 분반(class section), 강의실, 과목을 저장한다. 개념 설계 단계이므로 속성 없이 엔터티·관계만 표기한다.

| 비즈니스 규칙 | UML 다중성 표현 |
|---|---|
| 학생은 하나 이상의 분반에 등록해야 하고, 한 분반은 여러 학생이 수강한다 | Student `1..*` —enrolls— `1..*` ClassSection |
| 각 분반은 특정 강의실 하나에 배정되고, 한 강의실은 여러 분반이 사용한다 | ClassSection `*` —assigned— `1..1` Room |
| 교수는 분반을 **안 가르칠 수도**(연구만 할 수도) 있고(0..*), 한 분반은 정확히 한 교수가 가르친다 | Professor `1..1` —teaches— `0..*` ClassSection |
| 한 과목은 여러 분반을 갖고, 한 분반은 특정 과목 하나에 속한다 | Course `1..1` —has— `1..*` ClassSection |

"may teach"처럼 **선택적(may)** 표현은 참여 0(optional)으로 읽는 것이 포인트.

## 요약

- 설계 프로세스는 요구사항 수집 → 개념 설계 → 논리 설계 → 물리 설계 → 구현의 5단계다.
- ER 모델은 엔터티(명사)와 관계(동사, 양방향)로 구성되며, 표기법은 Chen·UML·Crow's Foot이 있고 이 강좌는 UML을 사용한다.
- 다중성 = 참여(최소, 0/1) + 카디널리티(최대, 1/*)이며, 외래 키는 many 쪽에 배치한다.
- 속성은 단일값·복합·다중값·파생으로 나뉘고, 복합·다중값은 구현 시 별도 처리, 파생 속성은 스키마에서 제외한다.
- 기본 키는 엔터티 무결성을, 외래 키는 참조 무결성을 보장한다.
- 다음 강의는 개념 수준에서 논리 설계 수준의 상세 ERD 작성으로 넘어간다.
