# Scoring for Consistency, Relevance, Correctness

## 개요
- 정확성·관련성·형식(일관성)이라는 여러 평가 차원을 **가중 합성 점수(weighted composite score)**로 결합하는 방법과, 차원별 임계값·검토 규칙을 함께 사용해야 하는 이유를 다루는 8분 영상. "LLM-as-a-Judge Methodologies" 레슨의 두 번째 영상.

## 내용

### 왜 하나의 점수만으로는 부족한가
- 하나의 점수는 그것이 무엇으로 구성되었는지 이해하지 못하면 대체로 너무 모호함.
- 강력한 프로덕션 평가 프로세스는 중요한 차원들을 **개별적으로** 점수 매기고, 비즈니스 우선순위에 따라 가중치를 부여한 뒤, 단순하고 투명한 방식으로 결합해야 함.

### 채점 차원과 가중 합성 점수
- 주요 채점 차원: **정확성(Correctness), 관련성(Relevance), 형식/일관성(Format/Consistency)** — 모든 것을 너무 일찍 하나의 불명확한 등급으로 뭉치지 않고 각 응답을 이 개별 측면들로 판정해야 함.
- 200개 평가 예시에 걸쳐 합성 점수를 계산하는 방법: 평가자 실행 → 차원별 점수 전달 → 가중 공식 적용.
- **가중 공식**: `0.5 × 정확성 + 0.3 × 관련성 + 0.2 × 형식`.
- 이 가중치가 알려주는 것: 모든 차원이 동등하게 중요하지 않음 — 이 예시에서는 정확성이 최우선 순위라 가장 큰 가중치를 받음. 관련성도 중요하고 형식/일관성도 중요하지만, 답이 실제로 맞는지를 압도해서는 안 됨.
- 채점 후에는 차원별 **평균, 표준편차, 임계값 미만 비율** 같은 요약 통계를 계산해야 함 — 평균 품질뿐 아니라 점수가 얼마나 안정적인지, 실패가 어디에 집중되는지도 파악하는 데 도움.

### 합성 점수를 pass/fail 결정으로 전환하는 운영 규칙
- 시스템이 전체 평가셋에 평가자를 실행 → 각 예시의 가중 점수 계산 → 이 결과로 회귀(regression)를 탐지하고 실행(run)의 통과 여부를 결정.
- **두 가지 중요한 규칙**:
  1. **정확성이 3 미만인 예시는 사람의 검토를 위해 로깅되어야 함** — 전체 평균이 좋아 보여도 명백히 약한 답변을 무시할 수 없음.
  2. **요약 규칙**: 합성 점수가 4 이상이면 통과이지만, 어떤 차원의 평균이 3.5 미만이면 결과는 검토로 보내져야 함 — 하나의 강한 차원이 다른 차원의 약점을 가리는 것을 방지.
- 전체 메시지: 합성 점수는 유용하지만 **단독으로 사용되어서는 안 됨** — 평가를 신뢰할 수 있게 만들려면 여전히 차원별 임계값과 검토 규칙이 필요함.

### 핵심 원칙 4가지
1. **가중 합성 채점(Weighted Composite Scoring)**: `정확성 × 0.5`는 형식보다 정확성의 비즈니스 우선순위를 반영함 — 가중치는 해당 사용 사례에서 가장 중요한 것을 반영해야 함.
2. **차원별 임계값(Per-dimension Threshold)**: 각 차원은 자체 최소 목표를 가져야 다른 곳의 강한 점수에 의해 한 영역의 낮은 점수가 가려지지 않음.
3. **낮은 점수 플래그**: 정확성이 3 미만인 예시는 승격 전 사람의 검토를 위해 로깅되어야 함 — 명백히 약한 답변이 전체 평균에 묻혀 사라지지 않도록 보장.
4. **요약 리포팅**: 팀은 이해관계자가 평가를 명확하고 투명하게 이해할 수 있도록 차원별 평균, 표준편차, 실패율(percent fail)을 리포트해야 함.
- 핵심 요점: 합성 점수는 가중 논리가 명시적이고 구성 차원들이 여전히 가시적일 때만 유용함.

### 코드 예시
- 점수가 **0.82 이상**이면 통과.
- 코드는 정확성이 가장 크게 기여하고, 관련성이 그다음, 일관성이 가장 적게 기여하는 가중 점수를 적용 → 최종 점수를 임계값(0.82)과 비교해 충분히 높으면 게이트를 통과.
- 주목할 점: 공식이 짧고 읽기 쉬움 — 가중 논리는 단순하고, 명시적이고, 검토 가능해야 하기 때문에 중요. 공식이 너무 복잡하면 팀이 릴리스 결정을 정당화하기 어려워짐.

### 실전 지침 3가지
1. **정확성에 스타일보다 더 무거운 가중치를 부여하라**: 답을 맞히는 것이 우아하게 제시하는 것보다 대체로 더 중요.
2. **가중 논리를 가시적으로 유지하라**: 숨겨진 가중치는 사람들이 점수가 어떻게 만들어졌는지 이해하지 못하면 릴리스 논거를 더 어렵게 만듦.
3. **가중치를 비즈니스 리스크에 맞춰 튜닝하라**: 올바른 가중치 체계는 제품에서 어떤 실패가 가장 중요한지에 달려 있음 — 어떤 사용 사례는 정확성을 중시하고, 어떤 사용 사례는 더 엄격한 형식·일관성 요건이 필요할 수 있음.
- 결과: 하나의 점수가 부분들을 숨기지 않으면서 품질을 요약할 수 있지만, 이는 방법이 투명하고 검토 가능할 때만 가능함.

### 결론
- **합성 지표는 가중 논리가 단순하고, 명시적이고, 검토 가능할 때만 유용함.**
- 합성 채점은 의사결정을 단순화하기 때문에 강력하지만, 명확한 차원, 투명한 가중치, 약한 출력이 평균에 가려지는 것을 막는 검토 규칙에 항상 기반을 두어야 함.

## 예시
```python
# 가중 합성 점수 (개념 구조)
def composite_score(correctness, relevance, format_score):
    return 0.5 * correctness + 0.3 * relevance + 0.2 * format_score

def evaluate(example):
    score = composite_score(example.correctness, example.relevance, example.format_score)

    if example.correctness < 3:
        flag_for_human_review(example)  # 정확성 낮으면 무조건 사람 검토

    if score >= 4 and min(example.correctness, example.relevance, example.format_score) >= 3.5:
        return "PASS"
    return "REVIEW"
```

```text
[가중 공식 예시]
합성 점수 = 0.5 × 정확성 + 0.3 × 관련성 + 0.2 × 형식

승격 규칙:
- 합성 점수 ≥ 4 AND 모든 차원 평균 ≥ 3.5 → 통과
- 어느 차원이든 평균 < 3.5 → 검토로 이동
- 개별 예시의 정확성 < 3 → 항상 사람 검토 로깅
```

## 요약
- LLM 출력 평가는 정확성·관련성·형식이라는 개별 차원을 비즈니스 우선순위에 따라 가중치(예: 0.5/0.3/0.2)를 부여해 결합한 합성 점수로 요약할 수 있지만, 이 가중치와 계산 방식이 단순하고 투명해야 하며, 차원별 최소 임계값과 정확성 3점 미만 예시에 대한 자동 사람 검토 플래그를 함께 적용해야 강한 차원이 약한 차원의 문제를 가리는 것을 방지하고 신뢰할 수 있는 릴리스 결정을 내릴 수 있다.
