# Limits of Automated Scoring

## 개요
- LLM-as-a-Judge 방식의 5가지 알려진 한계(길이 편향, 자기 편향, 캘리브레이션 드리프트, 도메인 사각지대, 형식 취약성)와 각각의 대응책, 그리고 Spearman RHO를 이용한 판정자 캘리브레이션 검증 방법을 다루는 6분 영상. "LLM-as-a-Judge Methodologies" 레슨의 마지막 영상.

## 내용

### 자동 채점의 한계를 인식해야 하는 이유
- 자동화된 채점은 유용하지만 명확한 한계가 있음 — 실패를 탐지하고 적절히 대응할 방법이 필요함.
- 목표는 자동 채점을 없애는 것이 아니라, 그것을 **언제 신뢰해야 하고 언제 신뢰하지 말아야 하는지** 이해하는 것.

### LLM-as-a-Judge의 5가지 알려진 한계와 대응책
1. **길이 편향(Length Bias)**: 더 긴 답변이 더 높은 점수를 받을 수 있음 → 대응: **길이에 무관한 루브릭(length-agnostic rubric)** 사용.
2. **자기 편향(Self-bias)**: 동일한 모델이 자신의 출력을 판정할 수 있음 → 대응: **다른 판정 모델(different judge model)** 사용.
3. **캘리브레이션 드리프트(Calibration Drift)**: 판정 점수 분포가 시간이 지나며 이동할 수 있음 → 대응: **매달 재캘리브레이션(recalibrate monthly)**.
4. **도메인 사각지대(Domain Blind Spots)**: 판정자가 도메인 지식이 부족할 수 있음 → 대응: **10% 무작위 샘플에 대한 사람 검토**.
5. **형식 취약성(Format Brittleness)**: 모델이 유효하지 않은 JSON을 반환할 수 있음 → 대응: **try/except + 폴백 파서(fallback parser)**.
- 결론: 자동화된 판정자는 자동으로 신뢰할 수 있는 것이 아니며, 각 실패 모드에 구체적인 안전장치가 필요함.

### 캘리브레이션 검증: Spearman RHO
- CI/CD에서 LLM 판정자를 사용하기 전, 그것이 사람의 판단과 상관관계가 있는지 검증해야 함.
- 프로세스: LLM 점수와 사람 전문가 점수를 모두 가진 **50개 예시** 수집 → SciPy의 stats로 **Spearman RHO** 계산 → 배포를 위한 임계값 사용.
- **RHO ≥ 0.75**이면 판정자가 캘리브레이션되어 CI/CD에서 사용하기 안전하다고 간주. **RHO < 0.75**이면 그대로 진행하지 않고, 대신 루브릭을 더 적고(few) 짧고(short) 앵커(anchor)가 있는 형태로 재정의한 뒤 재시도.
- 실전 규칙: **캘리브레이션은 배포 전에 반드시 측정되어야 함**.

### 운영 원칙 4가지
1. **먼저 캘리브레이션하라(Calibrate First)**: 판정자를 CI/CD에 배포하기 전 사람 점수 대비 Spearman RHO가 최소 0.75여야 함.
2. **매달 재캘리브레이션**: 판정 점수 분포가 시간이 지나며 드리프트되므로 베이스라인을 정기적으로 갱신해야 함.
3. **인간 참여(Human in the Loop)**: 사각지대를 잡아내기 위해 무작위 10% 샘플을 사람이 검토해야 함.
4. **폴백 파서**: try/except 블록으로 판정 모델의 유효하지 않은 JSON을 우아하게 처리해야 함.
- 이런 원칙들이 흔한 실패와 드리프트를 자동 채점 시스템 운영을 위한 실용적 규칙으로 전환함.

### 코드 기반 에스컬레이션 예시: `escalator.py`
- 판정자의 신뢰도(confidence)가 낮거나 여러 판정자 간 불일치(disagreement)가 높을 때 사례를 사람의 검토로 보내는 로직.
- 규칙: **판정 신뢰도 < 0.5**이면 사람 검토로 전송. **판정자 간 불일치 > 0.2**이면 역시 사람 검토로 전송. 그 외에는 자동 점수를 수용.

### 핵심 요약 (4단어: Know, Escalate, Preserve, Result)
- **Know(알라)**: 자동화된 판정자는 모호성과 뉘앙스에서 가장 약함.
- **Escalate(에스컬레이션하라)**: 여러 판정자가 의견이 갈리는 것은 강력한 경고 신호.
- **Preserve(보존하라)**: 사람의 검토가 벤치마크를 신뢰할 수 있게 유지시킴.
- **Result(결과)**: 자동 채점은 스스로 완벽하다고 가장하지 않으면서 확장(scale)됨 — 강력한 자동 채점 시스템은 **스스로를 언제 신뢰하지 말아야 하는지에 대한 명시적 규칙**을 포함함.

### 결론
- 자동화된 채점은 길이 편향, 자기 편향, 캘리브레이션 드리프트, 도메인 사각지대, 형식 취약성이라는 명확한 한계를 가짐.
- 대응 프레임워크: 사람 점수 대비 캘리브레이션, 매달 정기적인 재캘리브레이션 유지, 사람 검토 샘플 유지, 폴백 파서 사용, 불확실한 사례를 사람에게 에스컬레이션.

## 예시
```python
# escalator.py (개념 구조)
def route_for_review(judge_confidence, judge_disagreement):
    if judge_confidence < 0.5 or judge_disagreement > 0.2:
        return "HUMAN_REVIEW"
    return "AUTO_ACCEPT"
```

```python
# 캘리브레이션 검증 (개념 구조)
from scipy import stats

llm_scores = [...]     # 50개 예시의 LLM 판정 점수
human_scores = [...]   # 동일 50개 예시의 사람 전문가 점수

rho, _ = stats.spearmanr(llm_scores, human_scores)

if rho >= 0.75:
    deploy_judge_to_cicd()
else:
    redesign_rubric(shorter=True, more_anchored=True)  # 재시도
```

| 한계 | 대응책 |
|---|---|
| 길이 편향 | 길이에 무관한 루브릭 |
| 자기 편향 | 다른 판정 모델 사용 |
| 캘리브레이션 드리프트 | 매달 재캘리브레이션 |
| 도메인 사각지대 | 10% 무작위 샘플 사람 검토 |
| 형식 취약성 | try/except + 폴백 파서 |

## 요약
- LLM-as-a-Judge는 길이 편향·자기 편향·캘리브레이션 드리프트·도메인 사각지대·형식 취약성이라는 5가지 한계를 가지므로, CI/CD에 배포하기 전 사람 점수와의 Spearman RHO가 0.75 이상인지 검증하고, 매달 재캘리브레이션하며, 10% 무작위 샘플을 사람이 검토하고, 폴백 파서로 형식 오류를 처리하고, 판정 신뢰도가 낮거나 판정자 간 불일치가 클 때 사람에게 에스컬레이션하는 안전장치를 갖춰야 스스로의 한계를 인정하면서도 신뢰성 있게 확장되는 자동 채점 시스템을 만들 수 있다.
