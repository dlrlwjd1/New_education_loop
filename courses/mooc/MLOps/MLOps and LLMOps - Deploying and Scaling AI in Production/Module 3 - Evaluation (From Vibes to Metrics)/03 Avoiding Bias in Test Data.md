# Avoiding Bias in Test Data

## 개요
- 평가 데이터셋의 5가지 편향(bias) 유형과 해결책, 그리고 데이터셋을 동결하기 전 실행해야 할 **5단계 편향 감사 체크리스트**를 다루는 5분 영상. "Designing LLM Evaluation Datasets" 레슨의 마지막 영상.

## 내용

### 왜 편향 체크가 중요한가
- 모델이 신중하게 평가되어도, 결과는 사용된 데이터셋만큼만 신뢰할 수 있음 — 평가셋이 편향되어 있으면, 최종 점수는 좋아 보여도 심각한 약점을 숨기고 있을 수 있음.
- 이 레슨은 평가셋의 **품질 보증(QA)**에 초점 — 편향 체크는 출시 시점에만 생각하는 것이 아니라 데이터셋 QA의 일부가 되어야 함.

### 5가지 흔한 편향 유형과 해결책
1. **카테고리 불균형(Category Imbalance)**: 어떤 카테고리가 데이터셋의 5% 미만이면 과소 대표될 수 있음 — 해당 카테고리를 업샘플링하거나 최소한 리포트에 문제를 명시할 것을 권장.
2. **라벨 편향(Label Bias)**: 한 명의 주석자(annotator)가 특정 응답을 선호하는 경향이 있을 때 발생 — 이를 줄이려면 항상 **2명 이상의 평가자**를 사용해야 함.
3. **최신성 편향(Recency Bias)**: 데이터가 짧은 시간 창(time window) 하나에서만 나오면 계절적이거나 변화하는 사용 패턴을 놓칠 수 있음 — 해결책은 **30일 이상**에 걸쳐 샘플링하는 것.
4. **난이도 편향(Difficulty Bias)**: 데이터셋에 쉬운 예시가 너무 많으면 최종 점수가 시스템의 실제 성능보다 좋아 보일 수 있음 — 세트의 약 **20%가 어렵거나 엣지 케이스**를 포함하도록 권장.
5. **선택 편향(Selection Bias)**: 사람들이 체계적으로 샘플링하는 대신 흥미로운 예시를 직접 골라낼 때 발생 — 해결책은 **알고리즘적 계층화 샘플링(algorithmic stratified sampling)** 사용.
- 핵심 요점: 편향은 평가셋에 여러 방식으로 들어올 수 있으므로, 팀은 무엇이 포함되었는지뿐 아니라 어떻게 선택되고 라벨링되었는지도 확인해야 함.

### 편향 감사 체크리스트 (동결 전 5단계)
1. **카테고리 균형 확인**: 어떤 카테고리도 전체의 5% 미만이 아닌지 검증 — 문제를 **플래그하되 데이터를 삭제하지는 말 것**(중요한 학습 포인트).
2. **길이 분포 확인**: 질의 길이 히스토그램이 짧은 예시만으로 지배되지 않아야 함.
3. **평가자 간 합의도 계산**: **Cohen's Kappa**를 사용 — 값이 0.7 미만이면 해당 배치를 재주석(re-annotate)해야 함.
4. **라벨 분포 확인**: 예시의 80% 이상이 정답(correct)이면 데이터셋이 너무 쉬운 것이므로 더 어려운 케이스를 추가해야 함.
5. **시간적 분산(Temporal Spread)**: 예시가 최신성 편향을 줄이기 위해 최소 **4주** 이상의 프로덕션 데이터에 걸쳐 있어야 함.

### 편향 인식 접근의 핵심 원칙 4가지
1. **다중 소스 체크(Multi-source Check)**: 팀은 카테고리, 라벨, 최신성, 난이도, 선택이라는 5개 영역 모두를 감사해야 함.
2. **동결 전 감사(Pre-freeze Audit)**: 편향 체크리스트는 어떤 평가 데이터셋이든 버전 관리하기 **전에** 실행되어야 함 — QA가 데이터셋이 릴리스 결정의 근거가 되기 전에 이루어짐을 의미.
3. **분기별 검토(Quarterly Review)**: 프로덕션 분포가 시간이 지나며 변할 수 있으므로 평가셋은 3개월마다 재감사되어야 함.
4. **투명성(Transparency)**: 어떤 데이터셋도 완벽하지 않으므로 평가 담당자는 평가셋 준비 시 알려진 편향을 문서화해야 함 — 목표는 완벽함을 주장하는 것이 아니라 한계를 명확히 이해하고 공개하는 것.
- 핵심 요점: 좋은 데이터셋 QA는 지속적이고, 체계적이고, 투명해야 함.

## 예시
```text
[5가지 편향 유형과 해결책]
카테고리 불균형 → 업샘플링 또는 문제 명시 (5% 미만 카테고리)
라벨 편향       → 2명 이상 평가자 사용
최신성 편향     → 30일 이상에 걸쳐 샘플링
난이도 편향     → 20% 이상 어려운/엣지 케이스 포함
선택 편향       → 알고리즘적 계층화 샘플링 사용
```

```text
[동결 전 5단계 편향 감사 체크리스트]
1. 카테고리 균형 확인 (5% 미만 카테고리 플래그, 삭제 금지)
2. 길이 분포 확인 (짧은 예시 편중 방지)
3. Cohen's Kappa 계산 (< 0.7이면 재주석)
4. 라벨 분포 확인 (80% 이상 정답이면 더 어려운 케이스 추가)
5. 시간적 분산 확인 (최소 4주 이상의 데이터)
```

## 요약
- 평가 데이터셋은 카테고리 불균형·라벨 편향·최신성 편향·난이도 편향·선택 편향이라는 5가지 편향에 취약할 수 있으며, 데이터셋을 동결하기 전 카테고리 균형·길이 분포·Cohen's Kappa 합의도·라벨 분포·시간적 분산을 확인하는 5단계 감사 체크리스트를 실행하고, 이를 분기별로 재감사하며 알려진 편향을 투명하게 문서화하는 지속적이고 체계적인 QA 프로세스가 신뢰할 수 있는 릴리스 결정의 전제 조건이다.
