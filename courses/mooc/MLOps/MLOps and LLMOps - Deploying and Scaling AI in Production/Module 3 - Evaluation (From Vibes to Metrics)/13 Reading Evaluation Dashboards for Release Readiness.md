# Reading Evaluation Dashboards for Release Readiness

## 개요
- 평가 대시보드를 프로덕션 릴리스 결정에 활용하는 방법 — 신호등(traffic light) 상태 체계, 30일 트렌드, 차원별 분해, 회귀 비교라는 4대 요소와 릴리스 매니저의 실전 검토 흐름을 다루는 7분 영상. "Integrating Evaluation into CI/CD Pipelines" 레슨의 세 번째 영상.

## 내용

### 대시보드는 단순 보고용이 아니다
- 프로덕션에서 대시보드는 팀이 시스템이 출시할 준비가 되었는지, 사람의 검토가 필요한지, 차단되어야 하는지 결정하는 데 도움을 줌 — 좋은 대시보드는 평가 결과를 **실행 가능한 것**으로 전환해야 함.

### 릴리스 준비 신호 (신호등 체계)
- **초록(Green)**: 모든 중요한 차원이 임계값 이상이고 베이스라인 대비 회귀가 없음.
- **노랑(Yellow)**: 결과가 아슬아슬하게 통과(marginal pass) — 예: 임계값의 1% 이내 — 이 경우 자동 승인해서는 안 되고 사람의 검토가 필요함.
- **빨강(Red)**: 절대 게이트가 실패했거나 회귀가 감지됨 — 이 경우 릴리스가 자동으로 차단되어야 함.
- 두 가지 보조 뷰:
  1. **30일 트렌드 뷰**: 서서히 진행되는 성능 저하를 위기가 되기 전에 잡아내는 데 도움.
  2. **차원별 분해(Dimension Breakdown)**: 정확성, 관련성, 형식을 개별적으로 표시해 문제가 어디서 오는지 팀이 볼 수 있게 함.
- 핵심 요점: 좋은 대시보드는 팀이 모든 것을 처음부터 해석하도록 강요해서는 안 됨 — 상태를 명확히 보여주고 그 상태를 행동에 직접 연결해야 함.

### 실전 시나리오: 릴리스 매니저의 대시보드 검토
- 후보 버전 2.3.1이 준비됨 → 릴리스 매니저가 대시보드 검토:
  1. **합성 점수**: 4.32/5, 베이스라인(4.21) 대비 **+2.6%** — 초록 상태.
  2. **차원별 지표**: 정확성 4.4, P95 지연시간 1,840ms, 형식 4.87 — 모두 초록으로 표시.
  3. **30일 트렌드**: 안정적이며 저하 없음 — 드리프트 징후 없음.
  4. **회귀 테스트**: 프로덕션 버전 v2.2.0 대비 모든 델타가 양(positive)수.
- 이를 바탕으로 대시보드가 **승인(approved)** 결정을 뒷받침함.
- 핵심 교훈: 릴리스 대시보드는 간단한 형태를 지원해야 함 — **헤드라인 상태 확인 → 차원 검증 → 트렌드 문제 확인 → 프로덕션과 비교 → 결정**.

### 효과적인 릴리스 대시보드의 핵심 원칙 4가지
1. **신호등 시스템(Traffic Light System)**: 초록/노랑/빨강이 릴리스 상태를 명확하게 만들고 모호함을 제거해야 함.
2. **트렌드 추적(Trend Tracking)**: 30일 트렌드 점수 이력이 단일 평가로는 놓칠 수 있는 단기 드리프트를 드러냄 — 대시보드를 일회성 결정뿐 아니라 장기적 신뢰성에도 유용하게 만듦.
3. **차원 세분성(Dimension Granularity)**: 팀은 합성 점수를 정확성, 형식, 지연시간 같은 부분으로 분해해 약한 결과의 근본 원인을 진단할 수 있어야 함.
4. **회귀 비교(Regression Comparison)**: 대시보드는 항상 후보를 현재 프로덕션 베이스라인과 비교해야 함 — 팀은 절대 점수 하나만으로 릴리스해서는 안 됨.
- 핵심 요점: 대시보드는 즉각적인 의사결정과 빠른 근본 원인 이해를 모두 도울 때 가장 가치 있음.

### 준비 상태 예시 구조
- `eval_score`: 전체 품질 결과.
- `hallucination_rate`: 안전 관련 리스크 지표.
- `p95_latency_ms`: 시스템의 꼬리 지연시간(tail latency) — 사용자 경험에 중요.
- `status`: 결과 상태를 요약(예: green).
- 핵심 아이디어: 헤드라인 상태가 드릴다운 지표보다 먼저 보여야 함 — 릴리스 매니저는 후보가 출시하기에 안전해 보이는지 즉시 알아야 하고, 그 다음 보조 지표로 이유를 이해해야 함. 최상위 지표는 go/no-go 결정 기준과 직접 일치해야 함.

### 실전 사용법 3가지
1. **요약(Summarize)**: 릴리스 상태가 드릴다운 지표보다 먼저 보여야 팀이 상황을 빠르게 파악할 수 있음.
2. **표시(Show)**: 사용자는 왜 빨강인지 빠르게 알아야 함 — 대시보드는 차단 상태를 보여주는 것뿐 아니라 여러 페이지를 뒤지지 않고도 이유를 가시화해야 함.
3. **정렬(Align)**: 대시보드는 릴리스 결정에 사용되는 규칙과 동일하게 반영해야 함.
- 결과: 팀이 대시보드를 단순히 차트 모음이 아니라 **행동 보드(action board)**로 읽게 됨.

### 결론
- 대시보드는 헤드라인 지표가 출시 결정에 직접 매핑될 때 가장 가치 있음.
- 강력한 평가 대시보드는 상태, 트렌드, 회귀, 행동의 이유를 즉시 가시화함으로써 팀이 더 빠르고 자신 있게 결정하도록 도움 — 가장 큰 가치는 숫자를 단순히 나열하는 것이 아니라, 릴리스 준비 상태를 가시화하고, 문제를 빠르게 설명하며, 지표를 출시 결정에 직접 연결하는 것.

## 예시
```json
// 대시보드 준비 상태 구조 예시
{
  "eval_score": 4.32,
  "baseline_score": 4.21,
  "delta_pct": 2.6,
  "hallucination_rate": 0.012,
  "p95_latency_ms": 1840,
  "status": "green"
}
```

```text
[릴리스 매니저의 검토 흐름]
1. 헤드라인 상태 확인 (green/yellow/red)
2. 차원별 지표 검증 (정확성/지연시간/형식)
3. 30일 트렌드 확인 (드리프트 여부)
4. 프로덕션 베이스라인과 비교 (회귀 확인)
5. 결정 (승인/사람 검토/차단)
```

| 상태 | 의미 | 조치 |
|---|---|---|
| 초록(Green) | 모든 차원 임계값 이상, 회귀 없음 | 자동 승인 가능 |
| 노랑(Yellow) | 임계값 근처 아슬아슬한 통과 | 사람 검토 필요 |
| 빨강(Red) | 절대 게이트 실패 또는 회귀 감지 | 자동 차단 |

## 요약
- 효과적인 평가 대시보드는 초록/노랑/빨강 신호등으로 릴리스 상태를 즉시 명확하게 만들고, 30일 트렌드로 서서히 진행되는 드리프트를 드러내며, 정확성·형식·지연시간 같은 차원별 분해로 근본 원인을 진단하고, 항상 프로덕션 베이스라인과의 회귀 비교를 포함해야 하며, 헤드라인 지표가 go/no-go 결정 기준과 직접 일치할 때 팀이 단순히 숫자를 보는 것을 넘어 빠르고 확신 있게 릴리스 결정을 내릴 수 있는 행동 보드가 된다.
