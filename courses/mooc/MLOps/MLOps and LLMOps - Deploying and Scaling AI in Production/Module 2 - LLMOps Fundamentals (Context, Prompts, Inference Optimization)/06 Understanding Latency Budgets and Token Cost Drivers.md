# Understanding Latency Budgets & Token Cost Drivers

## 개요
- 프로덕션 AI에서 정확도만큼 중요한 **속도(latency)**와 **비용(cost)**을 측정하는 핵심 지표, 비용을 좌우하는 3대 레버, 그리고 지원 봇(support bot) 최적화 실전 사례(비용 70% 절감)를 다루는 12분 영상. "Inference Optimization: Latency & Token Cost" 레슨의 첫 번째 영상.

## 내용

### 핵심 마인드셋 전환
- 시스템은 정확하다는 이유만으로 성공하지 않음 — 사용자에게 충분히 빠르고, 비즈니스가 확장할 수 있을 만큼 저렴해야 함.
- 매우 뛰어난 모델도 응답이 너무 느리거나 프로덕션에서 너무 비싸면 잘못된 솔루션일 수 있음.
- 최고의 프로덕션 시스템은 대체로 가장 크거나 가장 똑똑한 것이 아니라, **올바른 비용으로 사용자에게 올바른 경험을 제공하는 것**.

### 4대 핵심 지표
1. **TTFT(Time-to-First Token)**: 사용자가 모델이 응답을 시작하는 것을 보기까지 걸리는 시간 — "첫인상 지표"라 할 수 있음. 전체 답변이 좋아도, 느린 시작은 시스템을 반응 없는 것처럼 느끼게 만들 수 있음.
2. **전체 지연시간(Total Latency)**: 요청부터 완전한 응답까지의 전체 시간 — 팀은 평균이 아니라 **P95**(예: P95가 2초 미만)를 살펴봄. 평균은 가장 느린 사용자 경험을 가릴 수 있기 때문 — 프로덕션에서는 이런 느린 케이스들이 중요함.
3. **토큰 비용(Token Cost)**: 처리된 토큰 수에 따른 상호작용 비용 — 보내고 생성하는 토큰이 많을수록 대체로 더 많이 지불하게 됨.
4. **컨텍스트 비용(Context Cost)**: 특히 입력 토큰의 비용에 초점 — 긴 프롬프트, 큰 대화 이력, 과도한 검색 결과는 이 비용을 빠르게 증가시킬 수 있음.
- 요점: 프로덕션 AI는 속도 지표와 비용 지표 양쪽 모두로 측정되어야 함 — 한쪽만 보면 불완전한 그림을 얻게 됨.

### 비용을 좌우하는 3대 레버
1. **모델 크기(Model Size)**: 더 큰 모델은 대체로 더 유능하지만 더 비쌈 — 더 나은 성능은 공짜가 아니라는 교훈. 더 발전된 모델은 품질 향상이 추가 비용을 실제로 정당화할 때만 사용해야 함.
2. **컨텍스트 길이(Context Length)**: 프롬프트에 포함된 모든 토큰에는 비용이 있음 — 긴 지시문, 전체 채팅 이력, 과도한 검색 정보를 보내면 비용과 지연시간이 모두 증가함. 프롬프트 설계는 명확성뿐 아니라 **효율성**의 문제이기도 함.
3. **출력 길이(Output Length)**: 모델이 응답으로 생성하는 토큰 수 — 더 긴 답변은 비용이 더 들고 대체로 생성 시간도 더 걸림. 간결한 답변이 사용자 경험과 시스템 경제성을 동시에 개선할 수 있음.
- 핵심 요점: 비용 통제는 대체로 어떤 모델을 사용할지, 입력을 얼마나 보낼지, 출력을 얼마나 흐르게 할지에 대한 더 나은 결정에서 나옴.

### 실전 사례: 지원 봇(Support Bot) 비용 최적화
- **베이스라인**: GPT-4 사용, 평균 입력 12,000토큰 → 요청당 약 **36센트**.
- **최적화된 버전의 3가지 변경**:
  1. 단순한 질의의 80%를 **GPT-3.5 Turbo**로 라우팅 — 모든 요청이 강력한 모델을 필요로 하지 않는다는 중요한 개념. 더 쉬운 작업은 더 작고 저렴한 모델로 처리 가능.
  2. **시맨틱 청킹(semantic chunking)**으로 평균 컨텍스트를 12k에서 4k 토큰으로 축소 — 가장 관련성 높은 정보만 프롬프트에 포함. 검색 품질이 검색 양만큼 중요함을 강조.
  3. 출력을 **150토큰**으로 제한 — 길고 불필요한 완성(completion)을 방지.
- **결과**: 요청당 비용이 36센트에서 **11센트**로 하락 — 약 **70% 절감**, 정확도는 단 2%만 하락.
- 핵심 요점: 프로덕션 최적화는 대체로 희귀한 엣지 케이스가 아니라 **가장 흔한 사례**에 초점을 맞춤 — 스마트 라우팅, 더 작은 컨텍스트, 통제된 출력은 품질을 심각하게 해치지 않으면서 큰 절감을 만들어낼 수 있음.

### 핵심 원칙 4가지
1. **TTFT가 사용자 경험에 가장 중요함**: 사람들은 대체로 응답성을 얼마나 빨리 "시작하는지"로 판단하지, 끝나는 시점으로 판단하지 않음 — 체감 속도(perceived speed)는 제품 품질의 주요 부분.
2. **모델 크기를 적절히 맞춰라(Right-size the Model)**: 필요한 정확도 수준을 충족하는 가장 작은 모델로 시작 — 작업이 진정으로 필요로 할 때만 더 큰 모델로 이동. 더 크다고 항상 더 좋은 것은 아님.
3. **컨텍스트를 적극적으로 최소화하라**: 큰 프롬프트는 비용을 늘리고 시스템을 느리게 함 — 청킹, 필터링, 요약, 캐싱 같은 기법을 사용해 모델이 가장 관련성 높은 정보만 받도록 할 것.
4. **출력 길이를 제한하라(Cap Output Length)**: 답변을 집중적이고, 예측 가능하고, 비용 효율적으로 유지하는 데 도움.
- 요약: 경험을 측정하고, 올바른 모델을 선택하고, 프롬프트를 줄이고, 완성을 제한하는 것.

### 코드 안에 비용 인식을 내장하기
- 실전 예시: 시스템이 총 토큰 사용량(입력 3,400토큰 + 출력 600토큰 = 총 4,000토큰)에 기반해 요청의 비용을 계산 — 1,000토큰당 $0.0025 가격에서 요청 비용은 약 **1센트**.
- 이 금액이 **2센트 임계값**보다 낮으므로 요청은 정상적으로 진행 허용됨. 만약 예상 비용이 예산보다 높았다면, 시스템은 프롬프트를 전송하기 전에 컨텍스트를 축소·압축하는 `shrink_context`를 호출했을 것.
- 중요한 학습 개념: **비용 통제는 사후 보고 지표로만 남아서는 안 되고 시스템 의사결정 프로세스의 일부가 되어야 함**.
- **TURN·BALANCE·GUARDS·RESULT** 개념:
  - **TURN**: 상호작용당 비용을 계산.
  - **BALANCE**: 사용자 경험과 나란히 비용의 무게를 재라.
  - **GUARDS**: 요청이 너무 비싸질 때 통제를 트리거하라.
  - **RESULT**: 실제로 지출이 누적되는 곳을 최적화하라.

### 결론
- 좋은 프로덕션 시스템은 엔지니어링 결정과 예산 결정을 분리하지 않음 — 지연시간, 품질, 비용을 함께 관리함.
- 가장 중요한 교훈: **프로덕션 AI는 트레이드오프에 관한 것** — 강력한 솔루션은 실제 사용자에게 효과가 있도록 성능, 속도, 경제성의 균형을 맞추는 방식으로 만들어짐.

## 예시
```text
[4대 핵심 지표]
TTFT (Time-to-First Token)  — 첫 토큰까지 걸리는 시간 (첫인상)
Total Latency (P95 기준)     — 전체 응답 시간, 평균이 아닌 P95로 측정
Token Cost                   — 처리된 토큰 수 기반 비용
Context Cost                 — 입력 토큰(긴 프롬프트/이력/검색결과)의 비용
```

```text
[지원 봇 비용 최적화 사례]
베이스라인: GPT-4, 평균 입력 12,000토큰 → 36센트/요청
        │
        ▼ (3가지 변경)
1. 단순 질의 80% → GPT-3.5 Turbo로 라우팅
2. 시맨틱 청킹으로 컨텍스트 12k → 4k 토큰 축소
3. 출력 150토큰으로 제한
        │
        ▼
결과: 11센트/요청 (70% 절감), 정확도 -2%만 하락
```

```python
# 요청 비용 계산 및 가드 (개념 구조)
COST_PER_1K_TOKENS = 0.0025
BUDGET_THRESHOLD_CENTS = 2

def estimate_cost(input_tokens, output_tokens):
    total_tokens = input_tokens + output_tokens
    return (total_tokens / 1000) * COST_PER_1K_TOKENS * 100  # cents

def handle_request(prompt, input_tokens, output_tokens):
    cost = estimate_cost(input_tokens, output_tokens)  # 예: 4000 토큰 → 약 1센트
    if cost > BUDGET_THRESHOLD_CENTS:
        prompt = shrink_context(prompt)  # 프롬프트 축소/압축 후 재계산
    return send_request(prompt)
```

## 요약
- 프로덕션 AI는 정확도뿐 아니라 TTFT·전체 지연시간(P95)·토큰 비용·컨텍스트 비용이라는 4대 지표로 함께 측정되어야 하며, 비용은 모델 크기·컨텍스트 길이·출력 길이라는 3대 레버로 통제할 수 있고, 지원 봇 사례처럼 단순 질의를 작은 모델로 라우팅하고 컨텍스트를 시맨틱 청킹으로 압축하며 출력을 제한하면 정확도 손실을 최소화하면서 비용을 크게(사례에서 70%) 절감할 수 있으며, 이런 비용 통제는 사후 리포트가 아니라 요청 처리 로직 자체에 가드로 내장되어야 한다.
