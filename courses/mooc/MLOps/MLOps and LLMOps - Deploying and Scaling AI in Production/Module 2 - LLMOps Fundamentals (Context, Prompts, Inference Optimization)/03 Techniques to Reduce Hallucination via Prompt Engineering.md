# Techniques to Reduce Hallucination via Prompt Engineering

## 개요
- 프로덕션 AI의 주요 문제인 **환각(Hallucination)**을 그라운딩(grounding), 거부(refusal), 인용(citation), temperature=0 같은 프롬프트 엔지니어링 기법으로 줄이는 방법을 실제 수치 사례(18%→2.1%)와 함께 다루는 8분 영상.

## 내용

### 환각이란
- 모델이 맞는 것처럼 들리지만 실제로는 틀렸거나, 근거 없거나, 지어낸 정보를 제공하는 것.
- 위험한 이유: 사용자가 실제 근거에 기반하지 않은 답변도 신뢰할 수 있기 때문.
- 목표는 모델이 단순히 자신 있게 답하도록 만드는 것이 아니라, **실제로 가진 정보를 바탕으로 진실하게(truthfully) 답하도록 만드는 것**.

### 4가지 대표적인 항환각(anti-hallucination) 기법
1. **그라운딩(Grounding)**: 제공된 컨텍스트를 사용하도록 함 — 환각률에 **70%**의 영향을 미침.
2. **거부 조항(Refusal Clause)**: 확실하지 않으면 "모른다"고 답하도록 함 — 자신감 있는 오답을 방지.
3. **사고 사슬(Chain of Thought)**: 먼저 단계별로 추론하게 함 — 가장 높은 사실적 정확도(factual accuracy) 달성에 도움.
4. **검증 요청(Verification Ask)**: 사용한 문장을 인용하고 근거(grounding)를 명시하도록 요청.

### 실전 사례: 지원 봇(Support Bot)
- 문제: 봇이 정책 세부사항을 지어내고(fabricate) 있었음 — 제공된 정보로 실제로 뒷받침되지 않는 답변을 하고 있었음.
- 추가된 3가지 강력한 규칙:
  1. **그라운딩**: 아래 컨텍스트에서만 답변할 것.
  2. **거부**: 컨텍스트가 불충분하면 "그 정보를 가지고 있지 않습니다"라고 답할 것.
  3. **인용**: 사용한 정확한 문장을 출처와 함께 인용할 것.
- 이 규칙들을 적용한 후 **환각률이 18%에서 2.1%로 하락**.
- 교훈: 모델을 그라운딩하고, 거부를 허용하고, 근거를 요구하면 환각이 크게 낮아짐 — 모델이 컨텍스트를 사용해야 하고, 확실하지 않을 때 거부해야 하며, 근거를 보여줘야 할 때 더 안전해짐.

### Temperature를 0으로 설정하는 이유
- **Temperature**는 모델 출력이 얼마나 무작위적일 수 있는지를 제어.
- Temperature를 0으로 설정하면 출력이 더 **결정론적(deterministic)**이 됨 — 동일한 입력에 대해 동일한 답변을 낼 가능성이 높아짐.
- 프로덕션 시스템에서 유용한 이유: 안정적인 동작, 반복 가능한 답변, 적은 무작위 변동을 원하기 때문 — 동일한 입력은 매번 동일한 출력을 내야 함.
- **Temperature=0이 환각 자체를 해결하지는 않지만**, 더 신뢰할 수 있는 프로덕션 동작을 지원 — 무작위성을 줄이고 출력을 더 안정적으로 만듦.

### 항환각 핵심 원칙 4가지
1. **응답을 그라운딩하라(Ground Response)**: 제공된 컨텍스트에서만 답하도록 모델에게 지시.
2. **거부를 허용하라(Enable Refusal)**: 컨텍스트가 불충분할 때 "모른다"고 말할 수 있게 허용.
3. **인용을 요구하라(Require Citations)**: 사용한 정확한 출처 문장을 인용하도록 요청.
4. **Temperature=0 사용**: 출력을 더 결정론적이고 안정적으로 만듦.
- 이 규칙들은 추측을 더 어렵게 만들고 정직함을 더 쉽게 만드는 강력한 실전 규칙 — 핵심 규칙은 답변을 그라운딩하고, 거부를 허용하고, 근거를 요구하고, 무작위성을 줄이는 것.

### 그라운딩된 프롬프트 예시
- 프롬프트 지시: "제공된 컨텍스트만 사용하라. 근거가 없으면 '제공된 컨텍스트로는 모른다'고 답하라. 다음을 반환하라: (1) 답변, (2) 인용된 근거(cited evidence), (3) 누락된 필요 정보(missing information needed)."
- 이 프롬프트가 강력한 이유는 3가지를 동시에 수행하기 때문:
  1. 모델을 제공된 컨텍스트로 제한.
  2. 안전한 거부를 허용.
  3. 모델이 근거와 누락 정보를 포함하도록 강제.
- 즉 모델이 추측하도록 유도되지 않고, 자신이 아는 것과 모르는 것에 대해 정직하도록 유도됨 — 이것이 단순한 시스템을 더 안전하고 신뢰하기 쉽게 만듦.

### 실전 이점
1. **제약(Constrain)**: 그라운딩된 응답 또는 기권(abstain)을 강제.
2. **요구(Require)**: 인용된 근거 없는 답변은 거부하기 쉬워짐.
3. **개선(Improve)**: 오정보(misinformation) 프롬프트가 도구 사용이나 후속 조치를 개선.
- 결과: **추측하는 것이 정직한 것보다 더 어려워짐**.
- 최종 메시지: **기권 규칙(abstention rules)과 근거 요구사항(evidence requirements)은 종종 신중한 문구(careful wording) 하나만으로는 얻을 수 없는 강력함을 제공**함 — 단순히 모델에게 조심하라고 말하는 것으로는 충분하지 않으며, 실제로 동작을 바꾸는 규칙이 필요함: 컨텍스트만 사용, 컨텍스트가 없으면 거부, 마지막으로 근거 제공.

### 결론
- 환각을 줄이는 가장 좋은 방법은 단순히 모델에게 경고하는 것이 아니라, **근거와 거부에 대한 명확한 규칙을 주는 것**.
- 항환각 기법(컨텍스트 그라운딩, 근거 부족 시 거부 허용, 인용 요구, temperature=0을 통한 안정적 출력)은 시스템을 더 안전하고 신뢰할 수 있게 만듦 — 핵심 아이디어는 단순함: **정직함을 추측보다 더 쉽게 만들라**.

## 예시
```text
[그라운딩된 프롬프트 구조]
"아래 제공된 컨텍스트만 사용해 답변하라.
근거가 부족하면 '제공된 컨텍스트로는 알 수 없습니다'라고 답하라.
다음 세 가지를 반환하라:
1) answer (답변)
2) cited_evidence (인용된 근거 문장)
3) missing_information_needed (부족한 정보)"
```

| 조치 | 환각률 |
|---|---|
| 그라운딩·거부·인용 규칙 적용 전 | 18% |
| 그라운딩·거부·인용 규칙 적용 후 | 2.1% |

```text
[항환각 4대 원칙]
1. 응답 그라운딩 — 제공된 컨텍스트에서만 답변
2. 거부 허용 — 근거 부족 시 "모른다" 허용
3. 인용 요구 — 사용한 정확한 문장 인용
4. Temperature = 0 — 결정론적·안정적 출력
```

## 요약
- LLM의 환각은 응답을 제공된 컨텍스트에 그라운딩하고, 근거가 부족할 때 거부를 허용하며, 정확한 출처 문장의 인용을 요구하고, temperature를 0으로 설정해 출력을 안정화하는 조합으로 크게 줄일 수 있으며(실제 사례에서 18%→2.1%), 핵심은 모델에게 단순히 조심하라고 경고하는 것이 아니라 추측보다 정직함이 쉬워지도록 실제로 동작을 바꾸는 명시적 규칙(기권 규칙 + 근거 요구사항)을 프롬프트에 강제하는 것이다.
