# Logging Prompt Variants with W&B/MLflow

## 개요
- 프로덕션 AI에서 프롬프트 로깅이 왜 중요한지, 그리고 시맨틱 버저닝과 메타데이터 로깅을 통해 프롬프트를 추적 가능·재현 가능·측정 가능하게 만드는 방법을 다루는 2분 영상. "Prompt Versioning & Experiment Tracking" 레슨의 첫 번째 영상.

## 내용

### 프롬프트는 임시 텍스트가 아니다
- 프로덕션에서 프롬프트는 시스템 동작에 영향을 미치므로 신중하게 추적되어야 함.
- 팀은 어떤 프롬프트 버전이 사용되었는지, 어떤 설정이 연결되어 있었는지, 어떤 결과를 만들어냈는지 알아야 함.
- **프롬프트 로깅**은 프롬프트 변경을 추적 가능(traceable)하고, 재현 가능(reproducible)하고, 측정 가능(measurable)하게 만드는 방법.
- W&B, MLflow 같은 도구들이 팀이 프롬프트 엔지니어링과 실험을 구조화된 방식으로 관리하도록 도움.

### 프롬프트를 위한 시맨틱 버전
- **모든 프롬프트 변경은 새로운 버전으로 취급되어야 함** — "프롬프트가 업데이트되었다"고 말하는 대신, 팀은 v1.3.2에서 v1.4.0으로 이동하는 것 같은 시맨틱 버전을 사용 — 변경 사항을 더 명확하게 추적·논의할 수 있게 됨.
- 각 버전과 함께 로깅되어야 할 메타데이터: **버전, 시스템 프롬프트, temperature, 모델, 평가 데이터셋 버전**.

### 두 가지 핵심 규칙
1. **로그된 프롬프트는 불변(immutable)이어야 함**: 한 번 버전이 저장되면 절대 수정되어서는 안 됨.
2. **프롬프트 로깅은 재현성을 지원함**: 동일한 프롬프트와 동일한 데이터는 동일한 결과를 만들어내야 함.

### 결론
- 핵심 요점은 단순함: **프롬프트 변경을 버전 관리하고, 프롬프트를 제어 시스템(control system)처럼 다루라.**

## 예시
```yaml
# 프롬프트 버전 메타데이터 (개념 구조)
version: 1.4.0
system_prompt: "당신은 고객 지원 어시스턴트입니다..."
temperature: 0.0
model: gpt-4
eval_dataset_version: 3.2.0
immutable: true
```

## 요약
- 프로덕션 프롬프트는 시스템 동작에 직접 영향을 미치는 자산이므로 v1.3.2→v1.4.0 같은 시맨틱 버전으로 관리하고, 버전·시스템 프롬프트·temperature·모델·평가 데이터셋 버전을 메타데이터로 함께 로깅해야 하며, 한 번 저장된 로그는 절대 수정하지 않는 불변성과 동일 입력이 동일 결과를 내는 재현성이라는 두 원칙 아래 W&B/MLflow 같은 도구로 프롬프트를 제어 시스템처럼 다뤄야 한다.
