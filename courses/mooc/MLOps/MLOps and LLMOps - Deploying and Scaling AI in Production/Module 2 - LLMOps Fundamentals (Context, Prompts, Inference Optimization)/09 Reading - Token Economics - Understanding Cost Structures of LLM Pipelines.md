# "Token Economics: Understanding Cost Structures of LLM Pipelines"

## 개요
- 앞선 3개 영상([06 지연시간·토큰 비용](06%20Understanding%20Latency%20Budgets%20and%20Token%20Cost%20Drivers.md), [07 배칭·캐싱·스트리밍](07%20Batching%2C%20Caching%2C%20Streaming%2C%20Compression.md), [08 API vs 로컬 모델](08%20Model%20Choices%20-%20API%20vs%20Local%20Models.md))을 요약하며 **prefill/decode 단계**와 **양자화(quantization)**라는 새로운 개념을 보충하는 리딩(30분).

## 내용

### LLM 추론의 두 단계: Prefill과 Decode
- LLM 추론은 두 단계로 나뉨 — 각기 다른 연산 특성을 가짐:
  1. **Prefill(프리필)**: 모든 입력 토큰을 **병렬로** 처리하는 단계.
  2. **Decode(디코드)**: 출력 토큰을 **순차적으로** 생성하는 단계.
- 토큰 비용은 모델 크기, 제공업체의 가격 구조(pricing tier), 처리된 총 토큰 수(입력+출력)에 의해 결정됨 — 이 때문에 **프롬프트 길이 최적화가 직접적인 비용 레버**가 됨.

### 배칭·캐싱·스트리밍·압축 — 4대 기법 보충
- **시맨틱 캐싱**은 유사한 질의에 대한 응답을 저장해 API 비용을 **최대 73%**까지 절감할 수 있음.
- **응답 스트리밍**은 완료를 기다리지 않고 토큰이 생성되는 대로 반환해 체감 지연시간을 개선.
- **배칭**은 여러 요청을 그룹화해 GPU 활용을 효율화.
- **압축(Compression) — 양자화(Quantization)**: **AWQ, FP8** 같은 기법으로 모델 크기를 **50~75%** 줄이면서도 품질 손실은 크지 않게 유지 가능 — 앞선 영상에서 다루지 않은 새로운 압축 기법.

### API 기반 vs 로컬 호스팅 모델 — 트레이드오프 보충
- 클라우드 API는 인프라 관리가 전혀 필요 없고 최신 모델에 즉시 접근 가능하지만, 사용량에 선형적으로 비례하는 토큰당 비용이 발생.
- **vLLM이나 SGLang** 같은 서빙 엔진을 사용한 로컬 배포는 사전 GPU 투자가 필요하지만, 예측 가능한 비용, 더 낮은 지연시간, 완전한 데이터 프라이버시를 제공 — 대량 트래픽이나 민감한 애플리케이션에 더 선호됨.

## 예시
```text
[LLM 추론 2단계]
Prefill (병렬 처리)  — 입력 토큰 전체를 한 번에 처리
Decode  (순차 생성)  — 출력 토큰을 하나씩 순차적으로 생성
→ 두 단계의 연산 특성이 다르므로 최적화 전략도 다르게 적용해야 함
```

```text
[양자화(Quantization) 압축 기법]
AWQ, FP8 등 → 모델 크기 50~75% 축소, 품질 손실 최소화
→ 배칭·캐싱·스트리밍과 함께 사용하는 네 번째 최적화 축
```

| 서빙 엔진 | 특징 |
|---|---|
| vLLM / SGLang | 로컬 GPU 서빙 엔진 — 예측 가능한 비용, 낮은 지연시간, 완전한 데이터 프라이버시 |

## 요약
- 이 리딩은 LLM 추론이 병렬 처리되는 prefill 단계와 순차 생성되는 decode 단계로 나뉜다는 점, 시맨틱 캐싱이 API 비용을 최대 73%까지 줄일 수 있다는 구체적 수치, 그리고 AWQ/FP8 같은 양자화 기법으로 모델 크기를 50~75% 압축할 수 있다는 새로운 최적화 축을 보충하며, vLLM/SGLang 같은 로컬 서빙 엔진이 예측 가능한 비용과 데이터 프라이버시를 제공한다는 점을 강조한다.
