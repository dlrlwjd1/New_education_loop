# "Prompt Architecture Patterns for Production LLM Systems"

## 개요
- 앞선 3개 영상([01 컨텍스트 윈도우](01%20Designing%20Efficient%20Context%20Windows.md), [02 구조화된 프롬프트](02%20Structured%20Prompts%20for%20Reliability%20and%20Determinism.md), [03 환각 감소 기법](03%20Techniques%20to%20Reduce%20Hallucination%20via%20Prompt%20Engineering.md))을 요약하며 **"lost in the middle" 효과**라는 새로운 개념을 보충하는 리딩(30분).

## 내용

### 컨텍스트 윈도우 설계 — "Lost in the Middle" 효과
- 검색된 콘텐츠를 전략적으로 순서 배치하고, 가장 관련성 높은 메타데이터만 주입하고, 토큰 한계를 지켜 LLM이 사용할 수 있는 유용한 정보를 극대화해야 함.
- **연구에 따르면 LLM은 컨텍스트 윈도우의 시작과 끝 부분의 콘텐츠에 더 강하게 주의를 기울인다** — 이를 **"lost in the middle" 효과**라고 부름. (앞선 영상에서 다룬 "최신성 편향"이 끝부분만 언급했다면, 이 리딩은 **시작과 끝 모두**가 강조된다는 점을 보충함.)
- 따라서 가장 관련성 높은 문서를 이 위치(시작·끝)에 배치하면 응답 품질이 향상됨.
- 메타데이터 주입(출처 제목, 날짜, 관련도 점수를 검색된 텍스트와 함께 추가)은 모델이 응답을 그라운딩하고 출처를 명시(source attribution)할 수 있게 도움.

### 구조화된 프롬프트 — 프로덕션 아키텍처 패턴
- 시스템 지시문, 사용자 컨텍스트, 검색된 문서, 출력 형식 명세를 명확히 분리한 구조화된 프롬프트가 더 신뢰할 수 있고 결정론적인 출력을 만듦.
- 프로덕션 프롬프트 아키텍처는 일반적으로 **템플릿 시스템**을 사용해 모든 호출에서 일관된 구조를 강제하면서 동적 콘텐츠 주입을 허용.
- **XML 태그 섹션, 번호가 매겨진 문서 참조, 명시적 제약 문장** 같은 기법들이 모호성을 줄이고 프롬프트를 버전 관리·테스트·디버깅하기 쉽게 만듦.

### 환각 감소 — 검색 최적화와의 상호 보완성
- 프롬프트 엔지니어링을 통한 환각 감소: 명시적 그라운딩 지시("제공된 문서에 기반해서만 답하라"), 신뢰도 보정("컨텍스트에 답이 없으면 '모른다'고 말하라"), 특정 출처 구절을 참조하도록 강제하는 인용 요구사항.
- 이 기법들은 **검색 최적화(retrieval optimization)와 상호 보완적**: 고정된 검색 품질에서는 더 나은 프롬프트가 환각을 줄이고, 고정된 프롬프트에서는 더 나은 검색이 환각을 줄임.
- **두 접근을 결합하는 것이 가장 신뢰할 수 있는 프로덕션 시스템을 만든다.**

## 예시
```text
[Lost in the Middle 효과]
컨텍스트 윈도우: [시작 — 강한 주의] ... [중간 — 약한 주의] ... [끝 — 강한 주의]
→ 가장 관련성 높은 문서를 시작 또는 끝에 배치할 것 (중간에 묻히지 않도록)
```

```xml
<!-- XML 태그 기반 프롬프트 구조 예시 -->
<system>당신은 고객 지원 어시스턴트입니다.</system>
<context>
  <document id="1" source="FAQ" date="2026-01-10">...</document>
  <document id="2" source="Manual" date="2025-11-02">...</document>
</context>
<constraints>제공된 문서 내용만 사용하라. 근거가 없으면 "모른다"고 답하라.</constraints>
<output_format>JSON: {answer, cited_document_id, confidence}</output_format>
```

## 요약
- 이 리딩은 컨텍스트 윈도우 설계에서 LLM이 시작과 끝 부분에 더 강하게 주의를 기울이는 "lost in the middle" 효과를 새롭게 짚어주고, 구조화된 프롬프트가 XML 태그·번호 참조·명시적 제약을 통해 프로덕션급 템플릿 시스템으로 발전한다는 점, 그리고 환각 감소가 프롬프트 엔지니어링과 검색 최적화 양쪽 모두에서 상호 보완적으로 이루어져야 가장 신뢰할 수 있는 시스템이 된다는 점을 강조한다.
