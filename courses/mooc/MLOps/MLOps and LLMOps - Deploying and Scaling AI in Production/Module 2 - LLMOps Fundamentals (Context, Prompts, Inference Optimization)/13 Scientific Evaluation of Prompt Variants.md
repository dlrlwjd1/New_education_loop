# Scientific Evaluation of Prompt Variants (Statistical Testing)

## 개요
- 프롬프트 변경이 우연한 노이즈가 아니라 **통계적으로 유의미하고 실질적으로 가치 있는** 개선인지 검증하는 방법 — 고정된 평가 데이터셋, 표본 크기, 대응표본 t-검정(paired t-test), 최소 실질 개선 임계값을 다루는 7분 영상. "Prompt Versioning & Experiment Tracking" 레슨의 마지막 영상.

## 내용

### 왜 통계적 검정이 필요한가
- 모든 개선이 진짜 개선은 아님 — 새 프롬프트가 더 나아 보이는 것은 때로 평가 데이터의 무작위 변동 때문일 수 있음.
- 프로덕션에서 팀은 작게 관측된 이득만으로 프롬프트 변경을 승격해서는 안 됨 — 그 이득이 **통계적으로 신뢰할 수 있고 실질적으로 유용하다**는 증거가 필요함.
- 프롬프트 승격은 직관이 아니라 **증거**에 기반해야 함.

### 유효한 통계적 비교를 위한 4가지 요건
1. **동일한 평가 데이터셋 사용**: 모든 실험에 동일한 데이터셋을 사용 — 데이터는 고정(frozen)되고 버전 관리되어야 하며, 비교 사이에 절대 다시 실행(rerun)해서는 안 됨. 예시가 바뀌면 결과를 더 이상 직접 비교할 수 없기 때문.
2. **표본 크기(Sample Size)**: **3%의 품질 차이를 탐지하기 위해 80%의 검정력(power)을 달성하려면 n은 최소 200 이상**이어야 함 — 의미 있는 개선을 신뢰성 있게 탐지하기에 충분한 예시 수가 필요.
3. **샘플별 지표 로깅**: 점수, 밀리초 단위 지연시간, USD 단위 비용, 형식 정확성을 포함 — 승격 결정은 품질만이 아니라 더 많은 것을 고려해야 하기 때문.
4. **통계적 유의성**: **대응표본 t-검정(paired t-test)의 p-값이 0.05 미만**이어야 승격 가능. 마지막으로 **승격 규칙**: 정확성이 하락하지 않고, 다른 어떤 지표도 1% 넘게 퇴보하지 않을 때만 승격.
- 핵심 요점: 유효한 평가는 일관성, 충분한 데이터, 명확하게 정의된 임계값에 달려 있음.

### 실전 A/B 실험 예시
- 고정된 200개 예시에서 버전 1.3.2와 1.4.0 비교.
- 프로세스: 버전 1.3.2를 200개 예시 전체에 실행해 각각의 점수 기록 → 버전 1.4.0을 동일한 200개 예시에 실행해 점수 기록.
- **대응표본 t-검정** 적용(`scipy.stats.ttest_rel`) — 이 예시에서 p-값은 **0.0023**으로 0.05보다 낮음 → 개선이 통계적으로 유의미하고 우연에 의한 것일 가능성이 낮음.
- 유의성 검정을 통과하고 다른 모든 지표도 임계값을 충족하므로, 시스템은 버전 1.4.0을 스테이징으로 **자동 승격**할 수 있음.
- 핵심 교훈: 팀은 새 프롬프트가 단순히 더 나아 보인다는 이유로 승격하는 것이 아니라, 그것이 개선되었고, 테스트되었고, 통계적 증거로 뒷받침된다는 이유로 승격함.

### 핵심 원칙 4가지
1. **고정 데이터셋(Fixed Dataset)**.
2. **통계적 엄격성(Statistical Rigor)**.
3. **다중 지표 게이트(Multi-metric Gates)**: 품질만으로는 충분하지 않음 — 지연시간, 비용, 형식도 허용 가능한 범위 내에 있어야 함.
4. **재현성(Reproducibility)**: 팀은 평가 데이터셋을 버전 관리하고 모든 점수를 로깅해 모든 결정에 명확한 감사 추적(audit trail)이 남도록 해야 함.
- 핵심 요점: 신뢰할 수 있는 승격은 건전한 실험 설계와 완전한 기록 관리 모두에 달려 있음.

### 구현 예시: A/B 테스트 (Python)
- 스크립트가 변형 B와 변형 A 사이의 **승률 차이(lift)**를 계산 → 두 변형의 점수 배열에 대해 t-검정으로 p-값 계산.
- **결정 규칙**: `lift > 0.03`(3% 초과 개선) **그리고** `p-value < 0.05`일 때만 변형 B를 승격.
- 핵심 통찰: **통계적 유의성만으로는 충분하지 않음** — 결과는 최소한의 실질적 개선 임계값도 충족해야 함. 즉 통계적으로 유의미하지만 비즈니스 관점에서는 무시해도 될 만큼 작을 수 있음.
- 핵심 교훈: 프로덕션 팀은 통계적 확신과 실질적 가치를 **모두** 필요로 함.

### 실전 의미 요약
1. 작은 승리(small win)가 노이즈에 불과하다면 승격되어서는 안 됨 — 신뢰할 수 없는 미세한 차이에 과잉 반응하지 않도록 주의해야 함.
2. 두 변형을 **동일한 예시**로 점수 매겨야 공정하고 통제된 비교가 됨.
3. 유의미한 승리도 여전히 **실질적인 비즈니스 가치**를 가져야 함 — 통계적으로 진짜라도, 운영상 의미 있을 만큼 충분히 커야 함.
- 결과: 프롬프트 승격이 증거 기반(evidence-based)이 됨.

### 최종 메시지
- **통계적 검정은 최소 실질 개선 임계값과 결합될 때 가장 유용함.**
- AI 프로덕션에서 프롬프트는 실제적이고, 측정 가능하고, 의미 있는 개선을 보여줄 때만 승격되어야 함 — 승격 결정은 추측이나 고립된 승리가 아니라 공정한 평가, 통계적 증거, 명확한 실질적 이익에 기반해야 함.

## 예시
```python
# A/B 테스트 결정 규칙 (개념 구조)
from scipy import stats

def evaluate_promotion(scores_baseline, scores_candidate):
    lift = win_rate(scores_candidate) - win_rate(scores_baseline)
    t_stat, p_value = stats.ttest_rel(scores_candidate, scores_baseline)

    if lift > 0.03 and p_value < 0.05:
        return "PROMOTE"  # 통계적 유의성 + 실질적 개선(3% 초과) 모두 충족
    return "HOLD"
```

```text
[프롬프트 승격 실전 사례]
버전 1.3.2(베이스라인) vs 1.4.0(후보), 고정 200개 예시
paired t-test → p-value = 0.0023 (< 0.05, 통계적으로 유의미)
+ 다른 지표(지연시간, 비용, 형식)도 임계값 충족
→ 자동 승격(auto-promote) → 스테이징 이동
```

| 요건 | 기준 |
|---|---|
| 표본 크기 | n ≥ 200 (3% 품질 차이를 80% 검정력으로 탐지) |
| 통계적 유의성 | paired t-test p-value < 0.05 |
| 승격 규칙 | 정확성 하락 없음 + 다른 지표 1% 초과 퇴보 없음 |
| 실질적 개선 임계값 | lift > 0.03 (3% 초과) |

## 요약
- 프롬프트 변경의 승격은 고정되고 버전 관리된 평가 데이터셋에서 충분한 표본 크기(n≥200)로 대응표본 t-검정을 수행해 p-value가 0.05 미만인 통계적 유의성을 확인하는 것에 더해, 3% 초과 같은 최소 실질 개선 임계값까지 함께 충족해야 하며, 정확성·지연시간·비용·형식이라는 다중 지표 게이트와 완전한 기록 관리(재현성)를 결합했을 때만 증거 기반의 신뢰할 수 있는 프롬프트 승격이 가능하다.
