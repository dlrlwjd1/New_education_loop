# Model Registries: MLflow, W&B, and Custom Systems

## 개요
- 모델 레지스트리가 ML/LLM 딜리버리에서 왜 중요한지, MLflow·Weights & Biases·커스텀 레지스트리를 비교하고, 코드 기반 승격 기준(promotion criteria)과 레지스트리 선택 기준·핵심 원칙을 다루는 7분 영상.

## 내용

### 모델 레지스트리란 무엇이고 왜 필요한가
- 모델 학습은 생애주기의 일부에 불과함 — 모델이 평가된 후에도 팀은 이를 신뢰성 있게 저장하고, 버전을 관리하고, 메타데이터를 추적하고, 스테이징에서 프로덕션으로 어떻게 이동하는지 통제할 방법이 필요.
- **모델 레지스트리**는 모델 버전, 그 계보(lineage), 승인 상태(approval state), 배포 준비 상태(deployment readiness)에 대한 **시스템 오브 레코드(system of record)**.

### 레지스트리 옵션 비교
- **MLflow**: 실험 추적과 모델 생애주기 관리와 잘 통합되는, 개방적이고 널리 채택된 레지스트리를 원하는 팀에 강력한 선택.
- **Weights & Biases(W&B)**: 이미 실험(experimentation)에 W&B를 많이 사용하고 있고, 실험 추적과 거버넌스 워크플로 사이의 더 긴밀한 통합을 원하는 팀에 매력적.
- **커스텀 레지스트리**: 조직이 내부 승인 흐름(approval flow), 컴플라이언스 통제, 또는 자체 배포 플랫폼과의 깊은 통합 같은 특별한 요구사항을 가질 때 필요해짐.
- 진짜 질문은 "어떤 도구가 보편적으로 최고인가"가 아니라, **어떤 레지스트리가 팀에게 사용성·거버넌스·추적성·운영 적합성의 올바른 균형을 주는가**.

### 승격 기준(Promotion Criteria)
- 첫 번째 원칙: **프로덕션으로의 승격은 절대 수동으로 하지 않는다** — 승격은 누군가 직관에 따라 버튼을 클릭하는 것이 아니라 **코드와 정책**에 의해 이루어져야 함.
- 예시 기준 3가지:
  1. 후보 모델은 **절대 정확도 임계값 0.88 이상**을 충족해야 함.
  2. 현재 프로덕션 모델 대비 성능이 실질적으로 퇴보하지 않아야 함 — **상대적 델타(relative delta)가 -1%보다 나빠서는 안 됨**.
  3. **지연시간 요구사항**을 충족해야 함 — 예: **P95 지연시간이 2,000밀리초 미만**.
- 이는 모델 릴리스를 단순한 수동 판단이 아니라 객관적 게이트(objective gate)로 뒷받침되는 엔지니어링 결정으로 전환하는 좋은 예시.

### 올바른 레지스트리 선택하기
- 분기(quarterly)마다 모델을 릴리스하는 팀과 매일 변경을 배포하는 팀은 우선순위가 다름 — 후자는 신뢰성, 감사 추적(audit trail), 공식 승인 워크플로를 반복 속도보다 더 중요하게 여길 수 있음.
- 레지스트리 선택 시 고려할 질문들:
  - 모델을 얼마나 자주 릴리스하는가?
  - 얼마나 많은 거버넌스가 필요한가?
  - 릴리스를 승인하는 이해관계자가 몇 명인가?
  - 배포가 중앙화되어 있는가, 분산되어 있는가?
  - 내장된 계보(lineage) 추적이 얼마나 중요한가?
- 요점: 레지스트리 선택은 도구의 인기도가 아니라 **팀의 운영 모델(operating model)**을 따라야 함.

### 레지스트리 설계·사용의 4대 핵심 원칙
1. **추적 가능성(Traceability)**: 등록된 모든 모델은 그것을 만든 실행(run), 데이터 지표, 환경을 명확히 가리켜야 함.
2. **통제된 승격(Controlled Promotion)**: 스테이징·프로덕션 같은 모델 단계는 규칙과 승인을 통해 관리되어야 하며, 비공식적인 인계(informal handoff)로 관리되어서는 안 됨.
3. **메타데이터 완전성(Metadata Completeness)**: 레지스트리는 단순히 바이너리를 저장하는 곳이 아니라, 무엇이 배포되었는지 이해하는 데 필요한 맥락적 메타데이터를 담고 있어야 함.
4. **운영 가시성(Operational Visibility)**: 온콜(on-call) 담당자, 감사자, 배포 담당자, 사고 조사자가 여러 개의 연결되지 않은 시스템을 오가지 않고도 레지스트리에서 릴리스를 이해할 수 있어야 함.

## 예시
```text
[승격 기준 예시 — 코드/정책 기반]
1. 절대 정확도 ≥ 0.88
2. 프로덕션 대비 상대적 성능 델타 ≥ -1% (그 이상 나빠지면 안 됨)
3. P95 지연시간 < 2,000ms
→ 모두 충족해야만 자동으로 프로덕션 승격
```

| 레지스트리 | 적합한 경우 |
|---|---|
| MLflow | 개방적이고 널리 쓰이는 실험 추적·생애주기 관리 통합 필요 |
| Weights & Biases | 이미 W&B로 실험 중이며 거버넌스와의 긴밀한 통합 필요 |
| 커스텀 레지스트리 | 내부 승인 흐름, 컴플라이언스, 자체 배포 플랫폼과의 깊은 통합 필요 |

## 요약
- 모델 레지스트리는 모델 버전·계보·승인 상태·배포 준비 상태에 대한 시스템 오브 레코드로, MLflow·W&B·커스텀 시스템 중 선택은 도구의 인기도가 아니라 팀의 릴리스 빈도·거버넌스 요구·승인 구조 같은 운영 모델에 따라 결정되어야 하며, 프로덕션 승격은 정확도·상대적 성능·지연시간 같은 객관적 코드 기반 기준으로만 이루어져야 하고 추적 가능성·통제된 승격·메타데이터 완전성·운영 가시성이라는 4대 원칙을 갖춰야 한다.
