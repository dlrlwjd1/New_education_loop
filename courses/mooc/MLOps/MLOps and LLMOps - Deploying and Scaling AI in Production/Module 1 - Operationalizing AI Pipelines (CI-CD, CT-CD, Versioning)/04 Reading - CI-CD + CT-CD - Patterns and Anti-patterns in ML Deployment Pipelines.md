# "CI/CD + CT/CD: Patterns & Anti-patterns in ML Deployment Pipelines"

## 개요
- 앞선 3개 영상(ML/LLM CI/CD 아키텍처, 빌드-테스트-배포 자동화, 모델·데이터 검증)의 내용을 요약하며, **연속 학습(Continuous Training, CT)**이라는 세 번째 축과 **배포 전략(canary, blue-green, shadow mode)**, 그리고 피해야 할 **안티패턴(anti-pattern)**을 정리하는 리딩(30분). 각 단락에 외부 사이트로 연결되는 "Read more" 링크가 포함됨.

## 내용

### ML CI/CD가 전통적 소프트웨어 CI/CD와 근본적으로 다른 이유
- ML 시스템은 코드뿐 아니라 **데이터, 모델 성능, 파이프라인 재현성**까지 검증해야 함.
- 표준 DevOps 파이프라인은 소스 코드를 테스트하고 바이너리를 배포하지만, ML 파이프라인은 **연속 학습(Continuous Training, CT)**을 세 번째 차원으로 추가함 — 데이터가 드리프트되거나 성능이 임계값 아래로 떨어지면 모델을 자동으로 재학습.

### 계층화된 테스트 (빌드-테스트-배포 자동화)
- ML 파이프라인의 빌드-테스트-배포 사이클을 자동화하려면 여러 계층의 테스트가 필요:
  1. 피처 엔지니어링 코드를 위한 **유닛 테스트**.
  2. 스키마와 통계적 속성을 확인하는 **데이터 검증 테스트**.
  3. 홀드아웃(holdout) 세트에 대한 **모델 성능 테스트**.
  4. 엔드투엔드 추론을 검증하는 **스모크 테스트(smoke test)**.
- 각 테스트 계층은 품질 게이트 역할을 함 — 어느 게이트든 실패하면 파이프라인이 중단되고 팀에 알림이 가며, 저하된 모델이 배포되지 않음.
- **배포 전략**으로 추가적인 안전장치 제공:
  - **카나리 릴리스(Canary Release)**: 신규 모델을 일부 트래픽에만 점진적으로 노출.
  - **블루-그린 배포(Blue-Green Deployment)**: 두 개의 동일한 환경을 번갈아 전환.
  - **섀도 모드(Shadow Mode)**: 신규 모델이 실제 트래픽에 영향을 주지 않으면서 프로덕션 트래픽에 대해 예측만 수행해 검증.

### 데이터·모델 검증 통합과 안티패턴
- 모델·데이터 검증을 CI/CD에 통합하면 모든 파이프라인 실행이 신뢰할 수 있는 아티팩트를 생성하도록 보장함:
  - **데이터 검증**: 학습 시작 전 스키마 드리프트, 결측값, 분포 이동(distribution shift)을 확인.
  - **모델 검증**: 성능 지표가 평가 데이터셋에서 사전 정의된 임계값을 충족하는지 확인.
- **피해야 할 안티패턴**:
  1. 속도를 위해 데이터 테스트를 건너뛰는 것.
  2. 평가 게이트 없이 배포하는 것.
  3. 프로덕션 성능이 예기치 않게 저하될 때 **롤백 메커니즘이 없는 것**.

## 예시
```text
[배포 전략 3가지]
카나리 릴리스   — 신규 모델을 소수 트래픽에만 점진적으로 노출 → 문제 없으면 확대
블루-그린 배포  — 두 동일 환경(blue/green) 중 하나로 트래픽을 즉시 전환, 문제 시 즉시 복귀
섀도 모드      — 신규 모델이 실제 응답에 영향 없이 프로덕션 트래픽으로 "그림자" 예측만 수행
```

```text
[피해야 할 3대 안티패턴]
1. 속도를 위해 데이터 테스트 생략
2. 평가 게이트 없이 배포
3. 롤백 메커니즘 부재
```

## 요약
- ML CI/CD는 코드 검증에 더해 연속 학습(CT)이라는 세 번째 축을 가지며, 유닛·데이터·모델·스모크 테스트라는 계층화된 품질 게이트와 카나리/블루-그린/섀도 모드 같은 점진적 배포 전략으로 안전성을 확보해야 하고, 데이터 테스트 생략·평가 게이트 부재·롤백 메커니즘 부재라는 3대 안티패턴을 피해야 한다.
