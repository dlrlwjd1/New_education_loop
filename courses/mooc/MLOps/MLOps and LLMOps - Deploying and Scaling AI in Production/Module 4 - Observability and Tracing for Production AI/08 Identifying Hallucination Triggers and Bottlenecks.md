# Identifying Hallucination Triggers and Bottlenecks

## 개요
- 환각을 유발하는 조건과 그 배후의 실제 병목(bottleneck)을 식별하는 방법 — 3가지 흔한 트리거 패턴과 Phoenix를 이용한 구조화된 실패 분석 사례(47개 실패 질의 중 37개가 낮은 검색 점수)를 다루는 5분 영상. "Tracing and Debugging with Arize Phoenix" 레슨의 마지막 영상.

## 내용

### 환각은 거의 무작위가 아니다
- 프로덕션 시스템에서 환각은 대체로 **반복되는 패턴** 때문에 발생함 — 약한 검색, 긴 질의, 그라운딩 체크 누락, 범위를 벗어난(out-of-scope) 요청 등.
- 이 레슨의 목표는 단순히 나쁜 답변을 알아차리는 것이 아니라, **왜 그 나쁜 답변이 계속 발생하는지** 이해하는 것.

### 흔한 환각 트리거 패턴 3가지
1. **낮은 검색 품질**: 시스템이 약하거나 관련 없는 문서를 검색하면, 모델은 부실한 컨텍스트로 답할 가능성이 높음.
2. **매우 긴 질의 또는 매우 큰 컨텍스트**: 잘라내기(truncation)를 유발할 수 있음 — 중요한 근거가 모델이 응답을 생성하기 전에 누락될 수 있음.
3. **범위를 벗어난 질문(Out-of-scope Questions)**: 질의가 도메인 밖에 있으면, 시스템이 거부하거나 리다이렉트하도록 설계되었어도 모델이 여전히 답하려고 시도할 수 있음.
- 핵심 교훈: 환각은 대체로 예측 가능한 시스템 약점에서 비롯됨 — 그 약점을 식별하면 더 체계적으로 고칠 수 있음.

### Phoenix로 최상위 근본 원인 찾기 (구조화된 실패 분석)
- 팀이 LLM 판정자의 코드에서 정확성이 3 미만인 사례를 필터링해 검사할 실패 질의 세트를 만듦.
- 실패들을 패턴으로 그룹화한 결과:
  - **47개 중 37개**의 질의가 **검색 점수 0.6 미만**.
  - **47개 중 10개**가 **매우 긴 질의**로 컨텍스트 잘라내기 유발.
  - **나머지 47개 중 6개**가 **범위를 벗어난 질의**.
- 각 패턴은 특정 수정으로 이어짐:
  - 낮은 검색 점수 → 임계값 상향.
  - 긴 질의 → 재순위(re-ranker) 추가.
  - 범위 이탈 → 주제 분류기(topic classifier) 가드 추가.
- 강력한 교훈: 모든 실패를 하나씩 고치려 하는 대신, 팀은 **소수의 반복되는 근본 원인**을 고쳐 대부분의 실패를 제거할 수 있음.

### 이런 실패를 식별하는 핵심 원칙 4가지
1. 검색 점수가 0.6 미만이고 질의의 상당 비율에 해당하면, 이는 **체계적인 환각 리스크**임.
2. 응답이 길고 자신감 있어 보이지만 인용이나 그라운딩 근거를 포함하지 않으면, 모델이 사실을 지어내고 있을 수 있음.
3. **높은 지연시간과 낮은 품질이 함께 나타나면**, 검색이 두 문제 모두를 일으키는 병목일 수 있음.
4. **Phoenix 필터링**은 팀이 유사한 실패의 클러스터를 식별하는 데 도움 — 고립된 답변에 반응적으로 대응하는 대신 최상위 패턴을 고치기 쉽게 만듦.
- 핵심 요점: 환각은 신비로운 모델 행동이 아니라 증거 기반 패턴으로 취급될 때 훨씬 고치기 쉬워짐.

### 근본 원인 로깅 예시
- 실패는 구조화된 로그 항목으로 포착될 수 있음 — 원본 질의, 검색된 문서 수, 답변 모드, 판정 점수(judge score), 실패 태그(failure tag)를 저장.
- 핵심 아이디어: 좋은 디버깅은 좋은 증거에 달려 있음 — 실패가 제대로 라벨링되면, 팀은 이를 세고, 그룹화하고, 시스템의 올바른 부분을 개선할 수 있음.

### 실전 교훈
- 실패를 컨텍스트 누락, 오래된 컨텍스트, 프롬프트 혼란 등으로 **분리**할 것.
- 반복되는 실패 유형을 클러스터링하는 데 도움이 되므로 점수(score)를 함께 로깅할 것.
- 결과: 완화(mitigation)가 추측이 아니라 실제 병목에 집중하게 됨.
- 핵심 요점: 각 실패가 검색·프롬프트·점수 증거로 태깅될 때 환각은 고칠 수 있는 문제가 됨.

## 예시
```text
[Phoenix 구조화된 실패 분석 사례 — 47개 실패 질의]
검색 점수 < 0.6         : 37/47 (79%) → 임계값 상향으로 해결
매우 긴 질의(컨텍스트 잘림) : 10/47 (21%) → 재순위(re-ranker) 추가로 해결
범위를 벗어난 질의       : 6/47 (13%) → 주제 분류기 가드 추가로 해결
```

## 요약
- 환각은 대체로 낮은 검색 품질, 매우 긴 질의로 인한 컨텍스트 잘라내기, 범위를 벗어난 질문이라는 예측 가능한 3가지 패턴에서 비롯되며, Phoenix로 정확성이 낮은 실패 질의들을 필터링해 그룹화하면(사례에서 47개 중 37개가 낮은 검색 점수) 각 패턴에 맞는 구체적 수정(임계값 상향, 재순위 추가, 주제 분류기 가드)을 적용해 모든 실패를 개별적으로 고치는 대신 소수의 반복되는 근본 원인을 고쳐 대부분의 실패를 제거할 수 있고, 이는 실패를 검색·프롬프트·점수 증거로 구조화해 로깅함으로써 가능해진다.
