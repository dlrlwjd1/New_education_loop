# Drift Dashboards & Alerting

## 개요
- 드리프트를 대시보드와 알림으로 모니터링하는 방법 — 입력·출력·품질 신호를 함께 보여주는 좋은 드리프트 대시보드의 구성 요소, 임계값 설계, 주간 리포트+Slack 알림 자동화를 다루는 3분 영상. "Monitoring Drift & System Health" 레슨의 두 번째 영상.

## 내용

### 왜 가시성과 대응이 모두 필요한가
- 드리프트를 탐지하는 것도 중요하지만, 팀은 무엇이 변하고 있는지 명확히 보고 빠르게 대응할 방법도 있어야 함.
- **대시보드**는 트렌드를 추적하는 데 도움이 되고, **알림**은 적절한 시점에 조치를 취하는 데 도움이 됨.

### 좋은 드리프트 대시보드의 구성 요소
- **입력 신호, 출력 신호, 품질 신호를 함께 추적**해야 함 — 예: 대시보드가 PSI, 응답 길이, 거부율(refusal rate), 평가 점수를 보여줄 수 있음.
- 동시에 알림은 **의미 있는 임계값**으로 설정되어야 함:
  - 임계값이 너무 민감하면 팀이 알림을 무시하게 됨.
  - 너무 느슨하면 팀이 너무 늦게 반응할 수 있음.
- 목표: 명확하면서도 유용한 대시보드와 알림을 설계하는 것.

### 모니터링을 자동화하는 방법
- **주간 드리프트 리포트**가 중요한 지표와 트렌드를 요약해 팀이 정기적으로 시스템 건강 상태를 검토할 수 있게 함.
- 임계값이 넘어가면 **Slack 알림**이 즉시 팀에 통보 — 지속적인 수동 확인의 필요성을 줄이고, 중요한 이슈가 적절한 사람에게 빠르게 보이도록 보장.

### 대시보드·알림의 핵심 원칙
1. 대시보드는 읽기 쉽고 유용한 신호에 집중해야 함.
2. 알림은 실행 가능(actionable)해야 하고 명확한 소유권(ownership)에 연결되어야 함.
3. 모니터링은 문제만 보여주는 것이 아니라 **의사결정을 지원**해야 함.
- 요약: 좋은 대시보드는 가시성을 돕고, 좋은 알림은 대응을 돕는다.

### 코드 예시
- 코드가 드리프트 지표를 수집하고, 임계값을 넘었는지 확인하고, 요약을 생성한 뒤 필요시 Slack 알림을 전송.
- 핵심 요점: 대시보드는 리포팅·알림 워크플로와 직접 연결될 때 훨씬 더 가치 있어짐 — 모니터링 전략을 실제 구현 예시에 연결.

## 예시
```python
# drift_monitor.py (개념 구조)
def run_weekly_drift_check():
    metrics = collect_drift_metrics()  # PSI, 응답 길이, 거부율, 평가 점수

    summary = summarize(metrics)
    save_weekly_report(summary)

    for metric_name, value in metrics.items():
        if value > THRESHOLDS[metric_name]:
            send_slack_alert(metric_name, value)
```

```text
[좋은 드리프트 대시보드의 3대 신호]
입력 신호  — PSI
출력 신호  — 응답 길이, 거부율
품질 신호  — 평가 점수

+ 주간 리포트(정기 검토) + 임계값 기반 Slack 알림(즉시 대응)
```

## 요약
- 효과적인 드리프트 모니터링은 PSI 같은 입력 신호, 응답 길이·거부율 같은 출력 신호, 평가 점수 같은 품질 신호를 하나의 대시보드에 함께 보여주고, 너무 민감하지도 느슨하지도 않은 의미 있는 임계값을 설정해, 주간 리포트로 정기적인 검토를, Slack 알림으로 즉각적인 대응을 자동화함으로써 대시보드가 단순한 문제 표시를 넘어 명확한 소유권을 가진 실행 가능한 의사결정 지원 도구가 되도록 하는 것이 핵심이다.
