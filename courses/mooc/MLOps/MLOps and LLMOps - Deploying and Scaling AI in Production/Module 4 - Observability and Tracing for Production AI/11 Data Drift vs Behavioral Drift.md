# Data Drift vs Behavioral Drift

## 개요
- AI 시스템에서 **데이터 드리프트(Data Drift)**와 **행동 드리프트(Behavioral Drift)**의 차이, 3가지 드리프트 유형, 그리고 어떤 신호 조합이 재학습·프롬프트 수정·조사 중 무엇을 트리거해야 하는지 결정하는 의사결정 매트릭스를 다루는 4분 영상. "Monitoring Drift & System Health" 레슨의 첫 번째 영상.

## 내용

### 데이터 드리프트 vs 행동 드리프트
- 두 용어는 관련되어 있지만 같지 않음:
  - **데이터 드리프트**: 입력이 시간이 지나며 변할 때 발생.
  - **행동 드리프트**: 입력이 비슷해 보여도 모델의 출력이 행동적으로 변할 때 발생.
- 이 차이를 이해하는 것이 중요한 이유: **해결책이 드리프트의 유형에 따라 달라지기 때문** — 모든 변화가 동일하게 취급되어서는 안 됨.

### 3가지 드리프트 유형과 탐지 방법
1. **입력 드리프트(Input Drift)**: 사용자 질의나 피처 값이 변하고 있음을 의미 — **PSI(Population Stability Index)**나 **임베딩 거리(embedding distance)** 같은 도구로 측정 가능.
2. **행동 드리프트(Behavioral Drift)**: 모델의 출력이 시간, 구조, 또는 어조(tone) 면에서 변하고 있음을 의미.
3. **품질 드리프트(Quality Drift)**: 시스템이 실제로 더 나쁘게 성능을 내고 있는지 알려줌.
- 이 신호들은 은밀하게(secretly, 지속적으로) 모니터링되어야 팀이 무슨 일이 일어나고 있는지 명확히 이해할 수 있음.
- 드리프트는 입력, 출력, 전체 품질이라는 서로 다른 수준에서 발생할 수 있음.

### 신호 조합에 따른 의사결정 매트릭스
- **입력 드리프트 + 품질 하락이 함께 나타나면**: 대체로 모델 **재학습**이 필요함을 의미.
- **출력 행동만 변하면**: 문제가 **프롬프트나 파이프라인**에 있을 수 있음.
- **입력과 출력 드리프트가 함께 발생하면**: 행동을 취하기 전에 먼저 **근본 원인을 조사**해야 함.
- 이 의사결정 매트릭스는 팀이 매번 모든 것을 시도하는 대신 올바른 대응을 선택하는 데 도움 — 서로 다른 드리프트 탐지를 재학습, 프롬프트 업데이트, 조사 같은 실전 대응에 연결.

### 드리프트 탐지 파이프라인 예시
- 하나의 작업(job)이 PSI와 임베딩을 사용해 최근 데이터를 베이스라인과 비교해 **입력 드리프트**를 확인.
- 다른 작업이 길이나 구조 같은 응답 행동을 모니터링해 **출력 드리프트**를 확인.
- 이 체크들을 분리해서 유지하는 것이 유용한 이유: 문제가 변화하는 사용자 행동에서 오는지, 변화하는 모델 행동에서 오는지 알려주기 때문 — 이는 트러블슈팅을 더 빠르고 정확하게 만듦.

### 핵심 요약
1. 입력 드리프트와 행동 드리프트는 서로 다르며 섞여서는 안 됨.
2. 드리프트를 아는 것만으로는 충분하지 않음 — **품질 영향을 측정**해야 함.
3. 모든 드리프트 신호는 명확한 다음 조치(next action)에 연결되어야 함.
- 요점: 좋은 드리프트 모니터링은 팀이 올바른 결정을 빠르게 내리도록 도움.

### 코드 예시
- 코드가 입력 드리프트와 행동 드리프트를 각각 별도로 확인한 뒤, 알림을 울릴지 검토를 트리거할지 결정 — 시간에 따른 이슈 진행을 계속 추적.
- 목적은 문법이 아니라, 모니터링 규칙이 어떻게 실전으로 전환되는지 보여주는 것.

## 예시
```text
[드리프트 신호 조합별 대응]
입력 드리프트 + 품질 하락      → 모델 재학습 필요
출력 행동만 변화               → 프롬프트/파이프라인 문제 조사
입력 드리프트 + 출력 드리프트 동시 발생 → 조치 전 근본 원인 조사
```

```python
# 드리프트 탐지 로직 (개념 구조)
def check_drift(recent_data, baseline_data, recent_outputs, baseline_outputs):
    input_drift = compute_psi(recent_data, baseline_data) > PSI_THRESHOLD
    behavioral_drift = compare_output_structure(recent_outputs, baseline_outputs) > BEHAVIOR_THRESHOLD

    if input_drift and quality_dropped():
        return "RETRAIN"
    if behavioral_drift and not input_drift:
        return "REVIEW_PROMPT_OR_PIPELINE"
    if input_drift and behavioral_drift:
        return "INVESTIGATE_ROOT_CAUSE"
    return "OK"
```

| 드리프트 유형 | 탐지 방법 |
|---|---|
| 입력 드리프트 | PSI, 임베딩 거리 |
| 행동 드리프트 | 응답 길이·구조·어조 모니터링 |
| 품질 드리프트 | 실제 성능 저하 측정 |

## 요약
- 데이터 드리프트(입력 변화)와 행동 드리프트(출력 변화)는 서로 다른 개념이며, PSI·임베딩 거리로 입력 드리프트를, 응답 구조·어조로 행동 드리프트를 탐지한 뒤 품질 저하 여부와 결합해 재학습·프롬프트 검토·근본 원인 조사 중 올바른 대응을 선택하는 의사결정 매트릭스를 적용하는 것이 효과적인 드리프트 모니터링의 핵심이다.
