# Troubleshooting Container Deployment

## 개요
- 배포에서 흔히 마주치는 **두 가지 실패 유형**(잘못된 포트, 코드 문법 오류)을 일부러 재현하고 로그로 원인을 진단하는 4분 실습.

## 내용

### 문제 1 — 잘못된 포트 설정
- 일부러 애플리케이션이 다른 포트(예: 8000이 아닌 다른 값)를 쓰도록 바꾼 뒤 커밋 → 자동화(빌드→ACR 푸시→Azure 배포)가 정상적으로 완료됨.
- 하지만 애플리케이션 URL에 접속하면 **계속 로딩만 되고 아무 반응이 없음**.
- **Deployment Center → 로그**에서 확인: **"waiting for response to warm up for a container"**가 61초 넘게 지속 — 로그에 **"Docker run Port 80"**이라는 단서가 있음(실제로는 8000을 기대하는데 80으로 시도).
- **핵심 문제**: Azure는 포트가 틀렸다고 명시적으로 알려주지 않고, 그냥 계속 대기하다가 결국 **타임아웃**된다는 것 — "이런 상황을 막으려면 더 작은 타임아웃 임계값을 두거나, 이런 변경을 미리 잡아내는 테스트가 있어야 한다"고 조언.

### 문제 2 — 코드 문법 오류(Syntax Error)
- 이전에 일부러 넣었던 문법 오류가 있는 상태에서 배포하면, 컨테이너가 시작 시 깨져서 **역시 응답이 없는 상태**로 남음.
- 로그를 **처음부터 끝까지 스크롤**해야 문법 오류 자체가 로그 어딘가에 찍혀 있는 것을 발견할 수 있음 — "찾기 꽤 어렵지만 로그를 끝까지 훑으면 보인다."
- 로그 맨 아래는 여전히 **포트 80에서 응답을 기다리는 중**이라는 메시지로 남아 있음.

### 핵심 교훈
- 배포가 "성공"(빌드/푸시/업데이트 자체는 성공)했더라도, 실제 애플리케이션이 정상 기동하지 못하면 **끝없는 대기 → 타임아웃**이라는 형태로만 실패가 드러남 — 명확한 에러 메시지가 바로 뜨지 않는다는 점이 까다로움.
- 이런 문제를 예방하려면: **① 포트 설정을 배포 전에 한 번 더 확인, ② 코드 문법 오류를 잡아낼 테스트/린트를 CI에 포함, ③ 로그를 끝까지 살펴보는 습관**이 필요.

## 요약
- Azure Container App 배포 실패의 대표적인 두 원인은 **잘못된 포트 매핑**과 **컨테이너 시작을 막는 코드 오류(문법 오류 등)**이며, 두 경우 모두 명확한 에러 메시지 대신 **"응답 대기 → 타임아웃"**이라는 형태로만 나타나므로 로그를 끝까지 확인하는 습관이 중요하다.
