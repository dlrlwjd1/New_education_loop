# Deploy App for Insurance Agents to Upload all Insurance Claims

## 개요
- 보험 청구 자동화라는 실제 비즈니스 사례로, 지금까지 배운 모든 도구(모델 개발, MLflow)를 하나로 통합해 엔드투엔드 ML 파이프라인을 구축하는 캡스톤 모듈의 도입 영상(7분).

## 내용

### 기존 프로세스(사람 중심)
- 사용자가 웹/모바일 앱으로 보험 청구를 제출 → 대량의 청구 건이 쌓임 → **보험 청구 담당자(claim agents)**가 검토해 두 부류로 분류:
  1. **승인(Approved)**: 문제 없음 → 자동으로 사용자에게 지급.
  2. **재검토 필요(Needs Review)**: 데이터에 이상(anomaly)이 있어 **청구 재조사 부서(claim reinvestigation department)**가 문제를 파악하고 필요 시 추가 서류를 요청 → 서류 제공 후 승인.

### ML 모델 도입 후 프로세스
- 동일한 흐름이지만, 사람이 수작업으로 검토하는 대신 **ML 모델**이 청구를 분류: 승인 vs 재검토 필요.
- 재검토가 필요한 건만 재조사 부서로 전달 → 추가 서류 요청 → 승인.
- ML 모델은 조직에 비용, 성능 등 다양한 영향을 미치며, 이런 문제 정의(problem statement)는 조직이 어디서 이득을 얻을 수 있는지 파악하기 위해 모든 조직에서 식별되어야 함.

### 이번 데모의 범위
- 전체 시스템의 일부를 구축 — 그 달/주의 모든 청구를 업로드할 수 있는 **웹 포털**을 만들고, ML 모델이 모든 청구 세부사항을 분석해 **재검토가 필요한 것만 플래그** 처리.
- 이렇게 하면 모든 청구를 일일이 검토할 필요 없이, 청구 묶음을 웹 포털에 업로드하기만 하면 재검토가 필요한 청구 결과를 얻을 수 있음.

### ML 모델 도입의 이점
1. **빠른 처리(Faster Processing)**: 수작업 검증은 며칠~몇 주가 걸리지만, ML 모델은 수천 건의 청구를 몇 초 만에 스캔해 이상 징후를 즉시 플래그.
2. **정확도 향상(Improved Accuracy)**: 사람은 대규모 데이터셋의 패턴·이상을 놓칠 수 있지만, ML 모델은 방대한 데이터를 분석해 정교하게 사기성 청구를 탐지 — 오류를 줄이고 잠재적 손실로부터 회사를 보호.
3. **효율성 증대(Increased Efficiency)**: 자동화로 사람 조정자(adjuster)가 반복적인 작업에서 벗어나 더 복잡하거나 가치 높은 청구에 집중 가능 — 인간과 기계의 시너지.
4. **비용 절감(Reduced Cost)**: 자동화와 정확도 향상으로 오류 감소, 처리 속도 향상, 사기성 지급 감소 → 절감된 비용을 서비스 개선이나 보험료 인하로 재투자 가능.
5. **고객 경험 향상(Enhanced Customer Experience)**: 빠른 처리와 신속한 지급으로 더 만족한 고객 → 신뢰와 호의 구축.
6. **리스크 평가(Risk Assessment)**: ML 모델은 과거 데이터를 분석해 향후 청구의 발생 가능성과 심각도를 정확히 예측 — 보험사가 정보에 기반한 언더라이팅(underwriting)과 가격 책정 결정을 내리는 데 도움.

### 다음 단계 예고
- 이제 이 이점들을 이해했으니, 데모 섹션에서는 지금까지 배운 모든 도구·서비스를 활용해 청구 담당자가 사용할 수 있는 ML 기반 서비스를 실제로 구축할 예정.

## 요약
- 보험 청구 자동화는 사람이 모든 청구를 수작업 검토하던 프로세스를 ML 모델이 승인/재검토 필요로 자동 분류하는 프로세스로 전환하는 것이며, 이는 처리 속도·정확도·효율성·비용·고객 경험·리스크 평가 6가지 측면에서 조직에 이득을 준다.
