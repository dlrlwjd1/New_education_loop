# Introduction to MLflow

## 개요
- 주택 가격 예측 사례로 MLflow의 4가지 핵심 구성 요소(Tracking, Projects, Models, Model Registry)를 소개하는 4분 영상.

## 내용

### 모델 개발 생애주기 복습
- 데이터 과학자가 사용 사례에 적합한 모델을 선택 → **실험(experiment) 실행** — 유사하거나 동일한 데이터에 서로 다른 모델을 적용해 결과를 비교하는 리포트 작성.
- 모든 사용 사례에 하나의 모델이 통하는 것은 아님 — 사용 사례마다 다른 모델이 필요할 수 있음.
- 분석이 끝나면 ML 제품/모델을 프로덕션에 배포 — 이 단계가 바로 **배포(deployment)** 단계.
- 이 전 과정에서 데이터를 시각화하고 어떤 모델이 가장 적합한지 이해하는 것이 중요한 **반복적(iterative) 과정** — 여기서 MLflow가 도움을 줌.

### MLflow란
- 실험 추적부터 모델 배포까지 머신러닝 프로젝트의 전체 생애주기를 관리하도록 설계된 **오픈소스 플랫폼**.
- 모듈형 프레임워크로 유연성과 확장성을 보장해 데이터 과학자·ML 엔지니어의 대표적인 도구로 자리잡음.

### 4가지 핵심 구성 요소(주택 가격 예측 사례로 설명)

1. **Tracking(추적)**: 실험의 모든 측면 — 코드, 데이터셋, 설정, 결과 — 를 기록. 예: 학습률(learning rate), 배치 크기(batch size) 같은 하이퍼파라미터와 정확도 같은 결과를 로깅해, 가장 성능이 좋은 모델을 효과적으로 비교·식별.
2. **Projects(프로젝트)**: 패키징 형식으로 ML 코드를 표준화. 예: 모델 학습 파이프라인과 의존성을 ML 프로젝트 파일에 정의 — 동료가 최소한의 설정만으로 동일한 코드를 자신의 머신에서 실행 가능하도록 **재현성**을 보장.
3. **Models(모델)**: ML 모델의 배포를 표준화 — 모델을 저장·서빙하는 통합된 방식 제공. 예: 최종 모델을 MLflow 형식으로 저장한 뒤 Flask, FastAPI, 또는 다음 섹션에서 다룰 **BentoML** 등 어떤 플랫폼에도 배포 가능.
4. **Model Registry(모델 레지스트리)**: 모델의 "관제 센터" 역할 — 주택 가격 예측 모델의 여러 버전을 관리하고, 프로덕션용으로 표시하거나 구버전으로 보관 가능. 이는 팀 간 협업을 향상시킴. **Docker 레지스트리**와 유사하게 생각하면 됨 — 다양한 이미지를 저장하고 모든 변경 이력을 보관하는 것처럼.

### 핵심 통찰
- 이 4가지 구성 요소만으로 모델 개발·추적과 관련된 대부분의 문제를 해결할 수 있음.
- 다음 영상에서는 MLflow를 실제로 설정하고, 실험을 실행하고, 결과를 저장하며 이 모든 과정이 실제로 어떻게 효과적인지 확인할 예정.

## 요약
- MLflow는 Tracking(실험 기록) → Projects(코드 재현성) → Models(배포 표준화) → Model Registry(버전 관리)라는 4가지 구성 요소를 통해 모델 개발부터 배포까지의 전체 생애주기를 관리하는 오픈소스 플랫폼이다.
