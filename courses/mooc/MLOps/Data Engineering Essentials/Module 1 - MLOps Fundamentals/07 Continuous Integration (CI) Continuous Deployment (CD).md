# Continuous Integration (CI), Continuous Deployment (CD)

## 개요
- MLOps에서 CI(지속적 통합)와 CD(지속적 배포)가 실제로 무엇을 의미하는지, 핵심 관행과 실제 사례를 통해 설명하는 4분 영상.

## 내용

### 지속적 통합(Continuous Integration, CI)
- 코드, 데이터, ML 모델이 공유 저장소로 매끄럽게 통합되도록 보장하는 것.
- **자동화된 코드 병합**: 코드 변경과 ML 모델을 공유 저장소에 병합하는 과정을 자동화해 일관성을 유지하고 사람의 실수를 줄임. 예: 사기 탐지 모델을 여러 개발자가 동시에 업데이트할 때, CI가 병합 과정을 자동화해 모든 것이 깔끔하게 통합되도록 함.
- **버전 관리**: 변경 사항을 효과적으로 관리하는 데 핵심적 — Git, DVC, MLflow 같은 도구로 코드·데이터·모델의 변경을 추적해 협업과 실험 재현을 쉽게 만듦.
- **자동화된 테스트**: 단위 테스트(unit test), 통합 테스트(integration test), 검증 테스트(validation test)로 다양한 환경에서 ML 파이프라인이 예상대로 동작하는지 보장.
- **빌드 재현성(Build Reproducibility)**: 개발·배포 환경 간 불일치를 피하기 위해 빌드가 여러 환경에서 일관되어야 함.
- **팀워크 개선**: CI는 데이터 과학자, 엔지니어, 이해관계자 간 협업을 촉진해 전체 생산성과 효율성을 높임.

### 지속적 배포(Continuous Deployment, CD)
- 모델을 프로덕션 환경에 효율적이고 안전하게 배포하는 것.
- **자동화된 모델 배포**: 예: 이커머스 웹사이트의 추천 시스템 — 새 데이터로 모델이 업데이트되면 CD가 실시간 추천 서비스에 매끄럽게 배포되도록 보장.
- **Infrastructure as Code**: Terraform, Kubernetes 같은 도구로 배포 인프라를 코드로 정의·관리해 확장성과 재현성 확보.
- **블루-그린 배포(Blue-Green Deployment)/카나리 배포(Canary Deployment)**: 점진적으로 릴리스를 진행해 최소한의 다운타임으로 안전한 릴리스를 보장.
- **롤백 메커니즘**: 문제가 생겼을 때 빠르게 이전 버전으로 복원할 수 있는 전략 — ML 모델의 신뢰성을 보장.
- **CI 파이프라인과의 통합**: CD는 CI 파이프라인과 매끄럽게 통합되어, 통합 단계에서 배포 단계로의 원활한 전환을 보장.

### 다음 주제 예고
- 다음으로 MLOps의 **지속적 학습(Continuous Training, CT)** 설정을 다룰 예정 — 새 데이터가 도착함에 따라 모델을 정기적으로 재학습시켜 성능을 유지하는 것.

## 요약
- CI는 코드·데이터·모델의 자동화된 병합, 버전 관리, 테스트, 빌드 재현성을 통해 안정적인 통합을 보장하고, CD는 자동화된 배포, Infrastructure as Code, 블루-그린/카나리 배포, 롤백 메커니즘을 통해 안전하고 효율적인 프로덕션 배포를 보장한다.
