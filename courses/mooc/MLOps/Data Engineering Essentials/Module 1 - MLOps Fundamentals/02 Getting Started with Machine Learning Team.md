# Getting Started with Machine Learning Team

## 개요
- 머신러닝 팀(ML team)을 구성하는 4개 하위 팀 — 제품(Product), 데이터 과학(Data Science), 데이터 엔지니어링(Data Engineering), DevOps/MLOps 엔지니어링 — 의 역할과 협업 흐름을 설명하는 5분 영상.

## 내용

### 1. 제품 관리 팀(Product Management Team)
- 목표: 조직에 매출을 창출할 수 있는 **머신러닝에 적합한 사용 사례**를 식별.
- 예: 웹사이트의 수많은 제품을 어떤 순서로 노출할지 — 어떤 제품을 먼저/나중에 보여줄지 결정하는 데 머신러닝을 활용할 수 있는지 파악하는 것이 제품팀/제품 엔지니어의 역할.
- 비즈니스 사용 사례를 식별한 뒤, **목표(goal)**를 설정 — 예: "이 순위 매기기가 500만 달러의 총 매출을 창출할 것"과 같은 구체적 목표.
- 마지막으로 **마일스톤과 측정 기준(measuring criteria)**을 확립 — ML 모델 개발·배포가 올바른 방향으로 가고 있는지, 혹은 이 아이디어가 ML에 적합하지 않아 중단해야 하는지 판단하는 데 필수적.

### 2. 데이터 과학 팀(Data Science Team)
- 목표: 제품팀이 정의한 비즈니스 사용 사례를 먼저 이해.
- 그다음 **가용 데이터를 탐색** — 이 비즈니스 문제를 해결할 ML 모델을 만들 데이터가 있는지 확인. 없다면 확보 방법을 찾아야 함.
- 이후 이 비즈니스 문제를 해결하는 데 어떤 ML 모델이 도움이 될지 파악.

### 3. 데이터 엔지니어링/분석 팀(Data Engineering / Data Analyst Team)
- 목표: 데이터 과학자가 ML 모델을 구축하는 데 필요한 모든 데이터를 수집.
- **영구적인 ETL 파이프라인**을 구축·유지해 데이터 레이크하우스(data lakehouse)로 안정적인 데이터 흐름을 확보 — ML 모델 학습에 사용.
- 또한 **실시간 학습(real-time training)** 설정을 가능하게 함 — 예: ML 모델이 프로덕션에 배포된 후 제품팀이 설정한 측정 기준을 실제로 달성하고 있는지 실시간 데이터로 분석하는 인프라·분석 플랫폼 구축을 지원.

### 4. DevOps/MLOps 엔지니어링 팀
- 남은 질문들: ML 모델을 어디에 배포할 것인가? 다른 API 서비스가 이 모델을 어떻게 호출·트리거하고 응답을 받을 것인가? 새 버전의 ML 모델을 어떻게 배포하고 지속적 CI/CD 프로세스를 어떻게 구축할 것인가? 모델 서빙, 모델 레지스트리, 인프라, 모니터링은?
- 이를 돕는 것이 **DevOps 엔지니어링 팀**의 역할이지만, DevOps 엔지니어와는 다른 몇 가지 정보·기술 스택이 필요.
- 이를 숙달하면(ML 모델 배포, 이를 구축·유지하는 인프라 설정 등) **MLOps 엔지니어**로 전환됨.
- **MLOps 엔지니어**는 사실 DevOps 엔지니어링의 기본 기술 스택 경험을 가진 **숙련된 DevOps 엔지니어**임.

### 핵심 통찰
- 제품팀, 데이터 과학팀, 데이터 엔지니어링팀에 DevOps/MLOps 엔지니어링팀이 더해져야 완전한 머신러닝 팀이 완성됨.

## 요약
- 완전한 ML 팀은 제품팀(사용 사례·목표·마일스톤 정의) → 데이터 과학팀(데이터 탐색·모델 선정) → 데이터 엔지니어링팀(ETL 파이프라인·실시간 학습 인프라) → MLOps 엔지니어링팀(배포·CI/CD·모델 서빙·모니터링)의 4단계 협업으로 구성되며, MLOps 엔지니어는 DevOps 기술 스택을 갖춘 숙련된 DevOps 엔지니어라는 것이 핵심이다.
