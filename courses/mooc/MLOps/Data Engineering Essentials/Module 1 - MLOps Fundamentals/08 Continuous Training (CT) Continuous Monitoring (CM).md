# Continuous Training (CT), Continuous Monitoring (CM)

## 개요
- MLOps의 나머지 두 축인 CT(지속적 학습)와 CM(지속적 모니터링)의 핵심 관행을 설명하는 3분 영상. (앞선 영상의 CI/CD에 이어지는 내용)

## 내용

### 지속적 학습(Continuous Training, CT)
- **자동화된 재학습 파이프라인**: 데이터 업데이트나 성능 지표에 기반해 모델 재학습을 스케줄링·트리거. 예: 날씨 예측 모델이 새 데이터가 들어올 때마다 지속적으로 스스로 업데이트.
- **데이터 버전 관리**: DVC, Delta Lake 같은 도구로 데이터셋을 효율적으로 추적·관리.
- **하이퍼파라미터 튜닝과 실험**: 모델의 최적 효율을 얻기 위해 매우 중요한 방법론 — 추후 영상에서 더 자세히 다룰 예정.
- **확장 가능한 학습 인프라**: 클라우드 서비스나 분산 컴퓨팅을 활용해 대규모 학습을 효율적으로 처리.
- **배포 전 검증·테스트**: 배포되기 전 모델이 성능·품질 기준을 충족하는지 검증.

### 지속적 모니터링(Continuous Monitoring, CM)
- 배포된 모델이 프로덕션 환경에서 예상대로 동작하는지 확인하는 것.
- **실시간 모니터링 설정**: Prometheus, Grafana 같은 도구로 지표를 실시간 추적. 예: 사기 탐지 시스템이 정확도·지연시간(latency) 같은 성능 지표를 모니터링 — Prometheus에 저장하고 Grafana로 시각화. (DevOps 엔지니어에게 이미 익숙한 도구들.)
- **데이터·모델 드리프트 탐지**: 데이터 분포나 모델 예측의 변화를 식별해 장기적 문제를 파악. 모델 드리프트를 식별하고 알림을 주는 기법에 능숙해야 함.
- **알림과 통지(Alerting and Notification)**: 이상 징후, 성능 저하, 장애에 대한 알림 설정.
- **포괄적인 로그 유지**: 컴플라이언스와 트러블슈팅 목적의 로그 관리 — 모델 서빙과 개발 워크플로 전반에서 모든 데이터 과학자에게 필수.
- **피드백 루프**: 모델 개선을 위한 피드백 루프 구축.

### 핵심 통찰
- 각 섹션(CI, CD, CT, CM)은 저마다 고유하고 중요한 역할을 하며, 이를 데이터 과학자가 ML 모델을 분석·학습·구축할 수 있도록 세팅하는 데 필요한 도구들을 숙달해야 함.
- DevOps에서는 이런 기능들을 애플리케이션이나 마이크로서비스를 위해 생각하지만, **MLOps 엔지니어**로서는 이 모든 도구·기술·명명 규칙을 **ML 모델 자체**에 어떻게 적용할지에 초점을 맞춰야 함 — 이것이 바로 MLOps의 본질.

## 요약
- CT는 자동화된 재학습·데이터 버전 관리·하이퍼파라미터 튜닝·확장 가능한 학습 인프라로 모델을 최신 상태로 유지하고, CM은 실시간 모니터링·드리프트 탐지·알림·로깅·피드백 루프로 프로덕션 모델의 신뢰성을 보장하며, 이 모든 DevOps 기법을 ML 모델 자체에 적용하는 것이 MLOps의 핵심이다.
