# Benefits of using a Feature Store

## 개요
- 항공권 예약 서비스를 사례로, 피처 스토어가 제공하는 4가지 핵심 이점(저지연 서빙, 일관성, 고급 전처리, 확장성)을 설명하는 5분 영상(직전 영상에 이어짐).

## 내용

### 1. 저지연 서빙(Low Latency Serving)
- 데이터 웨어하우스에서 복잡한 데이터셋을 쿼리하는 것은 느릴 수 있음 — 예: 인기 항공 노선의 동적 가격을 가져오는 데 몇 초가 걸려 검색 결과가 느려짐.
- 피처 스토어에서는 최저 항공료, 좌석 가용성 같은 피처가 **밀리초 단위**로 서빙됨 — 빠른 응답 시간으로 즉각적인 검색 결과 제공.
- 높은 지연시간은 사용자 경험에 악영향 — 응답이 느리면 고객이 세션을 이탈할 수 있음. 피처 스토어의 저지연은 동적 가격·실시간 좌석 업그레이드를 매끄럽게 제공.
- 예: 사용자가 항공편을 검색하면 ML 모델이 **평균 예약 리드타임**(feature store에 저장된 피처)을 밀리초 단위로 조회해 빠르고 개인화된 추천 제공.

### 2. 일관성(Consistency)
- 데이터 웨어하우스에서는 평균 좌석 점유율 같은 피처가 학습 환경과 서빙 환경에서 서로 다르게 계산될 수 있어 **모델 불일치**로 이어짐.
- 피처 스토어는 피처를 **한 번 계산해 여러 환경에서 일관되게 재사용**하도록 보장 — 불일치를 방지하고 모델 신뢰성을 높임.
- 왜곡된 데이터는 가격이나 업그레이드 예측 같은 모델 성능을 저하시킬 수 있는데, 피처 스토어의 일관된 계산이 모델 정확도를 유지시켜 정확한 요금·업그레이드 예측을 보장.

### 3. 고급 전처리 지원(Feature Engineering)
- 실시간 사용 사례(항공권 예약)에서 피처 엔지니어링은 핵심이지만, 데이터 레이크는 이를 지원하지 않음 — 특정 승객 세그먼트를 위한 할인 계산 같은 복잡한 실시간 변환을 지원하지 않음.
- 피처 스토어는 고급 변환을 위한 파이프라인을 제공 — 노선별 할인 같은 피처가 미리 전처리되어 즉시 사용 가능.
- 실시간 정규화(normalization)가 필요한 피처는 종종 지연되어 추천 시스템에 영향을 미치는데, 피처 스토어의 실시간 전처리는 평균 예약 리드타임 같은 정규화된 데이터를 일관되게 서빙하며 ML 모델 배포·서빙 전체를 원활하게 만듦.

### 4. 확장성(Scalability)
- 데이터 웨어하우스는 높은 빈도의 동시 접근(concurrent access) 상황에서 확장성에 한계가 있음 — ML 모델이 대규모 동시성 상황에서 웨어하우스 데이터에 접근하는 데 제약이 생김.
- 피처 스토어는 선택된 피처만 저장하므로 모든 조회가 더 빠르고(밀리초 단위 조회), 동시 접근도 문제가 되지 않음 — 동시 접근 부족으로 인한 ML 모델의 성능 병목을 해결.

### 핵심 통찰
- 피처 스토어는 데이터 레이크 같은 전통적 시스템의 문제(신선도, 지연시간, 일관성, 전처리, 동시성)를 해결하도록 설계됨. 항공권 예약 서비스의 경우 신선하고 실시간인 피처, 저지연 예측, 일관된 계산, 고급 전처리, 피크 부하에서의 확장 가능한 성능을 보장.
- MLOps 엔지니어라면 조직에서 어떤 형태로든 피처 스토어를 도입해야 함.
- **중요한 참고**: 피처 스토어는 완전히 새로운 도구가 아니라, **피처(feature)**라 부르는 특정 정보를 저장하는 **다른 방식**일 뿐 — 백엔드 시스템은 조직의 인프라 구성에 따라 BigQuery, DynamoDB, S3, GCP 버킷 등이 될 수 있음.

## 요약
| 이점 | 데이터 웨어하우스의 한계 | 피처 스토어의 해결책 |
|---|---|---|
| 저지연 서빙 | 복잡한 쿼리로 초 단위 지연 | 밀리초 단위 피처 서빙 |
| 일관성 | 학습/서빙 환경 간 계산 불일치 | 한 번 계산해 일관되게 재사용 |
| 전처리 | 실시간 복잡한 변환 미지원 | 사전 처리된 파이프라인 제공 |
| 확장성 | 높은 동시 접근에서 병목 | 선택된 피처만 저장해 빠른 동시 조회 |

- 피처 스토어는 새로운 도구가 아니라 피처를 저장하는 방식(BigQuery/DynamoDB/S3/GCP 버킷 등 기존 백엔드 위에 구현)이며, 저지연·일관성·전처리·확장성 문제를 해결해 실시간 ML 서비스의 핵심 인프라가 된다.
