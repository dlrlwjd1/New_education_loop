# What is Feature Store?

## 개요
- 항공권 예약 서비스 사례로 데이터 레이크의 실시간 ML 한계를 짚고, 이를 해결하는 **피처 스토어(Feature Store)**의 필요성을 설명하는 5분 영상.

## 내용

### 데이터 레이크의 이상적 시나리오와 현실의 간극
- 이상적 시나리오: 데이터 레이크에 항공권 예약 데이터를 모두 저장 → 이 데이터로 ML 모델 학습 → 모델 서빙 → 재학습 시 다시 데이터 레이크를 참조.
- 현실: 항공권 예약의 입력값은 계속 변함 — 새 항공편 추가, 신규 목적지, 가격 변동, 국제 정세 변화가 항공권 가격 모델에 영향을 미침. ML 모델도 이에 실시간으로 반응해야 하는데, 이것이 바로 **데이터 레이크의 한계**.

### 데이터 레이크의 장점(항공권 예약 서비스 관점)
1. **데이터 신선도와 실시간 접근**: 방대한 데이터를 저장해 과거 예약, 승객 선호도, 트렌드 분석 가능(예: 성수기 파악). 하지만 **실시간 신선도 유지가 어렵다**는 것이 가장 큰 단점.
2. **실시간 추론을 위한 저지연 서빙**: 최저 항공료 표시 같은 실시간 예측에는 빠른 데이터 접근이 필수인데, 데이터 레이크는 밀리초 단위 지연시간에 최적화되어 있지 않을 수 있음.
3. **학습-서빙 일관성**: 과거 항공료 데이터로 학습한 가격 모델이 현재 서빙 환경과 일치해야 하지만, 데이터 신선도가 떨어지면 모델 성능이 저하됨.
4. **복잡한 변환 지원**: 항공편당 평균 좌석 점유율, 노선별 할인 같은 피처는 복잡한 변환이 필요 — 데이터 레이크는 원본 데이터를 저장해 이런 전처리 워크플로를 지원.
5. **안정성과 확장성**: 실시간 좌석 가용성, 항공편 지연, 승객 예약 행동 등 테라바이트급 데이터를 수집 가능.

### 피처 스토어의 등장
- 피처 스토어는 데이터 레이크의 한계(실시간성)를 해결 — 실시간 항공편 가용성 표시, 동적 항공료 추천, 좌석 업그레이드 예측 등에서 피처를 **실시간·저지연**으로 제공해 매끄러운 예약 경험을 가능하게 함.

### 데이터 웨어하우스 vs 피처 스토어 — 데이터 신선도 비교

| 측면 | 데이터 웨어하우스(배치 처리) | 피처 스토어(스트리밍 수집) |
|---|---|---|
| **업데이트 방식** | 시간별/일별 배치로 주기적 업데이트 — 새 예약이 다음 배치까지 반영 안 됨(잘못된 좌석 가용성/가격 표시 위험) | 실시간 스트리밍 수집 — 새 예약이 즉시 반영되어 정확한 가용성·가격 제공(ML 모델이 스트리밍 데이터로 즉시 재학습되는 효과) |
| **취소 반영** | 배치 처리로 데이터가 금방 낡아짐 — 취소된 좌석이 몇 시간 동안 여전히 "불가"로 표시되어 막판 예약 기회 손실 | 취소로 좌석이 풀리면 즉시 가용성 업데이트 — 해당 좌석 판매 가능성 증가 |
| **평균 예약 리드타임 등** | 최근 예약을 놓칠 수 있음 | 실시간으로 데이터를 캡처해 ML 모델이 학습한 최신 정보를 항상 고객에게 제공 |

## 요약
- 피처 스토어는 데이터 레이크·웨어하우스의 배치 처리 한계(신선도 부족, 밀리초 단위 서빙 불가)를 스트리밍 수집으로 해결해, 실시간 좌석 가용성·동적 가격·업그레이드 예측 같은 ML 기반 서비스에 정확하고 최신인 피처를 제공한다.
