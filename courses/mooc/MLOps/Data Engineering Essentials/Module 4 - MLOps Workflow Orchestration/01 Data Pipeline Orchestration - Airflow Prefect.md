# Data Pipeline Orchestration - Airflow, Prefect

## 개요
- 데이터 파이프라인 오케스트레이션 도구가 왜 필요한지, 그리고 대표적인 두 도구 Apache Airflow와 Prefect를 비교하는 8분 영상.

## 내용

### 오케스트레이션 도구가 필요한 이유
- 예시 파이프라인: 공개 데이터 스크래핑 → S3에 저장 → 변환 → 시각화 가능한 프레젠테이션 레이어에 저장.
- 이 단계들을 매일 하나씩 수동으로 실행할 수는 없음. 한 단계는 다른 단계 직후에 실행되어야 하고, 실패 시 알림을 받아야 함 — 이것이 오케스트레이션 도구의 역할.
- 조직에는 수백~수천 개의 파이프라인이 존재할 수 있어, 이를 하나의 서버에서 cron job으로 관리하는 것은 불가능.

### 파이프라인 없이 발생하는 문제들
1. **모든 파이프라인을 한곳에서 설정·관리하기**: Apache Airflow나 Prefect 같은 도구로 데이터 파이프라인 관리를 중앙화 — 하나의 대시보드에서 작업을 모니터링·스케줄링.
2. **단일 대시보드/UI에서 모니터링**: 통합 대시보드로 모든 파이프라인의 상태를 실시간 추적 — 예: ETL 프로세스 실패나 데이터 지연 증가를 확인.
3. **손쉬운 백필(backfill)과 파이프라인 간 의존성 관리**: 무언가 잘못되거나 새 데이터 소스가 추가되었을 때 데이터를 백필해야 하는 경우가 있음. Airflow 같은 도구는 손쉬운 백필과 파이프라인 간 의존성 관리 기능을 제공해 데이터 흐름이 올바른 순서로 이뤄지도록 보장.

### 오케스트레이션 도구의 이점
1. **작업 자동화와 스케줄링/의존성 관리**: 데이터 추출·변환 같은 작업을 특정 시간에 자동 실행하도록 스케줄링해 수작업 개입을 줄임 — 예: 소매 회사가 매일 자정에 경쟁사 상품 데이터 스크래핑을 스케줄링해 매일 아침 신선한 데이터 확보.
2. **견고한 에러 처리와 재시도**: 실제 데이터 환경에서 오류는 불가피 — 내장된 에러 처리와 자동 재시도로 문제가 발생해도 파이프라인이 매끄럽게 계속 실행됨.
3. **확장 가능한 병렬 처리**: 증가하는 데이터 양을 다루기 위해 수평적으로 확장 가능(워커 추가) — 금융처럼 대량의 거래·데이터를 처리하는 산업에 특히 유용.
4. **가시성을 위한 모니터링·로깅**: 실시간 대시보드로 파이프라인 상태에 대한 완전한 가시성 제공 — 예: 헬스케어 제공업체가 환자 데이터 흐름을 추적해 컴플라이언스 준수를 보장.
5. **다른 시스템과의 매끄러운 통합**: Airflow 같은 오케스트레이터는 다양한 시스템·데이터 소스와 잘 통합되어 여러 도구·데이터베이스를 연결하는 포괄적인 워크플로 구축 가능 — 예: CRM 고객 데이터와 주문 데이터를 연결해 고객 행동의 전체적인 시각 확보.

### Airflow vs Prefect 비교

| 측면 | Apache Airflow | Prefect |
|---|---|---|
| **작업 시각화** | 작업 의존성을 시각화하는 풍부한 UI 제공 | 더 현대적인 API와 단순화된 워크플로 설계 제공 |
| **스케줄링·의존성 관리** | 시간 또는 트리거 기반 작업 스케줄링, 작업 간 의존성 관리(예: 추출 → 변환 → 적재 순서 보장) | 동일 |
| **확장성·성능** | 수평적으로 확장 가능 — 대용량 데이터와 조직 성장에 대응 | 동일 |
| **확장성·통합** | AWS, GCP, 커스텀 API 등과 통합해 맞춤형 워크플로 구축 가능 | 동일 |
| **모니터링·로깅** | 실시간 대시보드와 상세 로깅 제공 | 동일 |
| **에러 처리·재시도** | 내장 에러 처리와 자동 재시도(사전 정의된 설정 기반) | 동일 |
| **커뮤니티·업계 채택** | 대규모 활성 커뮤니티, 수년간 업계에서 널리 채택 | 성장 중인 지원 커뮤니티, 현대적 접근과 사용 편의성으로 인기 상승 중 |

## 요약
- 데이터 오케스트레이션 도구(Airflow, Prefect)는 자동화, 견고한 에러 처리, 확장 가능한 병렬 처리, 모니터링·로깅, 시스템 통합을 통해 수많은 파이프라인을 중앙에서 안정적으로 관리할 수 있게 해주며, Airflow는 성숙한 생태계와 큰 커뮤니티를, Prefect는 현대적이고 단순한 API를 강점으로 내세운다.
