# Idea of Data Lake

## 개요
- ETL로 처리된 데이터를 저장하는 아키텍처 설계인 **데이터 레이크**의 핵심 특징(중앙화, 확장성, 다양한 데이터 유형 지원, 비용 효율성, 고급 처리, 보안·거버넌스, 통합)을 실제 기업 사례로 설명하는 4분 영상.

## 내용

### 데이터 레이크란
- ETL 프로세스로 여러 형식의 조직 데이터를 처리한 뒤, 이를 **하나의 장소·형식으로 저장**하는 곳이 바로 데이터 레이크.

### 데이터 레이크의 핵심 특징

1. **중앙화된 데이터 저장소**: 구조화된 데이터(판매 기록)든 비구조화된 데이터(고객 리뷰)든 모든 데이터가 존재하는 거대한 단일 저장 공간. 예: Amazon 같은 대형 유통업체가 재고·판매·고객 상호작용 데이터를 한곳에 저장 — 사일로 걱정 없이 접근·분석이 훨씬 쉬워짐.

2. **확장성과 유연성**: 급증하는 데이터 양을 문제없이 처리 — 예: 블랙프라이데이 세일로 인한 웹사이트 트래픽 급증, 새로운 IoT 기기 도입. 예: Tesla가 자율주행차에서 나오는 테라바이트급 센서 데이터를 데이터 레이크에 저장해, 차량 수 증가와 데이터 유형 복잡화에 맞춰 확장.

3. **다양한 데이터 유형 지원**: 단순 텍스트 로그부터 복잡한 이미지·영상, 실시간 스트리밍 데이터까지 처리 가능. 예: Netflix가 시청 패턴, 비디오 메타데이터, 서비스 품질 데이터를 동시에 관리하는 데 데이터 레이크 활용.

4. **비용 효율성**: 데이터 레이크는 도구도 데이터베이스도 아니며, **저장 방식에 대한 아키텍처 설계**임 — Amazon S3, Azure Data Lake, GCP Storage 위에서 구현 가능. 별도로 구매해야 하는 값비싼 도구가 아니라 선택하는 설계이며, 어떤 블롭 스토리지에서도 동작하므로 비용 효율적.

5. **고급 데이터 처리 지원**: 다양한 처리된 데이터가 한곳에 저장되는 방식 덕분에 고급 데이터 처리가 가능 — 여기서 머신러닝 개념이 등장. 문제 정의와 관련된 데이터가 많을수록 ML 결과가 좋아지므로, 데이터 레이크 형식으로 저장하는 것이 이런 고급 처리를 가능하게 함.

6. **데이터 보안·거버넌스**: 데이터 레이크는 데이터를 보호하고 거버넌스를 갖출 수 있는 방법을 제공 — 이후 영상에서 더 자세히 다룰 예정.

7. **매끄러운 도구 통합**: 예를 들어 데이터가 S3에 있으면 Athena로 읽을 수 있고, BI 도구나 Tableau가 데이터 레이크에서 훨씬 빠르게 데이터를 읽을 수 있음.

### 핵심 통찰
- MLOps 엔지니어로서, ML 모델을 위한 모든 관련 데이터를 데이터 레이크 형식으로 저장하는 것은 이제 당연한 선택 — 현재의 도구·설계 기준으로는 이것이 정석적인 방법.
- 미래에는 데이터 레이크보다 더 나은 무언가가 등장하겠지만, 현재 시점에서는 다양한 ML 모델 개발에 효율적임이 입증된 설계.

## 요약
- 데이터 레이크는 도구가 아니라 아키텍처 설계로서, 중앙화·확장성·다양한 데이터 유형 지원·비용 효율성·고급 처리·보안·통합이라는 특징을 통해 현재 ML 모델 개발에 가장 효율적인 데이터 저장 방식으로 자리잡았다.
