# Data Cleaning and Data Transformation

## 개요
- 데이터 레이크에 저장된 다양한 형식의 데이터를 정제·표준화하는 전략과, 이를 위한 대표적 도구(Pandas, Spark, AWS Glue, Talend, DBT)를 소개하는 5분 영상.

## 내용

### 왜 정제·변환이 필요한가
- 데이터 레이크에 저장된 데이터는 CSV, 문서, JSON, 이미지, Parquet 등 다양한 형식일 수 있음 — 최종 사용자가 분석하려면 결국 **하나의 통일된 형식**(널리 쓰이는 Parquet 등)으로 변환해야 함.
- 변환 전, 반드시 짚어야 할 질문: **데이터 품질**은 어떠한가? 필요한 모든 정보와 데이터 포인트를 담고 있는가? — 변환을 시작하기 전 또는 변환 과정 중에 이를 분석해야 함.

### 데이터 품질 개선을 위한 핵심 전략
1. **데이터 정확성 보장**: 모든 분석의 기초 — 오류와 불일치는 잘못된 인사이트로 이어짐. 예: 물류 회사가 배송 주소 오류를 수정하면 배송 시간과 고객 만족도가 크게 개선됨.
2. **중복 제거**: 예: 동일 고객에 대해 여러 항목이 있는 고객 데이터베이스 — 비효율적일 뿐 아니라 마케팅·청구 과정에서 혼란을 야기.
3. **형식 표준화**: 대표 사례가 날짜 필드 — 한 시스템은 MM/DD/YYYY, 다른 시스템은 YYYY/MM/DD로 기록. 표준화만으로도 워크플로 전체를 효율적으로 최적화할 수 있음.
4. **결측값 처리**: 결측 데이터는 모델을 교란해 잘못된 예측으로 이어질 수 있음 — 예: 소매업의 고객 나이 결측치 처리가 개인화 오퍼의 정확도를 개선.
5. **분석을 위한 데이터 최적화**: 원본 데이터를 처리하기 쉬운 구조화된 형식으로 변환 — 예: 소셜 미디어 플랫폼이 원본 게시물을 감성 점수(sentiment score)로 변환해 트렌드를 빠르게 식별.

### 데이터 처리·변환 도구
- **Pandas**: 단순함과 유연성으로 사랑받는 Python 라이브러리 — 소규모~중간 규모 데이터 작업에 적합. 예: 스타트업이 Pandas로 판매 데이터를 정제해 대시보드 생성.
- **Apache Spark**: 산업 수준으로 데이터 처리를 확장 — 예: Uber가 전 세계 차량에서 나오는 테라바이트급 데이터를 실시간 분석하는 데 Spark 활용.
- **AWS Glue**: ETL을 단순화하는 서버리스 도구 — 예: 게임 회사가 플레이어 활동 데이터를 구조화된 테이블로 변환해 리텐션 전략에 활용.
- **Talend**: ETL 프로세스를 위한 시각화 인터페이스 — 드래그 앤 드롭 방식을 원하는 팀에 이상적. 예: 헬스케어 회사가 여러 시스템의 환자 기록을 하나의 일관된 형식으로 통합. 많은 대기업이 여전히 활발히 사용.
- **DBT(Data Build Tool)**: 비교적 신생 도구지만 훨씬 효과적 — 데이터 웨어하우스 내부에서 직접 데이터를 변환하는 데 초점. 데이터 분석가가 엔지니어처럼 일할 수 있게 해줌. 예: 이커머스 플랫폼이 원본 클릭스트림 데이터를 실행 가능한 고객 세그먼트로 변환하는 데 DBT 사용.

### 다음 단계 예고
- 데이터 정제·처리는 **소규모/중간 규모 데이터 처리**와 **대규모 데이터 처리**로 나눌 수 있음.
- 다음 영상에서는 **Python(Pandas/Polars)을 활용한 소규모·중간 규모 데이터 처리·변환**에 집중할 예정.

## 요약
| 도구 | 적합한 규모/용도 |
|---|---|
| Pandas | 소규모~중간 규모, 간단하고 유연 |
| Apache Spark | 대규모, 산업 수준 실시간 처리 |
| AWS Glue | 서버리스 ETL |
| Talend | 드래그 앤 드롭 ETL, 대기업에서 널리 사용 |
| DBT | 데이터 웨어하우스 내부 변환, 분석가의 엔지니어링화 |

- 데이터 정제·변환은 정확성·중복 제거·형식 표준화·결측값 처리·분석 최적화라는 다섯 가지 전략을 기반으로 하며, 데이터 규모에 따라 Pandas/Spark/Glue/Talend/DBT 중 적합한 도구를 선택한다.
