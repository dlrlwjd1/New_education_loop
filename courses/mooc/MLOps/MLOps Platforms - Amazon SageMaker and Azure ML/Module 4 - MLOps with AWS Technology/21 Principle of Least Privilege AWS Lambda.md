# Principle of Least Privilege AWS Lambda

## 개요
- S3 업로드 → Lambda 트리거 → DynamoDB 업데이트로 이어지는 서버리스 마이크로서비스 예시로 **최소 권한 원칙**을 설명하는 1분 영상.

## 내용

### 최소 권한 아키텍처 예시
- 이 마이크로서비스에서 Lambda는 오직 **S3 읽기(S3 Read)**와 **특정 DynamoDB 테이블 접근**만 부여받음.
- 이렇게 하면 이 마이크로서비스가 정확히 무엇을 하는지 제한할 수 있음 — 기능하는 데 필요한 작업만 할 수 있고, 불필요한 추가 권한은 부여되지 않아 훨씬 더 안전해짐.

### 흐름
- 이미지가 업로드되어 S3에 저장됨 → 이 Lambda 함수를 트리거 → Lambda가 사용자 프로필을 업데이트.
- 이는 머신러닝 시스템의 일부일 수 있음 — 이후 S3에 업로드된 이미지에 사전학습 모델을 적용해 인페인팅(in-painting)을 하거나 레이블을 식별하는 식으로 이어질 수 있음.

### 핵심 통찰
- 핵심 아이디어는, 시스템이 개발되는 과정에서 **각 부분이 오직 해당 마이크로서비스의 문제를 해결하는 데 필요한 권한만 사용**하도록 만드는 것.

## 요약
- 최소 권한 원칙은 각 마이크로서비스(예: Lambda)에 S3 읽기·특정 DynamoDB 테이블 접근처럼 꼭 필요한 권한만 부여해, 불필요한 책임을 없애고 시스템 전체의 보안을 강화하는 설계 원칙이다.
