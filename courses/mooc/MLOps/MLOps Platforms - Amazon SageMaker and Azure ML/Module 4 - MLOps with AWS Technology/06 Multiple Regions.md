# Multiple Regions

## 개요
- AWS의 리전(Region)·가용 영역(Availability Zone)·데이터센터 구조를 통해 지리적으로 분산되고 장애에 강한 애플리케이션을 설계하는 방법을 설명하는 1분 영상.

## 내용

### AWS 지리적 구조
- AWS 아키텍처는 여러 **리전(Region)**으로 구성됨 — 예: 리전 A(미국 동부 해안), 리전 B(유럽연합).
- 각 리전 내부에는 **가용 영역(Availability Zone, AZ)**이 있음 — AZ는 다른 AZ와 물리적으로 격리되어 있으며, 일반적으로 **2개 이상의 데이터센터**로 구성됨.
- 이를 통해 하나의 AZ 안에서도 어느 정도의 이중화(redundancy)가 가능.

### 다중 리전/다중 AZ 아키텍처
- 전 세계적으로 장애에 강한(resistant to failures) 지리적 분산 애플리케이션을 만들고 싶다면, 여러 리전에 걸쳐 리소스를 배치하고 각 리전 내부에서도 **다중 AZ 아키텍처**를 구축할 수 있음.
- 예: 데이터베이스가 하나의 리전 안의 3개 가용 영역을 모두 활용하도록 구성 가능.

### 핵심 통찰
- 이렇게 하면 소프트웨어 개발의 모범 사례를 따라 회복탄력적인(resilient) 애플리케이션을 구축할 수 있음 — 리전, 가용 영역, 또는 데이터센터 중 어느 하나에 문제가 생기더라도 애플리케이션이 매끄럽게(seamlessly) 그 문제를 처리할 수 있음.

## 요약
- AWS는 리전 → 가용 영역(2개 이상의 데이터센터로 구성) 구조로 이루어져 있으며, 다중 리전·다중 AZ에 리소스를 분산 배치하면 리전·AZ·데이터센터 단위의 장애에도 매끄럽게 대응하는 회복탄력적인 아키텍처를 만들 수 있다.
