# Practical Scenario — Provisioning EC2 for a Web App

## 개요
- EC2 프로비저닝 구성 요소(유저 데이터, 스토리지, 보안 그룹) 지식을 적용해보는 5분짜리 AI 생성 인터랙티브 성찰 활동.

## 내용

### 시나리오
- 새 웹 애플리케이션을 호스팅하기 위해 EC2 인스턴스를 실행해야 함. 이 애플리케이션은 인스턴스가 처음 실행될 때 의존성을 설치하고 웹 서버를 자동으로 구성하는 특정 시작 스크립트가 필요하며, 인터넷에서 포트 80(HTTP)과 443(HTTPS)으로 접근 가능해야 함.
- 질문: 이 특정 요구사항을 충족하기 위해 어떤 두 가지 EC2 프로비저닝 구성 요소에 집중할 것이며, 그 이유는?

### 종합 답변 (강의 개념 기반)
- **① 유저 데이터(User Data)**: 인스턴스가 처음 시작될 때 의존성 설치와 웹 서버 자동 구성을 수행해야 하므로, 이 특수 지시사항(시작 스크립트)을 정확히 담당하는 구성 요소는 **유저 데이터**다. 부팅 시점에 실행되는 스크립트를 여기에 넣어 자동화를 완성한다.
- **② 보안 그룹(Security Group)**: 인터넷에서 포트 80과 443으로 접근 가능해야 하므로, EC2 실행의 방화벽 규칙을 정의하는 **보안 그룹**에서 이 두 포트에 대한 인바운드(inbound) 규칙을 열어야 한다.
- 나머지 구성 요소(스토리지, AMI, 인스턴스 유형, 비용 모델, VPC, 역할)도 중요하지만, 이 시나리오에서 명시적으로 요구된 두 가지 요구사항(자동 시작 스크립트, 특정 포트로의 웹 접근)을 직접적으로 충족시키는 것은 유저 데이터와 보안 그룹이다.

## 요약
- "시작 시 자동 설정"은 유저 데이터로, "특정 포트로의 외부 접근"은 보안 그룹으로 해결하는 것이 이 시나리오의 핵심이다.
