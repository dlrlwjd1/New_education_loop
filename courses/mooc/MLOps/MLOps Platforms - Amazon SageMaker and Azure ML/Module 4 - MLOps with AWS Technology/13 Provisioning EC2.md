# Provisioning EC2

## 개요
- EC2 인스턴스를 실행(launch)할 때 관여하는 모든 하위 구성 요소(유저 데이터, 스토리지, 보안 그룹, AMI, 인스턴스 유형, 비용, VPC, 역할)를 개괄하는 1분 영상.

## 내용

### EC2 실행 방법
- 콘솔, SDK, CLI 중 어디서든 EC2를 실행(launch)할 수 있음.

### 반드시 짚어야 할 하위 구성 요소
- **유저 데이터(User Data)**: 특수 지시사항(예: 시작 스크립트)을 넣는 곳.
- **스토리지**: EBS 스토리지를 사용할지, 인스턴스 스토리지를 사용할지.
- **보안 그룹(Security Group)**: EC2 실행을 위한 방화벽 규칙.
- **SSH 키 페어**: 다른 위치(예: AWS CloudShell)에서 셸로 접속할 수 있게 해주는지 여부.
- **AMI(Amazon Machine Image)**: 커스텀 AMI를 만들었는지 여부.
- **인스턴스 유형**: CPU, 메모리, GPU 등 어떤 유형을 사용할지.
- **비용**: 온디맨드(on-demand)인지 스팟(spot)인지.
- **가상 사설 클라우드(VPC)**: 특정 클라우드로 격리되어 있는지, 어떤 VPC를 사용하는지.
- **역할(Role)**: 이 EC2 인스턴스가 무엇을 할 수 있어야 하는지 — 예: S3를 읽거나 DynamoDB와 통신할 수 있는지.

### 핵심 통찰
- EC2 인스턴스 실행이 제대로 작동하는 것은 바로 이 모든 하위 구성 요소들이 하나로 캡슐화(encapsulation)되어 있기 때문.

## 요약
- EC2 인스턴스 프로비저닝은 유저 데이터·스토리지·보안 그룹·SSH 키·AMI·인스턴스 유형·비용 모델(온디맨드/스팟)·VPC·IAM 역할이라는 여러 구성 요소가 하나로 결합되어 이뤄지는 과정이다.
