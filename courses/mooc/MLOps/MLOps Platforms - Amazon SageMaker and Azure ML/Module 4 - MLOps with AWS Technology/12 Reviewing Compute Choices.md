# Reviewing Compute Choices

## 개요
- 인프라 제어 수준과 개발·배포 속도 사이의 트레이드오프를 기준으로 가상 머신·컨테이너·PaaS·서버리스 컴퓨트 옵션을 비교하는 1분 영상.

## 내용

### 컴퓨트 스펙트럼
- 한쪽 끝(왼쪽): **가상 머신(virtual machines)** — EC2, Lightsail 같은 인스턴스. **더 높은 인프라 제어**.
- 서버리스 쪽으로 갈수록: **컨테이너**와 **Platform as a Service(PaaS)**.
- 가장 서버리스에 가까운 끝: **Lambda**, **Fargate** 같은 서버리스 — 직접 할 일이 별로 없음. 로직만 만들어 프로덕션에 올리면 됨.
- 전통적인 PaaS는 여전히 약간의 작업이 필요함 — 애플리케이션 안에 설정 파일을 넣는 정도이지만, 나머지는 PaaS가 대신 처리.

### 선택 기준
- 머신러닝 애플리케이션을 구축한다면 **서버리스 옵션**으로 기우는 것이 좋을 수 있음.
- 저수준(low-level) 작업을 직접 해야 한다면 **가상 머신과 컨테이너** 쪽으로 기우는 것이 좋을 수 있음.
- 결국 만들고 있는 각각의 "레시피"에 맞춰, 풀고자 하는 문제에 맞는 올바른 구성을 선택하는 것은 개발자의 몫.

## 요약
| 옵션 | 인프라 제어 | 개발·배포 속도 |
|---|---|---|
| 가상 머신(EC2/Lightsail) | 높음 | 느림 |
| 컨테이너 | 중간 | 중간 |
| PaaS | 낮음~중간 | 빠름 |
| 서버리스(Lambda/Fargate) | 낮음 | 매우 빠름 |

- 저수준 제어가 필요하면 가상 머신/컨테이너, 빠른 개발·배포가 우선이라면(머신러닝 애플리케이션 등) 서버리스를 선택하는 것이 일반적인 가이드라인이다.
