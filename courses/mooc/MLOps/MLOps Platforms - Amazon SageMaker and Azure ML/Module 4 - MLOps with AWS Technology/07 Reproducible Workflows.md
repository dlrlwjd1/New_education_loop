# Reproducible Workflows

## 개요
- Infrastructure as Code(IaC)를 중심으로 빌드 시스템·소스 코드 저장소가 결합된 재현 가능한 워크플로를 설명하는 1분 영상.

## 내용

### 재현 가능한 워크플로의 구성
- 재현 가능한 워크플로는 Infrastructure as Code뿐 아니라 빌드 시스템, 소스 코드 저장소 같은 구성 요소도 포함.
- 흐름: 클라우드 기반 개발 환경(Cloud9, GitHub Codespaces) 또는 로컬 개발 환경에서 코드 작성 → **테스트 → 머지 → 트리거 → 빌드** 워크플로 실행 — 코드를 테스트하고, 린팅(linting)이 잘 작동하는지, 배포 시스템이 정상 동작하는지 확인.

### Infrastructure as Code의 동작 방식
- 백그라운드의 IaC는 예를 들어 S3 버킷 같은 인프라를 생성할 수 있음.
- 만약 다음 배포 시점에 아무 변경도 없다면, S3 버킷의 상태를 그대로 유지.
- 예를 들어 S3 버킷을 정적 웹사이트로 바꾸는 등 변경이 필요하다면, **변형된(mutated) 인프라 변경**을 배포 가능.
- 변경을 되돌려야 한다면, 인프라를 삭제·파괴(delete and destroy)할 수 있음 — 예: S3 버킷 제거.

### 핵심 통찰
- Infrastructure as Code의 핵심 아이디어는, 무언가를 실행시키기 위해 사람이 직접 버튼을 누르는 것이 아니라 **코드가** 그것을 실행한다는 것.

## 요약
- 재현 가능한 워크플로는 개발 환경 → 테스트/머지/빌드 파이프라인 → Infrastructure as Code(생성·유지·변경·삭제)로 이어지며, 핵심은 사람의 수동 개입 없이 코드가 인프라 상태를 결정한다는 것이다.
