# Monitoring and Logging

## 개요
- 모니터링·로깅을 "소프트웨어 시스템을 위한 데이터 과학"으로 바라보는 관점과, AWS CloudWatch를 통한 시각화를 설명하는 1분 영상.

## 내용

### 모니터링과 로깅 = 소프트웨어 시스템을 위한 데이터 과학
- 머신러닝 운영(MLOps)을 하며 프로덕션에 무언가를 배포하더라도, 사용 중인 **인프라 자체의 데이터 과학**도 함께 살펴봐야 함.
- 서버의 경우 소스 코드 자체가 정보의 원천이 될 수 있고, 코드에 추가하는 로깅·계측(instrumentation)도 마찬가지 — 예: 특정 예측을 수행하는 데 걸리는 시간.
- 모니터링 에이전트에는 CPU, 디스크 I/O, 메모리 같은 핵심 지표를 포함시켜야 함.

### AWS CloudWatch로 확인하기
- **AWS CloudWatch**로 대시보드를 열람하고, 알림(alert)을 확인하고, 특정 시스템을 검색할 수 있음.
- CloudWatch 시스템에서 나오는 **자동화된 인사이트**도 얻을 수 있음.

### 핵심 통찰
- 모니터링과 로깅을 생각하는 가장 좋은 방법은 이를 소프트웨어 시스템을 위한 데이터 과학으로 바라보는 것 — 시스템에서 무슨 일이 일어나는지 알고 가시성을 확보하려면 모니터링과 로깅이 필요함.
- 데이터 과학자로서 가진 것과 같은 역량을, 머신러닝 모델을 배포하기 위해 구축한 소프트웨어 시스템에도 그대로 적용해야 함.

## 요약
- 모니터링·로깅은 소프트웨어 인프라(CPU, 디스크 I/O, 메모리, 예측 소요 시간 등)에 데이터 과학적 관점을 적용하는 것이며, AWS CloudWatch의 대시보드·알림·자동화된 인사이트를 통해 시스템 가시성을 확보할 수 있다.
