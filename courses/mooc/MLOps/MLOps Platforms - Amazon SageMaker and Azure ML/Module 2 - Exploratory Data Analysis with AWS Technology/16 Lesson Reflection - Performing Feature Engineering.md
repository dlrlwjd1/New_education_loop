# Lesson Reflection — Performing Feature Engineering

## 개요
- Lesson 2 전체를 요약하는 공식 회고 자료: AWS와 ML 모범 사례를 활용한 엔드투엔드 ML 프로젝트를 다루며, EDA에 초점을 두는 동시에 하이퍼파라미터 최적화, MLflow 실험 추적·모델 관리, 배치/실시간 배포, 모니터링 워크플로까지 다뤘다.

## 내용

### 핵심 포인트
- 시각화, EDA, 통계는 더 깊은 데이터 이해를 가능하게 한다.
- 하이퍼파라미터 튜닝은 최적의 모델 구성을 찾아준다.
- MLflow는 여러 실행에 걸친 실험을 추적해 모델 분석·비교를 가능하게 한다.
- Model Registry는 모델 버전과 생애주기 전환을 관리한다.
- 저지연 서빙은 확장 가능한 실시간 추론을 가능하게 한다.

### 회고 질문
1. EDA는 데이터의 모델링 과제와 기회를 어떻게 드러낼 수 있는가?
2. 하이퍼파라미터 튜닝이 수동 튜닝보다 가치 있는 시점은 언제인가?
3. MLflow 실험 추적은 팀 워크플로를 어떻게 개선하는가?
4. 프로덕션 모델을 업데이트할 시점을 결정하는 요인은 무엇인가?
5. 배포와 서빙 선택은 사용 사례에 따라 어떻게 달라지는가?

### 도전 과제
1. Pandas/Seaborn 시각화와 통계 분석으로 데이터셋을 탐색해보기(랩이 좋은 출발점).
2. 그리드 서치나 랜덤 서치로 scikit-learn 모델을 튜닝해보기.
3. MLflow Tracking API로 실행의 메트릭·파라미터·모델을 로깅해보기.
4. MLflow UI를 통해 모델을 등록하고 단계를 전환해보기.
5. Flask나 AWS App Runner로 모델을 로컬에서 컨테이너화·서빙해보기.

## 요약
- Lesson 2는 공개 데이터셋 활용(Hugging Face/S3/Kaggle) → 피처 엔지니어링(NBA 승리 시즌 실습) → 하이퍼파라미터 튜닝·MLflow 실험 추적·모델 등록·서빙까지 이어지는 엔드투엔드 ML 워크플로를 다뤘다.
