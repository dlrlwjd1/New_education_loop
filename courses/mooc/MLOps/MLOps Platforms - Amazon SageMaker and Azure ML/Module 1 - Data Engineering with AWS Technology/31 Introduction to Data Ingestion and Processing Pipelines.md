# Introduction to Data Ingestion and Processing Pipelines

## 개요
- **AWS Batch**와 **AWS Step Functions**가 각각 어떻게 관리형 서비스로서 복잡한 반복 작업(recurring jobs)과 오케스트레이션 문제를 해결하는지 설명하는 2분 영상.

## 내용

### AWS Batch
- 반복되는 작업(recurring jobs)의 복잡한 부분들을 여러 조각으로 나눠 관리해주는 서비스.
- 흐름: **트리거**(타이머 또는 코드/이벤트 호출) → 새 작업 생성 → **작업 큐(job queue)**에 등록 → 큐에는 수천 개의 작업이 쌓일 수 있으며, 허용된 프로세스 수에 따라 처리.
- 예: 200개의 GPU 컨테이너를 동시에 실행해, 조직의 이벤트 스케줄에 따라 Hugging Face 모델을 파인튜닝하는 것과 같은 작업.
- AWS Batch는 범용적이지만 **머신러닝, 특히 GPU 파인튜닝**에 매우 잘 맞음.

### AWS Step Functions
- 역시 **서버리스**로 관리되는 기술.
- 이벤트(API 호출 또는 데이터 트리거)가 발생하면, 여러 **Lambda 함수**를 연결(pipe)해 하나의 페이로드를 처리하고 파이프라인 끝에서 최종 결과를 반환.
- 핵심 장점: 파이프라인 사이의 **오케스트레이션**을 자동으로 제공 — 로그 확인, 각 단계 소요 시간 확인 등을 위한 생태계를 직접 구축할 필요 없이, 로직만 조립하면 됨.

## 요약
- AWS Batch는 대규모 반복 작업(특히 GPU 파인튜닝 같은 ML 작업)을 큐 기반으로 관리해주고, AWS Step Functions는 여러 Lambda 함수를 오케스트레이션된 파이프라인으로 연결해 로그·소요 시간까지 자동으로 제공하는 서버리스 조율 서비스다.
