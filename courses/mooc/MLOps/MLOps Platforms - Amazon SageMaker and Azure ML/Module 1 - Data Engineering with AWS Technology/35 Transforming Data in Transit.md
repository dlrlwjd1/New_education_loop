# Transforming Data in Transit

## 개요
- **AWS Glue**를 활용해 S3와 외부 PostgreSQL 데이터베이스를 하나의 ETL 파이프라인으로 결합하고, Athena로 서버리스 쿼리까지 이어지는 아키텍처 패턴을 설명하는 2분 영상.

## 내용

### Glue 기반 ETL 파이프라인 흐름
1. **타이머 트리거**로 Glue 작업 시작 — Glue는 서버리스 ETL 시스템으로, 여러 데이터 소스를 가리킬 수 있음.
2. 예: S3에 있는 수백만 행짜리 대용량 CSV 파일과 외부 PostgreSQL 데이터베이스를 함께 연결.
3. **Extract, Transform, Load(ETL)** 작업을 생성해 데이터를 변환한 뒤, 그 결과를 **또 다른 S3 버킷**에 저장.
4. 이 트리거는 주기적으로 실행되므로, 외부 데이터베이스가 벤더에 의해 업데이트되어도 **재사용 가능한(reusable) 연산**이 계속 새로운 버전의 데이터를 만들어냄.

### 카탈로그화와 Athena 쿼리
- Glue는 결과 버킷을 **카탈로그화(catalog)**해 메타데이터 레코드를 생성.
- 이 덕분에 데이터 과학자는 **Athena**로 S3에서 데이터를 직접 꺼내지 않고도 카탈로그를 쿼리할 수 있음 — 서버리스 쿼리, 데이터 시각화, 조작(manipulation)까지 Athena + Glue 조합으로 처리 가능.

### 핵심 통찰
- 이 아키텍처(Glue ETL → S3 → Glue 카탈로그 → Athena 쿼리)는 많은 조직에 적합한 매우 일반적인 패턴이며, 이해하고 유지보수하기에도 비교적 단순함.

## 요약
- AWS Glue는 S3와 외부 데이터베이스(PostgreSQL 등)를 결합해 주기적으로 ETL을 수행하고 결과를 새 S3 버킷에 카탈로그화하며, 이를 Athena로 서버리스 쿼리하는 것이 데이터를 전송 중(in transit) 변환하는 대표적이고 재사용 가능한 AWS 아키텍처 패턴이다.
