# Practical Scenario — Orchestrating a Data Pipeline

## 개요
- AWS Batch와 Step Functions 지식을 적용해보는 5분짜리 AI 생성 인터랙티브 성찰 활동.

## 내용

### 시나리오
- 대형 이커머스 회사의 데이터 수집 파이프라인을 설계 중 — 매일 수백만 건의 고객 주문을 처리하고, 데이터를 변환한 뒤 데이터 웨어하우스에 적재해야 함.
- 처리 단계: 초기 데이터 검증 → 고객 인구통계 정보로 보강(enrichment) → 매출 수치 집계(aggregation).
- 질문: 이 여러 개의 순차적 데이터 처리 단계를 올바른 순서로 실행하고 장애를 우아하게 처리하도록 오케스트레이션하려면 어떤 AWS 서비스를 주로 사용할 것이며, 그 이유는?

### 종합 답변 (강의 개념 기반)
- 이 시나리오에는 **AWS Step Functions**가 가장 적합하다.
  - **순차적 단계 오케스트레이션**: 검증 → 보강 → 집계처럼 서로 의존하는 순차적 단계를 각각의 Lambda 함수(또는 다른 작업 유형)로 구성하고, Step Functions가 그 사이를 파이프처럼 연결해 순서대로 실행되도록 조율한다.
  - **장애 처리**: Step Functions는 각 단계의 재시도(retry), 에러 캐치(catch), 폴백(fallback) 로직을 상태 머신(state machine) 정의 안에 선언적으로 포함할 수 있어, 특정 단계(예: 데이터 검증 실패)에서 장애가 발생해도 우아하게 처리 가능.
  - **가시성**: 별도의 오케스트레이션 인프라를 직접 구축할 필요 없이, 각 단계의 로그와 소요 시간을 자동으로 확인할 수 있어 디버깅과 모니터링이 쉬움.
- **AWS Batch**와 비교하면: Batch는 대량의 독립적이거나 동일한 유형의 작업(예: GPU 파인튜닝 잡 수천 개)을 큐에 넣고 병렬로 처리하는 데 특화되어 있어, "검증 → 보강 → 집계"처럼 **서로 다른 유형의 순차적 단계를 오케스트레이션**하는 데는 Step Functions가 더 적합하다.

## 요약
- 여러 이종(異種) 단계가 순서대로 실행되어야 하고 각 단계의 실패를 개별적으로 처리해야 하는 파이프라인에는 Step Functions의 오케스트레이션·재시도·가시성 기능이 AWS Batch의 대량 병렬 작업 처리보다 더 적합하다.
