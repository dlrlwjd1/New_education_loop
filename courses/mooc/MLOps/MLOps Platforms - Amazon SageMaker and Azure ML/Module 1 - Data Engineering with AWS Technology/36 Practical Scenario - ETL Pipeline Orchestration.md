# Practical Scenario — ETL Pipeline Orchestration

## 개요
- AWS Batch, Step Functions, Glue 지식을 적용해보는 5분짜리 AI 생성 인터랙티브 성찰 활동.

## 내용

### 시나리오
- 매일 대용량 데이터셋을 처리하는 회사의 데이터 엔지니어 — S3 버킷에서 원본 데이터를 추출 → ETL 작업으로 변환 → 정제된 데이터를 다른 S3 버킷에 적재해 분석에 활용하는 워크플로를 구축해야 함. 이 전체 과정은 자동화되고 모니터링되어야 함.
- 질문: 이 다단계 데이터 파이프라인을 오케스트레이션하며 각 단계가 올바른 순서로 실행되고 잠재적 장애를 처리하도록 하려면 어떤 AWS 서비스를 주로 사용할 것이며, 그 이유는?

### 종합 답변 (강의 개념 기반)
- 추출 → 변환 → 적재라는 전형적인 ETL 흐름 자체는 **AWS Glue**가 담당하기에 가장 자연스럽다 — Glue는 서버리스 ETL 시스템으로, S3의 원본 데이터를 가리켜 변환한 뒤 다른 S3 버킷에 저장하고 그 결과를 자동으로 카탈로그화하는 기능을 기본으로 제공하기 때문.
- 다만 질문이 "여러 단계를 순서대로 실행하고 장애를 처리하는 **오케스트레이션**"에 초점을 맞추고 있으므로, Glue 작업 자체를 하나의 단계로 삼아 **AWS Step Functions**로 감싸는 구성이 가장 적합하다.
  - Step Functions는 Glue ETL 작업 호출을 하나의 상태(state)로 정의하고, 그 앞뒤에 검증이나 알림 같은 추가 Lambda 단계를 순서대로 연결할 수 있음.
  - 각 단계의 실행 결과(input/output)를 시각적으로 확인할 수 있고, 재시도·에러 캐치 로직을 상태 머신에 선언적으로 포함시켜 특정 단계 실패 시에도 우아하게 처리 가능.
  - 반면 AWS Batch는 대량의 동일 유형 작업을 병렬로 처리하는 데 특화되어 있어, "추출 → 변환 → 적재"처럼 서로 다른 단계를 순서대로 조율하는 목적에는 맞지 않음.

## 요약
- ETL 자체의 실행은 Glue가 맡고, 그 앞뒤 단계를 포함한 전체 파이프라인의 순서 보장·장애 처리·모니터링은 Step Functions가 오케스트레이션하는 조합이 이 시나리오에 가장 적합하다.
