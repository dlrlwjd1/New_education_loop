# Batch vs. Streaming Job Styles

## 개요
- AWS에서 작업을 처리하는 두 가지 방식 — **배치(Batch)**와 **스트리밍(Streaming)** — 을 대표 서비스와 함께 비교하는 2분 영상.

## 내용

### 배치(Batch) — Glue, AWS Batch, Step Functions
- **AWS Glue**: S3나 데이터베이스에 있는 데이터에 대해 연산·변환을 수행할 수 있도록 메타데이터를 생성 — 대용량 데이터를 배치로 묶어 처리하는 좋은 예시.
- **AWS Batch**: 범용 배치 기반 프레임워크로, 대규모로 무엇이든 처리 가능 — 컨테이너 작업이나 GPU를 활용한 모델 학습에 특히 강점.
- **AWS Step Functions**: 여러 단계를 파라미터화해 하나로 묶어주는 서비스 — 예를 들어 여러 Lambda 함수를 입력이 서로 이어지도록 오케스트레이션하는 데 활용.

### 스트리밍(Streaming) — Kinesis, Kafka(Amazon MSK)
- **Kinesis**: 작은 페이로드(payload)를 지속적으로 전송하면 그것들이 들어오는 대로 처리하는 방식.
- **Kafka(Amazon MSK)**도 대표적인 스트리밍 기술 중 하나.

### 배치 vs 스트리밍 비교
| 기준 | 배치(Batch) | 스트리밍(Streaming) |
|---|---|---|
| **운영 복잡도** | 상대적으로 단순 — 대상 데이터를 모아 한 번에 연산을 실행하고 결과를 받음 | 상대적으로 복잡 — 데이터가 들어오는 대로 처리해야 하므로 문제가 발생할 여지가 더 많음 |
| **데이터 크기** | 대용량 데이터에 특히 적합(소량 데이터도 가능하지만, 보통 규모 있는 처리를 위해 배치로 묶음) | 보통 더 작은 단위의 데이터를 그때그때 처리 |

## 요약
- 배치는 대용량 데이터를 한 번에 모아 처리하는 상대적으로 단순한 방식(Glue/Batch/Step Functions)이고, 스트리밍은 작은 페이로드가 도착하는 즉시 처리하는 상대적으로 복잡한 방식(Kinesis/Kafka)이며, 데이터 규모와 운영 복잡도가 둘을 구분하는 핵심 기준이다.
