# Practical Scenario — Choosing a Storage Service

## 개요
- S3, EFS, EBS 등 AWS 스토리지 서비스 지식을 적용해보는 5분짜리 AI 생성 인터랙티브 성찰 활동.

## 내용

### 시나리오
- 스타트업의 데이터 엔지니어로서, 새로운 머신러닝 애플리케이션을 구축 중.
- 모델 학습용 대용량 데이터셋을 저장해야 하며, 이 데이터셋은 여러 데이터 과학자가 **동시에 자주 접근**함. 또한 높은 **내구성(durability)**과 **확장성(scalability)**이 필요.
- 질문: 이 시나리오에 어떤 AWS 스토리지 서비스를 추천하며, 그 이유는?

### 종합 답변 (강의 개념 기반)
- 이 시나리오에는 **Amazon S3**가 가장 적합하다.
  - **내구성·확장성**: S3는 객체 스토리지로서 매우 높은 내구성과 사실상 무제한에 가까운 확장성을 기본으로 제공.
  - **동시 다중 접근**: 여러 데이터 과학자가 SDK(boto3)나 CLI(`aws s3 sync`, `aws s3 cp`)를 통해 동시에 데이터셋에 접근·다운로드하는 데 특별한 제약이 없음 — S3는 원래 다수의 클라이언트가 동시에 읽기 요청을 보내는 워크로드에 최적화되어 있음.
  - **비용 효율성**: 학습 데이터셋처럼 자주 전체를 다시 쓰지 않고 읽기 위주로 접근하는 대용량 데이터에는 EBS(블록 스토리지, 단일 인스턴스에 연결)보다 S3가 더 적합.
- 만약 여러 컴퓨팅 인스턴스가 **파일 시스템처럼 마운트**해서 접근해야 하는 경우라면 **Amazon EFS**(관리형 NFS)를 고려할 수 있지만, 순수하게 데이터셋을 저장하고 여러 사용자가 SDK/CLI로 읽어가는 시나리오에서는 S3가 표준적인 선택.

## 요약
- 대용량 ML 데이터셋을 다수의 사용자가 동시에 읽어가는 시나리오에서는, 객체 스토리지의 내구성·확장성·동시 접근성이라는 특성 때문에 S3가 EBS/EFS보다 우선적으로 고려되는 표준 선택지다.
