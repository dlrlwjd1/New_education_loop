# Introduction to Python Modules

## 개요
- Python 모듈이란 그냥 **`.py`로 끝나는 Python 파일**일 뿐이라는 것, 그리고 왜 코드를 여러 모듈로 나누어 정리해야 하는지(유지보수성)를 실제 프로젝트 구조 예시로 설명한다.

## 내용

### 모듈 = `.py` 파일
- **"모듈은 그냥 파이썬 파일이다. `.py`로 끝나면 모듈이다."** 이게 전부다.
- 코드를 정리(organize)하는 방법으로 생각하면 된다.

### 왜 모듈로 나눠야 하는가 — 옷장 서랍 비유
- 클래스 여러 개, 함수 여러 개가 뒤섞인 200줄 넘는 긴 파일 하나는 정리가 안 된 상태다.
- 비유: **옷을 전부 서랍 하나에 넣는 것**과 같다 — 아마 잘 안 될 것이다. 물건을 분리해서 각자 제자리에 두는 것이 더 낫고 유지보수하기 쉽다.

### 실제 프로젝트 구조 예시
- 예시 CLI 프로젝트에는 `engine`, `exceptions`, `main`, `network` 등으로 파일이 나뉘어 있다 — 어떤 문제(예: 커스텀 예외 처리)를 다룰 때 `exceptions.py`처럼 어디를 봐야 할지 바로 짐작할 수 있게 해준다.
- Python 자체도 자신만의 모듈을 갖고 있다 — 예: `os` 모듈은 그 안에 아주 많은 기능을 담고 있다.
- 개인 프로젝트 예시(데코레이터, engine, exceptions 등)를 통해, **커스텀 예외처럼 재사용하고 다른 모듈에서 import해서 쓰고 싶은 코드를 모듈로 분리하는 것이 좋은 사용 사례**임을 보여준다.

## 예시
```
project/
├── __init__.py
├── engine.py
├── exceptions.py     # 커스텀 예외들을 모아두는 모듈
├── main.py
└── network.py
```
- 위 구조처럼, 관련 있는 코드끼리 별도의 `.py` 파일(모듈)로 묶어두면 어디서 무엇을 찾아야 할지 명확해진다.

## 요약
- 모듈 = `.py` 파일. 그 이상도 이하도 아니다.
- 하나의 거대한 파일에 모든 걸 넣는 대신, 관련 있는 코드끼리(예: 예외 처리, 엔진 로직) 별도 모듈로 나누면 코드가 훨씬 정리되고 유지보수하기 쉬워진다.
