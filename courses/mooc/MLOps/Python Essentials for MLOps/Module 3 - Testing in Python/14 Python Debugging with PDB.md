# Python Debugging with PDB

## 개요
- Python 표준 디버거 **PDB**를 pytest와 함께 쓰는 두 가지 방법 — **`pytest --pdb`로 첫 실패 지점에서 자동 진입**하는 법과, **코드에 직접 `pdb.set_trace()`를 심어두는 법** — 을 다루고, PDB 안에서 자주 쓰는 명령(`l`, `n`, `c`)을 소개한다.

## 내용

### `pytest --pdb` — 첫 실패에서 자동으로 디버거 진입
- `pytest --pdb test_failure_output.py`처럼 실행하면, **첫 번째 실패가 발생하는 순간 인터랙티브 PDB 터미널로 진입**한다.
- 진입 메시지로 "Entering PDB"가 뜨고, 어떤 예외(예: RuntimeError)가 발생했는지 보여준다.

### PDB 안에서 쓰는 명령
- **`h`**: 도움말(help) — 사용 가능한 명령어 목록.
- **`l`**(list): 현재 실행 위치 주변 코드를 보여준다. `l 줄번호`처럼 특정 줄 번호를 지정하면 그 주변 컨텍스트를 더 잘 볼 수 있다.
- 변수 이름을 그냥 입력하면 **그 시점의 실제 값을 바로 확인**할 수 있다 (예: `string`을 입력하면 실패 당시 그 변수의 실제 값을 보여줌).
- 실패 지점에서 **직접 코드를 실행해보며(예: `string.split(",")[0]`) 해결책을 그 자리에서 실험**해볼 수 있다 — 문제였던 값을 변형해 실제로 고쳐지는지 즉석에서 검증 가능.
- **`n`**(next): 다음 줄로 이동. **`c`**(continue): 디버깅을 끝내고 계속 실행.

### `pdb.set_trace()` — 코드에 직접 중단점 심기
- 특정 지점에서 항상 멈추고 싶다면, 그 코드(`utils.py`)에 직접 `import pdb; pdb.set_trace()`를 추가하는 방법도 있다.
- **주의**: 이 방식은 그 함수가 호출되는 **모든 테스트마다 매번 멈춘다** — 테스트가 3개면 3번 다 멈추게 되므로 번거로울 수 있다.
- 이 경우 `pytest --pdb` 플래그는 뺀다(`pytest -s`처럼 출력을 그대로 보여주는 옵션과 함께 씀) — 코드 자체에 심어둔 중단점이 우선 동작하기 때문.

### 두 가지 접근의 차이
- **테스트 자체를 디버깅**하고 싶으면 `pytest --pdb`(첫 실패에서 자동 진입).
- **테스트 대상 코드(예: `utils.py`)의 특정 지점**을 디버깅하고 싶으면 그 코드에 직접 `pdb.set_trace()`를 심는 것이 유리.

## 예시
```bash
# 방법 1: 첫 실패에서 자동으로 PDB 진입
pytest --pdb test_failure_output.py
```
```
(Pdb) l                # 현재 위치 주변 코드 확인
(Pdb) string             # 변수 값 확인 → '14,044'
(Pdb) string.split(",")[0]   # 해결책을 즉석에서 실험
(Pdb) c                  # 계속 실행
```
```python
# 방법 2: 코드에 직접 중단점 심기 (utils.py)
import pdb

def string_to_int(value):
    pdb.set_trace()
    return int(float(value))
```

## 요약
- `pytest --pdb`는 첫 실패 지점에서 자동으로 디버거에 진입시켜준다. `l`로 위치 확인, 변수명 입력으로 값 확인, `n`/`c`로 진행 제어.
- 코드에 직접 `pdb.set_trace()`를 심으면 그 지점에서 항상 멈추지만, 관련된 모든 테스트에서 반복적으로 멈추게 된다는 점을 감안해야 한다.
