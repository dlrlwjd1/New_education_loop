# Why a High Accuracy Score Can Be a Lie

## 개요
- 형식: 영상 (약 4분)
- 핵심: **정확도 역설(accuracy paradox).** 그리고 이 강좌에서 가장 값진 부분 — **강사의 실제 실패 사례에 숫자가 붙어 있다.**

## 내용

### 도입
> 정확도 99%인 머신러닝 모델이 **재앙적 실패**일 수 있다고 하면 반직관적으로 들린다. 99%는 다른 어떤 맥락에서든 A+처럼 느껴진다. 하지만 데이터의 세계에서 **높은 정확도는 훨씬 복잡한 진실을 감추는 위험한 거짓**일 수 있다.

### 정확도 역설
사기 탐지 모델을 만든 팀이 몇 주 작업 끝에 정확도 99%를 달성한다. 팀은 축하하고 경영진은 기뻐하며 배포한다. **이 팀은 고전적인 함정에 빠졌다.**

산수로 보면 명확하다.

| 상황 | 결과 |
|---|---|
| 금융 데이터에서 사기는 매우 드물다 — **1,000건 중 1건** | — |
| **모든 거래를 "사기 아님"으로만 예측하는 모델** | 1,000번 중 999번 맞는다 → **정확도 99.9%** |
| 그 모델이 잡은 실제 사기 건수 | **0건** |

> 기술적으로는 정확하지만 **완전히 쓸모없다.** 그 팀의 모델은 **정확해지는 가장 쉬운 방법이 드물지만 결정적으로 중요한 사기 사례를 무시하는 것**임을 학습했다.

### 강사의 실제 사례 — 숫자가 붙은 실패담

결제(payments) 프로젝트에서 첫 사기 모델이 검증셋에서 **정확도 98%** 를 기록했고 모두가 박수쳤다. 배포 1주 후 수동 감사에서 **놓친 고액 차지백(chargeback) 군집**이 발견되었다.

사후 분석 결과:

| 지표 | 값 |
|---|---|
| 사기 유병률(prevalence) | **약 0.6%** |
| 모델의 실제 동작 | 거의 모든 곳에서 "사기 아님"으로 조용히 최적화되어 있었다 |
| **사기에 대한 재현율(recall)** | **0.07** |
| PR-AUC | **거의 무작위 수준** |

> **정확도가 실패를 감췄다(Accuracy hid the failure).**

**재구축 방법 — 네 가지를 바꿨다.**

1. 평가를 **정밀도-재현율 중심으로** 재편
2. **비용 가중 목적함수(cost-weighted objective)** 추가
3. **결정 임계값(decision threshold)을 사업 비용 기준으로** 조정
4. **캘리브레이션(Brier score) 모니터링** — 확률이 실제 의미를 갖도록

**결과:**

| | 변화 |
|---|---|
| 정확도 | 98% → **93% (하락)** |
| **사기 재현율** | **6배 상승** |
| 순손실(net loss) | 첫 달에 측정 가능하게 감소 |

> **그날 이후 나는 단일 숫자를 축하하는 것을 그만두었다.**

### 결론
> 맥락이 전부다. **단일 숫자는 좀처럼 전체 이야기를 말해주지 않는다.** 사기 탐지, **의료 진단, 품질 관리**처럼 불균형 데이터 상황에서 정확도에만 의존하면 비용이 크고 심지어 위험한 결과로 이어질 수 있다.
>
> 다음에 프로젝트나 모델을 평가할 때 **헤드라인 지표에 도전하라.** 스스로 물어라 — **"이 숫자가 진짜로 말해주는 것은 무엇인가? 그리고 더 중요하게, 무엇을 감추고 있는가?"**

## 요약
- **정확도 역설**: 사기가 1/1000이면 "전부 정상"이라 답하는 모델이 정확도 99.9%를 받는다. 잡은 사기는 0건이다.
- 강사의 실제 사례가 이것을 숫자로 확인해 준다 — **정확도 98%, 사기 재현율 0.07, PR-AUC 무작위 수준.**
- 고친 방법은 지표 교체만이 아니다: **정밀도-재현율 중심 평가 + 비용 가중 목적함수 + 사업 비용 기준 임계값 + 캘리브레이션 모니터링.**
- **정확도가 5%p 떨어지는 대가로 사기 재현율이 6배 올랐다.** 이것이 "올바른 지표"의 실질적 의미다.
- 위험 영역: 사기 탐지 · **의료 진단** · 품질 관리 — 모두 소수 클래스가 중요한 문제다.
