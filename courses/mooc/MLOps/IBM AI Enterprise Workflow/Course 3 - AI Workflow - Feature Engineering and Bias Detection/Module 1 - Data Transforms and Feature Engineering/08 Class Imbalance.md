# Class Imbalance

## 개요
- 형식: 읽기 자료 (약 5분)
- 핵심: **정확도(accuracy)는 불균형 클래스에 쓰면 안 되는 지표다.** 왜 안 되는지와 무엇으로 대체하는지를 다룬다.

## 내용

### 암묵적 가정
분류에 쓰이는 많은 ML 알고리즘은 **각 클래스의 예시 수가 비교적 균등하다는 암묵적 가정**을 담고 있다. 스팸 판별이나 이탈 예측용 로지스틱 회귀는 클래스 데이터 수가 비슷할 때 분류가 더 쉽다.

### 균형을 기대할 수 없는 문제들
비즈니스의 전형적인 예는 **사기 탐지(fraud detection)** 다. 대규모 신용카드 처리 업체는 하루 수백만 건을 처리하고, 압도적 다수는 정상 거래다.

### 정확도가 왜 무용한가 — 이 자료의 핵심

> **경고: 정확도는 불균형한 클래스에 적합한 지표가 아니다. F1 점수나 다른 지표를 사용하라.**

숫자로 보면 명확하다. 학습 샘플에서 거래 중 **1%가 사기**라면, **항상 "사기 아님"으로 예측하는 모델은 정확도 99%** 를 보이지만 실질적으로 아무 쓸모가 없다.

### 해결 — 이분법을 네 갈래로 쪼갠다
"정답 대 오답"을 네 가지로 세분한다.

- 진양성 (true positive, TP)
- 진음성 (true negative, TN)
- 거짓양성 (false positive, FP)
- 거짓음성 (false negative, FN)

관례상 **드문 클래스(소수 클래스, 예: 사기)를 양성 클래스로 지정**한다. 그래서 정확도를 대체하는 두 지표의 분자에 진양성이 들어간다.

| 지표 | 식 | 분모에 TN이 있는가 |
|---|---|---|
| 정확도 (accuracy) | (TP+TN) / (TP+FP+TN+FN) | **있다 → 다수 클래스에 압도된다** |
| 정밀도 (precision) | TP / (TP + FP) | 없다 |
| 재현율 (recall) | TP / (TP + FN) | 없다 |
| F1 점수 | 정밀도와 재현율의 **조화평균** | 없다 |

TN이 분자·분모에서 빠지기 때문에 정밀도·재현율이 이 문제에 더 특화된 지표가 된다.

### 지표만으로는 부족하다
더 나은 지표는 **필요조건이지만 충분조건이 아니다.**

단순 로지스틱 회귀는 **거짓음성의 비용과 거짓양성의 비용이 같은** 비용 함수를 최적화한다. 그래서 음성 학습 예시가 훨씬 많으면 결과가 "항상 음성으로 예측"하는 쪽으로 치우친다.

대응 방향은 두 가지다.

1. **비용 함수를 조정**해 오류에 다른 가중치를 준다 (모델마다 적합도가 다르다)
2. **학습 데이터 자체를 조정**해 클래스 균형을 맞춘다 → 업샘플링/다운샘플링

## 요약
- 불균형 상황에서 정확도는 거짓 안심을 준다. 1% 사기 데이터에서 "전부 정상"이라고 답하면 99%가 나온다.
- 원인은 정확도 식의 분자·분모에 **TN이 들어 있어 다수 클래스에 압도되기 때문**이다.
- 대체 지표는 정밀도·재현율·F1이며, 소수 클래스를 양성으로 잡는 것이 관례다.
- 지표를 바꾸는 것만으로는 부족하고, 비용 함수나 데이터 분포 자체를 손대야 한다.
