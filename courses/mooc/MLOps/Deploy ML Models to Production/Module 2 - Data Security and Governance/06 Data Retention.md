# Data Retention

## 개요
- 데이터 생애주기(data lifecycle)의 핵심 개념인 **데이터 보존(Data Retention)**의 5단계 프레임워크(법적 요구사항 이해 → 보존 기간 정의 → 안전한 저장 → 폐기 절차 수립 → 컴플라이언스 모니터링)를 실제 기업 사례와 함께 설명하는 7분 영상.

## 내용

### 1. 법적 요구사항 이해(Understanding Legal Requirements)
- 조직은 먼저 데이터 보존을 규율하는 법적 프레임워크를 이해해야 함 — **GDPR**(유럽), **HIPAA**(의료 분야) 등이 엄격한 경계를 설정. 예: GDPR은 더 이상 필요하지 않은 개인 데이터를 삭제하도록 요구.
- 규정 준수를 위해 법무팀·외부 컨설턴트와 협업해 관련 규제를 조사해야 함.
- **데이터 분류**: 예를 들어 병원 시스템이라면 환자 개인 기록, 운영 로그, 재무 거래 데이터를 각각 다른 보존 요건에 따라 분류해야 함.

### 2. 보존 기간 정의(Defining the Retention Period)
- 보존 기간은 특정 유형의 데이터를 안전하게 삭제하기 전까지 얼마나 보관할지를 정의 — 운영 안정성과 컴플라이언스의 균형이 핵심.
- 예: 재무 데이터는 감사(audit)를 위해 **7년** 보존이 필요할 수 있는 반면, 마케팅 분석 데이터는 **2년**만 유효할 수 있음.
- 명확한 타임라인을 세워야 운영 필요와 규제 요건 모두에 부합.
- **정책 정기 검토**도 중요 — 기술은 진화하고 법은 바뀌며 조직의 우선순위도 변함 — Google 같은 기업은 보존 정책에 대해 주기적으로 감사를 실시.

### 3. 안전한 저장(Secure Storage Solutions)
- 데이터를 안전하게 보관하는 것은 모든 보존 전략의 근간 — 사이버 위협이 증가하는 상황에서 타협할 수 없는 단계.
- **아카이빙 도구 활용**: Dropbox 같은 기업은 암호화를 사용해 데이터를 안전하게 아카이빙하고 승인된 인력·도구만 접근하도록 함.
- 예: 소매점이 고객 데이터를 저장하는 데이터베이스가 다요소 인증이나 암호화로 보호되지 않으면 그 자체로 부채(liability)가 됨 — 안전한 저장은 리스크를 최소화하고 고객 신뢰를 높임.

### 4. 데이터 폐기 절차 수립(Establishing Procedures for Data Disposal)
- 데이터 폐기는 결코 마지막에 대충 처리할 단계가 아님 — 부적절한 폐기는 데이터 유출·침해로 이어질 수 있음.
- **폐기 프로세스 문서화**가 핵심 — 예: 은행은 종이 문서를 파쇄하고, 민감한 파일은 인증된 디지털 삭제 도구를 사용.
- **안전한 삭제 방법 사용**으로 되돌릴 수 없는 삭제 보장 — 예: 하드드라이브용 **DBAN**, **AWS S3 라이프사이클**을 통한 영구 삭제.
- **조직 내 협업 조성**: 데이터 보존은 한 팀만의 책임이 아니라 공동의 노력 — 여러 부서의 이해관계자를 참여시켜 법무·IT·운영 요구를 모두 충족(예: Amazon은 데이터 팀과 법무 자문을 정렬해 보존 정책이 운영 워크플로에 부합하도록 함).
- **직원 교육**: 잘 훈련된 인력이 보존 위반에 대한 첫 번째 방어선 — 예: Google은 데이터 취급 모범 사례에 대한 정기 워크숍 진행.

### 5. 컴플라이언스 모니터링(Monitoring Compliance)
- 보존 정책 수립은 시작에 불과 — 컴플라이언스 모니터링이 준수를 보장.
- **감사 메커니즘 구현**: JP Morgan 같은 금융회사는 빈번한 감사로 규정 준수를 유지.
- **자동화**: Splunk, Datadog 같은 프로그램이 데이터 처리의 이상 징후를 자동으로 플래그 — 예: 보존 기간을 초과해 저장된 파일에 대한 알림을 받아 시간과 법적 리스크를 절감하는 선제적 접근.

### 결론
- 이 5단계는 법적 요구사항 이해에서 안전한 폐기까지 서로 연결된 하나의 견고한 시스템을 이룸 — 데이터 보존은 단순한 규제 체크박스가 아니라 **전략적 이점**.
- ML 모델을 대량의 데이터로 학습시킬 때, 이러한 보존 기법을 이해하는 것은 최종적으로 ML 모델이 어떻게 동작하는지에 매우 중요한 역할을 함.

## 예시
```text
[데이터 보존 5단계 프레임워크]
1. 법적 요구사항 이해 (GDPR, HIPAA) → 데이터 분류
2. 보존 기간 정의 (예: 재무 7년 / 마케팅 2년) → 정기 정책 검토
3. 안전한 저장 (암호화, MFA, 아카이빙 도구)
4. 데이터 폐기 절차 (DBAN, S3 lifecycle, 파쇄) + 조직 협업 + 직원 교육
5. 컴플라이언스 모니터링 (정기 감사, Splunk/Datadog 자동 이상 탐지)
```

## 요약
- 데이터 보존은 법적 요구사항 이해 → 데이터 유형별 보존 기간 정의 → 암호화된 안전한 저장 → 문서화된 안전한 폐기 절차 → 감사·자동화를 통한 컴플라이언스 모니터링이라는 5단계가 서로 맞물려 구성되는 전략적 프레임워크이며, 특히 대량의 데이터로 학습되는 ML 모델의 거동에도 직접적인 영향을 미치는 중요한 요소다.
