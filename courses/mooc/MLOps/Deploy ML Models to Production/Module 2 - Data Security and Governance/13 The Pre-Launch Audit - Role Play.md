# The Pre-Launch Audit — Role Play

## 개요
- 음성 채팅 기반 AI 롤플레이 활동(15분) — 헬스케어 기술 기업의 시니어 MLOps 아키텍트가 되어, 최고 컴플라이언스 책임자(CCO) Gordon에게 진단 모델의 배포 전 'Go/No-Go' 승인을 받는 시뮬레이션. Module 2 전체 내용(BentoML 서빙, 모니터링 도구, 데이터 프라이버시/보안, 데이터 접근 관리, 데이터 보존, GDPR/HIPAA)을 종합적으로 적용해보는 자리.

## 내용

### 시나리오
- 선도적인 헬스케어 기술 기업의 **시니어 MLOps 아키텍트**로서, 팀이 개발한 혁신적인 진단 모델을 **BentoML**로 배포할 준비가 됨.
- 하지만 실제 서비스 전 **최고 컴플라이언스 책임자(Chief Compliance Officer) Gordon**의 승인이 담긴 중요한 'Go/No-Go' 리뷰를 통과해야 함.
- 이 모델은 매우 민감한 환자 데이터를 처리하므로 **HIPAA**와 **GDPR** 표준 준수가 타협 불가능한 요건.
- Gordon은 꼼꼼하지만 지지적이고 협조적인 성격 — 배포 전략을 명확히 설명하고, 모델 버전을 어떻게 관리하며 지속적인 컴플라이언스와 데이터 프라이버시를 어떻게 보장하는지에 초점. Gordon은 특히 기술적 솔루션이 민감 데이터 관련 리스크를 어떻게 완화하는지 이해하고 싶어함.

### 목표
- 신규 진단 모델의 배포 전략과 모니터링 접근법을 CCO에게 성공적으로 설명해 HIPAA·GDPR 컴플라이언스 기준을 충족함을 증명.
- BentoML 배포가 **모델 버전 관리(model versioning)**와 **온라인 서빙(online serving)**을 어떻게 처리하는지 설명.
- **모니터링 스택(Prometheus, Grafana, Evidently)**이 데이터 프라이버시를 침해하지 않으면서 정확도와 컴플라이언스를 어떻게 보장하는지 설명.
- **"침묵의 실패(Silent Failure)"**, 즉 **모델 드리프트(Model Drift)**에 대한 우려 해소.
- **데이터 보존 정책**(환자 데이터 보관 기간, 접근 관리 규칙 준수 방법) 설명.

### 종합 답변 (강의 개념 기반)
- **모델 버전 관리·온라인 서빙 설명**: BentoML로 v1, v2 등 모델 버전을 개별 엔드포인트(`/predict_v1`, `/predict_v2`)로 관리하거나, 하나의 서비스 안에서 여러 러너(runner)를 병합해 블루-그린 방식으로 트래픽을 점진 전환할 수 있음을 설명 — `bentoml models list`로 각 버전을 latest/previous로 추적 가능해 감사(audit) 시 어떤 버전이 어떤 시점에 서빙되었는지 명확히 증명 가능.
- **모니터링 스택으로 정확도·컴플라이언스 보장**: Prometheus로 추론 지연시간·자원 사용률 등 기본 지표를 수집하고, Grafana로 시각화해 팀이 실시간으로 상태를 파악하며, Evidently AI로 데이터 드리프트·모델 드리프트를 정밀 탐지 — 이 모니터링은 익명화된 지표(정확도, 지연시간, 드리프트 점수)만 다루므로 환자 개인 식별 정보(PII) 자체를 노출하지 않아 프라이버시를 침해하지 않음.
- **모델 드리프트("Silent Failure") 대응**: 데이터 드리프트, 타깃 변수 드리프트, 업스트림 데이터 변화 등 여러 형태의 드리프트가 모니터링 없이는 장기간 감지되지 않을 수 있음을 설명 — 조기 모니터링 시작, 명확한 임계값 설정, 여러 신호 교차 검토, 정기 리뷰라는 4대 모범 사례로 이런 침묵의 실패를 방지.
- **데이터 보존 정책 설명**: 법적 요구사항(HIPAA) 이해 → 환자 데이터를 유형별로 분류 → 보존 기간을 명확히 정의(예: 진단 기록은 규제 요건에 따라 특정 연수 보관 후 안전하게 폐기) → 암호화된 안전한 저장 → 문서화된 폐기 절차(인증된 디지털 삭제 도구) → 정기 감사로 컴플라이언스 모니터링.
- **접근 관리 규칙 준수 설명**: 역할 기반 접근 통제(RBAC)로 환자 데이터에 접근 가능한 인원을 최소화(최소 권한 원칙), 다요소 인증과 암호화로 접근 통제, 모든 접근 로그를 남겨 감사 가능하게 함.
- **HIPAA/GDPR 정합성 요약**: HIPAA의 프라이버시·보안·유출 통지 규칙과 GDPR의 데이터 최소화·목적 제한·저장 제한 원칙 모두, 지금 설명한 BentoML 버전 관리 + 모니터링 스택 + 접근 관리 + 데이터 보존 정책이라는 하나의 통합된 아키텍처로 충족됨을 강조.

## 요약
- 이 롤플레이는 "모델 배포를 어떻게 관리하는가"와 "민감한 환자 데이터를 어떻게 안전하게 다루는가"라는 두 축을 연결하는 연습이며, BentoML의 버전 관리·서빙 구조, Prometheus/Grafana/Evidently 모니터링 스택, 데이터 접근 관리와 보존 정책을 하나의 일관된 컴플라이언스 스토리로 엮어 설명하는 것이 핵심이다.
