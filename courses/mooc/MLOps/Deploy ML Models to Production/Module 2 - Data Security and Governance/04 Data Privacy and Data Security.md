# Data Privacy and Data Security

## 개요
- **데이터 프라이버시(Data Privacy)**와 **데이터 보안(Data Security)**의 개념·차이·상호 연관성을 실제 데이터 유출 사례(Yahoo, Aadhaar, Facebook)와 함께 설명하는 10분 영상. Module 2의 도입부.

## 내용

### 데이터 프라이버시란
- 개인의 **개인정보에 대한 권리**에 초점 — 세 가지 핵심 요소:
  1. **수집(Collect)**: 조직이 개인정보를 수집 — 프라이버시 보호가 필수.
  2. **사용(Use)**: 수집된 데이터가 처리되는 방식 — 사용자와 합의된 조건에 맞게 사용되어야 함.
  3. **공유(Share)**: 데이터 공유 관행 — 오용이나 무단 공유는 심각한 프라이버시 침해로 이어질 수 있음.
- 프라이버시는 개인을 보호하기 위한 법률·프로토콜 체계도 포함 — 이름, 연락처, 생체 정보 같은 개인 데이터 보호와 무단 접근 방지가 핵심(강력한 접근 통제 필요).

### 데이터 보안이란
- 프라이버시가 '권리'를 다룬다면, 보안은 **보호 메커니즘**에 초점 — 두 핵심 요소:
  1. **기술적 조치(Technical measures)**: 암호화(encryption), 방화벽(firewall) 등 데이터를 보호하는 도구·기술.
  2. **프로토콜(Protocols)**: 안전한 데이터 저장·공유를 위한 규칙.
- 데이터를 생애주기 전반에서 조직이 통제하도록 보장하고, 해커 등 악의적 행위자의 취약점 악용을 방지.

### 실제 데이터 유출 사례
1. **Yahoo 유출(2013년 8월)**: 약 **30억 개 계정** 노출. 결제 데이터는 도난당하지 않았지만 개인 계정 정보가 유출되어 선제적 보안 조치의 중요성을 부각.
2. **Aadhaar 유출(2018년 1월)**: 인도 시민 **11억 명 이상**의 신원·생체 정보 노출. **취약한 API 보안**이 원인 — 강력한 접근 통제 정책과 암호화 프로토콜의 중요성을 강조.
3. **Facebook 유출(2019년 4월)**: **5억 3,300만 개** 계정 영향. 전화번호와 계정 ID가 인터넷에 공개적으로 노출 — 사용자 데이터에 대한 정기적인 감사(audit)와 보안의 중요성 강조.

### 컴플라이언스(Compliance)
- 데이터 프라이버시: 법적 프레임워크를 통한 개인정보 보호 — **동의(Consent)**가 핵심(개인이 데이터 사용에 동의해야 함), **GDPR·CPPA** 등 규제 프레임워크가 전 세계적 프라이버시·컴플라이언스 기준을 제공.
- 데이터 보안: 다양한 전략적 접근으로 개인·조직 데이터를 무단 접근·유출·오용으로부터 보호.
  - **암호화(Encryption)**: 민감한 데이터를 무단 사용자가 해석할 수 없는 형식으로 인코딩 — 데이터가 가로채여도 올바른 키 없이는 읽을 수 없음.
  - **접근 통제(Access Control)**: 승인된 개인·시스템만 데이터를 조회·조작할 수 있도록 해 오용이나 우발적 노출을 방지하는 계층 추가.
  - **네트워크 보안(Network Security)**: 사이버 공격으로부터 기반 시스템·네트워크를 보호해 조직 자원에 대한 중단 없는 안전한 접근을 보장.

### 프라이버시 vs 보안 핵심 차이
| 구분 | 데이터 프라이버시 | 데이터 보안 |
|---|---|---|
| 초점 | 개인의 권리 — 개인정보의 수집·공유·사용 통제 | 데이터 자체를 유출·무단 접근으로부터 보호 |
| 범위 | GDPR·CPPA 같은 법률 프레임워크, 사용자 동의·규제 준수 | 방화벽, 암호화, 네트워크 방어 같은 기술적 통제 |
| 목표 | 데이터가 윤리적·책임감 있게 다뤄지도록 보장 | 데이터의 도난·손상·손실을 방지하고 가용성·무결성 보장 |

### 프라이버시와 보안의 상호 연관성
- **데이터 프라이버시는 데이터 보안에 의존** — 데이터를 저장·관리하는 시스템이 안전하지 않으면 프라이버시 규정·관행은 효과를 발휘할 수 없음. 견고한 보안 조치(감사, 강력한 암호화, 통제된 접근)가 없으면 유출 위험이 프라이버시를 훼손함.
- 감사(audit), 견고한 암호화, 통제된 접근 같은 보안 조치가 개인정보의 기밀성·변조 방지·승인된 사용자만의 접근을 보장하는 **신뢰와 컴플라이언스의 기반**이 됨.
- 프라이버시 정책은 충분한 보안 조치 없이는 시행될 수 없음 — 예: 방화벽, 탐지 시스템, 보안 프로토콜 같은 기술을 구현해야 프라이버시 약속을 이행 가능. 프라이버시 중심 정책과 기술 중심 보안 조치를 결합해야 프라이버시 목표와 운영을 효과적으로 정렬 가능.

### 모범 사례 3가지
1. **정기적인 감사(Regular Audits)**: 시스템·프로세스의 취약점을 파악해 보안·규정 준수 상태 유지 — 공격자가 악용하기 전에 허점을 발견.
2. **직원 교육(Employee Training)**: 고객 데이터를 포함한 조직 데이터를 다루는 방법에 대해 모든 직원을 교육.
3. **사고 대응 계획(Incident Response Plans)**: 데이터 유출(또는 유출 의심 보고) 발생 시 견고한 대응 계획 필요 — 어떤 팀이 관여할지, 어떻게 탐지할지, 예를 들어 고객 데이터 유출이라면 해당 데이터가 어디 저장되어 있고 누가 접근 권한이 있는지 파악하고 로그를 통해 모든 사용자 행위를 추적해야 함.

## 예시
```text
[데이터 프라이버시] ←── 의존 ──── [데이터 보안]
  (개인의 권리: 수집/사용/공유 통제)      (보호 메커니즘: 암호화/접근통제/네트워크 보안)

법률 프레임워크: GDPR, CPPA           기술적 통제: 방화벽, 암호화, 감사
동의(Consent) 기반                      기밀성·무결성·가용성 보장
```

```text
데이터 사고 예방 3원칙:
1. 정기 감사(Regular Audits) — 취약점 사전 발견
2. 직원 교육(Employee Training) — 데이터 취급 역량 강화
3. 사고 대응 계획(Incident Response Plans) — 유출 시 신속·체계적 대응
```

## 요약
- 데이터 프라이버시는 개인정보의 수집·사용·공유에 대한 개인의 권리(GDPR·CPPA 등 법률 기반)를, 데이터 보안은 암호화·접근통제·네트워크 보안 같은 기술적 조치로 데이터 자체를 보호하는 것을 의미하며, 둘은 서로 의존적인 관계(보안 없이는 프라이버시가 실현될 수 없음)로 Yahoo·Aadhaar·Facebook 사례처럼 취약한 보안은 곧 대규모 프라이버시 침해로 이어지므로 정기 감사·직원 교육·사고 대응 계획을 갖춰야 한다.
