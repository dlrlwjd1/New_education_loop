# PCI Compliance

## 개요
- 신용카드 결제 정보를 다루는 기업이 반드시 준수해야 하는 **PCI DSS(Payment Card Industry Data Security Standards)**의 핵심 혜택과 미준수 시 결과, 그리고 사기 탐지 ML 모델 개발과의 관련성을 다루는 4분 영상.

## 내용

### PCI DSS란
- **PCI DSS**: 2004년 제정, 신용카드 정보를 수용·처리·저장·전송하는 모든 기업이 안전한 환경을 유지하도록 보장.
- 온라인 쇼핑에서 신용카드를 사용할 때마다 PCI가 그 거래를 보호함 — 이러한 표준이 없다면 사이버 범죄자가 결제 시스템의 취약점을 악용해 금융 사기를 저지를 수 있음.

### PCI 준수의 핵심 혜택
1. **안전한 네트워크 구축·유지**: 방화벽 설치, 기본 비밀번호 변경 등으로 카드 소지자 데이터 보호 — 예: 소매업체가 무단 접근 시도를 차단하는 방화벽 구축.
2. **카드 소지자 데이터 보호**: 결제 처리업체가 온라인 거래 중 신용카드 정보를 암호화하는 것이 실제 예시.
3. **취약점 관리 프로그램 유지**: 백신 소프트웨어 사용, 시스템 최신 상태 유지 — 예: 전자상거래 플랫폼이 새로운 위협에 대응해 보안 소프트웨어를 정기적으로 업데이트.
4. **강력한 접근 통제 조치 구현**: 카드 소지자 데이터에 접근이 필요한 사람만 접근 가능하도록 함 — 예: 직원에게 고유 ID를 부여해 책임 소재를 명확히 함.
5. **네트워크 정기 모니터링·테스트**: 자원 접근을 모니터링하고 정기적인 보안 점검 수행 — 예: 결제 게이트웨이가 서버에 대한 모든 접근 시도를 추적.
6. **정보 보안 정책 유지**: 보안 프로토콜을 문서화하고 직원에게 전달해 고객 데이터 보호에서 각자의 역할을 이해하도록 함.

### 미준수 시 결과
- PCI 미준수는 심각한 결과로 이어질 수 있음: 결제 카드 제공업체로부터의 벌금, 더 높은 거래 수수료, 심지어 신용카드 결제 처리 능력 자체를 상실할 수 있음.
- 예: 데이터 유출을 겪은 소규모 기업은 벌금뿐 아니라 고객 신뢰까지 잃을 수 있음.
- 교훈: 컴플라이언스는 선택이 아니라 기업과 고객 모두를 보호하는 데 필수적임.

### MLOps 엔지니어와의 관련성
- 금융 사기 탐지(financial fraud) 관련 ML 모델을 다룰 때: 이 모델을 학습시키기 위해 사용하는 데이터가 어디서 왔는지, 그 데이터가 PCI를 준수하는지, PCI 규정에 부합하지 않는 고객 정보를 포함하고 있지는 않은지를 반드시 확인해야 함.
- 이런 정보는 사기 탐지 관련 모델을 구축할 때 매우 중요함.

## 예시
```text
[PCI 준수 6대 혜택]
1. 안전한 네트워크(방화벽, 기본 비밀번호 변경)
2. 카드 소지자 데이터 암호화
3. 취약점 관리(백신, 시스템 업데이트)
4. 강력한 접근 통제(고유 ID 부여)
5. 정기 모니터링·테스트(접근 로그 추적)
6. 정보 보안 정책 문서화·전파

[미준수 결과]
벌금 → 거래 수수료 인상 → 카드 결제 처리 자격 상실 → 고객 신뢰 상실
```

## 요약
- PCI DSS는 신용카드 정보를 다루는 모든 기업이 안전한 네트워크·데이터 암호화·취약점 관리·접근 통제·모니터링·보안 정책 문서화라는 6가지 조치를 통해 결제 데이터를 보호하도록 요구하며, 미준수 시 벌금과 결제 처리 자격 상실로 이어질 수 있으므로, 금융 사기 탐지 ML 모델을 구축하는 MLOps 엔지니어는 학습 데이터의 출처와 PCI 준수 여부를 반드시 확인해야 한다.
