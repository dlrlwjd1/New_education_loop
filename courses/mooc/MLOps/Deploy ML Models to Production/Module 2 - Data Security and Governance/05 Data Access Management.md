# Data Access Management

## 개요
- **데이터 접근 관리(Data Access Management, DAM)**의 핵심 개념·구성 요소·구현 방법·모범 사례를 다루는 7분 영상.

## 내용

### 데이터 접근 관리의 핵심 축(pillars)
1. **자동화된 계정 매핑(Automated Account Mapping)**: 직원 계정을 필요한 리소스에 자동 연결 — 예: 신규 입사자가 역할에 맞는 툴·플랫폼 접근 권한을 자동으로 부여받음.
2. **온디맨드 권한 부여(On-Demand Permission Grants)**: 사용자가 리소스에 대한 임시 접근을 요청·부여받을 수 있게 함 — 예: 개발자가 트러블슈팅을 위해 프로덕션 데이터베이스 접근을 요청하고, 일정 기간 후 자동으로 권한이 회수됨.
3. **거버넌스 규칙 적용(Governance Rule Application)**: 접근 정책이 규제 요건(GDPR, PCI 등)에 부합하도록 보장 — 예: 금융기관이 거버넌스 규칙으로 민감 데이터 접근을 제한.
4. **통합 신원 검증(Unified Identity Verification)**: 비밀번호, 생체인증, 기기 인식 등 여러 인증 요소를 하나의 매끄러운 프로세스로 통합.
5. **지속적 모니터링과 인사이트(Continuous Monitoring and Insights)**: 누가 언제 어떤 데이터에 접근하는지 실시간 가시성 제공 — 예: 제한된 정보에 접근 시도가 있으면 보안팀에 알림.
6. **적응형 접근 제어(Adaptive Access Control)**: 위치나 기기 같은 맥락(context)에 따라 접근 권한을 동적으로 조정 — 예: 새로운 국가에서 로그인 시 추가 인증 요구.

### 효과적인 데이터 접근 관리의 핵심 구성 요소
- **접근 통제 조치(Access Control Measures)**: 다요소 인증(MFA), 생체 인증 등 활용 — 예: 직원이 비밀번호와 지문을 모두 사용해 로그인.
- **데이터 분류(Data Classification)**: 민감도에 따라 데이터를 공개(public)/기밀(confidential)/제한(restricted)로 분류 — 예: 병원이 환자 의료 기록을 기밀로, 일반 공지는 공개로 분류.
- **안전한 데이터 처리(Secure Data Handling)**: 저장(at rest) 및 전송(in transit) 중인 데이터 암호화 — 예: 은행이 데이터베이스와 온라인 거래 중 데이터를 암호화.
- **사용자 교육과 인식(User Training and Awareness)**: 인간 오류를 최소화하는 핵심 요소 — 예: 정기 워크숍으로 피싱 시도 식별, 민감 데이터의 책임감 있는 관리 교육.

### 구현 방법
1. **견고한 정책 수립**: 누가 무엇을 어떤 조건에서 접근할 수 있는지 명시 — 예: HR 정책상 급여 정보는 급여 담당 직원만 접근 가능.
2. **접근 통제 모델 활용**:
   - **역할 기반 접근 통제(Role-Based Access Control, RBAC)**: 직무 역할에 따라 접근 권한 부여.
   - **임의 접근 통제(Discretionary Access Control, DAC)**: 리소스 소유자가 접근 권한을 결정 — 예: 프로젝트 매니저가 공유 문서 편집 권한자를 결정.
   - **강제 접근 통제(Mandatory Access Control, MAC)**: 조직 전체에 걸쳐 인가 등급(clearance level)에 따른 더 엄격한 접근 통제 — 군사 환경에서 가장 흔함.
3. **자동화된 신원 관리(Automated Identity Management)**: 수동 오류를 줄임 — 예: 퇴사자의 접근 권한을 자동 도구로 즉시 회수.
4. **정기 감사와 모니터링**: 무단 접근 시도를 식별 — 예: 감사를 통해 접근 권한이 없는 사용자의 시스템 접근이 드러나 신속한 시정 조치 가능.

### 모범 사례
1. **최소 권한 원칙(Principle of Least Privilege)**: 사용자에게 업무에 필요한 최소한의 접근 권한만 부여 — 예: 마케팅 인턴은 재무 보고서에 접근할 필요 없음.
2. **정기적인 권한 검토**: 접근 권한이 여전히 타당한지 정기 확인 — 예: 영업에서 인사로 부서 이동한 직원은 더 이상 영업 데이터 접근 권한이 없어야 함.
3. **포괄적인 로깅(Comprehensive Logging)**: 누가 언제 무엇에 접근했는지 상세 기록 유지 — 감사·조사에 필수적 — 예: 로그를 통해 유출이 무단 접근인지 내부 오류인지 파악.
4. **지속적인 직원 교육**: 데이터 보안 모범 사례에 대해 지속적으로 교육.

### 결론
- 데이터 접근 관리는 단순히 데이터를 보호하는 것을 넘어, 조직이 효과적이고 안전하게 운영될 수 있게 하는 것 — 프로세스 자동화, 견고한 통제 적용, 지속적 모니터링과 교육을 통해 안전하고 규정을 준수하며 매끄러운 데이터 환경을 달성할 수 있음.

## 예시
```text
[데이터 접근 관리 6대 축]
자동화된 계정 매핑 → 온디맨드 권한 부여 → 거버넌스 규칙 적용
→ 통합 신원 검증 → 지속적 모니터링 → 적응형 접근 제어
```

| 접근 통제 모델 | 특징 | 예시 |
|---|---|---|
| RBAC (역할 기반) | 직무 역할에 따라 권한 부여 | 회계 담당자만 재무 시스템 접근 |
| DAC (임의) | 리소스 소유자가 권한 결정 | 프로젝트 매니저가 문서 편집자 지정 |
| MAC (강제) | 조직 전체 인가 등급 기반, 가장 엄격 | 군사 환경의 클리어런스 레벨 |

## 요약
- 데이터 접근 관리는 자동화된 계정 매핑·온디맨드 권한·거버넌스 규칙·통합 신원 검증·지속적 모니터링·적응형 접근 제어라는 6가지 축과, 접근 통제 조치·데이터 분류·안전한 데이터 처리·사용자 교육이라는 핵심 구성 요소를 바탕으로 RBAC/DAC/MAC 같은 접근 통제 모델을 적용하며, 최소 권한 원칙·정기 검토·포괄적 로깅·지속적 교육을 모범 사례로 삼아 안전하고 규정을 준수하는 데이터 환경을 구축하는 것을 목표로 한다.
