# Monitoring Tools (Prometheus, Grafana, Evidently)

## 개요
- 배포 이후 ML 모델을 모니터링해야 하는 이유, 추적해야 할 핵심 지표, 모니터링 모범 사례, 그리고 Prometheus·Grafana·Evidently AI·New Relic 등 대표 도구를 소개하는 5분 영상.

## 내용

### ML 모니터링이 필요한 이유
- 약국 재고 예측 예시로 돌아가서: 창고 운영자가 의존하는 예측 대시보드는 Kubernetes 클러스터에 배포되어 있고, 대시보드(퍼블릭 도메인)에서 클러스터로 100% 트래픽이 흐름 → 이 애플리케이션들을 모니터링해야 하며, 이 모니터링은 일반 네임스페이스뿐 아니라 **ML 서빙 레이어**에도 동일하게 적용되어야 함.
- ML 모니터링은 배포 이후 발생하는 머신러닝 생애주기의 **중요한 단계**.

### 모니터링이 필요한 3가지 근본 이유
1. **성능과 유지보수(Performance and Maintenance)**: 모델의 건강 검진과 같음 — 예: 신용평가 모델의 정확도가 3개월 사이 경제 상황 변화로 95%에서 85%로 떨어졌다면 즉시 알아야 함.
2. **문제 감소(Reduction of Issues)**: 단순 성능 지표를 넘어서는 문제 — 예: 추천 시스템이 계절적 변화로 인해 특정 카테고리에 편향을 보이기 시작하는 경우, 적절한 모니터링 없이는 몇 달간 감지되지 않을 수 있음.
3. **피드백 루프(Feedback Loop)**: 모델의 지속적 개선 사이클 — 예: 사기 탐지 시스템에서 모니터링을 통해 어떤 거짓 양성(false positive)이 가장 흔한지 파악해 더 나은 데이터로 재학습 가능.

### 추적해야 할 핵심 지표
1. **정확도(Accuracy)**: 전체 정확도뿐 아니라 클래스별 정확도(pre-class accuracy), 혼동 행렬(confusion matrix) 추이, 신뢰도 점수 분포(confidence score distribution) 등도 함께 추적 — 예: 프로덕션 이미지 분류 모델.
2. **데이터 품질(Data Quality)**: 피처 드리프트, 결측값 패턴, 데이터 스키마 진화 — 예: 센서 데이터 처리 시 예상된 값의 범위를 벗어나는지 확인.
3. **자원 사용률(Resource Utilization)**: 추론 지연시간(inference latency), 메모리 사용량, GPU 사용률 모니터링 — 지연시간이 갑자기 급증하면 데이터 전처리 병목(bottleneck)을 의미할 수 있음.

### 4가지 핵심 모범 사례
1. **모니터링을 일찍 시작하라**: 모델 검증(validation) 단계부터 시작 — 프로덕션 이슈가 될 때까지 기다리지 말 것.
2. **임계값(threshold) 설정**: 성능 저하, 데이터 드리프트, 시스템 자원 사용률에 대한 명확한 경계 설정.
3. **여러 신호를 종합하라**: 서로 다른 지표들을 교차 참조 — 예: 정확도가 떨어지면 데이터 드리프트나 자원 제약과 상관관계가 있는지 확인.
4. **정기적인 검토(Regular Review) 필수**: 모니터링 지표를 체계적으로 정기 검토 — 자동화된 알림에만 의존하지 말 것.

### 특화 도구 소개
- **Prometheus**: DevOps 세계에서도 유명한 모니터링 도구 — 뛰어난 시계열(time series) 모니터링 시스템으로, 모델 모니터링에도 활용 가능.
- **Evidently AI**: ML 모니터링과 드리프트 탐지에 특화.
- **Grafana**: Prometheus 위에 훌륭한 시각화와 대시보딩 기능 추가.
- **New Relic**: 모델에 대한 엔드투엔드 관측 가능성(observability) 제공.
- 조합 예: Prometheus로 기본 지표 수집 → Grafana로 시각화 → Evidently AI로 정교한 데이터 드리프트 탐지.

### 결론
- 모델 모니터링은 일회성 설정이 아니라 **지속적인 프로세스** — 작게 시작해 핵심 지표에 집중하고, 점진적으로 배포된 모델에 대한 신뢰를 주는 포괄적인 모니터링 시스템을 구축해 나가야 함.

## 예시
```text
[모니터링 도구 조합 예시]
Prometheus (기본 지표 수집: latency, 자원 사용률)
        │
        ▼
Grafana (시각화·대시보딩)
        │
        ▼
Evidently AI (데이터 드리프트·모델 드리프트 정밀 탐지)
```

| 지표 범주 | 세부 항목 |
|---|---|
| 정확도 | 클래스별 정확도, 혼동 행렬 추이, 신뢰도 점수 분포 |
| 데이터 품질 | 피처 드리프트, 결측값 패턴, 스키마 진화 |
| 자원 사용률 | 추론 지연시간, 메모리 사용량, GPU 사용률 |

## 요약
- ML 모델 모니터링은 성능 유지, 문제 조기 발견, 피드백 루프 형성을 위해 배포 후 반드시 수행해야 하는 지속적 프로세스이며, 정확도·데이터 품질·자원 사용률을 핵심 지표로 삼아 Prometheus(수집)·Grafana(시각화)·Evidently AI(드리프트 탐지) 같은 도구를 조합해 일찍부터, 임계값을 세워, 여러 신호를 교차 검토하며 정기적으로 운영해야 한다.
