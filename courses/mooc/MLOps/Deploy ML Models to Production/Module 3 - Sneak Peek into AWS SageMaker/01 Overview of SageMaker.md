# Overview of SageMaker

## 개요
- MLOps 생애주기 전체를 다시 정리하고, ML 개발 과정에서 흔히 겪는 문제(표준화 부재, 모델 복잡성, 도구 과부하)와 이를 완전관리형 서비스인 **AWS SageMaker**가 어떻게 해결하는지 소개하는 6분 영상. Module 3 전체의 도입부.

## 내용

### MLOps 생애주기 재정리 (High-Level Architecture)
1. **문제 정의(Problem Statement)** → 데이터 수집·수집(ingestion)·변환·정제 → 데이터 분석·시각화 — 예: 사기 탐지(fraud detection) 문제라면 관련 데이터를 수집하고 여러 소스에서 가져와 변환·정제한 후 분석.
2. **결정 지점 1**: 이 문제에 **ML 모델이 필요한가?**
   - 아니오 → 문제 정의로 돌아가 다른 해결 방법 모색.
   - 예 → 피처 엔지니어링, 모델 탐색, 모델 구축, 모델 학습, 모델 평가로 진행.
3. **결정 지점 2**: 개발된 ML 모델이 **문제를 실제로 해결하는가?**
   - 아마도(maybe) → 피처 엔지니어링으로 돌아가 몇 차례 재학습.
   - 아니오 → 문제 정의 자체를 재정의.
   - 예 → 모델 개발 완료 → **모델 배포**, **모델 모니터링·디버깅**으로 진행 → 최신 데이터로 **지속적인 모델 재학습(continuous training)**까지 이어짐.
- 이 모든 단계에 **MLOps 엔지니어**가 관여함.

### ML 개발 생애주기의 공통 문제
1. **표준화 부재(Lack of Standardization)**: 일관성 없는 워크플로가 비효율을 초래 — 예: 팀마다 데이터 전처리 단계가 달라 데이터의 다양성, 결국 모델 결과물의 다양성으로 이어짐.
2. **모델 자체의 복잡성**: ML 모델 배포는 번거롭고 오류가 발생하기 쉬움 — 모델을 배포할 때마다 의존성과 환경 설정을 수동으로 관리하는 것은 매우 어려움.
3. **도구 과부하(Tools Overload)**: MLOps 생태계를 유지하기 위해 필요한 도구가 너무 많아 상당한 운영 부담 발생 — 파편화된 파이프라인과 생산성 저하로 이어짐. 이 코스 전체에서 배운 수많은 오픈소스 도구들(MLflow, BentoML, Prometheus, Grafana, Evidently 등)을 조직이 20~30개의 ML 모델을 위해 직접 배포·유지한다고 상상하면 이는 분명 큰 부담.

### AWS SageMaker의 해결 방식
- SageMaker는 이런 과제를 해결하기 위한 **완전관리형 서비스(fully managed service)** — 모델 구축부터 개발까지 머신러닝 생애주기를 단순화.
- 엔드투엔드 ML 워크플로에 맞춘 인프라와 도구를 제공 — ML을 처음 시작하든 프로덕션급 파이프라인을 관리하든 SageMaker의 기능으로 대응 가능.

### SageMaker의 핵심 기능 (앞서 언급한 문제 해결 방식)
1. **표준화(Standardization)**: 사전 구축된 알고리즘이나 커스텀 모델을 균일한 배포 파이프라인으로 사용해 팀 간 워크플로를 표준화하고 일관성 확보.
2. **단순화된 배포 프로세스**: 원클릭 배포(one-click deployment)로 인프라 관리의 복잡성 제거 — 모델을 실시간으로 모니터링·디버깅해 최적의 성능 보장, 데이터 드리프트나 성능 저하에 대한 알림 설정 가능.
3. **협업**: 팀이 동일 프로젝트에서 버전 관리와 공유를 위한 중앙화된 도구를 활용해 협업 가능.
4. **자동 확장(Auto-Scaling)**: 수요에 따라 인프라가 자동으로 확장 — 추가 컴퓨팅 자원 프로비저닝을 걱정할 필요 없음. 컴퓨터 비전 모델처럼 대량의 GPU가 필요한 학습에서 특히 중요.
5. **재현성(Reproducibility)**: 데이터, 코드, 설정의 변경 사항을 쉽게 추적해 코드의 재현성 보장 — 예: 사기 탐지 모델의 여러 실험 반복(iteration)을 유지 관리. 이는 오픈소스 도구인 MLflow로도 달성했지만 AWS SageMaker도 동일하게 제공.
6. **CI/CD 통합**: SageMaker가 AWS 클라우드 환경 내부에 있으므로, 배포가 EKS·EC2에 있고 S3 같은 다른 AWS 서비스와 상호작용해야 할 때 이런 통합이 쉬움. AWS 클라우드 환경 외부로도 배포할 수 있는 견고한 CI/CD 통합도 제공.

## 예시
```text
[MLOps 생애주기 흐름]
문제 정의 → 데이터 수집·변환·정제 → 데이터 분석·시각화
        │
        ▼
   [ML 모델이 필요한가?] ──아니오──▶ 문제 정의로 복귀
        │ 예
        ▼
피처 엔지니어링 → 모델 탐색·구축·학습 → 모델 평가
        │
        ▼
   [모델이 문제를 해결하는가?] ──아니오──▶ 문제 재정의
        │ ──마이비──▶ 피처 엔지니어링으로 복귀(재학습)
        │ 예
        ▼
모델 배포 → 모니터링·디버깅 → 최신 데이터로 지속적 재학습
```

| ML 개발의 공통 문제 | SageMaker의 해결책 |
|---|---|
| 표준화 부재 | 사전 구축 알고리즘 + 균일한 배포 파이프라인 |
| 모델 복잡성(배포 어려움) | 원클릭 배포, 실시간 모니터링·디버깅 |
| 도구 과부하 | 단일 완전관리형 플랫폼으로 통합(버전 관리·자동 확장·CI/CD 포함) |

## 요약
- MLOps 생애주기는 문제 정의부터 지속적 재학습까지 여러 결정 지점을 거치는 반복적 과정이며, 이 과정에서 표준화 부재·모델 복잡성·도구 과부하라는 공통 문제가 발생하는데, AWS SageMaker는 표준화된 배포 파이프라인, 원클릭 배포와 실시간 모니터링, 협업 도구, 자동 확장, 재현성 추적, CI/CD 통합을 갖춘 완전관리형 서비스로 이런 문제를 해결한다.
