# Describe OAuth2

## 개요
- **OAuth2** 의 정의(인가 프로토콜이며 인증 프로토콜이 아님), 세 구성 요소(client·resource server·authorization server), 그리고 4단계 동작 흐름을 설명하는 강의

## 내용

### OAuth2란
- **Open Authorization** 의 약자다.
- 웹사이트나 애플리케이션이 **원격 API나 사용자 데이터 같은 자원 집합에 접근**하도록 설계된 표준이다.
- **Facebook, Gmail, GitHub** 같은 **외부 서비스 제공자**를 이용해 애플리케이션의 사용자를 **인가**하는 인가 프로토콜이다.
- **OAuth2는 인가(authorization) 프로토콜이며 인증(authentication) 프로토콜이 아니다** — 이 점이 중요하다.
- **클라이언트 개발자의 단순성**에 초점을 두면서 **웹·데스크톱·모바일 애플리케이션**에 특정한 인가 흐름을 제공한다.

### 세 구성 요소
| 구성 요소 | 설명 |
|---|---|
| **클라이언트(client)** | 로그인하려는 사람·사용자. 즉 **보호된 자원에 접근이 필요한 시스템**. 자원에 접근하려면 적절한 **액세스 토큰**을 가져야 한다 |
| **자원 서버(resource server)** | 클라이언트가 로그인해 데이터에 접근하려는 **애플리케이션**. 클라이언트의 액세스 토큰을 **받아 검증**하고 적절한 자원을 돌려준다 |
| **인가 서버(authorization server)** | 사용자 신원을 인증하는 **외부 애플리케이션** — Facebook, GitHub, Gmail 등. 클라이언트의 액세스 토큰 요청을 받아 **인증 성공과 자원 소유자의 동의 후 토큰을 발행**한다 |

### 동작 4단계
1. **클라이언트가 인가 서버에 인가를 요청**하며 식별용 자격 증명을 제공한다.
2. **인가 서버가 클라이언트를 인증**하고 요청이 허용됨을 확인해 **액세스 토큰을 부여**한다.
3. 액세스 토큰을 받은 **클라이언트가 자원 서버에 자원 X 접근을 요청**한다.
4. **자원 서버가 액세스 토큰의 유효성을 검증**한 뒤 클라이언트에 자원 X 접근을 제공한다.

## 예시
```text
        ① 인가 요청 (자격 증명)
클라이언트 ──────────────────▶ 인가 서버 (GitHub · Google · Facebook)
클라이언트 ◀────────────────── ② 인증 + 동의 → 액세스 토큰
        ③ 자원 X 요청 + 액세스 토큰
클라이언트 ──────────────────▶ 자원 서버 (내 앱)
클라이언트 ◀────────────────── ④ 토큰 검증 → 자원 X
```

| | OAuth2 | JWT |
|---|---|---|
| 본질 | **인가** 프로토콜 | 토큰 **형식**·인증 표준 |
| 누가 신원을 확인 | 외부 인가 서버 | 내 인증 서버 |

## 요약
- OAuth2는 Facebook·Gmail·GitHub 같은 외부 제공자로 사용자를 인가하는 개방형 표준이며, 인가 프로토콜이지 인증 프로토콜이 아니다.
- 클라이언트(토큰이 필요한 시스템), 자원 서버(토큰을 검증해 자원을 주는 앱), 인가 서버(신원을 인증하고 토큰을 발행하는 외부 앱) 세 요소로 이뤄진다.
- 흐름은 인가 요청 → 인증·동의 후 토큰 부여 → 토큰으로 자원 요청 → 토큰 검증 후 자원 제공 4단계다.
