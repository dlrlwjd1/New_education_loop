# Context Setting

## 개요
- 캡스톤 프로젝트의 취지를 설명하는 강의
- 전문과정에서 배운 백엔드 서비스 구축 도구·기법을 하나의 비자명한(non-trivial) 풀스택 프로젝트에 적용한다.

## 내용

### 왜 캡스톤인가
- 이 전문과정에서 백엔드 서비스를 만드는 도구와 기법을 배웠다. 과제를 해결할 때는 **각 개념이 어떤 목표를 달성하는 데 도움이 됐는지** 이해해야 한다.
- 캡스톤은 다음 질문에 스스로 답해 보게 한다:
  - 소비자 대상 백엔드 서비스를 만들 때 **불필요한 재작업(rework)을 피하려면 어디서 시작해야 하는가?**
  - 실무 프로젝트는 대개 비자명하다. **복잡한 요구사항을 더 단순한 것들로 어떻게 분해하는가?**
  - 솔루션 개발에 어떤 접근법을 따를 것인가?
  - 명시된 요구사항이 모두 올바르게 구현됐음을 어떻게 보장하는가?
  - 프로젝트 리뷰와 리팩터링(refactoring) 과정을 어떻게 경험하는가?
- 처음부터 직접 만들어 보는 경험이 자신감을 키운다.

### 과제 상황
- Node.js 개발자로서 **mealDrop 애플리케이션의 백엔드 서비스**를 만드는 풀스택 프로젝트를 배정받았다.
- 개발 전에 생각해 볼 질문:
  - 실무 풀스택 프로젝트는 어떤 모습인가?
  - 풀스택 개발자로서 프로젝트에 어떻게 접근하는가?
  - 그런 과제를 다룰 준비가 되었는가?
  - 비자명한 풀스택 프로젝트를 해 보지 않고도 그런 과제를 다룰 수 있는가?

### 풀스택 개발자란
- **프런트엔드와 백엔드 기술 모두에 능숙한** 개발자다.
- 추가로 **일부 DevOps 작업도 수행할 수 있다.**

### 이 프로젝트에서 해야 할 일
- 지금까지 배운 모든 기술과 지식을 적용해 비자명한 풀스택 프로젝트를 완성한다.
- 실제 프로젝트로 여기고 **요구사항 분석 → 설계 → 코딩 → 테스트**를 수행한다.
- 여기에 **리뷰(review), 리팩터링(refactor), 통합(integration)** 까지 포함한다.

### 개발 방법론
- 이 프로젝트는 **애자일(Agile) 개발 방법론**으로 진행한다.
- 애자일 소프트웨어 개발은 **반복적 개발(iterative development)** 개념을 중심에 둔 방법론들을 가리킨다.
- 여기서 요구사항과 솔루션은 **자기조직적(self-organizing)·다기능(cross-functional) 팀 간의 협업을 통해 진화**한다.

## 예시
```text
캡스톤 진행 흐름
요구사항 분석 → 설계 → 코딩 → 테스트 → 리뷰 → 리팩터링 → 통합
        ↑                                              │
        └──────── 애자일: 반복적 개발로 순환 ───────────┘
```

## 요약
- 캡스톤은 배운 것을 하나의 비자명한 풀스택 프로젝트로 통합해 실무 자신감을 만드는 과정이다.
- 과제는 mealDrop 앱의 백엔드 서비스 개발이며, 요구사항 분석부터 통합까지 전 과정을 직접 수행한다.
- 애자일 방법론으로 진행하며, 요구사항과 솔루션은 반복과 협업을 통해 진화한다.
