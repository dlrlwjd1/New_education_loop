# Explore microservices communication

## 개요
- 마이크로서비스 통신의 두 유형(동기·비동기)을 정의하고 차이를 정리하는 강의

## 내용

### 왜 프로세스 간 통신이 필요한가
- 마이크로서비스 아키텍처 패턴은 **서로 다른 머신에서 프로세스 또는 서비스로 실행되는 분산 시스템(distributed system)** 이다.
- 클라이언트 요청을 효과적으로 처리하려면 **시스템의 컴포넌트들이 서로 상호작용하는 것이 중요하다.**
- 서비스들은 요청을 처리하기 위해 자주 협력하므로, 마이크로서비스 아키텍처 기반 시스템을 구현할 때 **프로세스 간 통신 프로토콜(inter process communication protocol)** 을 써야 한다.
- **마이크로서비스 간 통신을 어떻게 할지는 중요한 결정**이다.

### 동기 통신 (synchronous)
- 한 마이크로서비스가 **HTTP 프로토콜 위의 REST 엔드포인트**를 통해 다른 마이크로서비스와 통신한다.
- 이 방식에서 **호출하는 서비스는 호출받은 서비스가 응답할 때까지 기다릴 수 있다.**
- 클라이언트 요청을 처리하는 동안 **마이크로서비스 사이에 요청의 연쇄(chain of requests)** 가 만들어진다.

### 비동기 통신 (asynchronous)
- 한 마이크로서비스가 **비동기 메시지 또는 HTTP 폴링(polling)** 을 사용해 다른 마이크로서비스와 통신한다.
- **호출하는 서비스는 호출받은 서비스의 응답을 기다리지 않는다.**
- 마이크로서비스의 비동기 통신은 **Apache Kafka, RabbitMQ 같은 메시지 브로커(message broker)** 를 통해 이룰 수 있다.

## 예시
```text
[동기 통신]
서비스 A ──REST/HTTP 요청──> 서비스 B
        <──── 응답 ────────
   A는 B의 응답을 기다린다 → 요청의 연쇄가 생긴다

[비동기 통신]
서비스 A ──메시지──> [메시지 브로커] ──> 서비스 B
   A는 기다리지 않는다 (또는 HTTP 폴링으로 나중에 확인)
   브로커: Apache Kafka · RabbitMQ
```

| | 동기 | 비동기 |
|---|---|---|
| 수단 | HTTP 위 REST 엔드포인트 | 비동기 메시지 · HTTP 폴링 |
| 호출자 | 응답을 기다릴 수 있다 | 응답을 기다리지 않는다 |
| 결과 | 서비스 간 요청 연쇄 발생 | 메시지 브로커가 중개 |
| 구현 | REST | Apache Kafka · RabbitMQ |

## 요약
- 마이크로서비스는 서로 다른 머신에서 도는 분산 시스템이므로 프로세스 간 통신 프로토콜이 반드시 필요하다.
- 동기 통신은 HTTP 위 REST 엔드포인트를 쓰고 호출자가 응답을 기다리며, 요청의 연쇄가 만들어진다.
- 비동기 통신은 비동기 메시지나 HTTP 폴링을 쓰고 호출자가 기다리지 않으며, Kafka·RabbitMQ 같은 메시지 브로커로 구현한다.
