# Explore the Microservices Architecture

## 개요
- 차량 공유 앱을 예로 마이크로서비스 아키텍처를 살펴보고, SOA와의 관계 및 적합한 상황을 정리하는 강의

## 내용

### 차량 공유 앱을 분해하면
- 모놀리스로 개발하는 대신 애플리케이션을 여러 부분으로 **분해(decompose)** 해 개별적으로 개발할 수 있다.
- 클라이언트는 모바일 기기나 데스크톱 브라우저 클라이언트가 될 수 있고, 서비스들은 손쉽게 서로 통신한다.
- **인증 방식을 JWT에서 다른 방식으로 바꾸고 싶다면, 애플리케이션의 다른 마이크로서비스를 건드리지 않고 할 수 있다.**
- **요금 정산(billing) 서비스의 DB 스키마를 바꿔도 다른 서비스에 영향을 주지 않는다.**

### 마이크로서비스 아키텍처란
- **독립적으로 배포 가능한 작은 모듈형 서비스들의 모음**으로 엔터프라이즈 소프트웨어를 개발하는 방법이다.
- 각 서비스는 **고유한 프로세스를 실행**하고 **잘 정의된 경량 메커니즘으로 통신**하며 하나의 비즈니스 목표에 봉사한다.
- 용어가 생긴 이후 소프트웨어 개발에서 계속 세를 넓혀 왔다.

### SOA와의 관계
- 마이크로서비스 아키텍처는 **SOA(Service Oriented Architecture, 서비스 지향 아키텍처)의 변종(variant)** 이다.
- 서비스가 **비즈니스 도메인에 따라 덩어리(chunk)로 나뉜** 큰 애플리케이션을 개발하기 위한 것이다.

### 무엇을 제공하는가
- 복잡한 애플리케이션의 **지속적 전달(continuous delivery)과 배포**를 제공한다.
- 애플리케이션을 **이해하고 개발하고 테스트하기 쉽게** 만들고, **아키텍처 침식(architecture erosion)에 더 강하게** 만든다.
- 기존 시스템을 새로운 방식으로 엮어 **소프트웨어 솔루션을 빠르게 전달**하는 새 방법을 준다.
- 많은 엔터프라이즈 소프트웨어 개발사가 **모듈성·확장성·가용성**을 제공하는 능력 때문에 도입에 적극적이다.

### 적합한 상황
- **여러 종류의 클라이언트를 지원해야 할 때** — 데스크톱 브라우저, 모바일 브라우저, 네이티브 모바일 애플리케이션
- **웹 서비스나 메시지 브로커(message broker)를 통해 다른 애플리케이션과 통합해야 할 때**

## 예시
```text
차량 공유 앱을 서비스로 분해
클라이언트(모바일 / 데스크톱 브라우저)
   │
   ├─ 인증 서비스   ← JWT를 다른 방식으로 교체해도 나머지 무영향
   ├─ 승객 관리
   ├─ 요금 정산     ← DB 스키마를 바꿔도 나머지 무영향
   └─ 알림
   서비스 간 통신은 잘 정의된 경량 메커니즘
```

## 요약
- 서비스를 분해하면 인증 방식 교체나 특정 서비스의 DB 스키마 변경이 다른 서비스로 번지지 않는다.
- 마이크로서비스 아키텍처는 SOA의 변종으로, 비즈니스 도메인에 따라 서비스를 나눈다.
- 지속적 전달·배포, 이해·개발·테스트 용이성, 아키텍처 침식 저항, 모듈성·확장성·가용성을 제공한다.
- 여러 종류의 클라이언트를 지원해야 하거나 웹 서비스·메시지 브로커로 다른 앱과 통합해야 할 때 적합하다.
