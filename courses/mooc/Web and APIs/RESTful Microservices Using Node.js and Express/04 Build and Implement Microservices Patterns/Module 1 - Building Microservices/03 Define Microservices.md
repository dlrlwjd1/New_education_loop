# Define Microservices

## 개요
- 마이크로서비스의 정의와 11가지 장점, 그리고 4가지 과제를 다루는 강의

## 내용

### 정의
- 마이크로서비스는 **모듈화되고, 자율적(autonomous)이며, 논리적인 기능 단위**로서 **독립적으로 배포·확장 가능**하다.
- 마이크로서비스 아키텍처 스타일은 **하나의 애플리케이션을 작은 서비스들의 모음(suite)으로 개발하는 접근법**이며, 각 서비스는 **자기 프로세스에서 실행되고 경량 메커니즘으로 통신**한다.
- 각 마이크로서비스는 **오직 하나의 작업을 완수하는 데 집중하고, 그 하나를 잘한다.** 여기서 작업(task)은 **작은 비즈니스 역량(business capability)** 을 뜻한다.
- 각 마이크로서비스는 인터페이스를 통해 다른 마이크로서비스와 통신해 비즈니스 문제를 해결하고, **UI 마이크로서비스**와 통신해 클라이언트에 독립적으로 서비스를 제공한다.

### 장점 11가지
1. **모듈성(modularity)** — 각 마이크로서비스는 **경계가 잘 정의된**, 논리적으로 응집력 있고 경량이며 독립적인 비즈니스 기능을 보여 준다.
2. **단일 기능 원칙(single functionality principle)** — 각 서비스는 하나의 비즈니스 기능을 캡슐화한다.
3. **비동기 호출(asynchronous invocation)** — 마이크로서비스는 기본적으로 **무상태(stateless)** 이므로 비동기로 호출하기 좋다.
4. **독립 배포와 확장성** — 각각 독립적으로 배포되므로, 변동하는 부하와 사용자 수요에 맞춰 **독립적으로 확장**된다.
5. **자기완결성(self containment)** — 마이크로서비스 배포 단위는 **의존 라이브러리, 저장 단위, 데이터베이스를 모두 포함**해 자기완결적이다.
6. **장애 내성(fault tolerant)** — 응집력 있는 기능을 여러 서비스에 분산해 **단일 장애점(single point of failure)을 제거**한다. 서비스 하나가 죽어도 애플리케이션은 계속 동작한다. **서킷 브레이커(circuit breaker) 패턴**을 활용하면 장애 내성을 더 높일 수 있다.
7. **느슨한 결합(loose coupling)** — 다른 서비스와 라이브러리에 대한 의존을 최소화하도록 설계된다.
8. **잘 정의된 서비스 간 통신** — 잘 정의된 **REST 엔드포인트**로 서로 통신한다.
9. **확장 가능성(extensible)** — 새 서비스를 빠르게 온보딩해 확장 가능한 솔루션을 만들 수 있다.
10. **다중 기술 지원** — 각 마이크로서비스가 **서로 독립적으로 아무 기술이나** 쓸 수 있다.
11. **빠른 릴리스 주기** — 여러 개발자가 **병렬로** 개발할 수 있어 릴리스 시간이 줄어든다.

### 과제 4가지
1. **가시성(visibility)** — 개별 서비스가 서로 다른 앱 개발자 그룹에 의해 개발되고 언제든 애플리케이션에 투입될 수 있다. 개발자는 **서비스가 살아나는 즉시 그 서비스와 의존 관계를 자동으로 발견(discover)할 방법**이 필요하다.
2. **경계 문맥(bounded context)** — 애플리케이션을 여러 마이크로서비스로 나눌 때 각 서비스가 고유한 기능을 포함해야 한다. **각 마이크로서비스의 기능 경계를 정하는 것이 어렵기 때문에** 이는 도전 과제가 된다.
3. **설정 관리(configuration management)** — 각 마이크로서비스는 서로 다른 환경에 여러 인스턴스를 갖는다. 마이크로서비스 수가 많은 큰 애플리케이션에서는 **운영 팀이 설정을 관리하기가 곤란**해진다.
4. **동적 스케일 업·다운** — 애플리케이션 실행 중 필요한 마이크로서비스의 수가 요구에 따라 시점마다 달라진다. 이 유연성을 얻으려면 **동적 로드 밸런싱(dynamic load balancing)** 을 위해 배포해야 하는데, 이 구성 자체가 과제가 될 수 있다.

## 예시
```text
마이크로서비스 = "하나의 작은 비즈니스 역량 하나만, 잘"

각 서비스
  자기 프로세스에서 실행
  경량 메커니즘(REST 엔드포인트)으로 통신
  의존 라이브러리·저장소·DB를 함께 포함 (자기완결)
  기본 무상태 → 비동기 호출 가능
  독립 배포·독립 확장
  서비스 하나가 죽어도 나머지는 동작 (+ 서킷 브레이커로 강화)
```

## 요약
- 마이크로서비스는 하나의 작은 비즈니스 역량만 담당하는 독립 배포·확장 가능한 자율 단위다.
- 모듈성, 독립 배포·확장, 자기완결성, 장애 내성, 느슨한 결합, 기술 자유, 병렬 개발이 장점이다.
- 대가는 서비스 발견(가시성), 기능 경계 설정, 설정 관리, 동적 스케일링이라는 네 가지 운영 과제다.
