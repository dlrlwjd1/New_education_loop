# Explain ER Model and Data Normalization

## 개요
- 데이터베이스와 DBMS의 정의, 데이터 모델의 분류, **ER 모델**의 4가지 구성 요소와 관계의 3가지 카디널리티, 은행 시스템 ER 다이어그램 예시
- **RDBMS**, 구조화·비구조화 데이터, **중복 데이터의 문제**와 **정규화(normalization)**, **기본 키·외래 키**, RDBMS 데이터 구조 용어

## 내용

### 데이터베이스와 DBMS
- **데이터베이스**는 조직의 필수 요소이며 **논리적으로 연관된 데이터의 모음**이다. 파일이나 페이지를 뒤지는 대신 데이터베이스로 데이터를 검색해 질의에 답할 수 있다.
- 데이터베이스는 **일괄 처리(batch processing), 실시간 처리, 온라인 처리**용으로 설계될 수 있다.
- **DBMS(Database Management System)** 는 데이터베이스에서 정보를 **저장·수정·추출**할 수 있게 해 주는 소프트웨어·프로그램의 집합이다. 데이터를 추가·삭제·수정·접근·분석하는 도구를 제공하며, DBMS를 쓰도록 작성된 애플리케이션 프로그램을 통해서도 데이터에 접근할 수 있다.
- DBMS는 원시 데이터·수치·통계·값·사실을 토대로 세워진다. 데이터 추출은 두 단계다 — ① 사용자 시스템이 비즈니스 로직 기반 소프트웨어 애플리케이션으로 데이터베이스에서 정보를 추출한다 ② 데이터베이스가 요청을 처리해 결과를 반환한다.
- 데이터가 항상 정확하고 최신이도록 **데이터베이스 모델이 논리적 설계와 구조를 정의**한다 — 즉 데이터가 어떻게 저장·접근·갱신될지를 정한다.

### 데이터 모델의 분류
데이터 모델은 데이터가 수집·저장되는 현실 세계 상황의 표현이며, 데이터 흐름과 데이터 요소 간 논리적 상호관계를 그린다.

| 분류 | 모델 | 표현 방식 |
|---|---|---|
| **객체 기반 논리 모델** | **ER(Entity Relationship) 모델** | 객체와 그 관계 |
| **레코드 기반 논리 모델** | **관계형(relational) 모델** | 테이블 |
| | **네트워크(network) 모델** | 레코드와 링크 |
| | **계층(hierarchical) 모델** | 트리 구조, 관계는 링크로 표현 |

### ER 모델의 4가지 구성 요소
ER 모델은 데이터베이스 설계에 널리 쓰이는 데이터 모델로, **세상을 객체와 그 관계로 보는 이해 방식**이다.

1. **엔터티(entity)** — 객체·장소·사람에 관한 데이터를 기록하면 그 정보가 엔터티다. **엔터티 타입**(공통 속성을 공유하는 것들의 집합)과 **엔터티 인스턴스**(엔터티 타입의 개별 발생)로 나뉜다.
2. **속성(attribute)** — 엔터티 타입을 정의하는 성질
3. **관계 타입(relationship type)** — 엔터티 타입 간의 연관
4. **카디널리티(cardinality)** — 집합의 엔터티가 관계에 참여하는 횟수

### 관계의 3가지 유형
데이터베이스 관계는 테이블과 데이터베이스 사이의 연결로 정의된다.

| 유형 | 정의 | 예 |
|---|---|---|
| **일대일(one-to-one)** | 집합 A의 엔터티 하나가 집합 B의 엔터티 하나에만 연관되고 그 역도 성립 | 지점 하나는 지점장 한 명이 이끈다 |
| **일대다(one-to-many)** / 다대일 | A의 엔터티 하나가 B의 여러 엔터티에 연관 (다대일은 A의 여러 엔터티가 B의 하나에 연관) | 많은 고객이 하나의 지점에 속한다 |
| **다대다(many-to-many)** | A의 여러 엔터티가 B의 여러 엔터티에 연관되고 그 역도 성립 | 은행에서 여러 고객이 여러 계좌를 가질 수 있다 |

- 특정 데이터베이스 시스템에 **모든 종류의 카디널리티가 반드시 존재해야 하는 것은 아니다.**

### 은행 시스템 ER 다이어그램 예시
1. **엔터티 식별** — customer, branch, account, loan, employee
2. **속성 나열과 키 속성 식별**

| 엔터티 | 속성 | 키 속성 |
|---|---|---|
| customer | customer name, customer ID, customer address | **customer ID** |
| branch | branch name, branch ID, branch address | **branch ID** |
| account | account number, balance | **account number** |
| loan | loan number, amount, payment mode | **loan number** |
| employee | employee ID, employee name, address, salary, qualification | **employee ID** |

3. **카디널리티에 따른 관계 식별** — 예를 들어 customer는 account와 **다대다**, branch와 **다대일** 관계를 갖는다. 다섯 엔터티 각각에 대해 같은 작업을 한다.

### RDBMS
- **관계형 데이터베이스 관리 시스템**은 데이터를 저장·조직하는 강력한 도구다. 데이터베이스 안 **여러 테이블 간의 관계를 유지**해 정보를 추적하게 해 준다.
- 대표적으로 **MySQL, Oracle SQL, Microsoft SQL** 이 있다.

### 구조화 데이터와 비구조화 데이터
| | 구조화(structured) | 비구조화(unstructured) |
|---|---|---|
| 형태 | 테이블·스프레드시트에 넣을 수 있음. 고도로 조직되고 깔끔하게 포맷됨 | 구조화된 포맷이 없음 |
| 별칭 | 정량 데이터(quantitative data) | — |
| 예 | 소비자 리포트, 신용카드 번호, 금액 | 리포트, 오디오 파일, 텍스트 파일, 소셜 미디어 댓글, 의견 |
| 특징 | — | 수집·처리·분석이 어렵고 매년 커져 기업이 관리하기 힘들어진다 |

### 중복 데이터(redundant data)의 문제
- `Customer Order Product` 테이블에서 **Customer Name, Order Number, Product Name 이 여러 번 반복**된다.
- 입력 시 고객 이름 **John이 오타이고 Joan으로 고쳐야 한다면** 몇 곳을 수정해야 하는가? 고객 데이터가 구매한 상품마다 복제되어 붙어 있으면 **출처를 알 수 없는 불일치(inconsistency)** 가 생긴다.
- 여러 곳을 수정하는 것은 위험하다 — **일부를 놓치면 데이터 불일치**가 된다.
- **삭제해도 정보가 손실되지 않으면 그 데이터 값은 중복이다.** 즉 중복은 **불필요한 복제**다.

### 정규화(normalization)
- 데이터베이스 정규화의 목표는 항상 **최적화**다.
- 정규화는 **중복과 의존성을 최소화하도록 관계형 데이터베이스의 필드와 테이블을 조직하는 과정**이다. 큰 테이블을 더 작거나 덜 중복된 테이블로 나누고 그들 사이의 관계를 정의한다.
- 데이터 중복을 줄여 테이블의 데이터 불일치를 최소화한다.
- 예시에서 `Customer Order Product` 테이블을 **Customer Order, Product, Order Detail 세 테이블**로 나눈다. 이제 **Joan으로의 이름 변경은 한 테이블에서만** 한다. 특정 고객의 청구서 상세를 상품명과 함께 보려면 주문 번호와 상품 ID를 가져오면 된다.
- 따라서 각 테이블이 **고유 값만 받는 열로 레코드의 유일성을 유지**하고, 한 테이블의 데이터를 다른 테이블에서 참조할 때 그 유일성을 유지하는 열을 참조해야 한다. 이것을 **기본 키와 외래 키**로 이룬다.

### 기본 키 vs 외래 키
- 테이블은 **기본 키·외래 키 관계**로 다른 테이블과 연결된다. 관계형 데이터베이스에서 테이블 간 **다대일 관계**를 정의하는 데 쓰인다.
- **기본 키(primary key)** — Product 테이블의 `product ID`처럼 테이블의 행을 유일하게 식별한다. **null이 아닌 고유 값만** 저장할 수 있다.
- **외래 키(foreign key)** — Order 테이블의 `product ID`처럼 Product 테이블 `product ID` 값에 대응하는 값을 나타낸다. **참조하는 기본 키 열에 존재하는 값만** 저장할 수 있다.

### RDBMS 데이터 구조 용어
| 용어 | 의미 |
|---|---|
| 테이블 이름 | 데이터베이스의 각 테이블은 고유한 이름을 가져야 한다 |
| **속성(attribute)** | 테이블의 열(column) 또는 필드. 고유해야 한다 |
| **차수(degree)** | 속성의 개수 |
| **기본 키** | 각 행을 유일하게 식별하는 열 또는 열의 조합 |
| **튜플(tuple)** | 행(row) 또는 레코드 |
| **카디널리티(cardinality)** | 튜플의 개수 |
| **관계(relation)** | 서로 다른 값을 가진 행들이 함께 있는 것 |
| **도메인(domain)** | 하나 이상의 속성이 실제 값을 끌어오는 값들의 모음 |

## 예시

```text
[중복이 있는 테이블]
Customer Order Product
| CustomerName | OrderNumber | ProductName |
| John         | 1001        | Laptop      |
| John         | 1001        | Mouse       |   ← John이 오타라면 여러 행을 고쳐야 한다
| John         | 1002        | Keyboard    |

[정규화 후 — 세 테이블로 분리]
Customer Order            Product                 Order Detail
| OrderNumber | Customer | | ProductID | Name   | | OrderNumber | ProductID |
| 1001        | Joan     | | P1        | Laptop | | 1001        | P1        |
| 1002        | Joan     | | P2        | Mouse  | | 1001        | P2        |
                          | P3        | Keyboard| | 1002        | P3        |
  ↑ 이름 수정은 여기서만          ↑ 기본 키              ↑ 외래 키 (Product.ProductID 참조)
```

```sql
-- 기본 키와 외래 키
CREATE TABLE product (
  product_id   INT PRIMARY KEY,        -- null 아닌 고유 값만
  product_name VARCHAR(100)
);

CREATE TABLE order_detail (
  order_number INT,
  product_id   INT,
  FOREIGN KEY (product_id) REFERENCES product(product_id)   -- 참조 대상에 있는 값만
);
```

```text
[은행 ER 다이어그램 관계 예]
customer ──다대다── account      (여러 고객이 여러 계좌)
customer ──다대일── branch       (많은 고객이 하나의 지점에)
branch   ──일대일── branch head  (지점 하나에 지점장 한 명)
```

## 요약
- 데이터베이스는 논리적으로 연관된 데이터의 모음이고, DBMS는 이를 저장·수정·추출하는 소프트웨어 집합이다.
- 데이터 모델은 객체 기반(ER)과 레코드 기반(관계형·네트워크·계층)으로 나뉘며, ER 모델은 엔터티·속성·관계 타입·카디널리티 4요소로 이뤄진다.
- 관계는 일대일·일대다·다대다 세 유형이며, ER 다이어그램은 엔터티 식별 → 속성과 키 속성 나열 → 카디널리티별 관계 식별 순서로 그린다.
- 중복은 삭제해도 정보가 손실되지 않는 불필요한 복제이며, 수정 누락으로 불일치를 낳는다.
- 정규화는 큰 테이블을 덜 중복된 테이블로 나누고 기본 키(null 아닌 고유 값)와 외래 키(참조 대상에 존재하는 값)로 관계를 잇는 것이다.
