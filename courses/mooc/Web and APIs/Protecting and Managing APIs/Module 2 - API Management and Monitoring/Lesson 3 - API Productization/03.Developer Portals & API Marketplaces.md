# Developer Portals & API Marketplaces (개발자 포털과 API 마켓플레이스)

## 개요
- 개발자 포털과 API 마켓플레이스가 API를 발견·테스트·통합 가능한 제품으로 만드는 방법을 다루는 3분 39초 분량 영상 — Module 2 "Lesson 3: API Productization"의 세 번째 영상

## 내용

### 개발자 포털과 API 마켓플레이스란
- API는 혁신의 엔진일 수 있지만, 이를 선보일 적절한 플랫폼이 없으면 숨겨진 보석으로 남음 — 이때 개발자 포털과 API 마켓플레이스가 등장함
- 이들은 스토어프론트이자 커뮤니티처럼 작동해, 기업이 API를 게시하고 개발자가 이를 발견·테스트·구축할 수 있게 도움
- 기업들이 API-first 전략을 채택함에 따라 표준화된 접근이 불가피해짐 — 개발자들은 원본 엔드포인트 이상으로 문서화·SDK·협업할 공간을 원했고, 이 수요가 개발자 포털의 성장으로 이어짐
- 시간이 지나며 마켓플레이스가 진화해 앱 스토어처럼 API를 정리함으로써 발견·수익화·통합을 더 쉽게 만듦

### 포털/마켓플레이스의 유형 — 접근 게이트의 종류
1. **API 기반 포털**: 순전히 내부용으로, 회사 개발자만 사용하며 내부 프로젝트를 간소화함
2. **파트너 포털**: 선택적인 문을 열어 신뢰할 수 있는 협력사에게 특정 API에 대한 접근을 부여함
3. **공개 마켓플레이스**: 오픈 마켓과 같아 어떤 개발자든 API를 탐색하고 발견할 수 있음
4. **하이브리드 모델**: 세 가지의 장점을 결합해 통제와 유연성의 균형을 맞춤
- 이런 분류를 통해 API가 적절한 대상에게 적절한 방식으로 공유될 수 있음

### 일반적인 워크플로
1. **게시(Publish)**: API 제공자가 문서화·가격·이용 약관을 포함해 API를 게시함
2. **탐색(Discover)**: 개발자가 완전히 커밋하기 전 데모를 사용해보듯 API를 검색·테스트·탐색함
3. **통합(Integrate)**: 선택된 API가 애플리케이션이나 제품에 통합되어 새로운 기능을 구현함
4. **추적(Track)**: 제공자가 사용량·성능·청구를 추적함
- 이 사이클은 기업과 개발자 모두에게 이득이 됨 — 기업은 통찰과 매출을 얻고, 개발자는 신뢰할 수 있고 잘 문서화된 도구를 얻음

### 성공을 위한 모범 사례
1. **명확하고 최신인 문서화와 튜토리얼 유지**: 모호한 지침만큼 개발자를 좌절시키는 것은 없음
2. **샌드박스 환경 제공**: 자동차를 시승해보듯 위험 없이 API를 시도할 수 있게 함
3. **투명한 가격과 구독 모델**: 신뢰를 구축함
4. **강력한 커뮤니티 지원과 피드백 채널**: 채택이 계속 성장하도록 함
- 이런 관행들이 합쳐져 개발자 포털을 단순한 API 목록이 아닌 번성하는 생태계로 바꿈

## 요약
- 개발자 포털과 API 마켓플레이스는 내부용·파트너용·공개용·하이브리드로 나뉘며, 게시 → 탐색 → 통합 → 추적이라는 워크플로를 통해 기업과 개발자 모두에게 이득을 줌
- 명확한 문서화, 샌드박스 환경, 투명한 가격, 커뮤니티 지원이라는 모범 사례가 성공적인 생태계를 만듦
