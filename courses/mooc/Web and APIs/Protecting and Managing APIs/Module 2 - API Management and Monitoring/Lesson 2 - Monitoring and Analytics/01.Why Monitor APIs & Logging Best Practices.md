# Why Monitor APIs & Logging Best Practices (API를 모니터링해야 하는 이유와 로깅 모범 사례)

## 개요
- API 모니터링이 왜 미션 크리티컬한지, 부실한 로깅이 어떤 위험을 초래하는지, 시스템을 안전하고 신뢰할 수 있으며 감사 대응 가능하게 유지하는 모범 사례를 다루는 3분 15초 분량 영상 — Module 2 "Lesson 2: Monitoring and Analytics"의 첫 번째 영상

## 내용

### API 모니터링이 중요한 이유
- API는 모바일 뱅킹부터 온라인 쇼핑까지 오늘날 우리가 의존하는 거의 모든 디지털 경험을 뒷받침함
- 적절한 모니터링과 로깅이 없으면 치명적인 문제가 너무 늦을 때까지 발견되지 않을 수 있음
- API 모니터링은 단순한 가동 시간(uptime) 확인을 훨씬 넘어섬:
  1. **신뢰성(Reliability)**: 장애를 조기에 감지해 고객이 영향받기 전에 다운타임을 줄임
  2. **성능(Performance)**: 지연 시간(latency)과 처리량(throughput)을 추적해 API가 빠르고 확장 가능하도록 보장함
  3. **보안(Security)**: 위협이나 침해를 암시할 수 있는 비정상적인 트래픽 패턴을 드러냄
  4. **컴플라이언스(Compliance)**: 규제는 흔히 감사 추적(audit trail)을 요구하며, 모니터링이 그 증거를 제공함
- API 모니터링은 디지털 생태계를 위한 건강 검진과 같음 — 모든 것이 원활하고 안전하게 돌아가도록 보장함

### 로깅의 함정
- 로깅은 강력하지만 제대로 관리하지 않으면 함정이 생김:
  1. **로그 과부하(Log overload)**: 구조 없이 너무 많은 데이터를 수집하면 노이즈가 생겨 실제 문제를 발견하기 어려워짐
  2. **맥락 부재(Missing context)**: 관련 세부정보가 없는 로그는 가장자리 없는 퍼즐 조각과 같아 거의 쓸모없음
  3. **보안 위험(Security risks)**: 로그는 흔히 민감한 정보를 담고 있어 노출되면 부채가 됨
  4. **높은 비용(High costs)**: 방대한 로그의 저장·처리는 빠르게 비용이 커질 수 있음

### 로깅 모범 사례
1. **구조화된 로깅(Structured logging)**: 표준 형식으로 로그를 정리해 기계와 사람 모두 쉽게 읽을 수 있게 함
2. **로그 레벨(Log levels)**: info, warning, error로 로그를 분류해 우선순위를 매김
3. **상관관계 ID(Correlation IDs)**: 고유 식별자를 사용해 여러 서비스에 걸친 사용자의 여정을 추적함
4. **중앙화된 로그(Centralized logs)**: 모든 것을 하나의 플랫폼으로 통합해 분석을 쉽게 함
5. **민감 데이터 보호**: 로그 속 민감 데이터를 항상 보호해 유출을 방지함
- 이런 모범 사례를 따르면 로그가 시끄러운 데이터 더미에서 통찰력과 보안을 위한 강력한 도구로 바뀜

## 요약
- API 모니터링은 신뢰성·성능·보안·컴플라이언스의 네 가지 축에서 필수적이며, 로그 과부하·맥락 부재·보안 위험·높은 비용 같은 로깅의 함정을 인식하는 것이 중요함
- 구조화된 로깅, 로그 레벨, 상관관계 ID, 중앙화된 로그, 민감 데이터 보호라는 다섯 가지 모범 사례가 효과적인 로깅 전략의 핵심임
