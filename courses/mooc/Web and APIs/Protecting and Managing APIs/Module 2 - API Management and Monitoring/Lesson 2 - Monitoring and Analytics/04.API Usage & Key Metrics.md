# API Usage & Key Metrics (API 사용량과 핵심 지표)

## 개요
- API 사용량이 무엇을 의미하는지, 추적해야 할 핵심 지표는 무엇인지, 이 지표들이 어떻게 더 나은 의사결정을 돕는지 다루는 3분 40초 분량 영상 — Module 2 "Lesson 2: Monitoring and Analytics"의 네 번째 영상

## 내용

### API 사용량과 핵심 지표란
- API는 현대 애플리케이션과 고객 경험의 생명선이지만, API가 효과적이고 신뢰할 수 있는지는 어떻게 알 수 있을까 — 이때 사용량 추적과 핵심 지표가 등장함
- **API 사용량(API usage)**은 클라이언트가 API와 상호작용하는 방식을 의미함 — 얼마나 자주, 어떤 방식으로, 어떤 조건에서 상호작용하는지
- 이를 측정하기 위해 트래픽·오류율·응답 시간 같은 정량적 지표인 **핵심 지표(key metrics)**에 의존함 — 이 숫자들은 API가 어떻게 작동하는지뿐 아니라 어디서 문제가 생길 수 있는지도 알려줌
- 이런 지표를 추적하는 것은 병목을 식별해 성능을 높이고, 문제가 심각해지기 전에 강조하며, 궁극적으로 사용자 경험을 개선하는 데 도움이 됨 — API 생태계를 위한 건강 검진과 같음

### 왜 API 지표를 추적해야 하는가
1. **신뢰성(Reliability)**: API가 기대한 대로 일관되게 작동한다는 확신이 필요함
2. **사용 패턴(Usage patterns)**: 고객이 제품을 실제로 어떻게 사용하는지 드러내고 예상치 못한 트렌드를 발견할 수 있게 함
3. **성능(Performance)**: API가 빠르고 효율적인지, 아니면 부하 속에서 뒤처지는지를 보여줌
4. **최적화와 확장(Optimization and scaling)**: 수요가 언제 어디서 증가하는지 알면 팀이 자원을 현명하게 배분하고 값비싼 다운타임을 피할 수 있음
- 요약하면, 지표는 백미러(rearview mirror)이자 앞으로의 로드맵을 동시에 제공함

### 구체적인 지표들
- **요청 수(Request count)**: API 호출의 총 수 — 사용량의 명확한 지표
- **오류율(Error rate)**: 실패한 요청의 비율 — 사용자가 장애물에 부딪히고 있는지 보여줌
- **지연 시간(Latency)/응답 시간**: API가 얼마나 빨리 응답하는지 포착함 — 사용자 만족도에 직접 영향을 미침
- **처리량(Throughput)/대역폭**: 초당 처리할 수 있는 요청 수 또는 전송되는 데이터 양을 반영함
- 이 지표들이 합쳐져 자동차의 속도계와 연료 게이지를 동시에 확인하는 것처럼 API 건강 상태의 종합적인 그림을 제공함

### 실무에서의 활용
- **개발자**는 API가 어떻게 작동하는지, 어디를 개선해야 하는지 통찰을 얻는 데 지표를 사용함
- **비즈니스**는 서비스 수준 계약(SLA)을 위해 지표에 의존해 고객에게 한 약속이 지켜지는지 확인함
- 지표는 **확장 결정**도 안내함 — 언제 서버를 추가하거나 인프라를 최적화해야 하는지 알 수 있게 함
- 지표는 **비즈니스 분석**에도 반영되어 전략·혁신·고객 참여를 형성할 수 있는 트렌드를 드러냄
- 결론적으로 API 지표는 단순히 시스템을 원활하게 유지하는 것을 넘어 조직 전체가 더 똑똑하고 강하게 성장하도록 도움

## 요약
- API 사용량은 클라이언트가 API와 상호작용하는 방식이고, 요청 수·오류율·지연 시간·처리량이라는 핵심 지표가 이를 정량적으로 측정함
- 이 지표들은 신뢰성·사용 패턴 파악·성능 확인·최적화/확장 결정에 필수적이며, 개발자의 통찰뿐 아니라 SLA·확장 결정·비즈니스 분석에도 활용됨
