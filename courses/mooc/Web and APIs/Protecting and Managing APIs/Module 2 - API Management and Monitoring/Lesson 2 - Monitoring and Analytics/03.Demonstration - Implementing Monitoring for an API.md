# Demonstration: Implementing Monitoring for an API (API에 모니터링 구현하기 실습 데모)

## 개요
- Prometheus로 FastAPI 애플리케이션의 상태·응답 시간·오류를 추적하고 Grafana로 시각화하는 3분 48초 분량 실습 데모 영상 — Module 2 "Lesson 2: Monitoring and Analytics"의 세 번째 영상
- 완료 시점에는 API 성능을 실시간으로 보여주는 라이브 대시보드를 갖추게 됨

## 내용

### Step 1 — FastAPI 앱에 Prometheus 메트릭 추가
- 프로젝트 폴더 안에 `main.py` 파일을 생성함
- FastAPI, Prometheus 메트릭 클래스, Starlette의 request/response 헬퍼를 임포트함
- FastAPI 앱 인스턴스를 만들고 두 개의 Prometheus 메트릭을 정의함: 전체 API 요청 수를 추적하는 카운터(Counter), 요청 지연 시간을 측정하는 히스토그램(Histogram)
- `/hello` 엔드포인트를 추가함 — 이 엔드포인트 안에서 요청 카운터를 증가시키고, 처리 과정을 시뮬레이션하고, 지연 시간을 기록한 뒤 JSON 응답을 반환함
- 마지막으로 `/metrics` 엔드포인트를 추가해 Prometheus가 필요로 하는 형식으로 메트릭을 노출함 — 이 두 엔드포인트 덕분에 Prometheus가 메트릭을 스크래핑하고 실시간으로 요청 성능을 추적할 수 있음

### Step 2 — API 실행 및 확인
```bash
uvicorn main:app --reload --port 8000
```
- 브라우저에서 `http://localhost:8000/hello`로 이동하면 `{"message": "Hello, FastAPI"}` 같은 JSON 응답이 보임
- `http://localhost:8000/metrics`로 이동하면 원본 Prometheus 메트릭이 노출되는 것을 확인할 수 있음
- Prometheus의 Targets 페이지로 이동하면 FastAPI 데모와 Prometheus 타깃이 모두 정상 작동(up) 상태임을 확인할 수 있음

### Step 3 — Grafana 상태 확인 및 대시보드 생성
```bash
sudo systemctl status grafana-server
```
- Grafana가 활성화되어 실행 중임을 확인함 — 이는 API 메트릭을 시각화할 준비가 되었다는 의미
- 브라우저에서 `http://localhost:3000`으로 Grafana 대시보드에 접속함
- 홈페이지에서 새 대시보드를 만들고, 시각화(visualization)를 추가한 뒤 데이터 소스로 Prometheus를 선택함
- 첫 번째 메트릭으로 `api_requests_total`을 추가해 전체 API 요청 수를 보여줌 — 처음에는 앞서 보낸 한 번의 요청에 대한 단일 라인만 표시됨

### Step 4 — 트래픽 생성 및 실시간 업데이트 확인
```bash
curl http://localhost:8000/hello
```
- 이 명령을 여러 번 반복 실행하면 각 요청마다 카운터가 증가하고, Grafana의 그래프가 매 요청마다 실시간으로 업데이트되는 것을 확인할 수 있음

## 요약
- FastAPI 앱에 Prometheus의 Counter(요청 수)와 Histogram(지연 시간) 메트릭을 추가하고 `/metrics` 엔드포인트로 노출한 뒤, Grafana 대시보드에서 Prometheus를 데이터 소스로 연결해 실시간 API 모니터링 대시보드를 구축하는 전체 과정을 실습함
- curl로 반복 요청을 보내 Grafana 그래프가 실시간으로 업데이트되는 것을 검증함
