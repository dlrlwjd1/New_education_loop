# Reading: API Monitoring and Analytics: Ensuring Reliability, Insights, and Growth (API 모니터링과 분석: 신뢰성·통찰·성장 보장하기)

## 개요
- 앞선 영상들(왜 모니터링해야 하는지, 모니터링 도구·알림·분석, 실습 데모, 사용량과 핵심 지표, 대시보드와 A/B 테스트)의 핵심 개념을 정리하는 5분 분량 읽기자료 — Module 2 "Lesson 2: Monitoring and Analytics"의 여덟 번째이자 마지막 항목
- API는 살아있는 시스템(living systems)임 — 신뢰할 수 있고 안전하며 비즈니스 목표와 일치하도록 유지하기 위해 조직은 모니터링과 분석에 의존함

## 내용

### API를 모니터링하고 로깅해야 하는 이유
- API 모니터링은 상태·성능·사용량을 추적하고, 로깅은 문제 해결과 감사를 위해 이벤트와 오류를 포착함
- **핵심 기능**:
  - **오류 탐지(Error Detection)**: 실패한 요청, 느린 응답, 타임아웃을 식별함
  - **성능 추적(Performance Tracking)**: 응답 시간·처리량·지연 시간을 모니터링함
- **활용 예시**: 로그인 실패의 비정상적인 급증을 탐지하는 경우
- **학습 팁**: 모니터링을 API의 건강 검진이라고 생각하면 됨 — 로그가 없으면 문제가 숨겨진 채로 남음

### 모니터링 도구, 알림, 분석
- 도구들이 모니터링을 자동화하고 알림을 생성하며 통찰을 위한 대시보드를 제공함
- **핵심 기능**:
  - **모니터링 도구**: Prometheus, Datadog, Postman
  - **분석 대시보드**: 트래픽·지연 시간·오류 추세를 시각화함
- **활용 예시**: 가동 시간이 99.9% 아래로 떨어지면 PagerDuty가 알림을 보내는 경우
- **학습 팁**: 알림은 화재경보와 같음 — 적절한 담당자에게 즉시 알려줌

### 실습: API에 모니터링 구현하기
- **시나리오**: 영화 추천 API
- **이점**: API 상태에 대한 실시간 인지
- **학습 팁**: 모니터링은 자동차 대시보드와 같음 — 문제가 심각해지기 전에 경고를 볼 수 있음

### API 사용량과 핵심 지표
- 분석은 API가 어떻게, 언제, 누구에 의해 사용되는지를 추적해 채택·성능·비즈니스 영향을 측정함
- **핵심 지표**:
  - **요청량(Request Volume)**: API 호출 수
  - **지연 시간(Latency)**: 응답 시간
- **활용 예시**: 폭풍 전에 날씨 API 사용량이 급증하는 경우
- **학습 팁**: 지표는 스코어보드와 같음 — API의 성공이나 문제를 보여줌

### API를 위한 대시보드와 A/B 테스트
- 대시보드는 성능을 시각화하고, A/B 테스트는 API 버전이나 전략을 비교함
- **핵심 기능**:
  - **대시보드**: 지연 시간·가동 시간·사용량 추세 차트
- **활용 예시**: API 호출의 지리적 분포를 보여주는 대시보드, 두 인증 플로우를 비교하는 A/B 테스트, 가격 모델 전반의 사용자 행동 모니터링
- **학습 팁**: 대시보드는 눈(eyes)이고, A/B 테스트는 채택과 성능을 위한 실험실(experiment lab)임

## 요약
- API 모니터링·로깅은 오류 탐지와 성능 추적을 통해 문제를 조기에 드러내며, Prometheus·Datadog·Postman 같은 도구와 대시보드·알림이 이를 자동화함
- 사용량 지표(요청량·지연 시간)는 API 채택과 비즈니스 영향을 보여주는 스코어보드 역할을 하고, 대시보드와 A/B 테스트는 각각 눈과 실험실 역할을 하며 데이터 기반 개선을 가능하게 함
