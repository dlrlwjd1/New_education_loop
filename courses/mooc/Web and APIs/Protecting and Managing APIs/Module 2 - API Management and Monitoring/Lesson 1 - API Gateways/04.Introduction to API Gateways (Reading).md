# Reading: Introduction to API Gateways: Concepts, Tools, and Traffic Management (API 게이트웨이 개념·도구·트래픽 관리 소개)

## 개요
- 앞선 세 영상(API 게이트웨이란 무엇인가, 널리 쓰이는 API 게이트웨이, 라우팅과 프록시)의 핵심 개념을 정리하는 10분 분량 읽기자료 — Module 2 "Lesson 1: API Gateways"의 네 번째 항목
- 현대 애플리케이션은 여러 API와 마이크로서비스에 의존하는 경우가 많은데, API 게이트웨이는 클라이언트를 위한 단일 진입점 역할을 하며 클라이언트와 백엔드 서비스 사이의 요청·응답을 관리함

## 내용

### API 게이트웨이란 무엇인가
- API 게이트웨이는 클라이언트(앱·사용자·기기)와 백엔드 서비스 사이의 관리 계층임 — 요청을 처리하고 정책을 강제하며 안전하고 신뢰할 수 있는 통신을 보장함
- **핵심 기능**:
  - **요청 라우팅(Request Routing)**: 들어오는 요청을 올바른 서비스로 전달함
  - **보안 강제(Security Enforcement)**: 인증·인가·위협 방어를 처리함
- **활용 예시**: 전자상거래 앱이 체크아웃 요청을 게이트웨이로 보내면, 게이트웨이가 토큰을 검증하고 결제 서비스로 라우팅함
- **학습 팁**: API 게이트웨이를 API 생태계의 "프런트 데스크"라고 생각하면 됨 — 요청을 맞이하고, 신분증을 확인하고, 올바른 부서로 안내함

### 널리 쓰이는 API 게이트웨이
- 엔터프라이즈·오픈소스 솔루션들이 대규모로 API를 관리하며 라우팅·보안·모니터링·수익화를 위한 도구를 제공함
- **대표 예시**:
  - **Kong Gateway**: 오픈소스, 경량, 플러그인 기반
  - **Amazon API Gateway**: AWS와 통합된 완전 관리형 서비스
- **활용 예시**: 스타트업이 빠른 마이크로서비스 배포를 위해 Kong을 사용하는 경우
- **학습 팁**: 게이트웨이를 선택하는 것은 교통 관제사를 선택하는 것과 같음 — 어떤 것은 속도에, 어떤 것은 분석에, 어떤 것은 거버넌스에 특화되어 있으므로 비즈니스 요구에 맞는 것을 골라야 함

### 라우팅과 프록시
- 라우팅과 프록시는 API 게이트웨이의 핵심 기능으로, 요청이 어디로 가고 어떻게 처리되는지를 결정함
- **핵심 기능**:
  - **라우팅(Routing)**: URL, 헤더, 규칙에 기반해 API 호출 방향을 정함
  - **리버스 프록시(Reverse Proxying)**: 클라이언트를 대신해 동작하며 백엔드 세부사항을 숨김
- **활용 예시**: `/users` 요청은 사용자 서비스로, `/orders` 요청은 주문 서비스로 라우팅하는 경우
- **학습 팁**: 라우팅은 지도이고 프록시는 운전자임 — 둘이 함께 요청이 안전하고 효율적으로 올바른 목적지에 도달하도록 보장함

### 왜 이 모든 것이 함께 중요한가
- API 게이트웨이는 현대 API 생태계에 필수적임 — 보안·라우팅·모니터링을 중앙화하고, 마이크로서비스 아키텍처에서 확장성과 신뢰성을 제공함
- **요약**:
  - **API 게이트웨이**: API를 위한 단일 진입점으로 보안과 트래픽을 처리함
  - **널리 쓰이는 게이트웨이**: Kong, NGINX, Apigee, Amazon API Gateway, Azure API Management
  - **라우팅과 프록시**: 트래픽을 안내하고 효율성·보안을 위한 중간 계층 역할을 함

## 요약
- API 게이트웨이는 클라이언트와 백엔드 서비스 사이의 관리 계층으로서 요청 라우팅과 보안 강제를 핵심 기능으로 하며, Kong·Amazon API Gateway·NGINX·Apigee·Azure API Management 등 다양한 솔루션이 존재함
- 라우팅(지도)과 프록시(운전자)가 함께 작동해 트래픽을 안전하고 효율적으로 목적지까지 전달함
