# What is an API Gateway? (API 게이트웨이란 무엇인가)

## 개요
- API 게이트웨이의 정의, 필요성, 핵심 기능, 현대 IT 시스템에서의 역할을 다루는 4분 37초 분량 영상 — Module 2 "Lesson 1: API Gateways"의 첫 번째 영상

## 내용

### API 게이트웨이란
- API 게이트웨이는 모든 클라이언트 요청이 백엔드 서비스에 도달하기 전에 거쳐가는 중앙 관문(central doorway) 역할을 함
- 비유하자면 바쁜 사무실의 리셉셔니스트와 같음 — 요청을 받아 올바른 부서로 안내하고, 응답이 제대로 전달되도록 함
- 기술적으로는 모든 API에 대한 단일 진입점(single entry point) 역할을 하는 서버임 — 클라이언트가 여러 마이크로서비스에 직접 연결하는 대신 게이트웨이를 거쳐 요청을 보냄
- 게이트웨이는 요청을 관리하고 올바른 마이크로서비스로 라우팅하며 응답을 수집해 클라이언트에 반환함 — 이를 통해 통신이 더 단순하고 구조화됨
- 여기서 그치지 않고 인증(authentication), 감사를 위한 로깅(logging), 남용 방지를 위한 속도 제한(rate limiting) 같은 횡단 관심사(cross-cutting concerns)도 처리함 — 요청 흐름을 조직화되고 안전하며 효율적으로 유지하는 교통 관제사(traffic controller)와 같음

### 왜 API 게이트웨이가 필요한가
1. **단순화된 통신(Simplified communication)**: 각 클라이언트가 여러 서비스를 개별적으로 처리하는 대신, 게이트웨이가 하나의 중앙 연결점 역할을 함
2. **성능 최적화(Performance optimization)**: 캐싱·로드 밸런싱·스로틀링을 추가함으로써 트래픽이 많을 때도 시스템이 원활하게 실행되도록 보장함
3. **강화된 보안(Security)**: 각 마이크로서비스가 개별적으로 처리하는 대신 인증·인가를 중앙에서 관리함으로써 보안을 강화함
4. **보호막 제공(Protective shield)**: 내부 아키텍처를 외부 사용자로부터 숨겨 직접 공격에 덜 취약하게 만듦

### 핵심 기능
- **요청 라우팅(Request routing)**: 클라이언트가 세부사항을 알 필요 없이 들어오는 트래픽을 올바른 마이크로서비스로 전달함
- **속도 제한(Rate limiting)**: 일정 시간 내 요청 수를 제어해 남용을 방지하고 과부하·오용으로부터 시스템을 보호함
- **인증과 인가**: 유효한 사용자와 적절한 권한을 가진 사용자만 민감한 서비스에 접근할 수 있도록 보장함
- **로깅과 모니터링**: 모든 활동을 추적하고 오류를 기록하며 팀이 성능을 분석하도록 도움
- 이 기능들이 합쳐져 API 게이트웨이는 통신 허브일 뿐 아니라 보안 경비원, 트래픽 관리자, 시스템 모니터 역할까지 한 번에 수행함

### 현대 IT 시스템에서의 역할
- 마이크로서비스 아키텍처의 핵심 구성 요소로서 복잡한 시스템에 통합된 접근점을 제공함
- API 수익화(monetization)를 가능하게 함 — 기업이 API를 제품으로 안전하게 제공하고 서드파티 통합을 관리할 수 있게 함
- 개발자 생산성 향상 — 인증·모니터링·속도 제한 같은 공통 관심사를 게이트웨이로 위임함으로써 개발자는 보안 계층을 재발명하는 대신 기능 개발에 집중할 수 있음
- 클라우드 네이티브 애플리케이션과 DevOps 파이프라인의 기반 — 자동화와 확장성이 필수적인 환경에서 핵심적인 역할을 함
- 결론적으로 API 게이트웨이는 선택적 부가 기능이 아니라 현대 IT 인프라의 백본(backbone)임

## 요약
- API 게이트웨이는 모든 클라이언트 요청의 단일 진입점으로서 라우팅·속도 제한·인증/인가·로깅/모니터링을 수행하며, 통신 단순화·성능 최적화·보안 강화·내부 아키텍처 보호라는 이점을 제공함
