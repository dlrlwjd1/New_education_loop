# Reading: Practice Project — Building a Secure and Scalable API Management Platform (실습 프로젝트: 안전하고 확장 가능한 API 관리 플랫폼 구축하기)

## 개요
- 코스 전체(Module 1의 보안 기초와 Module 2의 관리·모니터링·제품화)를 종합해 적용해보는 1시간 분량 실습 프로젝트 개요 읽기자료 — Module 3 "Course Wrap-Up and Assessment"의 첫 번째 항목

## 내용

### 시나리오
- 여러 마이크로서비스를 가진 핀테크 스타트업 ApexFin은 API를 보호하고 관리하는 데 어려움을 겪고 있음
- 팀마다 서로 다른 인증 방법을 사용하고, 중앙 게이트웨이가 없으며, 모니터링이 최소한임 — 키 유출이나 갑작스러운 트래픽 급증 같은 사고를 탐지하기 어려움
- 경영진은 일부 API를 사용 계획(usage plans)과 개발자 포털을 갖춘 제품으로 전환하고 싶어함

### 초기 문제점
- **일관되지 않은 인증·인가**: Basic Authentication과 API 키가 혼재되어 있고 표준화된 OAuth 2.0/JWT 접근법이 없음
- **중앙 제어 부재**: 서비스가 직접 노출되어 있고 통합된 라우팅·속도 제한·요청 검증이 없음
- **낮은 가시성**: 제한된 로그와 지표, 신뢰성·사용량을 위한 명확한 대시보드나 알림 부재
- **취약한 거버넌스**: 역할 기반/속성 기반 접근 제어가 거의 없고, 감사가 최소화되어 있으며, 버전 관리가 불명확함

### 프로젝트 목표
- 안전하고 관찰 가능하며 제품화 준비가 된 API 플랫폼 구축: 인증·인가 표준화, 트래픽 제어를 위한 중앙 게이트웨이 추가, 모니터링·분석 구현, 제품화 지원

### 과제
1. 인증과 인가
2. API 게이트웨이 설정
3. 보안과 컴플라이언스
4. 모니터링과 분석
5. 제품화와 개발자 경험
6. 생명주기와 거버넌스

### 산출물(Deliverables)
- 역할·속성·스코프·감사 로그를 갖춘 작동하는 OAuth 2.0과 JWT 설정
- 샘플 서비스에 대해 테스트된 게이트웨이 구성(HTTPS, 속도 제한, 스키마 검증, 웹 애플리케이션 방화벽)
- 개선 노트를 포함한 보안 테스트 보고서
- 대시보드와 알림 규칙, 그리고 기본 분석 요약
- OpenAPI 문서·퀵스타트·키 관리를 갖춘 개발자 포털
- 버전 관리와 거버넌스 가이드

### 기대 결과
- **더 강력한 보안**: 중앙화된 강제와 함께 일관된 인증·인가
- **개선된 신뢰성**: 속도 제한, 방화벽 규칙, 알림이 사고를 줄임
- **명확한 가시성**: 지표와 트레이스가 문제 해결과 용량 계획을 가속화함
- **더 빠른 통합**: 셀프서비스 온보딩과 좋은 문서화
- **비즈니스 준비 완료**: 사용 계획·분석·포털이 수익화를 가능하게 함

## 요약
- 이 실습 프로젝트는 코스 전체에서 배운 인증/인가 표준화, API 게이트웨이, 보안·컴플라이언스, 모니터링/분석, 제품화, 거버넌스를 ApexFin 핀테크 시나리오에 종합적으로 적용해보는 캡스톤 성격의 과제임
