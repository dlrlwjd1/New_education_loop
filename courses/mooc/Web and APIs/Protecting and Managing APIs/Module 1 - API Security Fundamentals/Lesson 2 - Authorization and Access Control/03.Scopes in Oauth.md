# Scopes in OAuth (OAuth의 스코프)

## 개요
- OAuth 스코프(scope) — 앱이 접근할 수 있는 것을 통제하는 권한 — 가 왜 중요한지, 어떻게 정의·승인되는지, 실생활 사례를 다루는 3분 5초 분량 영상 — Module 1 "Lesson 2: Authorization and Access Control"의 세 번째 영상

## 내용

### 비유 — 집 전체 열쇠가 아니라 방 열쇠
- 스코프는 방 열쇠와 같음 — 집 전체 열쇠를 주는 게 아니라 필요한 방의 열쇠만 줌
- 예: 피트니스 앱은 걸음 수를 원하지, Gmail 받은편지함을 원하지 않음 — 스코프가 없다면 앱이 의도한 것보다 훨씬 많은 것에 접근할 수 있음

### 스코프란 무엇인가
- 스코프는 애플리케이션이 요청하는 권한 — 어떤 데이터나 행동이 허용되는지를 정의함(예: 캘린더 일정을 읽을 수는 있지만 삭제할 수는 없음)
- **최소 권한 원칙(least privilege)**을 강제함 — 앱이 필요한 최소한의 접근 권한만 받도록 함
- 사용자에게 직접적인 통제권을 줌 — 사용자가 그 권한을 부여할지 거부할지 결정함
- 스코프는 사용자와 앱 사이의 명확한 계약을 만들어 투명성과 보안을 보장함

### 스코프의 작동 흐름
1. 앱이 특정 스코프(예: email, profile)를 요청함
2. 사용자가 동의 화면(consent screen)을 통해 그 스코프를 검토·승인함
3. 인가 서버(authorization server)가 승인된 스코프를 인코딩한 접근 토큰을 발급함
4. 앱이 그 토큰을 사용하면 서버가 토큰을 검증하고 허용된 행동만 허가함
- 토큰을 콘서트의 손목 밴드라고 생각하면 됨 — 밴드의 색깔이 어디까지 들어갈 수 있는지를 보여줌

### 실생활 사례
- **클라우드 스토리지**: 앱이 파일에 대한 전체 통제권 대신 읽기 전용 접근만 받을 수 있음
- **Google로 로그인**: 이름과 이메일만 공유됨
- **캘린더 동기화**: 앱이 모든 약속을 읽지 않고도 일정을 추가함
- **모바일 앱**: 위치 데이터는 필요하지만 연락처는 필요하지 않을 수 있음
- 평소 사용하는 앱에서 권한을 확인하거나 거부했던 경험을 떠올려보면 — 그것이 바로 스코프가 실제로 작동하는 모습임

## 요약
- 스코프는 OAuth에서 최소 권한 원칙을 실현하는 메커니즘으로, 앱이 요청한 권한을 사용자가 검토·승인하면 인가 서버가 그 권한만 인코딩한 토큰을 발급해 앱의 접근을 정확히 제한함
- 클라우드 스토리지·소셜 로그인·캘린더 동기화·모바일 앱 등 일상적으로 사용하는 서비스 전반에서 스코프가 프라이버시를 보호함
