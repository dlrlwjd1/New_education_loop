# Role-Based Access Control (RBAC) (역할 기반 접근 제어)

## 개요
- RBAC가 무엇이고 어떻게 작동하는지, 왜 중요한지, 어떤 유형이 있고 산업별로 어떻게 쓰이는지 다루는 3분 49초 분량 영상 — Module 1 "Lesson 2: Authorization and Access Control"의 첫 영상

## 내용

### 문제 상황 — 아무나 모든 것에 접근할 수 있다면
- 병원에서 청소부부터 CEO까지 모든 직원이 모든 환자 기록에 접근할 수 있다면 얼마나 위험할지 상상해보면, 바로 이런 이유로 조직들이 RBAC(Role-Based Access Control)를 사용함

### RBAC의 작동 방식
- RBAC는 권한을 개인이 아니라 역할(role)에 직접 연결함 — 예를 들어 의사는 자신의 역할이 요구하기 때문에 환자 기록에 접근할 수 있고, 간호사는 활력징후만 업데이트할 수 있으며 전체 접근 권한은 필요하지 않음. 관리자는 일반적으로 시스템 전체에 더 넓은 통제권을 가짐
- 핵심은 권한이 역할에 묶여 있고 사용자는 자신의 역할에 따라 권한을 상속받는다는 것 — 이는 불필요한 노출을 방지하고 모두가 자신의 책임 범위 내에서만 활동하도록 보장함

### RBAC가 중요한 이유
1. 자원을 중앙화해 조직이 한 곳에서 접근을 관리할 수 있게 함
2. 역할 기반 접근을 제공해 누가 무엇을 할 수 있는지에 대한 추측이 필요 없게 함
3. 온보딩·오프보딩이 효율적임 — 역할을 배정하거나 제거하기만 하면 됨
4. 직무가 분리되어 한 사람이 통제되지 않은 권한을 갖지 않도록 보장함
5. 성장하는 조직에서 필수적인 확장성을 가짐
6. 오용 위험을 최소화해 보안을 강화함

### RBAC의 유형
- **플랫(Flat) RBAC**: 가장 단순한 형태 — 역할이 권한에 직접 매핑됨
- **계층적(Hierarchical) RBAC**: 구조를 추가해 역할이 상위 역할(예: 팀장 위의 관리자)로부터 권한을 상속받게 함
- **제약적(Constrained) RBAC**: 충돌하는 접근을 피하기 위한 규칙을 도입해, 한 사람이 상충하는 책임을 갖지 않도록 보장함
- **대칭적(Symmetric) RBAC**: 관리자에게도 규칙을 적용해 관리자의 행동 역시 역할에 의해 통제되도록 모델을 확장함
- 각 유형은 조직의 규모와 복잡성에 따라 서로 다른 유연성을 제공함

### 산업별 사용 사례
- **뱅킹**: 민감한 금융 데이터 접근을 제한해 승인된 직원만 거래를 조회·처리할 수 있게 함
- **헬스케어**: 의사·간호사가 자신의 환자와 관련된 정보만 보도록 해 프라이버시를 보호함
- **IT 시스템**: 서버·코드베이스·핵심 인프라에 대한 접근을 통제하는 데 필수적
- 민감한 데이터나 핵심 운영이 있는 곳이라면 어디든 RBAC가 신뢰·컴플라이언스·효율성의 근간이 됨

## 요약
- RBAC는 권한을 개인이 아닌 역할에 연결해 접근을 관리하며, 플랫·계층적·제약적·대칭적 등 조직 규모에 맞는 다양한 유형을 제공함
- 뱅킹·헬스케어·IT 등 민감한 데이터를 다루는 모든 산업에서 신뢰와 컴플라이언스의 핵심 메커니즘으로 작동함
