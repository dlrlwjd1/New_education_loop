# Attribute-Based Access Control (ABAC) (속성 기반 접근 제어)

## 개요
- ABAC가 무엇이고 RBAC와 어떻게 다른지, 핵심 특징과 속성 범주, 산업별 사용 사례를 다루는 3분 25초 분량 영상 — Module 1 "Lesson 2: Authorization and Access Control"의 두 번째 영상

## 내용

### 시작 비유 — 직함만이 아니라 맥락까지 확인하기
- 회사에서 민감한 파일에 접근하려 할 때, 시스템이 단순히 직함만 확인하는 게 아니라 당신이 누구인지, 어디에 있는지, 몇 시인지, 심지어 어떤 기기를 사용하는지까지 고려한다면 — 이것이 바로 속성 기반 접근 제어(ABAC)의 힘

### ABAC의 특징
- 사용자·리소스·행동·환경이라는 여러 속성(attribute)을 고려함 — 이는 ABAC를 맥락 인식적(context-aware)으로 만들어 시간·위치·기기에 따라 적응하게 함
- 정적인 역할보다 더 정밀한 세밀한 통제(granular control)를 제공함
- ABAC의 정책은 동적(dynamic)임 — 규칙이 바뀌어도 계속 재정의할 필요 없이 진화함
- 대규모 조직이 역할 과부하(role overload)를 피하도록 돕는 확장성을 가짐
- 이런 특성들이 함께 ABAC를 오늘날 빠르게 변화하는 IT 환경에 매우 유연하고 적합하게 만듦

### 왜 ABAC가 등장했는가
- 회사의 보안 네트워크에서 "기밀(confidential)"로 표시된 파일을 열려고 할 때, 시스템은 역할만 확인하는 게 아니라 "이것이 올바른 네트워크인가?", "사용자가 승인되었는가?", "조건이 충족되었는가?"를 묻고, 그래야만 접근이 허용됨
- 전통적인 RBAC는 정적인 환경에서 잘 작동했지만, 시스템이 점점 동적으로 변하면서 ABAC가 더 스마트하고 적응적인 해법으로 등장함

### ABAC의 세 가지 핵심 특성과 속성 범주
- **핵심 특성**: 다중 속성 기반(multi-attribute-based), 정책 주도(policy-driven), 맥락 인식(context-aware) — 결정이 하드코딩되지 않고 실시간으로 유연하게 적응함
- **속성 범주**:
  - **사용자 속성**: 부서, 역할, 승인 등급(clearance) 등
  - **리소스 속성**: 파일 유형, 소유자 등
  - **행동 속성**: 읽기·수정·삭제 등
- 이 속성들이 결합되면 시스템은 정적인 역할 전용 접근으로는 불가능한, 스마트하고 조건에 특화된 결정을 내릴 수 있음

### 산업별 사용 사례
- **교육**: 역할과 학기에 따라 접근을 결정
- **정부**: 승인 등급과 정책 규칙을 집행
- **클라우드 서비스**: 승인된 기기나 안전한 지역으로 접근을 제한
- **전자상거래**: 고객·벤더·지원 직원마다 권한을 맞춤화
- 이런 실제 사례들은 ABAC가 유연성과 보안을 결합해, 정적인 접근 규칙만으로는 부족한 상황에서 얼마나 유용한지를 보여줌

## 요약
- ABAC는 사용자·리소스·행동·환경 속성을 종합적으로 고려하는 맥락 인식적·정책 주도적 접근 제어 모델로, 정적인 RBAC의 한계를 넘어 동적이고 세밀한 접근 결정을 가능하게 함
- 교육·정부·클라우드·전자상거래 등 다양한 산업에서 유연성과 보안을 모두 요구하는 상황에 적합함
