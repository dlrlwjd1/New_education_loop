# Demonstration: Setting Up RBAC for an API (API에 RBAC 설정하기 실습 데모)

## 개요
- Node.js/Express로 브라우저 GUI를 갖춘 역할 기반 접근 제어(RBAC) 데모를 구축하는 7분 18초 분량 실습 데모 영상 — Module 1 "Lesson 2: Authorization and Access Control"의 다섯 번째이자 마지막 영상 항목
- 완성하면 서로 다른 역할로 로그인해 편집을 수행해보고 허용/거부 결정의 감사 추적(audit trail)을 확인할 수 있게 됨

## 내용

### Step 1 — 프로젝트 폴더 생성 및 라이브러리 설치

```bash
# 새 프로젝트 폴더 생성 후 이동
mkdir rbac-api-demo && cd rbac-api-demo

# Node.js 프로젝트 초기화 (기본 package.json 생성)
npm init -y

# 필요한 패키지 설치
npm install express jsonwebtoken dotenv
```
- Express(서버 구축), jsonwebtoken(JWT 인증 처리), dotenv(환경 변수 관리)를 설치함

### Step 2 — 파일 3개 준비
1. **`.env`**: 포트 3000에서 실행, 데모용 시크릿으로 토큰 서명, TTL(유효기간) 1시간으로 설정(시크릿은 나중에 변경 가능)
2. **`package.json`**: `main` 필드를 `server.js`로 지정(진입점), `start` 스크립트를 `node server.js`로 정의해 `npm start`로 서버 실행 가능하게 함, `dotenv`·`express`·`jsonwebtoken`이 dependencies에 포함되었는지 확인
3. **`server.js`**: JSON API와 브라우저 기반 GUI를 모두 구동하는 핵심 파일

### Step 3 — server.js 구조
- **초기 설정**: `.env`·Express·jsonwebtoken을 로드하고 Express 앱을 띄운 뒤 URL 인코딩·JSON 요청 바디를 처리하도록 설정. 환경변수에서 포트·JWT 시크릿·토큰 수명을 가져오거나, 설정되지 않았으면 안전한 기본값으로 대체함
- **샘플 데이터**: 두 개의 샘플 문서(document)와 빈 감사 로그(audit log) 배열을 정의 — 모든 읽기/편집 결정이 타임스탬프와 함께 여기 기록됨
- **헬퍼 함수**:
  - `issueToken`: 역할(role)과 스코프가 담긴 서명된 JWT 생성
  - `verifyToken`: 토큰 유효성 검증
  - `authenticate` 미들웨어: 요청에서 bearer 토큰을 찾아 미승인 사용자를 거부
  - `requireRole`: 사용자가 올바른 역할을 가졌는지 확인해 RBAC를 강제
  - `canReadDoc`/`canEditDoc`: 역할과 소유권(ownership)에 따라 사용자가 문서를 보거나 편집할 수 있는지 결정
- **API 라우트**:
  - `/login`: 사용자 ID와 역할을 받아 서명된 토큰을 반환
  - `/api/me`: 현재 로그인한 사용자 정보를 반환
  - `/document`(GET): 사용자에게 읽기 권한이 있으면 문서를 조회하고 그 결정을 감사 로그에 기록
  - `/document`(PUT): 사용자에게 편집 권한이 있으면 문서 수정을 허용하고 제목·본문 텍스트를 업데이트
  - `/audit`: 가장 최근의 접근 결정들을 반환해 누가 무엇에 왜 접근했는지 확인 가능
- **브라우저 인터페이스**: 서버가 직접 제공하는 완전한 웹 페이지 — 로그인 폼, 문서 뷰어/편집기, 감사 로그 표시 섹션을 포함해 브라우저에서 시각적으로 전체 시스템과 상호작용 가능
- **서버 시작**: `app.listen`으로 서버를 시작하고 콘솔에 `localhost:3000`에서 실행 중임을 확인하는 메시지를 출력

### Step 4 — 서버 실행 및 확인

```bash
npm start
```
- "Role-based and attribute-based access control is running at localhost:3000" 같은 메시지가 표시됨
- 브라우저에서 확인하면: 왼쪽에 로그인 패널(사용자 ID 입력 + admin/editor/viewer 역할 선택, 로그인 클릭 시 서명된 토큰 생성·저장), 오른쪽에 문서 패널(문서 ID로 조회, 제목·본문 보기/편집), 하단에 감사 섹션(가장 최근 접근 결정과 허용/거부 여부 표시)이 나타남

### Step 5 — 역할별 동작 테스트
- **Admin으로 로그인**: 모든 문서를 자유롭게 편집 가능 — 관리자는 시스템에 대한 완전한 통제권을 가지며 제한 없이 읽기·수정·삭제 가능
- **Editor로 로그인**: 모든 문서를 조회할 수 있지만, 자신이 소유한 문서만 편집 가능 — 다른 사용자 소유 문서를 편집하려 하면 "forbidden" 메시지를 받음(속성 기반 통제가 작동하는 것을 보여줌)
- **Viewer로 로그인**: 문서를 열고 읽을 수 있지만 저장 버튼이 아무 동작도 하지 않음 — 뷰어는 엄격한 읽기 전용 접근만 가지며 아무것도 수정·삭제할 수 없음
- 모든 행동은 감사를 위해 기록됨

## 요약
- Express·JWT 기반 미니 API에서 `requireRole`·`canReadDoc`/`canEditDoc` 헬퍼로 RBAC(+속성 기반 소유권 검사)를 구현하고, 모든 읽기/편집 결정을 감사 로그에 남기는 전체 흐름을 손으로 확인함
- Admin(전권)·Editor(자기 소유 문서만 편집)·Viewer(읽기 전용)라는 세 역할이 실제로 어떻게 다른 접근 수준을 갖는지, 그리고 감사 로그가 모든 접근 결정을 어떻게 기록하는지가 핵심 검증 포인트
