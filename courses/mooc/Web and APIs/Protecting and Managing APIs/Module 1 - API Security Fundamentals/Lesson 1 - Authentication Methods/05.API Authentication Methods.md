# API Authentication Methods (API 인증 방법)

## 개요
- API 인증이 무엇이고 왜 API 보안의 근간인지, 주요 인증 방법의 종류와 아키텍처, 실생활 적용 사례를 다루는 4분 47초 분량 영상 — Module 1 "Lesson 1: Authentication Methods"의 다섯 번째 항목

## 내용

### API 인증이란
- API는 애플리케이션·서비스·기기를 잇는 디지털 다리와 같은데, 이 다리가 안전하지 않으면 공격자가 몰래 건너와 민감한 데이터에 접근할 수 있음
- API 인증(authentication)은 클라이언트나 사용자가 자신이 주장하는 존재임을 접근 권한을 부여받기 전에 검증하는 것 — 보안 건물에 들어가기 전 신분증을 확인하는 것과 같음, 검증된 사용자만 민감한 리소스와 상호작용할 수 있게 하는 첫 번째 방어선
- 인증은 인가(authorization, 검증된 사용자가 실제로 수행할 수 있는 행동을 정의)와 긴밀히 연결되어 함께 게이트키핑 시스템을 이룸

### 인증이 중요한 이유
1. 소중한 디지털 자원에 대한 무단 접근을 방지함(현관문의 잠금장치와 같음)
2. 모든 요청이 검증되고 신뢰할 수 있도록 데이터 무결성을 유지함
3. 클라이언트-API 간 통신을 안전하게 지켜 민감 정보가 가로채이지 않도록 함
4. 신뢰와 컴플라이언스를 구축함 — 기업이 엄격한 규제를 준수하고 고객 신뢰를 보호해야 하는 오늘날 필수적

### 인증 방법의 종류
- **API 키(API keys)**: 애플리케이션을 위한 비밀번호처럼 작동하는 가장 단순한 방법 — 노출되면 안전하지 않을 수 있음
- **OAuth 2.0**: 구글·페이스북 계정으로 앱에 로그인하는 것 같은 위임된 접근(delegated access)에 널리 사용됨
- **정적 인증(Static authentication)**: 각 요청과 함께 사용자명·비밀번호를 전송하는 방법 — 단순하지만 가장 안전하지는 않음
- **JWT(JSON Web Token)**: 사용자 데이터를 안전하게 담고 무상태(stateless) 통신을 가능하게 해 현대 웹·모바일 애플리케이션에 효율적 — 인기가 높아지는 방법
- 각 방법에는 트레이드오프가 있으며, 조직은 맥락과 위험도에 따라 선택함

### 인증 아키텍처의 작동 방식
1. 클라이언트가 자격증명이나 토큰과 함께 API에 요청을 보냄
2. 요청은 API 게이트웨이를 거치며, 게이트웨이가 인증 세부사항을 검증함
3. 자격증명이 유효하면 게이트웨이가 요청을 리소스 서버로 전달함
4. 서버는 인증과 인가를 모두 확인한 뒤에만 응답함
- 요약하면 인증은 "당신은 누구인가?"에 답하고, 인가는 "당신이 할 수 있는 것은 무엇인가?"를 묻는 것 — 둘이 함께 모든 단계에서 요청이 안전하고 통제되도록 보장함

### 실생활 적용 사례
- **온라인 뱅킹**: 계좌 소유자만 송금할 수 있도록 보장
- **소셜 미디어**: 계정 탈취로부터 사용자 계정을 보호
- **전자상거래**: 거래 중 결제 정보와 고객 데이터를 보호
- **헬스케어**: 엄격한 데이터 보호법을 준수하면서 민감한 환자 기록을 보호
- 업종을 막론하고 인증은 선택 사항이 아니며 안전하고 신뢰할 수 있는 디지털 상호작용의 근간임

## 요약
- API 인증은 클라이언트의 신원을 검증하는 첫 방어선이며, 인가와 함께 게이트키핑 시스템을 이룸 — API 키·OAuth 2.0·정적 인증·JWT 등 다양한 방법이 존재하며 각기 트레이드오프가 다름
- 인증 아키텍처는 클라이언트 → API 게이트웨이(검증) → 리소스 서버(인증+인가 확인) → 응답의 흐름을 따르며, 온라인 뱅킹부터 헬스케어까지 모든 산업에서 필수적임
