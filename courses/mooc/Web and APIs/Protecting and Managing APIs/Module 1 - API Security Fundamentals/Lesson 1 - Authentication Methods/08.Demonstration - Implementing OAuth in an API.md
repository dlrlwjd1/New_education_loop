# Demonstration: Implementing OAuth in an API (API에 OAuth 구현하기 실습 데모)

## 개요
- GitHub OAuth 앱을 만들고 Node.js/Express 프로젝트를 구성해 사용자가 GitHub 계정으로 로그인할 수 있게 만드는 6분 30초 분량 실습 데모 영상 — Module 1 "Lesson 1: Authentication Methods"의 여덟 번째이자 마지막 영상 항목
- 완성되면 OAuth 인증으로 라우트를 보호하고 사용자 세션을 개인화하는 실제로 동작하는 API를 갖추게 됨

## 내용

### 사전 준비 확인
- 터미널(Windows는 Command Prompt/PowerShell, macOS는 터미널 앱)을 열어 `node -v`로 Node.js 설치를, `npm -v`로 npm(Node Package Manager) 설치를 확인함 — 두 명령 모두 버전 번호가 나오면 준비 완료

### Step 1 — GitHub OAuth 앱 생성
1. GitHub 계정에 로그인 → 우측 상단 프로필 사진 클릭 → Settings
2. 왼쪽 메뉴에서 아래로 스크롤해 Developer Settings 선택
3. OAuth Apps → New OAuth App 클릭
4. 폼 입력: Application name = `OAuth Mini Demo`, Homepage URL = `localhost:3000`, Authorization callback URL = `localhost:3000/callback`
5. Register Application 클릭 → Client ID 확인·복사 → Generate a New Client Secret으로 Client Secret도 생성·복사 (이 두 값은 이후 `.env` 파일에 붙여넣음)

### Step 2 — 로컬 프로젝트 설정

```bash
# 새 폴더 생성 후 이동
mkdir oauth-mini-demo && cd oauth-mini-demo

# Node.js 프로젝트 초기화
npm init -y

# 필요한 패키지 설치
npm i express express-session axios dotenv
```

### Step 3 — 환경 변수 파일(.env) 작성
- `oauth-mini-demo` 폴더 안에 `.env` 파일을 만들고, GitHub Client ID·Secret 값을 앞서 복사한 값으로 채워 넣음

### Step 4 — 서버 코드(server.js) 작성
- 같은 폴더에 `server.js` 파일을 만들어 코드를 작성함(영상 리소스 섹션에 전체 코드 제공)
- 핵심 로직:
  - **루트 라우트(`/`)**: 방문 시 "OAuth Mini Demo" 제목과 함께, `request.session.user`가 설정되어 있으면 "Logged in as: {GitHub 사용자명}"을, 없으면 "Not logged in"을 표시하는 HTML을 동적으로 생성함. 아래에 세 개의 링크를 둠 — `/login`(GitHub로 로그인), `/api/hello`(보호된 API 엔드포인트), `/logout`(세션 종료)
  - **`/login`**: GitHub OAuth 인증 흐름을 시작함
  - **`/callback`**: GitHub가 인증 후 리다이렉트하는 콜백 라우트
  - **`/api/hello`**: 로그인하지 않은 상태로 접근하면 `{"error": "unauthorized, visit /login first"}` 같은 JSON 오류를 반환하는 보호된 엔드포인트 — 로그인 후에는 `{"message": "hello, {GitHub 사용자명}"}` 같은 친근한 JSON 메시지를 반환함
  - **`/logout`**: 세션을 지움

### Step 5 — 실행 스크립트 확인 및 서버 시작
- `package.json`의 `scripts` 섹션에 `start` 스크립트가 포함되어 있는지 확인(한 번의 명령으로 앱을 시작할 수 있도록)

```bash
npm start
```
- "Running on localhost:3000" 같은 메시지가 보이면 서버가 정상 구동된 것

### Step 6 — 동작 확인
1. 브라우저에서 `localhost:3000` 접속 → "OAuth Mini Demo" 제목과 "Not logged in" 표시, 세 개의 링크 확인
2. 로그인 전 `/api/hello`에 직접 접근하면 "unauthorized, visit /login first" 같은 JSON 에러 반환 — 엔드포인트가 보호되고 있음을 확인
3. "Login with GitHub" 클릭 → GitHub 권한 요청 승인 → 홈페이지로 리다이렉트되며 "Logged in as: {GitHub 사용자명}" 표시로 변경
4. 이제 `/api/hello`에 접근하면 `{"message": "hello, {GitHub 사용자명}"}` 같은 정상 JSON 응답을 받음

## 요약
- GitHub OAuth 앱 생성 → `.env`에 Client ID/Secret 저장 → Express 서버에서 `/login`·`/callback`·`/api/hello`(보호됨)·`/logout` 라우트를 구성하는 전체 흐름을 통해, OAuth 2.0이 실제로 API 엔드포인트를 어떻게 보호하고 세션을 개인화하는지 손으로 확인함
- 로그인 전에는 보호된 API가 401 성격의 JSON 에러를 반환하고, GitHub 인증 후에는 세션 기반으로 사용자 이름이 포함된 응답을 반환하는 것이 핵심 검증 포인트
