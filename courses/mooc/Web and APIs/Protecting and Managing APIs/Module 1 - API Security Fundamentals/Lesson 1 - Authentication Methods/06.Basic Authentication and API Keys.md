# Basic Authentication and API Keys (기본 인증과 API 키)

## 개요
- 기본 인증(Basic Authentication)과 API 키라는 가장 널리 쓰이는 두 인증 방법의 작동 방식과 워크플로, 실생활 사용 사례를 다루는 5분 3초 분량 영상 — Module 1 "Lesson 1: Authentication Methods"의 여섯 번째 항목

## 내용

### 개요 — 두 방법의 공통점
- 기본 인증과 API 키 모두 API를 보호하는 데 널리 사용되며 디지털 자원의 첫 방어선 역할을 함 — 클라이언트나 애플리케이션이 시스템에 접근할 자격이 있음을 증명하는 디지털 신분증과 같음
- 인증이 없다면 누구나 데이터에 접근을 시도할 수 있어 큰 보안 위험이 됨 — 접근을 허용하기 전 클라이언트 신원을 검증함으로써 신뢰된 사용자·애플리케이션만 API와 상호작용할 수 있게 함

### 기본 인증(Basic Authentication)
- API를 보호하는 가장 오래되고 단순한 방법 중 하나 — 모든 요청과 함께 전송해야 하는 사용자명·비밀번호 조합을 사용함
- 노출을 방지하기 위해 이 방법은 전송 중 자격증명을 암호화하도록 HTTPS를 요구함
- 단순하지만 검증된 사용자만 리소스에 접근하도록 보장함 — 다만 자격증명을 반복 사용하는 방식이라 현대적 방법보다 덜 안전하며, 소규모 또는 저위험 환경에서 주로 사용됨
- **워크플로**: 클라이언트가 요청 헤더에 사용자명·비밀번호를 담아 요청을 시작 → 서버로 전송 → 서버가 기록과 대조해 자격증명을 검증 → 일치하면 검증된 응답으로 접근을 허용, 아니면 요청을 거부 — 매 요청마다 자격증명이 전달되므로 안전한 전송이 중요함을 보여줌

### API 키(API Key)
- 고유한 접근 토큰처럼 작동함 — 애플리케이션을 위한 디지털 신분증이라 생각하면 됨
- 앱이 API를 호출할 때마다 이 키가 요청자를 인증하고 사용량을 추적하는 데 사용됨 — 예: 날씨 앱이 API 키로 제공자로부터 예보 데이터를 가져와 등록된 앱만 서비스를 사용하도록 보장
- 집 열쇠처럼 API 키를 비공개로 안전하게 유지하는 것이 중요함 — 다른 사람이 키를 손에 넣으면 오용하거나 무단 요청을 하거나 비용을 발생시킬 수 있음
- **워크플로**: 클라이언트가 고유 키를 담아 요청을 전송 → 서버가 키를 수신·검증 → 유효하면 응답을 반환 — 사용자명이나 비밀번호 없이 키 자체만 교환되므로, 기본 인증보다 빠르고 사용이 쉬워 특히 기계 간(machine-to-machine) 통신에 적합함. 다만 키가 노출되거나 제대로 보호되지 않으면 무단 접근을 허용할 수 있어, 속도 제한(rate limiting)·암호화·키 로테이션(key rotation) 같은 모범 사례가 중요함

### 실생활 사용 사례
- **기본 인증**: 직원이 사용자명·비밀번호로 회사 포털에 로그인하는 것 같은 단순한 설정에 흔히 사용됨 — 구현이 쉽지만 현대적인 분산 시스템에는 유연성이 떨어짐
- **API 키**: 모바일 앱이나 서드파티 서비스에서 널리 사용됨 — 예: 모바일 앱이 API 키로 날씨 서비스에서 데이터를 가져오는 경우
- 두 접근법 모두 오늘날에도 여전히 유효하지만, 각각의 한계를 이해하는 것이 언제 사용할지 아는 핵심임

## 요약
- 기본 인증은 사용자명·비밀번호를 매 요청마다 HTTPS로 암호화해 전송하는 단순하지만 덜 유연한 방법이고, API 키는 애플리케이션 단위의 고유 토큰으로 빠르고 기계 간 통신에 적합하지만 키 유출 시 위험이 있어 속도 제한·암호화·키 로테이션 같은 보호 조치가 필요함
