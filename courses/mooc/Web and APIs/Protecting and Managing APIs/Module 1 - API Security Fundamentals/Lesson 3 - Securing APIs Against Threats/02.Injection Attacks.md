# Injection Attacks (인젝션 공격)

## 개요
- 인젝션 공격이 무엇이고 어떻게 시작·진화했는지, 주요 실제 사고 사례, 핵심 방어 기법을 다루는 3분 44초 분량 영상 — Module 1 "Lesson 3: Securing APIs Against Threats"의 두 번째 영상

## 내용

### 역사 — 1990년대 후반부터 오늘날까지
- 인젝션 공격은 1990년대 후반, 공격자들이 웹사이트 쿼리에 악성 SQL 코드를 삽입하는 방법을 찾아내면서 처음 등장함 — 처음에는 단순했음: 로그인 폼에 예상치 못한 코드를 입력해 보안을 우회하는 방식
- 시간이 지나며 공격자들은 NoSQL 인젝션과 명령어 인젝션(command injection) 변형을 만들어내며 다양화함
- 수십 년이 지난 지금도 이 공격은 매우 중요해서 오늘날까지도 OWASP Top 10 보안 위험에 포함되어 있음

### 실제 사고 사례
- **2011년 소니 PlayStation Network**: SQL 인젝션으로 7,700만 사용자 계정이 노출되고, 수 주간의 다운타임과 무거운 법적 처벌로 이어짐
- **2015년 TalkTalk**: 단순한 SQL 결함으로 공격자가 은행 정보를 포함한 15만 건의 고객 기록을 훔침
- **2017년**: 잘못 설정된 쿼리로 개인정보와 정치 데이터를 포함한 1억 9,800만 건의 미국 유권자 기록이 노출됨
- 이 사례들은 인젝션 공격이 기업·정부·수백만 명의 개인에게 영향을 미칠 수 있음을 보여주며, 방어를 최우선 과제로 만듦

### 인젝션 공격의 3단계
1. **입력 진입(Input entry)**: 공격자가 정상적인 입력으로 위장한 악성 페이로드를 폼 필드나 URL에 삽입함
2. **쿼리 실행(Query execution)**: 애플리케이션이 입력을 정제(sanitize)하지 못하고 데이터베이스 명령어에 직접 삽입해, 공격자의 코드가 실행됨
3. **무단 결과(Unauthorized results)**: 데이터 유출, 데이터 변조, 심지어 전체 시스템 침해로 이어질 수 있음
- 아무 열쇠나 받아주는 자물쇠를 상상하면 됨 — 열쇠를 신중히 확인하지 않으면 침입자가 그냥 걸어 들어옴

### 방어 — 계층화된 접근법
1. **입력 검증(Input validation)**: 사용자 입력을 엄격히 확인하고 예상 패턴을 벗어나는 것은 모두 거부함
2. **파라미터화된 쿼리(Parameterized queries)**: 준비된 문(prepared statement)을 사용해 데이터가 항상 명령어와 분리되도록 함
3. **저장 프로시저(Stored procedures)**: 미리 정의된 데이터베이스 쿼리를 실행해 공격자가 근본 로직을 바꿀 수 없게 함
4. **보안 테스트**: 정기적인 코드 리뷰, 자동화된 스캔, 침투 테스트로 취약점을 조기에 발견함
- 디지털 문에 여러 개의 자물쇠를 다는 것과 같음 — 계층이 많을수록 공격자가 침입하기 어려워짐

## 요약
- 인젝션 공격은 1990년대 SQL 인젝션에서 시작해 NoSQL·명령어 인젝션으로 진화했으며, 소니 PSN·TalkTalk·미국 유권자 데이터베이스 같은 대규모 실제 사고를 일으켜 옴
- 입력 진입 → 쿼리 실행 → 무단 결과의 3단계로 진행되며, 입력 검증·파라미터화된 쿼리·저장 프로시저·정기적 보안 테스트라는 계층화된 방어로 막을 수 있음
