# Demonstration: Conducting Security Testing on an API — Part 1: script.js and index.html Setup (API 보안 테스트 실습 데모 1부)

## 개요
- SQL 인젝션·경로 순회(path traversal)·접근 제어 결함·서비스 거부 같은 흔한 공격이 취약한 API를 어떻게 악용하는지, 그리고 입력 검증·경로 확인·적절한 인가·속도 제한을 갖춘 강화된(hardened) API에서는 같은 테스트가 어떻게 차단되는지 보여주는 3부작 실습 데모의 1부(3분 52초) — Module 1 "Lesson 3: Securing APIs Against Threats"의 다섯 번째 영상 항목
- 안전한 코딩과 철저한 테스트의 중요성을 강조하는 데모로, 이 1부에서는 프로젝트 설정과 프런트엔드(index.html, script.js) 구성을 다룸

## 내용

### Step 1 — 프로젝트 초기 설정

```bash
# 프로젝트 폴더 생성 후 이동
mkdir api-security-testing-demo && cd api-security-testing-demo

# Node.js 프로젝트 초기화
npm init

# 필요한 패키지 설치
npm install express dotenv
```
- `.env` 파일을 만들고 `PORT=3000`을 추가함(다른 포트를 쓰려면 숫자를 바꾸면 됨)

### Step 2 — package.json 구성
- 새로 만든 `package.json` 파일을 열어 내용을 전부 지우고, 영상 리소스 섹션에 제공된 블록으로 교체함
- `package.json`은 프로젝트의 정체성과 핵심 설정(이름·버전·설명), 메인 진입 파일(`server_vulnerable.js`), 취약(vulnerable)/강화(hardened) 서버를 각각 시작하는 두 개의 스크립트 단축키, 서버 실행에 필요한 의존성을 정의함

### Step 3 — index.html 작성
- 데모 서버를 테스트하는 단일 페이지 인터페이스를 제공하는 `index.html`을 영상 리소스 섹션의 파일로 작성함
- 단순한 CSS로 깔끔한 레이아웃을 구성하고, 다섯 개의 인터랙티브 카드로 조직됨: **Injection test**(인젝션 테스트), **Path traversal**(경로 순회), **Auth bypass**(인증 우회), **Rate limit/DoS simulation**(속도 제한/DoS 시뮬레이션), **Audit**(감사)
- 각 카드는 입력란과 버튼을 포함하며, `script.js`의 JavaScript 함수를 호출해 서버에 요청을 보내고 응답을 표시함
- 이 동일한 페이지가 취약한 서버와 강화된 서버 모두에서 작동해, 안전하지 않은 동작과 안전한 동작을 나란히 비교하기 쉽게 만듦

### Step 4 — script.js 작성
- 데모 인터페이스의 모든 프런트엔드 로직을 제공하는 `script.js`를 영상 리소스 섹션의 파일로 작성함
- HTTP 요청을 수행하고 JSON 응답을 파싱하는 재사용 가능한 API 헬퍼 함수를 정의함
- 각 보안 테스트를 처리하는 별도 함수들:
  - `runInjection`: SQL 인젝션 점검
  - `runRead`: 경로 순회 파일 읽기
  - `runAdmin`/`runAdminHeader`: 관리자 접근 테스트
  - `runDos`: 속도 제한/DoS 점검을 위한 다중 로그인 시도 시뮬레이션
  - `refreshAudit`: 화면상의 감사 로그를 갱신
- 이 코드는 의도적으로 단순하고 안전하게 작성되었으며, 취약한 서버와 강화된 서버 어느 쪽과도 작동해 결과를 브라우저에 직접 표시함

## 요약
- 이 1부에서는 5가지 보안 테스트(인젝션·경로 순회·인증 우회·DoS·감사)를 위한 단일 페이지 테스트 UI(`index.html`)와 그 프런트엔드 로직(`script.js`)을 준비함 — 같은 UI로 취약한 서버와 강화된 서버의 동작을 나란히 비교할 수 있게 설계됨
