# Common API Attacks Overview (흔한 API 공격 개요)

## 개요
- 공격자가 API 취약점을 어떻게 악용하는지, 주목해야 할 주요 공격 유형, 시스템을 안전하게 지키는 핵심 전략을 다루는 3분 44초 분량 영상 — Module 1 "Lesson 3: Securing APIs Against Threats"의 첫 영상

## 내용

### API 공격이란
- 누군가 애플리케이션의 API에 있는 취약점을 악용할 때 발생함 — 해커는 이런 약점을 이용해 무단 접근을 얻거나, 데이터를 훔치거나, 서비스를 방해함
- API는 흔히 개인정보·금융 데이터·비즈니스 기밀 같은 민감한 정보를 다루므로, 침해당하면 금전적 손실뿐 아니라 법적 문제와 고객 신뢰의 심각한 훼손으로 이어짐

### 다섯 가지 흔한 공격 유형
1. **인증 결함(Broken authentication)**: 약한 토큰이나 부실한 세션 통제로 공격자가 실제 사용자를 사칭할 수 있게 됨
2. **과도한 데이터 노출(Excessive data exposure)**: API가 필요 이상의 데이터를 전송해 의도치 않게 민감한 정보를 노출함
3. **매스 어사인먼트(Mass assignment)**: 숨겨진 필드가 조작되어 권한이 상승될 수 있음
4. **인젝션 공격(Injection attack)**: SQL·NoSQL 인젝션 같은 악성 코드가 입력 필드를 통해 스며듦
5. **DoS 또는 속도 제한 남용(Rate abuse)**: 트래픽으로 API를 압도해 서비스를 방해함
- 각각 다른 약점을 악용하지만 모두 심각한 결과를 초래할 수 있음

### 공격자의 전형적인 워크플로
1. **정찰과 공격(Reconnaissance and attack)**: 엔드포인트를 찾아 조작된 요청을 전송함
2. **악용(Exploitation)**: 부실한 검증이나 누락된 인증 확인 때문에 API가 입력을 잘못 처리함
3. **영향(Impact)**: 데이터가 유출되거나 서비스가 저하·중단됨
4. **탐지와 감사(Detection and audit)**: 로그가 의심스러운 활동을 포착해 사고 대응을 촉발함
- 이 패턴을 이해하면 심각한 피해가 발생하기 전에 공격을 더 잘 예측하고 차단할 수 있음

### API를 보호하는 방법
1. **강력한 인증**: 견고한 토큰과 엄격한 세션 통제를 강제함
2. **입력 검증**: 들어오는 모든 요청을 정제(sanitize)해 악성 코드를 차단함
3. **속도 제한(Rate limiting)**: 과도하거나 남용적인 트래픽을 제한해 DoS 공격을 방지함
4. **로깅과 알림**: 실시간으로 활동을 추적하고 이상 징후를 빠르게 표시함
- 이런 조치들을 구현하는 것이 대부분의 API 공격에 대한 강력한 방어를 형성하며 조직 보안 태세의 핵심 요소임

## 요약
- API 공격은 인증 결함·과도한 데이터 노출·매스 어사인먼트·인젝션·DoS 등 다양한 형태를 취하며, 공격자는 정찰 → 악용 → 영향 → 탐지의 예측 가능한 패턴을 따름
- 강력한 인증, 입력 검증, 속도 제한, 로깅·알림이 이런 공격에 대한 핵심 방어선을 형성함
