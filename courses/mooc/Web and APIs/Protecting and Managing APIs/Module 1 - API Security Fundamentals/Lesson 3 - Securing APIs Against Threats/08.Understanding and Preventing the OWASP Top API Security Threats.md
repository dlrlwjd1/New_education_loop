# Reading: Understanding and Preventing the OWASP Top API Security Threats (OWASP Top API 보안 위협 이해와 예방)

## 개요
- OWASP API Security Top 10이 강조하는 가장 치명적인 취약점들, 실제 사례, 예방을 위한 모범 사례를 다루는 10분 분량 읽기자료 — Module 1 "Lesson 3: Securing APIs Against Threats"의 여덟 번째이자 마지막 항목
- API는 모바일 앱부터 엔터프라이즈 통합까지 현대 애플리케이션의 근간이지만, 그 개방성과 연결성 때문에 공격자의 주요 표적이 됨

## 내용

### 흔한 API 보안 위협
- **BOLA(Broken Object Level Authorization, 객체 수준 인가 결함)**
  - **문제**: 공격자가 객체 ID를 조작해 접근해서는 안 되는 데이터에 접근함
  - **예시**: `/user/123`을 `/user/124`로 바꿔 다른 사용자의 프로필을 봄
  - **영향**: 데이터 노출, 프라이버시 침해
  - **예방**: 모든 요청에 대해 객체 수준 인가 확인을 강제함
- **인증 결함(Broken Authentication)**
  - **문제**: 약하거나 잘못 설정된 인증 메커니즘이 무단 접근을 허용함
  - **예시**: 기본 자격증명에 의존하거나 토큰 만료가 없는 API
  - **영향**: 계정 탈취, 무단 데이터 접근
  - **예방**: 강력한 인증(OAuth 2.0, MFA) 구현
- **과도한 데이터 노출(Excessive Data Exposure)**
  - **문제**: API가 필요 이상의 데이터를 반환해 민감한 세부사항을 노출함
  - **예시**: 이름만 필요한데 전체 고객 기록을 반환하는 엔드포인트
  - **영향**: 개인·금융 정보 유출
  - **예방**: "최소 권한" 원칙을 따르고 응답을 필터링함

### 공격 벡터 심화
- **인젝션 공격**
  - **문제**: 검증되지 않은 입력이 악성 코드(SQL, NoSQL, LDAP 등)의 삽입을 허용함
  - **예시**: `id=1 OR 1=1`로 인증을 우회함
  - **영향**: 데이터 도난·손상 또는 시스템 전체 침해
  - **예방**: 파라미터화된 쿼리와 입력 검증 사용
- **중간자 공격(MITM)**
  - **문제**: 공격자가 클라이언트-서버 간 통신을 가로챔
  - **예시**: 암호화되지 않은 HTTP를 통한 API 트래픽 스니핑
  - **영향**: 자격증명 도난, 데이터 변조
  - **예방**: HTTPS/TLS와 인증서 피닝(certificate pinning)을 항상 강제함
- **서비스 거부(DoS)**
  - **문제**: 공격자가 요청으로 API를 압도해 자원을 고갈시킴
  - **예시**: 초당 수천 개의 요청을 보내는 자동화된 봇
  - **영향**: API 다운타임, 서비스 중단, 매출 손실
  - **예방**: 속도 제한, 스로틀링, 로드 밸런싱 적용

### 보안 모범 사례와 예방
1. **강력한 인증과 인가**: OAuth 2.0, JWT, 역할/속성 기반 접근을 사용함
2. **입력 검증과 정제**: 사용자 입력을 절대 신뢰하지 않고 형식과 길이를 검증함
3. **모든 곳에 암호화**: 전송 중 데이터는 TLS로, 저장 데이터는 강력한 알고리즘으로 보호함
4. **속도 제한과 모니터링**: 임계값을 설정하고 이상 징후에 알림을 보내 남용을 방지함
5. **보안 테스트**: 정기적인 침투 테스트, 취약점 스캔, 자동화된 API 테스트
6. **로깅과 감사**: 사고 대응을 위해 접근·변경 기록을 유지함

## 요약
- OWASP API Security Top 10은 BOLA·인증 결함·과도한 데이터 노출·인젝션·MITM·DoS 같은 가장 위험한 위협을 식별하고 완화하기 위한 로드맵 역할을 함
- 강력한 인증, 암호화, 속도 제한 같은 예방 조치를 적용함으로써 개발자는 사용자와 조직을 모두 보호하는 견고한 API를 만들 수 있음
