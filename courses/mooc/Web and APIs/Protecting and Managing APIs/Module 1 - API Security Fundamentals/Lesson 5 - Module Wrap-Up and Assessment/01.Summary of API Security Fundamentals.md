# Reading: Summary of API Security Fundamentals (Module 1 요약)

## 개요
- Module 1 전체("API Security Fundamentals")를 정리하는 30분 분량 요약 읽기자료 — 인증·인가 방법, 흔한 보안 위협, 암호화, 컴플라이언스·안전한 API 운영을 위한 모범 사례를 되짚음

## 내용

### API 보안 기초 이해하기
- API는 클라이언트와 서버 간 통신을 가능하게 하는 현대 애플리케이션의 핵심이지만, 보안이 확보되지 않은 API는 공격에 취약함 — API 보안은 정당한 사용자만 데이터에 접근하고 다양한 조건에서도 API가 신뢰할 수 있게 유지되도록 보장함
- **인증 vs. 인가**: 인증(authentication)은 사용자나 클라이언트의 신원을 검증하고, 인가(authorization)는 그들이 수행할 수 있는 행동을 통제함 — OAuth 2.0과 JWT 같은 고급 방법은 기본 인증이나 API 키보다 더 강력한 보안과 세밀한 접근 제어를 제공함. RBAC와 ABAC는 권한을 체계적으로 강제하는 데 도움을 줌
- **흔한 위협**: API는 인젝션 공격, 중간자(MITM) 공격, 서비스 거부(DoS) 공격 같은 위험에 직면함 — 예를 들어 SQL 인젝션은 정제되지 않은 입력을 악용하고, MITM 공격은 전송 중인 민감 데이터를 가로챔

### API 보안 확보의 핵심 이점
1. **데이터 보호와 컴플라이언스**: 암호화가 기밀성을 보장하고, GDPR·HIPAA·PCI DSS 같은 표준 준수가 법적 요구사항을 충족함
2. **신뢰성과 신뢰**: 안전한 API는 침해와 서비스 중단을 방지해 사용자와 파트너 사이의 신뢰를 높임
3. **운영 효율성**: 자동화된 보안 통제가 수작업 부담을 줄여 팀이 더 상위 수준의 작업에 집중할 수 있게 함
4. **위험 감소와 ROI**: 침해를 방지하는 것이 다운타임·복구·평판 손상과 관련된 비용을 낮춤

### API 워크플로에 보안 통합하기
- **통합 단계**: 민감 데이터를 다루는 핵심 엔드포인트 식별 → 인증·인가(OAuth 2.0, RBAC/ABAC) 구현 → 전송 중(HTTPS)·저장 데이터 암호화 → 보안 테스트와 취약점 평가 수행 → API 트래픽 모니터링과 컴플라이언스를 위한 감사 로그 유지
- **성공을 측정하는 KPI**: 탐지·차단된 공격 수, 보안 조치가 적용된 엔드포인트 비율, 보안 조치 하에서의 응답 시간, 컴플라이언스 준수 점수
- **API 보안 확장하기**: 핵심 보안 조치가 확립되면 추가 API·서비스·환경으로 확장할 수 있음 — 정기 감사, 암호화 표준 업데이트, 적응형 접근 제어 정책이 진화하는 위협에 대한 장기적 회복탄력성을 보장함
