# Reading: Practice Project — Building a Secure and Compliant Healthcare API Ecosystem (실습 프로젝트: 안전하고 규정을 준수하는 헬스케어 API 생태계 구축)

## 개요
- Module 1에서 배운 인증·인가·암호화·위협 방지를 종합해 적용해보는 45분 분량 실습 프로젝트 개요 읽기자료 — Module 1 "Lesson 5: Module Wrap-Up and Assessment"의 두 번째 항목

## 내용

### 시나리오
- 헬스케어 스타트업 MediServe는 병원·클리닉·보험 파트너를 연결해 환자 기록을 안전하게 교환하는 API를 제공함
- 사용량이 늘어나면서 심각한 문제들이 나타남: 테스트 환경에 노출된 API 키, 서비스 전반에 걸친 취약한 인증 방법, 컴플라이언스 담당자가 제기한 암호화·규제 표준 우려
- 이는 다음으로 이어짐: 비프로덕션 환경의 노출된 API 키, 일관되지 않은 인증 방법으로 인한 보안 위험, 민감한 의료 데이터에 대한 무단 접근 시도, HIPAA·GDPR 표준 관련 컴플라이언스 위험
- CTO는 표준화된 인증, 견고한 인가, 암호화, 흔한 위협에 대한 방어를 갖춘 강력한 API 보안 프레임워크를 원함

### 과제
다음을 포함하는 API 보안 솔루션을 설계함:
1. 안전한 인증을 위해 JWT와 함께 OAuth 2.0 구현
2. 서로 다른 파트너 역할을 위한 RBAC(역할 기반 접근 제어) 설정
3. 입력 검증과 속도 제한을 사용해 인젝션·DoS 공격으로부터 API 보호
4. 모든 엔드포인트에 HTTPS/TLS를 활성화하고 전송 중·저장 데이터의 민감 정보 암호화
5. 무단 요청에 대한 방어를 검증하는 보안 테스트 수행

### 요구사항
- 공개·보호된 엔드포인트를 갖춘 작동하는 샘플 API(FastAPI, Express 등)
- 파트너 접근을 위한 OAuth 2.0 + JWT 플로우 구현
- 최소 두 개 역할(예: Doctor, Admin)을 갖춘 RBAC
- TLS 인증서를 사용해 구성된 HTTPS
- API 보안 테스트 시연(Postman, curl, 또는 자동화된 스캔)

### 기대 결과
- 인증·인가·암호화·위협 방지 조치를 강제하는 안전하고 규정을 준수하는 API — 무단 요청이 어떻게 차단되고, 민감 데이터가 어떻게 보호되며, 컴플라이언스 표준이 어떻게 충족되는지를 명확히 보여줘 헬스케어 파트너 통합을 위한 신뢰할 수 있는 기반을 구축함
