# Demonstration: Implementing HTTPS for an API (API에 HTTPS 구현하기 실습 데모)

## 개요
- 자체 서명 인증서(self-signed certificate)를 사용해 FastAPI를 HTTPS로 보호하는 3분 49초 분량 실습 데모 영상 — Module 1 "Lesson 4: Encryption and Compliance"의 세 번째 영상
- 전송 중 데이터를 보호하고 API가 안전하게 접근될 수 있도록 보장하는 중요한 단계를 다룸

## 내용

### 시작 상태
- 항목을 나열·조회·생성할 수 있는 완전히 작동하는 FastAPI가 이미 HTTP로 존재함 — 이제 SSL을 추가해 안전하게 실행되도록 함

### Step 1 — 자체 서명 SSL 인증서 생성

```bash
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365
```
- 이 명령은 두 개의 파일을 생성함: 개인 키 파일 `key.pem`과 공개 인증서 파일 `cert.pem`
- 인증서는 365일간 유효하도록 설정됨
- 명령은 국가·주(state)·도시·조직·조직 단위·공통 이름(common name)·이메일 같은 인증서 세부 정보를 입력하라는 프롬프트를 표시함 — 이를 채우면 진행 표시줄이 나타나고 최종적으로 SSL에 필요한 두 파일이 생성됨

### Step 2 — HTTPS로 FastAPI 서버 시작

```bash
uvicorn app:app --host 0.0.0.0 --port 8000 --ssl-keyfile key.pem --ssl-certfile cert.pem
```
- 앱 모듈, 호스트, 포트(8000)를 지정하고 SSL 키·인증서 파일 경로를 제공함
- 실행하면 uvicorn이 서버를 초기화하고 시작 메시지를 표시하며 서버가 `https://localhost:8000`에서 실행 중임을 확인함 — 이제 API가 HTTPS로 안전하게 요청을 처리함

### Step 3 — cURL로 HTTPS 엔드포인트 테스트

```bash
# 자체 서명 인증서이므로 -k로 인증서 검증을 건너뜀(테스트 목적)
curl -k https://localhost:8000/items
```
- JSON 응답으로 항목 목록이 반환되어 API가 HTTPS로 안전하게 실행되고 있음을 확인함

### Step 4 — 브라우저에서 대화형 문서로 확인
- FastAPI는 두 가지 UI를 제공함: Swagger UI(`https://localhost:8000/docs`)와 ReDoc(`https://localhost:8000/redoc`)
- 자체 서명 인증서이므로 브라우저가 보안 경고를 표시함 — "고급 설정"을 클릭하고 "계속 진행"을 선택하면 됨
- API 엔드포인트가 HTTPS를 통해 완전히 접근 가능하고 문서화된 것을 확인할 수 있음
- 같은 엔드포인트를 일반 HTTP로 접근해보면 예상대로 요청이 실패하고 브라우저가 "사이트에 연결할 수 없음"을 표시함 — 이는 API 트래픽을 보호하는 데 HTTPS가 왜 중요한지를 보여줌

## 요약
- OpenSSL로 자체 서명 인증서(`key.pem`, `cert.pem`)를 생성하고, uvicorn 실행 시 `--ssl-keyfile`/`--ssl-certfile` 옵션으로 FastAPI를 HTTPS로 구동하는 전체 과정을 실습함
- cURL(`-k` 플래그)과 브라우저의 Swagger UI/ReDoc으로 HTTPS 접근을 검증하고, 동일 엔드포인트에 대한 일반 HTTP 접근이 실패하는 것을 대조해 HTTPS의 필요성을 명확히 보여줌
