# Encrypting Sensitive Data & Compliance Standards (민감 데이터 암호화와 컴플라이언스 표준)

## 개요
- 민감한 정보가 왜 고가치 표적이 되는지, 암호화가 어떻게 이를 안전하게 지키는지, 전 세계 조직을 이끄는 컴플라이언스 프레임워크에는 무엇이 있는지 다루는 3분 7초 분량 영상 — Module 1 "Lesson 4: Encryption and Compliance"의 두 번째 영상

## 내용

### 왜 암호화와 컴플라이언스가 필요한가
- 민감 데이터는 디지털 세계의 금과 같아서 항상 공격 대상이 됨 — 암호화는 금고처럼 작동해 데이터가 도난당하더라도 읽을 수 없게 만듦
- GDPR·HIPAA 같은 규제는 개인·금융 데이터에 강력한 보호 장치를 요구함 — 이것이 없으면 기업은 벌금·소송·평판 손실 위험에 처함
- 더 중요하게는, 암호화가 고객과 파트너에게 그들의 신뢰가 제대로 놓여 있음을 보여주며 신뢰를 구축함

### 데이터 암호화가 필요한 시점
- **저장 데이터(Data at rest)**: 파일·데이터베이스 같은 경우 무단 접근을 막기 위해 암호화가 필요함
- **전송 중 데이터(Data in transit)**: 이메일·API 호출 같은 경우 가로채기로부터 보호되어야 함
- 원격 근무는 공용 Wi-Fi를 위험하게 만들므로 암호화가 안전한 연결을 보장함
- 서드파티와 데이터를 공유하거나 모바일 기기에 저장하는 것도 암호화를 요구함
- 간단히 말해 데이터가 이동하거나 머무는 모든 곳에 암호화가 따라야 함

### 거버넌스 프레임워크
- **GDPR**: EU 시민의 데이터를 보호함
- **HIPAA**: 헬스케어 기록을 보호함
- **PCI-DSS**: 결제 카드 정보가 암호화되도록 보장함
- **ISO 27001**: 정보 보안에 대한 글로벌 벤치마크를 설정함
- 이런 표준들은 단순한 규칙이 아니라, 조직이 민감 데이터를 일관되게 보호하고, 처벌을 피하며, 규제가 엄격한 산업에서 신뢰성을 구축하도록 보장하는 로드맵임

### 실무 적용 사례
- **헬스케어**: 환자 기록을 보호함
- **정부**: 시민 데이터를 보호함
- **금융**: 은행 정보를 보호하고 컴플라이언스를 가능하게 함
- **전자상거래**: 고객 결제 정보를 안전하게 유지함
- 이런 실제 적용 사례들은 암호화가 단순한 기술적 안전장치가 아니라 조직을 보호하면서 매끄럽고 신뢰할 수 있는 디지털 상호작용을 보장하는 비즈니스 인에이블러임을 보여줌

## 요약
- 민감 데이터는 항상 공격 표적이 되며, 암호화는 저장 데이터와 전송 중 데이터 모두를 보호하는 금고 역할을 함 — GDPR·HIPAA·PCI-DSS·ISO 27001 같은 컴플라이언스 프레임워크가 이를 일관되게 실천하도록 안내함
- 헬스케어·정부·금융·전자상거래 전반에서 암호화는 단순한 기술적 보호를 넘어 신뢰와 비즈니스를 가능하게 하는 요소임
