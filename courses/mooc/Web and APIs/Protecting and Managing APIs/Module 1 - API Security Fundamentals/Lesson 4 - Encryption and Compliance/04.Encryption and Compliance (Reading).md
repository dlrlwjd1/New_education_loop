# Reading: Encryption and Compliance (암호화와 컴플라이언스)

## 개요
- 암호화 유형, API에서 암호화가 적용되는 위치, HTTPS의 역할, 주요 컴플라이언스 표준을 다루는 10분 분량 읽기자료 — Module 1 "Lesson 4: Encryption and Compliance"의 네 번째이자 마지막 항목
- API는 개인정보·금융 세부사항·기밀 비즈니스 데이터 같은 민감한 데이터를 흔히 다루므로, 이를 보호하는 것은 보안뿐 아니라 사용자 신뢰 유지와 법적 규제 준수에도 필수적임

## 내용

### 데이터 암호화 — 정보를 기밀로 유지하기
- 암호화는 알고리즘과 키를 사용해 읽을 수 있는 데이터(평문, plaintext)를 읽을 수 없는 형식(암호문, ciphertext)으로 변환함 — 올바른 키를 가진 승인된 당사자만 데이터를 다시 읽을 수 있는 형태로 복호화할 수 있음
- **암호화 유형**:
  - **대칭 암호화(Symmetric Encryption)**: 암호화와 복호화 모두에 단일 키를 사용함 — 빠르고 대용량 데이터셋에 적합하지만 안전한 키 공유가 필요함
  - **비대칭 암호화(Asymmetric Encryption)**: 공개키·개인키 한 쌍을 사용함 — 공개키로 암호화된 데이터는 개인키로만 복호화할 수 있음, 인터넷을 통한 안전한 통신에 이상적
- **API에서 암호화가 적용되는 위치**:
  - **전송 중 데이터(Data in Transit)**: HTTPS를 사용해 클라이언트와 서버 사이에 전송되는 데이터를 암호화함
  - **저장 데이터(Data at Rest)**: 저장소가 침해되더라도 무단 접근을 막기 위해 데이터베이스나 클라우드 스토리지에 저장된 데이터를 암호화함

### HTTPS — 전송 중 데이터 보호하기
- HTTPS(Hypertext Transfer Protocol Secure)는 클라이언트와 API 사이를 이동하는 데이터를 보호하는 표준 프로토콜로, 다음을 보장함:
  - **기밀성(Confidentiality)**: 도청을 방지함
  - **무결성(Integrity)**: 데이터가 변조되었는지 탐지함
  - **인증(Authentication)**: 디지털 인증서를 통해 서버의 신원을 확인함
- **API에 HTTPS 구현하기**:
  1. 신뢰할 수 있는 기관으로부터 SSL/TLS 인증서를 발급받음
  2. API 서버가 HTTPS 엔드포인트를 사용하도록 구성함
  3. 모든 엔드포인트에 HTTPS를 강제하고 모든 HTTP 요청을 HTTPS로 리다이렉트함

### 컴플라이언스 표준
- 민감한 데이터를 다루는 API는 처벌을 피하고 사용자를 보호하기 위해 법적·업계별 컴플라이언스 규제를 준수해야 함:
  - **GDPR(General Data Protection Regulation)**: EU 시민의 개인 데이터를 보호함 — 암호화, 동의 관리, 데이터 접근 통제를 요구함
  - **HIPAA(Health Insurance Portability and Accountability Act)**: 미국의 헬스케어 관련 데이터를 보호함 — 암호화와 감사 추적을 의무화함
  - **PCI DSS(Payment Card Industry Data Security Standard)**: 신용카드 정보의 안전한 취급을 보장함
- **컴플라이언스를 위한 모범 사례**:
  - 전송 중과 저장 모두에서 모든 민감 데이터를 암호화함
  - 데이터 접근을 추적하기 위한 상세한 감사 로그를 유지함
  - 현재 보안 표준에 맞춰 암호화 프로토콜을 정기적으로 업데이트함
  - 정기적인 컴플라이언스 감사와 취약점 평가를 수행함

## 요약
- 암호화는 기밀성과 무결성을 보장하고, 컴플라이언스 표준은 데이터 취급을 위한 법적·윤리적 프레임워크를 제공함 — HTTPS를 구현하고 규제 가이드라인을 따름으로써 개발자는 안전하고 신뢰할 수 있으며 규정을 준수하는 API를 만들 수 있음
