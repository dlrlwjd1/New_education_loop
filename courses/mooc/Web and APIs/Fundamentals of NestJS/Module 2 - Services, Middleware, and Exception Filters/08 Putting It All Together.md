# Putting it all Together

## 개요
- 이 코스 전체에서 다룬 내용(NestJS 개요, 모듈·컨트롤러·서비스, 미들웨어, 예외 필터)을 코드를 다시 살펴보며 총정리하는 마지막 강의.

## 내용
### NestJS 전반 복습
- NestJS가 Node와 Express에 아키텍처(architecture)를 제공하며, Node와 Express에 있는 모든 기능을 NestJS 안에서도 사용할 수 있게 해준다는 점, 그리고 여기에 추가 기능과 더 높은 수준의 모듈성(modularity)과 아키텍처를 더해준다는 점을 다시 짚는다.

### 모듈·컨트롤러·서비스·프로바이더 복습
- 모듈(modules)이 무엇인지, 컨트롤러와 서비스가 모듈에 어떻게 연결되는지, 그리고 다양한 프로바이더(providers)를 통해 의존성 주입(dependency injection)이 어떻게 이루어지는지를 배웠다.
- 모듈의 스코프(scope)에 대해서도 배웠다 — 각 모듈은 자신에게 연결된 컨트롤러와 서비스를 가지며, 서로 다른 모듈들이 필요할 때 다른 모듈들을 사용할 수 있다는 것.
- 이는 모듈, 컨트롤러, 서비스 간의 **상호운용성(interoperability)**을 보여주며, 이것이 서로 다른 서비스를 유연하게 사용하고 애플리케이션을 더 확장 가능(scalable)하게 만들어준다.

### 미들웨어 복습
- NestJS에서 미들웨어(middleware)를 어떻게 만드는지, 그리고 이 미들웨어가 여러 작업을 수행해 개발을 더 쉽게 만들어준다는 것을 배웠다.
- 실제로 `authorization` 헤더를 확인하는 미들웨어를 만들어, 헤더가 없으면 에러를 보내도록 구현했다.

### 예외 필터 복습
- 예외 필터(exception filters)가 무엇이고 어떻게 동작하는지 배웠고, 프로젝트에서 실제로 몇 가지를 사용해보았다.

### 코드 전체 다시 훑어보기
- `app.module` — `SumService`가 프로바이더로 등록되어 있고, 새로 만든 `Sayname` 모듈이 `app.module`에 import되어 메인 모듈과 연결되어 있다. 또한 애플리케이션의 모든 라우트에 대해 미들웨어가 연결되어 있다.
- DTO — `AnswerDto`와 `SaynameDto` 두 개의 DTO를 만들었고, 각각 POST 요청에서 사용했다.
- 미들웨어 — `AuthcheckMiddleware`를 만들어 헤더에 authorization이 있는지 확인하고, 없으면 예외 필터를 사용해 예외를 처리했다.
- `Sayname` 모듈 — Nest 명령어들을 사용해 모듈, 컨트롤러, (컨트롤러와 모듈에 대한) 테스트 파일, 그리고 서비스 파일을 생성했다.
- `sum-service` — 두 숫자를 받아 그 합을 반환하는 서비스도 만들었다.
- 컨트롤러에는 POST, GET을 비롯한 여러 요청(routes)을 추가했다.

## 요약
- NestJS는 Node·Express 위에 아키텍처와 모듈성을 더한 프레임워크이며, 모듈·컨트롤러·서비스·프로바이더로 애플리케이션을 구성한다.
- 미들웨어로 요청을 가로채 인증 등을 처리하고, 예외 필터로 에러 응답을 일관되게 관리할 수 있다.
- 코스 전반에 걸쳐 `AppModule`, `SayName` 모듈, `sum-service`, `AnswerDto`/`SaynameDto`, `AuthcheckMiddleware` 등을 직접 만들며 이 개념들을 실습했다.
- 이것으로 "Fundamentals of NestJS" 코스의 모든 내용을 마무리한다.
