# Route Parameters and Query Strings

## 개요
- URL에서 값을 추출하는 **라우트 파라미터(route parameters)**와 **쿼리 스트링(query strings)**의 개념을 설명하고, NestJS 컨트롤러에서 `@Param()`과 `@Query()` 데코레이터로 이를 실제로 사용해보는 강의.

## 내용
### 라우트 파라미터(route parameters)란
- 라우트 파라미터는 웹 요청의 URL로부터 값을 추출하는 방법이다.
- 예를 들어 `users/userId`에서 `userId` 부분이 라우트 파라미터이며, 코드에서 이를 추출해 원하는 곳에 사용할 수 있다.
- 특정 파라미터를 기준으로 데이터를 보여주는 동적인 페이지들을 본 적이 있을 텐데, 라우트 파라미터는 이러한 동적이고(dynamic) 파라미터화된(parameterized) URL을 웹 애플리케이션에서 가능하게 해준다.

### 쿼리 스트링(query strings)이란
- 쿼리 스트링은 웹 서버에 데이터나 파라미터를 전달하는 데 사용되는 URL의 일부다.
- 물음표(`?`)로 쿼리 스트링의 시작을 알리고, 앰퍼샌드(`&`)로 여러 값을 구분한다. 예: `?name=John&age=30`에서 `name`은 John, `age`는 30이라는 값을 전달한다.
- 주로 GET 요청을 보낼 때 서버로 데이터를 보내는 용도로 웹 애플리케이션에서 사용된다.

### 코드에서 라우트 파라미터 사용하기
- 기존에 만들어둔 루트(root) 라우트에 라우트 파라미터를 추가하려면, 콜론(`:`)과 함께 파라미터 이름을 붙인다(예: `:id`).
- 새 메서드 `getRouteParam`을 만들고 우선 빈 문자열을 반환하도록 작성한다.
- 이 파라미터 값을 가져오려면 메서드 인자에 `@Param()` 데코레이터를 사용한다. `Param`은 NestJS(`@nestjs/common`)에서 가져온다(import).
- `@Param()` 안에 라우트 파라미터의 이름(`'id'`)을 넣고, 이를 받을 변수 이름(예: `userId`)을 정의한 뒤 이 값을 반환하도록 한다.
- Postman에서 어떤 id 값을 넣고 요청을 보내면 그 id 값이 그대로 반환되는 것을 확인한다.

### 라우트 순서(route order)의 중요성
- `askquestion` 같은 리터럴 라우트를 호출했는데 라우트 파라미터를 받는 핸들러가 이를 가로채는 문제가 발생했다. 그 이유는 NestJS가 라우트를 **위에서 아래로(top to bottom)** 순서대로 평가하기 때문이다. 라우트 파라미터 라우트(`:id`)가 `askquestion` 라우트보다 먼저 선언되어 있어서, `askquestion`이라는 값 자체를 id로 취급해버린 것이다.
- 이를 해결하려면 라우트 파라미터를 받는 라우트를 **가장 마지막(last)**에 배치해야 한다. 그래야 다른 구체적인 라우트들과 매칭되지 않는 경우에만 이 라우트가 값을 받게 된다.
- 순서를 바꾼 뒤에는 `askquestion`을 호출하면 정상적으로 질문이 반환되고, 임의의 숫자를 id로 넣으면 그 값이 정상적으로 반환된다.

### 코드에서 쿼리 스트링 사용하기
- 같은 루트 라우트를 사용하되(라우트 자체는 변경하지 않음), 이번에는 `getQueryStrings`라는 GET 메서드를 만들고 역시 처음에는 빈 문자열을 반환한다.
- URL에서 쿼리 스트링을 가져오려면 `@Query()` 데코레이터를 사용한다. 라우트 파라미터와 마찬가지로 안에 이름을 넣는다. 예를 들어 `name`이라는 쿼리 값을 받고 싶다면 `@Query('name')`으로 지정하고, 이를 받을 변수 이름은 자유롭게 지정할 수 있다(예: `username`).
- 동일한 라우트가 두 개 존재하면 충돌하므로, 하나를 주석 처리(comment)한 뒤 진행한다.
- Postman에서 쿼리 값으로 `name=John`을 전달하면 `John`이 반환된다. 하지만 `age=30`을 추가로 전달해도 처음에는 `John`만 보인다.
- 두 번째 쿼리 파라미터도 받으려면, 메서드 인자에 콤마(`,`)로 구분해 `@Query('age')` 데코레이터를 하나 더 추가하면 된다. 이렇게 하면 `age` 값도 함께 접근할 수 있다.

## 예시
```typescript
// 라우트 파라미터 예시 — 반드시 다른 구체적인 라우트들 뒤에 위치시켜야 함
@Get(':id')
getRouteParam(@Param('id') userId: string): string {
  return userId;
}
```

```typescript
// 쿼리 스트링 예시 — 여러 개의 @Query()를 콤마로 구분해 함께 사용 가능
@Get()
getQueryStrings(
  @Query('name') username: string,
  @Query('age') age: string,
): string {
  return username;
}
```

```
GET /123           → "123" (라우트 파라미터 id로 인식)
GET /askquestion    → "How are you?" (구체적인 라우트가 먼저 매칭됨)
GET /?name=John&age=30 → "John" (쿼리 스트링에서 name 값 추출)
```

## 요약
- 라우트 파라미터(`:id` 형태)는 URL 경로 자체에서 값을 추출하며, `@Param()` 데코레이터로 받는다.
- 쿼리 스트링(`?key=value&key2=value2` 형태)은 `@Query()` 데코레이터로 받으며, 여러 값을 각각 별도의 `@Query()` 인자로 받을 수 있다.
- NestJS는 라우트를 위에서 아래로 순서대로 매칭하므로, 라우트 파라미터를 받는 라우트는 다른 구체적인 라우트들보다 뒤에 두어야 라우트 충돌을 피할 수 있다.
- 다음 영상에서는 NestJS에서 요청(request)과 응답(response)을 처리하는 방법을 다룬다.
