# Introduction to Interceptors

## 개요
- NestJS의 **인터셉터(interceptor)**가 무엇인지, 미들웨어(middleware)·가드(guard)와 어떻게 다르고 어떤 순서로 실행되는지를 개념적으로 소개하는 강의.

## 내용
### 인터셉터란 무엇인가
- **인터셉터(interceptor)**는 미들웨어(middleware)와 마찬가지로 요청(request)이 라우트 핸들러(route handler)에 도달하기 전에 이를 가로챈다(intercept).
- 또한 응답(response)도 가로챌 수 있어, 요청과 응답 양쪽에 모두 직접 접근(access)할 수 있다.
- 미들웨어와 비슷하지만 더 강력한 기능(more powerful capabilities)을 가지고 있다고 설명한다.
- 인터셉터를 이용하면 요청에 특정 데이터를 추가해 수정하거나, 요청이 특정 기준(criteria)을 충족하는지 검증(validate)하는 등의 작업을 라우트 핸들러에 도달하기 전에 수행할 수 있다.
- 응답에 대해서도 캐싱(caching), 에러 처리(error handling), 변환(transformation) 등의 작업을 수행할 수 있다.
- 결국 인터셉터는 클라이언트(client)와 Nest API 엔드포인트(endpoint) 사이에 위치하며, 목적지에 도달하기 전에 요청이나 응답에 원하는 처리를 할 수 있는 지점이다.

### 요청-응답 생명주기(life cycle)에서의 실행 순서
- 인터셉터는 미들웨어(middleware)와 가드(guard) **다음에** 실행된다.
- 먼저 미들웨어가 실행되어 데이터 파싱(parsing)이나 인증(authentication) 체크 같은 요청 처리를 수행한다.
- 그다음 가드가 실행되어 요청이 인가(authorized)되었는지 확인한다. 가드는 어떤 라우트 핸들러나 인터셉터보다도 먼저 실행된다.
- 그 다음에 인터셉터가 실행되어 라우트 핸들러에 도달하기 전에 요청을 가로챈다. 이 시점에서 인터셉터는 요청을 수정하거나 추가 로직(additional logic)을 넣거나 변환(transformation)을 처리한다.
- 라우트 핸들러가 요청을 처리하고 응답을 보내면, 인터셉터는 다시 한번 응답을 가로채서 수정 로직이나 에러 체크, 기타 추가 처리를 수행한다.
- 즉 인터셉터는 요청이 들어올 때와 응답이 나갈 때, 양방향으로 개입한다.

### 인터셉터의 적용 범위(level)
- 인터셉터는 미들웨어, 가드와 마찬가지로 세 가지 레벨(level)에 적용할 수 있다.
  - **메서드 레벨(method level)**: 개별 라우트 핸들러에 적용
  - **컨트롤러 레벨(controller level)**: 해당 컨트롤러의 모든 라우트 핸들러에 적용
  - **전역 레벨(global level)**: 애플리케이션 전체의 모든 라우트 핸들러에 적용

## 요약
- 인터셉터는 미들웨어처럼 요청과 응답을 가로챌 수 있지만 더 강력한 기능을 제공한다.
- 실행 순서는 미들웨어 → 가드 → 인터셉터(요청 처리) → 라우트 핸들러 → 인터셉터(응답 처리) 순이다.
- 인터셉터는 메서드, 컨트롤러, 전역 세 가지 레벨에 적용할 수 있다.
- 다음 강의부터 인터셉터를 더 구체적으로 다룬다.
