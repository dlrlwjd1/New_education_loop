# Introduction to Nest Middlewares

## 개요
- 백엔드 애플리케이션에서 **미들웨어(middleware)**가 왜 필요한지, 그리고 클라이언트-서버 요청/응답 흐름에서 미들웨어가 어떤 역할을 하는지 개념적으로 설명하는 강의.

## 내용
### 미들웨어란 무엇인가
- 미들웨어는 NestJS만의 고유한 개념이 아니라, 언어나 프레임워크와 상관없이 거의 모든 백엔드 애플리케이션에서 공통적으로 사용되는 개념이다.
- 미들웨어는 들어오는 HTTP 요청(request)을 가로채서(intercept) 어떤 로직을 실행한 뒤, 요청을 다음 미들웨어로 넘기거나(pass) 직접 응답(response)을 반환하는 역할을 한다.

### 요청-응답 흐름에서의 미들웨어 위치
- 기본적으로 클라이언트(client)가 요청을 보내면, 서버 쪽의 컨트롤러(controller)가 이를 처리하고 응답을 클라이언트에 돌려주는 것이 일반적인 요청-응답 패턴이다.
- 여기에 미들웨어를 추가하면, 클라이언트의 요청은 컨트롤러로 바로 가지 않고 먼저 미들웨어를 거친다.
- 미들웨어는 일종의 중간자(middleman) 역할을 하며, 클라이언트 요청에 대해 특정 정보를 확인하거나 처리 과정을 수행한다.
- 미들웨어가 수행하는 처리와 요구되는 조건(criteria)이 충족되면, 그때 비로소 요청이 컨트롤러로 전달되고 컨트롤러가 후속 처리를 한 뒤 응답을 클라이언트에게 돌려준다.

### 미들웨어가 필요한 이유
- 애플리케이션의 여러 라우트(route)나 여러 레벨에서 반복적으로 사용되는 코드가 있을 때 유용하다. 예를 들어 특정 사용자의 id나 uuid를 검증(validate)하는 코드가 있다고 하면, 이를 각 라우트마다 똑같이 반복해서 작성하는 대신 미들웨어로 한 번 정의해두고 필요한 곳에 적용(apply)할 수 있다.
- 이 경우 미들웨어가 사용자 검증(user validation)을 수행하고, 검증에 실패하면 요청 자체가 컨트롤러로 전달되지 않는다.
- 미들웨어는 로깅(logging), 사용자나 관리자(admin)의 로그인 여부 확인, 그에 따른 기능 접근 권한 제어, 에러 처리(error handling), 요청 검증(request validation) 등에도 사용될 수 있다.
- 이런 처리들을 애플리케이션의 핵심 로직(core logic)을 직접 수정하지 않고도 미들웨어를 통해 손쉽게 구현할 수 있다.

### NestJS 미들웨어와 Express 미들웨어의 관계
- NestJS의 미들웨어는 기본적으로 Express의 미들웨어와 동등(equivalent)하다.
- 따라서 Express에서 미들웨어를 다뤄본 경험이 있다면, NestJS 미들웨어를 구현하는 것도 쉽게 익힐 수 있다.

## 요약
- 미들웨어는 클라이언트 요청과 컨트롤러 사이에 위치하여 요청을 가로채고, 특정 로직을 실행한 뒤 다음 단계로 전달하거나 직접 응답하는 역할을 한다.
- 반복되는 검증 로직, 로깅, 로그인 여부 확인, 에러 처리, 요청 검증 등을 core logic 수정 없이 처리할 수 있어 유용하다.
- NestJS 미들웨어는 기본적으로 Express 미들웨어와 동일한 방식으로 동작한다.
