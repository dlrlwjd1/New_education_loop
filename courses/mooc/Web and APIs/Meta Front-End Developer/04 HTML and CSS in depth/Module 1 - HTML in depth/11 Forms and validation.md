# Forms and validation

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/html-and-css-in-depth/lecture/EqLq5/forms-and-validation)

## 개요
- 양식 유효성 검사에는 클라이언트 측 유효성 검사와 서버 측 유효성 검사의 두 가지 방법이 있습니다.

## 내용
- 양식 유효성 검사에는 클라이언트 측 유효성 검사와 서버 측 유효성 검사의 두 가지 방법이 있습니다.
- 그러나 오류가 있는 경우 사용자에게 잘못된 데이터와 성공적인 제출을 위해 데이터를 변경하는 방법을 알리는 오류 메시지가 표시됩니다.
- 사용자가 유효한 이메일 주소를 입력하지 않으면 입력한 데이터가 유효한 이메일 주소가 아님을 알리는 오류 메시지가 웹 브라우저에 표시됩니다.
- 이 검증은 데이터베이스를 기준으로 데이터를 검사하거나 비즈니스 요구 사항에 맞게 데이터를 검증하는 것과 같은 보다 복잡한 검사를 실행할 수 있습니다.
- 대부분의 웹사이트는 사용자에게 즉각적인 피드백을 제공할 뿐만 아니라 악의적인 데이터 전송을 방지하고 데이터 무결성을 보장하기 위해 클라이언트측 검사와 서버측 유효성 검사를 모두 사용합니다.
- 다른 것으로는 전화번호의 경우 “tel”, www.data.com과 같은 URL의 경우 “url”, 날짜 값의 “날짜”, 시간 값의 “시간”, 숫자 값의 “숫자”, 최소값과 최대값이 있는 숫자 값의 “범위”, 색상 선택을 위한 “색상”이 있습니다.
- 예를 들어 사용자가 전화번호와 URL을 입력할 때 사용자 계정 양식에 실수를 하면 브라우저는 입력된 데이터를 입력 유형의 요구 사항과 비교하여 검증하고 사용자 피드백을 제공합니다.

## 예시
- 예를 들어 온라인 음식 배달 웹사이트를 구축한다고 가정해 보겠습니다.

## 요약
- 다른 것으로는 전화번호의 경우 “tel”, www.data.com과 같은 URL의 경우 “url”, 날짜 값의 “날짜”, 시간 값의 “시간”, 숫자 값의 “숫자”, 최소값과 최대값이 있는 숫자 값의 “범위”, 색상 선택을 위한 “색상”이 있습니다. 예를 들어 사용자가 전화번호와 URL을 입력할 때 사용자 계정 양식에 실수를 하면 브라우저는 입력된 데이터를 입력 유형의 요구 사항과 비교하여 검증하고 사용자 피드백을 제공합니다.
