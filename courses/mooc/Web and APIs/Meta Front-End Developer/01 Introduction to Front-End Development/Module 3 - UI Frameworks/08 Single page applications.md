# Single page applications

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-front-end-development/lecture/FLW1z/single-page-applications)

## 개요
- 그런 다음 단일 페이지 애플리케이션 또는 SPA를 사용하여 사용자에게 독특하고 빠르며 매력적인 경험을 구축하는 것을 고려해야 합니다.

## 내용
- 그런 다음 단일 페이지 애플리케이션 또는 SPA를 사용하여 사용자에게 독특하고 빠르며 매력적인 경험을 구축하는 것을 고려해야 합니다.
- 하지만 모든 요청에 대해 전체 웹 페이지를 보내는 것은 과도한 대역폭을 소비하고 동적 페이지를 생성하는 데 CPU 시간을 소비하기 때문에 기존 애플리케이션은 웹 서버 리소스를 많이 사용하게 됩니다.
- 지연 로딩의 경우 브라우저가 응용 프로그램을 요청하고 서버는 응용 프로그램을 로드하는 데 필요한 최소 HTML, CSS 및 JavaScript만 반환합니다.
- 예를 들어 번들링 접근 방식을 사용하면 애플리케이션이 복잡하고 리소스가 많은 경우 번들 크기가 상당히 커져 다운로드하는 데 시간이 오래 걸립니다.
- 예를 들어 살펴보겠습니다.영화 리뷰 전용 사이트가 있는데 사람들이 다음에 무엇을 볼지 모르기 때문에 사용자에게 영화를 무작위로 추천하는 기능을 설치하기로 결정했다고 가정해 보겠습니다.
- 응용 프로그램이 로드될 때 모든 리소스가 제공되는 경우 단일 페이지 응용 프로그램은 초기 로드 시 모든 페이지에 대한 보기를 포함해야 합니다.
- 리소스가 동적으로 로드되는 경우 단일 페이지 애플리케이션은 필요에 따라 뷰를 요청하고 후속 요청을 위해 브라우저에 뷰를 저장합니다.

## 예시
- 예를 들어, 사용자가 애플리케이션의 특정 섹션을 탐색하는 경우 두 가지 접근 방식 모두 유효합니다.

## 요약
- 응용 프로그램이 로드될 때 모든 리소스가 제공되는 경우 단일 페이지 응용 프로그램은 초기 로드 시 모든 페이지에 대한 보기를 포함해야 합니다. 리소스가 동적으로 로드되는 경우 단일 페이지 애플리케이션은 필요에 따라 뷰를 요청하고 후속 요청을 위해 브라우저에 뷰를 저장합니다.
