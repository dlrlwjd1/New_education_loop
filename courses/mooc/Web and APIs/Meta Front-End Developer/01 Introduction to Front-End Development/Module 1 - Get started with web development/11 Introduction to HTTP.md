# Introduction to HTTP

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-front-end-development/lecture/mvVXy/introduction-to-http)

## 개요
- 웹 브라우저 또는 클라이언트가 서버에 HTTP 요청을 보내고 웹 서버는 HTTP 응답을 브라우저로 다시 보냅니다.

## 내용
- 웹 브라우저 또는 클라이언트가 서버에 HTTP 요청을 보내고 웹 서버는 HTTP 응답을 브라우저로 다시 보냅니다.
- 예를 들어 웹 사이트의 페이지에서 이미지를 요청하려는 경우 주소 표시줄의 URL에 웹 서버의 특정 파일에 대한 전체 경로 ( 예: 닷컴, 정방향 슬래시 이미지, 정방향 슬래시 이미지, 도트 jpg) 가 포함되어야 합니다.
- 가장 일반적인 정보 응답은 100 Continue이며, 이는 웹 클라이언트가 응답을 계속 요청하거나 요청이 이미 완료된 경우 응답을 무시해야 함을 나타냅니다.
- POST인 경우 리소스가 웹 서버로 성공적으로 전송되었음을 의미하고, PUT인 경우 리소스가 웹 서버로 성공적으로 전송되었음을 의미합니다.
- 가장 일반적으로 사용되는 코드는 웹 브라우저 또는 클라이언트가 잘못된 데이터를 웹 서버에 제출한 경우 400이고, 401은 사용자가 계정에 로그인해야 요청을 처리할 수 있음을 나타내는 데 사용되고, 403은 요청이 유효하지만 웹 서버가 처리를 거부하고 있음을 나타내는 데 사용됩니다.
- 이는 종종 사용자에게 웹 애플리케이션에서 작업을 실행할 수 있는 충분한 권한이 없음을 나타내는 데 사용되며, 404는 요청 리소스가 웹 서버에서 발견되지 않았음을 나타내는 데 사용됩니다.
- 가장 일반적으로 사용되는 코드는 500 내부 서버 오류이며, 이는 서버가 요청을 처리하지 못했음을 나타내는 일반적인 오류 상태입니다.

## 예시
- 예를 들어 웹 사이트의 페이지에서 이미지를 요청하려는 경우 주소 표시줄의 URL에 웹 서버의 특정 파일에 대한 전체 경로 ( 예: 닷컴, 정방향 슬래시 이미지, 정방향 슬래시 이미지, 도트 jpg) 가 포함되어야 합니다.
