# What are controlled components? — 대화정리

> 원본 강의: [09 What are controlled components.md](09%20What%20are%20controlled%20components.md)

## 개요
- 폼 요소(입력창 등)의 표시 값을 React state가 단일 정보 소스(single source of truth)로 완전히 통제하는 **제어 컴포넌트(controlled component)** 개념을 다룬다. 08번에서 본 "입력값이 엉뚱한 항목에 남는" 버그와 직접 연결된다.

## 내용

### 제어 컴포넌트란
- DOM 요소 자신의 내부 상태(기본 상태, `defaultValue` 등)에 의존하는 대신, **React state를 값의 원천으로 삼아** 폼 요소의 표시 값을 항상 통제하는 방식이다.
- `value` prop으로 값을 넣고, `onChange`로 변경을 잡아 state를 갱신하고, 그 state가 다시 `value`로 내려가는 순환 구조를 이룬다.
- 폼 제출은 `onSubmit`으로 처리한다.
- React는 대부분의 입력 타입에 대해 제어된 버전을 지원하며, 폼 구현에는 이 방식을 권장한다.

### 08번의 버그가 왜 제어 컴포넌트로 해결되는가
- 08번(uncontrolled)에서는 사용자가 타이핑한 값이 **DOM 요소 자신의 메모리**(`defaultValue`)에 저장됐다. React가 index-key 때문에 그 DOM 요소를 재사용해도 값을 다시 채워 넣지 않으니, 값이 위치에 눌러붙어 있었다.
- 제어 컴포넌트에서는 `value={todo.text}`처럼 **매 렌더링마다 React가 강제로 값을 밀어넣는다.** DOM 요소가 재사용되든 안 되든 상관없이, 화면에 보이는 값은 항상 지금 이 순간의 데이터(state)를 그대로 반영한다. DOM이 "자기 기억"을 가질 여지 자체가 없어진다.

### 주의: 이건 증상만 고치는 것이다
- "제어 컴포넌트로 만드는 것"은 **입력값이 어긋나 보이는 이 특정 증상**을 고치는 것이지, index를 key로 쓰는 게 여전히 좋은 습관인 것은 아니다.
- index-key 때문에 React가 여전히 엉뚱한 인스턴스를 재사용하는 건 그대로라서:
  - 불필요한 리렌더링(성능 저하)은 여전히 남고,
  - props로 안 내려주고 컴포넌트 내부에서만 관리하는 **다른 상태**(05번 체크박스 예시처럼)는 여전히 잘못된 위치에 눌러붙을 수 있다.
- 즉 "제어 컴포넌트로 만드는 것"과 "제대로 된 key를 쓰는 것"은 서로 다른 문제를 고치는, 둘 다 필요한 습관이다.

## 예시
- 리틀 레몬 레스토랑의 테이블 예약 폼처럼, 사용자가 입력한 값을 React state로 관리하고 제출 시 `onSubmit`으로 처리하는 형태가 제어 컴포넌트의 전형적인 사용 예다.

## 요약
- 제어 컴포넌트는 폼 요소의 값을 DOM이 아니라 React state가 통제하는 방식이며, React가 폼 구현 시 권장하는 방식이다.
- 이 방식은 08번에서 본 "값이 위치에 눌러붙는" 문제를 해결하지만, index-key 자체의 성능·다른 상태 오염 문제까지 없애주는 건 아니다. 두 습관(제어 컴포넌트 + 올바른 key)은 서로 다른 문제를 고치므로 둘 다 필요하다.
