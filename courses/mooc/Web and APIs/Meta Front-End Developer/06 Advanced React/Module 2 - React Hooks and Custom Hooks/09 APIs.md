# APIs

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/advanced-react/lecture/9UsEG/apis)

## 개요
- Meta for API의 디자인 프로세스에는 일반적으로 코드를 작성할 때 동료 및 동료에게 검토를 요청하는 것과 같은 방식으로 여러 번의 반복이 포함됩니다.

## 내용
- Meta for API의 디자인 프로세스에는 일반적으로 코드를 작성할 때 동료 및 동료에게 검토를 요청하는 것과 같은 방식으로 여러 번의 반복이 포함됩니다.
- 보통 누군가 또는 여러 사람이 API의 형태와 구조가 무엇인지, 애플리케이션의 각 부분이 서로 어떤 합의를 맺을 것인지에 대한 제안서인 문서를 작성합니다.
- 전체 스택에서 API가 일관되고 의미가 있는지 확인하기 위해 프런트 엔드 엔지니어, 백엔드 엔지니어 및 중간 계층에서 작업하는 사람들과도 이야기를 나눌 것입니다.
- 무언가를 가져오면 특정 물건에서 기대하는 것이 있고 다른 것을 얻을 수 있습니다.이러한 형식 안전성은 이러한 실수나 문제를 최소화하고 스택 전체에서 일관된 유형 안전성을 유지할 때 애플리케이션의 안정성을 높입니다.
- 우리의 API가 미래와 매우 잘 호환되도록 만들고 싶고 응용 프로그램이 어떻게 발전할지 예측하는 데 집착할 수 있는 목표가 조금 있습니다.
- 마치 인생의 모든 일이 예측하려고 노력하는 것처럼, 또한 지금 눈앞에 있는 문제와 그 문제를 효과적으로 해결할 수 있는 방법에 초점을 맞추려고 노력하는 것과 같습니다.
- 때때로 우리는 지나치게 생각하고 많은 것을 API에 집어넣고 복잡하고 복잡한 디자인 패턴을 사용하여 매우 화려하게 만들려고 하는 경향이 있습니다.

## 예시
- 때때로 우리는 지나치게 생각하고 많은 것을 API에 집어넣고 복잡하고 복잡한 디자인 패턴을 사용하여 매우 화려하게 만들려고 하는 경향이 있습니다.
