# TDD (Test-Driven Development)

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/programming-with-javascript/lecture/8hZR0/tdd-test-driven-development)

## 개요
- 기존 개발 프로세스와 비교하여 주어진 기능을 코딩하여 이 실패한 테스트를 통과하면 해당 TDD 접근 방식이 다소 거꾸로 보일 수 있습니다.

## 내용
- 기존 개발 프로세스와 비교하여 주어진 기능을 코딩하여 이 실패한 테스트를 통과하면 해당 TDD 접근 방식이 다소 거꾸로 보일 수 있습니다.
- 이제 JavaScript 파일에 대한 실패한 테스트를 작성한 다음 TDD가 작동하는 방식을 이해하기 위해 이 테스트를 통과하도록 코드를 작성하여 TDD 접근 방식을 시연할 것입니다.
- 예를 들어, 실제 구현을 작성하기 전에 TDD 방식으로 코딩을 하기 때문에, 예를 들어 키의 상태라는 함수가 존재하는지 테스트한 다음 테스트 프레임워크의 일부 테스트 함수를 사용합니다.
- 따라서 아직 구현을 작성하지 않았기 때문에 다시 실패하는 또 다른 테스트를 작성하고 작성하면 이전에 실패한 테스트가 통과됩니다.
- RE Factor는 구현 세부 사항을 변경하지 않는 코드에 대한 최종 조정을 나타내며, 올바르게 구현될 때 다른 후속 테스트를 실행하여 항상 확인할 수 있습니다.
- 모든 테스트가 통과되었는지 확인하는 것은 현재 요구 사항과 이 앱 조각에 대한 이전 요구 사항이 모두 성공적으로 전달되었으며 아무 것도 깨지지 않는다는 강력한 신호입니다.
- 새 요구 사항을 코딩하여 이전 코드에 도입된 우발적인 버그인 회귀를 최소화하고 있으며 새 구현이 앱의 다른 부분을 손상시키지 않는다는 증거도 있습니다.

## 예시
- 예를 들어, 실제 구현을 작성하기 전에 TDD 방식으로 코딩을 하기 때문에, 예를 들어 키의 상태라는 함수가 존재하는지 테스트한 다음 테스트 프레임워크의 일부 테스트 함수를 사용합니다.

## 요약
- 모든 테스트가 통과되었는지 확인하는 것은 현재 요구 사항과 이 앱 조각에 대한 이전 요구 사항이 모두 성공적으로 전달되었으며 아무 것도 깨지지 않는다는 강력한 신호입니다. 새 요구 사항을 코딩하여 이전 코드에 도입된 우발적인 버그인 회귀를 최소화하고 있으며 새 구현이 앱의 다른 부분을 손상시키지 않는다는 증거도 있습니다.
