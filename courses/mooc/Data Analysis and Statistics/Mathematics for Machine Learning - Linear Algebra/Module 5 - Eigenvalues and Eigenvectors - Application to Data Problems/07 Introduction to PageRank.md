## 내용

### 배경
> **1998년 Google 창업자 Larry Page와 동료들이 발표**하고 그의 이름을 딴 알고리즘. **검색 결과에서 웹사이트를 어떤 순서로 표시할지 결정**하는 데 쓰였다.
>
> ⭐ **핵심 가정: 웹사이트의 중요도는 다른 웹사이트들과 주고받는 링크와 관련된다.**

### 모델 — 미루기 대장 팻(Procrastinating Pat) ⭐
> **A, B, C, D 네 페이지**로 이루어진 모형 미니 인터넷. 화살표는 링크다.
>
> **팻은 일을 피하려고 인터넷에서 무작위로 링크를 클릭하는 가상의 사람**이다. **가능한 모든 링크를 지도로 만들면, 팻이 각 페이지에서 보낼 것으로 기대되는 시간을 추정하는 모델**을 만들 수 있다.

### 링크 벡터 ⭐
페이지 A의 링크를 벡터로 쓰되, **각 행은 해당 페이지로 가는 링크가 있으면 1, 없으면 0**. 그다음 **총 링크 수로 정규화**해 **확률**로 쓴다.
```
A는 B, C, D로 링크하고 자기 자신에게는 링크하지 않는다 → (0, 1, 1, 1)
총 3개 링크이므로 1/3로 정규화

L_A = (0, ⅓, ⅓, ⅓)
```
같은 논리로 D는 B와 C에만 링크하므로(총 2개):
```
L_D = (0, ½, ½, 0)
```

### 링크 행렬 L
> **각 링크 벡터를 열로 써서 정사각 행렬 L**을 만든다.
>
> ⚠️ **자기 참조적(self-referential) 문제**다 — **A에 가는 유일한 방법은 B에 있는 것**인데, **B에 있을 확률은 A나 D에서 왔을 확률에 달려 있다.** 즉 **모든 페이지의 순위가 다른 모든 페이지에 의존한다.**
>
> **열은 나가는 링크로 만들었지만, 행은 출발 페이지 기준으로 정규화된 들어오는 링크를 기술**한다.

### 순위 식 ⭐⭐
벡터 **r** 에 모든 웹페이지의 순위를 담는다. 페이지 A의 순위를 계산하려면 다른 모든 페이지에 대해 **세 가지**를 알아야 한다.

1. **너의 순위는?**
2. **너는 A에 링크하는가?**
3. **너는 총 몇 개의 나가는 링크를 갖는가?**

```
r_A = Σⱼ L_Aⱼ · rⱼ
```
> **A의 순위 = A에 링크하는 모든 페이지의 순위를, 행렬 L에서 가져온 각자의 링크 확률로 가중해 더한 것.**

**모든 페이지에 대해 동시에 쓰면**
```
r = L r
```
> ⭐⭐ **이것은 정확히 [고유 문제의 형태](04%20Calculating%20eigenvectors.md)다** — `A x = λ x` 에서 **λ = 1** 인 경우.

### 반복으로 푼다 ⭐
> **r을 모르는 상태로 시작**하므로 **모든 순위가 같다고 가정하고 웹페이지 수로 정규화**한다.
```
r = (¼, ¼, ¼, ¼)

r_{i+1} = L r_i
```
> **반복해서 적용하면 r의 값이 갱신되다가 결국 변하지 않게 된다.** 그때 진짜로 `r = Lr` 이고, ⭐ **r은 고유값 1을 갖는 행렬 L의 고유벡터**다.

⚠️ **대각화를 쓰면 되지 않나?** → **안 된다.** 대각화하려면 **이미 모든 고유벡터를 알아야 하는데, 그것이 바로 지금 찾으려는 것**이다.

### 결과
> **숫자가 안정되는 데 약 10번의 반복**이 걸리지만 **순서는 첫 반복 만에 이미 정해진다.** (시스템이 아주 작아서 생긴 현상이다.)

| 페이지 | 팻이 보내는 시간 |
|---|---|
| **D** | **약 40%** ← 1위 |
| B | 24% |
| C | 24% |
| **A** | **약 12%** ← 최하위 |

### 거듭제곱 법(power method)이 여전히 효과적인 이유 ⭐
> **무작위 초기 추측 벡터에 행렬을 반복해서 곱하는 것**을 **거듭제곱 법**이라 하며, PageRank 문제에는 **두 가지 이유로 여전히 매우 효과적**이다.

1. **거듭제곱 법은 고유벡터를 하나만 주지만** — n개 페이지면 n개가 있는데 — **링크 행렬을 구성한 방식 때문에 항상 우리가 찾는 그 벡터, 즉 고유값 1인 것을 준다.**
2. ⭐ **실제 인터넷에서는 링크 행렬의 거의 모든 원소가 0이다** — **대부분의 페이지는 대부분의 다른 페이지로 연결되지 않는다.** 이를 **희소 행렬(sparse matrix)** 이라 하며, **곱셈을 매우 효율적으로 수행하는 알고리즘들이 존재한다.**

### 감쇠 인자(damping factor) d ⭐
```
r_{i+1} = d · L r_i + (1 − d)/n
```
> **d는 0과 1 사이의 수**이고, **1 − d는 팻이 현재 페이지의 링크를 클릭하는 대신 갑자기 무작위로 웹 주소를 입력할 확률**로 생각하면 된다.
>
> 실제 계산에서의 효과는 **반복 수렴 과정의 속도와 안정성 사이의 타협을 찾는 것**이다.

### 지금은
> **1998년 PageRank가 처음 발표됐을 때 웹사이트는 수백만 개였지만 오늘날 10억 개가 넘는다.** 검색과 순위 방법은 **효율을 최대화하기 위해 진화해야 했지만, 핵심 개념은 여러 해 동안 변하지 않았다.**

## 요약
- **PageRank의 가정: 웹사이트의 중요도는 링크 관계로 결정된다.**
- **링크 벡터** = 링크 유무를 0/1로 쓰고 **총 링크 수로 정규화**한 확률. 이것들을 열로 모아 **링크 행렬 L**.
- ⭐⭐ **`r = L r`** — 이것은 **고유값 1인 고유벡터 문제**다.
- **균등한 초기값에서 반복 곱셈**으로 수렴시킨다(= **거듭제곱 법**). ⚠️ **대각화는 쓸 수 없다** — 고유벡터를 이미 알아야 하기 때문.
- 예제 결과: **D 40% > B·C 24% > A 12%.**
- 거듭제곱 법이 통하는 이유: **항상 λ=1 고유벡터를 주고**, 실제 인터넷의 링크 행렬은 **희소 행렬**이라 곱셈이 효율적이다.
- **감쇠 인자 d** — 팻이 무작위로 주소를 입력할 확률을 반영해 **수렴 속도와 안정성을 타협**한다.
