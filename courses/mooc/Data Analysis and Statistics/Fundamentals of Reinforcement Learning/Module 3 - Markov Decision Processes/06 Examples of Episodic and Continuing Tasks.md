## 내용

### 에피소드형 예 — 단순 비디오 게임 ⭐
| 요소 | 설계 |
|---|---|
| **게임 규칙** | **파란색 플레이어가 흰색 보물 블록을 모으면 점수. 초록색 적 블록에 닿으면 게임이 끝난다** |
| **상태** | ⭐ **현재 화면에 대응하는 픽셀 값 배열** |
| **행동** | **위 · 아래 · 왼쪽 · 오른쪽 네 가지** |
| **보상** | **보물 블록을 모을 때마다 +1** |
| **에피소드 종료** | **초록색 적 중 하나에 닿을 때** |
| **다음 에피소드** | ⭐ **어떻게 끝났든 상관없이, 에이전트가 화면 중앙에 있고 적이 없는 상태로 시작한다** |

> **이 게임은 자연스럽게 에피소드형 MDP로 표현된다. 에이전트는 게임이 끝나기 전까지 최대한 많은 점수를 모아 높은 점수를 얻으려 한다.**
>
> 💡 **영상 속 에이전트는 Q-learning으로 훈련했다. Course 2에서 이 알고리즘을 배우고 직접 구현한다.**

### 연속형 예 — 서버 작업 스케줄링 ⭐
강화학습 연구자들이 실험을 돌리는 **서버 3대**가 있고, 연구자들은 **우선순위가 다른 작업을 하나의 큐에 제출**한다.

| 요소 | 설계 |
|---|---|
| **상태** | ⭐ **비어 있는 서버 수 + 큐 맨 앞 작업의 우선순위** |
| **행동** | **서버가 비어 있다면 큐 맨 앞 작업을 수락(accept) 또는 거절(reject)** |
| **보상** | **수락 → 작업을 실행하고 그 작업의 우선순위와 같은 보상.** **거절 → 우선순위에 비례하는 음의 보상**을 받고 **작업은 큐의 맨 뒤로 보낸다** |

> ⚠️ **에이전트는 낮은 우선순위 작업을 스케줄링하는 데 신중해야 한다. 그러면 나중에 높은 우선순위 작업을 스케줄링하지 못하게 될 수 있기 때문**이다.
>
> **서버는 작업을 마치면 다시 비고, 연구자들은 계속 작업을 큐에 넣고, 에이전트는 계속 수락·거절한다. 이 과정은 멈추지 않으므로 연속 과제로 잘 기술된다.**
