# Hello, World(s)

## 개요

- 첫 에이전트에게 간단한 웹 앱을 맡긴다.
- 두 에이전트를 병렬로 실행해 다국어 페이지를 만들고 연결한다.
- 구현 계획과 walkthrough 산출물을 검토한다.

## 내용

### 첫 비행

간단한 Hello World 앱을 요청한다. 에이전트가 불필요한 패키지 설치나 터미널 명령으로 과도하게 설계하면 더 단순하게 접근하도록 교정한다.

이 실습에서 드러나는 두 가지 특징은 다음과 같다.

- 비결정적 AI 출력에는 항상 인간 검토자(HITL)가 필요하다.
- Antigravity의 브라우저 서브에이전트는 생성한 코드를 실제 브라우저에서 테스트할 수 있다.

### 병렬 오케스트레이션

Planning 모드에서 일본어 페이지와 스페인어 페이지를 각각 다른 에이전트에게 맡긴다. 역할이 충돌하지 않도록 담당 언어와 파일 위치를 구체적으로 지정한다.

Planning 모드의 대표 산출물은 다음과 같다.

- **Implementation plan**: 작업 절차이며 사용자가 댓글로 방향을 수정할 수 있다.
- **Walkthrough**: 완료한 작업의 요약이며 스크린샷이나 녹화를 포함할 수 있다.

모든 페이지가 서로 연결되지 않았다면 한 에이전트에게 세 페이지 사이의 탐색 버튼을 추가하도록 요청한다.

### 좋은 관리자의 지침

- 결과물과 저장 위치를 명확히 한다.
- 에이전트별 역할을 겹치지 않게 정의한다.
- 선행 작업이 완료된 후 의존 작업을 시작한다.

## 예시

```text
Hi Gemini. Please make me a simple app that displays "Hello, World!"
```

과도한 구현을 시도할 때의 짧은 교정 예시:

```text
Think simpler. No terminal commands should be necessary.
```

## 요약

- 병렬 실행보다 역할, 산출물, 의존성 정의가 먼저다.
- 구현 계획을 승인하기 전에 범위와 충돌 여부를 검토한다.
- 에이전트 결과는 매번 달라질 수 있으므로 완성 상태를 직접 확인한다.
