# Prompt engineering

## 개요

- 6개 질문으로 제품 비전을 구체화한다.
- 프롬프트 체이닝과 반복 개선으로 에이전트 지시문을 만든다.

## 내용

### 여섯 가지 질문

사용자 경험과 개발자 경험 양쪽에 다음 질문을 적용한다.

1. **Who**: 누가 사용하고 누가 개발·소유하는가?
2. **What**: 원하는 사용자 경험과 개발 경험은 무엇인가?
3. **When**: 기능과 백엔드 서비스는 언제 실행되는가?
4. **Where**: 사용자는 어디서 행동하고 앱과 데이터는 어디에 존재하는가?
5. **Why**: 사용 이유와 개발 목적은 무엇인가?
6. **How**: 사용 방식과 구현 방식은 무엇인가?

### 프롬프트 체이닝

질문에 대한 답을 컨텍스트로 제공하고 Gemini 같은 AI에게 에이전트용 프롬프트 초안을 작성하게 한다. AI가 AI를 위한 지시문을 만드는 방식이 프롬프트 체이닝이다.

초안은 출발점일 뿐이다. 사용자는 실제 실행 결과를 보고 편집해야 한다.

### 실패에서 배우기

Voyager 초기 설계는 Agent A와 B만 사용했지만 게임과 리더보드가 따로 동작했다. 이를 해결하기 위해 통합 검증을 전담하는 Agent C를 추가했다.

프롬프트는 세 관점에서 평가한다.

- **Strategy**: 에이전트 수, 역할 분배, 실행 순서, 도구 선택
- **Tactics**: 단계별 작업, 성공 조건, 테스트와 오류 처리
- **Context**: 파일, 스킬, 요구사항, 제약과 참고 자료

### 90-10 규칙

AI가 프로젝트 대부분을 빠르게 만들더라도 마지막 10%를 완성하는 데 인간 노력의 90%가 들 수 있다. 코드가 대부분 동작하면 수정하며 전진하고, 근본 구조가 잘못됐으면 프롬프트 단계로 돌아간다.

### 반복 절차

1. 6개 질문으로 비전을 명확히 한다.
2. 프롬프트 체이닝으로 초안을 만든다.
3. 전략·전술·컨텍스트 관점에서 편집한다.
4. 에이전트를 실행하고 감독한다.
5. 생성된 코드를 테스트한다.
6. 대부분 동작하면 마지막 문제를 수정한다.
7. 대부분 미완성이면 프롬프트를 재설계하고 다시 시작한다.

## 예시

```text
제품 비전
  → 6W 질문에 답하기
  → AI로 프롬프트 초안 생성
  → 전략·전술·컨텍스트 검토
  → 실행·테스트
  → 수정 또는 재설계
```

## 요약

- 좋은 프롬프트는 제품 비전과 실행 제약을 함께 담는다.
- 프롬프트 체이닝 결과에는 반드시 사람의 편집이 필요하다.
- 실패가 국소적이면 코드를 수정하고, 구조적이면 프롬프트를 다시 설계한다.
