# 셀프 프롬프팅 에이전트: 전문 작업을 위한 LLM 활용

## LLM의 범용성

대형 언어 모델(LLM)은 놀라울 정도로 다재다능한 컴퓨팅 도구다. 세심하게 설계된 프롬프트를 통해 다음과 같은 작업을 수행할 수 있다:

- **자연어 처리**: 감정 분석, 텍스트 분류
- **분석적 추론**: 문제 해결
- **구조화**: 비정형 텍스트에서 정형 데이터 생성
- **도메인 전문가 역할**: 소프트웨어 아키텍처, 사이버보안 등 특수 분야

이러한 유연성은 LLM이 복잡한 지시를 이해하고 따르며, 멀티턴 대화에서 맥락을 유지하고, 특정 형식과 요구사항에 맞게 출력을 조정하는 능력에서 비롯된다.

예를 들어, 동일한 모델이 다음을 모두 수행할 수 있다:
- 비정형 데이터를 JSON으로 변환
- Graphviz 같은 도구로 시각화 생성
- 특수 도메인에서 전문가 분석 제공
- 교육용 게임이나 시뮬레이션 시스템 같은 인터랙티브 경험 생성

---

## 핵심 과제: 깔끔한 아키텍처 유지

그러나 이 강력함은 문제를 동반한다. 에이전트에게 단순히 "마케팅 전문가처럼 생각해"라거나 "데이터 과학자처럼 분석해"라고 말하면, 에이전트의 의사결정 과정이 뒤엉킬 위험이 있다.

에이전트의 본래 역할은 **행동을 조율하고 목표를 달성**하는 것이지, 도메인별 추론에 빠져드는 것이 아니다. 에이전트의 전략적 사고와 전문적 분석 능력 사이에 명확한 분리가 필요하다.

### CEO 비유

회사 조직 구조를 생각해보자. CEO는 마케팅, 엔지니어링, 재무 모두의 전문가일 필요가 없다. 대신, **언제 각 부서 전문가에게 조언을 구해야 하는지**, 그리고 **그 의견들을 회사 목표를 향해 어떻게 조율할지**를 알면 된다.

에이전트도 같은 방식으로 작동해야 한다. 명확한 의사결정을 유지하면서, 잘 정의된 인터페이스를 통해 전문 능력에 접근하는 것이다.

**해결책**: 특정 작업에 집중하는 프롬프트들을 **도구(Tool)** 로 격리하고 노출시키는 것이다. 이렇게 하면 에이전트 아키텍처를 깔끔하게 유지하면서도, 필요할 때 LLM 기반 연산의 전체 능력을 활용할 수 있다.

---

## 셀프 다이얼로그(Self-Dialog) 이해

에이전트에게 "프롬프팅"을 도구로 노출하면, 에이전트는 **셀프 다이얼로그**를 수행할 수 있게 된다. 즉, 자신의 능력을 활용해 스스로에게 전문 작업을 지시하는 것이다.

이 패턴이 가능하게 하는 것:
- 동적으로 전문가 페르소나 채택
- 복잡한 분석 수행
- 구조화된 콘텐츠 생성

이 모든 것을 **전략적 의사결정과 전문 처리를 명확히 분리**한 채로 수행한다.

### LLM이 도구로서 할 수 있는 일

| 작업 유형 | 내용 |
|-----------|------|
| 구조화 변환 | 패턴과 관계를 분석해 비정형 데이터를 정형 형식으로 변환 |
| 감정 분석 | 언어의 뉘앙스와 맥락을 신중하게 고려해 감정/정서 분석 |
| 창의적 해결책 생성 | 다양한 관점에서 가능성을 탐색 |
| 핵심 인사이트 추출 | 다양한 분석 프레임워크로 정보를 체계적으로 검토 |
| 데이터 정제 및 정규화 | 일관된 규칙 적용 및 예외 상황 처리 |

**예시**: 고객 피드백을 분석할 때, LLM은 먼저 원시 텍스트를 구조화된 카테고리로 분류하고, 각 카테고리의 감정을 분석한 뒤, 고객 만족도 트렌드에 대한 인사이트를 종합한다. 각 단계에서 LLM은 서로 다른 유형의 분석적 사고를 수행한다.

## 도구 기반 해결책

LLM의 능력을 도구로 노출하면 다음을 달성할 수 있다:

- 에이전트의 의사결정 과정을 깔끔하게 유지 (행동 조율에 집중)
- 필요할 때 LLM 기반 분석과 변환의 전체 능력 활용
- 전략적 조율과 전문 처리 사이의 명확한 경계 유지
- 공통 분석 작업을 위한 재사용 가능하고 잘 정의된 인터페이스 생성

이 도구들은 조직의 **전문 부서**와 같다. 각 부서는 명확한 목적과 인터페이스를 가지지만, 내부 작동 방식(특정 프롬프트와 추론 체인)은 도구 내부에 캡슐화되어 있다.

에이전트는 감정 분석 도구가 내부적으로 어떻게 작동하는지 알 필요가 없다. **언제 사용해야 하는지**, **무엇을 기대할 수 있는지**만 알면 된다.

## 툴킷 구성하기

다양한 전문 작업을 처리하기 위해 여러 유형의 LLM 기반 도구를 만들 수 있다:

| 도구 유형 | 설명 |
|-----------|------|
| **변환 도구 (Transformation Tools)** | 서로 다른 데이터 형식과 구조 간 변환 |
| **분석 도구 (Analysis Tools)** | 특정 도메인에서 전문가 인사이트 제공 |
| **생성 도구 (Generation Tools)** | 명세로부터 구조화된 콘텐츠 생성 |
| **검증 도구 (Validation Tools)** | 콘텐츠가 특정 기준을 충족하는지 확인 |
| **추출 도구 (Extraction Tools)** | 더 큰 맥락에서 특정 정보 추출 |

각 도구 유형은 특정 종류의 셀프 다이얼로그를 캡슐화하여, 깔끔한 인터페이스를 통해 에이전트에게 제공한다.

## 요약

이 접근 방식의 핵심은 **관심사의 분리(Separation of Concerns)** 다.

```
에이전트 (전략적 조율)
    ↓ 필요할 때 호출
도구들 (전문 LLM 프롬프트)
 - 감정 분석 도구
 - 데이터 변환 도구
 - 인사이트 추출 도구
 - ...
```

에이전트는 "무엇을 해야 하는가"에 집중하고, 도구는 "어떻게 처리하는가"를 담당한다. 이를 통해 LLM 기반 연산의 전체 능력을 활용하면서도, 에이전트의 의사결정 과정을 명확하고 집중된 상태로 유지할 수 있다.
