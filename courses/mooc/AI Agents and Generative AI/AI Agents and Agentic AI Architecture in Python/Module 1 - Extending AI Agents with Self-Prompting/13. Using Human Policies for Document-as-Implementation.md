# 문서를 구현체로 사용하는 패턴 (Document-as-Implementation)

---

## 기존 방식의 문제점

전통적인 AI 시스템에서도 비즈니스 로직은 아래의 흐름을 따릅니다.

```
정책 문서 → 개발자 이해 → 코드 구현
```

이 과정에서 발생하는 근본적인 문제들:

| 문제 | 설명 |
|---|---|
| **번역 손실** | 지식이 포맷을 이동할 때마다 맥락과 뉘앙스가 소실됨 |
| **유지보수 어려움** | 정책 문서는 업데이트되어도, 코드는 개발자가 수동으로 반영하기 전까지 변경되지 않음 |
| **지식 사일로** | 개발자만이 시스템 동작을 수정할 수 있어 병목 발생 |
| **검증 어려움** | 코드가 현재 정책을 정확히 반영하는지 확인하기 어려움 |

---

## Document-as-Implementation 패턴이란?

송장 처리 예시에서 실제로 사용한 방식을 살펴봅니다.

```python
# 디스크에서 최신 구매 규칙을 로드
rules_path = "config/purchasing_rules.txt"

try:
    with open(rules_path, "r") as f:
        purchasing_rules = f.read()
except FileNotFoundError:
    purchasing_rules = "No rules available. Assume all invoices are compliant."
```

이 단순한 파일 로딩 코드가 비즈니스 로직 구현 방식의 **패러다임 전환**을 의미합니다.  
정책을 코드로 번역하는 대신, **사람이 읽을 수 있는 문서 자체가 로직이 됩니다.**

---

## 핵심 장점

### 1. 인간 지식의 직접 활용
정책을 코드로 번역하는 과정 없이, 사람이 작성한 문서를 구현체로 직접 사용합니다.

### 2. 코드 변경 없이 동적 업데이트
정책이 변경되면 문서만 수정하면 됩니다. 다음 실행 시 시스템이 자동으로 최신 규칙을 반영하며, 개발자 개입이나 재배포가 불필요합니다.

### 3. 조직 구조와의 정렬
정책을 정의하는 담당자(법무, 컴플라이언스, 재무팀)가 **시스템 동작을 직접 제어하는 문서를 유지관리**할 수 있습니다.

### 4. 추적 가능성과 투명성
에이전트가 결정을 내릴 때 어떤 버전의 문서를 사용했는지 명확히 알 수 있어, 결정과 정책을 연결하는 **감사 추적(Audit Trail)** 이 생성됩니다.

---

## 패턴 확장 가능성

단순 텍스트 파일을 넘어 다양한 형태로 확장할 수 있습니다.

| 확장 형태 | 설명 |
|---|---|
| **지식 베이스 / 위키** | 전사 지식 베이스나 내부 위키 전체를 참조하여 방대한 조직 지식을 추론 |
| **버전 관리 문서** | 어떤 버전의 정책이 적용되었는지 추적 가능 — 컴플라이언스 감사에 필수 |
| **다중 문서 추론** | 여러 문서에 걸쳐 정보를 종합하여 인간 전문가처럼 추론 |
| **문서 기반 워크플로우** | 표준 운영 절차(SOP) 문서가 전체 워크플로우의 다음 단계를 결정 |

---

## 실제 적용 분야

| 분야 | 활용 방식 |
|---|---|
| **컴플라이언스 시스템** | 규제 준수 문서를 진실의 원천으로 사용, 현행 규정을 항상 반영 |
| **의료 프로토콜** | 임상 가이드라인과 병원 규정을 직접 참조, 베스트 프랙티스 변경 즉시 반영 |
| **HR 정책 집행** | 실제 인사 정책 문서를 기준으로 요청을 평가 |
| **고객 서비스** | 제품 문서, FAQ, 정책 문서를 활용한 일관성 있는 응답 제공 |

---

## 구현 방법

1. 조직 내에서 의사결정 지식이 담긴 **사람이 읽을 수 있는 문서**를 식별
2. 해당 문서를 **인간 전문가와 AI 시스템 사이의 인터페이스**로 취급
3. 런타임에 현재 문서 버전을 가져오는 **로딩 메커니즘** 구축
4. LLM이 문서 내용을 효과적으로 추론할 수 있도록 **프롬프트 설계**
5. 하위 시스템이 처리할 수 있는 형식으로 **결정 사항을 구조화하여 출력**

---

## 결론

Document-as-Implementation 패턴은 지능형 시스템을 구축하는 방식을 근본적으로 바꿉니다.

- **도메인 전문가**가 시스템 동작에 직접 영향을 미칠 수 있음
- **정책 변경**이 즉시 시스템 결정에 반영됨
- **문서와 구현 사이의 간극**이 사라짐
- 조직이 보유한 **기존 지식 자산을 그대로 활용** 가능
