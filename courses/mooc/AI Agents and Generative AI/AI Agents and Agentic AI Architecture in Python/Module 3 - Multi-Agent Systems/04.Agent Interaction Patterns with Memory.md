# 멀티 에이전트 시스템의 메모리 상호작용 패턴

에이전트들이 협력할 때, 메모리를 어떻게 공유하고 관리하느냐에 따라 협업 방식이 크게 달라진다. 에이전트 간 메모리 상호작용의 다양한 패턴을 살펴보고, 각 패턴이 언제 유용한지, 어떻게 구현하는지 알아보자.

---

## 메시지 전달(Message Passing): 기본 패턴

에이전트 상호작용의 가장 단순한 형태는 **메시지 전달**이다. 한 에이전트가 요청을 보내고 응답을 받는 방식으로, 동료에게 이메일을 보내는 것과 비슷하다. 상대방은 메시지를 받아 작업을 수행하고 결과를 돌려준다. 어떻게 답을 도출했는지는 볼 수 없고, 오직 최종 응답만 받게 된다.

기본 메시지 전달 구현 방법은 다음과 같다.

```python
@register_tool()
def call_agent(action_context: ActionContext, 
               agent_name: str, 
               task: str) -> dict:
    """에이전트 간 기본 메시지 전달."""
    agent_registry = action_context.get_agent_registry()
    agent_run = agent_registry.get_agent(agent_name)
    
    # 호출된 에이전트를 위한 새 메모리 생성
    invoked_memory = Memory()
    
    # 에이전트 실행 후 결과 수신
    result_memory = agent_run(
        user_input=task,
        memory=invoked_memory
    )
    
    # 최종 메모리 항목만 반환
    return {
        "result": result_memory.items[-1].get("content", "No result")
    }
```

이 패턴은 첫 번째 에이전트가 추론 과정이 아닌 **최종 답변만** 필요할 때 적합하다. 예를 들어, 프로젝트 매니저 에이전트가 스케줄링 에이전트에게 회의 시간을 찾아달라고 요청할 때, 어떻게 시간을 정했는지보다 언제 회의가 잡혔는지만 알면 된다.

## 메모리 반영(Memory Reflection): 과정으로부터 학습하기

때로는 첫 번째 에이전트가 두 번째 에이전트가 어떻게 결론에 도달했는지 이해해야 할 때가 있다. 이는 동료에게 답만 달라고 하는 게 아니라 **사고 과정까지 설명해 달라**고 요청하는 것과 같다. 두 번째 에이전트의 모든 메모리를 첫 번째 에이전트에게 복사함으로써 이를 구현할 수 있다.

```python
@register_tool()
def call_agent_with_reflection(action_context: ActionContext, 
                             agent_name: str, 
                             task: str) -> dict:
    """에이전트를 호출하고 전체 사고 과정을 받아온다."""
    agent_registry = action_context.get_agent_registry()
    agent_run = agent_registry.get_agent(agent_name)
    
    # 호출된 에이전트를 위한 새 메모리 생성
    invoked_memory = Memory()
    
    # 에이전트 실행
    result_memory = agent_run(
        user_input=task,
        memory=invoked_memory
    )
    
    # 호출자(caller)의 메모리 가져오기
    caller_memory = action_context.get_memory()
    
    # 호출된 에이전트의 모든 메모리를 호출자에게 추가
    # (중복 방지를 위해 마지막 메모리는 제외할 수도 있음)
    for memory_item in result_memory.items:
        caller_memory.add_memory({
            "type": f"{agent_name}_thought",  # 메모리 출처 표시
            "content": memory_item["content"]
        })
    
    return {
        "result": result_memory.items[-1].get("content", "No result"),
        "memories_added": len(result_memory.items)
    }
```

이 패턴은 첫 번째 에이전트가 **추론 과정을 이해해야 할 때** 유용하다. 예를 들어, 연구 코디네이터 에이전트가 데이터 분석 에이전트에게 결과를 분석해 달라고 요청한다면, 분석 과정을 함께 확인함으로써 결론을 더 잘 이해하고 활용할 수 있다.

## 메모리 인계(Memory Handoff): 대화 이어받기

두 번째 에이전트가 첫 번째 에이전트가 멈춘 지점에서 전체 맥락을 갖고 **이어서 작업**해야 하는 경우도 있다. 이는 동료에게 프로젝트를 넘길 때, 지금까지의 모든 내용을 알려주는 것과 같다.

```python
@register_tool()
def hand_off_to_agent(action_context: ActionContext, 
                      agent_name: str, 
                      task: str) -> dict:
    """공유 메모리와 함께 다른 에이전트에게 제어권을 이전한다."""
    agent_registry = action_context.get_agent_registry()
    agent_run = agent_registry.get_agent(agent_name)
    
    # 현재 메모리를 인계하기 위해 가져오기
    current_memory = action_context.get_memory()
    
    # 기존 메모리를 넘겨 에이전트 실행
    result_memory = agent_run(
        user_input=task,
        memory=current_memory  # 기존 메모리 전달
    )
    
    return {
        "result": result_memory.items[-1].get("content", "No result"),
        "memory_id": id(result_memory)
    }
```

이 패턴은 **맥락이 중요한 복잡한 작업**에 적합하다. 예를 들어, 고객 서비스 에이전트가 기술 지원 에이전트에게 고객을 인계할 때, 기술 지원 에이전트는 고객 문제의 전체 히스토리를 알아야 한다.

## 세 가지 패턴 비교

| 패턴 | 전달되는 정보 | 적합한 상황 |
|------|-------------|-----------|
| 메시지 전달 | 최종 결과만 | 결과만 필요하고 과정은 불필요한 경우 |
| 메모리 반영 | 결과 + 사고 과정 전체 | 추론 과정을 이해하고 학습해야 하는 경우 |
| 메모리 인계 | 기존 메모리 전체 공유 | 다른 에이전트가 작업을 완전히 이어받아야 하는 경우 |
