# 멀티 에이전트 시스템 구축: 에이전트 간 통신

## `call_agent` 도구

여러 전문화된 에이전트들이 협력하는 시스템을 만들고 싶다고 상상해보자. 각 에이전트는 고유한 능력을 갖추고 복잡한 문제를 함께 해결한다. 예를 들어, 상위 수준의 작업을 조율하는 기본 에이전트가 있고, 특화된 작업은 다른 에이전트에게 위임하는 구조다. 이를 가능하게 하려면 에이전트들이 서로 통신하는 방법이 필요하다.

앞서 살펴봤듯이, 에이전트에 새로운 기능을 추가하는 가장 효과적인 방법은 그 기능을 **도구(tool)로 노출**하는 것이다. 이 설계 방식은 에이전트 간에 적절한 도구 인터페이스만 노출하면 멀티 에이전트 협력 시스템을 간단하게 만들 수 있게 해준다. 이제 한 에이전트가 다른 에이전트를 호출하고 결과를 받을 수 있는 `call_agent` 도구를 만들어서 멀티 에이전트 협력 기능을 구축해보자. `ActionContext`를 활용하면 이를 놀랍도록 간단하게 구현할 수 있다.

먼저, 이 도구가 에이전트 실행 안에서 어떻게 동작하는지 살펴보자:

```python
@register_tool()
def call_agent(action_context: ActionContext, 
               agent_name: str, 
               task: str) -> dict:
    """
    다른 에이전트를 호출하여 특정 작업을 수행하게 한다.
    
    Args:
        action_context: 사용 가능한 에이전트 레지스트리를 포함
        agent_name: 호출할 에이전트의 이름
        task: 에이전트에게 수행시킬 작업
        
    Returns:
        호출된 에이전트의 최종 메모리 결과
    """
    # 컨텍스트에서 에이전트 레지스트리를 가져온다
    agent_registry = action_context.get_agent_registry()
    if not agent_registry:
        raise ValueError("컨텍스트에 에이전트 레지스트리가 없습니다")
    
    # 레지스트리에서 에이전트의 실행 함수를 가져온다
    agent_run = agent_registry.get_agent(agent_name)
    if not agent_run:
        raise ValueError(f"에이전트 '{agent_name}'을 레지스트리에서 찾을 수 없습니다")
    
    # 호출될 에이전트를 위한 새로운 메모리 인스턴스를 생성한다
    invoked_memory = Memory()
    
    try:
        # 제공된 작업으로 에이전트를 실행한다
        result_memory = agent_run(
            user_input=task,
            memory=invoked_memory,
            # 필요한 컨텍스트 속성만 전달한다
            action_context_props={
                'auth_token': action_context.get('auth_token'),
                'user_config': action_context.get('user_config'),
                # 무한 재귀 방지를 위해 agent_registry는 전달하지 않는다
            }
        )
        
        # 마지막 메모리 항목을 결과로 반환한다
        if result_memory.items:
            last_memory = result_memory.items[-1]
            return {
                "success": True,
                "agent": agent_name,
                "result": last_memory.get("content", "결과 내용 없음")
            }
        else:
            return {
                "success": False,
                "error": "에이전트 실행에 실패했습니다."
            }
            
    except Exception as e:
        return {
            "success": False,
            "error": str(e)
        }
```

### `call_agent` 도구의 동작 방식

`call_agent` 도구가 멀티 에이전트 시스템 내에서 에이전트 간 통신을 어떻게 가능하게 하는지 살펴보자. 이 도구는 적절한 경계를 유지하면서 올바른 에이전트 호출을 보장하는 프로토콜을 따른다.

한 에이전트가 다른 에이전트의 기능을 사용해야 할 때, 대상 에이전트의 이름과 수행할 작업 설명을 인수로 이 함수를 호출한다. 함수는 먼저 `ActionContext`에서 에이전트 레지스트리를 가져온다 — 레지스트리는 시스템 내 모든 에이전트의 중앙 디렉터리 역할을 한다. 요청된 에이전트가 존재하는지 확인한 후, 호출될 에이전트를 위해 **새로운 메모리 인스턴스**를 생성한다. 이를 통해 매번 깨끗한 상태에서 시작할 수 있다.

이 함수의 핵심은 대상 에이전트를 실제로 실행하는 부분이다. 제공된 작업으로 에이전트의 실행 함수를 호출하면서, 호출하는 에이전트로부터 **필요한 컨텍스트 속성만** 전달한다. 주목할 점은 에이전트 레지스트리 자체는 의도적으로 전달하지 않는다는 것이다 — 에이전트들이 제약 없이 서로를 계속 호출하는 **무한 재귀 루프**를 방지하기 위해서다. 호출된 에이전트가 작업을 완료하면, 함수는 최종 메모리 항목을 결과로 추출한다. 이것이 에이전트의 최종 결론 또는 출력을 나타낸다.

이 구조화된 에이전트 간 통신 방식은 에이전트들이 효과적으로 협력하면서도 명확한 역할 분리를 유지하고, 순환 참조나 과도한 컨텍스트 공유 같은 잠재적 문제를 방지하여 시스템의 안정성과 보안을 지킨다.

## 전문 에이전트로 회의 일정 시스템 구축하기

프로젝트 관리 시스템을 예시로 살펴보자. 여기서 두 에이전트가 협력하여 필요한 회의를 파악하고 일정을 잡는다. **프로젝트 관리 에이전트**는 회의가 필요한 시점을 결정하고, **스케줄링 전문 에이전트**는 실제 일정 조율을 담당한다.

### 스케줄링 전문 에이전트의 도구

이 에이전트는 캘린더와 상호작용하고 초대장을 생성하는 데 집중한다:

```python
@register_tool()
def check_availability(
    action_context: ActionContext,
    attendees: List[str],
    start_date: str,
    end_date: str,
    duration_minutes: int,
    _calendar_api_key: str
) -> List[Dict]:
    """모든 참석자의 가능한 시간대를 찾는다."""
    return calendar_service.find_available_slots(...)

@register_tool()
def create_calendar_invite(
    action_context: ActionContext,
    title: str,
    description: str,
    start_time: str,
    duration_minutes: int,
    attendees: List[str],
    _calendar_api_key: str
) -> Dict:
    """캘린더 초대장을 생성하고 발송한다."""
    return calendar_service.create_event(...)
```

스케줄링 전문 에이전트는 시간 찾기와 회의 생성에만 집중한다:

```python
scheduler_agent = Agent(
    goals=[
        Goal(
            name="schedule_meetings",
            description="""다음을 통해 효율적으로 회의를 일정 잡기:
            1. 모든 참석자에게 맞는 시간대 찾기
            2. 캘린더 초대장 생성 및 발송
            3. 일정 충돌 처리"""
        )
    ],
    ...
)
```

### 프로젝트 관리 에이전트의 도구

이 에이전트는 프로젝트 상태 파악과 회의 필요 여부 결정에 집중한다:

```python
@register_tool()
def get_project_status(
```

프로젝트 관리 에이전트는 이 도구들로 진행 상황을 모니터링하고 필요시 회의를 주선한다:

### 역할 분리의 핵심

이 역할 분담은 각 에이전트가 핵심 역량에만 집중하게 한다:

- **프로젝트 매니저**: 프로젝트 상태를 이해하고 회의가 필요한 시점을 판단
- **스케줄러**: 가용 시간 찾기와 캘린더 관리 로직에 특화
- **`call_agent` 도구**: 두 에이전트 간의 원활한 협력을 가능하게 함

---

## `call_agent` 도구의 핵심 설계 원칙

| 원칙 | 설명 |
|------|------|
| **메모리 격리** | 호출되는 에이전트는 독립된 메모리 인스턴스를 가진다. 서로 다른 에이전트의 대화 이력이 뒤섞이는 것을 방지한다. |
| **컨텍스트 관리** | 전달되는 컨텍스트 속성을 신중하게 통제한다. 무한 재귀를 막으면서도 필요한 리소스는 제공한다. |
| **결과 처리** | 최종 메모리 항목을 결과로 추출하여, 호출한 에이전트에 정보를 깔끔하게 반환한다. |

## 에이전트 등록하기

이 시스템이 동작하려면 에이전트를 레지스트리에 등록해야 한다:

```python
class AgentRegistry:
    def __init__(self):
        self.agents = {}
        
    def register_agent(self, name: str, run_function: callable):
        """에이전트의 실행 함수를 등록한다."""
        self.agents[name] = run_function
        
    def get_agent(self, name: str) -> callable:
        """이름으로 에이전트의 실행 함수를 가져온다."""
        return self.agents.get(name)

# 시스템 설정 시
registry = AgentRegistry()
registry.register_agent("scheduler_agent", scheduler_agent.run)

# 액션 컨텍스트에 레지스트리 포함
action_context = ActionContext({
    'agent_registry': registry,
    # 기타 공유 리소스...
})
```

`ActionContext`는 에이전트 레지스트리를 모든 도구에 직접 노출하지 않으면서도 `call_agent` 도구가 사용할 수 있게 하는 깔끔한 방법을 제공한다. 에이전트가 작업을 위임해야 할 때는 단순히 다른 도구를 사용하듯이 이 도구를 호출하면 되고, 환경 시스템이 올바른 에이전트를 찾아 호출하는 세부 사항을 처리한다.

이 아키텍처를 통해 각 에이전트가 전문성을 유지하면서도 필요할 때 다른 에이전트와 협력할 수 있는 복잡한 멀티 에이전트 시스템을 구축할 수 있다. 메모리 격리는 각 에이전트가 깨끗한 컨텍스트로 작동하게 보장하고, 결과 추출은 에이전트 간에 정보를 전달하는 표준화된 방법을 제공한다.
