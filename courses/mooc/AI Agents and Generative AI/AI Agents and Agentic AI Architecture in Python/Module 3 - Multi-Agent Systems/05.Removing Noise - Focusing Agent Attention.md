# 노이즈 제거: 에이전트의 집중력 높이기

## 에이전트 간 메모리 공유의 핵심 문제

에이전트 간 메모리 공유를 생각할 때 아직 다루지 않은 중요한 문제가 하나 있다. 한 에이전트가 다른 에이전트에게 메시지를 보내는 **태스크 모델**로 돌아가 보자.

이 모델에는 중요한 제약이 있다. **메시지 크기에는 항상 한계가 존재한다는 것이다.** 에이전트가 태스크를 생성하려면 결국 토큰을 생성해야 하는데, 모든 LLM에는 출력할 수 있는 토큰 수의 한계가 있기 때문이다.

---

## 입력 토큰 vs 출력 토큰의 비대칭

LLM의 특성을 생각해보자:

- **입력(Input)**: 대량의 토큰을 받아들일 수 있다
- **출력(Output)**: 입력보다 훨씬 적은 토큰만 생성할 수 있다
- **비용**: 출력 토큰이 입력 토큰보다 더 비싸다

시각적으로 표현하면, LLM으로 들어가는 토큰의 양은 매우 크고, 나오는 토큰의 양은 상대적으로 훨씬 작다.

```
[대량의 입력 토큰] → [LLM] → [소량의 출력 토큰]
```

이 비대칭 구조가 바로 문제의 핵심이다. **메모리는 매우 클 수 있지만, 에이전트가 생성하는 태스크 설명은 작을 수밖에 없다.**

---

## 두 가지 극단의 문제

### 1. 작은 태스크 메시지만 전달할 경우
- LLM이 필요한 모든 정보를 태스크에 담기 어렵다
- 토큰 출력 한계로 인해 중요한 컨텍스트가 누락될 수 있다

### 2. 전체 메모리를 넘길 경우
- 비용이 많이 든다
- 속도가 느려진다
- 프롬프트가 비대해진다
- 다른 에이전트에게 불필요한 정보까지 노출된다

---

## 해결책: 메모리 ID 기반 선택 및 팽창(Inflation)

이 문제를 해결하는 영리한 방법이 있다. 바로 **메모리 ID를 활용한 선택과 팽창** 기법이다.

메모리가 다음과 같이 구성되어 있다고 가정하자:

```
메모리: [1] [2] [3] [4] [5] ...
```

### 작동 방식

**1단계: 에이전트가 관련 메모리 ID를 선택한다**

에이전트는 전체 메모리를 훑어보고 다른 에이전트에게 필요한 메모리의 **ID(식별자)** 를 출력한다:

```
출력: [1, 3, 4]
```

이것이 핵심이다. 메모리의 **내용(content)** 이 아닌 **식별자(identifier)** 를 출력하는 것이다. 숫자 ID는 매우 짧고 효율적이다.

**2단계: 코드가 ID를 실제 메모리 내용으로 팽창시킨다**

프로그래밍 코드가 해당 ID를 실제 메모리 내용으로 대체한다:

```
ID [1] → 실제 메모리 1의 내용
ID [3] → 실제 메모리 3의 내용
ID [4] → 실제 메모리 4의 내용
```

**3단계: 팽창된 내용을 태스크에 담아 다른 에이전트에게 전달한다**

---

## 이 기법의 장점

### 1. 토큰 한계 극복
- 첫 번째 에이전트는 짧은 ID 목록만 출력하면 된다
- 두 번째 에이전트는 팽창된 전체 내용을 받아 컨텍스트 윈도우를 최대한 활용할 수 있다

### 2. 환각(Hallucination) 방지
에이전트는 메모리 **내용을 요약하거나 변형하지 않는다**. 오직 어떤 메모리를 포함할지 **선택**만 한다. 실제 내용은 코드가 그대로 가져오기 때문에 메모리 내용이 왜곡될 위험이 없다.

예를 들어, API에서 데이터를 조회하고 그 결과를 정확하게 전달해야 할 때, 에이전트가 결과를 "요약"하면서 사실을 변경할 가능성을 원천 차단할 수 있다.

### 3. 출력 효율성
- 출력이 ID 목록으로만 구성되어 매우 간결하다
- 입출력 토큰 비대칭 문제를 효과적으로 해결한다

### 4. 역할 분리 가능
이 선택 과정을 독립적인 에이전트나 전문 프롬프트에 위임할 수 있다. 즉, **"관련 메모리를 선택하는 것"** 만을 전담하는 에이전트를 만들 수 있다:

```
선택 전담 프롬프트: "이 태스크에 관련된 메시지의 ID를 선택하라"
→ 선택된 ID를 팽창시켜 다른 에이전트에게 전달
```

이렇게 하면 첫 번째 에이전트의 부담을 줄이고, 역할을 명확하게 분리할 수 있다.

---

## 요약

| 문제 | 해결 방법 |
|------|----------|
| 출력 토큰 한계 | ID만 출력 → 코드로 팽창 |
| 불필요한 정보 노출 | 관련 메모리만 선택적으로 전달 |
| 환각으로 인한 내용 변형 | 내용을 생성하지 않고 참조만 허용 |
| 전체 메모리 전달의 비용 | 필요한 메모리만 선별하여 전달 |

이 기법은 에이전트가 **"무엇을 알아야 하는가"** 를 지능적으로 선택하면서도, 출력 토큰의 물리적 한계를 극복할 수 있는 실용적인 방법이다.
