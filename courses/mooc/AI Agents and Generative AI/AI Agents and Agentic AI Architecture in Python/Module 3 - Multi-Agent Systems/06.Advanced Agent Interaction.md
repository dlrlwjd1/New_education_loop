## 선택적 메모리 공유: LLM의 이해력을 활용한 컨텍스트 선택

때로는 에이전트가 다른 에이전트와 메모리의 어떤 부분을 공유할지 지능적으로 선택하길 원할 수 있다. 고정된 규칙을 사용하는 대신, LLM의 컨텍스트 이해력을 활용해 현재 작업에 가장 관련성 높은 메모리를 선택하게 할 수 있다.

자기 프롬프팅(self-prompting)을 통해 LLM이 관련 메모리를 분석하고 선택하는 메모리 공유 방식을 구현해보자:

```python
@register_tool(description="선택된 컨텍스트와 함께 다른 에이전트에게 작업을 위임한다")
def call_agent_with_selected_context(action_context: ActionContext,
                                   agent_name: str,
                                   task: str) -> dict:
    """LLM이 선택한 관련 메모리와 함께 에이전트를 호출한다."""
    agent_registry = action_context.get_agent_registry()
    agent_run = agent_registry.get_agent(agent_name)
    
    # 현재 메모리를 가져와 ID 부여
    current_memory = action_context.get_memory()
    memory_with_ids = []
    for idx, item in enumerate(current_memory.items):
        memory_with_ids.append({
            **item,
            "memory_id": f"mem_{idx}"
        })
    
    # 메모리 선택을 위한 스키마 생성
    selection_schema = {
        "type": "object",
        "properties": {
            "selected_memories": {
                "type": "array",
                "items": {
                    "type": "string",
                    "description": "포함할 메모리의 ID"
                }
            },
            "reasoning": {
                "type": "string",
                "description": "해당 메모리를 선택한 이유 설명"
            }
        },
        "required": ["selected_memories", "reasoning"]
    }
    
    # LLM 검토를 위해 메모리를 텍스트로 포맷
    memory_text = "\n".join([
        f"메모리 {m['memory_id']}: {m['content']}" 
        for m in memory_with_ids
    ])
    
    # LLM에게 관련 메모리 선택 요청
    selection_prompt = f"""아래 메모리를 검토하고 이 작업에 관련된 것들을 선택하라:

작업: {task}

사용 가능한 메모리:
{memory_text}

이 특정 작업에 중요한 컨텍스트나 정보를 제공하는 메모리를 선택하라.
선택 과정을 설명하라."""

    # 가장 관련성 높은 메모리를 찾기 위한 자기 프롬프팅
    selection = prompt_llm_for_json(
        action_context=action_context,
        schema=selection_schema,
        prompt=selection_prompt
    )
    
    # 선택된 메모리로 필터링된 메모리 생성
    filtered_memory = Memory()
    selected_ids = set(selection["selected_memories"])
    for item in memory_with_ids:
        if item["memory_id"] in selected_ids:
            # 추가 전 임시 memory_id 제거
            item_copy = item.copy()
            del item_copy["memory_id"]
            filtered_memory.add_memory(item_copy)
    
    # 선택된 메모리와 함께 에이전트 실행
    result_memory = agent_run(
        user_input=task,
        memory=filtered_memory
    )
    
    # 결과와 선택 이유를 원래 메모리에 추가
    current_memory.add_memory({
        "type": "system",
        "content": f"메모리 선택 이유: {selection['reasoning']}"
    })
    
    for memory_item in result_memory.items:
        current_memory.add_memory(memory_item)
    
    return {
        "result": result_memory.items[-1].get("content", "결과 없음"),
        "shared_memories": len(filtered_memory.items),
        "selection_reasoning": selection["reasoning"]
    }
```

이 구현은 메모리 선택을 더 지능적이고 투명하게 만든다:

1. 각 메모리에 참조용 고유 ID가 부여된다.
2. 전체 메모리 목록이 ID와 함께 LLM에 제공된다.
3. LLM은 특정 작업의 맥락에서 메모리를 분석하고, 구조화된 JSON 출력을 통해 관련 메모리를 선택한다.
4. LLM은 선택 이유를 제공하며, 이는 원래 에이전트의 메모리에 보존된다.

예를 들어, 프로젝트 관리 에이전트가 예산 검토 작업을 위임할 경우 상호작용은 다음과 같이 이루어질 수 있다:

```python
# 예시 메모리 내용:
memories = [
    {"type": "user", "content": "새로운 보고 대시보드를 만들어야 합니다"},
    {"type": "assistant", "content": "초기 비용 견적: $50,000"},
    {"type": "user", "content": "너무 비싼 것 같습니다"},
    {"type": "assistant", "content": "세부 내역: 개발 $20k, 디자인 $15k..."},
    {"type": "system", "content": "프로젝트 마감일이 3분기로 변경됨"},
    {"type": "user", "content": "비용을 줄일 수 있을까요?"}
]

# LLM의 선택 결과 예시:
{
    "selected_memories": ["mem_1", "mem_3", "mem_5"],
    "reasoning": "비용 정보와 비용 절감 요청이 담긴 메모리를 선택했습니다. 프로젝트 일정이나 일반적인 논의는 예산 검토 작업과 직접적인 관련이 없어 제외했습니다."
}
```

두 번째 에이전트는 비용 견적, 세부 내역, 절감 요청에 관한 메모리만 받게 되어, 일정이나 기타 프로젝트 내용과 같은 불필요한 정보 없이 예산 검토에 집중할 수 있는 맥락을 갖게 된다.

이 방식은 규칙 기반 필터링에 비해 여러 장점이 있다:

- 단순한 패턴 매칭이 아닌, **맥락과 의미**를 이해하여 선택할 수 있다.
- 선택 이유가 보존되어 어떤 정보가 왜 공유됐는지(혹은 공유되지 않았는지) 추적할 수 있다.
- 코드를 수정하지 않아도 다양한 유형의 작업과 맥락에 적응할 수 있다.
- 원래 에이전트가 어떤 정보를 왜 공유했는지 기록을 유지한다.

이 패턴은 두 번째 에이전트에 특정 컨텍스트를 제공하되, 불필요한 정보로 과부하를 주지 않을 때 유용하다. 예를 들어, 프로젝트 계획 에이전트가 예산 전문 에이전트에게 비용 검토를 요청할 경우, 전체 프로젝트 히스토리가 아닌 자원 배분과 지출에 관련된 메모리만 공유할 수 있다.

## 4가지 메모리 공유 패턴 정리

각 패턴은 에이전트 간 협업에서 서로 다른 목적을 위해 사용된다:

| 패턴 | 목적 |
|------|------|
| **메시지 전달** | 상호작용을 단순하고 집중적으로 유지 |
| **메모리 반영** | 에이전트가 서로의 프로세스에서 학습 |
| **메모리 인계** | 복잡한 작업의 원활한 이어받기 |
| **선택적 메모리 공유** | 노이즈를 줄이면서 관련 컨텍스트 제공 |

패턴 선택은 다음 기준에 따라 결정된다:

- **두 번째 에이전트에게 얼마나 많은 컨텍스트가 필요한가?**
- **첫 번째 에이전트가 두 번째 에이전트의 프로세스를 이해해야 하는가?**
- **대화 히스토리를 보존해야 하는가?**
- **필터링이 필요한 민감한 정보가 있는가?**

이러한 패턴을 이해하면, 정보 공유와 작업 집중 사이의 균형을 효과적으로 맞추는 에이전트 상호작용을 설계할 수 있으며, 이를 통해 더 효율적이고 유능한 멀티 에이전트 시스템을 구축할 수 있다.
