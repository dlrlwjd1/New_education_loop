# 인-컨텍스트 학습으로 AI 에이전트 추론 개선하기

## 인턴 비유로 돌아가서

사람에게 일을 가르치는 방법은 두 가지다.

1. **명시적 지시**: "이렇게 해라, 저렇게 해라"
2. **예시를 통한 교육**: 잘 풀린 사례를 보여주고, 그 사고 과정을 따라가게 한다

인턴에게 보고서 작성을 가르칠 때 우리는 이렇게 한다:
> "여기 보고서야. 내가 어떤 생각으로 작성했는지, 최종 결과물은 이거야."

소프트웨어 디버깅을 가르칠 때도 마찬가지다:
> "구현하려던 기능이 이거고, 내가 어떻게 문제를 추적했는지, 결과는 이거야."

**생성형 AI에서도 똑같이 할 수 있다 — 이것이 인-컨텍스트 학습(In-Context Learning)이다.**

---

## 인-컨텍스트 학습이란?

> 예시를 컨텍스트(프롬프트) 안에 넣어줌으로써, 모델이 별도 학습 없이 패턴을 학습하는 것.

많은 에이전틱 AI 시스템에서 **예시 없이는 원하는 성능을 내기가 매우 어렵다.**
명시적 지시만으로 커버하기 어려운 상황에서 인-컨텍스트 학습이 핵심 도구가 된다.

---

## 예시 1: 외계 우주선 탈출 — 이름 없는 도구 학습

### 상황

도구 이름: `X155`, `Q63`, `L199` — 설명도 없고, 이름만으로는 무슨 도구인지 알 수 없다.

### 퓨샷(Few-Shot) 예시 제공

```
예시 1
Problem: 배가 고프다
Thought: 음식을 준비해야 한다
Tool: Q63
Result: 외계인 피자가 준비됐다

예시 2
Problem: 다른 행성으로 이동해야 한다
Thought: 웜홀이 필요하다
Tool: X155
Result: 밴더빌트 대학교로 향하는 웜홀이 열렸다

예시 3
Problem: 반중력 방으로 가야 한다
Thought: 선내 이동 수단이 필요하다
Tool: L199
Result: 스쿠터를 타고 그 방으로 이동 중이다
```

도구가 **무엇인지 설명하지 않았다.** 대신 어떤 문제에서 어떤 사고 과정을 거쳐 어떤 도구를 썼는지를 보여줬다.

### 결과

```
Problem: 지구로 탈출해야 한다!
Thought: 가장 가까운 탈출 포드를 찾을 방법이 필요하다
Tool: X155
Result: 밴더빌트 대학교로 향하는 웜홀이 열렸다
```

모델이 **패턴을 인식하고 완성**했다. X155가 이동 수단임을 예시에서 추론한 것이다.

### 새로운 도구가 추가된 경우

```
New tool added: inner_wormhole

Problem: 밴더빌트 대학교에서 지구로 돌아가야 한다
Thought: 웜홀 도구를 사용해 지구로 이동해야 한다
Tool: inner_wormhole
```

설명 없이 추가된 새 도구도, **기존 패턴에 맞춰 올바르게 활용**했다.

---

## 왜 이것이 작동하는가? — 패턴 완성 원리

LLM은 근본적으로 **다음 토큰을 예측하도록 훈련**된 모델이다.

- 불완전한 패턴을 보면 → 완성하려는 경향이 생긴다
- `Problem → Thought → Tool → Result` 패턴을 반복해서 보여주면 → 새 문제에서도 같은 구조로 응답한다

이 패턴 완성 특성이 인-컨텍스트 학습의 핵심 메커니즘이다.

## 예시 2: 전자레인지 — 반복 도구 호출 패턴 학습

### 목표

"시간 증가" 도구를 1회 호출하면 5초가 늘어난다. 에이전트가 이 도구를 **여러 번 반복 호출**해서 원하는 시간에 도달하게 만들고 싶다.

### 이전 문제

> "60초가 필요하면 그냥 60초 늘리면 되지 않나요?"

→ 도구 한 번에 5초씩밖에 못 늘린다는 제약을 이해하지 못한 것.

### 퓨샷 예시 제공

```
예시 1 — 피자 20초 재가열
Problem: 남은 피자를 데워야 한다
Thought: 피자를 20초 가열해야 한다
Tool: microwave_open_door
Tool: microwave_close_door
Tool: microwave_increase_time  (×4회 = 20초)
Result: 피자가 데워졌다

예시 2 — 아이스크림 10초 녹이기
Problem: 아이스크림을 살짝 녹여야 한다
Thought: 10초 가열이 필요하다
Tool: microwave_open_door
Tool: microwave_close_door
Tool: microwave_increase_time  (×2회 = 10초)
Result: 아이스크림이 살짝 녹았다
```

### 실제 요청

```
Problem: 나초에 체다 치즈를 녹여야 한다
Thought: 30초 가열이 필요하다
Tool: microwave_open_door
Tool: microwave_close_door
Tool: microwave_increase_time  (×6회 = 30초)
→ 결과 요청
```

에이전트가 **30초 = 6번 호출**이라는 것을 예시에서 스스로 유추했다.

## 인-컨텍스트 학습이 특히 중요한 상황

### 컴퓨터 시스템과의 인터페이스

사람은 애매한 입력을 받아도 유연하게 해석하지만, **컴퓨터 시스템은 그렇지 않다.**

- 데이터베이스는 정해진 쿼리 형식만 받는다
- 이메일 서버는 정해진 프로토콜만 따른다
- API는 정해진 JSON 구조만 허용한다

에이전트가 조금이라도 다른 형식으로 요청하면 시스템이 오류를 낸다.

→ 이럴 때 인-컨텍스트 학습으로 **올바른 형식의 예시를 보여주면** 에이전트가 그 패턴을 따른다.

---

## 실전 가이드

| 상황 | 권장 조치 |
|---|---|
| 에이전트 응답이 일관되지 않음 | 퓨샷 예시 추가 |
| 특정 도구를 잘못 사용함 | 해당 도구를 올바르게 사용한 예시 제공 |
| 컴퓨터 시스템과 인터페이스 오류 반복 | 올바른 형식의 실제 trace 예시 제공 |
| 규칙으로 설명하기 너무 복잡한 패턴 | 예시 몇 개로 대체 |

> **톨스토이처럼 쓰는 법을 규칙으로 설명하는 것보다, 톨스토이 몇 페이지를 보여주는 것이 훨씬 빠르다.**

---

## 핵심 요약

1. **인-컨텍스트 학습** = 프롬프트 안에 예시를 넣어 모델이 패턴을 따르게 하는 것
2. LLM의 **패턴 완성 본능**을 적극 활용한다
3. 도구 설명 없이도 **사용 예시만으로** 도구 사용법을 학습시킬 수 있다
4. 반복 호출, 순서, 형식 등 **복잡한 행동 패턴**도 예시로 가르칠 수 있다
5. 컴퓨터 시스템처럼 **엄격한 형식**이 필요한 곳에서 특히 강력하다

> **에이전트가 말을 안 들으면 규칙을 더 추가하기 전에, 먼저 예시를 추가해보라.**
