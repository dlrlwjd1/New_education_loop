# 사전 계획(Up-front Planning)과 Chain of Thought로 AI 에이전트 추론 개선하기

## 핵심 개념

LLM에게 **생각할 시간**을 주고 **단계적으로 사고**하도록 지시하면 문제 해결 능력이 향상된다.

**왜 그럴까?**
- 1단계를 올바르게 수행하면, 단계별 문제 해결 데이터로 훈련된 LLM은 자연스럽게 다음 올바른 단계를 예측한다.
- 즉흥적(ad hoc) 실행 시에는 완전한 chain of thought가 형성되지 않는다.

---

## 사전 계획(Up-front Planning) 전략

에이전트가 **행동을 시작하기 전에** 전체 계획을 먼저 수립하게 한다.
도구를 사용하거나 액션을 취하기 전, 대화 시작 시점에 단계별 계획을 세우는 것이 핵심이다.

---

## 계획 활용 방법 3가지

### 1. 고정 실행 (Fixed Execution) — 코드로 구체화

```
계획 수립 → 코드 생성 → 코드 실행 → 결과 반환
```

- LLM이 계획을 **코드로 변환**하고, 이후 LLM 개입 없이 코드만 실행
- 워크플로우 언어나 비즈니스 프로세스로도 변환 가능

**장점:**
- **반복 실행 가능** — 동일한 입력 구조라면 저장된 코드를 재사용
- 코드 저장소에 보관 후 다른 프로젝트에서도 활용 가능

**단점:**
- 실행 중 오류 발생 시 LLM이 개입할 수 없어 동적 적응 불가
- 스택 트레이스를 받더라도 중간에 수정 불가

---

### 2. 메모리에 계획 저장 후 단계별 실행 (권장)

```
계획 수립 → 메모리(컨텍스트)에 저장 → 단계별 ad hoc 실행 → 적응
```

- LLM이 사전에 계획을 세우고, 그 계획을 **메모리(시스템 프롬프트/컨텍스트)에 저장**
- 이후 한 단계씩 실행하면서 **예상치 못한 상황에 유연하게 대응**

**장점:**
- 사전 chain of thought 효과를 유지하면서도 동적 적응 가능
- 계획의 틀 안에서 실시간으로 수정 가능

**사용법:** "이 계획을 따르세요"라고 지시하며 계획을 메모리로 주입

---

### 3. 모델 분리 전략 (고급)

```
고성능 모델(계획 수립) → 저성능 모델(계획 실행)
```

- 계획 수립을 **도구(tool)** 로 분리하여 에이전트 시작 시 강제 호출
- **비싸고 느린 고성능 모델**로 초기 계획만 생성
- **저렴하고 빠른 모델**이 해당 계획을 따라 실행

**장점:**
- 모든 단계에 고비용 모델을 쓰지 않아도 됨
- 비용 효율적으로 높은 추론 품질 달성 가능

---

## 핵심 정리

| 방식 | 유연성 | 반복성 | 적응력 |
|------|--------|--------|--------|
| 코드 생성 후 실행 | 낮음 | 높음 | 없음 |
| 메모리 저장 후 실행 | 높음 | 보통 | 있음 |
| 모델 분리 전략 | 높음 | 보통 | 있음 |

> **결론:** 가장 간단하고 효과적인 방법은 — **계획을 먼저 수립하고, 메모리에 저장한 뒤, 단계별로 실행**하는 것이다. 이 단순한 접근만으로도 에이전트의 성능을 크게 향상시킬 수 있다.
