# Contextual Preferences Pattern

## 개요
- 이 강좌의 마지막 강의로, RECIPE로는 완전히 해결하기 어려운 흔한 문제 — **"같은 작업(예: 이메일 쓰기)이라도 맥락(context)에 따라 완전히 다른 방식으로 수행해야 하는 문제"**를 다루는 실전 패턴을 소개한다.

## 내용
### 해결하려는 문제
- 이메일 작성이 대표적 사례: 어떤 이메일이냐에 따라(리더십에게 보내는 이메일, 강좌 공지 이메일, 강연 소개용 답장 등) **스타일이 완전히 달라져야** 한다.
- 생성형 AI가 기본적으로 쓰는 이메일 문체는 내 스타일과 다르고, 단순히 메모리(memory)에 의존해서는 맥락별로 정확히 다르게 쓰게 만들기 어렵다.
- 목표: "이메일을 써라"라는 **하나의 범용 스킬(one-size-fits-all)**에서 벗어나, **맥락에 따라 빠르게 전문화(specialize)되는 스킬**을 효율적으로 만드는 것.

## Contextual Preferences 패턴 구조
1. **일반 작업(generic task) 정의**: "이메일을 쓸 때 이 스킬을 사용하라" 같은 상위 설명.
2. **맥락 탐지(context detection) 지시**: "아래 맥락 목록을 보고, 적합한 맥락을 골라라"는 지시와 그 판단 방법.
3. **전역 공통 단계(global concrete steps)**: 모든 맥락에 공통으로 적용되는 절차(맥락 탐지 방법 포함).
4. **맥락 목록(list of contexts)**: 각 맥락마다 짧은 설명 + 해당 맥락 전용 규칙/예시가 담긴 **별도 파일로의 참조**.
5. **폴백(fallback)**: 어떤 맥락에도 맞지 않을 때 사용할 일반적인 처리 방법.

### 실전 사례 — 이메일 작성 스킬
- 최상단 지시: "아래 맥락 목록을 보고 적절한 맥락을 선택하고, 그 맥락의 예시를 읽은 뒤, 그 예시 스타일에 맞는 이메일을 써라."
- 추가 공통 절차: 이메일의 목적 파악 → 맥락 목록 검토.
- 맥락(context) 목록 예시 (강사의 실제 사례):
  1. 리더십에게 보내는 이메일 (email to leadership)
  2. MOOC 강좌 공지 이메일 (MOOC course announcement)
  3. 강연/키노트용 bio·abstract를 담은 답장 이메일 (email reply with bio or abstract for a keynote or talk)
- 각 맥락마다:
  - 짧고 간결한 설명(description) — 스킬의 description처럼 "언제 이 맥락을 쓰는지"를 pithy(간결)하게.
  - (선택) 해당 맥락에 적용되는 전역 규칙 (예: "리더십에게는 항상 formal 하게").
  - **별도 파일로의 참조(reference)** — 그 맥락 전용 세부 지침과 예시.

### 왜 맥락 판단 부분과 세부 내용을 분리하는가
- SKILL.md 안에서는 "어떤 맥락인지 정확히 판단하는 것"에만 집중하게 만들고, 샘플 이메일 등 세부 내용을 한꺼번에 다 욱여넣지 않는다.
- 즉, 여기서도 **점진적 노출(progressive disclosure)** 원칙이 적용됨 — 맥락을 먼저 정확히 고르게 하고, 그다음에 해당 파일만 읽게 함.
- 파일 참조 시 마크다운 링크 형태(`텍스트`)를 쓸 수도 있고, 단순히 "이 파일을 읽어라"고 경로를 알려줘도 잘 동작함.

### 맥락별 파일 내부 구성
- 예: "리더십 이메일" 맥락 파일 안에는
  - "사용자가 보낸 이메일을 검토하라"
  - "헤드샷(headshot)이 필요하면 여기 있는 파일을 참조하라" (assets로 이미지 파일을 함께 번들링 가능)
  - **긍정 예시(positive example)** — 실제 이런 이메일이 어떻게 생겼는지 템플릿+실제 bio/abstract 예시로 제공.
- bio처럼 자주 바뀌지 않는 정보는 스킬에 미리 넣어두고, 필요하면 나중에 업데이트.
- abstract처럼 매번 다른 정보는 "사용자에게 물어보거나, 제공되지 않으면 이 예시를 참고하라"는 식으로 유연하게 처리 가능.

### 핵심 통찰 — 예시(examples) 중심 설계
- 이메일처럼 "스타일"이 중요한 작업은, 규칙을 말로 다 설명하는 것보다 **과거에 잘 썼던 실제 이메일들을 예시로 모아두는 파일**을 만들어 두는 것이 훨씬 효과적.
- 이렇게 하면 AI가 예시로부터 스타일을 빠르게 학습해 그 방식대로 작성한다.

## 예시
```
email-writer/
├── SKILL.md                        ← 일반 작업 정의 + 맥락 탐지 지시 + 맥락 목록
└── references/
    ├── leadership-email.md         ← 리더십 이메일 맥락: 규칙 + 예시
    ├── course-announcement.md      ← 강좌 공지 이메일 맥락: 규칙 + 예시
    └── bio-abstract-reply.md       ← bio/abstract 답장 맥락: 헤드샷 참조 + 예시
```

## 요약
- Contextual Preferences 패턴은 **"같은 작업이라도 맥락에 따라 완전히 다르게 수행해야 하는 문제"**를 해결하는 실전 패턴이다.
- 구조: 일반 작업 정의 → 맥락 탐지 지시 → 맥락 목록(각각 별도 파일로 참조) → 폴백.
- 각 맥락 파일은 **점진적 노출** 원칙에 따라 필요할 때만 읽히며, 내부는 대부분 **실제 예시(example) 중심**으로 구성하는 것이 이메일 같은 스타일 중심 작업에 특히 효과적이다.
