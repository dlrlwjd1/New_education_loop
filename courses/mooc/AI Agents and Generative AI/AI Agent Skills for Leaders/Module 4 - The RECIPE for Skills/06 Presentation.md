# Presentation

## 개요
- RECIPE 프레임워크의 다섯 번째 요소 **P = Presentation**을 다루는 강의.
- Ideal Result(무엇을 만들지)와 밀접하게 연관되는 요소로, **그것을 어떤 형태로 제시할지**를 다룬다.

## 내용
### Presentation이란
- 결과물의 **파일 형식(file format)**, 파일이 하나인지 여러 개인지, 그 안의 **구성·포맷**까지 포함하는 개념.
- 예: 여행 경비 스킬에서
  - "정확히 이런 구조를 가진 HTML 웹페이지(대시보드)로 만들어라. 여기에 지출 내역을 채워라."
  - "이 특정 컬럼들을 가진 CSV 파일로 만들어라. 엑셀에서 열 수 있게."

### 명시하지 않으면 생기는 문제
- Presentation을 specify하지 않으면 **AI가 알아서 결정**하게 되고, 그 결과 매번 다른 형태의 결과물이 나오는 **변동성(variation)**이 생긴다.
  - 예: 어느 날은 이 컬럼으로 표를 만들고, 다음날은 완전히 다른 컬럼으로 표를 만듦.
- 이런 변동성이 바로 사람들이 AI 에이전트와 작업할 때 자주 느끼는 **좌절(frustration)**의 원인.
- 결론: 결과물이 어떻게 제시되어야 하는지에 대한 **모든 요구사항을 명확히** 밝혀야 한다.

### Assets(템플릿)로 프레젠테이션을 고정하기 — "플레이스홀더 패턴"
- 프레젠테이션을 확실히 고정하는 강력한 방법: **템플릿을 assets로 제공하고, 이를 채우게 하는 것.**
- 사람에게 서류를 작성시킬 때와 동일한 방식: "여기에 이름을 쓰세요", "여기에 날짜를 쓰세요" 처럼 **플레이스홀더(placeholder)**를 넣어둔 양식을 채우게 하는 것과 같다.
- 예: "Expense Report Review" 템플릿에 `[Employee: ___]`, `[Date: ___]`, `[Amount: ___]` 같은 플레이스홀더를 두면 AI가 이를 채워야 한다는 신호를 받는다.

### 플레이스홀더만으로는 부족할 수 있다 — 세부 형식까지 지정 필요
- 단순 플레이스홀더(`[Name]`)만 두면 여전히 변동성이 남을 수 있다.
  - 예: 이름을 "성, 이름" 순서로 원한다면 `[Name: Last, First]`처럼 형식을 구체적으로 명시해야 한다.
  - 날짜도 "월/일/년"인지 "일/월/년"인지 명시해야 한다.
- 즉, 플레이스홀더에 **지시문(instructions)을 함께 적어** 정확한 형식을 규정해야 변동성을 더 줄일 수 있다.
- (다음 강의에서 다룰 내용) 모든 걸 지시문으로 다 설명하지 않고, **예시(examples)를 제공하는 방식**으로도 형식을 고정할 수 있다.

## 예시
```
Expense Report Review
Employee: [Last, First]
Date: [MM/DD/YYYY]
Amount: [$0.00]
```
- 플레이스홀더에 형식 지시를 덧붙여 변동성을 최소화.

## 요약
- Presentation은 **결과물의 형식·구조를 얼마나 구체적으로 지정하느냐**를 다루는 요소이며, 명시하지 않으면 매번 다른 형태의 결과물이 나온다.
- 사람에게 양식을 채우게 하듯, **템플릿(assets) + 플레이스홀더** 방식으로 형식을 고정하는 것이 강력한 전략이다.
- 플레이스홀더에도 정확한 형식(순서, 표기법 등)을 함께 지시해야 변동성을 더 줄일 수 있다.
