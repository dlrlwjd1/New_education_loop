# The Anatomy of a Skill

## 개요
- 스킬(skill)이 실제로 어떻게 패키징되는지, 즉 파일/폴더 구조를 다루는 강의.
- 스킬 = "특정 이름의 폴더 안에 정해진 방식으로 배치된 파일들의 묶음"임을 설명한다.

## 내용
### 스킬의 물리적 구조
- 스킬의 실체는 **폴더(folder)**다. 이 폴더를 zip으로 압축해 AI에게 주면, AI가 스킬에 접근할 수 있게 된다.
- 폴더 이름은 스킬 이름을 따른다. (예: 경비 보고서 스킬 → `expense-reports` 폴더)
- 폴더 내부에는 다음 네 가지 요소가 들어갈 수 있다.

### 1. SKILL.md — 핵심 지시문
- 스킬의 핵심(core instructions)을 담은 텍스트 파일.
- 앞서 다룬 "Word 문서에 적은 지시문"과 동일한 역할을 하지만, 매번 대화마다 업로드할 필요 없이 **AI가 항상 접근 가능한 형태로 등록해두는 것**이 SKILL.md의 차이점.
- 즉, Word 문서 = SKILL.md의 원형. SKILL.md는 그 매뉴얼(지시문)을 AI 에이전트가 상시 참조할 수 있게 만든 것.

### 2. scripts 폴더 — 도구/코드
- 필수는 아니지만, 에이전트가 문제 해결에 사용할 수 있는 **코드나 도구(tools)**를 패키징해서 넣을 수 있다.
- 즉 매뉴얼(SKILL.md) + 에이전트가 쓸 수 있는 도구(scripts)를 함께 제공하는 것.

### 3. references 폴더 — 추가 참고 자료
- SKILL.md 핵심 지시문에서 "만약 국제 출장이라면 references 폴더에 있는 국제 출장 경비 보고 가이드를 참고하라"는 식으로 **더 상세한 가이드나 매뉴얼로 연결(link)**할 수 있다.
- 즉, 특정 상황·맥락에서만 필요한 심화 정보를 별도로 분리해두는 공간.

### 4. assets 폴더 — 재사용 가능한 자료
- 매번 처음부터 다시 만들 필요 없는 **템플릿, 데이터, 부분적으로 완성된 결과물**을 담아둔다.
- 예: 여행 경비 대시보드가 매번 거의 동일한 구조라면, 완성에 가까운 대시보드 템플릿을 assets에 넣어두고 AI가 세부 내용만 채우게 할 수 있다.
- 템플릿, 데이터, 부분 완성 대시보드 등 다양한 형태가 가능.

## 예시
```
expense-reports/              ← 스킬 폴더 (스킬 이름과 동일)
├── SKILL.md                  ← 핵심 지시문 (매뉴얼 본체)
├── scripts/                  ← 에이전트가 쓸 도구/코드
├── references/               ← 추가 참고 자료 (예: 국제 출장 경비 가이드)
└── assets/                   ← 재사용 템플릿/데이터 (예: 대시보드 템플릿)
```

## 요약
- 스킬은 **폴더 하나**이며, 그 안에 SKILL.md(핵심 지시문) + scripts(도구) + references(추가 참고자료) + assets(재사용 템플릿/데이터) 4가지 요소로 구성될 수 있다.
- SKILL.md만으로도 스킬은 성립하지만, 나머지 3개 폴더를 추가하면 에이전트에게 더 풍부한 능력(도구), 더 깊은 맥락(참고자료), 더 빠른 시작점(재사용 자산)을 제공할 수 있다.
