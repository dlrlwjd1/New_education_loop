# Demonstration - Refining Prompts to Improve Agent Reasoning

## 개요
- 문제는 에이전트가 모호하거나, 일반적이거나, 실제 상황에 근거하지 않은 방식으로 답변한다는 점입니다 상황에 근거하지 않은 방식으로 답변을 내놓는다는 점입니다.

## 내용
- 문제는 에이전트가 모호하거나, 일반적이거나, 실제 상황에 근거하지 않은 방식으로 답변한다는 점입니다 상황에 근거하지 않은 방식으로 답변을 내놓는다는 점입니다.
- 이 역할은 초기 단계 SaaS 비즈니스 전략가로 바뀌며, 목표에는 이제 매우 구체적인 스타트업 상황, 즉 B2B SaaS 스타트업, 직원 3명, 매출 0, 제품 개발과 영업 중 어느 쪽을 선택할지 결정하는 것 등이 포함됩니다.
- 배경 이야기는 신뢰할 수 있는 전문성을 뒷받침하는 근거를 더해주며, 액셀러레이터를 통해 초기 단계의 스타트업을 멘토링하고 스타트업 패턴과 데이터에 기반한 증거 중심의 전략을 활용한다는 점이 포함됩니다.
- 에이전트의 역할은 동일하지만, 이제 목표는 에이전트가 권고안을 제시하기 전에 양측을 모두 고려하여 추론한 후 권고안을 제시해야 한다는 점이 명시적으로 요구됩니다.
- 이 질문은 모호하므로, 모델은 명확한 결정을 내리지 않은 채 ‘두 가지 모두 균형을 맞추라’거나 ‘시장을 검증하라’는 식의 포괄적인 조언으로 응답할 가능성이 높습니다.
- 그리고 기대되는 결과물은 초기 단계 스타트업 전략에 근거한 초기 단계 스타트업 전략에 근거한 근거를 제시해야 합니다.
- `run_version` 함수는 에이전트 1명과 작업 1개로 구성된 크루를 생성하고, 이를 순차적으로 실행하며, 어떤 버전이 실행 중인지와 해당 반복에서 무엇이 변경되었는지를 보여주는 간결한 헤더를 출력합니다 을 보여주는 깔끔한 헤더를 출력합니다.

## 예시
- 에이전트의 추론 능력을 향상시키기 위한 프롬프트 개선 방법에 대한 이 데모에 오신 것을 환영합니다.

## 요약
- 그리고 기대되는 결과물은 초기 단계 스타트업 전략에 근거한 초기 단계 스타트업 전략에 근거한 근거를 제시해야 합니다. `run_version` 함수는 에이전트 1명과 작업 1개로 구성된 크루를 생성하고, 이를 순차적으로 실행하며, 어떤 버전이 실행 중인지와 해당 반복에서 무엇이 변경되었는지를 보여주는 간결한 헤더를 출력합니다 을 보여주는 깔끔한 헤더를 출력합니다.
