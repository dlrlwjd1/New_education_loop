# Simulating Agents in ChatGPT — 대화로 에이전트를 빠르게 프로토타이핑하기

## 개요
- 에이전트 개발에서 **가장 어려운 부분은 코드 구현이 아니라 설계**(지시사항, 도구 집합, 정보가 돌아오는 형식)다. 이를 빠르게 반복(iterate)하는 가장 좋은 방법은 **ChatGPT 같은 도구와의 대화로 에이전트를 시뮬레이션**하는 것 — Agent Loop 자체가 본질적으로 "자동화된 대화"이기 때문에 거의 그대로 재현할 수 있다.

## 내용

### 시뮬레이션 설정 프롬프트
> "AI 에이전트를 시뮬레이션하고 싶다. GAME 프레임워크로 만들 건데 구성 요소는: **Goals** — 프로젝트의 모든 코드를 문서화한다. **Actions** — `list_files`, `read_file`(전체 경로 필요), `write_file`. 매 단계마다 출력은 반드시 취할 행동(action)이어야 하고, 멈춰서 기다려라. 내가 그 행동의 결과를 다음 메시지로 입력하겠다. 첫 번째 작업이 뭔지 물어봐줘."

- 이 프롬프트에서 **Goals**는 명시되어 있고, **Actions**도 명시되어 있으며, **Environment는 사용자 자신**이다 — 사용자가 "수동 실행 환경(human execution environment)"이 되어 결과를 입력해준다.
- 이 방식의 장점: **어떤 도구든 마음대로 상상해서 어떻게 동작할지 정의**할 수 있고, **에러를 임의로 주입**할 수도 있다.
- **Memory는 그냥 대화 자체**다.

### 실제 시뮬레이션 흐름과 설계 결함 발견
1. "문서화 작업을 진행해줘" → 에이전트: "list_files, 전체 경로(fully qualified path)" 요청.
2. 사용자가 일부러 "error, no path provided"라고 응답 → 에이전트가 아무 값이나 채워 넣고는 "프로젝트 디렉토리의 전체 경로를 알려달라"고 요청.
3. **→ 이는 설계 결함(design flaw)을 드러낸 것**: `list_files`/`read_file`/`write_file` 도구가 모두 전체 경로에 의존하는데, **시작 경로를 애초에 제공하지 않았다.**
   - 해결책 후보 1: 메모리에 전체 시작 경로를 주입.
   - 해결책 후보 2: **디렉토리를 조회할 수 있는 새 도구(GetProjectDirectory) 추가.**
4. 프롬프트를 수정해 `GetProjectDirectory` 도구를 추가 — **코드 한 줄도 짜지 않고, 프롬프트만 수정**해서 새 행동을 즉시 추가. 이후 사용자가 그 도구의 출력을 직접 시뮬레이션(예: 실제 경로 값 제공) → 그 경로 기반으로 `list_files` 실행 → 사용자가 파일 목록을 시뮬레이션으로 제공.
5. 에이전트가 `read_file` 실행 → 사용자가 "print hello world만 있다"고 시뮬레이션 → 에이전트가 `write_file` 실행.
6. **여기서 또 다른 설계 이슈 발견**: "프로젝트를 문서화하라"는 목표가 무엇을 의미하는지 명확히 정의하지 않아서, 에이전트가 **기존 파일을 덮어쓰고 주석을 추가**하기로 결정 — 목표(Goals)의 모호함이 원인.
   - 해결책 후보 1: 목표를 더 명시적으로 리팩터링.
   - 해결책 후보 2: 도구 설계를 바꿔서 이런 문제를 원천 차단 — 예: 기존 파일에 덮어쓰려고 하면 에러를 던지게 하거나, `create_doc(file_name)`처럼 문서화 대상 파일명을 명시적으로 전달받는 별도 도구로 만들어 **에이전트의 판단 재량을 줄이는 방향**으로 설계.

### 왜 이 방법이 강력한가
- 코드를 실행/컴파일하며 반복하는 것보다 **훨씬 빠르고 저렴하게** 설계 결함을 발견하고 수정할 수 있다.
- 다양한 시나리오(다른 프로그래밍 언어의 파일 읽기, 대화가 얼마나 길어질 수 있는지, 몇 개의 파일까지 견딜 수 있는지 등)를 자유롭게 실험해볼 수 있다.
- 실제 구현 전에 이 **저비용의 빠른 실험(rapid, cheap experimentation)**을 통해 목표/지시/행동/정보 형식이 적절한지 미리 검증하는 것이 좋다. (구현 후에도 추가 실험은 계속하게 되지만, 구현 전 단계에서 먼저 걸러내는 것이 효율적.)

## 요약
- 에이전트 설계를 검증하는 가장 빠른 방법은 **ChatGPT/Claude와의 대화에서 GAME 요소를 프롬프트로 명시하고, 사용자가 직접 Environment 역할을 하며 시뮬레이션**해보는 것.
- 이 과정에서 **도구 설계 결함**(경로 누락 등)이나 **목표의 모호함**(문서화의 의미가 불분명해 기존 파일을 덮어씀) 같은 문제를 코드를 짜기 전에 발견할 수 있다.
- 문제 발견 시 해결 방법은 대개 두 갈래: **목표/지시를 더 명확하게 다듬거나**, **도구 설계 자체를 바꿔 에이전트의 재량을 제한**하는 것.
