# AI Agent Feedback and Memory — Part 3: 메모리 갱신과 루프 종료 판단

## 개요
- "Building a Simple AI Agent" 시리즈의 마지막 Part 3. **16**.md)~**17**.md)에서 다룬 프롬프트 구성/파싱/실행에 이어, **행동 결과를 메모리에 반영하고 루프를 계속할지 종료할지 판단**하는 마지막 두 단계를 다룬다.

## 내용

### Step 5 — 에이전트 메모리 갱신
- 행동을 실행한 뒤, 에이전트는 그 결과를 메모리에 갱신한다. 메모리는 사용자 요청·수행된 행동·그 결과를 포함해 **상호작용 동안 일어난 모든 일의 기록**이다. 이 정보를 메모리에 계속 추가함으로써 에이전트는 맥락을 유지하고 다음 반복에서 더 informed된 결정을 내릴 수 있다.

```python
memory.extend([
    {"role": "assistant", "content": response},
    {"role": "user", "content": json.dumps(result)}
])
```

- **assistant 역할**: LLM이 생성한 구조화된 응답(에이전트의 "의도")을 담음.
- **user 역할**: 행동 실행 결과(피드백)를 담음 — **행동의 결과는 항상 "user" 역할로 LLM에게 전달**된다. 이렇게 해야 LLM이 행동 수행 후 무슨 일이 일어났는지 명확히 이해할 수 있다.
- 이렇게 교환 기록을 계속 쌓아가면, 메모리가 커질수록 에이전트가 자신의 행동을 동적으로 다듬고 작업 상태를 추적할 수 있는 연속성이 유지된다.

### Step 6 — 계속할지 결정하기
- 루프의 각 반복에서 마지막 단계는 **계속할지 종료할지 결정**하는 것. 실행된 행동과 현재 작업 상태를 근거로 판단한다.
- 파싱된 행동이 `terminate`를 지정하거나, 사전 정의된 조건(예: 최대 반복 횟수)이 충족되면 루프를 종료한다.

```python
if action["tool_name"] == "terminate":
    print(action["args"]["message"])
    break
```

- 종료가 지정되면 루프를 빠져나오고, `terminate` 행동의 인자에 정의된 마무리 메시지를 출력한다. 종료 조건이 아니면 다음 사용자 요청 처리나 작업 계속으로 루프백한다.

### 예시 — 반복적 적응(Iterative Adaptation)
- 에이전트가 파일을 읽어야 하는데 처음 요청에 파일명이 빠져있는 상황을 가정:
  1. 첫 반복에서 `list_files`를 실행해 사용 가능한 파일 목록을 가져옴.
  2. 이 결과를 메모리로 기억한 뒤, 사용자에게 특정 파일을 선택하라고 요청하는 방향으로 다음 행동을 조정.
  3. 작업이 완료되거나 더 이상 행동이 필요 없다고 판단할 때까지 이 과정을 반복.
- 매 반복마다 에이전트는 **메모리를 되돌아보며 전체 작업이 끝났는지 판단**할 수 있다. 메모리는 "계속할지 종료할지" 결정의 핵심 근거다.
- 종료 조건은 명시적으로 지시할 수도 있다 — 예: "에러가 2번 넘게 발생하면 종료해라" 같은 특정 조건.

## 요약
- Part 3은 Agent Loop의 5~6단계를 다룬다: **결과를 assistant/user 메시지 쌍으로 메모리에 누적** → **terminate 행동이나 종료 조건 충족 여부로 루프 지속/종료를 판단**.
- 행동 결과는 항상 "user" 역할로 LLM에 피드백된다는 점, 그리고 메모리가 곧 "계속 vs 종료" 판단의 근거가 된다는 점이 핵심.
- **16**.md)~**18**.md) 세 파트를 합치면 완전한 Agent Loop(프롬프트 구성 → 응답 생성 → 파싱 → 실행 → 메모리 갱신 → 종료 판단)의 실제 Python 구현이 완성된다.
