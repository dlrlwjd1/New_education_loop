# Practicing Programmatic Prompting for Agents — 준(準)에이전트(Quasi-Agent) 만들기

## 개요
- 지금까지 배운 프로그래밍적 프롬프팅 + 메모리 관리를 활용해, 사용자 요구에 맞는 **Python 함수를 작성해주는 "준(準)에이전트(quasi-agent)"**를 직접 만들어보는 실습 과제.
- "준(準)에이전트"라고 부르는 이유: 실제 에이전트처럼 상황에 반응(react)하고 적응(adapt)하지는 못하지만, 그래도 유용한 작업을 수행하기 때문.
- 목적: **여러 프롬프트에 걸쳐 맥락(context)을 유지하는 법**, **사용자와 LLM 사이의 정보 흐름을 관리하는 법**을 익히고, LLM 출력이 항상 일관되지 않아 파싱/처리하기 까다롭다는 점을 직접 체감하는 것.

## 내용

### 사전 준비
```bash
pip install litellm
```
- 사용할 LLM 제공자의 API 키를 환경 변수로 설정해둘 것 (OpenAI API 키 발급 방법은 [05](05%20Running%20the%20Code%20Samples%20in%20the%20Course.md) 참고).

### 실습 과제 사양 — 3단계 순차 프롬프트
1. **첫 번째 프롬프트**
   - 사용자에게 어떤 함수를 만들고 싶은지 질문
   - 그 설명을 바탕으로 LLM에게 기본적인 Python 함수 작성을 요청
   - 응답을 다음 프롬프트에서 쓸 수 있도록 저장
   - 응답에서 **코드와 LLM의 설명(commentary)을 분리(parse)**
2. **두 번째 프롬프트**
   - 1단계에서 생성된 코드를 전달
   - LLM에게 다음을 포함한 포괄적인 문서화(documentation)를 요청:
     - 함수 설명, 파라미터 설명, 반환값 설명, 사용 예시, 엣지 케이스
3. **세 번째 프롬프트**
   - 2단계에서 문서화된 코드를 전달
   - `unittest` 프레임워크를 사용한 테스트 케이스 추가 요청
   - 테스트는 다음을 커버: 기본 기능, 엣지 케이스, 에러 케이스, 다양한 입력 시나리오

### 요구사항
- LiteLLM 라이브러리 사용
- 프롬프트 간 **대화 맥락(conversation context) 유지** — [12 Giving Agents Memory](12%20Giving%20Agents%20Memory.md)에서 배운 대로 assistant 메시지로 이전 응답을 누적
- 개발 과정의 각 단계를 출력(print)
- 최종 버전을 Python 파일로 저장

### 추가 연습 (선택)
- system 메시지를 이용해 LLM이 항상 특정 스타일(예: 함수형 프로그래밍)이나 특정 라이브러리를 사용하도록 강제해보기.

## 요약
- 이 실습은 [06~09](06%20Programmatic%20Prompting%20for%20Agents.md)의 프로그래밍적 프롬프팅과 [12](12%20Giving%20Agents%20Memory.md)의 메모리 관리를 결합해, **작성 → 문서화 → 테스트 추가**의 3단계 파이프라인을 직접 구현해보는 과제.
- 핵심 학습 포인트: (1) 여러 프롬프트에 걸친 맥락 유지, (2) LLM 응답에서 코드/설명을 안정적으로 분리하는 파싱의 어려움 체감.
