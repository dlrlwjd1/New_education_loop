# Tool Descriptions and Naming — 도구 이름/설명이 에이전트 성능을 좌우한다

## 개요
- 도구가 "냄비", "팬"처럼 누구나 아는 개념이면 생성형 AI가 직관적으로 이해하지만, **우리가 만든 커스텀 컴퓨터 시스템의 도구**는 이름만으로는 무엇을 하는지 전혀 알 수 없다.
- 이 영상은 **도구의 이름(naming)과 설명(description)이 에이전트 성능을 얼마나 크게 좌우하는지**를 "외계 우주선 탈출" 예시로 보여준다.

## 내용

### 문제 제기
- 컴퓨터 시스템끼리도 같은 이름의 도구/함수가 완전히 다른 의미를 가질 수 있다 — 우리가 만든 커스텀 소프트웨어 도구들은 사실상 "외계의 도구"와 같아서, **그 능력(capability)을 명확하게 설명**해줘야 한다.

### 예시 — 외계 우주선 탈출 (설명 포함 버전)
- 도구 목록: `X155 tool - 외계인 피자를 준비한다`, `Q63 tool - 설정 가능한 목적지로 이어지는 차원 포털을 연다`, `l199 tool - 우주선에서 비틀즈 음악을 반복 재생시킨다`
- 이름 자체(X155, Q63, l199)는 아무 의미가 없지만, **하이픈 뒤 설명**이 핵심 정보를 제공한다.
- 결과: "1단계, X155 도구로 외계인 피자를 준비해서 외계인들의 주의를 분산시켜라" → "2단계, Q63으로 차원 포털을 열어 탈출로로 삼아라" → "3단계, l199로 비틀즈 음악을 틀어 추가로 주의를 분산시켜라."
- → **한 번도 들어본 적 없는 도구라도, 설명만 정확히 주면 에이전트가 올바르게 활용**한다. 이름이 이상해도 설명이 있으면 문제없다.

### 도구 이름(Naming)의 중요성
- 좋은 이름 하나만으로도 도구를 더 효과적으로 사용하게 만들 수 있다. 위 도구들을 `makeAlienPizza`, `openDimensionalPortal`, `playBeatlesMusic`로 이름만 바꾸자 — 설명 없이도 똑같이 잘 작동했다 (첫 단계로 "make alien pizza"를 정확히 선택).
- 반대로 이름을 **약어(abbreviation)**로 바꾸고 설명도 없앤 경우 (`mkpz`, `odprtl`, `pbm`) — 완전히 다른 결과가 나왔다:
  - `mkpz`를 "외계 우주선의 지도를 상세히 만드는 도구"로 오해.
  - `odprtl`을 "우주선 내 다른 곳으로 이동하게 해주는 포털"로 오해 (원래 목적: 어디로든 갈 수 있는 차원 이동).
  - → **사람은 약어에 대한 "제도적 지식(institutional knowledge)"이 있어서 스스로 풀어낼 수 있지만, LLM은 그런 배경지식이 없을 수 있다.**
- 결론: **이름(naming)만 바꿔도 시스템이 완전히 다르게(더 좋게 또는 더 나쁘게) 동작할 수 있다.** 많은 사람들이 "생성형 AI가 형편없다"고 불평하지만, 실제로는 도구 이름과 설명, 맥락 정보를 조금만 조정하면 해결되는 경우가 많다.

### 도구 조합/제시 방식(맥락)의 중요성
- 이름을 명확하게(`pliers`, `scooter`, `escape hatch`) 바꾼 경우에도, **어떤 도구를 왜 쓰는지에 대한 맥락 정보가 없으면 잘못된 추론**을 할 수 있다.
- 예: 탈출 해치(escape hatch)를 찾아야 하는 상황에서, 렌치(pliers)가 있다는 것만으로 "볼트/나사를 풀기 위해 사용해야 한다"고 지레짐작 — 실제로 볼트/나사가 있다고 말한 적이 없는데도.
- 고려해야 할 것들:
  - 도구를 **모두 사용해야 하는지, 일부만 선택적으로 사용해도 되는지**
  - 도구의 **제시 순서**, 함께 주어지는 **언어적 맥락**
  - 어떤 도구가 **왜/언제** 필요한지에 대한 부가 설명

## 예시
> **설명 없이 이름만 좋은 경우 (성공)**
> Tools: `makeAlienPizza`, `openDimensionalPortal`, `playBeatlesMusic`
> → 1단계: "Use makeAlienPizza to distract the aliens." (의도대로 동작)

> **약어 + 설명 없음 (실패)**
> Tools: `mkpz`, `odprtl`, `pbm`
> → 1단계: "Use mkpz to create a detailed map of the ship's layout." (완전히 다른 의미로 오해)

## 요약
- **도구의 이름과 설명은 에이전트 성능을 좌우하는 핵심 요소** — 이름이 이상해도 좋은 설명이 있으면 문제없지만, 설명 없이 약어만 주면 LLM이 잘못 추론할 위험이 크다.
- 가능하면 **이름 자체를 풍부하고 설명적으로** 짓고, 여기에 더해 좋은 설명까지 곁들이는 것이 이상적.
- 도구를 나열할 때는 이름/설명뿐 아니라 **어떤 도구를 언제/왜 쓰는지, 전부 써야 하는지 선택적인지**까지 맥락으로 제공해야 에이전트가 엉뚱한 추론을 하지 않는다.
- 이는 [01 GAIL](01%20GAIL%20-%20Goals%2C%20Actions%2C%20Information%2C%20Language.md)의 "Actions" 요소를 실제로 잘 설계하는 방법에 해당한다.
