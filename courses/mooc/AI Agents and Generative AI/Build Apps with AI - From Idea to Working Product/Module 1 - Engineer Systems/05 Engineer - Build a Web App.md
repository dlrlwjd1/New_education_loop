# Engineer - Build a Web App

## 개요
- Module 1의 첫 실습 — **"웹 앱(web app)"**이라는 핵심 용어와, 웹 앱을 만들 때 쓰는 최소한의 프롬프트 공식을 실제로 시연하는 강의.

## 내용
### "웹 앱(web app)"이란
- 브라우저에서 열 수 있는 것 — 온라인 SaaS(Software as a Service)에 접속하는 것과 비슷한 경험을 주는 결과물.

### 실전 시연 — 강좌 영상들로 나만의 학습관리시스템(LMS) 만들기
- 이 강좌의 모든 영상을 폴더에 모아두고, 그 폴더를 기반으로 학습관리시스템(LMS)을 만들어달라고 요청.
- 프롬프트:
  > "이 강좌를 위한 간단한 웹 애플리케이션을 만들어줘. 모든 레슨과 관련 영상을 보여줘야 해. Node를 사용해줘. 완료되면 실행해서 브라우저로 열어줘."
- 폴더 안에는 이미 콘텐츠와 구조가 있었기 때문에, AI가 그것을 보고 스스로 무엇을 만들어야 하는지 파악할 수 있었음.

### 프롬프트 공식 — 기억해야 할 핵심 문구 3가지
1. **"Build me a (simple) web application that [원하는 기능]"**
   - "simple"을 붙이는 이유: 너무 앞서 나가지 않게 하기 위해 — 다만 이번 사례에서는 오히려 매우 앞서 나가며 훌륭한 결과가 나왔다고 언급.
   - 프롬프트 자체는 짧아도 괜찮다 — 폴더 안에 **충분한 콘텐츠와 구조**가 있으면 AI가 그것으로 무엇을 만들지 판단할 근거가 된다.
2. **"Use Node"** (또는 "Build me a Node.js web application")
   - Python 등 다른 언어를 쓸 수도 있지만, 저자는 **Node를 강력히 추천** — 대부분의 컴퓨터에 설치·실행이 쉽기 때문.
   - Magic 설치 시 Node 설치 옵션을 선택했다면 추가 설정이 필요 없음. 다른 도구를 쓰거나 Node를 설치하지 않았다면 추가 단계가 필요(별도 읽기 자료 참고).
   - "Use Node"는 **AI가 컴퓨터에 접근하는 인터페이스**로 이해하면 된다.
3. **"When you're done, start it and open it in my browser."**
   - 이 문구가 없으면 AI가 "다 만들었어요"라고만 말하고 끝나서, 사용자가 "그래서 이제 뭘 해야 하지?"라고 막막해질 수 있다.
   - 이 문구를 추가하면 AI가 직접 실행해서 브라우저로 열어주기 때문에 훨씬 흥미롭고 재미있는 경험이 된다.
   - 부가 효과: 실행 중 문제가 있으면 **AI가 스스로 알아채고 고칠 가능성**이 높아진다.

### 결과
- AI가 폴더의 모든 강의를 발견하고, 그 구조를 바탕으로 계획과 요구사항을 스스로 세운 뒤 완성된 LMS를 만들어 브라우저에 열어줌.
- 결과물: 모든 강의 항목 클릭 가능, 영상 재생, 아래에 노트와 실습 내용까지 포함된 완전한 학습관리시스템 — **단 하나의 프롬프트**로 완성.

## 예시
```
프롬프트 공식:
"Build me a (simple) web application that [원하는 기능].
Use Node. When you're done, start it and open it in my browser."
```

## 요약
- "웹 앱을 만들어줘"라는 프롬프트에 **"Use Node"**와 **"완료되면 실행해서 브라우저로 열어줘"**라는 두 문구만 더하면, 비기술자도 완전한 웹 애플리케이션을 한 번의 프롬프트로 만들 수 있다.
- 프롬프트 자체는 짧아도 되며, 대신 **참고할 콘텐츠/폴더 구조**가 충분하면 AI가 알아서 좋은 결과를 만들어낸다.
- 이 세 가지 문구(웹 앱 요청 + Node 사용 + 실행 후 브라우저 열기)가 앞으로 웹 앱을 만드는 데 필요한 **기본 공식**이다.
