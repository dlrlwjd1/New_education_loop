# The Best of N Pattern

## 개요
- 소프트웨어 개발에서 가장 흔한 실수 — **"잘못된 것을 만드는 것"**을 방지하는 강력한 기법, **"Best of N 패턴"**을 다루는 강의.

## 내용
### 소프트웨어의 가장 흔한 실수 — "잘못된 것을 만드는 것"
- 팀/개인이 문제를 안다고 생각하고 설계해서 만들었는데, 막상 문제를 제대로 해결하지 못하는 경우가 매우 흔하다.
- 우리가 싫어하는 소프트웨어 대부분이 바로 이런 "뭔가 딱 맞지 않는 것"이다.

### 핵심 기법 — "여러 버전을 만들어서 다 써보고, 그중 최고를 고르는 것"
- AI를 쓸 때 가장 중요한 것 중 하나는, **하나의 아이디어에 대해 여러 다른 버전을 만들게 하고, 직접 다 써본 뒤 최선의 것을 고르는 것**이다.
- 단순하지만 엄청나게 강력한 기법.

### 실전 예시 1 — 목업(mockup)으로 빠르게 여러 안 비교하기
- 상황: 만들어둔 LMS(학습관리시스템)에 게이미피케이션(순위표 등) 기능을 추가하고 싶어짐.
- 프롬프트: "게이미피케이션을 추가하고 싶어. 목(mock) 데이터를 사용해서 흥미로운 점수판이 어떤 모습일지 3가지 목업을 웹 앱 안에 만들어줘. 서로 시각적으로 매우 다르게 만들되, 원래 앱의 테마에는 맞아야 해. 각각을 열어서 보여줘."
- 핵심 키워드 — **"mock(목/가짜)"**: 완전한 코드를 짤 필요 없이, **체험해보고 느낌을 확인할 수 있는 정도의 간단한 프로토타입**만 만들어달라는 뜻. "일단 시도해보는 것"이 목적이므로 완성도 높은 구현은 필요 없다.
- 결과: 서로 다른 3가지 버전의 리더보드가 생성됨 → 살펴본 뒤 "다 마음에 안 든다"고 판단해 **모두 버릴 수도 있음.**
- 핵심 통찰: **가벼운 프로토타입(mock)으로 여러 버전을 만들면, 토큰과 시간을 크게 들이지 않고도 "이 아이디어가 별로다" 또는 "이건 정말 마음에 든다"를 빠르게 판단**할 수 있다.
- 마음에 드는 버전을 찾으면: "이 하이스코어 버전이 마음에 들어. 목 데이터 없이 실제로 동작하게 완전히 구현해줘"라고 후속 요청.

### 실전 예시 2 — 별도의 대화로 완전히 독립적인 여러 버전 만들기
- 때로는 하나의 대화 안에서 하지 않고, **각각 별도의 새 대화(task)**로 진행하는 것이 유용하다 — 코드가 있는 동일한 폴더를 주고, 각 대화에서 완전히 독립적으로 접근하게 함.
- 사례 — 신용카드 명세서 12개월치로 재무 대시보드 만들기, **3개의 완전히 다른 대화**에서 각기 다른 관점으로 요청:
  1. "이 12개월치 신용카드 명세서를 읽고, 모든 카테고리·트렌드·이상치를 담은 포괄적인 재무 대시보드를 만들어줘." → 종합 대시보드 버전.
  2. (새 대화, 같은 폴더) "80-20 버전을 줘 — 내 행동을 바꾸는 데 실제로 필요한 딱 3개의 숫자만." → 핵심만 담은 미니멀 버전.
  3. (새 대화, 같은 폴더) "네가 재무 상담사라고 생각하고, 고객에게 보내는 한 페이지짜리 메모를 써줘. 스프레드시트가 아니라 조언처럼 느껴지게 만들어줘." → 재무 상담사 스타일 메모 버전.
- 핵심: 같은 데이터로 **완전히 다른 표현 방식(매우 구체적으로 지시 vs. 결과 지향적으로 지시)**을 시도하며 어떤 접근이 더 좋을지 실험할 수 있다.

### 왜 이 패턴이 강력한가 — "빠르고 저렴하게 시도해볼 수 있다"
- 핵심 통찰: 무언가를 만드는 것이 **너무 빠르고 저렴(cheap)**해졌기 때문에, 특정 기능을 실제로 도입하기 전에 **여러 버전을 만들어 다 써보고 마음에 드는 것을 고르거나, 여러 버전에서 마음에 드는 부분들을 조합**하는 것이 가능해졌다.
- 이것이 **"AI CS PhD"를 활용하는 가장 효과적이고 놀라운 방법 중 하나**다.

## 예시
```
1) 같은 대화 안에서 목업 여러 개:
"Create three mock-ups in the web app using mock data of what an exciting scoreboard could look like.
I want each to be visually very different, but fit the original theme of the application.
Then open each of them for me."

2) 마음에 든 버전을 실제 구현으로 전환:
"I really like this high scores version. Can you complete the implementation of it so it doesn't use mock data?"

3) 별도 대화로 완전히 다른 접근 실험:
대화 A: "...comprehensive financial dashboard, every category, trend and anomaly."
대화 B: "...give me the 80-20 version, just the three numbers I actually need to change my behavior."
대화 C: "...pretend you're a financial advisor writing a one page memo to your client."
```

## 요약
- 소프트웨어의 가장 흔한 실수는 "잘못된 것을 만드는 것"이며, 이를 막는 강력한 방법은 **여러 버전을 만들어보고 최선을 고르는 "Best of N" 패턴**이다.
- **"mock" 데이터/목업**을 활용하면 완성도 높은 구현 없이도 빠르고 저렴하게 여러 아이디어를 체험하고 비교할 수 있다.
- 각기 다른 **별도의 대화**에서 같은 데이터에 다른 접근(구체적 지시 vs. 결과 지향적 지시)을 시도하면, 어떤 표현/관점이 더 나은 결과를 내는지 실험할 수 있다.
- 무언가를 만드는 비용이 매우 낮아졌다는 것을 활용해, **커밋하기 전에 여러 버전을 실험하고 조합하는 것**이 AI 시대의 새로운 개발 방식이다.
