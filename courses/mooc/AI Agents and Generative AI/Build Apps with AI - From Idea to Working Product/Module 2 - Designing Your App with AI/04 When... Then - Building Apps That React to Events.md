# When… Then: Building Apps That React to Events

## 개요
- 요구사항에 **"타이밍(timing)"**을 추가하는 방법 — **"When(언제) ... Then(그러면)"** 패턴으로 자동화(automation) 요구사항을 명시하는 법을 다루며, 그 과정에서 주의해야 할 위험(무한 루프 등)도 함께 짚는 강의.

## 내용
### When... Then 패턴이란
- 자동화(automation)란 본질적으로 **"이 일이 일어나면, 저 일이 자동으로 일어난다"**는 것.
- 패턴의 핵심 구조: **When(트리거 — 시간, 새 파일 추가, 새 행 추가 등 특정 이벤트) → Then(그 결과로 일어나야 할 일)**.

### 실전 예시 1 — 폴더 감시로 대시보드 자동 갱신
- 상황: 리포트 폴더를 읽는 대시보드가 있는데, 지금은 수동으로 새로고침해야 함.
- 요청: "폴더에 새 파일이 추가될 때마다 자동으로 업데이트되게 해줘." (명시적으로 "when/then" 어투는 아니지만 본질은 동일 — "새 파일 추가"가 트리거, "자동 업데이트"가 결과)

### 중요한 주의사항 1 — "이벤트를 감지하려면 프로그램이 계속 실행 중이어야 한다"
- 이벤트에 반응하는 무언가를 만들면, 그 이벤트가 발생할 때 **그것을 감지할 프로그램이 계속 실행되고 있어야** 한다.
- 그래서 이 패턴은 **웹 앱처럼 계속 켜져서 폴더나 시간을 지켜보는 것**에 잘 맞고, **한 번 실행하고 곧 끝나버리는 프로그램**에는 잘 맞지 않는다.
- 실행 중이 아니면 이벤트를 관찰할 수 없다는 점을 반드시 기억해야 한다.

### 중요한 주의사항 2 — "끄는 법을 모른 채 계속 돌아가게 만들지 마라"
- 뭔가를 계속 실행되게 만들었다면, **어떻게 멈출지도 함께 알아둬야** 한다. 특히 이벤트에 반응하는 프로그램일수록 더욱 그렇다.

### 중요한 주의사항 3 — "무한 루프(infinite loop)를 조심하라"
- 위험 시나리오: "이 폴더에 새 파일이 추가되면, 이런 새 파일을 만들어서 (같은 폴더에) 추가해줘"라고 요청하면?
- 트리거 발생 → 새 파일을 같은 폴더에 추가 → 그 파일 추가가 다시 트리거를 발동 → 또 새 파일 추가 → ... **무한 루프**에 빠진다.
- **안전한 패턴**: "여기서 이벤트를 읽고, 다른 곳에 결과를 쓰는 것"은 안전 (예: A 폴더의 변화를 감지해서 B 폴더에 결과를 쓰는 것).
- **위험한 패턴**: 이벤트가 발생한 바로 그 장소에 다시 결과를 쓰는 것 (자기 자신을 다시 트리거하게 됨).

### 실전 예시 2 — 주문 스프레드시트 변경 시 재고/요약 자동 업데이트 (안전한 패턴)
- 요청: "주문 스프레드시트에 새 행이 추가될 때마다, inventory.xlsx와 요약 보고서가 자동으로 업데이트되어야 해. 지금은 수동으로 하고 있어."
- 이는 **"여기(주문 스프레드시트)의 이벤트를 읽고, 저기(재고/요약 파일)에 쓰는"** 안전한 패턴 — 같은 파일에 다시 쓰지 않으므로 루프 위험이 없음.

## 예시
```
1) 안전한 패턴 (다른 곳에 쓰기):
"Whenever a new row is added to this spreadsheet, update inventory.xlsx and the summary report automatically."

2) 위험한 패턴 (같은 곳에 다시 쓰기 — 피해야 함):
"Whenever a new file is added to this folder, create a new file and add it back to this same folder."
→ 무한 루프 위험
```

## 요약
- **When... Then 패턴**은 요구사항에 타이밍(자동화 트리거와 반응)을 명시하는 방법이며, 자동화를 구현할 때 핵심적으로 쓰인다.
- 이벤트에 반응하는 프로그램은 **계속 실행 중이어야 하며(웹 앱 등에 적합)**, 어떻게 중지시킬지도 알아둬야 한다.
- 가장 큰 위험은 **무한 루프** — 이벤트가 발생한 바로 그 위치에 다시 결과를 쓰면 스스로를 계속 트리거하게 되므로, **이벤트를 읽는 곳과 결과를 쓰는 곳을 분리**하는 것이 안전하다.
