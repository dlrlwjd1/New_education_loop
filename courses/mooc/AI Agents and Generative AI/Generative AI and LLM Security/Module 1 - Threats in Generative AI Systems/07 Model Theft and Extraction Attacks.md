# Model Theft and Extraction Attacks

## 개요

- 모델 탈취(model theft) 또는 모델 추출 공격(model extraction attack)은 공격자가 머신러닝 모델을 무단으로 복제하는 것이다.
- 생성형 AI 모델은 수백만 달러의 자원으로 훈련되는 귀중한 지적 재산(intellectual property)이며, 민감한 데이터처럼 탈취되거나 복제될 수 있다.
- 공격 방식(블랙박스·화이트박스), 4단계 추출 과정, 실제 사례, 결과, 그리고 기본·고급 방어책을 다룬다.

## 내용

### 모델 탈취의 정의

- 모델 탈취(model extraction attack)는 공격자가 머신러닝 모델을 무단으로 복제할 때 발생한다.
- 예를 들어 한 회사가 텍스트 생성이나 사기 탐지(fraud detection) 서비스처럼 API를 통해 AI 모델을 노출하면, 공격자는 모델을 반복 질의(query)해 근접 복제본을 재구성할 만큼의 입력-출력 데이터를 수집한다.
- 탈취된 모델은 라이선스 비용을 우회한 무료 접근이나 악성 애플리케이션 구동에 악용될 수 있다. 최종 제품이 아니라 그 안의 지능(intelligence)을 훔친다는 점에서 불법 복제 소프트웨어와 유사하다.

### 두 가지 추출 형태: 블랙박스 vs 화이트박스

- **블랙박스 공격(black box attack)**: 공격자가 오직 API를 통해서만 모델과 상호작용한다. 연구자들은 수천 건의 질의만으로 내부 코드를 전혀 보지 않고도 텍스트 분류기(text classifier)를 원본 정확도의 거의 90%로 복제할 수 있음을 보였다. 밖에서 시스템을 테스트하며 동작을 학습하는 방식이다.
- **화이트박스 공격(white box attack)**: 공격자가 내부 접근 권한을 가진다. 내부자가 모델 가중치(weights)를 다운로드하거나, 클라우드 설정 오류(misconfiguration)로 모델 파일이 노출되는 경우다. 아키텍처와 파라미터가 보이므로 복제가 사소한 일이 된다. 내부자 지식을 갖고 곧장 걸어 들어가는 격이다.

### 모델 추출의 4단계

- **대상 모델 질의(querying the target model)**: 공격자가 체계적으로 API 질의를 만든다. 2020년 연구자들은 Google Vision API에 반복 질의해 이미지 분류기를 재구성할 수 있음을 보였다.
- **데이터 수집(data collection)**: 수천에서 수백만 개의 입력-출력 쌍을 기록한다. 이것이 곧 준비된 훈련 데이터셋이 된다.
- **대리 모델 훈련(training a surrogate model)**: 이 데이터셋으로 자신의 복제본을 훈련하며, 종종 대상의 결정을 높은 충실도(fidelity)로 모방한다.
- **효율성·효과성 점검(efficiency and effectiveness checks)**: 마지막으로 대리 모델이 원본 대비 얼마나 잘 작동하는지 측정하고 필요에 따라 다듬는다.
- 원본 자물쇠의 메커니즘을 복제할 때까지 열쇠를 테스트해 위조 자물쇠를 만드는 것과 같다.

### 모델 탈취의 결과

- **지적 재산 손실(intellectual property loss)**: 가장 직접적이고 큰 영향. 독창적이고 강력한 모델에 기반한 경쟁 우위가 즉시 무력화될 수 있다.
- **전략적 영향(strategic impact)**: 공격자가 탈취한 모델로 경쟁 서비스를 출시해 원 제공자의 가격을 무너뜨리고 상당한 매출 손실을 초래한다. 또한 원 모델의 라이선스나 이용 약관을 위반하는 서비스에 쓰일 수 있다.
- **보안 침해(security breaches)**: 탈취된 모델은 추가 적대적 공격의 시험대(testbed)가 된다. 공격자가 로컬 복제본을 탐색해 취약점이나 적대적 예제(adversarial examples)를 찾은 뒤, 이를 더 안전한 온라인 원본 모델로 전이(transfer)할 수 있다.
- **윤리·법적 우려(ethical and legal concerns)**: 원 모델이 민감하거나 저작권이 있는 데이터로 훈련되었다면, 추출된 모델이 그 정보를 담거나 재현해 개인정보 침해와 법적 결과로 이어질 수 있다.
- 요컨대 단지 모델을 잃는 것이 아니라 신뢰·매출·보안을 잃는 것이다.

### 기본 방어책

- **API 속도 제한(API rate-limiting)**: 질의 수를 제한해 대규모 탐색을 어렵게 만든다.
- **질의 모니터링(query monitoring)**: 모델을 역설계하려는 반복 질의 같은 비정상 패턴을 탐지한다.
- **사용자 인증(user authentication)**: 검증된 사용자만 모델에 접근하게 해 익명 공격 노출을 줄인다.
- 이 방어책들은 시설 주변의 보안 카메라와 검문소처럼 작동해 가벼운 공격자를 저지하고 집요한 공격자를 늦춘다.

### 고급 방어 기법

- **출력 교란(output perturbation)**: API가 출력에 통제된 노이즈를 더해 공격자는 모델을 완벽히 재구성하지 못하게 하면서도 실제 사용자에게는 정확한 결과를 제공한다.
- **모델 워터마킹(model watermarking)**: Fiddler AI, DeepMind 같은 곳이 출력에 보이지 않는 패턴을 심는 방법을 탐구해 왔다. 이는 디지털 지문(fingerprint)처럼 작동해 복제본이 나타나면 추적할 수 있다.
- **정기 보안 감사(regular security audits)**: 지속적인 침투 테스트(penetration test)와 레드팀 훈련으로 공격자보다 앞선다. 금융 감사가 사기를 밝혀내는 것과 유사하다.
- 이 고급 기법들은 탈취를 막을 뿐 아니라 소유권을 입증하고 복제 시 대응할 수단을 제공한다.

## 예시

- 블랙박스 추출 사례: 수천 건의 API 질의만으로 텍스트 분류기를 원본 정확도의 약 90%로 복제.
- 2020년 사례: Google Vision API에 반복 질의해 이미지 분류기를 재구성.

## 요약

- 모델 탈취·추출 공격은 오늘날 AI 시스템에 대한 가장 심각한 위협 중 하나로, 블랙박스 탐색 또는 내부자 기반 화이트박스 접근으로 일어난다.
- 위험은 IP 손실과 불공정 경쟁에서 컴플라이언스 위반까지 이른다.
- 추출은 질의 → 데이터 수집 → 대리 모델 훈련 → 성능 점검의 4단계를 따른다.
- 속도 제한, 모니터링, 인증, 출력 교란, 워터마킹, 감사를 겹겹이 쌓는 계층적 방어(layered defenses)로 AI 투자를 보호하고 신뢰를 유지할 수 있다.
