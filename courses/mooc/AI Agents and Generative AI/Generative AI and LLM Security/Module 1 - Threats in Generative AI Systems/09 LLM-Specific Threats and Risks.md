# LLM-Specific Threats and Risks

## 개요

- 대규모 언어 모델(LLM, large language model)은 강력하지만, 잘못 구성되면 공격자에게 열린 문이 되는 클라우드 서버 클러스터처럼 고유한 취약점을 동반한다.
- 프롬프트 기반 공격, 데이터·모델 위협, 인프라 위협, 공급망·지적 재산 위험 등 LLM 특유의 위협을 범주별로 살펴본다.
- 네트워크 보안의 방화벽(firewall)처럼, 보안 인식은 유해한 트래픽만 걸러내며 활용을 막지 않는다.

## 내용

### LLM 위협의 개요

- **프롬프트 인젝션(prompt injections)**: 악성 지시로 모델을 조작한다.
- **데이터 오염(data poisoning)**: 훈련 데이터를 오염시킨다.
- **오용(misuse)**: 편향적·공격적·부정확한 출력을 유발한다.
- 유용한 앱과 위장한 멀웨어가 공존하는 모바일 앱스토어처럼, LLM도 유용하지만 주의 깊게 감시하지 않으면 조작·악용될 수 있다.

### 프롬프트 기반 공격

- **컨텍스트 인젝션(context injection)**: 입력에 악성 콘텐츠를 몰래 넣는다. 예를 들어 사용자 질의에 숨은 지시를 삽입해 모델이 원래 작업을 무시하게 한다.
- **모델 익스플로잇(model exploits)**: 프롬프트가 전달·처리되는 방식의 결함을 찾아 시스템 동작을 조작한다.
- **권한 상승(privilege escalation)**: 프롬프트로 숨겨진 기능, 관리 기능, 제한된 데이터셋에 접근한다.
- **악성 지시(malicious instructions)**: 안전장치를 덮어쓰는 지시를 심어 개인 정보를 드러내거나 의도치 않은 작업을 하게 만든다.
- 이는 데이터베이스의 SQL 인젝션 공격과 매우 유사하다. 악성 SQL 명령 대신 정교하게 만든 자연어로 모델을 침해한다.

### 데이터와 모델 위험

- **회피 공격(evasion attacks)**: 모델 방어를 통과하도록 설계된 적대적 입력을 만든다. 예를 들어 악성 코드를 살짝 변형해 AI 멀웨어 탐지기가 안전하다고 분류하게 한다.
- **데이터 오염(data poisoning)**: 오염되거나 오도하는 샘플을 훈련 데이터에 삽입한다. 사기 탐지 모델이 사기 거래를 잘못 승인하게 만들 수 있다.
- **모델 백도어(model backdoors)**: 훈련 중 숨겨진 트리거를 심는다. 평소엔 정상 작동하지만 특정 문구나 패턴이 제시되면 악의적으로 행동한다.
- **데이터 유출(data exfiltration)**: 세심한 상호작용을 통해 모델이 훈련받은 기밀 정보(예: 독점 데이터셋)를 추출한다.
- 이는 상수원(water supply)을 오염시키는 것과 같다. 정화 시스템이 대부분 작동해도 충분한 독성 물질이 유입되면 전체 시스템이 무너진다.

### 인프라 위험

- **서비스 거부 공격(denial of service attacks)**: API에 요청을 폭주시켜 응답 불능으로 만든다.
- **자원 고갈(resource exhaustion)**: 과도한 연산을 강제하는 질의를 만들어 서비스를 늦추거나 멈춘다.
- **취약한 의존성(vulnerable dependencies)**: LLM이 의존하는 오픈소스 라이브러리·프레임워크의 약한 의존성 하나를 악용해 전체 시스템을 침해한다.
- **제한된 모니터링과 가시성(limited monitoring and visibility)**: 강력한 로깅·모니터링이 없으면 비정상·악성 사용 패턴이 탐지되지 않을 수 있다.
- AI 모델이 안전해도 지원 인프라가 약한 고리(weak link)가 되는, 트래픽 과부하로 인한 클라우드 장애에 비유된다.

### 공급망과 지적 재산 위험

- **서드파티 컴포넌트 취약점(third-party component vulnerabilities)**: 많은 LLM이 사전 훈련 모델, API, 외부 데이터셋을 쓴다. 이 출처가 침해되면 위험이 시스템으로 퍼진다.
- **지적 재산 침해(intellectual property infringement)**: LLM이 의도치 않게 저작권·독점 콘텐츠를 생성해 법적 위험을 만든다.
- **규제·컴플라이언스 문제(regulatory and compliance issues)**: GDPR 및 다가올 AI 규제 하에서 미준수는 처벌과 평판 손상을 초래한다.

## 요약

- LLM은 막대한 잠재력과 함께 고유한 위협을 가져온다.
- 위협은 프롬프트 기반 공격, 데이터 무결성 문제, 인프라 취약점, 컴플라이언스 문제로 나뉜다.
- 프롬프트 기반 공격은 SQL 인젝션처럼, 데이터 오염은 상수원 오염처럼, 인프라 위험은 클라우드 과부하 장애처럼 이해할 수 있다.
- 이 위험들을 이해함으로써 조직은 견고한 안전장치를 설계하고 책임 있는 AI 배포를 보장할 수 있다.
