# Dependency Scanning and Third-Party Model Risks

## 개요
- 현대 AI 개발은 외부 라이브러리와 사전 훈련된 모델(pre-trained model)에 크게 의존한다. 이들은 혁신을 가속하지만 동시에 숨은 위험을 들여온다.
- 의존성 스캐닝(dependency scanning)의 과제, 그 워크플로가 동작하는 방식, 서드파티(third-party) AI 모델의 위험, 그리고 이 위험을 효과적으로 완화하는 전략을 다룬다.

## 내용

### 의존성 스캐닝이란
- 외부 코드, 오픈소스 라이브러리, 프레임워크에서 취약점(vulnerability)을 자동으로 탐지하는 과정이다. 현대 애플리케이션이 서드파티 구성요소에 크게 의존하므로 전체 보안 유지에 필수적이다.

### 의존성 스캐닝의 이점
- **조기 취약점 탐지(early vulnerability detection)**: 문제가 프로덕션에 도달하기 전에 표시되어 시간과 위험을 줄인다.
- **보안 태세 개선(improved security posture)**: 약점을 지속 모니터링해 전체 방어를 강화한다.
- **규제 준수(regulatory compliance)**: 자동 보고서와 취약점 점검으로 준수 요건 충족과 실사(due diligence) 입증이 쉬워진다.
- **운영 효율(operational efficiency)**: 자동화가 수동 검토를 줄여 개발자가 구축과 수정에 집중하게 한다.
- **지속 모니터링(continuous monitoring)**: 매일 새로운 취약점이 나타나므로 지속 스캔으로 코드베이스를 최신·안전하게 유지한다.

### AI 의존성 스캐닝의 과제
- **보안 사각지대(security blind spots)**: 감시되지 않는 출입구를 가진 집처럼, 스캔하지 않은 의존성은 공격자가 악용할 수 있는 보이지 않는 취약점을 만든다.
- **불완전한 데이터베이스(incomplete databases)**: 취약점 데이터베이스가 항상 최신이 아니어서 일부 위험이 탐지되지 않을 수 있다.
- **복잡한 의존성 체인(complex dependency chains)**: AI 프로젝트는 중첩된 의존성을 자주 쓰며, 체인 깊숙한 곳의 단일 취약 라이브러리가 시스템 전체에 영향을 준다.
- **서드파티 모델 신뢰 문제**: 코드를 넘어 AI 모델 자체가 손상되어 새로운 위험 계층을 더할 수 있다.
- **빠른 코드 변경(rapid code changes)**: 의존성이 빠르게 진화해 모든 버전을 지속 추적·보호하기 어렵다.
- 여러 스캐닝 도구를 기존 워크플로에 통합하는 것 자체도 과제다.

### 의존성 스캐닝 도구의 동작 방식
- **인벤토리 생성(inventory creation)**: 프로젝트 코드베이스와 빌드 파일을 스캔해 소프트웨어 자재 명세서(Software Bill of Materials, SBOM)를 만든다. 시스템이 의존하는 모든 것의 "쇼핑 목록"을 작성하는 셈이다.
- **취약점 교차 참조(vulnerability cross-referencing)**: SBOM을 국가 취약점 데이터베이스(National Vulnerability Database, NVD) 같은 내부·공개 데이터베이스와 대조한다.
- **위험 평가(risk assessment)**: 탐지된 취약점에 CVSS 같은 표준으로 심각도 점수를 매겨 우선순위를 정하게 한다.
- **개선 안내(remediation guidance)**: 안전한 버전으로 업그레이드하거나 패치를 적용하는 등 실행 가능한 수정책을 제공한다.

### 서드파티 AI 모델의 위험
- 외부 사전 훈련 모델을 개발 과정에 대한 완전한 통제 없이 사용하는 데서 비롯된다.
- **편향·공정성 문제(bias and fairness issues)**: 모델이 훈련 데이터의 편견을 반영할 수 있다.
- **모델 회피(model evasion)**: 공격자가 입력을 조작해 모델이 오분류하게 만든다.
- **데이터 누출(data leakage)**: 민감한 훈련 정보가 의도치 않게 노출된다.
- **오염 공격(poisoning attacks)**: 훈련 중 주입된 악성 데이터가 모델 동작을 손상시킨다.

### 서드파티 모델 위험 완화 전략
- **AI 위험 프레임워크 수립**: 외부 AI 모델 평가를 위한 명확한 정책을 정의한다.
- **벤더 규제 준수 검증(vendor compliance verification)**: 제공자가 보안·규제 표준을 충족하는지 확인한다.
- **계약상 투명성(contractual transparency)**: 훈련 데이터, 방법, 한계에 대한 명확성을 요구한다.
- **데이터·편향 평가**: 데이터셋과 모델 출력을 정기적으로 감사해 공정성과 신뢰성을 점검한다.
- **지속 모니터링과 감사**: 자동 테스트와 보안 검토로 진화하는 위협을 포착한다.
- **비상 계획(contingency planning)**: 장애나 침해에 대비해 백업 모델과 대응 전략을 항상 유지한다.

## 요약
- 의존성 스캐닝과 서드파티 모델 위험 관리는 AI 보안의 두 핵심 기둥이다.
- 의존성 스캐닝은 SBOM 생성 → 취약점 교차 참조 → 위험 평가(CVSS) → 개선 안내의 흐름으로 코드 라이브러리의 안전을 보장한다.
- 서드파티 모델은 편향, 모델 회피, 데이터 누출, 오염 공격의 위험을 가지며, 위험 프레임워크·벤더 검증·계약 투명성·지속 감사·비상 계획으로 완화한다.
- 두 접근을 결합해야 안전하고 신뢰할 수 있는 AI 시스템의 견고한 기반이 만들어진다.
