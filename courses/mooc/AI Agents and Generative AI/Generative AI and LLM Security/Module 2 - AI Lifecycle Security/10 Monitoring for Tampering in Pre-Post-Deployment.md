# Monitoring for Tampering in Pre/Post-Deployment

## 개요

- AI 모델은 가치 있는 자산이지만, 배포 전(pre-deployment)과 배포 후(post-deployment) 모두에서 변조(tampering)의 표적이 될 수 있다.
- 모니터링(monitoring)은 보안을 훼손하거나 신뢰를 해칠 수 있는 무단 변경을 지속적으로 감시하는 과정이다.
- 모니터링이 왜 중요한지, 배포 전후 취해야 할 단계, 흔한 위험, 이를 지키기 위한 모범 사례를 다룬다.

## 내용

### 모니터링이 중요한 이유

- 변조를 위한 모니터링은 모델 신뢰성을 보존하고 AI 보안을 강화하기 위해 무단 변경을 탐지하는 것이다.
- 모니터링이 없으면 변경된 모델 파일이나 악성 코드 같은 유해한 변화가 눈에 띄지 않을 수 있고, 이는 부정확한 예측, 데이터 유출, 규제 위반으로 이어질 수 있다.
- 강력한 모니터링이 있으면 문제를 조기에 포착해 피해가 발생하기 전에 대응할 수 있다.

### 배포 전(pre-deployment) 모니터링

- **모델 해시 검증**: 모델의 디지털 지문이나 체크섬을 기대값과 비교해 수정되지 않았는지 확인한다.
- **아티팩트 멀웨어 스캔**: 모델 파일, 코드 패키지, 데이터셋에 숨겨진 악성 소프트웨어가 있는지 검사한다.
- **코드·의존성 검토**: 라이브러리와 외부 패키지를 점검한다. 공급망 공격(supply chain attack)은 검증되지 않은 서드파티 코드에 숨는 경우가 많다.
- **설정 컴플라이언스 확인**: 접근 권한, 암호화 옵션, 네트워크 규칙 같은 설정이 릴리스 전 조직의 보안 표준을 충족하는지 확인한다.

### 배포 후(post-deployment) 실시간 모니터링

- **실시간 모델 추적(real-time model tracking)**: 모델이 프로덕션에서 어떻게 동작하는지 관찰하고 예기치 않은 변화를 빠르게 포착한다.
- **출력 이상 탐지(output anomaly detection)**: 변조나 데이터 오염을 시사할 수 있는 비정상적인 예측을 식별한다.
- **접근 로그 모니터링**: 누가 모델 API를 호출하거나 파일을 내려받는지 정기적으로 검토해 의심스러운 패턴이나 오용을 탐지한다.
- **맞춤형 내부 도구**: 변조 징후가 있을 때 즉시 경고를 발동해 신속히 대응할 수 있게 한다.

### 흔한 변조 위험

- **훈련 중 데이터 오염(data poisoning)**: 공격자가 훈련 세트에 오염되거나 오도하는 데이터를 조용히 삽입한다. 잘못된 패턴 학습이나 나중에 악용 가능한 의도적 백도어(backdoor)로 이어질 수 있다.
- **모델 파일 조작**: 훈련 후 모델의 가중치(weights)나 파일이 변경되는 경우다. 아주 작은 미탐지 변경도 정확도를 낮추거나 편향을 도입하거나 모델 동작에 숨은 트리거를 허용할 수 있다.
- **무단 API 접근**: 해커가 부실하게 보안된 엔드포인트를 악용해 독점 모델을 훔치거나 유해한 입력을 주입하거나 설정을 덮어쓸 수 있다.
- **설정 변경**: 예를 들어 승인 없이 암호화를 비활성화하거나 접근 통제를 변경하는 경우다. 이런 변경은 조용히 방어를 약화시켜 더 큰 공격의 문을 열 수 있다.
- **내부 보안 위험**: 부주의하거나 악의적인 내부자가 취약점을 만들거나 키를 유출하거나 승인되지 않은 변경을 가해 시스템을 위태롭게 할 수 있다.

### 모범 사례

- **상세한 활동 로깅 활성화**: 모델 업데이트, 설정 변경, 접근 시도 등 모든 행동을 기록해 감사할 수 있게 한다.
- **보안 컴플라이언스 검사 자동화**: CI/CD 또는 MLOps 파이프라인에 통합해 검사가 지속적으로 실행되게 한다.
- **정기적 프로세스 감사**: 모니터링과 대응 절차가 의도대로 작동하는지 확인한다.
- **엄격한 접근 통제 시행**: 올바른 사람만 모델과 핵심 설정을 수정·상호작용할 수 있게 한다.

## 요약

- 변조 모니터링은 일회성 단계가 아니라 지속적인 규율(ongoing discipline)이다.
- 배포 전에는 해시 검증, 멀웨어 스캔, 의존성 검토, 설정 컴플라이언스 확인을 수행한다.
- 배포 후에는 실시간 추적, 출력 이상 탐지, 접근 로그 모니터링, 즉각적 경고 체계를 유지한다.
- 데이터 오염, 모델 파일 조작, 무단 API 접근, 설정 변경, 내부 위험이라는 흔한 위협을 이해하고, 로깅·자동화·감사·접근 통제라는 모범 사례를 적용하면 AI 시스템의 무결성과 신뢰를 지킬 수 있다.
