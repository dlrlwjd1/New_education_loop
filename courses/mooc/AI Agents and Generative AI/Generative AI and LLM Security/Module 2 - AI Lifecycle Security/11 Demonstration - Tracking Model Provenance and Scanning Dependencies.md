# Demonstration: Tracking Model Provenance and Scanning Dependencies

## 개요

- ML 모델을 포장된 의약품에 비유한다. 안에 무엇이 들었는지, 어디서 왔는지, 약국으로 오는 길에 바뀌지 않았음을 증명하는 밀봉 라벨이 필요하듯, 데이터와 아티팩트에도 명확한 관리 연속성(chain of custody)과 서드파티 구성 요소에 대한 빠른 위험 점검이 필요하다.
- Google Colab에서 작은 모델을 훈련하고, 데이터셋을 해시(hash)해 출처(provenance)를 기록하고, 모델 파일의 체크섬(checksum)을 계산하고, 이 정보를 담은 매니페스트(manifest)를 작성한 뒤, 가벼운 의존성 스캔을 실행하고 전체 과정을 종단 간(end-to-end) 검증하는 데모다.

## 내용

### 시나리오와 목표

- **시나리오**: Orchid Analytics는 보안 모델을 만들며, 모든 데이터셋과 아티팩트가 어디서 왔는지 증명해야 한다. 위험한 서드파티 의존성을 조기에 잡아내고, 프로덕션에 배포되는 모델이 정확히 훈련된 그 모델임을 검증할 수 있어야 한다.
- **목표**:
  1. 훈련 데이터셋을 해시하고 핵심 훈련 메타데이터를 기록해 출처와 계보(lineage)를 남긴다.
  2. 알려진 위험 패키지나 버전을 표시하는 빠른 의존성 스캔을 실행한다.
  3. 모델 아티팩트에 대한 체크섬 기반 매니페스트를 만들고 검증해, 다운스트림 팀이 전달받은 것을 신뢰하고 재현할 수 있게 한다.

### 셀 1 - 환경 준비

- scikit-learn과 pandas를 설치하고, 해싱(hashing), JSON, 피클링(pickling), 시간 측정, 셸 호출을 위한 유틸리티를 임포트한다.
- NumPy와 pandas는 데이터를 다루고, scikit-learn은 간단한 분류기(classifier)를 제공한다.
- 실행 후 특별한 출력은 없으며, 이는 정상이다. 데이터를 만들고, 모델을 훈련하고, 파일을 디스크에 쓸 준비가 된 것이다.

### 셀 2 - 데이터셋 생성과 해시, 모델 훈련

- scikit-learn의 `make_classification`으로 8개 특성을 가진 작은 2-클래스 데이터셋을 생성해 pandas 데이터프레임에 담고 레이블 열을 추가한다.
- 전체 데이터셋을 CSV 바이트로 직렬화(serialize)하고 SHA-256 해시를 계산한다. 이 해시가 데이터셋의 지문(fingerprint)이자 출처의 앵커(provenance anchor)가 된다.
- 특성으로 간단한 로지스틱 회귀(logistic regression) 모델을 훈련한다.
- `model.pkl`(피클로 저장한 훈련된 모델)과 `dataset.csv`(정확한 훈련 데이터)라는 두 아티팩트를 디스크에 저장한다.
- 데이터셋 해시를 로그에 출력한다. 이 값이 있으면 누구든 나중에 정확히 같은 데이터셋 스냅샷을 쓰고 있음을 증명할 수 있다. CSV가 단 한 바이트라도 바뀌면 재계산한 해시가 달라져 드리프트(drift)나 변조를 드러낸다.

### 셀 3 - 모델 체크섬과 매니페스트 작성

- 저장된 `model.pkl`을 열어 SHA-256 체크섬을 계산하고, 아티팩트 이름, 아티팩트 해시, UTC 타임스탬프, 훈련 진입점(entry point) 이름, 앞서 구한 데이터셋 해시, 짧은 메모를 담은 작은 매니페스트를 구성한다.
- 이를 `manifest.json`에 저장하고 모델 해시와 성공 메시지를 출력한다.
- `model.pkl`과 `manifest.json`이 함께 검증 가능한 패키지를 이룬다. 다운스트림에서 모델의 SHA-256을 다시 계산해 매니페스트와 비교할 수 있으며, 값이 다르면 그 파일은 훈련한 모델이 아님을 뜻한다.

### 셀 4 - 의존성 스캔

- `pip freeze`로 현재 환경의 정확한 패키지 버전을 조회해 딕셔너리로 만들고, 알려진 위험 패키지·버전을 나타내는 시뮬레이션된 권고(advisory) 목록과 비교한다.
- 일치하는 것이 있으면 히트(hit)로 수집한다. 프로덕션에서는 하드코딩된 권고 대신 실제 데이터베이스나 API로 대체해야 하지만, 이 데모는 전체 워크플로를 종단 간으로 보여준다.
- `dependency scan hits` 출력 줄이 위험한 버전이 발견되었는지 알려준다. 이번 작은 환경에서는 권고 목록과 일치하는 것이 없었다.

### 마무리 - 종단 간 검증

- 최종 검증 단계는 재계산과 비교가 성공적으로 이루어졌음을 확인해 준다. 이것이 CI 게이트나 컨슈머(consumer)가 모델을 승격(promote)하기 전에 수행할 점검이다.
- 정리하면 CSV 해시를 통한 데이터셋 출처, 모델 체크섬을 통한 아티팩트 무결성, 공급망 위험을 줄이는 기본 의존성 점검을 갖춘 것이다.
- 작은 모델을 훈련하고, SHA-256으로 데이터셋 계보를 기록하고, 모델 아티팩트용 체크섬 매니페스트를 만들고, 가벼운 의존성 스캔을 실행했다. 이 단계들은 모델을 훈련에서 프로덕션으로 옮길 때 추적 가능(traceable)하고 검증 가능(verifiable)하며 더 안전하게 만들어 준다.

## 예시

- 의약품 비유: 밀봉 라벨이 내용물, 출처, 무변조를 증명하듯, SHA-256 해시와 매니페스트가 데이터셋·모델의 관리 연속성을 증명한다.
- 데이터셋 지문: 훈련 데이터 전체를 CSV로 직렬화한 뒤 계산한 SHA-256 해시를 `dataset hash`로 출력.
- 모델 매니페스트(`manifest.json`) 구성 요소: 아티팩트 이름, 아티팩트 SHA-256 해시, UTC 타임스탬프, 훈련 진입점, 데이터셋 해시, 짧은 메모.
- 의존성 스캔: `pip freeze` 결과를 시뮬레이션된 위험 패키지·버전 권고 목록과 대조해 `dependency scan hits`로 출력.
- 검증 원리: 모델 파일의 SHA-256을 다시 계산해 매니페스트에 기록된 값과 비교하면, 값이 다를 때 파일이 변경되었음을 알 수 있다.

## 요약

- 데이터셋과 모델 아티팩트에 SHA-256 해시 기반 지문을 남기면 출처와 무결성을 증명하는 관리 연속성이 만들어진다.
- 아티팩트 이름·해시·타임스탬프·진입점·데이터셋 해시를 담은 매니페스트는 다운스트림 팀이 전달받은 모델을 신뢰하고 재현할 수 있게 한다.
- `pip freeze`와 위험 권고 목록을 비교하는 가벼운 의존성 스캔은 공급망 위험을 조기에 드러낸다.
- 이 워크플로 전체가 모델을 훈련부터 프로덕션 승격까지 추적 가능하고 검증 가능하게 만든다.
