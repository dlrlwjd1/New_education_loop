# Best Practices for Securing AI Data Pipelines

## 개요
- 모든 AI 시스템은 데이터가 수집되는 순간부터 모델이 예측을 내놓는 지점까지 끊임없는 데이터 흐름에 의존한다. 이 파이프라인(pipeline)이 안전하지 않으면 모델이 아무리 뛰어나도 프로젝트 전체가 무너질 수 있다.
- AI 데이터 파이프라인의 동작 방식, 주요 보안 과제, 그리고 파이프라인을 처음부터 끝까지(end-to-end) 보호하는 핵심 실천법을 다룬다.

## 내용

### AI 데이터 파이프라인의 단계
- **데이터 수집(data collection)**: 센서, 로그, 사용자 입력 같은 소스에서 정보를 끌어온다.
- **수집 및 저장(ingestion and storage)**: 데이터가 데이터베이스나 클라우드 버킷(cloud bucket)으로 이동한다. 식재료를 팬트리에 조심스럽게 보관하는 것에 비유된다.
- **전처리(preprocessing)**: 데이터를 정제하고 변환해 분석 준비를 마친다.
- **모델 훈련(model training)**: AI가 훈련과 검증을 통해 패턴을 학습하며, 흔히 MLOps 프로세스의 지원을 받는다.
- **배포(deployment)**: 훈련된 모델을 프로덕션에 투입해 예측하거나 결과를 제공한다.
- 각 단계가 핵심적 역할을 하며, 어느 한 단계의 약점이 AI 시스템 전체를 위험에 빠뜨릴 수 있다.

### 주요 보안 과제
- **내부자 위협(insider threats)**: 위험은 외부에서만 오지 않는다. 접근 권한이 있는 직원이나 계약자가 실수로 또는 의도적으로 민감 정보를 유출할 수 있다.
- **모델 탈취(model theft)**: 공격자가 훈련된 모델을 복제하거나 역공학(reverse engineer)한다. 수개월에서 수년에 걸쳐 구축한 지식 재산(intellectual property)을 잃을 수 있다.
- **데이터 오염(data poisoning)**: 악의적 행위자가 훈련 세트에 손상되거나 오도하는 데이터를 주입해 AI가 잘못된 패턴을 학습하고 신뢰할 수 없는 예측을 하게 만든다.
- **데이터 유출(data breaches)**: 외부 공격자가 취약점을 악용해 기밀 데이터를 훔쳐 재무와 평판 모두에 손해를 입힌다.

### 데이터 수집 단계 보호
- **인증과 암호화(authentication and encryption)**: 데이터 소스를 항상 검증하고, 전송 중에 암호화해 가로채여도 읽을 수 없게 한다.
- **검증과 최소화(validation and minimization)**: 유입 데이터의 정확성을 확인하고, 꼭 필요한 것만 수집한다. 수집량을 제한하면 노출 위험이 줄고 규제 준수(compliance)도 단순해진다.

### 안전한 데이터 접근
- **접근 제한**: 강력한 권한(permissions)과 다중 인증(multi-factor authentication, MFA)으로 인가된 사용자만 민감 정보에 접근하게 한다.
- **저장 데이터 암호화**: 침입자가 접근하더라도 읽을 수 없게 만든다.
- **네트워크 트래픽 분할(segment)**: 인프라의 각 부분을 격리해 공격자가 시스템 사이를 자유롭게 이동하지 못하게 한다.
- **정기 데이터 감사(regular data audits)**: 비정상 활동을 조기에 발견한다.
- **명확한 사용자 정책 시행**: 모든 팀원이 데이터를 어떻게 다뤄야 하는지 이해하게 한다.

### 전처리 단계 보호
- 데이터 입력 채널을 보호하고 의심스러운 활동을 모니터링한다.
- 처리 시작 전에 데이터 검증(data validation)을 수행해 이상치나 악성 패턴을 탐지한다.
- 데이터 처리 중에는 변경 권한을 제한하고 모든 변환(transformation)을 로그로 남긴다.
- AI 저장소에서는 중간 데이터셋(intermediate dataset)을 암호화하고 접근 로그를 유지한다. 임시 파일조차 매력적인 공격 대상이 될 수 있다.

### 거버넌스와 규제 준수
- **규제 프레임워크 정합**: GDPR, HIPAA 또는 해당 산업의 표준에 맞춘다.
- **자동 정책 시행(automated policy enforcement)**: 수동 점검에 의존하지 않고 보안 규칙을 일관되게 적용한다.
- **거버넌스 워크플로 통합**: MLOps 프로세스에 직접 통합해 보안이 일상 운영의 일부가 되게 한다.
- **지속적 규제 준수 감사(continuous compliance auditing)**: 진화하는 규제에 앞서 문제를 사전에 포착한다.

## 요약
- AI 데이터 파이프라인은 모든 AI 시스템의 척추(backbone)이며, 어느 한 단계의 약점도 전체를 위협한다.
- 주요 위협은 내부자 위협, 모델 탈취, 데이터 오염, 데이터 유출이다.
- 데이터 수집(인증·암호화·검증·최소화), 저장·접근(권한·암호화·분할·감사), 전처리(검증·로깅), 거버넌스·규제 준수를 각각 보호해야 회복력 있고 신뢰할 수 있는 파이프라인이 완성된다.
