# Resources

## 개요
- MCP의 또 다른 핵심 요소인 **리소스(resources)** — AI가 도구를 올바르게 사용하기 위해 필요한 **맥락 정보(context)**를 발견하고 읽어오는 개념을 다루는 강의.
- Module 3의 유일한 비디오 강의 (이 모듈의 나머지는 읽기 자료와 인터랙티브 실습 위젯으로 구성됨).

## 내용
### 왜 도구만으로는 부족한가
- 도구를 잘 쓰려면 **맥락(context)에 대한 정보**가 필요하다.
  - 예: 누군가에게 이메일을 쓸 때, 그 사람의 배경(우리 회사에 만족하는지/불만족하는지, 관심 있는 제품이 무엇인지 등)을 알아야 제대로 쓸 수 있다.
  - 예: 가스레인지를 켤 때, 어떤 화구가 고장났는지 미리 알아야 올바른 화구를 선택할 수 있다.
- MCP는 이런 맥락 정보를 **리소스(resources)**라는 개념으로 다룬다 — AI 에이전트가 과제 수행이나 도구 사용에 필요한 정보를 **발견하고 읽을 수 있게** 해준다.

### 실습 예시 — 회사 데이터베이스 쿼리하기
- 프롬프트 구성: "사용 가능한 도구: query(쿼리 도구)" + **리소스 섹션**: 데이터베이스 매뉴얼(database manual) 등.
- 도구뿐 아니라 **리소스도 목록으로 발견**할 수 있다는 점이 새로운 개념.

### AI의 실제 행동 순서
1. AI는 데이터베이스를 곧바로 쿼리하지 않고, **먼저 "데이터베이스 스키마를 읽겠다"**고 판단한다 — 올바른 쿼리를 작성하려면 구조를 이해해야 하기 때문.
2. 스키마를 읽은 결과: 테이블이 하나 있고, 그 구조가 어떻다는 정보를 얻음.
3. 하지만 구조만으로는 부족할 수 있으므로, AI는 이어서 **"데이터베이스 매뉴얼"이라는 또 다른 리소스**를 읽는다.
4. 매뉴얼에서 데이터의 출처, 의미(semantics) 등 **구조를 넘어선 풍부한 맥락 정보**를 얻는다.
5. 필요한 정보를 모두 확보한 뒤에야, 비로소 **query 도구를 실제로 사용**해 쿼리를 실행하고 결과를 얻는다.

### 핵심 통찰 — "구문적으로 올바름"과 "의미적으로 올바름"은 다르다
- AI가 데이터베이스 구조만 보고 쿼리를 작성하면, **문법적으로는 올바른 쿼리**를 만들 수는 있어도, 데이터의 실제 의미나 출처를 몰라 **의도와 다른(틀린) 결과**를 낼 수 있다.
- 즉, "도구를 올바르게 사용했다"는 것과 "우리가 진짜 원하는 답을 얻었다"는 것은 별개의 문제이며, **리소스를 통한 맥락 정보 확보**가 이 간극을 메워준다.

## 예시
```
사용 가능한 도구: query
사용 가능한 리소스: database_schema, database_manual

AI의 실행 순서:
1. read: database_schema → 테이블 구조 파악
2. read: database_manual → 데이터 출처/의미 파악
3. use: query → 올바른 맥락을 반영한 쿼리 실행
```

## 요약
- **리소스(resources)**는 AI 에이전트가 도구를 올바르게 사용하기 위해 필요한 **배경 지식·맥락 정보**를 담고 있으며, 도구처럼 발견(discover)하고 읽을(read) 수 있다.
- AI는 도구를 바로 사용하기 전에 **관련 리소스(스키마, 매뉴얼 등)를 먼저 읽어 맥락을 확보**하는 것이 중요하다.
- 리소스가 없으면 AI는 "구문적으로는 맞지만 의미적으로는 틀린" 결과를 낼 위험이 있다 — 리소스는 이런 간극을 메워 과제를 진짜 의도에 맞게 수행하도록 돕는다.
