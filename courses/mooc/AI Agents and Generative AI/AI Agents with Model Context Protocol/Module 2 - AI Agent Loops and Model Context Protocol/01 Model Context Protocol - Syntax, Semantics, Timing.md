# Model Context Protocol: Syntax, Semantics, Timing

## 개요
- MCP를 "프로토콜(protocol)"이라는 관점에서 정의하며, **문법(syntax) · 의미(semantics) · 타이밍(timing)**이라는 세 가지 구성 요소로 설명하는 강의.
- 스타워즈의 통역 로봇 **C-3PO**("protocol droid") 비유를 다시 가져온다.

## 내용
### C-3PO 비유 — "프로토콜 드로이드"
- C-3PO는 여러 언어를 구사하며 다양한 장비(수확기 등)와 소통하는 "다리(bridge)" 역할을 한다.
- MCP도 마찬가지로 **AI가 컴퓨터와 소통하기 위한 프로토콜**이다. AI는 C-3PO처럼 "프로토콜을 알려주기만 하면 그 언어로 말할 수 있는" 존재.

### 프로토콜이란 무엇인가
- 예: "다음 주 화요일 오후 3시에 Alex와 회의를 잡아줘"라는 자연어 요청을 받으면, AI는 내부적으로 `tools.list` 같은 **컴퓨터가 이해하는 특수한 형식의 메시지**를 컴퓨터에 보낸다.
- 이 메시지는 사람이 읽으면 이해할 수는 있지만, **본질적으로 사람이 아니라 컴퓨터를 위한 언어**다.
- AI는 C-3PO처럼 "이 프로토콜이 무엇인지"만 알려주면 그 언어를 구사할 수 있다.

### MCP의 세 가지 구성 요소
1. **문법(Syntax)**: 언어의 구조 — 단어를 어떻게 표기하고, 문장을 어떻게 구성하고, 어떤 규칙이 허용되는지.
2. **의미(Semantics)**: 각 메시지가 실제로 무엇을 뜻하는지. 예: `mcp://tools.list` (실제 정확한 형식은 아니지만 개념 예시) 같은 메시지를 컴퓨터가 받으면 "사용 가능한 도구 목록을 돌려달라는 뜻"임을 이해하고 그에 맞게 응답한다.
3. **타이밍(Timing)**: 어떤 메시지가 언제 보내져야 하고, 그에 대한 응답으로 무엇이 언제 와야 하는지에 대한 순서/시퀀스 규칙.

### 컴퓨터가 "대화의 참여자"가 된다는 관점 전환
- 지금까지는 "나 ↔ AI"의 대화만 생각했지만, MCP가 개입하면 **"컴퓨터"도 AI와 직접 메시지를 주고받는 대화 참여자**가 된다.
- 즉, AI는 하나의 큰 대화 속에서 여러 참여자(사람, 컴퓨터, 어쩌면 다른 컴퓨터들)와 대화하며, **상대가 누구냐에 따라 사용하는 언어를 전환**한다.
  - 사람과 대화할 때: **자연어(natural language)**.
  - 컴퓨터와 대화할 때: **Model Context Protocol**.
- 겉보기엔 하나의 대화지만, 속을 들여다보면 언어를 스위칭하며 여러 상대와 대화하는 구조.

### 실제로 우리가 보는 것 — "블랙박스 뒤의 대화"
- 사용자가 Claude 등에게 작업을 지시하면, 화면에 보이지 않는 곳에서 AI가 **컴퓨터와 MCP로 대화하며 일련의 작업을 처리**한다.
- 작업이 끝나면 AI는 다시 **자연어로 전환**해 "이런 작업들을 수행했습니다"라고 결과를 사용자에게 보고한다.
- 즉, 우리가 보는 것은 "자연어 요청 → (보이지 않는 MCP 대화) → 자연어 결과 보고"라는 흐름의 앞뒤 부분뿐이다.

## 예시
- 개념적 예시 메시지: `tools.list` (실제 정확한 MCP 메시지 포맷은 아니지만, "사용 가능한 도구 목록을 요청한다"는 의미를 전달하는 예시)
- 흐름: 사용자(자연어) → AI → 컴퓨터(MCP, 보이지 않음) → AI → 사용자(자연어 결과 보고)

## 요약
- MCP는 C-3PO 같은 "프로토콜 드로이드"의 역할을 AI가 수행하도록 만드는 프로토콜이며, **문법(syntax) · 의미(semantics) · 타이밍(timing)** 세 요소로 정의된다.
- MCP가 도입되면 **컴퓨터도 AI와의 대화에 직접 참여**하게 되며, AI는 대화 상대(사람 vs. 컴퓨터)에 따라 자연어와 MCP 사이를 전환하며 소통한다.
- 사용자가 보는 것은 이 전체 대화의 시작(자연어 요청)과 끝(자연어 결과 보고)뿐이며, 그 사이의 AI-컴퓨터 간 MCP 대화는 보이지 않는 곳에서 이루어진다.
