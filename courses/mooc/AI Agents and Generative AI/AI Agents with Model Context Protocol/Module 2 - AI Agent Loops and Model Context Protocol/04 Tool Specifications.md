# Tool Specifications

## 개요
- AI가 도구를 "발견"하는 것을 넘어, **정확하게 사용하기 위해 필요한 "도구 명세(tool specification)"**, 특히 **파라미터 스키마(parameter schema)**의 개념을 다루는 강의.

## 내용
### 왜 이름(name)만으로는 부족한가
- 도구 이름을 아는 것만으로는 충분하지 않다 — 예를 들어 "이메일 보내기"는 **매우 엄격한 형식과 정보**를 요구한다.
- 비유: 가스레인지를 켤 때도 특정 손잡이로 특정 화구를 선택하고, 정해진 단계(설정값) 중 하나로 조절해야 한다 — 화구가 4개인지 6개인지, 최소/최대 설정값이 무엇인지 등이 그 도구의 "파라미터"에 해당한다.
- 컴퓨터는 이런 세부사항에 대해 **매우 까다롭기(picky)** 때문에, AI가 각 도구별로 이런 세부 규칙을 학습할 방법이 필요하다.

### 파라미터 스키마(Parameter Schema)란
- 도구를 발견할 때 AI가 함께 받는 **"스키마(schema)"**는 그 도구가 받아들이는 정보의 엄격한 형식을 정의한다.
- 예: 이메일 보내기 도구의 파라미터 → 수신자(to), 참조(CC), 제목(subject), 본문(body).
- 예: 캘린더 확인 도구의 파라미터 → 언제 확인할지(날짜), 얼마나 긴 시간의 빈 슬롯을 찾을지(duration).

### 필수 파라미터(required parameters) vs. 선택 파라미터(optional parameters)
- **필수 파라미터**: 반드시 제공해야 하는 정보. 예: 이메일은 수신자(to) 없이 보낼 수 없고, 캘린더 확인도 "언제, 얼마나"라는 정보 없이는 실행할 수 없다.
- **선택 파라미터**: 제공해도 되고 안 해도 되는 정보. 예: 캘린더 이벤트 생성 시 "제목(title)"은 필수지만 "장소(location)"는 선택.

### 형식(format) 규칙도 스키마에 포함됨
- 날짜는 사람이 쓰면 다양한 형식(예: "10월 1일", "2024/10/1" 등)이 가능하지만, **컴퓨터는 임의의 형식을 받아들이지 않는다.**
- LLM과는 달리 컴퓨터는 매우 엄격(rigid)하므로, 스키마는 정확한 형식(예: `YYYY-MM-DD` 형태의 4자리 연도-2자리 월-2자리 일)까지 명시한다.
- 반면 "제목(title)" 같은 파라미터는 형식이 느슨해서 **문자열(string)**이면 무엇이든(자연어, 숫자 등) 허용될 수 있다.

### 실전 예시 — 캘린더 확인 도구 호출
- AI가 스키마를 파악한 뒤 다음과 같이 정확한 형식으로 파라미터를 채워 호출: `date=2024-10-01, duration=60, time_range=afternoon`
  - (참고: `time_range=afternoon`이 실제 스키마상 유효한 값인지는 불확실하다는 언급 — 스키마에 없는 값이면 컴퓨터가 오류 처리를 하게 됨.)

### 비대칭성 — "AI → 컴퓨터"는 엄격, "컴퓨터 → AI"는 유연
- **AI가 컴퓨터에게 말할 때**는 스키마에 정확히 맞는 엄격한 형식을 지켜야 한다 (이메일의 `to` 필드에 `@`와 유효한 도메인이 포함된 정확한 형식이 필요한 것처럼).
- **컴퓨터가 AI에게 결과를 돌려줄 때**는 훨씬 유연하다 — 다양한 형식으로 데이터를 던져줘도 AI가 알아서 해석하고 처리할 수 있다. (동일한 데이터를 컴퓨터에 그렇게 던지면 컴퓨터는 전혀 이해하지 못할 것.)

### 비용(토큰) 관점에서의 실전 팁
- 그럼에도 컴퓨터가 AI에게 결과를 반환할 때는 **가능한 한 간결하고 정보 밀도가 높은 형식**으로 주는 것이 좋다.
- 이유: 응답이 장황(verbose)할수록 AI가 처리해야 할 **토큰(token) 수가 늘어나 비용이 증가**하기 때문.
- 즉, "컴퓨터 → AI" 방향은 형식은 유연해도 되지만, **간결성(conciseness)**은 신경 써야 한다.

## 예시
```
도구: send_email
필수 파라미터: to (형식: 유효한 이메일 주소), subject (string), body (string)
선택 파라미터: cc (형식: 유효한 이메일 주소)

도구: check_calendar
필수 파라미터: date (형식: YYYY-MM-DD), duration (분 단위 정수)

도구: create_calendar_event
필수 파라미터: title (string)
선택 파라미터: location (string)
```

## 요약
- 도구 명세(tool specification)의 핵심은 **파라미터 스키마** — 어떤 정보가 필수/선택인지, 어떤 형식(날짜 포맷 등)을 요구하는지를 정의한다.
- AI는 도구를 발견할 때 이 스키마도 함께 받아, 정확한 형식으로 파라미터를 채워 도구를 호출해야 한다.
- **AI→컴퓨터 방향은 엄격한 형식 준수가 필요**하지만, **컴퓨터→AI 방향은 형식이 유연**하다 — 다만 토큰 비용을 줄이기 위해 간결하게 응답하는 것이 좋다.
