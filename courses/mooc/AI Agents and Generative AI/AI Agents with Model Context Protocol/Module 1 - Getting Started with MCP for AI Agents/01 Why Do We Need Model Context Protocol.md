# Why Do We Need Model Context Protocol?

## 개요
- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**이 왜 필요한지를 "사람이 AI와 도구 사이의 중간 전달자(middleman) 역할을 하는 문제"에서 출발해 설명하는 강좌의 도입 강의.

## 내용
### 문제 상황 — 사람이 AI의 "중간 전달자"가 되는 비효율
- 비유: 개인 비서를 고용했는데, 회의를 잡을 때마다 "캘린더를 주세요", "이번 주 일정을 알려주세요", "다음 주 일정도 알려주세요"라고 계속 요청한 뒤에야 "이 날짜에 시간이 비네요"라고 답한다면? "그거 내가 이미 다 알려줬잖아"라는 느낌이 들 것이다.
- 이것이 바로 AI와 일할 때 흔히 겪는 문제 — **AI가 캘린더나 이메일 같은 것에 직접 접근할 수 없어서, 사람이 계속 복사·붙여넣기하며 자료를 전달해줘야 하는 상황**.
- 저자가 원하는 것: AI의 **리더(leader)**가 되는 것이지, AI가 쓸 도구들 사이를 오가며 정보를 날라주는 **중간 전달자(middleman)**가 되는 것이 아니다.

### 해결책 — Model Context Protocol (MCP)
- MCP의 핵심: AI에게 **도구(tools)에 직접 접근해 스스로 작업을 수행할 수 있는 능력**을 부여하는 것.

### 실전 시연 — Claude로 회의 일정 잡기
- 프롬프트: "다음 주 목요일이나 금요일에 회의를 잡아야 해. 언제 시간이 비어?"
- Claude(Anthropic)의 반응: "다음 주 목요일과 금요일 캘린더를 확인해볼게요"라는 메시지와 함께 **"searched calendar events"**라는 표시가 뜸 — 이것이 바로 **MCP가 실제로 작동하는 순간**.
- 결과: 캘린더를 직접 조회해 실제 비어 있는 시간대를 정리해서 알려줌.
- 또 다른 예: "다음 주에 Michael과 채팅하는 시간을 알려줘" → "10월 2일 오후 1:30~2:30입니다"라고 캘린더 기반으로 정확히 답변.

### 핵심 개념 — 도구 사용(Tool Use)
- MCP의 근본 원리는 **AI의 도구 사용(tool use)** 능력이다.
- 동물의 지능을 판단할 때 "도구를 사용한다"는 것이 중요한 척도이듯, 이제 **AI도 우리가 매일 쓰는 도구(캘린더, 이메일, 파일, 데이터베이스, 소프트웨어 등)를 직접 사용할 수 있게 되었다**는 것이 놀라운 지점.
- MCP가 다루는 범위는 캘린더 조회처럼 단순해 보이는 것부터, 소프트웨어 작성, 데이터베이스 쿼리처럼 훨씬 복잡한 작업까지 아우른다.

### 이 강좌가 다룰 방향
- MCP의 작동 원리를 배우고, 그 이면의 "마법"을 이해한다 — 사실 이는 **누구나 배울 수 있는 몇 가지 단순한 원칙에 기반한 대화(conversation)**일 뿐이다.
- 궁극적 목표: 조직을 위해 어떤 전략이 필요한지, MCP로 어떻게 놀라운 도구를 만들어 AI에게 노출시킬지를 이해하는 것.

## 예시
```
프롬프트: "I need to schedule a meeting next Thursday or Friday. When am I free?"
→ Claude가 "searched calendar events"(MCP 호출)를 통해 실제 캘린더를 조회하고 빈 시간대를 알려줌.

프롬프트: "Can you remind me when I'm chatting with Michael next week?"
→ 캘린더 조회 결과로 정확한 날짜/시간 답변.
```

## 요약
- MCP가 없으면 사람이 AI와 각종 도구(캘린더, 이메일 등) 사이의 **중간 전달자** 역할을 계속해야 한다.
- MCP는 AI에게 **도구를 직접 사용할 수 있는 능력**을 부여해, 사람이 리더로서 AI에게 일을 맡길 수 있게 해준다.
- 핵심 원리는 **도구 사용(tool use)**이며, 이는 단순한 일정 조회부터 복잡한 소프트웨어 작업까지 확장될 수 있다.
