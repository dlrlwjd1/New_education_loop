# LangGraph versus LangChain - When to Use What

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/agentic-ai-with-langchain-and-langgraph/lecture/Y54Xs/langgraph-versus-langchain-when-to-use-what)

## 개요
- LangChain과 LangGraph는 모두 개발자가 대규모 언어 모델을 활용한 대규모 언어 모델을 활용한 애플리케이션을 구축할 수 있도록 돕기 위해 설계된 오픈 소스 프레임워크입니다.

## 내용
- LangChain과 LangGraph는 모두 개발자가 대규모 언어 모델을 활용한 대규모 언어 모델을 활용한 애플리케이션을 구축할 수 있도록 돕기 위해 설계된 오픈 소스 프레임워크입니다.
- 그리고 해당 문서 중 일부가 용량이 큰 경우, 텍스트를 의미론적으로 의미 있는 더 작은 단위로 분할하는 또 다른 LangChain 컴포넌트인 ‘텍스트 분할기(text splitter)’를 사용할 수도 있습니다.
- 그리고 요약 내용과 기록 컨텍스트를 바탕으로 답변을 생성하기 위해 또 다른 프롬프트 구성 요소와 LLM 구성 요소를 추가할 것입니다.
- 이제 LangGraph를 사용하면 이를 그래프 구조로 만들 수 있는데, 여기서 각 작업은 각각 노드로 간주되는 그래프 구조로 만들 수 있게 해줍니다.
- LangGraph의 아키텍처를 통해 확장된 상호작용 전반에 걸쳐 컨텍스트를 유지할 수 있는 유지할 수 있는 유연하고 상태를 유지하는 에이전트를 구축할 수 있게 해줍니다.
- 반면, LangGraph의 그래프 구조는 루프를 허용하고 이전 상태를 다시 방문할 수 있게 해주기 때문에 루프를 허용하고 이전 상태로 되돌아갈 수 있기 때문입니다.
- 이는 상태가 모든 노드가 접근하고 수정할 수 있는 CORE 구성 요소이기 때문이며, 이를 통해 더 복잡하고 맥락을 인식하는 동작이 가능하기 때문입니다.

## 예시
- 예를 들어, 작업 1번으로 시작하면, 그 다음에는 작업 2번과 3번 작업으로 갈라지는 분기가 생기고, 그 후 다시 중앙의 4번 작업으로 돌아오게 됩니다.

## 요약
- 반면, LangGraph의 그래프 구조는 루프를 허용하고 이전 상태를 다시 방문할 수 있게 해주기 때문에 루프를 허용하고 이전 상태로 되돌아갈 수 있기 때문입니다. 이는 상태가 모든 노드가 접근하고 수정할 수 있는 CORE 구성 요소이기 때문이며, 이를 통해 더 복잡하고 맥락을 인식하는 동작이 가능하기 때문입니다.
