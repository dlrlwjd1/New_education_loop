# 09 Expert Viewpoints: Key Considerations in Choosing Prompt Engineering Approach

## 개요
- 최적의 프롬프트 엔지니어링 접근법을 선택할 때 고려해야 할 핵심 요인들을 전문가 인터뷰로 정리하는 영상

## 내용

### 고려 요인 1 — 작업 목표(Task Objective)
- 생성형 AI로 수행할 작업의 종류를 먼저 파악해야 함: **텍스트 생성·요약, 코드 생성, 코드 번역, 이미지 생성** 등
- 어떤 작업을 다루려는지가 먼저 결정돼야 이후 선택이 의미를 가짐

### 고려 요인 2 — 모델 역량(Model Capability)
- 모델마다 겨냥하는 사용 사례가 다름 — 목표하는 애플리케이션 종류에 따라 요구사항이 달라짐
- 예: 특정 형식의 문단을 작성해야 한다면, 문단이 어떻게 조직되고 연결되어야 하는지 **매우 명확히** 지정해야 함 → 결국 다시 "맥락 분석"으로 귀결

### 고려 요인 3 — 사고의 명확성(Clarity of Thought)
- 구체적인 작업이 있다면 최대한 상세하고 명확하게 명시해야 함
- 그렇지 않으면 출력이 **지나치게 일반적**이 되거나, 더 나쁘게는 **AI 환각(hallucination)**과 연관될 수 있음
- 코드 생성의 경우: 필요한 출력의 모든 기능을 **순차적이고 매우 서술적인 순서**로 명시해야 함 — 안 그러면 프롬프트가 그저 일반적인(쓸모없을 수 있는) 응답만 줌

### 핵심 3요소 — 명확성(Clarity) · 맥락(Context) · 기능(Features)
- 좋은 프롬프트의 3대 축: **명확성 · 맥락 · (요구되는) 기능**을 적절한 순서와 충분한 맥락으로 배치해야 서술적이고 적절한 응답을 얻을 수 있음
- 프롬프트를 명확하고 간결하게 유지, **구체성과 개방성(specificity vs. openness) 사이의 균형**을 잡고, 최적의 결과를 위해 다양한 관점(lens)으로 실험해볼 것
- AI 모델의 강점을 활용하도록 프롬프트를 맞추고, 일관된 응답을 위해 충분한 맥락을 제공할 것

### 고려 요인 4 — 데이터 요구사항(Data Requirements)
- 어떤 모델은 더 많은 데이터가 필요하고, 어떤 모델은 더 적은 데이터로 충분함
- **맥락 민감도(context sensitivity)**: 모델이 원하는 방식으로 응답하려면 얼마나 많은 맥락/배경지식을 제공해야 하는지가 중요

### 고려 요인 5 — 피드백 메커니즘(Feedback Mechanism)
- 특정 프롬프트에 대해 응답이 어떻게 제공되는지 학습하고, 모델과의 상호작용 방식을 개선하며, 생성되는 출력을 향상시키는 과정

## 요약
- 프롬프트 엔지니어링 접근법을 고를 때 고려할 5가지: **작업 목표 · 모델 역량 · 사고의 명확성 · 데이터 요구사항(맥락 민감도) · 피드백 메커니즘**
- 좋은 프롬프트의 핵심 3축은 **명확성 · 맥락 · 기능** — [01 Text-to-Text Prompt Techniques](01%20Text-to-Text%20Prompt%20Techniques.md)의 6대 기법과 [04 Chain-of-Thought](04%20Chain-of-Thought%20Approach.md)/[06 Tree-of-Thought](06%20Tree-of-Thought%20Approach.md) 접근법 중 무엇을 선택할지는 결국 이 요인들에 달려 있음
- 구체성과 개방성의 균형, 다양한 관점으로 실험하는 것이 최적의 결과를 얻는 실무적 팁
