# Understanding SCD2 Core Components and Business Logic

## 개요

- SCD2의 4대 구성 요소(비즈니스 키·대리 키·유효 기간·현재 플래그)와 변경 감지 로직

## 내용

### SCD2의 접근

- 사진첩 비유 — 사진을 갱신본으로 교체하는 대신 중요한 변화마다 사진을 추가해 완전한 이야기 보존
- 전통적 갱신은 값을 덮어쓰고 이력 소실; SCD2는 원본을 보존하며 변경을 담은 **새 레코드 생성**

### 4대 구성 요소

1. **비즈니스 키(business key)** — 실세계 엔터티 식별 (고객 ID, 상품 코드) — 비즈니스 사용자가 이해하는 키
2. **대리 키(surrogate key)** — 시스템 생성 인공 식별자 — 각 역사적 레코드의 유일성 보장
   - 예: CUST_001이 주소를 두 번 바꾸면 레코드 3개 — 비즈니스 키는 모두 CUST_001, 대리 키는 1·2·3
   - 대리 키 없이는 이력 추적·정확한 팩트 조인·다중 버전 관리가 모호해짐
3. **유효 기간(validity period)** — `VALID_FROM`(활성 시점) / `VALID_TO`(대체 시점). 현재 레코드는 VALID_TO가 NULL 또는 9999-12-31 같은 먼 미래
4. **현재 상태 플래그(IS_CURRENT)** — 최신 버전만 쉽게 조회하는 불리언

### 변경 감지 (change detection)

- 유입 데이터와 기존 레코드의 핵심 속성(이름·주소·가격·상태 코드) 비교 → 차이 발견 시 이력 버전을 보존하며 갱신 값으로 새 레코드 생성
- dbt 같은 현대 도구는 이를 **선언적**으로 — 복잡한 저장 프로시저 대신 "무엇이 변경인가"만 정의하면 비교·레코드 생성은 도구가 자동 처리

### 예시 시나리오

- 이커머스 고객 CUST_001: 뉴욕 거주 → 캘리포니아 이사 → 이메일 변경 = SCD2 테이블에 유효 기간·현재 플래그가 달린 3개 버전 레코드

## 요약

- 비즈니스 키(누구인가) + 대리 키(어느 버전인가) + 유효 기간(언제 유효했나) + 현재 플래그(지금 버전인가)의 4요소가 SCD2다.
- 변경 감지가 파괴적 갱신을 건설적 버저닝으로 바꿔 이력·현재 상태 질의를 모두 지원한다.
