# CIDR

## 개요

- **CIDR(Classless Inter-Domain Routing)** 는 IP 주소 블록을 기술하는 **훨씬 유연한 방식**이다.
- 핵심: **주소 클래스 개념을 완전히 버리고**, 네트워크 ID와 서브넷 ID를 **하나로 합친다.**
- 결과: 임의 크기의 네트워크가 가능해지고, **라우팅 테이블 항목이 줄고, 쓸 수 있는 호스트 IP가 늘어난다.**

## 내용

### 왜 필요했나

- 주소 클래스는 전역 IP 공간을 나누는 **첫 번째 시도**였고, 그것만으로 부족해지자 **서브넷팅**이 도입됐다. 그런데 인터넷이 계속 커지면서 **전통적인 서브넷팅으로도 감당이 안 됐다.**
- 전통 방식에서는 네트워크 ID가 **클래스 A는 8비트, B는 16비트, C는 24비트**로 고정된다.
  - 그래서 **클래스 A 네트워크는 254개뿐**일 수 있는 반면, **클래스 C 네트워크는 2,097,152개**가 가능하다. **라우팅 테이블 항목이 어마어마해진다.**
- 게다가 **크기가 실제 기업 수요에 맞지 않는다.**
  - 클래스 C의 **254 호스트**는 많은 경우 **너무 작고**,
  - 클래스 B의 **65,534 호스트**는 대개 **너무 크다.**
- 그래서 많은 회사가 **인접한 여러 클래스 C 네트워크**를 확보했고, 결과적으로 라우팅 테이블에는 **실제로는 같은 곳으로 라우팅되는 클래스 C 항목이 잔뜩** 쌓였다.

### CIDR이 하는 일

- 서브넷 마스크를 사용해 네트워크를 **구획(demarcate)** 한다.
  - **demarcate** = 무언가를 구분해 놓는 것. 네트워킹에서는 **한 네트워크나 시스템이 끝나고 다른 것이 시작되는 지점**을 **구획점(demarcation point)** 이라 부른다.
- 기존 모델: **네트워크 ID + 서브넷 ID + 호스트 ID** 세 개로 배달.
- **CIDR: 네트워크 ID와 서브넷 ID를 하나로 합친다.** 즉 **두 개의 ID만으로** 주소가 정의된다.
- 앞서 서브넷팅에서 본 **슬래시 표기가 곧 CIDR 표기(CIDR notation)** 다.

### 예시로 보기

- `9.100.100.100` + 넷마스크 `255.255.255.0` = `9.100.100.100/24`
- **주소 클래스를 더 이상 신경 쓰지 않는 세계에서는**, 네트워크 ID를 알아내는 데 **넷마스크가 알려 주는 것만 있으면 된다.**
  - 이 경우 네트워크 ID = **`9.100.100`**, 호스트 ID는 그대로.

### 임의 크기의 네트워크

- 이전에는 **네트워크 크기가 고정**이었다(클래스 A/B/C). **서브넷만** 크기가 달라질 수 있었다.
- **CIDR은 네트워크 자체의 크기를 다르게** 만들 수 있다.
- 예전에는 클래스 C 하나로 부족하면 **두 번째 클래스 C 전체**가 필요했다. CIDR에서는 그 주소 공간을 **넷마스크 /23 (255.255.254.0)의 하나의 연속된 덩어리**로 합칠 수 있다.
- 그러면 라우터는 이 주소들로 트래픽을 보내기 위해 **라우팅 테이블 항목 2개가 아니라 1개만** 알면 된다.

### 보너스 — 호스트 IP가 늘어난다

**네트워크마다 호스트 ID 2개를 항상 잃는다**는 점을 기억하면:

| 구성 | 계산 | 사용 가능 호스트 |
|---|---|---|
| /24 하나 | 2^8 = 256 → 256 − 2 | **254** |
| /24 **두 개** | 254 + 254 | **508** |
| /23 **하나** | 2^9 = 512 → 512 − 2 | **510** |

→ **같은 주소 공간인데 /23 하나로 묶으면 호스트가 2개 더 생긴다.**

## 요약

- CIDR은 주소 클래스를 폐기하고 네트워크 ID와 서브넷 ID를 하나로 합친 방식이다.
- 넷마스크만으로 네트워크 ID를 결정하므로 네트워크 크기를 자유롭게 정할 수 있다.
- 인접 네트워크를 하나로 묶으면 라우팅 테이블 항목이 줄어든다.
- 묶으면 네트워크당 잃는 2개가 한 번만 발생하므로 사용 가능한 호스트 수도 늘어난다.
