# Basic Routing Concepts

## 개요

- 라우팅의 기본 4단계와, 라우터가 패킷을 실제로 어떻게 다시 만들어 넘기는지를 예시로 따라간다.
- 핵심: 라우터는 **목적지 IP를 보고 → 라우팅 테이블을 찾고 → 가장 가까운 인터페이스로 내보낸다.** 이 과정이 반복될 뿐이다.

## 내용

### 이 레슨을 마치면

- 라우팅의 기초와 **라우팅 테이블**의 동작을 설명할 수 있다.
- 주요 **라우팅 프로토콜**들을 정의하고 무엇을 하는지 말할 수 있다.
- **라우팅 불가 주소 공간(non-routable address space)** 을 식별하고 어떻게 쓰이는지 안다.
- **RFC 체계**와 그것이 인터넷을 어떻게 만들었는지 이해한다.

> 라우팅은 아주 단순하면서 동시에 아주 복잡한 주제다. 오늘날 집중적인 라우팅 이슈는 거의 전적으로 **ISP와 최대 규모 기업들**이 다룬다.

### 라우터와 기본 4단계

- 라우터는 **트래픽의 목적지 주소에 따라 트래픽을 전달하는 네트워크 장치**다.
- 일을 하려면 두 네트워크에 연결돼야 하므로 **최소 두 개의 네트워크 인터페이스**를 갖는다.

1. 라우터가 자신의 인터페이스 중 하나로 **데이터 패킷을 받는다.**
2. 그 패킷의 **목적지 IP를 검사**한다.
3. 그 IP의 **목적지 네트워크를 라우팅 테이블에서 찾는다.**
4. 라우팅 테이블의 추가 정보로 판단해 **원격 네트워크에 가장 가까운 인터페이스로 내보낸다.**

이 단계가 트래픽이 목적지에 닿을 때까지 필요한 만큼 반복된다.

### 예시 1 — 라우터 하나, 네트워크 둘

| 네트워크 | 주소 공간 | 라우터 인터페이스 IP |
|---|---|---|
| Network A | 192.168.1.0/24 | 192.168.1.1 |
| Network B | 10.0.0.0/24 | 10.0.0.254 |

`192.168.1.100`이 `10.0.0.10`으로 패킷을 보낼 때:

1. 보내는 컴퓨터는 `10.0.0.10`이 **자기 로컬 서브넷이 아님**을 안다. 그래서 **게이트웨이(라우터)의 MAC 주소로** 패킷을 보낸다.
2. 라우터의 Network A 인터페이스가 **목적지 MAC이 자기 것임을 보고** 패킷을 받는다.
3. 라우터가 **데이터 링크 계층 캡슐화를 벗겨 내** IP 데이터그램을 남긴다.
4. IP 데이터그램 헤더의 **목적지 IP 필드**를 직접 검사해 `10.0.0.10`을 찾는다.
5. 라우팅 테이블에서 **`10.0.0.0/24`가 맞는 네트워크**이고 **한 홉 거리**임을 확인한다. 직접 연결돼 있으므로 **ARP 테이블에 그 IP의 MAC 주소도 이미 있다.**
6. 라우터가 **새 패킷을 만든다.** 첫 IP 데이터그램의 데이터를 그대로 복제하되 **TTL을 1 줄이고 체크섬을 새로 계산**한다.
7. 이 새 IP 데이터그램을 **새 이더넷 프레임 안에 캡슐화**한다. 이때 **출발지 MAC은 자신의 Network B 인터페이스 MAC**, **목적지 MAC은 `10.0.0.10`의 MAC**으로 설정한다.
8. Network B 인터페이스로 내보내면 데이터가 최종 배달된다.

### 예시 2 — 라우터 둘, 네트워크 셋

- Network C: `172.16.1.0/23` 추가. 두 번째 라우터가 Network B와 C를 연결하며, Network B 쪽 IP는 `10.0.0.1`, Network C 쪽 IP는 `172.16.1.1`이다.
- `192.168.1.100` → `172.16.1.100`:
  1. 로컬이 아니므로 게이트웨이(A–B 라우터)로 보낸다.
  2. 그 라우터가 목적지 `172.16.1.100`을 보고, 라우팅 테이블 조회로 **`172.16.1.0/23`으로 가는 가장 빠른 길은 IP `10.0.0.1`인 다른 라우터를 경유하는 것**임을 안다.
  3. **TTL을 줄이고** `10.0.0.1` 라우터로 보낸다.
  4. 그 라우터는 목적지가 **직접 연결돼 있음**을 알고 최종 목적지로 전달한다.

### 인터넷과의 차이는 규모뿐

- 라우터는 보통 **두 개보다 훨씬 많은 네트워크**에 연결된다.
- 트래픽이 최종 목적지에 닿기까지 **열두 개 이상의 라우터**를 건너는 일도 흔하다.
- 고장에 대비해 **코어 인터넷 라우터들은 메시(mesh) 형태로 연결**되어, 패킷이 갈 수 있는 경로가 여러 개다.
- 그래도 개념은 같다: **목적지 IP 검사 → 라우팅 테이블에서 가장 빠른 경로 판단 → 그 경로로 전달.**

## 요약

- 라우팅 4단계: 수신 → 목적지 IP 검사 → 라우팅 테이블 조회 → 알맞은 인터페이스로 전달.
- 라우터는 패킷을 그대로 넘기지 않고 TTL을 줄이고 체크섬을 다시 계산해 새 이더넷 프레임으로 다시 감싼다.
- 출발지 MAC은 자신의 나가는 인터페이스, 목적지 MAC은 다음 홉의 것으로 바뀐다.
- 인터넷도 같은 원리이며 규모와 메시 구조만 다르다.
