# The Network Layer

## 개요

- **MAC 주소만으로는 규모 확장이 안 되는 이유**를 설명하고, 그 해법으로 네트워크 계층과 **IP(Internet Protocol)** 를 도입한다.

## 내용

### MAC 주소로는 왜 안 되는가

- LAN 안에서는 노드들이 **물리적 MAC 주소**로 통신할 수 있다. 스위치가 각 포트에 연결된 MAC 주소를 빠르게 학습하기 때문에 **소규모에서는 잘 동작한다.**
- 그러나 **MAC 주소 체계는 확장성이 없다.**
  - 지구상의 모든 네트워크 인터페이스가 고유한 MAC 주소를 갖지만, **어떤 체계적인 순서로도 정렬돼 있지 않다.**
  - 특정 MAC 주소가 **지금 지구 어디에 있는지 알 방법이 없다.** 그래서 먼 거리 통신에는 부적합하다.
- 게다가 뒤에 나올 **ARP(Address Resolution Protocol)** 에서 보게 되듯, 노드들이 서로의 물리 주소를 학습하는 방식 자체가 **하나의 네트워크 구간 밖으로는 옮길 수 없는** 방식이다.

### 그래서 네트워크 계층과 IP

- 명백히 다른 해법이 필요하고, 그것이 **네트워크 계층 + 인터넷 프로토콜(IP) + 그에 딸린 IP 주소**다.

### 이 레슨을 마치면

- **IP 주소를 식별**할 수 있다.
- **IP 데이터그램이 이더넷 프레임의 페이로드 안에 어떻게 캡슐화되는지** 설명할 수 있다.
- **IP 데이터그램 헤더의 여러 필드를 정확히 식별하고 설명**할 수 있다.

## 요약

- MAC 주소는 전역 고유하지만 정렬되어 있지 않아 위치를 알 수 없고, 학습 방식도 단일 구간에 갇혀 있다.
- 따라서 거리 확장을 위해 계층적으로 배분되는 IP 주소와 네트워크 계층이 필요하다.
