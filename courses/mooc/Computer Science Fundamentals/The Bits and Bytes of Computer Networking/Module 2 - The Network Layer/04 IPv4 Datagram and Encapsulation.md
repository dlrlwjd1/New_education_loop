# IPv4 Datagram and Encapsulation

## 개요

- 네트워크 계층의 패킷을 **IP 데이터그램(IP datagram)** 이라 하며, **헤더와 페이로드** 두 부분으로 나뉜다.
- 헤더의 각 필드를 순서대로 살펴보고, **캡슐화(encapsulation)** 가 무엇인지 정리한다.

## 내용

### IP 데이터그램 헤더 필드

| 필드 | 크기 | 설명 |
|---|---|---|
| **Version** | 4비트 | 사용 중인 IP 버전. 가장 흔한 것은 **IPv4**, **IPv6**도 빠르게 확산 중 |
| **Header Length** | 4비트 | 헤더 전체 길이. IPv4에서는 **거의 항상 20바이트**이며 **20바이트가 최소 길이**다 |
| **Service Type** | 8비트 | **QoS(Quality of Service)** 관련 상세를 지정. 라우터가 **어떤 데이터그램이 더 중요한지 판단**할 수 있게 하는 서비스가 있다는 점이 핵심 |
| **Total Length** | 16비트 | 이 IP 데이터그램의 **전체 길이** |
| **Identification** | 16비트 | **메시지들을 묶는 그룹 번호** |
| **Flag** | — | 데이터그램의 **분할(fragmentation) 허용 여부**, 또는 **이미 분할되었음**을 표시 |
| **Fragmentation Offset** | — | 수신 측이 분할된 조각들을 **올바른 순서로 재조립**할 때 쓰는 값 |
| **TTL (Time To Live)** | 8비트 | 버려지기 전까지 **거칠 수 있는 라우터 홉 수** |
| **Protocol** | 8비트 | 사용 중인 **전송 계층 프로토콜**(가장 흔한 것은 TCP, UDP) |
| **Header Checksum** | — | **IP 헤더 전체 내용의 체크섬**. 이더넷 체크섬과 유사하게 동작 |
| **Source IP Address** | 32비트 | 출발지 IP |
| **Destination IP Address** | 32비트 | 목적지 IP |
| **IP Options** | 가변(선택) | 데이터그램의 특수 특성 설정. **주로 테스트 목적** |
| **Padding** | 가변 | **0의 나열.** IP Options가 선택적이고 길이가 가변이므로, **헤더 전체 크기를 맞추기 위해** 채운다 |

### 최대 크기와 분할(Fragmentation)

- Total Length 필드가 **16비트**이므로, **단일 데이터그램의 최대 크기는 65,535** (16비트로 표현 가능한 최대값)다.
- 보낼 데이터가 데이터그램 하나에 안 들어가면 IP 계층이 **여러 개의 개별 패킷으로 쪼갠다.**
- 이때 **Identification 필드**가 쓰인다. 수신 측은 **같은 값을 가진 패킷들이 같은 전송의 일부**임을 이해한다.
- **분할(fragmentation)** 은 하나의 IP 데이터그램을 **여러 개의 더 작은 데이터그램으로 쪼개는 과정**이다.
- 대부분의 네트워크는 허용 데이터그램 크기 설정이 비슷하지만 다를 수도 있다. **큰 크기를 허용하는 네트워크에서 작은 크기를 허용하는 네트워크로 넘어가야 하면 분할이 필요하다.**

### TTL이 필요한 이유

- 데이터그램이 새 라우터에 도달할 때마다 **그 라우터가 TTL을 1 감소**시킨다.
- **0이 되면** 라우터는 더 이상 전달할 필요가 없다는 것을 안다.
- 주된 목적: **라우팅 설정 오류로 무한 루프가 생겼을 때**, 데이터그램이 영원히 목적지를 찾아 헤매지 않게 하는 것.
- 무한 루프의 예: **라우터 A는 다음 홉이 라우터 B라고 생각하고, 라우터 B는 다음 홉이 라우터 A라고 생각하는** 상황.
- 참고: **TTL이 라우터마다 다시 계산되므로 헤더 체크섬도 필연적으로 함께 바뀐다.**

### 캡슐화 (Encapsulation)

- 이더넷 프레임을 해부할 때 **데이터 페이로드 구간**이 있었다. **바로 그 자리에 IP 데이터그램 전체가 들어간다.** 이 과정을 **캡슐화**라 한다.
- IP 데이터그램에도 **페이로드 구간**이 있는데, **그 내용물이 TCP 또는 UDP 패킷 전체**다.

## 예시

```
[ 이더넷 프레임 ]
  헤더 | 페이로드 = [ IP 데이터그램 ]
                      헤더 | 페이로드 = [ TCP 또는 UDP 패킷 전체 ]
                   | FCS
```

> 각 계층이 그 위 계층을 위해 필요하다는 것이 이 그림에서 드러난다.

## 요약

- 네트워크 계층 패킷 = IP 데이터그램. 헤더(최소 20바이트) + 페이로드.
- Total Length가 16비트여서 최대 크기는 65,535이고, 초과하면 분할하며 Identification으로 묶는다.
- TTL은 홉마다 1씩 줄어 무한 루프를 방지하고, 그래서 헤더 체크섬도 홉마다 재계산된다.
- 캡슐화: 이더넷 페이로드 = IP 데이터그램, IP 페이로드 = TCP/UDP 패킷.
