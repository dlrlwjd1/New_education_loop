# Routing Tables

## 개요

- 라우팅 테이블의 **기본 4개 열**: 목적지 네트워크 / 다음 홉 / 총 홉 수 / 인터페이스.
- 라우터의 make·class에 따라 테이블은 천차만별이지만 **공통점은 이 네 가지**다.

## 내용

### 역사와 현재

- 최초의 라우터는 그냥 **그 시절의 일반 컴퓨터**였다. 네트워크 인터페이스 두 개로 두 네트워크를 잇고, **수동으로 갱신하는 라우팅 테이블**을 가졌다.
- 실제로 **오늘날 모든 주요 운영체제도 데이터를 보내기 전에 참조하는 라우팅 테이블을 갖고 있다.**
- 네트워크 인터페이스 두 개짜리 컴퓨터와 수동 라우팅 테이블만 있으면 **지금도 직접 라우터를 만들 수 있다.**

### 열 1 — 목적지 네트워크 (Destination network)

- 라우터가 **알고 있는 각 네트워크마다 한 행**이 있다.
- 내용은 **원격 네트워크의 정의**, 즉 **네트워크 ID와 넷마스크**다.
  - CIDR 표기로 한 열에 담기도 하고, 네트워크 ID와 넷마스크를 **별도 열**로 두기도 한다. 개념은 같다.
- 라우터는 이 정의로 **어떤 IP 주소들이 그 네트워크에 살 수 있는지** 안다. 패킷이 들어오면 목적지 IP를 검사해 **어느 네트워크에 속하는지** 판단한다.
- 라우팅 테이블에는 보통 **명시적 항목이 없는 IP 전부에 매칭되는 catch-all 항목**이 있다.

### 열 2 — 다음 홉 (Next hop)

- 해당 목적지 네트워크로 갈 데이터를 **받아야 할 다음 라우터의 IP 주소**.
- 또는 **그 네트워크가 직접 연결되어 추가 홉이 필요 없다**는 표시일 수도 있다.

### 열 3 — 총 홉 수 (Total hops)

> 라우팅과 라우팅 테이블을 이해하는 데 **결정적인 부분**이다.

- 인터넷 같은 복잡한 네트워크에서 A에서 B로 가는 **경로는 여러 개**다.
- 라우터는 적시 배달을 위해 **항상 가장 짧은 경로를 고르려** 한다.
- 그런데 **가장 짧은 경로는 시간이 지나며 바뀔 수 있고, 때로는 급격히 바뀐다.**
  - 중간 라우터가 죽거나, 링크가 끊기거나, 새 라우터가 들어오거나, **트래픽 혼잡으로 특정 경로가 너무 느려질 수** 있다.
- 그래서 **각 다음 홉과 각 목적지 네트워크마다 현재 거리가 얼마인지 추적**해야 한다.
- 그래야 이웃 라우터에게서 갱신된 정보를 받았을 때, **지금 알고 있는 것이 최선인지 아니면 더 나은 새 경로가 생겼는지** 판단할 수 있다.

### 열 4 — 인터페이스 (Interface)

- 목적지 네트워크에 해당하는 트래픽을 **자신의 어느 인터페이스로 내보내야 하는지**.

### 규모

- 대부분의 경우 라우팅 테이블은 꽤 단순하다.
- 인상적인 것은 **많은 코어 인터넷 라우터의 라우팅 테이블에 수백만 개의 행**이 있고, **라우터를 지나는 모든 패킷 하나하나마다 이 테이블을 참조해야 한다**는 점이다.

## 예시

| 목적지 네트워크 | 다음 홉 | 총 홉 수 | 인터페이스 |
|---|---|---|---|
| 10.0.0.0/24 | 직접 연결 | 1 | Interface 2 |
| 172.16.1.0/23 | 10.0.0.1 | 2 | Interface 2 |
| 0.0.0.0/0 (catch-all) | 192.0.2.1 | — | Interface 1 |

## 요약

- 라우팅 테이블의 기본 4열은 목적지 네트워크, 다음 홉, 총 홉 수, 인터페이스다.
- 목적지 네트워크는 네트워크 ID + 넷마스크로 정의되고 catch-all 항목이 보통 존재한다.
- 홉 수를 추적해야 이웃에게서 온 갱신 정보와 비교해 더 나은 경로를 채택할 수 있다.
- 코어 라우터는 수백만 행을 모든 패킷마다 조회한다.
