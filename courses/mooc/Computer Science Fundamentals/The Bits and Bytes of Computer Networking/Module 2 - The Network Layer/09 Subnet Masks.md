# Subnet Masks

## 개요

- 네트워크 ID·호스트 ID에 더해 세 번째 개념인 **서브넷 ID(subnet ID)** 를 도입한다.
- 서브넷 ID는 **서브넷 마스크(subnet mask)** 로 계산한다. 서브넷 마스크도 IP처럼 **32비트 수**이며 4옥텟 십진으로 쓴다.
- **슬래시 표기(/27 같은)** 는 마스크의 1의 개수를 뜻한다.

## 내용

### 세 개의 ID

- 서브넷이 없는 세계에서는 32비트 중 일정 비트가 **네트워크 ID**, 나머지가 **호스트 ID**다.
- 서브넷이 있는 세계에서는 **원래 호스트 ID였을 비트 일부를 서브넷 ID로** 쓴다.
- 세 ID가 하나의 IP 주소로 표현되므로, **하나의 32비트 수로 여러 네트워크를 가로질러 정확히 배달**할 수 있다.

전달 과정에서 각 ID의 역할:

| 단계 | 보는 것 | 하는 일 |
|---|---|---|
| 인터넷 수준 (코어 라우터) | **네트워크 ID** | 해당 네트워크의 게이트웨이 라우터로 보냄 |
| 게이트웨이 라우터 | **서브넷 ID** | 목적지 장비 또는 경로상 다음 라우터로 보냄 |
| 마지막 라우터 | **호스트 ID** | 의도된 수신 장비에 배달 |

### 서브넷 마스크의 구조

- 서브넷 마스크는 **두 구간으로 이루어진 이진수**다. 앞부분은 **1의 나열(마스크 자체)**, 그 뒤는 **0의 나열**이다.
- **1인 부분** = 호스트 ID를 계산할 때 **무시해도 되는 부분**.
- **0인 부분** = **남겨 둘 부분**.
- 마스크(1인 부분)의 목적은 라우터에게 **IP 주소의 어느 부분이 서브넷 ID인지** 알려 주는 것이다.

### 이진수로 보기

`9.100.100.100`을 이진수로 바꾸면:

- 숫자 **9**는 이진수로 `1001`인데, 옥텟은 8비트여야 하므로 앞을 0으로 채워 **`00001001`**.
- 숫자 **100**은 8비트로 **`01100100`**.

서브넷 마스크 **255.255.255.0** → **1이 24개, 그 뒤 0이 8개**.

계산 방법:

1. `9.100.100.100`은 클래스 A이므로 **네트워크 ID는 첫 옥텟**이다.
2. 남은 세 옥텟을 서브넷 마스크와 **이진수로 나란히 놓는다.**
3. 남은 옥텟 중 **마스크의 대응 자리가 1인 부분 → 서브넷 ID**.
4. 남은 옥텟 중 **마스크의 대응 자리가 0인 부분 → 호스트 ID**.

### 서브넷 크기와 "총 개수 -2"

- **서브넷의 크기는 전적으로 서브넷 마스크가 결정한다.**
- 마스크가 `255.255.255.0`이면, 네트워크·서브넷 ID의 크기와 무관하게 **마지막 옥텟만 호스트 ID로 쓸 수 있다.** 8비트는 **0~255, 총 256개**를 표현한다.
- 그런데 **서브넷이 실제로 담을 수 있는 호스트 ID는 보통 총 개수보다 2개 적다.**
  - **0은 일반적으로 쓰지 않고**, **255는 보통 그 서브넷의 브로드캐스트 주소로 예약**되기 때문이다.
  - 즉 실제 할당 가능한 것은 **1~254**.
- 다만 **말할 때는 전체 수로 부른다.** 8비트 호스트 ID 공간은 (2개를 못 쓴다는 것을 알면서도) **254개가 아니라 256개 주소가 있다**고 말한다. 그 주소들도 여전히 IP 주소이기 때문이다.

### 옥텟 경계에 걸치지 않는 마스크

- **255.255.255.224** → **1이 27개, 0이 5개**.
- 호스트 ID 공간이 **5비트 = 총 32개 주소**.

### 슬래시 표기

- `255.255.255.224`는 1이 27개이므로 **`/27`** 로 줄여 쓴다.
- 전체는 **`9.100.100.100/27`** 로 표기한다.
- **두 표기 중 어느 쪽이 더 흔하다고 할 수 없으므로 둘 다 이해해야 한다.**

## 예시

```
IP        9.100.100.100
마스크     255.255.255.0    = 11111111 11111111 11111111 00000000  (/24)
                              └── 1: 무시 ──┘ └ 0: 호스트 ID ┘

마스크     255.255.255.224  = 11111111 11111111 11111111 11100000  (/27)
                                                         └─┬─┘└┬┘
                                                    서브넷 ID  호스트 5비트 → 32개 주소
```

## 요약

- 서브넷 ID는 원래 호스트 ID였던 비트 일부를 떼어 만든다.
- 서브넷 마스크는 32비트이며 앞의 1들이 "무시할 부분", 뒤의 0들이 "호스트 ID로 남길 부분"을 가리킨다.
- 서브넷 크기는 마스크가 결정하며, 실제 할당 가능한 호스트는 보통 총 개수보다 2개 적다(0과 브로드캐스트 제외).
- /24, /27 같은 슬래시 표기는 마스크의 1의 개수이며, 점 십진 표기와 함께 둘 다 알아야 한다.
