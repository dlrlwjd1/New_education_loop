# Exterior Gateways, Autonomous Systems, and the IANA

## 개요

- **외부 게이트웨이 프로토콜(exterior gateway protocol)** 은 **자율 시스템의 가장자리(edge)** 를 대표하는 라우터들 사이에서 데이터를 주고받는다.
- **IANA**는 IP 주소 할당과 **ASN(자율 시스템 번호)** 할당을 관리하는 비영리 기관이다.

## 내용

### 외부 게이트웨이 프로토콜

- 내부 게이트웨이 프로토콜로 데이터를 공유하는 라우터들은 **모두 같은 조직의 통제 아래** 있다.
- **서로 다른 조직 사이**에서 정보를 공유해야 할 때 외부 게이트웨이 프로토콜을 쓴다.
- 이것이 **오늘날 인터넷이 지금처럼 동작하는 데 핵심**이다.

### 인터넷은 자율 시스템들의 거대한 메시

- 최상위 수준에서 **코어 인터넷 라우터는 트래픽을 제대로 전달하기 위해 자율 시스템들을 알아야** 한다.
- 자율 시스템은 **알려져 있고 정의된 네트워크들의 모음**이므로, **자율 시스템의 엣지 라우터까지 데이터를 보내는 것이 코어 인터넷 라우터의 최우선 목표**다.

### IANA (Internet Assigned Numbers Authority)

- **IP 주소 할당 같은 일을 관리하는 비영리 조직**이다.
- 이런 문제를 다루는 **단일 권위 기관 없이는 인터넷이 기능할 수 없다.** 그렇지 않으면 누구나 원하는 IP 공간을 쓰려 들어 **온라인이 완전히 혼돈**에 빠진다.
- IANA는 IP 주소 할당과 함께 **ASN(Autonomous System Number) 할당**도 책임진다.

### ASN

- **개별 자율 시스템에 부여되는 번호**다.
- IP 주소처럼 **32비트 수**이지만, IP와 달리 **읽기 좋은 조각으로 나누지 않고 하나의 십진수로** 표기한다. 이유는 두 가지다.

1. **IP 주소는 네트워크 ID 부분과 호스트 ID 부분을 표현해야** 하므로 8비트씩 네 구간으로 나누는 편이 낫다(특히 주소 클래스가 지배하던 시절에는 더욱). 반면 **ASN은 더 많은 네트워크나 호스트를 표현하기 위해 바뀔 필요가 전혀 없다.** 그 ASN이 무엇을 대표하는지 아는 것은 **코어 인터넷 라우팅 테이블**이 갱신되면 되는 문제다.
2. **ASN은 IP 주소보다 사람이 훨씬 덜 들여다본다.** `9.100.100.100`을 보고 `9.0.0.0/8`이 IBM 소유임을 아는 것은 유용하지만, ASN은 **자율 시스템 전체**를 대표하므로 **AS 19604가 IBM에 속한다는 사실만 찾아볼 수 있으면 충분**하다 — ISP에서 일하게 되지 않는 한.

> 외부 게이트웨이 프로토콜의 더 자세한 동작은 대부분의 IT 종사자에게는 범위 밖이지만, **자율 시스템·ASN·코어 라우터가 그 사이로 트래픽을 라우팅하는 방식**의 기초는 인터넷의 기본 구성 요소를 이해하는 데 중요하다.

## 요약

- 외부 게이트웨이 프로토콜은 조직(자율 시스템)의 경계를 넘는 정보 교환용이다.
- 코어 인터넷 라우터의 최우선 목표는 목적지 자율 시스템의 엣지 라우터까지 보내는 것이다.
- IANA가 IP 주소와 ASN 할당을 관장하며, 이런 단일 권위 없이는 인터넷이 성립하지 않는다.
- ASN은 32비트지만 하나의 십진수로 표기하며, 사람이 자주 볼 일이 없기 때문이다.
