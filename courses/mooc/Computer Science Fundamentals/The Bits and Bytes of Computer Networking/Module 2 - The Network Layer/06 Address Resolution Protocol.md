# Address Resolution Protocol

## 개요

- **ARP(Address Resolution Protocol)** 는 **특정 IP 주소를 가진 노드의 하드웨어(MAC) 주소를 알아내는** 프로토콜이다.
- 데이터 링크 계층의 MAC 주소와 네트워크 계층의 IP 주소를 **이어 주는 다리**다.

## 내용

### 왜 필요한가

- IP 데이터그램이 완성되면 **이더넷 프레임 안에 캡슐화**되어야 한다.
- 그러려면 송신 장치가 **이더넷 프레임 헤더를 완성할 목적지 MAC 주소**를 알아야 한다.

### ARP 테이블

- 거의 모든 네트워크 연결 장치는 **로컬 ARP 테이블**을 유지한다.
- **ARP 테이블** = IP 주소 목록과 그에 연결된 MAC 주소들의 목록.

### 동작 순서

`10.20.30.40`으로 데이터를 보내려는데 ARP 테이블에 항목이 없는 경우:

1. 보내려는 노드가 **MAC 브로드캐스트 주소(all F)** 로 **브로드캐스트 ARP 메시지**를 보낸다.
2. 이 브로드캐스트 ARP 메시지는 **로컬 네트워크의 모든 컴퓨터에 전달**된다.
3. IP `10.20.30.40`을 할당받은 네트워크 인터페이스가 이 브로드캐스트를 받으면 **ARP 응답(ARP response)** 을 돌려보낸다.
4. 이 응답에는 **해당 네트워크 인터페이스의 MAC 주소**가 담겨 있다.
5. 이제 송신 컴퓨터는 **목적지 하드웨어 주소 필드에 넣을 MAC 주소**를 알게 되고, 이더넷 프레임을 완성해 전송할 수 있다.
6. 송신 측은 보통 이 IP를 **로컬 ARP 테이블에 저장**해, 다음에 같은 IP와 통신할 때 **다시 브로드캐스트하지 않아도 되게** 한다.

### 만료

- **ARP 테이블 항목은 보통 짧은 시간이 지나면 만료된다.** 네트워크의 변경 사항이 반영되도록 하기 위해서다.

## 예시

```
[전송 요청] 10.20.30.40 으로 보내고 싶다
   ↓ ARP 테이블에 없음
[ARP 브로드캐스트] → 목적지 MAC = FF:FF:FF:FF:FF:FF (로컬 전체)
   ↓
[ARP 응답] 10.20.30.40 을 가진 인터페이스가 자기 MAC을 회신
   ↓
[이더넷 프레임 완성] 목적지 MAC 채워서 전송 + ARP 테이블에 캐시(짧은 TTL)
```

## 요약

- ARP는 IP 주소 → MAC 주소를 알아내는 프로토콜이다.
- 모르면 all F 브로드캐스트로 묻고, 해당 인터페이스가 자기 MAC으로 답한다.
- 결과는 로컬 ARP 테이블에 캐시되며, 변화 반영을 위해 짧은 시간 뒤 만료된다.
