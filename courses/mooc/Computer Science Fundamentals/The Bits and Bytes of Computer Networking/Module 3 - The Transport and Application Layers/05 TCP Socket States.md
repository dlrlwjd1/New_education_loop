# TCP Socket States

## 개요

- **소켓(socket)** = 잠재적 TCP 연결의 **끝점(endpoint)이 실제로 구현된 것(instantiation)**.
- 포트는 가상의 서술적 개념이지만, **소켓은 실제 프로그램이 만들어야** 존재한다.
- 소켓 상태를 읽을 줄 알면 **네트워크 연결 문제 진단**에 도움이 된다.

## 내용

### 소켓 vs 포트

- **instantiation** = 다른 곳에 정의된 것을 **실제로 구현한 것**.
- TCP 소켓은 **실제 프로그램이 있어야 만들어진다.**
- 반면 **포트는 더 가상적이고 서술적인 것**이다.
- 그래서: **어떤 포트로든 트래픽을 보낼 수는 있지만, 그 포트에 프로그램이 소켓을 열어 두었을 때만 응답을 받는다.**

### 주요 소켓 상태

| 상태 | 의미 | 어느 쪽에서 보이나 |
|---|---|---|
| **LISTEN** | TCP 소켓이 준비되어 **들어오는 연결을 듣고 있음** | **서버 측만** |
| **SYN_SENT** | **동기화 요청을 보냈으나** 연결이 아직 수립되지 않음 | **클라이언트 측만** |
| **SYN_RECEIVED** | LISTEN 상태였던 소켓이 **동기화 요청을 받아 SYN/ACK를 돌려보냈으나 클라이언트의 마지막 ACK를 아직 못 받음** | **서버 측만** |
| **ESTABLISHED** | TCP 연결이 **정상 동작 중**이며 양쪽이 자유롭게 데이터를 주고받을 수 있음 | **양쪽 모두** |
| **FIN_WAIT** | **FIN을 보냈으나** 상대의 해당 ACK를 아직 받지 못함 | 양쪽 모두 |
| **CLOSE_WAIT** | **TCP 계층에서는 연결이 닫혔지만**, 소켓을 연 애플리케이션이 **아직 소켓을 놓아주지 않음** | 양쪽 모두 |
| **CLOSED** | 연결이 **완전히 종료**되어 더 이상 통신 불가 | 양쪽 모두 |

> ESTABLISHED 이후의 상태들은 모두 **클라이언트·서버 양쪽에서** 볼 수 있다.

### 주의 — 상태 이름은 OS마다 다르다

- 위에 없는 다른 TCP 소켓 상태도 존재한다.
- **소켓 상태와 그 이름은 운영체제마다 다를 수 있다.** 왜냐하면 **TCP 정의 자체의 범위 밖**에 있기 때문이다.
- **TCP 프로토콜 자체는 보편적**이다. TCP를 말하는 모든 장치가 정확히 같은 방식으로 해야 통신이 성공한다.
- 하지만 **운영체제 수준에서 소켓 상태를 어떻게 서술할지는 그만큼 보편적이지 않다.**
- **TCP 계층 문제를 진단할 때는 작업 중인 시스템의 정확한 소켓 상태 정의를 반드시 확인**해야 한다.

## 요약

- 소켓은 프로그램이 실제로 연 끝점이고, 포트는 그 주소를 가리키는 번호일 뿐이다.
- 프로그램이 소켓을 열어 두지 않은 포트로 보낸 트래픽에는 응답이 없다.
- LISTEN/SYN_RECEIVED는 서버 측, SYN_SENT는 클라이언트 측에서만 보인다.
- 소켓 상태 이름은 TCP 표준 밖이므로 OS별 정의를 확인해야 한다.
