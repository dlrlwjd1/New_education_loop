# The Transport Layer

## 개요

- 전송 계층의 핵심 기능: **멀티플렉싱·디멀티플렉싱**, **장기 연결 수립**, **오류 검사와 데이터 검증을 통한 무결성 확보**.
- 멀티플렉싱을 가능하게 하는 장치가 **포트(port)** 이며, IP와 포트를 합쳐 쓴 것이 **소켓 주소(socket address)** 다.

## 내용

### 멀티플렉싱과 디멀티플렉싱

- **이 능력이 전송 계층을 다른 모든 계층과 구별짓는다.**
- **멀티플렉싱(multiplexing)**: 네트워크의 노드가 **여러 다른 수신 서비스로 트래픽을 보낼 수 있는** 능력.
- **디멀티플렉싱(demultiplexing)**: 같은 개념의 수신 측 버전. **같은 노드로 향한 트래픽을 받아 알맞은 수신 서비스로 전달**하는 것.
- 전송 계층은 이 둘을 **포트를 통해** 처리한다.

### 포트

> **포트(port)** = 네트워크에 연결된 컴퓨터에서 **돌아가는 특정 서비스로 트래픽을 보내기 위해 쓰는 16비트 수**.

- **서버(서비스)** = 데이터 요청을 기다리며 돌아가는 프로그램. **클라이언트** = 그 데이터를 요청하는 프로그램.
- 서로 다른 네트워크 서비스는 **각자 특정 포트에서 들어오는 요청을 듣고(listen)** 있다.

| 서비스 | 전통적 포트 |
|---|---|
| **HTTP** (암호화되지 않은 웹 트래픽) | **80** |
| **FTP** (File Transfer Protocol) | **21** |

- FTP는 한 컴퓨터에서 다른 컴퓨터로 파일을 옮기는 **오래된 방식**이지만 **오늘날에도 여전히 쓰인다.**

### 소켓 주소

- 포트는 보통 **IP 주소 뒤에 콜론을 붙여** 표기한다.
- 예: `10.1.1.100:80` — 이렇게 쓴 것을 **소켓 주소(socket address)** 또는 **소켓 번호(socket number)** 라 한다.

## 예시

같은 IP `10.1.1.100`에서 여러 서비스가 동시에 동작하는 경우:

```
10.1.1.100:80   → 웹 서버 (HTTP)
10.1.1.100:21   → FTP 서버
```

**소규모 사업장의 IT 지원 현장**에서는 **서버 한 대가 사업에 필요한 거의 모든 애플리케이션을 호스팅**하는 일이 흔하다 — 사내 웹사이트, 회사 메일 서버, 파일 공유용 파일 서버, 네트워크 프린터용 프린트 서버 등 거의 무엇이든. **이것이 가능한 이유가 멀티플렉싱·디멀티플렉싱과 주소 체계에 포트가 추가된 덕분**이다.

## 요약

- 전송 계층만이 멀티플렉싱·디멀티플렉싱을 한다.
- 포트는 16비트 수로, 어느 서비스로 보낼지를 가른다. HTTP 80, FTP 21.
- IP:포트 형태를 소켓 주소라 한다.
- 서버 한 대가 여러 서비스를 동시에 제공할 수 있는 근거가 바로 포트다.
