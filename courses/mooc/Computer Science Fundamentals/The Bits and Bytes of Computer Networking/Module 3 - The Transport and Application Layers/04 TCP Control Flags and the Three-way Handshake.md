# TCP Control Flags and the Three-way Handshake

## 개요

- TCP는 **연결을 수립해 긴 세그먼트 사슬**을 보낸다. 개별 패킷만 보내는 하위 계층(IP, 이더넷)과 대비된다.
- 연결 수립은 **6개의 TCP 제어 플래그**를 **아주 특정한 순서**로 사용해 이루어진다.
- 수립은 **3-way handshake**, 종료는 **4-way handshake**.

## 내용

### 6개의 TCP 제어 플래그

TCP 헤더에 나타나는 순서대로 (사용 빈도나 중요도 순이 아님):

| 플래그 | 뜻 | 값이 1이면 |
|---|---|---|
| **URG** | urgent | 이 세그먼트가 **긴급**하며 Urgent Pointer 필드에 더 많은 정보가 있음. **널리 채택된 적이 없고 보통 보이지 않는다** |
| **ACK** | acknowledged | **확인 응답 번호(acknowledgment number) 필드를 검사해야 함** |
| **PSH** | push | 송신 장치가 수신 장치에게 **현재 버퍼에 있는 데이터를 가능한 한 빨리 애플리케이션으로 밀어 올리라**고 요청 |
| **RST** | reset | 한쪽이 **누락되거나 잘못된 세그먼트들로부터 제대로 회복하지 못했음.** "무슨 말인지 조합할 수가 없다. 처음부터 다시 하자"는 뜻 |
| **SYN** | synchronize | **TCP 연결을 처음 수립할 때** 사용. 수신 측이 **시퀀스 번호 필드를 검사하도록** 함 |
| **FIN** | finish | 송신 컴퓨터가 **더 보낼 데이터가 없으며 연결을 닫아도 된다**는 뜻 |

### 버퍼와 PSH

- **버퍼(buffer)** = 데이터를 다른 곳으로 보내기 전에 일정량을 어딘가에 담아 두는 기법.
- TCP에서는 **큰 덩어리 데이터를 더 효율적으로 보내는 데** 쓰인다. 일정량을 버퍼에 모아 두면 **기다리는 프로그램에게 더 의미 있는 덩어리**를 전달할 수 있다.
- 하지만 **아주 적은 정보를 보내면서 듣고 있는 프로그램이 즉시 응답해 주기를 바라는 경우**가 있다. 그때 쓰는 것이 push 플래그다.

### 3-way handshake (연결 수립)

컴퓨터 A(송신) → 컴퓨터 B(수신):

1. **A → B: SYN**
   "연결을 맺자. 내 시퀀스 번호 필드를 봐라. 이 대화가 어디서 시작하는지 알 수 있게."
2. **B → A: SYN + ACK**
   "좋다, 연결을 맺자. 그리고 네 시퀀스 번호를 확인했다."
3. **A → B: ACK**
   "네 확인을 확인했다. 데이터를 보내기 시작하자."

- 이 **SYN → SYN/ACK → ACK** 교환은 **어디서든 TCP 연결이 수립될 때마다 매번 일어나며**, 워낙 유명해서 **3-way handshake**라는 별명이 있다.
- **핸드셰이크** = 두 장치가 **같은 프로토콜을 말하고 서로 이해할 수 있음을 확인하는 방법**.

### 연결 수립 이후

- 3-way handshake가 끝나면 TCP 연결이 수립되고, **A와 B 모두 원하는 데이터를 자유롭게** 보낼 수 있다.
- 양쪽이 서로에게 SYN/ACK 쌍을 보냈으므로, 이 상태의 TCP 연결은 **풀 듀플렉스(full duplex)** 로 동작한다.
- 어느 방향으로 보낸 세그먼트든 **ACK 필드가 설정된 TCP 세그먼트로 응답**되어야 한다. 그래야 상대가 **무엇이 수신됐는지 항상 알 수** 있다.

### 4-way handshake (연결 종료)

1. 닫을 준비가 된 컴퓨터가 **FIN**을 보낸다.
2. 상대가 **ACK**로 확인한다.
3. 상대도 닫을 준비가 됐다면(거의 항상 그렇다) **FIN**을 보낸다.
4. 다시 **ACK**로 응답한다.

- 이론상으로는 **한쪽만 연결을 닫아 심플렉스(simplex) 모드로 TCP 연결이 열려 있을 수도** 있지만, **자주 마주치는 상황은 아니다.**

## 예시

```
연결 수립 (3-way)          연결 종료 (4-way)
A ──── SYN ────→ B         A ──── FIN ────→ B
A ←── SYN/ACK ── B         A ←─── ACK ──── B
A ──── ACK ────→ B         A ←─── FIN ──── B
                            A ──── ACK ────→ B
```

## 요약

- 6개 플래그: URG, ACK, PSH, RST, SYN, FIN. 이 중 URG는 사실상 사용되지 않는다.
- 연결 수립은 SYN → SYN/ACK → ACK의 3-way handshake다.
- 수립 후에는 full duplex이며 모든 세그먼트가 ACK로 응답된다.
- 종료는 FIN/ACK를 양방향으로 주고받는 4-way handshake다.
