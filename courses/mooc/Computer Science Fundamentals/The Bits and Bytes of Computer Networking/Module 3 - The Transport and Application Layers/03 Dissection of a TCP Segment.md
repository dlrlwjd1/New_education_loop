# Dissection of a TCP Segment

## 개요

- 캡슐화의 세 번째 층: **이더넷 프레임 ⊃ IP 데이터그램 ⊃ TCP 세그먼트**.
- TCP 세그먼트 = **TCP 헤더 + 데이터 섹션**(애플리케이션 계층이 데이터를 넣는 페이로드 영역).

## 내용

### TCP 헤더 필드

| 필드 | 크기 | 설명 |
|---|---|---|
| **Source Port** | — | **임시 포트(ephemeral port)** 중에서 고른 높은 번호의 포트. **나가는 여러 연결을 구분**하기 위해 필요 |
| **Destination Port** | — | 트래픽이 향하는 **서비스의 포트** |
| **Sequence Number** | 32비트 | 이 세그먼트가 **TCP 세그먼트들의 순서 중 몇 번째**인지 추적 |
| **Acknowledgment Number** | — | **다음에 올 것으로 기대되는 세그먼트의 번호** |
| **Data Offset** | 4비트 | 이 세그먼트의 **TCP 헤더 길이**. 수신 장치가 **실제 데이터 페이로드가 어디서 시작하는지** 알기 위함 |
| **TCP 제어 플래그** | 6비트 | 여섯 개의 제어 플래그용으로 예약 |
| **TCP Window** | 16비트 | **응답(ACK)이 요구되기 전에 보낼 수 있는 시퀀스 번호의 범위** |
| **Checksum** | 16비트 | IP·이더넷의 체크섬과 동일하게 동작 |
| **Urgent Pointer** | — | 제어 플래그 중 하나와 함께 쓰여 **더 중요한 세그먼트를 지목**. **실제로 채택된 적이 거의 없어 현대 네트워킹에서는 보기 어렵다** |
| **Options** | — | 역시 실무에서는 드물게 쓰이며, **더 복잡한 흐름 제어 프로토콜**에 가끔 사용 |
| **Padding** | — | **0의 나열.** 데이터 페이로드가 기대되는 위치에서 시작하도록 보장 |

### 출발지 포트가 왜 필요한가

- 목적지 포트 80은 **트래픽이 특정 IP의 웹 서버에 도달하게** 하는 데 필요하다.
- 마찬가지로 **출발지 포트는 웹 서버가 응답할 때, 원래 요청한 컴퓨터가 그 데이터를 실제로 요청한 프로그램에게 전달할 수 있게** 하는 데 필요하다.
- 그래서 웹페이지 요청에 대한 응답이 **워드프로세서가 아니라 웹 브라우저**에게 도착한다.

### 시퀀스 번호가 필요한 이유

- 프로토콜 스택 아래쪽에는 **한 번에 보낼 수 있는 크기의 한계**가 있다. **이더넷 프레임은 보통 1,518바이트로 제한**된다.
- 하지만 보내야 할 데이터는 대개 그보다 훨씬 크다.
- 그래서 **전송 계층에서 TCP가 데이터를 여러 세그먼트로 쪼갠다.**
- 헤더의 시퀀스 번호는 **이 세그먼트가 여럿 중 몇 번째인지 추적**한다.

### 시퀀스 번호와 확인 응답 번호 읽는 법

> 시퀀스 번호 1 + 확인 응답 번호 2 = **"이건 1번 세그먼트이고, 다음은 2번을 기대한다"**

### TCP는 확인 응답에 크게 의존한다

- TCP Window가 존재하는 이유: **기대한 데이터가 실제로 수신되고 있는지 확인**하고, **수신되지 않는 데이터를 보내느라 시간을 낭비하지 않기** 위해서다.

### 체크섬

- 세그먼트 전체가 수신되면 **세그먼트 전체에 걸쳐 체크섬을 계산해 헤더의 체크섬과 비교**한다. 도중에 유실·손상된 데이터가 없는지 확인하기 위함이다.

## 예시

```
[ 이더넷 프레임 ]
  └ 페이로드 = [ IP 데이터그램 ]
                 └ 페이로드 = [ TCP 세그먼트 ]
                                ├ TCP 헤더
                                └ 데이터 섹션 ← 애플리케이션 계층 데이터
```

## 요약

- TCP 세그먼트는 IP 데이터그램의 페이로드이며, 헤더와 데이터 섹션으로 나뉜다.
- 출발지 포트(임시 포트)는 응답이 올바른 프로그램에 돌아가게 하고, 목적지 포트는 올바른 서비스로 보낸다.
- 이더넷 프레임 크기 한계 때문에 데이터를 쪼개며, 시퀀스 번호로 순서를 추적하고 확인 응답 번호로 다음 기대값을 알린다.
- Urgent Pointer와 Options는 현실에서 거의 쓰이지 않지만 헤더 구성은 알아 둬야 한다.
