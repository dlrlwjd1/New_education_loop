# The Application Layer

## 개요

- 마지막 계층인 **애플리케이션 계층**에서는 실제 애플리케이션들이 데이터를 주고받는다.
- 다른 계층과 달리 **프로토콜이 매우 많고 다양**하다. 대신 **애플리케이션 종류별로 표준화**되어 있다.

## 내용

### 여기까지 온 길

| 계층 | 배운 것 |
|---|---|
| 물리 | 전기·광 신호를 처리해 케이블로 통신을 보내는 방법 |
| 데이터 링크 | 이더넷으로 개별 컴퓨터끼리 주소를 지정하고 데이터를 보내는 방법 |
| 네트워크 | 컴퓨터와 라우터가 IP로 서로 다른 네트워크 사이를 통신하는 방법 |
| 전송 | 데이터가 **올바른 애플리케이션**에 의해 송수신되도록 보장하는 방법 |
| **애플리케이션** | **실제 애플리케이션들이 데이터를 주고받는 방법** ← 지금 |

### TCP 세그먼트의 페이로드가 곧 애플리케이션 데이터

- 다른 모든 계층과 마찬가지로 **TCP 세그먼트에도 범용 데이터 섹션**이 있다.
- 이 페이로드 섹션이 바로 **애플리케이션들이 서로 보내고 싶어 하는 데이터 전체**다.
  - 웹 브라우저가 웹 서버에 접속한다면 **웹 페이지의 내용**
  - PlayStation의 Netflix 앱이 Netflix 서버에 접속한다면 **스트리밍 비디오 콘텐츠**
  - 워드프로세서가 프린터로 보내는 **문서의 내용**
  - 그 밖에도 많다.

### 계층별 프로토콜 다양성 비교

| 계층 | 프로토콜 상황 |
|---|---|
| 데이터 링크 | 가장 흔한 것은 **이더넷**(무선 기술은 다른 프로토콜을 쓴다) |
| 네트워크 | 어디를 봐도 **IP** |
| 전송 | **TCP와 UDP**가 대부분의 경우를 커버 |
| **애플리케이션** | **너무 많아서 다 다루는 것이 말이 안 될 정도** |

### 핵심 개념 — 애플리케이션 종류별 표준화

- 프로토콜이 많아도 **애플리케이션 종류(application type)별로는 표준화**되어 있다.

**웹의 예:**

- 웹 브라우저는 Chrome, Safari 등 여러 가지가 있다.
- 웹 서버도 여러 가지다. 가장 인기 있는 것은 **Microsoft IIS, Apache, nginx**.
- 이 관계에서 **웹 브라우저가 클라이언트, 웹 서버가 서버**다.
- **웹 트래픽의 애플리케이션 계층 프로토콜은 HTTP**다.
- 이 모든 브라우저와 서버가 **같은 HTTP 프로토콜 명세로 통신해야 상호운용성(interoperability)이 보장**된다. 그래서 **어떤 브라우저를 쓰든 어떤 서버와도 대화할 수 있다.**

- 다른 대부분의 애플리케이션 부류도 마찬가지다. **FTP 클라이언트는 수십 가지 중 고를 수 있지만, 모두 같은 방식으로 FTP 프로토콜을 말해야 한다.**

## 요약

- 애플리케이션 계층 데이터는 TCP 세그먼트의 페이로드에 실린다.
- 하위 계층은 프로토콜이 소수로 수렴하지만 애플리케이션 계층은 매우 다양하다.
- 대신 애플리케이션 종류별로 프로토콜이 표준화되어 상호운용성이 확보된다.
- 웹은 HTTP, 파일 전송은 FTP처럼 클라이언트와 서버가 같은 프로토콜을 말한다.
