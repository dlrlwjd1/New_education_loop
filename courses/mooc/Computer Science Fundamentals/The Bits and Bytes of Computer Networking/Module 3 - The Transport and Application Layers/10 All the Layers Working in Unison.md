# All the Layers Working in Unison

## 개요

- 모든 계층이 실제로 어떻게 맞물려 동작하는지, **단 하나의 SYN 세그먼트가 클라이언트에서 서버까지 가는 과정**을 끝에서 끝까지 따라간다.
- 이 긴 과정 전체가 **3-way handshake의 첫 단계 하나**에 해당한다.

## 내용

### 구성

| 구성 요소 | 값 |
|---|---|
| Network A | 10.1.1.0/24 |
| Network B | 192.168.1.0/24 |
| Network C | 172.16.1.0/24 |
| Router A | Network A: **10.1.1.1** / Network B: **192.168.1.254** |
| Router B | Network B: **192.168.1.1** / Network C: **172.16.1.1** |
| Computer 1 (클라이언트, 데스크톱) | Network A, **10.1.1.100** |
| Computer 2 (서버, 데이터센터) | Network C, **172.16.1.100**, **포트 80에서 웹 서버 리스닝** |

사용자가 Computer 1의 웹 브라우저 주소창에 `172.16.1.100`을 입력한다.

### 1단계 — 클라이언트에서 패킷 만들기

1. 웹 브라우저가 `172.16.1.100`에서 웹페이지를 가져오라는 명령을 받았음을 안다.
2. 브라우저가 **로컬 네트워킹 스택**(네트워킹 기능을 담당하는 운영체제의 일부)에 **`172.16.1.100:80`으로 TCP 연결을 맺고 싶다**고 알린다.
3. 네트워킹 스택이 **자기 서브넷을 확인**한다. 자신은 `10.1.1.0/24`에 있으므로 **목적지가 다른 네트워크**임을 안다.
4. 따라서 **게이트웨이로 보내야** 하며, 게이트웨이는 `10.1.1.1`로 설정돼 있다.
5. **ARP 테이블**에서 `10.1.1.1`의 MAC 주소를 찾지만 **항목이 없다.**
6. `10.1.1.1`에 대한 **ARP 요청을 만들어 하드웨어 브로드캐스트 주소(all F)로** 보낸다. 로컬 네트워크의 **모든 노드**에 전달된다.
7. Router A가 이 ARP 메시지를 받고 **자신이 현재 `10.1.1.1`을 배정받은 컴퓨터**임을 확인해, 자신의 MAC 주소 **`00:11:22:33:44:55`** 를 응답한다.
8. Computer 1이 응답을 받아 **게이트웨이의 하드웨어 주소를 알게 된다.**

### 2단계 — 계층별로 캡슐화

9. 브라우저가 **아웃바운드 TCP 연결**을 요청했으므로 **아웃바운드 TCP 포트**가 필요하다. 운영체제가 **임시 포트(ephemeral port) 50,000**이 사용 가능함을 확인하고, 웹 브라우저를 이 포트에 연결하는 **소켓을 연다.**
10. TCP 연결이므로 **데이터를 보내기 전에 연결을 수립**해야 한다. 네트워킹 스택이 **TCP 세그먼트**를 만든다.
    - **출발지 포트 50,000**, **목적지 포트 80**
    - **시퀀스 번호**를 골라 채움
    - **SYN 플래그 설정**
    - 세그먼트 **체크섬 계산 후 기록**
11. 이 TCP 세그먼트가 **IP 계층**으로 전달되고, IP 계층이 **IP 헤더**를 만든다.
    - **출발지 IP, 목적지 IP, TTL 64**(이 필드의 꽤 표준적인 값)
    - TCP 세그먼트를 **IP 데이터그램의 데이터 페이로드로 삽입**
    - 전체에 대해 **체크섬 계산**
12. IP 데이터그램을 게이트웨이(MAC `00:11:22:33:44:55`)로 보내야 하므로 **이더넷 프레임**을 만든다.
    - **출발지·목적지 MAC 주소**를 포함해 관련 필드를 채움
    - IP 데이터그램을 **이더넷 프레임의 데이터 페이로드로 삽입**
    - **또 한 번 체크섬 계산**

### 3단계 — 물리 계층과 스위치

13. Computer 1의 네트워크 인터페이스가 이 이진 데이터를 **Cat 6 케이블을 흐르는 전류의 전압 변조**로 내보낸다.
14. **스위치**가 프레임을 받아 **목적지 MAC 주소를 검사**하고, 그 MAC이 붙어 있는 인터페이스를 알고 있으므로 **그 케이블로만** 전달한다.

### 4단계 — Router A

15. Router A가 프레임을 받아 **목적지가 자신의 하드웨어 주소**임을 확인한다.
16. 프레임 전체에 **체크섬을 계산해 헤더의 값과 비교** → 일치. 데이터가 온전히 도착했다.
17. **이더넷 프레임을 벗겨 내** IP 데이터그램만 남긴다. 다시 **데이터그램 전체에 체크섬을 계산해 비교** → 일치.
18. **목적지 IP를 검사**하고 **라우팅 테이블을 조회**한다. `172.16.1.0/24`로 가는 가장 빠른 길은 **IP `192.168.1.1`인 Router B를 거쳐 한 홉**임을 확인한다.
19. **TTL을 1 감소**시키고, 그에 맞춰 **새 체크섬을 계산**해 **새 IP 데이터그램**을 만든다.
20. **ARP 테이블**에 `192.168.1.1` 항목이 있음을 확인한다.
21. **출발지 = 자신의 Network B 인터페이스 MAC**, **목적지 = Router B의 Network B 인터페이스 MAC**으로 **새 이더넷 프레임**을 만들고, 새 IP 데이터그램을 페이로드로 넣고 체크섬을 계산해 Network B로 내보낸다.

### 5단계 — Router B

22. Router B가 같은 검사를 모두 수행하고, 이더넷 캡슐화를 제거한 뒤 IP 데이터그램에 체크섬을 수행한다.
23. 목적지 IP를 검사하고 라우팅 테이블을 보니 **`172.16.1.100`은 로컬로 직접 연결된 네트워크**에 있다.
24. **다시 TTL을 1 감소**시키고 새 체크섬을 계산해 새 IP 데이터그램을 만든다.
25. **출발지 = Router B, 목적지 = Computer 2**의 MAC으로 새 이더넷 프레임에 담아 Network C로 내보낸다. 스위치가 Computer 2가 연결된 인터페이스로 보낸다.

### 6단계 — 서버에서 벗겨 내기

26. Computer 2가 프레임을 받아 **목적지 MAC이 자신**임을 확인한다.
27. 이더넷 프레임을 벗기고 **CRC 수행** → 데이터가 온전함을 확인.
28. **목적지 IP가 자신**임을 확인한다.
29. IP 데이터그램을 벗겨 **TCP 세그먼트**만 남기고, 이 계층의 **체크섬도 검사** → 이상 없음.
30. **목적지 포트 80**을 확인한다. 네트워킹 스택이 **포트 80에 열린 소켓이 있는지 확인** → 있다. **LISTEN 상태**이며 **실행 중인 Apache 웹 서버**가 잡고 있다.
31. 이 패킷에 **SYN 플래그가 설정**된 것을 보고, **시퀀스 번호를 검사해 저장**한다. 응답을 만들 때 **확인 응답 필드에 넣어야** 하기 때문이다.

### 그리고 이것이 전부 한 세그먼트다

- 여기까지 한 일은 **한 컴퓨터에서 다른 컴퓨터로 SYN 플래그가 담긴 TCP 세그먼트 하나를 보낸 것**뿐이다.
- Computer 2가 **SYN-ACK 응답**을 보내려면 이 모든 과정이 **처음부터 다시** 일어나야 한다.
- Computer 1이 **ACK**를 돌려보낼 때도 **또 한 번 전부 다시** 일어난다.

## 요약

- 계층별로 헤더를 씌우며 내려가고(캡슐화), 받는 쪽에서는 벗기며 올라간다.
- 라우터를 지날 때마다 이더넷 프레임은 새로 만들어지고 MAC 주소가 바뀌지만 IP 주소는 그대로다.
- 홉마다 TTL이 줄고 그때마다 IP 체크섬이 재계산된다.
- 각 계층에서 체크섬을 검증하고, 서버는 포트에 LISTEN 소켓이 있어야 응답한다.
- 이 전 과정이 3-way handshake의 첫 SYN 하나에 해당한다.
