# Course Introduction

## 개요

- 강사 Victor Escobedo(Google Corporate Operations Engineer)의 소개와 이 코스가 무엇을 다루는지 안내하는 첫 강의다.
- 핵심 메시지: **컴퓨터 통신은 사람의 대화와 같고, 그 규칙을 프로토콜(protocol)이라 부른다.**
- 이 코스는 **TCP/IP 5계층 모델**을 뼈대로 삼고, OSI 7계층 모델도 함께 다룬다.

## 내용

### 강사 배경

- 9살 때 아버지가 CAD 작업용으로 사 온 첫 컴퓨터를 만지며 IT에 관심을 갖게 됐다. 케이스를 열어 부품을 빼 보는 시행착오로 배웠다.
- 1세대 멕시코계 미국인으로, 주변에 IT 커리어를 밟는 사람이 없었고 학교에도 기술 수업이 거의 없었다.
- 대학에서 컴퓨터 과학을 택했고, **기초(foundational) 지식이 있어야 상위 개념을 이해할 수 있다**는 것을 실감했다.
- IT 경력 12년, 그중 7년이 Google. 현재는 사내 대규모 IT 프로젝트 배포를 관리한다.
- 이 역할에서 **네트워킹 지식이 결정적**인 이유: 애플리케이션이 한 시스템에서 어떻게 도는지만이 아니라, 회사 안팎의 다른 모든 시스템과 어떻게 상호작용하는지 알아야 변경의 영향을 판단할 수 있기 때문이다.

### 컴퓨터 통신은 사람의 대화와 같다

사람이 말로 소통할 때 지키는 규칙들이 그대로 대응된다.

| 사람의 대화 | 컴퓨터 통신 |
|---|---|
| 같은 언어를 쓰고 서로 들을 수 있어야 한다 | 같은 프로토콜을 쓰고 물리적으로 연결돼야 한다 |
| 시끄러우면 "다시 말해 줘"라고 한다 | 전달되지 않은 메시지를 재전송한다 |
| 이해가 덜 되면 되묻는다 | 확인·재요청 메커니즘이 있다 |
| 한 사람에게 말할 수도, 여럿에게 말할 수도 있다 | 유니캐스트 / 멀티캐스트 / 브로드캐스트 |
| 인사로 시작하고 마무리하는 절차가 있다 | 연결 수립과 종료 절차가 있다 |

> **프로토콜(protocol)** = 컴퓨터가 제대로 통신하기 위해 반드시 따라야 하는, 정의된 표준의 집합.
> **컴퓨터 네트워킹(computer networking)** = 컴퓨터들이 서로 통신하는 방식 전체를 가리키는 이름.

### 왜 계층 모델인가

- 네트워킹을 설명하는 모델은 여러 가지가 있지만, 이 코스는 **TCP/IP 5계층 모델**을 쓴다. 다른 주요 모델인 **OSI 모델(7계층)** 도 함께 다룬다.
- 계층 모델을 알아야 하는 이유: 네트워킹이 실제로 **철저하게 계층적(layered)** 이기 때문이다.
- **각 계층의 프로토콜은 그 위 계층을 실어 나른다.** 네트워킹 케이블의 한쪽 끝에서 반대쪽 끝까지 데이터를 옮기는 프로토콜과, 지구 반대편까지 데이터를 옮기는 프로토콜은 완전히 다르다. 그런데 인터넷과 사내 네트워크가 동작하려면 **이 둘이 동시에 작동해야 한다.**

### 이 코스를 마치면

- 5개 계층 전부를 설명할 수 있다.
- 컴퓨터가 메시지를 **어디로 보낼지 어떻게 결정하는지** 설명할 수 있다.
- **DNS와 DHCP** 같은 네트워크 서비스가 어떻게 동작하는지 설명할 수 있다.
- 네트워크 문제를 해결하는 **강력한 도구들**을 쓸 수 있다.

## 요약

- 프로토콜은 컴퓨터판 "대화 규칙"이고, 컴퓨터 네트워킹은 그 규칙 전체를 다루는 분야다.
- 네트워킹은 계층적이며, 아래 계층 프로토콜이 위 계층을 실어 나른다.
- 이 코스는 TCP/IP 5계층 모델을 중심축으로 쓰고 OSI 7계층도 함께 본다.
- IT 지원 담당자에게 네트워킹 지식이 필요한 이유는, 문제가 생겼을 때 고쳐야 하는 사람이 결국 그들이기 때문이다.
