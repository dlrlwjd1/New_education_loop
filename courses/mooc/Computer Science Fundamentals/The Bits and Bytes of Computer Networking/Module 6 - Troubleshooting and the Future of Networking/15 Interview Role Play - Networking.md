# Interview Role Play: Networking

## 개요

- 이 코스가 다룬 기술 주제로 **면접이 어떻게 진행될 수 있는지 보여 주는 역할극**이다.
- 시나리오: **글로벌 회사 헬프데스크에 원격 사무실 사용자가 "네트워크가 죽었다"고 전화**한다.
- 교훈 두 가지: **명확화 질문을 던질 것**, **자기가 쓰는 용어를 설명할 수 있을 것**.

## 내용

### 시나리오 진행

1. **사용자**: 아침 일찍 전화해 **"사무실 네트워크가 죽었다"** 고 다급하게 말한다.
2. **응대자**: 도와주겠다고 안심시키고 **장애 증상**을 묻는다. **"에러 메시지를 받고 있나요?"**
3. **사용자**: 노트북을 열고 **사내 웹사이트에 접속했더니 `page can't be displayed`** 에러가 뜬다.
4. **응대자**: **다른 사용자도 같은 문제를 겪는지** 묻는다.
5. **사용자**: 모른다. **아침 일찍이라 자신이 첫 출근자**다.
6. **응대자**: **사이트 이름을 알려 달라**고 해서 **자기 컴퓨터에서 테스트**한다. (`internet.companyx.com`)
7. **결과**: **응대자 쪽에서는 정상적으로 로딩**된다.
8. **응대자**: **외부 사이트도 시도해 보라**고 한다 (`google.com`).
9. **사용자**: **google.com도 같은 `page can't be displayed`**.
10. **응대자**: **OS를 확인**한다 (Windows 7). **시작 메뉴에서 `CMD`를 검색해 명령 프롬프트를 열게** 한다.
11. **응대자**: **`ipconfig` 명령을 실행**하게 한다. 사용자에게 **IP 주소, 기본 게이트웨이, DNS**가 보인다.

### 사용자가 용어 설명을 요구했을 때

| 용어 | 답변 |
|---|---|
| **IP 주소** | 컴퓨팅 장치가 **인터넷에서 다른 컴퓨터와 통신하기 위해 부여받는 고유한 숫자 주소** |
| **기본 게이트웨이(default gateway)** | 컴퓨터가 **다른 컴퓨터나 인터넷으로 정보를 보낼 때 사용하는 접근 지점(access point)**. 라우터 같은 것 |
| **DNS** | **Domain Name System**, **도메인 이름을 IP 주소로 번역**한다 |
| **DHCP** | **Dynamic Host Configuration Protocol**, **컴퓨팅 장치에 IP 주소를 자동으로 배정**하며 **네트워크 설정도 함께 보낼 수 있다** |

### 결정적 단서 — IP 대역이 다르다

12. 사용자의 IP는 **`192.x.x.x`** 인데, **회사 네트워크는 `172.x.x.x` 대역만 사용**한다.
13. **응대자**: 이 장비가 **DHCP를 쓰는지** 확인한다. → 쓴다.
    - **왜 중요한가**: **IP가 정적으로 배정되고 있다면 직접 들어가 바꿔야 하지만, 자동으로 배정되고 있어야 정상**이기 때문이다.
14. **DHCP에서 잘못된 IP를 받는 이유로 가능한 것**:
    - **DHCP가 잘못 설정됐거나**
    - **잘못된 네트워크에 연결됐거나**
15. **더 단순한 설명부터 확인**한다. **유선인지 무선인지** 묻는다 → **노트북, 무선**.
16. **오른쪽 아래 Wi-Fi 아이콘 → 네트워크 설정**에서 **실제로 어느 네트워크에 연결됐는지** 확인하게 한다.
17. **원인**: 사용자가 **길 건너의 엉뚱한 네트워크에 연결**돼 있었다.
18. **회사 무선으로 다시 전환하니 문제 해결.** **네트워크는 애초에 죽지 않았다.**

### 정리 — 이 역할극의 교훈

**1. 명확화 질문(clarifying questions)을 던져라**

- 문제는 사용자가 **"네트워크가 죽었다"** 고 말하는 데서 시작했지만, **그 말은 사실 여러 가지를 뜻할 수 있다.**
- **고치려 들기 전에 정확히 무엇이 잘못되고 있는지 파악하는 것이 중요하다.**

**2. 자기가 쓰는 용어를 설명할 수 있어야 한다**

- **DNS나 DHCP 같은 용어를 쓴다면, 그것이 무슨 뜻이고 지금 상황과 어떻게 관련되는지 알고 있어야 한다.**

## 예시

```
증상 확인 → 내부 사이트 실패
   ↓ 응대자 쪽에서는 정상  → 사용자 쪽 문제로 좁혀짐
외부 사이트(google.com)도 실패 → 특정 사이트 문제 아님
   ↓
ipconfig → IP가 192.x.x.x (회사는 172.x.x.x)
   ↓
DHCP는 켜져 있음 → 설정 오류 or 잘못된 네트워크
   ↓ 더 단순한 쪽부터
Wi-Fi 연결 네트워크 확인 → 길 건너 남의 네트워크
   ↓
회사 Wi-Fi로 전환 → 해결
```

> 참고: 이 강의의 Transcript에는 **`DHCP`가 "DHTP"로, `ipconfig /all`로 추정되는 명령이 "ipconfig/o"** 로 표기되어 있다. 자동 생성 자막의 오기이며, 위 정리에서는 올바른 표기로 옮겼다.

## 요약

- "네트워크가 죽었다"는 진술은 그 자체로 아무것도 특정하지 않는다. 증상부터 확인한다.
- 내부/외부 사이트를 나눠 테스트해 문제 범위를 좁힌다.
- ipconfig로 받은 IP가 회사 대역과 다르면 연결된 네트워크 자체를 의심한다.
- 복잡한 원인(DHCP 설정 오류)보다 단순한 원인(엉뚱한 Wi-Fi)을 먼저 확인한다.
- 면접에서는 자기가 쓰는 용어를 정의할 수 있어야 한다.
