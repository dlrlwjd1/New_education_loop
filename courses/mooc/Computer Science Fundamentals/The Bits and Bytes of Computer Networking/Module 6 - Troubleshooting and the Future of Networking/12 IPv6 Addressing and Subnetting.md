# IPv6 Addressing and Subnetting

## 개요

- **IANA의 IP 주소가 바닥났다.** IPv4의 32비트로는 부족해서 **IPv6**가 개발됐다.
- **IPv6는 128비트**이며, **8개 그룹 × 16비트(16진수 4자리)** 로 표기한다.
- 축약 규칙 두 가지: **선행 0 제거**, **연속된 0 그룹을 `::`로 한 번만 치환**.
- **앞 64비트가 네트워크 ID, 뒤 64비트가 호스트 ID**로 처음부터 단순하게 나뉜다.

## 내용

### 배경

- IPv4가 처음 개발될 때는 **인터넷이 초창기**였고 **이렇게 폭발적으로 인기를 끌 것이라고 아무도 예상하지 못했다.** 그래서 32비트가 선택됐다.
- **1990년대 중반**에는 언젠가 IPv4 주소 공간이 고갈되리라는 것이 점점 분명해졌고, 그래서 **IPv6**가 개발됐다.

### IPv5는 어디로 갔나

- **IPv5는 연결(connection) 개념을 도입한 실험적 프로토콜**이었다.
- **널리 채택되지 못했고**, 연결 상태는 나중에 **전송 계층과 TCP가 더 잘 처리**했다.
- IPv5는 대체로 역사의 유물이지만, **IPv6 개발을 시작할 때 IPv5라는 이름을 재사용하지 않기로 합의**했다.

### 주소 공간의 크기

| 버전 | 비트 | 주소 개수 |
|---|---|---|
| **IPv4** | 32비트 | 약 **42억(4.2 billion)** |
| **IPv6** | **128비트** | **2^128 = 39자리 수** |

- **2^128은 undecillion 단위**의 수로, **그 규모로 존재하는 것 자체가 별로 없다.**
- **지구 전체와 그 위의 모든 것을 이루는 원자의 총 개수 추정치**가 그 범위에 들어간다는 추측이 있다.
- **지구의 모든 원자에 IP를 하나씩 줄 수 있다면 네트워크 장치는 아주 오랫동안 걱정 없다.**

### 표기법

- IPv4는 사람이 읽기 쉽도록 **4개 옥텟의 십진수**로 쓴다. 그런데 **IPv6에 같은 방식을 쓰면 감당이 안 된다.**
- 그래서 IPv6는 **각 16비트씩 8개 그룹**으로 쓰고, **각 그룹은 다시 16진수 네 자리**로 이루어진다.

### 문서·교육용 예약 대역

- **`2001:0db8`로 시작하는 모든 IPv6 주소는 문서화와 교육용, 즉 이런 책이나 강좌를 위해 예약**돼 있다.
- 그 수가 **1,800경(18 quintillion) 개가 넘는다** — **이 용도 하나에 예약된 것이 IPv4 전체 주소 공간보다 훨씬 크다.**

### 축약 규칙 두 가지

1. **각 그룹의 선행 0(leading zeros)을 제거할 수 있다.**
2. **0으로만 이루어진 연속된 그룹들을 콜론 두 개(`::`)로 치환할 수 있다.**
   - **이 치환은 한 주소에서 한 번만 가능하다.** 그렇지 않으면 **`::`가 정확히 몇 개의 0을 대체했는지 알 수 없기** 때문이다.

### 예약 대역들

| 시작 | 용도 |
|---|---|
| **`::1`** | **루프백 주소.** 31개의 0 뒤에 1이 오는 형태를 끝까지 축약한 것 |
| **`FF00::`** | **멀티캐스트.** 여러 호스트 그룹을 한 번에 지정하는 방법 |
| **`FE80::`** | **링크 로컬 유니캐스트(link-local unicast)** |
| **`2001:0db8`** | 문서·교육용 |

### 링크 로컬 유니캐스트

- **로컬 네트워크 구간 내 통신을 가능하게** 하며, **호스트의 MAC 주소를 기반으로 구성**된다.
- IPv6 호스트가 **네트워크 설정을 받는 데** 사용되며, **DHCP가 동작하는 방식과 매우 비슷하다.**
- 방식: **호스트의 MAC 주소를 알고리즘에 통과시켜 48비트 수를 고유한 64비트 수로 바꾼 뒤, 주소의 호스트 ID에 삽입**한다.

### 네트워크 ID와 호스트 ID

- **IPv6 주소 공간이 워낙 거대해서 IPv4처럼 주소 클래스로 쪼갤 필요가 전혀 없었다.**
- **처음부터 네트워크 ID와 호스트 ID의 경계가 아주 단순**하다.
  - **앞 64비트 = 네트워크 ID**
  - **뒤 64비트 = 호스트 ID**
- 즉 **어떤 IPv6 네트워크든 900경(9 quintillion) 개가 넘는 호스트 공간**을 갖는다.
- 그래도 **관리 목적으로 네트워크를 쪼개고 싶을 때**가 있는데, **IPv6 서브넷팅도 이미 익숙한 CIDR 표기를 그대로 사용**한다. 이는 **IPv6 주소의 네트워크 ID 부분에 대한 서브넷 마스크를 정의**하는 데 쓰인다.

## 예시

```
축약 전:  2001:0db8:0000:0000:0000:0000:0000:0001

규칙 1 (선행 0 제거):
          2001:db8:0:0:0:0:0:1

규칙 2 (연속된 0 그룹 → ::, 한 번만):
          2001:db8::1
```

```
IPv6 루프백:  0000:...:0001  →  ::1
```

> 참고: 이 강의의 발화에서 IPv4 루프백을 `127.0.0.0`이라고 말하지만, **정확한 IPv4 루프백 주소는 `127.0.0.1`** 이다(같은 모듈의 [08 Hosts Files](08%20Hosts%20Files.md) 강의 참조).

## 요약

- IPv4의 32비트(약 42억)가 고갈되어 128비트의 IPv6가 만들어졌다. IPv5는 채택되지 못한 실험 프로토콜이었다.
- IPv6는 16비트씩 8그룹, 각 그룹을 16진수 4자리로 쓴다.
- 선행 0을 지우고, 연속된 0 그룹을 `::`로 딱 한 번 치환해 줄인다.
- ::1은 루프백, FF00::은 멀티캐스트, FE80::은 MAC 기반 링크 로컬이다.
- 주소 클래스 없이 앞 64비트가 네트워크 ID, 뒤 64비트가 호스트 ID이며 서브넷팅은 CIDR 표기를 그대로 쓴다.
