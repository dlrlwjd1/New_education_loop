# Ping: Internet Control Message Protocol

## 개요

- 가장 흔한 네트워크 문제는 **무언가에 연결을 수립하지 못하는 것**이다.
- **ICMP(Internet Control Message Protocol)** 는 **전송이 왜 실패했는지 출발지에 알리는** 프로토콜이다.
- **ping**은 ICMP의 **echo request / echo reply** 두 메시지 타입을 사람이 쓸 수 있게 만든 도구다.

## 내용

### ICMP가 필요한 상황

네트워크 오류가 발생하면 그것을 감지한 장치가 **문제가 된 트래픽의 출발지에 알릴 방법**이 필요하다.

- 라우터가 **목적지로 가는 경로를 모를** 수 있다
- 특정 **포트에 도달할 수 없을** 수 있다
- **IP 데이터그램의 TTL이 만료**되어 더 이상 라우터 홉을 시도하지 않을 수 있다

**이 모든 상황을 알리는 데 ICMP가 쓰인다.** ICMP는 주로 **라우터나 원격 호스트가 전송 실패 이유를 전송 출발지에 알리는 데** 사용된다.

### ICMP 패킷 구조

| 필드 | 크기 | 설명 |
|---|---|---|
| **Type** | 8비트 | **어떤 종류의 메시지**인지 지정. 예: `destination unreachable`, `time exceeded` |
| **Code** | — | 타입보다 **더 구체적인 이유**. 예: destination unreachable 타입 안에 `destination network unreachable`, `destination port unreachable` 같은 개별 코드가 있다 |
| **Checksum** | 16비트 | 지금까지 다룬 다른 체크섬과 동일하게 동작 |
| **Rest of Header** | 32비트 | 일부 특정 타입·코드가 **추가 데이터를 보내는 데 선택적으로** 사용 |
| **Data payload** | — | 아래 참조 |

### 페이로드의 목적

- ICMP 패킷의 페이로드는 **오로지 수신자가 자신의 어떤 전송이 이 오류를 유발했는지 알기 위해** 존재한다.
- 내용: **문제가 된 패킷의 IP 헤더 전체와 데이터 페이로드 구간의 첫 8바이트**.

### ping

- **ICMP는 원래 사람이 상호작용하라고 만든 것이 아니다.** 이런 오류 메시지가 **네트워크 컴퓨터 사이에서 자동으로 전달되게** 하는 것이 목적이다.
- 하지만 **사람에게 매우 유용한 도구 하나와 메시지 타입 두 개**가 있다. 그 도구가 **ping**이다.
- **거의 모든 운영체제에 어떤 형태로든 아주 오랫동안 존재**해 왔고, **어느 OS를 쓰든 기본은 같다.**

동작:

1. ping이 **ICMP echo request**라는 특별한 메시지를 보낸다. 뜻은 **"거기 있니?"**
2. 목적지가 살아 있고 네트워크에서 통신할 수 있으면 **ICMP echo reply** 메시지 타입으로 답한다.

### 사용법과 출력

- 현대 운영체제의 명령줄에서 **`ping` 뒤에 목적지 IP나 FQDN**을 적는다.
- 출력은 OS마다 매우 비슷하다. 각 줄에 보통 표시되는 것:
  - **ICMP echo reply를 보낸 주소**
  - **왕복(round trip) 통신에 걸린 시간**
  - **남은 TTL**
  - **ICMP 메시지의 크기(바이트)**
- 명령이 끝나면 **통계**가 표시된다 — **전송·수신된 패킷의 비율**, **평균 왕복 시간** 등.

### OS별 차이

| OS | 기본 동작 |
|---|---|
| **Linux · macOS** | **사용자가 인터럽트(Ctrl + C)를 보낼 때까지 계속** 실행 |
| **Windows** | **echo request를 4개만** 보내고 종료 |

- 모든 환경에서 ping은 **여러 명령줄 플래그**를 지원한다 — 보낼 echo request 개수, 크기, 전송 속도 등. **자세한 것은 사용 중인 OS의 문서를 참고**한다.

## 예시

```bash
ping 8.8.8.8
ping www.google.com
```

출력 각 줄: 응답 주소 · 왕복 시간 · 남은 TTL · 메시지 크기
종료 시: 전송/수신 패킷 비율, 평균 왕복 시간 등 통계

## 요약

- ICMP는 전송 실패 이유를 출발지에 자동으로 알리는 프로토콜이다.
- Type이 큰 분류, Code가 구체적 이유이며, 페이로드에는 문제가 된 패킷의 IP 헤더와 데이터 첫 8바이트가 담긴다.
- ping은 echo request를 보내고 echo reply를 받아 도달 가능성과 연결 품질을 확인한다.
- Linux·macOS는 Ctrl+C까지 계속, Windows는 기본 4회다.
