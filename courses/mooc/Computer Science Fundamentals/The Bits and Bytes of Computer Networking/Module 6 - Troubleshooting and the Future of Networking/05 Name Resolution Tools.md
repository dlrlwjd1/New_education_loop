# Name Resolution Tools

## 개요

- 대개는 운영체제가 이름 조회를 알아서 처리하지만, IT 지원 담당자는 **직접 질의를 실행해 뒤에서 무슨 일이 벌어지는지 볼 수 있어야** 한다.
- 가장 흔한 도구는 **`nslookup`** 이며 **Linux·Mac·Windows 세 OS 모두**에서 쓸 수 있다.
- 강력한 것은 **대화형 모드(interactive mode)** 다.

## 내용

### 기본 사용

- **`nslookup` 뒤에 호스트 이름**을 붙여 실행하면, 출력에 **요청에 사용된 서버**와 **해석 결과**가 표시된다.
- 예: `twitter.com`의 IP가 필요하면 **`nslookup twitter.com`** 을 입력하면 **A 레코드가 반환**된다.

### 대화형 모드

- **호스트 이름 없이 `nslookup`만 입력**하면 대화형 세션이 시작된다. **꺾쇠 괄호(`>`)가 프롬프트**로 나타난다.
- 대화형 모드에서는 **연달아 여러 요청**을 할 수 있고, **더 깊이 있는 진단을 위한 추가 설정**을 할 수 있다.

| 명령 | 하는 일 |
|---|---|
| **`server <주소>`** | 이후 모든 이름 해석 질의를 **기본 네임서버 대신 그 서버로** 시도한다 |
| **`set type=<레코드 타입>`** | 기본값은 **A 레코드**인데, **AAAA·MX·TXT** 등 원하는 리소스 레코드를 **명시적으로 요청**할 수 있다 |
| **`set debug`** | **전체 응답 패킷을 표시**한다. 중간 요청들과 그 내용 전부 포함 |

### `set debug` 주의

- **데이터가 아주 많다.**
- 포함될 수 있는 상세 정보:
  - **캐시된 응답이라면 남은 TTL**
  - **요청이 수행된 대상 존 파일의 일련번호(serial number)** 까지

## 예시

```
nslookup twitter.com            # A 레코드 조회

nslookup                        # 대화형 모드 진입
> server 8.8.8.8                # 질의할 네임서버 변경
> set type=MX                   # 조회할 레코드 타입 변경
> twitter.com
> set debug                     # 전체 응답 패킷 표시
> twitter.com
```

## 요약

- nslookup은 세 OS 공통의 이름 해석 도구이며 기본은 A 레코드를 조회한다.
- 대화형 모드에서 여러 질의를 연달아 하고 설정을 바꿀 수 있다.
- `server`로 질의 대상 네임서버를, `set type=`으로 레코드 타입을 바꾼다.
- `set debug`는 중간 요청까지 포함한 전체 응답 패킷을 보여 주며, 캐시 잔여 TTL과 존 파일 일련번호까지 나온다.
