# Hosts Files

## 개요

- **호스트 파일(hosts file)** = **네트워크 주소와 그 이름을 한 줄에 하나씩 담은 평문 파일.** DNS 이전의 이름 해석 방식이다.
- 오래된 기술이지만 **모든 현대 운영체제에 여전히 존재**한다. 가장 큰 이유는 **루프백 주소**다.
- **호스트 파일은 DNS 해석 시도보다 먼저 검사된다.** — 진단에 쓸 수 있는 지점이자 **바이러스가 악용하는 지점**이다.

## 내용

### 형식

- 각 줄에 **네트워크 주소 다음에 그것을 부를 호스트 이름**을 적는다.
- 예: `1.2.3.4 webserver` — 이 호스트 파일이 있는 컴퓨터에서는 사용자가 **IP `1.2.3.4` 대신 `webserver`라고 부를 수 있다.**

### 운영체제 수준에서 동작한다

- **호스트 파일은 운영체제의 네트워킹 스택 자체가 평가**한다.
- 즉 **거기 있는 항목은 네트워크 주소를 쓰는 어느 곳에서든 적용**된다.
- 위 예시라면 **웹 브라우저 URL 창에 `webserver`를 입력하든 `ping webserver` 명령을 실행하든** 두 경우 모두 `1.2.3.4`로 번역된다.

### 왜 아직도 남아 있나 — 루프백 주소

- **호스트 파일은 고대 기술이지만 지금까지 살아남았다.** 휴대폰과 태블릿을 구동하는 것을 포함해 **모든 현대 운영체제에 여전히 호스트 파일이 있다.**
- 한 가지 이유는 **아직 다루지 않은 특별한 IP 주소, 루프백 주소(loopback address)** 때문이다.

> **루프백 주소** = **항상 자기 자신을 가리키는 주소.** 자신에게 네트워크 트래픽을 보내는 방법이다.
> 루프백 주소로 보낸 트래픽은 **네트워크 인프라 자체를 우회하며, 그런 트래픽은 결코 노드를 떠나지 않는다.**

- **IPv4의 루프백 IP는 `127.0.0.1`** 이며, **오늘날까지도 모든 현대 운영체제에서 호스트 파일의 항목을 통해 설정**된다.
- 거의 모든 호스트 파일에는 최소한 다음 줄이 들어 있다.
  - `127.0.0.1 localhost`
  - 그 뒤에 대개 `::1 localhost` (여기서 **`::1`은 IPv6의 루프백 주소**)

### 오늘날의 위치

- **DNS가 어디에나 있으므로 호스트 파일은 더 이상 많이 쓰이지 않지만, 여전히 존재하고 알아 둘 가치가 있다.**
- **일부 소프트웨어는 제대로 동작하기 위해 호스트 파일에 특정 항목을 요구**하기도 한다. 구식으로 보이는 관행이지만 그렇다.
- **호스트 파일은 컴퓨터 바이러스가 사용자 트래픽을 방해하고 리다이렉트하는 데 흔히 쓰는 방법**이기도 하다.
- **오늘날 호스트 파일을 사용하는 것은 좋은 생각이 아니지만**, IT 지원에서 **유용한 진단 용도**가 있다.
- **거의 모든 주요 운영체제에서 호스트 파일은 DNS 해석 시도가 일어나기 전에 검사된다.** 그래서 **특정 도메인 이름이 항상 특정 IP를 가리킨다고 개별 컴퓨터가 믿게 강제**할 수 있다.

## 예시

```
# 일반적인 hosts 파일 내용
127.0.0.1   localhost
::1         localhost

# 진단용으로 강제 매핑
1.2.3.4     webserver
```

```bash
# 위 항목이 있으면 둘 다 1.2.3.4로 번역된다
ping webserver
# 브라우저 주소창에 webserver 입력
```

## 요약

- 호스트 파일은 "IP 이름" 한 줄씩으로 된 DNS 이전의 이름 해석 방식이다.
- OS 네트워킹 스택이 평가하므로 브라우저든 ping이든 모든 곳에 적용된다.
- IPv4 루프백 127.0.0.1과 IPv6 루프백 ::1이 지금도 여기서 설정된다.
- DNS보다 먼저 검사되기 때문에 특정 도메인을 강제 매핑할 수 있고, 같은 이유로 바이러스의 리다이렉트 수법에 악용된다.
