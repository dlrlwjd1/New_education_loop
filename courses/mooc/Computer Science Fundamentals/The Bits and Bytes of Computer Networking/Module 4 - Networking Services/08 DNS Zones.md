# DNS Zones

## 개요

- 권한 네임서버는 사실 **특정 DNS 존(zone)** 을 책임진다.
- **존은 계층적이며 서로 겹치지 않는다.**
- 존의 목적은 **도메인의 여러 단계를 더 쉽게 통제**하는 것이다. 설정은 **존 파일(zone file)** 로 한다.

## 내용

### 존의 계층

| 서버 | 책임지는 존 |
|---|---|
| **루트 네임서버** | **루트 존** |
| **TLD 네임서버** | 자신의 **특정 TLD를 포괄하는 존** |
| **권한 네임서버** | 그 아래의 **더 세분화된 존** |

- **루트 서버와 TLD 서버도 사실은 권한 네임서버**다. 다만 그들이 권한을 갖는 존이 **특수한 경우**일 뿐이다.

### 존은 겹치지 않는다

- 예: **`.com` TLD 네임서버의 관리 권한은 `google.com` 도메인을 포함하지 않는다.** `google.com`을 책임지는 권한 서버에서 **끝난다.**

### 존의 목적 — 관리 부담 분할

- 한 도메인의 리소스 레코드 수가 늘어나면 **전부 관리하기가 골치 아파진다.**
- 네트워크 관리자는 **설정을 여러 존으로 나눠** 이 고통을 덜 수 있다.

#### 예시 — largecompany.com

- `largecompany.com`을 소유한 대기업이 **로스앤젤레스, 파리, 상하이**에 사무실을 두고 있다.
- 각 사무실에 **약 200명**이 있고 각자 고유한 이름의 데스크톱을 쓴다.
- 단일 존으로 설정하면 **A 레코드 600개**를 관리해야 한다.
- 대신 **각 사무실을 자기 존으로 분리**할 수 있다.
  - `la.largecompany.com`
  - `pa.largecompany.com`
  - `sh.largecompany.com`
- 이렇게 하면 **총 4개의 권한 네임서버**가 필요하다 — `largecompany.com`용 1개, 각 서브도메인용 1개씩.

### 존 파일 (Zone File)

- **특정 존의 모든 리소스 레코드를 선언하는 단순한 설정 파일**이다.

필수 및 주요 구성:

| 레코드 | 역할 |
|---|---|
| **SOA (Start of Authority)** | **반드시 있어야 한다.** **존과, 그 존에 권한을 갖는 네임서버의 이름을 선언**한다 |
| **NS** | **이 존을 함께 책임질 수 있는 다른 네임서버들**을 나타낸다 |
| **A, AAAA(Quad A), CNAME** 등 | 앞서 다룬 리소스 레코드 타입들 |
| **기본 TTL 값** 등의 설정 | 이 존이 서비스하는 레코드들의 기본 TTL |

### 서버는 보통 여러 대다

- 지금까지 편의상 존을 책임지는 "서버"를 단수로 불렀지만(루트·TLD·도메인 수준 모두), **실제로는 각자의 FQDN과 IP 주소를 가진 물리 서버가 여러 대**인 경우가 많다.
- **DNS처럼 중요한 것에 서버를 여러 대 두는 것은 꽤 흔한 일**이다.
- 이유: **한 서버에 문제가 생기거나 하드웨어 장애가 나도 다른 서버가 DNS 트래픽을 처리**할 수 있기 때문이다.

### 존의 깊이

- 서브도메인이 여러 단계로 깊어질 수 있듯 **존도 깊게 구성할 수 있다.** 다만 서브도메인과 마찬가지로 **몇 단계보다 깊은 존은 드물다.**

### 역방향 조회 존 파일 (Reverse Lookup Zone File)

- **DNS 리졸버가 IP를 묻고 그에 연결된 FQDN을 돌려받게** 해 준다.
- 일반 존 파일과 형식은 같지만, **이름을 IP로 해석하는 A·AAAA 레코드 대신 주로 포인터(PTR) 리소스 레코드 선언**이 들어 있다.
- **PTR(pointer) 레코드는 IP를 이름으로 해석**한다.

## 예시

```
largecompany.com                    ← 권한 네임서버 1
├── la.largecompany.com  (존)       ← 권한 네임서버 2  (LA 200대)
├── pa.largecompany.com  (존)       ← 권한 네임서버 3  (파리 200대)
└── sh.largecompany.com  (존)       ← 권한 네임서버 4  (상하이 200대)

단일 존이면 A 레코드 600개를 한곳에서 관리해야 한다.
```

## 요약

- 권한 네임서버는 존을 책임지며, 루트·TLD 서버도 특수한 존의 권한 서버다.
- 존은 계층적이고 서로 겹치지 않으며, 통제가 넘어가는 지점에서 끝난다.
- 존을 나누면 레코드 관리 부담을 분산할 수 있고, 존마다 권한 네임서버가 필요하다.
- 존 파일에는 SOA가 필수이고 NS, A/AAAA/CNAME, 기본 TTL 등이 들어간다.
- 가용성을 위해 존당 서버를 여러 대 두는 것이 일반적이다.
- 역방향 조회 존은 PTR 레코드로 IP → 이름 해석을 제공한다.
