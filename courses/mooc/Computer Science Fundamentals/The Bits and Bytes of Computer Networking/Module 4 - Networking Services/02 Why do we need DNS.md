# Why do we need DNS?

## 개요

- **DNS(Domain Name System)** = **글자로 된 문자열을 IP 주소로 해석해 주는, 전 지구적이고 고도로 분산된 네트워크 서비스**.
- 필요한 이유는 두 가지다: **사람이 숫자를 잘 기억하지 못한다**는 것, 그리고 **관리상의 변경을 사용자 모르게 처리할 수 있다**는 것.

## 내용

### 사람은 단어를 더 잘 기억한다

- 가장 낮은 수준에서 컴퓨터가 이해하는 것은 **1과 0**뿐이다. 이진수는 사람이 읽기 쉽지 않아 여러 형태로 표현된다.
- 방문하는 모든 웹사이트의 **IP 주소 네 옥텟을 전부 외워야 한다고 상상해 보라.** 사람의 뇌가 잘하는 일이 아니다.
- **사람은 단어를 훨씬 잘 기억한다.**
- 예: 날씨를 확인하려 할 때 `www.weather.com`을 입력하는 것이, 이 사이트의 IP 중 하나가 `184.29.131.121`이라는 것을 기억하는 것보다 훨씬 쉽다.

> **도메인 이름(domain name)** = DNS로 해석될 수 있는 것을 가리키는 용어.

### IP는 계속 바뀔 수 있다

- 도메인 이름에 대한 IP 주소는 **여러 이유로 언제든 바뀔 수 있다.**
- 예: `weather.com`이 웹 서버를 **새 데이터센터로 옮기는** 경우 — 새 계약을 맺었거나 기존 데이터센터가 문을 닫는 등.
- DNS를 쓰면 조직은 **도메인 이름이 어떤 IP로 해석되는지만 바꾸면 되고, 최종 사용자는 전혀 알아차리지 못한다.**
- 즉 DNS는 사람이 웹사이트에 가는 길을 기억하기 쉽게 할 뿐 아니라, **사용자가 행동을 바꿀 필요 없이 관리상의 변경이 뒤에서 일어나게** 해 준다.

### 지역에 따라 다른 IP로 해석된다

- 대부분의 인터넷 통신은 빛의 속도로 이동하지만, **데이터를 멀리 라우팅할수록 느려진다.**
- 거의 모든 상황에서 **지리적으로 가까운 곳 사이에서 데이터를 전송하는 것이 더 빠르다.**
- 글로벌 웹 기업이라면 전 세계 사람들이 좋은 경험을 하기를 원한다. 그래서 **웹 서버를 한곳에 두지 않고 전 세계 데이터센터에 분산**한다.
- 뉴욕에서 접속한 사람은 **뉴욕 가까운 웹 서버**가, 뉴델리에서 접속한 사람은 **뉴델리 가까운 웹 서버**가 응답한다.
- **이 기능도 DNS가 제공한다.** 전 지구적 구조 덕분에, 조직은 **"이 지역이면 이 IP로, 다른 지역이면 다른 IP로 해석하라"** 고 정할 수 있다.

## 예시

```
www.weather.com  →  184.29.131.121   (여러 IP 중 하나이며 언제든 바뀔 수 있다)

데이터센터 이전 시:
  변경 전: www.weather.com → (구 데이터센터 IP)
  변경 후: www.weather.com → (신 데이터센터 IP)
  사용자가 하는 일: 아무것도 없음
```

## 요약

- DNS는 이름을 IP로 바꿔 주는 전 지구적 분산 서비스다.
- 사람이 IP를 외울 필요가 없어지고, 서버 이전 같은 변경을 사용자 모르게 처리할 수 있다.
- 지역별로 다른 IP를 돌려줄 수 있어 지리적으로 가까운 서버로 유도하는 것도 DNS의 기능이다.
- IT 지원 담당자가 네트워크 문제를 효과적으로 진단하려면 가장 이해해야 할 기술 중 하나다.
