# DNS and UDP

## 개요

- DNS는 **전송 계층으로 TCP가 아니라 UDP를 쓰는** 애플리케이션 계층 서비스의 좋은 예다.
- 이유: **UDP는 비연결이라 연결 수립·해제가 없고**, 요청 하나와 응답 하나가 **UDP 데이터그램 하나에 들어가기** 때문이다.
- **DNS의 포트는 53**이다.
- 완전 재귀 조회를 TCP로 하면 **최소 44패킷**, UDP로 하면 **8패킷**이다.

## 내용

### 왜 UDP인가

- TCP와 UDP의 가장 큰 차이는 **UDP가 비연결(connectionless)** 이라는 것이다. **연결의 수립도 해제도 없으므로 전송해야 할 트래픽이 훨씬 적다.**
- **DNS 요청 하나와 그 응답은 보통 UDP 데이터그램 하나 안에 들어간다.** 비연결 프로토콜에 이상적인 후보다.
- **DNS는 트래픽을 많이 만들 수 있다.** 로컬 머신과 캐싱 네임서버에 캐시가 있긴 하지만, **완전한 해석을 처리해야 한다면 트래픽이 훨씬 많아진다.**

### TCP로 하면 — 44패킷

1. 요청 호스트가 로컬 네임서버 **포트 53**으로 **SYN** → 네임서버 **SYN-ACK** → 호스트 **ACK**. **3패킷** (3-way handshake)
2. 호스트가 실제 요청 전송("foo.com의 IP를 알려 달라") → 네임서버가 **ACK**. **누적 5패킷**
3. 캐시에 없으므로 **루트 네임서버**와 통신: 3-way handshake + 요청 + 요청 ACK + 응답 + 응답 ACK + 4-way handshake 종료 = **11패킷**. **누적 16패킷**
4. **TLD 네임서버**를 찾기 위해 같은 과정 반복 = **11패킷**. **누적 27패킷**
5. **권한 네임서버**와 같은 과정 반복 = **11패킷**. **누적 38패킷**
6. 로컬 네임서버가 최초 요청자에게 응답 → 요청자가 **ACK**. **누적 40패킷**
7. TCP 연결을 **4-way handshake로 종료**. **총 44패킷**

> 44패킷은 현대 네트워크 속도에서 큰 수는 아니지만 **빠르게 누적된다.**
> 게다가 **DNS 트래픽은 실제 트래픽의 전주곡일 뿐**이다. 컴퓨터가 DNS 조회를 하는 이유는 궁금해서가 아니라 **그 도메인에 추가 데이터를 보내야 하기 때문**이다.

### UDP로 하면 — 8패킷

1. 원래 컴퓨터가 로컬 네임서버 **포트 53**으로 UDP 패킷 전송("foo.com의 IP를 달라"). **1패킷**
2. 로컬 네임서버가 재귀 서버로서 **루트 서버**에 UDP 패킷 전송 → 응답(알맞은 TLD 네임서버). **누적 3패킷**
3. **TLD 서버**에 패킷 전송 → 응답(올바른 권한 서버). **누적 5패킷**
4. **권한 네임서버**에 최종 요청 → 응답(foo.com의 IP). **누적 7패킷**
5. 로컬 네임서버가 최초 요청자에게 IP로 응답. **총 8패킷**

### 오류 복구는 어떻게 하나

- UDP에는 오류 복구가 없다. **답은 단순하다: DNS 리졸버가 응답을 받지 못하면 그냥 다시 묻는다.**
- 즉 **TCP가 전송 계층에서 제공하는 기능을 DNS가 애플리케이션 계층에서 가장 단순한 방식으로 제공**하는 셈이다.
- **DNS 서버는 들어오는 조회에 응답하는 것 외에는 신경 쓸 필요가 없고**, **DNS 리졸버는 조회를 수행하고 실패하면 반복하기만 하면 된다.**

### DNS over TCP도 존재한다

- **DNS over TCP도 실제로 존재하며 널리 쓰인다.**
- 웹이 복잡해지면서 **모든 DNS 조회 응답이 UDP 데이터그램 하나에 들어가지는 않게** 됐다.
- 이런 경우 **DNS 네임서버가 "응답이 너무 크다"는 패킷으로 응답**하고, **DNS 클라이언트가 TCP 연결을 수립해** 조회를 수행한다.

## 예시

| 방식 | 패킷 수 |
|---|---|
| TCP 완전 재귀 조회 | **최소 44** |
| UDP 완전 재귀 조회 | **8** |

## 요약

- DNS는 포트 53에서 UDP를 기본으로 쓴다.
- 요청·응답이 데이터그램 하나에 들어가고 연결 오버헤드가 없어 UDP가 적합하다.
- 같은 재귀 조회가 TCP로는 44패킷, UDP로는 8패킷이다.
- 오류 복구는 리졸버가 그냥 다시 묻는 방식으로 애플리케이션 계층에서 처리한다.
- 응답이 커서 데이터그램 하나에 안 들어가면 TCP로 전환한다.
