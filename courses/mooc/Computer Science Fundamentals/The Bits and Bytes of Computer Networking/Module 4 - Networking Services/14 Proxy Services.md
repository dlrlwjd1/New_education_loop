# Proxy Services

## 개요

- **프록시 서비스(proxy service)** = **클라이언트를 대신해 다른 서비스에 접근하는 서버**.
- 클라이언트와 다른 서버 사이에 앉아 **익명성, 보안, 콘텐츠 필터링, 성능 향상** 등의 이점을 제공한다.
- **프록시는 특정 구현이 아니라 개념·추상**이며, **거의 모든 계층에 존재**한다.

## 내용

### 이미 배운 프록시

- **게이트웨이 라우터**가 그 예다. 그렇게 부르지는 않지만, **게이트웨이는 프록시의 정의와 동작에 분명히 부합**한다.

### 웹 프록시 (Web Proxy)

프록시라는 말은 대개 **웹 프록시**를 가리킨다. **웹 트래픽 전용으로 만들어진 프록시**다.

#### 과거의 용도 — 성능

- 인터넷 연결이 지금보다 훨씬 느리던 시절, 많은 조직이 **성능 향상**을 위해 웹 프록시를 썼다.
- 모든 웹 트래픽을 프록시로 보내면, **프록시 서버가 인터넷에서 웹페이지 데이터를 가져와 캐시**한다.
- 다른 사람이 같은 페이지를 요청하면 **매번 새로 가져오지 않고 캐시된 데이터를 반환**한다.
- **오늘날에는 잘 쓰이지 않는다.** 이유:
  - 대부분의 조직이 **개별 웹페이지를 캐싱해서 얻는 이득이 별로 없을 만큼 빠른 회선**을 갖게 됐다.
  - **웹이 훨씬 동적**이 됐다. `www.twitter.com`은 자기 계정을 가진 사람마다 다르게 보이므로 **캐싱해도 소용이 없다.**

#### 오늘날의 용도 — 접근 차단

- 오늘날 더 흔한 용도는 **특정 사이트 접근을 아예 막는 것**이다.
- 예: 회사가 **업무 시간의 Twitter 접속이 생산성을 떨어뜨린다**고 판단할 수 있다.
- 모든 웹 트래픽을 웹 프록시로 보내고, **프록시가 어떤 데이터를 요청하는지 검사한 뒤 접속 사이트에 따라 허용하거나 거부**한다.

### 리버스 프록시 (Reverse Proxy)

> 외부 클라이언트에게는 **단일 서버처럼 보이지만**, 실제로는 **그 뒤에 있는 여러 서버를 대표**하는 서비스.

#### 로드 밸런싱

- Twitter처럼 아주 인기 있는 사이트는 트래픽이 너무 많아 **단일 웹 서버로는 도저히 감당할 수 없다.** 들어오는 요청을 처리하려면 **웹 서버가 여러 대** 필요하다.
- 리버스 프록시는 **뒤에 있는 여러 웹 서버의 단일 프론트엔드** 역할을 한다.
- **클라이언트 관점에서는 모두 같은 서버에 연결된 것처럼 보이지만**, 뒤에서는 리버스 프록시가 **들어오는 요청을 여러 물리 서버에 분배**한다.
- **DNS 라운드 로빈과 마찬가지로 이것도 로드 밸런싱의 한 형태**다.

#### 암복호화 오프로드

- **현재 웹 트래픽의 절반 이상이 암호화**돼 있는데, **암호화와 복호화는 처리 능력을 많이 쓰는 과정**이다.
- 그래서 **암호화 전용 하드웨어를 갖춘 리버스 프록시가 암복호화 작업을 대신 수행**하고, **웹 서버는 콘텐츠를 서비스하는 데만 집중**하도록 한다.

## 요약

- 프록시는 클라이언트와 서버 사이에서 대신 동작하는 중개 서버 일반을 가리키는 개념이다.
- 게이트웨이 라우터도 사실상 프록시다.
- 웹 프록시는 과거에는 캐싱으로 성능을 얻었지만, 회선이 빨라지고 웹이 동적이 되면서 지금은 주로 접근 통제에 쓰인다.
- 리버스 프록시는 다수의 백엔드 서버를 하나처럼 보이게 하며, 로드 밸런싱과 암복호화 오프로드에 쓰인다.
