# Resource Record Types

## 개요

- DNS는 **정의된 리소스 레코드 타입(resource record type)** 집합으로 동작한다. 수십 가지가 정의돼 있지만 대부분은 아주 특수한 용도다.
- 기본적인 것들: **A, AAAA(Quad A), CNAME, MX, SRV, TXT**, 그리고 존 관련 **SOA·NS**.

## 내용

### A 레코드

- **가장 흔한 리소스 레코드**로, **특정 도메인 이름을 특정 IPv4 주소로 가리키게** 한다.
- 앞서 DNS 설명에서 리졸버가 요청한다고 가정했던 것이 바로 **A 레코드**다.
- 기본 사용은 도메인 이름 하나에 A 레코드 하나지만, **하나의 도메인 이름이 여러 A 레코드를 가질 수도 있다.**
- 이를 통해 **DNS 라운드 로빈(DNS round robin)** 으로 여러 IP에 트래픽을 분산할 수 있다.

> **라운드 로빈(round robin)** = 목록의 항목들을 **순서대로 하나씩 순회**하는 개념. 목록의 각 항목이 **비교적 균등하게 선택**되도록 하는 것이 목적이다.

#### DNS 라운드 로빈 예시

`www.microsoft.com`에 A 레코드 4개를 설정한다고 하자: `10.1.1.1`, `10.1.1.2`, `10.1.1.3`, `10.1.1.4`.

| 조회 순서 | 응답에 담기는 IP 순서 |
|---|---|
| 첫 번째 조회 | 10.1.1.1 → 10.1.1.2 → 10.1.1.3 → 10.1.1.4 |
| 두 번째 조회 | 10.1.1.2 → 10.1.1.3 → 10.1.1.4 → 10.1.1.1 |
| 이후 | 계속 순환 |

- 조회한 컴퓨터는 **첫 항목을 우선 사용**하되 **네 개를 모두 알고 있다.** 첫 IP로의 연결이 실패할 경우를 대비한 것이다.
- 매 조회마다 순서가 바뀌면서 **트래픽이 IP들에 분산**된다.

### AAAA (Quad A) 레코드

- A 레코드와 매우 비슷하되 **IPv4 대신 IPv6 주소를 반환**한다. **점점 더 많이 쓰이고 있다.**

### CNAME 레코드

- **한 도메인에서 다른 도메인으로 트래픽을 리다이렉트**하는 데 쓴다. **CNAME은 canonical name의 줄임말**이다.
- 예: Microsoft가 웹 서버를 `www.microsoft.com`에서 운영하면서, **`microsoft.com`만 입력한 사람도 제대로 리다이렉트되기를** 원한다.
  - `microsoft.com`에 **`www.microsoft.com`으로 해석되는 CNAME**을 설정한다.
  - 그러면 클라이언트는 **`www.microsoft.com`에 대해 한 번 더 해석을 수행**하고, **두 번째 시도에서 반환된 IP를 사용**한다.

#### CNAME이 유용한 이유 — 단일 진실 공급원

두 도메인이 같은 곳을 가리키게 하는 방법은 두 가지다.

| 방법 | IP가 바뀌면 |
|---|---|
| `microsoft.com`과 `www.microsoft.com`에 **동일한 A 레코드**를 각각 설정 | **두 군데를 모두** 바꿔야 한다 |
| `microsoft.com`에 **CNAME**을 두고 `www.microsoft.com`을 가리키게 함 | **`www.microsoft.com`의 A 레코드 하나만** 바꾸면 된다 |

- 레코드가 두 개일 때는 큰 문제가 아닌 것 같지만, **복잡한 웹 존재감을 가진 대기업은 이런 리다이렉션이 수십 개**일 수 있다.
- **진실의 원천(source of truth)은 하나인 편이 언제나 낫다.**

### MX 레코드

- **MX = mail exchange.** **이메일을 올바른 서버로 배달**하기 위해 쓴다.
- 많은 회사가 **웹 서버와 메일 서버를 서로 다른 머신, 다른 IP에서** 운영한다.
- MX 레코드 덕분에 **이메일은 메일 서버로, 웹 같은 다른 트래픽은 웹 서버로** 확실히 배달된다.

### SRV 레코드

- **SRV = service record.** **여러 특정 서비스의 위치를 정의**하는 데 쓴다.
- MX 레코드와 **목적이 정확히 같되 한 가지가 다르다**: **MX는 메일 서비스 전용**이지만, **SRV는 다양한 서비스 타입의 상세 정보를 반환하도록 정의**할 수 있다.
- 예: **CalDAV**(캘린더·일정 서비스) 같은 서비스의 레코드를 반환하는 데 자주 쓰인다.

### TXT 레코드

- **TXT = text.** 원래는 **사람이 읽을 설명 텍스트를 도메인 이름에 연결**하는 용도로만 의도됐다. 네트워크의 임의적인 세부 사항을 알리는 메모나 메시지를 남겨 두는 발상이었다.
- 그러나 인터넷과 그 위의 서비스가 복잡해지면서, **다른 컴퓨터가 처리할 추가 데이터를 전달하는 데 점점 더 많이 쓰이게** 됐다.
- **완전히 자유 형식(free form)인 필드**가 있어서, 엔지니어들이 **원래 DNS가 전달하려던 것이 아닌 데이터를 전달하는 방법**을 찾아낸 것이다.
- 흔한 용도: **도메인의 어떤 네트워크 서비스를 다른 조직에 맡겼을 때 그 설정 선호를 전달**하는 것.
  - 예: **이메일 배달을 대행하는 email-as-a-service 제공자에게 추가 정보를 전달**하는 데 흔히 쓰인다.

### 그 밖에

- **SOA 레코드** 등은 **DNS 존(zone)에 대한 권한 정보를 정의**하는 데 쓰인다.

## 요약

- A는 IPv4, AAAA는 IPv6 주소를 가리킨다. A 레코드 여러 개로 DNS 라운드 로빈 분산이 가능하다.
- CNAME은 도메인을 다른 도메인으로 리다이렉트하며, IP 변경 지점을 하나로 모아 준다.
- MX는 메일 전용, SRV는 임의 서비스의 위치를 알린다.
- TXT는 자유 형식 필드라 원래 목적을 넘어 기계용 설정 전달에 널리 쓰인다.
