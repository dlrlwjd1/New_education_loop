# NAT and the Transport Layer

## 개요

- 네트워크 계층의 NAT은 단순하지만, **전송 계층에서는 돌아오는 트래픽을 어느 내부 컴퓨터에 줄지** 가려야 해서 복잡해진다.
- 두 가지 기법: **포트 보존(port preservation)** 과 **포트 포워딩(port forwarding)**.

## 내용

### 문제 — 돌아오는 트래픽

- 일대다 NAT에서는 수백, 수천 대의 컴퓨터가 **모두 하나의 IP로 번역**되어 나간다.
- 나가는 것은 이해하기 쉽지만 **돌아오는 트래픽은 더 복잡하다.** 잠재적으로 **수백 개의 응답이 모두 같은 IP로 향하고**, 그 IP의 라우터는 **어느 응답이 어느 컴퓨터로 가야 하는지** 알아내야 한다.

### 포트 보존 (Port Preservation)

> **클라이언트가 고른 출발지 포트를 라우터도 그대로 사용하는 기법.**

- 아웃바운드 연결은 **임시 포트(ephemeral port), 즉 49,152~65,535 범위**에서 출발지 포트를 무작위로 고른다.
- 가장 단순한 구성에서 NAT 라우터는 **이 출발지 포트를 기억해 두었다가, 돌아오는 트래픽을 올바른 컴퓨터로 보내는 데 사용**한다.

#### 예시

1. IP `10.1.1.100` 장치가 아웃바운드 연결을 맺으려 한다. OS의 네트워킹 스택이 **포트 51,300**을 고른다.
2. 이 아웃바운드 연결이 라우터에 도착하면, 라우터는 NAT을 수행해 **IP 데이터그램의 출발지 주소 필드에 자신의 IP**를 넣는다.
3. 하지만 **TCP 쪽의 출발지 포트는 그대로 두고**, 이 데이터를 **내부 테이블에 저장**한다.
4. 이후 **포트 51,300으로 트래픽이 돌아오면**, 라우터는 그것을 **`10.1.1.100`으로 전달해야 함**을 안다.

#### 충돌

- 임시 포트 집합이 아무리 커도, **네트워크의 서로 다른 두 컴퓨터가 비슷한 시점에 같은 출발지 포트를 고를 가능성**은 여전히 있다.
- 이런 일이 생기면 **라우터가 보통 사용되지 않는 포트를 무작위로 골라 대신 사용**한다.

### 포트 포워딩 (Port Forwarding)

> **특정 목적지 포트가 항상 특정 노드로 전달되도록 설정하는 기법.**

- **완전한 IP 마스커레이딩을 유지하면서도 인바운드 트래픽에 응답하는 서비스를 운영**할 수 있게 한다.

#### 예시 1 — 웹 서버 하나

- 네트워크 `10.1.1.0/24`에 **IP `10.1.1.5`인 웹 서버**가 있다.
- 포트 포워딩을 쓰면 **아무도 이 IP를 알 필요가 없다.** 웹 클라이언트는 **라우터의 외부 IP만** 알면 된다.
- 라우터 외부 IP의 **포트 80으로 향한 트래픽은 자동으로 `10.1.1.5`로 전달**된다.
- 응답 트래픽은 **출발지 IP가 라우터의 외부 IP처럼 보이도록 재작성**된다.

#### 예시 2 — 웹 서버와 메일 서버

- 한 회사가 **웹 서버와 메일 서버**를 둘 다 외부에 공개해야 하는데, **서로 다른 서버, 다른 IP**에서 돌아간다.
  - 웹 서버 `10.1.1.5`
  - 메일 서버 `10.1.1.6`
- 포트 포워딩을 쓰면 **두 서비스의 트래픽을 같은 외부 IP(따라서 같은 DNS 이름)** 로 향하게 하면서도, **목적지 포트가 다르기 때문에 완전히 다른 내부 서버로 배달**된다.
- 즉 포트 포워딩은 IP 마스커레이딩뿐 아니라 **외부 사용자가 한 조직이 운영하는 여러 서비스와 상호작용하는 방식을 단순화**한다.

## 요약

- 일대다 NAT에서 돌아오는 트래픽을 구분하는 기본 장치가 출발지 포트다.
- 포트 보존은 클라이언트가 고른 임시 포트를 라우터가 그대로 쓰며 매핑 테이블로 되돌려 보내는 방식이다.
- 두 내부 호스트가 같은 포트를 고르면 라우터가 빈 포트를 무작위로 바꿔 쓴다.
- 포트 포워딩은 외부 포트별로 내부 서버를 지정해, 하나의 외부 IP·DNS 이름으로 여러 내부 서비스를 노출한다.
