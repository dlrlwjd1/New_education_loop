# DHCP in Action

## 개요

- **DHCP 디스커버리(DHCP discovery)** 는 **4단계**로 이루어진다: **DISCOVER → OFFER → REQUEST → ACK**.
- 역설: DHCP는 애플리케이션 계층 프로토콜이라 하위 계층에 의존하는데, **정작 그 목적이 네트워크 계층 설정 자체**다. 그래서 **브로드캐스트로 통신**한다.
- **DHCP 서버는 UDP 67번, 클라이언트는 68번**에서 동작한다.

## 내용

### 1단계 — 서버 디스커버리 (DHCP DISCOVER)

- 클라이언트가 네트워크로 **DHCP discover 메시지**를 보낸다.
- 이 머신은 **IP도 없고 DHCP 서버의 IP도 모르므로**, **특별히 만들어진 브로드캐스트 메시지**를 쓴다.

| 항목 | 값 |
|---|---|
| 목적지 포트 | **UDP 67** |
| 출발지 포트 | **UDP 68** |
| 목적지 IP | **255.255.255.255** (브로드캐스트) |
| 출발지 IP | **0.0.0.0** |

- 이 브로드캐스트는 **LAN의 모든 노드에 전달**되고, DHCP 서버가 있으면 이를 수신한다.

### 2단계 — DHCP OFFER

- DHCP 서버가 **자신의 설정을 검토**해 클라이언트에게 **어떤 IP를 제안할지(또는 제안하지 않을지) 결정**한다. 이는 **동적·자동·고정 중 어떤 할당 방식으로 설정됐는지**에 달려 있다.

| 항목 | 값 |
|---|---|
| 목적지 포트 | 68 |
| 출발지 포트 | 67 |
| 목적지 IP | **255.255.255.255** (브로드캐스트) |
| 출발지 IP | **DHCP 서버의 실제 IP** |

- DHCP offer도 브로드캐스트이므로 **네트워크의 모든 머신에 도달**한다.
- 원래 클라이언트는 이 메시지가 **자신을 위한 것임을 알아본다.** **DHCP offer에 DISCOVER를 보낸 클라이언트의 MAC 주소를 지정하는 필드**가 있기 때문이다.

### 3단계 — DHCP REQUEST

- 클라이언트가 제안된 IP를 확인한다. **기술적으로는 거절할 수도 있다.**
  - **같은 네트워크에서 여러 DHCP 서버가 돌 수도** 있고, 클라이언트가 **특정 범위 안의 IP 제안에만 응답하도록 설정**될 수도 있다. **다만 드문 일이다.**
- 보통은 **DHCP request 메시지**로 응답한다. 뜻은 **"네, 제안해 주신 IP를 받겠습니다."**
- **아직 IP가 배정되지 않았으므로** 출발지 IP는 여전히 **0.0.0.0**, 목적지는 **255.255.255.255**.

### 4단계 — DHCP ACK

- DHCP 서버가 request를 받고 **DHCP ACK(acknowledgment) 메시지**로 응답한다.
- 목적지는 **브로드캐스트 IP 255.255.255.255**, 출발지는 **DHCP 서버의 실제 IP**.
- 클라이언트는 **메시지 필드에 담긴 자신의 MAC 주소**로 이 메시지가 자신을 위한 것임을 알아본다.
- 이제 클라이언트의 **네트워킹 스택이 받은 설정 정보로 자신의 네트워크 계층 설정을 구성**할 수 있다.
- 이 시점에서 클라이언트는 **연결된 네트워크에서 온전히 동작하는 데 필요한 모든 정보**를 갖게 된다.

### DHCP 리스 (Lease)

- 이 모든 설정을 **DHCP 리스(lease)** 라 부르며, **만료 시간(expiration time)** 을 포함한다.
- 리스는 **며칠 동안 유지될 수도, 아주 짧을 수도** 있다.
- **리스가 만료되면 클라이언트는 DHCP 디스커버리 전 과정을 처음부터 다시 수행해 새 리스를 협상**해야 한다.
- 클라이언트는 **네트워크에서 분리될 때 리스를 반납(release)** 할 수도 있다. 그러면 **DHCP 서버가 그 IP를 사용 가능한 풀로 되돌린다.**

## 예시

```
클라이언트                                DHCP 서버
   │  DISCOVER  0.0.0.0:68 → 255.255.255.255:67   │
   │ ───────────────────────────────────────────→ │
   │  OFFER     서버IP:67 → 255.255.255.255:68     │
   │ ←─────────────────────────────────────────── │
   │  REQUEST   0.0.0.0:68 → 255.255.255.255:67   │
   │ ───────────────────────────────────────────→ │
   │  ACK       서버IP:67 → 255.255.255.255:68     │
   │ ←─────────────────────────────────────────── │
        (자기 MAC 주소로 자기 메시지임을 식별)
```

## 요약

- DHCP 디스커버리는 DISCOVER → OFFER → REQUEST → ACK의 4단계다.
- IP가 없는 상태라 전 과정이 브로드캐스트(255.255.255.255)로 오가며, 출발지 IP는 0.0.0.0이다.
- 서버 포트 67, 클라이언트 포트 68이다.
- 브로드캐스트라 모두가 받지만 메시지 안의 MAC 주소로 자기 것을 가려낸다.
- 받은 설정은 만료 시간이 있는 리스이며, 만료되면 전 과정을 다시 수행한다.
