# 06 Approaches to Developing Heuristics (Relaxed Problems, Sub-problems, Learned from Experience)

## 개요
- 강좌: Intelligent Agents and Search Algorithms (University of Colorado Boulder)
- 모듈: Module 3 — Informed Searches
- [MOOC 원본 강의](https://www.mooc.org/learn/intelligent-agents-and-search-algorithms/lecture/AAKOt/approaches-to-developing-heuristics-relaxed-problems-sub-problems-learned-from)
- 휴리스틱을 만드는 **네 가지 접근**: 수작업 → **완화 문제** → **패턴 데이터베이스** → **학습된 휴리스틱**. 8-타일 퍼즐로 관통한다.

---

## 내용

### 출발점 — 8-타일 퍼즐은 완전 탐색이 불가능하다
- 3×3 격자, 타일 1~8과 빈 칸 하나. 목표 배치와 일치할 때까지 한 번에 한 타일씩 민다.
- 규칙은 단순한데 **도달 가능한 상태가 약 1억 8,100만 개**다. → **완전 탐색(brute force)은 완전히 비현실적이다.**
- 그래서 **휴리스틱으로 탐색을 유도**한다.

### 휴리스틱 개발의 역사적 흐름
| 시기 | 방법 |
|---|---|
| 초기 | **단순한 수작업(handcrafted)** — 문제에 대한 인간의 직관 |
| 성숙기 | **문제 구조에서 유도** — 흔히 제약을 제거한 **완화 버전(relaxed version)** 에서 |
| 이후 | **패턴 데이터베이스** — 상태의 부분집합에 대한 **정확한 최적 해**를 저장 |
| 현대 | 로보틱스·게임 AI에서 **휴리스틱을 설계하지 않고 학습한다** |

### 1. 수작업 휴리스틱
- 가장 단순한 접근. **도메인 지식으로 직접 설계**한다.
- 8-타일의 **제자리에 없는 타일 수(misplaced tile)** — **계산은 쉽지만 안내를 거의 못 준다.**

### 2. 완화 문제(relaxed problem)에서 유도하기 ⭐
> **제약을 제거하고 더 쉬운 문제를 풀어** 휴리스틱을 만든다.

**8-타일의 형식적 정의**
> 타일은 A가 B와 **수평 또는 수직으로 인접**하고, **B가 비어 있을 때** A에서 B로 이동할 수 있다.

여기서 제거할 수 있는 제약이 **세 가지**다.

| 제거하는 제약 | 만들어지는 휴리스틱 |
|---|---|
| **A가 B와 인접해야 한다** | 타일을 **임의의 거리로** 옮길 수 있다 → 타일은 제 위치에 있거나 없거나 → **제자리에 없는 타일 수** |
| **이동할 칸이 비어 있어야 한다** | 인접 칸이 비어 있지 않아도 이동 가능 → **맨해튼 거리** (현재 위치에서 최종 위치까지의 거리) |
| **한 번에 한 칸만 이동한다** | → 역시 **제자리에 없는 타일 수** |

> 두 휴리스틱 모두 **허용 가능**하지만 **실제 비용을 꽤 많이 과소평가**하므로 탐색이 매우 느려질 수 있다.

### 3. 패턴 데이터베이스(pattern database) ⭐
> **문제의 부분집합에 대한 정확한 최적 해 비용**을 미리 계산해 **조회 테이블(lookup table)** 에 저장한다. 탐색 중에는 **즉석 계산 없이 값을 조회**만 한다.

**8-타일 예시 — 타일을 세 묶음으로 나눈다**

| 패턴 집합 | 이 배치에서의 최적 비용 |
|---|---|
| 타일 **1, 2, 3** | **9** |
| 타일 **4, 5, 6** | **7** |
| 타일 **7, 8, 빈 칸** | **3** |
| **합계 = 휴리스틱 값** | **19** |

- 각 패턴 데이터베이스는 **그 타일들을 목표 위치로 옮기는 데 필요한 최소 이동 수**를, 보드 어디에 있든 각 배치마다 저장한다.
- **패턴 데이터베이스끼리 겹치지 않는다(non-overlapping).** 한 타일의 해는 오직 하나의 데이터베이스에만 있다. **겹치지 않기 때문에 합해도 허용 가능성이 유지된다.**
- 각 집합의 최적 비용은 **BFS 같은 알고리즘으로 미리 계산**해 저장한다. 해당 타일들의 이동만 세고 **나머지 타일 이동은 비용 0**으로 친다.
- 이 예에서 **패턴 DB 휴리스틱 19 > 맨해튼 거리 17** → **맨해튼 거리를 지배한다.**

### 4. 학습된 휴리스틱(learned heuristics) ⭐
현대 AI에서는 휴리스틱을 **설계하지 않고 학습**하는 경우가 많다.

- **신경망과 강화학습**이 데이터나 자가 대국(self-play)에서 **cost-to-go 함수를 직접 근사**한다.
- 이런 학습된 휴리스틱은 **항상 허용 가능하지는 않지만**, 고전 휴리스틱을 넘어서는 성능을 낸다.

| 예 | 내용 |
|---|---|
| **Neural A\*** | **휴리스틱 함수를 신경망이 학습**하는 현대판 A* |
| **AlphaZero** | 게임 규칙만 주어진 채 시작한다 — **오프닝도, 전술도, 엔드게임 패턴도 없다.** 자기 자신과 수백만 번 대국하며 학습한다. 초기에는 거의 무작위로 두지만 매 게임 후 결과에서 배운다 — **이기는 수는 강화되고 지는 수는 약화된다.** **심층 신경망으로 수를 안내하고, 몬테카를로 탐색 트리(MCTS) 같은 탐색 알고리즘으로 탐색 트리의 가장 유망한 부분에만 집중**한다 |

## 요약
- 8-타일은 **상태 약 1억 8,100만 개** — 완전 탐색이 불가능해 휴리스틱이 필수다.
- 개발 흐름: **수작업 → 완화 문제 → 패턴 데이터베이스 → 학습**.
- **완화 문제**: 제약을 제거해 휴리스틱을 유도한다. "인접" 제약 제거 → 제자리에 없는 타일 수, **"빈 칸" 제약 제거 → 맨해튼 거리**.
- **패턴 데이터베이스**: 겹치지 않는 타일 부분집합의 **정확한 최적 비용**을 미리 계산해 합산. 예시에서 **19로 맨해튼 거리 17을 지배**한다. 대가는 **사전 계산 시간과 메모리**.
- **학습된 휴리스틱**(Neural A*, AlphaZero): 데이터·자가 대국으로 cost-to-go를 근사한다. **허용 가능성을 희생할 수 있지만 크고 불규칙한 환경에서 훨씬 강력하다.**
