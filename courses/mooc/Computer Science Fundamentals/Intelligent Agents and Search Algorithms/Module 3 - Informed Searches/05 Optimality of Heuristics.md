# 05 Optimality of Heuristics

## 개요
- 강좌: Intelligent Agents and Search Algorithms (University of Colorado Boulder)
- 모듈: Module 3 — Informed Searches
- [MOOC 원본 강의](https://www.mooc.org/learn/intelligent-agents-and-search-algorithms/lecture/FRhDx/optimality-of-heuristics)
- **휴리스틱의 품질**이 A*의 실행 시간과 메모리에 미치는 영향. **지배(dominance)** 개념과 **유효 분기 계수**.

---

## 내용

### 휴리스틱 품질이란 — 지배(dominance) ⭐
> 두 허용 가능 휴리스틱 **h₁, h₂** 가 있을 때,
>
> **모든 n에 대해 `h₂(n) ≥ h₁(n)` 이고, 적어도 하나의 n에서 부등호가 엄격하면**
> **h₂가 h₁을 지배한다(dominates)** 고 한다. (엄격 부등호 조건은 둘이 동일하지 않음을 보장한다)

**h₂가 h₁을 지배하면, h₂를 쓰는 A\*는 h₁을 쓰는 A\*보다 노드를 더 많이 확장하지 않는다.**

**왜 그런가**
- A*는 노드의 **f 값이 가장 작을 때만** 그 노드를 확장한다.
- **휴리스틱 값이 크면 f 값이 커지고**, 목표에서 먼 노드의 확장을 **미루거나 아예 막는다.**
- 따라서 지배하는 휴리스틱은 **탐색 초기에 더 많은 노드를 후보에서 제거**한다. **프론티어를 더 일찍 좁혀 메모리를 덜 쓰고, 탐험하는 탐색 트리를 줄인다.**
- 두 휴리스틱이 모두 허용 가능하면 **지배하는 쪽도 허용 가능**하므로 **A\* 최적성은 여전히 보장된다.**

### 예시 — 8-타일 퍼즐의 두 휴리스틱 ⭐

| | h₁ — 제자리에 없는 타일 수 | h₂ — 맨해튼 거리 |
|---|---|---|
| 정의 | 최종 위치에 있지 않은 타일의 **개수** | 각 타일이 **최종 위치까지 떨어진 거리의 합** |
| 예 | 타일 7만 제자리 → **h₁ = 7** | 1번 타일 2칸, 2번 타일 2칸, 3번 타일 1칸… 을 **모두 더한 값** |

- **h₂는 명백히 h₁보다 큰 값을 낸다.** 따라서 **모든 상태 n에서 h₂(n) ≥ h₁(n)** — **맨해튼 거리가 제자리에 없는 타일 수를 지배한다.**
- **맨해튼 거리도 허용 가능하다.** 다른 타일을 비켜 주는 추가 비용을 고려하지 않기 때문이다(즉 과대평가하지 않는다).
- 결론: **맨해튼 거리를 쓰는 A\*는 제자리에 없는 타일 수를 쓸 때보다 극적으로 적은 노드를 확장한다.**

### 유효 분기 계수 (effective branching factor, b*) ⭐
속도 향상을 설명하는 지표다. 주어진 휴리스틱의 안내를 받을 때 **탐색 트리가 평균 몇 개의 자식을 실질적으로 확장하는가**를 측정한다.

```
A*가 깊이 d의 목표에 도달하기까지 n개 노드를 확장했다면
b* = 각 레벨에서 평균 확장 노드 수
```

**왜 중요한가 — 분기 계수의 작은 감소가 탐색 시간의 지수적 절약을 만든다.**

| 상황 | 유효 분기 계수 |
|---|---|
| 휴리스틱 없음 | 약 **10** |
| 약한 휴리스틱 | **6** |
| 강한 휴리스틱 | **2 또는 1.5** |

> 이 지수적 실행 시간 감소 때문에 **휴리스틱 연구가 AI의 주요 분야**가 된다.

### 단 하나의 단서 — 계산 비용 트레이드오프 ⚠️
- **지배하는 휴리스틱은 노드당 계산 시간이 더 들 수 있다.**
- 즉 **강한 휴리스틱은 탐색 효율을 높이지만, 계산이 적당히 싸야 한다.**
- 여기서 설계 트레이드오프가 생긴다 — **휴리스틱을 계산하는 시간 vs 확장을 피해서 아끼는 시간.**

**예 — 8-타일 퍼즐**
- **맨해튼 거리**는 계산이 싸지만, 현실의 지저분한 AI 시스템에는 충분하지 않을 수 있다.
- **패턴 데이터베이스(pattern database)** 휴리스틱은 부분 해를 미리 계산해 **실제 비용에 훨씬 가까운 추정치**를 준다. 대신 **사전 계산 시간과 메모리**가 필요하다.

> 실무에서는 **확장을 줄이는 정확도와 계산 비용의 균형**으로 휴리스틱을 고른다. **휴리스틱 평가 자체가 병목이 되지 않도록.**

### 가중 A*에서의 휴리스틱 품질
- 가중 A*는 `f = g + w·h` (w > 1)로 **휴리스틱의 영향을 증폭**한다. 최적성 보장 대신 **목표 지향 탐험**을 우선한다.
- 최적이 보장되진 않지만 **ε-최적**인 경우가 많다 — 찾은 해의 비용 ≤ **w × 최적 비용**. 이 **유계 준최적 보장**은 속도가 정확한 최적성보다 중요한 실제 시스템에서 유용하다.
- 여기서도 **휴리스틱 품질이 효율을 크게 좌우한다.**
  - **좋은 휴리스틱**(실제 비용에 가까움) → **작은 가중치로도 충분한 속도 향상**
  - **나쁜 휴리스틱** → 실행 시간 이득을 보려면 **큰 가중치가 필요**하고, 그러면 **최적 경로에서 크게 벗어날 위험**이 커진다
- 즉 **가중 A\*는 휴리스틱의 강점과 약점을 둘 다 증폭한다.**

---

## 요약
- **지배(dominance)**: 모든 n에서 `h₂(n) ≥ h₁(n)`이면 h₂가 h₁을 지배하고, **h₂를 쓰는 A\*는 확장 노드가 더 많지 않다.** 둘 다 허용 가능하면 **최적성도 유지**된다.
- 8-타일 퍼즐에서 **맨해튼 거리가 "제자리에 없는 타일 수"를 지배**한다.
- **유효 분기 계수 b\***로 휴리스틱 품질을 잰다. **10 → 6 → 1.5** 로 줄면 탐색 시간이 **지수적으로** 절약된다.
- ⚠️ **트레이드오프**: 강한 휴리스틱은 노드당 계산이 비쌀 수 있다. **정확도와 계산 비용의 균형**으로 고른다.
- 두 휴리스틱이 모두 허용 가능해 **똑같이 최적해를 내더라도, 하나는 밀리초 다른 하나는 몇 시간이 걸릴 수 있다.**
