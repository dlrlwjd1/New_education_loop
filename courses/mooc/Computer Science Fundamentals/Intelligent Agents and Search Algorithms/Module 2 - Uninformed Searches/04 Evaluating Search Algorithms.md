# 04 Evaluating Search Algorithms

## 개요
- 강좌: Intelligent Agents and Search Algorithms (University of Colorado Boulder)
- 모듈: Module 2 — Uninformed Searches
- [MOOC 원본 강의](https://www.mooc.org/learn/intelligent-agents-and-search-algorithms/lecture/h3L4K/evaluating-search-algorithms)
- 탐색 알고리즘이 **좋은지 판단하는 네 가지 고전 기준**과, 실제 AI 시스템에서 추가로 보는 기준들.

---

## 내용

### 왜 평가하는가 — 전부 트레이드오프다
- 어떤 알고리즘은 **빠르지만 최선의 해를 놓칠 수 있고**, 어떤 것은 **최적해를 보장하지만 시간·공간을 엄청나게 먹는다.**
- 평가는 **작업에 맞는 도구를 고르기 위한 것**이다.

| 응용 | 우선순위 |
|---|---|
| 경로 계획 앱 | **최적성** — 최단 경로 |
| 비디오 게임 AI | **속도** — 최선이 아니어도 좋은 행동을 빨리 |
| 실시간 로보틱스 | **메모리** — 제한된 자원 안에서 동작해야 |

### 네 가지 고전 기준 ⭐

#### 1. 완전성(completeness) — 해가 있으면 반드시 찾는가
- **BFS는 완전하다.** 레벨 단위로 모든 노드를 탐험한다.
- **DFS는 무한 공간에서 완전하지 않다.** 끝없는 가지로 내려가 다른 가지로 되돌아오지 못할 수 있다.
- 완전성은 **상태 공간의 구조**와 알고리즘이 **순환(cycle)과 무한 가지를 어떻게 다루는지**에 달려 있다.
- 신뢰성의 **기준선(baseline)** 이다.

#### 2. 최적성(optimality) — 최저 비용 해를 찾는가
| 알고리즘 | 최적성 조건 |
|---|---|
| BFS | **모든 단계 비용이 같을 때만** 최적 |
| 균일 비용 탐색 | 경로 비용 순으로 확장하므로 **최적** |
| A* | 휴리스틱이 **허용 가능(admissible, 실제 비용을 절대 과대평가하지 않음)** 하고 **일관적(consistent, 단조)** 이면 최적 |

> 최적성을 평가할 때는 **"어떤 조건에서 최적이 보장되는가"** 를 함께 물어야 한다.

#### 3. 시간 복잡도(time complexity)
기호 정의:

| 기호 | 뜻 |
|---|---|
| **b** | **분기 계수(branching factor)** — 탐색 트리에서 노드당 평균 후계 수 |
| **d** | **가장 얕은 해의 깊이** |
| **m** | 탐색 트리의 **최대 깊이** |

| 알고리즘 | 시간 복잡도 |
|---|---|
| BFS · DFS | **O(V + E)** — 최악의 경우 지수적 |
| A* (좋은 휴리스틱) | **O(E log V)** — 역시 최악의 경우 지수적 |

> 이 지수적 증가 때문에 **좋은 휴리스틱이 있어도 큰 상태 공간은 금세 다루기 어려워진다.** 그래서 현대 탐색 알고리즘은 시간과 최적성을 저울질한다 — **최선의 해를 오래 걸려 찾는 것보다 좋은 해를 빨리 찾는 편이 나은 경우가 많다.**

#### 4. 공간 복잡도(space complexity)
| 알고리즘 | 메모리 |
|---|---|
| BFS | **모든 프론티어 노드를 저장 → b^d** |
| DFS | **한 경로의 정점만 저장 → O(m)** |
| A* | **방문한 모든 노드를 메모리에 유지 → BFS와 비슷** |

> 탐색 그래프의 노드 100만 개가 각각 수 KB만 써도 **가용 메모리를 금방 넘긴다.** 그래서 A*는 실제 응용에서 변형이 필요하다 — **IDA\*(DFS를 결합)** 나 **동적 A\*(이전 탐색 결과를 재사용)**.

### 실제 시스템에서 추가로 보는 기준

#### 확장성(scalability)
- 문제 크기가 커질 때의 성능. **A\*가 100노드 격자에서는 훌륭해도 10만 노드에서는 완전히 멈출 수 있다.**
- 확장성 있는 알고리즘은 문제 크기 대비 **준선형(sublinear) 또는 로그(logarithmic)** 증가를 보인다.
- 예: 로봇 모션 플래닝의 **RRT(rapidly exploring random trees)** 나 **PRM(probabilistic roadmaps)** 는 A*가 감당 못 하는 **고차원 공간으로 확장된다.**
- 해석: **이론적으로 최적이어도 확장이 나쁘면 산업 규모에서 쓸 수 없다.**

#### 견고성(robustness)
- 변화와 불확실성에 적응하는가. 배달 드론이 돌풍에 적응하거나, 자율주행차가 우회로를 만나면 **탐색 공간 자체가 시간에 따라 변한다.**
- **동적 A\*(dynamic A*)** 는 이전 탐색 결과를 재사용해 장애물이나 비용이 바뀌어도 효율적으로 재계획한다. 반면 고전 BFS·A*는 **처음부터 다시 시작**해야 해 변화하는 환경에서 취약하다.
- 견고성은 **우아한 성능 저하(graceful degradation)** 의 척도다 — 최적은 아니어도 조건이 변할 때 **여전히 합리적으로 동작한다.**

#### 휴리스틱 품질(heuristic quality)
- 휴리스틱 추정치가 **실제 비용에 얼마나 가까운가.** 허용 가능하더라도 **정확도가 효율을 좌우한다.**
- 추정치가 남은 실제 비용에 가까울수록 **A\*는 훨씬 적은 노드를 확장한다.**
- 정량화 지표: **유효 분기 계수(effective branching factor)**
  ```
  b* ≈ (확장된 노드 수) ^ (1/d)
  ```
  탐색 트리 각 레벨의 노드 수를 계산하는 등비급수의 근사다. **b\*가 1에 가까울수록 좋은 휴리스틱**이다.

#### 그 밖에
- **병렬화 가능성** — 여러 코어나 GPU에 분산할 수 있는가
- **학습 가능성(learnability)** — 시간이 지나며 점점 더 나은 해를 내는가
- **에너지·자원 비용** — 모바일에서는 **CPU 시간 대신 전력 사용이 제약**이 될 수 있다

---

## 요약
- 네 가지 고전 기준: **완전성 · 최적성 · 시간 복잡도 · 공간 복잡도.**
- BFS는 완전하고 (단계 비용이 같으면) 최적이지만 **메모리 b^d**. DFS는 메모리 O(m)이지만 **무한 공간에서 불완전**. 균일 비용 탐색은 최적. A*는 **허용 가능 + 일관적** 휴리스틱이면 최적이나 메모리가 지수적.
- 기호: **b**=분기 계수, **d**=최얕은 해 깊이, **m**=최대 깊이.
- 실제 시스템은 **확장성 · 견고성 · 휴리스틱 품질 · 병렬화 · 자원 비용**까지 본다.
- **유효 분기 계수 b\* ≈ (확장 노드 수)^(1/d)** 로 휴리스틱 품질을 측정한다. **1에 가까울수록 좋다.**
- 핵심은 **트레이드오프의 이해** — 속도 vs 정확도, 메모리 vs 완전성, 최적성 vs 실시간 제약.
