# 02 Games in an AI Context

## 개요

- 모듈: Module 5 — Informed Adversarial Searches
- [MOOC 원본 강의](https://www.mooc.org/learn/intelligent-agents-and-search-algorithms/lecture/aTDY3/games-in-an-ai-context)
- **적대적 탐색(adversarial search)** — 환경에 **나와 목표가 정면으로 충돌하는 지능적 상대**가 있는 새로운 종류의 탐색 문제.

---

## 내용

### 무엇이 근본적으로 다른가 ⭐
- 지금까지의 탐색 문제에서는 **세계가 수동적(passive)** 이었다. **미로는 나를 막으려 하지 않고, 퍼즐은 내 전략에 적응하지 않는다.**
- 게임은 다르다. 체스나 틱택토에서는 **환경 안에 내 목표와 직접 충돌하는 목표를 가진 또 하나의 지능적 에이전트**가 있다. **내가 두는 모든 수에 내 진전을 무너뜨리도록 설계된 대응이 돌아온다.**
- 이 **행동-반응(action-reaction) 모델**이 적대적 탐색의 토대다. 탐색 과정은 이제 **지능적 적을 상대로 최선의 행동 방침을 찾는 것**이 된다.

### AI가 집중하는 게임의 종류
> **2인 · 제로섬 · 턴제 · 완전 정보(complete information) 게임**

| 조건 | 뜻 |
|---|---|
| **2인(two-player)** | 정확히 두 에이전트가 참여 |
| **제로섬(zero-sum)** | **한 쪽이 얻는 만큼 다른 쪽이 잃는다** |
| **턴제(turn-taking)** | 동시에 행동하지 않고 **번갈아** 둔다 |
| **완전 정보** | 두 플레이어 모두 **게임 상태 전체를 항상 볼 수 있다.** 숨겨진 카드나 주사위가 없다 |

고전적 예: **틱택토, 체커, 체스, 바둑.**

- **틱택토**는 겉보기엔 사소하지만 **적대적 탐색 문제에 필요한 요소를 전부 담고 있다.** 각 플레이어는 **상대가 내 모든 수에 어떻게 대응할지 예상하며 앞을 내다봐야** 한다. **좋은 수란 지금 유망해 보이는 수가 아니라, 상대의 최선의 대응 아래에서도 버티는 수**다.
- **체스**는 규칙이 훨씬 복잡하다. 각 플레이어가 이동 옵션이 있는 기물 집합을 갖고 **상대 킹을 잡는 것이 목적**이다. **상대가 약화시키려 시도한 뒤에도 강하게 남는 수**를 찾아야 하며, 이는 **여러 수 앞을 추론한다**는 뜻이다.

> **적대적 탐색의 목표: 지능적 상대가 나를 상대로 계획을 세우고 있다고 가정하면서 계획하는 것.**
>
> 질문은 이렇게 바뀐다 — **모든 행동에 최적 상대의 최악 대응이 돌아올 때, AI는 어떻게 수를 골라야 하는가?**

### 게임을 탐색 문제로 형식화하기 ⭐
경로 탐색 문제와 비슷하게 **다섯 요소**로 정의한다.

| 요소 | 뜻 |
|---|---|
| **초기 상태(initial state)** | 게임의 시작 |
| **플레이어(players)** | 예제에서는 **Max**와 **Min**으로 부른다 — 제로섬으로 대립하는 목표를 반영 |
| **행동(actions, 후계 함수)** | 각 게임 상태에서 플레이어가 쓸 수 있는 수 |
| **종료 검사(terminal test)** | 게임이 끝났는지 확인 |
| **효용 함수(utility function)** | 특정 게임 상태에서 **각 플레이어의 보상**. 종료 상태를 포함한다 |

- 이 요소들로 게임을 **게임 트리(game tree)** 로 표현한다 — **노드=상태, 간선=각 플레이어가 둘 수 있는 행동.**
- 경로 탐색의 탐색 트리와 마찬가지로, 게임 트리 위에서 **적대적 탐색 알고리즘**을 돌린다 — **미니맥스**와 **알파-베타 가지치기**.

### 체스가 만족하는 성질
| 성질 | 체스에서 |
|---|---|
| 2인 | 정확히 두 에이전트가 번갈아 둔다 |
| 제로섬 | **승-패 또는 무승부.** 한 쪽이 이기면 다른 쪽이 진다 |
| 턴제 | 동시에 두지 않는다 |
| **결정적(deterministic)** | **무작위성이 없다.** 행동은 예측 가능한 상태로 이어진다 — 기물을 옮기면 항상 그 기물이 옮겨진다 |
| **완전 정보** | 두 플레이어가 항상 전체 상태를 본다 |

> 이렇게 설정하면 **한 플레이어의 최선 행동은 상대의 최적 대응을 예상하는 데 달려 있다.**

### Max와 Min, 그리고 게임 트리의 층 ⭐
- **제로섬 틀은 각 플레이어의 목표 표현을 단순하게 만든다** — 이해관계가 완벽히 대립한다.
- 계산적으로는 플레이어를 **max**와 **min**으로 이름 붙인다. **각 게임 상태에 효용 값이 있고, max는 그것을 최대화하려 하고 min은 최소화하려 한다.**

게임 트리는 **층이 번갈아 나타난다**.

| 노드 | 누구 차례 | 무엇을 고르는가 |
|---|---|---|
| **max 노드** | 우리(에이전트) 차례 | **효용이 가장 높은 행동** |
| **min 노드** | 상대 차례 | **효용이 가장 낮은 행동** |

> **미니맥스 탐색 알고리즘은 min도 최적으로 결정한다는 가정 아래 max의 최적 전략을 계산한다.**

**게임 트리를 그리면** — max가 루트에 있고, max의 자식은 min의 효용 값, min의 자식은 다시 max가 만들 수 있는 값… 이 식으로 **종료 상태까지** 내려간다. 종료 상태는 **게임이 끝나는 모든 지점**이고 규칙에 따라 값이 정해진다.

### 근본 문제 — 조합 폭발 ⚠️
> **가장 작고 단순한 게임조차 조합적(combinatorial) 게임 트리를 갖는다.** 모든 가능한 수를 탐험하는 **전수 탐색은 계산적으로 다루기 어렵다.**
>
> **예: 체스의 가능한 판 상태는 10^40 개.**

그래서 적대적 탐색 알고리즘은 아래에 크게 의존한다.

| 전략 | 트레이드오프 |
|---|---|
| **가지치기(pruning)** | **최적해를 찾는다.** 다만 **게임 트리를 어떻게 구성하느냐가 절약되는 시간에 큰 영향**을 준다 |
| **휴리스틱 · 컷오프 깊이(cutoff depths)** | **빠르다. 대신 최적성을 희생한다** |

## 요약
- **적대적 탐색** = 환경에 **내 목표와 충돌하는 지능적 상대**가 있는 탐색. 미로와 달리 **세계가 나에게 반응한다.**
- AI가 다루는 표준형: **2인 · 제로섬 · 턴제 · 완전 정보 · 결정적** 게임(틱택토·체커·체스·바둑).
- 게임을 다섯 요소로 형식화한다 — **초기 상태 · 플레이어 · 행동 · 종료 검사 · 효용 함수.** 이를 **게임 트리**로 표현한다.
- 플레이어를 **Max**(효용 최대화)와 **Min**(최소화)으로 두고, 게임 트리의 **층이 번갈아** 나타난다.
- **체스의 상태 수는 10^40** — 전수 탐색이 불가능하다. 그래서 **가지치기(최적 유지)** 와 **휴리스틱·컷오프 깊이(빠르지만 준최적)** 가 필수다.
