# 3.1.3 – UML Component Diagram

## 개요

- 컴포넌트 다이어그램(component diagram)은 시스템의 컴포넌트들과 그들 사이의 상호작용·관계를 시각화한다.
- 속성(attribute)이나 메서드(method) 같은 세부 사항이 아니라 고수준 구조(high-level structure)에 집중하는 것이 특징이다.
- 제공 인터페이스(provided interface, 볼 커넥터)와 요구 인터페이스(required interface, 소켓 커넥터)가 맞물리는 조립 관계(assembly relationship)로 컴포넌트 간 관계를 표현한다.

## 내용

### 컴포넌트와 컴포넌트 다이어그램

컴포넌트(component)는 시스템 안의 독립적이고 캡슐화된 단위(independent, encapsulated unit)로 정의된다. 각 컴포넌트는 다른 컴포넌트가 자신과 상호작용할 수 있도록 인터페이스(interface)를 제공한다. 컴포넌트 다이어그램은 시스템의 조각들이 어떻게 상호작용하고 어떤 관계를 갖는지 시각화하는 데 사용된다.

피자에 비유하면, 피자를 이루는 여러 재료 각각이 별개의 컴포넌트이며 서로 상호작용하고 보완하면서 더 큰 시스템(피자) 안에 존재한다.

### 다른 다이어그램과의 차이

컴포넌트 다이어그램을 다른 다이어그램과 구별 짓는 점은 **고수준 구조**를 다룬다는 것이다. 속성과 메서드 같은 세부 사항이 아니라 순수하게 컴포넌트와 그 상호작용만 다룬다. 레스토랑 메뉴가 피자의 조리법을 기술하지 않고 재료와 그 조합만 보여주는 것과 같다. 메뉴에 재료를 모두 나열하면 손님은 컴포넌트들이 전체로서 어떻게 어우러지는지를 보고 그 피자를 좋아할지 판단할 수 있다.

또한 컴포넌트 다이어그램은 소프트웨어 시스템의 **정적 뷰(static view)** 로, 개발·진화 과정의 특정 시점(specific point)에서의 시스템 설계를 보여준다. 이는 레스토랑의 특정 시점에 피자 셰프가 의도한 메뉴 구성과 같다.

### 인터페이스 표기

- **볼 커넥터(ball connector)**: 제공 인터페이스(provided interface)를 표시한다. 컴포넌트가 다른 컴포넌트들이 상호작용할 수 있는 인터페이스를 제공함을 나타내며, 클라이언트·소비자 컴포넌트가 그 컴포넌트와 소통할 수단이 있다는 뜻이다.
- **소켓 커넥터(socket connector)**: 요구 인터페이스(required interface)를 표시한다. 어떤 컴포넌트가 자신의 책임을 수행하기 위해 다른 컴포넌트가 제공하는 특정 인터페이스를 기대함을 나타낸다.
- **조립 관계(assembly relationship)**: 한 컴포넌트의 제공 인터페이스(볼)가 다른 컴포넌트의 요구 인터페이스(소켓)와 맞물리는 관계다.

### 컴포넌트 다이어그램 작성 단계

1. 시스템에서 사용되는 주요 객체(main object)를 식별한다.
2. 시스템에 필요한 관련 라이브러리(library)를 모두 식별한다.
3. 이 컴포넌트들 사이의 관계를 도출한다.

컴포넌트 다이어그램은 직접 구현하는 것에만 집중하지 않는다. 서드파티(third-party) 구현 의존성도 모두 식별해 관련 있는 위치에 다이어그램에 통합해야 한다. 즉 시스템에서 서드파티 라이브러리를 사용한다면 컴포넌트 다이어그램에 표기해야 한다.

### 유용성

- 과도한 세부 사항 없이 컴포넌트 간 관계를 보여주는 데 매우 유용하다.
- 고수준에 집중하므로 빠르게 그릴 수 있고 설계 프로세스 초기부터 유용하다.
- 여러 수준(level)에서 그릴 수 있어 전체 시스템뿐 아니라 특정 하위 시스템(subsystem)에 초점을 맞출 수도 있다. 다이어그램의 스케일을 쉽게 선택할 수 있어 다재다능한 설계 기법이다.

## 예시

- **피자 비유**: 타이 치킨 피자(Thai chicken pizza)의 메뉴에는 치킨, 땅콩 소스, 고수, 치즈가 재료로 나열된다. 메뉴는 조리 방법을 기술하지 않고 재료(컴포넌트)와 그것들이 어떻게 어우러지는지만 보여준다 — 컴포넌트 다이어그램이 구현 세부가 아닌 컴포넌트와 상호작용에 집중하는 것과 같다.
- **인터페이스 표기(텍스트로)**:

```text
[컴포넌트 A] ──○  (볼: A가 제공하는 인터페이스, provided interface)
[컴포넌트 B] ──(  (소켓: B가 요구하는 인터페이스, required interface)

조립 관계: [A] ──○)── [B]   (A의 제공 인터페이스가 B의 요구 인터페이스에 맞물림)
```

## 요약

- 컴포넌트는 인터페이스를 통해 상호작용하는 독립적이고 캡슐화된 단위다.
- 컴포넌트 다이어그램은 속성·메서드 같은 세부 없이 컴포넌트와 그 관계만 보여주는 고수준·정적 뷰다.
- 제공 인터페이스는 볼, 요구 인터페이스는 소켓으로 표기하며, 둘이 맞물리면 조립 관계다.
- 작성 순서: 주요 객체 식별 → 라이브러리(서드파티 포함) 식별 → 관계 도출.
- 빠르게 그릴 수 있어 설계 초기에 유용하고, 전체 시스템부터 하위 시스템까지 스케일을 자유롭게 선택할 수 있다.
