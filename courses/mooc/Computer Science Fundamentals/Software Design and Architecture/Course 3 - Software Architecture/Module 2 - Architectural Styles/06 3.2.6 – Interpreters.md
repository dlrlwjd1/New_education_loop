# 3.2.6 – Interpreters

## 개요

- 인터프리터 기반 아키텍처(interpreter-based architecture)는 최종 사용자가 스크립트(script), 매크로(macro), 규칙(rule)을 작성해 시스템의 기본 기능을 새로운 방식으로 조합·실행할 수 있게 한다.
- 인터프리터(interpreter)는 사용자 입력을 중간 표현(intermediate representation)으로 해석한 뒤 실행하는 컴포넌트다.
- 프로그래밍 가능성(programmability), 유연성(flexibility), 이식성(portability)을 제공하지만 실행 속도가 느릴 수 있다.

## 내용

### 인터프리터란

- 어떤 소프트웨어 시스템은 최종 사용자가 언어를 통해 상호작용할 수 있다. 사용자는 스크립트, 매크로, 규칙을 작성해 시스템의 기본 기능에 접근하고 새로운 방식으로 조합한다.
- Microsoft Excel의 수식이 대표적이다. 셀 A1~A4 값을 합산하라는 수식을 Excel이 런타임(run time)에 수행할 수 있는 이유는, 수식을 중간 표현으로 해석(interpret)한 뒤 그 표현을 실행하기 때문이다. Excel에 내장된 인터프리터가 이 책임을 진다.
- 최종 사용자는 함수의 내부 구현을 알 필요가 없고, 수식이나 스프레드시트가 어떻게 표현되는지도 알 필요가 없다. 인터프리터가 요청된 계산을 알아서 처리한다.
- 인터프리터 기반 아키텍처는 유연하고 이식성 있는 기능을 제공하기 때문에 다양한 상용 시스템에서 사용된다.

### 스크립트와 매크로

- 시스템은 인터프리터로 사용자가 지정한 프로그래밍 가능한 동작을 구동할 수 있다.
- **스크립트**는 흔히 일반 작업 자동화에 쓰인다. 작업 스케줄링, 반복 동작 수행, 다른 명령을 호출하는 복잡한 작업 조합 등을 스크립트로 작성할 수 있다.
- **매크로**는 스크립트의 진화형으로, 그래픽 사용자 인터페이스(GUI)의 등장과 함께 인기를 얻었다. 매크로는 키보드·마우스 입력을 기록해 나중에 실행할 수 있게 한다. 반복적이거나 복잡한 UI 상호작용을 기록해 두었다가 간단하고 빠르게 재생할 수 있다.

### 기능 확장과 최종 사용자 커스터마이징

- 인터프리터는 기존 기능들을 특정 순서로 조합해 새로운 것을 만들어냄으로써 시스템에 기능을 추가하거나 기존 기능을 확장할 수 있게 한다. 이 기존 함수들은 시스템 아키텍처가 정의해 사용자에게 제공하며, 개발자는 가능한 모든 기능 조합을 직접 구현할 필요가 없어진다.
- 예: 웹 브라우저 확장(extension, 플러그인이 아님)은 브라우저에 새 기능을 추가하고 렌더링되는 페이지를 커스터마이징하는 컴포넌트다. 보통 브라우저에 내장된 인터프리터가 실행하는 JavaScript 같은 언어로 구현된다.
- 내장 인터프리터는 개발자뿐 아니라 최종 사용자가 스스로 커스터마이징을 구현하도록 장려한다. 이를 위해 시스템은 최종 사용자의 필요와 사고에 맞는 도메인 특화 추상화(domain specific abstraction)를 가진, 더 쓰기 쉬운 언어를 제공할 수 있다. 전문 개발자가 쓰는 범용 프로그래밍 언어를 요구하는 것보다 진일보한 방식이다.

### 이식성

- 인터프리터를 시스템에 내장하는 것 외에, 시스템 자체를 인터프리터 위에서 도는 언어로 구현할 수도 있다. 이렇게 하면 인터프리터가 지원하는 플랫폼에서 동작하므로 시스템의 이식성이 높아진다.
- 인터프리터와 그 환경이 하부 플랫폼을 추상화하므로 시스템이 더 플랫폼 독립적이 된다.
- 가상 머신(virtual machine)과 가상 환경의 부상으로 이식성이 더 중요해지고 있다. 클라우드(Cloud)에 호스팅되는 서비스가 늘면서, 통제할 수 없는 하드웨어에 소프트웨어를 개발·배포할 수 있는 능력이 점점 중요해진다.

### 단점: 속도

- 인터프리터는 느릴 수 있다. 기본적인 구현은 소스 코드 분석에 시간을 거의 들이지 않고 한 줄씩 번역-실행(line by line translate and execute) 전략을 쓴다.
- 이는 고전적 트레이드오프다. 인터프리터 언어는 개발자에게는 더 빠르고 유연하지만, 컴퓨터가 실행하기에는 더 느리다.

## 예시

### Excel 수식

- `A1`부터 `A4`까지 셀 값을 합산하는 단순한 수식을 Excel의 내장 인터프리터가 중간 표현으로 해석해 실행한다. 이 기능은 A1~A4에 국한되지 않는다.

### Java와 JVM(Java Virtual Machine)

- Java 프로그램은 먼저 중간 언어(intermediate language)로 번역되어 JVM에 로드되고, JVM이 이 중간 언어를 실행한다.
- JVM은 명령이 실행되는 빈도를 모니터링하여 중간 명령을 최적화한다. 자주 실행되는 명령은 기계어(machine code)로 번역해 즉시 실행하고, 같은 중간 명령이 다시 실행될 때는 지연 링킹(Lazy Linking)으로 이전 기계어 번역을 가리키게 한다.
- 자주 쓰이지 않는 명령은 JVM의 인터프리터가 실행하도록 남겨둔다. 자주 쓰는 명령을 매번 번역할 필요가 없고 프로그램 전체를 한꺼번에 번역할 필요도 없어 실행 시간이 줄어든다.
- JVM은 Java 프로그램이 다양한 운영 환경에서 실행되도록 이식성도 제공한다.

## 요약

- 인터프리터는 스크립팅, 매크로 생성, 서로 다른 컴퓨터 아키텍처에서의 프로그램 동작 등 다양한 용도를 지원한다.
- 인터프리터 기반 시스템은 최종 사용자가 기존 기능을 조합해 시스템을 확장·커스터마이징할 수 있게 하며, 도메인 특화 언어로 진입 장벽을 낮출 수 있다.
- 인터프리터 위에 시스템을 구현하면 하부 플랫폼이 추상화되어 이식성이 높아진다(예: JVM).
- 개발 유연성과 실행 속도 사이의 트레이드오프가 있으며, 설계자는 프로그래밍 가능성·유연성·이식성 요구를 다루는 데 인터프리터의 역할을 이해해야 한다.
