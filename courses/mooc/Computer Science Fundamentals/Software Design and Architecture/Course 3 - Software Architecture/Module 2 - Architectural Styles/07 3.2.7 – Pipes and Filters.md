# 3.2.7 – Pipes and Filters

## 개요

- 파이프-필터(pipe and filter) 아키텍처는 데이터 흐름 아키텍처(data flow architecture)의 한 종류로, 시스템을 데이터 집합에 대한 일련의 변환(transformation)으로 본다.
- 필터(filter)는 입력 데이터를 변환하는 독립 개체이고, 파이프(pipe)는 변환되는 데이터 스트림의 커넥터(connector) 역할을 한다.
- 느슨한 결합, 블랙박스화, 재사용성이 장점이지만 필터 오버헤드로 인한 성능 저하가 있고 대화형(interactive) 애플리케이션에는 부적합하다.

## 내용

### 구조와 동작

- 데이터 흐름 아키텍처는 시스템을 단순히 데이터 집합에 대한 일련의 변환으로 간주한다. 데이터는 여러 연산을 거치며 한 형태에서 다른 형태로 변환된다.
- 물이 파이프와 필터를 통과하는 것에 비유할 수 있다. 파이프는 물을 한 곳에서 다른 곳으로 옮기고 필터는 물을 어떤 식으로든 변환한다. 예: 한 필터는 불순물을 걸러 물을 깨끗하게 하고, 다른 필터는 물을 데워, 사용자에게 도달할 때는 깨끗하고 뜨거운 물이 된다.
- 데이터는 한 방향으로 흐른다. 데이터 소스(data source)에서 시작해 파이프와 필터의 연속을 거쳐 데이터 타깃(data target)에서 끝난다.
- 데이터 변경은 필터에서 필터로 순차적으로(sequentially) 이루어진다. 각 파이프는 한 필터의 출력을 다음 필터의 입력으로 전달하는 커넥터다. 각 필터는 이전 파이프에서 받은 입력에 지역 변환(local transformation)을 수행하고 출력을 다음 파이프로 보낸다.

### 필터 순서의 중요성

- 필터가 데이터를 변환하는 순서가 최종 결과를 바꿀 수 있다.
- 물의 예에서는 순서가 무관하다. 물은 결국 뜨겁고 깨끗하게 나온다. 그러나 수학에서 덧셈과 곱셈이 일어나는 순서가 결과를 바꾸는 것처럼, 파이프-필터 아키텍처에서도 순서가 결과에 영향을 줄 수 있다.
- 한 필터의 입력이 다른 필터의 출력이므로 순서가 매우 중요하다.

### UML 표현

- UML 컴포넌트 다이어그램(component diagram)이 파이프-필터 아키텍처의 세부를 보여주기 좋다.
- 데이터 소스는 여러 필터에 연결될 수 있다. 각 필터는 데이터 소스나 다른 필터로부터 입력을 받는 요구 인터페이스(required interface)와 변환된 데이터를 출력하는 제공 인터페이스(provided interface)를 가진다. 데이터 타깃은 완전히 변환된 결과를 받도록 연결된다.

### 장점

- **느슨하고 유연한 결합(loose and flexible coupling)**: 각 필터는 자기 입력과 출력 데이터에만 집중하며 다른 필터와 독립적으로 실행된다. 새로 개발한 필터를 쉽게 추가하거나 필터들을 옮겨 다른 결과를 얻을 수 있다. 개별 필터의 변경도 다른 필터에 영향 없이 쉽게 할 수 있어, 빠르게 변하는 시스템 개발에 매우 중요하다.
- **블랙박스(black box)화**: 시스템 사용자는 각 필터의 내부 동작을 알 필요가 없다. 변환 뒤의 로직을 몰라도 필터를 사용해 다양한 데이터셋을 변환할 수 있다.
- **재사용성(reusability)**: 각 필터는 서로 다른 입력으로 반복해서 호출·사용할 수 있고, 다른 애플리케이션에서 다른 목적으로도 반복 사용할 수 있다.

### 단점

- **필터 오버헤드로 인한 성능 저하**: 각 필터는 입력을 받아 어떤 자료 구조(data structure)로 파싱하고, 변환을 수행한 뒤 데이터를 내보낸다. 다음 필터도 똑같이 파싱-변환-전송을 반복한다. 모든 필터가 비슷한 파싱·출력 단계를 거치면 오버헤드가 크며, 필터가 늘어날수록 시스템 성능이 급격히 떨어진다.
- **필터 과부하와 기아(starvation)**: 필터가 처리해야 할 대량의 데이터로 과부하될 수 있다. 한 필터가 큰 데이터를 처리하느라 바쁜 동안 다른 필터들은 입력을 기다리며 굶주릴 수 있다.
- **대화형 애플리케이션에 부적합**: 데이터 전송과 변환은 전송되는 데이터 양에 따라 시간이 걸리므로, 빠른 응답이 필요한 애플리케이션에는 적합하지 않다.

## 예시

- **물 파이프와 필터 비유**: 한 필터는 물의 불순물을 제거하고 다른 필터는 물을 데워, 최종적으로 깨끗하고 뜨거운 물이 사용자에게 전달된다.
- **UNIX 텍스트 기반 유틸리티**: 파이프-필터 아키텍처가 쓰이는 대표적 시스템으로, UNIX 운영체제의 텍스트 기반 유틸리티들이 있다.

## 요약

- 파이프-필터 아키텍처는 데이터를 데이터 소스에서 데이터 타깃까지 한 방향으로 흘리며 필터마다 순차적으로 변환한다.
- 필터 순서가 최종 결과에 영향을 줄 수 있으므로 순서가 매우 중요하다.
- 장점: 느슨한 결합, 필터의 블랙박스화, 높은 재사용성과 유연성.
- 단점: 필터마다 반복되는 파싱 오버헤드로 인한 성능 저하, 필터 과부하·기아, 대화형 애플리케이션 부적합.
- 서로 다른 데이터셋을 다양한 방식으로 조작해야 할 때 고려할 만한 인기 있는 아키텍처다.
