# 3.2.2 – Main Program and Subroutine

## 개요

- 메인 프로그램과 서브루틴(main program and subroutine) 아키텍처 스타일은 절차적 프로그래밍 패러다임(procedural programming paradigm)에서 비롯된다. C가 이 패러다임을 따르는 대표 언어다.
- 시스템의 전체 기능을 메인 프로그램과 서브루틴들로 분해하며, 함수의 동작과 데이터 흐름을 중심으로 사고한다.
- 계산 중심(computation-focused) 시스템에 적합한 스타일이다.

## 내용

### 용어와 기본 구조

- 루틴(routine), 프로시저(procedure), 함수(function)는 서브루틴(subroutine)과 서로 바꿔 쓰이는 용어다.
- 이 스타일은 근본적으로 **함수에 초점**을 둔다. 시스템의 전체 기능을 메인 프로그램과 서브루틴들로 쪼갠다.
- 서브루틴들은 프로시저 호출(procedure call)로 연결되며, 서브루틴이 다른 서브루틴을 부르고 그것이 또 다른 서브루틴을 부르는 중첩 호출(nested call)이 가능하다.
- 그 결과 코드 구조는 평평하지 않고 계층적(hierarchical)이며, 방향 그래프(directed graph)로 모델링할 수 있다. 코드에 선언된 서브루틴들은 큰 호출 트리(call tree) 형태로 구조화된다.
- 서브루틴들의 구조가 시스템 전체의 구조에 영향을 준다.

### 데이터 처리 방식

- 이 패러다임에서 데이터는 변수(variable)로 저장된다.
- 객체지향처럼 추상 데이터 타입(abstract data type)을 지원하지만, **상속(inheritance)은 명시적으로 지원되지 않는다.** 한 추상 타입을 다른 타입의 확장으로 만들기 쉽지 않다.
- 객체지향과 달리 주된 관심사는 함수의 행동과 데이터가 함수들을 통해 어떻게 이동하는가다.
- 각 서브루틴은 자체 지역 변수(local variable)를 가질 수 있으며, 자기 스코프(scope) 안의 모든 데이터에 접근할 수 있다.
- 스코프 밖의 데이터는 매개변수(parameter)로 값 전달(by value) 또는 참조 전달(by reference)로 넘겨주고, 반환값(return value)으로 데이터를 내보낸다.
- 이 패러다임에서 나오는 원칙으로 **서브루틴당 하나의 진입점, 하나의 출구(one entry, one exit)** 가 있으며, 이는 제어 흐름을 따라가기 쉽게 만든다.

### 장점

- 모듈성(modularity)과 함수 재사용(function reuse)을 촉진한다.
- 함수가 잘 정의되면 블랙박스(black box)처럼 취급할 수 있다. 특정 입력에 대해 항상 같은 출력을 기대할 수 있다.
- 모든 기능을 처음부터 작성하는 대신 라이브러리 함수를 쉽게 통합할 수 있다.

### 잠재적 문제

- 서브루틴이 데이터를 예기치 않게 변경(mutate)할 수 있다. 실행 중 다른 서브루틴이 바꾼 데이터의 영향을 받을 수 있다.
- 이 문제는 서브루틴 간에 공유되는 전역 데이터(global data)에서 특히 심각하다.
- 예측 불가능한 데이터 변경은 함수가 예상하지 못한 입력, 혹은 올바르게 처리할 수 없는 입력을 받게 만들어 런타임 오류(runtime error)로 이어질 수 있다.

### 객체지향 스타일과의 비교

- 계산 중심 시스템에서 객체지향 컴포넌트를 식별하는 일은 힘들고, 특히 단순한 프로그램에 적용하면 지나치게 복잡한 해법이 될 수 있다.
- 반대로 상속을 가진 추상 데이터 타입이 문제 모델링을 쉽게 해준다면 객체지향 아키텍처 스타일이 더 합리적일 수 있다. 문제에 따라 선택이 달라진다.

## 예시

### 지출 관리 프로그램(spending management program)

- 총 지출액을 추적할 뿐 아니라 지출이 어떤 카테고리에 속하는지 정보를 제공하는 지출 보고 프로그램이다.
- 전체 기능을 각각의 부분을 담당하는 작은 서브루틴들로 쉽게 구현할 수 있어 이 스타일이 특히 적합하다.
- 동작 흐름:
  1. 카테고리별 지출 계산을 담당하는 서브루틴이 먼저 모든 구매 내역을 파싱(parse)하여 각 구매의 카테고리를 판별하는 서브루틴을 호출한다.
  2. 이어서 각 카테고리의 구매 금액을 합산하는 서브루틴을 호출한다.
  3. 다음으로 메인(main)에서 전체 카테고리의 지출 합계를 구하는 서브루틴을 호출한다.
  4. 마지막으로 메인에서 이 데이터를 보고서로 변환해 사용자에게 출력하는 서브루틴을 호출한다.

## 요약

- 메인 프로그램과 서브루틴 스타일은 절차적 프로그래밍 패러다임에서 나오며, 프로그램을 작은 서브루틴들로 구성해 함수 모듈성과 재사용을 촉진한다.
- 데이터는 변수로 저장되고 매개변수·반환값으로 이동하며, 상속은 명시적으로 지원되지 않는다.
- 계산 중심 시스템에 이상적인 후보이지만, 공유 전역 데이터의 예기치 않은 변경이 런타임 오류를 일으킬 수 있다.
- 상속이 있는 추상 데이터 타입이 모델링을 쉽게 한다면 객체지향 스타일이 더 적합할 수 있다.
