# 3.2.1 – Abstract Data Types and Object-Oriented

## 개요

- 시스템 구현에 사용하는 언어의 프로그래밍 패러다임(programming paradigm)이 시스템의 아키텍처 스타일에 영향을 준다.
- 이 강의는 객체지향 프로그래밍 패러다임에서 비롯되는 객체지향 아키텍처 스타일(object-oriented architectural style)을 다룬다.
- 객체지향 스타일은 데이터를 중심에 두고 시스템을 추상 데이터 타입(abstract data type)으로 분해한다.

## 내용

### 언어 기반 아키텍처와 프로그래밍 패러다임

- 각 프로그래밍 패러다임은 고유한 구성 요소(construct)를 가지며, 그 사용 방식이 만들어지는 시스템의 형태를 결정한다.
- Java나 C++ 같은 객체지향 언어를 선택하면 단순히 언어만 고르는 것이 아니라 객체지향 원칙, 구성 요소, 설계 문제 전체를 함께 선택하는 셈이다.

### 객체지향 원칙 복습

- **추상화(abstraction)**: 중요하지 않은 세부 사항을 무시하여 개념을 단순화한다.
- **캡슐화(encapsulation)**: 데이터와 함수를 하나의 자기 완결적 객체로 묶고, 다른 객체는 노출된 인터페이스를 통해서만 상호작용하게 한다.
- **분해(decomposition)**: 전체 문제를 더 작고 구별되는 부분으로 나눈다.
- **일반화(generalization)**: 개념적 공통점을 추출(factor out)한다.

### 객체지향 디자인 패턴

- 객체지향 디자인 패턴은 생성(creational), 구조(structural), 행동(behavioral) 범주로 나뉜다.
- 생성 패턴은 새 객체를 만드는 방법을 안내한다.
- 구조 패턴은 객체 간의 관계와 클래스·서브클래스 간의 상호작용을 기술한다.
- 행동 패턴은 객체가 개별적으로 일을 수행하는 방식과 그룹으로 협력해 무언가를 이루는 방식에 초점을 둔다.
- 이런 요소들이 모여 시스템의 객체지향 아키텍처 스타일을 이끌어낸다.

### 객체지향 아키텍처 스타일의 특징

- 이 스타일은 **데이터에 초점**을 둔다. 시스템이 다루는 여러 종류의 데이터를 살펴보고 시스템을 추상 데이터 타입으로 분해할 수 있는지 본다.
- 추상 데이터 타입은 관련 속성(attribute)과 그에 딸린 메서드(method)를 의미 있게 묶어 정의한 클래스(class)로 표현된다.
- 캡슐화는 데이터 접근을 제한하고 데이터로 무엇을 할 수 있는지를 규정한다.
- 객체지향이란 객체(object)들로 구성된 시스템을 뜻하며, 각 객체는 클래스의 인스턴스(instance)다. 즉 객체의 타입은 그 클래스다.
- 객체들은 메서드를 통해 서로 상호작용한다.
- 객체지향 패러다임은 추상 데이터 타입 간의 **상속(inheritance)** 을 지원한다. 한 추상 타입을 다른 타입의 확장(extension)으로 선언할 수 있다.
- 시스템 내 클래스들이 시스템의 전체 구조를 결정하며, 이는 기본 객체지향 원칙에서 자연스럽게 나오는 언어 기반 아키텍처다.

### 스타일의 적합성과 한계

- 어떤 문제는 객체지향 아키텍처 스타일에 잘 맞지만, 클래스 식별이 항상 쉬운 것은 아니다.
- 과학 계산(scientific computation) 중심 시스템에서는 클래스 식별이 불필요한 복잡성을 낳고 성능 저하로 이어질 수 있다.
- 객체지향 패러다임이 항상 가장 적절한 해법은 아니며, 문제에 따라 다른 설계 선택이 더 적합할 수 있다.

## 예시

### 자동 급식기(automatic pet feeder)

- 시스템의 객체는 반려동물(pet)과 급식기(food dispenser)다.
- 급식기는 사료(kibble)를 담는 저장 용기를 갖고, 용기 바닥이 일시적으로 열려 아래 그릇에 사료를 배출하며, 사료가 떨어지면 위쪽 표시등이 깜박인다.
- 각 반려동물은 고유 ID 태그가 달린 목걸이를 착용하고, 급식기에 가까이 가면 태그가 급식기를 작동시켜 사료 한 끼분을 배출하게 한다.
- **Pet 클래스**: 목걸이 ID, 하루 최대 섭취량(pet owner가 설정), 현재 섭취량을 속성으로 가지며, 매일 아침 현재 섭취량을 0으로 재설정하는 메서드를 가진다.
- **Food Dispenser 클래스**: 어떤 반려동물이 이용 가능한지(authorized)와 남은 사료량을 속성으로 추적하고, 사료 배출 메서드와 사료 소진 시 표시등을 깜박이는 메서드를 가진다.
- 이 클래스들의 인스턴스가 상호작용하여 특정 반려동물이 방문했을 때 사료를 배출할지 결정한다.

## 요약

- 객체지향 아키텍처 스타일은 객체지향 개발 접근에서 직접적으로 따라 나온다.
- 시스템의 데이터를 추상 데이터 타입(클래스)으로 모델링하고, 캡슐화로 접근을 제한하며, 상속으로 타입을 확장한다.
- 클래스 식별이 쉬운 문제(예: 자동 급식기)에는 잘 맞지만, 계산 중심 시스템에서는 불필요한 복잡성과 성능 저하를 초래할 수 있다.
- 문제에 따라 객체지향이 아닌 다른 설계 선택이 더 적절할 수 있다.
