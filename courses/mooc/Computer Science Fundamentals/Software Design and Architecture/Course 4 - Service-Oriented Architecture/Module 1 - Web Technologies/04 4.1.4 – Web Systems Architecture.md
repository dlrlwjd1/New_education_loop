# 4.1.4 – Web Systems Architecture

## 개요

- 계층형 아키텍처(layered architecture)를 웹 기반 시스템에 적용하는 방법을 다룬다.
- 웹 기반 시스템은 보통 웹 브라우저, 웹 서버, 애플리케이션, 데이터의 4개 계층으로 나뉜다.
- 정적 콘텐츠 제공에는 애플리케이션 계층이 필요 없고, 동적 콘텐츠 제공에는 4개 계층이 모두 필요하다.
- 계층화와 외부 웹 서비스 활용은 관심사의 분리(Separation of Concerns)와 코드 재사용(Code Reuse)이라는 기본 설계 원칙의 실현이다.

## 내용

### 계층(Layer) 복습

계층은 공통 목적을 향해 함께 동작하는 컴포넌트들의 모음이다. 계층을 사용해 시스템의 위계(hierarchy)를 식별하고 계층 간 상호작용을 제한한다.

- 한 계층의 컴포넌트는 같은 계층 또는 **인접 계층**의 컴포넌트와만 상호작용하며, 각 컴포넌트가 제공하는 인터페이스를 통해서만 한다.
- 일반적으로 하위 계층이 상위 계층에 서비스를 제공한다.
- 복잡한 시스템일수록 컴포넌트를 논리적으로 분리하기 위해 더 많은 계층이 필요하지만, 계층이 늘어나면 계층 간 통신 증가로 성능이 저하되는 단점이 있다.
- 계층형 시스템은 흔히 프레젠테이션(presentation), 애플리케이션(application), 데이터(data) 티어(tier)로 개념화된다. 웹 기반 시스템에서는 프레젠테이션 티어를 웹 브라우저와 웹 서버, 두 계층으로 나눈다.

### 웹 기반 시스템의 4계층

아키텍처는 각 계층을 노드(node)로 표현한 UML 배치 다이어그램(deployment diagram)으로 나타낼 수 있다.

- **웹 브라우저 계층**: 최상위 계층. 사용자에게 정보를 표시한다.
- **웹 서버 계층**: 브라우저 바로 아래. 브라우저의 요청을 받아 요청된 콘텐츠를 얻은 뒤 브라우저에 반환한다.
- **애플리케이션 계층**: 시스템이 제공하는 기능(function) 또는 서비스가 수행되도록 책임진다.
- **데이터 계층**: 최하위 계층. 데이터의 저장·유지·관리를 담당한다. 데이터 접근은 읽기 전용(read-only)일 수도 있고 읽기·쓰기 모두 허용할 수도 있으며, 시스템에 따라 파일 시스템이나 데이터베이스 형태를 띤다.

이것이 웹 시스템을 나누는 전형적인 계층이지만 유일한 방법은 아니다. 모든 시스템이 4개 계층을 다 필요로 하지 않고, 같은 방식으로 사용하지도 않는다.

### 정적 웹 콘텐츠의 계층 구조

정적 웹 페이지를 제공하려면 웹 브라우저 계층, 웹 서버 계층, 데이터 계층이 필요하다.

- 웹 브라우저 계층: 웹 서버가 제공한 정보를 표시한다.
- 웹 서버 계층: 브라우저의 요청을 받아 데이터 계층에 저장된 해당 HTML 문서를 가져와 브라우저에 반환한다.
- 데이터 계층: 웹 서버가 변경 없이 그대로 브라우저에 전달할 정적 HTML 문서들로 구성된다. 문서가 변하지 않으므로 파일 시스템은 읽기 전용이어도 된다.
- **애플리케이션 계층은 없다.** 서버가 제공하는 HTML 문서가 파일 시스템에 저장된 것과 완전히 동일해서 어떤 처리도 필요 없기 때문이다.

### 동적 웹 콘텐츠의 계층 구조

동적 웹 페이지를 제공하려면 웹 브라우저, 웹 서버, 애플리케이션, 데이터 계층이 모두 필요하다.

- 브라우저와 서버(프레젠테이션)는 정적 콘텐츠 때와 동일하게 동작한다.
- 정적 페이지와 달리 HTML 문서는 브라우저가 요청할 때 생성된다. 웹 서버는 요청을 애플리케이션 계층의 애플리케이션 서버(application server)로 넘겨 처리한다.
- 애플리케이션 계층은 요청을 처리해 결과 콘텐츠를 생성하는 하나 이상의 프로그램·애플리케이션으로 구성될 수 있다. 또한 다른 웹 서비스를 호출하거나 데이터 계층을 통해 데이터베이스를 읽고 쓸 수 있다.
- 이 계층화 방식은 복잡한 웹 애플리케이션의 아키텍처에도 그대로 적용된다.

### 서비스 관점의 대안적 시각

UML 컴포넌트 다이어그램(component diagram)을 사용해, 웹 기반 시스템의 설계를 서비스들과 서비스 요청자–제공자 쌍(requester-provider pairings)의 모음으로 볼 수도 있다.

- 예: 데이터베이스는 데이터 서비스를 제공하고, 애플리케이션 서버는 데이터베이스에 대한 서비스 요청자다.
- 애플리케이션 서버가 실행하는 프로그램은 시스템 외부에서 제공되는 다양한 웹 서비스에 접근할 수 있고, 그 웹 서비스는 다시 다른 서비스에 접근할 수 있다.

### 설계 원칙과의 연결

계층형 아키텍처와 외부 웹 서비스 사용은 매우 기본적인 설계 원칙, 즉 **관심사의 분리**와 **코드 재사용**으로 돌아간다.

- 각 계층은 매우 구체적인 책임을 가진다(관심사의 분리).
- 외부 서비스는 시스템이 직접 구현하지 않아도 되는 기능을 제공한다 — 소프트웨어 재사용의 훌륭한 예다.
- 웹 서비스 활용의 범위는 방대하지만, 어떤 서비스를 쓸지 올바르게 식별하는 과제가 따른다.
- 서로 다른 플랫폼·언어 환경에서 이것이 동작하려면 웹 콘텐츠와 통신에 대한 표준이 중요하며, 이는 다음 강의들에서 다룬다.

## 요약

- 웹 기반 시스템은 보통 웹 브라우저 → 웹 서버 → 애플리케이션 → 데이터의 계층으로 구성되며, 인접 계층끼리 인터페이스를 통해서만 상호작용한다.
- 정적 콘텐츠 시스템은 데이터 계층 + 두 개의 프레젠테이션 계층(브라우저·서버)으로 매핑되고 애플리케이션 계층이 없다.
- 동적 콘텐츠 시스템은 요청 시 맞춤 HTML을 생성하기 위해 웹 서버와 데이터 계층 사이에 애플리케이션 계층이 필요하다.
- 시스템은 서비스 요청자–제공자 쌍의 모음으로도 볼 수 있으며, 계층화와 외부 서비스 사용은 관심사의 분리와 코드 재사용의 실천이다.
