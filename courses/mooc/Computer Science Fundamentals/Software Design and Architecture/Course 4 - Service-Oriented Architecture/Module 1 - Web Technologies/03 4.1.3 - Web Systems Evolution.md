# 4.1.3 - Web Systems Evolution

## 개요

- 웹 서비스 기반 SOA를 이해하기 위해 웹 기반 시스템의 기원과 진화를 살펴본다.
- 인터넷(Internet)과 월드 와이드 웹(World Wide Web)은 서로 다른 개념이며, 인터넷이 약 20년 먼저 등장했다.
- 웹은 정적 웹 페이지(static web page) → 동적 웹 페이지(dynamic web page) → 웹 애플리케이션(web application)으로 진화했다.
- 웹 애플리케이션은 웹 서비스와 통합해 실시간 정보를 활용하는 더 풍부한 애플리케이션을 만든다.

## 내용

### 인터넷과 웹의 기원

인터넷과 웹은 흔히 혼용되지만 서로 다른 것을 가리킨다.

- 1969년, 인터넷의 전신인 소규모 컴퓨터 네트워크 **ARPANET**을 통해 미국 연구자들이 컴퓨터 쌍 사이에 소량의 데이터를 전송했다. 컴퓨터 네트워크로 데이터가 전송된 최초의 사례다.
- 이후 미국 각지 연구 기관의 소규모 네트워크들이 서로 연결되기 시작했고, 이 "네트워크들의 네트워크"가 전 지구적 규모로 성장하면서 인터넷이 탄생했다.
- 뇌가 연상(association)을 통해 정보를 연결하는 방식에서 영감을 받은 **팀 버너스리(Tim Berners-Lee)** 는 네트워크 상에서 문서를 연결하는 방법을 연구했고, 1990년 하이퍼텍스트(hypertext)에서 영감을 받아 인터넷 위에 구축된 웹 관리 시스템, 즉 **월드 와이드 웹**을 제안했다.

웹은 인터넷을 통한 컴퓨터 기반 통신을 위한 표준과 기술로 이어졌다. 대표적으로,

- **HTML(HyperText Markup Language)**: 웹 콘텐츠를 표현하는 표준
- **HTTP(HyperText Transfer Protocol)**: 요청을 만들고, 응답을 받고, 콘텐츠를 주고받는 표준

1990년대 초 HTML과 웹 브라우저의 등장으로 웹의 인기가 크게 높아졌다. 웹 페이지를 보려면 브라우저가 해당 페이지를 호스팅하는 웹 서버에 요청을 보내고, 웹 서버는 요청된 웹 페이지에 해당하는 HTML 문서를 반환하며, 브라우저가 그 문서를 렌더링해 사용자에게 보여준다. 브라우저와 서버의 관계는 **클라이언트-서버(client-server)** 관계이며, 요청과 응답 모두 양쪽이 이해하는 통신 프로토콜인 HTTP 메시지로 전달된다.

### 정적 웹 페이지 (Static Web Pages)

초기 웹은 정적 웹 페이지로만 이루어져 있었다.

- 각 정적 페이지는 서버에 별도의 HTML 파일로 저장된다.
- 브라우저에 렌더링되는 HTML은 서버에 저장된 HTML 문서와 동일하다. 즉, 서버의 문서는 클라이언트에 제공되기 전에 변경되거나 맞춤화되지 않는다.
- 페이지의 모양이나 내용을 바꾸려면 개발자가 해당 HTML 문서를 직접 수정해야 하고, 작은 변경도 사이트 전체의 일관성을 위해 여러 HTML 문서를 수정해야 할 수 있다.
- 모든 변경에 개발자의 수동 개입이 필요하므로, 정적 사이트는 개인 웹사이트나 출판물처럼 자주 바뀌지 않는 정보 제시에 주로 쓰인다.

### 동적 웹 페이지 (Dynamic Web Pages)

1993년, 정적 페이지의 맞춤화·확장성 한계에 대응해 동적 웹 페이지가 등장했다.

- 동적 웹 페이지는 **접근 시점에 애플리케이션이 생성**한다. 정적 페이지와 달리 서버에 미리 존재하지 않는다.
- 웹 서버는 요청을 애플리케이션에 넘기고, 애플리케이션은 계산을 수행하거나, 데이터베이스에서 정보를 조회하거나, 웹 서비스에 정보를 요청해 동적 콘텐츠를 출력으로 만든다. 애플리케이션이 HTML 문서를 생성하면 서버가 이를 브라우저에 보내고, 브라우저가 표시한다.
- 개발자 입장에서는 데이터베이스 요소 하나나 애플리케이션 변수 하나만 바꿔도 사이트 전체에 변경이 반영되므로, 정적 사이트보다 변경이 쉽다.

동적 웹 페이지가 매력적인 이유: 보는 사람에 맞게 맞춤화할 수 있고, 외부 이벤트에 반응할 수 있고, 일반적으로 더 많은 기능을 제공하며, 개발자가 수정하기 쉽다. 이런 이유로 현재 동적 페이지가 웹을 지배하며, 개인 블로그부터 뉴스피드까지 모든 곳에 쓰인다.

방문 중인 사이트가 정적인지 동적인지 구별하는 단서는 페이지의 복잡성이다. 방문 시점에 따라 내용이 달라지는가? 같은 페이지를 다른 사람이 볼 때 다른 내용이 보이는가? 접근 전에 로그인 같은 추가 정보를 제공해야 하는가? 하나라도 "예"라면 동적 페이지일 가능성이 높다.

다만 정적 페이지도 여전히 쓸모가 있다. 모든 페이지가 개인화되거나 하루 종일 내용이 바뀔 필요는 없으며, 단순하고 변하지 않는 정보 제시에는 성능 보장을 위해 정적 페이지가 나은 선택일 수 있다.

### 웹 애플리케이션 (Web Applications)

최근에는 웹 기반 애플리케이션, 줄여서 웹 애플리케이션으로의 흐름이 커지고 있다.

- 웹 애플리케이션은 데스크톱 애플리케이션처럼 GUI를 제공해 사용자와 상호작용한다.
- 큰 차이: 데스크톱 앱은 로컬 컴퓨터에 저장되어 실행되지만, 웹 앱은 **웹 브라우저에서 실행되고 원격 웹 서버에 저장**된다.
- 웹 앱은 플랫폼 독립적(platform independent)이다. 호환되는 브라우저만 있으면 어떤 운영체제에서도 동작하며, 사용자가 소프트웨어를 내려받고 유지 관리할 필요가 없다.
- 대신 정보가 HTTP로 웹 서버·애플리케이션 서버와 통신되므로 거의 항상 인터넷 접속이 필요하다. 애플리케이션에 따라 이는 수용 가능한 트레이드오프일 수 있다.
- 웹 앱은 단순한 동적·정적 페이지보다 더 풍부하고 인터랙티브한 경험을 제공한다. 온라인 뱅킹, 온라인 학습, 온라인 게임, 계산기, 캘린더 등이 그 예다. 예를 들어 Google Docs는 여러 사용자가 실시간으로 텍스트 문서를 공동 편집할 수 있는 브라우저 기반 워드 프로세서다.

### 웹 서비스와의 통합

현대의 웹사이트·웹 앱은 특정 콘텐츠를 제공하기 위해 다른 웹 서비스와 통합하는 경우가 많고, 그 웹 서비스는 다시 다른 서비스에 의존할 수 있다.

- 웹 서비스는 주식 시장 데이터, 날씨 정보, 환율 변환 같은 특정 요구를 충족하는 데 쓰인다.
- 웹 서비스를 **재사용 가능한 컴포넌트**처럼 취급하면, 하나의 웹 서비스가 만든 정보를 여러 웹 앱이 동시에 사용할 수 있다.
- 웹 앱과 웹 서비스는 HTTP, XML, JSON처럼 기계가 다루기 쉬운 개방형 표준(open standards)으로 통신한다. 일부 서비스는 프로그래밍 방식으로 접근하지만, 웹 페이지나 앱에 임베드할 수 있는 사용자 인터페이스가 딸린 서비스도 있다.

구체적 예시: 개인 랜딩 페이지를 만든다고 하자. 블로그나 글 포트폴리오 같은 자체 콘텐츠 외에, 마이크로블로깅 서비스의 최신 게시물, 외부 사진 저장 서비스의 사진, 캘린더와 여행 일정 정보를 통합한 애플릿(만날 수 있는 시간과 위치 표시) 등 외부 서비스를 사용한다. 이 서비스들의 요청·응답은 **비동기(asynchronous)** 다. 즉, 응답을 기다리지 않고 로직이 계속 실행되도록 설계되어, 개별 서비스가 요청을 처리하고 응답을 보내는 동안 페이지의 나머지 부분이 생성될 수 있다.

## 요약

- 인터넷은 1969년 ARPANET에서 출발했고, 웹은 1990년 팀 버너스리가 하이퍼텍스트에 기반해 인터넷 위에 제안한 시스템이다.
- 웹은 정적 웹 페이지로 시작해, 사용자에 맞게 HTML을 맞춤 생성하는 동적 웹 페이지로 진화했다.
- 현재는 웹 애플리케이션이 부상해 사용자에게 인터랙티브한 경험을 제공한다.
- 웹 애플리케이션은 웹 서비스와 통합함으로써 실시간 정보를 활용해 더 복잡하고 풍부한 애플리케이션이 된다.
