# 4.1.2 – Service Principles

## 개요

- 유용하고 재사용 가능한 서비스를 제공하기 위한 모범 사례(best practices)는 결국 서비스의 바람직한 속성들로 수렴한다.
- 이 강의는 다섯 가지 속성을 다룬다: 모듈성(modular), 조합 가능성(composable), 플랫폼·언어 독립성(platform- and language-independent), 자기 기술성(self-describing), 자기 홍보성(self-advertising).

## 내용

### 모듈성 (Modular)

서비스는 모듈화되고 느슨하게 결합(loosely coupled)되어야 한다. 이것이 재사용 가능하고 조합 가능하다는 속성을 만들어 준다. 서비스는 섞고 맞추어(mix and match) 쓰도록 만들어진 것이다.

- 객체지향 프로그래밍(OOP)에서는 클래스나 컴포넌트의 관련 요소만 클라이언트에 노출함으로써 느슨한 결합을 달성한다.
- SOA에서는 서비스의 인터페이스에 맞는 형태의 통신(communication)을 서비스에 전달해 요청한다. 서비스는 필요한 연산을 수행한 뒤 결과 또는 요청 완료 확인이 담긴 통신을 돌려보낸다.
- 이 통신은 이름 있는 연산과 파라미터를 갖는 **메서드 호출(method call)과 비슷한 형태**일 수도 있고, 서비스 제공자에게 필요한 정보를 내용으로 담은 **요청을 구현한 문서(document)** 에 가까운 형태일 수도 있다.

### 조합 가능성 (Composable)

서비스는 조합해서 사용 가능한 애플리케이션이나 또 다른 서비스를 만들 수 있어야 하고, 실제로 그렇게 사용되어야 한다. 조합 가능하려면 서비스가 모듈화되어 있어야 한다. 서비스를 조합해 쓰는 것은 OOP 패러다임에서 객체를 합성(compose)하는 것과 같다 — 객체를 조합해 원하는 동작을 만들 수 있듯이 SOA의 서비스도 마찬가지다.

### 플랫폼·언어 독립성 (Platform- and Language-Independent)

좋은 서비스는 플랫폼과 언어에 독립적이다. 예를 들어 Java로 작성된 서비스를 Ruby로 작성된 서비스 요청자가 사용할 수 있어야 한다.

- 이 독립성은 통신 표준(standards)과 프로토콜(protocols)을 따름으로써 달성된다.
- 인터넷 상의 서비스는 흔히 XML 파일이나 HTTP 요청으로 요청된다.
- 서로 다른 플랫폼·언어의 서비스를 조율하는 핵심은 **잘 정의된 통신을 강제하는 것**이다.

### 자기 기술성 (Self-describing)

서비스는 자신과 상호작용하는 방법, 즉 자신의 인터페이스를 스스로 기술해야 한다. 어떤 입력을 받고 어떤 출력을 주는지가 여기에 포함된다. 서비스 기술에는 공식 표준이 있는데, WSDL(Web Services Description Language)이 그것이며 코스 후반에 더 다룬다.

### 자기 홍보성 (Self-Advertising)

서비스가 사용되려면 잠재 클라이언트가 어떤 서비스가 있는지 알아야 한다.

- 사내 조직은 비즈니스에 맞는 어떤 방식으로든 서비스를 카탈로그화할 수 있다.
- 웹 서비스를 사용하는 분산 애플리케이션에는 서비스 제공자와 잠재 요청자를 연결해 주는 UDDI(Universal Description, Discovery and Integration) 같은 표준이 있다.

### 마무리

서비스는 대규모 조직이 사업 부서들에 서비스를 제공하는 맥락에서도, 누구나 서비스를 제공·사용할 수 있는 인터넷에서도 다양한 방식으로 사용된다. 어디에 어떻게 배포되든, 위 속성들은 효과적인 서비스와 SOA에 필수적이다.

## 요약

- 모듈성: 느슨한 결합으로 재사용·조합 가능해야 하며, 요청·응답은 메서드 호출형이거나 문서형일 수 있다.
- 조합 가능성: 서비스를 조합해 애플리케이션이나 새 서비스를 만들 수 있어야 한다(객체 합성과 유사).
- 플랫폼·언어 독립성: 표준과 프로토콜(XML, HTTP 등) 기반의 잘 정의된 통신으로 달성한다.
- 자기 기술성: WSDL 같은 표준으로 자신의 인터페이스(입력·출력)를 기술한다.
- 자기 홍보성: UDDI 같은 표준이나 사내 카탈로그로 서비스의 존재를 알린다.
