# 4.2.1 – Introduction to Web Services

## 개요

- 서비스(service)와 웹 서비스(web service)의 정의, 그리고 웹 서비스가 등장하게 된 배경을 다룬다.
- 기업 내 소프트웨어 통합 문제와 EAI(Enterprise Application Integration)의 한계, 특히 B2B 상호작용에서의 문제를 설명한다.
- 1세대 웹 서비스의 3대 기반 표준인 SOAP, WSDL, UDDI와 서비스 조합(service composition)을 위한 BPEL을 소개한다.

## 내용

### 서비스와 웹 서비스의 정의

- 서비스(service)란 다른 프로세스가 사용할 수 있도록 노출된 기능(functionality)이다. 즉, 서비스는 서비스 요청자(service requester)가 사용할 수 있는 인터페이스(interface)를 가진다.
- 웹 서비스(web service)는 웹 기술(web technologies)을 사용해 노출되고 접근 가능한 기능이다.
- W3C(World Wide Web Consortium)는 웹 서비스를 "네트워크 상에서 상호운용 가능한 기계 대 기계 상호작용(interoperable machine-to-machine interaction)을 지원하도록 설계된 소프트웨어 시스템"으로 정의한다.

### 웹 서비스 이전: 통합 문제와 EAI

- 한 기업이 여러 부문에 서로 다른 소프트웨어 솔루션을 사용한다고 하자. 6개의 서로 다른 소프트웨어로 통합 시스템을 만들려면 쌍(pairwise) 단위 연결마다 언어와 플랫폼 조합이 달라질 수 있고, 노드가 6개만 되어도 최대 15개의 쌍별 상호작용이 생긴다.
- 대부분의 연결에 래퍼(wrapper)가 필요하므로 구현이 노동 집약적일 뿐 아니라 유지보수와 확장도 어렵다.
- EAI(Enterprise Application Integration)는 이 통합 문제에 대한 기업 수준의 해법으로, 미들웨어(middleware) — 소프트웨어들 사이에 위치해 그들 간의 통신을 촉진하는 소프트웨어 — 를 사용한다. 구현·유지할 인터페이스 수가 훨씬 줄어들어 한 조직 안에서는 복잡도를 관리하는 데 도움이 된다.
- 그러나 기업 간(B2B, business to business) 상호작용에서는 문제가 생긴다. 어느 기업이 미들웨어를 구현할 것인가? 제3자가 호스팅하는가? 보안은 어떻게 관리하는가? 기업 데이터는 외부 영향으로부터 어떻게 보호하는가? 이런 질문이 해결 불가능한 것은 아니지만, 실제로 EAI는 B2B 상호작용에는 쓰이지 않는다. 기업 간 상호작용은 웹 서비스로 구현하는 편이 낫다.

### 웹 서비스의 기술 기반

- 웹 서비스는 지난 모듈에서 배운 웹 인프라 위에 구축된다(계층형 웹 아키텍처, HTTP, XML).
- 가장 아래는 TCP로, 신뢰성 있고 순서가 보장되는 연결 지향(connection-oriented) 통신을 담당하는 네트워킹 프로토콜이다.
- 그 위에 HTTP(Hypertext Transfer Protocol)가 있다. 웹 서비스는 HTTP로 정보를 전송하고 클라이언트와 상호작용한다. 다른 전송 프로토콜 위에도 구축할 수 있지만 이 강의에서는 HTTP에 집중한다.
- 이 웹 인프라는 거의 모든 기계와 호환되므로 플랫폼 독립성(platform independence)과 상호운용성(interoperability)의 강력한 기반이 된다. 이는 이 모듈의 웹 서비스뿐 아니라 다음 모듈에서 다룰 RESTful 웹 서비스의 기반이기도 하다.
- 이 모듈에서 웹 서비스는 XML 형식 문서를 주고받으며 상호작용하며, 보통 요청-응답(request-response) 메시징 설계를 따른다. XML은 마크업 언어(markup language)로, 기계도 사람도 읽을 수 있는 구조화된 정보를 담은 문서를 서비스끼리 주고받게 해 준다.

### 웹 서비스의 핵심 활동과 표준

- **호출(invocation) — SOAP**: 서비스 요청자가 서비스를 사용하려면 호출해야 한다. 호출은 객체지향 언어의 메서드 호출과 비슷하지만 XML 형식의 요청으로 이루어져야 하며, 어떤 연산(operation)을 요청하는지와 매개변수·데이터를 포함한다. 웹 서비스에서 호출은 SOAP으로 수행된다. SOAP은 XML 기반으로 서비스들이 서로 정보를 보낼 수 있게 하는 프로토콜 명세다. 한때 Simple Object Access Protocol의 약자였으나 이 의미는 이후 폐기되었다. 메시지가 XML 기반이고 보편적으로 수용되는 웹 인프라 위로 전송되므로, 서로 다른 언어와 플랫폼의 시스템이 쉽게 통신할 수 있다.
- **기술(description) — WSDL**: 서비스들이 상호작용하려면 상호작용 방법을 알아야 한다. WSDL(Web Service Description Language)은 서비스의 인터페이스를 기술하는 표준 프로토콜이며, SOAP처럼 XML로 작성된다. WSDL 기술서(description)는 서비스 인터페이스를 기계가 읽을 수 있는(machine-readable) 방식으로 기술하므로 서비스 요청자가 이 인터페이스에 바인딩(binding)할 수 있다. 바인딩이란 서비스와 상호작용하는 데 필요한 코드를 생성해 서비스 요청자가 호출을 시작할 수 있게 하는 행위다. 인터페이스가 WSDL로 모호함 없이 기술되어 있다면 필요한 코드를 자동으로 생성해 바인딩할 수 있다.
- **공표(publication)와 발견(discovery) — UDDI**: 인터넷은 거대하므로 서비스 요청자와 서비스 제공자(service provider)가 서로 만날 방법이 필요하다. 서비스 제공자는 UDDI(Universal Description, Discovery and Integration)로 서비스 기술서를 공표할 수 있다. UDDI는 공개 또는 사설 웹 서비스 레지스트리(registry)를 구축하는 데 사용된다. 서비스를 찾는 요청자는 WSDL 기술서나 서비스의 다른 측면으로 검색할 수 있으며 이를 발견(discovery)이라 한다.
- SOAP, WSDL, UDDI가 웹 서비스의 3대 기반 표준이다. 이들은 모두 웹 인프라에 의존하며, 웹 서비스가 호출되고, 자신을 기술하고, 레지스트리에 공표되어 발견될 수 있게 한다.

### 확장 표준과 서비스 조합

- 이 세 표준 위에 다양한 표준이 구축되며, 흔히 WS- 접두사가 붙는다. 예: 보안 기능을 추가하는 WS-Security, 여러 서비스의 활동을 조정하는 WS-Coordination.
- 이 모듈에서는 그중 WS-BPEL(간단히 BPEL, Business Process Execution Language)을 배운다. BPEL은 기존 서비스들을 결합해 새로운 복합 서비스(composite service)를 만들 수 있게 한다.
- 복합 서비스는 다른 서비스들로 만들어진 서비스로, 그 구성 요소는 다시 복합 서비스일 수도, 기본 서비스(basic service)일 수도 있다. 기본 서비스는 다른 서비스에 의존하지 않는 서비스다. 서비스들을 결합해 새 서비스를 만드는 행위를 서비스 조합(service composition)이라 한다.

### 웹 서비스의 장점

- 웹 서비스는 표준화된 방식으로 호출·기술·공표되므로 내부 구현은 중요하지 않다. 서비스 요청자와 서비스가 다른 플랫폼, 다른 언어에 있어도 효과적으로 상호작용할 수 있다.
- 다만 표준만으로 충분한 것은 아니다. 양쪽 플랫폼이 SOAP을 이해하더라도 SOAP 메시지에는 서비스 제공자가 지원하는 명령과 매개변수가 담겨야 한다.
- 그럼에도 서비스와 요청자 간 통신이 표준화되어 있으므로 인터페이스 구축이 쉬워진다. 상호작용은 여전히 쌍 단위지만 웹 서비스 표준으로 구현된다. 애플리케이션은 표준 웹 기술을 지원하는 어떤 언어·플랫폼으로도 개발할 수 있다.
- B2B 상호작용에서는 누가 미들웨어를 호스팅하고 상호작용을 어떻게 중재하는가라는 모호함이 단순해진다. 프로세스 간 상호작용을 촉진하는 미들웨어의 역할을 웹 서비스 표준이 대신 담당하기 때문이다. 각 기업은 서비스를 어떻게 노출할지 선택함으로써 상호작용 방식을 통제할 수 있고, 외부 회사마다 다른 인터페이스를 제공할 필요도 없다.

## 요약

- 서비스는 다른 프로세스가 쓸 수 있게 노출된 기능이고, 웹 서비스는 웹 기술로 노출·접근되는 기능이다.
- 쌍별 통합의 복잡성 문제를 기업 내부에서는 EAI(미들웨어)가 해결하지만, B2B에서는 미들웨어 호스팅·보안 문제 때문에 웹 서비스가 더 적합하다.
- 웹 서비스는 TCP → HTTP → XML이라는 웹 인프라 위에 구축되어 플랫폼 독립성과 상호운용성을 확보한다.
- 3대 기반 표준: SOAP(호출), WSDL(인터페이스 기술), UDDI(공표와 발견).
- BPEL(WS-BPEL)로 기존 서비스를 조합해 복합 서비스를 만들 수 있으며, 이를 서비스 조합이라 한다.
