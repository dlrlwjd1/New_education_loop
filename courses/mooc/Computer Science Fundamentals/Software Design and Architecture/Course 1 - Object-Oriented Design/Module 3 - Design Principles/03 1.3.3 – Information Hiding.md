# 1.3.3 – Information Hiding

## 개요

- 정보 은닉(information hiding)은 모듈이 자신을 올바르게 사용하는 데 필요한 최소한의 정보만 다른 모듈에 제공하고 나머지는 숨기는 원칙이다.
- 변할 수 있는 것(구현 세부사항)은 숨기고, 변하지 않아야 하는 것(가정, assumption)은 인터페이스(interface)로 드러낸다.
- Java에서는 접근 제어자(access modifier) — public, protected, default, private — 로 정보 은닉을 적용한다.

## 내용

### 정보 은닉이란

- 잘 설계된 시스템은 잘 조직되어야 하며, 시스템의 모든 것이 다른 모든 것을 알 필요는 없다. 각 모듈은 자기 일을 하는 데 필요한 정보에만 접근해야 한다.
- 정보 은닉은 모듈이 다른 모듈에게 올바른 사용에 필요한 **최소한의 정보**만 주고 그 외 모든 것을 숨기게 한다.
- 정보 은닉 덕분에 한 개발자는 다른 개발자들이 자기 모듈의 구현 세부사항을 알 필요 없이 그 모듈을 독립적으로 작업할 수 있다. 다른 개발자는 오직 인터페이스를 통해서만 그 모듈을 사용한다.
- 일반 원칙: **변할 수 있는 것**(구현 세부사항 등)은 숨기고, **변하지 않아야 하는 것**(가정)은 인터페이스를 통해 드러낸다.
- 두 사람이 같은 시스템의 다른 모듈을 작업할 때, 내 모듈이 네 모듈의 정보를 필요로 하면 정보 은닉은 딱 필요한 정보만 제공하게 해 준다. 서로의 모듈 내부를 알 필요가 없다.

### 정보 은닉과 캡슐화(encapsulation)

- 정보 은닉은 흔히 캡슐화와 연관된다. 캡슐화는 속성(attribute)과 행동(behavior)을 적절한 클래스에 묶고, 접근을 위한 인터페이스를 노출한다.
- 캡슐화는 행동의 구현을 효과적으로 숨긴다. 접근이 특정 메서드들의 인터페이스를 통해서만 가능하기 때문이다. 다른 클래스는 메서드 시그니처(method signature)에 담긴 정보에만 의존할 수 있고 내부 구현에는 의존할 수 없다.
- 캡슐화를 통한 정보 은닉은 기대되는 결과를 바꾸지 않으면서 구현을 바꿀 수 있게 한다.
- 예: String 라이브러리의 `concat` 메서드. 내부에서 추가 자료구조를 쓰는지, 접근할 수 없는 다른 메서드를 호출하는지 사용자에게는 보이지 않는다. 사용자는 특정 메서드 시그니처라는 인터페이스를 통해 문자열 연결(concatenation) 기능에 접근할 뿐, 구현 방식은 볼 수 없다. 구현은 바뀔 수 있으므로 실제 동작 방식에 의존해서는 안 되고, 인터페이스만이 의존할 수 있는 유일한 가정이다.
- 속성도 숨길 수 있다. 클래스의 모든 행동에 핵심적인(critical) 속성이라면 외부 클래스가 직접 바꾸지 못하게 해야 한다.

### Java의 접근 제어자(access modifier)

캡슐화는 정보 은닉 개념을 적용하는 실천적 설계 원칙이며, 접근 제어자를 통해 정보를 숨긴다. 접근 제어자는 어떤 클래스가 속성과 행동에 접근할 수 있는지, 그리고 상위 클래스(superclass)가 하위 클래스(subclass)와 무엇을 공유할지 결정한다. Java에는 네 가지 접근 수준이 있다.

- **public**: 시스템의 모든 클래스가 접근 가능. public 속성은 다른 클래스가 조회·수정할 수 있다. public 메서드도 모든 클래스가 호출하고 출력을 받을 수 있지만, 행동의 구현 자체를 바꿀 수는 없다 — 구현은 캡슐화로 숨겨져 있다.
- **protected**: 캡슐화한 클래스 자신, 모든 하위 클래스, 그리고 같은 패키지(package) 안의 클래스만 접근 가능. 패키지는 Java가 관련 클래스들을 하나의 네임스페이스(namespace)로 조직하는 수단이다. 메서드에도 동일하게 적용된다.
- **default (no modifier)**: 접근 제어자를 명시하지 않은 경우다. 캡슐화한 클래스와 하위 클래스에서 접근할 수 있다.
- **private**: 캡슐화한 클래스 자신 외에는 어떤 클래스도 접근 불가. 속성에 직접 접근할 수 없고 메서드도 다른 클래스에서 호출할 수 없다.

## 예시

강의의 Person 클래스 예시. public 속성과 메서드의 동작을 보여준다.

```java
public class Person {
    public String name; // public: 누구나 접근·수정 가능

    public void sleep() {
        // 행동을 호출할 수는 있지만, 구현은 캡슐화로 숨겨져 있어
        // 다른 클래스가 바꿀 수 없다
        System.out.println("Zzz...");
    }
}

class Main {
    public static void main(String[] args) {
        Person p = new Person();
        p.name = "johnDoe"; // public이므로 직접 수정 가능
        p.sleep();          // public 메서드 호출 가능
    }
}
```

protected 속성과 패키지 예시. Person을 Populace 패키지에 두고 name을 protected로 바꾸면, 다른 패키지의 클래스는 접근할 수 없다.

```java
// Populace 패키지: 한 나라의 사람들과 관련된 클래스들
package Populace;

public class Person {
    protected String name; // 같은 패키지, 자기 자신, 하위 클래스만 접근 가능

    public void sleep() {
        System.out.println("Zzz...");
    }
}
```

```java
// EducationalInstitution 패키지: 다른 패키지
package EducationalInstitution;

import Populace.*; // public인 Person 클래스에는 접근 가능

public class University {
    public static void main(String[] args) {
        Person p = new Person();
        // p.name = "johnDoe"; // 컴파일 오류!
        // name은 protected이고 University는 다른 패키지에 있어 접근 불가
    }
}
```

## 요약

- 정보 은닉은 모듈 사용에 필요한 최소한의 정보만 제공하고 나머지는 숨기는 원칙이다.
- 변할 수 있는 구현 세부사항은 숨기고, 의존해도 되는 가정은 인터페이스로 드러낸다 (예: String의 concat).
- 캡슐화가 정보 은닉을 적용하는 실천적 수단이며, Java의 접근 제어자로 구현한다.
- 접근 수준: public(전체) > protected(자신·하위 클래스·같은 패키지) > default(자신·하위 클래스) > private(자신만).
- 정보 은닉은 유연하고 재사용 가능하며 유지보수하기 좋은 시스템을 만드는 데 기여한다.
