# 1.2.6 – Generalization

## 개요

- 일반화(generalization)는 문제 해결 시 중복(redundancy)을 줄이는 설계 원리로, 메서드와 클래스 상속(inheritance) 두 형태로 나타난다.
- 두 개 이상의 클래스가 공유하는 공통 특성을 부모 클래스(superclass)로 뽑아내고, 자식 클래스(subclass)가 이를 상속받는다.
- D.R.Y.(Don't Repeat Yourself) 규칙을 실현해 코드의 재사용성·유지보수성·확장성을 높인다.

## 내용

### 메서드를 통한 일반화

- 객체 지향 모델링과 프로그래밍의 아이디어는 문제 공간의 개념을 컴퓨터 표현으로 만들어, 관련 속성과 행동을 컴퓨터가 시뮬레이션할 수 있게 모델링하는 것이다.
- 현실 세계의 많은 행동과 시스템은 반복적인 동작으로 작동한다. 행동을 메서드(method)로 모델링하면 행동을 일반화할 수 있고, 프로그램 곳곳에 동일한 코드를 작성할 필요가 없어진다.
- 예: 배열 생성·초기화 코드처럼 반복적인 코드는 별도 메서드로 만들어 호출함으로써 일반화할 수 있다. 이는 시스템 전체에서 거의 똑같이 생긴 코드의 양을 줄인다.
- 메서드는 같은 행동을 서로 다른 데이터 집합에 적용하는 방법이다. 일반화는 알고리즘 설계에 자주 쓰인다 — 같은 동작을 다른 데이터 집합에 수행하도록 동작을 메서드로 일반화하고, 인자(arguments)로 다른 데이터를 전달하면 된다.

### 클래스를 통한 일반화 — 상속

- 메서드 안의 코드를 재사용할 수 있고 메서드는 클래스 안에 있다면, 클래스의 코드도 재사용할 수 있을까? 클래스를 일반화할 수 있을까?
- 일반화는 객체 지향 모델링·프로그래밍의 주요 설계 원리 중 하나이며, 클래스에서는 상속(inheritance)을 통해 달성된다.
- 일반화에서는 두 개 이상의 클래스 사이에 반복되거나 공통되거나 공유되는 특성을 뽑아내어(factor out) 다른 클래스에 넣는다.
- 부모 클래스(parent class)와 자식 클래스(child class)가 있을 때, 자식 클래스가 부모 클래스를 상속하면 자식은 부모의 속성과 행동을 갖게 된다.
- 공통 속성과 행동은 부모 클래스에 둔다. 하나의 부모 클래스를 상속하는 자식 클래스는 여러 개일 수 있으며, 모두 이 공통 속성·행동을 받는다.
- 자식 클래스는 추가 속성과 행동도 가질 수 있어, 더 특수화된(specialized) 일을 할 수 있다.
- 표준 용어로 부모 클래스는 **슈퍼클래스(superclass)**, 자식 클래스는 **서브클래스(subclass)** 라 한다.

### 예시: 고양이 Mittens와 개 Doug

- 고양이 Mittens는 다리 4개와 꼬리가 있고 걷기·달리기·먹기를 할 줄 안다. 그런데 이 속성과 행동은 개 Doug에게도 그대로 적용된다.
- 이 특성만으로 cat, dog 클래스를 각각 설계하면 코드가 크게 겹친다. 비슷한 특성을 하나 더 모델링하려면 같은 코드를 두 클래스 모두에 추가해야 한다.
- 클래스가 둘일 때는 괜찮아 보여도, 공통 특성을 공유하는 클래스가 여럿이면 모두에 조심스럽게 코드를 추가하는 일은 시간이 오래 걸리고 오류가 나기 쉽다(error-prone). 그 결과 유연하지도, 유지보수하기 쉽지도, 재사용 가능하지도 않은 시스템이 된다.
- Mittens와 Doug의 공통점: 둘 다 다리와 꼬리가 있는 동물(animal)의 일종이고, 걷기·달리기·먹기 같은 공유 행동을 가진다.
- 동물은 일반적(general) 아이디어다. 더 구체적인 클래스들의 큰 묶음을 기술하는 넓은 용어로, 고양이·개 같은 특정 동물 종류에 속하는 공통 특성과 행동의 집합을 정의하는 데 쓸 수 있다.
- 그래서 cat, dog 클래스의 공통 속성·행동을 animal이라는 슈퍼클래스로 일반화한다. 클래스 이름은 마음대로 지을 수 있지만, 현실 세계의 것을 의미 있게 추상화하는 만큼 모델링 대상의 이름을 따르는 것이 코드 이해에 좋다.
- 서브클래스는 슈퍼클래스의 속성과 행동을 상속받는다. 고양이와 개는 둘 다 동물이므로 animal 슈퍼클래스를 상속한다.

### 상속의 장점

1. 두 서브클래스에 공통인 코드의 변경을 슈퍼클래스에서 한 번만 하면 된다.
2. 새 동물을 시스템에 쉽게 추가할 수 있다 — 공통 속성·행동을 다시 작성할 필요 없이, 상속을 통해 animal 클래스의 모든 서브클래스가 그 속성·행동을 부여받는다.

### D.R.Y. 규칙

- 상속과 메서드는 일반화 설계 원리의 본보기다. 이 기법들은 **D.R.Y.(Don't Repeat Yourself)** 규칙을 적용하게 해 준다.
- 같은 작업을 수행하면서도 더 적은 코드로 프로그램을 작성할 수 있다.
- 서로 다른 클래스나 메서드가 같은 코드 블록을 공유할 수 있으므로 코드가 더 재사용 가능해진다.
- 반복 코드가 없으므로 시스템 유지보수가 쉬워진다.
- 일반화는 확장하기 쉽고, 변경을 적용하기 쉽고, 유지보수하기 쉬운 소프트웨어를 만드는 데 도움이 된다. 클래스와 행동 간의 공통점을 식별하는 법을 익히면 매우 견고한(robust) 소프트웨어 솔루션을 설계할 수 있다.

## 요약

- 일반화는 중복을 줄이는 설계 원리로, 메서드(같은 행동을 다른 데이터에 적용)와 클래스 상속 두 방식으로 실현된다.
- 공통 속성·행동은 슈퍼클래스(superclass)에 두고, 서브클래스(subclass)가 상속받아 추가로 특수화한다.
- 공통 코드 변경은 슈퍼클래스 한 곳에서만 하면 되고, 새 서브클래스 추가도 쉬워진다.
- D.R.Y.(Don't Repeat Yourself): 반복 없는 코드가 재사용성과 유지보수성을 높인다.
