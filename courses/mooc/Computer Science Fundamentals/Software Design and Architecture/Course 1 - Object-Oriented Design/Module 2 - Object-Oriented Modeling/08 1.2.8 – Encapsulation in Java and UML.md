# 1.2.8 – Encapsulation in Java and UML

## 개요

- 캡슐화(encapsulation)의 세 아이디어(묶기·노출·제한)를 UML 클래스 다이어그램과 Java 코드로 표현하는 방법을 배운다.
- UML에서 마이너스 기호(−)는 private, 즉 클래스 내부에서만 접근 가능한 속성·메서드를 나타낸다.
- 게터(getter)·세터(setter) 메서드를 통해서만 데이터에 접근하게 하여 데이터 무결성(data integrity)을 지킨다.

## 내용

### 캡슐화 복습

- 캡슐화는 세 아이디어를 포함한다.
  1. 데이터와 그 데이터를 조작하는 함수를 자기 완결적(self-contained) 객체로 묶는다(bundle).
  2. 그 객체의 특정 데이터와 함수를 다른 객체가 접근할 수 있게 노출한다(expose).
  3. 특정 데이터와 함수에 대한 접근을 그 객체 내부로만 제한한다(restrict).
- 설계 이론이 유용하려면 적용되어야 한다. 이것이 코드와 설계에서 어떻게 보이는지 살펴본다.

### UML에서의 캡슐화 표기

- 대학 학생을 캡슐화로 모델링한다면, 학생의 관련 데이터를 student 클래스의 속성으로 정의하고, 그 속성에 접근하는 특정 public 메서드들을 둔다. 예시에서 관련 데이터는 학위 과정(degree program)과 평점(GPA)이다.
- student 클래스의 UML 클래스 다이어그램에서 속성은 공개 접근으로부터 숨겨져 있다. 이는 GPA와 degreeProgram 앞의 **마이너스 기호(−)** 로 표시된다.
- 마이너스 기호는 해당 메서드나 속성이 **private** 임을 뜻한다. private 속성은 클래스 내부에서만 접근할 수 있다.
- 클래스 밖에서는 학생의 GPA 속성을 직접 조작할 수 없고, public 메서드 `setGPA`를 통해 GPA를 설정해야 한다.
- 객체의 데이터를 public 메서드로만 조작하게 하면 그 데이터가 언제 어떻게 접근되는지 통제할 수 있다. 이 통제는 문(gate)을 만드는 것과 같다 — 허용한 데이터 접근만 통과시킨다. GPA가 4점 척도라면 누군가 값을 직접 10으로 설정할 수 있게 두어서는 안 된다.
- 모든 본질적 데이터에는 승인되지 않은 조작으로부터의 보호층이 필요하다. 이는 국가의 법을 바꾸는 것과 같다 — 아무나 마음대로 아무 때나 법을 바꿀 수 없고 적법한 절차가 있으며, 그 절차가 경솔한 변경으로부터 보호한다.

### 게터와 세터

- **게터 메서드(Getter Methods)**: 데이터를 조회하는 메서드로, 이름은 보통 get으로 시작해 반환할 속성 이름으로 끝난다. 운전자(driver) 객체의 예로는 get license ID 메서드. 게터는 흔히 private 데이터를 조회한다.
- **세터 메서드(Setter Methods)**: 데이터를 변경하는 메서드로, 이름은 보통 set으로 시작해 설정할 변수 이름으로 끝난다. 운전자 예시에서는 set car 함수. 세터는 private 속성을 안전한 방식으로 설정한다.
- 게터·세터를 두는 이유는 데이터 무결성이다. 데이터를 바꾸려면 올바른 경로를 거쳐야 하며, 승인된 방식으로 접근되어야 한다.

### Java 코드에서의 캡슐화

- 속성이나 메서드가 private인지 public인지가 접근성에 영향을 준다. private 속성은 클래스 내부가 아닌 어디에서도 접근할 수 없다 — 클래스 밖의 모든 것으로부터 숨겨진다.
- 숨겨진 데이터를 조작하는 유일한 방법은 접근을 허용하는 public 함수를 작성하는 것이다.
- 연습 — 사람(person)에 관련된 가장 기본적인 데이터는 이름이다. 사람의 이름을 나타내는 private 속성 하나를 두고, 외부 클래스의 직접 접근으로부터 숨기기 위해 public 메서드로만 접근하게 한다.

### 게터·세터는 더 많은 일을 할 수 있다

- 외부 클래스는 메서드가 어떻게 구현되었는지 신경 쓰지 않는다. 메서드가 기대한 출력을 반환하는지, 기대한 책임을 수행하는지만 중요하다.
- 따라서 게터·세터가 순수하게 private 속성 값을 반환·변경만 해야 하는 것은 아니다 — 더 많은 일을 할 수 있다.
- 학생 예시: 학위 과정 변경에 제약이 있는 상황이라면, GPA가 2.7보다 커야 학위 과정을 변경할 수 있다는 제약을 코드에 반영할 수 있다.
- 외부 관찰자는 public 메서드의 구현 방식을 알 필요가 없고, 기대대로 동작하기만 하면 된다. 필요하다면 게터·세터에 추가 코드를 넣을 수 있다.

## 예시

Student 클래스의 UML 클래스 다이어그램(텍스트 표현) — 마이너스(−)는 private, 플러스(+)는 public:

```text
+-------------------------------------------+
| Student                                   |
+-------------------------------------------+
| -gpa: float                               |
| -degreeProgram: String                    |
+-------------------------------------------+
| +getGPA(): float                          |
| +setGPA( gpa: float )                     |
| +getDegreeProgram(): String               |
| +setDegreeProgram( degreeProgram: String )|
+-------------------------------------------+
```

데이터를 묶고 조작 메서드를 두는 클래스, 그리고 GPA 2.7 초과일 때만 학위 과정을 바꿀 수 있게 하는 세터:

```java
public class Student {
    private float gpa;
    private String degreeProgram;

    public float getGPA() {
        return gpa;
    }

    public void setGPA(float gpa) {
        this.gpa = gpa;
    }

    public String getDegreeProgram() {
        return degreeProgram;
    }

    public void setDegreeProgram(String degreeProgram) {
        if (gpa > 2.7) {
            this.degreeProgram = degreeProgram;
        }
    }
}
```

private 속성 하나(이름)를 public 메서드로만 접근하게 하는 연습 예:

```java
public class Person {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

## 요약

- UML에서 −는 private(클래스 내부에서만 접근), +는 public을 나타낸다.
- 속성은 private으로 숨기고 public 메서드를 통해서만 조작하게 하면 데이터 접근을 통제하는 문(gate)이 생긴다.
- 게터는 데이터 조회, 세터는 안전한 데이터 변경을 담당하며, 둘의 존재 이유는 데이터 무결성이다.
- 게터·세터는 단순 반환·대입을 넘어 제약 검사 같은 추가 로직을 담을 수 있다 — 외부는 구현이 아니라 기대 동작만 알면 된다.
- 캡슐화는 클래스와 객체를 보호하고, 다른 클래스가 안전하게 쓸 수 있는 승인된 메서드의 인터페이스를 제공하며, 구현 세부를 숨긴다.
