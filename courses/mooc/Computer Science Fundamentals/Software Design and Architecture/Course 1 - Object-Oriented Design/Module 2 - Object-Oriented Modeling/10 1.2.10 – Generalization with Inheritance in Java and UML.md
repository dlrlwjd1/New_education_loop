# 1.2.10 – Generalization with Inheritance in Java and UML

## 개요

- UML 클래스 다이어그램에서 상속(inheritance)은 서브클래스에서 슈퍼클래스로 향하는 실선 화살표로 표현하며, 화살표는 위를 향하게 그린다.
- Java에서는 `extends` 키워드로 상속을 선언하고, `abstract`로 인스턴스화 불가 클래스를, `super`로 슈퍼클래스의 생성자·속성·메서드 접근을, 오버라이딩(overriding)으로 메서드 재정의를 처리한다.
- Java의 구현 상속(implementation inheritance)은 단일 상속만 허용된다 — 서브클래스는 슈퍼클래스 하나만 상속할 수 있다.

## 내용

### UML에서 상속 표기

- UML 클래스 다이어그램에서 상속 표시는 간단하다. 두 클래스를 **실선 화살표(solid lined arrow)** 로 연결하면 두 클래스가 상속으로 연결되었다는 뜻이다.
- 슈퍼클래스(superclass)가 화살표 머리 쪽, 서브클래스(subclass)가 꼬리 쪽이다.
- 표준 그리기 방식은 화살표가 위를 향하게 하는 것이다. 슈퍼클래스는 항상 위쪽, 서브클래스는 항상 아래쪽에 놓인다. 종이에 그린 가계도(family tree)처럼, 어린 세대일수록 페이지 아래쪽에 있다.
- 상속받은 슈퍼클래스의 속성과 행동을 서브클래스에 다시 적을 필요가 없다. 화살표가 상속을 전달하므로, 서브클래스가 슈퍼클래스의 속성과 메서드를 가진다는 것이 함축된다.
- 슈퍼클래스는 일반화된(generalized) 클래스이고, 서브클래스는 특수화된(specialized) 클래스다.

### Dog와 Animal — UML에서 코드로

- Doug은 개일 뿐 아니라 동물이다. dog 클래스와 Animal 클래스가 있다면 dog가 서브클래스, Animal이 슈퍼클래스다. dog 클래스는 Animal 클래스를 상속한다.
- UML 다이어그램에서 **해시 기호(#)** 는 Animal의 속성이 **protected** 임을 나타낸다. Java에서 protected 속성·메서드는 다음에서만 접근할 수 있다.
  - 캡슐화하는 클래스 자신
  - 모든 서브클래스
  - 같은 패키지(package) 안의 모든 클래스
- Java에서 패키지는 클래스들을 네임스페이스(namespace)로 조직하는 수단이다.
- 서브클래스는 상속받는 슈퍼클래스의 모든 속성과 행동을 가지므로, UML 다이어그램의 서브클래스에 슈퍼클래스의 속성·행동을 다시 넣을 필요가 없다 — 상속 표기가 이미 그것을 말해 준다.

### abstract 클래스와 extends

- 동물은 특정 종(species)의 일반화이므로 animal 객체를 단독으로 생성할 수 있게 하고 싶지 않다. **abstract** 키워드로 이 클래스가 인스턴스화될 수 없다고 선언한다 — animal 객체를 만들 수 없다.
- Animal 클래스를 상속하는 모든 클래스는 그 속성과 행동을 갖는다. cat 서브클래스를 추가로 도입해 Animal을 상속시키면, cat과 dog 서브클래스는 animal 슈퍼클래스와 같은 속성·행동을 갖게 된다.
- 코드에서도 dog 클래스가 Animal에서 상속받는 속성·행동을 다시 선언할 필요가 없다. 코드와 UML 다이어그램은 슈퍼클래스·서브클래스에 어떤 속성·메서드가 선언되는지에서 서로 비슷하다.
- Java에서 상속 선언 키워드는 **extends** 다.

### 생성자(constructor)와 super

- 객체는 생성자(constructor)로 클래스에서 인스턴스화한다. 상속이 있을 때 서브클래스의 인스턴스를 만들려면, 슈퍼클래스가 그 객체의 속성을 적절히 준비할 기회를 줘야 한다.
- 클래스는 암시적(implicit) 생성자 또는 명시적(explicit) 생성자를 가질 수 있다.
  - 생성자를 직접 작성하지 않으면 암시적 생성자를 갖는다. 기본 생성자(default constructor)를 쓰면 모든 속성은 0이나 null로 할당된다.
  - 명시적 생성자는 인스턴스화 시 속성에 값을 할당할 수 있게 한다. 예: 명시적 생성자가 있는 Animal 구현은 원하는 다리 개수로 animal을 인스턴스화하게 해 준다.
- 슈퍼클래스에 명시적 생성자가 있으면, 서브클래스의 생성자는 반드시 슈퍼클래스의 생성자를 호출해야 한다. 그렇지 않으면 슈퍼클래스 속성이 적절히 초기화되지 않는다.
- 슈퍼클래스의 속성·메서드·생성자에 접근하기 위해 서브클래스는 **super** 키워드를 사용한다.

### 메서드 오버라이딩(overriding)

- 서브클래스는 슈퍼클래스의 메서드를 오버라이드할 수 있다. 즉, 상속받은 슈퍼클래스 메서드에 대해 자신만의 구현을 제공할 수 있다.
- 예: dog 클래스가 animal 클래스의 walk 메서드를 오버라이드했다. 개에게 걸으라고 하면 Animal 클래스에 구현된 행동을 수행하는 대신 소파에 누워 있겠다고 말할 것이다.

### 구현 상속과 단일 상속

- 지금까지 본 상속은 **구현 상속(implementation inheritance)** 이다. Java에서는 단일(single) 구현 상속만 허용된다.
- 슈퍼클래스는 여러 서브클래스를 가질 수 있지만, 서브클래스는 하나의 슈퍼클래스에서만 상속할 수 있다. 예: dog와 cat 서브클래스는 각각 animal이라는 하나의 슈퍼클래스와만 구현 상속 관계를 가질 수 있고, animal 슈퍼클래스는 몇 개든 서브클래스를 가질 수 있다(이 예에서는 둘).
- 코드로는 cat과 dog 클래스가 Animal 클래스를 extends 하면 된다. 이제 명시적으로 코드를 작성하지 않고도 동물처럼 행동하는 cat과 dog이 생기며, 각자 자신만의 행동도 가진다. Doug은 공놀이(fetch)를 알지만 Mittens처럼 털실을 갖고 놀 줄은 모른다. 이렇게 커스텀 또는 특수한 행동을 가진 특수화된 클래스를 만들 수 있다.
- 서브클래스 자체가 다른 클래스의 슈퍼클래스가 될 수도 있다. 상속은 원하는 만큼 여러 클래스로 흘러내려갈(trickle down) 수 있다.

## 예시

UML 상속 표기(텍스트 표현) — 화살표는 서브클래스에서 슈퍼클래스로 위를 향한다. `#`은 protected:

```text
        +---------------------+
        | Animal              |
        +---------------------+
        | #numberOfLegs: int  |
        +---------------------+
        | +walk()             |
        +---------------------+
              ^         ^
              |         |
   +--------------+  +--------------+
   | Dog          |  | Cat          |
   +--------------+  +--------------+
   | +playFetch() |  | +playYarn()  |
   +--------------+  +--------------+
```

abstract 슈퍼클래스, 명시적 생성자, super 호출, 메서드 오버라이딩:

```java
public abstract class Animal {
    protected int numberOfLegs;

    public Animal(int numberOfLegs) {
        this.numberOfLegs = numberOfLegs;
    }

    public void walk() {
        System.out.println("Walking...");
    }
}

public class Dog extends Animal {
    public Dog(int numberOfLegs) {
        super(numberOfLegs);
    }

    @Override
    public void walk() {
        System.out.println("I'd rather lay on the couch.");
    }
}
```

## 요약

- UML 상속은 서브클래스 → 슈퍼클래스 실선 화살표로 표시하며, 슈퍼클래스를 위에 둔다. 상속받은 멤버는 서브클래스에 다시 적지 않는다.
- `#`(protected) 멤버는 클래스 자신, 서브클래스, 같은 패키지의 클래스만 접근 가능하다.
- `abstract` 클래스는 인스턴스화할 수 없고, 상속은 `extends`로 선언한다.
- 슈퍼클래스에 명시적 생성자가 있으면 서브클래스 생성자는 `super`로 이를 호출해야 한다.
- 서브클래스는 메서드를 오버라이드해 자신만의 구현을 제공할 수 있다.
- Java의 구현 상속은 단일 상속이며, 상속은 여러 단계로 이어질 수 있다.
