# 1.2.9 – Decomposition in Java and UML

## 개요

- 분해(decomposition)에는 세 가지 관계 유형이 있다: 연관(association), 집약(aggregation), 합성(composition). 이들은 전체와 부분의 상호작용을 정의한다.
- 연관은 완전히 독립적인 두 객체의 느슨한 관계, 집약은 약한 has-a 관계, 합성은 서로 없이는 존재할 수 없는 강한 has-a 관계다.
- 각 관계를 정의, UML 클래스 다이어그램, Java 코드의 세 관점에서 살펴본다.

## 내용

### 분해의 세 관계

- 분해의 정의는 전체를 서로 다른 부분들로 나누는 것, 또는 서로 다른 기능을 가진 별개의 부분들을 결합해 전체를 만드는 것이다.
- 프로그래밍에서 이 정의를 더 구체화하면, 분해에서 발견되는 관계는 연관·집약·합성 세 유형이며, 전체와 부분 사이의 상호작용을 정의한다.

### 연관(association)

- 연관은 "some" 관계다. 두 객체 사이의 느슨한(loose) 관계로, 두 객체가 얼마 동안 상호작용할 수 있다는 뜻이다. 예를 들어 한 클래스의 객체가 다른 클래스 객체가 제공하는 서비스/메서드를 사용할 수 있다.
- 예: 사람(person)과 항공사(airline)의 관계. 사람은 보통 항공사를 소유하지 않지만 상호작용할 수 있고, 항공사도 여러 사람 객체와 상호작용할 수 있다. 사람도 여럿, 항공사도 여럿이며 어느 쪽도 상대에 의존하지 않는다.
- UML 표기: 두 객체(박스) 사이의 **직선**이 연관 관계를 나타낸다. 양쪽에 `0..*`가 있으면, 사람 객체는 0개 이상의 항공사 객체와 연관되고, 항공사 객체도 0개 이상의 사람 객체와 연관된다는 뜻이다.
- 연관의 다른 예: 음식과 와인, 학생과 스포츠, 새끼 고양이와 털실. 각 관계는 완전히 별개인 개체들 사이의 관계다. 한 객체가 파괴되어도 다른 객체는 계속 존재할 수 있다(인간과 장기의 관계와 다름). 관계 속 각 항목의 수는 제한이 없고, 한 객체가 다른 객체에 속하지 않는다.
- 코드 예: 학생이 스포츠 객체를 전달받아 플레이한다. 학생은 플레이하는 동안 외에는 그 스포츠를 소유하지 않는다. 학생은 여러 스포츠를 할 수 있고, 여러 학생이 한 스포츠를 할 수 있다.
- 와인과 음식 연습: 와인은 음식과 독립적으로 존재할 수 있다. 음식이 있어야 존재하는 것도, 항상 음식과 함께 있는 것도 아니다. 두 객체는 서로에게 속하지 않으면서 상호작용한다.
- 정리: 연관은 완전히 독립적으로 존재하는 두 객체 간의 느슨한 파트너십이며, 개수도 서로 묶여 있지 않다.

### 집약(aggregation)

- 집약은 **has-a 관계**로, 전체가 자신에게 속한 부분들을 갖는 관계다. 부분이 여러 전체에 공유(sharing)될 수도 있다.
- 전체에서 부분으로의 has-a 관계가 **약하다(weak)**. 부분이 전체에 속할 수 있지만 독립적으로도 존재할 수 있다는 뜻이다.
- 예: 여객기(airliner)와 승무원(crew). 승무원은 여객기의 중요한 부분이고 승무원 없이는 비행할 수 없지만, 승무원이 탑승하지 않았다고 여객기가 존재하지 않게 되는 것은 아니다. 승무원도 여객기에 탑승하지 않았다고 사라지거나 파괴되지 않는다. 관계는 있지만 그 밖에서도 존재할 수 있다.
- UML 표기: **빈 다이아몬드(empty diamond)** 가 관계에서 어느 객체가 부분이 아닌 전체인지 나타내며, 집약의 기호다. 여객기 객체는 0명 이상의 승무원을 갖고, 승무원 객체도 0개 이상의 항공기 객체에 속할 수 있다.
- 집약의 다른 예: 과목 분반(course section)과 학생, 애완동물 가게와 애완동물, 책장과 책. 모두 has-a 관계지만 약하다 — 한쪽이 파괴되어도 다른 쪽이 계속 존재하는 것이 자연스럽다.
- 코드 예: airliner 클래스에 승무원 목록(list)이 있다. 목록은 비어 있는 상태로 초기화되고, public 메서드로 새 승무원을 추가할 수 있다. 여객기는 0명 이상의 승무원을 가질 수 있다.
- 애완동물 가게 연습: 애완동물 가게는 애완동물을 갖는다(약한 has-a). 0마리 이상을 담을 수 있는 목록을 갖고 언제든 추가할 수 있으며, 가게와 애완동물은 서로 없이도 존재할 수 있다.
- 정리: 집약은 클래스 간의 약한 has-a 관계다. 한 객체가 다른 객체를 갖지만 강하게 묶여 있지 않으며, 둘 다 상대 없이 존재할 수 있다.

### 합성(composition)

- 합성은 부분의 **배타적 포함(exclusive containment)**, 즉 **강한(strong) has-a 관계**다.
- 전체는 부분 없이 존재할 수 없다. 부분을 잃으면 전체가 존재하지 않게 되고, 전체가 파괴되면 모든 부분도 파괴된다. 보통 부분에는 전체를 통해서만 접근할 수 있으며, 포함된 부분은 전체에 배타적이다.
- 예: 집과 방. 집은 여러 방으로 이루어지지만, 집을 없애면 방도 존재하지 않게 된다. 집 없는 방은 있을 수 없다.
- UML 표기: **채워진 다이아몬드(filled diamond)** 가 전체 쪽에 붙는다. 다이아몬드가 채워져 있으면 has-a 관계가 강하다는 뜻이며, 두 객체는 서로 없이 존재할 수 없다. 집 객체는 1개 이상의 방 객체를 갖는다.
- 합성의 예: 인간과 뇌. 완전히 의존적인 클래스들 간의 관계로, 하나가 파괴되면 다른 것도 파괴된다.
- 코드 예: 인간(human) 객체가 생성될 때 뇌(brain)도 동시에 생성된다. 뇌는 다른 곳에서 인스턴스화될 필요도, 생성 시 인간 객체로 전달될 필요도 없다 — 인간과 함께 자동으로 생성된다. 인간과 뇌 두 부분은 강하게 의존해 하나가 없으면 다른 것도 존재할 수 없다.
- 직원과 급여 연습: 직원(employee)은 급여(salary) 없이 존재할 수 없고 급여도 직원 없이 존재할 수 없다. 직원을 인스턴스화할 때 급여 부분이 만들어지며, 그 시점부터 직원이 존재하는 한 급여도 항상 존재해야 한다.
- 정리: 합성은 분해 관계 중 가장 의존적인 관계로, 각 객체가 존재하는 동안에만 존재하는 관계를 형성한다.

## 예시

UML 표기(텍스트 표현):

```text
연관 (직선, 0..*)
[Person] 0..* ------------------ 0..* [Airline]

집약 (빈 다이아몬드가 전체 쪽)
[Airliner] <>------------------- 0..* [CrewMember]

합성 (채워진 다이아몬드가 전체 쪽)
[House] ◆-------------------- 1..* [Room]
```

연관 — 학생이 스포츠 객체를 전달받아 사용:

```java
public class Student {
    public void play(Sport sport) {
        sport.play();
    }
}
```

집약 — 여객기가 승무원 목록을 갖고 추가할 수 있음:

```java
import java.util.ArrayList;
import java.util.List;

public class Airliner {
    private List<CrewMember> crew = new ArrayList<CrewMember>();

    public void addCrewMember(CrewMember member) {
        crew.add(member);
    }
}
```

합성 — 인간 생성 시 뇌가 함께 생성됨:

```java
public class Human {
    private Brain brain;

    public Human() {
        brain = new Brain();
    }
}
```

## 요약

- 분해의 세 관계는 결합 강도가 점점 강해지는 순서로 연관 → 집약 → 합성이다.
- 연관(association): 완전히 독립적인 두 객체의 매우 느슨한 상호작용. UML은 직선.
- 집약(aggregation): 전체가 부분을 갖지만 둘 다 독립적으로 살 수 있는 약한 has-a 관계. UML은 빈 다이아몬드.
- 합성(composition): 전체가 부분 없이 존재할 수 없고 그 역도 성립하는 강한 has-a 관계. UML은 채워진 다이아몬드.
- 세 관계 모두 소프트웨어 설계에 유용하고 다재다능하다.
