# 1.1.1 – Welcome to Software Design and Architecture

## 개요

- Software Design and Architecture 전문과정(specialization)의 소개 강의로, 좋은 설계(design)가 왜 필요한지와 전문과정 전체 구성을 안내한다.
- 좋은 설계는 코드만의 문제가 아니라 다른 개발자·팀·클라이언트와 소프트웨어에 대한 아이디어를 표현하는 능력이며, 소프트웨어를 유연하고(flexible) 재사용 가능하며(reusable) 유지보수 가능하게(maintainable) 만든다.
- 전문과정은 총 4개 코스(객체지향 설계, 디자인 패턴, 소프트웨어 아키텍처, 서비스 지향 아키텍처)로 구성되며, 각 코스에 캡스톤 프로젝트가 포함된다.

## 내용

### 좋은 설계가 필요한 이유

강사(Ken Wong)는 과거에 참여했던 프로젝트를 돌아보라고 권한다. 설계가 좋았는지 판단하는 질문은 다음과 같다.

- 작은 코드 변경이 코드의 다른 곳까지 연쇄적인 변경(ripple-effect)을 일으켰는가?
- 코드를 재사용하기 어려웠는가?
- 릴리스 후 소프트웨어를 유지보수하기 어려웠는가?

이 질문 중 하나라도 "예"라면 더 나은 설계의 도움을 받을 수 있다. 좋은 설계는 단지 코드에 관한 것이 아니라, 소프트웨어에 대한 아이디어를 다른 개발자, 다른 팀, 클라이언트와 표현하고 소통하는 것이다. 잘 고민된 설계는 구현을 쉽게 만들고, 프로젝트 후반의 큰 변경 필요를 줄이며, 나중의 골칫거리를 예방한다.

### 설계 부재가 만드는 흔한 시나리오

학습 내비게이터(Sam Jeffery)는 업계에서 흔한 두 가지 시나리오를 제시한다.

- **기존 프로젝트 합류**: 개발이 한창 진행된 프로젝트에 합류했는데 코드를 보고 압도된다. 각 부분의 목적을 알 수 없고, 정리가 안 되어 있으며, 설계 문서(design documentation)가 존재하지 않는다. 이는 처음부터 잘 설계되지 않았다는 신호다.
- **개인 프로젝트**: 기능이 확실하지 않은 상태에서 그냥 코딩부터 시작한다. 혼자 작업하니 코드가 정리되지 않아도 문제없다고 생각하지만, 새 기능을 구현하다가 프로그램의 다른 부분이 망가진다. 처음부터 제대로 설계했어야 한다.

### 전문과정에서 배우는 것

- 설계 원칙(design principles), 패턴(patterns), 아키텍처(architecture)를 적용해 재사용 가능하고 유연한 소프트웨어 애플리케이션과 시스템을 만드는 방법
- 시각적 표기법(visual notation)을 사용해 소프트웨어 시스템의 설계와 아키텍처를 표현하고 문서화하는 방법
- 이 전문과정은 주로 소프트웨어 설계를 다루며 사용자 인터페이스 설계(user-interface design)는 다루지 않는다.
- ACM/IEEE Software Engineering Curriculum Guidelines에 맞추려 노력했으나, ACM이나 IEEE와 공식 제휴 관계는 없다.

### 4개 코스 구성

각 코스는 4개 모듈로 구성되며, 앞의 3개 모듈은 내용과 캡스톤 프로젝트 초기 부분, 4번째 모듈은 캡스톤 프로젝트 완성에 할애된다.

1. **Course 1 – 객체지향 설계(Object-Oriented Design)**: Java 기초 위에 객체지향 분석 및 설계(object-oriented analysis and design)를 다룬다. 객체지향 설계 원칙으로 유연하고 재사용 가능하며 유지보수 가능한 소프트웨어를 만들고, 이를 UML(Unified Modeling Language)로 표현하는 법을 배운다. 캡스톤에서는 Java 코드베이스를 발전시키고 UML 문서를 작성한다.
2. **Course 2 – 디자인 패턴(Design Patterns)**: 전문가들이 흔히 적용하는 디자인 패턴으로 설계 문제를 해결한다. 인터랙티브 애플리케이션에 쓰이는 디자인 패턴을 조사하고, 코드 스멜(code smell) 카탈로그를 참조해 문제 있는 설계를 식별하는 법을 배운다. 캡스톤에서는 애플리케이션을 디자인 패턴을 사용하도록 재설계한다.
3. **Course 3 – 소프트웨어 아키텍처(Software Architecture)**: 아키텍처 스타일(architectural style)을 통해 대규모 시스템의 구조와 행동을 탐구한다. 수정가능성(modifiability)과 성능(performance) 같은 경쟁하는 품질 속성(quality attribute) 간 트레이드오프를 검토해 아키텍처를 분석·평가하는 법을 배운다. 캡스톤에서는 계층형(layered) Java 시스템의 아키텍처를 문서화하고 평가한다.
4. **Course 4 – 서비스 지향 아키텍처(Service-Oriented Architecture, SOA)**: 웹 애플리케이션 아키텍처를 검토하고 SOA를 웹 서비스(web services)와 REST(Representational State Transfer) 두 접근으로 탐구한다. 캡스톤에서는 모바일 애플리케이션을 다양한 REST 인터페이스와 연결해 저장·검색·연산 서비스에 접근한다.

### 수강 안내

- 코스는 순서대로 수강하도록 설계되었지만 각 코스는 독립적으로도 수강할 수 있다.
- 기본적인 Java 프로그래밍 지식을 전제로 하며, 이 모듈에는 Java 실력이 충분한지 확인하는 Java 사전 테스트(pre-test)가 있다. 사전 테스트는 수강을 막으려는 것이 아니라 복습이 필요한 영역을 파악해 성공을 돕기 위한 것이다.
- 다양한 배경의 학습자를 위해 새 용어를 명시적으로 소개하며, 경험 많은 개발자라도 배울 것이 많으므로 이미 아는 내용이어도 강의에 참여하고 토론 포럼에서 전문성을 공유할 것을 권장한다.

## 요약

- 작은 변경의 연쇄 효과, 재사용의 어려움, 유지보수의 어려움은 설계가 부족하다는 신호다.
- 좋은 설계는 구현을 쉽게 하고 이후의 큰 변경을 줄이며, 개발자·팀·클라이언트와의 소통 수단이 된다.
- 전문과정은 객체지향 설계 → 디자인 패턴 → 소프트웨어 아키텍처 → 서비스 지향 아키텍처의 4개 코스로 구성되며, 각 코스마다 실제 소프트웨어 제품에 지식을 적용하는 캡스톤 프로젝트가 있다.
- 기본 Java 지식이 전제되며, UML로 설계를 표현·문서화하는 방법을 배운다.
