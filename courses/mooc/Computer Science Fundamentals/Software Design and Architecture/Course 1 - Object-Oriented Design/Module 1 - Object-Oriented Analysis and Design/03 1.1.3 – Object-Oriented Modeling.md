# 1.1.3 – Object-Oriented Modeling

## 개요

- 객체지향 모델링(object-oriented modeling)은 문제를 풀 때 핵심 개념(key concepts)을 소프트웨어의 객체(object)로 표현하는 실천 방법이다.
- 객체로 표현하면 코드가 정리되고(organized), 유연하며(flexible), 재사용 가능해진다(reusable).
- 객체지향 사고에서는 사람·장소·사물은 물론 무생물까지 모든 것을 자기 정보를 아는(self-aware) 객체로 본다.

## 내용

### 객체지향 모델링이란

문제를 해결할 때 핵심 개념들을 소프트웨어의 객체로 표현하는 실천이다. 문제에 따라 많은 개념, 심지어 사람·장소·사물의 인스턴스(instance)도 소프트웨어의 개별 객체가 된다. 객체는 우리 주변 어디에나 있다 — 컴퓨터나 태블릿, 테이블, 문, 커피 머그 같은 물리적 사물, 방 안의 다른 사람, 그리고 방 자체도 객체다.

### 왜 객체를 사용하는가

코드를 정리되고 유연하며 재사용 가능하게 유지하는 방법이기 때문이다.

- **정리(organized)**: 관련된 세부 사항과 특정 기능이 뚜렷하고 찾기 쉬운 위치에 모인다.
- **유연성(flexible)**: 나머지 코드에 영향을 주지 않고 모듈 방식(modular way)으로 세부 사항을 쉽게 변경할 수 있다.
- **재사용(reusable)**: 코드를 재사용해 프로그램을 단순하게 유지할 수 있다.

### 객체의 세부 사항(details)과 행동(behaviors)

세미나실(seminar room)을 예로 들면, 먼저 방 자체가 객체이고 방 번호(room number)와 좌석 수용 인원(seating capacity) 같은 세부 사항을 가진다. 방 안에는 의자, 테이블, 프로젝터, 화이트보드 같은 물리적 객체들이 있고, 각각 소프트웨어의 객체로 표현될 수 있다.

- 각 객체에는 고유한 세부 사항이 있다: 프로젝터는 해상도(resolution)와 밝기(brightness) 같은 성능 스펙을, 의자는 사용자에게 의미 있는 좌석 치수(seat dimensions)를 가진다.
- 객체는 개별 책임(responsibility) 또는 행동(behavior)도 가진다: 프로젝터는 전원을 켜고, 비디오 입력을 받고, 이미지를 표시할 책임이 있다.

### 사람도 객체다

사람 객체(person object)는 이름, 나이, 성별, 직업 같은 세부 사항을 가지며 수많은 행동을 할 수 있다. 예에서 Ken은 화이트보드에 쓰고, 프로젝터를 켜고, 의자에 앉고, 테이블 위에 노트북을 펼 수 있다.

### 무생물도 자기 정보를 안다

사람이나 전자기기가 정보를 알고 행동을 수행한다고 생각하기는 쉽다(사람 객체는 자기 이름과 나이를 알고, 노트북은 자기 스펙을 안다). 객체지향 모델링에서는 **무생물 객체도 자기 정보를 안다**.

- 의자는 자신의 치수와 위치를 안다.
- 문은 문틀 높이와 문이 열린 각도를 안다.
- 화이트보드는 높이와 너비, 그리고 비어 있는지 글씨가 있는지를 안다.

객체지향 사고(object-oriented thinking)에서는 생물을 포함한 모든 것을 객체로 생각하며, 무생물조차 자기 자신을 아는(self-aware) 존재로 본다.

## 예시

세미나실을 객체로 모델링한 강의 예시:

| 객체 | 세부 사항(details) | 행동/책임(behaviors/responsibilities) |
|------|------|------|
| 방(room) | 방 번호, 좌석 수용 인원 | — |
| 프로젝터 | 해상도, 밝기 | 전원 켜기, 비디오 입력 받기, 이미지 표시 |
| 의자 | 좌석 치수, 위치 | — |
| 문 | 문틀 높이, 열린 각도 | — |
| 화이트보드 | 높이, 너비, 비었는지/글씨가 있는지 | — |
| 사람(Ken) | 이름, 나이, 성별, 직업 | 화이트보드에 쓰기, 프로젝터 켜기, 의자에 앉기, 노트북 열기 |

## 요약

- 객체지향 모델링은 핵심 개념을 소프트웨어의 객체로 표현하는 실천이며, 이 전문과정의 주요 주제다.
- 객체를 쓰면 코드가 정리되고, 모듈 방식의 변경이 가능해 유연하며, 재사용으로 프로그램을 단순하게 유지할 수 있다.
- 객체는 세부 사항(정보)과 행동(책임)을 가지며, 객체지향 사고에서는 무생물조차 자기 정보를 아는 객체로 본다.
- 주변 세계를 객체의 관점으로 보는 연습이 객체지향 설계에 도움이 된다 — "Think objects."
