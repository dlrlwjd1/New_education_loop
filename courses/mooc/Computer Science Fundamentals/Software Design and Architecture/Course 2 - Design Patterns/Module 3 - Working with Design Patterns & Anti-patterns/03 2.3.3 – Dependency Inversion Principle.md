# 2.3.3 – Dependency Inversion Principle

## 개요

- 소프트웨어 의존성(dependency)은 본질적으로 결합(coupling)이며, 시스템 변경의 용이성을 결정한다.
- 의존성 역전 원칙(Dependency Inversion Principle)은 "상위 수준 모듈은 하위 수준 세부 사항이 아니라 상위 수준 일반화(generalization)에 의존해야 한다"고 말한다.
- 정렬(sorting) 클래스 교체 예제로 저수준 의존(low level dependency)의 문제와 인터페이스를 통한 간접화(indirection)의 이점을 설명한다.

## 내용

### 의존성과 결합

시스템을 설계할 때 흔히 다뤄야 하는 문제가 의존성이다. "의존 지점은 어디인가?", "시스템 또는 서브시스템이 특정 자원에 어느 정도로 의존하는가?" 같은 질문이 생긴다. 소프트웨어 의존성은 본질적으로 결합(coupling)이며, 소프트웨어의 서로 다른 구성 요소 간에 얼마나 의존하는지를 정의한다. 시스템의 어떤 부분이 강하게 결합되어 있으면 서로에 대한 의존도가 높은 것이고, 낮은 의존성은 결합도가 낮다는 뜻이다. (결합에 대한 복습은 코스 1의 응집도와 결합도(cohesion and coupling) 강의를 참고.)

의존성이 중요한 이유는 **시스템을 얼마나 쉽게 변경할 수 있는지를 결정**하기 때문이다. 생존을 위해 특정 음식에 의존한다면 다른 것으로 대체할 수 없는 것과 같다. 우리 몸은 물에 의존하며, 물을 빵으로 대체하고 같은 결과를 기대할 수 없다. 소프트웨어에서도 마찬가지로, 어떤 클래스나 자원을 다른 것으로 대체하는 일은 쉽지 않거나 불가능할 수 있다. 시스템이 그 특정 클래스만 제공하는 기능에 의존하기 때문이다.

### 원칙의 내용

의존성 역전 원칙은 시스템을 더 견고(robust)하고 유연하게 만드는 데 도움을 준다. 이 원칙은 **상위 수준 모듈(high level module)은 상위 수준 일반화에 의존해야 하며, 하위 수준 세부 사항(low level detail)에 의존해서는 안 된다**고 말한다.

- 클라이언트 클래스는 구체적(concrete) 자원을 직접 참조하는 대신 인터페이스(interface)나 추상 클래스(abstract class)에 의존해야 한다.
- 구체적 자원의 행동은 인터페이스나 추상 클래스로 일반화되어야 한다.
- 인터페이스와 추상 클래스는 상위 수준(high level) 자원, 구체 클래스는 하위 수준(low level) 자원으로 본다. 인터페이스·추상 클래스가 일반적 행동 집합을 정의하고, 구체 클래스가 그 구현을 제공한다.
- 이렇게 하면 클라이언트 클래스가 하위 수준 기능으로부터 독립적이 된다. 이 코스에서 소개한 모든 디자인 패턴이 이 원칙 위에 세워져 있다.

### 저수준 의존의 문제 — 정렬 예제

전통적인 소프트웨어 설계에서는 서브시스템들이 서로 직접 의존한다. 클라이언트 클래스가 엔터프라이즈 서브시스템의 구체 클래스를 직접 참조하고, 그 클래스는 다시 백엔드의 구체 클래스를 직접 참조한다. 클라이언트 클래스가 구체 클래스를 직접 이름으로 참조하는 이런 의존을 **저수준 의존(low level dependency)** 이라 한다.

예를 들어 사용자가 보낸 리스트를 정렬하기 위해 QuickSorting이라는 구체 클래스를 직접 이름으로 참조한다고 하자. 나중에 MergeSort라는 다른 정렬 클래스로 바꾸려면 클라이언트 서브시스템 클래스에 상당한 변경이 필요하다. 정렬 클래스의 타입을 QuickSorting에서 MergeSorting으로 바꾸고, 정렬 메서드 호출도 바꿔야 한다. 정렬 알고리즘을 바꿀 때마다 이만큼의 작업이 필요하다면 비실용적일 뿐 아니라, 오래된 참조를 하나라도 놓치면 예기치 않은 부작용이 생길 수 있다.

### 고수준 의존으로의 전환

의존성 역전 원칙은 하위 수준 기능을 인터페이스나 추상 클래스로 일반화해, 대안 구현이 나왔을 때 쉽게 사용할 수 있게 한다. 이 원칙을 적용하면 시스템 전체 아키텍처가 우리가 살펴본 디자인 패턴들과 매우 비슷해진다.

1. 각 서브시스템에 걸친 행동을 인터페이스로 일반화한다.
2. 각 서브시스템의 구체 클래스가 그 인터페이스를 구현한다.
3. 클라이언트 클래스는 구체 클래스가 아니라 인터페이스를 참조한다.

구체 클래스를 선언하는 대신 Sorting 인터페이스를 선언하고, 인스턴스화(instantiation) 시점에 클라이언트 서브시스템이 어떤 정렬 클래스 인스턴스를 가질지 결정하면 된다. 정렬 행동을 인터페이스의 `sort` 메서드로 일반화했으므로 클라이언트 서브시스템의 메서드 호출을 바꿀 필요도 없다.

클라이언트 클래스가 하위 수준 구체 클래스가 아닌 상위 수준 일반화에 의존하므로, 클라이언트가 사용할 자원을 쉽게 바꿀 수 있다. 일반화는 인터페이스를 통해 구체 클래스의 행동을 호출하게 하는 **간접화(indirection)의 정도**를 제공한다. 고수준 의존은 클라이언트 클래스가 특정 구체 클래스와 직접 결합되는 것을 막는다. 즉 클라이언트 클래스는 **특정 구현이 아니라 기대되는 행동(expected behaviors)에 의존**하게 된다.

C 같은 절차적 언어에서는 프로그램 실행 중 특정 시점에 호출이 직접 이루어지는 경우가 많지만, 객체지향 시스템에서는 메서드 호출을 그렇게 직접적으로 할 필요가 없다. 객체지향 설계의 메서드 호출은 간접화 수준(level of indirection)을 통해 이루어져야 하며, 의존성 역전 원칙은 구체 클래스가 아닌 일반화에 의존성을 작성함으로써 간접화를 활용하라고 제안한다.

### 적용 시점과 가치

디자인 패턴과 마찬가지로 의존성 역전 원칙은 설계 과정에서 사용해야 한다. 유연하고 재사용 가능하며 유지보수 가능한 시스템은 소프트웨어의 수명을 연장하므로, 이 원칙의 적용이 그 목표 달성을 돕는다. 설계·구현에 추가 작업이 들 수 있지만, 나중에 얻는 시간과 자원이 그만한 가치가 있다. 대규모 시스템은 유지보수가 어렵고, 지나치게 강하게 결합되면 변경이 힘들어진다. 이 원칙은 시스템의 일부를 특정 기능 구현으로부터 절연(insulate)하는 데 도움을 준다.

## 예시

강의의 정렬 예제를 코드로 옮기면 다음과 같다. 구체 클래스 직접 참조(저수준 의존) 대신 인터페이스를 참조(고수준 의존)한다.

```java
// 정렬 행동을 일반화한 인터페이스
public interface Sorting {
    int[] sort(int[] list);
}

// 구체 클래스들이 인터페이스를 구현한다
public class QuickSorting implements Sorting {
    @Override
    public int[] sort(int[] list) {
        // 퀵 정렬 구현
        return list;
    }
}

public class MergeSorting implements Sorting {
    @Override
    public int[] sort(int[] list) {
        // 병합 정렬 구현
        return list;
    }
}
```

```java
// 클라이언트는 구체 클래스가 아니라 Sorting 인터페이스를 선언한다
public class ClientSubsystem {
    private Sorting sorter;

    // 어떤 정렬 클래스를 쓸지는 인스턴스화 시점에 결정한다
    public ClientSubsystem(Sorting sorter) {
        this.sorter = sorter;
    }

    public int[] sortList(int[] list) {
        // 구현이 QuickSorting에서 MergeSorting으로 바뀌어도
        // 이 메서드 호출은 변경할 필요가 없다
        return sorter.sort(list);
    }
}
```

## 요약

- 의존성 역전 원칙(Dependency Inversion Principle)은 구체 클래스에 대한 직접 참조를 간접 참조로 바꾸는 수단이다.
- 구체 클래스의 행동을 추상 클래스와 인터페이스로 일반화한다.
- 클라이언트 클래스가 구체적 자원과 직접이 아니라 일반화를 통해 시스템과 상호작용하게 한다.
- 저수준 구체 의존보다 고수준 의존을 강조한다.
- 프로그램은 구체 클래스가 아니라 인터페이스·추상 클래스 같은 일반화에 의존하도록 작성해야 하며, 이는 견고한 소프트웨어 솔루션을 만들기 위해 따라야 할 원칙이다.
