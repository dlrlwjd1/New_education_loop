# 2.2.3 – State Pattern

## 개요

- 상태 패턴(State Pattern)은 객체가 자신의 현재 상태(state)에 따라 적절한 행동을 선택하고, 상태가 바뀌면 행동도 바뀌게 하는 행위 패턴이다.
- 런타임(run-time)에 객체의 상태에 따라 행동을 바꿔야 할 때 주로 사용한다.
- 자판기(vending machine) 예시를 통해, 긴 조건문 대신 상태별 클래스에 처리를 위임(delegate)하는 구조를 배운다.

## 내용

### 상태에 따른 행동 — 춤 비유

- 강의는 "지금 어떤 자세인가"라는 질문으로 시작한다. 같은 자세를 유지한 채 춤을 추라고 하면, 앉아 있다면 팔과 어깨를 흔들고 고개를 까딱이는 춤을, 서 있다면 발동작을 추가한 춤을, 누워 있다면 손을 들고 몸을 꿈틀대는 춤을 추게 된다. "춤을 추라"고만 했을 뿐인데 현재 상태에 맞는 춤을 스스로 골랐다.
- 반대로 발을 바닥에 두드려야 하는 탭댄스(tap dance)를 시키면 누워 있는 상태에서는 어렵고, 그 동작을 하려면 상태를 바꿔야 할 것이다.
- 코드의 객체도 자신의 현재 상태를 알고 있으므로 이 전제를 활용할 수 있다. 현재 상태에 기반해 적절한 행동을 선택하고, 상태가 바뀌면 그 행동이 달라진다. 이것이 상태 패턴이다.

### 언제 사용하는가

- 런타임에 객체가 처한 상태에 따라 객체의 행동을 바꿔야 할 때 주로 사용한다.

### 자판기 예시

- 자판기는 여러 상태와 상태별 행동을 갖기 때문에 상태 패턴을 잘 보여준다. $1짜리 초콜릿 바를 산다고 하자.
  - 일반적인 경우: 자판기에 다가가 1달러를 넣고 선택하면 초콜릿 바가 나온다.
  - 다른 상황 1: 1달러를 넣은 뒤 마음이 바뀌어 반환 버튼(eject money)을 누르면 돈이 돌아온다.
  - 다른 상황 2: 초콜릿 바 재고가 떨어지면, 자판기는 재고(inventory)를 추적하다가 특정 상품이 더 없음을 고객에게 알려야 한다.
- UML 상태 다이어그램(state diagram)으로 표현하면:
  - 상태 3개: idle(대기), has $1(1달러 보유), out of stock(품절). 자판기는 한 번에 이 중 하나의 상태에 있다.
  - 트리거(trigger, 이벤트) 3개: insertDollar(달러 투입), ejectMoney(반환 요청), dispense(상품 배출 요청).
  - 액션(action) 2개: doReturnMoney(돈 반환), doReleaseProduct(상품 배출).

### 조건문 기반의 1차 구현

- 먼저 싱글턴(singleton) 상태 객체들을 만든다. 세 상태를 State 객체로 정의한다: State.Idle(대기), State.HasOneDollar(1달러 보유), State.OutOfStock(품절).
- VendingMachine 클래스에서 currentState는 자판기의 현재 상태를 나타내는 특정 상태 객체를 가리킨다.
  - 재고 수(stock count)가 0보다 큰 상태로 생성되면 currentState는 State.Idle, 아니면 State.OutOfStock으로 설정된다.
- 달러를 넣었을 때(insertDollar):
  - currentState가 State.Idle이면 → State.HasOneDollar로 바뀐다.
  - 이미 State.HasOneDollar이면 → 돈을 돌려주고 State.Idle로 설정된다.
  - State.OutOfStock이면 → 돈을 돌려주고 State.OutOfStock에 머문다.
- 문제점: 이 상태 객체들은 꽤 비대해 보이는데 정작 자기 책임은 별로 없다. 상태 패턴으로 제대로 재구성할 필요가 있다.

### 상태 패턴으로 재구성

- State 인터페이스를 정의하고, 상태가 응답해야 하는 각 트리거마다 메서드를 둔다: insertDollar, ejectMoney, dispense.
- 필요한 상태마다 State 인터페이스를 구현하는 상태 클래스를 만든다: IdleState, HasOneDollarState, OutOfStockState. 상태 클래스는 인터페이스의 메서드를 구현해 각 트리거에 응답해야 한다.
- 각 상태 클래스의 동작:
  - IdleState: 달러가 투입되어 insertDollar가 호출되면, vendingMachine 객체의 setState 메서드를 호출해 현재 상태를 HasOneDollarState로 바꾼다.
  - HasOneDollarState: ejectMoney가 호출되면 돈을 돌려주고 setState로 상태를 IdleState로 바꾼다. dispense가 호출되면 상품을 배출하고, 배출 후 재고가 남았는지에 따라 현재 상태를 IdleState 또는 OutOfStockState로 설정한다.
- VendingMachine 클래스의 생성자(constructor)는 각 상태 클래스를 인스턴스화하고, currentState는 이 상태 객체들 중 하나를 가리킨다.
- VendingMachine에는 이전처럼 트리거를 처리하는 메서드가 있지만, 이제는 처리를 현재 상태 객체에 위임(delegate)한다.
- 결과: 메서드 안의 긴 조건문(long conditionals)이 사라져 코드가 훨씬 깔끔해진다.

### 패턴의 일반 구조

- 상태 패턴의 구조에서 자판기는 컨텍스트(context) 클래스에 해당한다. 컨텍스트는 자신의 현재 상태를 추적한다.
- 트리거가 발생해 컨텍스트 객체에 요청이 들어오면, 컨텍스트는 실제 처리를 상태 객체에 위임한다.

## 예시

강의에서 설명한 자판기 상태 패턴 구조를 Java 코드로 옮기면 다음과 같다.

```java
public interface State {
    void insertDollar(VendingMachine vendingMachine);
    void ejectMoney(VendingMachine vendingMachine);
    void dispense(VendingMachine vendingMachine);
}
```

```java
public class IdleState implements State {

    @Override
    public void insertDollar(VendingMachine vendingMachine) {
        System.out.println("dollar inserted");
        vendingMachine.setState(vendingMachine.getHasOneDollarState());
    }

    @Override
    public void ejectMoney(VendingMachine vendingMachine) {
        System.out.println("no money to return");
    }

    @Override
    public void dispense(VendingMachine vendingMachine) {
        System.out.println("payment required");
    }
}
```

```java
public class HasOneDollarState implements State {

    @Override
    public void insertDollar(VendingMachine vendingMachine) {
        System.out.println("already have one dollar");
        vendingMachine.doReturnMoney();
    }

    @Override
    public void ejectMoney(VendingMachine vendingMachine) {
        // 돈을 돌려주고 대기 상태로 전환
        vendingMachine.doReturnMoney();
        vendingMachine.setState(vendingMachine.getIdleState());
    }

    @Override
    public void dispense(VendingMachine vendingMachine) {
        // 상품을 배출하고, 남은 재고에 따라 상태 전환
        vendingMachine.doReleaseProduct();
        if (vendingMachine.getCount() > 0) {
            vendingMachine.setState(vendingMachine.getIdleState());
        } else {
            vendingMachine.setState(vendingMachine.getOutOfStockState());
        }
    }
}
```

```java
public class VendingMachine {
    private final State idleState;
    private final State hasOneDollarState;
    private final State outOfStockState;

    private State currentState;
    private int count;

    // 생성자에서 각 상태 클래스를 인스턴스화하고 초기 상태를 정한다
    public VendingMachine(int count) {
        idleState = new IdleState();
        hasOneDollarState = new HasOneDollarState();
        outOfStockState = new OutOfStockState();

        this.count = count;
        if (count > 0) {
            currentState = idleState;
        } else {
            currentState = outOfStockState;
        }
    }

    // 트리거 처리 메서드 — 현재 상태 객체에 위임한다
    public void insertDollar() { currentState.insertDollar(this); }
    public void ejectMoney()  { currentState.ejectMoney(this); }
    public void dispense()    { currentState.dispense(this); }

    public void setState(State state) { this.currentState = state; }

    public void doReturnMoney()    { System.out.println("returning money"); }
    public void doReleaseProduct() { count--; System.out.println("releasing product"); }

    public State getIdleState()        { return idleState; }
    public State getHasOneDollarState() { return hasOneDollarState; }
    public State getOutOfStockState()  { return outOfStockState; }
    public int getCount()              { return count; }
}
```

컨텍스트인 VendingMachine은 긴 조건문 없이 currentState 객체에 처리를 위임하고, 각 상태 클래스가 자기 상태에서의 트리거 응답과 상태 전환을 책임진다.

## 요약

- 상태 패턴은 객체의 내부 상태 변화에 따라 행동을 바꿔야 할 때 사용하는 행위 패턴이다.
- 자판기 예시의 구성 요소: 상태 3개(idle, has $1, out of stock), 트리거 3개(insertDollar, ejectMoney, dispense), 액션 2개(doReturnMoney, doReleaseProduct).
- 조건문으로 상태를 처리하면 상태 객체가 비대해지고 책임이 불분명해진다. 대신 State 인터페이스와 상태별 구현 클래스를 만들어 각 상태가 자기 행동과 상태 전환을 책임지게 한다.
- 컨텍스트(context) 클래스는 현재 상태를 추적하고, 요청이 들어오면 상태 객체에 처리를 위임한다.
- 객체 상태에 의존하는 긴 조건문이 있는 메서드를 단순화하는 데에도 이 패턴을 활용할 수 있다.
