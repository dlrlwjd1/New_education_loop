# 2.2.1 – Template Method Pattern

## 개요

- 행위 패턴(behavioral pattern)은 독립적인 객체들이 공통의 목표를 향해 협력하는 방식에 초점을 둔 패턴이다.
- 템플릿 메서드 패턴(Template Method Pattern)은 알고리즘의 단계를 상위 클래스에서 일반적으로 정의하고, 일부 단계의 구현은 하위 클래스에 위임한다.
- 두 클래스가 매우 유사한 기능과 연산 순서(order of operations)를 가질 때, 일반화(generalization)와 상속(inheritance)을 활용해 중복을 제거하는 실용적 기법이다.

## 내용

### 행위 패턴이란

- 소프트웨어를 설계할 때는 서로 다른 객체들이 공통 목표를 향해 어떻게 함께 일하는지 인식하는 것이 중요하다. 각 객체는 더 큰 해결책의 한 조각이며, 효과적으로 일하려면 정해진 목적이 필요하다.
- 강의는 이를 회사의 직원에 비유한다. 직원들에게 미리 정의된 역할이 없다면 각자의 기능이 수행되는지 보장할 수 없고, 회사는 덜 효과적이고 덜 조직적이 된다.
- 행위 패턴은 이처럼 독립적인 객체들이 공통 목표를 향해 일하는 방식, 즉 객체의 행동(behavior)을 정의하는 다양한 방법을 다룬다.

### 실생활 예시 — 파스타 레시피

- 수프 만들기나 분말 음료 타기의 설명서는 비슷한 단계로 기술된다: 용기를 준비하고, 재료를 붓고, 물을 넣고, 젓고, 완성한다. 단계의 순서는 같지만, 일부 단계는 동일하고 일부는 구현이 다르다.
- 강의의 핵심 예시: 파스타 체인 레스토랑의 총괄 셰프(executive chef)가 모든 지점에서 요리가 일관되도록 각 요리의 지침을 제공한다.
  - 인기 메뉴 두 가지: 토마토소스 미트볼 스파게티(spaghetti with tomato sauce and meatballs), 알프레도소스 치킨 펜네(penne with Alfredo sauce and chicken).
  - 두 요리 모두 물 끓이기 → 파스타 삶기 → 소스 추가 → 단백질 추가 → 가니시(garnish) 순서를 따른다.
  - 소스·단백질·가니시는 요리마다 다르게 구현되지만, 물 끓이기는 어떤 요리든 한 가지 방식뿐이므로 동일하게 구현된다.
- 이 상황은 레시피를 만드는 메서드를 가진 PastaDish 클래스와 그 하위 클래스(SpaghettiMeatballs, PenneAlfredo)로 모델링할 수 있다. 이 메서드는 물 끓이기부터 가니시까지 일반적인 단계 전체를 알고 있고, 요리마다 특수한 단계(예: 어떤 소스를 넣을지)는 하위 클래스에서 구현한다.

### 템플릿 메서드 패턴의 정의

- 템플릿 메서드는 알고리즘의 단계를 일반적으로(generally) 정의하되, 일부 단계의 구현을 하위 클래스에 미룬다(defer).
- 행위 디자인 패턴이며, 책임(responsibility)의 할당과 관련이 있다.
- 자율주행 차량 예시: 자율주행 자동차와 오토바이 모두에 driveToDestination 같은 템플릿 메서드를 둘 수 있다. 가속, 조향(steering), 제동, 목적지 확인 등의 메서드 호출을 템플릿 메서드 안에 배치하고, 두 하위 클래스에서 같은 방식으로 호출한다. 다만 자동차의 조향과 오토바이의 조향처럼 일부 메서드의 구현은 서로 다르다.
- 사용 시점: 두 클래스를 새로운 상위 클래스로 일반화할 수 있을 때 가장 적합하다. 매우 유사한 기능과 연산 순서를 가진 별개의 두 클래스를 발견했을 때 쓰는 또 하나의 기법이다. 일반화 후 상속을 통해 기능을 공유하면 객체 재사용이 쉬워지고 코드가 더 명확하고 자명해진다.

### UML 구조

- PastaDish 상위 클래스에 템플릿 메서드 makeRecipe가 있고, 이 메서드가 레시피 각 단계의 다른 메서드들을 호출한다.
- 물 끓이기처럼 모든 요리에 공통인 단계는 PastaDish의 일반 메서드(boilWater)다.
- 소스 추가처럼 요리마다 특수한 단계는 PastaDish의 추상 메서드(abstract method)다. addSauce의 본문은 하위 클래스가 제공해 올바른 소스를 넣는다.
- SpaghettiMeatballs와 PenneAlfredo는 PastaDish의 하위 클래스로, 각자 addPasta, addSauce, addProtein, addGarnish의 자기 버전을 제공해야 한다.

### 구현 포인트 (Java)

- PastaDish는 추상 클래스(abstract class)여야 한다. 어떤 파스타·단백질·소스·가니시를 넣을지 모르는 일반적인 PastaDish는 생성할 수 없기 때문이다.
- 템플릿 메서드 makeRecipe는 final로 선언한다. Java에서 final 키워드는 해당 메서드를 하위 클래스가 오버라이드(override)할 수 없음을 뜻한다. 따라서 어떤 요리 하위 클래스도 자기만의 makeRecipe를 가질 수 없어, 요리 단계의 일관성이 보장되고 중복 코드가 줄어든다.
- makeRecipe 안에서 다른 메서드들을 호출한다. boilWater는 모든 하위 클래스에서 동일하므로 구현이 상위 클래스에 통합(consolidate)된다.
- addPasta, addProtein, addSauce, addGarnish는 SpaghettiMeatballs나 PenneAlfredo 같은 하위 클래스가 구현하도록 남겨둔다. 템플릿 메서드는 하위 클래스에 상속되어, 올바른 재료로 요리를 만들도록 기대대로 동작한다.

## 예시

강의에서 설명한 PastaDish 상위 클래스와 하위 클래스 구조를 Java 코드로 옮기면 다음과 같다.

```java
public abstract class PastaDish {

    // 템플릿 메서드: final이므로 하위 클래스가 오버라이드할 수 없다
    public final void makeRecipe() {
        boilWater();
        addPasta();
        addSauce();
        addProtein();
        addGarnish();
    }

    // 모든 요리에 공통인 단계 — 상위 클래스에 구현을 통합
    private void boilWater() {
        System.out.println("Boiling water");
    }

    // 요리마다 다른 단계 — 하위 클래스가 구현
    protected abstract void addPasta();
    protected abstract void addSauce();
    protected abstract void addProtein();
    protected abstract void addGarnish();
}
```

```java
public class SpaghettiMeatballs extends PastaDish {

    @Override
    protected void addPasta() {
        System.out.println("Add spaghetti noodles");
    }

    @Override
    protected void addSauce() {
        System.out.println("Add tomato sauce");
    }

    @Override
    protected void addProtein() {
        System.out.println("Add meatballs");
    }

    @Override
    protected void addGarnish() {
        System.out.println("Add Parmesan cheese");
    }
}
```

```java
public class PenneAlfredo extends PastaDish {

    @Override
    protected void addPasta() {
        System.out.println("Add penne noodles");
    }

    @Override
    protected void addSauce() {
        System.out.println("Add Alfredo sauce");
    }

    @Override
    protected void addProtein() {
        System.out.println("Add chicken");
    }

    @Override
    protected void addGarnish() {
        System.out.println("Add parsley");
    }
}
```

두 하위 클래스 모두 PastaDish를 상속(extends)하고 추상 메서드를 구현한다. 상속받은 makeRecipe 템플릿 메서드를 호출하면 올바른 재료로 요리가 만들어진다.

## 요약

- 행위 패턴은 독립적인 객체들이 공통 목표를 향해 협력하는 방식을 정의한다.
- 템플릿 메서드 패턴은 알고리즘의 골격을 상위 클래스의 템플릿 메서드에 정의하고, 요리마다 다른 단계 같은 차이점은 추상 메서드 호출을 통해 하위 클래스 구현에 맡긴다.
- 비슷한 알고리즘을 가진 두 클래스를 발견하면, 알고리즘을 두 곳에서 따로 수정하는 대신 상위 클래스의 템플릿 메서드 한 곳으로 통합(consolidate)한다.
- Java에서는 상위 클래스를 abstract로, 템플릿 메서드를 final로 선언해 단계의 일관성을 보장하고 중복 코드를 줄인다.
- 이 패턴은 일반화와 상속의 실용적 응용으로, 더 명확하고 자기설명적인(self-explanatory) 코드를 만든다.
