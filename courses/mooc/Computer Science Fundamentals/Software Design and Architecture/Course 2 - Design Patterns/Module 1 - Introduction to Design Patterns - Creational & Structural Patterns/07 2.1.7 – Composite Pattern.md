# 2.1.7 – Composite Pattern

## 개요

- 컴포지트 패턴(Composite pattern)의 두 가지 목표: 객체들의 **중첩 구조(nested structure)를 합성**하는 것과, 그 객체들의 클래스를 **균일하게(uniformly) 다루는 것**.
- 컴포넌트 인터페이스(component interface) — 컴포지트 클래스(composite class) — 리프 클래스(leaf class) 구조로, 재귀적 합성(recursive composition)을 통해 트리(tree) 형태의 구조를 만든다.
- 건물(building) — 층(floor) — 방(room) 예시로, 다형성(polymorphism)을 강제해 타입 검사 없이 개별 객체들을 동일하게 다룬다.

## 내용

### 동기: 건물과 방

- 건물은 방들로 구성된다. 건물과 방은 기능이 조금 다르지만 본질적으로 일반적인 주거 구조물(housing structure)로 취급할 수 있다 — 건물이든 방이든 들어가고 나올 수 있고, 둘 다 가구를 보관할 수 있다.
- 서로 다른 타입의 객체지만 균일하게 다룰 수 있다는 것이 핵심이다.

### 패턴의 기본 설계

- **컴포넌트 인터페이스(component interface)**: 클래스 집합의 슈퍼타입(supertype) 역할을 해서 모두를 균일하게 다룰 수 있게 한다. 다형성(polymorphism)을 강제해 모든 구현 클래스가 같은 인터페이스를 따르게 하는 방식이다. 인터페이스 대신 추상 슈퍼클래스(abstract superclass)를 써도 된다 — 둘 다 다형성을 허용하기 때문. 강의에서는 인터페이스를 사용한다.
- **컴포지트 클래스(composite class)**: 컴포넌트 인터페이스를 구현하는 어떤 클래스든 집약(aggregate)한다. 컴포지트 객체가 담고 있는 컴포넌트 객체들을 순회(traverse)하고 잠재적으로 조작할 수 있게 해 준다.
- **리프 클래스(leaf class)**: 비합성(non-composite) 타입을 나타낸다. 다른 컴포넌트로 구성되지 않는다.
- 리프 클래스와 컴포지트 클래스가 모두 컴포넌트 인터페이스를 구현하게 함으로써 하나의 타입으로 통일한다. 둘 다 컴포넌트의 서브타입(subtype)이 된다.
- 문제에 따라 컴포지트·리프 클래스는 여러 개 둘 수 있지만, 전체 컴포넌트 인터페이스(또는 추상 슈퍼클래스)는 하나만 둔다.

### 재귀적 합성(Recursive Composition)과 트리 구조

- 컴포지트 클래스가 컴포넌트의 서브타입이므로, 컴포지트 객체는 다른 컴포지트 객체를 담을 수 있다. 이를 재귀적 합성(recursive composition)이라 하며, 이 패턴의 다른 이름이기도 하다.
- 컴포지트 클래스의 순환적으로 보이는 성질 때문에 이 패턴의 실제 모습을 상상하기 어려울 수 있는데, **트리(tree)** 로 생각하는 것이 가장 쉽다.
  - 루트(root)에는 다른 컴포넌트 객체들로 이루어진 메인 컴포지트 객체가 있다.
  - 각 레벨에서 컴포지트 객체 아래에 다른 컴포지트나 리프 같은 컴포넌트를 더 추가할 수 있다.
  - 컴포넌트는 컴포지트 객체에만 추가할 수 있고 리프 객체에는 추가할 수 없다. 즉, 컴포지트 객체는 트리를 키울 수 있지만 리프 객체는 그 자리에서 트리를 끝낸다.
- 이 패턴이 해결하는 두 가지 문제: 개별 타입의 객체들로 트리 같은 구조를 어떻게 만들 것인가, 그리고 타입 검사 없이 개별 타입 객체들을 어떻게 균일하게 다룰 것인가.

### 건물 예시에 적용

- 앞의 건물 예시를 적용하면, 일반적 주거 구조물이 컴포넌트 인터페이스(`IStructure`)다. 건물·층·방이 각기 고유한 타입임에도 이 인터페이스로 기술할 수 있다.
- `Housing` 클래스가 컴포지트 클래스다. Housing은 구조물(structure)의 일종이면서 다른 구조물을 담을 수 있다. 즉, Housing 객체가 다른 Housing 객체를 담을 수 있다.
  - 예: 건물을 Housing 객체로 표현하고, 건물이 층들을 담는다. 각 층도 또 다른 Housing 객체로 표현할 수 있다. 건물이 층들(모두 Housing 객체)로 합성되어 있으므로 층에서 층으로 건물을 순회할 수 있다.
- `Room`은 리프 클래스다. 방은 다른 방을 담을 수 없고, 건물의 층 같은 Housing 안에 담긴다.
- 이렇게 건물이 Housing과 Room 타입의 구조물로 구성되는 모델을 UML 클래스 다이어그램으로 표현할 수 있다.

### Java로 구현하는 3단계

1. **전체 타입을 정의하는 인터페이스 설계**: 컴포지트 클래스와 리프 클래스가 구현할 인터페이스를 정의한다. 이것이 다형성을 뒷받침한다.
2. **컴포지트 클래스 구현**: 인터페이스를 `Housing` 클래스에서 구현해 클라이언트 코드가 쓸 자체 행동을 부여한다.
   - Housing 객체는 다른 구조물들로 합성될 수 있으므로 이 포함(containment)을 적절한 컬렉션(collection)으로 표현해야 한다.
   - 컴포지트 객체에 컴포넌트를 더 추가하는 메서드도 필요하다. 예시에서는 private `ArrayList`를 두고 public `addStructure` 메서드를 통해서만 변경한다.
   - 컴포지트 객체의 컴포넌트들을 순회하려면 요청 시 컴포넌트를 꺼낼 수 있어야 한다. 컴포넌트 객체 관리를 돕는 추가 메서드도 넣을 수 있다 — 컴포지트 클래스에 무엇을 더 담을지는 설계자의 결정이다.
3. **리프 클래스 구현**: 리프 클래스는 컴포넌트를 담지 않으므로 컴포넌트 컬렉션이나 컬렉션 관리 메서드가 필요 없다. `IStructure` 인터페이스의 메서드만 구현하면 된다.

### 사용

- 구조물을 하나씩 만들어 건물을 구성한다. 예시의 건물은 1개 층을 가지고, 그 층은 공용 방(common room) 하나와 화장실(washroom) 두 개를 담는다.
- 단순한 예지만 이 패턴의 강력함을 보여준다. 컴포지트 객체는 빠르고 쉽게 만들 수 있고, 각 컴포넌트는 타입 검사 없이 같은 행동 집합을 가질 것으로 기대할 수 있다.

## 예시

강의에서 단계별로 설명한 건물 예시를 Java로 정리하면 다음과 같다.

```java
import java.util.ArrayList;

// 1단계: 전체 타입을 정의하는 컴포넌트 인터페이스
public interface IStructure {
    void enter();
    void exit();
    void location();
    String getName();
}

// 2단계: 컴포지트 클래스 — 다른 IStructure 컴포넌트들을 집약
public class Housing implements IStructure {
    // 포함 관계를 표현하는 컬렉션 (private, addStructure로만 변경)
    private ArrayList<IStructure> structures = new ArrayList<IStructure>();
    private String address;

    public Housing(String address) {
        this.address = address;
    }

    // 컴포지트에 컴포넌트를 추가하는 메서드
    public int addStructure(IStructure component) {
        structures.add(component);
        return structures.size() - 1;
    }

    // 순회를 위해 컴포넌트를 꺼내는 메서드
    public IStructure getStructure(int componentNumber) {
        return structures.get(componentNumber);
    }

    public void enter() { System.out.println("You have entered the " + getName()); }
    public void exit() { System.out.println("You have left the " + getName()); }
    public void location() {
        System.out.println("You are currently in the " + getName() + ". It has:");
        for (IStructure struct : structures) {
            System.out.println(struct.getName());
        }
    }
    public String getName() { return address; }
}

// 3단계: 리프 클래스 — 컴포넌트를 담지 않으므로 컬렉션이 필요 없다
public class Room implements IStructure {
    private String name;

    public Room(String name) {
        this.name = name;
    }

    public void enter() { System.out.println("You have entered the " + name); }
    public void exit() { System.out.println("You have left the " + name); }
    public void location() { System.out.println("You are currently in the " + name); }
    public String getName() { return name; }
}

// 사용: 건물을 구조물 하나씩 조립 — 층 하나에 공용 방 1개, 화장실 2개
public class Program {
    public static void main(String[] args) {
        Housing building = new Housing("123 Street");
        Housing floor1 = new Housing("123 Street - First Floor");
        int firstFloor = building.addStructure(floor1);

        Room commonRoom = new Room("Common Room");
        Room washroom1 = new Room("Washroom 1");
        Room washroom2 = new Room("Washroom 2");
        floor1.addStructure(commonRoom);
        floor1.addStructure(washroom1);
        floor1.addStructure(washroom2);

        building.enter();
        Housing currentFloor = (Housing) building.getStructure(firstFloor);
        currentFloor.enter();
        currentFloor.location();
    }
}
```

## 요약

- 컴포지트 패턴(Composite pattern)은 트리 같은 객체 구조를 만드는 문제와, 개별 타입 객체들을 균일하게 다루는 문제를 해결한다.
- 수단: 인터페이스 구현(또는 슈퍼클래스 상속)으로 모든 클래스에 다형성을 강제 + 공통 타입 객체들이 서로를 담을 수 있게 하는 재귀적 합성(recursive composition).
- 컴포지트 객체는 트리를 키울 수 있고, 리프 객체는 트리를 끝낸다. 컴포넌트 추가는 컴포지트에만 가능하다.
- 분해(decomposition)와 일반화(generalization) 원칙을 함께 적용해 전체를 부분으로 나누되, 전체와 부분이 공통 타입을 따르게 하는 것으로 볼 수 있다.
- 구조를 이해·조작하기 쉬워지고 더 읽기 쉽고 재사용 가능하며 의미 있는 코드로 이어진다.
