# Suffix Array

## 개요
- 접미사 배열(suffix array)은 문자열 S의 모든 접미사(suffix)를 사전식 순서(lexicographic order)로 정렬하는 문제다.
- 매우 긴 문자열(예: 수십억 개 뉴클레오티드로 이루어진 게놈)의 부분 문자열 매칭에 유용하다.
- 이 모듈에서는 접미사 배열을 효율적으로 **구성(build)** 하고 **저장(store)** 하는 실제 알고리즘 문제를 다룬다.

## 내용

### 사전식 순서 (Lexicographic order)
- 먼저 알파벳(alphabet)이 있다. 알파벳은 문자열에 나타날 수 있는 모든 문자의 집합이며 정렬되어 있다고 가정한다.
  - 영어: a부터 z까지 정렬.
  - 게놈: a, c, g, t 네 가지 뉴클레오티드로 이루어진 알파벳.
- 문자열 S가 문자열 T보다 사전식으로 작다는 것은 다음 둘 중 하나가 성립할 때다.
  1. S가 T의 접두사(prefix)인 경우.
  2. S와 T가 (비어 있을 수도 있는) 공통 접두사를 가지고, 그 다음 문자가 S 쪽이 T 쪽보다 작은 경우.

### 특수 문자 $ 추가
- 접미사 배열을 만들 때 "S가 T의 접두사면 S가 더 작다"는 규칙은 다루기 불편하다.
- 이를 피하기 위해 모든 문자열 끝에 특수 문자 `$`(dollar)를 붙인다.
- `$`는 알파벳의 모든 문자보다 **작다**고 정의한다.
- 초기에 S가 T의 접두사였다면, `S$`는 S의 길이 위치에서 `$`를 가지고 `T$`는 그 위치에서 알파벳의 어떤 문자를 가진다. `$`가 더 작으므로 `S$ < T$`가 자동으로 성립한다.
- 따라서 접두사 규칙을 따로 고려하지 않아도 된다.
- `$`를 붙여 정렬한 뒤 `$`를 제거해도 초기 문자열 접미사들의 순서는 동일하다.

### 접미사 배열의 저장
- 문자열 S의 모든 접미사의 총 길이는 S 길이의 **제곱(quadratic)** 에 비례한다. 게놈처럼 수십억 문자인 경우 접미사 자체를 저장하는 것은 사실상 불가능하다.
- 대신 접미사 **자체가 아니라 순서(order)** 만 저장한다.
- 순서는 각 접미사가 원래 문자열에서 시작하는 위치(정수)들의 수열로 표현한다. 이 크기는 문자열 길이에 비례한다.
- 즉, 이 강의에서 접미사 배열은 접미사들의 배열이 아니라 **접미사들의 순서**를 뜻한다.

## 예시

문자열 `S = ababaa`의 접미사를 사전식으로 정렬하면:

```
a
aa
abaa
ababaa
baa
babaa
```

`$`를 붙인 `S = ababaa$` (위치는 0부터 시작):

- 접미사는 시작 위치로 번호를 매긴다.
  - 전체 문자열 `ababaa$` → 위치 0
  - `abaa$` → 위치 2

정렬된 순서(가장 작은 것부터)와 시작 위치:

| 접미사 | 시작 위치 |
|--------|-----------|
| `$` | 6 |
| `a$` | 5 |
| `aa$` | 4 |
| `abaa$` | 2 |
| `ababaa$` | 0 |
| `baa$` | 3 |
| `babaa$` | 1 |

따라서 접미사 배열은 `6, 5, 4, 2, 0, 3, 1`이다.

## 요약
- 접미사 배열 = 문자열의 모든 접미사를 사전식으로 정렬한 순서.
- 끝에 `$`(모든 문자보다 작음)를 붙여 접두사 규칙을 제거한다.
- 접미사 자체(제곱 크기)가 아니라 시작 위치의 수열(선형 크기)로 저장한다.
- 예: `ababaa$`의 접미사 배열은 `6, 5, 4, 2, 0, 3, 1`.
