# Using BWT for Pattern Matching

## 개요
- 접미사 트리(suffix tree)를 이용한 패턴 매칭은 시간이 O(텍스트 길이 + 모든 패턴 길이의 합)이지만, 메모리는 최선의 구현에서도 텍스트 길이의 약 20배가 필요해 사람 게놈처럼 큰 문자열에는 비효율적이다.
- 버로우즈-휠러 변환(BWT)을 이용해 메모리 효율적인 선형 시간(linear-time) 다중 패턴 매칭 알고리즘을 만드는 방법을 다룬다.

## 내용

### 패턴 매칭 아이디어: 뒤에서부터 매칭
- 패턴을 뒤에서부터(마지막 글자부터) 매칭한다.
- 예를 들어 `panamabananas`에서 `ana`를 찾을 때, 먼저 `a`로 시작하는 행들을 찾고, 그중 `n`으로 끝나는(즉 `na`에 대응하는) 행을 좁혀간다.
- first-last property를 이용해 이 좁혀진 범위가 첫 번째 열의 어느 위치에 대응하는지 찾고, 다시 남은 문자(`a`)를 매칭해 범위를 좁혀 나간다.

### top/bottom 포인터를 이용한 BWMatching 알고리즘
- 알고리즘은 BWT 행렬에서 관심 있는 위치의 범위를 나타내는 두 포인터 `top`, `bottom`을 사용한다.
- 처음에는 `top = 0`, `bottom = (텍스트 길이 - 1)`로 전체 범위를 나타낸다.
- 패턴을 뒤에서부터 한 글자씩 처리하며, 마지막 열에서 그 글자가 처음/마지막으로 등장하는 위치를 찾고, first-last property로 첫 번째 열에서의 대응 위치로 범위를 좁힌다.
- 이 과정을 패턴의 모든 문자에 대해 반복하면 최종적으로 패턴이 매칭되는 행의 범위(top, bottom)를 얻는다.

### Count 배열을 이용한 최적화
- 기본 BWMatching은 매 단계마다 top부터 bottom까지 마지막 열의 모든 기호를 탐색해야 해서 느리다.
- **Count 배열**은 마지막 열의 앞 i개 위치에서 특정 기호가 몇 번 등장했는지를 미리 기록한 배열이다.
- Count 배열을 이용하면 top부터 bottom까지 모든 기호를 일일이 탐색할 필요 없이 상수 시간에 범위를 갱신할 수 있어, 4줄이던 로직을 2줄로 줄일 수 있다.

## 예시
- `panamabananas`에서 `ana` 검색: `a`로 시작하는 행 6개 중 `na`로 끝나는(즉 뒤 두 글자가 `na`인) 행은 3개다.
- 이 3개 행에 대해 first-last property를 적용해 첫 열에서의 위치(`na`가 시작하는 위치)를 찾는다.
- 다시 남은 첫 글자 `a`를 매칭해 최종적으로 `ana`가 3번 등장하는 것을 확인한다.
- top/bottom 포인터 예시: 초기 `top=0, bottom=13` → `n` 매칭 후 `top=9, bottom=11`처럼 범위가 좁혀진다.

## 요약
- BWT 기반 패턴 매칭은 패턴을 뒤에서부터 읽으며 top/bottom 포인터로 매칭 범위를 좁혀가는 방식이다.
- first-last property를 이용해 마지막 열의 위치를 첫 번째 열의 위치로 변환한다.
- Count 배열을 도입하면 매 단계 전체 탐색 없이 상수 시간에 범위를 갱신할 수 있어 훨씬 빠르다.
- 남은 문제는 매칭된 위치가 BWT 행렬에서의 위치일 뿐, 원래 텍스트에서 정확히 어디인지는 아직 알 수 없다는 것이다.
