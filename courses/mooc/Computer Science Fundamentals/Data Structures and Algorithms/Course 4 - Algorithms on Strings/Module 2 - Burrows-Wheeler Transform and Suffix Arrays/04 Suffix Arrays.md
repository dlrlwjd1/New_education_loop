# Suffix Arrays

## 개요
- BWT 기반 패턴 매칭에서 찾은 매칭 위치가 텍스트의 어디에 해당하는지 알아내는 문제를 접미사 배열(suffix array)로 해결한다.
- 접미사 배열을 완전히 저장하지 않고 일부만 저장하는 부분 접미사 배열(partial suffix array)로 메모리를 더 절약하는 방법도 다룬다.

## 내용

### 접미사 배열이란
- 접미사 배열은 문자열의 각 접미사(suffix)가 시작하는 위치를 정렬된 순서로 담고 있는 배열이다.
- 접미사 배열이 있으면 패턴이 텍스트의 어느 위치에서 등장하는지 빠르게 답할 수 있다.

### 접미사 배열과 접미사 트리의 관계
- 접미사 트리(suffix tree)가 이미 있다면, 접미사 트리를 깊이 우선 탐색(depth-first traversal)으로 순회하며 리프를 방문하는 순서가 곧 접미사 배열이다.
- 접미사 트리로부터 구성하면 O(텍스트 길이) 시간과 텍스트 길이의 약 20배 공간이 필요하다.
- Manber-Myers(1990) 알고리즘은 접미사 트리 없이 O(텍스트 길이 · log(텍스트 길이)) 시간, 텍스트 길이의 4배 공간으로 접미사 배열을 직접 구성하는 최초의 방법이다.
- (단순 나이브 방법은 모든 접미사를 정렬해야 하므로 O(텍스트 길이 · log(텍스트 길이)) 비교가 필요하고 각 비교도 시간이 걸린다.)

### 부분 접미사 배열(partial suffix array)
- 게놈처럼 큰 문자열에서는 접미사 배열 전체를 저장해도 메모리가 부족할 수 있다.
- 아이디어: 접미사 배열의 원소 중 인덱스가 정수 K의 배수인 것만 저장한다. 예를 들어 K=5이면 배열의 5, 10, 0번째 원소만 저장한다.
- 매칭 위치가 저장되지 않은 인덱스라면, first-last property를 이용해 한 글자씩 앞으로 이동하며 저장된 인덱스에 도달할 때까지 반복한다.
- 저장된 인덱스에 도달하면 그 값을 이용해 원래 찾던 매칭 위치를 역산할 수 있다.
- 이 방법은 검색 시간이 최대 K배 늘어날 수 있지만, K는 상수이므로 시간 복잡도에 영향을 주지 않는다.

## 예시
- 문자열에서 `ana`의 접미사 배열 값이 1, 7, 9라면 `ana`는 텍스트의 위치 1, 7, 9에서 등장한다.
- K=5인 부분 접미사 배열에서는 배열의 5, 10, 0번째 원소만 저장한다. `ana`가 있는 위치(예: 위치 7)가 저장되지 않은 인덱스라면, first-last property로 한 글자씩 앞으로 이동한다.
  - `ana`의 위치를 모르므로 `bana`의 위치를 확인하고, 그것도 모르면 `abana`의 위치를 확인한다.
  - `abana`가 부분 접미사 배열에 저장된 위치(예: 5)라면, `bana`는 위치 6, `ana`는 위치 7이라는 것을 역산할 수 있다.

## 요약
- 접미사 배열은 각 접미사의 시작 위치를 정렬한 배열이며, 접미사 트리의 깊이 우선 순회 순서와 같다.
- 나이브 정렬은 O(텍스트 길이 · log(텍스트 길이))가 필요하고, Manber-Myers 알고리즘은 접미사 트리 없이 이를 구성한다.
- 부분 접미사 배열은 K의 배수 인덱스만 저장해 메모리를 줄이고, first-last property로 저장된 인덱스까지 이동해 위치를 역산한다.
- 부분 접미사 배열을 쓰면 검색 시간이 최대 K배 늘어나지만 K는 상수이므로 여전히 효율적이다.
