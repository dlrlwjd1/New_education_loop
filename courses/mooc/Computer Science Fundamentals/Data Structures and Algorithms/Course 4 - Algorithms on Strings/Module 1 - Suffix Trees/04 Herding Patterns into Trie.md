# Herding Patterns into Trie

## 개요
- 여러 패턴을 각각 처리하는 대신 하나의 트라이(trie)로 묶어 텍스트를 한 번만 훑는 아이디어를 제시한다.
- 트라이 구성 방법과 TrieMatching 알고리즘, 그리고 그 시간·메모리 특성을 설명한다.

## 내용

### 아이디어: 패턴들을 버스에 싣기
- 무차별 대입에서는 각 패턴을 따로 "차"에 실어 여러 번 운전하기 때문에 느리다.
- 대신 모든 패턴을 하나의 "버스(bus)", 즉 트라이(trie of patterns)에 담아 텍스트를 한 번만 운전한다.

### 트라이 구성
- 첫 패턴을 트리(tree)에서 루트로부터의 경로(path)로 표현한다.
- 각 패턴을 차례로 추가하되, 이미 존재하는 접두사(prefix) 경로는 공유하고 갈라지는 지점에서 가지(branch)를 친다.
- 예: `panamabananas`에 대한 패턴들(예: antenna, bandana, ananas, nana 등)을 추가하며, 공통 접두사에서 갈라질 때마다 경로를 분기한다.

### TrieMatching 알고리즘
- 구성한 트라이를 텍스트를 따라 운전한다.
- 텍스트의 각 위치에서 텍스트 기호를 하나씩 따라가며 트라이를 내려간다(walk down).
- 리프(leaf)에 도달할 때마다 Patterns 집합의 한 패턴이 텍스트에 매칭된 것이다.
- 예: `panamabananas`의 각 시작 위치에서 트라이를 내려가며 pan, banana 등의 매칭을 한 번의 순회로 모두 찾는다.

### 복잡도 분석
- 무차별 대입 실행 시간: O(|Text| × |Patterns|) — 패턴 총 길이가 커서 느렸다.
- TrieMatching 실행 시간: **O(|Text| × 가장 긴 패턴의 길이)**. 현대 시퀀싱에서 리드는 길이가 200~300 뉴클레오티드에 불과하다.
- 메모리(간선 수): 트라이의 간선 수는 **O(모든 패턴의 총 길이)**이다.
- 인간 유전체에서는 패턴 총 길이가 수조(trillions)에 이르러, 이 알고리즘은 리드 매칭에 비현실적이다.

## 예시
- 강의 예제 트라이는 30개의 간선(edge)을 가진다.
- TrieMatching 실행 시간: `O(|Text| × (가장 긴 패턴의 길이))`
- 트라이 간선 수: `O(|Patterns|)`, |Patterns| = 모든 패턴의 총 길이

## 요약
- 트라이는 여러 패턴을 하나로 묶어 텍스트를 한 번만 훑게 해준다.
- TrieMatching은 O(|Text| × 가장 긴 패턴 길이)로 매우 빠르다.
- 그러나 트라이의 메모리(간선 수)가 모든 패턴 총 길이에 비례해, 유전체 규모에서는 여전히 비현실적이다.
