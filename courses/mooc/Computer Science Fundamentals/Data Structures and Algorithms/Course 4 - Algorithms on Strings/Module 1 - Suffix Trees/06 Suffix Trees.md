# Suffix Trees

## 개요
- 접미사 트라이(suffix trie)의 분기 없는 경로를 하나의 간선으로 압축한 접미사 트리(suffix tree)를 제시한다.
- 간선 라벨을 두 숫자(시작 위치, 길이)로 저장해 메모리를 크게 절약하는 방법을 설명한다.
- `$` 기호의 역할과 접미사 트리 구성 알고리즘의 복잡도, 그리고 남은 한계를 다룬다.

## 내용

### 경로 압축(path compression)
- 접미사 트라이에서 `bananas` 같은 부분은 여러 간선을 차지한다.
- 분기 없는(non-branching) 경로를 하나의 간선으로 압축하면 트리가 훨씬 작아진다.
- 이렇게 만든 것을 텍스트의 접미사 트리(SuffixTree of text)라 한다.

### 정점 수와 메모리
- 각 접미사는 리프 하나와 최대 내부 정점(internal vertex) 하나를 추가한다.
- 따라서 접미사 트리의 정점 수는 **2 × |Text| 미만**이다.
- 간선 수에 비례하는 메모리 사용량도 **O(|Text|)**이다.

### 간선 라벨 저장
- 라벨 문자열을 그대로 저장하면 결국 접미사 트라이와 같은 공간을 쓰게 된다.
- 대신 라벨을 두 숫자로 저장한다: 시작 위치와 길이. 예: `bananas`는 텍스트 위치 6에서 시작하고 길이 8이므로, (6, 8)만 저장하면 전체 라벨을 복원할 수 있다.
- 모든 간선 라벨에 이 방식을 적용하면 접미사 트리는 매우 메모리 효율적이다.

### 달러 기호 `$`의 역할
- `panamabananas`에 `$`를 붙인 이유는 각 접미사가 반드시 리프(leaf)에 대응되도록 하기 위해서다.
- `papa`를 `$` 없이, 그리고 `papa$`로 각각 접미사 트리를 만들어 비교하면 `$`의 중요성을 확인할 수 있다.

### 구성 알고리즘 복잡도
- 모든 접미사를 결합하는 나이브(naive) 구성은 **O(|Text|²)** 시간이 걸린다.
- 그러나 40여 년 전 개발된 독창적인 선형 시간 알고리즘이 존재하며, **O(|Text|)** 시간에 접미사 트리를 구성한다.

### Big O 표기법의 숨은 상수와 남은 한계
- 접미사 트리는 정확 다중 패턴 매칭을 실행 시간 **O(|Text| + |Patterns|)**, 메모리 **O(|Text|)**로 해결한다. 이론상 최선이다.
- 그러나 Big O는 상수를 감춘다. 알려진 최선의 접미사 트리 구현조차 메모리 사용량이 약 **20 × |Text|**로, 인간 유전체 같은 긴 서열에는 매우 큰 요구량이다.
- 더 중요한 점은, 우리의 목표가 돌연변이(mutation) 탐색이라는 것이다. 접미사 트리로 빠른 근사 다중 패턴 매칭(approximate multiple pattern matching)을 어떻게 할지는 불분명하다.

## 예시
- 간선 라벨 저장: 문자열 `bananas` 대신 (시작 위치 6, 길이 8)만 저장
- 정점 수: `< 2 × |Text|`
- 나이브 구성 시간: `O(|Text|²)`; 선형 시간 알고리즘: `O(|Text|)`
- 정확 다중 패턴 매칭: 시간 `O(|Text| + |Patterns|)`, 메모리 `O(|Text|)` (단, 실제 구현 상수는 약 20 × |Text|)

## 요약
- 접미사 트리는 접미사 트라이의 분기 없는 경로를 압축하고, 간선 라벨을 (시작 위치, 길이) 두 숫자로 저장해 메모리를 O(|Text|)로 줄인다.
- `$` 기호는 모든 접미사가 리프에 대응되도록 보장한다.
- 선형 시간 구성이 가능하지만, 실제 메모리 상수가 크고 근사 패턴 매칭에는 적합하지 않아 새로운 접근(BWT)이 필요하다.
