# Amortized Analysis: Summary

## 개요
- 동적 배열의 용량을 늘릴 때 반드시 두 배(factor 2)로 늘려야 하는 것은 아니며, 2.5배처럼 다른 상수 배율(constant multiplicative factor)을 사용해도 무방하다.
- 반면 매번 일정한 "양(constant amount)"만큼만 용량을 늘리는 방식은 분할상환 비용을 O(1)에서 O(n)으로 악화시킨다는 것을 집계 방법(aggregate method)으로 보일 수 있다.
- 세 가지 분할상환 분석 방법(집계 방법, 뱅커 방법, 물리학자 방법)을 정리한다.

## 내용

### 상수 배율 대신 상수량으로 늘리면 어떻게 되는가
- 예시로, 용량을 두 배가 아니라 매번 10씩(예: 10칸이 다 차면 10칸을 더 추가) 늘리는 방식을 가정한다.
- i번째 삽입의 비용 c_i는: 원소를 넣는 기본 비용 1 + (i-1)이 10의 배수라면 이전까지의 원소 i-1개를 새 배열로 옮기는 비용, 아니면 0.
- 집계 방법으로 총 비용을 구하면 `n + (10칸마다 발생하는 이동 비용의 합)`이 되는데, 이 이동 비용의 합은 `10 × sum_{j=1}^{(n-1)/10} j` 형태가 되어 O(n²)에 해당한다(1부터 (n-1)/10까지의 합은 등차수열 합 공식에 의해 그 항 수의 제곱에 비례하기 때문).
- 따라서 전체 비용은 `n + O(n²)`이 되고, 이를 n으로 나누면 분할상환 비용은 O(n)이 된다.
- 결론: 배열 크기가 커질수록 리사이징 사이에 벌어들이는(저축하는) 여유가 상수량 증가 방식으로는 충분하지 않아, 매번 상수 배율로 늘려야만 O(1) 분할상환 비용을 얻을 수 있다.

### 세 가지 분할상환 분석 방법 정리
- 집계 방법(aggregate method): 분할상환 비용의 정의(총 비용 / n)에 따라 직접 총 비용을 계산하는 무차별 대입(brute-force) 방식.
- 뱅커 방법(banker's method): 저렴한 연산마다 여분의 비용을 토큰(token) 형태로 자료구조에 개념적으로 저축해두고, 비싼 연산이 생기면 그 토큰으로 지불하는 방식.
- 물리학자 방법(physicist's method): 자료구조의 상태를 정수로 매핑하는 퍼텐셜 함수(potential function)를 정의하고, 그 변화량을 실제 비용에 더해 분할상환 비용을 계산하는 방식.
- 세 방법 모두 실제 코드나 자료구조를 바꾸지 않는다 — 순수하게 실행 시간을 분석하기 위한 기법일 뿐이며, 토큰이나 퍼텐셜이 실제로 자료구조에 저장되는 것은 아니다.

## 예시
- 상수량(10)씩 늘리는 경우의 비용 합 계산: `n + 10 × sum_{j=1}^{(n-1)/10} j`이며, 이 합은 O(((n-1)/10)²) = O(n²)에 해당하므로 전체는 `n + O(n²)`, 분할상환 비용은 이를 n으로 나눈 O(n)이다.

## 요약
- 동적 배열은 용량을 늘릴 때 반드시 일정한 상수 배율(예: 2배, 2.5배 등)로 늘려야 PushBack의 분할상환 비용이 O(1)로 유지된다. 매번 상수량만큼만 늘리면 분할상환 비용이 O(n)으로 나빠진다.
- 분할상환 분석에는 집계 방법, 뱅커 방법, 물리학자 방법 세 가지 접근이 있으며, 관점은 다르지만 모두 "연산 하나가 아니라 시퀀스 전체의 총 비용"을 바탕으로 평균적인 비용을 계산한다는 공통점을 가진다.
- 세 방법 모두 코드 자체를 바꾸지 않는 순수한 실행 시간 분석 기법이다.
