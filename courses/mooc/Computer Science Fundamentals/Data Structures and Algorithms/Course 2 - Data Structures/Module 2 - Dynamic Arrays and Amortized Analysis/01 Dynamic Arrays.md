# Dynamic Arrays

## 개요
- 정적 배열(static array)은 컴파일 시점(compile time)에 크기를 정해야 해서 크기를 미리 알 수 없는 경우에 대응하기 어렵다.
- 동적으로 할당된 배열(dynamically-allocated array)도 실행 시점(runtime)에 크기를 정할 수는 있지만, 일단 할당하면 그 뒤로는 크기가 고정된다.
- 동적 배열(dynamic array, resizable array)은 "간접 참조(indirection)"를 한 단계 추가해, 배열을 가리키는 포인터를 두고 필요할 때 더 큰 배열을 새로 할당해 옮겨감으로써 크기가 자유롭게 늘어나는 배열처럼 동작하게 만든 자료구조다.

## 내용

### 문제 상황과 해결 아이디어
- 예: 개수를 미리 알 수 없는 숫자들을 배열에 담아야 하는 경우, 배열을 얼마나 크게 잡아야 할지 알 수 없다.
- 해결책은 "간접 참조를 한 단계 더 추가"하는 것이다. 배열 자체를 직접 참조하는 대신, 동적으로 할당된 배열을 가리키는 포인터를 둔다. 원소가 너무 많아지면 더 큰 배열을 새로 할당하고, 기존 원소를 복사하고, 기존 배열을 없앤 뒤, 포인터를 새 배열로 갱신하면 된다.

### 동적 배열의 구성 요소와 API
- 내부 상태: arr(동적 할당된 실제 배열), capacity(그 배열의 크기), size(현재 사용 중인 원소 개수).
- Get(i): 인덱스 i의 원소를 반환 — O(1).
- Set(i, val): 인덱스 i의 원소를 val로 설정 — O(1).
- PushBack(val): 배열 끝에 새 원소를 추가.
- Remove(i): 인덱스 i의 원소를 제거하고 이후 원소들을 앞으로 당긴다.
- Size(): 현재 원소 개수를 반환.
- Get과 Set은 배열이라는 이름에 걸맞게 반드시 상수 시간(O(1))이어야 한다 — 이것이 임의 접근(random access)의 의미다.

### 리사이징(resizing) 동작
- capacity가 2, size가 0인 상태에서 시작한다고 하자.
- PushBack(a), PushBack(b)를 하면 size가 capacity와 같아져(2=2) 배열이 가득 찬다.
- 이 상태에서 다시 PushBack을 하면: 더 큰(예: 4칸) 새 배열을 할당하고, 기존 원소를 모두 복사한 뒤, 포인터를 새 배열로 갱신하고 기존 배열은 폐기한다. 그런 다음 새 원소를 추가한다.
- 이 과정을 반복하며 배열이 다시 가득 차면 또 한 번 더 큰 배열(예: 8칸)로 교체한다.

### 각 연산의 의사코드
- Get(i): i가 0 이상이고 size-1 이하 범위인지 확인 후, 범위 밖이면 에러, 범위 안이면 arr[i] 반환.
- Set(i, val): 마찬가지로 범위를 확인한 뒤 arr[i] = val.
- PushBack(val): size == capacity이면 capacity를 두 배로 하는 새 배열을 할당하고 기존 원소를 모두 복사한 뒤 기존 배열을 해제하고 포인터를 교체한다. 그런 다음(또는 애초에 자리가 있었다면 바로) arr[size] = val 후 size를 1 증가.
- Remove(i): 범위를 확인한 뒤, i 이후의 원소들을 한 칸씩 앞으로 당기고 size를 1 감소.
- Size(): size 값을 그대로 반환.

### 실제 언어에서의 사례
- C++의 `vector`가 동적 배열의 대표적인 예이며, 연산자 오버로딩을 통해 `[]`로 접근·수정할 수 있다.
- Java의 `ArrayList`, Python의 `list`도 동적 배열이다. Python에는 정적 배열이 따로 없고 모든 리스트가 동적이다.

## 예시
- 연산별 시간 복잡도: Get O(1), Set O(1), PushBack O(n)(최악의 경우, 대부분은 실제로 훨씬 저렴함 — 다음 강의의 분할상환 분석에서 자세히 다룸), Remove O(n)(뒤 원소들을 당겨야 하므로), Size O(1).
- 용량을 두 배(factor 2)로 늘리는 경우 낭비되는 공간은 최대 절반이다. 세 배로 늘리면 최대 3분의 2가 낭비될 수 있고, 1.5배로 늘리면 낭비가 더 적다.

## 요약
- 동적 배열(dynamic array)은 포인터 간접 참조를 이용해 필요할 때 더 큰 배열로 교체하며 크기를 늘려가는 자료구조로, Get/Set/PushBack/Remove/Size 연산을 제공한다.
- Get, Set, Size는 항상 O(1)이고, PushBack과 Remove는 대체로 저렴하지만 최악의 경우 O(n)(리사이징 또는 원소 이동)이다.
- 용량을 일정한 배수(예: 2배)로 늘리는 방식이 표준이며, 배수가 클수록 낭비되는 공간도 커진다.
- PushBack의 실제 평균적인 비용을 정확히 이해하려면 다음 강의에서 다룰 분할상환 분석(amortized analysis)의 집계 방법(aggregate method)이 필요하다.
