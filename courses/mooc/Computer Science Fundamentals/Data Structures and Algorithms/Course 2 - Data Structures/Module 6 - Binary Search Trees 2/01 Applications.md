# Applications

## 개요
- 이진 탐색 트리의 두 가지 응용을 다룬다. 하나는 순위 통계(order statistics) 계산이고, 다른 하나는 정렬된 리스트를 저장하는 용도로 트리를 사용해 구간 뒤집기(flip) 연산을 빠르게 처리하는 방법이다.

## 내용
### 순위 통계 문제(Order Statistics)
- 예: k번째로 큰 원소, 중앙값(median), 25번째 백분위수(percentile) 원소를 찾는 문제는 모두 순위 통계 문제의 사례다.
- `OrderStatistic(T, k)`: 트리 `T`의 루트와 정수 `k`를 받아, 트리에 저장된 원소 중 k번째로 작은 원소를 반환한다.
- 이 문제도 일종의 탐색 문제지만, 어느 서브트리를 봐야 할지 알려면 왼쪽 서브트리에 원소가 몇 개 있는지(size) 알아야 한다.

### Size 필드
- `N.Size`: 노드 `N`의 서브트리에 있는 원소 개수를 반환하는 새 필드.
- 성질: `N.Size = N.Left.Size + N.Right.Size + 1` (null 포인터의 size는 0).
- height와 마찬가지로 이 필드도 트리가 재배열될 때마다 다시 계산해 최신 상태로 유지해야 한다.
- 회전(rotation)을 수행하면 이동한 두 노드의 서브트리 크기만 바뀌므로, `RecomputeSize`로 그 두 노드만 다시 계산하면 된다. 이때 자식의 size를 먼저 계산한 뒤 부모의 size를 계산해야 한다(부모의 size가 자식의 size에 의존하므로).

### OrderStatistic 알고리즘
- `s = R.Left.Size`로 왼쪽 서브트리 크기를 구한다.
- `k == s + 1`이면 왼쪽에 정확히 s개의 더 작은 원소가 있다는 뜻이므로, 루트 `R`이 바로 (s+1)번째로 작은 원소다. `R`을 반환한다.
- `k < s + 1`이면 k번째로 작은 원소는 왼쪽 서브트리에 있으므로 `R.Left`에서 재귀적으로 `k`번째 원소를 구한다.
- `k > s + 1`이면 오른쪽 서브트리를 봐야 하는데, 이미 왼쪽에 s개, 루트에 1개(=s+1개)의 더 작은 원소가 있으므로 오른쪽 서브트리에서는 `k - s - 1`번째로 작은 원소를 구해야 한다.
- 실행 시간은 탐색하는 노드의 높이(height)에 비례하며, 사실상 이진 탐색과 같은 방식이지만 키 대신 size를 비교해 방향을 정한다는 점이 다르다.
- (생각해 볼 문제) 반대로 어떤 노드가 주어졌을 때 그보다 작은 노드가 몇 개인지 구하는 것도 비슷한 아이디어로 가능하다.

### 응용: 흑백 배열의 구간 뒤집기(Flip)
- 문제 설정: 흑/백으로 칠해진 정사각형들의 배열이 있고, `Flip(x)` 연산은 인덱스 x 이후의 모든 정사각형 색을 반전(흑↔백)시킨다.
- 필요한 연산: 크기 n의 배열 생성, m번째 정사각형의 색 조회, `Flip(x)`.
- 배열로 구현하면 flip마다 x 이후 모든 원소를 순회해야 해서 O(n)이 걸려 비효율적이다.

### 트리를 정렬된 리스트로 사용하기
- 지금까지는 트리에 저장된 키(key) 자체로 검색을 했지만, 트리 구조만으로도 "정렬된 순서"를 표현할 수 있다.
- 예: 강좌 로고 트리는 노드에 문자가 있지만 알파벳 순으로 정렬되어 있지 않다. 그러나 트리 구조상 가장 왼쪽 경로부터 차례로 읽으면 올바른 순서(algorithms라는 단어)가 나온다.
- 즉, 노드에 실제 키를 저장하지 않고도 트리의 구조 자체로 정렬된 리스트를 표현할 수 있다.

### Flip 문제의 트리 기반 해법
- 흑백 색을 배열이 아니라 트리(정렬된 리스트 형태)로 저장한다.
- 트리 두 개를 유지한다: 하나는 실제 색을 담은 트리, 다른 하나는 정반대 색(dual)을 담은 트리.
- `Flip(x)`를 수행할 때, 뒤집을 구간(마지막 몇 개)에 대해 이 dual 트리의 같은 구간은 이미 반대 색을 담고 있으므로, 두 트리에서 해당 구간을 서로 맞바꾸기(swap)만 하면 색이 반전된 효과를 낸다.
- 이 맞바꾸기는 이전에 배운 Split과 Merge 연산으로 구현할 수 있다.
- 구현
  - 초기화: `T1`은 모든 원소가 흰색, `T2`는 모든 원소가 검은색인 두 트리를 만든다.
  - m번째 원소 색 조회: `T1`에서 m번째 원소를 찾아 그 색을 반환한다.
  - `Flip(x)`: `T1`을 x 위치에서 분할(split)하고, `T2`도 x 위치에서 분할한다. 그런 다음 `T1`의 왼쪽 절반과 `T2`의 오른쪽 절반을 합치고(merge), `T2`의 왼쪽 절반과 `T1`의 오른쪽 절반을 합친다. 이렇게 하면 마지막 구간의 색이 실질적으로 반전된다.

## 예시
- 순위 통계 예시: 트리에서 노드 A, B, C, D, E 중 5번째로 작은 원소가 D인 경우를 들어 왼쪽부터 순서를 세는 방법을 보여준다.
- Flip 예시: [백, 백, 흑, 백] 배열에서 마지막 4칸을 뒤집으면 [흑, 흑, 백, 흑]이 된다.

## 요약
- Size 필드를 추가하면 순위 통계(k번째로 작은 원소 찾기)를 트리 높이에 비례하는 시간에 계산할 수 있다.
- 트리는 키로 검색하는 용도뿐 아니라, 구조 자체로 정렬된 리스트를 표현하는 용도로도 쓸 수 있다.
- 이 아이디어를 이용하면 흑백 배열의 구간 뒤집기(flip)를, 정방향·역방향(dual) 두 트리를 유지하며 Split/Merge로 O(log n)에 처리할 수 있다.
- 다음 강의(선택)에서는 이런 연산들을 구현하는 또 다른 방식을 다룬다.
