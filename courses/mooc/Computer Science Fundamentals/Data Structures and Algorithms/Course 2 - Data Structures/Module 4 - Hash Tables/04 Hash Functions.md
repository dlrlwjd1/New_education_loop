# Hash Functions

## 개요
- 해싱(hashing)의 기반이 되는 해시 함수(hash function)의 정의와 바람직한 성질(desirable property)을 소개한다.
- 전화번호부(phone book) 문제를 예로, 왜 해시 함수가 필요한지, 그리고 왜 완벽한 해시 함수는 불가능한지를 설명한다.

## 내용

### 동기: 전화번호부 문제
- 국제 전화번호처럼 긴 값을 0~999 같은 작은 정수로 인코딩(encode)할 수 있다면, 직접 주소 지정(direct addressing)을 그대로 쓸 수 있다.
- 단, 전화번호부 안의 서로 다른 전화번호들은 서로 다른 코드(0~999)를 가져야 한다.
- 이 조건은 연락처가 1000개 미만일 때만 성립한다. 보통 연락처는 10,000개 미만이므로 0~9999 범위면 충분할 수 있다.
- 문제는 "긴 국제 전화번호를 어떻게 작은 정수로 인코딩할 것인가"이며, 해시 함수가 그 답이다.

### 해시 함수의 정의
- 해시 함수(hash function)란 어떤 객체 집합 S를 0부터 m−1까지의 정수 집합으로 매핑하는 함수다(m은 0보다 큰 정수).
- 이때 m을 해시 함수의 카디널리티(cardinality)라고 하며, m은 해시 함수가 가질 수 있는 서로 다른 값의 개수다.

### 바람직한 성질과 그 불가능성
- 원하는 성질:
  1. 계산이 빨라야 한다(fast to compute).
  2. 서로 다른 객체는 서로 다른 값을 가져야 한다.
  3. 카디널리티 m이 작아야 한다(그러면 direct addressing을 O(m) 메모리로 사용할 수 있다).
- 그러나 이 세 조건을 동시에 만족하는 것은 일반적으로 불가능하다.
- 비둘기집 원리(pigeonhole principle)에 의해, 객체 집합 S의 크기가 m보다 크면 반드시 같은 값을 갖는 객체 쌍이 존재한다.
- 서로 다른 두 객체가 같은 해시 값을 갖는 상황을 충돌(collision)이라 한다.

### 현실적인 재정의
- 계산은 여전히 빨라야 한다.
- "서로 다른 값" 대신 "충돌 확률이 작아야 한다"로 완화한다.
- 카디널리티 m은 여전히 충분히 작아야 한다.
- 이 세 조건이 모두 만족되더라도, 확률은 낮지만 충돌이 여전히 발생할 수 있으므로, 크기 m인 배열에 그대로 direct addressing을 적용할 수는 없다(같은 칸에 서로 다른 전화번호의 이름을 둘 다 쓸 수 없기 때문).

## 요약
- 해시 함수(hash function): 객체 집합을 0 ~ m−1 정수(카디널리티 m)로 매핑하는 함수.
- 빠른 계산, 무충돌, 작은 m을 동시에 만족하는 해시 함수는 비둘기집 원리에 의해 불가능하다.
- 현실적인 목표는 "빠른 계산 + 낮은 충돌 확률 + 작은 m"이며, 그래도 발생하는 충돌을 처리하는 방법(다음 강의의 체이닝(chaining))이 필요하다.
