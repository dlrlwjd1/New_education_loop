# Analysing Service Access Logs

## 개요
- 이 강의 전체에서 계속 예시로 사용할 문제인 "웹 서비스 접속 로그 분석"을 소개한다.
- 목표: 서비스 거부 공격(Denial of Service, DoS)을 탐지하기 위해, 최근 한 시간 동안 각 IP 주소에서 몇 번 접속했는지를 빠르게 알아내는 것이다.

## 내용

### 문제 배경: IP 주소
- IP 주소(IP address)는 인터넷의 각 컴퓨터에 부여되는 고유 주소로, 점으로 구분된 4개의 정수(0~255)로 표현된다(IPv4).
- 각 정수는 8비트(1바이트)이므로 전체 IP 주소는 32비트로 저장되며, 가능한 주소 개수는 2^32(약 40억)개다.
- 인터넷 규모가 커지면서 2^32개로는 부족해져 IPv6가 등장했고, IPv6는 2^128개(39자리 숫자)의 주소를 지원한다. 이 강의에서는 여전히 널리 쓰이는 IPv4를 다룬다.

### 접속 로그(access log)와 요구사항
- 서비스에 접속하면 접속 시각과 IP 주소가 access log 파일에 기록된다.
- DoS 공격은 공격자가 한 컴퓨터에서 매우 많은 요청을 보내 서비스를 마비시키는 공격이다.
- 알아내고 싶은 것: 특정 IP가 지난 한 시간 동안 접속했는지, 몇 번 접속했는지, 지난 한 시간 동안 서로 다른 IP가 몇 개 사용되었는지.
- 로그는 수만~수백만 줄에 달할 수 있으므로, 매번 한 시간 치 로그 전체를 다시 훑는 방식은 너무 느리다.

### 카운터를 이용한 접근
- 각 IP 주소마다 "지난 한 시간 동안 몇 번 등장했는가"를 나타내는 카운터(counter)를 유지한다.
- 이 매핑(IP → 카운터)을 저장하는 자료구조를 C라고 하며, 아직 구현 방법은 정하지 않은 상태다.
- 매초 다음을 수행한다.
  - 새로 들어온 로그 줄(현재 시각 이하)에 대해 해당 IP의 카운터를 증가시킨다.
  - 한 시간이 지나 윈도우에서 빠져나간 오래된 로그 줄에 대해 해당 IP의 카운터를 감소시킨다.
- 인덱스 `i`는 아직 처리하지 않은 첫 로그 줄(새 줄 처리용), `j`는 현재 1시간 윈도우의 가장 오래된 줄(오래된 줄 처리용)을 가리킨다.

### 의사코드 구조
- 전역 변수: `log`(로그 배열), `C`(IP→카운터 매핑), `i`, `j`(각각 0으로 초기화), `C`는 빈 매핑으로 초기화.
- 매초 `UpdateAccessList(log, i, j, C)`를 호출한다.
- `UpdateAccessList` 내부는 두 부분으로 구성된다.
  1. **새 줄 처리**: `log[i]`의 시각이 현재 시각 이하인 동안, 해당 IP의 카운터를 증가시키고 `i`를 다음으로 이동.
  2. **오래된 줄 처리**: 현재 시각에서 3600초(1시간)를 뺀 시각보다 `log[j]`의 시각이 작거나 같은 동안, 해당 IP의 카운터를 감소시키고 `j`를 다음으로 이동.
- 특정 IP가 지난 한 시간 동안 사용되었는지는 해당 카운터가 0보다 큰지로 판단한다.

## 요약
- 접속 로그 분석 문제는 "IP → 카운터" 매핑 자료구조 C를 빠르게 갱신·조회하는 문제로 귀결된다.
- 슬라이딩 윈도우(sliding window) 방식으로 인덱스 `i`(신규), `j`(만료)를 이용해 초당 상수 시간에 가까운 갱신을 목표로 한다.
- 아직 C를 구체적으로 어떻게 구현할지는 다루지 않았으며, 이후 강의에서 다룬다.
