# Direct Addressing

## 개요
- 해싱(hashing)으로 가는 첫걸음인 직접 주소 지정(direct addressing)을 다룬다.
- 앞선 문제의 자료구조 C를, IP 주소를 정수로 변환한 뒤 그 정수를 배열의 인덱스로 바로 사용하는 방식으로 구현한다.
- 이 방식의 한계(메모리 낭비)를 통해 왜 해싱이 필요한지를 보여준다.

## 내용

### IP 주소 → 정수 변환
- IPv4 주소는 32비트 정수와 1대1 대응(one-to-one correspondence)된다.
- 크기 2^32인 배열 A(인덱스 0 ~ 2^32 − 1)를 만들면, 모든 IP 주소마다 배열의 고유한 위치가 하나씩 대응된다.
- 변환 방법: IP 주소를 이루는 4개의 정수(각 1바이트)를 이어 붙여 32비트 정수로 만든다.
  - 가장 낮은 8비트는 IP의 네 번째 숫자를 그대로 사용.
  - 세 번째 숫자는 2^8을 곱해 왼쪽으로 8비트 이동.
  - 두 번째 숫자는 2^16을 곱해 왼쪽으로 16비트 이동.
  - 첫 번째 숫자는 2^24를 곱해 왼쪽으로 24비트 이동.
  - 네 값을 모두 더하면 하나의 정수가 된다.
  - 예: `0.0.0.1` → 정수 `1` (최상위 바이트들이 모두 0이고 최하위 비트만 1).

### 배열 A를 이용한 UpdateAccessList 재작성
- 자료구조 C 대신 배열 A를 사용한다.
- IP를 정수로 변환한 뒤 `A[인덱스]`를 증가/감소시키기만 하면 되므로, 카운터 증가·감소는 매우 단순해진다.
- 각 IP는 서로 다른 고유한 정수로 매핑되므로, 서로 다른 IP끼리 카운터가 충돌(다른 IP의 카운터를 잘못 건드리는 일)하는 일이 없다.
- `AccessedLastHour(IP)`도 해당 인덱스의 카운터가 0보다 큰지만 확인하면 된다.

### 시간·공간 복잡도
- `UpdateAccessList`: 로그 한 줄당 상수 시간(constant time) — 배열의 한 위치를 찾아 증가/감소시키는 것뿐이므로 더 빠르게 만들 수 없는 수준이다.
- `AccessedLastHour`: 배열의 한 위치를 읽어 0과 비교하는 것뿐이므로 역시 상수 시간이다.
- 단점: 실제로 접속한 IP가 밤에 5개, 10개, 100개뿐이더라도, 항상 2^32개의 메모리 셀이 필요하다.
- 일반화하면, 직접 주소 지정 방식은 O(N) 메모리가 필요하다. 여기서 N은 유니버스(universe, 저장할 수 있는 모든 가능한 객체 집합)의 크기다. 어떤 객체가 한 번도 저장되지 않더라도 그 객체를 위한 자리는 미리 마련해 두어야 한다.
- IPv6처럼 유니버스 크기가 2^128인 경우, 이 정도 크기의 배열은 컴퓨터 메모리에 들어가지 않는다. 즉, 유니버스가 매우 크거나(문자열, 파일 등) 무한한 경우 직접 주소 지정은 사용할 수 없다.

## 예시
- IP `0.0.0.1` → 정수 `1`.
- 그림 속 예시 IP → 정수 `2886794753`.
- 퀴즈로 제시된 다른 IP → 정수 `1168893508`.

## 요약
- 직접 주소 지정(direct addressing): 객체(IP)를 정수로 1대1 매핑한 뒤, 그 정수를 배열 인덱스로 직접 사용해 O(1) 시간에 접근하는 방식.
- 장점: 매우 빠르고(상수 시간) 충돌이 전혀 없다.
- 단점: 유니버스 크기 N만큼의 메모리가 항상 필요해(O(N)), 유니버스가 크거나 무한하면 사용할 수 없다.
- 다음 강의부터 더 큰(또는 무한한) 유니버스에서 동작하는 방법, 즉 해시 함수(hash function)를 다룬다.
