# Rabin-Karp's Algorithm

## 개요
- 해싱을 이용해 부분 문자열 검색(substring search) 문제를 나이브 알고리즘보다 빠르게 푸는 Rabin-Karp's 알고리즘의 기본 아이디어와 초기(비최적화) 구현을 소개하고, 그 실행 시간을 분석한다.

## 내용

### 핵심 아이디어
- 패턴 P와 텍스트 T의 모든 부분 문자열 S(길이 |P|)를 직접 비교하는 대신, 먼저 해시(hash) 값을 비교해서 비교 속도를 높인다.
- 해시 함수 h를 하나 고른다고 하자. hash(P) ≠ hash(S)이면 P ≠ S가 확실하다.
- 반대로 해시 값이 같다면, 그때만 `AreEqual` 함수를 호출해 실제로 P = S인지 확인한다.
- 다항식 해시 함수족(polynomial hash family) P_p(작은 p, 즉 소수 하나를 고정)를 사용한다. P ≠ S일 때 충돌(collision) 확률은 최대 |P|/p이며, p를 아주 크게 고르면 이 확률을 매우 작게 만들 수 있다.
- 즉, 문자열 자체를 직접 비교하는 것은 두 문자열이 실제로 같거나(진짜 일치), 혹은 드물게 충돌이 일어났을 때만 필요하다.

### 초기 구현(최적화 이전)
1. 아주 큰 소수 p와 1 ~ p−1 사이의 무작위 정수 x를 고른다(다항식 해시 함수족에서 무작위로 함수를 고르는 것).
2. 결과 위치 리스트를 빈 리스트로 초기화한다.
3. 패턴 P의 해시 값을 `PolyHash`로 한 번만 계산해 둔다(패턴은 변하지 않으므로).
4. 텍스트의 가능한 모든 부분 문자열 위치 i에 대해:
   - 해당 부분 문자열 T[i..i+|P|−1]의 해시 값을 `PolyHash`로 계산한다.
   - 두 해시 값이 다르면 P ≠ 해당 부분 문자열이 확실하므로 다음 위치로 넘어간다.
   - 두 해시 값이 같으면 `AreEqual`로 실제 문자열이 같은지 확인하고, 같다면 위치 i를 결과 리스트에 추가한다.
5. 결과 리스트를 반환한다.

### 거짓 경보(false alarm)
- 거짓 경보란 P와 부분 문자열 S를 비교했는데(즉 해시 값은 같았는데) 실제로는 P ≠ S인 경우를 말한다.
- 거짓 경보가 일어날 확률은 충돌 확률과 같으며, 최대 |P|/p다.
- 평균 거짓 경보 횟수는 (|T| − |P| + 1) × (|P|/p) 정도이며, p를 |T| × |P|보다 훨씬 크게 잡으면(예를 들어 p ≈ 10¹⁸ 정도로도 상수 시간에 계산 가능) 이 값을 매우 작게 만들 수 있다.

### 실행 시간 분석
- `AreEqual`을 제외한 부분:
  - 패턴의 해시는 O(|P|)에 한 번 계산한다.
  - 각 위치의 부분 문자열 해시는 매번 O(|P|)가 걸리고, 이를 |T| − |P| + 1번 반복하므로 전체는 O(|T| × |P|)다.
  - 즉 이 부분만 보면 나이브 알고리즘과 같은 O(|T| × |P|)로, 아직 개선되지 않았다. (다음 강의에서 이 부분을 최적화한다.)
- `AreEqual` 호출에 걸리는 시간:
  - `AreEqual`은 호출될 때마다 O(|P|)가 걸리지만, 해시가 일치할 때만(진짜 일치이거나 거짓 경보일 때만) 호출된다.
  - 패턴이 텍스트에서 실제로 q번 나타난다면, `AreEqual`에 들어가는 총 시간은 평균적으로 O((q + 거짓 경보 수) × |P|)이며, p가 |T| × |P|보다 충분히 크면 거짓 경보 수는 무시할 만하므로 평균 O(q × |P|)가 된다.
- 전체 평균 실행 시간: O(|T| × |P| + q × |P|) = O(|T| × |P|)(q ≤ |T|이므로). 즉 이 초기 구현의 실행 시간은 나이브 알고리즘과 같은 수준이며, q × |P| 항목(둘째 항)은 실제 발생 횟수만큼 반드시 필요한(피할 수 없는) 비용이지만, 첫째 항 O(|T| × |P|)는 부분 문자열 해시를 매번 따로 계산하기 때문에 생기는 비용으로 크게 최적화할 수 있다.
- 실전에서는 패턴이 텍스트에 등장하는 횟수 q가 대체로 작다(유전체에서 유전자는 1~3회, 위키백과 문서에서 단어는 10~100회 정도). 따라서 q × |P| 항은 보통 작지만, 첫째 항이 여전히 병목이므로 다음 강의에서 이를 개선한다.

## 예시
- 초기 구현의 실행 시간 O(|T| × |P| + q × |P|)에서, q ≤ |T|이므로 이는 O(|T| × |P|)로 정리된다.

## 요약
- Rabin-Karp's 알고리즘은 해시 값을 먼저 비교하고, 값이 같을 때만 `AreEqual`로 실제 비교를 수행해 불필요한 비교를 줄이는 아이디어다.
- 초기(비최적화) 구현의 평균 실행 시간은 여전히 O(|T| × |P|)로, 나이브 알고리즘과 다르지 않다. 이는 부분 문자열마다 해시를 처음부터 다시 계산하기 때문이다.
- `AreEqual`에 들어가는 시간 O(q × |P|)(q는 실제 등장 횟수)는 원리적으로 피할 수 없는 비용이다.
- 다음 강의에서 부분 문자열들의 해시 값 사이의 점화식(recurrence)을 이용해 첫째 항을 O(|T| + |P|)로 줄이는 방법을 다룬다.
