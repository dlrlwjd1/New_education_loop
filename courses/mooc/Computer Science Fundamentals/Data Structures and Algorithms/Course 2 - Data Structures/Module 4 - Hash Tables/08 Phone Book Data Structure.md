# Phone Book Data Structure

## 개요
- 앞서 미뤄두었던 핵심 질문 "좋은 해시 함수를 어떻게 만들 것인가"를 본격적으로 다룬다.
- 전화번호부(phone book) 문제를 "이름 추가/삭제, 이름으로 전화 걸기, 전화번호로 발신자 확인"까지 포함한 완전한 문제로 확장하고, 좋은 해시 함수의 조건과 그 조건을 만족하는 함수를 찾는 것이 왜 근본적으로 불가능한지를 증명한다.

## 내용

### 확장된 전화번호부 문제
- 필요한 기능: 연락처 추가/삭제, 이름만으로 전화 걸기, 전화번호만으로 발신자 이름 확인 — 모두 빨라야 한다.
- 이를 위해 두 개의 맵(map)이 필요하다: 전화번호 → 이름, 이름 → 전화번호. 둘 다 효율적이고 메모리도 적게 써야 한다.
- 두 맵 모두 해시 테이블(hash table)로 구현할 수 있으며, 먼저 "전화번호 → 이름" 맵에 집중한다.

### 파라미터 복습
- n: 저장할 연락처 수, m: 해시 함수의 카디널리티(=해시 테이블 크기), c: 가장 긴 체인(chain)의 길이.
- 메모리 사용량은 Θ(n + m), 연산 시간은 Θ(c + 1)이다.
- 비둘기집 원리(pigeonhole principle)에 의해 항상 c ≥ n/m이 성립하므로, m과 c를 마음대로 동시에 작게 만들 수는 없다.

### 좋은 예 / 나쁜 예
- 좋은 예: 카디널리티 8, 객체 8개일 때 가장 긴 체인 길이가 2인 경우(이상적으로는 1이 최선이지만 2도 괜찮은 경우로 제시됨).
- 나쁜 예: 카디널리티 8, 객체 8개인데 가장 긴 체인 길이가 8인 경우 — 이는 일반적으로 n개 객체에 대해 가장 긴 체인이 n이 되는 최악의 경우이며, 이때 연산 시간이 Θ(n)까지 늘어나 체이닝을 쓰지 않고 단순 리스트를 쓰는 것과 다를 바 없어진다.

### 여러 해시 함수 시도와 실패
- **첫 세 자리 사용**(m=1000): 지역 번호(area code)가 전화번호 앞자리에 오는 경우가 많아, 같은 지역 번호의 번호들이 모두 같은 해시 값을 가져 긴 체인이 생긴다.
- **마지막 세 자리 사용**(m=1000): 많은 전화번호가 000처럼 같은 끝자리로 끝나는 경우가 있어 역시 충돌이 많이 생길 수 있다.
- **완전한 난수(random number) 반환**(0~999): 키들을 거의 균등하게 분포시키므로 이상적으로 보이지만, 결정적(deterministic)이지 않아 저장할 때와 조회할 때 서로 다른 값을 반환하게 되어 저장한 것을 다시 찾을 수 없다. 즉 사용할 수 없다.
- 결론: 좋은 해시 함수는 **결정적(deterministic)**이어야 하고, **계산이 빨라야** 하며, 키를 **여러 셀에 고르게 분산**시켜(=충돌이 적어야) 한다.

### 보편적 해시 함수의 부재 증명
- **정리(Lemma)**: 가능한 키의 개수가 매우 크고 해시 함수의 카디널리티 m보다 훨씬 크다면, 그 어떤 카디널리티 m의 해시 함수에도 충돌이 많이 발생하는 나쁜 입력(bad input)이 존재한다.
- 증명 아이디어: 가능한 모든 키의 집합 S를 해시 값에 따라 m개의 그룹으로 나눈다(카디널리티 m=3 예시로 설명). 이 중 가장 큰 그룹을 고르면, 그 그룹은 전체 키의 1/m 이상을 차지한다(예: m=3인 경우 한 그룹이 42%를 차지하는 예시 제시).
- 만약 저장해야 할 키들이 하필 이 가장 큰 그룹에서 나온다면, 그 키들은 모두 같은 셀로 몰려 가장 긴 체인의 길이가 저장할 키 개수와 같아진다. 이 그룹의 크기는 "전체 가능한 키 집합 크기 / m" 이상이므로 매우 클 수 있다.
- 따라서 카디널리티 m인 임의의 해시 함수에 대해, 전체 키 집합 크기가 m보다 훨씬 크면 항상 나쁜 입력이 존재하며, 모든 경우에 잘 동작하는 보편적인(universal) 해시 함수는 존재하지 않는다.

## 요약
- 체이닝의 성능은 m(카디널리티)과 c(최장 체인 길이) 모두를 작게 유지해야 좋아지지만, 비둘기집 원리로 인해 c ≥ n/m이라는 근본적 제약이 있다.
- 좋은 해시 함수의 조건: 결정적(deterministic), 계산이 빠름, 키를 고르게 분산(충돌 최소화).
- 그러나 가능한 키 집합이 카디널리티보다 훨씬 크면, 어떤 고정된 해시 함수에도 충돌이 몰리는 나쁜 입력이 항상 존재한다(보편적 해시 함수는 존재하지 않는다).
