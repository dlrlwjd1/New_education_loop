# Improving Running Time

## 개요
- 앞선 강의에서 유도한 점화식(recurrence)을 이용해 텍스트의 모든 부분 문자열 해시를 미리 계산(precomputation)하고, 이를 바탕으로 Rabin-Karp's 알고리즘의 실행 시간을 O(|T| × |P|)에서 O(|T| + |P|)로 크게 개선한다.
- 이 강의로 해싱(hashing) 관련 핵심 내용이 마무리되고, 다음은 선택적으로 블록체인(blockchain)을 다룬다.

## 내용

### PrecomputeHashes 절차
- `PrecomputeHashes(T, |P|, p, x)`는 텍스트 T, 패턴 길이 |P|, 소수 p, 다항식 해시 함수족 파라미터 x를 입력받아, T의 모든 길이-|P| 부분 문자열의 해시 값을 담은 배열 H를 반환한다(패턴 P 자체는 필요 없다).
1. 배열 H의 크기를 |T| − |P| + 1로 초기화한다(이것이 텍스트 안에서 길이가 |P|인 부분 문자열의 개수다).
2. 텍스트의 마지막 부분 문자열 S(가장 뒤쪽 길이-|P| 구간)를 `PolyHash`로 직접 계산해 H의 마지막 원소로 저장한다. 이 계산은 O(|P|)다.
3. y = x^|P| mod p를 계산한다. y = 1로 시작해서 |P|번 반복하며 매번 y ← y·x mod p로 갱신한다. 이 루프는 O(|P|)다.
4. 마지막 for 루프에서, 앞서 유도한 점화식 H(i) = x·H(i+1) + T[i] − T[i+|P|]·y (mod p)를 이용해 뒤에서부터 앞으로 H의 나머지 값들을 채운다. 이 계산은 각 단계가 O(1)이며, |T| − |P|번 반복하므로 전체 O(|T| − |P|)다.
5. 배열 H를 반환한다.
- 전체 사전 계산(precomputation) 시간: O(|P|)(첫 부분 문자열 해시) + O(|P|)(x^|P| 계산) + O(|T| − |P|)(나머지 해시들) = **O(|T| + |P|)**.
- 이는 이전에 부분 문자열마다 해시를 따로 계산했을 때 걸리던 O(|T| × |P|)보다 훨씬 빠르다(곱셈이 아니라 덧셈 관계).

### 개선된 Rabin-Karp's 알고리즘
- 입력: 텍스트 T, 패턴 P만 있으면 된다(큰 소수 p와 무작위 정수 x는 알고리즘 내부에서 생성).
1. 큰 소수 p를 생성하고, 1 ~ p−1 사이의 무작위 정수 x를 고른다.
2. 결과 위치 리스트를 빈 리스트로 초기화한다.
3. 패턴 P의 해시를 `PolyHash`로 한 번 계산한다 — O(|P|).
4. `PrecomputeHashes`로 텍스트의 모든 부분 문자열 해시 배열 H를 미리 계산한다 — O(|T| + |P|).
5. 각 위치 i에 대해, 미리 계산해 둔 H[i]와 패턴의 해시를 비교한다.
   - 값이 다르면 해당 위치를 건너뛴다.
   - 값이 같으면 `AreEqual`로 실제 문자열이 같은지 확인하고, 같으면 i를 결과 리스트에 추가한다.
6. 결과 리스트를 반환한다.
- 이전 버전과의 유일한 차이는, 매번 부분 문자열 해시를 새로 계산하는 대신 미리 계산해 둔 H[i]를 그대로 사용한다는 점이다.

### 전체 실행 시간
- 패턴 해시 계산: O(|P|).
- 사전 계산(`PrecomputeHashes`): O(|T| + |P|).
- `AreEqual` 호출에 드는 평균 시간: 큰 소수 p에서는 여전히 O(q × |P|)(q는 패턴의 실제 등장 횟수).
- 전체 평균 실행 시간: **O(|T| + (q + 1) × |P|)** — 패턴이 한 번도 등장하지 않아도(q = 0) 최소한 해시 계산은 해야 하므로 (q+1)로 표기한다.
- q가 작은 경우가 대부분이므로(예: 유전체에서 유전자, 위키백과에서 단어), 이 실행 시간은 나이브 알고리즘의 O(|T| × |P|)보다 훨씬 빠르다.
- 예: |T|가 수십억(유전체), |P|가 수백만(유전자) 수준이면, Rabin-Karp's는 대략 10⁹ 수준의 연산이 필요한 반면, 나이브 알고리즘은 대략 10¹⁵ 수준으로 100만 배 느리다.

### 해싱 파트 마무리
- 해시 테이블(hash table)은 집합(set)과 맵(map)을 저장하는 데 유용하며, 좋은 해시 함수족(hash family)과 무작위성(randomization)을 이용하면 평균적으로 상수 시간(O(1))에 탐색·수정이 가능하다.
- 해싱은 문자열/텍스트를 빠르게 비교하는 데도 유용하며, 이 밖에도 블록체인(blockchain) 등 다양한 응용이 있다.

## 예시
- 실행 시간 비교(|T| ≈ 10⁹, |P| ≈ 10⁶ 가정 시):
  - Rabin-Karp's(개선판): 약 10⁹ 수준의 연산.
  - 나이브 알고리즘: 약 10⁹ × 10⁶ = 10¹⁵ 수준의 연산(약 100만 배 느림).

## 요약
- 점화식을 이용해 텍스트의 모든 부분 문자열 해시를 O(|T| + |P|)에 미리 계산할 수 있다(`PrecomputeHashes`).
- 이를 적용한 개선된 Rabin-Karp's 알고리즘의 평균 실행 시간은 O(|T| + (q+1) × |P|)로, 실전에서 q가 작을 때 나이브 알고리즘보다 훨씬 빠르다.
- 해시 테이블은 평균 O(1) 탐색·수정과 선형 메모리를 제공하며, 문자열 비교나 부분 문자열 검색 등 다양한 문제에 응용할 수 있다.
- 다음 선택 강의들에서는 해싱이 블록체인(blockchain)에서 어떻게 쓰이는지를 다룬다.
