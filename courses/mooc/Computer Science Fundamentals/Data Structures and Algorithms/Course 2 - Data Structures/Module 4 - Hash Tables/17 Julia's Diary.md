# Julia's Diary

## 개요
- 블록체인(blockchain)의 아이디어를 밑바닥부터 직관적으로 이해하기 위해 "줄리아의 일기(Julia's Diary)"라는 이야기를 통해 설명을 시작한다.
- 일기를 위조(forge)하기 어렵게 만들기 위해 각 줄에 해시 값(hash value)을 덧붙이는 아이디어를 소개한다.

## 내용

### 이야기의 발단
- 줄리아는 매일 있었던 일을 일기에 순서대로 기록한다(예: 239번째 줄 "다니엘에게 100달러를 빌려줬다", 240번째 줄 "하우스 오브 카드를 봤다").
- 나중에 누군가와 무엇을 했는지에 대해 다툼이 생기면, 일기의 해당 기록을 보여줌으로써 논쟁을 해결했다.
- 어느 날 줄리아와 다니엘 사이에 100달러를 빌려줬는지 여부로 다툼이 생겼다. 줄리아는 일기를 다음 날 보여주기로 했는데, 그날 밤 다니엘이 100달러를 갚기 싫어 줄리아의 방에 몰래 들어가 239번째 줄("다니엘에게 100달러를 빌려줬다")을 "왕좌의 게임을 봤다"로 위조(forge)했다.
- 다음 날 줄리아는 일기에서 그런 기록을 찾지 못해 다니엘에게 사과하고 넘어갔다.
- 10년 뒤 다니엘은 양심의 가책을 느껴 사실을 고백했고, 이 사건을 계기로 줄리아는 일기를 위조하기 더 어렵게 만들 방법을 고민하게 된다.

### 해시 함수를 이용한 보강 아이디어
- 줄리아는 다항식 해시 함수족(polynomial hash family)처럼 임의의 문자열을 정수로 요약(digest)할 수 있는 해시 함수를 알게 된다.
- MD5 같은 일부 해시 함수는 "충돌이 존재하긴 하지만, 의도적으로 같은 해시 값을 갖는 다른 문자열을 찾아내는 것이 극도로 어렵다"는 유용한 성질을 가진다. 이 성질이 일기의 무결성(integrity)을 지키는 데 중요하다.
- 줄리아는 일기에 새로운 열(column)을 추가해 각 줄의 해시 값을 함께 기록하기로 한다. i+1번째 줄의 해시 값은 다음 두 가지를 합쳐 만든다.
  1. 그 줄 자체 기록 내용의 해시 값.
  2. 바로 이전 줄의 해시 값.
- 두 값을 이어 붙인(concatenate) 문자열을 다시 해시해서 최종 해시 값을 얻는다. 이렇게 하면 각 줄의 해시 값에는 그 줄의 내용뿐 아니라 그 이전 모든 줄에 대한 정보가 누적되어 담기게 된다.
- 결과적으로 중간의 한 기록이라도 바꾸면, 그 뒤에 이어지는 모든 줄의 해시 값을 전부 다시 계산해서 바꿔야 앞뒤가 맞으므로 위조가 훨씬 어려워진다.

### 계산 절차와 예시
- 특수한 0번째 줄(빈 기록)을 가정하고, 그 해시 값을 0000으로 둔다.
- 1번째 줄 "아침을 먹었다"의 내용 해시가 364라고 하면, 이를 이전 줄의 해시 0000과 이어붙여 "3640000"을 만들고, 이를 다시 해시해 2308을 얻는다. 이것이 1번째 줄의 해시 값이다.
- 2번째 줄 "산책을 나갔다"의 내용 해시가 1782라고 하면, 이전 줄의 해시 2308과 이어붙여 "17822308"을 만들고, 다시 해시해 204를 얻는다. 이것이 2번째 줄의 해시 값이다.
- 이 과정은 첫 줄부터 끝 줄까지 어느 기존 일기에 대해서도 계산할 수 있고, 새 줄을 추가할 때는 그 줄의 내용 해시와 직전 줄의 해시를 이어붙여 다시 해시하기만 하면 되므로 계산 자체는 매우 빠르다(간단한 프로그램으로 즉시 처리 가능).
- 이렇게 하면 특정 기록 하나를 위조하려면 그 뒤에 오는 모든 줄의 해시 값도 함께 고쳐야 하므로, 위조가 훨씬 어려워진다. 친구 사이의 소액 대여 정도를 지키기에는 이 정도로도 충분히 좋은 보호가 된다(위조자가 여러 줄을 고쳐야 함을 깨닫지 못하거나, 깨닫더라도 그만큼 시간이 오래 걸리기 때문).

## 예시
- 0번째 줄(특수): 해시 값 0000.
- 1번째 줄 "아침을 먹었다": 내용 해시 364 → "364" + "0000" = "3640000" → 해시("3640000") = 2308.
- 2번째 줄 "산책을 나갔다": 내용 해시 1782 → "1782" + "2308" = "17822308" → 해시("17822308") = 204.

## 요약
- 줄리아는 일기 위조를 겪은 뒤, 각 줄에 "그 줄 내용의 해시"와 "직전 줄 해시"를 이어붙여 다시 해시한 값을 기록하는 방식을 고안했다.
- 이 구조 덕분에 한 줄을 위조하려면 그 뒤의 모든 줄의 해시 값을 연쇄적으로 다시 계산해 고쳐야 하므로 위조가 훨씬 어려워진다.
- 이는 MD5처럼 "의도적으로 같은 해시 값을 갖는 다른 입력을 찾기 어렵다"는 성질을 가진 해시 함수를 전제로 한다.
- 다음 강의에서는 줄리아가 이 방식을 은행 업무(대출 기록)로 확장했을 때 벌어진 일을 다룬다.
