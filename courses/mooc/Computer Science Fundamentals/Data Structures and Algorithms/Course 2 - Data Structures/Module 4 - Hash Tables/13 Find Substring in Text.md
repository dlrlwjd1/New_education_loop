# Find Substring in Text

## 개요
- 해싱을 완전히 다른 문제인 부분 문자열 검색(substring search)에 적용하는 첫 강의로, 문제를 정의하고 나이브 알고리즘(naive algorithm)을 제시한 뒤 그 한계를 분석한다.

## 내용

### 문제 정의
- 표기법: 문자열 S에서 위치 i부터 j까지(양 끝 포함)의 부분 문자열을 S[i..j]로 표기한다.
  - 예: S = "hashing"이면 S[0..3] = "hash", S[4..6] = "ing", S[2..5] = "shin". 인덱스는 0부터 시작한다.
- 입력: 텍스트 T(긴 문자열)와 패턴 P(짧은 문자열).
- 출력: 0 ≤ i ≤ |T| − |P|를 만족하는 모든 위치 i 중에서, T[i .. i+|P|−1] = P인 모든 i(패턴이 나타나는 시작 위치들).
- 실제 응용 예: 브라우저에서 긴 위키백과 문서 안의 특정 단어 찾기, 생물학자가 유전체(genome)에서 유전자(gene) 위치 찾기, 바이러스 특유의 코드 패턴으로 감염된 파일 탐지하기 등.

### 나이브 알고리즘(Naive algorithm)
- 아이디어: 가능한 모든 시작 위치 i(0 ~ |T|−|P|)에 대해 T[i..i+|P|−1]이 P와 같은지 하나씩 확인한다.
- 보조 함수 `AreEqual(문자열1, 문자열2)`:
  1. 두 문자열의 길이가 다르면 즉시 false를 반환한다.
  2. 길이가 같으면 인덱스 i = 0부터 (길이−1)까지 순회하며 대응하는 문자가 하나라도 다르면 false를 반환한다.
  3. 끝까지 다른 문자를 찾지 못했으면 true를 반환한다.
- 메인 절차 `FindSubstringNaive(T, P)`:
  1. 결과 위치 리스트를 빈 리스트로 초기화한다.
  2. i = 0부터 |T| − |P|까지(패턴이 텍스트 안에 완전히 들어갈 수 있는 마지막 위치까지) 순회한다.
  3. T[i .. i+|P|−1]과 P가 `AreEqual`로 같다고 판정되면 i를 결과 리스트에 추가한다.
  4. 결과 리스트를 반환한다.

### 실행 시간 분석
- `AreEqual` 한 번의 호출은 두 문자열(길이 |P|)을 한 번씩만 비교하므로 O(|P|)이다.
- 시작 위치 i는 |T| − |P| + 1가지가 있고, 각 위치마다 최악의 경우 `AreEqual`이 |P|번 전체를 다 비교해야 할 수 있다.
- 따라서 전체 실행 시간은 O((|T| − |P| + 1) × |P|) = O(|T| × |P|)이다(|T|가 |P|보다 훨씬 크다고 가정).
- 이 상한이 실제로 타이트(tight)한지 확인하기 위한 최악의 예: 텍스트 T가 문자 'a'만 100만 개 있는 문자열이고, 패턴 P가 'a'가 999개 연속된 뒤 마지막에 'b'가 하나 오는 문자열(길이 1000)인 경우.
  - 각 위치 i(0 ~ 약 999,000)에서 `AreEqual`은 마지막 문자에서야 불일치를 발견하므로 매번 1000번 전체 비교를 수행해야 한다.
  - 결과적으로 이 경우 나이브 알고리즘은 Θ(|T| × |P|) 시간이 걸리며, 이는 실제로 나쁜 경우다.
  - T가 유전체(수십억 길이), P가 유전자(수백만 길이)라면 이 곱은 매우 커져서 사실상 실행이 끝나지 않을 수준이 된다.

## 예시
- T = "hashing"일 때: S[0..3] = "hash", S[4..6] = "ing", S[2..5] = "shin".
- 최악의 경우 예: T = "aaa...a"(100만 개의 a), P = "aaa...ab"(999개의 a 다음 b, 길이 1000).
  - 이 경우 나이브 알고리즘은 Θ(|T| × |P|) 시간이 걸린다.

## 요약
- 부분 문자열 검색 문제는 텍스트 T 안에서 패턴 P가 나타나는 모든 시작 위치를 찾는 문제다.
- 나이브 알고리즘은 모든 가능한 시작 위치에서 `AreEqual`로 직접 비교하며, 실행 시간은 O(|T| × |P|)이고 특정 입력(반복 문자 텍스트 + 마지막만 다른 패턴)에서는 이 상한이 실제로 달성된다(타이트하다).
- 텍스트와 패턴이 매우 길 경우(예: 유전체 검색) 이 실행 시간은 비현실적으로 느리므로, 더 빠른 알고리즘이 필요하다.
- 다음 강의부터 해싱을 이용해 이 문제를 훨씬 빠르게 푸는 방법(Rabin-Karp's algorithm)을 다룬다.
