# Analysis of Polynomial Hashing

## 개요
- 앞선 강의에서 소개한 다항식 해시 함수족(polynomial hash family)이 왜 문자열에 대해 좋은 해시 함수족인지, 그리고 왜 Java의 `hashCode()`가 이 방식으로 구현되었는지를 증명을 통해 분석한다.
- 카디널리티(cardinality)가 고정되지 않은 다항식 해시 함수족을, 원하는 테이블 크기 m에 맞게 변환하는 방법도 다룬다.

## 내용

### 다항식 해시 함수족의 충돌 확률 (보조정리 1)
- **보조정리(Lemma)**: 길이가 최대 L+1인 서로 다른 두 문자열 s₁, s₂에 대해, 다항식 해시 함수족 P에서 무작위로 x(1 ~ p−1)를 골라 해시 함수를 정하면, 두 문자열이 충돌할 확률은 최대 L/p다.
- 증명의 핵심 사실: 임의의 소수 p에 대해, 차수(degree)가 최대 L인 다항식 방정식 a₀ + a₁x + a₂x² + ... + a_L x^L ≡ 0 (mod p)은 0 ~ p−1 범위의 나머지 x에 대해 최대 L개의 서로 다른 해(solution)를 가진다.
- 서로 다른 두 문자열 s₁, s₂의 해시 값은 각각 차수가 최대 L인 x의 다항식이므로, 두 해시 값의 차이도 차수가 최대 L인 다항식이다. 충돌이 일어나려면 이 차이가 mod p로 0이 되어야 하는데, 이런 x는 최대 L개뿐이다.
- x는 1 ~ p−1 사이에서 무작위로 고르므로, 이 조건을 만족하는 x를 뽑을 확률은 최대 L/p다.
- 따라서 p를 충분히 크게 잡으면 충돌 확률 L/p를 원하는 만큼 작게 만들 수 있다.

### 카디널리티를 원하는 크기 m으로 맞추기
- 문제: 다항식 해시 함수족의 카디널리티는 소수 p이므로, 그대로 쓰면 해시 테이블 크기도 p로 맞춰야 해서 메모리가 낭비된다. 테이블 크기는 저장할 키의 개수에 맞춰 정하고 싶다.
- 해결책: 다항식 해시 함수 위에 정수용 보편적 해시 함수족(universal family for integers)을 한 번 더 적용해 카디널리티를 m으로 줄인다.
  1. 먼저 다항식 해시 함수족에서 무작위로 x(1 ~ p−1)를 골라 h_x를 만들고, 문자열을 0 ~ p−1 사이의 정수로 변환한다. 이 계산은 문자열 길이에 비례하는 시간이 걸린다.
  2. p가 소수이므로 0 ~ p−1 정수에 대한 보편적 해시 함수족이 존재한다. 여기서 파라미터 a(1 ~ p−1), b(0 ~ p−1)를 무작위로 골라 h_{a,b}를 만든다. 이 계산은 상수 시간이다.
  3. 두 단계를 합성한 최종 함수 h_m은 카디널리티 m을 가진다.

### 합성 해시 함수의 충돌 확률 (보조정리 2)
- **보조정리(Lemma)**: 길이가 최대 L+1인 서로 다른 두 문자열 s₁, s₂와 임의의 카디널리티 m에 대해, 위와 같이 만든 h_m을 사용할 때 충돌 확률은 최대 1/m + L/p다.
- 근거: 충돌이 일어나려면 (a) h_x 단계에서 이미 충돌이 일어나거나(확률 최대 L/p), 또는 (b) h_x 단계에서는 값이 다르지만 그 다음 보편적 해시 함수족 h_{a,b} 단계에서 충돌이 일어나야 한다(확률 최대 1/m). 둘 중 하나만 일어나도 충돌이므로, 전체 확률은 각 확률의 합을 넘지 않는다: 1/m + L/p.

### 따름정리: p가 충분히 클 때
- **따름정리(Corollary)**: p > m·L이면, 충돌 확률은 O(1/m)이다.
- 증명: p > m·L이면 L/p < L/(m·L) = 1/m이므로, 1/m + L/p < 1/m + 1/m = 2/m = O(1/m)이다.
- 결과적으로, p를 m·L보다 큰 소수로 고르면 해시 테이블의 가장 긴 체인(chain)의 길이는 O(1 + n/m) = O(1 + α)가 되며(α는 부하율(load factor)), 이는 정수 해싱에서 얻었던 것과 동일한 좋은 성능이다.

### 전화번호부 문제의 완성
- 이름의 길이가 상수 L로 제한되어 있다면, 모든 이름의 해시 값을 계산하는 데 O(L), 즉 상수 시간이 걸린다.
- 결과적으로 "이름 → 전화번호" 맵도 삽입, 삭제, 조회가 평균적으로 상수 시간에 동작한다.
- 전화번호부는 이제 두 개의 해시 테이블로 구현할 수 있다: 정수용 보편적 해시 함수족을 쓰는 "전화번호 → 이름" 맵, 그리고 다항식 해시 함수족 위에 정수용 보편적 해시 함수족을 겹쳐 쓰는 "이름 → 전화번호" 맵. 둘 다 평균적으로 상수 시간에 검색·수정이 가능하고 메모리 사용량도 저장된 항목 수에 선형으로 비례한다.
- 평균적으로는 이보다 더 빠르게(점근적으로) 만들 수 없고, 메모리도 이보다 더 줄일 수 없다. 다만 최악의 경우에는 해시 테이블이 느리게 동작할 수 있으며, 그런 최악의 경우가 발생할 확률이 매우 작다는 것도 정리로 알려져 있다.
- Java가 매번 무작위 x를 고르지 않고 x = 31로 고정한 이유도 여기서 설명된다. 결정적(deterministic)이어야 하므로 무작위 선택 대신 하나의 "무작위스러운" 값을 예시로 고정해 쓰는데, 이 특정 구현에 대해 특별히 나쁜 입력을 만날 확률이 매우 작기 때문에 실전에서는 대체로 빠르고 매끄럽게 동작한다.

## 예시
- 보조정리 2의 확률 부등식을 정리하면: p > m·L일 때
  - L/p < L/(mL) = 1/m
  - 따라서 1/m + L/p < 1/m + 1/m = 2/m
  - 즉 충돌 확률은 O(1/m)이다.

## 요약
- 다항식 해시 함수족은 길이 최대 L+1인 두 문자열에 대해 충돌 확률이 최대 L/p이다.
- 다항식 해시 값(0~p−1 정수) 위에 정수용 보편적 해시 함수족을 한 번 더 적용하면, 임의의 카디널리티 m에 대해 충돌 확률이 최대 1/m + L/p인 해시 함수 h_m을 얻는다.
- p > m·L로 고르면 충돌 확률은 O(1/m)이 되어, 정수 해싱과 동일하게 체인 길이 O(1+α)를 얻을 수 있다.
- 문자열 해시 계산은 O(문자열 길이)이므로, 이름 길이가 상수라면 상수 시간에 해시를 계산할 수 있다.
- 이로써 전화번호부 문제의 두 방향("전화번호→이름", "이름→전화번호") 모두 평균 O(1) 연산과 선형 메모리로 구현이 완성된다.
- 다음 강의부터는 해싱을 이용해 텍스트 안에서 부분 문자열(substring)을 빠르게 찾는 문제를 다룬다.
