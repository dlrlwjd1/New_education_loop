# Universal Family

## 개요
- 단일한 보편적 해시 함수는 존재하지 않음을 앞서 증명했지만, 무작위성(randomization)을 활용한 보편적 해시 함수족(universal family of hash functions)이라는 개념으로 문제를 해결할 수 있음을 소개한다.
- 부하율(load factor)이라는 개념과, 이를 이용해 해시 테이블 크기를 정하고 동적으로 리해시(rehash)하는 방법도 다룬다.

## 내용

### 아이디어: 퀵소트(QuickSort)의 교훈
- 퀵소트에서 고정된 피벗(pivot)을 쓰면 최악의 경우 Θ(n²)이지만, 무작위 피벗을 쓰면 이 문제를 회피할 수 있었다.
- 마찬가지로, 완전한 무작위 해시 함수는 키를 잘 분산시키지만 매번 다른 값을 반환하기 때문에 그대로 쓸 수는 없다.
- 해결책: 먼저 해시 함수들의 **집합(family)**을 정의해 두고, 그중 하나를 무작위로 골라 고정적으로 사용한다. 무작위성은 "함수를 고르는 단계"에만 사용되고, 일단 고른 함수는 완전히 결정적(deterministic)으로 계속 사용된다.

### 보편적 해시 함수족(universal family)의 정의
- U를 유니버스(모든 가능한 키의 집합)라 하자.
- 카디널리티 m이 같은 해시 함수들의 집합 H를 생각한다. H의 모든 함수는 U를 0 ~ m−1의 정수로 매핑한다.
- H가 **보편적 해시 함수족(universal family)** 이라는 것은: 유니버스 안의 임의의 서로 다른 두 키 x, y에 대해, H에서 무작위로 고른 해시 함수가 x와 y를 충돌시킬 확률이 1/m 이하라는 뜻이다.
- 즉, 특정 고정된 키 쌍 (x, y)에 대해 충돌이 일어나는 해시 함수의 비율이 H 전체의 1/m을 넘지 않는다는 의미다. (같은 해시 함수가 다른 키 쌍에 대해서는 충돌을 일으킬 수도 있지만, 지금 관심 있는 것은 고정된 한 쌍에 대한 확률이다.)
- H의 모든 개별 함수는 결정적이며, 무작위성은 오직 "H에서 함수를 고르는 것" 한 번뿐이다. 이렇게 고른 함수는 삽입, 검색, 삭제 전체에 걸쳐 동일하게 사용된다.

### 부하율(load factor)
- 부하율(load factor) = 해시 테이블에 저장된 키의 개수 / 해시 테이블 크기.
- 부하율이 너무 작으면 대부분의 셀이 비어 있어 공간을 낭비하는 것이고, 부하율이 1보다 크면 반드시 충돌이 존재하며, 부하율이 크면 충돌이 많고 최장 체인이 길어져 연산이 느려진다.
- **정리(Lemma)**: 해시 함수를 보편적 해시 함수족에서 무작위로 고르면, 해시 테이블에서 가장 긴 체인의 평균 길이는 O(1 + α)다. 여기서 α는 부하율(load factor).
- **따름정리(Corollary)**: 연산은 평균적으로 O(1 + α) 시간에 동작한다. (연산 시간이 O(1+c)이고 c = O(1+α)이므로, O(1+c) = O(1+α).)
- 확률 집중 정리(probability concentration theorem)에 의해, 최장 체인이 평균보다 훨씬 길어질 확률은 매우 작다는 것도 알려져 있다(강의에서는 결과만 언급).

### 해시 테이블 크기 정하기
- 메모리 사용량은 m으로 제어할 수 있다. 부하율 α는 0.5~1의 중간 범위로 유지하는 것이 이상적이다(1보다 크면 충돌 다수 발생, 0.5보다 작으면 절반 이상의 공간이 낭비).
- m = n/α로 두면(정의상), 이는 O(n) 메모리와 같다(α가 상수이므로).
- 연산 시간은 평균 O(1 + α) = O(1)이다(α가 1.5~2 사이 범위이므로 사실상 상수).

### 키 개수를 미리 모를 때: 리해시(rehash)
- 방법 1: 아주 큰 해시 테이블로 시작 — 초기에 테이블이 거의 비어 메모리를 낭비한다.
- 방법 2: 동적 배열(dynamic array)과 같은 아이디어를 적용해, 부하율이 너무 커지면 해시 테이블 크기를 점진적으로 늘린다.
- 테이블 크기를 바꾸면 카디널리티가 바뀌므로 해시 함수도 새로 골라야 하며, 기존 테이블의 모든 키를 새 테이블로 다시 삽입(재해시)해야 한다.
- **리해시 절차** (부하율을 예를 들어 0.9 미만으로 유지한다고 가정):
  1. 현재 부하율(저장된 키 수 / 테이블 크기)을 계산한다.
  2. 부하율이 0.9를 넘었다면, 현재 크기의 2배인 새 해시 테이블을 만들고, 그 카디널리티에 맞는 새 해시 함수를 고른다.
  3. 현재 테이블의 모든 객체를 새 해시 함수를 이용해 새 테이블에 삽입한다.
  4. 현재 테이블과 해시 함수를 새 테이블·새 해시 함수로 교체한다.
- 매 연산(삽입 등) 후에 리해시를 호출해야 부하율 초과 시점을 놓치지 않는다.
- 한 번의 리해시는 선형 시간이 걸리지만, 동적 배열(dynamic array)에서와 마찬가지로 크기가 n인 테이블이 다시 두 배가 되기까지 n번의 삽입이 더 필요하므로, 평균(분할 상환, amortized) 삽입 비용은 여전히 O(1)이다.

## 요약
- 보편적 해시 함수족(universal family) H: 임의의 서로 다른 키 쌍에 대해, H에서 무작위로 고른 함수가 충돌을 일으킬 확률이 1/m 이하인 해시 함수들의 집합.
- 무작위성은 "H에서 함수를 한 번 고르는 것"에만 쓰이고, 고른 함수는 계속 결정적으로 사용된다.
- 부하율 α = n/m을 0.5~1 사이로 유지하면, 평균 연산 시간 O(1+α)=O(1), 메모리 O(n)을 달성할 수 있다.
- 키 개수를 모를 때는 동적 배열처럼 부하율이 임계값(예: 0.9)을 넘으면 테이블을 2배로 늘리고 재해시(rehash)하며, 분할 상환 O(1) 삽입 비용을 유지한다.
