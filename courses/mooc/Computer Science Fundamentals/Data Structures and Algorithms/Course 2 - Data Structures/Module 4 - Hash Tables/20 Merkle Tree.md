# Merkle Tree

## 개요
- 블록 안에 특정 거래(transaction)가 포함되어 있는지 확인하는 과정을 선형 시간 O(n)에서 로그 시간(logarithmic time)으로 줄여주는 자료구조인 머클 트리(Merkle tree)를 소개한다.
- 이 강의를 끝으로 해싱(hashing)이 블록체인(blockchain)의 여러 단계(기록 해싱, 논스 탐색, 트리를 이용한 검증)에 걸쳐 어떻게 핵심적으로 쓰이는지를 정리한다.

## 내용

### 기존 방식의 한계
- 블록 안에 어떤 거래가 기록되어 있음을 확인하려면, 블록 안 거래들의 해시 체인 전체를 계산해 검증해야 했다.
- 블록 안 거래 개수가 n개면 이 검증에 O(n) 시간이 걸리고, 그만큼 많은 정보를 네트워크를 통해 전송해야 하므로 거래가 많을수록 비효율적이다.

### 머클 트리의 구조
- 맨 아래층(잎, leaf)에 데이터 블록(=거래) L1, L2, L3, L4가 있다고 하자(예시는 4개).
- 각 데이터 블록을 각각 해시해 hash00, hash01, hash10, hash11을 얻는다(둘씩 짝지어 계산할 것이므로 이런 식으로 번호를 붙인다).
- 짝을 이룬 두 해시(hash00과 hash01)를 이어붙여(concatenate) 다시 해시하면 hash0을 얻는다. 마찬가지로 hash10과 hash11을 이어붙여 해시하면 hash1을 얻는다.
- hash0과 hash1을 다시 이어붙여 해시하면 블록의 최상위 해시(top hash)를 얻는다.
- 거래 개수가 홀수라 짝이 없는 블록이 남으면, 그 블록을 자기 자신의 복사본과 짝지어 해시를 만든다. 이런 식으로 각 레벨에서 홀수 개가 남을 때마다 마지막 블록을 자기 복사본과 짝짓는 규칙을 적용한다.
- 트리를 만드는 이 과정 자체는 선형 시간(O(n))이 걸리지만, 특정 데이터 블록이 포함되어 있는지 확인하는 과정은 훨씬 빠르게 할 수 있다.

### 포함 여부를 빠르게 확인하는 방법
- 예를 들어 데이터 블록 L2의 소유자가 자신의 블록이 포함되어 있는지 확인하고 싶다고 하자.
  1. 자신의 블록을 직접 해시해 hash01을 얻는다.
  2. 짝이 되는 블록의 해시 hash00을 전달받는다. 자신의 hash01과 hash00을 이어붙여 해시하면 hash0을 얻고, 이를 상대방이 보내준 hash0과 비교해 검증한다.
  3. 다음 레벨로 올라가기 위해 짝이 되는 hash1을 전달받는다. hash0과 hash1을 이어붙여 해시하면 최상위 해시(top hash)를 얻는다.
  4. 최상위 해시를 전달받아 직접 계산한 값과 비교하면, 자신의 블록이 실제로 그 블록체인 블록 안에 있는지 최종적으로 확인할 수 있다.
- 일반화하면: n개의 데이터 블록이 있는 첫 레벨, n/2개가 있는 다음 레벨, ... 이런 식으로 레벨이 올라갈 때마다 블록 수가 절반이 되므로 레벨 수는 로그(logarithmic) 수준이다.
- 각 레벨에서 자신이 모르는 해시 값 하나(또는 그 짝)만 전달받으면 되므로, 전체적으로 로그 개수의 해시 값만 전달받으면 포함 여부를 검증할 수 있다. 이는 선형 시간 대비 큰 이득이다.

### 실제 블록체인에서의 머클 트리
- 실제 블록체인 다이어그램에서, 새로 추가되는 블록은 그 안의 거래들을 머클 트리(이진 트리 구조)로 구성한다. 거래들을 짝지어 해시하고, 그 결과를 다시 짝지어 해시하는 과정을 반복해 최종적으로 하나의 루트 해시(머클 루트)를 얻는다.
- 이렇게 만들어진 블록들이 체인으로 이어지며 실제 블록체인이 형성된다.
- 블록체인은 결국 위조하기 매우 어려운 분산 일기(distributed diary)이며, 누구나 이 일기에 쓸 수 있지만 그 과정은 경쟁적(competitive)이다. 가장 먼저 조건을 만족하는 논스(nonce)를 찾아내는 사람이 자신의 거래를 기록할 권리를 얻는다.
- 암호화폐(cryptocurrency)의 경우, 논스를 찾아 블록을 채굴(mining)하는 사람들을 채굴자(miner)라고 부르며, 이들에게 보상(금전적 인센티브)이 주어져야 이 활동을 계속하게 된다.
- 블록체인은 전체적으로 해싱을 여러 단계에서 적극적으로 활용한다. 기록 내용을 해싱하고, 그 내용을 이전 해시와 함께 다시 해싱해 위조를 어렵게 만들며, 머클 트리를 이용해 거래가 블록 안에 있는지 효율적으로 검증한다. 이 프로토콜 전체가 다양한 해시 함수의 성질에 기반해 설계되어 있다.
- 또한 효율적인 검증을 위해 이진 트리(binary tree) 구조(머클 트리)를 활용하는데, 이진 트리와 그 안에서의 효율적인 연산에 대해서는 이 코스의 다음 모듈에서 다룬다.

## 예시
- 4개의 데이터 블록(L1, L2, L3, L4)에 대한 머클 트리 구성:
  1. 각 블록을 해시: hash00, hash01, hash10, hash11.
  2. 짝을 지어 해시: hash0 = hash(hash00 + hash01), hash1 = hash(hash10 + hash11).
  3. 최상위 해시: top hash = hash(hash0 + hash1).
- L2 소유자가 포함 여부를 검증하는 절차:
  1. 자신의 블록을 해시해 hash01을 얻는다.
  2. hash00을 전달받아 hash0 = hash(hash00 + hash01)을 계산하고 검증한다.
  3. hash1을 전달받아 top hash = hash(hash0 + hash1)을 계산한다.
  4. 전달받은 top hash와 비교해 일치하면 자신의 거래가 블록에 포함되어 있음이 확인된다.
- 이 경우 필요한 전달 정보는 로그(log) 개수의 해시 값(레벨마다 하나 또는 두 개)뿐이다.

## 요약
- 머클 트리(Merkle tree)는 데이터 블록들을 둘씩 짝지어 해시하고, 그 결과를 다시 짝지어 해시하는 과정을 반복해 하나의 최상위 해시(top hash, 머클 루트)를 만드는 이진 트리 구조다.
- 홀수 개가 남는 레벨에서는 마지막 블록을 자기 자신의 복사본과 짝짓는다.
- 특정 데이터 블록이 트리(블록)에 포함되어 있는지 확인하려면, 각 레벨에서 모르는 해시 값 하나만 전달받아 위로 올라가며 계산하면 되므로, 전체 검증 비용이 O(n)에서 O(log n)으로 줄어든다.
- 실제 블록체인은 각 블록의 거래들을 머클 트리로 구성하며, 채굴자(miner)가 조건을 만족하는 논스(nonce)를 찾아 블록을 추가하는 경쟁적 과정으로 동작한다.
- 블록체인은 기록 해싱, 논스 탐색, 머클 트리 검증 등 여러 단계에서 해시 함수의 성질에 의존하는 시스템이다.
