# Search Trees

## 개요
- 이진 탐색(binary search) 과정을 트리 구조로 표현하면 이진 탐색 트리(binary search tree)가 되며, 이 트리가 만족해야 하는 핵심 성질인 search tree property를 설명한다.

## 내용
### 이진 탐색에서 트리로
- 정렬된 배열에서 이진 탐색을 할 때 "중간 값보다 큰가 작은가"를 반복해서 묻는 과정을 나타내면 자연스럽게 트리 구조(질문마다 두 갈래로 분기)가 된다.
- 예: 처음 7과 비교 → 작으면 4와 비교, 크면 13과 비교 → 이런 식으로 질문 트리가 만들어진다.
- 배열 대신 이 트리 자체를 데이터 구조로 사용하면, 정렬된 배열만큼 탐색이 빠르면서도 삽입이 훨씬 쉬워진다.

### 노드 구조
- 각 노드(node)는 다음을 저장한다.
  - 키(key): 비교에 사용하는 값
  - 부모(parent)에 대한 포인터
  - 왼쪽 자식(left child)에 대한 포인터
  - 오른쪽 자식(right child)에 대한 포인터

### Search Tree Property
- 노드 X의 키를 기준으로,
  - X의 왼쪽 서브트리(left subtree)에 있는 모든 노드의 키는 X의 키보다 작아야 한다.
  - X의 오른쪽 서브트리(right subtree)에 있는 모든 노드의 키는 X의 키보다 커야 한다.
- 이 성질이 모든 노드에서 성립해야 진짜 이진 탐색 트리다.

## 예시
- 세 트리 A, B, C 중 search tree property를 만족하는 것을 고르는 문제.
  - A: 루트가 4인데 왼쪽에 4보다 큰 값들, 오른쪽에 4보다 작은 값들이 있어 좌우가 뒤바뀐 오류. 좌우를 바꾸면 성립.
  - B: 정답. search tree property를 만족한다.
  - C: 루트가 5인데, 5의 오른쪽 서브트리 안에 5보다 작은 4가 들어 있어 오류.

## 요약
- 이진 탐색 트리는 각 노드가 key/parent/left/right를 가지며, 왼쪽 서브트리는 더 작은 키만, 오른쪽 서브트리는 더 큰 키만 담아야 한다는 search tree property를 만족해야 한다.
- 다음 강의에서 이 구조 위에서 기본 연산(find, insert, delete 등)을 구현하는 방법을 다룬다.
