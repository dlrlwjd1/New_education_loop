# Balance

## 개요
- 이진 탐색 트리 연산의 실행 시간이 트리의 깊이(depth)에 좌우된다는 점을 보이고, 이를 개선하기 위한 균형(balance) 개념과 그 도구인 회전(rotation) 연산을 소개한다.

## 내용
### 연산의 실행 시간과 깊이
- `Find` 연산은 루트에서 목표 노드까지 트리를 따라 내려가며 각 단계마다 상수 시간(constant time) 작업을 한다.
- 따라서 `Find`의 실행 시간은 O(트리의 깊이, Depth)다.
- 같은 트리라도 노드의 위치(깊이)에 따라 탐색 속도가 다르다. 루트에 가까운 노드일수록 빠르게 찾을 수 있다.

### 깊이가 나쁠 수 있는 경우
- 노드 10개짜리 트리라도 특정 노드의 깊이가 6이 될 수 있다.
- 최악의 경우 노드들이 한 줄로 길게 늘어선 체인(chain) 형태가 되면, n개 노드 트리의 깊이가 n이 될 수 있다.
- 이 경우 탐색이 O(n)이 되어, 다른 자료구조보다 나을 게 없어진다.

### 균형(Balance)의 개념
- 같은 10개의 노드라도 트리를 잘 재배열하면 최대 깊이를 4 정도로 줄일 수 있다.
- 이진 탐색(binary search)이 효율적이려면 매번 "중간" 값을 질문해야 하는 것처럼, 이진 탐색 트리에서도 각 노드의 왼쪽 서브트리와 오른쪽 서브트리의 크기가 거의 같아야 한다. 이것이 균형(balance)의 의미다.
- 완벽하게 균형 잡힌 트리에서는 한 단계 내려갈 때마다 서브트리 크기가 절반이 되므로, O(log n) 단계 만에 크기 1의 서브트리에 도달한다.
- 즉, 트리가 잘 균형 잡혀 있으면 연산은 O(log n) 시간에 실행된다.

### 삽입이 균형을 깨는 문제
- 빈 트리에 1을 넣고 완벽히 균형 잡힌 상태에서 시작해도, 2, 3, 5, 4를 순서대로 삽입하면 매우 불균형한 트리가 될 수 있다.
- 단순한 갱신(update) 연산만으로도 균형이 쉽게 깨질 수 있으므로, 균형을 유지하면서 갱신하는 방법이 필요하다.

### 회전(Rotation)
- 트리를 재배열하되 반드시 search tree property(정렬 성질)를 유지해야 한다.
- 회전은 이를 만족하는 국소적(local) 재배열 연산이다.
- 노드 `X`와 그 부모(parent) `Y`가 있을 때, 회전을 하면 `Y`가 `X`의 자식이 되도록 부모·자식 관계가 뒤바뀐다. 이때 `X`, `Y`에 매달려 있던 서브트리 A, B, C를 올바르게 재배치해야 정렬 순서가 유지된다.
- 절차(우측 회전 예시): `P`를 `X`의 부모, `Y`를 `X`의 왼쪽 자식, `B`를 `Y`의 오른쪽 자식이라 하자.
  - `P`는 이제 `Y`의 새 부모가 되고 `Y`는 `P`의 자식이 된다.
  - `Y`는 이제 `X`의 새 부모가 되고 `X`는 `Y`의 오른쪽 자식이 된다.
  - `X`는 이제 `B`의 새 부모가 되고 `B`는 `X`의 왼쪽 자식이 된다.
- 이 재배정만 하면 정렬 성질이 그대로 유지되며, 이 연산은 상수 시간(constant time)에 실행된다.

## 예시
- 트리 A, B, C, D 중 A가 루트에 있어 가장 빠르고, D(깊이 3) → B(깊이 4) → C(깊이 5) 순으로 느려진다.
- 빈 트리에서 1을 넣은 뒤 2, 3, 5, 4를 순서대로 삽입하면 한쪽으로 치우친 불균형 트리가 만들어지는 예를 보여준다.

## 요약
- 이진 탐색 트리 연산의 실행 시간은 O(depth)이며, 최악의 경우 O(n)까지 나빠질 수 있다.
- 균형(balance)이란 각 노드에서 왼쪽·오른쪽 서브트리 크기가 비슷한 상태를 말하며, 균형이 유지되면 O(log n) 성능을 얻는다.
- 단순 삽입은 균형을 깨뜨릴 수 있으므로, search tree property를 유지하면서 국소적으로 트리를 재배열하는 회전(rotation) 연산이 필요하다.
- 다음 강의에서는 회전을 이용해 균형을 유지하는 구체적인 방법인 AVL 트리를 다룬다.
