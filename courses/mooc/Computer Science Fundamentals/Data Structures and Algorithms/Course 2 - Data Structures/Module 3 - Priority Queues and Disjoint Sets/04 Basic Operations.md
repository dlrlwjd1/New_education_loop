# Basic Operations

## 개요
- 이진 최대 힙(binary max heap)에서 `GetMax`, `Insert`, `ExtractMax`, `ChangePriority`, `Remove` 연산이 어떻게 동작하는지 설명한다.
- 핵심 아이디어는 원소를 위로 올리는 시프트 업(sift up)과 아래로 내리는 시프트 다운(sift down) 두 절차다.

## 내용

### GetMax
- 힙 속성(부모 값 ≥ 자식 값)에 따라 트리 아래에서 위로 갈수록 값이 커지므로, 최댓값은 항상 루트(root)에 저장된다.
- 루트 값을 그냥 반환하면 되므로 상수 시간(constant time)이다.

### Insert와 시프트 업(sift up)
- 새 원소는 루트에 바로 붙일 수 없으므로(루트가 이미 자식 2개를 가질 수 있음) 트리의 어떤 리프(leaf)에 새 노드로 붙인다.
- 이 과정에서 힙 속성이 깨질 수 있다(새 값이 부모보다 큰 경우). 이를 고치기 위해 새 원소를 부모와 반복적으로 교환(swap)하며 위로 올리는데, 이를 시프트 업이라 한다.
- 매 시점에 문제가 되는 간선은 최대 1개만 존재하도록 유지되며, 교환할 때마다 문제 노드가 루트에 한 걸음씩 가까워진다.
- 따라서 스왑 횟수는 최대 트리 높이(tree height)만큼이며, `Insert`와 `sift up`의 실행 시간은 O(트리 높이)다.

### ExtractMax와 시프트 다운(sift down)
- 최댓값은 루트에 있지만, 루트를 그냥 떼어내면 두 서브트리가 분리되어 트리 구조가 깨진다.
- 대신 트리에서 리프 하나를 선택해 루트 자리에 옮겨 놓는다. 이렇게 하면 힙 속성이 깨질 수 있다.
- 새 루트를 자식 중 더 큰 값을 가진 쪽과 교환하는 과정을 반복하며 아래로 내리는데, 이를 시프트 다운이라 한다. 더 큰 자식과 교환해야 두 문제 간선 중 하나가 자동으로 해결된다.
- 역시 매 시점에 문제 간선이 최대 1개만 존재하며, 문제 노드가 리프 쪽으로 한 걸음씩 가까워지므로 `ExtractMax`와 `sift down`의 실행 시간도 O(트리 높이)다.

### ChangePriority
- 특정 원소의 우선순위를 올리거나 내린 뒤, 값이 커졌다면 시프트 업을, 작아졌다면 시프트 다운을 호출해 힙 속성을 복구한다.
- 이 경우도 실행 시간은 O(트리 높이)다.

### Remove
- 제거할 원소의 우선순위를 양의 무한대(+∞)로 바꾼 뒤 `ChangePriority`(내부적으로 시프트 업)를 호출하면 그 원소가 루트까지 올라간다.
- 이후 `ExtractMax`를 호출해 루트를 제거하면 된다.
- 즉 `Remove`는 시프트 업과 `ExtractMax` 두 절차만으로 구현되며, 실행 시간 역시 O(트리 높이)다.

## 예시
- 리프 7에 새 값 32를 붙였다고 하자. 7과 32를 교환하고, 그다음 32의 새 부모(29)와 다시 교환하면 힙 속성이 회복된다 — 시프트 업 2회.
- 루트를 제거한 뒤 리프 12를 루트 자리에 놓으면 12가 두 자식보다 작아 속성이 깨진다. 더 큰 자식(예: 29)과 교환하고, 이어서 필요하면 14와 다시 교환해 속성을 회복한다 — 시프트 다운 과정.

## 요약
- `GetMax`는 루트 값을 반환하는 상수 시간 연산이다.
- `Insert`(시프트 업), `ExtractMax`(시프트 다운), `ChangePriority`, `Remove`는 모두 O(트리 높이)에 수행된다.
- 모든 연산이 힙 속성 위반을 "한 번에 최대 한 간선"으로 유지하면서 문제 노드를 루트 또는 리프 방향으로 한 걸음씩 옮기는 방식으로 동작한다.
- 트리를 얕게(shallow) 유지하는 것이 다음 목표다.
