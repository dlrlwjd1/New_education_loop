# Heap Sort

## 개요
- 이진 힙(binary heap)을 이용해 배열을 정렬하는 힙 정렬(heap sort) 알고리즘을 소개한다.
- 처음에는 별도의 우선순위 큐(priority queue)를 만들어 정렬하는 방식을 살펴본 뒤, 추가 메모리 없이 제자리(in place)에서 정렬하는 방식으로 개선한다.

## 내용

### 우선순위 큐를 이용한 기본 아이디어
- 크기 n인 배열 A가 주어지면, 빈 우선순위 큐를 만들고 A의 모든 원소를 삽입(`Insert`)한 뒤, `ExtractMax`를 반복 호출해 큰 값부터 순서대로 배열의 뒤에서부터 채운다.
- 이진 힙 기반 우선순위 큐를 사용하면 모든 연산이 로그 시간이므로 전체 실행 시간은 O(n log n)이다.
- 비교 기반(comparison-based) 정렬 알고리즘 중에서 이 O(n log n)은 점근적으로 최적(asymptotically optimal)이다.
- 이 방식은 선택 정렬(selection sort)의 자연스러운 일반화다. 선택 정렬이 매번 배열을 훑어 최댓값을 찾는 대신, 힙 정렬은 이진 힙이라는 똑똑한 자료구조로 최댓값을 빠르게 찾는다.
- 단점: 우선순위 큐를 저장하기 위한 추가 공간(additional space)이 필요하다.

### 제자리(in-place) 힙 정렬로 개선
- 별도의 우선순위 큐 없이, 주어진 배열 A 자체를 힙 속성을 만족하도록 원소들을 재배열(permute)한 뒤 그 배열 안에서 정렬을 완료한다.

### BuildHeap 절차
- 배열 A(크기 n)에 대해 `size = n`으로 설정한 뒤, `i`를 `⌊n/2⌋`부터 1까지 내려가면서 `SiftDown(i)`를 호출한다.
- 리프 노드들은 애초에 힙 속성이 깨질 수 없으므로(자식이 없어 비교할 간선이 없음) 건너뛰고, 리프 바로 위 레벨부터 시작해 점점 위쪽(루트 방향)으로 올라가며 각 서브트리의 힙 속성을 복구한다.
- 실행 시간: `SiftDown`을 대략 n/2번 호출하고 각 호출이 O(log n)이므로 얼핏 O(n log n)으로 보인다(다음 강의에서 더 정밀하게 O(n)으로 개선됨을 다룬다).

### In-place Heap Sort 절차
1. `BuildHeap(A)`로 배열 A를 힙으로 변환한다(`size = n`으로 설정됨).
2. `n-1`번 다음을 반복한다.
   - `A[1]`(현재 최댓값)과 `A[size]`를 교환한다.
   - `size`를 1 감소시켜 방금 옮긴 원소를 힙에서 제외한다.
   - `SiftDown(1)`을 호출해 힙 속성을 복구한다.
- 매 반복마다 남은 부분에서 최댓값을 배열의 그 시점 마지막 자리로 보내는 방식으로, 이 역시 선택 정렬의 개선판이다.

### 힙 정렬의 특성
- 제자리(in place) 알고리즘으로 추가 메모리가 필요 없다.
- 실행 시간이 O(n log n)이며 이는 최적(optimal)이다.
- 퀵 정렬(quick sort)은 평균(average case) O(n log n)이지만 최악의 경우(worst case) O(n²)가 될 수 있는 반면, 힙 정렬은 최악의 경우에도 O(n log n)을 보장한다.
- 실무에서는 퀵 정렬이 보통 더 빠르므로, 두 알고리즘을 결합한 인트로 정렬(introsort)이 널리 쓰인다: 먼저 퀵 정렬로 시작하되, 재귀 깊이(recursion depth)가 c·log n(c는 상수)을 넘어서면 힙 정렬로 전환해 최악의 경우에도 O(n log n)을 보장한다.

## 예시
- 배열 A를 `BuildHeap`으로 힙으로 만든 후: `A[1]`(최댓값)과 `A[n]`을 교환 → `size`를 n-1로 감소 → `SiftDown(1)`. 다시 `A[1]`과 `A[n-1]`을 교환 → `size`를 n-2로 감소 → `SiftDown(1)`. 이 과정을 `n-1`번 반복하면 배열 전체가 오름차순으로 정렬된다.

## 요약
- 힙 정렬(heap sort)은 이진 힙을 이용해 O(n log n) 시간에 배열을 제자리에서(in place) 정렬하는 비교 기반 알고리즘이다.
- 우선순위 큐를 따로 두는 방식은 추가 공간이 필요하지만, `BuildHeap` + 반복적인 루트-마지막 원소 교환 및 `SiftDown`으로 추가 공간 없이 같은 효과를 낼 수 있다.
- 최악의 경우에도 O(n log n)을 보장한다는 점에서 퀵 정렬과 상호보완적이며, 실무에서는 인트로 정렬(introsort)처럼 둘을 결합해 사용하기도 한다.
