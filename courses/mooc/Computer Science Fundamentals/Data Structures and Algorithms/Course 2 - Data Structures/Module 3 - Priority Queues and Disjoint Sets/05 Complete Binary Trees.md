# Complete Binary Trees

## 개요
- 이진 최대 힙(binary max heap)의 높이를 낮게(shallow) 유지하기 위해 완전 이진 트리(complete binary tree)라는 개념을 도입한다.
- 완전 이진 트리는 (1) 높이가 O(log n)이라는 장점과 (2) 배열(array) 하나만으로 트리 전체를 표현할 수 있다는 장점을 가진다.

## 내용

### 완전 이진 트리(complete binary tree)의 정의
- 마지막 레벨을 제외한 모든 레벨이 완전히 채워져 있고, 마지막 레벨의 노드들은 모두 가능한 한 왼쪽(leftmost)에 몰려 있는 이진 트리.
- 예: 마지막 레벨의 노드가 왼쪽부터 채워지지 않고 중간에 빈 자리 없이 오른쪽에 몰려 있으면 완전 이진 트리가 아니다.

### 장점 1 — 높이가 O(log n)
- n개의 노드를 가진 완전 이진 트리는 같은 노드 수를 가진 모든 이진 트리 중 높이가 최소다.
- 증명 개요: 마지막 레벨까지 완전히 채운 트리의 노드 수를 n′이라 하면 n′ ≤ 2n이다(마지막 레벨의 노드 수가 그 이전 모든 레벨의 노드 수 합보다 최대 1개 많으므로). 완전히 채워진 트리에서는 n′ = 2^l − 1(l은 레벨 수)이므로 l = log₂(n′+1) ≤ log₂(2n+1) = O(log n).

### 장점 2 — 배열로 저장 가능
- 루트부터 아래로, 각 레벨은 왼쪽에서 오른쪽으로 번호(1부터)를 매기면, 노드 번호 i에 대해 부모(parent)는 ⌊i/2⌋, 왼쪽 자식(left child)은 2i, 오른쪽 자식(right child)은 2i+1로 계산할 수 있다.
- 예: i=4의 부모는 2, 자식은 8과 9. i=3의 부모는 1, 자식은 6과 7.
- 이 성질 덕분에 부모/자식으로의 링크를 따로 저장할 필요 없이 배열 인덱스 계산만으로 트리 구조를 알 수 있다.

### 완전성 유지 비용
- 이 두 장점을 얻으려면 트리를 항상 완전 이진 트리 상태로 유지해야 한다.
- 트리의 모양(shape)을 바꾸는 연산은 `Insert`와 `ExtractMax`뿐이다(`sift up`/`sift down`은 원소 값만 교환할 뿐 모양은 바꾸지 않고, `Remove`는 내부적으로 `ExtractMax`를 호출한다).

### 완전성을 유지하는 Insert
- 새 원소를 마지막 레벨의 가장 왼쪽 빈 자리에 리프로 삽입한 뒤, 시프트 업(sift up)으로 힙 속성을 복구한다.

### 완전성을 유지하는 ExtractMax
- 루트를 제거할 때, 완전성을 유지하기 위해 마지막 레벨의 가장 마지막(rightmost) 리프를 루트 자리로 옮긴 뒤, 시프트 다운(sift down)으로 힙 속성을 복구한다.

## 예시
- n=10인 완전 이진 트리에서 마지막 레벨까지 채우면 n′=15, 레벨 수 l=4이며 l ≤ log₂(2·10+1) = O(log n)이 성립함을 확인할 수 있다.
- 30을 삽입할 때 마지막 레벨의 가장 왼쪽 빈 자리에 넣고, 14 → 29 순서로 교환하며 시프트 업한다.
- 42(루트)를 추출할 때 마지막 레벨의 마지막 리프였던 14를 루트로 옮기고, 30 → 29 순서로 교환하며 시프트 다운한다.

## 요약
- 완전 이진 트리(complete binary tree)는 마지막 레벨을 제외한 모든 레벨이 가득 차 있고 마지막 레벨은 왼쪽부터 채워진 트리다.
- n개 노드를 가진 완전 이진 트리의 높이는 O(log n)이며, 노드 번호만으로 부모(⌊i/2⌋)와 자식(2i, 2i+1)을 계산할 수 있어 배열 하나로 저장 가능하다.
- `Insert`는 마지막 레벨의 가장 왼쪽 빈 자리에 추가 후 시프트 업, `ExtractMax`는 마지막 리프를 루트로 옮긴 후 시프트 다운으로 완전성과 힙 속성을 동시에 유지한다.
