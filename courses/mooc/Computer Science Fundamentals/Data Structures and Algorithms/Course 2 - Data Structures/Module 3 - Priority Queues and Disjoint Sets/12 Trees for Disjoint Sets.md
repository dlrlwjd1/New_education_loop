# Trees for Disjoint Sets

## 개요
- 서로소 집합(disjoint sets)을 트리(rooted tree)로 표현하는 구현 방식을 소개한다.
- 각 집합을 뿌리 있는 트리(rooted tree)로 나타내고 트리의 루트를 집합의 ID로 사용하며, 두 트리를 병합할 때 어느 쪽을 어느 쪽 아래에 매달지가 성능에 영향을 준다는 점을 설명한다.

## 내용

### 트리 기반 표현
- 각 집합은 하나의 뿌리 있는 트리로 표현되며, 트리의 루트(root)를 그 집합의 ID로 사용한다.
- 각 원소 i에 대해 부모(parent)를 배열 `parent`에 저장한다. j가 i의 부모이면 `parent[i] = j`, i가 루트이면 `parent[i] = i`.
- 예: 세 그루의 트리(루트가 각각 5, 6, 4)가 있는 경우, `parent[4] = 4`(4가 루트), `parent[7] = 9`(9가 7의 부모)처럼 배열에 저장된다.

### MakeSet
- `MakeSet(i)`: `parent[i] = i`로 설정해 자기 자신이 루트인, 원소 하나짜리 트리를 만든다. 상수 시간.

### Find
- `Find(i)`: `parent[i] = i`가 될 때까지(루트에 도달할 때까지) `i = parent[i]`를 반복하며 부모 링크를 따라 올라간다.
- 실행 시간은 최대 해당 트리의 높이(height)만큼이다.

### Union — 두 트리를 합치는 방법
- 두 트리를 병합할 때는 한 트리의 루트를 다른 트리의 루트 아래에 매단다(hang). 즉 한쪽 루트의 부모를 다른 쪽 루트로 바꾸는 것만으로 병합이 끝난다.
- 어느 쪽을 어느 쪽 아래에 매달지 선택할 수 있는데, 높이가 더 작은 트리를 높이가 더 큰 트리의 루트 아래에 매다는 것이 합리적이다.
- 이유: `Find`의 최악 실행 시간은 숲(forest) 안에서 가장 높은 트리의 높이에 비례하므로, 트리를 얕게(shallow) 유지해야 `Find`가 빨라진다.
- 예: 높이 1짜리 트리와 높이 2짜리 트리를 `Union`할 때, 낮은 트리를 높은 트리 아래에 매달면 결과 트리의 높이가 그대로 유지되지만, 반대로 하면 결과 트리의 높이가 늘어난다.

## 예시
- 세 노드짜리 트리(루트 자기 자신을 가리킴)와 다른 트리를 합칠 때, 왼쪽 트리의 루트를 오른쪽 트리의 루트 아래에 매달면 왼쪽 루트는 더 이상 루트가 아니게 되고 오른쪽 루트가 병합된 트리 전체의 루트가 된다.
- 높이 1짜리 트리와 높이 2짜리 트리를 합칠 때, 낮은 트리(높이 1)를 높은 트리(높이 2) 아래에 매달면 결과 트리 높이는 여전히 2지만, 반대로 매달면 결과 트리 높이가 3으로 늘어난다.

## 요약
- 서로소 집합을 뿌리 있는 트리 숲(forest of rooted trees)으로 표현하며, `parent` 배열로 부모 관계를 저장하고 루트를 집합 ID로 쓴다.
- `MakeSet`은 O(1), `Find`는 O(트리 높이), `Union`은 두 루트를 찾은 뒤 한쪽을 다른 쪽 아래에 매다는 상수 시간 연산이다.
- 병합 시 더 낮은 트리를 더 높은 트리 아래에 매달아야 트리가 얕게 유지되어 `Find`가 느려지지 않는다 — 이것이 다음 강의의 union by rank 휴리스틱(heuristic)으로 이어진다.
