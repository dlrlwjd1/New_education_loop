# Path Compression

## 개요
- 서로소 집합(disjoint sets) 자료구조를 더욱 빠르게 만드는 두 번째 휴리스틱(heuristic)인 경로 압축(path compression)을 소개한다.
- 경로 압축과 union by rank를 함께 쓰면, m번의 연산에 대한 총 실행 시간이 O(m log* n)까지 줄어든다는 결과를 제시한다(증명은 다음 강의).

## 내용

### 경로 압축(path compression)의 아이디어
- `Find(i)`를 호출하면 i에서 루트까지의 경로(path)를 따라가며 그 경로 위에 있는 모든 노드가 속한 집합의 루트를 알아내게 된다.
- 이렇게 얻은 정보를 버리지 않고, 경로 위의 모든 노드를 아예 루트에 직접 매달아(reattach) 저장해 두면 이후의 `Find` 호출이 더 빨라진다.
- 즉, 경로 위 노드들의 부모를 전부 루트로 바꿔버리는 것이 경로 압축이다.

### Find의 경로 압축 구현
```
Find(i):
    if i == parent[i]:
        return i
    parent[i] = Find(parent[i])
    return parent[i]
```
- i가 루트이면 그대로 반환한다.
- 루트가 아니면 부모에 대해 재귀적으로 `Find`를 호출해 루트를 구한 뒤, i의 부모를 그 루트로 바로 바꾸고 그 루트를 반환한다.
- 재귀를 통해 경로 위의 모든 노드에 대해 이 과정이 적용되어, 결국 경로 위 모든 노드가 루트에 직접 매달리게 된다.
- 단 3줄 정도의 매우 간단한 코드로 구현된다.

### 반복 로그 함수(iterated logarithm, log* n)
- log* n은 n에 이진 로그(binary logarithm)를 반복 적용하여 결과가 1 이하가 될 때까지 필요한 적용 횟수로 정의된다.
- 예: log*(1) = 0 (이미 1 이하). log*(2) = 1 (log₂2 = 1). log*(3) = log*(4) = 2. log*(2^65536) = 5 — 65536 → 16 → 4 → 2 → 1로 총 5번 이진 로그를 적용해야 1 이하가 된다.
- 이론적으로 log* n은 상한이 없는 함수이지만(n이 극도로 커지면 log* n도 6, 7, … 로 커질 수 있음), 현실적으로 있을 수 있는 모든 n 값에 대해서는 log* n ≤ 5이다.

### 두 휴리스틱을 결합했을 때의 실행 시간
- Union by rank와 경로 압축을 모두 사용하고, 총 n개의 원소에 대해 m번의 연산(그중 일부가 `MakeSet`)을 수행한다고 하면, 전체 연산의 총 실행 시간은 O(m log* n)이다.
- 즉 연산 1회당 상환(amortized) 실행 시간은 O(log* n)이며, 현실적인 모든 n에 대해 log* n ≤ 5이므로 사실상 상수 시간에 가깝다.

## 예시
- `Find(6)`을 호출했을 때 6 → 12 → 3 → (루트)로 이어지는 경로를 따라간다고 하면, 경로 압축 후에는 6과 12 모두 부모가 곧바로 루트(예: 5)로 바뀐다.
- log*(2^65536) = 5: 65536 → 16 → 4 → 2 → 1, 총 5회 이진 로그 적용.

## 요약
- 경로 압축(path compression)은 `Find` 호출 시 지나간 경로 위의 모든 노드를 루트에 직접 매달아, 이후의 `Find` 호출을 더 빠르게 만드는 휴리스틱이다.
- 구현은 재귀적인 `Find` 호출과 부모 갱신만으로 3줄 정도의 간단한 코드로 가능하다.
- 반복 로그 함수 log* n은 이론적으로 무한히 커질 수 있지만 현실적인 모든 n에 대해 최대 5이며, union by rank와 경로 압축을 함께 쓰면 연산당 상환 실행 시간이 O(log* n)으로 사실상 상수에 가까워진다.
