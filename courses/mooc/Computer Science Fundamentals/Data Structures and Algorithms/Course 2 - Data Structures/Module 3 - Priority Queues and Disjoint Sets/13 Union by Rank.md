# Union by Rank

## 개요
- 두 트리를 병합할 때 항상 더 낮은 트리를 더 높은 트리 아래에 매다는 union by rank 휴리스틱(heuristic)을 정의한다.
- 이 휴리스틱을 적용하면 숲(forest)에 있는 모든 트리의 높이가 O(log n)으로 제한되어, `Union`과 `Find`의 실행 시간이 O(log n)이 됨을 증명한다.

## 내용

### rank 배열
- 매번 트리 높이를 직접 계산하는 대신, 각 노드 i에 대해 그 노드를 루트로 하는 서브트리의 높이를 `rank[i]`에 저장해 관리한다.
- `MakeSet(i)`: `parent[i] = i`에 더해 `rank[i] = 0`으로 설정한다(원소 하나짜리 트리는 높이 0).
- `Find`는 rank를 사용하지도, 변경하지도 않는다.

### Union by rank 절차
```
i_id = Find(i)
j_id = Find(j)
if i_id == j_id:
    return
if rank[i_id] > rank[j_id]:
    parent[j_id] = i_id
else:
    parent[i_id] = j_id
    if rank[i_id] == rank[j_id]:
        rank[j_id] = rank[j_id] + 1
```
- 두 원소가 속한 트리의 루트(`i_id`, `j_id`)를 `Find`로 구한다.
- 이미 같은 집합이면 아무것도 하지 않는다.
- 높이(rank)가 더 큰 트리 쪽에 낮은 트리를 매단다.
- 두 트리의 rank가 같을 때만 결과 트리의 rank(높이)가 1 증가한다 — 이것이 유일하게 높이가 늘어나는 경우다.

### 불변식(invariant)과 핵심 보조정리(lemma)
- 불변식: 어느 시점에서든 모든 노드 i에 대해 `rank[i]`는 i를 루트로 하는 서브트리의 실제 높이와 같다.
- 보조정리: rank가 k인 트리는 항상 최소 2^k개의 노드를 포함한다. (귀납법: rank k인 트리는 반드시 rank k-1인 두 트리를 합쳐서 만들어지며, 각각 최소 2^(k-1)개의 노드를 가지므로 합치면 최소 2^k개.)
- 위 보조정리로부터, 어떤 트리의 높이가 log₂(n)을 넘으면 그 트리는 n개보다 많은 노드를 가져야 하는데 이는 전체 원소 수 n과 모순이므로, 숲에 있는 모든 트리의 높이는 최대 log₂(n)이다.

### 실행 시간
- 모든 트리의 높이가 O(log n)으로 유지되므로 `Find`의 실행 시간은 O(log n)이다.
- `Union`은 `Find` 호출 두 번과 상수 시간 연산 몇 개로 이루어지므로 실행 시간 역시 O(log n)이다.

## 예시
- 원소 1~6에 `MakeSet`을 호출하면 모두 자기 자신이 루트이고 rank는 모두 0이다.
- `Union(2,4)`: 두 rank가 같으므로(둘 다 0) 2를 4 아래에 매달고 `rank[4] = 1`로 갱신.
- `Union(5,2)`: 2가 속한 트리의 rank(1)가 5가 속한 트리의 rank(0)보다 크므로 5를 4 아래에 매단다. rank는 갱신되지 않는다(1 그대로).
- `Union(3,1)`: 마찬가지로 3을 1 아래에 매달고 `rank[1] = 1`로 갱신.
- `Union(2,3)`: 2가 속한 트리(루트 4, rank 1)와 3이 속한 트리(루트 1, rank 1)의 rank가 같으므로 하나를 합치고 결과 트리의 rank는 2가 된다(예: 4를 1 아래에 매달고 `rank[1] = 2`).
- `Union(2,6)`: 6을 1 아래에 매단다.

## 요약
- Union by rank는 두 트리를 병합할 때 rank(서브트리 높이)가 더 작은 트리를 더 큰 트리 아래에 매다는 휴리스틱이며, 두 rank가 같을 때만 결과 트리의 rank가 1 증가한다.
- 이 휴리스틱을 쓰면 rank가 k인 트리는 최소 2^k개의 노드를 가진다는 성질에 의해, 모든 트리의 높이가 O(log n)으로 제한된다.
- 결과적으로 `Find`와 `Union` 모두 최악의 경우 O(log n) 시간에 수행된다.
