# Analysis (Optional)

## 개요
- Union by rank와 경로 압축(path compression)을 함께 사용했을 때, m번의 연산에 대한 평균(상환, amortized) 실행 시간이 O(log* n)임을 증명한다. (선택 심화 내용)

## 내용

### 경로 압축 도입 후 rank의 의미 변화
- 경로 압축을 사용하면 더 이상 `rank[i]`가 i를 루트로 하는 서브트리의 실제 높이와 정확히 같지 않다. 경로 압축이 트리를 낮춰버릴 수 있기 때문이다.
- 그러나 여전히 rank는 실제 높이의 상한(upper bound)이다. 즉 실제 높이 ≤ rank.
- 예: rank가 2인 루트 아래에서 `Find`로 경로 압축이 일어나면 실제 높이는 1로 줄어들 수 있지만, rank 값 자체는 갱신되지 않고 2로 남아 있다(Find는 rank를 바꾸지 않음).

### 경로 압축 후에도 유지되는 성질들
- **성질 1**: rank가 k인 루트 노드의 서브트리는 여전히 최소 2^k개의 노드를 포함한다. 경로 압축은 루트 노드 자체에는 영향을 주지 않고, 그 서브트리에 속한 노드들이 다른 서브트리로 옮겨가는 일도 없기 때문이다.
- **성질 2**: 숲(forest)에는 rank가 k인 노드가 최대 n / 2^k개 존재한다. rank k인 노드가 만들어질 때 그 서브트리는 최소 2^k개의 노드를 가지므로, 그런 노드가 n/2^k개보다 많으면 전체 노드 수가 n을 넘어 모순이 된다.
- **성질 3**: 루트에서 멀어질수록(트리를 따라 내려갈수록) rank는 항상 엄격히 증가한다. 부모의 rank는 자식의 rank보다 항상 크다(경로 압축이 일어나도 이 성질은 유지된다).
- **성질 4**: 한 번 내부 노드(non-root)가 된 노드는 영원히 내부 노드로 남는다. `Find`는 루트를 바꾸지 않고, `Union`은 두 루트 중 하나만 남기고 나머지를 내부 노드로 만들기 때문이다.

### 실행 시간 분석의 틀
- `Union`은 `Find` 호출 두 번과 상수 시간 연산으로 귀결되므로, 전체 실행 시간 분석은 m번의 `Find` 호출이 지나가는 간선(edge)의 총 개수를 세는 문제로 환원된다.
- 이 간선들을 편의상 세 그룹으로 나눈다.
  1. 어떤 노드에서 곧바로 루트로 이어지는 간선.
  2. 루트가 아닌 부모 j로 가는 간선 중 `log*(rank[i]) < log*(rank[j])`인 경우.
  3. 루트가 아닌 부모 j로 가는 간선 중 `log*(rank[i]) = log*(rank[j])`인 나머지 모든 경우.
- 세 그룹 각각이 O(m log* n) 이내임을 보이면 전체 증명이 끝난다.

### 그룹 1 — 루트로 바로 이어지는 간선
- `Find` 한 번 호출당 루트로 이어지는 간선은 최대 2개(경로의 마지막 단계, 그리고 경로 압축으로 재배치되는 마지막 연결)이므로 총합은 O(m).

### 그룹 2 — log*(rank)가 증가하는 간선
- 루트 방향으로 올라갈수록 rank는 항상 증가하지만(성질 3), rank의 최댓값(루트의 rank)은 최대 log n이다.
- 따라서 한 번의 `Find` 호출 동안 log*(rank)가 증가할 수 있는 횟수는 최대 log* n번이다.
- m번의 `Find` 호출에 대해 총합은 O(m log* n).

### 그룹 3 — log*(rank)가 동일하게 유지되는 간선
- rank가 구간 [k+1, 2^k]에 속하는 노드의 개수는 성질 2에 의해 최대 n / 2^k개다(이 구간이 log* 값이 고정되는 구간의 형태).
- 특정 노드 i에 대해, i가 이 구간에 머무는 동안 부모가 바뀔 때마다(경로 압축으로 새 부모로 재배정될 때마다) 새 부모의 rank는 항상 이전보다 크다(성질 3). 이 구간의 rank 범위는 최대 2^k이므로, 최대 2^k번 재배정되면 반드시 이 구간을 벗어난다.
- 즉 이 구간에 속한 노드 각각은 이 그룹에 최대 2^k번만 기여하며, 구간에 속한 노드 수가 최대 n/2^k이므로 이 구간 전체의 기여는 최대 O(n)이다.
- log* n의 값은 최대 log* n가지 구간으로 나뉘므로, 전체 합은 O(n log* n)이며, m ≥ n이므로 이는 O(m log* n) 이내다.

### 결론
- 세 그룹의 합이 모두 O(m log* n) 이내이므로, union by rank와 경로 압축을 함께 사용한 서로소 집합 자료구조의 m번 연산 총 실행 시간은 O(m log* n)이다.
- 연산 1회당 상환 실행 시간은 O(log* n)이며, log* n은 매우 느리게 증가하는 함수이므로(현실적인 모든 n에 대해 최대 5) 사실상 상수 시간에 가까운 매우 효율적인 자료구조다.

## 예시
- 어떤 트리에서 rank가 각각 0, 1, 0인 노드 5(루트), 2, 3, 6이 있을 때 `Find(6)`을 호출하면 6이 루트 5에 바로 매달린다. 이때 실제 높이는 줄어들지만 rank 값(2 등)은 그대로 유지된다.
- 간선 분류 예: 경로 위 두 노드의 rank가 17과 21이고 log*(17) = log*(21)이면 이 간선은 그룹 3(log* 값 동일)에 속하고, rank가 14와 17이고 log* 값이 다르면 그룹 2(log* 값 증가)에 속한다.

## 요약
- 경로 압축을 쓰면 rank는 더 이상 실제 높이와 같지 않지만 여전히 그 상한이며, rank가 k인 루트의 서브트리는 여전히 최소 2^k개의 노드를 가진다는 성질은 유지된다.
- `Find`가 지나가는 간선을 세 그룹(루트 직행, log* 증가, log* 동일)으로 나누어 각각 O(m log* n) 이내임을 보이면, 전체 m번 연산의 총 실행 시간이 O(m log* n)임이 증명된다.
- 결과적으로 union by rank와 경로 압축을 함께 사용하면 서로소 집합 연산의 상환 실행 시간은 O(log* n)으로, 현실적으로 상수 시간과 다름없다.
