# Arrays

## 개요
- 배열(array)은 메모리상에서 연속된(contiguous) 하나의 덩어리이며, 동일한 크기의 원소들이 연속된 정수로 인덱싱된다.
- 이 세 가지 특성(연속된 메모리, 동일 크기 원소, 연속된 정수 인덱스) 덕분에 임의의 원소에 대해 산술 연산만으로 주소를 계산할 수 있어 상수 시간 접근(random access)이 가능하다.
- 배열 끝에서의 추가/삭제는 O(1)이지만, 중간이나 앞부분에서의 추가/삭제는 O(n)이다.

## 내용

### 배열의 정의
- 배열은 하나의 연속된 메모리 영역(스택이든 힙이든 상관없음)이다.
- 동일한 크기의 원소들로 나뉘어 있다.
- 각 원소는 연속된 정수로 인덱싱된다.
- 언어에 따라 0 기반 인덱싱(zero-based indexing) 또는 1 기반 인덱싱(one-based indexing)을 사용하며, 초기 인덱스를 임의로 지정할 수 있는 언어도 있다.

### 랜덤 액세스와 주소 계산
- 배열의 핵심 특징은 랜덤 액세스(random access), 즉 어떤 원소든 읽기·쓰기 모두 상수 시간(O(1))으로 접근 가능하다는 점이다.
- 원소의 주소는 `배열의 시작 주소 + 원소 크기 × (인덱스 - 첫 인덱스)`로 계산한다.
- 원소 크기가 모두 동일하기 때문에 이 곱셈 하나로 주소를 구할 수 있다. 만약 원소 크기가 제각각이라면 n개의 원소 크기를 모두 더해야 하므로 O(n)이 걸린다.

### 다차원 배열과 메모리 레이아웃
- 2차원 배열의 원소 (행, 열)의 주소도 비슷한 산술로 계산할 수 있다: 건너뛰어야 할 완전한 행 수 × 열 개수 + 같은 행 내에서 건너뛸 원소 수, 그 결과에 원소 크기를 곱해 배열 시작 주소에 더한다.
- 행 우선 순서(row-major ordering): 첫 번째 행의 모든 원소를 먼저 배치하고, 그다음 두 번째 행을 배치하는 방식. 연속된 원소를 볼 때 열 인덱스가 가장 빠르게 바뀐다.
- 열 우선 순서(column-major ordering): 반대로 열 단위로 배치하는 방식. 연속된 원소를 볼 때 행 인덱스가 가장 빠르게 바뀐다.

### 연산별 시간 복잡도
- 읽기(read), 쓰기(write): O(1) — 배열의 표준적인 특징.
- 끝에 원소 추가(마지막에 삽입): O(1) — 사용 중인 원소 개수만 갱신하면 된다.
- 끝의 원소 제거: O(1) — 마찬가지로 개수만 갱신.
- 맨 앞에서 원소 제거/삽입: O(n) — 나머지 원소들을 한 칸씩 이동시켜야 하므로.
- 중간에서 원소 추가/삭제: O(n) — 정확히 중간이라면 n/2개의 원소를 이동해야 하며, 이는 여전히 O(n)이다.

## 예시
- 2차원 배열에서 인덱스가 (1,1)부터 시작하고 3행 4열(즉 인덱스 (3,4))의 주소를 구하는 경우 (한 행에 6개의 열이 있다고 가정):
  - 건너뛸 완전한 행 수: (3 - 1) = 2행 → 2 × 6 = 12개 원소
  - 같은 행에서 (3,4) 이전에 건너뛸 원소 수: (4 - 1) = 3개
  - 총 건너뛸 원소 수: 12 + 3 = 15
  - 최종 주소 = 배열 시작 주소 + 15 × 원소 크기

## 요약
- 배열은 연속된 메모리, 동일 크기 원소, 연속된 정수 인덱스라는 세 조건 덕분에 O(1) 랜덤 액세스가 가능하다.
- 끝에서의 추가/삭제는 O(1), 그 외 위치(앞이나 중간)에서의 추가/삭제는 모두 O(n)이다.
- 다차원 배열은 행 우선(row-major) 또는 열 우선(column-major) 순서로 메모리에 저장되며, 두 경우 모두 산술 계산으로 주소를 구할 수 있다.
