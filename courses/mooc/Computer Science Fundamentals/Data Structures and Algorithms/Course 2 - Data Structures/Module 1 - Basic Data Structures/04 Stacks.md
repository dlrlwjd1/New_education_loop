# Stacks

## 개요
- 스택(stack)은 가장 나중에 넣은 원소를 가장 먼저 꺼내는 추상 자료형(abstract data type)으로, LIFO(Last In First Out)라고 부른다.
- 책 더미에 책을 쌓거나 맨 위 책을 꺼내는 것처럼, 맨 위 원소만 접근·추가·제거할 수 있다.
- 배열이나 연결 리스트로 구현할 수 있으며, 두 방식 모두 모든 연산이 O(1)이다.

## 내용

### 기본 연산
- Push(key): 새 key를 스택에 추가한다.
- Top: 가장 최근에 추가된 key를 반환한다(제거하지 않음).
- Pop: 가장 최근에 추가된 key를 반환하면서 제거한다.
- Empty: 스택이 비어있는지 확인한다.
- 이 연산들을 조합해 사용할 수 있다.

### 활용 예시: 괄호 짝 맞추기(balanced brackets)
- 문자열에 있는 소괄호 `()`와 대괄호 `[]`가 모두 순서에 맞게 짝지어져 있는지(balanced) 판별하는 문제다.
- 짝이 맞으려면 각 여는 괄호에 대응하는 닫는 괄호가 있어야 하고, 순서가 교차되면 안 된다.
- 알고리즘: 문자열을 순회하며 여는 괄호(`(`, `[`)를 만나면 스택에 push한다. 닫는 괄호를 만났을 때 스택이 비어있으면 짝이 없는 것이므로 불균형이다. 스택이 비어있지 않다면 pop한 원소가 현재 닫는 괄호와 짝이 맞는지 확인하고, 맞지 않으면 불균형이다.
- 문자열을 모두 순회한 뒤에도 스택이 비어있지 않다면(예: `(((` 처럼 여는 괄호만 있는 경우) 짝이 맞지 않는 것이므로, 마지막에 스택이 비었는지 확인해야 한다.
- 스택은 아직 짝지어지지 않은 괄호들을 순서대로 보관하는 역할을 하며, 가장 바깥쪽 괄호가 스택 맨 아래에, 가장 최근에 열린(가장 안쪽) 괄호가 맨 위에 위치한다.
- 스택은 이 문제 외에도 컴파일러 등 다양한 알고리즘에서 널리 사용된다.

### 배열을 이용한 구현
- 최대 크기를 가진 배열을 미리 할당하고, 현재 사용 중인 원소 개수(numElements)를 별도로 관리한다.
- Push: 배열의 numElements 위치에 값을 넣고 numElements를 증가시킨다 — O(1).
- Top: 배열의 (numElements - 1) 위치 값을 반환한다 — O(1).
- Pop: 배열의 (numElements - 1) 위치 값을 반환하며 지우고 numElements를 감소시킨다 — O(1).
- 배열이 가득 찬 상태에서 Push하면 에러가 발생한다(최대 크기 제한).
- Empty: numElements가 0보다 큰지 확인 — O(1).
- 단점: 미리 정해진 최대 크기를 넘을 수 없고, 크게 할당하면 사용하지 않는 공간이 낭비될 수 있다.

### 연결 리스트를 이용한 구현
- 연결 리스트의 각 노드가 스택의 한 원소를 표현한다.
- Push는 리스트의 PushFront로, Top은 TopFront로, Pop은 TopFront와 PopFront의 조합으로, Empty는 리스트의 Empty로 그대로 대응된다.
- 장점: 사용 가능한 메모리가 있는 한 크기 제한 없이 계속 추가할 수 있어 낭비되는 공간이 없다.
- 단점: 각 원소마다 포인터를 저장해야 하므로 배열 방식보다 원소당 오버헤드(overhead)가 있다.

## 예시
- 배열 구현 시나리오: 크기 5인 배열에 Push(a), Push(b)를 하면 numElements=2, Top은 b를 반환. Push(c) 후 Pop을 하면 c를 반환하고 제거하며 numElements는 다시 2가 된다. 이후 두 번 더 Push하면 배열이 가득 차 numElements=5가 되고, 이 상태에서 추가 Push는 에러가 된다.
- 각 구현 방식의 시간 복잡도: Push, Top, Pop, Empty 모두 배열/연결 리스트 구현 둘 다 O(1)이다. 차이는 최대 크기 제약(배열은 있음, 연결 리스트는 없음)과 메모리 오버헤드(배열은 미사용 공간 낭비 가능, 연결 리스트는 포인터당 오버헤드)에 있다.

## 요약
- 스택은 Push, Top, Pop, Empty 연산을 갖는 LIFO(Last In First Out) 추상 자료형이다.
- 괄호 짝 맞추기처럼 이전에 발생한 것을 특정 순서로 기억해야 하는 문제에 유용하다.
- 배열 또는 연결 리스트로 구현할 수 있고, 두 방식 모두 모든 연산이 O(1)이지만, 배열은 최대 크기 제한과 공간 낭비 가능성이, 연결 리스트는 포인터 오버헤드가 각각의 트레이드오프다.
