# Doubly-Linked Lists

## 개요
- 단일 연결 리스트(singly-linked list)는 PopBack과 AddBefore가 이전 노드를 알 수 없어 O(n)이었다.
- 이중 연결 리스트(doubly-linked list)는 각 노드에 next 포인터뿐 아니라 prev(이전) 포인터를 추가해 양방향으로 이동할 수 있게 함으로써 이 문제를 해결한다.

## 내용

### 구조
- 노드는 key, next 포인터, prev 포인터로 구성된다.
- 예를 들어 값이 10인 노드의 next가 4를 가리키고, prev가 7을 가리키는 식으로 각 노드가 양쪽 방향의 연결 정보를 모두 갖는다.
- next만 관리하면 되던 단일 연결 리스트와 달리, 모든 삽입·삭제 연산에서 prev와 next를 함께 갱신해야 하므로 코드가 다소 복잡해진다.

### PushBack (뒤에 추가)
- 새 노드를 할당한다.
- tail이 nil(빈 리스트)이면 새 노드의 prev, next를 모두 nil로 설정하고 head와 tail이 모두 이 노드를 가리키게 한다.
- 그렇지 않으면 기존 tail의 next를 새 노드로 연결하고, 새 노드의 prev를 기존 tail로 설정한 뒤, tail 포인터를 새 노드로 갱신한다.

### PopBack (뒤에서 제거)
- 빈 리스트면 에러, 원소가 하나뿐이면 단순 처리한다.
- 그 외의 경우: prev 포인터 덕분에 tail의 이전 노드를 O(1)에 바로 찾을 수 있다. tail을 이전 노드로 갱신하고, 그 노드의 next를 nil로 설정한 뒤 기존 tail 노드를 제거한다.
- 단일 연결 리스트에서는 이전 노드를 찾으려면 head부터 순회해야 해 O(n)이었지만, 이중 연결 리스트에서는 prev 포인터로 바로 접근하므로 O(1)이 된다.

### AddAfter와 AddBefore
- AddAfter(특정 노드 뒤에 삽입): prev 포인터까지 유지해야 한다는 점만 빼면 기존과 유사하게 O(1).
- AddBefore(특정 노드 앞에 삽입): 새 노드를 할당하고, 새 노드의 prev를 기존 노드의 prev로 설정한 뒤, 기존 이전 노드의 next를 새 노드로 연결한다. prev 포인터가 있으므로 이전 노드를 순회 없이 바로 알 수 있어 O(1)이 된다. 만약 head 앞에 삽입하는 경우라면 head 포인터도 갱신해야 한다.

### 배열 vs 연결 리스트 비교
- 배열은 임의 접근(random access)이 O(1)이라 이진 탐색(binary search)처럼 중간 원소로 바로 이동해 탐색 범위를 좁혀나갈 수 있다.
- 연결 리스트는 중간 원소를 찾으려면 head나 tail에서부터 순회해야 하므로 임의의 원소를 찾는 데 O(n)이 걸린다. 원소들이 배열처럼 연속된 메모리에 있지 않고, 개별적으로 할당된 메모리 위치를 포인터로 연결한 구조이기 때문이다.
- 반면 연결 리스트는 앞쪽에서의 삽입/제거가 항상 O(1)이다. 배열은 앞쪽 삽입/제거 시 나머지 원소들을 모두 옮겨야 해 O(n)이 걸린다.
- tail 포인터가 있는 이중 연결 리스트는 뒤쪽에서의 삽입/제거(PushBack, PopBack)도 O(1)이며, 임의의 두 노드 사이에 삽입하거나 특정 노드를 제거하는 것도 O(1)이다.

## 예시
- 연산별 시간 복잡도 요약 (tail과 prev 포인터를 모두 갖춘 이중 연결 리스트 기준):
  - PushBack: O(1)
  - PopBack: O(1) — 단일 연결 리스트에서는 O(n)이었음
  - AddAfter: O(1)
  - AddBefore: O(1) — 단일 연결 리스트에서는 O(n)이었음
  - 임의 원소 탐색(중간 원소 접근): O(n) — 배열의 O(1)과 대조됨
  - 노드 사이 삽입/제거: O(1)

## 요약
- 이중 연결 리스트(doubly-linked list)는 next와 prev 포인터를 모두 사용해 양방향 이동을 지원한다.
- 이를 통해 단일 연결 리스트의 약점이었던 PopBack과 AddBefore를 모두 O(1)로 개선한다.
- 다만 배열과 달리 임의 원소에 대한 상수 시간 접근(random access)은 여전히 불가능하며, 이는 O(n)으로 남는다.
- 대신 앞/뒤 삽입·삭제, 노드 사이 삽입·삭제는 모두 O(1)이라는 것이 연결 리스트의 강점이다.
