# Final Remarks

## 개요
- 배낭 문제(knapsack problem) 강의를 마무리하며 두 가지 중요한 주제를 다룬다: 메모이제이션(memoization) 기법과, 배낭 문제 알고리즘의 실제 실행 시간이 다항 시간(polynomial time)이 아니라는 사실.

## 내용

### 상향식(bottom-up) vs 하향식(top-down) 접근
- 동적 계획법 알고리즘을 설계할 때는 먼저 최적해의 구조를 분석해 하위 문제(subproblem)를 정의하고, 이를 더 작은 하위 문제로 표현하는 점화식(recurrence relation)을 세운다.
- 이 점화식을 반복적(iterative) 알고리즘으로 구현하면, 작은 하위 문제부터 큰 하위 문제 순으로 모두 풀어나가므로 **상향식(bottom-up) 알고리즘**이라 부른다.
- 반대로 재귀적(recursive) 알고리즘은 하위 문제를 풀기 위해 더 작은 하위 문제를 재귀 호출로 푸는 방식이며, 이를 **하향식(top-down) 접근**이라 부른다.

### 메모이제이션(memoization)
- 재귀 알고리즘을 그대로(naively) 구현하면 동일한 하위 문제를 수없이 반복 계산하게 되어 매우 느려질 수 있다.
- 메모이제이션(memoization)은 이를 방지하는 기법이다: 하위 문제를 풀 때마다 그 해를 테이블(예: hash table)에 저장하고, 재귀 호출 시 먼저 테이블에 이미 계산된 값이 있는지 확인한다. 있으면 즉시 반환(테이블 조회, table look up)하고, 없으면 계산 후 저장한다.
- 반복 허용 배낭 문제(knapsack with repetitions)를 예로 든 재귀 절차:
  1. hash table에 무게 w에 대한 `value(w)`가 이미 있는지 확인한다.
  2. 있으면 즉시 반환한다.
  3. 없으면 `value(w - wi)`를 구하는 재귀 호출을 통해 계산하고, 결과를 hash table에 저장한다.
- 상향식 알고리즘과 하향식(메모이제이션) 알고리즘은 전체 하위 문제 범위를 모두 풀어야 하는 경우 사실상 동일한 일을 하지만, 재귀 알고리즘은 함수 호출 시 리턴 주소(return address)를 스택에 쌓는 등 오버헤드(overhead)가 있어 다소 느릴 수 있다.
- 그러나 모든 하위 문제를 풀 필요가 없는 경우도 있으며, 배낭 문제가 좋은 예다. 예를 들어 n개 아이템의 무게와 배낭의 총 무게가 모두 100으로 나누어떨어진다면, 100으로 나누어떨어지지 않는 무게의 하위 문제는 애초에 필요하지 않다. 상향식 알고리즘은 이런 불필요한 하위 문제까지 전부 풀지만, 재귀(메모이제이션) 알고리즘은 실제로 필요한 하위 문제(100으로 나누어떨어지는 무게)만 재귀 호출한다.

### 실행 시간에 대한 진실 — 실제로는 지수 시간(exponential time)
- 앞서 설계한 알고리즘의 실행 시간은 O(n × W)로, 다항식(polynomial)처럼 보이지만 실제로는 그렇지 않다.
- 예를 들어 배낭의 총 무게 W가 10^20 규모(20자리 십진수)인 입력을 생각해보자. 입력 크기는 겨우 20자리(디지트) 수준으로 매우 작지만, 알고리즘은 대략 10^20번의 연산을 수행해야 한다. 이는 일반 노트북으로 처리할 수 없는 규모다.
- 이유는 W를 표현하는 데 필요한 자릿수가 log W이기 때문이다. 즉, 배낭 문제의 입력 크기는 n + W가 아니라 **n + log W**에 비례한다.
- 실행 시간을 n과 log W로 표현하면 `n × 2^(log W)`가 되며, 이는 사실상 **지수 시간(exponential time) 알고리즘**이다.
- 즉 이 알고리즘은 W가 충분히 크지 않을 때(대략 10억, 1 billion 미만)만 처리 가능하다.
- 배낭 문제를 진정한 다항 시간(truly polynomial time)에 푸는 알고리즘을 만드는 것은 매우 어렵다고 여겨지며, 이런 부류의 문제를 다항 시간에 풀면 100만 달러(1 million dollars)의 상금을 받게 된다는 사실이 이후 강의에서 다뤄진다.

## 요약
- 동적 계획법은 상향식(iterative, bottom-up) 또는 하향식(recursive, top-down) 방식으로 구현할 수 있으며, 하향식에서는 메모이제이션(memoization)으로 중복 계산을 피한다.
- 메모이제이션은 hash table에 계산된 값을 저장해 재귀 호출을 테이블 조회로 대체하는 기법이다.
- 필요한 하위 문제만 계산하면 되는 경우, 재귀+메모이제이션 방식이 모든 하위 문제를 계산하는 상향식 방식보다 유리할 수 있다.
- 배낭 문제 알고리즘의 실행 시간 O(n × W)는 입력 크기 기준(n + log W)으로 보면 사실상 지수 시간(n × 2^(log W))이다.
