# Reconstructing a Solution

## 개요
- 동적 계획법 알고리즘이 계산한 두 테이블 m(최솟값), M(최댓값)으로부터 실제 최적 괄호 배치(parenthesizing) 자체를 재구성(reconstructing)하는 방법을 다룬다.

## 내용

### 재구성의 기본 아이디어 — 역추적(back tracing)
- 토이 예제 `5 - 8 + 7 × 4 - 8 + 9` (숫자 6개)에서 `M(1,6) = 200`이 전체 표현식의 최댓값이다.
- 목표는 이 200이라는 값이 어느 두 부분식으로부터, 어떤 연산으로 계산되었는지를 테이블에서 역추적하여 전체 괄호 배치를 복원하는 것이다.

### 1단계: M(1,6) = 200의 유래 찾기
- M(1,6)을 계산할 때 시도했던 모든 분할 중 하나를 확인한다.
- 분할: (1,1)과 (2,6), 연산은 뺄셈(minus).
  - (1,1)의 최솟값·최댓값은 모두 5.
  - (2,6)의 최솟값은 -195, 최댓값은 75.
- `부분식1 - 부분식2`를 최대화하려면 부분식1은 최대(5), 부분식2는 최소(-195)로 만들어야 한다.
- `5 - (-195) = 5 + 195 = 200` → 일치! 따라서 마지막 연산은 이 뺄셈이며, 첫 번째 부분식은 5, 두 번째 부분식은 -195를 만들어야 함을 확인.

### 2단계: (2,6)에서 -195의 유래 찾기
- (2,6)을 분할하는 여러 방법을 시도한다.
- 시도 1: (2,2)와 (3,6), 연산 덧셈. (2,2)의 최솟값 8, (3,6)의 최솟값 -91. 합은 8 + (-91) = -83 ≠ -195 → 이 분할은 아님.
- 시도 2: (2,3)과 (4,6), 연산 곱셈.
  - (2,3)의 최솟값·최댓값은 모두 15.
  - (4,6)의 최솟값은 -13, 최댓값은 5.
  - 곱을 최소화하려면 15 × (-13) = -195 → 일치! 이 분할이 정답.
- 즉, (2,6) = (8+7) × (4-(8+9))이며, 8+7 = 15, 그리고 (4-(8+9))가 -13이 되어야 함.

### 3단계: (4,6)에서 -13의 유래 찾기
- (4,6) = `4-8+9`는 이미 작은 표현식이므로 쉽게 확인: 먼저 `8+9`를 계산해 17을 얻고, `4 - 17 = -13`.

### 최종 재구성된 순서와 검증
- 재구성된 연산 순서: ① 8+9=17 → ② 4-17=-13 → ③ 8+7=15 → ④ 15×(-13)=-195 → ⑤ 5-(-195)=200.
- 검증: 8+9=17, 4-17=-13, 8+7=15, 15×(-13)=-195, 5-(-195)=200 → 최댓값 200과 정확히 일치.

### 재구성 알고리즘의 실행 시간
- n개의 숫자, n-1개의 연산을 갖는 표현식에서, 마지막 연산부터 첫 연산까지 순서대로 n-1개의 연산을 복원해야 한다.
- 각 연산에 대해 최악의 경우 모든 가능한 분할(최대 n가지)을 확인해야 할 수 있다.
- 따라서 재구성 알고리즘의 실행 시간은 대략 **O(n × n) = O(n²)** (2차, quadratic)이다.
- 이 역추적(back tracing) 기법은 매우 일반적이며 다양한 동적 계획법 알고리즘에서 최적해 자체를 복원하는 데 널리 쓰인다.

## 예시
- 위 "1~3단계"에서 다룬 `5 - 8 + 7 × 4 - 8 + 9`의 역추적 과정 전체가 하나의 완결된 예시다. 최종적으로 `5 - ((8+7) × (4-(8+9))) = 200`이라는 괄호 배치가 복원된다.

## 요약
- 최적값이 저장된 M, m 테이블을 이용해, 마지막 연산부터 역방향으로 어떤 분할과 어떤 최댓값/최솟값 조합이 그 값을 만들어냈는지 확인하는 방식으로 실제 괄호 배치를 재구성(reconstruction)한다.
- 재구성 알고리즘의 실행 시간은 O(n²)이며, 이 역추적 기법은 동적 계획법 전반에서 널리 사용되는 일반적인 기법이다.
