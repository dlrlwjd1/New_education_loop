# Problem Overview

## 개요
- 그리디 알고리즘(Greedy Algorithms) 모듈에서 다뤘던 배낭 문제(knapsack problem)를 다시 살펴본다.
- 배낭 문제의 정의를 복습하고, 실생활 응용 예시를 통해 문제를 동기부여한 뒤, 이번에는 동적 계획법(dynamic programming)으로 해결한다.

## 내용

### 실생활 예시
- **TV 광고 편성**: 주어진 시간 슬롯(예: 2~3분)과 여러 TV 광고가 있을 때, 각 광고는 수익(revenue)과 길이(duration, 분 단위)를 가진다. 총 길이가 시간 슬롯을 넘지 않으면서 총 수익을 최대화하는 광고의 부분집합을 선택해야 한다.
- **컴퓨터 구매**: 고정된 예산이 주어지고, 여러 컴퓨터(각각 가격과 성능을 가짐) 중에서 총 성능을 최대화하도록 구매할 컴퓨터 집합을 선택해야 한다.
- 두 예시 모두 아래에서 정의하는 일반적인 배낭 문제(Knapsack Problem)의 특수한 경우다.

### 배낭 문제의 정의
- 입력: 아이템 집합(각 아이템은 가치value와 무게weight를 가짐), 배낭의 총 용량(capacity).
- 목표: 총 무게가 배낭의 용량을 넘지 않으면서 총 가치가 최대가 되는 아이템의 부분집합을 선택.
- 예시에서 초록색 아이템의 가치는 4, 무게는 12이며, 배낭의 총 용량은 15다.

### 배낭 문제의 두 가지 버전
- **분할 가능 배낭(fractional knapsack)**: 아이템의 일부(fraction)만 가져갈 수 있다. 이미 그리디 알고리즘으로 풀 수 있음을 알고 있다 — 매 단계에서 무게 대비 가치(value per unit of weight)가 가장 큰 아이템을 선택하는 방식이다.
- **이산 배낭(discrete knapsack)**: 각 아이템은 전부 가져가거나 전혀 가져가지 않는다(all or nothing). 여기에는 다시 두 가지 변형이 있다.
  - **반복 허용 배낭(knapsack with repetitions)**: 각 아이템을 무제한으로 가져갈 수 있다.
  - **반복 불허 배낭(knapsack without repetitions)**: 각 아이템은 단 하나의 사본(single copy)만 존재한다.
- 이산 버전에서는 그리디 전략이 통하지 않으므로, 동적 계획법(dynamic programming) 솔루션을 설계한다.

### 토이 예제로 본 그리디 알고리즘의 실패
- 배낭 총 용량 10, 아이템 4개가 주어진 예제:
  - 반복 불허(without repetitions) 최적값: 46 (첫 번째 아이템 + 세 번째 아이템)
  - 반복 허용(with repetitions) 최적값: 48 (첫 번째 아이템 1개 + 마지막 아이템 2개)
  - 분할 가능(fractional) 최적값: 48.5 (첫 번째 + 두 번째 아이템 + 마지막 아이템의 절반)
- 그리디 전략(무게 대비 가치가 가장 큰 아이템부터 선택)을 적용하면:
  - 무게 대비 가치: 첫 번째 아이템 5, 두 번째 아이템 4와 3분의 2, 세 번째 아이템 4, 네 번째(마지막) 아이템 4와 2분의 1.
  - 첫 번째와 두 번째 아이템을 선택 → 총 가치 44 (최적값 46보다 작음).
  - 두 번째 아이템을 세 번째 아이템으로 바꾸면 총 가치가 더 커지므로, 무게 대비 가치가 최대인 아이템을 선택하는 것은 안전한 단계(safe step)가 아니다.

## 요약
- 배낭 문제는 분할 가능(fractional) 버전과 이산(discrete) 버전으로 나뉘며, 이산 버전은 다시 반복 허용(with repetitions)과 반복 불허(without repetitions)로 나뉜다.
- 분할 가능 배낭은 그리디 알고리즘으로 최적해를 구할 수 있지만, 이산 배낭에서는 그리디 전략이 최적해를 보장하지 못한다.
- 이산 배낭 문제는 동적 계획법(dynamic programming)으로 해결하며, 다음 영상에서 구체적인 알고리즘을 다룬다.
