# Knapsack without Repetitions

## 개요
- 반복 불허 배낭 문제(knapsack without repetitions)에 대한 동적 계획법(dynamic programming) 알고리즘을 설계한다.
- 이 문제에서는 각 아이템의 사본(copy)이 단 하나만 주어진다.

## 내용

### 이전 알고리즘이 통하지 않는 이유
- 토이 예제에서 반복 허용(with repetitions) 최적값은 48이었지만, 반복 불허(without repetitions) 최적값은 46이다. 따라서 이전 알고리즘을 그대로 쓰면 잘못된 결과가 나온다.
- 총 무게 W인 배낭의 최적 부분집합이 n번째(마지막) 아이템을 포함한다고 가정하고 이를 꺼내면, 남은 것은 무게 W - wn인 더 작은 배낭의 최적해여야 한다.
- 문제는, 이 더 작은 배낭의 최적해가 이미 n번째 아이템을 포함하고 있을 수 있다는 것이다. 그러면 n번째 아이템을 다시 추가할 수 없다(반복이 금지되므로 사본이 두 개가 되어버림).
- 따라서 하위 문제(subproblem)의 정의를 다르게 잡아야 한다.

### 두 가지 경우 분석
- 총 무게 W인 배낭의 최적해는 다음 두 경우 중 하나다.
  1. n번째 아이템을 포함하는 경우: 이를 제거하면 남은 것은 무게 W - wn이면서 1부터 n-1번 아이템만 사용하는 최적해.
  2. n번째 아이템을 포함하지 않는 경우: 그 최적해는 1부터 n-1번 아이템만 사용한다.
- 이 관찰을 통해, 사용 가능한 아이템 개수와 배낭 무게를 함께 파라미터로 삼는 하위 문제 정의가 필요함을 알 수 있다.

### 하위 문제 정의와 점화식
- 0부터 W까지의 모든 w와 0부터 n까지의 모든 i에 대해, `value(w, i)`를 "1번부터 i번까지의 아이템만 사용하고 총 무게가 w 이하일 때의 최적 총 가치"로 정의한다.
- 점화식:
  ```
  value(w, i) = max(
      value(w - wi, i-1) + vi,   # i번째 아이템을 사용하는 경우
      value(w, i-1)              # i번째 아이템을 사용하지 않는 경우
  )
  ```
- i번째 아이템을 사용하는 경우 그 아이템을 제거하면 남은 것은 1부터 i-1까지의 아이템만으로 무게 w - wi 이하를 채우는 최적해다.
- i번째 아이템을 사용하지 않는 경우, 값은 1부터 i-1까지 아이템만 사용하는 무게 w의 최적해와 동일하다.

### 알고리즘(의사코드)
- 초기화: 아이템이 0개일 때(`value(j, 0) = 0`, 모든 j)와 배낭 무게가 0일 때(`value(0, w) = 0`, 모든 w)는 0.
- 바깥 루프: i를 1부터 n까지 증가.
- 안쪽 루프: w를 1부터 W까지 증가.
  - `value(w, i) = value(w, i-1)`로 우선 설정.
  - 만약 `wi ≤ w`이면, `value(w - wi, i-1) + vi`를 계산해 현재 값보다 크면 갱신.
- 최종적으로 `value(W, n)`을 반환 (모든 n개 아이템을 사용할 수 있는 총 용량 W 배낭의 해).

### 실행 시간(running time)
- 두 개의 중첩 루프(바깥 n번, 안쪽 W번)와 내부 상수 시간 연산으로 인해 실행 시간은 반복 허용 버전과 동일한 **O(n × W)**.

## 예시
- 토이 예제: 배낭 총 용량 10, 아이템 4개. 2차원 테이블(행 = i, 열 = w)에 `value(w, i)`를 저장한다.
- 첫 번째 행과 첫 번째 열은 모두 0으로 초기화한 뒤, 행 단위로(row by row) 채운다. 최종적으로 `value(10, 4) = 46`을 얻는다.
- 예시 계산: `value(10, 2)`는 "무게 10 이하, 처음 두 아이템만 사용"의 최적값.
  - 두 번째 아이템을 사용하지 않으면 `value(10, 1) = 30`.
  - 두 번째 아이템(무게 3, 가치 14)을 사용하면 `value(7, 1) + 14 = 30 + 14 = 44`.
  - 더 큰 값인 44가 `value(10, 2)`가 된다.

### 최적해 재구성(reconstructing an optimal solution)
- 어떤 아이템이 실제로 선택되었는지 표시할 boolean 배열(크기 n)을 만든다.
- `value(10, 4) = 46`부터 역추적(back trace)한다.
  - 4번째 아이템 미사용 시: `value(10, 3)`.
  - 4번째 아이템 사용 시: `value(8, 3) + v4 = 30 + 9 = 39`.
  - `max(value(10,3), 39) = 46`이므로 4번째 아이템은 **미사용**으로 판정 → boolean 배열에 0 기록.
  - 다음으로 `value(10, 3)`을 같은 방식으로 분석: 3번째 아이템을 사용하지 않는 경우와, `value(6, 2) + v3 = 30 + 16 = 46`인 경우를 비교 → 44보다 46이 크므로 3번째 아이템은 **사용**으로 판정 → 1 기록.
  - 계속하여 `value(10, 2)`를 분석: `max(30, 0+14) = 30`이 더 크므로 2번째 아이템은 **미사용**.
  - 마지막으로 남은 값 30은 왼쪽 위 모서리(첫 번째 아이템)에서 왔음을 확인.
- 최종적으로 첫 번째 아이템과 세 번째 아이템을 선택 → 총 무게 10, 총 가치 30 + 16 = 46으로 검증 완료.

## 요약
- 반복 불허 배낭 문제는 하위 문제를 `value(w, i)` (무게 w, 아이템 1~i)로 정의해야 하며, 점화식은 i번째 아이템을 사용/미사용하는 두 경우의 최댓값이다.
- 상향식 알고리즘의 실행 시간은 O(n × W)이며, 2차원 테이블을 행 단위로 채운다.
- 최적해 자체를 복원하려면 테이블 값을 역추적(back trace)하는 재구성(reconstruction) 기법을 사용한다.
