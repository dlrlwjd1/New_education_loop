# Problem Overview

## 개요
- 동적 계획법(dynamic programming) 모듈의 다음 레슨으로, "무언가의 최적 순서(optimal order)"를 찾는 넓은 범주의 문제를 다룬다.
- 이를 괄호 배치 문제(placing parentheses problem)를 통해 설명한다.

## 내용

### 괄호 배치 문제(placing parentheses problem)
- 입력: 숫자(자릿수, digits)와 산술 연산(arithmetic operations)으로 이루어진 산술 표현식(arithmetic expression).
- 목표: 이 연산들을 적용하는 순서를 정해 결과값(값, value)을 최대화하는 것.
- 순서는 괄호(parentheses)를 배치하는 방식으로 지정하기 때문에 "괄호 배치 문제"라 부른다.

### 토이 예제: 1 + 2 - 3 × 4 - 5
- 숫자 5개, 연산 4개로 구성.
- 연산 순서가 정해지면: 첫 연산을 취해 인접한 두 숫자에 적용하고 그 결과로 대체하는 과정을 반복하여 최종적으로 하나의 숫자를 얻는다.
- 예를 들어 곱셈이 먼저라면 3과 4를 곱해 12로 대체한다.
- **왼쪽부터 순서대로 계산**: `(((1+2)-3)×4)-5` → 1+2=3 → 3-3=0 → 0×4=0 → 0-5 = **-5** (최적이 아님).
- **더 나은 순서**: 3×4=12 → 12-5=7 → 1+2=3 → 3-7 = **-4** (여전히 최적은 아님).
- **최적 순서**: 4-5=-1 → -1×3=-3 → 1+2=3 → 3-(-3) = 3+3 = **6** (최적값).

### 모든 순서를 다 시도하는 방법의 한계
- 연산이 4개면 순서의 총 가짓수는 4×3×2×1 = 24가지로, 일일이 나열해 계산 가능.
- 하지만 숫자 6개, 연산 5개인 예제라면 5×4×3×2×1 = 120가지 순서를 다 확인해야 하며, 사람이 손으로 하기엔 이미 벅차다.
- 일반적으로 연산이 n개면 전수조사(brute-force)는 대략 **n!(n factorial)** 단계를 필요로 한다.
- n!은 매우 빠르게 증가하는 함수다: 예를 들어 20! ≈ 2 × 10^18. 숫자 20개짜리 표현식조차 1년이 걸려도 계산이 끝나지 않을 수 있다.
- 따라서 더 효율적인 알고리즘이 필요하며, 동적 계획법(dynamic programming)을 사용해 설계한다.

## 요약
- 괄호 배치 문제는 산술 표현식에서 연산의 적용 순서를 정해 결과값을 최대화하는 문제다.
- 모든 순서를 전수조사하면 n!(n factorial) 단계가 필요해 현실적으로 계산이 불가능해진다.
- 다음 영상부터 동적 계획법(dynamic programming)을 이용한 효율적인 알고리즘을 설계한다.
