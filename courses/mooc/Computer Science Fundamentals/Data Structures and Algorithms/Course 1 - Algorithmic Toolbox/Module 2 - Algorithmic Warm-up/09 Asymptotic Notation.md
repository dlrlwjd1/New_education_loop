# Asymptotic Notation

## 개요
- 정확한 실행 시간 계산의 복잡함을 피하기 위한 점근 표기법(asymptotic notation)의 기본 아이디어와 그 유용성을 소개한다.

## 내용
### 핵심 아이디어: 상수 배(constant multiple) 무시하기
- 실행 시간에 영향을 주는 여러 요소(컴퓨터 속도, 곱셈/덧셈 상대 속도, 메모리 계층 구조 등)는 대부분 실행 시간을 상수 배(constant multiple)로만 바꾼다.
  - 예: 100배 빠른 컴퓨터에서는 시간이 1/100이 된다. 곱셈이 덧셈보다 3배 느리면 곱셈이 많은 프로그램은 최대 3배 정도 더 걸릴 뿐이다.
- 따라서 이런 상수 배를 무시하는 실행 시간 복잡도 척도를 만들면, n 시간과 100n 시간을 "같은 것"으로 취급할 수 있어 세부 사항을 신경 쓰지 않아도 된다.

### 왜 "점근적"이어야 하는가
- 단순히 상수 배를 무시하면 문제가 생긴다: 1초, 1시간, 1년도 서로 상수 배 차이(1년 ≈ 3천만 초)일 뿐이므로, 이 기준으로는 1초짜리와 1년짜리 실행 시간을 구별할 수 없다.
- 해결책: 특정 입력에서의 실행 시간이 아니라, 입력 크기(input size) n이 커질 때 실행 시간이 어떻게 스케일(scale)되는지, 즉 점근적 실행 시간(asymptotic runtime)을 본다.
- n에 비례하는지, n²에 비례하는지, 지수적(exponential)인지에 따라 결과가 완전히 다르며, n이 충분히 크면 이 차이(n vs n²)는 어떤 상수 배 차이보다도 커진다.
  - 예: 1000n은 상수가 커 보여도 n이 매우 크면 여전히 n²보다 낫다.

### 입력 크기별 실행 시간 비교 예시 (1GHz 컴퓨터, 1초 내 처리 가능한 입력 크기)
- 실행 시간이 n에 비례: 약 10억(1 billion) 크기까지 처리 가능
- n log n에 비례: 약 3천만(30 million) 크기까지 처리 가능
- n²에 비례: 약 3만(30,000) 크기까지 처리 가능
- 2^n에 비례: 약 30 크기까지만 처리 가능 — 입력 크기 50이면 2주, 100이면 사실상 영원히 끝나지 않음

### 흔한 실행 시간들의 상대적 크기
- log n ≪ √n ≪ n ≪ n log n ≪ n² ≪ 2^n 순서로 커진다.
- 작은 입력에서는 그래프가 서로 뒤섞여 구분하기 어렵지만, 입력이 커질수록 뚜렷하게 분리된다.
- 2^n은 대략 n=4 이후 급격히 치솟아 다른 모든 것을 압도한다.
- n²은 n log n, n보다 여전히 상당히 크다.
- √n과 log n은 작은 입력에서는 비슷해 보이지만 입력이 커지면 빠르게 차이가 벌어진다(예: √1,000,000 ≈ 1000, log 1,000,000 ≈ 20).

## 예시
- 1GHz 컴퓨터에서 1초 내 처리 가능한 입력 크기 비교: n → 10억, n log n → 3천만, n² → 3만, 2^n → 30
- 흔한 실행 시간의 크기 순서: log n < √n < n < n log n < n² < 2^n

## 요약
- 점근 표기법은 실행 시간에서 상수 배를 무시하고, 입력 크기가 매우 커질 때 실행 시간이 어떻게 스케일되는지에 집중하는 방법이다.
- 이렇게 하면 컴퓨터 속도나 컴파일러 같은 세부 사항 없이도 알고리즘을 비교할 수 있다.
- n, n log n, n², 2^n 같은 서로 다른 스케일링은 입력이 커질수록 상수 배 차이보다 훨씬 더 큰 영향을 미친다.
