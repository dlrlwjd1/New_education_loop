# Big-O Notation

## 개요
- 이 강의 전반에서 가장 자주 사용할 점근 표기법인 빅오 표기법(Big-O notation)의 정의와 장단점을 설명한다.

## 내용
### 빅오의 정의
- 두 함수 f, g에 대해, 어떤 상수 N(대문자)과 c(소문자)가 존재해서 모든 n ≥ N에 대해 f(n) ≤ c·g(n)이 성립하면, f(n)은 O(g(n))이라고 한다.
- 의미: 충분히 큰 입력에 대해 f는 g의 어떤 상수 배 이하로 위에서 제한(bounded above)된다.

### 예시로 이해하기
- 3n² + 5n + 2는 O(n²)이다. n ≥ 1일 때 3n² + 5n + 2 ≤ 3n² + 5n² + 2n² = 10n²이므로 n²의 상수 배로 위에서 제한된다.
- 두 함수의 비율(ratio)을 보면, n=1일 때는 10배지만 n이 커질수록 비율은 약 3으로 줄어든다. n=100일 때 n²은 100만, 3n²+5n+2는 약 300만 조금 넘는 정도로, 최대 약 3배 정도만 차이 난다.

### 빅오 표기법의 장점
1. **성장률(growth rate)을 명확히 함**: 입력이 매우 클 때 어떻게 스케일되는지가 중요한데, 복잡한 식을 그대로 비교하면 어떤 입력에서 어느 쪽이 더 큰지 판단하기 번거롭다. 하지만 점근적으로 보면 n이 매우 클 때 어느 알고리즘이 더 나은지 훨씬 명확해진다.
2. **표기를 깔끔하게 함**: 3n²+5n+2 대신 O(n²), n+log₂(n)+sin(n) 대신 O(n), 4n log₂(n)+7 대신 O(n log n)으로 쓸 수 있다.
   - 빅오 안에서는 로그의 밑(base)을 명시할 필요가 없다. log₂(n), log₃(n), log₁₀(n), log₇(n)은 서로 상수 배 차이일 뿐이므로 빅오 관점에서 동일하다.
3. **대수 연산(algebra)이 쉬워짐**: 저차항(lower order term)을 신경 쓸 필요가 없어 식을 다루기 쉬워진다.
4. **실행 시간 계산의 복잡함 문제를 해결함**: 컴퓨터 속도, 메모리 계층 구조, 컴파일러 등은 실행 시간에 큰 영향을 주지만 대개 상수 배 차이일 뿐이며, 상수 배만 차이 나면 빅오는 동일하다.

### 빅오의 한계와 주의점
- **정보 손실**: 빅오는 상수 배에 대한 정보를 잃는다. 한 알고리즘이 다른 것보다 100배 빠르더라도 빅오가 같을 수 있다. 실제로 빠르게 만들고 싶다면, 좋은 점근적 실행 시간을 확보한 뒤에도 상수 배를 줄이는 세부적인 최적화(메모리 계층과의 상호작용 개선 등)를 추가로 고민해야 한다.
- **점근적일 뿐**: 빅오는 입력이 "정말, 정말 큰" 경우에 대해서만 말해준다. 특정 입력에 대한 실제 실행 시간은 알려주지 않는다. 점근적으로 더 나쁜 알고리즘이라도, 실제로 사용 가능한 모든 입력 크기 범위에서는 다른 알고리즘에 밀릴 수도 있다(그 "정말 큰" 크기가 컴퓨터에 저장할 수 있는 범위를 넘어설 수도 있기 때문).

## 예시
- 정의: f(n) = O(g(n)) ⟺ ∃ N, c 상수, 모든 n ≥ N에 대해 f(n) ≤ c·g(n)
- 3n² + 5n + 2 = O(n²) (n≥1일 때 3n²+5n+2 ≤ 10n²)
- 3n²+5n+2 대 n²의 비율: n=1일 때 10, n=100일 때 약 3

## 요약
- 빅오 표기법은 "충분히 큰 n에 대해 f(n)이 g(n)의 상수 배 이하"임을 나타내며, 이 강의에서 알고리즘 실행 시간을 표현하는 기본 도구로 쓰인다.
- 성장률을 명확히 하고, 표기를 단순화하며, 계산의 복잡함 문제를 해결해주지만, 상수 배 정보를 잃고 매우 큰 입력에 대해서만 의미가 있다는 한계가 있다.
