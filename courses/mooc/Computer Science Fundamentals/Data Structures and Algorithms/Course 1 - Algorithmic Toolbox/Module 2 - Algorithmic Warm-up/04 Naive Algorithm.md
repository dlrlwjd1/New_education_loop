# Naive Algorithm

## 개요
- 피보나치 수를 정의를 그대로 옮겨 만든 나이브 재귀 알고리즘(naive recursive algorithm)을 제시하고, 이 알고리즘이 정확하지만 실행 시간이 지수적으로 느리다는 것을 보인다.

## 내용
### 나이브 알고리즘
- 정의: n이 0이면 0을, n이 1이면 1을 반환한다. 그 외에는 (n-1)번째와 (n-2)번째 피보나치 수를 재귀적으로 계산해 더한 값을 반환한다.
- n이 1 이하이면 n을 그대로 반환하고, 그렇지 않으면 두 재귀 호출의 합을 반환하는 단 4줄짜리 알고리즘으로, 정의를 그대로 코드로 옮긴 형태다.

### 실행 시간 분석
- 실행 시간을 실행되는 코드 줄 수 T(n)으로 근사해서 측정한다.
- n ≤ 1이면 if문 확인 후 return까지 2줄이 실행되므로 T(n) = 2.
- n ≥ 2이면 if, else, return에 3줄이 실행되고, 여기에 F(n-1), F(n-2)를 구하는 재귀 호출의 실행 줄 수가 더해진다.
- 따라서 재귀식(recursive formula)은 다음과 같다.
  - T(n) = 2, n ≤ 1일 때
  - T(n) = T(n-1) + T(n-2) + 3, n ≥ 2일 때
- 이 식은 피보나치 수를 정의하는 식과 형태가 매우 비슷하며, 이로부터 T(n)이 모든 n에 대해 n번째 피보나치 수 이상임을 쉽게 보일 수 있다.
- 피보나치 수가 매우 크게 자란다는 것을 이미 알고 있으므로, T(n) 역시 매우 커진다.
- 실제로 T(100)은 약 1.77×10^21(1.77 sextillion)에 달한다.
- 1초에 10억(1 gigahertz) 줄을 처리하는 컴퓨터로 실행해도 이 계산에는 약 56,000년이 걸린다 — 실용적으로 받아들일 수 없는 수준이다.

### 느린 이유: 중복 계산
- 재귀 호출 트리(tree of recursive calls)를 그려보면, 같은 값을 여러 번 반복 계산하고 있음을 알 수 있다.
- 예를 들어 F(n-3)은 이 트리에서 3번, F(n-4)는 5번 별도로 계산된다.
- 트리를 더 아래로 내려갈수록 동일한 값이 훨씬 더 많이 반복 계산되며, 이것이 알고리즘이 느린 근본 원인이다.
- 재귀 호출마다 처음부터 다시 계산하기 때문에 이런 중복이 발생한다.

## 예시
- T(n)의 재귀식: T(n) = 2 (n ≤ 1), T(n) = T(n-1) + T(n-2) + 3 (n ≥ 2)
- T(100) ≈ 1.77 × 10^21
- 1GHz 컴퓨터 기준 예상 실행 시간: 약 56,000년

## 요약
- 나이브 알고리즘은 정의를 그대로 재귀 코드로 옮긴 것으로 정확하게 동작하지만, 동일한 하위 문제를 반복 계산하기 때문에 실행 시간이 피보나치 수 자체만큼 지수적으로 커진다.
- 이 문제를 해결하려면 중복 계산을 없애는 더 나은 알고리즘이 필요하며, 이는 다음 강의에서 다룬다.
