# Efficient Algorithm

## 개요
- 유클리드 알고리즘(Euclidean algorithm)을 이용해 최대공약수(GCD)를 훨씬 효율적으로 계산하는 방법과 그 실행 시간을 다룬다.

## 내용
### 핵심 보조정리(Key Lemma)
- a를 b로 나눈 나머지를 a'이라 하면, GCD(a, b) = GCD(a', b) = GCD(b, a')이 성립한다.
- 증명: a'이 나머지이므로 a = a' + bq (q는 몫)로 쓸 수 있다. d가 a'과 b를 모두 나누면 a' + bq(=a)도 나누므로, a와 b의 공약수 집합은 a'과 b의 공약수 집합과 정확히 같다. 따라서 두 쌍의 최대공약수도 같다.

### 유클리드 알고리즘
- 아이디어: GCD(a, b) = GCD(b, a')이고, a'은 일반적으로 a보다 작으므로 더 작은 문제로 재귀적으로 축소해간다.
- 기저 사례(base case): b = 0이면 모든 수가 0을 나누므로, a를 나누는 가장 큰 수인 a 자신을 반환한다.
- 재귀 단계: b ≠ 0이면 a'을 a를 b로 나눈 나머지로 두고, GCD(b, a')을 재귀적으로 계산해 반환한다.
- 앞서 증명한 보조정리에 의해, 이 알고리즘이 답을 반환한다면 그 답은 항상 올바르다.

### 실행 시간
- 나머지를 취하는 나눗셈을 한 번 할 때마다 관련된 수의 크기가 대략 절반(factor of 2)으로 줄어든다.
- 매 단계마다 크기가 절반이 된다면, 대략 log(ab)번의 단계 후에는 수가 매우 작아지거나 0이 되어 알고리즘이 종료된다.
- 예를 들어 100자리 숫자의 GCD를 구한다면 약 600단계면 충분하며, 각 단계는 나머지를 구하는 나눗셈 한 번뿐이므로 어떤 컴퓨터에서도 사실상 즉시 처리된다.

### 이 사례가 보여주는 것
- 나이브 알고리즘은 정의에서 바로 나온 단순한 알고리즘이지만 너무 느렸다.
- 유클리드 알고리즘은 훨씬 빠르고 실용적이다.
- 여기서 특히 중요한 점은, 더 나은 알고리즘을 얻기 위해서는 문제의 구조에 대한 흥미로운 사실(위의 Key Lemma)을 알아야 했다는 것이다. 이는 이 강의 전체에서 반복해서 나타나는 주제다 — 좋은 알고리즘을 찾으려면 흔히 문제의 해(solution)의 구조에 대한 통찰이 필요하다.

## 예시
- GCD(3918848, 1653264)를 유클리드 알고리즘으로 계산하는 과정:
  1. 3918848 mod 1653264 = 612,000대
  2. 이전 값들로 계속 나머지를 구하며 428,000대 → 183,000대 → 61,000대 순으로 줄어듦
  3. 다시 나누면 나머지가 0이 되어 종료, 답은 61232
  - 총 6단계 만에 답을 구했으며, 나이브 알고리즘이라면 약 500만(5 million) 개의 후보를 검사해야 했을 것이다.
- 의사코드:
  - gcd(a, b): if b == 0: return a; else: a' = a mod b; return gcd(b, a')

## 요약
- 유클리드 알고리즘은 GCD(a, b) = GCD(b, a mod b)라는 Key Lemma에 기반해 문제를 재귀적으로 축소한다.
- 매 단계마다 수의 크기가 절반씩 줄어들어, 약 log(ab)단계 만에 종료되므로 매우 빠르다(예: 100자리 수 기준 약 600단계).
- 더 나은 알고리즘을 찾으려면 문제 구조에 대한 통찰(Key Lemma 같은)이 필요하다는 것이 이 사례의 핵심 교훈이다.
