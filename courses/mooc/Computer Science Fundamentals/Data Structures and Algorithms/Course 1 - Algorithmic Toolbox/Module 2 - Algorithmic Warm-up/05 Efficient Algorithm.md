# Efficient Algorithm

## 개요
- 배열(array)에 이전에 계산한 값을 저장해 재귀 호출과 중복 계산을 없애는 효율적인 피보나치 수 계산 알고리즘을 제시한다.

## 내용
### 아이디어: 손으로 계산하는 방식 흉내내기
- 사람이 손으로 피보나치 수열을 나열할 때는 0, 1을 먼저 적고, 이후 매 단계마다 마지막 두 값을 더해 다음 값을 적는다.
- 이렇게 하면 이전에 계산한 모든 값이 이미 적혀 있으므로, 나이브 알고리즘에서처럼 느린 재귀 호출을 반복할 필요가 없다.

### 알고리즘
- 배열을 만들어 수열의 모든 값을 저장한다.
- 배열의 0번째 원소를 0으로, 1번째 원소를 1로 설정한다(초기 조건).
- i를 2부터 n까지 증가시키며, i번째 원소를 (i-1)번째와 (i-2)번째 원소의 합으로 설정한다.
- 마지막에 배열의 n번째(마지막) 원소를 반환한다.

### 실행 시간 분석
- 초기 설정(배열 생성, 두 초기값 대입)에 3줄, 마지막 반환에 1줄로 총 4줄.
- for문은 n-1번 반복되며, 매번 2줄씩 실행된다.
- 전체를 더하면 T(n)은 대략 2n + 2.
- n = 100일 때 약 202줄만 실행되며, 이는 어떤 평범한 컴퓨터에서도 사실상 즉시 처리 가능한 수준이다.
- 100번째, 1000번째, 10000번째 피보나치 수를 계산하는 것도 아주 쉽게(trivial) 가능하다.

### 교훈
- 나이브 알고리즘은 정의에서 바로 나온 단순한 알고리즘이지만 수천 년이 걸린다.
- 이 효율적인 알고리즘은 큰 입력에서도 매우 빠르며 실용적으로 잘 작동한다.
- 결국 올바른 알고리즘을 찾는 것이 "평생 걸려도 끝나지 않는 계산"과 "눈 깜짝할 사이에 끝나는 계산"의 차이를 만든다는 것이 핵심 교훈이다.

## 예시
- T(n) ≈ 2n + 2
- n = 100일 때 실행 줄 수: 약 202줄

## 요약
- 배열에 이미 계산된 값을 저장해두는 방식으로 재귀 호출의 중복 계산 문제를 해결할 수 있다.
- 이 효율적 알고리즘의 실행 시간은 T(n) ≈ 2n + 2로, 나이브 알고리즘(지수적)에 비해 훨씬 빠르다(선형).
- 다음 강의에서는 유사한 이야기를 최대공약수(GCD) 계산 문제로 이어간다.
