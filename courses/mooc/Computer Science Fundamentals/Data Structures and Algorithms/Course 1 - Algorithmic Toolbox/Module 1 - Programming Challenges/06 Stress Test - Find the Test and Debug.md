# Stress Test - Find the Test and Debug

## 개요
- 실제로 스트레스 테스트를 실행해 두 해답이 달라지는 테스트를 찾고, 이를 최소화(minimize)한 뒤 버그를 디버깅한다.
- 큰 무작위 테스트를 작은 테스트로 축소해 디버깅을 쉽게 만드는 기법을 보여준다.
- `MaxPairwiseProductFast` 함수의 실제 버그(잘못된 비교 조건)를 찾아 수정한다.

## 내용

### 1차 실행: 큰 실패 테스트 발견
- 컴파일 시 채점 시스템에서 제공하는 C++ 플래그(flag)를 그대로 사용해 `stress_test`라는 실행 파일을 만든다.
- 실행하면 화면에 "OK"와 함께 2~11 사이의 n 값, 그리고 큰 입력 수들이 계속 출력되다가, 결국 n=11인 테스트에서 "Wrong answer"와 두 해답의 서로 다른(매우 큰) 결과값이 출력된다.
- 그러나 원소가 11개이고 값이 크며 답도 매우 커서 이 테스트로 디버깅하기는 어렵다.

### 테스트 최소화(minimizing the test)
- `stress_test.cpp`로 돌아가 n과 원소 값의 범위를 줄인다.
  - n을 4로 나눈 나머지(0~3)에 2를 더해 2~5 범위로 축소.
  - 원소 값도 10으로 나눈 나머지를 사용해 0~9 범위로 축소.
- 재컴파일 후 다시 실행하면 훨씬 빠르게(5~7개 테스트 만에) 실패 테스트를 발견한다.
- 발견한 실패 테스트: 원소 5개 `2, 9, 3, 1, 9`. 순진한 해답(main)의 결과는 81, 빠른 해답(fast)의 결과는 27.
- 81이 옳은 답이다. 배열에서 가장 큰 두 수는 9와 9(두 번째 9)이며, 그 곱이 81이기 때문이다. 따라서 순진한 해답이 맞고, 빠른 해답에 버그가 있다.

### 버그 위치 좁히기: 디버그 출력 추가
- 버그는 `MaxPairwiseProductFast` 함수 안에 있을 것으로 추정된다(별도 함수로 분리되어 있어 위치를 좁히기 쉬움).
- 함수 안에서 자신이 찾은 첫 번째 최댓값과 두 번째 최댓값의 인덱스를 `cout`으로 출력하도록 코드를 추가한다.
- 재컴파일 후 같은 테스트(의사난수이므로 재현 가능(reproducible))를 다시 실행하면, 5개 원소 `2, 9, 3, 1, 9` 아래에 디버그 출력 `1 2`가 나타난다.
  - 인덱스는 0부터 시작하므로 인덱스 1은 값 9(첫 번째 9), 인덱스 2는 값 3이다.
  - 즉, 함수는 두 번째 최댓값을 값 3(인덱스 2)이라고 잘못 판단하고 있다. 실제 두 번째 최댓값은 인덱스 4의 9여야 한다.

### 실제 버그 원인과 수정
- `max_index2`를 찾는 조건문에서, 위치 j의 값이 "이미 찾은 최댓값(`numbers[max_index1]`)과 값이 다른가"를 검사하고 있었다. 이것이 문제다.
- 필요한 조건은 값이 다른지가 아니라, 인덱스 j가 `max_index1`과 다른지(같은 원소를 두 번 세지 않는지)를 검사하는 것이다. 값이 같더라도 인덱스가 다르면 별개의 원소이므로 두 번째 최댓값 후보가 될 수 있다.
- 수정: 값 비교(`numbers[j] != numbers[max_index1]`)를 인덱스 비교(`j != max_index1`)로 변경한다.
- 수정 후 재컴파일 및 재실행하면, 입력 `2, 9, 3, 1, 9`에서 정상적으로 두 번째 9(인덱스 4)를 찾을 수 있게 된다.
- 이후 스트레스 테스트를 다시 돌려 10~30초 정도 기다려도 더 이상 실패 테스트가 나타나지 않는 것을 확인한다.

## 예시
```text
실패 테스트(축소된 버전):
입력: n=5, 배열=[2, 9, 3, 1, 9]
main 해답 결과: 81 (정답, 9*9)
fast 해답 결과: 27 (오답, 9*3)
디버그 출력: max_index1=1(값 9), max_index2=2(값 3) → 버그
```

```cpp
// 버그가 있던 조건 (값 비교)
if (numbers[j] != numbers[max_index1] &&
    (max_index2 == -1 || numbers[j] > numbers[max_index2]))
    max_index2 = j;

// 수정된 조건 (인덱스 비교)
if (j != max_index1 &&
    (max_index2 == -1 || numbers[j] > numbers[max_index2]))
    max_index2 = j;
```

## 요약
- 큰 실패 테스트를 얻었다면, 생성 범위를 줄여 더 작고 디버깅하기 쉬운 실패 테스트로 축소하는 것이 효과적이다.
- 함수를 기능별로 분리해두면 디버그 출력을 추가해 버그 위치를 좁히기 쉬워진다.
- 이번 버그의 원인은 두 번째 최댓값을 찾을 때 "값이 다른지" 대신 "인덱스가 다른지"를 검사해야 했던 것이었다.
