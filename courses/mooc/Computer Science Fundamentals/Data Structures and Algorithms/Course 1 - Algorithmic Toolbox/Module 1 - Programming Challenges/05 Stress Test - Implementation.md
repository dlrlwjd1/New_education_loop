# Stress Test - Implementation

## 개요
- 채점 시스템이 실패한 테스트 케이스를 알려주지 않는 상황에서 버그를 찾기 위한 스트레스 테스트(stress testing) 기법을 소개한다.
- 무작위 테스트를 무한 반복 생성해 두 해답을 비교하는 방식으로 동작한다.
- 최대 쌍별 곱 문제의 `stress_test.cpp` 파일을 통해 실제 구현을 살펴본다.

## 내용

### 스트레스 테스트란
- 무작위 테스트를 무한 루프(infinite loop)로 생성하며, 각 테스트마다 자신의 해답(main solution)과 대안 해답(alternative solution)을 실행해 결과를 비교하는 프로그램이다.
- 대안 해답은 직접 구현해야 하지만, 보통 단순하고 느린 무차별 대입(brute force) 해답이거나 주 해답과 다른 접근으로 작성한 아무 해답이어도 된다. 단, 주 해답과 확실히 다른 방식이어야 한다.
- 두 해답의 결과가 달라지는 테스트를 찾을 때까지 기다린다.
  - 하나는 옳고 하나는 틀렸다면, 언젠가 반드시 결과가 다른 테스트가 존재한다.
  - 둘 다 틀렸더라도 서로 다른 지점에서 틀렸을 가능성이 높으므로, 역시 결과가 다른 테스트를 찾을 가능성이 높다.
- 결과가 다른 테스트를 찾으면 어느 쪽이 틀렸는지 판별하고, 디버깅(debug)해서 고친 뒤 스트레스 테스트를 반복한다.

### stress_test.cpp 구조
- 기존 제출 해답과 거의 동일하지만 다음이 추가된다.
  - `<cstdlib>` 등 표준 라이브러리 include: 난수(random number) 생성을 위해 필요하다.
  - 기존의 `MaxPairwiseProduct`, `MaxPairwiseProductFast` 두 함수는 그대로 유지한다.
  - `main` 함수 안에 스트레스 테스트를 수행하는 while 루프가 추가된다.
- 루프 안에서: 무작위 테스트 생성 → 두 함수(`MaxPairwiseProduct`, `MaxPairwiseProduct Fast`)를 같은 테스트에 실행 → 결과 비교.
  - 두 해답이 모두 옳고 정답이 유일하다면, 두 옳은 해답은 어떤 테스트에서도 같은 결과를 내야 한다.
  - 하나는 틀리고 하나는 옳다면 결과가 달라지는 테스트가 존재한다.
  - 둘 다 틀렸어도 서로 다른 방식으로 틀렸다면 결과가 다른 테스트가 존재할 가능성이 높다.
- 충분히 많은 테스트를 생성하면 어느 시점에 결과가 다른 테스트를 발견하게 되고, 이를 통해 최소 한쪽 해답이 틀렸음을 알 수 있어 디버깅 후 재실행할 수 있다.

### 무작위 테스트 생성 절차
1. 원소 개수 n을 생성한다. 문제 조건상 n ≥ 2이므로, `rand()`로 큰 난수를 얻고 10으로 나눈 나머지(0~9)에 2를 더해 2~11 범위의 n을 만든다.
   - n을 작게 잡는 이유: 두 해답이 충분히 빠르게 동작하게 하고, 큰 테스트일수록 디버깅이 어렵기 때문이다.
2. 생성한 n을 화면에 즉시 출력한다. 이렇게 하면 실패 테스트를 발견했을 때 바로 확인할 수 있다.
3. 배열 `a`를 n개의 원소로 채운다. 각 원소는 0~99,999 범위(문제에서 허용하는 범위)의 난수로 생성해 한 줄에 공백으로 구분해 출력한다.
4. 두 해답(main solution, fast solution)을 이 입력에 대해 실행해 각각의 결과를 얻는다.
5. 두 결과를 비교한다. 다르면 화면에 "Wrong answer"와 두 결과값을 출력하고 루프를 종료(break)한다. 같으면 "OK"를 출력하고 무한 루프를 계속한다.
- 이 스트레스 테스트 코드는 기존에 입력을 표준 입력에서 읽던 부분 앞에 삽입되는 형태로, 표준 입력 대신 자동으로 실패 테스트를 찾도록 동작을 바꾼 것이다.

## 요약
- 스트레스 테스트는 무작위 테스트를 무한 생성해 주 해답과 대안 해답의 결과를 비교하는 기법이다.
- 대안 해답은 단순하고 느려도 되지만 주 해답과는 확실히 다른 방식이어야 한다.
- 처음에는 n과 값의 범위를 작게 잡아 디버깅하기 쉬운 작은 실패 테스트를 얻는 것이 핵심이다.
