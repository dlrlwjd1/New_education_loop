# Solving the Sum of Two Digits Programming Challenge (screencast)

## 개요
- 아주 기초적인 "A plus B" 문제를 통해 이 수업에서 코드 문제를 푸는 일반적인 파이프라인(pipeline)을 보여준다.
- 표준 입력(standard input)으로 두 정수를 받아 그 합을 표준 출력(standard output)으로 내보내는 문제다.
- 스타터 파일(starter file) 다운로드 → 컴파일 → 로컬 실행 → 제출(submit)의 4단계 절차를 익힌다.

## 내용

### 문제 정의: A plus B
- 표준 입력으로 두 정수가 주어지고, 그 합을 표준 출력으로 출력하는 것이 목표다.
- 샘플 테스트: 입력이 `3`과 `2`면 출력은 `5`, 입력이 `7`과 `9`면 출력은 `16`이다.
- 스타터 파일은 Python, Java, C++ 세 언어로 제공되며, 이 경우엔 사실상 완성된 해답(solution)에 가깝다.

### 문제 풀이 4단계 절차
1. 스타터 파일 중 하나를 다운로드한다. (예시에서는 C++ 파일 선택)
2. 페이지에 표시된 컴파일러 플래그(compiler flag)를 그대로 사용해 컴파일한다. 이렇게 하면 채점 시스템과 로컬 머신에서 프로그램이 동일하게 동작한다.
3. 컴파일 결과 실행 파일(예: `a.out`)을 실행해 직접 테스트한다. 예: 입력 `2 3` → 출력 `5`, 입력 `9 4` → 출력 `13`.
4. My Submission 탭에서 Create Submission을 누르고 `.cpp` 파일로 교체한 뒤 Submit을 눌러 제출한다.

### 제출과 채점 결과 해석
- 제출 후 채점 시스템이 모든 테스트를 통과했음을 알려준다. 이때 grader output이 비어 있으면 오류 메시지가 없다는 뜻이다.
- 같은 절차를 Python으로도 반복할 수 있다. Python 스타터 파일은 표준 입력에서 `a`, `b`를 받아 합을 출력하는 단순한 구조이며, 실행 방법(예: `python3`)은 "available programming languages" 페이지에서 확인한다.

### 다음 강의 예고: 실전 디버깅 흐름
- 다음 문제는 훨씬 흥미로운데, 순진한 해답(naive solution)에서 시작한다.
- 제출해 보면 버그(bug)가 있음을 알게 되고 → 버그 수정 후 다시 제출하면 해답이 느려서 시간 제한 초과(time limit exceeded) 피드백을 받고 → 훨씬 빠른 해답을 구현·제출하면 여전히 버그가 있음을 발견한다.
- 이때 스트레스 테스트(stress testing)를 이용해 버그를 찾아 수정하고, 최종적으로 모든 테스트를 통과하는 올바른 해답을 제출하게 된다.

## 요약
- 코드 문제 풀이의 표준 파이프라인은 스타터 파일 다운로드 → 지정된 플래그로 컴파일 → 로컬 실행/테스트 → 제출이다.
- 채점 시스템과 동일한 환경을 위해 권장 컴파일러 플래그를 반드시 사용한다.
- 다음 강의부터는 순진한 해답 → 버그 수정 → 성능 개선 → 스트레스 테스트로 이어지는 실전 문제 해결 흐름을 다룬다.
