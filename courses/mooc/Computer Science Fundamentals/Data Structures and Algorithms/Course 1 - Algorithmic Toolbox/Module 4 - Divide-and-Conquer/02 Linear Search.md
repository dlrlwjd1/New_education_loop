# Linear Search

## 개요
- 분할 정복 알고리즘의 첫 사례로, 정렬되지 않은 배열(unsorted array)에서 원하는 값을 찾는 선형 탐색(linear search)을 다룬다. 이는 분할 정복의 "퇴화된(degenerate)" 형태로 볼 수 있다.
- 강사가 20여 년 전 애플 뉴턴(Apple Newton)용 5개 언어(영어·프랑스어·이탈리아어·독일어·스페인어) 번역 애플리케이션을 컨설팅한 실제 사례를 통해, 선형 탐색의 성능 한계를 보여준다. 약 5만 단어 사전에서 평균 2만 5천 번 비교가 필요해 번역에 7~10초가 걸렸다.

## 내용

### 문제 정의
- 입력: 정렬되지 않은 배열(길이 n)과 찾을 값(key) k.
- 출력: 배열에서 A[i] = k인 인덱스 i. 중복 원소가 있을 수 있으므로 "유일한 인덱스"가 아니라 "어떤 하나의 인덱스"를 찾으면 된다. 일치하는 원소가 없으면 NOT_FOUND를 반환한다.

### 재귀적 분할 정복 해법
- 재귀 함수는 배열 A, 탐색 범위의 하한 low, 상한 high, 찾을 값 k를 인자로 받는다.
- 기저 사례(base case): 배열이 비어 있거나(low > high), 첫 번째 원소가 바로 일치하는 경우.
- 그 외의 경우: 첫 번째 원소를 제외한 나머지 부분 배열(sub-array)에 대해 재귀적으로 탐색하고 그 결과를 그대로 반환한다.
- 다만 이 하위 문제는 원래 문제의 일정 비율(50%, 80% 등)이 아니라 크기가 1만 줄어든 것이므로, 엄밀한 의미의 "분할 정복"보다는 "빼기 정복(subtract-and-conquer)"에 가깝다는 견해도 있다.

### 점화식(recurrence relation)을 통한 실행 시간 분석
- 점화식은 재귀적 공식으로 수열의 값을 정의한다(예: 피보나치 수열 F(n) = F(n-1) + F(n-2), 기저 사례 F(0), F(1)).
- 분할 정복 알고리즘의 실행 시간은 보통 T(n)(n은 문제 크기)에 대한 점화식으로 표현한다.
- 이 알고리즘의 최악의 경우(worst case)는 원소를 찾지 못해 배열 전체를 확인해야 할 때이다.
  - 재귀 호출 1회당 상수 시간 c만큼의 작업(비교, 인자 준비 등)이 필요하므로: T(n) = T(n-1) + c.
  - 기저 사례(빈 배열): T(0) = c.

### 재귀 트리(recursion tree)를 통한 풀이
- 문제 크기가 n, n-1, n-2, …, 0으로 줄어드는 재귀 트리를 그리면, 각 레벨에서 상수 c만큼의 작업이 발생한다.
- 전체 작업량은 합 Σ(i=0..n) c = (n+1)c이며, 이는 Θ(n)이다.
- 이는 이미 알려진 결과(배열 n개 원소를 훑는 데 Θ(n))와 같지만, 이런 재귀 분석 방법은 이후 더 복잡한 분할 정복 알고리즘을 분석할 때 유용하다.

### 반복문(iterative) 버전
- 재귀 대신 low부터 high까지 반복문으로 순회하며 일치하는 원소를 찾으면 그 인덱스를 반환하고, 끝까지 못 찾으면 NOT_FOUND를 반환한다.

## 예시

점화식과 실행 시간:
- T(n) = T(n-1) + c, T(0) = c
- 재귀 트리의 레벨 수: n+1 (크기 n, n-1, …, 0)
- 각 레벨의 작업량: c
- 총 작업량: Σ(i=0..n) c = (n+1)c = Θ(n)

의사코드 흐름(재귀):
1. high < low 이면 NOT_FOUND 반환 (기저 사례)
2. A[low] = k 이면 low 반환 (기저 사례)
3. 그 외에는 A, low+1, high, k에 대해 재귀 호출한 결과를 그대로 반환

## 요약
- 선형 탐색은 분할 정복의 가장 단순한 형태로, 배열을 한 칸씩 줄여가며 순차 비교한다.
- 점화식 T(n) = T(n-1) + c를 재귀 트리로 풀면 실행 시간은 Θ(n)이다.
- 재귀 해법 → 점화식 정의 → 점화식 풀이 → 반복문 변환이라는 네 단계는 이후 더 복잡한 분할 정복 알고리즘 분석에도 동일하게 적용된다.
- 다음 영상에서는 정렬된 배열에서의 탐색인 이진 탐색(binary search)을 다룬다.
