# Final Remarks

## 개요
- 퀵 정렬(quick sort) 강의의 마지막 영상으로, 공간 복잡도(space complexity)를 줄이는 구현 기법과, 무작위성(randomness) 없이도 안정적인 실행 시간을 보장하는 인트로 정렬(introsort) 기법 두 가지 구현 이슈를 다룬다.

## 내용

### 공간 복잡도(space complexity) 문제
- 퀵 정렬은 배열을 제자리(in place)에서 파티션하므로 별도의 큰 추가 공간은 필요 없다.
- 하지만 재귀 호출(recursive call) 자체가 스택(stack)에 정보를 저장하므로, 재귀 깊이(recursion depth)만큼 추가 공간이 든다.
- 평균적인 재귀 깊이는 로그(logarithmic) 수준임이 알려져 있지만, 최악의 경우에도 로그 수준의 공간만 쓰도록 만드는 우아한(elegant) 트릭이 있다.

### 꼬리 재귀(tail recursion) 제거 트릭
- 퀵 정렬은 파티션 호출 뒤 두 번의 재귀 호출로 구성되며, 이 중 마지막에 오는 재귀 호출은 흔히 "꼬리 재귀(tail recursion)"라 부른다.
- 꼬리 재귀는 while 루프로 대체해 제거할 수 있다: 오른쪽 부분에 대한 재귀 호출 대신, l 값을 m+1로 갱신하고 while 루프의 처음으로 돌아가는 방식으로 재귀 호출을 흉내 낸다.
- 두 재귀 호출은 서로 독립적(independent)이므로 어느 쪽을 먼저 처리하든 상관없다. 따라서 항상 더 짧은(shorter) 쪽에 대해 실제 재귀 호출을 하고, 더 긴(longer) 쪽은 반복문으로 처리하도록 선택할 수 있다.
- 항상 더 짧은 부분 배열에 대해 재귀 호출을 하면, 그 재귀 호출은 항상 원래 크기의 절반 이하(n/2, n/4, ...)로 줄어들기 때문에 재귀 깊이가 로그 수준으로 제한된다.
- 구현: 파티션 호출로 m을 얻은 뒤 두 부분의 길이를 비교해, 더 짧은 쪽에 재귀 호출하고 더 긴 쪽은 l 또는 r 값을 갱신하는 것으로 대체한다.
- 결과적으로 이 구현은 최악의 경우에도 로그 수준의 추가 공간만 사용한다.

### 재현성(reproducibility)과 인트로 정렬(introsort)
- 실무에서는 같은 데이터셋에 대해 프로그램이 항상 같은 결과를 내는 재현성(reproducibility)이 중요할 수 있다(예: 디버깅). 이런 경우 난수(random number)를 쓰지 않는 결정적(deterministic) 버전의 퀵 정렬이 필요하다.
- 인트로 정렬(introsort)은 실무에서 널리 쓰이는 방법으로, 기준 원소(pivot)를 무작위로 뽑는 대신 다음과 같은 간단한 휴리스틱(heuristic)을 쓴다: 부분 배열의 첫 원소, 마지막 원소, 중간 원소 세 개를 비교해 그중 중앙값(median)을 기준으로 사용한다. 이는 세 번의 비교만으로 구현 가능하며 많은 경우에 효과적이다.
- 그러나 이 휴리스틱만으로는 병적인(pathological) 최악의 입력에서 여전히 성능이 나빠질 수 있다.
- 이를 보완하기 위해, 퀵 정렬 실행 중 재귀 깊이(recursion depth)를 계속 추적하다가 어떤 상수 c에 대해 깊이가 c·log n을 넘어서면, 현재 알고리즘 실행을 중단하고 다른 알고리즘(예: 힙 정렬, heap sort)으로 전환한다.
- 힙 정렬은 점근적으로 병합 정렬(merge sort)만큼 우수한(O(n log n)) 알고리즘이지만, 실무에서는 대체로 퀵 정렬이 더 빠르다.
- 깊이가 c·log n에 도달하기 전까지는 O(n log n) 시간이 걸리고, 그 이후 힙 정렬로 전환해도 다시 O(n log n) 시간이 걸리므로, 전체적으로 이 방식은 최악의 경우에도 O(n log n)을 보장하면서 대부분의 경우 퀵 정렬처럼 빠르게 동작한다.

## 예시
- 꼬리 재귀 제거를 반영한 퀵 정렬 개념적 구현:
  ```
  quickSort(A, l, r):
      while l < r:
          m = partition(A, l, r)
          if (m - l) < (r - m):
              quickSort(A, l, m-1)
              l = m + 1
          else:
              quickSort(A, m+1, r)
              r = m - 1
  ```
- 인트로 정렬(introsort)의 기준 선택 휴리스틱: 첫 원소, 마지막 원소, 중간 원소를 비교하여 그중 중앙값을 기준(pivot)으로 사용(비교 3회로 계산 가능).
- 인트로 정렬의 전환 조건: 재귀 깊이가 c·log n을 초과하면 힙 정렬(heap sort)로 전환.

## 요약
- 퀵 정렬(quick sort)은 두 재귀 호출 중 더 짧은 쪽에만 실제로 재귀하고 더 긴 쪽은 반복문으로 처리하는 꼬리 재귀 제거 기법을 쓰면, 최악의 경우에도 로그 수준의 추가 공간만 사용할 수 있다.
- 재현성이 필요한 경우 무작위 기준 선택 대신 첫/중간/마지막 원소의 중앙값을 기준으로 쓰는 휴리스틱을 사용할 수 있다.
- 이 휴리스틱이 병적인 입력에서 실패할 가능성에 대비해, 재귀 깊이가 일정 임계값을 넘으면 힙 정렬로 전환하는 인트로 정렬(introsort) 기법을 쓰면 최악의 경우에도 O(n log n)을 보장할 수 있다.
- 종합하면 퀵 정렬은 평균적으로 O(n log n), 최악의 경우 O(n²)인 비교 기반 알고리즘이지만, 실무에서 병합 정렬 등보다 더 빠르게 동작하는 경우가 많아 널리 쓰인다.
