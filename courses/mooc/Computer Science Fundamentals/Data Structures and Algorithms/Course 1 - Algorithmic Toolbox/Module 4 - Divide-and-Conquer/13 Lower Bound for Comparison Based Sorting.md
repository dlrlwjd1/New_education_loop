# Lower Bound for Comparison Based Sorting

## 개요
- 앞선 강의에서 병합 정렬(merge sort)의 실행 시간이 O(n log n)임을 증명했는데, 이 강의에서는 이 상한(bound)이 사실상 최적(optimal)임을 보인다.
- 결론: 쌍(pair)을 비교(comparison)하는 방식으로만 정렬하는 모든 정렬 알고리즘 — 비교 기반(comparison based) 알고리즘 — 은 최악의 경우(worst case) 최소 Ω(n log n)번의 연산이 필요하다.

## 내용

### 비교 기반(comparison based) 알고리즘이란
- 주어진 원소들의 쌍을 서로 비교하는 것만으로 정렬을 수행하는 알고리즘을 말한다.
- 비유: 겉보기에 똑같지만 무게가 다른 공(ball)들이 있고, 양팔 저울(pen balance)로만 두 공을 비교할 수 있는 상황에서 무게 순으로 정렬하는 문제.
- 선택 정렬(selection sort)과 병합 정렬(merge sort)은 모두 비교 기반 알고리즘이다.
  - 선택 정렬: 매 단계마다 남은 부분에서 최솟값을 찾기 위해 쌍을 비교한다.
  - 병합 정렬: 병합(merge) 단계에서 두 정렬된 배열의 첫 원소끼리 비교해 더 작은 쪽을 결과 배열로 옮긴다.

### 정리(theorem)
- 모든 비교 기반 정렬 알고리즘의 최악의 경우 실행 시간은 최소 Ω(n log n)이다.
- 즉, 특정 입력에 대해서는 선형(linear) 횟수의 비교만으로 정렬을 끝낼 수도 있지만, 항상(모든 입력에 대해) n log n보다 점근적으로 적은 비교로 정렬할 수 있는 알고리즘은 존재하지 않는다.
- 다시 말해, 어떤 입력 시퀀스에 대해서는 그 알고리즘이 최소 Ω(n log n)번의 비교를 수행할 수밖에 없다.

### 결정 트리(decision tree)를 이용한 증명 구조
- 임의의 비교 기반 알고리즘은 가능한 모든 비교의 결과를 나타내는 하나의 거대한 트리(tree)로 표현할 수 있다.
- 트리의 각 내부 노드(internal node)는 하나의 비교를, 각 리프(leaf)는 입력 원소들의 한 순열(permutation)을 나타낸다.
- 예: 세 원소 a1, a2, a3를 정렬하는 알고리즘의 경우 — a1과 a2를 비교하고, 결과에 따라 a2와 a3 비교, 다시 필요하면 a1과 a3 비교 — 하는 식으로 트리가 구성된다.

### 핵심 관찰: 리프의 개수
- 이 트리는 최소 n! (n factorial, n×(n-1)×(n-2)×...×1)개의 리프를 가져야 한다.
- 이유: 입력 원소들의 가능한 순열이 n!가지이며, 각 순열이 알고리즘의 정답이 되는 경우가 실제로 존재할 수 있으므로, 모든 순열이 트리의 리프로 반드시 나타나야 한다.
- 예: 원소 3개인 경우 가능한 순열은 6가지(3! = 6)이며, 트리에는 실제로 6개의 리프가 존재한다.

### 트리의 깊이(depth)와 리프 개수의 관계
- 알고리즘이 수행하는 최대 비교 횟수는 트리의 깊이(root에서 리프까지의 최대 간선 수)와 같다.
- 이진 트리(binary tree)의 성질: 깊이가 d인 트리가 가질 수 있는 리프의 최대 개수는 2^d이다. (역으로 표현하면 깊이 d ≥ log₂(리프 개수))
  - 깊이 1: 최대 리프 2개. 깊이 2: 최대 리프 4개(완전 이진 트리일 때). 즉 최대 리프 수를 가지려면 깊이 d의 완전 이진 트리여야 하며 이때 리프 수는 정확히 2^d이다.
- 리프가 최소 n!개이므로, 트리 깊이 d는 최소 log(n!) 이상이어야 한다.

### log(n!)의 하한 계산
- log(n!) = log(1) + log(2) + ... + log(n) (곱의 로그는 로그의 합)
- 이 합의 앞쪽 절반을 버리고 뒤쪽 절반(n/2개의 항)만 남기면, 각 항은 최소 log(n/2)이다.
- 따라서 log(n!) ≥ (n/2)·log(n/2)
- log(n/2) = log(n) - 1 이며, 상수 1을 빼도 여전히 log n과 같은 차수로 자라므로, (n/2)·log(n/2)는 결국 n·log n과 같은 차수로 자란다.
- 결론: log(n!) = Ω(n log n) 이며, 따라서 트리의 깊이 d = Ω(n log n)이다.

### 결론과 다음 방향
- 어떤 비교 기반 정렬 알고리즘도 최악의 경우 Ω(n log n)번의 비교 없이는 정렬을 끝낼 수 없다.
- 이로써 병합 정렬(merge sort)이 점근적으로 최적(asymptotically optimal)임이 확인된다.
- 다음 강의에서는 원소를 서로 비교하지 않고도 정렬할 수 있는, n log n보다 빠른(선형 시간) 알고리즘을 다룬다. 단, 이는 원소가 작은 정수(small integer)라는 사전 정보를 활용하는 경우에 한정된다.

## 예시
- 3개 원소 a1, a2, a3를 정렬하는 결정 트리 예:
  1. a1과 a2를 비교
  2. a1 < a2이면 a2와 a3 비교 → a2 < a3이면 순서는 a1, a2, a3
  3. a2 ≥ a3이면 a1과 a3을 추가로 비교해 최종 순서 결정
  4. a1 ≥ a2인 경우도 대칭적으로 진행
  - 이 트리는 6가지 순열(순서 2·1·3 포함) 각각에 대응하는 6개의 리프를 가진다.
- 부등식 유도: log(n!) ≥ (n/2)·log(n/2) = Ω(n log n)

## 요약
- 비교 기반(comparison based) 정렬 알고리즘은 결정 트리로 표현할 수 있으며, 리프의 개수가 최소 n!개여야 한다.
- 트리 깊이는 리프 개수의 로그, 즉 최소 log(n!) = Ω(n log n)이어야 한다.
- 따라서 모든 비교 기반 정렬 알고리즘은 최악의 경우 Ω(n log n)번의 비교가 필요하며, 병합 정렬은 이 하한을 달성하는 점근적으로 최적인 알고리즘이다.
