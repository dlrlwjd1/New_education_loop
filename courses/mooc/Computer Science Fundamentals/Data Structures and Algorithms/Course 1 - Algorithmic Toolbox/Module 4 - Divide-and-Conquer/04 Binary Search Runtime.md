# Binary Search Runtime

## 개요
- 이진 탐색(binary search)의 실행 시간을 점화식으로 분석하고, 반복문(iterative) 버전을 살펴본다.
- 이전 영상에서 소개한 번역 애플리케이션 사례를, 정렬 배열과 보조 배열(augmented array)을 이용해 실제로 개선한 과정을 다룬다.

## 내용

### 점화식과 재귀 트리 분석
- 최악의 경우(원소를 찾지 못하는 경우) 점화식: T(n) = T(floor(n/2)) + c.
  - floor(n/2)를 쓰는 이유: n이 홀수(예: 5)여도 중간점을 제외한 나머지가 상위/하위 절반으로 균등하게 나뉘기 때문이다.
- 재귀 트리에서 문제 크기는 n, n/2, n/4, …로 줄어들며, 크기 1이 될 때까지 필요한 레벨 수는 log₂n + 1이다.
- 각 레벨에서 c만큼의 작업이 발생하므로 총 작업량은 Σ(i=0..log₂n) c = (log₂n + 1)c.
- 따라서 실행 시간은 Θ(log₂n) = Θ(log n) (로그의 밑은 상수 배수 차이이므로 무시).

### 반복문(iterative) 버전
- 매개변수는 재귀 버전과 동일(low, high, key)하며, `high < low`를 종료 조건으로 하는 while 루프를 사용한다.
- 매 반복마다 mid를 계산해 A[mid]와 key를 비교한다.
  - key < A[mid]: high = mid - 1로 갱신 (재귀 호출 대신 값만 변경).
  - key > A[mid]: low = mid + 1로 갱신.
- 루프가 high < low로 끝나면 배열이 비어 탐색 실패이므로 low - 1을 반환한다(재귀 버전과 동일한 결과).
- 차이점은 반복문 버전이 재귀 버전에서 쓰이는 추가 스택 공간(stack space)을 사용하지 않는다는 것이다.

### 실제 사례: 다국어 번역 애플리케이션 개선
- 원래는 영어·스페인어·프랑스어·이탈리아어·독일어 5개 병렬 배열(parallel array)에 같은 인덱스가 같은 단어의 번역을 나타내는 구조였다.
- 문제: 특정 언어 배열만 정렬하면, 인덱스 간의 대응 관계(같은 인덱스 = 같은 단어)가 깨진다.
- 해결책: 보조 정렬 배열(augmented array)을 추가로 유지한다. 이 배열은 원본 배열을 가리키는 포인터(간접 참조, indirection)들을 정렬된 순서로 담는다.
  - 예: 영어 배열에서 "chair, house, pimple" 순서가 알파벳순이라면, 보조 배열은 [2, 1, 3]처럼 원본 배열의 인덱스를 정렬 순서대로 담는다.
  - 스페인어는 정렬 순서가 다르므로 별도의 보조 배열([1, 3, 2] 형태)을 둔다.
- 공간 비용: 언어 5개 × 5만 항목 × 2바이트(16비트로 1~5만 인덱스 표현 가능) = 약 50만 바이트(0.5MB). 20년 전 기준으로도 충분히 감당 가능한 수준이었다.
- 시간 이득: 5만 번 비교(선형 탐색) 대신 log₂(50,000) ≈ 16번 비교(이진 탐색)만 필요 — 약 1,000배 개선. 결과적으로 번역 시 체감 지연이 10초에서 0.1초 미만으로 줄었다.

## 예시

실행 시간 비교:
- 선형 탐색: Θ(n) → n = 50,000일 때 최악 5만 회 비교.
- 이진 탐색: Θ(log n) → n = 50,000일 때 최악 약 16회 비교 (log₂50,000 ≈ 15.6).

공간 비용 계산: 5개 언어 × 50,000개 항목 × 2바이트 = 500,000바이트 ≈ 0.5MB.

## 요약
- 이진 탐색의 실행 시간은 점화식 T(n) = T(n/2) + c를 풀어 Θ(log n)이다.
- 반복문 버전은 재귀 버전과 결과는 같지만 스택 공간을 절약한다.
- 정렬 배열 + 보조(인덱스) 배열 구조를 쓰면, 병렬 배열 간 대응 관계를 유지하면서도 이진 탐색의 이점(공간과 시간의 트레이드오프, space-time trade-off)을 얻을 수 있다.
- 다음 레슨에서는 여러 개의 하위 문제를 갖는 더 복잡한 분할 정복 응용(다항식 곱셈)을 다룬다.
