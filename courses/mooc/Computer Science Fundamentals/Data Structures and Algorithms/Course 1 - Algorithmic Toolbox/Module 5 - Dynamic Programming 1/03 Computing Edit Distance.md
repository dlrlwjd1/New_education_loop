# Computing Edit Distance

## 개요
- 두 문자열의 접두사(prefix) 쌍에 대한 최적 정렬을 이용해 편집 거리(edit distance)를 동적 계획법(dynamic programming)으로 계산하는 재귀 관계(recurrence)를 유도한다.
- D(i, j) 표(matrix)를 왼쪽 위에서부터 채워나가는 절차를 구체적인 예시로 설명한다.
- 이 절차가 EditDistance 의사코드(pseudocode)로 어떻게 구현되는지 개관한다.

## 내용

### 접두사(prefix) 기반 재귀 관계 유도
- 문자열 A(길이 n)와 B(길이 m)가 주어졌을 때, A의 앞 i개 기호(i-prefix)와 B의 앞 j개 기호(j-prefix) 사이의 최적 정렬(optimal alignment)을 생각한다.
- 이 최적 정렬의 마지막 열(column)은 삽입, 삭제, 미스매치, 매치 중 하나다.
- 마지막 열을 제거하면, 남은 부분은 (i-prefix, j-prefix)보다 한 단계 짧은 접두사 쌍에 대한 최적 정렬이 된다.
- D(i, j)를 i-prefix와 j-prefix 사이의 편집 거리라고 정의하면, 다음 네 가지 값 중 최솟값으로 D(i, j)를 구할 수 있다.
  - D(i, j-1) + 1  (삽입에 대응)
  - D(i-1, j) + 1  (삭제에 대응)
  - D(i-1, j-1) + 1  (i-prefix와 j-prefix의 마지막 기호가 다를 때, 미스매치에 대응)
  - D(i-1, j-1)  (i-prefix와 j-prefix의 마지막 기호가 같을 때, 매치이므로 벌점 없음)

### 표를 채우는 절차: "editing"과 "distance" 예시
- 두 문자열 "editing"(길이 7)과 "distance"(길이 8)를 예로 들면, 8×9 크기의 격자(grid)를 구성해 모든 D(i, j)를 계산한다.
- **초기화**: 첫 번째 열 D(i, 0)은 i-prefix를 0-prefix(빈 문자열)와 비교하는 것이므로, 그냥 i번 삭제해야 하니 D(i, 0) = i다. 마찬가지로 첫 번째 행 D(0, j) = j로 쉽게 채운다.
- **D(1, 1) 계산**: 문자열 "e"(A의 1글자)와 "d"(B의 1글자)를 비교. 노드 (1,1)에 도달하는 세 가지 방법은 (0,0), (0,1), (1,0)에서 오는 것이다. 재귀 관계에 따라 이 세 값 중 최소를 선택한다. 예시에서는 (2, 2, 1) 중 최소인 1을 선택하며, 대각선 방향(diagonal edge)으로 도달한 것으로 기록해둔다.
- **D(2, 1) 계산**: D(2,0)+1, D(1,1)+1, D(1,0) 중 최솟값을 비교한 결과, 역시 대각선 방향이 최적임을 확인한다.
- 계속 진행하며, 어떤 노드는 수직 방향(vertical edge)이 최적이고, 어떤 노드(예시의 D(1,2))는 대각선과 수평 방향(horizontal edge) 두 가지가 모두 최적인 경우도 있다.
- 이런 식으로 표 전체를 순서대로(왼쪽 위에서 오른쪽 아래로) 채워나간다.

### EditDistance 의사코드(pseudocode)의 흐름
- 먼저 첫 번째 열과 첫 번째 행을 채운다.
- 이후 각 노드 (i, j)에 대해, 삽입/삭제/미스매치/매치, 즉 수직/수평/대각선 간선(edge)을 이용해 도달하는 세 가지 비용을 모두 계산한다.
- 이 세 가지(또는 매치인 경우 벌점 없는 대각선 포함) 값 중 최소를 D(i, j)로 선택한다.
- 이 과정을 격자 전체에 반복해, 최종적으로 D(n, m)이 두 전체 문자열 사이의 편집 거리가 된다.

## 예시
```text
재귀 관계:
D(i, j) = min {
    D(i, j-1) + 1,                                  // 삽입
    D(i-1, j) + 1,                                  // 삭제
    D(i-1, j-1) + 1,                                // 미스매치 (마지막 기호가 다를 때)
    D(i-1, j-1)                                     // 매치 (마지막 기호가 같을 때)
}

초기 조건: D(i, 0) = i,  D(0, j) = j

예: "editing" vs "distance" → 8x9 격자에서 D(i,j)를 순서대로 계산
D(1,1): 후보 {D(0,0)+1=2? / D(0,1)+1=2 / D(1,0)+1=2} 중 최소 → 대각선 경로 선택
```

```text
EditDistance(A, B):
    n = len(A), m = len(B)
    D[i][0] = i  for i = 0..n
    D[0][j] = j  for j = 0..m
    for i = 1..n:
        for j = 1..m:
            insertion = D[i][j-1] + 1
            deletion  = D[i-1][j] + 1
            match_or_mismatch = D[i-1][j-1] + (0 if A[i]==B[j] else 1)
            D[i][j] = min(insertion, deletion, match_or_mismatch)
    return D[n][m]
```

## 요약
- 편집 거리 D(i, j)는 i-prefix와 j-prefix에 대한 최적 정렬의 마지막 열(삽입/삭제/미스매치/매치)을 기준으로 한 재귀 관계로 정의된다.
- 첫 번째 행과 열은 자명하게 채울 수 있고(D(i,0)=i, D(0,j)=j), 이후 각 노드는 수직·수평·대각선 세 방향 중 최솟값을 선택해 채운다.
- 이 과정을 격자 전체에 적용하면 최종적으로 두 문자열 전체의 편집 거리 D(n, m)을 구할 수 있다.
