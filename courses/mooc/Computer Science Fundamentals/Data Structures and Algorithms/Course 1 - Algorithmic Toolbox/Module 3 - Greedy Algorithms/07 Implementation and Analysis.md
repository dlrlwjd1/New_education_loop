# Implementation and Analysis

## 개요
- 이전 강의(Greedy Algorithm)에서 증명한 "점을 선분으로 덮는" 탐욕 알고리즘을 구현하고 실행 시간을 분석한다.
- 최종적으로 Celebration Party Problem을 정렬(sort) + 탐욕(greedy)으로 O(n log n)에 풀 수 있음을 보이고, 이를 단순 알고리즘의 지수 시간(Ω(2ⁿ))과 비교한다.

## 내용
### 전제 조건
- 점들이 좌표 오름차순(ascending order)으로 이미 정렬되어 주어진다고 가정한다: x₁ ≤ x₂ ≤ … ≤ xₙ.

### 의사코드(pseudocode): PointsCoverSorted
- 함수 `PointsCoverSorted(x[1..n])`: 정렬된 점들을 입력받아, 모든 점을 덮는 (길이 2, 최소 개수의) 선분 목록을 반환한다.
- 초기화:
  - `segments = []` (빈 목록)
  - `left = 1` (아직 덮이지 않은 점 중 가장 왼쪽 점의 인덱스)
- `while left ≤ n`인 동안 반복(아직 덮이지 않은 점이 남아있는 동안):
  1. 가장 왼쪽 점(좌표 `x[left]`)을 기준으로 새 선분을 만든다: `l = x[left]`, `r = x[left] + 2`.
  2. 이 새 선분을 `segments`에 추가한다.
  3. `left`를 1 증가시킨다(이 점은 이제 덮였으므로).
  4. 내부 `while left ≤ n and x[left] ≤ r`인 동안: 다음 점들도 방금 만든 선분에 이미 덮여 있는지 확인하고, 덮여 있다면 `left`를 계속 1씩 증가시킨다.
- 외부 while 루프가 끝나면 모든 점이 선분으로 덮인 것이며, `segments`를 반환한다.

### 실행 시간 분석: PointsCoverSorted는 선형 시간
- **보조정리(lemma)**: `PointsCoverSorted`의 실행 시간은 **선형(linear, O(n))**이다.
- 증명: 변수 `left`는 1부터 n까지 계속 증가만 하며, n을 넘어서면 알고리즘이 멈춘다. 외부/내부 두 개의 while 루프가 있어 언뜻 O(n²)처럼 보일 수 있지만, 실제로는 `left` 변수가 총 최대 n번만 증가한다.
- `left`의 각 값에 대해 최대 1개의 새 선분만 `segments`에 추가되므로, 전체 작업량은 최대 2n번의 연산(`left` 증가 + 선분 추가)이다.
- 따라서 전체 실행 시간은 **O(n)**, 즉 선형 시간이다.

### 전체 실행 시간: 정렬 포함
- `PointsCoverSorted` 자체는 선형 시간이지만, 점들이 정렬되지 않은 상태로 주어진다면 먼저 정렬해야 한다.
- 정렬은 다음 모듈에서 배울 예정이며 **O(n log n)** 시간에 가능하다.
- 전체 실행 시간 = 정렬 O(n log n) + PointsCoverSorted O(n) = **O(n log n)** (선형 시간은 n log n보다 작으므로 지배항은 n log n).

### 단순 알고리즘과의 비교
- 단순(naive) 알고리즘: **Ω(2ⁿ)**, 즉 최소 지수 시간. n = 50이면 계산이 사실상 불가능한 수준이다.
- 정렬 + 탐욕(sort + greedy) 알고리즘: **O(n log n)**. n = 1000만(10 million) 정도의 아이가 있어도 노트북에서 1초 이내에 계산 가능할 정도로 빠르다.

### 문제 해결 과정 요약
1. 문제를 수학적 용어로 재정식화(reformulate)한다: 아이 그룹화 문제 → 점을 선분으로 덮는 문제.
2. 탐욕적 선택을 찾는다: 가장 왼쪽 점을 왼쪽 끝이 그 점과 일치하는 길이 2 선분으로 덮는다.
3. 이 선택이 안전한 선택임을 증명한다.
4. 최종 알고리즘: 모든 점을 정렬 → 탐욕 알고리즘을 선형 시간에 실행.

## 예시
- 의사코드 요약:
  ```
  function PointsCoverSorted(x[1..n]):
      segments = []
      left = 1
      while left <= n:
          l = x[left]
          r = x[left] + 2
          segments.append((l, r))
          left = left + 1
          while left <= n and x[left] <= r:
              left = left + 1
      return segments
  ```
- 복잡도 비교표

| 알고리즘 | 실행 시간 | n=50일 때 | n=10,000,000일 때 |
|---|---|---|---|
| 단순 알고리즘(모든 분배 시도) | Ω(2ⁿ) | 계산 불가능 수준 | 계산 불가능 |
| 정렬 + 탐욕 | O(n log n) | 즉시 | 1초 이내 |

## 요약
- `PointsCoverSorted`는 정렬된 점 배열에 대해 **O(n)**(선형 시간)으로 동작한다.
- 정렬되지 않은 입력이라면 정렬에 O(n log n)이 필요하므로, 전체 알고리즘의 실행 시간은 **O(n log n)**이다.
- 이는 단순 알고리즘의 **Ω(2ⁿ)**에 비해 압도적으로 빠르며, 문제를 수학적으로 재정식화하고 안전한 선택을 찾아 증명하는 것이 이러한 개선의 핵심이었다.
