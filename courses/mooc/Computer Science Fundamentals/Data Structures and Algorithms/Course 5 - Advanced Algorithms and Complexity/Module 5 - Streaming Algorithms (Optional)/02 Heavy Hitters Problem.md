# Heavy Hitters Problem

## 개요
- heavy hitters 문제를 다시 정의하고, 네트워크 트래픽 추정과 검색 엔진 질의 통계 추정이라는 두 가지 실제 응용 사례를 소개한다.
- 이론적으로 지수적 개선(exponential improvement)을 보이는 스트리밍 알고리즘이 실제로도 실용적임을 HyperLogLog 사례로 뒷받침한다.

## 내용

### 문제 재정의
- N개의 데이터 항목 i1, …, iN에 대해 단일 패스로 스캔하여, 스트림에서 가장 빈번한 top k 항목을 알려주는 작은 공간(small space)의 알고리즘을 설계한다.
- 목표 공간 복잡도는 O(k log N)이다.

### 응용 1: 네트워크 트래픽 추정
- 스위치(switch)를 지나가는 IP 트래픽을 트래픽 행렬(traffic matrix)로 시각화할 수 있다. 행은 출발지 IP, 열은 목적지 IP이며, (i, j) 원소는 IP i에서 IP j로 전달된 패킷 수다.
- 스위치는 메모리가 제한적인 반면 지나가는 트래픽 양은 방대하다.
- 특정 출발지-목적지 IP 쌍(플로우, flow)이 트래픽의 대부분을 차지하는지 파악하는 것이 중요하다. 이런 지배적/거대 플로우(dominant/elephant flow)는 서비스 거부 공격(denial of service attack)이나 스팸 활동의 징후일 수 있다.
- 모든 출발지-목적지 쌍을 저장하는 자명한 해법은 공간이 (쌍의 개수에 대해) 선형(linear)으로 매우 크다.
- 이 강의에서 설계할 알고리즘은 이 문제를 근사적으로(approximately) 해결하며, 실제 존재하는 출발지-목적지 쌍의 개수에 대해 로그(logarithmic) 공간만 사용한다. N에서 log N으로의 개선은 지수적 절감이다.

### 응용 2: 검색 엔진 질의 통계 추정
- 검색 엔진(예: google.com)에 들어오는 질의(query)의 스트림을 생각한다.
- 예시 스트림: "Geneva to New York", "coffee in Geneva", "Geneva to New York" — 이 중 "Geneva to New York"이 두 번 등장해 heavy hitter(top 1)가 된다.
- 실제 규모에서는 스트림 길이가 훨씬 길어 자명한 해법(모든 서로 다른 질의를 저장)은 질의 수에 선형인 공간을 필요로 한다.
- 이 강의에서 다룰 해법인 CountSketch 알고리즘은 스트림 길이에 로그 공간만 사용하며, 역시 지수적 개선을 제공한다.

### 실용성: HyperLogLog 사례
- 스트리밍 알고리즘의 이론적 개선이 실제로도 상수(constant)가 작아 실용적인지 확인하기 위한 예시로 distinct elements 문제(스트림 내 서로 다른 항목 수를 근사적으로 세는 문제)를 든다.
- HyperLogLog는 이 문제에 대한 이론적으로 효율적이면서도 실제 구현이 매우 뛰어난 알고리즘이다.
- HyperLogLog는 셰익스피어(Shakespeare) 작품의 어휘 수를 단 128비트의 메모리만으로 추정할 수 있을 정도로 상수가 작다.
- 이 때문에 스트리밍 문헌에서 개발된 많은 알고리즘이 실제로 확장 가능한(scalable) 데이터 분석에 널리 쓰인다.

## 예시
- 스위치를 지나는 6~7개의 플로우 중 두 개가 각각 트래픽 4, 5를 차지해 전체 트래픽의 대부분을 차지하는 상황이 지배적 플로우의 예다.
- 검색 질의 스트림 예시: "Geneva to New York"(2회), "coffee in Geneva"(1회) → top 1 heavy hitter는 "Geneva to New York".
- HyperLogLog로 셰익스피어 어휘 수를 128비트 메모리만으로 근사 추정.

## 요약
- heavy hitters 문제는 네트워크 트래픽의 지배적 플로우 탐지, 검색 엔진의 인기 질의 파악 등 실제 응용이 다양하다.
- 두 응용 모두 자명한 해법은 선형 공간이 필요하지만, 스트리밍 알고리즘(CountSketch 포함)은 로그 공간으로 지수적 개선을 달성한다.
- HyperLogLog 사례가 보여주듯 이런 이론적 알고리즘들은 상수 인자가 작아 실제로도 실용적이다.
