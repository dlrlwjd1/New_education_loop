# Basic Estimate 2

## 개요
- 앞서 설계한 기초 추정량(basic estimate)의 분산(variance)을 계산하고, Chebyshev 부등식을 이용해 추정량이 높은 확률로 실제 값에 가까움을 보인다.
- 이 기초 추정량이 언제 잘 동작하고 언제 잘 동작하지 않는지 예시로 살펴본 뒤, 이를 개선한 최종 CountSketch 알고리즘의 아이디어(해싱 + 반복)를 소개한다.

## 내용

### Chebyshev 부등식
- 평균 μ, 분산 σ²을 가지는 확률 변수 X에 대해, X가 평균에서 표준편차의 t배 이상 벗어날 확률은 최대 1/t²이다.
- 여기서는 X = C × s(i) (i는 고정된 항목)로 두고 Chebyshev 부등식을 적용한다. 평균은 이미 fi로 계산되었으므로, 남은 과제는 분산을 구하는 것이다.

### 분산 계산
- C × s(i) − fi = Σ_{j≠i} f(j) · s(j) · s(i) 이므로, 분산은 이 항의 제곱의 기댓값이다.
- 이를 전개하면 이중 합(double summation): Σ_{j≠i} Σ_{j'≠i} f(j) f(j') s(j) s(j') s(i)² 형태가 되고, s(i)² = 1이다.
- j ≠ j'인 항의 경우 s(j)와 s(j')의 곱의 기댓값이 0이 되어 사라진다(독립이고 각각 평균 0).
- 따라서 분산은 정확히 Σ_{j≠i} f(j)² (i를 제외한 나머지 모든 항목의 빈도 제곱의 합)이 된다.

### 언제 추정이 잘 되는가
- Chebyshev 부등식으로 결론을 내리려면, "다른 항목들의 빈도 제곱 합의 제곱근"이 fi에 비해 작아야 한다.
- 이는 스트림과 질의 항목에 따라 다르다.
  - 항목 1이 스트림을 압도적으로 지배하는 히스토그램에서 항목 1을 추정하면 추정이 잘 된다. 즉 fi가 다른 항목들의 빈도 제곱 합의 제곱근보다 대략 크면 잘 동작한다.
  - 반대로 같은 스트림에서 항목 6처럼 작은 항목을 추정하면, 오차에 지배적인 항목 1의 기여가 섞여 들어가 추정이 매우 부정확해진다.
- 요약하면 기초 추정량은 스트림을 지배하는(dominant) 큰 항목을 추정할 때는 잘 동작하고, 작은 항목을 추정할 때, 특히 스트림에 매우 큰 항목이 존재할 때는 성능이 나쁘다.

### CountSketch 알고리즘으로의 개선 아이디어
- 이 결점을 고치기 위한 최종 알고리즘(ApproxPointQuery의 완성본, CountSketch)의 핵심 아이디어는 다음과 같다.
  1. 데이터 항목의 유니버스를 k개(정확히는 이후 정의할 b개)의 버킷(bucket)으로 해싱(hashing)하여 부분 스트림(substream)들을 구성한다.
  2. 각 부분 스트림에 대해 앞서 설계한 기초 추정량을 실행한다.
  3. 신뢰도를 높이기(boost confidence) 위해 이 과정을 로그(logarithmic) 횟수만큼 반복한다.
- 해싱 과정 덕분에, 큰 항목(heavy hitter)을 추정할 때 대부분의 부분 스트림은 그 큰 항목이 지배하는 형태가 되어 기초 추정량이 잘 동작하는 좋은 경우가 된다. 반대로 작은 항목을 추정할 때는 대부분 큰 항목에 오염되지 않은 부분 스트림에서 추정이 이루어지도록 만들 수 있다.

## 예시
- 항목 1이 스트림을 지배하는 히스토그램에서 항목 1을 추정하면 정확도가 높다.
- 같은 히스토그램에서 항목 6을 추정하면 항목 1의 큰 기여가 오차에 섞여 부정확해진다.

## 요약
- 기초 추정량의 분산은 Σ_{j≠i} f(j)²이며, 이 값이 fi에 비해 작을 때만 정밀한 추정이 가능하다.
- 큰 항목을 추정할 때는 잘 동작하지만, 작은 항목이면서 스트림에 큰 항목이 함께 있을 때는 성능이 나쁘다.
- 해싱을 통한 부분 스트림 구성과 로그 횟수의 반복(median 추정)이 최종 CountSketch 알고리즘의 핵심 아이디어다.
