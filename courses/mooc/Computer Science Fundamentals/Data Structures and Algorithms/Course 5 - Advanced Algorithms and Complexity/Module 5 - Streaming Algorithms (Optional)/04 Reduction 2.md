# Reduction 2

## 개요
- PointQuery(또는 ApproxPointQuery) 데이터 구조가 있다면 이를 이용해 FindTop(또는 FindApproxTop)을 구현할 수 있음을 형식적인 환원(reduction)으로 보인다.
- k = 1인 단순한 경우부터 시작해 일반적인 k에 대한 힙(heap) 기반 방법으로 확장한다.

## 내용

### k = 1인 경우 (정확한 PointQuery 가정)
- 스트림 S = i1, …, iN을 스캔하면서 PointQuery 데이터 구조를 유지한다.
- 추가로 현재까지의 최빈 항목(current maximum)과 그 빈도(frequency)를 저장하는 두 변수를 유지하며, 초기값은 각각 null과 0이다.
- 스트림의 각 위치 p에서 도착한 항목 ip에 대해 PointQuery로 현재 빈도 f를 얻는다.
  - 현재 최빈 항목이 ip이면 빈도만 갱신하고 계속 진행한다.
  - 아직 아무것도 저장하지 않은 상태(스트림 맨 처음)라면 ip를 저장하고 빈도를 1로 초기화한다.
  - 그렇지 않으면 저장된 항목의 빈도와 ip의 빈도(f)를 비교해, 더 큰 쪽으로 교체(swap)한다.
- 이 방식이 성립하는 이유는, 스트림의 각 위치에서 저장된 변수가 항상 null이거나 그 시점까지의 실제 최빈 항목이기 때문이다.

### 일반적인 k에 대한 힙(heap) 기반 환원
- PointQuery 데이터 구조와 함께, 최대 k개의 항목을 빈도 기준으로 유지하는 힙 H를 유지한다.
- 각 위치 p에서 현재 항목의 PointQuery 빈도 f를 구한 뒤:
  - 힙에 이미 해당 항목이 있으면 빈도만 갱신한다.
  - 힙의 크기가 k 미만이면 현재 빈도로 항목을 추가한다.
  - 힙이 이미 k개로 가득 찼다면, 힙에서 가장 빈도가 낮은(least frequent) 항목과 비교하여, 현재 항목이 더 빈번하면 최소 항목을 제거(evict)하고 현재 항목을 삽입한다.
- top k 항목의 집합이 유일(unique)하다고 가정하면, top k에 속하는 각 항목 i에 대해 스트림에서 i가 마지막으로 등장하는 위치를 pi라 할 때, 위치 pi에서 i는 힙에 삽입되며 이후 다시는 제거되지 않는다. 이로써 환원이 올바르게 동작함을 알 수 있다. (유일하지 않은 경우의 증명은 유사하며 연습 문제로 남긴다.)

### 근사 버전으로의 확장
- 위와 완전히 동일한 코드 구조가 근사 버전에도 그대로 적용된다.
- ApproxPointQuery가 매 시점 각 항목 i에 대해 오차가 최대 ε·fk 이내인 빈도 추정치를 반환한다면, 이 추정치를 정확한 값처럼 사용해도 동일한 알고리즘으로 FindApproxTop을 구현할 수 있다.
- 즉, 정확한 PointQuery 대신 근사 ApproxPointQuery의 추정값을 그대로 heap 갱신 로직에 사용하면 된다.

### 남은 과제
- 이 환원 덕분에 이제 남은 핵심 과제는 작은 공간을 사용하는 ApproxPointQuery 데이터 구조를 설계하는 것으로 좁혀진다.
- 앞으로 다룰 내용: 사용 공간, 근사 정밀도(quality of approximation), 성공 확률(success probability)의 구체적인 파라미터 설정.

## 요약
- k = 1일 때는 현재 최빈 항목과 빈도 두 변수만으로 FindTop을 PointQuery로 환원할 수 있다.
- 일반적인 k에 대해서는 크기 k의 힙을 이용해 동일한 아이디어를 확장할 수 있다.
- 이 환원은 정확한 PointQuery뿐 아니라 근사 ApproxPointQuery에도 그대로 적용되므로, 이후 강의는 ApproxPointQuery 설계에 집중한다.
