# Introduction

## 개요
- 스트리밍 모델(streaming model of computation)의 정의와 이 모듈에서 다룰 핵심 문제인 heavy hitters 문제를 소개한다.
- 강의자는 Michael Kapralov이며, 데이터 스트림(data stream)에서 가장 빈번하게 등장하는 항목들을 찾는 알고리즘을 다룬다.

## 내용

### 스트리밍 모델(streaming model of computation)
- 1990년대 Alon, Matias, Szegedy의 논문에서 처음 정의된 오래된 계산 모델이다.
- 알고리즘은 매우 긴 데이터 항목의 스트림 i1, i2, …, iN을 관찰한다. 데이터 항목은 IP 패킷, 트윗, 검색 질의(search query) 등 무엇이든 될 수 있다.
- 스트림을 한 번만 훑는(single pass) 것으로 가정하며, 스트림 길이 N은 미리 알 수 없다고 가정한다.
- 알고리즘은 지금까지 본 스트림에 대한 작은 크기의 요약(small space summary)을 유지해야 하고, 이 요약으로부터 스트림의 기본적인 통계적 성질을 질의(query)할 수 있어야 한다.
- 저장 공간(storage capacity)은 스트림 길이보다 훨씬 작은 준선형(sub-linear) 크기여야 한다. 일반적으로 n^α (α < 1) 수준이며, 이번 강의에서 다루는 설정은 스트림 길이에 대해 다항로그(polylogarithmic) 수준의 공간이다.
- 공간은 비트, 바이트, 워드 단위로 측정할 수 있고, 경우에 따라 포인트(point)나 데이터 항목 수로 측정하기도 한다.
- 준선형 공간 복잡도를 달성하려면 많은 경우 무작위성(randomization)이 필요하며, 이번에 다루는 문제 역시 그렇다.

### heavy hitters 문제
- 알고리즘은 데이터 항목 시퀀스 i1, i2, …, iN을 한 번 훑고, 스트림 처리가 끝난 뒤 스트림에서 가장 빈번한 k개의 항목을 출력해야 한다.
- 이 k개의 지배적인(dominant) 최빈 항목을 k heavy hitters라고 부른다.
- 목표는 공간 복잡도 O(k log N) 수준의 알고리즘을 설계하는 것이다.
- 예를 들어 k = 1이면 공간 복잡도는 스트림 길이에 대해 로그(logarithmic) 수준이 되며, 이는 전체 스트림을 저장하는 자명한(trivial) 해법(공간 복잡도 O(N))보다 지수적으로(exponentially) 개선된 결과다.

## 예시
- 데이터 항목을 1부터 10 사이의 숫자로 나타낸 예시 스트림을 사용한다.
- 스트림이 진행되며 빈도 히스토그램(frequency histogram)이 갱신된다. 예를 들어 항목 3이 두 번 도착하면 히스토그램상 빈도 2로 표시된다.
- 예시 스트림에서 항목 3이 6번 등장해 다른 모든 항목(최대 5번)보다 많이 등장했으므로, 항목 3이 이 스트림의 최빈 항목(heavy hitter)이다.

## 요약
- 스트리밍 모델은 단일 패스(single pass), 준선형 공간, 낮은 처리 시간을 요구하는 계산 모델이다.
- heavy hitters 문제는 스트림에서 가장 빈번한 k개 항목을 O(k log N) 공간으로 찾는 문제로 정의된다.
- 다음 영상에서는 네트워크 트래픽 모니터링과 검색 질의 통계 추정 등 이 문제의 응용 사례를 다룬다.
