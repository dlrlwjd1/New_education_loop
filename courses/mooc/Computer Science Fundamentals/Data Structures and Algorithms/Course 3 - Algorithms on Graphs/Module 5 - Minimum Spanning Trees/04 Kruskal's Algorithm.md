# Kruskal's Algorithm

## 개요
- 크루스칼 알고리즘(Kruskal's algorithm)이 최소 신장 트리(minimum spanning tree)를 만든다는 것을 절단 속성(cut property)으로 증명한다.
- 서로소 집합(disjoint sets) 자료구조를 이용한 구현 세부 사항과 예시를 다룬다.
- 알고리즘의 시간 복잡도(running time)를 분석한다.

## 내용

### 알고리즘 진행 중 구조: 포레스트
- 크루스칼 알고리즘은 빈 집합 $X$에서 시작해 사이클을 만들지 않는 가장 가벼운 간선을 반복적으로 추가한다.
- 알고리즘 진행 중 어느 시점이든 $X$는 트리들의 모음, 즉 포레스트(forest)를 이룬다. 초기에는 각 정점이 크기 1짜리 트리(고립된 정점)를 이룬다.

### 절단 속성을 이용한 최적성 증명
- 어느 시점에 다음으로 추가할 가장 가벼운 간선 $e$가 서로 다른 두 트리 $T_1$과 다른 트리를 연결한다고 하자(같은 트리 안이면 사이클이 생기므로 추가하지 않는다).
- 이때 한 트리($T_1$)에 속한 정점 전체를 분할의 한쪽 $S$로, 나머지 정점을 $V-S$로 두면, $e$는 이 분할을 가로지르는 가장 가벼운 간선이 된다.
- 절단 속성에 의해 $e$를 $X$에 추가하는 것은 안전한(safe) 선택이며, 이 과정을 반복해 만든 트리가 곧 최소 신장 트리다.

### 서로소 집합 자료구조를 이용한 구현
- 두 정점이 같은 연결 요소(connected component, 즉 같은 트리)에 있는지 확인해야 하며, 다른 트리라면 두 트리를 합쳐야(merge) 한다. 이 작업에 서로소 집합(disjoint sets) 자료구조가 적합하다.
- 두 정점 $u$, $v$가 다른 연결 요소에 있는지는 `Find(u) ≠ Find(v)`로 확인한다.
- 간선을 추가할 때는 `Union(u, v)`를 호출해 두 트리를 합친다.

### 서로소 집합 갱신 예시(정점 A~F)
- 초기에는 각 정점이 별도의 집합에 속한다.
- 가중치 순으로 간선을 처리한다.
  - 간선 AE: `Find(A) ≠ Find(E)`이므로 추가하고 `Union(A, E)`.
  - 간선 CF: `Find(C) ≠ Find(F)`이므로 추가하고 `Union(C, F)`.
  - 간선 AD: `Find(A) ≠ Find(D)`이므로 추가하고 `Union(A, D)` → 이제 {A, E, D}, {B}, {C, F} 세 집합이 존재한다.
  - 간선 DE(가중치 3): `Find(D) = Find(E)`이므로 사이클이 생겨 건너뛴다.
  - 간선 AB: `Find(A) ≠ Find(B)`이므로 추가하고 `Union(A, B)`.
  - 간선 BE(가중치 5): 같은 집합이므로 건너뛴다.
  - 간선 BF(가중치 8): 다른 집합이므로 추가하고 `Union(B, F)` → 모든 정점이 하나의 집합이 되어 최소 신장 트리 완성.

## 예시

### 의사코드
```
Kruskal(G):
    for each vertex v in G.V:
        MakeSet(v)
    X = ∅
    sort edges of G.E by weight
    for each edge (u, v) in G.E, in non-decreasing order of weight:
        if Find(u) != Find(v):
            add edge (u, v) to X
            Union(u, v)
    return X
```

### 시간 복잡도 분석
- 간선 정렬(sorting): $O(E \log E)$이며, 단순 그래프에서 $E \le V^2$이므로 $O(E \log V^2) = O(2E \log V) = O(E \log V)$로 다시 쓸 수 있다.
- 간선 처리 단계: 각 간선마다 `Find`를 두 번 호출하므로 총 $O(E)$번의 `Find` 호출이 있고, `Union`은 연결 요소 수가 $V$에서 1로 줄어들므로 최대 $V-1$번 호출된다.
- 서로소 집합을 트리(포레스트)로 구현하고 랭크에 의한 합침(union by rank) 휴리스틱을 쓰면 각 연산은 $O(\log V)$이며, 그래프가 연결되어 있어 $E \ge V - 1$이므로 전체는 $O(E \log V)$가 된다.
- 랭크에 의한 합침과 경로 압축(path compression)을 함께 쓰면 각 연산은 $O(\log^* V)$까지 줄어들지만, 간선 정렬 비용이 여전히 $O(E \log V)$이므로 전체 복잡도는 개선되지 않는다.
- 다만 간선이 이미 정렬된 상태로 주어지는 경우에는 정렬 비용이 없으므로, 전체 시간 복잡도가 $O(E \log^* V)$(거의 선형)까지 줄어든다.

## 요약
- 크루스칼 알고리즘의 안전성은 절단 속성에서 직접 도출된다: 서로 다른 트리를 잇는 가장 가벼운 간선은 그 트리의 정점 집합을 기준으로 한 분할을 가로지르는 최소 간선이기 때문이다.
- 구현은 서로소 집합 자료구조(`MakeSet`, `Find`, `Union`)를 이용해 사이클 여부를 판별한다.
- 일반적인 시간 복잡도는 $O(E \log V)$이며, 간선이 미리 정렬돼 있으면 $O(E \log^* V)$까지 줄일 수 있다.
