# Prim's Algorithm

## 개요
- 프림 알고리즘(Prim's algorithm)이 트리를 하나씩 키워가며 최소 신장 트리를 만드는 과정을 예시로 설명한다.
- 다익스트라 알고리즘(Dijkstra's algorithm)과의 유사성을 짚고, 우선순위 큐(priority queue)를 이용한 구현과 의사코드를 제시한다.
- 시간 복잡도를 우선순위 큐 구현 방식(배열 vs 이진 힙)에 따라 비교하고, 모듈 전체 내용을 요약한다.

## 내용

### 알고리즘의 핵심 아이디어
- 집합 $X$는 항상 트리를 이루며, 매 반복마다 아직 트리에 없는 정점 중 현재 트리에 가장 가벼운 간선으로 연결되는 정점을 하나 골라 트리에 추가한다.
- 이는 다익스트라 알고리즘이 시작 정점으로부터의 최단 경로 트리를 만드는 방식과 매우 유사하다.

### 우선순위 큐를 이용한 예시 진행
- 초기에는 모든 정점의 우선순위(현재 트리에 붙이는 비용)를 무한대(infinity)로 둔다.
- 임의의 정점을 루트로 정하고 그 우선순위를 0으로 바꾼다.
- 루트에서 나가는 간선을 따라 인접 정점들의 우선순위를 갱신한다(가중치 1, 8 등).
- 매 반복마다 우선순위가 가장 낮은 정점을 추출(extract)해 트리에 편입시키고, 그 정점에서 나가는 간선으로 트리 밖 인접 정점들의 우선순위를 더 낮은 값으로 갱신할 수 있으면 갱신한다.
- 이 과정을 반복해 모든 정점이 트리에 편입되면 완성된 트리가 최소 신장 트리다.

### 의사코드의 구조
- 배열 `cost`: 각 정점을 현재 트리에 연결하는 최소 비용을 저장한다. 초기값은 모두 무한대이며, 루트 정점 $u_0$만 0으로 설정한다.
- 배열 `parent`: 최종 트리에서 각 정점의 부모를 저장한다. 초기값은 모두 미정의(undefined)다.
- 우선순위 큐에는 처음에 모든 정점이 `cost` 값을 우선순위로 하여 들어간다.
- 매 반복에서 우선순위가 최소인 정점 $v$를 추출하고, $v$의 이웃 $z$ 중 아직 큐에 남아 있고 `cost[z]`가 간선 $(v, z)$의 가중치보다 크면 `cost[z]`를 그 가중치로, `parent[z]`를 $v$로 갱신한 뒤 우선순위 큐의 우선순위도 갱신한다.

## 예시

### 진행 예시(같은 6정점 그래프)
- 루트에서 시작해 가중치 1인 간선으로 다음 정점을 편입한다.
- 이어서 가중치 6인 간선으로 다음 정점을 편입하면서, 다른 두 정점의 우선순위를 각각 4와 5로 더 낮게 갱신한다(더 싼 연결 경로를 발견).
- 우선순위 4인 정점을 편입하고, 남은 두 정점의 우선순위를 1과 2로 갱신한다.
- 우선순위 1인 정점, 마지막으로 우선순위 2인 정점을 차례로 편입해 트리를 완성한다.
- 완성된 트리의 총 가중치는 $2 + 1 + 4 + 6 + 1 = 14$다.

### 의사코드
```
Prim(G):
    for each vertex v in G.V:
        cost[v] = ∞
        parent[v] = null
    pick any vertex u0 in G.V
    cost[u0] = 0
    PriorityQueue Q = G.V, with priorities cost[·]
    while Q is not empty:
        v = ExtractMin(Q)
        for each neighbor z of v:
            if z is in Q and cost[z] > weight(v, z):
                cost[z] = weight(v, z)
                parent[z] = v
                ChangePriority(Q, z, cost[z])
```

### 시간 복잡도 분석
- 알고리즘은 `ExtractMin`을 $V$번, `ChangePriority`를 최대 $E$번 호출한다.
- **배열(array)로 우선순위 큐 구현**: `ChangePriority`는 $O(1)$이지만 `ExtractMin`은 배열 전체를 훑어야 하므로 $O(V)$다. 따라서 전체는 $O(V^2)$.
- **이진 힙(binary heap)으로 구현**: `ExtractMin`과 `ChangePriority` 모두 $O(\log V)$이며, 그래프가 연결되어 $E \ge V-1$이므로 전체는 $O((V+E)\log V) = O(E \log V)$가 된다.
- 어느 구현이 더 나은지는 그래프가 밀집(dense)인지 여부에 달려 있다.

## 요약
- 프림 알고리즘은 다익스트라 알고리즘과 유사하게 우선순위 큐를 이용해 트리를 하나씩 키운다.
- 각 정점에 "현재 트리에 붙는 최소 비용"을 저장하고, 정점을 편입할 때마다 그 이웃의 비용을 갱신한다.
- 시간 복잡도는 배열 기반 구현에서 $O(V^2)$, 이진 힙 기반 구현에서 $O(E \log V)$다.
- 모듈 전체 요약: 크루스칼 알고리즘은 사이클을 만들지 않는 가장 가벼운 간선을 서로소 집합으로 판별하며 추가하고, 프림 알고리즘은 우선순위 큐로 트리를 확장한다. 두 방식 모두 절단 속성(cut property)에 의해 최적성이 보장된다.
