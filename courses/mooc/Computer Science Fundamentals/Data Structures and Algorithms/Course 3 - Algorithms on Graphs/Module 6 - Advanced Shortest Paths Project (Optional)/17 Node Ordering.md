# Node Ordering

## 개요
- Contraction Hierarchies의 전처리·질의 속도를 좌우하는 정점 축약 순서(node ordering)를 어떻게 정할지 다룬다.
- 어떤 순서로 축약해도 알고리즘은 항상 올바르게 동작하지만, 순서에 따라 전처리 시간과 질의 시간이 크게 달라진다.
- 정점 중요도(importance)를 근사하기 위한 네 가지 기준(edge difference, contracted neighbors, shortcut cover, node level)과, 이를 반영하는 우선순위 큐 기반 알고리즘을 소개한다.

## 내용

### 좋은 순서가 갖춰야 할 세 가지 목표
- 추가되는 지름길(shortcut)의 수를 최소화한다. 지름길이 늘어날수록 증강 그래프의 간선이 늘어나 Dijkstra 계열 알고리즘이 느려진다.
- 중요한 정점들을 지도 전역에 고르게 분산시킨다. 실제로 충분히 큰 지역마다 중요한 도시가 존재하므로, 이 성질을 반영해야 한다.
- 증강 그래프에서 최단 경로 상의 간선 수 자체도 최소화한다. 즉 그래프를 도로망보다는 소셜 네트워크(예: 6단계 분리)에 가깝게 만들어, 양방향 Dijkstra가 몇 단계 만에 만나도록 지름길을 적절히 배치한다.

### 우선순위 큐 기반 축약 알고리즘
- 모든 정점을 중요도의 음수 값을 우선순위로 하는 우선순위 큐(priority queue)에 넣어, 가장 덜 중요한 정점이 큐의 맨 위에 오도록 한다.
- 매 반복(iteration)마다 큐에서 가장 덜 중요한 정점을 꺼내되, 다른 정점들의 축약으로 인해 중요도가 바뀌었을 수 있으므로 먼저 중요도를 다시 계산(recompute)한다.
- 새로 계산한 중요도를 현재 큐에 남아 있는 정점 중 가장 덜 중요한 정점(큐의 head)의 중요도와 비교한다.
- 재계산한 중요도가 여전히 최소라면 그 정점을 그대로 축약한다. 그렇지 않다면 갱신된 중요도로 다시 큐에 넣는다.
- 이 과정이 무한히 반복될 것 같지만, 실제로는 유한한 횟수 안에 반드시 정점이 축약됨이 보장된다. 정점을 축약하지 않고 중요도만 갱신할 때마다 그 정점의 중요도는 현재 남은 정점 집합 기준으로 최신화되며, 최대 (정점 개수)번의 시도 안에 모든 정점의 중요도가 최신 상태가 되어 그중 최소 중요도를 가진 정점이 반드시 축약된다. 실전에서는 보통 한두 번의 반복만으로 축약이 이루어져 빠르게 동작한다.

### 중요도 기준 1 — Edge Difference
- 정점 v를 축약할 때 실제로 추가될 지름길 수에서, 삭제되는 간선 수(v의 차수, degree)를 뺀 값을 edge difference라 한다.
- v를 축약하면 그래프의 간선 수가 정확히 edge difference만큼 증가한다.
- edge difference가 작은 정점을 먼저 축약하면 증강 그래프의 간선 수와 전처리 중인 그래프의 간선 수를 모두 줄일 수 있어 전처리 시간에도 영향을 준다.

### 중요도 기준 2 — Contracted Neighbors
- 이미 축약된 이웃 정점의 수를 나타낸다.
- 이미 축약된 이웃이 적은 정점을 먼저 축약하면, 축약되는 정점들이 한 지역에 몰리지 않고 지도 전역에 고르게 분산된다.

### 중요도 기준 3 — Shortcut Cover
- 정점 v를 축약할 때 지름길을 새로 만들어야 하는 이웃 w의 개수를 뜻하며, v가 얼마나 "우회 불가능한(unavoidable)" 정점인지를 나타낸다.
- 예를 들어 샌프란시스코와 오클랜드 사이의 트레저 아일랜드처럼, v가 많은 이웃 w에게 중요하다면 v 자체도 중요한 정점이다.
- shortcut cover가 작은 정점을 먼저 축약해야 한다.

### 중요도 기준 4 — Node Level
- 정점 v의 레벨 L(v)은 증강 그래프에서 임의의 정점 s로부터 v까지의 최단 경로 상 간선 수의 상한(upper bound)이다.
- 레벨은 0에서 시작하며, 정점 v를 축약할 때 v의 이웃 u에 대해: u에 도달하는 데 v를 거치지 않는 경로도 있을 수 있고(이 경우 영향 없음), v를 거쳐 도달할 수도 있다(이 경우 v까지 최대 L(v)개의 간선, 그리고 v→u 간선 1개가 추가로 필요). 따라서 L(u)는 L(v)+1로 갱신(최댓값 취함)된다.
- 레벨이 낮은(즉 덜 중요한) 정점을 먼저 축약해야 한다.

### 종합 중요도 계산과 실전 성능
- 위 네 가지 값을 단순히 합산한 값을 정점의 중요도(importance)로 사용한다. 이는 휴리스틱(heuristic)이지만 실전에서 잘 동작한다.
- 각 항목에 가중치를 두어(예: 2×edge difference + 3×contracted neighbors + …) 추가로 최적화할 수 있으며, 네 가지 기준 중 어느 하나라도 빠지면 전처리나 질의 시간이 지나치게 길어질 수 있다.
- 네 값 모두 전처리의 어느 단계에서든(처음이든, 이미 일부 정점이 축약된 이후든) 효율적으로 계산할 수 있어야 한다.
- 실측 성능: 약 1,800만 개 정점을 가진 유럽 도로망 그래프에서, 무작위로 선택한 정점 쌍에 대해 고전 Dijkstra는 평균 4.3초가 걸리지만, Contraction Hierarchies(휴리스틱 튜닝 포함)는 평균 18밀리초로 약 25,000배 빠르다.
- 그래프 규모가 유럽에서 전 세계로 커질수록 이 속도 향상 폭은 더 커진다.
- 과제(programming assignment)에서 요구되는 최소 성능 향상은 고전 Dijkstra 대비 수천 배(1000s of times) 수준이다.

## 예시
- Edge difference 계산: 추가되는 지름길 수 − v의 차수(degree, 삭제되는 간선 수)
- Node level 갱신 규칙: L(u) ← max(L(u), L(v) + 1) (v를 거쳐 u에 도달하는 경우)
- 종합 중요도(단순 합산): importance(v) = edge difference + contracted neighbors + shortcut cover + node level
- 가중치를 둔 변형 예: importance(v) = 2×edge difference + 3×contracted neighbors + …
- 실측 성능 비교: 유럽 그래프(정점 약 1,800만 개) 기준, 고전 Dijkstra 평균 4.3초 vs Contraction Hierarchies 평균 18ms (약 25,000배 향상)

## 요약
- 정점 축약 순서는 정확성에는 영향을 주지 않지만 전처리·질의 속도에 큰 영향을 미치므로, 지름길 최소화·중요 정점 분산·경로 간선 수 최소화라는 세 목표를 반영한 순서를 골라야 한다.
- edge difference, contracted neighbors, shortcut cover, node level 네 기준을 합산한 값을 정점 중요도로 사용하고, 우선순위 큐에서 재계산-비교를 반복하며 가장 덜 중요한 정점부터 축약한다.
- 실전에서는 이 방식이 고전 Dijkstra 대비 수천 배에서 최대 수만 배까지 속도를 향상시킬 수 있다(유럽 그래프 기준 약 25,000배).
