# Computing the Distance

## 개요
- 앞서 증명한 정리를 바탕으로 양방향 다익스트라(bidirectional Dijkstra)의 실제 알고리즘 절차를 정리한다.
- 경로 재구성(path reconstruction) 방법과 양방향 다익스트라의 시간·공간 복잡도를 일반 다익스트라와 비교한다.

## 내용

### 알고리즘 절차
- 정방향 탐색과 역방향 탐색을 번갈아 진행하다가 어떤 정점 $v$에서 만나면(양쪽 모두에서 처리되면) 탐색을 멈춘다.
- 정방향에서 처리된 정점들과 역방향에서 처리된 정점들을 각각 기록해 둔다.
- 둘 중 적어도 한쪽에서 처리된 모든 정점에 대해 $\text{dist}(u) + \text{dist}_R(u)$ 값을 계산하고, 이 합이 최소가 되는 정점 $u$를 찾는다.
- 이 최솟값이 곧 $s$-$t$ 최단 거리이며, 그 정점 $u$가 최단 경로가 지나는 정점이다.

### 경로 재구성
- $s$에서 $u$까지의 경로는 정방향 탐색에서, $u$에서 $t$까지의 경로는 역방향 탐색에서 각각 재구성한 뒤 두 경로를 이어 붙이면 전체 최단 경로가 된다.

### 성능 비교
- **시간 복잡도**: 양방향 다익스트라의 최악 시간 복잡도는 점근적으로(asymptotically) 일반 다익스트라와 동일하다. 도로망에서 관측한 2배 속도 향상은 점근적 차이가 아니라 상수 배 개선이다.
- **공간 복잡도**: 그래프 $G$와 역방향 그래프 $G^R$을 모두 저장해야 하고, 정방향·역방향 각각에 대한 보조 배열도 따로 필요하므로 메모리 사용량이 대략 2배가 된다. 이 역시 점근적으로 더 나쁜 것은 아니다.

## 요약
- 양방향 다익스트라는 두 탐색이 만난 뒤, 처리된 모든 정점 중 $\text{dist}(u) + \text{dist}_R(u)$가 최소인 정점 $u$를 찾아 최단 거리와 경로를 계산한다.
- 점근적 시간 복잡도는 일반 다익스트라와 같지만, 실무에서는 도로망에서 약 2배, 소셜 네트워크에서는 수천 배까지 속도 향상을 얻을 수 있다.
- 대신 그래프와 보조 배열을 두 벌 유지해야 하므로 메모리 사용량은 약 2배가 된다.
