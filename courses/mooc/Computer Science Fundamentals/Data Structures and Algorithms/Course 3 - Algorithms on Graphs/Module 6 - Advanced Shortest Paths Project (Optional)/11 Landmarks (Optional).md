# Landmarks (Optional)

## 개요
- 유클리드 거리(Euclidean distance) 외에 좋은 퍼텐셜(potential)을 얻는 또 다른 방법인 랜드마크(landmark) 기반 퍼텐셜을 다룬다.
- 랜드마크까지의 거리를 미리 계산(precompute)해 두면, 삼각 부등식(triangle inequality)을 이용해 실행 가능(feasible)하고 하한(lower bound)이 되는 퍼텐셜을 만들 수 있음을 증명한다.
- 랜드마크를 여러 개 선택하고 결합하는 방법과, 실전에서 랜드마크를 배치하는 전략을 소개한다.

## 내용

### 랜드마크 퍼텐셜의 정의
- 정점 A를 하나 고정하고 이를 랜드마크(landmark)라 부른다.
- 퍼텐셜을 π(v) = d(A, t) − d(A, v)로 정의한다. 여기서 d는 그래프 상의 실제 거리(distance)이며, t는 목표 정점이다.
- d(A, t)와 d(A, v)는 미리 알 수 없으므로, 랜드마크 A에서 다른 모든 정점까지의 거리를 사전에 계산해 둔다고 가정한다.

### 랜드마크 퍼텐셜이 실행 가능함(feasible)의 증명
- 새 그래프에서 간선 (u, v)의 길이를 정의에 따라 풀어 쓰면: l(u,v) − π(u) + π(v) = l(u,v) − (d(A,t) − d(A,u)) + (d(A,t) − d(A,v))
- d(A,t) 항이 서로 상쇄되어: = d(A,u) + l(u,v) − d(A,v)
- 삼각 부등식에 의해 d(A,v) ≤ d(A,u) + l(u,v)이므로, 위 식은 항상 0 이상(non-negative)이다.
- 따라서 이 퍼텐셜은 실행 가능하다.
- 목표 정점 자신에 대한 퍼텐셜 값은 π(t) = d(A,t) − d(A,t) = 0이다.
- 실행 가능하고 π(t) = 0(즉 0 이하)이므로, 이 퍼텐셜은 임의의 정점 v에서 목표까지의 실제 거리에 대한 하한(lower bound)이다.

### 여러 랜드마크 조합하기
- 랜드마크를 여러 개(예: 10개) 선택하고, 각 랜드마크에서 다른 모든 정점까지의 거리를 미리 계산한다.
- 모든 정점까지의 거리를 구해야 하므로 양방향 탐색이나 A*로는 이 사전 계산 자체를 줄일 수 없으며, 그래프 전체를 스캔하는 알고리즘(예: Dijkstra)을 랜드마크마다 한 번씩 실행해야 한다. 다만 이는 전처리(pre-computation) 단계에서 한 번만 수행하면 된다.
- 임의의 랜드마크 A에 대해 삼각 부등식으로부터 두 가지 하한을 얻을 수 있다.
  - d(v, t) ≥ d(A, t) − d(A, v)
  - d(v, t) ≥ d(v, A) − d(t, A) (랜드마크에서 다른 정점으로의 거리뿐 아니라, 다른 정점에서 랜드마크로의 거리도 미리 계산해 두면 사용 가능하며, 이는 그래프를 뒤집어(reverse) 각 랜드마크에서 다시 탐색하면 얻을 수 있다.)
- 각 정점 v에 대해 선택된 모든 랜드마크에 대한 위 두 하한 중 최댓값(maximum)을 취하면, 그 정점에 대해 가장 타이트한(tightest) 하한을 얻는다. 하한이 타이트할수록 A* 탐색이 더 빨라진다.

### 랜드마크 선택 전략
- 좋은 랜드마크는 출발 정점(source) 이전이나 목표 정점(target) 이후에 위치하는 경향이 있어야 하한을 실질적으로 개선한다.
- 어떤 질의(query)가 오더라도 대응할 수 있도록, 출발점보다 앞쪽과 목표점보다 뒤쪽 모두에 랜드마크가 있어야 한다.
- 실전에서는 지도의 경계(border) 부근에 랜드마크를 배치하는 것이 효과적이다. 예를 들어 미국 지도에서 여러 개의 랜드마크를 배치하면, 특정 질의에서는 그중 일부(예: 4개)만 실제로 하한 개선에 기여한다.
- 소수의 랜드마크(예: 약 20~21개)만으로도 방문하는 정점 수를 일반 양방향 탐색보다 크게 줄일 수 있다.

### 전처리 비용과 실전 적용
- 랜드마크 방식은 20개 정도의 랜드마크에서 모든 정점까지의 거리를 미리 계산해야 하므로 전처리 비용이 든다.
- 질의(query)가 한 번뿐이면 굳이 20번의 랜드마크 탐색을 거치는 것보다 직접 최단 경로를 구하는 편이 빠르다.
- 반면 질의가 많다면(예: 1,000번) 랜드마크 전처리(20번의 탐색)에 드는 비용을 상쇄하고도 남을 만큼 이후 질의들이 훨씬 빨라진다.

## 예시
- 랜드마크 퍼텐셜 정의: π(v) = d(A, t) − d(A, v)
- 실행 가능성 증명: l(u,v) − π(u) + π(v) = d(A,u) + l(u,v) − d(A,v) ≥ 0 (삼각 부등식 d(A,v) ≤ d(A,u) + l(u,v)에 의해)
- 목표 정점에서의 값: π(t) = 0
- 두 방향 하한: d(v,t) ≥ d(A,t) − d(A,v), d(v,t) ≥ d(v,A) − d(t,A)
- 여러 랜드마크의 최댓값 결합: 각 정점 v에 대해 선택된 랜드마크 집합에서 위 하한들의 최댓값을 사용

## 요약
- 랜드마크 A에서 목표/정점까지의 거리를 미리 계산해 두면, π(v) = d(A,t) − d(A,v)는 삼각 부등식에 의해 실행 가능하고 목표에서 값이 0인 퍼텐셜이 된다.
- 여러 랜드마크를 사용하고 각 정점에서 하한들의 최댓값을 취하면 더 타이트한 하한을 얻어 A* 탐색을 가속할 수 있다.
- 좋은 랜드마크는 지도의 경계(출발점 이전/목표점 이후)에 분산 배치하는 것이 효과적이며, 질의 횟수가 많을수록 랜드마크 전처리 비용이 상쇄된다.
