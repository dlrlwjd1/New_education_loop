# Case Study - Accessibility at Meta

## 개요
- Meta가 화면 읽기 도구, 글자 크기와 키보드 사용자를 위해 접근성을 구현·검증하는 방법을 알아본다.

## 내용
### 접근성 목표
화면 읽기 도구가 모든 요소를 이해하고, 글자 크기를 조절하며, 키보드만으로도 기능을 사용할 수 있어야 한다. 모든 사용자에게 같은 가치의 경험을 제공한다.

### 개발 중 검증
키보드 탭 순서와 단축키, 화면 읽기 도구의 요소 식별을 확인한다. 공통 UI 컴포넌트는 누락된 `aria-label` 같은 문제를 시각적으로 경고한다.

### 시스템 수준 지원
공통 컴포넌트와 스타일 변환으로 글자 크기 설정을 사이트 전체에 자동 적용하고, 출시 후에는 접근성 전문가와 표준 준수 여부를 검증한다.

## 예시
새 버튼에 접근 가능한 이름이 없으면 개발 도구가 경고를 표시하고, 엔지니어가 `aria-label`을 추가해 화면 읽기 도구에서 의미를 전달한다.

## 요약
- 화면 읽기, 글자 크기, 키보드 탐색을 기본 요구 사항으로 다룬다.
- 공통 컴포넌트에 접근성을 내장해 누락을 줄인다.
- 개별 변경과 출시 제품 모두 반복 검증한다.
