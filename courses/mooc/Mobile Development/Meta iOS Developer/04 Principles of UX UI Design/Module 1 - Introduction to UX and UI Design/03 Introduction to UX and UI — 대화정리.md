# Introduction to UX and UI — 대화정리

## 개요
- 사용자 경험(UX)과 사용자 인터페이스(UI)의 차이와 관련 직무를 구분한다.
- 수정 지시를 할 때 "이건 UX 문제인지 UI 문제인지"를 나누는 기준이 되는 강의.

## 내용

### UX (사용자 경험)
- 웹사이트 화면에 국한되지 않는다. 직원, 서비스, 음식, 공간, 디지털 제품까지 — **사용자가 사업과 접촉하는 전체 경험**이다.
- 사용자의 필요(needs), 목표 달성을 막는 요소, 사용 흐름의 직관성·효율성을 조사하고 해결한다.

### UI (사용자 인터페이스)
- 사용자가 실제로 보고 조작하는 것 — 글자, 색상, 버튼, 도형, 아이콘, 이미지.
- 이 요소들을 논리적이고 아름답게 조합해, 사용자가 브랜드 경험 안에서 목표를 **빠르게** 달성하게 한다.

### 실전 구분 기준 (대화에서 정리)
- "버튼 색이 배경과 비슷해서 잘 안 보인다" → **UI 문제**. 사용자가 눈으로 보는 시각 요소(색상, 대비)의 문제이지, 흐름·목표의 문제가 아니다.
- 반대로 "버튼은 잘 보이는데 눌러야 다음 단계로 간다는 걸 몰라서 헤맨다" → **UX 문제**. 흐름과 이해의 문제.
- 요약하면: **"안 보인다(시각) → UI" vs "헤맨다(흐름·이해) → UX"**로 구분하면 실전에서 쓸모 있는 잣대가 된다.

### 역할과 조직 규모
- **작은 회사**: 한 사람이 조사, 설계, 구현까지 다 맡는다.
- **큰 회사**: 전문 역할로 세분화된다 — **UX 연구, UX 카피, 디자인 시스템, 접근성(accessibility)** 등.

## 예시
UX 디자이너가 음식 주문 문제를 조사해 흐름과 프로토타입을 만들면, UI 디자이너는 디자인 시스템을 활용해 명확하고 일관된 화면과 상호작용을 구성한다.

## 요약
- UX는 사용자의 전체 경험과 문제 해결 과정, UI는 사용자가 보는 시각 요소와 상호작용 설계다.
- 실전 판단 기준: 안 보이는 문제는 UI, 헤매는 문제는 UX.
- 조직 규모가 커질수록 UX 연구·UX 카피·디자인 시스템·접근성처럼 역할이 전문화된다.
