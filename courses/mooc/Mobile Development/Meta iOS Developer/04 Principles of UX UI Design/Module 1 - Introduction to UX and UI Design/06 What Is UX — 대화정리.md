# What Is UX — 대화정리

## 개요
- 사용자 경험(UX)의 범위와 반복적인 UX 설계 프로세스를 다룬다.
- 03강에서 배운 UX 정의를 더 구체적으로 파고드는 강의.

## 내용

### 전체 경험
- UX는 사용자가 회사·서비스·제품과 상호작용하는 **전(before)·중(during)·후(after) 모든 경험**을 포함한다.
- 핵심 질문: 사용자가 목표를 쉽게 달성하는가? 통제감을 느끼는가? 기능이 **발견 가능(discoverable)**한가? 행동에 적절한 피드백을 주는가?

### 발견 가능성(discoverability) — 대화에서 정리
- "발견 가능하다"는 사용자가 어떤 기능이 거기 있다는 걸 **쉽게 알아차릴 수 있는가**를 뜻한다.
- 예: 유용한 기능이 있어도 3단계 메뉴 안에 숨어 있으면 발견 가능성이 낮은 것 — 아무리 기능 자체가 잘 만들어졌어도 UX 관점에서는 실패에 가깝다.
- 03강의 "버튼 색이 안 보인다 = UI 문제"와는 결이 다르다. 색은 잘 보이는데 애초에 "그런 기능이 있다는 걸 아무도 모른다"면, 이건 시각(UI)보다 **정보 구조·흐름(UX)** 문제에 더 가깝다.

### 사용자를 위한 설계
- 설계자가 사용자를 대신해 **추측하지 않고**, 실제 사용자의 연령·능력·행동을 **관찰**해야 한다.
- 직관적이지 않거나 상태(status)가 불명확한 제품 문제를 찾아 개선한다.

### 반복 프로세스 — 왜 반복하는가 (대화에서 정리)
- 순서: 사용자 작업 관찰 → 문제 식별 → 아이디어 → 프로토타입 제작·테스트 → 고객·사업 목표를 만족할 때까지 반복.
- 반복하는 근본 이유는 단순히 "더 좋게 다듬으려고"가 아니라, **"설계자의 첫 가정(assumption)은 틀릴 수 있다"**는 전제 때문이다.
  1. 관찰 + 아이디어로 프로토타입을 만든다 (이 단계에서 설계자의 가정이 들어간다)
  2. 실제 사용자에게 테스트해 그 가정이 맞았는지 확인한다
  3. 틀렸으면 그 지점으로 돌아가 다시 설계한다
- 즉 반복은 "**한 번의 설계로는 사용자를 제대로 알 수 없기 때문**"에 필요하며, 사용성 개선은 그 반복의 결과다.

## 예시
Little Lemon의 주문 과정을 관찰해 고객이 멈추는 지점을 찾고, 개선 흐름을 프로토타입으로 만든 뒤 반복 테스트한다.

## 요약
- UX는 상호작용 전·중·후를 포함한 전체 경험이며, 발견 가능성·피드백·쉬운 목표 달성이 핵심 기준이다.
- 발견 가능성 = 사용자가 기능의 존재를 쉽게 알아차릴 수 있는가 (UI의 시각 문제와는 다른, 정보 구조의 문제).
- 반복 설계 프로세스(관찰→문제식별→아이디어→프로토타입/테스트)는 설계자의 첫 가정이 틀릴 수 있다는 전제에서 나온다.
