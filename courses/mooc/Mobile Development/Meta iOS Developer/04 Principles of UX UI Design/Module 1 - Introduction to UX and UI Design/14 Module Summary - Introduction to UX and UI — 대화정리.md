# Module Summary - Introduction to UX and UI — 대화정리

## 개요
- UX·UI와 사용자 중심 설계 입문 모듈(01~13강)의 핵심을 복습한다.
- Module 1의 마지막 강의이자, Little Lemon 프로젝트를 관통하는 전체 흐름을 정리하는 자리.

## 내용

### UX와 UI
- UX·UI의 차이, 관련 직무와 경력 경로를 살펴봤다 (02~04강).
- UX 프로세스의 공감·정의·아이디어·프로토타입·테스트(08강)와 사용성 품질 요소(07강)를 익혔다.

### UI와 도구
- UI의 역할과 역사, 인터랙션(09강)과 Figma 기본 화면(10강)을 탐색했다.
- "인간 중심·보편적 디자인과 디자인 사고"도 이 모듈에서 언급되지만, 개별 강의 노트에는 이 용어들이 구체적으로 등장하지 않아 세부 내용은 확인되지 않았다.

### 사용자 중심 설계
- 인터뷰와 관찰로 문제를 찾고(11강), 고객 여정 지도, 페르소나와 공감 도구(11~12강)로 고객을 의사결정의 중심에 뒀다.

### Little Lemon 프로젝트 전체 정리 — 대화에서 다시 짚은 내용
- **Little Lemon**은 코스 전체에서 쓰이는 가상의 레스토랑 웹사이트로, 음식 주문(ordering)과 테이블 예약(reservation) 두 기능을 다룬다.
  - 강의 중 함께 따라가는 실습: 모바일 **주문** 흐름 재설계
  - 최종 과제: **예약** 흐름 직접 설계
- **올바른 사용자 이해 순서** (06·08·11~13강 기준, 대화 중 순서를 바로잡은 내용):
  1. **인터뷰/관찰** (11강) — 가장 먼저. 실제 사용자를 직접 보고 듣는다. 06강의 "추측하지 말고 관찰하라"는 원칙이 여기서 지켜져야 한다.
  2. 그 데이터로 **여정 지도 + 페르소나 + 공감 지도**를 만든다 (11~12강) — 상상이 아니라 관찰 결과의 종합. 페르소나를 먼저 상상하고 나중에 인터뷰하는 순서는 근거 없는 가정이 되어버려 06강의 경고와 충돌한다.
  3. **문제 정의(Define)** — "메뉴 버튼과 음식 분류가 불명확했다" 같은 구체적 문제는 관찰 데이터에서 나온다.
  4. **아이디어 → 프로토타입 → 테스트** (08강)
  5. **반복** — 13강의 "일찍, 자주 조사"가 이 순환을 뒷받침한다. 이 반복적 성격 자체는 선형이 아니라 계속 순회하며 제품을 업그레이드하는 과정이다.

## 예시
Little Lemon 고객 조사를 바탕으로 페르소나와 여정 지도를 만들고 주문 과정의 핵심 문제를 정의한다.

## 요약
- UX와 UI의 역할을 구분할 수 있고, 반복적인 UX 프로세스와 사용성 원칙을 설명할 수 있다.
- 사용자 조사 결과를 설계 판단의 근거로 사용한다.
- Little Lemon 프로젝트를 관통하는 올바른 순서는 **관찰 → 페르소나/여정지도 → 문제 정의 → 아이디어/프로토타입/테스트 → 반복**이며, 관찰이 언제나 가장 먼저다.
