# Overview of the UX Process — 대화정리

## 개요
- UX 프로세스의 핵심 단계를 이해하고 Little Lemon 재설계에 적용한다.
- 흔히 말하는 디자인 씽킹(Design Thinking) 5단계에 해당하며, 앞으로 어느 단계를 AI에 맡길지 정하는 지도 역할을 한다.

## 내용

### 다섯 단계
1. **Empathize (공감)**: 인터뷰와 관찰로 사용자 요구와 감정을 이해
2. **Define (정의)**: 조사 결과를 종합해 문제와 불편을 우선순위화
3. **Ideate (아이디어)**: 스케치, 브레인스토밍, 마인드맵으로 다양한 해결책 생성
4. **Prototype (프로토타입)**: 와이어프레임을 실제와 비슷한 인터랙티브 시뮬레이션으로 발전
5. **Test (테스트)**: 사용자가 과제를 수행하게 하고 피드백과 문제를 관찰

### 발견 가능성 문제는 어느 단계에서 드러나는가 — 대화에서 정리
- 06강에서 배운 "발견 가능성(discoverability)" 문제(사용자가 기능이 있는 줄도 몰랐다)는 **Test 단계**에서 드러난다.
- 이유: Empathize~Prototype까지는 아직 사용자가 완성된 흐름을 실제로 조작해보는 단계가 아니다. "이 기능을 못 찾겠다"는 반응은 사용자가 실제 과제를 수행할 때(Test)의 관찰을 통해서만 확인된다.
- 06강의 "설계자의 가정은 틀릴 수 있다"가 실제로 검증되는 지점이 바로 Test다.

### 반복과 구축
- UX는 선형(linear) 과정이 아니라 **이전 단계로 돌아가 계속 수정하는 반복 과정**이다.
- 어느 단계로 돌아가는지는 문제 종류에 따라 다르다 — "무조건 Empathize로 되돌아간다"는 규칙은 아니다. (예: 발견 가능성 문제라면 사용자 이해(Empathize)는 이미 맞았을 가능성이 높으므로, 배치를 다시 고민하는 Ideate·Prototype 쪽으로 돌아가는 편이 더 자연스러울 수 있다 — 다만 이는 강의가 구체적으로 명시한 내용은 아니다.)
- 충분히 검증한 후에야 실제 제품을 구축한다.

## 예시
주문 고객을 관찰해 페르소나와 여정 지도를 만들고 문제 진술을 정의한 뒤, 여러 아이디어를 와이어프레임과 프로토타입으로 만들어 과제 기반 테스트를 수행한다.

## 요약
- 공감, 정의, 아이디어, 프로토타입, 테스트가 UX 프로세스의 핵심 5단계다.
- 발견 가능성 같은 문제는 실제 사용자가 조작해보는 Test 단계에서 처음 드러난다.
- UX는 선형이 아니라 반복 과정이며, 어느 단계로 돌아갈지는 문제 성격에 따라 유연하게 정해지고, 검증된 설계만 실제 제품으로 구축한다.
