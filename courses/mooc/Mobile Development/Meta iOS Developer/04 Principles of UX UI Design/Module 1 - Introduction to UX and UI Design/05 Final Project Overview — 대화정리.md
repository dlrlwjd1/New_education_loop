# Final Project Overview — 대화정리

## 개요
- Little Lemon 모바일 웹사이트의 테이블 예약 흐름을 설계하는 최종 프로젝트를 소개한다.
- 01강에서 예고된 최종 과제를 구체적인 화면 흐름으로 보여주는 강의.

## 내용

### 문제와 학습 사례
- 고객은 음식 배달 주문과 테이블 예약 둘 다에서 어려움을 겪고 있다.
- 과정 중에는 사용자 중심으로 **온라인 주문** 요소를 조사·재설계·테스트하는 사례를 따라간다.

### 최종 과제
- 학습자는 같은 UX·UI 원칙과 모범 사례를 이번엔 **테이블 예약** 요소에 직접 적용해 인터랙티브 결과물을 만든다.
- 출발점은 고객 사용 데이터 — 거기서 필요한 기능과 흐름을 설계한다.

### 예약 흐름
```text
인원·날짜·시간 선택
→ 특별 요청 입력
→ 고객 정보 입력 (이름, 전화번호, 이메일, 결제 정보)
→ 예약 확인
→ 화면·이메일 확인
```

### 대화에서 나온 짐작 — 결제 정보를 받는 이유
- 예약 흐름에 "결제 정보"가 포함된 이유를 강의는 설명하지 않는다.
- 대화 중 "노쇼(no-show) 방지를 위해서가 아닐까"라는 추측이 나왔다. 실제 식당 예약 관행으로 타당한 추측이지만, **강의 본문에 나온 설명은 아니다.**
