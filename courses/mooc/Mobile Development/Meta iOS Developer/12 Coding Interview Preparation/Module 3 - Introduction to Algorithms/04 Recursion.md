# Recursion

## 개요

- 재귀(recursion)의 3요소(기저 사례·축소 구조·재귀 호출)와 콜 스택 비용, 루프 대신 재귀를 쓰는 이유

## 내용

### 재귀란

- 함수가 **자기 자신을 더 작은 문제 인스턴스로 반복 호출**하다가 종료 조건을 만나면 멈추는 방식 — 루프의 대안

### 3가지 요구사항

1. **기저 사례(base case)** — 함수가 무한히 자신을 부르지 않고 결국 끝나도록 보장 (예: `n == 0`이면 종료)
2. **축소 구조(diminishing structure)** — 호출마다 입력을 줄여 기저 사례에 도달하게 함 (기저 사례만큼 중요)
3. **재귀 호출(recursive call)** — 축소된 구조로 자신을 호출

### 콜 스택과 비용

- 호출마다 **콜 스택(call stack)** 에 새 인스턴스가 생성 — 예: `exponent(2, 3)`은 3개 인스턴스 생성
- 함수 호출 자원이 들어 계산 비용 증가
- 대신 각 결과가 콜 스택에 보존됨 — 계층적 문제나 어떤 단계로 결과에 이르렀는지 알면 좋은 문제(그래프 순회 등)에 유용

### 왜 재귀를 쓰는가

- 어떤 문제는 재귀에 자연스럽다 — 예: **피보나치**(앞 두 수의 합) — 다른 정수로 호출만 하면 필요한 단계의 분해를 반환
- **가독성** — 검사가 많은 문제에서 루프는 금세 복잡해진다; 재귀는 코드량을 줄이고 읽기 쉽다
- **분할 정복**의 구현 수단 — 문제를 최소 구성 요소로 쪼개 해결 (이진 탐색도 루프 또는 재귀로 구현 가능)

## 예시

```python
def exponent(x, n):
    if n == 0:          # 기저 사례
        return 1
    return x * exponent(x, n - 1)  # 축소 구조 + 재귀 호출

print(exponent(2, 3))  # 8 — 콜 스택에 3개 인스턴스
```

## 요약

- 재귀는 기저 사례·축소 구조·자기 호출의 3요소로 구성된다.
- 콜 스택 오버헤드가 있지만 우아하고 읽기 쉬운 코드를 만들고, 분할 정복 해법의 전형이다.
