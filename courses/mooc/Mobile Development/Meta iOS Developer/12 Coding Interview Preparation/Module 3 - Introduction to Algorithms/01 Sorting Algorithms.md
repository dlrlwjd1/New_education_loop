# Sorting Algorithms

## 개요

- 정렬 알고리즘 3종의 동작 원리와 장단점: 선택 정렬(selection sort), 삽입 정렬(insertion sort), 퀵소트(quicksort)

## 내용

### 정렬의 전제

- 정렬된 데이터로 작업하거나 정렬 능력이 있으면 상당한 시간 절약 — 이진 트리·힙도 데이터를 정렬 상태로 유지하도록 설계된 구조
- 순서를 매길 수 있는 데이터셋이 필수 — 알파벳·순번·연대·크기·색상 등 기준은 중요치 않고 오름/내림차순 배열 가능성이 중요
- 고려사항: 원본을 재배열(permute)하는가, 원본을 유지한 복사본을 만드는가

### 선택 정렬 (selection sort)

- 사람의 접근을 흉내낸 초기 방식:
  1. 리스트를 훑어 **최솟값**을 찾는다
  2. 첫 원소와 교환해 최솟값을 맨 앞에 둔다 (기존 첫 원소는 빈 자리로)
  3. 나머지 원소에 대해 반복 — 작은 것부터 큰 것 순으로 완성
- 매 위치마다 **배열 전체를 탐색**해야 함

### 삽입 정렬 (insertion sort)

- 앞의 두 원소부터 검사, 작은 쪽을 앞으로 이동
- 각 원소를 **왼쪽 원소와 비교**해 더 작으면 교환 — 더 큰 원소를 만날 때까지 왼쪽으로 이동
- 예: [35, 46, 36, 9, …]에서 36은 46과 교환 후 35보다 크므로 정지; 9는 46→36→35를 차례로 지나 맨 앞으로

### 퀵소트 (quicksort)

- 더 정교하고 구현이 복잡하지만 훨씬 효율적 — **피벗(pivot)** 원리:
  1. 배열에서 피벗 원소 선택
  2. 피벗보다 큰 원소는 오른쪽, 작은 원소는 왼쪽으로 이동
  3. 피벗 양쪽 부분에 같은 과정을 재귀 반복 — 모두 정렬되면 종료
- 예: 9를 피벗으로 → 6, 3이 왼쪽으로 분리 → 왼쪽 재귀 → 오른쪽에서 36을 새 피벗으로 반복

### 실무 관점

- 실제로는 각 언어의 우수한 내장 구현을 쓴다 — 원리를 알아야 문제에 맞는 것을 고를 수 있음
- 모든 상황에 최적인 정렬은 없다 — 접근마다 트레이드오프가 있고 환경에 따라 효과가 다름

## 요약

- 선택 정렬은 매번 최솟값을 찾아 앞으로, 삽입 정렬은 왼쪽과 비교하며 제자리로, 퀵소트는 피벗 기준 분할을 재귀한다.
- 단순한 두 방식보다 퀵소트가 효율적이지만, 상황별 트레이드오프를 보고 선택해야 한다.
