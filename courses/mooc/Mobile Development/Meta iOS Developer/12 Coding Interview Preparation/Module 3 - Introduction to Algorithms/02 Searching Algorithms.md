# Searching Algorithms

## 개요

- 탐색 알고리즘: 선형 탐색(linear search)과 이진 탐색(binary search)의 절차·복잡도·트레이드오프

## 내용

### 탐색 설계 시 고려사항

- 단순 키 대조 외에도 최댓값·최솟값·중앙값 반환 등 다양한 요구가 있음
- **값이 없을 때 무엇을 반환할 것인가** — null 반환은 이후 애플리케이션 동작을 방해할 수 있어 안전장치 필요 (null 발명자 Tony Hoare는 이를 "10억 달러짜리 실수"라 불렀다)
- 첫 번째 일치를 반환할지 마지막 일치를 반환할지도 결정 사항

### 선형 탐색 (linear search)

- 가장 단순한 탐색 — 인덱스 처음부터 끝까지 순차 확인
- 최선 O(1), 최악 O(n) — 없다고 말하려면 모든 원소를 확인해야 함

### 이진 탐색 (binary search)

- **정렬된 데이터**가 전제 (힙·이진 트리처럼 내재적으로 정렬되는 구조를 쓰거나, 먼저 정렬 알고리즘 적용)
- 절차: 중간 지점 확인 → 목표보다 작으면 왼쪽 절반 버리고 오른쪽 집중 → 다시 중간 확인 → 반복
- 매 반복마다 탐색 공간이 절반 — j회 반복 후 n/2^k → **O(log n)**
- 최선은 역시 O(1) (첫 시도에 발견)

### 트레이드오프

- 이진 탐색이 선형보다 훨씬 효율적이지만 **정렬 비용**을 상쇄해야 한다
- 읽기가 갱신보다 잦은 데이터면 적절, 갱신이 잦으면 정렬 유지 비용이 커진다

## 요약

- 선형 탐색은 O(n)으로 단순하고, 이진 탐색은 정렬을 전제로 O(log n)을 달성한다.
- 정렬 비용 vs 탐색 이득은 읽기/갱신 빈도로 판단한다.
- 값이 없을 때의 반환 정책(null 안전장치)을 반드시 설계하라.
