# Lists and sets

## 개요

- 리스트(배열 기반 vs 연결 리스트)와 셋의 구조·장단점 — 동적 확장 비용, 해시 기반 O(1) 탐색과 충돌(clashing)

## 내용

### 리스트

- 대부분의 언어에서 **객체**로 표현 — 데이터 저장 + 내장 메서드(예: sort) 보유
- 문자열·정수·실수 리스트로 선언하는 것이 일반적, 일부 언어는 혼합 타입 허용
- 리스트는 추상 개념 — 실제 구현은 **배열** 또는 **연결 리스트**

### 배열 기반 리스트

- 배열을 기반으로 한 순서 있는 컬렉션 — 배열의 강점·한계를 그대로 물려받음
- 초기 크기 지정이 관건: 동적 확장 구조도 내부적으로는 초기 크기가 있고, 한계에 이르면 **더 큰 새 구조로 자신을 복사**
- 루프 안에서 동적 확장이 반복되면 생성·복사 비용이 커진다 — **처음부터 크게 잡는 편이 유리**할 수 있음

### 연결 리스트 (linked list)

- 각 노드 = 데이터 + 다음 항목을 가리키는 **포인터**
- 빈 리스트에서 시작해 새 셀을 추가하며 동적으로 성장 — 새 노드를 추가하고 가리키기만 하면 됨 → 대량 데이터 저장에 매우 빠름
- 대가: 노드마다 주변 노드 참조를 위한 추가 저장 공간 필요
- **head**(시작 표시)와 **tail**(끝 표시) 보유

### 셋 (set)

- 리스트와 유사하지만 원소를 **무순서**로 저장 (순서 있는 셋 구현도 존재)
- **유일한 원소만** 보관 — 이미 있는 원소 추가는 무효과
- 출력 순서가 삽입 순서와 다를 수 있음
- 추가된 값은 변경 불가 — 삭제 후 새 값 추가로 처리

### 셋의 탐색 성능

- 내부적으로 **해시 테이블** 사용 — 해싱 함수(데이터를 고정 크기 값으로 매핑, 같은 입력이면 항상 같은 출력)로 저장 위치 결정
- 전체 순회 대신 매핑 함수 결과 위치만 확인 → **O(1) 탐색**
- 단, 초대형 데이터셋에서는 성능 저하 — 값이 많을수록 **충돌(clashing)**(다른 두 값이 같은 매핑을 받는 것) 위험 증가

## 요약

- 배열 기반 리스트는 확장 시 복사 비용, 연결 리스트는 포인터로 저렴하게 성장하는 대신 노드당 추가 공간이 든다.
- 셋은 유일·무순서 원소를 해시로 저장해 O(1) 탐색이 가능하지만, 데이터가 커지면 해시 충돌로 성능이 떨어진다.
