# Heaps

## 개요

- 힙(heap)의 구조와 특징 — 우선순위 기반 트리 구조, min-heap/max-heap, 핵심 연산과 복잡도, 스케줄링 활용

## 내용

### 힙이란

- 트리처럼 모델링되지만 큐처럼 동작하는 특수 자료구조 — 단, 일부 원소에 **우선순위**를 부여
- 각 원소는 키 값을 가짐:
  - **min-heap** — 가장 작은 키가 우선
  - **max-heap** — 가장 큰 키가 우선

### 핵심 연산

- min-heap: `insert`, `find_min`, `delete_min` (max-heap은 `find_max`, `delete_max`)
- 구현에 따라 추가 메서드 가능 — 예: `decrease key`(키 값 변경, 실제 우선순위가 바뀔 때)
- 우선순위 원소 이외의 삭제는 보통 지원하지 않음 — 트리 재구조화로 성능이 저하되기 때문. **기능을 제한해 생산성(속도)을 높인** 설계

### 내부 구조와 복잡도

- 이진 트리 기반으로 흔히 구축 (배열로 이진 트리 흉내도 가능)
- 최솟값은 항상 **루트**에 위치 → 최솟값 조회 **O(1)**
- 스택과 달리 값을 조회해도 제거되지 않음 — 제거는 `delete_min` 별도 호출
- **삽입 O(log n)** — 전파(propagation): 루트에 삽입 후 비교·교환을 반복해 자기 자리로 이동

### 활용

- 그룹에서 특정 값을 우선시하는 구조 → **스케줄링**이 자연스러운 응용: CPU, 라우터, 패킷 처리
- 예: 인터뷰 일정 관리 — 후보자의 단계나 역할 우선순위를 키로 저장해 중요도 기반 자동 스케줄링

## 요약

- 힙은 우선순위 원소를 최단 시간에 반환하도록 특화된 트리형 구조다 (min/max).
- 최솟값 조회 O(1), 삽입 O(log n)이며, 임의 삭제를 제한해 성능을 지킨다.
- CPU·네트워크·작업 스케줄링처럼 "다음으로 중요한 것"을 꺼내는 문제에 적합하다.
