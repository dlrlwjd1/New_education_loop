# Stacks and queues

## 개요

- 스택(LIFO)과 큐(FIFO)의 차이, 주요 메서드(push·pop·peek 등), 실전 사용 예

## 내용

### 공통 특성

- 추상 자료구조 — 언어마다 구현이 다르지만 **원소를 넣고 빼는 규칙**은 공통
- 리스트·배열이 임의 접근(random access)인 반면 스택·큐는 **순차 접근(sequential access)** — 접근 방식을 통제하고 싶을 때 유용

### 스택 (stack)

- 원소를 위로 쌓는 선형 구조 — 중간에서 꺼낼 수 없음
- **FILO**(First-In, Last-Out) = **LIFO**(Last-In, First-Out) — 꼭대기에서만 회수
- 예: Ctrl+Z(실행 취소)가 마지막 액션부터 되돌리는 것, Ctrl+Y는 다시 스택에 push
- 메서드:
  - **push** — 꼭대기에 추가 (스택 변경)
  - **pop** — 꼭대기에서 제거·반환, 빌 때까지 반복 호출 가능 (스택 변경)
  - **peek** — 꼭대기 항목을 제거하지 않고 보기 (상태 불변)
  - **isEmpty / isFull** — 비었는지 / 가득 찼는지 (가득 찬 상태에서 넘치면 "stack overflow")
- 예: 52장 카드 덱을 스택으로 만들면 딜할 때마다 꼭대기에서 제거 — 덱 상태 관리 코드가 단순해짐

### 큐 (queue)

- 스택과 유사한 메서드(생성·삽입·제거·상태 확인)를 갖지만 **FIFO**(First-In, First-Out)
- 예: 패스트푸드 줄 — 먼저 선 사람이 먼저 서비스받음
- 제거되는 원소는 가장 먼저 들어온 항목(가장 오래된 항목)
- 실전 예: 서버 로드 밸런싱 — 작업을 삽입 순서대로 보관, 서버가 비면 큐의 첫 작업을 꺼내 전달

## 요약

- 스택은 LIFO(꼭대기에서만 넣고 꺼냄), 큐는 FIFO(뒤로 넣고 앞에서 꺼냄)다.
- pop/push는 구조를 바꾸고 peek는 바꾸지 않는다.
- 데이터 접근 순서를 강제해야 하는 문제(실행 취소, 작업 대기열)에 적합하다.
