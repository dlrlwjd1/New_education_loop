# Hash tables

## 개요

- 해시 테이블(hash table)의 구조와 원리 — 해싱 함수, O(1) 탐색, 충돌(collision)과 해결책(생일 역설 포함)

## 내용

### 구조와 원리

- 키-값 쌍(key-value pair)을 담는 여러 **슬롯/버킷(bucket)** 으로 구성
- **해싱 함수** — 키에 적용해 고유 번호(고정 크기 값)를 생성하는 알고리즘 → 데이터를 넣을 버킷을 결정
- 압축과 유사: 키를 작고 다루기 쉬운 크기로 줄여 **인덱스 지표**로 사용
- 인덱스 생성에 쓰는 정보는 애플리케이션에 따라 다름 (데이터 자체, 사번 뒤 4자리, 딕셔너리 키 등)
- 대부분의 언어에 내장 해싱 함수 존재: MD5, SHA, CRC32

### O(1) 탐색

- 해시 테이블은 **공간보다 속도를 우선** — O(1)에 항목 회수
- 배열 탐색은 원소를 하나씩 비교 — 최악의 경우 O(n)
- 해시는 같은 함수를 다시 실행해 인덱스 위치만 확인 — 책의 색인처럼 위치 파악이 극적으로 빨라짐
- 활용처: 캐시, 딕셔너리, 데이터베이스 인덱스, 셋

### 간단한 예 — 모듈러 해싱

- 키 0~9를 `key mod 20`으로 해싱: 0→0, 1→1, 2→2, … 9개의 고유 값 생성
- 문제: 키가 20을 넘으면 1 mod 20 = 1이고 21 mod 20도 1 — 충돌 발생

### 충돌 (collision)

- 서로 다른 두 키의 해싱 결과가 같은 경우
- **생일 역설(birthday paradox)** — 무작위 23명만 모여도 두 명의 생일이 같을 확률이 약 50% → 365개 슬롯에 직원 24명을 생일로 해싱해도 충돌 확률이 50% 초과. 중복 해시는 반드시 대비해야 한다
- 해결책:
  1. 충돌 시 테이블을 키우고 해싱을 더 정교하게 만들어 값을 새 주소로 재배치 — 데이터 크기에 맞춰 유기적으로 성장
  2. 충돌 지점에 **연결 리스트**를 만들어 추가 값을 저장 (chaining)

## 요약

- 해시 테이블은 해싱 함수로 키를 인덱스로 변환해 O(1) 탐색을 달성한다 (속도 우선, 공간 오버헤드).
- 충돌은 확률적으로 생각보다 자주 발생하며(생일 역설), 테이블 확장·재해싱 또는 연결 리스트 체이닝으로 해결한다.
