# Basic data structures

## 개요

- 자료구조 개관 — 가변/불변, 선형/비선형 분류, 인덱스·길이·일급 객체, 참조 전달과 메모리 누수 주의점

## 내용

### 자료구조란

- 객체를 컴퓨터 메모리에 쉽게 저장·조직하도록 모델링한 것
- **불변(immutable)** — 생성 후 변하지 않음 / **가변(mutable)** — 내용에 대한 갱신·질의 연산 가능
- 가변 구조는 모델링에 시간·노력이 들고 복잡한 객체는 모델링이 어려우며 공간도 고려 대상 — 상황에 맞게 선택
- 구현·능력은 언어마다 다르지만 전체 아키텍처는 비슷한 패턴을 따른다

### 선형 구조 (linear)

- 원소가 입력 순서대로 **순차 배열** — 각 원소가 앞 원소에 연결
- 예: 배열(array), 큐(queue), 스택(stack), 리스트(list)
- 일부 언어는 동일 타입만 허용(정수 리스트, 문자열 배열), 다른 언어는 혼합 배열 허용 — 편하지만 나중에 오류 처리 비용 발생 (합계가 "파인애플 3 + 사과 1"이 되는 격)

### 인덱스와 길이

- **인덱스** — 대괄호와 정수 위치로 원소 접근: `array[4]`
- 언어 대부분이 **0 기반(zero based)** — `array[4]`는 실제로 5번째 원소
- 원소 7개인 배열에 인덱스 8을 요청하면 오류
- 길이 조회: Java `array.length`, Python `len()` 등 대부분의 언어에서 지원

### 일급 객체와 참조 전달

- 배열·리스트는 대개 **일급 객체(first class object)** — 함수 매개변수 전달, 결과 반환, 변수 할당 가능
- 함수에 전달 시 **구조 자체가 아닌 참조만 전달**될 수 있음 — 복사를 막는 메모리 절약 장치지만, 함수 안의 변경이 호출 환경의 배열에 영향을 주는 오류 가능 → 복사본을 만들어 전달하는 편이 안전

### 메모리 누수 (memory leak)

- 할당한 메모리를 쓰지 않으면 해제하는 것이 좋은 습관
- 반복 호출로 과다 할당·미해제가 누적되면 메모리 고갈로 크래시 — 대부분의 컴파일러가 감지·해제 알고리즘 보유

### 비선형 구조 (nonlinear)

- 트리, 그래프 등 — 한 번에 순회하지 않고 특정 경로를 탐사
- 자연 정렬을 포함할 수 있어 특정 데이터 질의가 매우 빠름

## 요약

- 자료구조는 가변/불변, 선형(배열·리스트·스택·큐)/비선형(트리·그래프)으로 분류된다.
- 0 기반 인덱스, 길이 메서드, 일급 객체 특성이 공통 기반이다.
- 참조 전달 부작용과 메모리 누수를 경계하라.
