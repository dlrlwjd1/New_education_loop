# What to expect from a technical interview

## 개요

- Meta 엔지니어들이 말하는 기술 인터뷰의 3가지 유형과 면접관이 실제로 보는 것

## 내용

### 인터뷰 3유형

1. **기술(technical)** — LeetCode 스타일 코딩 문제. 전체 프로세스에서 2~4회(스크리닝 1~2회 + 통과 후 추가), 문제당 20~30분
2. **아키텍처(architecture)** — 45분~1시간. 엔드투엔드 기능 구축 질문:
   - 제품 지향 (예: 테트리스 만들기)
   - 백엔드 지향 (데이터 흐름, 다수 사용자 스케일링)
   - 파이프라인별 도메인 질문 예: iOS라면 "Facebook 뉴스피드 화면을 어떻게 만들 것인가 — 어떤 객체, 객체 간 통신, 네트워킹 API는?"
3. **행동(behavioral)** — 협업 경험, 직면한 도전, 흥미로운 프로젝트. 예: "팀 작업이 잘 안 됐던 경험은?" — 협업·소통·성장 능력 확인

### 면접관이 보는 것

- **소리 내어 설명하는가** — 화이트보딩하며 사고 과정, 시간 복잡도·공간 절약 고려를 설명 (실무에서도 필요한 사고)
- **막혔을 때 침묵하지 않는가** — 무엇에·왜 막혔는지 설명하면 정답을 못 내도 문제 이해도를 보여 다음 라운드로 갈 수 있다
- **피드백을 받아들이는가** — 힌트를 듣고 함께 문제를 푸는 모습은 "같이 일하고 싶은 사람"의 신호
- **회사를 조사했는가** — 회사 가치와 자신의 기여를 연결
- **열정과 긍정적 태도**
- 면접관은 지원자가 잘하기를 응원한다 — 협업으로 최대한의 시그널을 얻고 싶어 한다

### 준비 팁

- 파이프라인(iOS 등)과 무관하게 **일반 알고리즘·자료구조 질문은 반드시 나온다** — 도메인 실력만으로는 부족
- 친구·동료 앞에서 (또는 인형에게라도) 소리 내어 엔드투엔드 연습
- 복장은 편하게 — 정장 기대 없음, 티셔츠·청바지도 흔함

## 요약

- 인터뷰는 기술(LeetCode)·아키텍처(엔드투엔드 설계)·행동(협업 경험) 3종으로 구성된다.
- 합격 신호는 정답이 아니라 사고 과정 설명, 막힘의 공유, 피드백 수용, 열정이다.
- 도메인 전문가라도 일반 알고리즘·자료구조 준비는 필수다.
