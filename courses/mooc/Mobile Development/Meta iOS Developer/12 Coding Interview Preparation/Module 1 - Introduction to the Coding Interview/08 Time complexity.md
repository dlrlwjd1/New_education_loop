# Time complexity

## 개요

- 시간 복잡도(time complexity)와 Big-O 표기법: O(1), O(log n), O(n), O(n²)의 의미와 최선/최악/평균 케이스

## 내용

### Big-O 표기법

- 알고리즘 효율의 지표 — 다양한 입력 집합에서 코드 실행 시간이 어떻게 변하는지 추정
- 시간을 초 단위로 말하지 않고 연산 횟수의 증가율로 표현

### 주요 복잡도

| 표기 | 이름 | 설명 | 예 |
| --- | --- | --- | --- |
| **O(1)** | 상수 시간 | 입력이 무엇이든 1번의 계산 | 배열의 첫(또는 n번째) 원소 출력 |
| **O(log n)** | 로그 시간 | 입력이 늘어도 증가폭이 미미 — 매 단계 탐색 공간 절반 | 이진 탐색: 1~100 추측 게임을 6~7회 안에 해결 (n이 10배가 되어도 추측이 10배 늘지 않음) |
| **O(n)** | 선형 시간 | 탐색이 배열 길이에 비례 — 10개 대신 100개면 10배 소요 | 루프로 배열 전체를 확인하는 탐색 |
| **O(n²)** | 이차 시간 | 원소마다 작업이 배가 — 중첩 루프(n×n) | 배열의 배열을 이중 루프로 순회 |

- 그래프(x=입력 수, y=시간)에서 O(1)만 기울기가 변하지 않는다. 목표: O(1) 최고 → O(log n) 매우 좋음 → O(n) 수용 가능 → O(n²) 나쁨

### 최선·최악·평균 케이스

- 같은 선형 탐색도 경우에 따라 다르다:
  - **최선(best case)** — 찾는 값이 첫 원소: O(1)
  - **최악(worst case)** — 값이 없어 전부 확인: O(n)
  - **평균(average case)** — 중간쯤에서 발견: O(n/2)

## 요약

- Big-O는 입력 크기에 따른 연산 횟수의 증가율이다 — O(1) < O(log n) < O(n) < O(n²).
- 해법을 구현하기 전에 "내 솔루션은 몇 번 계산하는가, 더 나은 방법은 없는가"를 물어라.
- 평가는 최선·최악·평균 케이스로 나눠 생각한다.
