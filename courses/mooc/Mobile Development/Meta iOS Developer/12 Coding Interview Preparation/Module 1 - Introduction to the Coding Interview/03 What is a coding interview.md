# What is a coding interview?

## 개요

- 기술 인터뷰에 접근하는 4단계 전략: 성공을 준비하라, 개념부터 풀어라, 적절한 도구를 써라, 솔루션을 최적화하라

## 내용

### 기술 인터뷰란

- 코딩 역량을 입증하는 자리 — 보통 스크리닝 콜에서 소프트 스킬(명확한 소통, 근면성, 회사 가치와의 정합)을 확인한 뒤 진행
- 역할 수행에 필요한 기술적 능력을 판단

### 1. 성공을 준비하라 (Prepare to succeed)

- "준비에 실패하는 것은 실패를 준비하는 것" — 사전 준비로 긴장에 대비

### 2. 개념부터 풀어라 (Solve conceptually first)

- 코드를 쓰기 전에 질문과 답의 그림을 명확히 하라 — **명확화 질문은 언제든 환영**된다
- 화이트보드가 있으면 활용: 문제 요점 정리 → 해법 윤곽
- **의사코드**로 추론 능력 시연 — 문제를 추론할 수 있으면 절반은 푼 것
- 소리 내어 사고 과정을 설명하고 왜 그 접근을 택했는지 밝혀라
- 아는 문제와 연결하고, **분할 정복**으로 작은 문제로 쪼개라 — 시간 초과 시에도 동작하는 코드 조각을 보여줄 수 있다

### 3. 적절한 도구를 써라 (Employ appropriate tools)

- 인터뷰 문제는 시간 내 풀 수 있게 설계 — 문제 해결 능력과 도구 인지를 시험
- 예: **양말 짝 세기 문제** — 색을 숫자로 표현한 배열 [1,2,2,1,1,3,5,1,4,4]에서 같은 색 짝의 수 구하기
  - **딕셔너리**(키=색, 값=개수)로 세고 홀수 값을 찾으면 짝 없는 양말 판별
- 수동 구현보다 기존 자료구조·접근법 활용 — 코드가 줄고 기본기가 드러난다
- 인터뷰 전에 주요 정렬·탐색 알고리즘 복습

### 4. 솔루션을 최적화하라 (Optimize)

- 최소 메모리·디스크·CPU·대역폭을 쓰도록 코드 다듬기
- **시간·공간 복잡도**를 설명하고 개선 여지 제시
- 반복·중복 코드는 함수로 모듈화 — **DRY**(Don't Repeat Yourself)
- 불필요해진 코드는 제거
- 조기 종료: 값을 찾으면 `return`하거나 불리언 조건 루프로 탈출 → 효율 향상, 시간 복잡도 감소
- 공간 복잡도: 불필요한 변수 생성 자제

## 요약

- 결과보다 추론 과정과 모범 사례를 보여주는 것이 핵심 — 모르는 문제라도 프레임워크(개념 → 도구 → 최적화)로 접근하라.
- 온라인 문제로 연습하되 매번 같은 방법론을 적용해 편안한 틀을 만들어라.
