# Space complexity

## 개요

- 공간 복잡도(space complexity): 입력 공간 + 보조 공간, 시간과의 트레이드오프, 메모리 사용을 늘리는 요인

## 내용

### 시간과 공간의 트레이드오프

- 얼마나 많은 메모리를 쓰는가는 시간과의 트레이드오프인 경우가 많다 — 자료구조 선택은 **속도 vs 압축성** 중 우선순위에 달림
- 예: 해시 테이블은 O(1)에 가까운 초고속 조회를 제공하지만 모든 원소마다 룩업이 필요해 공간 복잡도는 O(n)

### 표기와 측정

- 공간 복잡도의 Big-O 표기는 시간과 동일: O(1), O(log n), O(n)… (n = 입력 크기, 주로 바이트)
- 언어마다 메모리 비용이 다르다 — 예: Java에서 정수 4바이트, 빈 배열은 헤더 객체 12바이트 + 패딩 4바이트
  - 정수 4개 배열 = 12 + 4 + 4×4 = 32바이트

### 입력 공간과 보조 공간

- **공간 복잡도 = 입력 공간(input space) + 보조 공간(auxiliary space)**
- 보조 공간 — 해법 계산에 필요한 임시 공간 (예: 장제법(long division)에서 중간 계산을 담는 표)
- 입력 공간 — 함수·알고리즘·시스템에 데이터를 넣는 데 필요한 공간
- 배열을 4개 → 8개 정수로 늘리면 총량은 48바이트 — 입력은 늘었지만 보조 공간은 그대로. **입력 증가에 영향받지 않는 보조 공간은 Big-O 계산에서 무시 가능**

### 메모리 사용을 늘리는 요인

- 변수 할당 (계산용 임시 변수 포함)
- 새 자료구조 생성 — 새 배열·복제 배열 생성은 O(n) 보조 메모리 비용
- 함수 호출과 할당의 오버헤드
- 주의사항: 기존 변수를 덮어쓰는 대신 새 변수를 만들면 공간 효율 하락, 배열·복잡한 구조의 불필요한 복사는 영향이 크다, 단순한 구조로 충분한 곳에 복잡한 구조를 쓰면 패널티

## 요약

- 공간 복잡도 = 입력 공간 + 보조 공간이며, 속도와 메모리 효율은 자주 맞바꿈 관계다.
- 입력 크기와 무관한 보조 공간은 Big-O에서 무시할 수 있다.
- 불필요한 변수·복사·과한 자료구조가 공간 효율을 해친다.
