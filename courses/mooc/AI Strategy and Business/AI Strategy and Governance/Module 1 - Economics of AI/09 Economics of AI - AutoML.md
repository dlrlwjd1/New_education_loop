# Economics of AI: AutoML

## 개요
- **AutoML(자동화 머신러닝)** 은 데이터 준비부터 모델 선택·최적화까지 대부분의 단계를 자동화한다.
- 본질은 **전문성을 연산으로 대체**하는 것이다 — 스킬 비용이 클라우드 청구서로 바뀐다.
- 결과적으로 스킬 수요는 줄고 **컴퓨팅과 데이터 수요는 늘어난다.**

## 내용

### 기존 ML 워크플로와 AutoML의 차이
전형적인 머신러닝 워크플로:

> 데이터 수집 → 정제(cleaning) → 레이블링·준비 → **특성 공학(feature engineering)** → 모델 실행 → 최적화 → 예측 확인

**AutoML은 이 워크플로에서 거의 모든 단계를 가져간다.** 사용자가 하는 일은 **데이터를 넣고 예측을 받는 것**뿐이다.

작동 방식의 핵심은 **연산을 대량으로 투입해 여러 전문성을 대체**하는 것이다. 어떤 모델을 쓸지 지정할 필요조차 없다 — AutoML이 여러 변형을 시도해 가장 좋은 모델을 스스로 찾아낸다. 사용자가 지정하는 것은 **데이터**와 **예측하려는 레이블**뿐이다.

### 실제로 써 보면
강의자가 여러 번 직접 돌려 본 경험:

1. 정해진 형식으로 데이터를 업로드한다 (학습 레이블 포함). 이 시점에 선택지가 사실상 하나뿐이다.
2. 남은 선택지는 **"모델을 학습시켜라"** 하나다.
3. 몇 시간 뒤 결과가 담긴 이메일이 온다. Google이 여러 모델을 시도해 어느 것이 가장 좋은지 알려 준다.
4. **그리고 청구서도 함께 온다.** 클라우드 서비스로 돌아가므로 그들의 연산을 쓴 값이다.

### 본질 — 전문성을 연산으로 교환한다
> AutoML은 **내가 가져야 했던 전문성**의 비용을 **백엔드 연산** 비용으로 옮긴다.

구현은 극도로 쉬워지지만 **연산 자원은 매우 많이 든다.** Google 측 설명에 따르면 의도 자체가 연산력으로 머신러닝 전문성의 필요를 대체하는 것이다.

### 각 사업자의 이름

| 회사 | 명칭 |
|---|---|
| Google | **AutoML** |
| Microsoft | **Automated Machine Learning** |
| Amazon | **SageMaker Autopilot** |
| IBM | **AutoAI** |

각기 다른 워크플로를 개발하고 있지만 방향은 같다 — 전문성은 적지만 **좋은 데이터와 예측 필요**를 가진 사람이 AI를 통합해 효과적인 알고리즘적 의사결정을 하게 만드는 것.

### 시장에 주는 함의
- 머신러닝 **스킬** 시장 → 수요 감소 압력
- **컴퓨팅** 수요 → 증가
- **데이터 자산** 수요 → 증가
- 그리고 새로운 수요: **AI 예측을 맥락화하고 해석할 수 있는 사람** (다음 강의 주제)

## 요약
- AutoML은 데이터 업로드와 예측 수령을 제외한 전 과정을 자동화한다.
- 그 방식은 **연산을 퍼부어 전문성을 대체**하는 것이다 — 전문가 인건비가 클라우드 요금으로 전환된다.
- 4대 클라우드 모두 같은 제품을 갖고 있다(AutoML / Automated ML / SageMaker Autopilot / AutoAI).
- 순효과: 누구나 AI를 배포할 수 있는 생태계로 가되, **컴퓨팅·데이터·해석 능력의 몸값은 오른다.**
