# Creating an Outcome-Focused Definition of Done with HDD & User Stories

## 개요
- 가설 주도 개발(Hypothesis-Driven Development, HDD)과 사용자 스토리로 완료의 정의를 사용자 성과 중심으로 만든다.
- 원문: https://www.mooc.org/learn/uva-darden-digital-product-management/lecture/uR4ts/creating-an-outcome-focused-definition-of-done-with-hdd-user-stories

## 내용
### 사용자 스토리와 가설
- 사용자 스토리는 특정 사용자가 어떤 행동을 왜 원하는지 표현한다.
- 구현 방법을 미리 고정하지 않으면서도 팀이 해결할 문제와 보상을 이해하게 한다.

### 결과 중심 완료 기준
- 기능이 작동한다는 기술적 완료뿐 아니라 사용자가 의도한 행동을 실제로 수행했는지 측정한다.
- 분석·데이터 팀과 함께 관찰 방법을 제품에 포함한다.
- 다음 스프린트에서 결과를 검토하고 가설을 유지·수정·폐기한다.

## 예시
“기존 퀴즈 검색 화면이 완성됐다”가 아니라 “채용 담당자가 새 퀴즈를 만들기 전에 기존 퀴즈를 탐색한다”를 측정 가능한 완료 기준으로 둔다.

## 요약
- 사용자 스토리를 검증할 가설로 다룬다.
- 배포보다 행동 변화로 완료를 정의한다.
- 계측 결과를 다음 반복의 입력으로 사용한다.
