# The Trouble with New Features

## 개요
- 기존 제품에서 새 기능을 곧바로 구축하려는 편향을 경계하고, 고객·문제·가치를 먼저 검증한다.
- 원문: https://www.mooc.org/learn/uva-darden-digital-product-management/lecture/Iq5fn/the-trouble-with-new-features

## 내용
### 구축 편향
- 팀은 새 아이디어를 들으면 소프트웨어를 크게 만드는 쪽으로 쉽게 움직인다.
- 기존 제품의 맥락에 있다는 이유만으로 새 기능의 고객과 수요가 검증된 것은 아니다.
- 큰 계획은 아이디어에 대한 감정적·조직적 투자를 키운다.

### 기능도 신제품처럼 검증
- 누구에게 판매하거나 제공할 기능인지 명확히 한다.
- 그 고객에게 실제로 중요한 문제가 있는지 확인한다.
- 개발 비용을 쓰기 전에 가치와 행동을 작은 실험으로 시험한다.

## 예시
외부 채용 퀴즈 제품에 내부 경력 개발용 역량 감사 기능을 추가하기 전에, 내부 HR 사용자의 문제와 실제 사용 의향을 별도로 검증한다.

## 요약
- 새 기능도 미검증된 제품 아이디어다.
- 고객과 문제를 다시 정의한다.
- 가치 테스트가 구축보다 먼저다.
