# Implementation Strategies

## 개요

모델을 배포한 뒤 **실전에서 결과를 어떻게 다뤄야 하는지**를 다루는, 이 코스에서 가장 실무적인 강의 중 하나다. 임계값을 어떻게 정할지(히스토그램·ROC/AUC), 신경망이 사실 결정론적이라는 것, 이동평균 필터·홀드오프 같은 후처리 기법, 별도 코프로세서 아키텍처까지 폭넓게 다룬다.

## 내용

### 임계값(Threshold)을 정하는 법 — 히스토그램

- 검증/테스트 세트의 모든 샘플을 모델에 통과시켜, **목표 라벨의 확신도 점수**를 기록한다.
- **두 개의 히스토그램**을 그린다: (1) 실제로 목표 라벨인 샘플들의 확신도(True Positive 후보) — 이상적으로는 1에 가까워야 함. (2) 목표 라벨이 아닌 샘플들의 확신도(True Negative 후보) — 0에 가까워야 함. 흔히 정규분포(종형 곡선)를 이루지만 꼭 그럴 필요는 없다.
- **두 분포가 뚜렷이 분리**되어 있으면 그 사이 어딘가(예: 0.5)를 임계값으로 잡으면 된다.
- 하지만 현실에서는 **두 분포가 겹치는 경우가 많다** — 임계값을 낮추면 False Positive(비목표를 목표로 오판)가 늘고, 높이면 False Negative(목표를 놓침)가 는다.
- **임계값 선택은 응용에 따라 다르다**:
  - 질병 진단·보안 시스템: **False Negative는 절대 안 됨** → False Positive를 더 감수(낮은 임계값 + 사람의 추가 확인).
  - 키워드 스팟팅: 비슷한 발음의 다른 말에 **잘못 반응(오탐)하는 게 더 나쁨** → False Positive를 줄이는 **높은 임계값**을 선호.

### ROC 곡선과 AUC

- **ROC(Receiver Operating Characteristic) 곡선**: x축 = False Positive Rate, y축 = True Positive Rate. 임계값을 1에서 0까지 슬라이딩하며 각 지점의 FPR·TPR을 찍는다.
- **완벽한 분류기**: ROC가 왼쪽 위 모서리를 지나는 형태, **AUC(곡선 아래 면적) = 1** — 완벽한 분리가 가능해 FP 없이 모든 TP를 잡는 임계값이 존재.
- **최악의 분류기**: 대각선(50:50 랜덤 추측과 다름없음), **AUC = 0.5**.
- 대부분의 실제 분류기는 **AUC 0.5~1.0** 사이이고, 높을수록 좋은 분류기 — 여러 모델·임계값 설정을 **하나의 숫자로 비교**할 수 있는 도구.

### 신경망은 사실 결정론적(Deterministic)이다

- **결정론적 함수** vs **확률적(stochastic) 함수**: 같은 입력을 넣으면 항상 같은 출력이 나오는가(결정론)? 아니면 무작위성 때문에 매번 다를 수 있는가(확률적)?
- 지금까지 "확률(probability)"을 워낙 많이 다뤄서 신경망이 확률적 함수처럼 느껴질 수 있지만, **학습이 끝난 신경망 자체는 결정론적이다** — 곱셈·덧셈·비선형 연산의 조합일 뿐, 모델 내부에 무작위성이 없다. (학습 과정 자체는 초기 가중치·드롭아웃 때문에 무작위성이 있지만, **학습이 끝나고 나면** 같은 입력→항상 같은 출력.)
- **실용적 활용**: 컴�터/서버에서 학습한 모델에 특정 입력을 넣어 출력을 기록해두고, 같은 모델을 임베디드 기기에 옮긴 뒤 **동일한 입력으로 같은 출력이 나오는지 대조**하면 — 변환(양자화·라이브러리화) 과정이 제대로 됐는지 검증할 수 있다. Edge Impulse가 이 변환을 대신해주므로 대개는 안심해도 되지만, 이 원리는 직접 디버깅할 때 유용하다.
- 다만 **모르는(unknown) 입력**에 대해 논할 때는 여전히 모델을 확률적으로 다룬다 — 입력을 모르면 출력도 예측할 수 없으므로, 통계로 데이터/모델 출력의 경향을 분석하는 것이다.

### 출력 점수 후처리 기법

**1. 이동평균 필터(Moving Average Filter)**

- 주식 데이터처럼 시간에 따른 값의 노이즈를 줄이는 데 흔히 쓰는 기법. 가장 단순한 형태는 **단순 이동평균(simple moving average)** — 최근 값과 이전 몇 개 값을 평균낸다.
- 예: 키워드 스팟팅은 1초에 3번(1/3초마다) 확률을 낸다. **2점 이동평균**이면 최근 값과 바로 이전 값을 평균.
- **raw 확률 대신 이동평균이 임계값을 넘을 때만 트리거**하면, "stopping"이라는 단어를 말할 때 "stop" 부분에서 확률이 잠깐 튀었다가 "-ing" 부분에서 다시 떨어지는 식의 **일시적 오탐을 걸러낼 수 있다.**
- **단점**: **지연(lag)** 이 생긴다 — 이동평균이 실제 신호를 따라잡는 데 한 사이클 이상 걸리므로, 키워드를 말한 즉시 반응하지 않을 수 있다.

**2. 홀드오프(Hold-off)**

- 이벤트(이상 탐지, 키워드 감지 등)가 트리거된 후 **일정 시간 동안 추론 자체를 멈추는** 기법.
- 배경: 키워드 스팟팅은 333ms 주기 중 약 135ms를 특징 추출+추론에 쓰고 **약 198ms는 다른 작업에 쓸 수 있는 여유**다. 이벤트가 감지된 직후엔 어차피 그에 대한 동작(액션)을 수행해야 하므로, **그 동안 추론을 잠깐 멈춰서 자원을 그 액션에 몰아줘도 된다.**
- 대가: **그 멈춘 시간 동안 다른 이벤트를 놓칠 수 있다.**
- **실제 사례 — Amazon Echo**: "Alexa"를 감지하면 몇 초간 서버로 스트리밍하며 요청을 처리하는 동안, **그 사이에는 "Alexa"를 다시 불러도 반응하지 않는다** — 홀드오프의 실제 예.

**3. 별도의 코프로세서(Coprocessor) 아키텍처**

- 머신러닝 전용으로 **작은 별도 마이크로컨트롤러**(예: Arm Cortex-M4)를 마이크/센서에 붙여, 그 칩이 **센서 읽기+추론만 전담**하게 하는 구조.
- 이벤트가 감지되면 **핀 토글이나 시리얼/I²C 메시지**로 메인 마이크로컨트롤러에 알린다.
- 전력·코드가 더 필요할 수 있지만 **범용 마이크로컨트롤러로도 충분히 구현 가능**하고 비용이 더 저렴할 수 있다.
- 앞으로는 Apple M1처럼 **메인 프로세서와 같은 실리콘 위에 전용 ML 코프로세서/가속기**를 통합하는 방향으로 발전할 것으로 전망(Module 1에서 다룬 Arm Ethos-U 같은 NPU도 같은 맥락).

## 예시

키워드 스팟팅 시스템에서 "stop"의 확률이 잠깐 0.7까지 튀었다가 곧 0.2로 떨어지는 노이즈성 오탐을 2점 이동평균이 걸러내고, 실제로 감지되면 300ms 정도 홀드오프하며 LED를 켜는 동작을 수행한 뒤 다시 리스닝으로 복귀하는 흐름 — 이 강의에서 소개한 세 기법(임계값·이동평균·홀드오프)을 조합한 실전 예다.

## 요약

- 임계값은 **히스토그램으로 두 분포의 겹침 정도를 보고, 응용의 FP/FN 허용도에 따라** 정한다. ROC/AUC는 임계값과 무관하게 분류기 자체의 품질을 비교하는 도구다.
- **학습된 신경망은 결정론적**이다 — 이 사실을 이용해 서버에서의 출력과 임베디드에서의 출력을 대조해 변환 오류를 검증할 수 있다.
- **이동평균**(노이즈 완화, 대신 지연 발생)과 **홀드오프**(이벤트 후 잠깐 추론 중단, 대신 그 사이 이벤트를 놓칠 위험)는 임베디드 ML 출력을 다루는 대표적인 후처리 기법이다.
- 자원이 부족하면 **머신러닝 전담 코프로세서**로 작업을 분리하는 아키텍처도 고려할 수 있다.
