# Machine Learning on Embedded Devices

## 개요

임베디드 시스템이 무엇인지(싱글보드 컴퓨터 vs 마이크로컨트롤러), 왜 최근에야 마이크로컨트롤러에서 머신러닝이 가능해졌는지, 그리고 **확률적(probabilistic)인 머신러닝을 결정론적(deterministic)인 임베디드 시스템에 섞어 쓸 때의 위험**을 짚는다.

## 내용

### 임베디드 시스템이란

**임베디드 시스템** = 더 큰 기계·전기 시스템 안에 내장된 컴퓨터 시스템. 데스크톱·노트북·폰·서버와 대비된다.

| 구분 | 싱글보드 컴퓨터(예: Raspberry Pi) | 마이크로컨트롤러(예: Arduino) |
|---|---|---|
| 프로세서 | 수백 MHz~GHz | (상대적으로 훨씬 약함) |
| 메모리 | 수백 MB~GB RAM | 훨씬 적음 |
| OS | 리눅스 등 풀 OS 가능 | 보통 없음(bare-metal 슈퍼루프) 또는 경량 RTOS |
| UI | CLI 또는 GUI | 없거나 버튼+간단 LCD 정도 |
| 전력 | 상대적으로 많이 씀 | 훨씬 적게 씀 |
| 가격 | 상대적으로 비쌈 | 훨씬 저렴 |

### 왜 이제야 마이크로컨트롤러에서 머신러닝이 되는가

- scikit-learn·TensorFlow·PyTorch·Caffe 같은 프레임워크는 원래 **파이썬 같은 고수준 언어가 도는 데스크톱/서버**용으로 만들어졌다 — 싱글보드 컴퓨터(라즈베리파이 등)에서는 큰 문제 없이 돌아간다.
- 하지만 **마이크로컨트롤러**에서는 최근까지 거의 불가능했다. Google TensorFlow 팀이 마이크로컨트롤러 전용으로 축소한 **TensorFlow Lite**를 내놓으면서, 행렬 연산을 손수 짜지 않고도 간단한 신경망을 마이크로컨트롤러에서 돌릴 수 있게 됐다.
- 마이크로컨트롤러에서 행렬 연산 자체는 새로운 게 아니다 — **최근 몇 년간의 소프트웨어·하드웨어 최적화**가 겹쳐서 더 복잡한 머신러닝 알고리즘까지 돌릴 수 있게 된 것.

### 응용 사례

- 가정용 음성 인식 시스템, 특정 사물·사람을 인식하는 카메라.
- 야생동물 연구자가 특정 동물 울음소리를 식별해 개체를 추적.
- 산업·우주 장비의 **이상 징후를 고장 나기 전에 감지**해 수리·교체 비용을 절감.

### 핵심 경고 — 확률적 머신러닝을 결정론적 임베디드 시스템에 섞을 때

- 전통적인 펌웨어는 **결정론적(deterministic)** 이다 — "온도가 임계값을 넘으면 밸브를 연다"처럼 조건 A가 되면 항상 행동 B가 일어난다. 인터럽트·RTOS로 타이밍을 정밀하게 제어하는 이유도 이 결정론성 때문이다.
- **머신러닝은 본질적으로 확률적(probabilistic)** 이다 — 데이터의 경향을 근사하는 수학적 모델일 뿐, "항상" 정답을 보장하지 않는다.
- **예시 경고 사례**: 누군가 "정지(stop)"라고 외치면 제조 장비를 자동으로 멈추는 비상정지 버튼을 음성 인식으로 만든다고 하자. 인식률이 99%라면 음성 인식 시스템으로는 훌륭한 성능이지만, **그 1%의 실패가 사람을 다치게 하거나 죽일 수도 있다.** 99%조차 OSHA(산업안전) 승인이나 FDA(의료기기) 승인 기준에는 보통 못 미친다.
- **결론**: 임베디드 머신러닝은 "모든 것을 고치는 마법"이 아니다. 다른 결정론적 기능을 **보완**하는 용도로 쓰거나, 결정론적 방식으로는 풀 수 없는 새로운 문제에 쓰는 것이 적절하다 — 안전이 걸린 결정을 확률적 모델에만 온전히 맡기지 않는다.

## 예시

야생동물의 특정 울음소리를 인식하는 시스템은 실패해도 "이번엔 못 들었다" 정도로 끝나지만, 비상정지 버튼처럼 **실패가 곧 인명 피해로 이어지는 시스템**에는 머신러닝 단독으로 걸어서는 안 된다는 것이 이 강의의 핵심 메시지다.

## 요약

- 임베디드 머신러닝이 가능해진 것은 **TensorFlow Lite 같은 경량 프레임워크 + 하드웨어/소프트웨어 최적화**의 합작품이다.
- 싱글보드 컴퓨터(파이썬 프레임워크 그대로 가능)와 마이크로컨트롤러(경량 프레임워크 필요)를 구분해서 이해해야 한다.
- **확률적 모델의 실패 가능성을 안전이 중요한 결정론적 시스템에 그대로 위임하면 안 된다** — 이 코스 전체에서 반복될 안전 관련 원칙이다.
