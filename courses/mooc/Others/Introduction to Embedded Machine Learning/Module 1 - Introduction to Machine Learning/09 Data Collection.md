# Data Collection

## 개요

이 코스의 첫 실습 프로젝트인 **"마법 지팡이" 제스처 인식**(좌우/상하/원 그리기)을 위해 스마트폰·Arduino Nano로 실제 데이터를 모으는 과정과, 그 과정에서 반드시 알아야 할 핵심 개념(학습/검증/테스트 분할, 일반화 실패, 불균형 데이터셋)을 함께 다룬다. 분량은 짧지만 이 코스에서 가장 개념 밀도가 높은 강의 중 하나다.

## 내용

### 원칙 1 — 배포할 센서와 같은 센서로 데이터를 모은다

- Arduino Nano 33 BLE Sense에 배포할 계획이면, **처음부터 그 보드의 IMU(LSM9DS1, 3축 가속도계)로 데이터를 모아야 한다** — 센서 모델마다 특성이 달라 다른 센서로 모은 데이터로 학습하면 성능이 떨어질 수 있다.
- 예외: 푸리에 변환처럼 **센서 고유 특성에 덜 좌우되는 특징(feature)을 추출**하면 다른 센서 간에도 어느 정도 이식성이 생길 수 있다(뒤 강의에서 다룸). 하지만 이 코스에서는 우선 **한 종류의 센서만 일관되게** 쓰라고 권한다 — 스마트폰으로 모았으면 스마트폰에 배포, Arduino로 모았으면 Arduino에 배포.

### 스마트폰으로 데이터 수집

1. `smartphone.edgeimpulse.com`에서 폰 연결 확인 → Data Acquisition.
2. 라벨을 `left-right`로 설정 → **Start Sampling**(10초 단위로 수집) → 그 10초 동안 좌우 동작을 반복 수행.
3. 그래프에 **반복되는 패턴**이 보이지 않으면 샘플을 삭제하고 다시 수집한다 — 나쁜 데이터로 학습하지 않기 위해.
4. 클래스당 **약 200초**(약 20개 샘플)를 모은다. `left-right`, `up-down`, `circle`(시계·반시계 방향을 절반씩), 그리고 **정지 상태를 나타내는 `idle`** 클래스까지 4개 — 총 약 800초.
5. 자세·속도(주파수)는 최대한 일정하게 유지하는 것을 권장 — 다양성을 주면 더 강건한 모델이 될 수 있지만 지금 단계에서는 정확도가 떨어질 수 있다.

### Arduino로 데이터 수집

- 이전 강의처럼 `edge-impulse-daemon` 실행 → 시리얼 포트 선택 → 프로젝트 자동 연결 확인.
- Data Acquisition에서 라벨 지정 후 Start Sampling, 스마트폰과 동일한 4개 클래스를 동일하게 반복.
- **스마트폰과 Arduino 데이터를 한 프로젝트에 섞지 않는다** — 지금 단계에서는 별도 프로젝트로 분리해서 진행할 것을 권장(둘 다 써보고 싶으면 나중에 별도로 합쳐보라고 제안).
- 같은 Arduino를 다른 프로젝트로 옮기려면 `edge-impulse-daemon --clean`으로 재로그인·재설정.

### 학습/검증/테스트 데이터 분할

- 기본 방식(hold-out method): 데이터를 무작위로 섞어 **학습(training) / 검증(validation) / 테스트(test)** 세 세트로 나눈다. 보통 테스트 10~20%, 검증 10~20%, 나머지가 학습.
- **학습 세트**로 모델 파라미터를 갱신(예: 역전파).
- **검증 세트**로 성능을 확인하고, 부족하면 **하이퍼파라미터**(모델 크기·형태, 학습 스텝 수, 학습률 등)를 조정해 다시 학습 → 다시 검증, 을 반복.
- **테스트 세트**는 맨 처음 떼어놓고 **맨 마지막에 딱 한 번만** 사용 — 최종 성능 보고용.
- **왜 검증과 테스트를 나누는가**: 하이퍼파라미터를 검증 세트 성능에 맞춰 계속 조정하다 보면, 모델이 검증 세트의 특성까지 은근히 학습하게 된다. 검증은 잘 나오는데 테스트가 나쁘면 **과적합(overfitting)** 신호다(다음 강의에서 다룸).
- (참고: k-겹 교차검증 같은 다른 분할법도 있지만 이 코스는 더 단순한 hold-out 방식을 쓴다.) Edge Impulse는 학습 세트에서 검증 세트를 **자동으로** 뽑아주지만, 테스트 세트는 사용자가 직접 지정해야 한다.

### 대표성 없는 데이터의 위험 — 개 사진 사례

- 푸들 사진만으로 "개"를 학습시키고 웰시코기로 테스트하면? 모델이 눈·주둥이 같은 **공통 특징을 일반화**할 수도 있지만, 실제로는 **곱슬 털·처진 귀** 같은 학습 데이터에만 있던 특징에 꽂혀 새로운 견종을 잘 못 알아본다.
- **사람(심지어 유아)은 푸들 한 장만 보고도 "개"라는 개념을 다른 견종에 일반화**할 수 있지만, 현재의 머신러닝 알고리즘은 이런 일반화에 매우 서투르다 — 학습 데이터가 실제 쓰일 데이터를 대표하는지 세심하게 신경 써야 한다.
- 앞서 나온 **강사 본인의 핼러윈 호박 사례**(성인 목소리로만 학습해 아이 목소리를 인식 못함)도 같은 문제였다고 재확인한다.
- 배경이 전부 어두운 개 얼굴 사진만으로 학습하면: (1) "어두운 배경 = 개"로 착각, (2) 몸 전체나 뒤통수 사진은 놓칠 가능성, (3) **일러스트/만화 개는 인식 못할 가능성**이 크다 — 사람은 실제 개→그림 개로 쉽게 일반화하지만 모델은 그렇지 못하다.
- 교훈: **최종 응용에서 실제로 마주칠 데이터가 무엇인지 먼저 생각하고, 그걸 대표하는 학습 데이터를 모아야 한다.** "Garbage in, garbage out."

### 불균형 데이터셋과 "나이브 분류기(naive classifier)" 함정

- 예: 공원에 개가 있는지 감지하는 모델. 실제로는 99%가 빈 들판이라서, 학습 데이터도 99%를 빈 들판 사진으로, 1%만 개 사진으로 채웠다고 하자.
- 이렇게 학습한 모델이 **뭐든 다 "들판"으로만 분류**해도 테스트 세트가 99% 들판이면 **정확도 99%**가 나온다 — 숫자만 보면 훌륭해 보이지만, 개를 하나도 못 찾으므로 애초에 이 모델을 쓰는 의미가 없다.
- 이것이 **나이브 분류기**다 — 불균형 데이터셋에서 자주 나타나는 함정(자세한 탐지법은 이후 강의에서).
- **해결책**:
  1. 가능하면 **데이터를 더 모은다**(항상 도움이 됨).
  2. 그게 어렵다면 **클래스별 샘플 수를 비슷하게 맞춘다**(리밸런싱) — 2클래스면 50:50, 4클래스면 각 25% 근처로.
  3. 목표 클래스 샘플이 극히 적다면(예: 스팸 메일 탐지처럼 정상 메일은 많고 스팸은 극소수) 일반 분류 대신 **이상 탐지(anomaly detection)** 같은 다른 접근이 필요할 수 있다(이후 강의에서 다룸).

### Edge Impulse에서 실제로 리밸런싱하기

- Dashboard → **Rebalance dataset** 버튼 → 자동으로 학습 80% / 테스트 20%로 분할.
- Data Acquisition의 Training/Test 탭에서 확인. 4개 클래스가 각각 약 25%씩 고르게 들어가 있어야 한다.
- 특정 클래스가 한쪽에 쏠려 있으면, 샘플의 점 3개 메뉴에서 **"Move to test set" / "Move to training set"** 으로 몇 개씩 옮겨 수동으로 맞출 수 있다.

## 요약

- 데이터 수집의 첫 원칙은 **배포할 센서와 같은 센서로, 일관된 조건에서** 모으는 것.
- 데이터는 학습/검증/테스트로 나누고, **테스트 세트는 맨 마지막에 단 한 번만** 쓴다 — 그렇지 않으면 검증 세트에 대한 과적합을 스스로 못 알아챈다.
- 학습 데이터가 실제 배포 환경을 대표하지 못하면(개 사진 예시, 핼러윈 호박 예시) 모델은 겉보기 특징에만 꽂혀 일반화에 실패한다.
- 불균형 데이터셋은 "정확도는 높지만 쓸모없는" **나이브 분류기**를 만들기 쉽다 — 데이터 추가 또는 클래스 밸런싱, 극단적인 경우엔 이상 탐지로 접근을 바꿔야 한다.
