# Machine Learning Pipeline

## 개요

지금까지 실습으로 해본 과정(수집 → 특징 추출 → 학습 → 배포)을 **공식적인 머신러닝 파이프라인 용어**로 정리한다. 특히 **파라미터 vs 하이퍼파라미터**의 구분, 그리고 **학습(training)과 추론(inference)에서 특징 추출이 반드시 똑같아야 한다**는 원칙, 마지막으로 DevOps/MLOps 개념을 소개한다.

## 내용

### 파이프라인 전체 흐름

1. **데이터 수집** — wav 파일(오디오), CSV, 메모리 배열 등 어떤 형식이든 가능. **지도학습**(이 코스의 주요 대상)에서는 각 샘플에 **라벨**이 붙는다.
2. **특징 추출** — 필요하면 먼저 필터링/정제(pre-processing)를 거친 뒤, RMS·PSD 같은 특징을 계산한다. **원본 데이터의 라벨이 그 특징 세트에도 그대로 붙어간다.**
3. **모델 학습** — 특징+라벨로 **역전파(back-propagation)** 를 통해 모델 내부 파라미터를 갱신. 특징이 원본 데이터를 잘 대표한다면, 수백~수천 번의 반복(iteration)으로 예측 정확도가 올라간다.

### 파라미터(Parameter) vs 하이퍼파라미터(Hyperparameter)

| 구분 | 정의 | 예시 |
|---|---|---|
| **파라미터** | 모델 내부의 변수·계수. 특징을 입력받아 예측을 만드는 데 쓰이는 숫자들 | 신경망의 가중치·편향 — **학습 과정에서 자동으로 결정**된다. 사람이 직접 설정하는 경우는 거의 없다 |
| **하이퍼파라미터** | 모델 바깥의 설정값. 데이터로부터 자동으로 추정되지 않는다 | 모델의 크기·형태, 학습률, 학습 스텝 수, 어떤 특징을 쓸지, 전처리 방법 — **사람이 직접 정해야 하는 값이면 대개 하이퍼파라미터** |

- 하이퍼파라미터를 자동으로 여러 조합 시도해보는 프로그램(하이퍼파라미터 탐색)을 만들 수도 있지만, 그래도 그 값들은 모델·학습 알고리즘 "바깥"에 있으므로 여전히 하이퍼파라미터로 분류된다.

### 배포와 추론(Inference)

- 학습된 모델 = 결국 **숫자(파라미터)의 모음 + 몇 가지 수학 연산**. 그래서 마이크로컨트롤러 메모리에 함수처럼 저장할 수 있다.
- 가장 쉬운 비유: **모델 = 함수** — 특징을 입력하면 예측(클래스)을 반환값으로 돌려준다.
- 학습이 끝난 모델로 **처음 보는 데이터에 대해 예측하는 과정**을 **추론(inference)** 이라 부른다.
- **핵심 원칙**: 추론 시에도 학습 때와 **완전히 동일한 특징 추출·전처리 과정**을 거쳐야 한다. 모델은 "특징"을 입력으로 기대하므로, raw 데이터를 그대로 넣으면 안 된다.
- 임베디드 환경에서는 데이터 수집 자체가 곧 **센서에서 raw 값을 읽는 것**이 되고, 저장된 파일을 여러 번 재사용하는 대신 **데이터 → 특징 → 예측이 실시간으로 한 번에 흐르는 파이프라인**으로 구성하는 경우가 많다.

### 자동화 — Ingestion API

- 이 코스에서는 수동으로 데이터를 수집했지만, Edge Impulse의 **ingestion API**를 쓰면 데이터 전송·학습까지 프로그래밍 방식으로 자동화할 수 있다(이 코스에서 깊게 다루지는 않음). 제품을 스케일업할 때 고려할 옵션.

### DevOps와 MLOps

- **DevOps**: 개발과 운영(IT Ops)을 결합해 개발 주기를 단축하고 지속적으로 고품질 시스템을 제공하는 실무 관행 모음(애자일에서 유래).
- 머신러닝이 대규모 엔터프라이�즈 소프트웨어에 통합되면서, 데이터 사이언티스트를 그 과정에 끌어들여 **올바른 데이터 수집, 편향 제거, 비즈니스 요구에 맞는 모델 구축**을 지원하는 **MLOps**가 부상하고 있다.
- **임베디드 머신러닝에도 같은 문제가 생긴다**: 현장에서 새 데이터가 모이면 모델을 갱신해야 하는데, **이미 필드에 배포된 수천 대의 디바이스에 어떻게 업데이트된 모델(펌웨어)을 배포·유지할 것인가**는 IoT의 OTA(Over-The-Air) 업데이트 문제와 정확히 같은 도전 과제다. 이 코스의 범위 밖이지만 실제 제품을 만들 때는 반드시 염두에 둬야 한다고 강조한다.

## 예시

Edge Impulse에서 실습한 흐름을 이 강의 용어로 다시 표현하면: 스마트폰 가속도계(데이터 수집, 라벨=동작 이름) → Spectral Analysis 블록(특징 추출, RMS+PSD) → Neural Network 블록(학습, 파라미터=가중치, 하이퍼파라미터=학습률·에폭 수 등) → 학습된 모델을 마이크로컨트롤러에 배포해 실시간 추론.

## 요약

- 파이프라인은 **수집 → 특징 추출 → 학습 → 배포(추론)** 로 요약된다.
- **파라미터는 학습이 자동으로 정하고, 하이퍼파라미터는 사람이 직접 정한다** — 이 구분은 이후 모델 튜닝 강의에서 계속 등장한다.
- **추론 시 특징 추출 과정은 학습 때와 반드시 동일해야 한다** — 이 원칙을 어기면 모델이 오작동한다.
- 필드에 배포된 디바이스의 모델을 어떻게 유지·갱신할지(MLOps + OTA)는 이 코스 범위 밖이지만 실제 제품화에는 필수적으로 고려해야 할 문제다.
