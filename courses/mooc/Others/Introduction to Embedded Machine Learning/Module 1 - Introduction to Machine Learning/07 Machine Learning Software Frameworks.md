# Machine Learning Software Frameworks

## 개요

Arm 펌웨어 엔지니어(Felix)가 **TensorFlow Lite Micro**와 **CMSIS-NN** 라이브러리가 어떻게 함께 동작해 마이크로컨트롤러에서 신경망을 효율적으로 돌리는지, 그리고 최적화가 왜/누구의 책임인지 설명한다.

## 내용

### 왜 지금에서야 가능해졌는가 — 모델과 프레임워크의 동반 발전

- 모델 자체가 메모리·연산량을 크게 줄이는 방향으로 발전했다. 예:
  - **MobileNetV2**(부동소수점): 3MB 이상, 3억 회 이상의 곱셈-누산(MAC) 연산.
  - **TensorFlow Lite Micro의 사람 감지(person detect) 모델**(MobileNet 기반): **250KB**, 약 **700만 회** MAC.
- 이런 모델·프레임워크의 축소가 엣지 디바이스에서의 머신러닝을 현실적인 선택지로 만들었다.

### CMSIS-NN — TensorFlow Lite Micro와 짝을 이루는 최적화 라이브러리

- **CMSIS-NN**: Cortex-M 마이크로컨트롤러용, 연산이 많이 필요한 ML 연산자를 최적화한 소프트웨어 라이브러리. **Apache 2.0 라이선스**(오픈소스·상업 프로젝트 모두 사용 가능).
- 동작 방식: TensorFlow Lite Micro의 **인터프리터**가 실행할 때, CMSIS-NN에 최적화된 커널이 있으면 그것을 쓰고, 없으면 **참조 구현(reference kernel)** 으로 대체(fallback)한다.
- 이 구조 덕분에 CMSIS-NN은 **연산이 무거운 연산자만 골라 최적화**하는 데 집중할 수 있고, 새 연산자 지원도 점진적으로 추가할 수 있다.

### 왜 최적화가 필요한가

- 사용자 경험(속도) 외에, **전력 사이클 제약**이 진짜 이유다.
- 추론에 걸리는 사이클을 줄이면 프로세서의 "깨어있는 시간(awake time)"이 줄어 **배터리 수명이 늘어난다.**
- 같은 추론 시간 예산 안에서 **더 복잡한 모델**을 돌릴 여유가 생긴다 — 이 차이가 "이 응용은 실현 불가능하다"와 "실현 가능하다"를 가른다.

### 최적화는 누구의 책임인가 — "온 마을이 함께 아이를 키운다"

하드웨어 설계자, 모델 설계자, 소프트웨어 환경을 세팅하는 사람, 라이브러리 최적화 담당자 **모두가** 최종 애플리케이션 속도에 영향을 준다.

- **소프트웨어 환경**(빌드 설정, 컴파일러 옵션)이 기초다 — 잘못된 빌드 변형이나 남아있는 컴파일러 옵션 하나가 최적화된 모델·라이브러리의 이득을 완전히 상쇄시킬 수 있다.

### CMSIS-NN이 실제로 최적화하는 두 가지 문제

1. **사이클 바운드(cycle-bound) 문제** — 프로세서 능력을 최대한 활용. 단순하게는 복잡하지 않은 루프 작성부터, 컴파일러가 못 챙기는 경우엔 **intrinsic/어셈블리 명령어**까지 직접 사용.
2. **메모리 바운드(memory-bound) 문제** — 데이터 재사용(data reuse)으로 메모리 접근 횟수 자체를 줄인다.

프로세서 종류에 따라 접근이 다르다:

- **SIMD(Single Instruction Multiple Data) 미지원 프로세서**: 효율적인 메모리 접근, 중첩 루프 단순화(예: 가장 안쪽 루프에서 조건문 제거)에 집중.
- **SIMD 지원 프로세서**: 위에 더해 intrinsic/어셈블리로 **SIMD 명령어를 확실히 사용**하도록 강제.

### 실제 성능 향상

- 최신 벡터 지원 프로세서(**Cortex-M55**)에서 MobileNetV2 같은 인기 모델 기준 **약 10배 성능 향상**. (수치는 소프트웨어 환경·메모리 접근 지연·캐시 등 시스템에 따라 달라질 수 있다.)

### 모델 최적화 — 양자화만으로는 부족하다

- 모델이 8비트 또는 4비트로 **양자화(quantization)** 되어 있어도, 그것만으로 최고 성능이 보장되지 않는다.
- **텐서의 형태(shape)** 도 최적화 수준에 영향을 준다 — 정렬되지 않은 접근(unaligned access)을 유발하는 형태는 메모리 접근 시간을 늘린다. 어떤 형태는 특수 기법(예: im2col 변환) 없이도 태생적으로 최적화가 잘된다.

## 예시

같은 MobileNetV2 모델이라도: (1) 부동소수점 그대로 돌리면 느리고 크다 → (2) TensorFlow Lite Micro로 양자화하면 크기가 크게 준다 → (3) CMSIS-NN 최적화 커널로 돌리면 같은 정확도에서 몇 배 더 빨라진다 → (4) Cortex-M55 같은 벡터 지원 하드웨어와 결합하면 추가로 최대 10배가 더 빨라진다.

## 요약

- 마이크로컨트롤러에서 ML이 가능해진 것은 **모델 경량화(TensorFlow Lite Micro) + 연산 라이브러리 최적화(CMSIS-NN)**가 함께 발전한 결과다.
- CMSIS-NN은 TF Lite Micro의 무거운 연산자만 골라 최적화하고, 없으면 참조 구현으로 자동 대체되는 구조다.
- 최적화는 하드웨어부터 소프트웨어 빌드 환경, 모델 설계, 라이브러리까지 **여러 층이 함께 책임지는 팀 작업**이며, 텐서 형태 같은 디테일까지 성능에 영향을 준다.
