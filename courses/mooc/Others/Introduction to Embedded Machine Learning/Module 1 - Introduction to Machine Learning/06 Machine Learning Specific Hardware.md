# Machine Learning Specific Hardware

## 개요

Arm의 시니어 하드웨어 엔지니어(Tomas)가 "무엇이 진짜 AI 하드웨어 가속기를 만드는가"를 설명한다. TinyML의 정의, 대표 응용 3가지(3D: Vibration·Voice·Vision), 그리고 Arm의 Cortex-M55(CPU)·Ethos-U55/U65(NPU) 조합이 순수 소프트웨어 대비 얼마나 빨라지는지 구체적인 수치로 보여준다.

## 내용

### "AI 개발보드"라는 마케팅에 대한 경고

시중에 "AI 개발보드"라고 광고하는 제품 상당수가 사실은 **평범한 Arm Cortex-M4 + 센서 몇 개**일 뿐이다. 센서를 몇 개 달았다고 AI 능력이 생기는 게 아니다 — 이 강의는 진짜 ML 특화 하드웨어가 무엇인지 구분해서 보여준다.

### TinyML의 정의와 3가지 응용 영역(3D)

- **TinyML**: 보통 **1밀리와트 이하** 전력으로 디바이스 위에서 도는 머신러닝. 대개 배터리(때로는 에너지 하베스팅)로 구동되는 마이크로컨트롤러 시스템.
- 연산량이 적은 순서대로 3가지 응용(3D):
  1. **Vibration(진동)** — 모터 제어 + 그 모터에 국한된 예지보전(predictive maintenance).
  2. **Voice(음성)** — 마이크 1개 이상으로 키워드 감지·음성 인식.
  3. **Vision(비전)** — 산업 현장의 사물 분류·불량 검출, 사람 존재 감지, 얼굴 인식으로 잠금 해제 등. 연산량이 가장 크다.

### 왜 엣지 컴퓨팅이 IoT에 중요한가

지연시간(latency), 자율성(autonomy), 네트워크 대역폭, 그리고 **프라이버시·보안** — 이 네 가지 문제를 해결하기 위해 "가장 먼 엣지(far edge)"에서의 연산이 점점 중요해지고 있다.

### Arm의 ML 특화 하드웨어 라인업

| 제품 | 유형 | 특징 |
|---|---|---|
| Cortex-M4/M33/M35P/M7 | 기존 CPU | CMSIS 오픈소스 라이브러리로 신호처리 가능(기존에도 있던 능력) |
| **Cortex-M55** | 신형 CPU | Helium 벡터 확장을 지원하는 첫 M클래스 프로세서. **DSP 성능 최대 5배**, 8비트 내적(dot-product) 연산으로 **머신러닝 성능 최대 15배** 향상. 메모리 인터페이스도 모델 파라미터를 빠르게 읽도록 최적화. TrustZone 보안 지원, 필요한 기능만 골라 넣는 구성(configurability)으로 면적·전력 최적화 가능 |
| **Ethos-U55** | 마이크로 NPU(신경망 전용 가속기) | Cortex-M과 함께 쓰는 **첫 마이크로 NPU**. CNN·RNN 등 인기 신경망을 CPU 개입 없이 전담 처리. 압축된 가중치를 지원해 저장 용량·대역폭도 줄인다. 사이클당 32~256 MAC(곱셈-누산) 규모로 4단계 구성 가능. **Cortex-M55와 짝지을 때 최적** |
| **Ethos-U65** | 2세대 마이크로 NPU | 사이클당 최대 512 MAC까지 확장, DRAM 지원 시스템까지 대응. A클래스 시스템에 통합해 "상시 대기(always-on)" 기능 등에 활용 |

### 소프트웨어 배포 파이프라인 — TensorFlow Lite → Vela 컴파일러

1. 오프라인 호스트에서 TensorFlow로 신경망을 만들어 **TF Lite 파일**로 내보낸다.
2. 타깃 시스템에 Ethos-U가 있으면, **Vela**(오픈소스 오프라인 컴파일러)가 TF Lite 파일을 읽어 **Ethos-U가 지원하는 연산자를 컴파일된 그래프로 교체**한 새 TF Lite 파일을 만든다. 이 과정에서 가중치 압축까지 이뤄져 모델 크기와 필요한 SRAM이 줄어든다.
3. 배포 시: 신경망의 대부분(또는 전부)은 Ethos-U에서 돌고, Ethos-U가 지원하지 않는 연산만 Cortex-M이 CMSIS-NN 최적화 라이브러리로 처리한다.
4. 개발자 입장에서는 **하드웨어가 무엇이든 배포 과정이 투명(transparent)** 하다 — TF Lite 파일만 미리 컴파일해두면 된다.

### 실제 성능 수치 — Wav2Letter(음성 인식 신경망) 기준

| 구성 | M4 대비 속도 향상 |
|---|---|
| CMSIS-NN (M4) vs 최적화 안 된 TF Lite 참조 커널 (M4) | 3.5배 |
| + Helium(M55) | 추가 11배 |
| + Ethos-U55 | 추가 25배 |
| **총합** | **약 1,000배** (순수 신경망 연산 기준) |

**전체 음성 비서 애플리케이션**(빔포밍·에코 캔슬링·MFCC 변환 등 전처리 포함, 기준을 M7+CMSIS-NN으로 잡았을 때):

- M55만 쓰면 M7 대비 **6배** 빠름.
- M55+Ethos-U55 조합이면 **50배** 빠름.
- 게다가 **최대 25배 더 적은 에너지**를 소비한다.

### 응용별 권장 하드웨어 요약

| 응용 | 필요 하드웨어 |
|---|---|
| 진동, 단순 음성(키워드 감지) | 기존 Cortex-M으로 이미 가능 |
| 고급 음성, 단순 비전(이상 탐지·사물 감지) | Cortex-M55(Helium) |
| 완전한 음성 인식, 고급 비전(제스처 인식) | Cortex-M55 + Ethos-U55 |
| 최고 성능(고급 전통 ML 포함) | A클래스 + Ethos-U65 또는 클라이언트급 Ethos NPU |

> 필요한 연산량은 정확도 목표에 크게 좌우된다 — 음성 응용이면 마이크 개수·오디오 비트 정확도·목표 정확도에 따라 필요 연산량이 크게 달라지고, 정확도를 조금만 높여도 연산 비용이 크게 늘 수 있다.

## 요약

- "AI 보드"라는 이름만으로 진짜 ML 가속 하드웨어인지 판단하면 안 된다 — CPU 자체의 벡터 확장(Helium)이나 전용 NPU(Ethos-U) 유무를 봐야 한다.
- TinyML 응용은 연산량 순으로 **진동 < 음성 < 비전**.
- 소프트웨어(TensorFlow Lite + Vela 컴파일러)와 하드웨어(Cortex-M55 + Ethos-U)를 함께 최적화하면 순수 CPU 대비 **최대 1,000배**(신경망 단독), 실제 애플리케이션 기준으로도 수십 배의 속도·에너지 개선이 가능하다.
- 어떤 하드웨어를 고를지는 응용 종류뿐 아니라 **목표 정확도·전력 예산**에 따라 달라진다.
