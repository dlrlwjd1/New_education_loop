# Feature Extraction from Motion Data

## 개요

앞서 모은 가속도계 데이터로부터 **어떤 특징(feature)을 뽑아 모델에 넣을지**를 다룬다. 왜 임베디드 환경에서는 딥러닝의 "raw 데이터를 그대로 넣고 모델이 알아서 특징을 찾게 하는" 방식이 부담스러운지, 그리고 Edge Impulse가 실제로 어떤 특징(RMS, FFT/PSD)을 계산하는지 설명한다.

## 내용

### 특징(feature)이란

머신러닝에서 특징 = **관찰 대상의 개별적으로 측정 가능한 속성/특성**.

### 나쁜 특징 세트의 예 — 한 시점의 스냅샷

- 어떤 시점 하나의 (x, y, z) 가속도 값 3개를 특징으로 쓴다고 하자 — **3차원 입력**.
- 문제: **시간에 따른 변화(시계열 정보)** 가 전혀 없다. 그냥 한 순간의 스냅샷일 뿐.
- 4개 클래스(좌우/상하/원/정지)의 스냅샷들을 3차원 공간에 색깔별로 찍어보면 대체로 구분되는 군집이 보이긴 하지만, **중심부에서는 네 클래스가 뒤섞여 겹친다** — 특정 순간엔 어떤 동작이든 가속도 값이 비슷해질 수 있기 때문. 이 지점에서 모델이 구별하기 어려워진다.
- 경험칙: **분류 문제에서 샘플 군집을 사람 눈으로 시각적으로 구분할 수 있으면, 기계도 대체로 학습할 수 있다.**

### 개선 시도 — 시간 윈도우를 늘리면?

- 한 동작 주기(약 1~2초)를 포함하도록 **2초 윈도우**로 늘려보자. 샘플링 속도 62.5Hz 기준 축당 125개 샘플 × 3축 = **375차원** 입력.
- 사람이 시각화하기엔 너무 커졌고, 이 375차원을 그대로 딥러닝 모델(CNN 등, 나중 강의에서 다룸)에 넣으면 모델이 알아서 유용한 특징을 학습할 수는 있다.
- 하지만 두 가지 문제가 있다:
  1. **연산 비용** — 입력 차원이 클수록 저장할 메모리와 연산량이 늘고, 특징 추출 레이어가 여러 겹이면 추론 연산량이 배가된다.
  2. **더 많은 학습 데이터가 필요** — 모델이 커질수록 학습에 필요한 데이터도 늘어나는데, 임베디드 프로젝트에는 무한한 데이터·시간이 없다.
- 결론: 서버팜에서는 이런 대형 모델이 괜찮지만, **임베디드 시스템에서는 raw 데이터를 그대로 넣기보다 사람이 직접 의미 있는 특징을 골라 차원을 줄이는 편이 유리**하다. 목표는 **모델을 최대한 작고 빠르게** 유지하는 것.

### 사람이 직접 뽑는 특징 — RMS

- 125개 샘플을 축마다 **RMS(root mean square, 제곱평균제곱근)** 값 하나로 압축 → 다시 **3차원**(축당 1개)이 되면서도 2초 분량의 정보를 담는다.
- RMS 계산 전에 **평균(중력 성분)을 빼서 필터링**하는 것이 일반적 — Edge Impulse가 실제로 이렇게 처리한다.
- RMS만으로도 클래스 간 분리가 꽤 잘 되어, 이것만으로 괜찮은 분류기를 만들 수도 있다.

### 한 단계 더 — 푸리에 변환(FFT)과 파워 스펙트럼 밀도(PSD)

- 진동/모션 데이터에서 흔히 쓰는 기법: **푸리에 변환**으로 신호를 **주파수 성분**으로 분해한다. 이산 샘플링 데이터에는 **FFT(고속 푸리에 변환)** 를 쓴다.
- 예: 좌우 동작을 1초에 한 번(1Hz) 반복했다면, FFT 결과 그래프에서 **1Hz 지점에 뚜렷한 피크**가 나타난다. 더 빠르게(3Hz) 흔들면 피크가 3Hz로 이동한다.
- Edge Impulse는 FFT에서 한 단계 더 나아가 **PSD(Power Spectral Density)** 를 계산한다 — FFT는 빈(bin)의 주파수 폭에 따라 진폭이 왜곡될 수 있는데, PSD는 그 폭으로 정규화해 이 왜곡을 보정한다.
- PSD 전체 값을 다 쓰지 않고, Edge Impulse는 **핵심 특성만 추출**한다:
  1. 각 축에서 **가장 높은 피크의 진폭과 위치(주파수)**.
  2. PSD의 특정 구간별 **값을 합산**한 값들.
  - 이 두 가지로 PSD의 "모양"을 적은 차원으로 요약한다.

### 최종 특징 세트 — 375차원 → 33차원

축(x/y/z)마다: RMS 1개 + PSD 피크 진폭 3개 + PSD 피크 주파수 3개 + PSD 구간 합산 4개 = **축당 11개 × 3축 = 33차원**.

- 375차원 raw 입력을 **33차원**으로 크게 줄이면서도 핵심 정보는 보존한다.
- 특징의 순서는 자유롭게 정해도 되지만, **학습 때와 배포(추론) 때 반드시 같은 순서**를 유지해야 한다.

### 슬라이딩 윈도우 — 학습용 데이터 늘리기

- 10초짜리 샘플 하나를 2초 단위로 딱 잘라 쓰면 샘플 수가 적다. 대신 **2초 윈도우를 조금씩(Edge Impulse 기본값 80ms) 밀어가며(sliding window)** 여러 개의 겹치는 윈도우를 만들면, 10초짜리 녹화 하나에서 **훨씬 많은 학습 샘플**을 뽑아낼 수 있다.
- **주의**: 이 슬라이딩 윈도우는 학습 데이터를 늘리기 위한 기법일 뿐, **실제 배포된 임베디드 시스템에서는 쓰지 않는다** — 배포 시엔 그냥 2초간 데이터를 모으고, 특징을 계산해서, 학습된 분류기에 한 번 넣는다(다음 강의에서 자세히).

## 예시

375차원(원본) → RMS+FFT/PSD로 33차원까지 압축 → 사람이 3차원 스냅샷으로는 못 구분하던 4개 동작(좌우/상하/원/정지)을 시간 윈도우 기반 특징으로는 뚜렷하게 구분할 수 있게 된다.

## 요약

- 임베디드 ML에서는 raw 데이터를 그대로 큰 모델에 넣기보다, **사람이 도메인 지식으로 특징을 직접 설계**해 입력 차원을 줄이는 것이 실용적이다.
- 모션/진동 데이터의 대표적 특징: **RMS**(시간 영역 요약)와 **FFT 기반 PSD**(주파수 영역 요약, 피크 위치·진폭·구간 합산).
- 슬라이딩 윈도우로 학습 데이터를 늘릴 수 있지만, 이는 학습 전용 기법이며 배포된 디바이스는 실시간으로 한 윈도우씩만 처리한다.
