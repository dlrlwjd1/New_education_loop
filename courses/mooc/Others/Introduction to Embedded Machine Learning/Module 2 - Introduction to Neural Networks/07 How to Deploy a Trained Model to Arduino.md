# How to Deploy a Trained Model to Arduino

## 개요

이 코스의 첫 번째 실제 **마이크로컨트롤러 배포** 실습. Edge Impulse의 Deployment 페이지에서 Arduino 라이브러리를 빌드하고, Arduino IDE에 설치해 실제 Nano 33 BLE Sense 보드에서 모션을 실시간으로 분류한다. 단일 스레드 예제와 멀티스레드(연속 추론) 예제를 둘 다 다룬다.

## 내용

### Deployment 옵션

- **범용 C++ 라이브러리**도 선택 가능(C++ 컴파일러만 있으면 어떤 마이크로컨트롤러에도 컴파일 가능) — 이 코스는 더 쉬운 **Arduino library**를 사용.
- **EON Compiler**: 기본적으로 TensorFlow Lite 모델은 런타임에 로드되는 FlatBuffer로 변환되고, C++로 작성된 **인터프리터**가 그 안의 연산을 읽어 실행한다. Edge Impulse의 **EON 컴파일러**는 TensorFlow Lite 커뮤니티의 작업을 기반으로, 모델을 아예 **C++ 소스 코드로 컴파일**해서 타깃 디바이스의 RAM·플래시 사용량을 줄인다. 기본 TFLite 인터프리터가 꼭 필요한 경우가 아니면 **EON을 켜두는 것을 권장**.
- **Analyze** 버튼: 예상 추론 시간·RAM·플래시 요구량을 알려준다. 단, 이 추정치는 **Arm Cortex-M4F @ 80MHz 기준**이라, Nano 33 BLE Sense(64MHz)는 더 오래 걸릴 수 있다. 또한 **이 추정치엔 특징 추출 시간이 포함되지 않는다** — 별도로 processing block에서 확인해야 한다.
- **Floating point vs 양자화(Quantized)**: 대부분의 임베디드 시스템에는 **양자화 옵션 유지를 권장**(정확도는 약간 손해지만 RAM·플래시를 아낀다).
- **Build** 클릭 → `.zip` 라이브러리 다운로드(압축 풀지 않고 그대로 Arduino IDE에 임포트).

### Arduino IDE에 설치

1. (재설치라면) Arduino Libraries 폴더에서 기존 `ei-프로젝트명` 폴더를 먼저 삭제.
2. Arduino IDE → **Sketch → Include Library → Add .ZIP Library** → 다운로드한 zip 선택(예제 스케치도 함께 임포트됨).
3. **Tools → Board → Arduino Nano 33 BLE**.
4. **File → Examples → (프로젝트명) 라이브러리 → nano_ble33_sense_accelerometer** 예제 열기.
5. 보드 연결 확인 후 **Tools → Port**에서 시리얼 포트 선택 → **Upload**.

### Windows 긴 경로 오류 대처

- Windows에서 라이브러리 파일 경로가 너무 길다는 에러가 나면, Edge Impulse 문서에서 **mbed 플랫폼용 `platform.local.txt`** 파일을 받아 `%LocalAppData%\Arduino15\packages\arduino\hardware\mbed\1.1.4\`에 복사한 뒤 다시 업로드한다.

### 예제 1 — 단일 스레드(비연속) 스케치 코드 구조

- 상단에서 Edge Impulse 라이브러리(학습된 모델 포함) + `Arduino_LSM9DS1`(가속도계) 라이브러리를 import.
- `ei_printf` 함수가 시리얼 모니터 출력을 담당(내부적으로 `Serial.write` 사용).
- `loop()` 안에서: **2초간 샘플링 → 버퍼를 NumPy 배열 형태로 변환 → `run_classifier()` 호출(특징 추출+추론을 한 번에 수행) → 결과를 시리얼 모니터에 출력**, 이 사이클을 반복.

### 실행 결과 확인

- 시리얼 모니터를 열면 샘플링 시작/진행/분류 결과가 출력된다.
- 보드를 좌우로 흔들면 `left-right`가, 상하로 흔들면 `up-down`이, 원으로 돌리면 `circle`이, 가만히 두면 `idle`이 가장 높은 확률로 나오는 것을 확인.

### `model_metadata.h` — 배포된 설정 확인

- 라이브러리 설치 경로의 `src/model-parameters/model_metadata.h`에서 프로젝트 설정을 확인할 수 있다.
- **중요한 차이**: 스마트폰은 **62.5Hz**로 데이터를 모았지만, **Arduino는 기본 100Hz**로 샘플링한다 — 축당 샘플 수도 125개가 아니라 **200개**로 달라진다(Edge Impulse에서 이 수집 주파수를 바꿀 수도 있지만 이 강의에서는 기본값 유지).
- 라벨 배열도 여기서 확인 가능 — **라벨의 순서가 중요하다**(예: `left-right`가 배열의 인덱스 2라면 코드에서 항상 그 순서를 참조해야 한다).

### 예제 2 — 연속(continuous)/멀티스레드 스케치

- **File → Examples → (라이브러리) → accelerometer_continuous** 예제는 **mbed OS의 두 스레드**로 데이터 수집과 추론을 분리해서 돈다(이 코스는 멀티스레드 프로그래밍 자체는 깊게 다루지 않지만 개념은 설명).
  - **스레드 1(`run_inference_background`)**: 내부에 자체 while 루프가 있고, 원시 가속도계 버퍼를 복사해 분류를 수행 — **약 200ms마다 한 번씩만** 돈다. 여러 번의 추론 결과를 몇 초에 걸쳐 **평균 내어(smoothing)** 더 확신 있는 답을 낸다 — 그래서 동작을 몇 초간 유지해야 결과가 안정적으로 나온다.
  - **메인 루프**: 독립적으로 동작 — 버퍼를 3개 포인트씩 앞으로 밀어(가장 오래된 3개를 버리고) 가속도계에서 새 값 3개를 채워 넣는 방식으로, **100Hz 샘플링을 유지하면서 슬라이딩 윈도우를 구현**한다.
- 시리얼 모니터 출력 해석:
  - **DSP** 시간 = 특징 추출 소요 시간, **Classification** 시간 = 추론 소요 시간.
  - (아직 켜지 않은) 이상 탐지(anomaly detection) 항목은 무시.
  - 예측 확률은 **0~10 스케일**(10 = 100%)로 표시되는 6개 숫자 배열 — 앞 4개는 4개 클래스, 5번째는 **불확실성(uncertainty)**, 6번째는 **이상 탐지 점수**.
  - 정지해두면 idle(2번째 값)이 10에 가까워지고, 원을 그리면 1번째 값이 오르다 8을 넘으면 `circle`로 판정. 격하게 움직이거나 전환 구간이면 불확실성 값이 오른다.

### 강사의 권장 학습 순서

- **처음엔 단순한 단일 스레드 예제**로 데이터 수집·추론이 어떻게 도는지 감을 잡고, 이후 실제 프로젝트에서 **수집과 추론을 동시에(백그라운드)** 해야 할 필요가 생기면 이 연속 예제(또는 다른 멀티스레드 예제, 타이머 인터럽트, DMA)로 돌아오라고 권한다.

## 예시

Arduino를 손에 쥐고 원을 그리며 8초쯤 기다리면, 시리얼 모니터의 첫 번째 확률 값이 서서히 올라가 8을 넘는 순간 `circle`이 최종 예측 라벨로 표시된다 — smoothing 때문에 즉각 반응하지 않고 몇 초의 지연이 있다는 것을 직접 체감하게 된다.

## 요약

- 배포 흐름: Deployment 페이지에서 **Arduino library(+EON 컴파일러, 양자화)** 빌드 → Arduino IDE에 zip으로 설치 → 예제 스케치 업로드.
- 단일 스레드 예제는 "수집 2초 → 특징 추출+추론 → 출력"을 반복하는 가장 단순한 형태.
- 연속(멀티스레드) 예제는 **백그라운드에서 계속 샘플링하면서 별도 스레드가 주기적으로 추론**하고, 여러 추론 결과를 평균 내어(smoothing) 더 안정적인 판정을 낸다 — 실전에서는 이쪽이 더 일반적인 패턴이다.
- 스마트폰(62.5Hz)과 Arduino(100Hz 기본값)의 **샘플링 주파수가 다르다**는 점, `model_metadata.h`에서 실제 배포 설정을 확인할 수 있다는 점을 기억해둔다.
