# Industrial Embedded Machine Learning Demo

## 개요

Edge Impulse의 창립 엔지니어 중 한 명인 **Daniel Situnayake**가 게스트로 등장해, 지금까지 배운 "제스처 인식과 똑같은 기법"을 **산업 현장(물류/자산 추적)** 에 적용한 실제 데모("스마트 팔레트")를 보여준다.

## 내용

### 데모 구성 — 스마트 팔레트

- 장난감 지게차 + 배터리를 붙인 마이크로컨트롤러 개발 보드가 달린 플라스틱 팔레트.
- 목표: 팔레트가 전 세계로 운송되는 동안 **어떤 상태였는지**(정지·이동·상하 리프트)를 3축 가속도계만으로 파악.

### 데이터 수집 — 3가지 클래스

1. **정지(stationary)** — 팔레트가 가만히 있는 상태, 약 4분.
2. **이동(driving)** — 지게차가 이동 중, 약 4분.
3. **리프트(lifting and lowering)** — 팔레트가 들어올려지거나 내려지는 상태, 약 4분.

### 신호 처리와 학습 결과

- 신호 처리(특징 추출)만으로도 세 상태가 **시각적으로 뚜렷이 구분되는 군집**으로 나뉜다 — driving(파란 군집), lifting/lowering, stationary가 서로 명확히 분리됨.
- "사람 눈으로 군집이 구분되면 기계도 학습할 수 있다"는 앞선 강의의 원칙 그대로, **딥러닝 모델로 95% 정확도**를 달성.

### 왜 이게 유용한가 — 로그의 경제성

- 운송 중인 팔레트에서 **가속도계 원시 데이터를 계속 기록·전송하는 것은 비현실적**이다 — 저장 용량이 부족하고, 실시간 전송은 전력을 많이 쓰고 비용이 크며, 이동 중인 화물의 연결성(connectivity)도 보장되지 않는다.
- 대신 **디바이스 위에서 직접 분류(추론)를 수행**해, "언제부터 이동이 시작됐는지, 언제 리프트됐는지, 언제 정지했는지"만 **저빈도의 숫자 로그**로 남긴다.
- 팔레트가 목적지에 도착하면 그 로그만 읽어서, 운송 과정에서 **이동/리프트/정지에 각각 얼마나 시간이 걸렸는지** 파악할 수 있다 — 물류 효율을 분석하고 개선점을 찾는 데 활용.

## 예시

원시 가속도계 데이터를 통째로 클라우드에 올리는 대신, "10:03 이동 시작 → 10:47 정지 → 10:52 리프트 시작 → 10:53 리프트 종료"처럼 **이벤트 로그만 남기는 것**이 엣지에서 추론하는 것의 실질적 가치다.

## 요약

- 이 강의의 핵심 메시지: **"raw 센서 데이터를 다 보내는 대신, 엣지에서 분류해서 의미 있는 저빈도 로그만 남긴다"** 는 것이 임베디드 머신러닝의 실전 가치 중 하나다.
- 기법 자체(신호 처리로 특징 추출 → 군집 분리 확인 → 신경망 학습)는 이 코스의 제스처 인식 프로젝트와 완전히 동일하며, **가정용 데모와 산업 현장 응용 사이의 거리가 생각보다 가깝다**는 것을 보여준다.
