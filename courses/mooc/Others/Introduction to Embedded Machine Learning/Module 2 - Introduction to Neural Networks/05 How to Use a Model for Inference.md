# How to Use a Model for Inference

## 개요

학습된 모델을 배포하기 전에, **Netron**이라는 도구로 모델 내부(양자화된 입출력 형태)를 들여다보고, 실제 임베디드 디바이스에서 **2초 샘플링 → 특징 추출 → 추론**의 실시간 루프를 어떻게 설계하는지 다룬다.

## 내용

### 추론(Inference)이란

학습이 끝난 뒤, **한 번도 본 적 없는 실시간(live) 데이터**로 예측을 만드는 과정. 실제 제품/프로덕션 환경에서 모델을 쓰는 단계.

### 모델 내부 들여다보기 — Netron

1. Edge Impulse 대시보드에서 신경망 모델을 다운로드 — **int8 양자화(quantized) 버전**을 받는다(Edge Impulse가 실제로 라이브러리에 빌드해 넣는 버전).
2. `netron.app`(웹 앱)에 업로드하면 신경망을 그래픽으로 볼 수 있다. Edge Impulse는 **`.tflite`**(TensorFlow Lite) 형식으로 모델을 만든다.
3. **입력(input) 확인**: **1×33 크기의 8비트 정수 배열**을 기대한다 — 앞서 만든 33개 특징과 일치.
4. **양자화(Quantization)란**: 신경망은 원래 부동소수점을 쓰지만, TensorFlow Lite는 입력·출력·파라미터를 **8비트 정수로 변환(양자화)** 할 수 있다. 이렇게 하면 메모리를 크게 절약하지만 **정확도가 약간 떨어질 수 있다.** Netron에서 이 변환에 쓰이는 수식(스케일·제로포인트)도 확인할 수 있다. 다행히 **Edge Impulse 라이브러리가 양자화·역양자화를 자동으로 처리**해줘서 직접 코드로 계산할 필요는 없다.
5. **출력(output) 확인**: 클래스 개수(4개)만큼의 양자화된 숫자 배열 — 역양자화하면 각각 **0~1 사이의 확률**이 된다.
6. 각 층을 클릭하면 입출력 노드 수를 확인할 수 있다 — 이 프로젝트는 **33 → 20 → 10 → 4** 구조(마지막에 소프트맥스 적용)임을 실제로 확인.
7. 다른 시스템에서 이 모델을 Edge Impulse 라이브러리 없이 직접 쓰려면, **타깃 시스템의 TensorFlow Lite 버전이 이 모델을 만든 버전과 일치해야 한다.**

### 배포 라이브러리에 포함되는 것

Edge Impulse 라이브러리를 다운로드하면 모델뿐 아니라 **특징 추출 코드까지 함께 포함**된다.

- 이 프로젝트는 **375개의 raw 값**(3축 × 62.5Hz × 2초)을 기대한다 — C++이면 이 버퍼를 가리키는 포인터를 라이브러리 함수에 넘기면 된다.
- 라이브러리가 알아서 375개 raw 값 → 33개 특징으로 변환 → 모델에 넣어 추론 → 4개 클래스 확률(소프트맥스 출력)을 반환.
- 애플리케이션 코드는 **가장 높은 확률의 클래스를 찾거나**, 또는 **임계값(threshold) 비교**로 판단하면 된다. 예: `left-right` 확률이 0.5를 넘으면 그 동작으로 간주(확률 합이 1이므로 하나가 0.5를 넘으면 자동으로 최댓값이다). 임계값을 높이면 더 엄격하게, 낮추면 더 관대하게 판정할 수 있다.

### 실시간 추론 루프 설계 — 임베디드에서의 실제 구현

기본 루프: **① 가속도계를 2초간 샘플링 → ② 특징 추출 → ③ 추론(결과에 따라 행동) → 반복.**

- 문제: 특징 추출+추론에 수십~수백 밀리초가 걸릴 수 있어, **그 시간 동안 새로운 동작을 놓칠 수 있다.**
- 해결책 — **샘플링과 추론을 분리(비동기화)**:
  - **타이머 인터럽트**(예: 16ms마다 발동)로 가속도계를 규칙적으로 샘플링.
  - 또는 **RTOS의 반복 태스크**로 샘플링을 예약.
  - 또는 마이크로컨트롤러가 지원하면 **DMA(Direct Memory Access)** 로 백그라운드에서 버퍼를 채운다.
- 버퍼가 2초 분량 채워지면, 그 버퍼를 라이브러리로 넘겨 특징 추출+추론을 수행하는 **동안에도 백그라운드(인터럽트/DMA)는 계속 다음 데이터를 모은다.**
- 매번 완전히 새로운 2초를 기다릴 필요 없이, **이전 데이터와 일부 겹치도록(슬라이딩 윈도우) 밀어서** 다음 추론용 버퍼를 구성할 수 있다 — 이렇게 하면 반응성이 좋아진다.
- **타이밍 관리가 핵심**: 추론이 너무 오래 걸리거나 자원을 너무 많이 쓰면 버퍼가 넘치거나(overflow) 샘플을 놓칠 수 있다. (오디오 분류 프로젝트에서 이 문제를 실제로 다룬다고 예고.)

## 예시

모델 출력이 `[left-right: 0.02, up-down: 0.05, circle: 0.10, idle: 0.83]`이라면, `idle`의 확률이 0.5를 넘으므로(그리고 자동으로 최댓값이므로) "정지 상태"로 판정하면 된다 — 애플리케이션 코드는 단순히 임계값 비교나 최댓값 탐색만 하면 된다.

## 요약

- 배포 전 **Netron으로 모델의 입출력 형태(양자화된 정수 배열 크기)를 확인**하는 습관을 들인다.
- **int8 양자화**는 메모리를 아끼는 대신 약간의 정확도를 희생하며, Edge Impulse 라이브러리가 양자화/역양자화를 자동 처리한다.
- 실제 배포 코드는 **raw 데이터 버퍼 → 라이브러리 호출(특징 추출+추론 자동) → 확률 배열 → 최댓값/임계값 판정**으로 요약된다.
- 실시간성을 지키려면 **샘플링(인터럽트/RTOS/DMA)과 추론을 분리**해서, 추론이 도는 동안에도 다음 데이터 수집이 끊기지 않게 설계해야 한다.
