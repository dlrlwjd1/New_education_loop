# How to Evaluate a Model

## 개요

**정확도(accuracy)만으로는 모델 성능을 제대로 평가할 수 없다.** 혼동 행렬(confusion matrix)을 기반으로 정확도·재현율(recall)·특이도(specificity)·정밀도(precision)·F1 점수를 계산하는 법과, 나이브 분류기를 정확도만으로는 못 잡아내는 이유를 실제 숫자로 보여준다.

## 내용

### 혼동 행렬(Confusion Matrix) 만드는 법

- 실제 정답(ground truth) 라벨이 있는 세트(학습/검증/테스트)에서만 계산할 수 있다.
- 행 = 실제 라벨, 열 = 예측 라벨. 샘플 하나씩 예측해서 해당 (실제, 예측) 칸에 1씩 더해간다.
- 모든 칸의 합 = 전체 샘플 수.
- 예: 1,000개 검증 샘플의 혼동 행렬을 보면, `left-right`는 잘 구분하지만 다른 클래스들이 `up-down`으로, 또는 `up-down`이 `circle`로 잘못 분류되는 경향이 바로 눈에 보인다 — **데이터 품질, 특징의 분리력, 모델 구조** 중 어디를 고쳐야 할지 힌트를 준다.

### 전체 정확도(Accuracy)의 함정

- 계산: (맞춘 예측 수) ÷ (전체 샘플 수). 예: 813/1000 = **81.3%**.
- 개념은 쉽지만 **불균형 데이터셋에서는 크게 오해를 부른다.**
- **나이브 분류기 예시**: 뭐든 항상 `idle`이라고만 예측하는 모델인데, 검증 세트가 97%가 idle이면 → **정확도 97%**가 나온다. 숫자만 보면 훌륭하지만, 실제로는 아무것도 분류하지 못하는 쓸모없는 모델이다.
- **혼동 행렬 자체가 나이브 분류기를 잡아내는 도구다** — 예측이 전부 한 클래스로만 쏠려 있으면 나이브 분류기를 의심해야 한다.

### 이진 분류 기준 용어 (의료 진단 비유)

| 용어 | 뜻 | 별칭 |
|---|---|---|
| **True Positive(TP)** | 양성을 양성으로 맞게 예측 | — |
| **True Negative(TN)** | 음성을 음성으로 맞게 예측 | — |
| **False Positive(FP)** | 음성인데 양성으로 잘못 예측 | **1종 오류(Type I error)** |
| **False Negative(FN)** | 양성인데 음성으로 잘못 예측 | **2종 오류(Type II error)** |

### 다중 클래스로 확장하기

- 클래스가 3개 이상이면, **한 클래스를 "양성", 나머지 전부를 "음성"으로 취급**해서 클래스별로 따로 TP/TN/FP/FN을 계산한다.
- 예: `idle`을 양성으로 두면 — TP는 idle을 idle로 맞춘 것, FP는 idle이 아닌데 idle로 예측한 합, FN은 idle인데 다른 걸로 예측한 합, 나머지는 전부 TN.

### 핵심 평가 지표

| 지표 | 계산식 | 별칭 | 의미 |
|---|---|---|---|
| **클래스별 정확도** | (TP+TN) / 전체 | — | 그 클래스를 양성으로 볼 때의 정확도 (예시: idle 기준 92.7%) |
| **True Positive Rate** | TP / (TP+FN) | **민감도(sensitivity), 재현율(recall), hit rate** | 실제 양성 중 몇 %를 잡아냈는가 (예시: 약 84%) |
| **True Negative Rate** | TN / (TN+FP) | **특이도(specificity), selectivity** | 실제 음성 중 몇 %를 정확히 걸러냈는가 (예시: idle 기준 95.4%) |
| **Precision(정밀도)** | TP / (TP+FP) | **양성 예측도(PPV)** | "양성"이라고 예측한 것 중 실제로 맞은 비율 (예시: 약 85%) |
| **F1 score** | Precision과 Recall의 조화평균 | — | 0~1 사이 값, **불균형 데이터셋**에서 정확도 대신 쓰기 좋음 (예시: idle 기준 약 0.845) |

- Recall(재현율)은 정보검색 분야 용어이고, Precision(정밀도)도 마찬가지다 — "검색 결과 중 관련 있는 것의 비율"이라는 원래 맥락에서 온 이름들.

### F1 점수가 나이브 분류기를 어떻게 잡아내는가

- 위의 나이브 분류기(정확도 97.3%, 클래스별 정확도도 그럴듯해 보임)를 F1 점수로 보면: **idle을 제외한 모든 클래스의 F1 점수가 0**(Precision·Recall이 둘 다 0이기 때문)이다.
- 클래스별 F1을 평균 내면 전체 정확도보다 훨씬 낮게 나와, **정확도로는 숨겨졌던 나이브 분류기 문제를 F1 점수가 드러낸다.**
- F1은 **Precision과 Recall에 동일한 가중치**를 준다 — 둘 중 하나가 더 중요하다면 다른 지표/가중치 방식을 찾아야 한다.

### 상황에 따라 다른 지표를 우선해야 한다

- 예: X-ray로 암을 탐지하는 모델이라면, **False Positive(과잉 진단)는 어느 정도 감수해도, False Negative(암을 놓치는 것)는 절대 피해야 한다** — 이런 경우 **민감도(sensitivity)** 에 더 큰 가중치를 두거나 다른 지표 체계를 써야 한다. 정확도나 F1만으로는 부족할 수 있다.

## 예시

97.3%라는 높은 정확도 숫자만 보고 모델을 채택했다가, F1 점수를 확인하고서야 "사실 아무것도 분류 못 하는 모델"이었다는 걸 깨닫는 상황 — 이 강의가 실제 수치로 정확히 재현해서 보여준다.

## 요약

- **정확도 하나만으로 모델을 판단하지 않는다** — 특히 클래스 불균형이 있을 때는 위험하다.
- 혼동 행렬에서 TP/TN/FP/FN을 뽑아 **Recall(민감도)·Precision(정밀도)·Specificity(특이도)·F1 점수**를 계산해 다각도로 본다.
- F1 점수는 나이브 분류기처럼 정확도가 숨기는 문제를 드러내는 데 특히 유용하다.
- 응용에 따라(예: 암 진단) 어떤 지표를 우선할지가 달라진다 — 지표 선택 자체가 도메인 판단의 일부다.
