# 18 Reading: Typography on the Web (읽기자료)

## 개요
- 웹의 HTML·CSS가 타이포그래피 논리에서 얼마나 많은 것을 물려받았는지, 그리고 화면 타이포그래피의 특수성(픽셀 단위, 반응형 디자인, 폰트 라이선싱)을 다루는 2분 36초 분량 읽기자료(비디오 형식)

## 내용

### 인터넷은 대부분 텍스트다
- 인터넷은 대부분 텍스트로 구성되어 있음 — 그래서 웹사이트가 구축되는 방식과 이를 만드는 코딩 언어가 타이포그래피의 논리에서 많은 DNA를 물려받은 것은 놀랍지 않음

### HTML, CSS와 타이포그래피
- 타이포그래피는 의미론적으로(텍스트의 의미와 구조를 명료화) 그리고 시각적으로(톤과 연상을 통해 추가적인 의미 층위를 전달) 둘 다 기능한다고 논의했음
- 코드의 구조가 이 이중 기능을 공식화함: **HTML**은 텍스트가 어떻게 구조화되고 읽혀야 하는지에 대한 지침을 주석으로 달고, **CSS**는 그것이 시각적으로 어떻게 스타일링되는지를 결정
- 지난 몇 강의에서 다룬 대부분의 타이포그래피 변수에 대응하는 CSS 속성이 있음 — 타입 크기("font-size")부터 리딩("line-height"), 행 길이("width")까지. 리게처부터 각종 대시, 수평 공간까지 거의 모든 특수 문자에 대응하는 HTML 코드도 있음 — 이 모든 속성과 이름은 W3 Schools 등 여러 온라인 자료에서 찾을 수 있음

### 웹에서의 타이포그래피 공간
- 웹에서 타입 크기와 리딩은 픽셀 단위로 측정되며, 픽셀 크기와 인쇄 크기 사이에는 절대적인 관계가 없음
- 화면 텍스트 크기에 관한 관습은 인쇄보다 훨씬 느슨함 — 웹 텍스트는 약 15px부터 24px를 훌쩍 넘는 크기까지 다양할 수 있음
- 웹에서 타입 크기에 대한 감각을 얻는 가장 좋은 방법은 좋아하는 웹사이트들의 타이포그래피를 비교해보는 것(브라우저의 코드 인스펙터로 타이포그래피 속성을 확인할 수 있음)
- 기기마다 화면 크기와 방향이 다르기 때문에, 타입 크기와 너비는 그 맥락에 맞게 유연해야 함 — 이 개념을 **반응형 디자인(responsive design)**이라 부름
- 반응형으로 디자인하면 타이포그래피에 대한 통제력이 다소 줄어들지만, 퍼센트·최대/최소 너비·하이픈네이션 규칙을 신중하게 사용하면 다양한 화면 크기에서도 타이포그래피가 보기 좋게 유지되도록 할 수 있음

### 웹에서의 폰트
- 웹사이트와 관련된 자산(asset)은 원칙적으로 공개되어 있음 — 이미지나 다른 자산처럼 폰트를 웹사이트 서버에 업로드하면, 그 폰트 파일은 브라우저를 가진 누구에게나 '도난'당할 수 있음
- 이런 이유로 웹에서 타입을 사용할 때의 모범 사례는, Google Fonts 같은 무료 서비스나 Adobe Fonts·Fontstand 같은 유료 서비스가 안전하게 호스팅하는 폰트 파일을 링크하는 것

## 요약
- HTML은 텍스트의 구조를, CSS는 시각적 스타일을 담당하며 이는 타이포그래피의 의미론적/시각적 이중 기능을 코드로 공식화한 것
- 웹 타이포그래피는 픽셀 단위(15~24px+)로 측정되고 인쇄와 절대적 관계가 없으며, 다양한 화면 크기에 대응하는 반응형 디자인이 요구됨
- 폰트 파일은 도난 위험이 있으므로 Google Fonts·Adobe Fonts·Fontstand 등 안전한 호스팅 서비스를 링크해 사용하는 것이 모범 사례
