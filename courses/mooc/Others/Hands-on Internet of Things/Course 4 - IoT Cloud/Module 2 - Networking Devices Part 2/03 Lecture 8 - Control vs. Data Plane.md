# Lecture 8 -  Control vs. Data Plane

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-cloud/lecture/ySG9p/lecture-8-control-vs-data-plane)

## 개요
- 그래서 우리가 하는 일은 이러한 라우팅 프로토콜을 실행하고 RIB를 계산하고 RIB에는 많은 경로가 들어 있습니다.

## 내용
- 그래서 우리가 하는 일은 이러한 라우팅 프로토콜을 실행하고 RIB를 계산하고 RIB에는 많은 경로가 들어 있습니다.
- 컨트롤 플레인에서는 라우팅 알림을 실행하고, 라우팅 프로토콜을 실행하고, 라우팅 업데이트, 접두사에 도달하는 방법에 대한 정보를 배포합니다.
- 따라서 필요한 정보만 데이터 플레인에 게시하면 컨트롤 플레인으로 이동하지 않고도 데이터 패킷을 빠르게 전달하고 전송할 수 있습니다.
- 하드웨어에서 물리적으로 구현되는 방식을 보면 다음과 같습니다.서로 다른 포트가 있는 서로 다른 라인 카드가 모두 있고 그 사이에 스위칭 패브릭이 있습니다.
- 라우트 프로세서는 거기에 위치하여 라우팅 프로토콜을 실행하고 리브를 계산한 다음 스위칭 패브릭에 정보를 게시합니다.
- 통과해야 하는 방화벽 규칙이 많으면 어떻게 하면 패킷 전달 속도가 느려지나요?” 이제 이러한 함수가 어디에서 구현되는지 생각해 볼 수 있기 때문에 이 질문에 답할 수 있습니다.
- 따라서 패킷을 받아들이고, 검색을 수행할 수 있을 만큼 IP 프로토콜을 잘 알고, 아웃바운드 포트를 결정한 다음 이를 스위칭 패브릭으로 전환하여 해당 작업을 실제로 수행할 수 있게 됩니다.

## 예시
- 따라서 패킷을 받아들이고, 검색을 수행할 수 있을 만큼 IP 프로토콜을 잘 알고, 아웃바운드 포트를 결정한 다음 이를 스위칭 패브릭으로 전환하여 해당 작업을 실제로 수행할 수 있게 됩니다.

## 요약
- 통과해야 하는 방화벽 규칙이 많으면 어떻게 하면 패킷 전달 속도가 느려지나요?” 이제 이러한 함수가 어디에서 구현되는지 생각해 볼 수 있기 때문에 이 질문에 답할 수 있습니다. 따라서 패킷을 받아들이고, 검색을 수행할 수 있을 만큼 IP 프로토콜을 잘 알고, 아웃바운드 포트를 결정한 다음 이를 스위칭 패브릭으로 전환하여 해당 작업을 실제로 수행할 수 있게 됩니다.
