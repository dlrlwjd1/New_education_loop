# Lecture 2 - How Can Many Hosts Communicate

## 개요
- 저랑 4.16.5.1 같은 주소가 연결되어 있어요.”문제는 모든 라우터가 연결된 모든 IP 주소를 광고하는 것은 그리 확장성이 높지 않다는 것입니다.

## 내용
- 저랑 4.16.5.1 같은 주소가 연결되어 있어요.”문제는 모든 라우터가 연결된 모든 IP 주소를 광고하는 것은 그리 확장성이 높지 않다는 것입니다.
- 따라서 라우터가 하는 일은 접두사에 대한 정보를 광고하는 것입니다.이를 통해 다이어그램을 더 명확하게 만들 수 있다는 점을 분명히 말씀드리죠.
- 그러면 라우터 D가 할 일은 분산 프로토콜을 사용하여 해당 접두사에 대한 정보를 퍼뜨리는 것입니다.
- 따라서 시간이 흐르면서 라우터는 이 정보를 축적하고 테이블을 만들어 서로 다른 접두사가 있는 위치를 기억하고 해당 접두사로 패킷을 전달할 수 있게 됩니다.
- DNS가 작동하는 방식은 다양한 수준의 이름을 관리할 수 있는 네임 서버와 DNS의 진입점 역할을 하는 로컬 DNS 서버가 곳곳에 분산되어 있다는 것입니다.
- 그러면 DNS 서버가 매핑을 알고 있으면 다시 응답하여 매핑을 보내게 됩니다.수신자가 수신하지 않으면 로버츠의 요청을 YouTube.com으로 전달합니다.
- 따라서 이는 반복적인 프로세스이며, 결국 로버트의 컴퓨터는 도달하고자 하는 DNS 이름의 신뢰할 수 있는 네임서버를 발견하고, 로버트에게 IP 주소를 반환하고, 로버트의 컴퓨터가 YouTube.com에 요청을 보내면 문제가 해결됩니다.

## 예시
- 예를 들어 접두사 4.0.0.0/8은 4로 시작하는 모든 주소를 의미하고, 슬래시 8은 처음 8비트가 중요하며, 나머지 24비트는 와일드카드입니다.

## 요약
- 그러면 DNS 서버가 매핑을 알고 있으면 다시 응답하여 매핑을 보내게 됩니다.수신자가 수신하지 않으면 로버츠의 요청을 YouTube.com으로 전달합니다. 따라서 이는 반복적인 프로세스이며, 결국 로버트의 컴퓨터는 도달하고자 하는 DNS 이름의 신뢰할 수 있는 네임서버를 발견하고, 로버트에게 IP 주소를 반환하고, 로버트의 컴퓨터가 YouTube.com에 요청을 보내면 문제가 해결됩니다.
