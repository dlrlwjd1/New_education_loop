# Lecture 6 -  Addressing Layers

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-devices-il/lecture/nC8sL/lecture-6-addressing-layers)

## 개요
- 따라서 인터넷상의 목적지로 이동하려는 경우 브라우저를 열고 주소를 입력할 수 있습니다.

## 내용
- 따라서 인터넷상의 목적지로 이동하려는 경우 브라우저를 열고 주소를 입력할 수 있습니다.
- 따라서 도메인 이름은 Illinois.edu와 같은 단일 관리 제어 하에 있는 컴퓨터 그룹을 식별합니다.
- 또한 도메인 이름 내의 특정 컴퓨터 또는 도메인 이름 내의 특정 컴퓨터 그룹인 호스트 이름이기도 합니다.
- 따라서 목적지로 패킷을 보내는 경우 해당 대상에서 실제로 어떤 응용 프로그램이 실행되고 있는지 명확하지 않습니다.
- 네트워크 코어 상위권을 많이 차지하는 운영자가 수동으로 구성할 수 있으며 DHCP를 통해 할당할 수도 있고, IoT 프로토콜을 실행 중인 경우 해당 프로토콜로 할당할 수도 있습니다.
- 예를 들어, 회사에서 특정 무선 네트워크를 사용하는 경우 특정 IP 주소를 사용하게 되지만 랩톱을 분리하고 집에 가서 플러그인을 하면 IP 주소는 변경되지만 MAC 주소는 변경되지 않습니다.
- 이러한 다양한 주소가 존재하는 이유, 사용 위치, 주소를 효율적으로 할당하고 효율적으로 사용하는 프로토콜을 작성하는 방법에 대해 어느 정도 이해하게 될 것입니다.

## 예시
- 예를 들어 애플리케이션 계층에서는 URL, 즉 유니폼 리소스 로케이터라는 것을 사용합니다.

## 요약
- 예를 들어, 회사에서 특정 무선 네트워크를 사용하는 경우 특정 IP 주소를 사용하게 되지만 랩톱을 분리하고 집에 가서 플러그인을 하면 IP 주소는 변경되지만 MAC 주소는 변경되지 않습니다. 이러한 다양한 주소가 존재하는 이유, 사용 위치, 주소를 효율적으로 할당하고 효율적으로 사용하는 프로토콜을 작성하는 방법에 대해 어느 정도 이해하게 될 것입니다.
