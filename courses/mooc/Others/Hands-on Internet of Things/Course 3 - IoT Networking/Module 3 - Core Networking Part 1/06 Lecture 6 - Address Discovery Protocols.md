# Lecture 6 -  Address Discovery Protocols

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-networking/lecture/5OxZK/lecture-6-address-discovery-protocols)

## 개요
- 따라서 주소 하나를 알고 있는 경우 해당 주소 세트를 찾아보면 실제로 목적지에 도달하도록 패킷을 구성하는 데 도움이 됩니다.

## 내용
- 따라서 주소 하나를 알고 있는 경우 해당 주소 세트를 찾아보면 실제로 목적지에 도달하도록 패킷을 구성하는 데 도움이 됩니다.
- 목적지로 패킷을 전송하려면 몇 가지 추가 주소 정보를 찾아야 하는데, 이는 서로 다른 계층에서 이러한 모든 주소를 입력해야 하기 때문입니다.
- 다음 MAC 주소는 로컬 서브넷상의 목적지인지, 아니면 퍼블릭 인터넷에 알려진 로컬 서브넷으로 패킷을 전송하는 데 사용되는 특수 라우터인 기본 게이트웨이인지 알려줘야 합니다.
- 따라서 목적지가 로컬인 경우 다음 홉의 MAC 주소가 대상 MAC 주소가 되고, 목적지가 로컬이 아닌 경우 First-Hop 라우터의 MAC 주소가 됩니다.
- 웹 페이지에 갈 때마다 cnn.com을 입력할 수 없고, 나가서 어떤 IP 주소인지 알아내고, 네트워크 사업자에게 연락하여 전화로 전화를 걸어 “ 네트워크에서 내리려면 First-hop MAC 주소가 무엇입니까?” 라고 물어봐야 한다면 얼마나 고통스러울지 상상해 보십시오.상황이 바뀔 때마다 이를 기록해 두어야 하기 때문에 골치 아픈 일이 될 것입니다.
- 따라서 IP 주소를 얻었더라도 해당 주소로 보내는 방법을 아직 모르는 경우 해당 주소를 MAC 주소가 필요하기 때문에 ARP에서 알아서 처리해 줍니다.
- 제가 여기에 질문을 쓴 것을 보면 “이봐, 누가 이 IP 주소를 가지고 있니?” 라고 묻는 것을 알 수 있습니다.“안녕하세요, 누군가 제게 IP 주소를 알려주실 수 있나요?” LAN에서 실행되기 때문에 브로드캐스트를 사용하여 이러한 질문에 답할 수 있습니다.
