# Lecture 1 -  Encapsulation

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-networking/lecture/z0d3s/lecture-1-encapsulation)

## 개요
- 이 모든 것은 데이터를 네트워크로 전송하려는 경우 데이터를 가져다가 패킷이라는 조각으로 쪼개는 손실이 발생한다는 생각에 기반을 두고 있습니다.

## 내용
- 이 모든 것은 데이터를 네트워크로 전송하려는 경우 데이터를 가져다가 패킷이라는 조각으로 쪼개는 손실이 발생한다는 생각에 기반을 두고 있습니다.
- 데이터를 전달하는 방법을 알아야 하는 중간 장치가 많이 있기 때문입니다.데이터를 처리하는 방법, 데이터에 제공할 품질 서비스, 이런 것들이요.
- 운영 체제 내에서, 즉 커널 내에서 이것이 작동하는 방식은 응용 프로그램이 TCP를 수행하는 코드가 있는 커널의 TCP 부분에 시스템 호출을 하고, 이 부분이 데이터를 래핑하고, TCP 세그먼트는 이를 IP 계층으로 전달하고, IP 세그먼트는 이를 이더넷 계층 , 장치 드라이버, 이더넷 프레임을 캡슐화하는 Nick으로 전달합니다.
- 그런 다음 데이터 패킷을 전달하면 패킷이 나가서 각 전달 장치, 라우터, 스위치, 블루투스 노드, 프록시, 각 노드가 이 데이터를 확인한 다음 헤더를 기반으로 어떤 작업을 할지 결정합니다.
- 스위치가 있는데 계층 3 또는 계층 4 스위치 또는 계층 4 로드 밸런서, 계층 7 방화벽 등에서 전달하고 있습니다.
- 그들은 네트워크에 장치가 있는 경우 장치가 패킷에 포함된 데이터에 구애받지 않아야 한다고 생각합니다.이더넷 데이터만을 기반으로 하는 이더넷 스위치가 있다면 IP 패킷이나 TCP 세그먼트 또는 애플리케이션 계층을 들여다볼 필요가 없습니다.따라서 작업이 더 복잡해집니다.
- 제가 ISP로서 데이터 트래픽을 전달하고 저는 데이터 트래픽을 전송하고 구글은 저를 통해 많은 트래픽을 전송합니다.

## 예시
- 예를 들어, 제가 아마존이고 사용자가 쇼핑 카드에 데이터를 저장하고 있다면 거대한 서버 구조의 로드 밸런싱을 하고 싶습니다.

## 요약
- 그들은 네트워크에 장치가 있는 경우 장치가 패킷에 포함된 데이터에 구애받지 않아야 한다고 생각합니다.이더넷 데이터만을 기반으로 하는 이더넷 스위치가 있다면 IP 패킷이나 TCP 세그먼트 또는 애플리케이션 계층을 들여다볼 필요가 없습니다.따라서 작업이 더 복잡해집니다. 제가 ISP로서 데이터 트래픽을 전달하고 저는 데이터 트래픽을 전송하고 구글은 저를 통해 많은 트래픽을 전송합니다.
