# Lecture 7 -  Dynamic Host Configuration Protocol

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-networking/lecture/RX5B6/lecture-7-dynamic-host-configuration-protocol)

## 개요
- 해당 호스트에 IP 주소를 제공해야 할 수도 있습니다.DNS 서버가 누구인지, DNS 서버가 어디로 가는지, 호스트를 다른 곳으로 지정하고 싶을 수도 있습니다.

## 내용
- 해당 호스트에 IP 주소를 제공해야 할 수도 있습니다.DNS 서버가 누구인지, DNS 서버가 어디로 가는지, 호스트를 다른 곳으로 지정하고 싶을 수도 있습니다.
- 따라서 이 정보는 호스트에 캐시되며 리스 기간이 만료된 후에는 유효하지 않은 것으로 간주되며, 이때 삭제되며, 필요에 따라 업데이트된 정보를 요청해 받을 수도 있습니다.이 정보를 찾아보면 이 모든 정보가 RFC에 정의되어 있습니다.
- 그래서 클라이언트가 하는 일은 네트워크에 처음 연결할 때 제가 새 네트워크에 연결되어 있고 이 네트워크에서 통신하려면 IP 주소가 필요하다는 것을 깨닫게 되는 것입니다.
- DHCP 프로토콜은 실제로 네트워크에 여러 서버가 존재할 수 있도록 허용하므로 실제로 여러 개의 오퍼를 받을 수도 있지만 괜찮습니다.
- 그러면 그 자리에 앉아서 하나 이상의 제안을 받게 됩니다.둘 중 하나를 고를 거예요.해당 주소의 사용을 요청하는 다른 메시지를 보내게 됩니다.
- 해당 DHCP 서버가 해당 주소를 수신하면 “좋아요, 그 주소를 사용해도 됩니다.” 라는 또 다른 메시지를 보냅니다.
- DHCP 서버로 다시 메시지를 보내 “그 주소를 공개하겠습니다.” 서버는 이 주소를 수신하고 사용 가능한 풀에 주소를 반환합니다.

## 예시
- 예를 들어 랩톱이나 IoT 장치 같은 클라이언트가 네트워크에서 연결 정보를 얻으려 한다고 가정해 보겠습니다.

## 요약
- 해당 DHCP 서버가 해당 주소를 수신하면 “좋아요, 그 주소를 사용해도 됩니다.” 라는 또 다른 메시지를 보냅니다. DHCP 서버로 다시 메시지를 보내 “그 주소를 공개하겠습니다.” 서버는 이 주소를 수신하고 사용 가능한 풀에 주소를 반환합니다.
