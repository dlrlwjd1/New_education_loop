# Lecture 12 -  Packet Forwarding

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-networking/lecture/rUgUA/lecture-12-packet-forwarding)

## 개요
- 따라서 장치가 있고 인터넷상의 다른 장치로 패킷을 보내려는 경우 (예: 랩톱에서 서버로 데이터를 보내는 경우).

## 내용
- 따라서 장치가 있고 인터넷상의 다른 장치로 패킷을 보내려는 경우 (예: 랩톱에서 서버로 데이터를 보내는 경우).
- 웹 트래픽을 보내는 경우 웹 요청을 생성하고 이를 레이어 3 IP 패킷에 캡슐화한 다음 레이어 2 패킷에 넣을 것입니다.
- 글쎄요, 이것은 정적으로 구성된 것이거나 DHCP를 통해 학습한 것일 수도 있습니다.어떤 이유에서든 확인을 수행할 수 있는 자체 로컬 DNS 서버를 알고 있습니다.
- 우리는 인터넷 반대편에 있는 서버의 IP 주소를 알고 있으며 로컬 서브넷에서 벗어나는 데 사용할 수 있는 다음 Layer 2 홉도 알고 있습니다.
- 따라서 여러 개의 접두사가 있는 경우 가장 긴 접두사, 즉 접두사에 따라 가장 많은 비트가 있는 접두사를 사용합니다.
- 그래서 이 라우터가 할 일은 직접 연결된 서브넷에 있는 서버의 IP 주소에 대한 ARP 요청을 보내는 것입니다.
- 그런 다음 패킷을 전송할 때 MAC 주소를 찾기 위해 실제로 데이터를 전송할 때 이 모든 작업을 다시 반복하게 됩니다.

## 예시
- 그런 다음 패킷을 전송할 때 MAC 주소를 찾기 위해 실제로 데이터를 전송할 때 이 모든 작업을 다시 반복하게 됩니다.

## 요약
- 그래서 이 라우터가 할 일은 직접 연결된 서브넷에 있는 서버의 IP 주소에 대한 ARP 요청을 보내는 것입니다. 그런 다음 패킷을 전송할 때 MAC 주소를 찾기 위해 실제로 데이터를 전송할 때 이 모든 작업을 다시 반복하게 됩니다.
