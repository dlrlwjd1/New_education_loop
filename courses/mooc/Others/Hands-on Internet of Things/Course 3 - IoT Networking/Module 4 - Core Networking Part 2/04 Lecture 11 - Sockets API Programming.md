# Lecture 11 -  Sockets API Programming

> MOOC video · [원본 학습 항목](https://www.mooc.org/learn/iot-networking/lecture/ghPuy/lecture-11-sockets-api-programming)

## 개요
- 이제 네트워크 프로그래밍에 대해 좀 더 자세히 설명하고 네트워크 애플리케이션을 작성하는 데 사용하는 이러한 특정 API에 대해 살펴보겠습니다.

## 내용
- 이제 네트워크 프로그래밍에 대해 좀 더 자세히 설명하고 네트워크 애플리케이션을 작성하는 데 사용하는 이러한 특정 API에 대해 살펴보겠습니다.
- 따라서 Sockets API의 기본 개념은 이러한 연결에 핸들이 들어 있고 핸들 위에서 핸들과 데이터를 참조할 수 있는 연결을 만드는 것입니다.
- TCP, UDP 또는 SCTP 또는 기타 전송을 수행하려는 경우 Sockets API가 모든 것을 추상화하므로 메커니즘의 모든 세부 사항에 대해 걱정할 필요가 없습니다.
- 이것이 커널의 전체 구조입니다.응용 프로그램이 있는데 라이브러리를 호출하는 애플리케이션은 커널 내에서 시스템 호출을 호출하고, 그 아래의 모든 것은 커널 내에서 호출합니다.
- 예를 들어 TCP의 경우 TCP는 시간이 지나도 지속되는 연결을 설정하는 데 있어 안정성이 가장 중요하며, Socket API에는 이를 위한 함수가 있습니다.소켓 번호를 유지하고, 소켓 번호를 네트워크 주소와 연결하고, 연결을 설정하는 함수가 있습니다.
- “이봐, 테이블이 있잖아, 열려 있는 소켓을 실행했니?제가 사용할 수 있는 미사용 소켓 디스크립터 하나 주세요.” 알겠네요.다음으로 할 일은 연결하려는 호스트에 대한 정보를 저장하는 주소 구조를 만들고 알고 있는 내용을 입력하는 것입니다.
- 이 소켓 설명자를 사용하여 다른 호스트에 대한 논리적 연결을 열고 싶습니다.” 라고 명령한 다음 연결을 만들고 열린 상태로 두면 연결됩니다.

## 예시
- 예를 들어 TCP의 경우 TCP는 시간이 지나도 지속되는 연결을 설정하는 데 있어 안정성이 가장 중요하며, Socket API에는 이를 위한 함수가 있습니다.소켓 번호를 유지하고, 소켓 번호를 네트워크 주소와 연결하고, 연결을 설정하는 함수가 있습니다.
