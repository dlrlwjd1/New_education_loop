## 개요
- 어떤 노드가 다른 노드와 같은 주소를 선택하는데, 예를 들어 제 노드가 들어와서 네트워크에 연결되면 어떤 주소를 사용해야 할까요?

## 내용
- 어떤 노드가 다른 노드와 같은 주소를 선택하는데, 예를 들어 제 노드가 들어와서 네트워크에 연결되면 어떤 주소를 사용해야 할까요?
- 다른 노드들도 모두 있는데 데이터를 137개로 돌았는데 어느 노드에 데이터를 보내는지 137개 중 하위 노드로 데이터를 보내는 것은 잘못된 것일 수 있습니다.
- 따라서 확률적 주소 지정의 경우 고유한 주소를 선택하도록 하는 프로토콜이 있는데, 이 프로토콜은 이 프로토콜 위에 겹쳐질 수 있는데, 복잡성이 증가하기 때문에 약간 불편합니다.
- 예를 들어 데이터를 여러 노드에 저장하고 싶은데 데이터를 완벽하게 안정적으로 저장할 필요가 없기 때문에 여러 개의 복사본을 보유해도 괜찮을 수도 있고 데이터의 사본을 여러 개 저장해도 괜찮을 수도 있습니다.
- 따라서 노드에 가입하면 해당 주소가 넘쳐나고, 그러면 해당 주소에 문제가 있는 모든 노드가 문제를 제기하여 충돌이 있음을 알릴 수 있습니다.
- 예를 들어, 새 노드가 가입하면 137을 선택한 다음 해당 주소를 브로드캐스트합니다.그러면 , 137을 사용하는 네트워크에 있는 모든 사람이 이 메시지를 브로드캐스트하고 네트워크를 통해 넘쳐나갑니다.
- 이러한 주소 지정 메커니즘은 다른 노드를 식별하는 방법을 정의하고 모든 것이 이를 기반으로 구축되기 때문에 IoT에서 매우 중요합니다.
