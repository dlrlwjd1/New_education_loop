# Stack in CloudFormation

## 개요
- CloudFormation 스택(Stack)의 정의, 목적, 주요 기능, 템플릿 예시(YAML vs JSON)를 정리.

## 내용
### 스택이란
- 하나의 단위로 관리되는 AWS 리소스의 모음. 스택 내 모든 리소스는 CloudFormation 템플릿을 기반으로 함께 생성·업데이트·삭제됨.
- 목적: 리소스 생성·업데이트·삭제를 조율(coordinated)된 방식으로 자동화해 인프라 라이프사이클을 관리하고, 매번 동일한 설정을 적용해 일관성을 보장 — 수작업과 설정 오류를 줄임.
- 예: VPC, Subnet 2개, EC2 인스턴스, S3 버킷을 배포하는 스택을 생성하면 이 리소스들이 함께 생성되고, 템플릿을 업데이트하면 변경된 리소스만 업데이트되며, 스택을 삭제하면 모든 리소스가 자동으로 제거됨.

### 스택의 주요 기능
1. **단일 단위 관리(Single Unit Management)** — 스택 내 모든 리소스를 하나의 단위로 관리.
2. **템플릿 기반(Template Driven)** — YAML/JSON 템플릿으로 리소스를 정의하며, 이 템플릿이 곧 source of truth.
3. **자동화된 리소스 프로비저닝** — 수동 단계 없이 리소스를 자동으로 생성·설정.
4. **변경 관리(Change Management)** — 템플릿에서 변경된 부분을 먼저 감지한 뒤, 실제로 필요한 변경 사항만 클라우드에 적용.
5. **중첩 스택(Nested Stacks)** — 큰 템플릿을 재사용 가능한 작은 모듈로 분리하는 모듈형 설계를 지원.

### 템플릿 예시 구조 (S3 버킷 + EC2 인스턴스)
- **YAML**: Format Version과 Description을 적고 그 아래 Resources 블록에 두 리소스를 정의. 중괄호·쉼표가 없어 더 간결.
- **JSON**: Version과 Description을 정의하고 Resources 블록 안에 여러 리소스를 정의. 문법이 더 엄격하고 구조화되어 있어 템플릿을 자동 생성하는 도구들이 주로 사용 — 따옴표나 쉼표 하나만 빠져도 오류 발생.
- **생성(create)**: 두 리소스가 함께 프로비저닝됨.
- **업데이트(update)**: 예를 들어 EC2 인스턴스만 수정하면 해당 리소스만 업데이트됨.
- **삭제(delete)**: 두 리소스가 모두 삭제됨.

## 요약
- CloudFormation 스택은 템플릿에 정의된 리소스들을 하나의 단위로 묶어 생성·업데이트·삭제를 자동화·조율하며, 변경 감지를 통해 필요한 부분만 업데이트하고 Nested Stacks로 큰 템플릿을 재사용 가능한 모듈로 나눌 수 있다.
