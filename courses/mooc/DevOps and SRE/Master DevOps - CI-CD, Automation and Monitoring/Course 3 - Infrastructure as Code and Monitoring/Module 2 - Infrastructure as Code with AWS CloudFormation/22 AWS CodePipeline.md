# AWS CodePipeline

## 개요
- AWS의 완전관리형 CI/CD 서비스인 CodePipeline의 정의, 주요 기능, 그리고 개발부터 피드백까지 이어지는 릴리스 프로세스를 정리.

## 내용
### AWS CodePipeline이란
- 애플리케이션과 인프라 업데이트를 빠르고 안정적으로 릴리스할 수 있도록 릴리스 파이프라인을 자동화하는 **완전관리형 지속적 배포(Continuous Delivery) 서비스**.
- Jenkins, GitLab CI 등 다른 CI 도구처럼 파이프라인을 만들어 소프트웨어와 인프라를 배포할 수 있으며, 릴리스에 필요한 단계를 모델링·시각화·자동화.

### CodePipeline으로 할 수 있는 것
1. **릴리스 프로세스 자동화** — 코드 커밋 시 빌드·배포가 자동으로 트리거되도록 구성. 비프로덕션 환경에는 자동 배포되지만, 프로덕션 환경은 보통 승인(Approval) 단계가 필요.
2. **일관된 릴리스 워크플로우 확립** — 자동 커밋·트리거 덕분에 배포된 코드가 항상 최신 상태와 동기화되며, 비프로덕션에서 충분히 테스트된 뒤 프로덕션에 배포되므로 일관성 확보.
3. **딜리버리 속도 향상과 품질 개선** — 빌드·배포가 자동화되어 수동 배포보다 개발자가 코드/애플리케이션 품질과 기능 개선에 집중 가능.
4. **파이프라인 진행 시각화** — 차트와 플로우 다이어그램으로 파이프라인 진행 상황을 쉽게 파악.
5. **파이프라인 이력(History) 확인** — 파이프라인이 언제 성공적으로 배포됐는지, 실패가 몇 번 있었는지 등의 이력을 조회 가능.

### 릴리스 프로세스 흐름
1. **개발(Develop)** — 개발자가 코드에 변경·업데이트·수정을 가함.
2. **소스 커밋(Source)** — 변경 사항을 소스 코드 저장소에 커밋.
3. **빌드(Build)** — 변경 사항이 자동으로 빌드됨(예: Java 애플리케이션이면 Maven 같은 빌드 도구 사용).
4. **스테이징 배포 및 테스트(Staging)** — 코드를 스테이징 환경에 배포해 테스터가 검증하며, 자동화된 테스트 케이스도 함께 실행.
5. **수동 승인(Manual Approval)** — 승인을 거쳐 프로덕션에 배포.
6. **피드백(Feedback)** — 프로덕션에 배포된 후 사용자·비즈니스 담당자·고객이 기능의 정상 동작 여부에 대한 피드백 제공, 신규 기능 요청이나 버그 리포트도 이 단계에서 발생.
7. **지속적 피드백(Continuous Feedback)** — 피드백과 버그가 개발자에게 다시 전달되어 개발자가 다시 변경·수정을 진행 — 이 사이클이 추가 개발이 필요 없을 때까지 반복.

## 요약
- AWS CodePipeline은 소스 커밋 → 빌드 → 스테이징 테스트 → 수동 승인 → 프로덕션 배포 → 사용자 피드백 → 재개발로 이어지는 릴리스 프로세스를 자동화·시각화하는 완전관리형 CI/CD 서비스로, 비프로덕션 환경은 자동 배포하되 프로덕션 배포에는 승인 단계를 둬 속도와 안정성을 동시에 확보한다.
