# Scenario - Trade Desk's Monitoring Issues

## 개요
- 디지털 광고 플랫폼 기업 Trade Desk가 하이브리드 인프라(물리 데이터센터 + 클라우드)의 모니터링 문제를 Prometheus·Grafana로 해결한 실제 사례.

## 내용
### Trade Desk 소개
- 디지털 광고용 소프트웨어 플랫폼을 제공하는 회사 — 2009년 설립, 직원 약 3,100명, 시가총액 약 591.21억 달러.
- 물리 데이터센터와 클라우드를 함께 사용하는 대규모 하이브리드 운영 체제.
- 광고 구매자가 여러 채널에 걸쳐 디지털 캠페인을 관리할 수 있게 해주는 **DSP(Demand-Side Platform)** 제공.

### 겪었던 모니터링 문제
1. 기존 모니터링 시스템이 **수작업(hand-holding)에 크게 의존**.
2. **최신 클라우드 기반 시스템과 레거시 인프라를 함께 확장(scaling)**하는 것이 어려움.
3. 지표(metrics)에 대한 **중앙 집중식 가시성 부족**.
4. **알림(Alerting)과 대시보드가 사용자 친화적이지 않음**.

### 해결책: Prometheus + Grafana
- **Prometheus**
  - 지표 수집 계층(metric collection layer) 역할 — 시계열 데이터베이스(time series database)로 배포되어 모든 운영 지표를 손쉽게 수집.
  - 최신 시스템과 레거시 시스템을 모두 모니터링할 수 있는 유연한 아키텍처를 제공해 Trade Desk의 하이브리드 환경과 잘 맞음.
- **Grafana**
  - 시각화와 알림(alerting) 담당 — 조직 내 여러 팀이 쉽게 접근할 수 있는 대시보드 제공.
  - 서비스·팀별 커스텀 대시보드를 가능하게 하고, 모든 시스템에 걸쳐 통합된 대시보드로 구성.
  - Prometheus를 데이터 소스로 쉽게 연동 가능.
  - 대시보드에 알림 메커니즘을 내장해 알림 기능을 함께 개선 — Prometheus와 Grafana를 함께 사용해 대시보드에서 바로 통합된 알림을 받을 수 있게 됨.

## 요약
- Trade Desk는 하이브리드 인프라 전반의 수작업 의존·확장 어려움·가시성 부족·불편한 알림/대시보드 문제를, 지표 수집은 Prometheus(시계열 DB)로 중앙화하고 시각화·알림은 Grafana로 통합함으로써 해결했다.
