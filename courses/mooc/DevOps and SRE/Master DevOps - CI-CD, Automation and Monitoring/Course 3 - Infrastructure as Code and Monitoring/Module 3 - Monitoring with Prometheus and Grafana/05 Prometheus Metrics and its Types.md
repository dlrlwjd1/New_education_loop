# Prometheus Metrics and its Types

## 개요
- Prometheus 지표(metrics)의 정의와 모니터링에서의 역할, 그리고 4가지 지표 타입(Counter, Gauge, Histogram, Summary)을 정리.

## 내용
### Prometheus Metrics란
- 시스템 성능의 특정 측면을 시간에 따라 나타내는 데이터 포인트 — 모니터링의 핵심 구성 요소.
- 팀이 성능 추세를 이해하고, 알림을 설정하고, 리소스 사용을 최적화할 수 있게 해줌.

### 모니터링에서 지표의 역할
- 지표는 시스템 동작을 정량화된 데이터로 바꿔 효과적인 모니터링의 기반을 제공.
- **시스템 모니터링** — CPU, 메모리, 네트워크를 지속적으로 추적하고 임계값을 초과하면 알림 트리거.
- **용량 계획(Capacity Planning)** — 추세를 활용해 향후 인프라 필요량을 예측.
- 예: 컨테이너의 메모리 사용량이 10분간 RAM 80%를 초과하면 알림이 오도록 메모리 사용량 지표에 알림을 설정.

### Prometheus 지표 타입
1. **Counter(카운터)**
   - 시간이 지남에 따라 **누적적으로 증가만** 하는 지표(리셋되면 0으로 초기화).
   - 사용 사례: HTTP 요청 수, 오류 수, 처리된 작업(job) 수.
2. **Gauge(게이지)**
   - 시간에 따라 **증가하거나 감소할 수 있는** 지표 — 현재 상태나 사용 수준 측정에 사용.
   - 사용 사례: 메모리 사용량, CPU 사용률, 온도.
3. **Histogram(히스토그램)**
   - 관측값을 버킷(bucket)에 기록하며 개수(count), 합계(sum), 버킷별 분포를 제공 — 시간에 따른 분포를 그래프 형태로 분석하는 데 도움.
   - 사용 사례: 요청 처리 시간(request duration), 응답 크기(response size), 지연(latency).
4. **Summary(서머리)**
   - 히스토그램과 유사하지만 버킷 대신 **분위수(quantile, 예: 95th percentile)**를 계산 — 슬라이딩 타임 윈도우에 걸쳐 정확한 백분위 데이터를 보여줌.
   - 사용 사례: 트랜잭션 처리 시간, 큐 지연(queue latency), 응답 시간 백분위.

## 요약
- Prometheus 지표는 Counter(누적 증가), Gauge(증감 가능), Histogram(버킷별 분포), Summary(분위수 계산)의 네 가지 타입으로 나뉘며, 각각 요청 수 추적·리소스 사용량 모니터링·응답 시간 분포 분석·지연 시간 백분위 계산 등 서로 다른 모니터링 목적에 맞게 선택해 사용한다.
