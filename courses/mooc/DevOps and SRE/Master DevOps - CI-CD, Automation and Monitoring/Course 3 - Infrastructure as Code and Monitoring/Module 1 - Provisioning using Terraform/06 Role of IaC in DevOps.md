# Role of IaC in DevOps

## 개요
- DevOps 파이프라인에서 IaC의 흐름, 이점, CI/CD와의 관계, 그리고 Jenkins·GitLab CI 같은 대표 도구의 역할을 설명.

## 내용
### IaC 워크플로우
1. 엔지니어가 스크립트·템플릿·정책 형태로 코드 작성 (예: Terraform의 `.tf` 파일, 권한용 정책, `.sh` 스크립트)
2. **버전 관리**(Git)로 코드 변경 이력 관리
3. Terraform, Ansible, Puppet, Chef 같은 도구로 AWS/Azure/GCP 등 클라우드 환경에 인프라 배포

### DevOps에서 IaC의 중요성과 이점
1. **환경 간 일관성** — dev/stage/test/prod 환경에서 동일한 인프라 유지
2. **확장성과 유연성** — 설정값 하나만 바꿔도(예: EC2 인스턴스 수 3→5) 손쉽게 스케일업
3. **모듈성과 재사용성** — EC2, S3, DynamoDB 등 리소스를 여러 파일로 나눠 다른 용도로 재사용 가능
4. **비용 효율성** — 인프라 전체를 한 번에 배포하고 한 번에 삭제(destroy) 가능해 불필요한 리소스 낭비 방지
5. **테스트를 통한 리스크 감소** — 배포 전 `terraform plan` 등으로 실제 적용될 변경사항을 미리 확인 가능

### IaC와 CI/CD
- **워크플로우 간소화** — 배포 자동화로 수동 단계를 줄이고 딜리버리 속도 향상
- **협업 강화** — Dev·Ops 팀이 동일한 코드베이스를 공유(버전 관리 시스템의 원격 저장소)해 통합된 접근 방식으로 협업
- **신뢰성 향상** — 인프라 코드와 애플리케이션 코드가 항상 동기화된 상태 유지(애플리케이션 스케일업 시 인프라 코드도 함께 업데이트)

### IaC를 위한 DevOps 도구
- **Jenkins**
  - Terraform·Ansible 스크립트를 Jenkins 파이프라인에서 실행
  - 배포 전 `terraform plan` 등으로 변경사항 검증(validate)·포맷팅
  - 버전 관리 시스템과 통합해 인프라 변경 감지 시 자동으로 파이프라인 트리거 → 코드와 배포된 인프라 상태의 동기화 유지
- **GitLab CI**
  - `.gitlab-ci.yml` 기반 YAML 파이프라인으로 IaC 배포 작업 정의
  - Git으로 인프라 변경 이력(커밋 히스토리) 추적
  - 내장 보안 스캐닝으로 Terraform/CloudFormation/Kubernetes YAML 설정을 베스트 프랙티스 기준으로 검증

## 요약
- IaC는 코드 작성→버전 관리→도구를 통한 클라우드 배포라는 흐름으로 DevOps에 통합되며, 일관성·확장성·모듈성·비용 효율·리스크 감소라는 이점을 제공하고, Jenkins·GitLab CI 같은 CI/CD 도구와 결합해 인프라 변경을 자동으로 검증·배포·동기화한다.
