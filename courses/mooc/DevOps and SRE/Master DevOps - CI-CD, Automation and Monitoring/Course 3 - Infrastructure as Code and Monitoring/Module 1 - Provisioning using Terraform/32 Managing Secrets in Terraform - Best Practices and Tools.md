# Managing Secrets in Terraform: Best Practices and Tools

## 개요
- Terraform에서 다루는 Secret(민감 정보)의 종류와 위험, 관리 방법 4가지, 그리고 베스트 프랙티스를 정리.

## 내용
### Secret이란
- 시스템·서비스 접근을 인증·인가하는 데 쓰이는 민감한 정보 — 클라우드 API 키, DB 자격 증명, SSH 키, 서드파티 서비스 토큰 등.

### 부적절한 Secret 관리의 위험
- 인프라 무단 접근, 데이터 유출, GDPR·HIPAA 등 규정 위반, 고객 신뢰 상실과 금전적 벌금.

### Secret 관리 방법 4가지
1. **환경 변수(Environment Variables)** — 코드에 하드코딩하지 않고 값을 주입하는 간단한 방법.
   - 장점: 코드·버전 관리에서 시크릿을 분리, 구현 간단
   - 단점: 프로세스 목록이나 로그에 노출될 수 있음, 복잡한 시크릿 관리엔 부적합
2. **`sensitive` 플래그가 있는 Terraform 변수** — 변수를 `sensitive = true`로 표시해 로그에 표시되지 않게 함.
   - 장점: 우발적 노출 위험 감소, Terraform 워크플로우에 통합됨
   - 단점: State 파일에는 여전히 시크릿이 남을 수 있어 State 파일 관리에 주의 필요
3. **암호화된 파일** — GPG나 SOPS로 시크릿 파일을 암호화해 저장.
   - 장점: 저장 시 암호화 유지, 안전하게 버전 관리 가능
   - 단점: 워크플로우에 복잡성 추가, 키 관리 필요
4. **전용 Secret 관리 도구** (예: HashiCorp Vault)
   - Vault에 시크릿 저장 → Terraform에 Vault Provider 설정 → Data Source로 시크릿 접근
   - 장점: 중앙집중식 관리, 자동 로테이션과 감사(auditing)
   - 단점: 추가 설정·구성 필요, 서비스 이용 비용 발생 가능

### Secret 관리 베스트 프랙티스
1. **시크릿 하드코딩 금지** — Terraform 코드나 버전 관리 시스템에 절대 직접 저장하지 않음
2. **암호화된 원격 State 사용** — AWS S3 등 원격 백엔드에 암호화 활성화해 State 파일 보호
3. **역할 기반 접근 제어(RBAC)** — 최소 권한 원칙에 따라 역할별로 시크릿 접근 제한
4. **정기적인 시크릿 로테이션** — 유출된 자격 증명의 위험을 최소화하기 위해 주기적으로 교체
5. **접근 감사·모니터링** — 누가 언제 어떤 시크릿에 접근했는지 로그로 기록해 무단 접근 탐지
6. **CI/CD 파이프라인에 시크릿 관리 통합** — 로그나 오류 메시지에 시크릿이 노출되지 않도록 보장

## 요약
- Terraform의 Secret은 환경 변수, `sensitive` 변수, 암호화 파일, 전용 도구(HashiCorp Vault) 중 상황에 맞게 선택해 관리하며, 하드코딩 금지·암호화된 원격 State·RBAC·정기 로테이션·접근 감사·CI/CD 통합이라는 원칙을 지켜야 보안 사고를 예방할 수 있다.
