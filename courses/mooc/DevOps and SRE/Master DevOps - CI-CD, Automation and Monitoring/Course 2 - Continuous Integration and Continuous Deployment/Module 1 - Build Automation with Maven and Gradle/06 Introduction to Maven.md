# Introduction to Maven

## 개요
- Maven의 정의, 작동 방식, 주요 기능, Apache Ant와의 비교, 목표를 설명.

## 내용
### Maven이란
- "많은 것을 축적한다"는 뜻처럼, Java 프로젝트와 통합되어 코드 컴파일·검증(테스트)·아티팩트 생성을 담당하는 도구.
- 컴파일 완료 → 컴파일된 파일 생성 / 테스트 완료 → 테스트 리포트(Surefire report) 생성 / 패키징 완료 → 아티팩트 생성

### 작동 방식
- 개발자가 **Maven 프로젝트**를 만들면 **POM(Project Object Model) 파일**(`pom.xml`)이 생성된다 — 처음엔 비어 있고, 개발자가 의존성(dependency)·속성(property)·빌드 플러그인을 채워나간다.

### Maven의 기능
1. 모두가 사용할 수 있는 공통 프로젝트 구조 제공(일관성)
2. 의존성 라이브러리를 다운로드할 수 있는 **중앙 저장소(central repository)** 제공
3. 빌드 자동화 — 명령어로 컴파일·테스트·패키징 실행
4. 코드 리뷰·코드 커버리지 지원
5. 문서화 및 리포트 저장 지원
6. 아티팩트 생성 및 Artifactory 관리

### Apache Ant vs Apache Maven
- **Ant** (2000년 등장) — 정해진 관습(convention)이 없어 XML로 모든 걸 직접 지시해야 함, 수동 단계가 많고 다소 구식(obsolete)이 됨.
- **Maven** — 프레임워크이자 의존성 관리 시스템. 관습과 미리 정의된 명령어(convention over configuration)로 훨씬 쉽게 실행 가능, 다른 자동화 도구와 통합해 빌드 프로세스를 자동화. Ant보다 훨씬 대중적.

### Maven의 목표
1. 빌드 프로세스를 쉽게 만들기 — 팀 전체가 통일된 빌드 시스템 사용
2. 개발 베스트 프랙티스에 대한 가이드라인 제공
3. 새 기능 마이그레이션에 대한 투명한 워크플로우 제공
4. 지속적인 컴파일·소규모 단위 테스트로 프로젝트 품질 향상

## 요약
- Maven은 `pom.xml`을 중심으로 공통 프로젝트 구조·중앙 저장소·빌드 자동화를 제공해 Ant보다 훨씬 간편하고 표준화된 방식으로 Java 프로젝트의 빌드 프로세스를 관리한다.
