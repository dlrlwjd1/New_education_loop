# Handlers

## 개요
- Ansible Handler의 개념, 실행 조건, 이점, 실무 활용 사례를 설명.

## 내용
### Handler란
- Playbook 안에 작성되는 특수한 task로, 이름과 실행할 모듈을 가지지만 **스스로 실행되지 않는다**.
- 오직 **부모(Parent) task가 실제로 변경을 일으켰을 때만** `notify`를 통해 실행되는 **의존적(dependent) task**.
- 부모 task가 아무런 변경도 만들지 않으면 handler는 트리거되지 않는다.

### Handler를 사용하는 이유
- 서비스를 항상 재시작/중지할 필요는 없고, **필요할 때만** 재시작/중지하고 싶을 때 유용하다.
- 필요할 때만 리소스를 시작/재로드하도록 보장 — 같은 상태에 대한 불필요한 반복 실행(리소스 낭비)을 방지.
- **조건 기반 실행** — 서버에 변경이 생겼을 때만 예를 들어 Apache 서비스를 재시작하는 식.
- Playbook 실행 속도를 높이고 여러 서버에 걸친 오케스트레이션을 가능하게 함.

### 실행 방식
- `notify` 키워드로 부모 task의 상태 변화를 handler에 알림.
- Handler는 **모든 task가 실행된 이후**에 실행된다(먼저 notify 되었더라도 마지막에 실행됨).
- 여러 handler가 notify되면, **notify된(또는 정의된) 순서대로** 실행된다.

### 실무 활용 사례
- 설정 변경 시 Apache, Nginx, MySQL 등 서비스 재시작/재로드
- 다운타임을 줄이기 위한 서비스 시작/중지
- 필요할 때만 마이그레이션을 적용하는 데이터베이스 마이그레이션

## 요약
- Handler는 부모 task가 실제 변경을 만들었을 때만 `notify`로 트리거되어 모든 task 실행이 끝난 뒤 순서대로 실행되는 조건부 task로, 서비스 재시작 등 "필요할 때만" 수행해야 하는 작업에 리소스 낭비 없이 대응할 수 있게 해준다.
