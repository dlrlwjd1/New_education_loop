# Scenario of an IT Company

## 개요
- 개발자 Dave와 시스템 엔지니어 Sam의 사례를 통해 Configuration Management의 필요성을 설명.

## 내용
### 시나리오
- 개발자 **Dave**는 새 기능을 만들고(민첩성 중시), 시스템 엔지니어 **Sam**은 그것을 배포해 안정적으로 서비스한다(안정성 중시).
- Dave: "내 서버(Ubuntu, Java 17, Tomcat 9)에서는 잘 동작한다"고 전달 → Sam이 자신의 서버에 배포하니 실패.
- 원인: Sam의 서버는 더 오래된 Java, 다른 OS, 더 오래된 Tomcat 버전을 사용 중이었음 — 환경 불일치.
- Sam은 이 문제를 수십~수백 대 서버에서 하나씩 수동으로 고쳐야 하는 상황 → 매니저가 트래픽 증가로 200대 서버 추가 배포까지 요청하며 문제가 더 커짐.

### 자동화 없이 겪는 문제
1. 대규모 서버 설정이 지루하고 시간 소모적
2. 오류가 발생하기 쉬움
3. 도구 없이 확장(scaling)하기 어려움
4. 모든 서버가 동일한 변경사항을 갖도록 보장하기 어려움

### 해결책: Configuration Management 도구
- **Puppet, Ansible, Chef, SaltStack** 같은 도구를 사용하면 자동화 도구가 모든 서버에 병렬로 연결해 몇 초 안에 코드가 배포되고 애플리케이션이 매끄럽게 동작하게 된다.
- **Configuration**이란 패키지 설치/제거, 파일 배포·복사, 권한 부여, 사용자 생성 등 서버에 가하는 모든 변경을 의미하며, **Management**란 도구를 통해 여러 서버에 이러한 변경을 적용하는 것을 뜻한다.
- 트래픽 증가로 서버를 확장해야 할 때도 Configuration Management 도구로 손쉽게 대응할 수 있다.

## 요약
- 서버 환경 불일치와 수작업 배포는 규모가 커질수록 감당할 수 없는 문제가 되며, Ansible 같은 Configuration Management 도구는 여러 서버에 동일한 설정·패키지·파일을 자동으로 일관되게 적용해 이 문제를 해결한다.
