# Infrastructure as Code

## 개요
- Infrastructure as Code(IaC)의 정의, 워크플로우, IaC 이전의 문제점과 도입 이점을 설명.

## 내용
### Infrastructure란
- 서버, VM, 스토리지, 하드웨어, 네트워크, 오토스케일러, 로드밸런서 등 애플리케이션이 실행되는 데 필요한 모든 구성요소.

### Infrastructure as Code(IaC)란
- 인프라를 수동으로 구성하는 대신, 코드를 작성해 클라우드 기반 서버/플랫폼을 자동화된 방식으로 관리·프로비저닝하는 관행.

### IaC 워크플로우
1. 개발자가 코드를 작성해 버전 관리 도구에 커밋
2. DevOps 엔지니어가 인프라 프로비저닝을 위한 코드를 작성해 마찬가지로 버전 관리에 저장
3. Jenkins, GitHub Workflows, GitLab CI/CD 같은 자동화 서버가 이 코드를 가져와 실행
4. AWS, Azure, GCP 등 클라우드 제공자에 연결해 필요한 인프라 프로비저닝
5. Configuration Management 스크립트로 프로비저닝된 인프라에 연결해 애플리케이션 배포
6. 코드를 push/pull하기 전에 인프라 코드 테스트 수행

### IaC 이전(온프레미스 데이터센터)의 문제
- 물리적으로 서버를 관리·설정해야 했음 — 오류 발생 가능성 높음, 비용이 큼, 서버 간 불일치, 확장이 어렵고 승인·확장에 시간 소요.

### IaC 도입의 이점
1. **저렴함** — 같은 코드를 반복 사용해 인프라를 빠르게 재생성
2. **배포 속도 향상** — 인프라가 즉시 준비되고, 필요 없어지면 바로 파기(destroy) 가능
3. **오류 감소** — 인프라 설정 단계를 자동화
4. **일관성 향상** — 예: 15일마다 필요한 테스트 환경을 매번 수동으로 만들 필요 없이 코드 실행만으로 생성·사용·파기 가능
5. **설정 드리프트(Configuration Drift) 제거** — Ansible 같은 설정 관리 도구에만 의존하기보다, Terraform·CloudFormation 같은 IaC 도구로 인프라 자체를 자동화하면 드리프트를 근본적으로 없앨 수 있다.

## 요약
- IaC는 인프라를 코드로 정의·버전관리하여 클라우드 인프라를 자동으로 프로비저닝·파기할 수 있게 하며, 온프레미스 수동 관리 대비 비용·속도·일관성·오류 감소 면에서 크게 유리하고 Terraform/CloudFormation 같은 도구로 설정 드리프트 문제까지 해결한다.
