# History of Jenkins

## 개요
- Hudson에서 Jenkins로 이어진 탄생 배경과 이후 성장·현대화 과정을 시기별로 정리.

## 내용
### 기원: Hudson에서 Jenkins로 (2004~2011)
- 2004년 Sun Microsystems의 개발자 Kohsuke Kawaguchi가 반복 작업 자동화를 위해 **"Hudson"**을 만듦 — 단순함과 확장성으로 빠르게 인기를 얻음.
- 2010년 Oracle의 Sun Microsystems 인수 이후 Hudson의 통제권을 둘러싼 분쟁 발생 → 커뮤니티가 프로젝트를 포크(fork)하기로 결정.
- 2011년 1월, 포크된 프로젝트가 공식적으로 **"Jenkins"**로 명명됨.

### 성장과 성숙 (2011~2015)
- 포크 이후 활발한 커뮤니티와 플러그인 생태계 덕분에 급성장 — 2015년까지 전 세계 10만 개 이상의 활성 설치 사례 확보.
- 플러그인 확대, 엔터프라이즈 도입 증가, Jenkins User Conference 등 커뮤니티 행사 활성화.

### 파이프라인과 클라우드 네이티브 트렌드 수용 (2016~2019)
- **Pipeline as Code** — Pipeline 플러그인 도입으로 빌드 프로세스를 코드로 정의, 재현성·버전 관리 강화.
- **Jenkins X**(2018) — Kubernetes 환경을 위한 클라우드 네이티브 애플리케이션용 자동 CI/CD.
- 2019년 **Continuous Delivery Foundation(CDF)**의 창립 프로젝트로 참여.

### 현대화와 커뮤니티 참여 (2020~2024)
- UI 개편 — 오래된 프레임워크(YUI) 제거, 새로운 디자인 요소 도입.
- 보안 강화 — 다수의 취약점 해결.
- Hacktoberfest, Google Summer of Code 등으로 신규 기여자 유입 확대.

### 2025년 현재와 전망
- **Java 21** 지원으로 최신 Java 애플리케이션과 호환.
- **플러그인 2,000개 이상**으로 폭넓은 커스터마이징 지원.
- 전 세계적으로 매달 수백만 건의 job이 실행되는 등 여전히 큰 시장 점유율 유지.
- 향후 확장성, 사용자 경험, 통합 능력을 지속적으로 개선할 계획.

## 요약
- Jenkins는 2004년 Hudson으로 시작해 2011년 커뮤니티 포크로 독립한 이후, Pipeline as Code·Jenkins X·CDF 참여 등을 거치며 오픈소스 협업의 대표 사례로 성장해 지금도 CI/CD 생태계의 핵심 도구로 남아 있다.
