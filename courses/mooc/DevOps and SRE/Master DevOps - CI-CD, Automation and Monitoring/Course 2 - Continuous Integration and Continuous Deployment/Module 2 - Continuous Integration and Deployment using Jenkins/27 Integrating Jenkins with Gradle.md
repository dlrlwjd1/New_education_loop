# Integrating Jenkins with Gradle

## 개요
- Jenkins-Gradle 통합의 이점, 잠재적 이슈, 베스트 프랙티스를 설명.

## 내용
### 통합이 필요한 이유
- 코드 통합·컴파일·테스트·배포·빌드가 훨씬 빨라진다.
- Gradle은 PHP, Java 등 다양한 언어와 통합해 빌드·테스트 가능.

### 이점
1. **풍부한 플러그인** — Maven보다 많은 플러그인으로 다양한 빌드 단계를 쉽게 수행
2. **병렬 실행** — 빌드 완료 속도 향상, 코드 추가 시 확장 용이
3. **빠르고 신뢰할 수 있는 빌드** — 자동화로 반복 작업을 더 빠르게 처리

### 잠재적 이슈
1. **초기 설정 복잡도** — Maven보다 설치·설정이 다소 복잡함(Gradle 바이너리 설치 → 도구 설정 → Jenkins 통합의 여러 단계 필요)
2. **자원 소모** — T2.micro보다는 T2.medium급 이상의 사양이 필요할 수 있음(자원이 부족하면 시스템이 느려짐)
3. **Gradle 지식 필요** — 빌드 파일·프로퍼티 파일·명령어를 알아야 설정 가능하며, 알고 있으면 디버깅·트러블슈팅이 쉽지만 모르면 어려움

### 베스트 프랙티스
1. 항상 버전 관리 도구로 소스 코드 관리
2. Selenium, TestNG, JIRA(테스트 관련) 등으로 테스트 프로세스 자동화
3. 증분 빌드 또는 병렬 실행을 지원하는 빌드 도구 사용
4. Jenkins 같은 CI 도구로 성능을 모니터링·최적화
5. 빌드 도구를 활용한 파이프라인 생성

## 요약
- Gradle은 풍부한 플러그인과 병렬 실행으로 Jenkins와 결합했을 때 빠르고 확장 가능한 빌드를 제공하지만, Maven보다 초기 설정이 복잡하고 자원을 더 요구하므로, 버전 관리·테스트 자동화·증분/병렬 빌드·모니터링이라는 베스트 프랙티스를 함께 지켜야 한다.
