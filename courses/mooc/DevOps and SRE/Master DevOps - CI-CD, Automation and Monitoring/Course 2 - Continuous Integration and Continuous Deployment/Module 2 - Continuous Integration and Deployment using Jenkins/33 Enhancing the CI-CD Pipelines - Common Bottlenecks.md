# Enhancing the CI-CD Pipelines - Common Bottlenecks

## 개요
- CI/CD 파이프라인에서 자주 발생하는 병목(bottleneck) 원인들을 정리.

## 내용
### 주요 병목 원인
1. **과도한 수동 개입** — 배포 단계나 통합 단계에서 테스트를 수동으로 실행하거나 파이프라인 자체를 수동으로 실행하는 경우가 많아 시간이 낭비된다.
2. **느린 빌드(Slow Build)** — 코드베이스가 크거나 리소스가 부족하고 설정이 비효율적이면 빌드·테스트·배포 전체가 느려진다.
3. **비효율적인 테스트** — 테스트 케이스가 충분하지 않거나 자동화 도구가 완전한 코드 커버리지를 제공하지 못하면, 통합 테스트나 사용자 승인 테스트(UAT) 단계에서 문제가 터져 파이프라인이 깨지고 배포가 막힌다.
4. **실패 시 지연된 피드백** — 결함 발견 후 개발자에게 알림이 가고 수정될 때까지 파이프라인을 수동으로 재실행해야 하는 등, 피드백-수정 루프에 지연이 생긴다.
5. **오래된 도구 버전 사용, Jenkins 서버 리소스 부족** 등도 흔한 원인이다.

### 느린 빌드의 세부 원인
- 빌드는 흔히 파이프라인의 첫 단계라서, 느린 빌드는 전체 파이프라인을 지연시킨다.
- 코드베이스가 클수록(Java 파일, 유틸리티 파일, 리소스 파일이 많을수록) 빌드 시간이 늘어난다.
- 개발자가 코드를 자주 변경해 파이프라인이 자주 실행돼야 하는 경우에도 부담이 커진다.
- 의존성 관리가 비효율적이거나 Jenkins 서버 리소스가 부족한 경우에도 빌드가 느려진다.

## 요약
- CI/CD 파이프라인의 대표적인 병목은 수동 개입, 느린 빌드, 비효율적인 테스트, 지연된 실패 피드백이며, 이는 대개 자동화 부족·리소스 부족·테스트 커버리지 부족·오래된 도구 버전이 원인이다.
