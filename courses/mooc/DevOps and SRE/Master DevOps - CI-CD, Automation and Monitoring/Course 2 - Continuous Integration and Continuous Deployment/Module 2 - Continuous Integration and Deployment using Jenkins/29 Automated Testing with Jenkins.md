# Automated Testing with Jenkins

## 개요
- 자동화 테스트의 정의, 필요성, Jenkins와 통합되는 테스트 유형과 이점을 설명.

## 내용
### 자동화 테스트란
- 도구/스크립트를 이용해 미리 정의된 테스트 케이스를 실행함으로써 소프트웨어가 요구사항대로 동작하는지 검증·확인하는 프로세스.
- Maven, Gradle 같은 빌드 도구, Jenkins 같은 CI 서버와 통합 가능.
- 대표 도구: Selenium, TestNG, JUnit, Cucumber — 사람처럼 동작하며 코드를 검증.

### 왜 자동화 테스트가 필요한가
- **시간 절약** — 빠르게 완료
- **사람의 실수 방지**
- **확장성** — 코드/애플리케이션 규모가 커질수록 테스트 케이스도 늘어나는데, 자동화하면 빠르게 처리 가능
- **반복 작업 효율화** — 매번 반복되는 유스케이스를 자동화해 팀 효율 향상
- **CI/CD 구현 필수 요소** — 수동 테스트는 빠른 배포를 지연시킴
- **디바이스 간 일관성** — 동일한 스크립트를 여러 OS/플랫폼에서 실행해 일관성 확보
- **회귀 테스트(Regression Testing)** — 코드가 바뀔 때마다 반복 실행해야 하는 테스트를 자동화

### Jenkins와 통합되는 테스트 유형
1. **Unit Testing** — 작은 코드 단위를 검증 (JUnit, Cucumber, TestNG)
2. **Integration Testing** — 여러 기능을 통합해 검증 (Selenium, Cucumber)
3. **End-to-End Testing** — 실제 사용자처럼 애플리케이션 전체 기능을 시뮬레이션해 검증

### 이점
- **코드 커버리지 증가** — 더 많은 테스트 케이스로 테스트된 비율을 정확히 측정
- **일관성·정확성 향상** — 여러 OS에서 일관된 결과
- **비용 절감** — 매번 테스터에게 비용을 지불하는 대신 도구 라이선스 비용만 발생
- **버그 조기 발견** — 개발팀이 충분한 시간을 갖고 수정 가능
- **CI/CD 지원** — 지속적 통합·딜리버리 가능
- **더 빠른 배포·개발 주기**

## 요약
- 자동화 테스트는 Unit→Integration→End-to-End 순으로 Jenkins 파이프라인에 통합되며, 코드 커버리지 향상·비용 절감·조기 버그 발견·빠른 배포라는 이점을 통해 CI/CD를 실질적으로 가능하게 만드는 핵심 요소다.
