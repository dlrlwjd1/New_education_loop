# Introduction to Containerization - History and Use Cases

## 개요
- 2013년 Docker 등장부터 2015년 OCI(Open Container Initiative)까지 이어지는 컨테이너 역사의 후반부와, 컨테이너화의 5가지 대표 사용 사례를 정리.

## 내용
### 컨테이너 역사 (2013년 이후)
- **2013년 — Docker 등장**: 2006년 도입된 Cgroups와 Kernel Namespaces를 활용해 동작. 단순히 컨테이너를 만드는 것을 넘어, 컨테이너용 네트워킹·볼륨·스토리지 관리, 마이크로서비스 관리, 오케스트레이션 환경까지 아우르는 도구.
- **2014년 — Kubernetes 등장**: Google이 개발했으며, 2014년 9월경 CNCF(Cloud Native Computing Foundation)에 기증되어 오픈소스가 됨. 컨테이너 자체를 만드는 도구가 아니라 **컨테이너 오케스트레이터**로, 컨테이너화된 애플리케이션의 고가용성(High Availability)과 장애 허용(Fault Tolerance)을 제공.
- **2015년 — OCI(Open Container Initiative)**: 오픈소스 커뮤니티가 주도해 상업적으로 운영되던 컨테이너 도구들을 대체하고 컨테이너를 더 개방적이고 배포하기 쉽게 만들기 위한 이니셔티브 — 어떤 컨테이너 이미지든 Docker, Podman, Kubernetes 등 여러 플랫폼에서 실행 가능하도록 표준화(범용성·상호 운용성 확보).

### 컨테이너화의 사용 사례
1. **일관된 개발·배포 환경** — 개발한 이미지를 그대로 가져가 배포하면 모든 의존성이 함께 패키징되어 있어 어디서든 동일하게 동작 — SRE·운영팀에 이미지만 전달하면 프로덕션에서도 문제없이 실행 가능.
2. **마이크로서비스 아키텍처(Microservice Architecture)** — 예: 프론트엔드와 데이터베이스를 각각 별도의 컨테이너에 배치하면, 프론트엔드는 사용자와 상호작용하고 데이터베이스와는 TCP/IP 네트워크로 통신 — 각 컴포넌트를 독립적으로 개발·테스트·배포·트러블슈팅할 수 있음(예: 데이터베이스 작업이 프론트엔드에 영향을 주지 않음).
3. **CI/CD 파이프라인** — 지속적 통합·지속적 배포를 수행하는 데 컨테이너가 폭넓게 활용됨.
4. **플랫폼 간 이식성(Portability)** — 예: Linux에서 개발한 애플리케이션을 컨테이너로 만들면, Windows에 WSL(Windows Subsystem for Linux)을 활성화해 동일한 컨테이너를 그대로 실행 가능 — 애플리케이션이 플랫폼에 상관없이 100% 이식 가능해짐.
5. **리소스 효율성과 확장성(Scalability)** — 컨테이너는 리소스를 효율적으로 사용하며, 부하가 증가하면 컨테이너 수를 빠르게 늘리고(Scale Up) 부하가 줄면 다시 줄이는(Scale Down) 것이 용이함.

## 요약
- 2013년 Docker(Cgroups·Namespaces 활용) → 2014년 Kubernetes(오케스트레이터, Google→CNCF 기증) → 2015년 OCI(표준화·상호운용성)로 이어지는 발전을 거쳐, 컨테이너화는 일관된 배포 환경, 마이크로서비스 아키텍처, CI/CD, 플랫폼 간 이식성, 리소스 효율적 확장성이라는 다섯 가지 핵심 사용 사례로 현대 DevOps의 표준이 되었다.
