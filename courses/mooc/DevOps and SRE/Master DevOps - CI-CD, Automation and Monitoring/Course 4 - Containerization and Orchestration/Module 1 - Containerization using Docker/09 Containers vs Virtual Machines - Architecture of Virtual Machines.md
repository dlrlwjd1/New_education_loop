# Containers vs Virtual Machines - Architecture of Virtual Machines

## 개요
- 컨테이너와 가상 머신(VM)을 비교하기 위한 사전 단계로, VM의 정의와 하이퍼바이저(Hypervisor) 기반 아키텍처를 정리.

## 내용
### 가상 머신(VM)이란
- 물리 컴퓨터를 소프트웨어로 에뮬레이션(emulation)한 것 — 하나의 물리 머신 위에서 여러 운영체제를 동시에 실행할 수 있게 해줌.
- 물리 서버 위에 **하이퍼바이저(Hypervisor)**를 설치하고, 그 위에 VM을 만들어 각 VM에 원하는 운영체제를 설치해 애플리케이션을 실행.
- 각 VM은 독립적으로 동작하며, 자신만의 CPU, 메모리, 스토리지, 네트워크, 그리고 운영체제를 가짐 — VM 자체가 물리적으로 존재하지 않는 별도의 컴퓨터처럼 동작.

### VM 아키텍처
1. **인프라(물리 서버)** — 예: CPU 2개×4코어(총 8 vCPU), RAM 32GB, 10GB NIC 카드 2개, 스토리지 1TB로 구성된 물리 서버.
2. **하이퍼바이저(Hypervisor)** — 물리 서버 위에 설치되는 소프트웨어 계층. 하드웨어를 에뮬레이션해 VM을 만들 수 있게 해주는 핵심 역할.
3. **가상 머신(VM)들** — 하이퍼바이저가 물리 서버의 리소스를 가상화해 각 VM에 분배(예: VM 하나에 CPU 2개·RAM 4GB 할당). 물리 서버의 총 용량을 넘어서는 리소스는 할당할 수 없음. 각 VM은 Windows, RHEL, Ubuntu 등 원하는 OS를 독립적으로 실행.
4. **애플리케이션 계층** — 각 VM 위에 애플리케이션과 그 바이너리·라이브러리·의존성·프레임워크를 설치 — 웹 서버(HTTP), Kafka, Hadoop, Redis, 데이터베이스 등 어떤 애플리케이션이든 VM 안에서 실행.

## 요약
- 가상 머신은 물리 서버 위에 하이퍼바이저를 설치하고, 하이퍼바이저가 물리 서버의 CPU·메모리·스토리지를 가상화해 여러 VM에 분배함으로써 각 VM이 독립적인 OS와 애플리케이션 스택을 가진 별도의 컴퓨터처럼 동작하게 하는 소프트웨어 에뮬레이션 기술이다.
