# Persistent Volumes - Lifecycle

## 개요
- Persistent Volume의 생명주기(Provisioning → Binding → Using)를 정리하고, 정적 프로비저닝(Static Provisioning)과 동적 프로비저닝(Dynamic Provisioning)의 차이를 설명.

## 내용
### 1단계: 프로비저닝(Provisioning)
- 먼저 **PVC**를 생성하는 것에서 시작.
- **정적 프로비저닝(Static Provisioning)** — 관리자가 볼륨을 수동으로 미리 만들어 Kubernetes 클러스터에 매핑하는 방식. Kubernetes는 매우 동적인 환경(Pod가 계속 온라인/오프라인되고, 스토리지 용량을 즉시 늘려야 하는 등)이기 때문에 **정적 프로비저닝은 프로덕션 워크로드에 거의 사용되지 않음**.
- **동적 프로비저닝(Dynamic Provisioning)** — 실제로 대부분 사용하는 방식. PVC를 생성하면 Kubernetes가 **CSI 드라이버**를 통해 이 요청을 스토리지 시스템에 전달하고, 스토리지 시스템이 볼륨을 생성해 돌려줌.

### 2단계: 바인딩(Binding)
- 볼륨이 만들어지면 해당 **PVC와 바인딩(bind)**됨 — 이제 이 볼륨을 사용할 준비가 됨.

### 3단계: 사용(Using)
- 최종 목표는 볼륨을 만드는 것 자체가 아니라 **그 볼륨을 사용하는 것** — 이를 위해 PVC를 Pod 안에 매핑하고, 컨테이너에 볼륨을 마운트해서 컨테이너가 그 볼륨에 데이터를 저장할 수 있게 함.
- Pod가 죽으면 컨테이너는 사라지지만, **볼륨은 사라지지 않음** — 볼륨은 외부 PVC로부터 오는 것이기 때문. Pod가 재생성되고 컨테이너가 이미지로부터 다시 만들어지면, **같은 PVC를 다시 매핑**하기만 하면 됨.

## 요약
- Persistent Volume의 생명주기는 프로비저닝(정적 또는 동적) → PVC와의 바인딩 → Pod/컨테이너에 마운트하여 사용의 순서로 진행되며, Kubernetes의 동적인 특성상 실무에서는 정적 프로비저닝보다 CSI 드라이버 기반 동적 프로비저닝을 사용하고, Pod가 죽어도 볼륨은 외부에 남아 있으므로 재생성된 Pod에 동일한 PVC를 다시 매핑하면 데이터 연속성이 보장된다.
