# Docker Image - Principles and Features

## 개요
- Docker 이미지의 정의, 기본 원칙(불변성·계층 구조·읽기 전용)과, 이미지가 담고 있는 구성 요소·특징을 정리.

## 내용
### Docker 이미지란
- 애플리케이션을 실행하는 데 필요한 모든 요소를 담은 패키지 — 애플리케이션과 그 의존성을 포함.
- Dockerfile → `docker build` 실행 → 이미지 생성 → 컨테이너 실행이라는 흐름에서, 이미지는 컨테이너가 어떻게 만들어져야 하는지, 어떤 소프트웨어 설정을 가져야 하는지를 정의하는 실행 가능한 패키지(템플릿).

### 기본 원칙
1. **불변성(Immutable)** — 이미지는 한 번 생성되면 변경할 수 없음. 무언가 추가·제거·수정하려면 Dockerfile을 고쳐서 다시 `docker build`로 이미지를 재생성해야 함.
2. **계층 구조(Layered Architecture)** — Dockerfile의 `FROM`, `RUN`, `COPY`, `ADD`, `EXPOSE`, `CMD`, `ENTRYPOINT` 등 각 지시문이 실행될 때마다 하나의 레이어가 됨. 각 레이어는 파일 추가·수정·삭제·설치 같은 특정 파일시스템 변경 사항을 담음.
3. **읽기 전용(Read-only)** — `docker build`로 만들어진 이미지는 완전히 읽기 전용. 컨테이너는 이 읽기 전용 이미지 위에 읽기-쓰기(read-write) 레이어를 얹은 것.

### 이미지의 특징
1. **플랫폼 독립성(Platform Independent)** — Linux에서 만든 이미지를 Windows나 다른 Linux 배포판(Ubuntu, CentOS, Rocky Linux 등) 어디서든 그대로 사용 가능 — Docker Hub에 올려두면 다양한 환경에서 컨테이너를 실행할 수 있음.
2. **애플리케이션 코드/패키지** — 실행할 애플리케이션의 코드 또는 패키지를 포함.
3. **런타임(Runtime)** — 애플리케이션 종류에 맞는 실행 환경 포함(예: Flask 애플리케이션이면 Python, Java 애플리케이션이면 JDK, .NET 애플리케이션이면 .NET 런타임, Node.js 애플리케이션이면 Node.js 런타임).
4. **라이브러리·의존성** — 애플리케이션이 필요로 하는 라이브러리·의존성 포함(예: Python 베이스 이미지 위에 Flask 라이브러리를 추가로 설치).
5. **시스템 도구·유틸리티** — `ping`, `ip`, `telnet`, `netstat`, `curl` 등 연결 확인·테스트에 필요한 OS 레벨 유틸리티도 이미지 안에 포함될 수 있음.

## 요약
- Docker 이미지는 불변(Immutable)·계층 구조(Layered)·읽기 전용(Read-only)이라는 세 가지 원칙을 따르며, 플랫폼 독립적으로 애플리케이션 코드·런타임·라이브러리/의존성·시스템 유틸리티를 모두 하나의 패키지에 담아 컨테이너 실행의 기반이 된다.
