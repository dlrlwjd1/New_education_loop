# Storage and Volumes in Docker - Managing Storage

## 개요
- 컨테이너의 쓰기 가능 레이어(writable layer)에 데이터를 저장할 때 발생하는 한계(휘발성·격리)와, 이를 해결하는 Docker 스토리지 옵션 4가지(Volume, Bind Mount, tmpfs, Named Pipe)를 정리.

## 내용
### 왜 Docker 스토리지 관리가 필요한가
- 컨테이너 안에서 애플리케이션(예: MySQL 데이터베이스)을 실행하면 데이터베이스·테이블 등의 데이터가 컨테이너에 저장됨.
- 컨테이너가 죽으면 이미지로부터 새 컨테이너를 다시 만들 수 있지만, **컨테이너 안에 있던 기존 데이터는 사라짐** — 이것이 해결해야 할 핵심 문제.
- 기본적으로 컨테이너 내에서 생성·수정되는 모든 데이터는 컨테이너의 **쓰기 가능 레이어(writable layer)**에 저장됨(이미지는 읽기 전용, 컨테이너는 읽기-쓰기 레이어라는 점 복습).

### 기본 방식의 한계
1. **휘발성(Ephemeral)** — 쓰기 가능 레이어는 컨테이너의 수명과 함께하므로, 컨테이너가 삭제되거나 교체되면 데이터도 함께 사라짐.
2. **격리(Isolation)** — 각 컨테이너는 자신만의 쓰기 가능 레이어를 가지므로, 컨테이너 간 데이터를 직접 공유하거나 호스트 시스템에서 접근하기 어려움.

### 해결책: Docker 스토리지 옵션
- 퍼시스턴트 데이터와 컨테이너·호스트 간의 매끄러운 데이터 공유를 위해 Docker는 다음과 같은 스토리지 전략을 제공:
1. **Volume(볼륨)** — Docker가 관리하는 스토리지.
2. **Bind Mount(바인드 마운트)** — 호스트의 특정 경로를 컨테이너에 마운트.
3. **tmpfs Mount** — 메모리 기반의 임시 스토리지.
4. **Named Pipe** — **Windows Docker Host 전용**으로 사용 가능한 방식(Linux Host에서는 사용 불가, Linux에서는 Bind Mount·Volume Mount·tmpfs Mount만 사용 가능).

## 요약
- 컨테이너의 쓰기 가능 레이어에만 데이터를 저장하면 컨테이너가 삭제될 때 데이터도 함께 사라지고(휘발성) 컨테이너 간 공유도 어려운(격리) 문제가 있으며, Docker는 이를 해결하기 위해 Linux에서는 Volume·Bind Mount·tmpfs를, Windows에서는 추가로 Named Pipe를 스토리지 옵션으로 제공한다.
