# Docker Container Running Modes - Foreground Mode

## 개요
- Foreground(Attach) 모드의 동작 원리, `-t`·`-a` 플래그, 그리고 Detach 모드와 대비되는 사용 사례를 정리.

## 내용
### Foreground(Attach) 모드란
- 컨테이너 애플리케이션이 콘솔(터미널)에 직접 연결(attach)되는 모드 — 컨테이너와 상호작용할 수 있지만, 그동안 터미널이 점유되어 다른 명령(예: 다른 컨테이너 실행)을 실행할 수 없음.
- Detach 모드와 마찬가지로 컨테이너는 루트 프로세스(애플리케이션 프로세스)가 종료되면 함께 종료됨.
- **플래그 없이(`docker run` 그대로) 실행하면 기본값이 Attach 모드** — `-d`를 명시해야만 Detach 모드가 됨. 즉 `-d` 유무가 두 모드를 가르는 핵심.
```bash
docker run -p <호스트포트>:<컨테이너포트> <이미지>   # -d 없이 실행 → Foreground/Attach 모드, 터미널 점유
```

### 관련 플래그
- **`-t`(Terminal)** — 컨테이너에 터미널(TTY 모드)을 부여해 bash 셸 등으로 입출력을 주고받을 수 있게 함.
- **`-a`(Attach)** — 컨테이너의 표준 입력(stdin)·표준 출력(stdout)·표준 에러(stderr)를 연결 — 표준 입력을 보내거나 표준 출력·에러 처리를 다룰 때 사용.

### Foreground 모드 사용 사례
1. **애플리케이션 디버깅·테스트** — 컨테이너를 실행하자마자 바로 정상 동작 여부를 확인하고 싶을 때.
2. **사용자 입력이 필요한 컨테이너 실행** — 예: 셸을 열어 설정 파일, 바인딩된 포트, 환경 변수 등을 즉시 확인해야 할 때.
3. **실시간 로그·애플리케이션 동작 모니터링** — 애플리케이션의 동작을 실시간으로 지켜봐야 할 때.
- 핵심 기준: **실행 시점에 애플리케이션과 직접 상호작용해야 하는가** → Attach 모드, **상호작용이 필요 없는가** → Detach 모드.

## 요약
- Foreground(Attach) 모드는 플래그 없이 `docker run`을 실행하면 기본으로 적용되며 컨테이너가 터미널을 점유해 즉시 상호작용(`-t`로 터미널, `-a`로 표준 입출력 연결)할 수 있는 반면, Detach 모드(`-d`)는 백그라운드에서 실행되어 터미널을 자유롭게 두므로, 디버깅·테스트·즉각적인 사용자 입력이 필요한 경우엔 Attach, 그렇지 않은 서비스 실행에는 Detach를 선택한다.
