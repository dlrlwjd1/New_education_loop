# Dockerfile - Instruction

## 개요
- Dockerfile의 정의와 역할, Dockerfile 지시문(Instruction)이 이미지의 레이어(Layer)를 이루는 원리, 그리고 이미지(읽기 전용)와 컨테이너(읽기-쓰기)의 관계를 정리.

## 내용
### Dockerfile이란
- Docker 이미지를 합성(synthesize)하기 위한 여러 지시문(instruction)을 담은 파일 — 함수나 반복문 없이 단순한 지시문과 인자로 구성된 일반 텍스트 스크립트.
- 컨테이너를 설정하고 애플리케이션을 실행하는 데 필요한 모든 것 — 베이스 이미지, 의존성, 환경 변수, 명령, 설정 — 을 정의.
- 예: WAR 파일을 배포하려면 Tomcat을 베이스 이미지로 지정해야 하고, Python Flask 애플리케이션을 배포하려면 Flask 모듈 설치를 지시문으로 정의해야 함.
- 이 Dockerfile을 `docker build` 명령으로 실행(execute)하면 이미지가 만들어지고, 그 이미지로 컨테이너를 생성.

### Dockerfile 지시문과 레이어(Layer)
- Dockerfile의 각 지시문(`FROM`, `COPY`, `RUN` 등)은 이미지의 **레이어(layer)** 하나에 해당.
- Docker 이미지는 여러 레이어로 구성되며, 각 레이어는 Dockerfile의 지시문 하나에서 만들어짐.
- 이 레이어들이 차곡차곡 쌓여(stack) 하나의 이미지를 형성하며, **이미지는 읽기 전용(read-only)**.

### 이미지(읽기 전용) vs 컨테이너(읽기-쓰기)
- 이미지는 읽기 전용이므로 그 자체로는 수정할 수 없음.
- 이미지를 실행해 컨테이너를 만들면, 읽기 전용 레이어 위에 **읽기-쓰기(read-write) 레이어**가 추가됨 — 이 읽기-쓰기 레이어가 바로 컨테이너.
- 이 읽기-쓰기 레이어 덕분에 애플리케이션 내부를 수정하거나, 로그를 남기거나, 모니터링을 수행하는 등 실행(running) 상태에서 필요한 작업이 가능해짐 — 읽기 전용 상태로는 이런 작업을 할 수 없기 때문.

## 요약
- Dockerfile은 베이스 이미지·의존성·설정을 정의하는 지시문들의 모음이며, 각 지시문은 이미지의 레이어 하나가 되어 읽기 전용 이미지를 구성하고, 그 이미지를 실행해 만든 컨테이너는 읽기 전용 레이어 위에 읽기-쓰기 레이어를 추가한 형태로 동작한다.
