# Multistage Dockerfile Builds

## 개요
- 이미지 크기와 보안 문제를 해결하는 Multistage Dockerfile Build의 개념, 이점, 구조, 기술 스택별 사용 사례, 베스트 프랙티스와 흔한 실수를 정리.

## 내용
### 왜 Multistage Build가 필요한가
- 전통적인 단일 단계(Single-stage) Dockerfile은 소스 코드, 빌드 도구, 의존성을 모두 최종 이미지에 포함시켜 이미지가 비대해지고, Pull 속도가 느려지며, 공격 표면(attack surface)이 커짐.
- **Multistage Build**는 Dockerfile을 여러 단계(Stage)로 나누어, 빌드 도구·의존성은 중간 단계에만 포함시키고 **최종 단계에는 실행에 꼭 필요한 런타임 구성 요소만** 남김 — 더 가볍고 안전한 프로덕션용 컨테이너를 만듦.

### Multistage Build가 중요한 이유
1. **이미지 크기 축소** — 불필요한 파일·의존성을 제거해 이미지 크기를 90% 이상 줄이는 경우도 많음 — 전송·배포가 빨라져 CI/CD 파이프라인에 이상적.
2. **보안 강화** — 컴파일러, 디버깅 도구, 패키지 매니저를 최종 이미지에서 제외해 공격 표면을 줄이고 취약점을 감소.
3. **CI/CD 효율성** — 각 단계를 개별적으로 캐싱 가능 — 의존성이 거의 바뀌지 않는다면 캐싱으로 빌드 시간을 크게 단축.
4. **유지보수 용이성** — 단계가 명확히 분리되어 있어 한 단계의 도구·코드를 업데이트해도 다른 단계에 영향을 주지 않아 보일러플레이트와 복잡성이 줄어듦.

### Multistage Dockerfile의 구조
- **Build Stage(빌더 단계)** — 애플리케이션을 컴파일하기 위한 빌드 도구와 의존성을 포함.
- **Runtime Stage(런타임 단계)** — Alpine이나 Scratch 같은 경량 이미지에 애플리케이션 바이너리만 포함하고 빌드 도구는 모두 제외.

### 기술 스택별 사용 사례
- **컴파일 언어(Go, C/C++, Rust)** — 전체 SDK 이미지로 빌드한 뒤, 컴파일된 바이너리만 `scratch`나 distroless 같은 최소 런타임 이미지로 복사.
- **인터프리터 언어(Node.js, Python, Java)** — 한 단계에서 빌드·번들링을 수행하고, 프로덕션에 필요한 결과물(예: Node 빌드 산출물, 패키징된 `.jar`)만 전달.
- **프론트엔드 앱(React, Angular, Vue)** — 빌드 단계에서 `npm build` 등을 실행하고, 최종 단계에서는 Nginx 같은 경량 이미지로 정적 파일만 서비스.

### 베스트 프랙티스·최적화 전략
- **설명적인 단계 이름 사용** — `AS builder`, `AS test`처럼 이름을 붙여 가독성 향상.
- **적절한 베이스 이미지 선택** — 빌드에는 SDK가 풍부한 이미지, 프로덕션에는 Alpine/Scratch/Distroless 같은 최소 이미지.
- **캐싱 활용** — `package.json`, `requirements.txt` 같은 정적 의존성 파일을 빌드 초반에 복사해 캐싱 효율 극대화.
- **레이어 최소화** — 관련된 `RUN` 명령을 병합하고 `.dockerignore`로 불필요한 파일을 빌드 컨텍스트에서 제외.
- **중간 산출물 테스트** — `docker build --target=<단계>`로 특정 단계만 빌드·디버깅해 정확성을 확인하고 트러블슈팅 속도를 높임.
- **CI/CD 최적화** — 정적 의존성 재사용을 극대화하도록 단계 순서를 재배치.

### 흔한 실수와 회피 방법
- **의도치 않은 파일 복사** — `.dockerignore`에 나열되지 않은 큰 파일들이 이미지를 비대하게 만들 수 있음.
- **경로 불일치** — `COPY --from=<단계>`가 올바른 소스 경로를 사용하도록 확인해 파일 누락이나 빌드 실패를 방지.
- **과도하게 복잡한 단계** — 불필요한 단계를 검토·제거해 명확성 유지.
- **비효율적인 재빌드** — 캐시 활용을 최적화하도록 단계 순서를 재배치하고, `dockerfile-lint`나 `hadolint` 같은 도구로 Dockerfile 구조를 분석·개선.

## 요약
- Multistage Build는 빌드 로직과 런타임 로직을 분리해 이미지 크기를 대폭 줄이고(최대 90%+) 공격 표면을 줄이며 CI/CD 빌드 속도와 유지보수성을 개선하는 핵심 기법으로, 언어별 최적 패턴(컴파일 언어는 바이너리만 복사, 인터프리터 언어는 프로덕션 산출물만 전달, 프론트엔드는 정적 파일만 서비스)과 캐싱·`.dockerignore`·단계 이름 지정 같은 베스트 프랙티스를 함께 적용해야 프로덕션 품질의 컨테이너화를 달성할 수 있다.
