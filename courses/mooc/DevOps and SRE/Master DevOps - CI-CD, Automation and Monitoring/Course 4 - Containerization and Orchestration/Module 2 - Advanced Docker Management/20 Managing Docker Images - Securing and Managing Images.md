# Managing Docker Images - Securing and Managing Images

## 개요
- Docker 이미지를 안전하고 효율적으로 관리하기 위한 버전 관리, 취약점 스캔(Docker Scout), 비루트 실행, 최소 권한 원칙, Multi-stage Build를 정리.

## 내용
### 버전 관리(Versioning)
- 커스텀 애플리케이션을 매일 빌드한다면 월요일에 `v1`, 화요일에 코드가 바뀌면 `v2`, 수요일에 또 바뀌면 `v3`처럼 버전을 붙여 Docker Hub에 업로드 — Docker Hub는 여러 버전을 동시에 유지·관리 가능(이미지 버전을 고정(pin)할 수도 있음).

### 취약점 스캔(Vulnerability Scanning)
- **취약점(Vulnerability)** — 애플리케이션에 노출된 허점으로, 해커가 침입해 애플리케이션을 손상시키거나 데이터를 탈취할 수 있는 지점.
- Docker Hub는 **Docker Scout** 같은 기능을 제공해 이미지에 취약점이 있는지 스캔 가능.

### 비루트(Non-root) 사용자로 컨테이너 실행
- 컨테이너를 root 권한으로 실행하면 누군가 컨테이너에 접근했을 때 임의로 변경을 가할 위험이 커짐 — 항상 **비루트 사용자로 컨테이너를 실행**하는 것이 좋음. 그러면 컨테이너에 접근하더라도 제한된 권한만 가지게 됨.

### 최소 권한 원칙(Principle of Least Privilege)
- 이미지 안에는 애플리케이션과 그 의존성만 최소한으로 포함 — 이미지를 만드는 사용자나 컨테이너를 시작하는 사용자 모두 **최소한의 권한**만 갖도록 함.

### Multi-stage Build(멀티 스테이지 빌드)
- 하나의 Dockerfile에 여러 개의 `FROM` 문을 사용해, 한 단계(Stage)의 산출물을 다른 단계의 입력으로 사용하는 방식.
- 예: 애플리케이션을 컴파일하는 단계를 별도 이미지로 두고, 컴파일된 결과물만 최종(빌더) 이미지로 가져오면 불필요한 빌드 도구·패키지가 최종 이미지에서 빠져 **이미지 크기를 크게 줄일 수 있음**.
- 컴파일 산출물만 필요한데 전체 빌드 환경(컴파일러, 빌드 도구 등)까지 최종 이미지에 포함시키면 이미지 크기가 불필요하게 커지는 문제를 해결.

### 종합 정리
- 이미지 보안·관리는 다음 원칙들을 함께 따라야 함:
  1. 최소한의 베이스 이미지 사용.
  2. 이미지 버전 고정(Pinning).
  3. Docker Scout 등으로 취약점 스캔.
  4. 컨테이너를 비루트로 실행.
  5. 최소 권한 원칙 적용.
  6. Multi-stage Build로 이미지 크기 최적화.

## 요약
- Docker 이미지를 안전하고 효율적으로 관리하려면 명확한 버전 관리, Docker Scout를 이용한 취약점 스캔, 비루트 사용자 실행, 최소 권한 원칙, 그리고 불필요한 빌드 도구를 최종 이미지에서 제외하는 Multi-stage Build를 함께 적용해야 한다.
