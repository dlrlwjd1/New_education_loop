# What are Pods

## 개요
- Kubernetes의 최소 배포 단위인 Pod의 정의, Pod가 캡슐화하는 3가지 요소(컨테이너·볼륨·네트워킹), 그리고 Single-container Pod와 Multi-container Pod의 차이를 정리.

## 내용
### Pod란
- Kubernetes가 생성·관리하는 **가장 작은 배포 단위(Smallest Deployable Unit)** — 클러스터에 속한 노드 위에서 실행됨.
- Pod는 하나 이상의 컨테이너 그룹을 나타내며, 같은 노드에 함께 위치(co-located)한 컨테이너들이 리소스(스토리지, 네트워킹, IP 주소)를 공유.

### Pod가 캡슐화하는 3가지 요소
1. **컨테이너(Containers)** — 애플리케이션과 그 의존성이 실행되는 컴퓨트 런타임 제공.
2. **볼륨(Volumes)** — 데이터 저장·지속성을 위한 스토리지.
3. **네트워킹(Networking)** — IP 주소는 Pod 단위로 할당되며, 그 Pod 안의 모든 컨테이너가 이 IP를 공유.

### 개념 예시
- Pod 1(IP `10.10.10.1`) — 컨테이너 1개.
- Pod 2(IP `10.10.10.2`) — 컨테이너 2개, 같은 IP 주소를 공유.
- Pod 3(IP `10.10.10.3`) — 컨테이너 3개(볼륨 1개 포함).
- Pod 4(IP `10.10.10.4`) — 컨테이너 5개.
- 이 모든 Pod는 하나의 Node(Worker Node/VM) 경계 안에서 실행되며, 각 Pod는 고유한 자신만의 IP 주소를 가짐.

### Pod의 종류
1. **Single-container Pod** — Pod 안에 컨테이너가 하나뿐. 독립적인(standalone) 애플리케이션, 단순하고 작은 마이크로서비스에 적합. 설정·관리가 단순함.
2. **Multi-container Pod** — Pod 안에 여러 컨테이너가 있음. 메인 애플리케이션과 함께 캐싱, 로그 저장, 보안(예: 키 주입, 인증서 주입) 같은 **헬퍼(사이드카) 컴포넌트**가 필요한 복잡한 애플리케이션에 적합. 컨테이너 간 상호작용 등 설정·관리가 더 복잡함.

### 리소스 공유와 복잡도
- **리소스 공유** — Pod에 할당된 모든 리소스(스토리지, 네트워킹)는 그 Pod 안의 컨테이너들이 함께 사용.
- **복잡도** — Single-container Pod는 설정·관리가 단순하지만, Multi-container Pod는 여러 컨테이너의 설정과 상호작용을 다뤄야 해 더 복잡하고 도전적임.
- 예시: Single-container — 웹 서버, 데이터베이스. Multi-container — 로깅이 붙은 웹 서버, 캐싱이 붙은 웹 서버, 사이드카 헬퍼가 붙은 메인 애플리케이션.

## 요약
- Pod는 Kubernetes의 최소 배포 단위로 컨테이너(컴퓨트)·볼륨(스토리지)·네트워킹(IP)을 하나로 캡슐화하며, 컨테이너가 하나뿐인 Single-container Pod는 단순한 독립 애플리케이션에, 캐싱·로깅·보안 같은 헬퍼 컴포넌트가 필요한 Multi-container Pod는 복잡한 애플리케이션에 적합하다.
