# What is Kubernetes - Introduction

## 개요
- Kubernetes의 정의와 역사, 그리고 물리 서버 → 가상화 → 컨테이너로 이어지는 인프라 배포 방식의 발전 과정을 정리.

## 내용
### Kubernetes란
- 컨테이너화된 애플리케이션의 배포·확장·관리를 위한 **컨테이너 오케스트레이터**.
- 단일 서버에 Docker만 설치해 컨테이너를 운영하면 고가용성이나 장애 허용을 얻을 수 없음 — 이를 해결하려면 오케스트레이터가 필요하며, 그중 가장 널리 쓰이는 오픈소스 플랫폼이 Kubernetes.

### 역사
- Google이 개발했으며, 2014년 **CNCF(Cloud Native Computing Foundation)**에 기증되어 오픈소스가 됨.
- 2014년 9월 Kubernetes 1.0 출시 — 현재 약 11년의 역사를 가진 프로젝트.
- CNCF는 Kubernetes 외에도 Calico, etcd, Prometheus 등 여러 프로젝트를 관리하는 전 세계 개발자 커뮤니티.

### 인프라 배포 방식의 발전
1. **전통적 환경(Bare Metal)** — 물리 서버(CPU, RAM, NIC 등)에 OS(Linux/Windows)를 설치하고 그 위에 애플리케이션을 직접 배포.
2. **가상화 환경(Virtualized)** — 하드웨어 위에 하이퍼바이저(VMware ESXi, Citrix XenServer, KVM 등)를 설치해 여러 VM을 생성. 각 VM은 원하는 크기(CPU, RAM)로 만들 수 있으며 각자 독립적인 OS·바이너리·라이브러리·애플리케이션을 가짐. 단점: OS를 여러 개 유지·관리해야 해 비용이 크고, VM을 여러 애플리케이션이 공유하기 어려움.
3. **컨테이너 환경** — 하드웨어 위에 OS를 설치하고 그 위에 Docker, CRI-O, Podman 같은 컨테이너 런타임을 설치, 그 위에서 여러 컨테이너 실행. **컨테이너는 OS를 자체적으로 갖지 않고 Base 머신의 OS를 공유** — 각 컨테이너는 애플리케이션과 그에 필요한 라이브러리·바이너리·프레임워크만 포함.

### 컨테이너의 장점
- OS를 포함하지 않아 **경량(lightweight)**이며, 배포·관리·유지보수가 쉽고 개발자 친화적.
- VM을 만들고 OS를 설치하는 번거로움 없이, 이미지만 있으면 몇 분 안에 애플리케이션을 실행 가능.
- 이렇게 물리 서버 → 가상 서버 → 컨테이너로 인프라 배포 방식이 발전해왔으며, 현재는 컨테이너 배포로 더욱 무게 중심이 옮겨가고 있음.

## 요약
- Kubernetes는 Google이 개발해 2014년 CNCF에 기증한 오픈소스 컨테이너 오케스트레이터로, 물리 서버(Bare Metal) → 하이퍼바이저 기반 가상화(VM) → OS를 공유하는 경량 컨테이너로 이어지는 인프라 배포 방식의 발전 흐름 속에서, 컨테이너의 고가용성·장애 허용을 제공하기 위해 등장했다.
