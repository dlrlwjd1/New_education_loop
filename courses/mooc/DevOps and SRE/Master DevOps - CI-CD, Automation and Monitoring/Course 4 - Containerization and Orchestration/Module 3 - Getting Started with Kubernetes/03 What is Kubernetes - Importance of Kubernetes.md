# What is Kubernetes - Importance of Kubernetes

## 개요
- Kubernetes가 필요한 이유(자동 배포·확장, 서비스 디스커버리·로드밸런싱, 셀프 힐링)와, Kubernetes가 "아닌 것"이 무엇인지 정리.

## 내용
### Kubernetes가 필요한 이유
1. **자동화된 배포와 확장(Automated Deployment and Scaling)**
   - 예: MySQL 컨테이너의 CPU 사용률이 70%를 넘으면 Kubernetes에 "스케일 업" 요청 → 자동으로 컨테이너 2개를 추가 배포해 총 3개의 컨테이너가 부하를 분산 처리.
   - CI/CD 파이프라인으로 Kubernetes 인프라에 애플리케이션을 배포할 수 있어 배포 프로세스와 수요 기반 자동 확장을 단순화.
2. **서비스 디스커버리와 로드밸런싱(Service Discovery and Load Balancing)**
   - 새로 배포된 컨테이너에 **자동으로 IP 주소가 할당**되고, 사용자 트래픽이 여러 컨테이너에 자동으로 로드밸런싱됨 — 수동 개입 없이 안정적인 배포 유지.
3. **셀프 힐링(Self-healing)**
   - 예: MySQL 컨테이너를 1개에서 3개로 스케일했는데 그중 하나가 실수로 죽으면, Kubernetes가 **자동으로 컨테이너를 재생성**해 항상 3개를 유지 — 고가용성뿐 아니라 장애로부터 자동 복구(Fault Tolerance)까지 제공.
   - 실패한 컨테이너를 자동으로 재시작·교체하고 리소스 관리를 최적화.

### Kubernetes가 아닌 것
1. **전통적인 PaaS(Platform as a Service) 시스템이 아님** — 전통적인 PaaS는 로드밸런싱·서비스 디스커버리·자동 확장을 수동으로 해야 하지만, Kubernetes는 이런 기능을 자동으로 제공하는 더 발전된 플랫폼.
2. **완전한 솔루션이 아님(단지 컨테이너 관리 도구)** — 컨테이너를 실행하려면 이미지가 필요한데, 그 **이미지 빌드는 Kubernetes의 역할이 아님**(Docker build나 BuildX 같은 별도 도구 필요). Kubernetes는 오직 컨테이너화된 애플리케이션의 관리·실행, 고가용성·장애 허용 제공에 집중.
3. **소규모 배포 전용이 아님** — 테스트, 스테이징, 비프로덕션, 프로덕션 등 모든 환경에 적합하며, 실제로 기업들은 노드 2개짜리부터 수천 노드 규모의 거대한 Kubernetes 클러스터까지 다양하게 운영.

## 요약
- Kubernetes는 CPU 임계치 기반 자동 확장, 자동 IP 할당과 로드밸런싱, 실패한 컨테이너의 자동 재생성(셀프 힐링)을 제공하는 컨테이너 오케스트레이터이지만, 전통적인 PaaS나 완전한 솔루션이 아니라 컨테이너 이미지 빌드는 별도 도구에 맡기고 컨테이너 관리·고가용성·장애 허용에만 집중하며, 소규모부터 수천 노드 규모까지 모든 환경에 적용 가능하다.
