# Introduction to Version Control

## 개요
- 버전 관리(Version Control)의 정의와 Tom/John/Sarah 시나리오를 통한 필요성, 이점, 대표 도구를 소개.

## 내용
### 버전 관리란
- 코드와 파일의 변경사항을 추적·관리하는 시스템. Source Control, Revision Control이라고도 부르며 Source Code Management와 밀접하게 연결된다.
- 여러 개발자가 서로의 작업을 덮어쓰지 않고 동시에 개발할 수 있게 한다.

### 시나리오: Tom, John, Sarah
- DevOps 엔지니어 Tom, 리드 개발자 John, CTO Sarah가 있는 조직에서 주요 업데이트 후 앱이 크래시.
- 버전 관리가 없어 누가 마지막으로 무엇을 바꿨는지, 어떻게 롤백할지 알 수 없어 위기 상황 발생.
- Tom: 버전 관리가 있었다면 안정 버전으로 즉시 롤백하고 몇 분 안에 문제 코드를 식별할 수 있었을 것이라 설명.
- 도입 후: 버그 수정이 빨라지고 테스트가 안전해졌으며 서로의 작업을 덮어쓰는 일이 사라짐.

### 버전 관리 없이 겪는 문제
- 같은 파일 작업 시 서로의 변경을 덮어써 작업 손실
- 변경 추적 불가로 누가·언제·왜 바꿨는지 알 수 없어 혼란
- 새 기능/버그 수정을 메인 프로젝트에 영향 없이 독립적으로 테스트할 안전한 방법 부재

### 버전 관리의 이점
1. **협업** — 여러 개발자가 체계적으로 기여를 병합
2. **변경 추적** — 모든 수정이 기록되어 검토·되돌리기 용이
3. **가역성(Reversibility)** — 새 기능이 시스템을 깨면 이전 안정 버전으로 되돌림
4. **브랜칭과 머징** — 독립된 브랜치에서 개발 후 테스트를 거쳐 안전하게 병합
5. **백업과 복구** — 실패해도 버전 관리 이력에서 프로젝트 전체 복구 가능
6. **책임 추적성** — 누가 어떤 변경을 했는지 명확한 로그로 확인
7. **개선된 워크플로우** — 자동 빌드·코드 리뷰·테스트 프로세스 지원
8. **확장성(Scalability)** — 팀·코드베이스가 커져도 협업 속도 저하 없이 처리

### 대표 도구
- **Git** — 오픈소스, 가장 널리 쓰임, 이력 관리·브랜칭·협업을 매끄럽게 지원
- **SVN(Subversion)** — 오래됐지만 여전히 존중받는 중앙집중형 버전 관리 시스템
- **Mercurial** — Git과 유사한 분산형, 일부 오픈소스 커뮤니티에서 인기

## 요약
- 버전 관리는 협업·변경 추적·가역성·브랜칭·백업·책임 추적성·워크플로우 개선·확장성이라는 8가지 이점을 제공하며, Git이 이를 구현하는 가장 대표적인 도구다.
