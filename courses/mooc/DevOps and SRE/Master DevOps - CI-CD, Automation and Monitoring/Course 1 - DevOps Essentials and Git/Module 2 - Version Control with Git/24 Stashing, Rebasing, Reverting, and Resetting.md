# Stashing, Rebasing, Reverting, and Resetting

## 개요
- Git의 4가지 핵심 조작 — Stash(임시 저장), Rebase(재적용), Revert(안전한 되돌리기), Reset(이력 재작성)을 설명.

## 내용
### Git Stash
- 커밋하지 않은 작업을 임시로 저장해두고 안전하게 브랜치를 전환할 수 있게 한다.
- 숙제를 마치지 않은 채 사물함에 넣어두고 다른 수업에 갔다가 나중에 이어서 하는 것과 유사.

```bash
git stash        # 추적 중인 파일 변경사항을 임시 저장
git stash -u      # 추적되지 않은(untracked) 새 파일까지 포함
git stash -a      # 무시된(ignored) 파일까지 포함해 완전히 클린한 워크스페이스로
```

### Rebase (재적용)
- 브랜치의 커밋을 다른 브랜치(주로 master)의 최신 이력 위에 다시 적용해 별도 머지 커밋 없이 깔끔하고 선형적인(linear) 이력을 만든다.
- 공유 보고서를 마지막에 그냥 덧붙이는 게 아니라 논리적으로 재구성하는 것과 유사.

```bash
git rebase master   # feature 브랜치를 master 위로 재적용
```

### Revert (안전한 되돌리기)
- 특정 커밋을 이력에서 지우지 않고, 그 변경을 되돌리는 새로운 커밋을 만든다.
- 공개(public) 브랜치에서 안전 — 팀 전체가 실수와 수정 모두를 감사(audit) 가능한 형태로 볼 수 있다.

```bash
git revert <커밋해시>
```

### Reset (이력 재작성 — 파괴적일 수 있음)
- HEAD, 스테이징 영역, 작업 디렉터리 세 영역에 영향을 줄 수 있으며, 모드에 따라 결과가 다르다.

| 모드 | 영향 범위 | 설명 |
|---|---|---|
| `git reset --soft` | HEAD만 이동 | 작업 파일·스테이징은 그대로, 마지막 커밋만 다시 하고 싶을 때 |
| `git reset --mixed` (기본값) | HEAD 이동 + 스테이징 초기화 | 실제 파일 내용은 유지 |
| `git reset --hard` | HEAD 이동 + 스테이징 초기화 + 작업 디렉터리 변경사항 삭제 | ⚠️ 파괴적 — 백업 없으면 파일이 영구 손실됨 |

## 요약
- Stash는 미완성 작업을 잠시 치워두고, Rebase는 이력을 깔끔한 선형으로 재정렬하며, Revert는 이력을 보존하면서 안전하게 되돌리고, Reset(특히 `--hard`)은 이력 자체를 지우는 파괴적인 도구이므로 신중하게 사용해야 한다.
