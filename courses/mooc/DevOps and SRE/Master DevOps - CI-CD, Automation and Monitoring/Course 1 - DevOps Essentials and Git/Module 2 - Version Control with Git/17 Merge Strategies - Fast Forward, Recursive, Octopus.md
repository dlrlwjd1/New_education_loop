# Merge Strategies - Fast Forward, Recursive, Octopus

## 개요
- Git이 브랜치를 병합할 때 사용하는 3가지 전략(Fast-forward, Recursive, Octopus)의 원리와 사용 시점을 설명.

## 내용
### Fast-forward Merge
- 병합할 브랜치가 현재 브랜치보다 그냥 앞서 있기만 하고 분기(divergence)가 없을 때 사용하는 가장 단순한 전략.
- Git이 브랜치 포인터를 병합 대상 브랜치의 최신 커밋으로 그냥 이동시킬 뿐, 별도의 병합 커밋을 만들지 않는다.
- 책을 페이지 건너뛰지 않고 순서대로 읽는 것과 같다 — 프로젝트 이력이 선형(linear)적으로 깔끔해진다.
- 병렬 작업이 없었을 때 사용되며, 사소한 기능 추가나 빠른 수정에 흔히 쓰인다. 다만 브랜칭 기록이 남지 않으므로, 필요하면 fast-forward가 가능해도 일부러 병합 커밋을 만들기도 한다.

### Recursive Merge (Git 기본 전략)
- 두 브랜치가 분기해 각자 독립적으로 커밋을 만들었을 때 사용하는 Git의 기본(default) 병합 전략.
- 두 팀원이 각각 책의 다른 챕터를 쓴 뒤 합치는 것과 유사 — 양쪽 브랜치의 변경사항을 결합하는 **병합 커밋(merge commit)**을 생성해 전체 이력을 보존한다.
- 병렬 개발이 일상적인 중~대규모 팀에서 필수적인 전략.

### Octopus Merge
- 두 개보다 많은 브랜치를 한 번에 병합할 때 사용.
- 서로 충돌하지 않는 여러 기능 브랜치를 한꺼번에 병합할 때 효율적 — 퍼즐 조각을 하나씩이 아니라 여러 개를 동시에 맞추는 것과 유사.
- 충돌이 있는 브랜치에는 적합하지 않다 — 충돌이 있으면 Git이 멈추고 수동 개입을 요구한다.
- 여러 개의 깔끔하고 충돌 없는 브랜치를 다룰 때 유용한 특화된(specialized) 전략.

## 요약
- 분기가 없으면 Fast-forward(단순 이동), 분기가 있으면 Recursive(병합 커밋 생성), 충돌 없는 여러 브랜치를 한번에 합칠 땐 Octopus를 사용하며, Git은 브랜치 이력과 개수에 따라 자동으로 적절한 전략을 선택한다.
