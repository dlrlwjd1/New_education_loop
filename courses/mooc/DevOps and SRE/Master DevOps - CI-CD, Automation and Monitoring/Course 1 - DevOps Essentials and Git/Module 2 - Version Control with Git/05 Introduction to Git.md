# Introduction to Git

## 개요
- Git의 정의, 이점, 핵심 구성요소, 기본 워크플로우, DevOps에서의 역할을 소개.

## 내용
### Git이란
- 오픈소스 분산 버전 관리 시스템(distributed VCS). 코드 변경을 추적하고 여러 개발자가 충돌 없이 협업하도록 지원.
- SVN, Mercurial 등과 비교해 가장 인기 있는 버전 관리 도구로 자리잡음.

### Git의 이점
1. **통합(Integration)** — GitHub, GitLab, Jenkins, 클라우드 서비스와 쉽게 연동
2. **분산(Distribution)** — 모든 개발자가 프로젝트 전체 사본 보유
3. **효율적인 브랜칭·머징** — 독립적으로 개발 후 준비되면 병합
4. **고성능** — 대형 저장소도 빠른 commit/pull/push 처리
5. **강력한 커뮤니티 지원**
6. **유연성** — 소규모 스크립트부터 대규모 엔터프라이즈 시스템까지 관리

### 핵심 구성요소
- **Working Directory** — 로컬에서 프로젝트 파일을 편집하는 폴더
- **Staging Area(Index)** — 커밋 전 파일을 준비하는 공간
- **Local Repository** — `.git` 폴더 안에 프로젝트의 모든 이력 저장
- **Remote Repository** — GitHub/GitLab 등에 호스팅되어 여러 위치의 개발자와 연결
- **Branch** — 메인 프로젝트를 건드리지 않고 독립적으로 기능/수정/실험 진행
- **Tag** — 릴리스 등 프로젝트 이력의 특정 지점을 표시
- **Commit** — 특정 시점의 프로젝트 스냅샷(무엇이·왜 바뀌었는지 기록)
- **HEAD** — 현재 작업 중인 브랜치/커밋을 가리키는 포인터

### 기본 워크플로우

```bash
git init      # 로컬 Git 저장소 초기화
git add .     # 변경된 파일을 스테이징 영역으로 이동
git commit -m "메시지"   # 스테이징된 변경을 로컬 저장소에 저장
git push      # 로컬 커밋을 원격 저장소로 업로드
```

### DevOps에서 Git의 역할
- 소스 코드 관리의 중심 허브로서 변경 추적·협업·자동화 워크플로우 트리거를 담당.
- CI/CD와 통합해 커밋 시 빌드·테스트·배포를 자동화, 딜리버리 속도를 높이고 수동 오류를 줄임.
- 강력한 롤백(rollback) — 배포 문제 발생 시 Git에 저장된 이전 안정 버전으로 신속 복귀.
- 버저닝(versioning) — 모든 기능·버그 수정을 태그·기록해 릴리스 추적과 핫픽스 관리를 용이하게 함.

## 요약
- Git은 Working Directory→Staging→Local Repo→Remote Repo로 이어지는 흐름을 통해 협업·이력 추적·롤백을 가능하게 하며, CI/CD와 결합해 현대 DevOps 파이프라인의 중심 허브 역할을 한다.
