# Scenario - Importance of Version Control

## 개요
- 전 세계로 확장한 조직의 사례를 통해 버전 관리(version control) 없이 겪는 문제와 도입 후 이점을 설명.

## 내용
### 조직 확장 시나리오
- 중앙집중형 팀에서 전 세계에 분산된 대규모 팀·오픈소스 기여자 그룹으로 성장하며 새로운 복잡성이 발생.

### 버전 관리 없이 겪는 문제
- **협업 조정의 어려움** — 시간대·언어·업무 문화가 다른 팀 간 코드 변경 추적·병합·관리가 힘들어짐. 고립된 개발로 코드 충돌·중복·낭비 발생.
- **버전 동기화 문제** — 라이브러리·브라우저·도구 버전을 통일하기 어려워 시스템 간 사소한 차이가 버그·불안정성을 유발.
- **배포 지연** — 중앙화된 시스템 없이 수동으로 조정해야 해 배포가 느리고 불안정.
- **느린 롤백** — 문제 발생 시 이전 안정 상태로 복원하는 데 시간이 오래 걸려 시간과 평판 모두 손실.
- **백업·데이터 저장 문제** — 데이터가 분산되어 실수나 장애에 취약, 강력한 백업 체계 부재로 소중한 코드·작업 이력을 영구히 잃을 위험.

### 버전 관리 없이 발생하는 핵심 이슈 요약
1. 팀원이 서로의 작업을 쉽게 덮어씀 (백업 없이는 영구 손실)
2. 변경 추적이 안 되면 누가 무엇을 바꿨는지 알 수 없어 책임 소재 불분명
3. 브랜칭·버저닝 없이는 협업이 혼란스러워지고 안전하게 실험할 방법이 없음

### 버전 관리 시스템 도입 후
- 독립적인 개발 — 여러 개발자가 동시에 기능을 개발하고 쉽게 병합
- 저장소를 로컬에 클론해 오프라인 작업 후 안전하게 동기화 — 중앙 서버 의존도 감소
- 개선된 버저닝·리뷰 시스템·협업으로 내부/외부 기여자의 구조화된 기여 가능

### 버전 관리가 필요한 이유
1. **변경 추적** — 모든 수정 이력을 기록해 검토·되돌리기 가능
2. **협업** — 여러 팀원이 동시에 다른 부분을 작업해도 서로 방해하지 않음
3. **백업과 복구** — 문제 발생 시 이전 안정 버전으로 복원하는 안전망
4. **실험과 브랜칭** — 메인 프로젝트를 건드리지 않고 새 기능을 시도, 준비되면 안전하게 병합
5. **책임 추적성(Accountability)** — 누가·언제·왜 변경했는지 상세 로그로 투명성 확보

## 요약
- 버전 관리 없이 조직이 커지면 협업·동기화·배포·백업 전방위에서 문제가 발생하며, 버전 관리 시스템 도입은 변경 추적·협업·백업·실험·책임 추적성이라는 5가지 핵심 가치를 제공한다.
