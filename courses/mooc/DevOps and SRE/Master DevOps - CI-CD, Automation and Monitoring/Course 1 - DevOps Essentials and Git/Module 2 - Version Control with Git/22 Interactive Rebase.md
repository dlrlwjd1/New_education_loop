# Interactive Rebase

## 개요
- 커밋 이력을 세밀하게 수정할 수 있는 Interactive Rebase 기능과 사용 시 주의사항을 설명.

## 내용
### Interactive Rebase란
- 커밋을 단순히 재생(replay)하는 게 아니라 편집(edit)·스쿼시(squash)·재정렬(reorder)·삭제(delete)까지 가능한 Git 기능.
- 공유하기 전에 프로젝트 이력을 더 깔끔하고 논리적으로 만들 수 있다.
- 문법: `git rebase -i <커밋ID>` — 여기서 `<커밋ID>`는 수정하고 싶은 커밋 범위 바로 이전 커밋의 해시.

### 주요 기능
- **커밋 메시지 수정** — 예전에 제대로 못 쓴 메시지를 지금 고침
- **원치 않는 커밋 삭제** — 중복 코드나 미완성 실험이 담긴 커밋 제거
- **여러 커밋 스쿼시(squash)** — 관련된 작은 변경들을 하나의 깔끔한 커밋으로 합침(문서의 여러 작은 수정을 최종 한 문단으로 합치는 것과 유사)
- **커밋 재정렬(reorder)** — 논리적인 기능 단계 순서로 재배열
- **오래된 커밋 수정(fix)** — 이전 실수를 처음부터 다시 하지 않고 수정
- **커밋 분할(split)** — 크고 지저분한 커밋을 의미 있는 작은 커밋들로 나눔

### 사용 시 주의사항
1. **공개(public) 브랜치에는 절대 사용 금지** — 이미 push되어 다른 사람이 쓰고 있는 브랜치의 이력을 바꾸면 큰 혼란과 동기화 문제 발생
2. **원본 이력을 보존해야 하는 경우 피할 것** — 금융·헬스케어처럼 커밋이 법적 기록 역할을 하는 산업에서는 컴플라이언스 문제 유발 가능
3. **대규모 팀의 공유 브랜치에서는 위험** — 이력을 다시 쓰면 팀 전체에 고통스러운 머지 충돌과 혼란 야기
4. **Git을 완전히 이해하지 못했다면 사용하지 말 것** — 리베이스 중 실수하면 복구가 복잡해지고 브랜치 전체를 리셋해야 할 수도 있음
5. 아무도 이전 커밋 이력에 의존하지 않는다는 확신이 있을 때만 신중하게 사용

## 요약
- Interactive Rebase는 커밋을 편집·스쿼시·재정렬·삭제·분할할 수 있는 강력한 도구지만, 이미 공유된(public) 브랜치의 이력을 바꾸면 팀 전체에 혼란을 줄 수 있어 오직 자신만 사용하는 로컬/개인 브랜치에서 신중히 써야 한다.
