# Branching and Merging in Git

## 개요
- 브랜칭(Branching)과 머징(Merging) 개념, 그리고 master 브랜치를 중심으로 한 협업 흐름을 설명.

## 내용
### 브랜칭(Branching)
- 메인 코드베이스에 영향을 주지 않고 새 기능·수정·실험을 독립적으로 작업할 수 있게 해준다.
- 병렬 개발(parallel development)과 격리된 테스트(isolated testing)를 가능하게 해 협업을 더 원활하게 만든다.
- `master`(또는 main)는 안정된 코드가 있는 메인 브랜치이며, 다른 브랜치는 기능 개발/버그 수정을 위해 별도로 생성된다.
- 예: 작은 기능은 master에서 브랜치를 따서 작업 후 테스트를 거쳐 다시 병합. 몇 주가 걸리는 큰 기능도 동일한 방식으로 독립 개발 후 안전하게 병합.

### 머징(Merging)
- 한 브랜치의 변경사항을 다른 브랜치(주로 master)에 통합하는 과정.
- 여러 기능 브랜치(branch 1, 2, 3)의 변경사항을 모아 master로 통합해 최종 버전을 만든다.
- 머징 완료 후 기능 브랜치의 작업은 master의 일부가 되며, 더 이상 필요 없는 기능 브랜치는 삭제해 저장소를 깔끔하게 유지할 수 있다.

## 요약
- 브랜칭은 독립적인 병렬 개발을, 머징은 완료된 작업을 메인 프로젝트로 통합하는 과정이며, 이 둘의 조합이 협업을 방해 없이 가능하게 하는 Git의 핵심 메커니즘이다.
