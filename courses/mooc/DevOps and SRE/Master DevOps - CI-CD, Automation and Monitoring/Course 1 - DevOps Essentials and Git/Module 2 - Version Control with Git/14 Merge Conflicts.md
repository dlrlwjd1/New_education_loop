# Merge Conflicts

## 개요
- 머지 충돌(merge conflict)이 발생하는 원인과 해결에 쓰이는 도구들을 설명.

## 내용
### 머지 충돌이란
- 두 브랜치가 같은 파일의 같은 부분을 서로 다르게 수정했을 때 Git이 어느 버전을 선택해야 할지 알 수 없어 발생.
- 예: 원본 3번째 줄이 `ijkl`인데, branch 1은 이를 `wxyz`로, branch 2는 `qrst`로 각각 수정 → 병합 시 Git이 충돌을 표시하고 자동으로 판단하지 않는다.
- 사람이 수동으로 어떤 버전을 유지할지 결정해야 한다.

### 충돌 해결 도구
- **내장(built-in) 도구**
  - `vimdiff` — 터미널에서 파일을 나란히(side-by-side) 비교
  - Emacs의 `Emerge` — 줄 단위로 대화형 충돌 해결
  - `tkdiff`, `diff3` — 시각적/텍스트 기반 비교
- **그래픽 서드파티 도구**
  - `tkdiff3` — 원본/내 변경/들어오는 변경을 보여주는 3-way merge 뷰
  - `Meld` — 사용이 쉽고 시각적으로 명확한 side-by-side 비교
  - `P4Merge` — 대형 프로젝트에서 강력한 시각화·해결 옵션 제공
  - VS Code 등 최신 에디터의 내장 Git 충돌 해결 UI — 클릭으로 섹션을 accept/reject 선택 가능

### 해결 절차
1. Git이 충돌을 표시하면 master 버전을 유지할지, 브랜치 버전을 유지할지, 또는 둘을 수동으로 합칠지 결정
2. 파일을 수정해 충돌을 해결
3. `git add`로 다시 스테이징
4. `git commit`으로 해결된 병합을 커밋해 완료

## 요약
- 머지 충돌은 같은 줄을 서로 다르게 고쳤을 때 발생하며, 내장 도구(vimdiff, Emerge)나 그래픽 도구(Meld, P4Merge, VS Code)로 충돌 부분을 확인해 수동으로 해결한 뒤 add→commit으로 마무리한다.
