# Types of Version Control System

## 개요
- Local, Centralized, Distributed 세 가지 버전 관리 시스템의 진화 과정과 각각의 한계를 설명.

## 내용
### 1. Local Version Control System (LVC)
- 가장 오래되고 단순한 형태 — 자신의 컴퓨터에서만 버전을 관리.
- `project_v1`, `project_v2`처럼 수동으로 백업 폴더를 여러 개 만드는 것과 유사.
- 문제: 여러 사람이 협업하려면 변경사항을 수동으로 병합해야 해 충돌이 거의 필연적으로 발생.

### 2. Centralized Version Control System (CVCS)
- 전체 코드베이스가 있는 중앙 서버에 개발자들이 접속해 변경사항을 내려받고 올림.
- 모두가 같은 공유 Google Drive 폴더에서 작업하는 것과 유사 — 조정이 쉬워짐.
- 문제: 중앙 서버가 다운되거나 손상되면 팀 전체가 접근을 잃고 작업을 잃을 수 있음.

### 3. Distributed Version Control System (DVCS)
- 모든 개발자가 최신 버전뿐 아니라 전체 이력을 포함한 프로젝트 전체 사본을 보유.
- 중앙 서버가 죽어도 어떤 개발자의 로컬 사본으로든 저장소를 복원할 수 있어 훨씬 회복력이 강함.
- 스페어키만 있는 게 아니라 집 전체의 완전한 백업을 갖고 있는 것과 유사.
- 개발자는 로컬에서 작업하고 오프라인으로 커밋한 뒤, 편할 때 원격 저장소로 푸시 — 원격·유연한 대규모 팀에 이상적.

## 요약
- 버전 관리는 Local(개인용) → Centralized(중앙 서버 의존) → Distributed(전체 이력을 각자 보유, 회복력↑)로 진화했으며, Git이 대표하는 분산형 모델이 오늘날 가장 널리 쓰이는 이유가 여기에 있다.
