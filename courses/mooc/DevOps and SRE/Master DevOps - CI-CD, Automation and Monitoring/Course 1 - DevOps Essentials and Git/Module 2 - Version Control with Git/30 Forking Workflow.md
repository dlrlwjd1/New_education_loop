# Forking Workflow

## 개요
- 오픈소스 세계에서 널리 쓰이는 Forking Workflow의 개념과 역할, 장점을 설명.

## 내용
### Forking Workflow란
- 각 개발자가 메인 프로젝트의 **자신만의 원격 사본(fork)**을 만들고, 그 사본에서 변경한 뒤 **Pull Request**로 반영을 제안한다.
- 오직 프로젝트 메인테이너(maintainer)만 공식 저장소에 변경사항을 승인·병합할 수 있다 — 통제는 중앙화되어 있지만 기여는 누구에게나 열려 있다.

### 장점
- **격리(Isolation)** — 각 개발자가 독립적으로 작업해 메인 코드베이스를 방해할 위험이 없다.
- **통제된 협업** — 메인테이너가 어떤 변경을 반영할지 결정해 프로젝트 품질을 일관되게 유지.
- **병렬 개발** — 여러 기여자가 동시에 각자의 fork에서 작업 가능, 서로를 막지 않음.
- **보안** — 기여자가 메인 저장소에 직접 쓰기 권한이 없어 악성/불안정한 코드 유입 위험 감소.
- **오픈소스에 이상적** — 누구나 fork·기여·개선 제안이 가능하지만 최종 반영 여부는 프로젝트 리드가 결정.

### 역할
- **공식 저장소(Official Repository)** — 프로젝트 리드가 관리, GitHub/GitLab에 호스팅
- **프로젝트 리드(Maintainer)** — 제출된 코드를 리뷰하고 승인된 변경을 병합, 프로젝트 방향을 이끔
- **개발자/기여자(Contributor)** — 프로젝트를 fork해서 기능을 만들거나 이슈를 고치고, 준비되면 Pull Request를 보냄

### 흐름
1. 각 협력자가 공식 저장소의 개인 fork 생성
2. 자신의 fork에서 독립적으로 작업 — 변경·커밋·테스트
3. 준비되면 Pull Request 제출
4. 메인테이너가 리뷰 후 병합 여부 결정 — 공식 저장소에는 오직 프로젝트 리드만 push 가능

## 요약
- Forking Workflow는 누구나 자유롭게 fork해서 기여하되 메인테이너만 공식 저장소를 통제하는 구조로, 오픈소스 프로젝트의 안전성과 개방성을 동시에 지켜준다.
