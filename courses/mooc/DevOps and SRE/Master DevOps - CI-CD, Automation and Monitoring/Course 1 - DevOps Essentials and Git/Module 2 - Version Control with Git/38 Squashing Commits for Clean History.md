# Squashing Commits for Clean History

## 개요
- 여러 개의 작은 커밋을 하나로 합쳐 깔끔한 프로젝트 이력을 만드는 Git Squash의 개념과 이점을 설명.

## 내용
### Git Squash란
- 개발 중 만든 여러 사소한/시험적 커밋들을 병합 전에 하나의 의미 있는 커밋으로 합치는 기법.
- 예: `fixed-typo`, `updated-spacing`, `adjusted-button` 같은 5개의 커밋 → `final login page design` 하나로 통합.

### 이점
1. **깔끔한 이력 유지** — 수십 개의 작은 커밋 대신 완성된 작업을 반영하는 하나의 정돈된 업데이트로 남는다.
2. **불필요한 노이즈 감소** — 불필요하거나 중복된 커밋으로 로그가 어지러워지는 것을 방지, 팀원이 변경을 리뷰·이해하기 쉬워짐.
3. **명확성 향상** — 작업을 하나의 의미 있는 업데이트로 제시할 수 있어 Pull Request 준비나 공유 코드베이스 기여 시 특히 유용.

### Before / After
- **스쿼시 전**: 기능을 만드는 동안의 여러 작업 중(work-in-progress) 커밋들이 뒤섞여 있어, 어떤 커밋이 실제로 기능을 완성했는지 리뷰어가 알기 어렵다.
- **스쿼시 후**: 중간 커밋들이 하나로 합쳐져 이력이 짧고 명확해지며, 코드 리뷰 시 팀에게 "무엇이 추가됐는지"에 대한 하나의 완전한 스냅샷을 제공한다.

## 요약
- Squash는 시행착오의 흔적인 여러 작은 커밋을 하나의 완성된 커밋으로 합쳐 이력을 깔끔하게 만들고, 협업과 코드 리뷰를 더 매끄럽게 만든다.
