# Submodules in Git

## 개요
- 하나의 Git 저장소를 다른 저장소 안에 포함시키는 Git Submodules의 개념, 사용 시점, 작동 방식, 베스트 프랙티스를 설명.

## 내용
### Submodule이란
- 한 프로젝트 안에 다른 프로젝트를 임베드하는 것과 유사 — 메인 저장소가 외부 라이브러리에 의존한다면 그 라이브러리를 서브모듈로 추가할 수 있다.
- 서브모듈은 자기만의 버전 이력을 가진 독립된 저장소이면서 메인 프로젝트 안에서 접근 가능하도록 연결되어 있다.
- 메인 저장소는 서브모듈의 파일을 전부 복사하지 않고, 서브모듈의 **특정 커밋에 대한 참조(pointer)**만 추적한다.

### 사용 시점
- 별도로 관리되는 외부 라이브러리/도구를 코드 복사 없이 포함시키고 싶을 때
- 공통 인증 모듈, UI 라이브러리 등 여러 코드베이스에서 공유하는 모듈을 쓰는 대규모 프로젝트
- 코드를 중복 없이 재사용하면서 독립적으로 버저닝하고 싶을 때

### 작동 방식
- 메인(부모) 저장소는 서브모듈의 커밋 해시(참조)만 저장하며, 전체 내용을 가져오지 않는다.
- 메인 저장소가 핵심(core) 역할을 하고, 서브모듈은 그 안의 독립적인 컴포넌트로 존재 — 코드베이스 간 책임 분리에 유용.
- 예: 핵심 제품 저장소가 클라이언트별 모듈을 서브모듈로 포함하면, 각 클라이언트 저장소는 서로 영향을 주지 않고 독립적으로 발전할 수 있다.
- 서브모듈은 필요에 따라 pull, update, 또는 특정 커밋에 고정(pin)할 수 있어 메인 저장소가 어느 버전을 추적할지 완전히 통제한다.

### 베스트 프랙티스
1. 서브모듈은 가볍게 유지 — 버저닝·공유가 중요할 때만 사용
2. 정기적으로 업데이트 — 오래된 코드로 작업하지 않도록 fetch/update 명령을 활용
3. 서브모듈을 직접 수정할 때 주의 — 여러 팀이 공유하면 다른 프로젝트에 영향을 줄 수 있음
4. 서브모듈 업데이트는 항상 부모 저장소에도 커밋 — 그렇지 않으면 팀원이 저장소를 체크아웃해도 정확한 서브모듈 버전을 놓칠 수 있음

## 요약
- Git Submodule은 외부/공유 코드를 복사 없이 커밋 참조로만 연결해 독립적으로 버전 관리하게 해주며, 대규모·다중 클라이언트 프로젝트에서 코드 재사용과 책임 분리에 유용하지만 항상 최신 상태로 관리하고 부모 저장소에 참조 변경을 커밋해야 한다.
