# Git Bisect

## 개요
- 이진 탐색(binary search)으로 버그를 유발한 커밋을 효율적으로 찾아내는 `git bisect`를 설명.

## 내용
### 문제 상황
- 프로덕션 로그인 페이지가 갑자기 크래시. 지난 주에는 문제없이 동작했는데, 그 사이 100개 이상의 커밋이 쌓여 어느 커밋이 문제인지 알 수 없다.

### git bisect란
- 버그를 유발한 커밋을 찾기 위해 이진 탐색을 사용하는 명령어 — 모든 커밋을 하나씩 확인하는 대신 목록을 반복해서 절반으로 나눈다.
- 100개의 커밋이 있어도 실제로 확인해야 할 커밋은 7~8개 정도로 줄어든다.

### 작동 방식
1. 버그가 있는 최근 커밋(bad)과 버그가 없었던 예전 커밋(good)을 표시
2. Git이 good과 bad 사이의 중간 커밋을 선택
3. 그 커밋을 테스트하고 good/bad 여부를 Git에게 알려줌
4. Git이 범위를 조정해 다음 중간 커밋을 선택 — 이 과정을 반복
5. 결국 버그를 정확히 유발한 커밋을 특정 → 수정하거나 롤백

### 이점
1. **시간 절약** — 대규모 커밋 이력에서 확인해야 할 개수를 수십·수백 개에서 몇 개로 줄임
2. **정확성** — 추측이 아니라 문제를 유발한 정확한 커밋을 완전한 추적성과 함께 확인
3. **자동화 가능** — 자동화된 테스트 스크립트와 결합해 Git이 직접 각 커밋을 good/bad로 판정하게 할 수 있음(수동 확인 불필요)

## 요약
- `git bisect`는 good/bad로 표시한 두 커밋 사이를 이진 탐색으로 좁혀가며 버그를 유발한 정확한 커밋을 몇 번의 테스트만으로 찾아내는, 대규모 커밋 이력에서 매우 효율적인 디버깅 도구다.
