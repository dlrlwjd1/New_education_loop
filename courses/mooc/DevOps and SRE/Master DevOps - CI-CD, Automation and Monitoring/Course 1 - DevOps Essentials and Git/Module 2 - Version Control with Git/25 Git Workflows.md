# Git Workflows

## 개요
- 팀이 Git으로 협업할 때 따르는 대표적인 패턴인 Centralized Workflow와 Feature Branching Workflow를 비교 설명.

## 내용
### Git 워크플로우란
- 개발자가 브랜치를 어떻게 만들고·업데이트하고·병합하는지 정의하는 모델/패턴.
- 명확한 구조가 없으면 서로의 작업을 덮어쓰거나 불안정한 코드를 실수로 푸시할 수 있어, 워크플로우는 혼란을 줄이고 팀을 조직적으로 만든다.

### Centralized Workflow
- 모두가 하나의 공유 브랜치(main/master)에서 pull/push. 격리(isolation) 없이 모든 변경이 바로 반영된다.
- 한 사람이 버그가 있거나 미완성인 코드를 푸시하면 즉시 팀 전체에 영향을 준다 — 안전망이 없다.
- 팀원이 1~2명이고 소통이 상시적이며 비공식 리뷰로도 충분한 아주 작은 팀에 적합.

### Feature Branching Workflow
- 새 기능/수정마다 별도 브랜치에서 개발해 메인 브랜치에 영향을 주지 않고 독립적으로 작업.
- 메인 브랜치는 항상 안정적이고 배포 가능한 상태 유지 — 테스트·리뷰를 거친 코드만 반영.
- 책을 쓸 때 모두가 같은 문서를 편집하는 게 아니라, 각자 별도 파일로 챕터를 쓰고 다듬어진 후에만 최종본에 추가하는 것과 유사.
- 각 기능 브랜치는 "샌드박스"처럼 자유롭게 실험·테스트·실패해도 괜찮은 공간.
- 병합은 보통 **Pull Request(PR)/Merge Request**를 통해 이루어져 팀원이 서로의 작업을 리뷰·제안·승인한 뒤에만 메인 브랜치에 반영된다.

## 요약
- Centralized Workflow는 단순하지만 위험하고 아주 작은 팀에만 적합하며, Feature Branching + Pull Request는 메인 브랜치를 항상 배포 가능한 상태로 유지하면서 병렬 개발과 리뷰를 가능하게 하는 더 견고한 모델이다.
