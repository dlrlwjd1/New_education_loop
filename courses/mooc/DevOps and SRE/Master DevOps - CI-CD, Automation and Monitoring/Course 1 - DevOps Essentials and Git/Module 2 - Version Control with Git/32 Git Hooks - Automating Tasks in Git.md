# Git Hooks - Automating Tasks in Git

## 개요
- Git 워크플로우의 특정 시점에 자동 실행되는 스크립트인 Git Hooks의 개념, 종류, 활용, 주의사항을 설명.

## 내용
### Git Hooks란
- 커밋·푸시 같은 특정 Git 이벤트가 발생할 때 자동으로 실행되는 스크립트 — 미니 이벤트 리스너와 유사.
- 코드 스타일 검사, 테스트 실행, 알림 전송 등을 자동화해 문제를 파이프라인 초반에 조기에 잡을 수 있다.
- 모든 Git 저장소에는 숨겨진 `.git/hooks` 폴더가 있으며, 샘플 훅 파일의 이름을 바꾸고 실행 권한을 주면 활성화된다.
- Bash, Python, Node.js 등 어떤 스크립팅 언어로도 작성 가능.

### 훅의 두 종류
- **클라이언트 사이드(Client-side)** — 로컬 머신에서 실행
- **서버 사이드(Server-side)** — 저장소 서버에서 실행

### 활용 사례
- 코딩 표준 강제 — 형식/규칙을 지키지 않으면 커밋 차단
- 커밋/푸시 전 자동화 테스트 실행 — 깨진 코드 공유 방지
- 문서 자동 생성 — 코드 주석 기반으로 푸시 시 문서 업데이트
- 알림 전송 — Slack/이메일로 푸시·병합 알림

### 주요 훅 종류
| 훅 | 시점 | 용도 |
|---|---|---|
| `pre-commit` | 커밋 확정 전 | 린팅(linting), 코드 포맷팅 |
| `prepare-commit-msg` | 메시지 편집기 열기 전 | 커밋 메시지 템플릿 커스터마이즈 |
| `commit-msg` | 메시지 작성 후, 커밋 확정 전 | 메시지 구조 검증 |
| `post-commit` | 커밋 성공 직후 | 테스트 트리거, 로그 생성 |
| `pre-receive`/`update`/`post-receive` (서버 사이드) | 푸시 시 | 푸시된 코드 검증, 배포 트리거, CI/CD 파이프라인 업데이트 |

- `update` 훅은 푸시되는 브랜치마다 한 번씩 실행되어 더 세밀한 제어가 가능하다.

### 주의사항
1. 훅은 기본적으로 버전 관리되지 않아 팀에 배포·공유하는 명확한 프로세스가 없으면 잊혀지기 쉽다.
2. 훅을 너무 복잡하게 만들면 워크플로우가 느려지고 개발자가 불편을 느낀다.
3. 환경이 일관되지 않으면(한 시스템에서는 동작, 다른 시스템에서는 실패) 혼란이나 오탐(false positive)을 유발할 수 있다.

## 요약
- Git Hooks는 커밋·푸시 등 Git 이벤트에 연결된 자동화 스크립트로 테스트·포맷팅·알림을 통해 코드 품질과 워크플로우를 개선하지만, 버전 관리 부재·과도한 복잡성·환경 불일치라는 함정을 주의해야 한다.
