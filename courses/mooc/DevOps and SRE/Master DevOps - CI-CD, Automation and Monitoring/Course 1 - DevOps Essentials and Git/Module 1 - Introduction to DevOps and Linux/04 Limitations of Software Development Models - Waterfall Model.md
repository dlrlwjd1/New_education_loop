# Limitations of Software Development Models - Waterfall Model

## 개요
- Waterfall(폭포수) 모델의 단계와 현대 개발 환경에서의 한계를 다룬다.

## 내용
### Waterfall 모델의 단계
1. Requirement Gathering — 고객/비즈니스 요구사항 수집 (초기에 모두 파악해야 함)
2. Analysis — 요구사항을 분석해 상세하게 이해
3. Design — 시스템 아키텍처, 컴포넌트 상호작용, 기술 스택, 데이터 흐름 확정
4. Coding — 설계를 바탕으로 실제 개발
5. Testing — 개발 완료 후(수 주~수 개월 뒤) 처음으로 동작 검증
6. Deployment & Maintenance — 배포 후 버그 수정과 유지보수

### 한계
- 프로세스 후반부까지 동작하는 결과물을 볼 수 없어 피드백이 늦다.
- 대규모·복잡한 시스템일수록 테스트·피드백 지연의 리스크가 커진다.
- 프로젝트 중간에 요구사항이 바뀌면 되돌아가 수정하기 어렵고 비용·시간이 많이 든다.
- 변화(change)에 유연하게 대응하도록 설계되지 않았다.

## 예시
- "6개월을 들여 만들었는데 막판에 고객이 원하던 게 아니었다"는 상황이 Waterfall의 전형적인 실패 시나리오다.

## 요약
- Waterfall은 선형적이고 예측 가능하지만, 늦은 피드백과 변경에 대한 경직성이 핵심 단점이며 다음 세션에서 다룰 Agile이 이 문제를 어떻게 보완하는지 이어진다.
