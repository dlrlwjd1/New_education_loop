# DevOps Delivery Pipeline - Unit Test and Deploy

## 개요
- Delivery Pipeline의 나머지 단계인 Unit Testing, 스테이징 배포, 자동화 테스트, 프로덕션 배포, 측정·검증을 설명.

## 내용
### Unit Testing
- 개별 함수/메서드 등 작은 코드 단위가 올바르게 동작하는지 검증 — 실수를 저렴하고 쉬운 단계에서 조기에 발견.
- 예: 로그인 함수가 올바른 사용자명/비밀번호는 받아들이고 잘못된 것은 거부하는지 테스트.
- 도구: JUnit(Java), PyTest(Python), NUnit(.NET)

### 스테이징 배포
- Unit Test 통과 후 프로덕션과 유사하지만 안전한 스테이징/테스트 환경에 배포해 환경별 이슈(설정 불일치, 시스템 통합 문제)를 잡는다.
- 배포 자동화가 중요 — 수동 배포는 설정 파일 누락 등 오류를 유발하지만 자동화는 매번 일관성을 보장.
- 도구: Jenkins, GitLab CI, Spinnaker

### 자동화 테스트
- 기능·성능·보안을 대규모로 검증하는 자동화 스크립트. 계정 생성, 결제, 부하 처리 같은 핵심 워크플로우 검증.
- 예: 수천 명이 동시에 로그인하거나 주문하는 상황을 시뮬레이션(수동으로는 거의 불가능).
- 도구: Selenium (브라우저 자동화 — 폼 제출, 링크 클릭, 장바구니 트랜잭션 등)

### 프로덕션 배포
- 실제 사용자가 이용하는 라이브 환경에 배포. 리스크 최소화를 위해 자동화하며 롤백(rollback) 메커니즘을 반드시 갖춘다.
- 모바일 앱이 조용히 업데이트되다가 치명적 문제 발견 시 즉시 안정 버전으로 롤백하는 것과 유사.
- 도구: AWS CodeDeploy, Kubernetes Deployments, Spinnaker, Ansible

### 측정과 검증
- 배포 후 서버 성능, 페이지 로드 시간, 오류율, 사용자 활동 등 핵심 지표를 실시간 모니터링.
- 문제 발생 시 자동 알림·롤백 트리거 가능.
- 도구: Prometheus(메트릭 수집), Grafana(시각화·알림) — 이 단계가 DevOps 피드백 루프를 완성한다.

## 요약
- Unit Test → 스테이징 배포(자동화) → 자동화 테스트 → 프로덕션 배포(롤백 메커니즘 포함) → 측정·검증까지가 Delivery Pipeline의 나머지 단계이며, 이 전체 흐름이 매 릴리스마다 학습하고 개선하는 피드백 루프를 완성한다.
