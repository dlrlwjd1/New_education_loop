# Limitations of Software Development Models - Agile Model

## 개요
- Agile이 Waterfall의 문제를 어떻게 개선했는지, 그리고 Agile 자체의 한계와 Dev-Ops 문화 부재 시 생기는 문제를 다룬다.

## 내용
### Agile의 특징
- Waterfall의 일회성 딜리버리 대신 짧은 사이클(sprint) 단위로 작동 가능한 결과물을 자주 전달한다.
- 각 스프린트: 계획(plan) → 빌드(build) → 테스트(test) → 딜리버리(deliver) → 피드백 반영 → 다음 스프린트
- 지속적 통합(continuous integration)으로 코드를 공유 저장소에 자주 푸시해 문제를 조기에 발견한다.
- 고객을 개발 전 과정에 지속적으로 참여시켜 요구사항 변화를 정상적인 것으로 수용한다.

### Agile의 한계
- 예측 가능성 부족 — 유연함 때문에 대규모 프로젝트에서 일정·범위·예산 추정이 어렵다.
- 지속적이고 긴밀한 커뮤니케이션 요구 — 원격팀·바쁜 이해관계자 환경에서는 어렵다.
- 문서화 부족 — 빠른 딜리버리에 집중하다 보니 문서가 부실해져 신규 합류자·확장 시 문제가 된다.
- 스케일링의 어려움 — 대규모·분산 팀, 다수 기능/우선순위/의존성 환경에서 조율이 복잡해진다.

### DevOps 문화가 없을 때의 문제 (Dev-Ops 분리/실로 운영)
- 개발과 운영이 협업하지 않고 각자 일하며, 장애 시 책임 소재가 불분명해진다("it worked on my machine" vs "it broke our server").
- 프로덕션 이슈가 개발팀에 늦게 전달되어 컨텍스트를 잃고 수정이 오래 걸린다.
- 협업 부재로 테스트·배포·모니터링 품질이 떨어진다.

### DevOps 도입 시 변화
- 개발·운영이 처음부터 함께 계획·빌드하고 공동 책임을 진다.
- 자동화, 지속적 통합·딜리버리, 정기적 피드백과 모니터링을 촉진해 신뢰·책임감·속도를 높인다.

## 요약
- Waterfall은 예측 가능하지만 경직되어 있고, Agile은 유연하지만 확장·문서화·예측에 약하다. DevOps는 두 모델의 장점(구조 + 속도)을 결합해 개발·운영 간 협업 문화로 격차를 메운다.
