# Components and Architecture of Linux

## 개요
- Linux를 구성하는 핵심 컴포넌트와 계층형 아키텍처, 커널의 역할과 커널 유형을 설명.

## 내용
### 핵심 컴포넌트
- **Init 프로그램** — 부팅 후 가장 먼저 실행되어 백그라운드 서비스를 시작하고 시스템을 사용 가능하게 준비 (예: SysVinit, Systemd)
- **Bootloader** — 전원이 켜졌을 때 OS를 로드하고 제어권을 넘김 (예: GRUB, SysLinux)
- **소프트웨어 라이브러리** — 애플리케이션이 재사용하는 공유 코드(그래픽 처리, 파일 접근 등)
- **패키지 매니저** — 소프트웨어 설치·업데이트·삭제와 의존성 관리 (예: DPKG, RPM)
- **인터페이스/도구** — GUI 데스크톱부터 커맨드라인 유틸리티까지

### 계층형 아키텍처
1. **Hardware** — CPU, RAM, 하드디스크, 연결 장치
   - RAM: 빠르지만 휘발성(전원 꺼지면 소실)
   - CPU: 모든 명령을 실행하는 핵심 프로세서
   - 하드디스크: 비휘발성, 전원이 꺼져도 데이터 유지
2. **Kernel** — 하드웨어와 소프트웨어 사이에서 자원을 관리하는 Linux의 핵심
3. **Shell/사용자 도구** — 사용자가 시스템과 상호작용하는 계층

### 커널의 역할
- 자원 할당(CPU 시간·메모리를 프로그램 간 충돌 없이 분배)
- 프로세스 관리(실행·일시정지·재개·종료)
- 보안 규칙 적용, 결함/악성 코드로부터 시스템 보호
- 디바이스 관리(하드웨어 목록 유지, 드라이버 상호작용)
- 스케줄링(어떤 프로세스를 언제 실행할지 결정)
- 메모리 관리(RAM에 남길 데이터, 스왑/해제 시점 결정)

### 커널 유형
- **Monolithic Kernel** — 디바이스 드라이버·메모리 관리·핵심 서비스가 하나로 통합 (Linux가 채택)
- **Microkernel** — 통신·프로세스 제어 등 필수 요소만 커널에 두고 나머지는 유저 스페이스로 이동 (모듈성↑)
- **Hybrid Kernel** — 성능을 위해 일부는 커널에, 유연성을 위해 일부는 유저 스페이스에 배치 (두 방식 혼합)

## 요약
- Linux는 Init/Bootloader/라이브러리/패키지 매니저/사용자 도구가 하드웨어-커널-사용자 계층 구조로 이어져 있으며, Monolithic Kernel 방식으로 자원·프로세스·보안·디바이스·스케줄링·메모리를 총괄 관리한다.
