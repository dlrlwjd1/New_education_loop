# Introduction to DevOps

## 개요
- DevOps의 정의와 두 축(협업·자동화), 전형적인 파이프라인 단계, 핵심 도구셋과 도입 효과를 설명.

## 내용
### DevOps란
- 개발(Development)과 운영(Operations)을 통합해 소프트웨어 라이프사이클 전체를 간소화하는 협업 접근 방식.
- 마지막 순간에 코드를 넘기는 대신, 계획부터 배포까지 두 팀이 공동 책임(shared ownership)을 진다.
- 두 축: **협업(collaboration)**과 **자동화(automation)** — 팀 간 마찰을 줄이고 배포 속도·품질을 높인다.

### DevOps 파이프라인 단계
1. Plan — 기능·수정사항 정의(기술+비즈니스 이해관계자 협업)
2. Code — Git 등 버전 관리 시스템으로 협업하며 개발
3. Build — 소스 코드 컴파일·패키징
4. Test — 자동화 테스트로 조기에 버그 발견
5. Release — 배포 승인·패키징·태깅
6. Deploy — 스테이징/프로덕션 환경에 자동 배포
7. Operate — 애플리케이션 운영, 개발자도 배포 후 지원·이슈 해결에 참여
8. Monitor — 시스템 상태·성능·사용자 행동을 지속 모니터링 → Plan 단계로 피드백 순환

### DevOps가 하는 일
- 개발·운영 팀 통합 (us-vs-them 구조 탈피)
- 인프라 자동화로 생산성 향상 (수동 서버 세팅/설정 드리프트 제거)
- 지속적 측정(continuous measurement) — 성능·버그·크래시·사용자 데이터를 상시 계측

### 핵심 도구셋
- CI/CD 도구 — 테스트·통합·배포 자동화
- 버전 관리(Git) — 동시 작업 협업
- 컨테이너화·오케스트레이션 — "내 컴퓨터에서는 되는데" 문제 해결
- Configuration Management — 인프라 셋업·유지보수 자동화
- 모니터링·로깅 도구 — 실시간 상태 추적, 트러블슈팅

### 도입 효과
- 비용 절감(cost avoidance), 혁신 가속화, 유연성(작은 단위 배포), 민첩성·속도, IT 효율성

## 요약
- DevOps는 협업과 자동화를 축으로 Plan→Code→Build→Test→Release→Deploy→Operate→Monitor의 순환 파이프라인을 통해 더 빠르고 안정적인 소프트웨어 딜리버리를 만든다.
