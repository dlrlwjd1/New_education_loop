# DevOps Stages - Continuous Monitoring

## 개요
- 시스템/애플리케이션의 성능·신뢰성·보안을 라이프사이클 전반에 걸쳐 선제적으로 추적하는 Continuous Monitoring을 설명.

## 내용
### Continuous Monitoring이란
- 고객이 문제를 신고하기 전에 팀이 실시간으로 문제를 감지하고 대응할 수 있게 하는 지속적 추적.
- **실시간 데이터 수집** — 서버 부하, 응답 시간, DB 상태 등을 계속 수집 (자동차 계기판처럼)
- **CI/CD 파이프라인과 통합** — 새 기능 배포 시마다 정상 동작 여부를 자동 검증
- **로그 관리(Log Management)** — 방대한 로그를 정리해 근본 원인을 빠르게 추적
- **성능 모니터링** — 속도·응답시간·부하 용량을 지속 측정해 사용자 영향 전에 slowdown 포착
- **보안 모니터링** — 무단 접근·취약점·공격을 실시간 탐지

### 필요한 이유
- 경영진 가시성(대시보드로 시스템 상태 확인), 운영 효율성 검증, 규제 준수(금융·헬스케어의 감사 요구사항), 리스크 기반 의사결정, 자동화된 피드백(알림→워크플로우 트리거), 최신 지표·리포팅 제공

### 대표 도구
- **Nagios** — 가장 오래된 신뢰받는 도구, 시스템/서비스 상태를 모니터링하고 알림 생성
- **Prometheus** — 컨테이너·클라우드 등 동적 환경에 특화된 오픈소스 도구, 클라우드 네이티브 앱에 적합
- **Grafana** — Prometheus가 수집한 데이터를 인터랙티브 대시보드로 시각화
- **New Relic** — 애플리케이션·서버·사용자 경험 지표를 실시간으로 제공하는 클라우드 기반 솔루션
- **Splunk** — 로그 관리·보안 이벤트 모니터링 특화, 대량의 머신 데이터 분석

### Prometheus 동작 방식
1. **Service Discovery** — 모니터링 대상 시스템/서비스를 자동으로 찾음
2. **Scraping** — EC2, Kubernetes 클러스터 등에서 일정 간격으로 메트릭을 능동적으로 수집(pull 방식)
3. **Exporters/Client Libraries** — 애플리케이션·인프라에서 데이터 수집
4. **Rules & Alerts** — 임계값(예: 메모리 사용량 초과)을 넘으면 자동 트리거
5. **저장·시각화** — 로컬에 데이터 저장, Grafana가 pull해서 실시간 대시보드 생성
6. **Alert Manager** — 알림 조건 충족 시 이메일·메신저·온콜 서비스로 알림 전송

## 요약
- Continuous Monitoring은 실시간 데이터 수집과 자동 알림으로 문제를 사전에 감지하게 하며, Prometheus(수집)+Grafana(시각화) 조합이 클라우드 네이티브 환경의 대표적인 모니터링 스택이다.
