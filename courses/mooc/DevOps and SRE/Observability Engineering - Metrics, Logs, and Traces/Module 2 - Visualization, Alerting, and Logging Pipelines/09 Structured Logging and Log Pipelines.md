# Structured Logging and Log Pipelines (구조화 로깅과 로그 파이프라인)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 2: Visualization, Alerting, and Logging Pipelines

## 개요
- 현대 시스템에서 로깅이 어떻게 작동하는지, 전통적 로깅의 한계, **구조화 로그(structured logs)**의 조건, 그리고 로그가 **수집·처리 파이프라인**을 거쳐 강력한 관찰 신호가 되는 과정을 설명한다.

## 내용

### 로깅의 역할
- **이벤트 기록(event recording)** — 중요한 동작·오류·상태 변화를 발생 시점에 포착.
- **시스템 가시성 향상** — 시스템이 실제로 무엇을 했는지.
- 장애·예상치 못한 동작 시 **깊은 운영 통찰**.
- 메트릭·트레이스와 **상관(correlate)** → 관찰 가능성 지원.
- **감사·컴플라이언스(audit/compliance)** — 활동의 역사적 증거.

### 전통적 로깅의 한계
- **비구조화 자유형 텍스트(unstructured free-form text)** → 기계가 해석하기 어려움.
- 앱·팀마다 형식이 달라 **일관성 상실** → 분석 복잡.
- 대규모에서 **검색·필터가 느리고 불안정**.
- 단일 요청이 여러 컴포넌트를 걸치는 분산 서비스에서 **로그 상관 어려움**.
- **수동 분석**은 시스템 성장에 확장되지 않음.

### 구조화 로그 (Structured Logs)
- 일관된 **기계 판독 가능 형식**을 따름.
- 각 항목이 **사전 정의 필드**(timestamp, level, service name, message 등) 포함.
- 흔한 형식: **JSON, 키-값 쌍**.
- → 대규모에서 **효율적 파싱·인덱싱·쿼리** 가능. 평문 텍스트를 검색 가능한 풍부한 데이터로 전환, 자동화·고급 분석 지원.

### 로그 수집·처리 파이프라인 (Log Ingestion & Processing)
1. **생성(generate)** — 앱·인프라가 실행·요청 처리 중 로그 생성.
2. **수집(collect)** — 여러 소스에서 모아 중앙 관리.
3. **파싱(parse)** — 원시 메시지를 구조화 필드로 변환 (검색·분석 용이).
4. **맥락 추가(enrich)** — service name·environment 등을 붙여 시스템과의 관계 속에서 이해.
5. **저장(store)** — 빠른 검색·분석용 시스템에 저장 → 효율적 조사.
- → 로그가 조직화·검색 가능·관찰 가능성/트러블슈팅 준비 완료 상태가 됨.

### 강력한 관찰 신호로서의 로그
- **왜(why)** 발생했는지 설명 (무엇이 발생했는지만이 아니라).
- 오류 메시지·**스택 트레이스** 포착 → 빠르고 정확한 디버깅.
- 분산 시스템의 **요청 수준 실행 가시성**.
- 메트릭·트레이스와 상관 → 깊은 근본 원인 분석. 감사·디버깅·인시던트 리뷰 지원.

## 요약
- **구조화 로깅**은 원시 이벤트를 실행 가능한 통찰로 바꾼다 (JSON·키-값, 사전 정의 필드).
- **로그 파이프라인**: 생성 → 수집 → 파싱 → 맥락 추가 → 저장.
- 구조화 로그 + 잘 설계된 파이프라인으로 확장 가능한 가시성·빠른 디버깅을 얻으며, 메트릭·트레이스와 결합해 시스템 동작의 전체 그림을 완성한다.
