# Trace Context, Spans, and Service Dependencies (트레이스 컨텍스트, 스팬, 서비스 의존성)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 3: Distributed Tracing and End-to-End Observability

## 개요
- **트레이스 컨텍스트(trace context)**가 서비스를 연결하는 방식, **스팬(span)**이 작업 단위를 나타내는 방식, **부모-자식 관계**가 실행 흐름을 모델링하는 방식을 설명한다.

## 내용

### 트레이스 컨텍스트 (Trace Context)
- 분산 시스템에서 단일 요청은 여러 서비스를 거침. 각 서비스가 **같은 요청을 처리 중임을 이해**해야 관찰 가능성이 작동.
- **트레이스 컨텍스트**는 요청 식별자(request identifiers)를 서비스 간에 전달 → 각 서비스가 자기 작업을 **동일한 전체 요청에 연결**.
- 공유 컨텍스트 덕분에 모든 연산이 하나로 묶여 **엔드투엔드 가시성** 유지 → 요청이 어떻게 이동했는지, 시간이 어디서 소모됐는지, 어떤 서비스가 관여했는지 파악.
- 컨텍스트가 없으면 각 서비스가 **고립된 데이터**를 생성해 요청을 처음부터 끝까지 따라갈 수 없음.

### 스팬 (Span)
- 서비스가 수행한 **단일 연산의 시간 기록(timed record)** — DB 쿼리, API 호출, 계산 단계 등 하나의 명확한 작업 단위.
- 정확히 하나의 서비스 연산 포착 → **세밀한(fine-grained) 성능 관찰**.
- 기록 항목: **시작 시간, 지속 시간(duration), 실행 상태(성공/실패)** + **메타데이터**(service name, operation name).
- 여러 스팬을 결합하면 완전한 **요청 트레이스** 형성 → 분산 시스템 동작 이해의 기본 빌딩 블록.

### 부모-자식 관계 (Parent-Child)
- **부모 스팬(parent span)**: 요청 처리를 시작하는 초기/업스트림 연산 (수신 API 호출, 게이트웨이 요청).
- **부모-자식 링크**: 서비스 간 의존 관계 표시 — 어느 서비스가 어느 다운스트림을 어떤 순서로 호출했는지.
- **자식 스팬(child span)**: 다운스트림 서비스 호출 시 생성, 부모가 트리거한 특정 연산 포착.
- 함께 요청의 **전체 실행 경로(execution path)**를 구조적으로 모델링.

### 트레이스 데이터로 진단
- 요청이 서비스를 어떻게 이동하고 시간이 어디서 소모되는지 표시.
- **트레이스 타임라인**이 요청을 스팬으로 분해 → **실패한 연산·느린 의존성·예상치 못한 지연**을 실행 경로 안에서 드러냄.
- 실행 흐름 + 정밀 타이밍 시각화 → **빠른 근본 원인 식별**, 조사 시간 단축.

## 요약
- **트레이스 컨텍스트가 서비스를 연결**하고, **스팬이 개별 연산을 표현**하며, **부모-자식 관계가 요청 흐름을 모델링**한다.
- 이 개념들이 분산 실행에 대한 깊은 가시성을 제공해 **성능 병목·장애 진단**을 쉽게 한다.
- 분산 추적은 복잡한 서비스 상호작용을 명확하고 실행 가능한 통찰로 바꾼다.
