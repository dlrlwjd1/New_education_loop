# Correlation Strategies Across Telemetry Signals (텔레메트리 신호 간 상관 전략)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 3: Distributed Tracing and End-to-End Observability

## 개요
- 메트릭·로그·트레이스를 **고립이 아니라 상관(correlate)**시켜, 탐지에서 진단으로 빠르게 이동하는 전략을 다룬다.

## 내용

### 각 신호가 답하는 질문
| 신호 | 제공 | 답하는 질문 |
|------|------|-------------|
| **메트릭(Metrics)** | 시스템 건강·성능 추세의 고수준 뷰 | **문제가 존재하는가** (이상 빠른 탐지) |
| **로그(Logs)** | 상세 이벤트·실행 정보 | **무엇이 일어났는가** (특정 시점 내부) |
| **트레이스(Traces)** | 요청의 서비스 전반 흐름 | **어디서 시간이 소모되고 실패가 시작되는가** (엔드투엔드) |

### 상관 흐름: 탐지 → 설명 → 맥락
1. **메트릭 = 첫 신호** — 지연 스파이크, 오류율 증가, 비정상 트래픽 등 이상 강조. "문제가 있다"는 알려주지만 **왜인지는 모름**.
2. **로그와 상관 → 탐지에서 설명으로** — 지연 스파이크를 타임아웃·실패한 DB 호출·설정 변경 로그와 직접 연결 → 성능 이상을 **구체적 이벤트·오류·변경**에 매핑, 추측 제거. 여러 도구를 수동 검색할 필요 없어 트러블슈팅 시간 단축.
3. **트레이스로 깊은 맥락** — 단일 요청이 여러 서비스를 거칠 때, 트레이스가 요청 전체 생애주기를 포착 → **어느 연산이 느린지/실패했는지 정밀 특정**, 서비스 간 의존을 하나의 일관된 이야기로.

### 통합 트러블슈팅 뷰
- 한 신호만 보면 **원인 없는 증상**만 봄.
- **메트릭(무엇이 잘못)** + **로그(왜, 내부 이벤트)** + **트레이스(어디서, 엔드투엔드 경로)** 를 상관 → 통합 관점 → **빠른 근본 원인 분석, 추측 감소, 신뢰성 있는 운영**.

## 요약
- 현대 관찰 가능성은 **신호 상관**이 핵심 — 고립 분석은 증상만 보여준다.
- 전형 흐름: **메트릭(탐지) → 로그(설명) → 트레이스(맥락·위치)**.
- 셋을 결합하면 원시 텔레메트리가 **실행 가능한 이해**로 바뀌어 더 깊은 가시성·빠른 진단을 제공한다.
