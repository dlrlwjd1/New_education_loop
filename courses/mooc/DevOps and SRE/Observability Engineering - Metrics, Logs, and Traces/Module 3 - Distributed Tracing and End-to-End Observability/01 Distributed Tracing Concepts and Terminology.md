# Distributed Tracing Concepts and Terminology (분산 추적 개념과 용어)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 3: Distributed Tracing and End-to-End Observability

## 개요
- 왜 추적(tracing)이 필요한지, 핵심 개념·용어, 요청 흐름·지연 시각화, 그리고 분산 추적이 가장 가치 있는 지점을 다룬다.

## 내용

### 왜 추적이 필요한가
- 현대 시스템은 **분산 서비스 아키텍처** — 단일 사용자 동작이 API·DB·백그라운드 서비스를 거치는 **다중 서비스 요청 경로**.
- **숨은 실행 의존성**은 메트릭만으로 안 보임 → **예측 불가한 지연**, 장애 시 **원인 서비스 특정(failure localization) 어려움**.
- 전통 모니터링은 개별 컴포넌트 중심이라 **엔드투엔드 가시성 제한** → 교차 서비스 디버깅이 느리고 오류 발생.
- → **요청 수준 추적**이 필수 — 각 요청을 서비스 전반에서 따라가 시스템 동작을 총체적으로 이해.

### 핵심 개념·용어
| 용어 | 의미 |
|------|------|
| **트레이스(Trace)** | 요청의 **전체 생애주기**(진입~완료)를 서비스 전반에 걸쳐 표현 |
| **스팬(Span)** | 트레이스 내 **단일 연산** (DB 쿼리, API 호출 등) |
| **스팬 메타데이터(Span metadata)** | 타이밍, 속성(attributes), 서비스 관계 포착 |
- 트레이스 + 스팬이 함께 **분산 실행(distributed execution)** — 여러 서비스·의존성에 걸친 엔드투엔드 요청 흐름 — 을 기술.

### 요청 흐름·지연 시각화
- **트레이스 타임라인**: 모든 서비스에 걸친 전체 요청 경로 시각화.
- **부모-자식 스팬(parent-child spans)**: 서비스 의존성·호출 관계 표시.
- **트레이스 컨텍스트 전파(trace context propagation)**: 서비스 경계를 넘어 요청 정체성(identity) 유지.
- **스팬 지속 시간 분석(span-duration analysis)**: 전체 지연을 서비스별 시간으로 분해.
- → **병목 식별(bottleneck identification)**: 엔드투엔드 성능에 영향을 주는 느린 서비스 강조.

### 분산 추적이 가장 가치 있는 곳
- 마이크로서비스 전반의 **진정한 엔드투엔드 가시성**.
- 서비스 간 **지연 스파이크를 정밀 진단** — 시간이 어디서 소모되는지.
- 메트릭·로그만으로 재현 어려운 **간헐적 서비스 장애 분석**.
- **교차 서비스 의존성 이해** → 아키텍처 사각지대·숨은 결합 감소.
- **더 빠른 인시던트 근본 원인 분석** → 신뢰성·대응 시간 향상.

## 요약
- 분산 추적은 복잡한 요청 경로를 **명확하고 실행 가능한 통찰**로 바꾼다.
- **트레이스·스팬·요청 실행**을 이해하면 분산 시스템의 깊은 가시성을 얻는다.
- 메트릭·로그와 결합하면 관찰 가능성의 이야기가 완성된다.
