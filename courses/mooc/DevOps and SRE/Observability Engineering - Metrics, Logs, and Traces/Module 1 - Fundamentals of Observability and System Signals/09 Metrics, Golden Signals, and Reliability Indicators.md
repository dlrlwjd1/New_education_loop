# Metrics, Golden Signals, and Reliability Indicators (메트릭, 골든 시그널, 신뢰성 지표)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 1: Fundamentals of Observability and System Signals

## 개요
- 어떤 메트릭이 **실행 가능(actionable)**한지, 서비스 건강을 반영하는 **골든 시그널(golden signals)**, 그리고 실제 시스템에서 안정성·성능을 재는 **신뢰성 지표(reliability indicators)**를 다룬다.

## 내용

### 실행 가능한 메트릭(Actionable Metrics)
모든 메트릭이 유용하지는 않다. 실행 가능한 메트릭은:
- **실제 시스템/사용자 영향 반영** — 내부 동작(지연·오류)을 실제 사용자 경험과 직접 연결.
- **운영 문제에 빠르게 반응** — 성능 저하·장애 발생 즉시 변화 → 조기 탐지.
- **명확한 다음 단계 유도** — 경고 트리거, 조사 안내, 시정 조치.
- **허영 지표(vanity metrics) 회피** — 인상적으로 보여도 건강·신뢰성에 통찰을 주지 않는 숫자 배제.

### 골든 시그널 (Golden Signals) — 4가지
수백 개 메트릭 대신, 서비스 건강을 고수준으로 보는 소수 신호.
| 신호 | 의미 |
|------|------|
| **지연(Latency)** | 요청 응답 시간 — 서비스 반응성. 상승은 장애 전 **가장 이른 성능 저하 지표** |
| **트래픽(Traffic)** | 유입 요청량·전체 부하 — 사용 패턴·수요 급증 파악, 부하 vs 내부 장애 구분 |
| **오류(Errors)** | 실패 요청 비율 — 타임아웃·잘못된 응답 등, 증가는 즉각 주의 필요한 기능 문제 |
| **포화도(Saturation)** | 자원(CPU·메모리·스레드 풀)이 용량 한계에 얼마나 근접했는지 — 병목·장애 예고 |

### 메트릭을 의미 있게 만들기
- 개별이 아니라 **함께 평가**하면 "무엇이 바뀌었나"뿐 아니라 "왜 중요한가" 맥락 제공.
- 골든 시그널 = **고수준 건강 요약**(사용자 영향? 시스템 스트레스?), 하위 지원 메트릭으로 특정 컴포넌트·자원·서비스로 **드릴다운**.
- 건강 저하는 보통 급격한 스파이크보다 **지속적 추세(sustained trends)**로 나타남 → 장기 패턴에 집중해 노이즈 구분.
- **일관되고 잘 정의된 임계값**으로 정확히 탐지 → 불필요한 경고·피로(fatigue) 방지.

### 신뢰성 지표 (Reliability Indicators)
| 지표 | 의미 |
|------|------|
| **지연 백분위(latency percentiles)** | 성능 일관성 — 응답 시간 분포 |
| **오류율(error rates)** | 전체 서비스 안정성 수준 |
| **가용성(availability)** | 사용자가 필요할 때 서비스 접근 가능한지 |
| **처리량(throughput)** | 시간에 걸친 지속 용량 — 신뢰성 있게 감당 가능한 부하 |

## 요약
- **실행 가능한 메트릭 + 골든 시그널(지연·트래픽·오류·포화도) + 잘 고른 신뢰성 지표(지연 백분위·오류율·가용성·처리량)**가 메트릭 기반 관찰 가능성의 척추다.
- 조기 탐지, 서비스 건강 이해, 대규모에서 일관된 성능 유지를 가능하게 한다.
- **진짜 중요한 메트릭에 집중**하면 신뢰성 있고 회복력 있는 시스템을 만들 수 있다.
