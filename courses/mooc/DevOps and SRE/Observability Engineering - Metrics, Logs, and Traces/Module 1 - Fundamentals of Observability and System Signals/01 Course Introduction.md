# Course Introduction (강좌 소개)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 1: Fundamentals of Observability and System Signals

## 개요
- 이 강좌는 현대 분산 시스템을 어떻게 모니터링·분석·최적화하는지, 즉 **관찰 가능성(observability)** 엔지니어링을 단계별로 배운다.
- 원시 텔레메트리(telemetry)를 실행 가능한 통찰(actionable insight)로 바꾸는 방법을 다룬다.

## 내용

### 왜 관찰 가능성인가
- 애플리케이션이 갑자기 느려지거나 경고 없이 다운될 때, 로그는 흩어져 있고 대시보드엔 스파이크가, 경고가 울리지만 **원인을 아무도 모르는** 상황.
- 관찰 가능성이 있으면 **무엇이 바뀌었는지 즉시 확인**하고, 서비스 전반에 걸쳐 요청을 추적(trace)하며, **정확한 근본 원인(root cause)을 몇 분 내 특정**할 수 있다.

### 학습 목표
- 관찰 가능성의 핵심 원리와 **로그(logs)·메트릭(metrics)·트레이스(traces)**의 역할 파악.
- 관찰 가능성이 전통적 **모니터링(monitoring)과 어떻게 다른지**, 분산·클라우드 네이티브 환경에서 왜 중요한지 이해.
- 로깅·메트릭·트레이싱 기법으로 시스템 성능·신뢰성 가시성 확보.
- 업계 표준 도구(**Prometheus, Grafana, OpenTelemetry, 중앙집중 로그 파이프라인**)로 관찰 가능성 구현.
- 텔레메트리 데이터로 성능 병목·장애 진단.
- 확장 가능·신뢰성 있는 시스템을 위한 견고한 관찰 가능성 전략 설계.

### 모듈 구성 (3개 핵심 모듈 + 마무리)
- **Module 1**: 관찰 가능성 원리 + **Prometheus** 기반 메트릭 엔지니어링 기초.
- **Module 2**: 시각화, 경고(alerting) 전략, 중앙집중 로깅 파이프라인 → 원시 텔레메트리를 대시보드·경고로.
- **Module 3**: 분산 추적(distributed tracing)과 엔드투엔드 관찰 가능성 → 마이크로서비스·컨테이너 환경에서 메트릭·로그·트레이스 상관(correlate).
- 각 모듈은 개념 + 실습 데모 + 읽기 자료 + 과제로 구성.

### 사용 도구 (production-grade)
| 도구 | 역할 |
|------|------|
| **Prometheus** | 시계열(time-series) 메트릭 수집·저장·조회 |
| **Grafana** | 인터랙티브 대시보드, 실시간 시스템 동작 시각화 |
| **OpenTelemetry** | 애플리케이션 계측(instrument)해 표준화된 텔레메트리 신호 생성 |
| **Grafana Loki** | 로그 중앙집중·효율적 조회 |
| **Jaeger** | 분산 서비스 전반 요청 추적 → 지연·의존성 이해 |

### 대상
소프트웨어 개발자, **DevOps·SRE 엔지니어**, 플랫폼·클라우드 엔지니어, 엔지니어링 매니저·테크 리드, IT 운영·지원팀.

## 요약
- 현대 시스템은 복잡·분산·지속 변화하며, 관찰 가능성 없이는 트러블슈팅이 **추측(guesswork)**이 되고 신뢰성이 **반응적(reactive)**이 된다.
- 이 강좌는 **로그·메트릭·트레이스** 3축을 중심으로, Prometheus·Grafana·OpenTelemetry·Loki·Jaeger로 **완전한 관찰 가능성 스택을 구현·운영**하는 실전 역량을 목표로 한다.
