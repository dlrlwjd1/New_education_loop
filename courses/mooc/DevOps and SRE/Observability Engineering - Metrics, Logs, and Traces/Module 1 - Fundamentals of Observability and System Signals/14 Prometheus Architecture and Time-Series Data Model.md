# Prometheus Architecture and Time-Series Data Model (Prometheus 아키텍처와 시계열 데이터 모델)

> 강좌: Observability Engineering: Metrics, Logs, and Traces · 모듈 1: Fundamentals of Observability and System Signals

## 개요
- Prometheus가 왜 현대 아키텍처에 맞는지, 핵심 컴포넌트, **풀 기반(pull-based) 수집**, 그리고 **시계열 데이터 모델**과 **PromQL**을 설명한다.

## 내용

### 왜 클라우드 네이티브에 맞나
- 서비스가 자주 스케일·재시작·이동하는 **동적 인프라**에 자연스럽게 대응.
- **풀 기반 신뢰성**: 타깃에서 메트릭을 능동적으로 당겨(pull) 와 단명(ephemeral) 워크로드에 적합.
- **라벨 기반 유연성(label-based flexibility)**: 변하는 서비스·인스턴스·환경에 자동 적응.

### 핵심 컴포넌트
| 컴포넌트 | 역할 |
|----------|------|
| **Prometheus Server** | 타깃에서 메트릭 스크레이프, 시계열로 저장. 조회·집계·경고 평가의 핵심 엔진 |
| **Exporters** | 애플리케이션·OS·인프라의 메트릭을 표준 형식으로 노출 → 직접 계측 없이 광범위 모니터링 |
| **Service Discovery** | 파드·노드·서비스 등 변하는 타깃을 자동 탐지·추적 → 스케일·변경에도 정확한 모니터링 |
| **Alertmanager** | 경고 수신 → 그룹화·중복 제거(dedup) → 이메일·Slack·인시던트 도구로 라우팅 |

### 풀 기반 수집 모델 (Pull-based)
- 에이전트가 push하지 않고, Prometheus가 **HTTP 엔드포인트에서 메트릭을 pull**.
- 각 타깃이 표준·가독 형식으로 메트릭 노출 → 일관성.
- **서비스 디스커버리**로 타깃 목록 자동 갱신 (동적 환경에 효과적).
- 스크레이프 실패를 외부 컴포넌트 의존 없이 **직접 탐지** → 수집 문제 가시성.
- → 무엇을/얼마나 자주 모니터링하는지, 언제 문제가 생겼는지 명확 → **예측 가능·관리 용이**.

### 시계열 데이터 모델 (Time-Series Data Model)
- **메트릭 시계열** = 일정 간격으로 수집된 값의 시퀀스 → 추세·스파이크·장기 동작 관찰.
- 각 시계열은 **메트릭 이름 + 라벨 집합**으로 고유 식별 (무엇을·어디서 측정하는지).
- **라벨 차원(label dimensions)**으로 서비스·인스턴스·환경 간 유연하게 필터·그룹·집계 (데이터 중복 없이).
- 각 데이터 포인트는 **정확한 타임스탬프 + 값** 저장 → 정확한 이력 분석·신뢰성 있는 경고. 고카디널리티(high-cardinality) 메트릭도 효율적으로 처리.

### PromQL
- Prometheus 데이터용 쿼리 언어. **라벨로 시계열 선택**, 집계·수학 연산 지원.
- 실시간 시스템 동작 분석, **대시보드·경고·SLO 평가**를 구동.

## 요약
- Prometheus는 **클라우드 네이티브 아키텍처 + 풀 기반 수집 + 시계열 데이터 모델**로 신뢰성 있는 메트릭 관찰 가능성을 제공한다.
- 컴포넌트: **Server·Exporters·Service Discovery·Alertmanager**.
- 시계열은 **메트릭 이름 + 라벨**로 식별되며, **PromQL**로 조회·집계해 대시보드·경고·신뢰성 지표를 만든다.
