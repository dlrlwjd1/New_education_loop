# Hands-on Lab: Analyze HTTP Logs

> 강좌: Monitoring and Observability for Development and DevOps (IBM) · 모듈 3: Methodologies and Tools in Logging
> 강사: John Rofrano (IBM Research, DevOps Champion)

## 개요
- 온라인 로그 뷰어·분석 도구 **CloudVyzor**로 샘플 Apache HTTP 로그 파일을 업로드해 로그 한 줄의 구조를 분석하고, 다양한 검색 쿼리로 로그를 탐색하는 60분짜리 실습.

## 내용
### Log Analyzer란
- 다양한 시스템·서버·애플리케이션이 생성한 로그 파일을 분석·해석하는 데 사용되는 소프트웨어 도구 — 로그 파일에는 시스템이나 애플리케이션 내에서 발생한 이벤트·활동·메시지가 기록되어 있어 문제 해결, 모니터링, 성능 분석 등에 귀중한 정보원이 됨.
- 로그 데이터를 파싱해 타임스탬프, 로그 레벨, 오류 메시지, 요청 세부 사항, IP 주소, 사용자 에이전트 등 관련 정보를 추출 — 시스템 동작에 대한 통찰을 제공하고, 패턴을 식별하고, 이상 징후를 탐지하고, 사용 추세를 추적하고, 문제를 진단하는 데 도움을 줌.
- 이 랩에서는 로그를 온라인에서 검토하고, 구조를 이해하고, 즉시 협업할 수 있는 온라인 로그 뷰어·분석 도구인 **CloudVyzor LogPad**를 사용.

### 학습 목표
- CloudVyzor로 업로드한 로그 파일을 분석하고, 일반적인 HTTP 로그의 구조를 설명하고, 특정 용어·구문으로 로그를 검색하고, 특정 용어·구문을 제외해 검색하고, 특정 날짜·시간으로 로그를 검색하고, 현재 상태를 복사해 팀과 공유·협업.

### Exercise 1 — 샘플 로그 파일 다운로드
- `apache_sample_log.txt` 파일 내용을 복사해 로컬 머신의 메모장에 저장.

### Exercise 2 — CloudVyzor 실행과 로그 업로드
- `https://cloudvyzor.com`에서 CloudVyzor 실행 → 홈페이지에서 "Drop .zip or .gz or text file with logs here or Browse for upload" 타일의 **Browse** 링크로 저장한 샘플 로그를 업로드.

### Exercise 3 — HTTP 로그 구조 이해
- 예시 로그 한 줄: `136.145.136.38 - - [15/Nov/2018:18:21:30 +0000] "GET / HTTP/1.1" 200 553 "-" "Mozilla/5.0 (Macintosh; Intel Mac OS X 10.14; rv:63.0) Gecko/20100101 Firefox/63.0"`
- **IP 주소**(`136.145.136.38`) — 웹 서버에 접근한 클라이언트/사용자의 IP.
- **하이픈(`-`) 2개** — 각각 클라이언트 신원(identity)과 사용자 신원을 나타내는 자리표시자(이 로그 항목에는 기록되지 않음).
- **날짜와 시간**(`[15/Nov/2018:18:21:30 +0000]`) — 대괄호 안에 요청이 이뤄진 날짜와 시간.
- **요청(Request)**(`GET / HTTP/1.1`) — 요청 메서드(`GET`), 요청된 리소스(`/`), HTTP 프로토콜 버전(`HTTP/1.1`)을 포함 — 클라이언트가 HTTP 1.1로 웹 서버의 루트 디렉터리에 GET 요청을 했음을 의미.
- **상태 코드**(`200`) — 서버가 이 요청에 반환한 HTTP 상태 코드. `200`은 요청이 성공했음을 의미.
- **크기**(`553`) — 서버가 이 요청에 대해 보낸 응답의 바이트 크기.
- **하이픈(`-`)** — 리퍼러(referrer) 필드 — 요청된 리소스로 연결된 웹페이지의 URL을 나타내며, 이 경우 기록되지 않음.
- **사용자 에이전트(User-Agent)**(`Mozilla/5.0 (Macintosh; Intel Mac OS X 10.14; rv:63.0) Gecko/20100101 Firefox/63.0`) — 요청에 사용된 클라이언트 애플리케이션·브라우저를 식별하는 문자열 — 클라이언트의 운영체제와 브라우저 버전에 대한 정보 제공(이 예시는 macOS 10.14 매킨토시에서 Firefox 63.0을 사용했음을 나타냄).

### Exercise 4 — 로그 분석(Supported Queries)
- CloudVyzor의 **Supported Queries** 탭에서 검색·분석용 템플릿 쿼리 목록을 확인 가능. 주요 쿼리 유형:
  - **단순 용어(`term`)** — 특정 단어를 검색. 예: `Firefox`를 검색하면 로그 파일에서 Firefox가 등장한 모든 항목과 발생 횟수·페이지를 보여줌.
  - **제외 용어(`-term`)** — 특정 단어를 제외하고 검색. 예: `-Firefox`.
  - **여러 용어(`term1 term2`)** — 두 용어가 함께 등장하는 로그 검색. 예: `"Mozilla" "5.0"` — 각각을 큰따옴표로 감싸 별개 용어로 검색해야 함(하나의 따옴표로 묶으면 구문(phrase) 검색으로 취급되어, 로그 안에서 Mozilla와 5.0 사이에 `/`가 있어 결과가 0건이 됨에 유의).
  - **전체 구문(`"구문"`)** — 특정 구문을 검색. 예: `500` 오류 코드 개수를 검색할 때 단순히 `500`을 검색하면 다른 숫자의 일부로 포함된 경우까지 잘못 포함될 수 있으므로, 앞뒤에 공백을 넣은 `" 500 "`으로 정확히 검색해야 함.
  - **제외 구문(`-"구문"`)** — 특정 구문을 제외하고 검색. 예: `-"200 553"`.
  - **날짜(`date=<날짜>`)** — 특정 날짜의 로그 검색. 예: `date=2018-11-15`.
  - **타임스탬프** — 특정 시간대의 로그 검색. 예: `timestamp>="2017-11-12 13:14:15.667"`, `timestamp>"2017-11-12 13:14:15"`, `timestamp<="2017-11-12"`, `timestamp<2017-11-12`. 검색창을 클릭하면 드롭다운 메뉴에서 시작·종료 시간을 입력하거나 시간/일/주 단위로 범위를 선택할 수도 있음.

### Exercise 5 — 검색 결과 공유
- **"Copy Current State"** 탭을 클릭하면 현재 검색 쿼리의 URL이 담긴 팝업이 열림 — **Copy to Clipboard**로 URL을 복사한 뒤 새 브라우저에 붙여넣으면 동일한 검색 결과를 확인 가능 — 이 상태를 팀과 공유해 협업 가능.

## 요약
- 이 실습은 CloudVyzor에 샘플 Apache 로그를 업로드해 IP·타임스탬프·요청·상태 코드·크기·리퍼러·사용자 에이전트로 구성된 HTTP 로그 한 줄의 구조를 분석하고, 단순/제외 용어·구문, 날짜, 타임스탬프 같은 다양한 Supported Queries로 로그를 검색하며, 검색 상태를 URL로 복사해 팀과 실시간으로 공유·협업하는 방법을 다룬다.
