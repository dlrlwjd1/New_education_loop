# Identity and Access Management

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-cloud/lecture/DJfhS/identity-and-access-management)

## 개요
- 포괄적인 보안 전략은 조직 사용자, 인터넷 및 소셜 기반 사용자, 타사 비즈니스 파트너 조직 및 벤더를 포함한 광범위한 대상 그룹의 보안 요구 사항을 포괄해야 합니다.사용자 유형으로는 관리 사용자, 개발자 사용자, 애플리케이션 사용자 등 세 가지가 있습니다.

## 내용
- 포괄적인 보안 전략은 조직 사용자, 인터넷 및 소셜 기반 사용자, 타사 비즈니스 파트너 조직 및 벤더를 포함한 광범위한 대상 그룹의 보안 요구 사항을 포괄해야 합니다.사용자 유형으로는 관리 사용자, 개발자 사용자, 애플리케이션 사용자 등 세 가지가 있습니다.
- 인증 또는 ID 서비스를 사용하면 클라우드에 배포된 애플리케이션이 클라우드 디렉터리와 같은 다양한 ID 공급자, Google, LinkedIn, Facebook, Twitter와 같은 소셜 ID 제공업체, 엔터프라이즈 호스팅 ID 제공업체, 클라우드 호스팅 ID 제공업체를 기반으로 애플리케이션 수준에서 사용자를 인증할 수 있습니다.호출하는 애플리케이션 또는 사용자를 식별하기 위해 API 키 또는 고유 식별자가 API로 전달되는 경우가 있습니다.
- 다단계 인증은 일회용 암호 또는 핀, 인증서, 토큰, 위험 기반 인증 (예: 사용자 위치, 과거 활동 및 기본 설정 변경) 과 같은 추가 인증 계층을 애플리케이션 사용자를 위한 추가 인증 계층을 추가하여 신원 도용을 방지하는 데 사용됩니다.
- 보고서는 일반적으로 어떤 사용자가 어떤 리소스에 액세스할 수 있는지, 어떤 사용자가 액세스 권한을 변경했는지, 각 사용자가 어떤 액세스를 악용하고 있는지, 그리고 어떤 조건에서 사용되는지에 대한 정보를 제공합니다.
- 사용자 및 서비스 액세스 관리 기능을 통해 클라우드 애플리케이션 및 서비스 소유자는 인적 개입을 최소화하면서 고객, 파트너 및 공급업체 사용자 프로필을 프로비저닝 및 프로비저닝 해제할 수 있습니다.
- 이러한 민감한 계정을 보호하는 데 도움이 되는 몇 가지 제어 기능으로는 각 사용자의 리소스에 대한 역할을 지정하여 사용자 프로비저닝, 특수 문자 사용, 최소 암호 길이 및 기타 유사한 설정을 제어하는 암호 정책, 시간 기반 일회용 암호와 같은 다단계 인증, 사용자가 역할을 떠나거나 역할을 변경할 때 즉시 액세스 권한 해제 등이 있습니다.
- 정책에는 주체 (사용자, 서비스 ID 또는 액세스 그룹이 될 수 있음) , 대상 ( 액세스를 제공하려는 리소스 또는 프로비전된 서비스 제공) , 정책 대상 , 즉 액세스 권한이 부여되는 리소스에 허용되는 작업을 정의하는 역할이 포함됩니다.
