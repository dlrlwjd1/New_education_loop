# Containers

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-cloud/lecture/OpPPu/containers)

## 개요
- 컨테이너는 작고 빠르며 이동성이 뛰어나며 가상 시스템과 달리 모든 인스턴스에 게스트 OS를 포함할 필요가 없으며 대신 호스트 OS의 기능과 리소스를 간단히 활용할 수 있습니다.

## 내용
- 컨테이너는 작고 빠르며 이동성이 뛰어나며 가상 시스템과 달리 모든 인스턴스에 게스트 OS를 포함할 필요가 없으며 대신 호스트 OS의 기능과 리소스를 간단히 활용할 수 있습니다.
- 제가 컨테이너를 언급할 때마다 요즘 대부분의 사람들은 Docker나 Kubernetes 같은 것을 기본으로 사용하는 경향이 있습니다.
- 다시 말하지만, 이미지의 경우 Docker와 같은 것으로 작업하는 경우 Docker 이미지와 비슷한 것이 될 수 있습니다.
- 따라서 여러 컨테이너를 배포하면 이번에는 게스트 OS에 대해 걱정할 필요가 없으므로 응용 프로그램 자체뿐만 아니라 라이브러리만 있으면 됩니다.
- 그래서 그는 서드파티 API 역할을 하는 서비스를 만들었고, 우리는 node.js 애플리케이션을 사용하여 파이썬 앱에 액세스한 다음 해당 서비스에 액세스하려고 합니다.
- 하지만 컨테이너 기반 접근 방식을 사용할 경우 우리가 할 수 있는 일은 모듈식이므로 Python 응용 프로그램 복사본을 하나만 배포하면 된다고 간단히 말할 수 있습니다.
- 사실 또 다른 이점은 이러한 컨테이너 프로세스 중 일부가 실제로 CPU나 메모리를 사용하지 않는 경우 해당 하드웨어 내에서 실행되는 다른 컨테이너에서 모든 공유 리소스에 액세스할 수 있다는 것입니다.

## 예시
- 예를 들어 코그너티브 API를 예로 들어 이미지 인식과 같은 작업을 수행하도록 하죠.

## 요약
- 하지만 컨테이너 기반 접근 방식을 사용할 경우 우리가 할 수 있는 일은 모듈식이므로 Python 응용 프로그램 복사본을 하나만 배포하면 된다고 간단히 말할 수 있습니다. 사실 또 다른 이점은 이러한 컨테이너 프로세스 중 일부가 실제로 CPU나 메모리를 사용하지 않는 경우 해당 하드웨어 내에서 실행되는 다른 컨테이너에서 모든 공유 리소스에 액세스할 수 있다는 것입니다.
