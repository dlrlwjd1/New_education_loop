# Object Storage - Tiers and APIs

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-cloud/lecture/z3rr0/object-storage-tiers-and-apis)

## 개요
- 또한 오브젝트 스토리지 버킷에는 이와 관련된 스토리지 계층 또는 클래스가 있으며 이러한 계층은 데이터 액세스 빈도에 따라 결정됩니다.

## 내용
- 또한 오브젝트 스토리지 버킷에는 이와 관련된 스토리지 계층 또는 클래스가 있으며 이러한 계층은 데이터 액세스 빈도에 따라 결정됩니다.
- 볼팅 또는 아카이브 티어는 한 달에 한두 번 또는 그 이하로만 액세스하는 문서를 저장할 수 있는 곳으로, 더 저렴한 스토리지 비용으로 제공됩니다.
- 공급자가 콜드 볼트 버킷을 제공하는 경우 스토리지가 오프라인 상태로 유지되므로 이러한 계층에서 데이터를 검색하는 데 몇 시간이 걸릴 수도 있습니다.
- 이러한 비용도 비슷하게 낮지만 볼트 또는 콜드 볼트 계층에 속하는 데이터의 경우 액세스 요금이 더 높을 수 있으므로 액세스 빈도에 따라 데이터가 올바른 계층에 속하는지 확인하는 것이 중요합니다.
- 많은 공급자가 S3와 호환되는 객체 스토리지에 API를 제공하는데, 이는 개발자가 여러 공급업체의 객체 스토리지에 액세스할 수 있는 코드를 작성할 수 있다는 점에서 유용합니다.
- API 호출을 통해 애플리케이션은 객체 스토리지 및 버킷을 관리할 수 있을 뿐 아니라 객체 스토리지와 버킷에 객체를 추가, 업로드 또는 다운로드할 수 있습니다.
- 오브젝트 스토리지는 테이프를 테이프 드라이브에 물리적으로 로드하거나 테이프 드라이브에 제거해야 하며 지리적 이중화를 위해 오프사이트로 이동해야 하는 테이프 백업 솔루션보다 효율적입니다.

## 예시
- 오브젝트 스토리지는 테이프를 테이프 드라이브에 물리적으로 로드하거나 테이프 드라이브에 제거해야 하며 지리적 이중화를 위해 오프사이트로 이동해야 하는 테이프 백업 솔루션보다 효율적입니다.

## 요약
- API 호출을 통해 애플리케이션은 객체 스토리지 및 버킷을 관리할 수 있을 뿐 아니라 객체 스토리지와 버킷에 객체를 추가, 업로드 또는 다운로드할 수 있습니다. 오브젝트 스토리지는 테이프를 테이프 드라이브에 물리적으로 로드하거나 테이프 드라이브에 제거해야 하며 지리적 이중화를 위해 오프사이트로 이동해야 하는 테이프 백업 솔루션보다 효율적입니다.
