# File Storage

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-cloud/lecture/YVr2u/file-storage)

## 개요
- 직접 연결 스토리지와 마찬가지로 파일 스토리지도 컴퓨팅 노드에 연결되어야 컴퓨팅 노드에 액세스하여 데이터를 저장할 수 있습니다.

## 내용
- 직접 연결 스토리지와 마찬가지로 파일 스토리지도 컴퓨팅 노드에 연결되어야 컴퓨팅 노드에 액세스하여 데이터를 저장할 수 있습니다.
- 그러나 파일 스토리지는 직접 연결 스토리지에 비해 비용이 저렴하고 장애에 대한 복원력이 뛰어나며 사용자가 수행해야 하는 디스크 관리 및 유지 관리 작업이 덜 필요할 수 있습니다.
- 워크로드 측면에서 파일 스토리지는 일반적으로 한 번에 둘 이상의 컴퓨팅 노드에 마운트될 수 있으며 , 마운트된 디스크 또는 볼륨은 컴퓨팅 노드의 다른 드라이브처럼 보입니다.
- 파일 스토리지는 한 번에 여러 컴퓨팅 노드에 마운트할 수 있으므로 부서별 파일 공유 , 애플리케이션에서 처리해야 하는 수신 파일을 위한 '랜딩 존' 또는 웹 서비스가 액세스할 수 있는 파일 리포지토리와 같은 일종의 공통 스토리지가 필요한 경우에 이상적인 솔루션입니다.
- 물론 비용이 문제가 되는 경우 데이터베이스와 같은 다른 애플리케이션에 파일 스토리지를 사용할 수 있지만 속도라는 단점이 있습니다.
- IOPS는 초당 입/출력 작업의 약자로 디스크가 데이터를 쓰고 읽을 수 있는 속도를 의미합니다 (스토리지와 컴퓨팅 노드 간 네트워크 속도는 아님).
- 예를 들어, 파일 공유가 30개의 서로 다른 컴퓨팅 노드에 마운트되어 있는 경우 애플리케이션이 해당 공유에 분당 60회 데이터를 쓰고 요청할 수 있습니다.

## 예시
- 예를 들어, 파일 공유가 30개의 서로 다른 컴퓨팅 노드에 마운트되어 있는 경우 애플리케이션이 해당 공유에 분당 60회 데이터를 쓰고 요청할 수 있습니다.

## 요약
- IOPS는 초당 입/출력 작업의 약자로 디스크가 데이터를 쓰고 읽을 수 있는 속도를 의미합니다 (스토리지와 컴퓨팅 노드 간 네트워크 속도는 아님). 예를 들어, 파일 공유가 30개의 서로 다른 컴퓨팅 노드에 마운트되어 있는 경우 애플리케이션이 해당 공유에 분당 60회 데이터를 쓰고 요청할 수 있습니다.
