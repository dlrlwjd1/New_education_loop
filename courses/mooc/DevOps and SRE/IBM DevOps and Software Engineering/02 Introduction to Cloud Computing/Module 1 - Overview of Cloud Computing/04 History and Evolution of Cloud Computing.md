# History and Evolution of Cloud Computing

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-cloud/lecture/NbAsv/history-and-evolution-of-cloud-computing)

## 개요
- 메인프레임에 대한 액세스를 용이하게 하는 것이 유일한 목적인 멍청한 터미널을 사용하면 여러 사용자가 어느 터미널에서든 동일한 데이터 스토리지 계층과 CPU 성능에 액세스할 수 있었습니다.

## 내용
- 메인프레임에 대한 액세스를 용이하게 하는 것이 유일한 목적인 멍청한 터미널을 사용하면 여러 사용자가 어느 터미널에서든 동일한 데이터 스토리지 계층과 CPU 성능에 액세스할 수 있었습니다.
- 1970년대에 가상 머신 (VM) 이라는 운영 체제가 출시되면서 메인프레임은 단일 물리적 노드에 여러 개의 가상 시스템 또는 가상 시스템을 보유하는 것이 가능해졌습니다.
- 인터넷 접근성이 향상되고 하드웨어 비용을 절감해야 하는 필요성이 커지면서 가상 머신 운영 체제가 제공하는 것과 동일한 기능을 사용하여 서버를 공유 호스팅 환경, 가상 사설 서버 및 가상 전용 서버로 가상화했습니다.
- 따라서 예를 들어 회사에서 애플리케이션을 실행하기 위해 'x' 개의 물리적 시스템이 필요한 경우 하나의 물리적 노드를 여러 개의 가상 시스템으로 분할할 수 있습니다.
- 하이퍼바이저는 여러 운영 체제를 나란히 실행하여 동일한 물리적 컴퓨팅 리소스를 공유할 수 있게 해주는 작은 소프트웨어 계층입니다.
- 또한 하이퍼바이저는 가상 시스템을 논리적으로 분리하여 기본 컴퓨팅 성능, 메모리 및 스토리지의 각 부분을 할당하여 가상 시스템이 서로 간섭하지 않도록 합니다.
- 이 모델은 하드웨어에 상당한 자본을 지출하는 대신 필요할 때 컴퓨팅 리소스에 대한 비용을 지불할 수 있기 때문에 하드웨어가 거의 없거나 전혀 없는 기업, 심지어 하드웨어를 많이 보유한 기업까지 모든 규모의 기업에 매력적이었습니다.

## 예시
- 따라서 예를 들어 회사에서 애플리케이션을 실행하기 위해 'x' 개의 물리적 시스템이 필요한 경우 하나의 물리적 노드를 여러 개의 가상 시스템으로 분할할 수 있습니다.

## 요약
- 또한 하이퍼바이저는 가상 시스템을 논리적으로 분리하여 기본 컴퓨팅 성능, 메모리 및 스토리지의 각 부분을 할당하여 가상 시스템이 서로 간섭하지 않도록 합니다. 이 모델은 하드웨어에 상당한 자본을 지출하는 대신 필요할 때 컴퓨팅 리소스에 대한 비용을 지불할 수 있기 때문에 하드웨어가 거의 없거나 전혀 없는 기업, 심지어 하드웨어를 많이 보유한 기업까지 모든 규모의 기업에 매력적이었습니다.
