# Module 3 Summary

> MOOC 읽기 자료 · [원본 강의](https://www.mooc.org/learn/devops-capstone-project/supplement/elH69/module-3-summary)

## 개요
- Module 3(CI와 보안 추가)에서 배운 핵심 내용을 정리한 공식 요약.

## 내용
- 스프린트에 관련된 작업을 시작하기 전에 사용자 스토리를 만들고 Sprint Backlog에 배치한 뒤, 관련 스토리를 스스로에게 배정하는 것이 필수적.
- GitHub는 지속적 통합에 사용할 스타터 설정 워크플로우를 제공.
- 워크플로우를 트리거할 설정(`on:` 이벤트)을 포함시키는 것이 필수적.
- Account 서비스가 데이터 저장에 사용하므로 Postgres 서비스를 만드는 것이 필요.
- 일련의 스텝을 실행하는 빌드 job을 설정.
- 의존성 오류가 없도록 빌드 실행 전에 Python 의존성을 설치하는 것이 필수적.
- 린팅은 코드의 구문·스타일 문제를 점검.
- `nosetests`로 단위 테스트를 실행하면 통과/실패한 테스트를 자세히 보여주고 코드 커버리지 리포트도 포함.
- Talisman으로 보안 헤더를 추가하기 전에 현재 동작을 확인하는 것이 필수적.
- 모든 테스트 통과는 보안 헤더가 성공적으로 구현되었음을 의미.

## 요약
- Module 3은 사용자 스토리 배정으로 시작해, GitHub Actions 워크플로우 트리거 설정과 Postgres 서비스 정의, 빌드 job의 의존성 설치·린팅·nosetests 단계, 그리고 변경 전후 동작 비교로 검증하는 Talisman 보안 헤더 구현까지, CI 파이프라인 구성과 보안 강화의 전체 과정을 요약한다.
