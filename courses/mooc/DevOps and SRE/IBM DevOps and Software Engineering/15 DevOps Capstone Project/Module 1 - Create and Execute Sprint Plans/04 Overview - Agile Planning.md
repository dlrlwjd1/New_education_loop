# Overview: Agile Planning

> MOOC 읽기 자료 · [원본 강의](https://www.mooc.org/learn/devops-capstone-project/supplement/CWdtq/overview-agile-planning)

## 개요
- Customer Accounts 마이크로서비스를 위한 Agile 계획을 세우는 Module 1 실습("Sprint 0")의 전체 흐름을 안내.

## 내용
### 사전 요구 사항
- Agile 계획과 Scrum에 대한 기본적인 이해.
- GitHub 계정.
- Agile 계획과 사용자 스토리 관리를 위해 GitHub Projects Kanban을 사용하거나, 공식 이메일 계정이 있다면 ZenHub에서 체험 계정을 만들어 칸반 보드를 설정 가능.

### 실습 흐름
- 이 모듈에서는 RESTful 마이크로서비스를 만들기 위한 Agile 계획을 개발하는 데 초점을 맞춤 — 이 프로젝트는 이후 여러 스프린트에 걸쳐 다양한 Agile, 클라우드 네이티브, CI/CD 도구와 기술을 사용해 완성됨.
- 첫 스프린트를 위한 Agile 계획을 세우는 것으로 프로젝트를 시작. 이 시점에서는 계획만 세울 뿐 코드 산출물을 만들지 않으므로, 일부 개발 팀은 이 단계를 "Sprint 0" 또는 계획 스프린트라고 부름. 목표는 실제 Agile 개발 팀이 스프린트를 계획할 때 하는 일을 시뮬레이션하는 것.
1. 프로젝트를 위한 GitHub 저장소를 만들고 이 저장소를 칸반 보드에 추가 — 이 보드를 사용해 Agile 계획을 만들고 관리.
2. GitHub에 사용자 스토리 템플릿을 만듦 — 이후 잘 구조화된 사용자 스토리를 작성하는 데 사용.
3. 칸반 보드에 **제품 백로그(Product Backlog)**를 구축 — 먼저 Customer Accounts 마이크로서비스를 빌드하는 데 필요한 각 단계를 나타내는 사용자 스토리를 추가.
4. 백로그 정제(refinement)를 준비하기 위해 이 스토리들을 정렬 — 스토리를 적절한 파이프라인으로 옮기고, 각 파이프라인 안에서 우선순위가 높은 순서부터 낮은 순서로 정렬.
5. 제품 백로그를 정렬한 뒤 스프린트 준비 상태(sprint-ready)로 만들기 위해 정제 — 아직 정렬되지 않은 나머지 스토리를 적절한 파이프라인으로 옮기고, 각 스토리에 충분한 세부 사항을 추가하고, 각 스토리에 적절한 라벨을 붙임.
6. 제품 백로그를 완성한 뒤 **스프린트 계획(Sprint Plan)**을 구축 — 스프린트 일정을 잡고, 스토리에 예상 스토리 포인트를 지정하고, 다음 스프린트에 여러 스토리를 배정하고, **스프린트 백로그(Sprint Backlog)**를 구축.

## 요약
- Module 1의 Agile 계획 실습은 GitHub 저장소와 칸반 보드 생성, 사용자 스토리 템플릿 작성, 제품 백로그 구축·정렬·정제, 그리고 스토리 포인트 추정과 스프린트 배정을 거친 스프린트 백로그 구축까지 이어지는 "Sprint 0" 계획 단계다.
