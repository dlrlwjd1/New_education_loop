# Demo Video: Example of an SQL Injection

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/Tk3ky/demo-video-example-of-an-sql-injection)

## 개요
- 관계형 데이터베이스에 대한 흔한 공격인 **SQL 인젝션**을 실제 로그인 폼 데모로 시연하고, 문자열 연결(concatenation) 방식과 플레이스홀더(placeholder) 방식의 차이를 비교.

## 내용
### SQL 인젝션 공격에 악용되는 의심스러운 문자
- 패치되지 않은 소프트웨어나 부적절한 설정 같은 데이터베이스 취약점은 SQL 인젝션을 이용한 악의적 공격을 가능하게 함.
- **작은따옴표/큰따옴표** — 문자열 연결을 사용하는 SQL 문을 변경하는 데 사용. 따옴표를 악용해 원래는 조건을 만족하지 않던 SQL 문이 참이 되도록 만들 수 있음.
- **세미콜론(;)** — SQL 명령을 구분하는 문자. 세미콜론으로 원래 명령을 끝내고 시스템을 공격하는 새로운 명령을 시작할 수 있음.
- **대시 문자(--)** — SQL 문법에서 이중 대시는 인라인 주석의 시작 — 공격자가 SQL 쿼리의 나머지 절반을 무효화하는 데 사용할 수 있음.

### 취약한 SQL 문 예시(Python)
```python
username = request.args.get("username")
password = request.args.get("password")
sql = "SELECT name FROM user WHERE username = '" + username + "' AND password = '" + password + "'"
# db 엔진에 그대로 전달되어 실행됨
```
- 요청 매개변수로 들어온 username과 password를 그대로 문자열 연결로 SQL 문에 삽입.

### 데모 — 정상 로그인 시도
- 사용자 이름 `admin`, 비밀번호 `admin` 입력 → 로그인 클릭 → 아이디/비밀번호가 유효하지 않아 접근 거부.
- 사용자 이름 `admin`, 비밀번호 `admin123` 입력 → 로그인 성공, 관리자 앱에 접근.

### 데모 — SQL 인젝션 공격
- 사용자 이름에 `admin`을 다시 입력하고, 비밀번호 필드에 특수 문자열을 입력: `unknown' or 1=1`.
  - 작은따옴표(`'`)가 SQL 문에서 문자열 연결될 때 비밀번호의 끝으로 해석됨.
  - 그 뒤에 SQL 키워드 `or`와 `1=1`이 이어짐.
- 로그인 버튼 클릭 → 공격자가 성공적으로 로그인.
- 실제로 실행된 전체 SQL 인젝션 문: `SELECT name FROM user WHERE name = admin AND password = unknown OR 1=1`
- `OR` 문은 두 인자 중 하나만 참이면 전체가 참으로 평가됨 — 비밀번호가 `unknown`과 일치하지 않아도 `1=1`은 항상 참이므로 전체 문이 참이 되어 SELECT 결과가 성공적으로 반환됨. 이것이 공격자가 로그인할 수 있게 되는 원리.
- 공격자는 이런 유형의 SQL 인젝션을 사용해 오류를 유발시켜 데이터베이스와 애플리케이션을 손상시키려 시도.

### 예방 — 플레이스홀더(placeholder) 사용
- 같은 두 줄로 username과 password를 요청에서 가져오되, SQL 문은 다르게 작성 — 문자열 연결 대신 물음표(`?`)를 변수가 치환될 위치의 플레이스홀더로 사용.
- 마지막 줄에서 데이터베이스 엔진이 SQL 문을 실행할 뿐 아니라, 치환에 사용할 두 변수도 함께 전달 — 물음표 자리에 이 값들을 사용.
- 차이는 미묘하지만 중요: 문자열 연결을 사용하면 데이터베이스는 삽입된 악성 명령을 포함해 전체 문자열을 해석 — 반면 플레이스홀더를 사용하면 데이터베이스는 변수가 데이터일 뿐 해석 대상이 아님을 인지.
- 예: 변수에 `DROP TABLE USER;` 문자열이 담겨 있어도, 문자열 연결 방식에서는 명령으로 해석되어 실행되지만, 플레이스홀더 방식에서는 단순히 텍스트로 안전하게 데이터베이스에 삽입될 뿐 테이블이 삭제되지 않음.

## 요약
- SQL 인젝션은 작은따옴표·세미콜론·대시 같은 의심스러운 문자를 악용해 문자열 연결로 만들어진 SQL 문을 조작하는 공격으로, 실제 데모에서는 비밀번호에 `unknown' or 1=1`을 입력해 `OR 1=1`이 항상 참이 되도록 만들어 인증을 우회했으며, 이를 예방하려면 문자열 연결 대신 물음표(`?`) 플레이스홀더로 변수를 데이터로만 치환해 악성 입력이 명령이 아닌 텍스트로 안전하게 처리되도록 해야 한다.
