# OWASP Top 7-10

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/nd6AS/owasp-top-7-10)

## 개요
- OWASP Top 10 중 7~10위인 **Identification and Authentication Failures(식별과 인증 실패)**, **Software and Data Integrity Failures(소프트웨어와 데이터 무결성 실패)**, **Security Logging and Monitoring Failures(보안 로깅과 모니터링 실패)**, **Server-Side Request Forgery(SSRF, 서버 사이드 요청 위조)**의 정의와 예방 전략을 정리.

## 내용
### 7위 — Identification and Authentication Failures(식별과 인증 실패)
- 앱이 다음을 허용할 때 발생: 자격 증명 스터핑(credential stuffing), 무차별 대입 공격(brute force), 기타 자동화된 공격.
- **자격 증명 스터핑**: 공격자가 정당한 사용자 이름과 비밀번호 목록을 확보하고, 자동화를 사용해 그 자격 증명들로 공격을 수행.
- URL에 세션 식별자(session ID) 정보가 드러나면, 누구든 그 세션 ID를 가진 사람이 웹사이트를 속여 자신이 실제 사용자 본인의 컴퓨터에 있는 것처럼 믿게 만들어 이전에 로그인했던 계정에 완전히 접근할 수 있음.
- 세션은 사용자 이름과 비밀번호로 로그인할 때 생성됨. 세션 타임아웃(비활동 기간 후 자동 로그아웃)은 애플리케이션 개발 중 종종 간과됨 — 이 기능이 없으면 로그인한 사용자가 컴퓨터를 떠난 사이 무단 접근과 데이터 유출 위험을 초래.
- **예방 방법**:
  - 소프트웨어 공급망(software supply chain)부터 시작 — 애플리케이션 개발 생애주기 전반에서 애플리케이션에 관여하는 모든 것을 포함. 소프트웨어 공급망 보안 도구로 애플리케이션 구성 요소를 스캔해 알려진 취약점이 없는지 확인.
  - 설정 변경에 대한 정기적 점검과 리뷰를 수행해 소프트웨어 파이프라인이 공격받을 위험을 줄임.
  - 신뢰할 수 없는 대상에게 암호화되지 않은 민감 데이터를 전송하지 않기 — 디지털 서명이나 다른 무결성 검사를 사용해 데이터 보안을 보장하고 변조를 방지.
  - 다중 인증(MFA)을 사용해 자격 증명 스터핑·무차별 대입·기타 자동화 공격을 예방하고, 기본 자격 증명이 활성화된 채로 애플리케이션을 배포하지 않기.
  - 서버 사이드 세션 관리자를 구현해 새롭고 무작위적인 세션 ID를 생성하고, 세션 식별자가 URL에 나타나지 않도록 보장 — 안전하게 저장하고 로그아웃·유휴·절대 타임아웃 이후 무효화되도록 함.

### 8위 — Software and Data Integrity Failures(소프트웨어와 데이터 무결성 실패)
- 이를 보호하지 못하는 코드와 인프라로 인해 발생. 애플리케이션이 의존하는 구성 요소가 신뢰할 수 없는 출처에서 온 경우 취약점을 유발할 수 있음.
- 오늘날 자동 업데이트 기능이 있는 많은 앱이 충분한 무결성 검증 없이 이전에 신뢰받던 애플리케이션에 업데이트를 다운로드·설치 — 공격자가 안전하지 않은 CI/CD 파이프라인에 악성 업데이트를 업로드해 모든 설치본에 배포·적용할 수 있고, 이는 데이터 유출이나 다른 유형의 공격으로 이어질 수 있음.
- **예방 방법**:
  - CI/CD 파이프라인을 분리(segregate)하고 올바르게 설정되었는지, 접근 제어가 정확하고 완전한지 확인 — 코드가 빌드·배포 과정을 거치는 동안 무결성을 보장하는 데 도움.
  - 소프트웨어 공급망 보안 도구를 사용해 앱 구성 요소의 알려진 취약점을 스캔.
  - 서명되지 않았거나, 암호화되지 않았거나, 직렬화된 데이터를 디지털 서명이나 무결성 검사 없이 신뢰할 수 없는 클라이언트로 전송하지 않기 — 디지털 서명과 다른 무결성 검사를 사용하면 데이터나 코드가 정당한 출처에서 왔고 변조되지 않았는지 검증하는 데 도움.

### 9위 — Security Logging and Monitoring Failures(보안 로깅과 모니터링 실패)
- 로깅과 모니터링은 침해를 탐지하고 대응하는 데 결정적 — 부적절한 로깅과 모니터링은 심각한 문제를 은폐할 수 있음. 누락되거나 약하거나 혼란스러운 항목이 있는 로그는 문제 해결 과정을 저해.
- 침입 시도, 로그인, 로그인 실패 같은 감사 가능한 이벤트를 기록하지 않는 앱은 득보다 실이 큼 — 침해나 다른 사이버 공격이 발생했을 때 이런 세부 사항을 로그에 담아두는 것이 필수.
- 로그가 너무 빨리 덮어써지면 지연된 포렌식 분석에 부정적 영향 — 몇 달 전 침해가 발생했는데 로그가 너무 빨리 덮어써지면 언제·어떻게 발생했는지, 재발했는지 결코 알 수 없게 됨.
- 모니터링 시스템 부재는 인프라에서 무슨 일이 일어나고 있는지 모두를 모르게 만듦 — 견고한 모니터링 시스템은 이슈·추세·기타 문제를 탐지하고 알림. 견고한 보안 로깅과 모니터링이 없으면 공격자가 누구도 알아채지 못한 채 조직 내에 오랫동안 남아 있을 수 있음.
- **예방 방법**:
  - 애플리케이션이 올바른 정보를 올바른 형식으로 적절한 시점에 기록하도록 보장.
  - 모든 로깅을 중앙화하고 원본 로그 파일을 정기적으로 백업 — 더 나아가 logstash 같은 로그 수집기로 스트리밍해 elasticsearch 같은 데이터베이스에 저장하고 Kibana 같은 도구로 시각화하며 장기간 보관. Kubernetes 같은 클라우드 네이티브 시스템 대부분이 이를 쉽게 지원.
  - 로그 분석 도구를 사용할 계획이라면 형식이 중요.
  - 로그인, 접근 제어, 서버 사이드 입력 검증 같은 감사 가능한 이벤트를 포함. 의심스럽거나 악의적인 계정을 식별하기에 충분한 맥락을 제공하고, 지연된 포렌식 분석을 위해 데이터가 충분히 오래 로그에 남아 있도록 보장.
  - 임계값(threshold), 대시보드, 알림을 갖춘 견고한 모니터링 시스템을 구현해 의심스러운 활동을 빠르게 탐지·대응.
  - 공격자에 의한 변조나 로그 파일 조작 시도의 증거를 찾기 위해 로그를 주기적으로 감사 — 많은 로그 항목을 살펴봐야 할 수 있음.

### 10위 — Server-Side Request Forgery(SSRF, 서버 사이드 요청 위조)
- 외부 공격자가 다른 내부 시스템에 대해 악의적인 요청을 생성·통제할 수 있게 함. 작동 방식: 해커가 내부 서버에 직접 접근을 시도하지만 방화벽이 연결 시도를 차단. 해커가 운 좋게 SSRF 공격에 취약한 웹 서버를 발견해 이를 악용.
- SSRF 공격은 내부 시스템 간의 신뢰 관계를 악용해 이를 수행 — 방화벽, VPN, 접근 제어 목록(ACL)을 우회. 영향받은 서버는 추가 공격과 탐색의 도구가 됨. 공격자는 영향받은 서버를 사용해 로컬·외부 네트워크의 열린 포트 스캔, 로컬 파일 접근, 다른 IP 주소 발견, 원격 코드 실행(RCE) 획득이 가능.
- SSRF 공격은 원래 외부에서 접근하도록 의도되지 않은 내부 시스템에 진입·조작할 수 있게 하므로 위험.
- **SSRF의 3가지 유형**:
  - **기본(Basic/Blind) SSRF** — 공격자가 영향받은 서버에 URL을 제공하지만, URL로부터의 데이터가 공격자에게 결코 반환되지 않음.
  - **세미블라인드(Semi-blind) SSRF** — 공격자가 URL을 제공하지만, 일부 데이터만 공격자에게 노출되어 더 많은 정보를 활용할 수 있게 함.
  - **논블라인드(Non-blind) SSRF** — 가장 위험. 어떤 URI로부터의 데이터든 내부 서비스에 의해 공격자에게 반환됨.
- **예방 방법**:
  - 클라이언트가 제공한 모든 입력 데이터를 살균(sanitize)하고 검증.
  - 허용된 URL, 포트, 대상을 강제하기 위한 화이트리스트를 생성.
  - HTTP 리다이렉트를 허용하지 않도록 웹 서버를 설정.
  - 검증 없이 클라이언트에 원본(raw) 응답을 보내지 않도록 애플리케이션을 설정.

## 요약
- 식별·인증 실패는 소프트웨어 공급망 점검, MFA, 안전한 서버 사이드 세션 관리로 예방하고, 소프트웨어·데이터 무결성 실패는 CI/CD 파이프라인 분리와 디지털 서명·무결성 검사로 예방하며, 보안 로깅·모니터링 실패는 중앙화된 로깅과 견고한 모니터링·알림 시스템, 정기적인 로그 감사로 예방하고, SSRF는 입력 살균·검증, URL 화이트리스트, 리다이렉트 비허용 설정으로 예방할 수 있다.
