# Cross Site Scripting

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/CXnuc/cross-site-scripting)

## 개요
- **크로스 사이트 스크립팅(Cross-Site Scripting, XSS)**의 정의, 3가지 유형(저장형·블라인드형·반사형), 예방 방법, 그리고 신용카드 입력 필드를 이용한 실제 공격 코드 예시를 정리.

## 내용
### 크로스 사이트 스크립팅이란
- 애플리케이션이 신뢰할 수 없는 데이터를 적절한 검증이나 이스케이프 없이 웹 브라우저로 전송할 때 발생 — 흔히 "XSS"로 표기.
- 공격자는 크로스 사이트 스크립팅을 이용해 피해자의 브라우저에서 스크립트를 실행.
- 공격 방식: 사용자 세션을 탈취, 이미지나 콘텐츠를 교체·제거해 웹사이트를 훼손, 신뢰할 수 있는 웹사이트에서 악성 웹사이트로 사용자를 리다이렉트.

### 3가지 흔한 유형
1. **저장형(Stored)** — 스크립트가 데이터베이스나 대상 서버에 영구적으로 저장되도록 주입 — 피해자가 악성 스크립트를 받아올 때 서버에 저장된 정보를 요청. 지속형(persistent) 크로스 사이트 스크립팅이라고도 부름.
2. **블라인드형(Blind)** — 사용자나 관리자가 모르는 사이에 애플리케이션 백엔드에서 실행될 페이로드를 가진 스크립트를 주입. 페이로드가 애플리케이션이나 서버를 손상시키거나, 심지어 사용자를 공격할 수도 있음.
3. **반사형(Reflected)** — 공격받은 서버에서 시스템 사용자에게 반사되도록 스크립트를 주입 — 악성 링크가 담긴 피싱 이메일 메시지를 보내 많은 피해자를 손상시키는 것이 반사형 크로스 사이트 스크립팅의 예.

### 예방 방법
- 스크립팅 엔진을 촉발할 수 있는 의심스러운 HTTP 요청과 키워드를 확인 — 예: 금지된 HTML 태그, 이스케이프 시퀀스.
- 의심스러운 목록이나 키워드를 이스케이프하거나 특수 문자를 차단.
- 사용자 쿠키를 수집해 악성 서버로 보낼 수 있는 HTTP TRACE 호출을 없애기 위해 웹 서버에서 HTTP TRACE 지원을 끄기.
- 안전하지 않은 싱크(unsafe sink, 웹 페이지의 함수나 변수)를 피하기 — `innerHTML` 같은 안전하지 않은 싱크에 대한 참조를 제거하도록 코드를 리팩터링하거나, 더 나은 방법으로 `textContent`나 `values`를 사용.

### 공격 예시 — 신용카드 입력 필드
```javascript
var page = "";
page += "<input name='credit_card' type='text' value='" + request.getParameter("CC") + "'>";
```
- 문자열을 연결하고 있다는 점이 문제 — 공격자는 신용카드 번호를 입력하는 대신 JavaScript를 입력할 수 있음.
- 공격자는 `CC` 매개변수를 조작해 `<script>` 태그로 치환할 수 있음.
- `document.location`이 공격자 사이트의 CGI bin 호출로 가는 페이로드가 되어, 피해자의 세션 ID가 공격자 웹사이트로 전송됨 — 이를 통해 공격자가 사용자의 현재 세션을 탈취할 수 있게 됨.

## 요약
- 크로스 사이트 스크립팅은 신뢰할 수 없는 데이터를 검증·이스케이프 없이 브라우저로 보낼 때 발생하는 공격으로, 저장형·블라인드형·반사형의 3가지 유형이 있으며, 신용카드 입력 필드처럼 사용자 입력을 문자열 연결로 HTML에 그대로 삽입하면 공격자가 스크립트 태그를 주입해 세션 ID를 탈취할 수 있고, 의심스러운 HTTP 요청 확인·이스케이프 목록·HTTP TRACE 비활성화·안전하지 않은 싱크(예: innerHTML) 회피로 예방할 수 있다.
