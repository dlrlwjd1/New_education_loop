# Discover Code Vulnerabilities with Snyk (SAST) Free Tool

> MOOC 읽기 자료 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/supplement/dFfZ5/discover-code-vulnerabilities-with-snyk-sast-free-tool)

## 개요
- 오픈소스 코드와 컨테이너의 취약점을 탐지·해결하는 개발자 중심 보안 플랫폼 **Snyk**의 주요 기능, 대상 사용자, 목적, 역사, 유사 제품을 정리.

## 내용
### Snyk란
- 개발자 중심 접근 방식을 취하는 보안 플랫폼으로, 조직이 오픈소스 코드와 컨테이너에 존재하는 취약점을 탐지·수정하도록 돕는다.
- 보안 조치를 개발 사이클에 매끄럽게 통합함으로써, 개발자가 소프트웨어 개발 초기 단계에서 능동적으로 보안 우려 사항을 짚어내고 해결할 수 있게 함.
- 개발자에게 오픈소스 의존성을 효과적으로 감독하고, 잠재적 취약점을 탐지하고, 코드베이스와 애플리케이션을 위한 안전한 토대를 마련할 수 있는 도구와 전략을 제공.

### Snyk의 주요 기능
- **의존성 정밀 조사(Dependability Scrutiny)** — 코드베이스를 꼼꼼히 스캔해 오픈소스 의존성 내 취약점을 짚어내고, 보안 우려가 있는 의존성에 대한 포괄적 통찰과 실행 가능한 수정 단계를 제시.
- **컨테이너 감시(Container Vigilance)** — 컨테이너 이미지까지 정밀 조사를 확장해 체계적으로 취약점을 스캔하여, 사용 중인 이미지가 잘 알려진 보안 위험으로부터 보호되도록 보장.
- **지속적 감시(Persistent Surveillance)** — 지속적인 모니터링을 통해 의존성과 컨테이너를 주시하며, 프로젝트에 영향을 줄 수 있는 새로 발견된 취약점을 즉시 알림.
- **해결과 수정(Resolution and Correction)** — 취약점 해결을 안내하며 필요한 수정 사항에 대한 지침을 제공. 종종 패치나 업데이트를 제안하고, 취약점에 노출되지 않은 대체 패키지 버전까지 제안.
- **조화로운 도구 통합(Harmonized Tool Integration)** — 코드 저장소, CI/CD 파이프라인, 이슈 추적 시스템을 아우르는 다양한 개발 도구에 매끄럽게 통합되어 개발 워크플로우 안에 보안 점검을 무리 없이 포함시킴.
- **보안 프레임워크(Security Frameworks)** — 조직이 허용 가능한 위험 수준을 규정하고 보안 조치의 시행을 자동화하는 보안 프로토콜을 설정할 수 있음.
- **개발자 중심 접근(Developer-Centric Approach)** — 개발자를 염두에 두고 설계되어 보안을 개발 프로세스에 매끄럽게 내장하고, 명확하고 실행 가능한 통찰을 제공해 개발자가 취약점을 이해하고 바로잡도록 돕는다.
- **폭넓은 호환성(Broad Compatibility)** — 소프트웨어 개발에서 광범위하게 사용되는 다양한 프로그래밍 언어와 패키지 매니저를 지원.
- Snyk는 취약점을 선제적으로 해결함으로써 보안·데이터 유출 노출을 크게 줄이며, 이는 DevOps와 지속적 전달 파이프라인에 보안 관행을 주입하는 전반적인 추세와 부합.

### Snyk의 대상 사용자
- **개발자(Developers)** — 코드를 작성하고 앱을 빌드하는 사람들. Snyk는 이들이 작업 중에 보안 이슈를 찾아 고치도록 도움.
- **DevOps 팀** — 앱을 실제로 가동시키는 팀. 사용 중인 앱이 취약점 없이 안전하게 유지되도록 도움.
- **보안 전문가** — 보안 유지에 집중하는 사람들로, 개발자와 협력해 문제를 짚고 해결책을 찾음.
- **제품 관리자** — 앱이 무엇을 해야 하는지 결정하고 사용자에게 안전한지 확인하는 사람들.
- **오픈소스 기여자** — 자신의 코드를 다른 사람과 공유하는 사람들로, Snyk가 코드의 문제를 점검하고 신뢰성을 유지하도록 도움.
- **앱 관리자** — 앱을 관리하고 잘 작동하도록 돌보는 사람들.
- **최고 보안 책임자급 인력** — 모든 것이 안전한지 총괄하는 사람들로, Snyk를 사용해 앱이 안전하고 제 역할을 하는지 확인.
- **컴플라이언스 팀** — 앱이 규칙을 따르고 안전 기준을 충족하는지 확인하는 팀.
- **클라우드 네이티브 팀** — 최신 기술로 작업하는 사람들로, 컨테이너 같은 앱의 특수한 부분을 안전하게 유지하도록 Snyk가 도움.

### Snyk의 목적
- 개발자와 팀이 소프트웨어를 안전하지 않게 만들 수 있는 문제를 찾아 고치도록 돕는 것이 핵심 목적 — 작성한 코드, 외부에서 가져온 것들, 소프트웨어의 특수한 부분을 점검함으로써 이를 달성.
- 취약점 탐지, 조기 수정(문제가 커지기 전에 해결), 보안 전문가가 아닌 사람도 문제와 해결법을 이해하도록 돕기, 오픈소스 공유 코드 감시, 해결책 안내, 모든 개발 도구와의 원활한 통합, 규칙 준수 지원, 새로운 문제에 대한 상시 경계, 컨테이너 같은 새롭고 특수한 형태의 소프트웨어까지 포괄.

### Snyk의 역사
- 2015년 Guy Podjarny, Danny Grander, Assaf Hefetz가 설립 — 오픈소스 소프트웨어의 보안 취약점을 해결하고 개발자·조직이 더 안전한 소프트웨어를 만들도록 돕는 것을 목표로 함.
- 2016년: 소프트웨어 개발·보안 커뮤니티에서 초기 인지도를 얻으며, 보안 관행을 개발 워크플로우에 통합하는 데 집중하기 시작.
- 2017년: 코드베이스와 오픈소스 의존성의 취약점을 스캔할 수 있는 첫 제품을 출시.
- 2018년: 컨테이너 보안으로 서비스를 확장 — 코드와 라이브러리를 넘어 컨테이너화된 애플리케이션의 취약점까지 다룸.
- 2019년: 다양한 투자 라운드를 통해 상당한 자금을 확보해 성장을 가속화.
- 2020년: GitHub, GitLab, Bitbucket, 각종 CI/CD 시스템 등 인기 개발 도구·플랫폼과의 통합을 강화.
- 2021년: 개발자에게 더 실행 가능한 통찰과 권고를 제공하는 데 초점을 맞춘 새로운 기능과 개선 사항을 출시.
- 2022년: 소프트웨어 보안 분야에서 영향력을 계속 확장하며 애플리케이션 보안 개선과 취약점 감소 효과로 인정받음.

### 유사 제품
- **WhiteSource** — 오픈소스 구성 요소 관리와 보안 위험 완화, 취약점 탐지, 라이선스 컴플라이언스 관리.
- **SonarQube** — 정적 코드 분석으로 취약점과 코드 스멜을 식별하는 코드 품질·보안 분석 도구.
- **Nexus Lifecycle**(Sonatype) — 오픈소스·타사 구성 요소의 취약점을 식별해 소프트웨어 공급망을 관리.
- **Veracode** — 정적·동적 분석을 포함한 애플리케이션 보안 솔루션.
- **Checkmarx** — SAST와 SCA를 포함한 애플리케이션 보안 테스트 전문.
- **Black Duck(Synopsys)** — 오픈소스 보안과 라이선스 컴플라이언스에 초점.
- **GitLab Security** / **GitHub Security** — 개발 파이프라인에 내장된 코드·오픈소스 취약점 스캔 기능.
- **Aqua Security Trivy** — 컨테이너 보안 전문 스캐너.
- **JFrog Xray** — 바이너리의 보안 취약점과 컴플라이언스 위반을 스캔하는 범용 바이너리 분석 도구.

## 요약
- Snyk는 오픈소스 의존성과 컨테이너의 취약점을 스캔·모니터링·수정 안내하며 다양한 개발 도구와 통합되는 개발자 중심 보안 플랫폼으로, 개발자·DevOps 팀·보안 전문가·컴플라이언스 팀 등 폭넓은 사용자를 대상으로 하고, 2015년 설립 이래 코드 스캔에서 컨테이너 보안·CI/CD 통합까지 기능을 확장해 왔으며, WhiteSource·SonarQube·Checkmarx·Black Duck 등과 함께 소프트웨어 보안·취약점 관리 시장을 이루는 대표 도구다.
