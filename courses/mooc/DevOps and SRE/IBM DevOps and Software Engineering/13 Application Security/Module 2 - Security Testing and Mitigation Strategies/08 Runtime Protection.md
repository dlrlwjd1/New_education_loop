# Runtime Protection

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/OLgNP/runtime-protection)

## 개요
- 애플리케이션이 실행되는 동안 위협으로부터 보호하는 **런타임 보호(Runtime Protection)** 메커니즘, 그리고 이를 구현하는 두 도구 **IAST(테스트 단계)**와 **RASP(프로덕션 단계)**의 특징을 정리.

## 내용
### 런타임 보호란
- 애플리케이션이 실행되는 동안 위협으로부터 보호하는 현대적인 보안 메커니즘. 애플리케이션이 실행되는 동안 약점을 스캔할 수 있는 보안 도구를 사용해 달성 가능:
  - **IAST(Interactive Application Security Testing)** — 테스트 과정 중 취약점을 스캔.
  - **RASP(Runtime Application Self-Protection)** — 프로덕션 환경에서 공격을 찾음.

### IAST — 테스트 단계의 실시간 보호
- 테스트 중 IAST를 구현하면 애플리케이션이 대중에게 공개되기 전에 실시간으로 보안 결함을 탐지 — 문제를 찾을 위치에 대한 중요한 정보를 얻어 데이터 유출이 발생하기 전에 빠르게 고칠 수 있음. IAST는 다른 자동화된 테스트 절차와 함께 실행 가능.
- IAST의 특징:
  - 애플리케이션을 실시간으로 검사해 낮은 위양성(false-positive) 출력을 만듦.
  - CI/CD에 통합하기 간단 — 표준 빌드, 테스트, QA 도구와 매끄럽게 연결되며, 위양성을 줄이기 위한 많은 설정이나 튜닝이 필요 없음.
  - 더 이르고 더 저렴한 수정을 가능하게 함 — 코드를 가까이서 다루는 개발 생애주기 초기에 취약점을 탐지·수정하는 데 우위를 줌. 그때가 자원과 보안 위험 측면에서 오류와 취약점을 고치는 데 가장 비용이 적게 드는 시점.
  - 어떤 기업 도메인에서도 확장 가능. 자동화·수동 방법과 Docker 기술을 포함한 다양한 배포 방식을 지원.

### RASP — 프로덕션 단계의 실시간 보호
- 애플리케이션을 배포해 프로덕션에서 실행 중일 때, RASP는 프로덕션 환경에서 런타임 수준의 보호를 제공 — 코드에서 위험한 부분에 대한 가시성을 줌.
- 애플리케이션에 통합되어, 프로그램의 행동과 활동의 맥락을 평가함으로써 유해한 입력으로부터 소프트웨어를 보호. RASP는 사람의 개입 없이 실시간으로 공격을 식별·방지하는 데 도움 — 애플리케이션을 모니터링하며 활동을 지속적으로 관찰·평가.
- RASP의 특징:
  - 악용(exploitation)으로부터 보호 — SQL 인젝션, 익스플로잇, 봇을 포함해 악의적 활동을 나타낼 수 있는 모든 유형의 트래픽을 가로챔. 위협을 감지하면 사용자 세션을 종료하고 보안 팀에 알릴 수 있음.
  - 애플리케이션 안에서 직접 작동 — 배포가 간단하고, 애플리케이션 행동을 모니터링하고 스스로 보호하는 것이 본질적으로 가능.
  - 악의적 요청과 합법적 요청을 구분해 매우 정밀하게 공격을 탐지·방지하고 위양성을 최소화.
  - 다양한 DevOps 시스템에 통합 가능 — 클라우드를 안전하게 지키는 것은 애플리케이션이 자신의 안전한 네트워크 밖에 있는 다른 누군가의 인프라에서 실행되기 때문에 쉽지 않고 많은 노력이 필요한데, 다행히 RASP는 클라우드 컴퓨팅과 매우 잘 호환됨.

## 요약
- 런타임 보호는 애플리케이션이 실행되는 동안 위협으로부터 보호하는 메커니즘으로, 테스트 단계에서 낮은 위양성으로 CI/CD에 매끄럽게 통합되고 초기에 저렴한 수정을 가능하게 하는 **IAST**와, 프로덕션 환경에서 사람의 개입 없이 실시간으로 악의적 트래픽을 탐지·차단하고 클라우드 환경과도 잘 호환되는 **RASP**라는 두 도구로 구현된다.
