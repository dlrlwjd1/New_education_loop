# Continuous Security Analysis

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/i8TWZ/continuous-security-analysis)

## 개요
- SDLC 전체에 걸쳐 보안을 지속적으로 통합·테스트하는 **지속적 보안 분석(Continuous Security Analysis)**의 목표와 이점, 대표 도구(Snyk Open Source), 그리고 4가지 모범 사례를 정리.

## 내용
### 지속적 보안 분석이란
- SDLC 안에서 보안을 지속적으로 통합·테스트하는 것 — 요구사항 단계부터 시작해 설계, 개발, 테스트 단계를 거쳐 코드를 배포할 때까지 지속적 보안 분석을 수행. 지속적 보안 테스트와 분석은 개발 초기 단계부터 배포 이후 코드가 프로덕션에 있을 때까지 우선순위가 되어야 함.

### 핵심 목표
- 보안 위험을 줄이고, 개발의 잠재적 병목을 제거하는 데 도움 — 소프트웨어를 빠르게 릴리스하기 위해 지속적 보안 분석을 수행. 이를 구현하면 조직을 위한 안전한 SDLC를 만들게 됨. 보안이 SDLC의 우선순위이자 결정적 요소가 됨.

### SDLC에 통합할 때 얻는 이점
- CI/CD 파이프라인에 직접 통합 가능.
- SDLC 전반에 걸쳐 높은 우선순위이므로 개발 과정 초기에 보안 이슈를 고칠 수 있음.
- 보안을 확보하면 개발의 혼란을 줄여, 새 기능 개발을 가속화.
- 기존과 새로운 애플리케이션 개발 모두에 대한 보안 요구사항을 자동화 가능.
- 개발자 사이의 소프트웨어 소유권과 책임감을 향상시키고, 안전한 코딩이 기본적인 개발 스타일이 됨.

### 대표 도구 — Snyk Open Source
- 오픈소스 라이브러리의 취약점을 찾아 고침. 오픈소스 라이브러리로 인한 라이선싱 이슈를 찾음. 개발 중 취약점을 고치기 위한 조언을 제공.
- GitHub 같은 SCM 코딩 저장소로 개발할 때 Pull Request를 이용해 취약점을 고침. Snyk Open Source는 이슈에 우선순위를 매기고 새로 발견된 취약점에 대해 리포트.

### 지속적 보안 분석을 구현하기 위한 4가지 모범 사례
1. 개발 전반에 걸쳐 보안 이슈와 위험을 감사하기 위한 계획을 요구.
2. 최신 운영체제와 안전한 환경의 소프트웨어로 코드를 개발.
3. 코드 개발의 모든 구성 요소를 분석해 전체 개발 스택에 직접 보안을 내장.
4. 모든 코드 테스트가 여러 유효한 테스트 기준을 충족하도록, 지속적 보안 분석에 더해 SAST와 SCA를 구현.

## 요약
- 지속적 보안 분석은 요구사항부터 배포까지 SDLC 전체에 걸쳐 보안을 지속적으로 통합·테스트해 위험과 병목을 줄이고 새 기능 개발을 가속화하며, Snyk Open Source 같은 도구로 오픈소스 취약점·라이선싱 이슈를 찾아 Pull Request로 고치고, 감사 계획·안전한 개발 환경·전체 스택 분석·SAST와 SCA 병행이라는 4가지 모범 사례를 따라 안전한 SDLC를 구축한다.
