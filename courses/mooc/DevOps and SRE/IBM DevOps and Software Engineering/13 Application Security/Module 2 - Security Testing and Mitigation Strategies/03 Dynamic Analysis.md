# Dynamic Analysis

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/F5Cei/dynamic-analysis)

## 개요
- 애플리케이션이 실행되는 동안 테스트·평가하는 **동적 분석(Dynamic Analysis)**과 DAST(Dynamic Application Security Testing)의 정의, 정적 분석과의 차이, 그리고 동적 분석의 3가지 핵심 이점을 정리.

## 내용
### 동적 분석이란
- 애플리케이션이 실행되는 동안 테스트·평가하는 과정 — 보통 완전히 빌드된 애플리케이션을 대상으로 실행됨. 정적 분석은 대개 개발 단계에서 수행하는 반면, 동적 분석은 스테이징, 프리프로덕션, 또는 프로덕션에 코드를 배포한 이후에도 수행.
- 인위적으로 테스트 케이스나 시나리오를 만들 필요 없이 바로 실시간 상황으로 뛰어듦 — 프로덕션에서의 취약점, 메모리 이슈, 가능한 크래시를 식별하는 데 도움.

### DAST(Dynamic Application Security Testing)
- 프런트엔드를 통해 외부에서 애플리케이션을 평가 — 기능 테스트가 아님. 공격자처럼 행동해 잠재적 위협과 취약점을 탐지하기 위한 공격을 시뮬레이션.
- DAST는 소스 코드에 접근할 수 없기 때문에 입력과 출력의 행동을 분석하는 **블랙박스 테스트**를 수행.

### 동적 분석의 3가지 핵심 이점
1. **애플리케이션 인터페이스를 크롤링(crawl)** — 동적 스캐닝을 사용하면 동적 분석 도구가 루트 URL부터 코드를 검사. 동적 스캐닝을 통해 의도적으로 시스템에 침투를 시도할 수 있고, 코드의 취약점과 결함 지점(breakpoint)을 식별해 패치함으로써 유리한 위치를 점할 수 있음.
2. **코드 행동에 대한 통찰을 제공하는 테스트 수행** — 테스트는 다양한 입력에 애플리케이션이 어떻게 반응하는지 보여줌. 입력은 URL이나 폼으로 취해지는 동작 형태일 수 있음. 실제 데이터베이스가 손상되지 않도록 안전을 위해 테스트를 실행할 때는 더미(dummy) 데이터베이스를 사용해야 함. 이 테스트에서 얻은 결과를 분석하면 코드가 입력에 어떻게 반응하는지 통찰을 얻게 됨 — 결과는 코드가 의도한 대로 작동하는지, 아니면 크래시하거나 오류를 던지거나 의도와 다르게 실행되는지 알려줌.
3. **동적 코드 경로의 결함을 밝혀냄(flush out)** — 정적 코드 경로에서 다른 테스트가 놓쳤을 수 있는 오류를 탐지·보고하는 데 도움 — 코드에서 어디를 변경해야 하는지 명확한 아이디어를 줌. 코드가 실행되는 동안 동적으로 테스트되기 때문에 동적 분석은 실제적이고 정확한 결과를 제공 — 만들어야 할 변경 사항을 찾고 이해하는 데 도움.

## 요약
- 동적 분석은 완전히 빌드된 애플리케이션이 실행되는 동안(스테이징·프리프로덕션·프로덕션 이후) 테스트·평가하는 것으로, 이를 위한 DAST는 소스 코드 없이 외부에서 공격을 시뮬레이션하는 블랙박스 테스트를 수행하며, 애플리케이션 인터페이스를 루트 URL부터 크롤링하고 다양한 입력(더미 DB 사용)에 대한 실제 코드 행동을 관찰함으로써 정적 분석이 놓칠 수 있는 동적 코드 경로의 결함을 정확하고 실시간으로 밝혀낸다.
