# Introduction to Security Testing and Mitigation Strategies

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/sbLE1/introduction-to-security-testing-and-mitigation-strategies)

## 개요
- 보안 테스트(Security Testing)의 정의와 기능적/자동화된 테스트 유형, 그리고 위험을 줄이는 5가지 핵심 완화 전략(Mitigation Strategy)을 소개.

## 내용
### 보안 테스트란
- 애플리케이션이나 시스템의 상태를 비교하는 절차 — 개발을 위한 안전한 코드 베이스라인을 제공. 영향의 위험을 줄이기 위해 모든 새 코드에 보안 테스트를 수행해야 함 — 어떤 코드 변경이든 이전에 안전했던 코드에 취약점을 만들 수 있기 때문.
- SDLC에서 보안 테스트는 코드 리뷰와 함께 **테스트 단계**에서 이뤄짐. 안전한 코드가 테스트 단계의 최우선 순위여야 하지만, 보안 테스트는 SDLC 전체에 걸쳐 안전한 코딩 과정의 일부가 되어야 함.
- 보안 테스트를 수행하는 첫 단계는 개발 중에 안전한 베이스라인을 제공하는 것 — 베이스라인이 확립되면 애플리케이션이나 시스템의 상태를 비교할 수 있음.

### 기능적 보안 테스트(Functional Security Testing)
- 보안 테스트 과정의 필수적인 부분이어야 함 — 소프트웨어나 시스템을 테스트할 때의 행동에 대한 기대. 이를 수행하려면 기능 요구사항 목록이 필요하며, 코드가 보안 요구사항을 충족하는지 확인하는 데 도움.
- 기능적 테스트의 두 유형:
  - **애드혹 테스트(Ad hoc testing)** — 취약점을 발견했을 때 수행하는 특화된 테스트.
  - **탐색적 테스트(Exploratory testing)** — 공식적인 테스트 밖에서 이뤄짐. 예: 이론을 테스트하거나 아이디어를 테스트하는 것.

### 자동화된 보안 테스트
- 인기 있는 두 가지 절차는 **단위 테스트(unit testing)**와 **통합 테스트(integration testing)**.
- **단위 테스트**는 API 계약을 평가하기 위해 클래스와 메서드를 테스트 — 제한된 범위에서 개별 클래스에 대해 수행.
- **통합 테스트**는 애플리케이션 내 여러 코드 클래스의 통합을 테스트 — 애플리케이션 계층에 걸쳐 넓은 테스트 범위로 수행.
- 애플리케이션이나 시스템의 보안 테스트를 자동화하기 위해 자동화 프레임워크도 사용 가능. 3가지 예시:
  - **BDD-Security** — 행동 주도 개발(behavior-driven development)을 사용하는 보안 테스트 프레임워크.
  - **Mittn** — 지속적 통합에 포함하기 인기 있는 도구 스위트.
  - **Gauntlt** — 간소화된 통합을 위해 보안 도구에 연결되는 보안 프레임워크.

### 5가지 핵심 완화 전략(Mitigation Strategies)
- 완화 전략을 사용하면 보안 위협·취약점의 위험과 영향을 줄이는 데 도움. 코드를 개발하면서 다음 5가지 핵심 완화 전략을 사용:
1. **API 데이터 페이로드에 JSON 사용** — XML과 달리 JSON은 복잡하게 중첩된 요소와 느린 파싱 대신 key-value 쌍으로 단순하게 데이터를 인코딩할 수 있게 해줌.
2. **안전한 코딩 관행 구현** — 팀과 조직 전반에 보안 표준을 전달. 취약점 스캐너로 코드의 취약점을 찾고, 취약점 스캐닝을 자동화할 수도 있음.
3. **위협 모델링(Threat modeling)** — 악의적 행위자의 행동을 명확히 이해하기 위해 위협 모델링을 포함. 위협 모델링은 무엇이 손상될 수 있는지 예측하고 위협을 즉시 봉쇄하는 방법을 결정하는 데 도움.
4. **OWASP Top 10에 대한 인식 유지** — 정기적으로 업데이트되는 이 목록은 프로덕션에 코드를 배포하기 전에 가장 중대한 보안 위험을 염두에 두고 개발 중 보안 테스트를 수행하는 데 도움이 됨.

## 요약
- 보안 테스트는 애플리케이션·시스템의 상태를 비교하는 절차로 SDLC의 테스트 단계(및 그 전반)에 걸쳐 수행되며, 기능적 보안 테스트(애드혹/탐색적)와 자동화된 보안 테스트(단위/통합 테스트, BDD-Security·Mittn·Gauntlt 같은 프레임워크)로 이뤄지고, JSON 사용·안전한 코딩 관행·위협 모델링·OWASP Top 10 인식 유지 같은 완화 전략을 함께 적용해 보안 위협과 취약점의 위험·영향을 줄여야 한다.
