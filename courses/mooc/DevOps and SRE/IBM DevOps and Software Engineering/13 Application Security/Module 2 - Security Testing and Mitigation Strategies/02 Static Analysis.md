# Static Analysis

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/jd5ph/static-analysis)

## 개요
- 코드를 실행하지 않고 검사하는 **정적 분석(Static Analysis)**과 SAST(Static Application Security Testing)의 정의, SDLC에서의 위치, 그리고 정적 분석 도구의 3가지 핵심 이점(깊이, 속도, 정확도)을 정리.

## 내용
### 정적 분석이란
- 모든 코드나 런타임 바이너리를 검사해 흔한 취약점을 탐지하도록 돕는 것 — 실행 전에 소스 코드를 자동으로 검사하는 디버깅 방법.
- **SAST(Static Application Security Testing)**는 소스 코드를 검사해 조직의 애플리케이션을 공격에 취약하게 만드는 보안 결함을 식별. 수동으로 평가한 코드의 문제를 탐지하는 데 매우 효과적.
- 일부 SAST 솔루션은 DevOps 통합을 위한 API를 제공하며 코드가 완성될 것을 요구하지 않음. 정적 분석은 코드를 철저히 스캔하기 때문에 시간이 오래 걸릴 수 있음.

### SDLC에서의 위치
- 정적 코드 분석은 소프트웨어 테스트가 시작되기 전, 개발 과정 초기에 이뤄짐. DevOps 기업에서는 **개발(Develop) 단계**에서 일어나며 자동 피드백 루프를 확립 — 처음부터 코드의 문제를 인지하게 되어 그 문제를 더 간단하게 해결할 수 있음.
- 정적 분석 도구는 파일 시스템에서 코드를 정적으로 검사 — "정적(static)"이라 불리는 이유는 코드가 실행되고 있지 않기 때문.

### 정적 분석 도구의 3가지 핵심 이점
1. **깊이(Depth)** — 테스트가 코드 실행의 모든 가능한 경로를 다룰 수는 없지만, 정적 코드 분석기는 대부분을 다룰 수 있음. 빌드 작업 중 정적 분석이 코드를 검증 — 설정한 기준에 따라 코드에 문제가 있을 수 있는 곳에 대한 심층 분석을 받게 됨.
2. **속도(Speed)** — 고품질 소프트웨어를 빠르고 저렴하게 전달하는 데 도움. 자동화된 도구는 수동 분석기보다 상당히 빠름. 정적 코드 검사는 문제를 초기에 식별하고 코드 안 문제의 정확한 위치를 짚어냄 — 결과적으로 문제를 더 빨리 고칠 수 있고, 초기 코드 문제는 고치는 비용이 더 저렴함.
3. **정확도(Accuracy)** — 자동화된 정적 분석 도구는 높은 수준의 정확도를 제공. 수동 리뷰는 취약점에 대한 높은 수준의 지식을 요구하는 반면, 자동화된 스캐닝은 최신 취약점에 대한 더 깊은 지식을 활용할 수 있음. 자동화된 도구는 코드의 모든 줄을 잠재적 오류에 대해 검사 — 그것들이 무엇인지 알면 테스트가 시작되기 전에 최선의 코드를 마련할 수 있음. 결국 코딩 표준에서 품질이 핵심.

## 요약
- 정적 분석(SAST)은 실행 전에 소스 코드를 자동으로 검사해 취약점을 탐지하는 디버깅 방법으로, DevOps 기업에서는 SDLC의 개발 단계 초기에 이뤄지며 파일 시스템에서 코드를 검사하고, 코드 실행의 대부분 경로를 다루는 깊이·수동 분석보다 훨씬 빠른 속도·자동화를 통한 높은 정확도라는 3가지 핵심 이점을 통해 문제를 더 빨리, 더 저렴하게 고칠 수 있게 해준다.
