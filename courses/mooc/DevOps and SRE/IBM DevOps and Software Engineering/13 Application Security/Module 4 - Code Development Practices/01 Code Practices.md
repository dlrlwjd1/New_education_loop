# Code Practices

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/2Xy4f/code-practices)

## 개요
- 안전한 소프트웨어 개발을 위한 **코드 관행(Code Practices)**의 일반 원칙, 입력 검증(input validation)과 살균(scrubbing) 과정, 출력 인코딩, 오류 처리 모범 사례를 정리.

## 내용
### 코드 관행이란
- 안전한 소프트웨어 개발을 위한 소프트웨어 개발 프로세스의 일부. DevOps 커뮤니티에서 보안이 주요 관심사인 이유는 공격자가 애플리케이션 계층의 안전하지 않은 코드를 표적으로 삼기 때문.
- 코드 관행 구현은 안전한 소프트웨어 개발의 중요한 부분이며, 개발 초기에 구현하면 비용 효율적 — 소프트웨어 개발 프로세스 후반에 안전하지 않은 코드를 수정하는 것은 비용이 많이 듦.
- 코드 관행 구현은 취약점과 공격을 완화하는 데 도움이 됨.

### 일반적인 코드 관행
- 안전한 소프트웨어 개발 생애주기(SDLC)를 구현 — 개발 생애주기에 보안을 포함시키는 것은 비용 효율적이며 애플리케이션이 처음부터 최대한 안전하도록 보장.
- 안전한 코딩 표준을 수립 — 일련의 안전한 코딩 표준을 따르면 좋은 습관이 형성됨.
- 효율성을 높이고 위험을 줄이기 위해 재사용 가능한 객체 라이브러리를 구축·사용.
- 테스트되고 승인된 관리형(managed) 코드만으로 개발.
- 노출된 위협이나 보안에 중요한 소스 코드에 초점을 맞춰 안전한 업데이트를 구현.
- 안전한 소프트웨어 개발에 초점을 맞춘 교육 과정에 참여 — 보안 인식을 높이고 역량을 강화할 수 있음.

### 입력 검증(Input Validation)
- 서버 사이드에서 사용자나 공격자가 제공한 입력이 기대하는 바와 일치하는지 확인하는 것.
- 검증해야 할 대상: 해커가 조작할 수 있는 모든 입력 데이터. 다음을 확인:
  - 기대하는 데이터 타입.
  - 데이터 범위와 데이터 길이.
  - 허용된 문자를 화이트리스트와 대조.
- 입력 데이터가 올바른 타입이 아니면 거부되어야 함. 신뢰할 수 없는 출처에서 오는 모든 데이터도 검증되어야 함.
- 신뢰할 수 있고 강화된(hardened) 시스템에서만 개발해 추가 위험을 줄임. 허용 문자에 대해서는 항상 화이트리스트 검증을 수행해야 함.

### 입력 살균(Scrubbing)
- 입력 데이터로 들어온 악성 문자를 살균 또는 제거 — 악성 문자에는 다음이 포함될 수 있음: `< > " ' % ( ) & + \`
- 공격자가 애플리케이션이 의도하지 않은 행동을 하게 만드는 데 사용할 수 있는 모든 것.
- 이런 악성 문자가 실제로 유효한 입력으로 허용된다면, 출력 인코딩, 작업별 API 보안 강화, 애플리케이션 전체에 걸친 모든 데이터 입력 고려 같은 추가 통제를 구현해야 함.

### 출력 인코딩(Output Encoding)
- 입력 코드를 안전한 출력 코드로 변환하는 것. 사용하는 각 유형의 아웃바운드 인코딩에 대해 정책과 관행을 구현.
- 인터프리터에 안전하지 않은 문자가 아니라면 모든 문자를 인코딩해야 함.
- SQL, XML, LDAP 같은 신뢰할 수 없는 쿼리의 모든 출력을 살균해야 하며, 로컬 운영체제 명령으로 향하는 신뢰할 수 없는 데이터 출력도 살균해야 함.

### 오류 처리(Error Handling)
- 부적절한 오류 처리는 애플리케이션에 다양한 보안 위험을 노출시킬 수 있음 — 너무 자세한 정보를 담은 오류 메시지는 공격자에게 악용할 잠재적 결함에 대한 귀중한 단서를 제공.
- 목표는 사용자에게 의미 있는 오류 메시지를 제공하고, 문제 해결을 위한 진단 정보를 제공하되, 공격자에게는 유용한 정보를 전혀 제공하지 않는 것.
- 오류 처리와 로깅에는 커스텀 오류 페이지와 일반적인(generic) 메시지를 사용. 오류 조건 발생 시 할당된 메모리를 해제해 손상을 방지.
- 로그에 대한 접근 제한을 구현해 공격자를 차단. 입력, 인증 시도, 접근 제어 같은 변조 이벤트와 실패도 로그에 기록해야 함.

## 요약
- 코드 관행은 안전한 소프트웨어 개발 생애주기 구현, 안전한 코딩 표준, 재사용 가능한 라이브러리, 테스트된 관리형 코드, 보안 교육 참여를 포함하며, 사용자 입력은 타입·범위·길이·화이트리스트 문자로 검증하고 악성 문자를 살균하며, 출력은 인터프리터에 안전하도록 인코딩·살균하고, 오류 처리는 공격자에게 유용한 정보를 주지 않으면서 사용자에게는 의미 있는 메시지와 진단 로깅을 제공해야 한다.
