# Security Patterns

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/OOb5j/security-patterns)

## 개요
- 반복되는 보안 위협에 대한 재사용 가능한 해법인 **보안 패턴(Security Pattern)**의 정의·목적·구조를 설명하고, 이를 카탈로그로 분류·조직화하는 것의 이점을 정리.

## 내용
### 왜 보안 패턴이 필요한가
- 잘못 설정된 소프트웨어 설정이 무단 접근으로 인한 보안 침해의 가장 흔한 원인 — 소프트웨어 설정의 보안 관련 설계 결함은 회사와 고객의 민감한 정보를 노출시킬 수 있음.
- 보안을 개발 계획에 매핑함으로써 시스템을 잠재적 공격으로부터 안전하게 지키고 조직이 공격으로부터 회복하는 능력을 강화할 수 있음 — 여기서 보안 패턴이 등장.

### 보안 패턴의 정의
- 보안 패턴은 본질적으로 반복되는 보안 위협이나 이슈에 대한 재사용 가능한 해법을 나타내고 정의하는 일련의 규칙.
- 보안 설계 아티팩트로서, 일반적으로 다음을 포함:
  - 보안 위협이나 이슈를 문서화.
  - 보안 이슈가 자산에 어떻게 영향을 미치는지 확립.
  - 사용성 촉진을 위해 사용법을 표준화.
  - 위협을 완화하기 위해 처방된 통제(control)를 추적 가능하게 유지.
  - 특정 벤더나 기술 구현으로부터 보안 이슈를 분리.

### 보안 패턴의 목적
- IT 업계 내 배포 사이클의 수요와 속도가 꾸준히 증가 — 이를 따라잡기 위해 조직은 더 똑똑하고 재사용 가능하며 적응 가능한 보안 아키텍처와 설계에 시간과 노력을 투입.
- 소프트웨어 개발자는 소프트웨어를 쉽게 식별·재사용 가능하고 다른 애플리케이션·서비스와 상호운용 가능하게 만들기 위해 보안 패턴을 사용해야 함.
- 보안 패턴은 보안 위협과 공격을 관리하는 복잡성을 단순화 — 보안 패턴을 따름으로써 조직은 시스템의 데이터 기밀성, 무결성, 가용성을 보장하면서 견고한 보안 프레임워크를 확립.
- 보안 패턴은 위험을 완화하고, 민감한 정보를 보호하며, 애플리케이션의 전반적인 보안 생태계를 향상시키는 표준화되고 입증된 접근을 제공. 또한 보안 통제, 모니터링 메커니즘, 인증 절차, 암호화 프로토콜 등을 구현하기 위한 실행 가능한 해법과 권장 사항도 제공.
- 보안 패턴의 주된 목표는 미래의 보안 위협을 줄이거나 없애는 것 — 이 패턴들은 취약점이 아니라 특정 위협과 직접 관련됨. 보안 패턴은 과거의 사고와 취약점을 기반으로 하므로, 새로운 위협이 발생하면 조직은 새로운 보안 패턴을 개발해야 함.

### 보안 패턴을 시각화하는 방법
- 개발자는 다이어그램으로 보안 패턴을 예시화할 수 있음 — **UML(Unified Modeling Language)**은 시스템의 아키텍처와 설계를 더 잘 이해하기 위해 시스템을 시각적으로 모델링·표현할 수 있음.
- 소프트웨어 설계를 통해서도 보안 패턴을 예시화할 수 있음 — 실제 코드를 분석하면 개발자가 소프트웨어가 애플리케이션, 서비스, 네트워크의 전체 보안에 어떻게 영향을 미치는지 이해하는 데 도움이 됨.

### 보안 패턴의 구조
- 보안 패턴이 포함해야 할 요소:
  - 설계가 **자산-, 서비스-, 프로세스 중심**이어야 함.
  - 개발자에게 단계와 프로세스를 제공하기 위해 위협을 분석하고 모델링해야 함.
  - 재사용성을 촉진하기 위해 위협 모델을 보안으로 다시 추적할 수 있어야 함.
  - 추적 가능성과 재사용성을 위해 표준 분류 체계(taxonomy)를 사용해야 함.

### 보안 패턴 조직화하기
- 유형과 주제에 따라 다양한 보안 패턴을 **보안 패턴 카탈로그**로 조직·분류할 수 있음 — 예: 인증, 접근 제어, 네트워크 트래픽 필터링 아래 분류 가능.
- 다른 예시로 인가(Authorization), 역할 기반 접근 제어, 방화벽, SAML·XACML·XML 방화벽 같은 웹 서비스 보안이 있음.

### 카탈로그화의 이점
- 보안 패턴 카탈로그는 소프트웨어 개발자가 애플리케이션 코드에 필요한 추가 보안 기능을 개발하기 위한 보안 패턴을 검토하고 선택할 수 있게 함.
- 배포를 위한 개발 시, 잘 분류된 보안 패턴 카탈로그는 개발자가 여러 애플리케이션에 걸쳐 보안 패턴을 재사용할 수 있게 함.
- 개발자는 또한 보안 패턴 카탈로그에 의존해 관련 보안 메커니즘을 더 잘 인식하게 됨 — 예: 네트워크 방화벽이 나가는 연결을 차단할 수 있고, 그에 대응하는 보안 패턴의 참조가 보안 패턴 카탈로그에 있음. 이 보안 패턴이 존재한다는 것을 알면, 개발자는 자신의 코드에 보안 메커니즘을 코딩해 추가 보안을 더하고 전반적인 애플리케이션 보안을 향상시킬 수 있음.
- 분류 외에도, 철저한 문서화는 보안 패턴을 더 사용하기 쉽게 만드는 또 다른 측면 — 개발자는 접근하기 쉽고, 정확하고, 읽고 따라 하기 쉬운 문서를 더 자주 참조하게 됨. 보안 패턴이 더 사용하기 쉽고 적용 가능할수록, 불필요한 코딩의 가능성은 줄어듦.
- 또한 보안 패턴은 개발자가 시스템 보안의 흔한 보안 패턴에 대해 더 배울 수 있게 함 — 새 보안 패턴에 대한 깊은 이해와 지속적인 학습을 통해 개발자는 보안 목표, 소프트웨어 개발 계획, 조직의 보안 조치를 지원 가능.

## 요약
- 보안 패턴은 반복되는 보안 위협에 대한 재사용 가능한 해법을 정의하는 규칙 집합으로, 위협 문서화·자산 영향 확립·사용법 표준화·통제 추적성 유지·벤더 중립성이라는 요소를 갖추고 UML이나 실제 코드 분석으로 시각화되며, 인증·접근 제어·네트워크 필터링 같은 유형과 주제에 따라 카탈로그로 분류하고 철저히 문서화하면 개발자가 여러 애플리케이션에 걸쳐 검증된 보안 메커니즘을 재사용하고 조직의 보안 목표를 지속적으로 지원할 수 있게 된다.
