# The OSI Model — 대화정리

> 원본 강의 노트: [06 The OSI Model.md](06%20The%20OSI%20Model.md) · 학습일 2026-09-04
> 네트워크 서비스 로드맵 Phase 1 · 1-A

## 개요

- 층을 나눈 이유를 "각 층이 하는 일이 다르다"에서 출발해 **"각 층이 위층에게 결과를 보장해서 넘긴다"** 까지 밀어붙였다.
- 3계층(경로)과 4계층(쪼개기 + 순서·도착 보장)의 역할을 갈랐고, **보장에 따르는 대가(크기 + 지연)** 를 통화·이메일 비교로 확인했다.
- 강의가 강조한 상위 3계층(5·6·7)이 왜 개발자 몫인지, 각 층에 붙은 보안 이야기가 무엇인지 정리했다.

## 내용

### 층을 나누는 이유 — "아래가 바뀌어도 위는 모른다"

층마다 책임이 다르다는 게 출발점이지만, 진짜 이득은 **아래 층 구현이 바뀌어도 위층 코드를 고치지 않아도 되는 것**이다.

유선 케이블 → Wi-Fi로 바꾸면 1계층(물리)이 완전히 달라진다. 그래도 브라우저(7계층)는 손댈 게 없다.

왜 몰라도 되는가 — 아래 층이 위층에게 **결과를 보장해서** 넘기기 때문이다.

| 층 | 아래에서 받는 것 | 위로 넘기는 것 |
|---|---|---|
| 1 물리 | — | 그냥 흘려보낸 비트 (잘 갔는지 모름) |
| 2 데이터 링크 | 전기 신호 비트 | **오류 없이 도착이 확인된 프레임** |
| 4 전송 | 뒤섞여 도착한 조각들 | **보낸 순서대로 맞춰진 데이터** |

2계층이 그 보장을 만드는 방법이 강의에 나온 **데이터 프레임 + 응답 프레임(acknowledgment frame)** 이다. 받은 쪽이 확인 응답을 돌려보내므로 "도착했다"가 확인된다.

### 3계층과 4계층 — 경로 vs 쪼개기

100MB 파일을 서울 → 뉴욕으로 보낸다고 할 때:

- **3계층(Network)** — 이 패킷을 **어떤 경로로** 보낼 것인가. 갈림길마다 목적지를 보고 다음 지점으로 넘기는 일이 **라우팅(routing)**. 강의의 "정적 테이블(static table)"은 그 길 선택표를 사람이 직접 적어두는 방식.
- **4계층(Transport)** — 데이터를 **어떻게 잘라서** 보낼 것인가. 그리고 **순서대로·빠짐없이 도착하게 보장**.

조각들이 서로 다른 경로로 갈 수 있으니 도착 순서가 뒤섞인다. 그래서 4계층이 원래 순서로 되돌려 위층에 올린다.

### 보장의 대가 — 크기와 시간

강의는 4계층이 연결 시점에 **서비스 유형을 고를 수 있다**고 하고, 그 선택지에 "같은 순서 보장"과 함께 **"순서 비보장"** 도 넣어 두었다. 보장이 항상 이득이 아니기 때문이다.

1. **크기** — 순서를 되돌리려면 순서 정보를 조각마다 붙여야 하므로 보낼 데이터가 늘어난다.
2. **시간(핵심)** — 3번 조각이 유실되면 4번·5번이 이미 도착해 있어도 **위층에 올릴 수 없다.** 3번이 다시 올 때까지 뒤가 전부 대기한다.

그래서 강의 첫머리의 "이메일 · 전화 통화 · 스트리밍" 중:

| | 기다림의 대가 | 보장 |
|---|---|---|
| 이메일 | 3초 늦게 도착해도 상관없다 | 보장하는 게 이득 |
| 전화 통화 | 실시간 대화라 기다리면 대화가 끊긴다 | **포기하는 게 이득** |

통화에서는 늦게 온 조각을 재전송으로 받아내도 **그 순간이 이미 지나가서 쓸 데가 없다.** 그래서 버리고 흘려보내는 쪽이 낫다.

### 개발자가 5~7계층을 보는 이유

1~4계층은 운영체제·네트워크 장비·통신사가 **이미 구현해 놓은 층**이다. 개발자가 코드를 쓰는 자리는 5~7계층이고, 그래서 **손댈 수 있는 층 = 책임져야 하는 층**이다. 강의가 상위 3계층에 보안 이야기를 하나씩 붙인 이유가 여기 있다.

**6계층(Presentation) — 왜 암호화가 여기 있는가**

6계층은 **데이터의 모양을 바꾸는 층**이고, 그 변환은 늘 짝으로 움직인다.

- 직렬화 ↔ 역직렬화
- 압축 ↔ 압축 해제
- **암호화 ↔ 복호화**

셋이 같은 구조다. 내용(의미)은 그대로 두고 표현만 바꿔 보내고, 받는 쪽에서 되돌린다. 암호화는 "받는 쪽만 되돌릴 수 있는 변환"일 뿐이다. 강의는 여기에 **보안 소켓 암호화**를 넣어 **중간자 공격(man-in-the-middle attack)** 을 막는다고 설명한다.

**7계층(Application) — HTTPS와 443**

강의는 7계층에서 다시 **443번 포트와 HTTPS**를 들며 "사용자와 신뢰를 구축한다"고 한다. 6계층 암호화와 별개의 이야기가 아니라 **같은 이야기를 다른 층에서 본 것**이다.

- 6계층 = 암호화라는 변환이 **일어나는 자리**
- 7계층 = 그걸 **켜는 방법** (HTTP 대신 HTTPS, 80 대신 443)

개발자가 실제로 하는 일은 후자 하나이고, 그 결과로 전자가 동작한다.

**5계층(Session) — 토큰 관리**

강의는 세션 계층의 이점으로 **대화 통제(dialog control)**, **전송 순번 추적**, **토큰 관리(token management)** 를 든다. 토큰 관리는 "두 사용자가 동시에 같은 중요한 작업을 시도하는 것을 없애는" 것이다.

좌석 하나 남은 항공권을 두 사람이 동시에 결제하면 좌석 하나에 승객이 둘이 된다. 토큰은 이걸 막아 **먼저 잡은 하나만 진행하고 나머지는 못 하게** 한다.

## 예시

### 층을 나눈 덕분에 몰라도 되는 것

```
[7 응용]  브라우저 — HTTP 요청을 쓴다
[6 표현]  직렬화 / 압축 / 암호화 ← HTTPS를 켜면 여기가 동작
[5 세션]  연결 수립, 대화 주도권(토큰)
──────────  여기까지가 개발자의 자리
[4 전송]  쪼개기 + 순서·도착 보장  (보장 여부 선택 가능)
[3 네트워크] 경로 선택 = 라우팅
[2 링크]  프레임 + 응답 프레임으로 "도착 확인"
[1 물리]  비트 전송 — 유선? Wi-Fi? 위층은 모른다
```

### 유실 한 조각이 뒤를 막는다

```
보낸 순서:  1 2 3 4 5
도착 상태:  1 2 ✗ 4 5      ← 3번 유실
순서 보장:  1 2 [ 대기… ]   ← 4·5는 도착했는데 못 올라간다
순서 비보장: 1 2 4 5        ← 3번은 버리고 그냥 진행 (통화)
```

## 오해했다가 교정된 지점

| 내가 생각한 것 | 강의·정리에서 확인한 것 |
|---|---|
| 층 사이에 오가는 건 "약속된 데이터 형식"이다 | 형식만이 아니라 **결과(보장)** 다. 2계층은 형식을 알려주는 게 아니라 "오류 없이 도착이 확인된 프레임"을 만들어 넘긴다. |
| 토큰 관리는 토큰으로 **사용자를 식별**하는 것 | 결과(먼저 잡은 하나만 진행)는 맞지만, 여기서 토큰은 식별표가 아니라 **"지금 작업할 차례라는 발언권"** 이다. 마이크를 든 사람만 말할 수 있는 규칙. 그래서 세션 계층의 **대화 통제**와 나란히 놓인다. |
| 토큰 관리는 6계층 이야기 | **5계층(Session)** 이다. 6계층은 직렬화·압축·암호화 쪽. |

### 강의 밖 확인 — OSI 세션 ≠ 웹 세션 / JWT

이름만 겹치는 다른 개념이다.

| | OSI 5계층의 세션·토큰 | 웹 세션 쿠키 · JWT |
|---|---|---|
| 사는 곳 | 두 머신 사이의 통신 연결 | 7계층 애플리케이션 코드 |
| 관리하는 것 | 연결이 살아 있는가, 전송 순번, 누가 보낼 차례인가 | 이 HTTP 요청을 보낸 게 누구인가 |
| 목적 | 대화의 진행·복구 | 사용자 인증·식별 |

웹 세션·JWT가 필요한 이유는 HTTP가 요청 하나하나를 서로 모르는 상태로 처리하기 때문이다. 하나는 **회선**을, 하나는 **사람**을 관리한다.

## 요약

- OSI는 컴퓨터 통신을 7계층으로 나눈 모델이다. 나눈 이유는 **아래 층이 바뀌어도 위층이 신경 쓰지 않아도 되게** 하는 것이고, 그게 가능한 건 각 층이 위층에게 **결과를 보장해서** 넘기기 때문이다.
- 3계층은 **경로(라우팅)**, 4계층은 **쪼개기 + 순서·도착 보장**을 맡는다.
- 보장은 공짜가 아니다 — 순서 정보만큼 **크기**가 늘고, 한 조각이 유실되면 뒤가 전부 **대기**한다. 그래서 실시간 통화는 보장을 포기하는 쪽이 낫다.
- 1~4계층은 이미 구현돼 있으므로 개발자는 **5~7계층**을 본다. 그 층이 손댈 수 있는 층이고, 따라서 **보안 책임도 거기** 있다 — 6계층 암호화(중간자 공격 방지), 7계층 HTTPS·443.
