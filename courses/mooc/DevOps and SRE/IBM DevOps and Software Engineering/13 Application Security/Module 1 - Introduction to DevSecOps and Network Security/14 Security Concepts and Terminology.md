# Security Concepts and Terminology

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/wrQTz/security-concepts-and-terminology)

## 개요
- 인증(Authentication)·인가(Authorization)·암호화(Encryption)·무결성(Integrity) 같은 핵심 보안 용어를 명확히 구분하고, CI/CD 파이프라인에 보안을 적용하는 구체적인 방법을 정리.

## 내용
### 인증(Authentication) vs 인가(Authorization)
- **인증**은 사용자의 신원을 확인하는 과정 — 누군가 정말로 자신이 주장하는 사람이 맞는지 확인하는 것(신원이 진짜임을 확인).
- **인가**는 사용자의 접근 권한을 결정하는 과정 — 다시 말해, 그 사람이 누구인지 알았으니 이제 "무엇을 하도록 허용되는가?"를 정하는 것.
- 사용자를 인증하면 그 사용자는 인가될 수 있음 — 인가는 그 사용자가 허용된 것만 할 수 있도록 보장.

### 암호화(Encryption)
- 승인된 접근 권한을 가진 사용자만 해독할 수 있도록 정보를 인코딩하는 과정 — 승인된 접근이란 올바른 접근 권한을 가지고 있다는 뜻.
- 암호화에는 두 가지 주요 유형이 있음:
  - **대칭 암호화(Symmetric encryption)** — 암호화와 복호화에 같은 키를 사용.
  - **비대칭 암호화(Asymmetric encryption)** — 암호화와 복호화에 서로 다른 키를 사용.

### 무결성(Integrity)
- 정확한 정의가 없어 보이지만 실제로는 명확함 — 데이터가 인증되지 않은 소스에 의해 변경되지 않았음을 보장하는 과정. 즉, 읽고 있는 데이터를 신뢰할 수 있다는 의미.
- 무결성을 달성하는 한 방법은 **보안 해시 알고리즘(secure hash algorithm)**을 사용하는 것 — 데이터의 해시를 만들어, 나중에 그 알고리즘을 다시 적용했을 때 예상과 다른 결과가 나오면 데이터가 변조되었음을 나타냄.

### CI/CD 용어의 정확한 의미
- CI/CD의 핵심 아이디어는 애플리케이션 개발 파이프라인에서 자동화를 사용하는 것.
- **CI(Continuous Integration)**는 새 코드 변경이 정기적으로 빌드·테스트·병합됨을 의미.
- **CD**는 실제로 두 개념을 가리킴:
  - **Continuous Delivery(지속적 전달)** — 테스트된 변경이 개발·테스트·스테이징 환경에 자동으로 릴리스됨을 의미.
  - **Continuous Deployment(지속적 배포)** — 새 릴리스가 프로덕션에 자동으로 배포됨을 의미.

### CI/CD 파이프라인에 보안 적용하기
- CI/CD 파이프라인의 보안은 SDLC에 필수적 — 비교적 쉽게 보안을 적용할 수 있음. 예:
  - 지속적 통합 단계 초기에 소스 코드를 스캔.
  - 소스 코드 스캐닝과 분석을 수행해 취약점을 드러냄.
  - CI/CD 파이프라인에 더 많은 테스트를 추가.
  - 다른 CI/CD 테스트와 함께 보안 테스트를 수행.
  - 배포 이후에도 새로운 위협을 지속적으로 탐지·보고.
  - 프로덕션에서 발생하는 위협을 탐지하기 위해 런타임 보안을 통합.

## 요약
- 인증은 사용자가 누구인지 확인하고 인가는 그 사용자가 무엇을 할 수 있는지 결정하며, 암호화는 같은 키(대칭)나 다른 키(비대칭)로 정보를 인코딩하고, 무결성은 보안 해시 알고리즘 등으로 데이터가 변조되지 않았음을 보장하며, CI(빌드·테스트·병합 자동화)와 CD(지속적 전달+지속적 배포)로 이뤄진 CI/CD 파이프라인에는 소스 코드 스캔·보안 테스트·런타임 보안 통합 같은 방법으로 보안을 적용할 수 있다.
