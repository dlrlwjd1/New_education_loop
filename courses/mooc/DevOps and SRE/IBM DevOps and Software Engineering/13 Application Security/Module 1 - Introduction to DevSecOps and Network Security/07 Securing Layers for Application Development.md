# Securing Layers for Application Development

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/A7COI/securing-layers-for-application-development)

## 개요
- 케이크의 여러 겹(layer)에 비유해, 애플리케이션 개발에서 보안해야 할 4가지 계층(웹 애플리케이션, 클라우드 인프라, 통신, 코드 전달 파이프라인)과, 로깅·분석·침입 탐지 방법을 정리.

## 내용
### 층층이 쌓인 보안 — 케이크 비유
- 케이크는 여러 겹의 맛과 프로스팅으로 만들어지며, 이 층들이 시각적 매력과 풍부한 맛을 줌 — 이는 개발자를 위한 여러 겹의 보안을 확보하는 것에 대한 훌륭한 비유.

### 계층 1 — 웹 애플리케이션 계층
- **프런트엔드**는 HTTPS를 통해 여러 기기에서 웹 브라우저로 실행되는 JavaScript, CSS, HTML 코드로 구성될 수 있음. **백엔드**는 사용자의 애플리케이션 경험 동안 프런트엔드에 데이터를 제공하는 데이터베이스로 구성.
- **미들 레이어**는 Python, Java, Ruby 같은 언어로 개발된 **API**를 통해 프런트엔드와 백엔드 사이의 연결을 제공.
- 개발자로서 웹 애플리케이션의 모든 계층을 테스트해야 함 — 취약점 스캐너 실행, 테스트 실행, 프로덕션 배포 전 다른 팀 개발자가 웹 애플리케이션을 감사(audit)하도록 허용.

### 계층 2 — 클라우드 인프라
- 클라우드 기반 데이터베이스는 사용자명, 비밀번호, 기타 기밀 정보 같은 사용자 정보의 원천 — 사이버 위협이 발생할 경우를 대비해 클라우드 기반 데이터베이스에 연결하는 애플리케이션을 개발할 때 관리자 자격 증명을 포함하지 않도록 주의해야 함.
- 또 다른 보호 조치는 특정 클라우드 리소스에 대한 접근을 제한하는 **보안 그룹(security group)**을 만드는 것.
- 접근 제한에 더해, 안전한 코드는 웹 애플리케이션의 모든 사용자에 대해 **2단계 인증(two-factor authentication)**을 구현해야 함 — 전화든 문자 인증이든, 악의적 행위자의 무단 침입 가능성을 줄이기 위해 강력한 인증을 포함해야 함.

### 계층 3 — 통신 계층
- SSH, HTTPS, SSL/TLS를 이용해 관리하는 것이 중요.
- **SSH(Secure Shell)**는 물리 서버·클라우드 서버 같은 원격 장치에 연결할 때의 보안 연결 보호 — SSH를 구현하면 개발자는 코드를 업로드·배포·테스트할 때 원격 장치와의 연결을 안전하게 지킬 수 있음.
- **SSL/TLS**는 클라이언트와 서버 사이의 연결을 안전하게 지키는 데 필수적인 기술 — SSL/TLS로 안전하게 연결된 데이터 전송은 중간자 공격을 시도하는 해커가 통신을 가로채지 못하도록 보장.

### 계층 4 — 보안 코드 전달 파이프라인 계층
- 개발자가 애플리케이션 프로젝트에 코드를 커밋해야 할 때, 이 계층도 안전하게 지키고 제한해야 함 — GitHub의 코드 저장소를 특정 권한으로 잠그고 정기적으로 감사를 수행할 수 있음.
- GitHub과 각 클라우드 제공자 같은 서드파티를 인증하는 데도 2단계 인증이 중요.
- 클라우드 소스를 애플리케이션 개발에 사용한다면, 개발 시 필요와 역할에 따라 클라우드 자산을 안전하게 지키기 위해 **IAM(Identification and Access Management)**을 설정해야 함 — IAM 역할은 클라우드 인프라 안에서 애플리케이션과 시스템에 권한을 부여하는 중요한 보안 메커니즘.
- 마지막으로 시크릿 비밀번호, 인증서, 암호화 키는 **HashiCorp Vault** 같은 시크릿 저장 서비스에 저장해야 함.

### 로깅과 분석
- 모든 애플리케이션은 이상 징후(anomaly)를 식별하기 위해 로그 메시지를 수집하는 **로깅 시스템**을 가져야 함 — 이상 징후는 애플리케이션이나 시스템 내에서 발생하는 고유하고 예상치 못한 사건. 예: 필요한 자격 증명 없이 시스템 관리자로 로그인을 시도하는 것.
- 로깅은 개발자가 향후 검사를 위해 분석·저장하는 또 다른 보안 계층으로 여겨짐.
- 로그 메시지에 대한 접근은 모든 시스템 사용자에게 제공되어서는 안 되며, 검토·분석을 위해 접근이 필요한 신뢰할 수 있는 사람에게만 제공되어야 함.

### 최종 방어선 — 침입 탐지(Intrusion Detection)
- 침입 탐지는 애플리케이션이나 시스템을 위협하는 사이버 공격, 위협, 침입을 지속적으로 탐지하는 것.
- 침입 탐지의 3가지 방법:
  - **엔드포인트 보안(Endpoint Security)** — 네트워크에 연결된 시스템, 서버, 다양한 유형의 장치를 보호.
  - **네트워크 보안(Network Security)** — Nmap, Snort 같은 네트워크 도구로 네트워크를 모니터링.
  - **시스템 콜 감사(System-Call Auditing)** — Linux 커널 같은 커널로부터 시스템 콜 정보를 가져와 검토.

## 요약
- 애플리케이션 개발의 4가지 보안 계층은 취약점 스캐너·테스트·감사로 지키는 웹 애플리케이션 계층(프런트엔드/백엔드/API), 관리자 자격 증명 배제·보안 그룹·2단계 인증으로 지키는 클라우드 인프라, SSH와 SSL/TLS로 지키는 통신 계층, 그리고 GitHub 권한 제한·IAM·HashiCorp Vault로 지키는 보안 코드 전달 파이프라인 계층이며, 여기에 이상 징후를 잡아내는 로깅 시스템과 엔드포인트 보안·네트워크 보안·시스템 콜 감사로 구성된 침입 탐지가 최종 방어선 역할을 한다.
