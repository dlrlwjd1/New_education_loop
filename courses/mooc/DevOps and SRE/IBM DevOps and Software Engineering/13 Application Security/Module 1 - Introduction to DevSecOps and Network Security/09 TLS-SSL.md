# TLS/SSL

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/dgp0m/tls-ssl)

## 개요
- TLS(Transport Layer Security)와 SSL(Secure Sockets Layer)의 관계, 최신 TLS가 안전한 연결을 확립하는 4단계 과정, 그리고 SDLC에서 TLS를 안전하게 유지하는 방법을 정리.

## 내용
### SSL과 TLS란
- 둘 다 네트워크 컴퓨터, 구체적으로는 서버와 클라이언트 사이에 안전한 연결을 확립하기 위한 프로토콜.
- "안전(secure)"하다는 것은, 누군가 통신을 가로채더라도 암호화 때문에 읽을 수 없어 쓸모가 없다는 의미 — 간단히 말해 인터넷이나 컴퓨터 네트워크를 통해 전송되는 데이터를 보호한다는 뜻.
- SSL과 TLS 모두 웹 브라우저와 서버 사이의 보안을 제공. 사실 TLS는 SSL의 후속(successor) — TLS의 첫 버전인 TLS 1.0은 1999년에 도입됨. 오늘날 사람들이 SSL이나 TLS/SSL을 말할 때는 보통 **최신 TLS**를 가리킴.

### 최신 TLS의 작동 방식 — 4단계
- 높은 수준에서 4단계를 사용 — 이 단계들을 따르면 SDLC에서 TLS가 안전하게 유지되는지 확인할 수 있음.
1. 두 컴퓨터가 보안 TLS 프로토콜로 통신하려면 먼저 사용할 **TLS 버전**에 합의해야 함 — 둘 다 지원하는 가장 높은 버전을 선택. 두 컴퓨터가 지원하는 버전이 없다면 과정이 실패함.
2. 클라이언트와 서버 컴퓨터가 사용할 TLS 버전에 합의하면, 그 버전에서 사용할 지원되는 **암호(cipher)**에 합의 — 암호는 서버와 클라이언트 사이에서 정보가 어떻게 암호화될지 정의.
3. 암호가 선택되면, 클라이언트가 서버의 공개 키와 서버의 TLS 인증서 서명을 이용해 **서버의 신원을 검증**.
4. 마지막으로 두 컴퓨터가 각자 인증서의 공개 키와 개인 키를 이용해 **세션 키**를 생성 — 이 키들은 2단계에서 선택한 암호에 사용되며, 서버와 클라이언트가 안전하게 통신할 수 있게 해주는 비밀.

### SDLC에서 TLS를 안전하게 유지하는 방법 — 두 가지 요소
1. **CI/CD로 TLS 인증서를 만료 전에 갱신** — 보통 1~2년마다 만료되지만, 몇 달마다처럼 더 일찍 갱신하는 것이 좋은 관행.
2. **애플리케이션의 TLS 버전 지원을 최신 상태로 유지** — 사용 가능한 가장 최신 TLS 버전을 지원해야 함. 또한 가장 견고한 암호를 우선하고 취약한 암호는 어떤 경우에도 피해야 함 — 이는 종종 TLS 1.0, 1.1 같은 오래된 버전에 대한 지원을 중단하는 것을 의미.

### 결론
- TLS와 SSL은 클라이언트와 서버 사이의 안전하고 신뢰할 수 있으며 매끄러운 통신에 기여 — 이 프로토콜들을 구현함으로써 데이터의 기밀성과 무결성을 보호하고 보장할 수 있음.

## 요약
- TLS는 SSL의 후속 프로토콜로, 오늘날 "SSL"이라 불릴 때도 실제로는 대부분 최신 TLS를 가리키며, TLS 버전 합의 → 암호 합의 → 서버 신원 검증(TLS 인증서 서명) → 세션 키 생성이라는 4단계로 안전한 연결을 확립하고, SDLC에서는 CI/CD로 인증서를 만료 전에 정기적으로 갱신하고 최신 TLS 버전과 견고한 암호를 유지(구버전인 TLS 1.0/1.1 지원 중단 포함)함으로써 TLS를 지속적으로 안전하게 관리해야 한다.
