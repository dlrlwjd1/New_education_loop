# Threat Monitoring

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/eSKCd/threat-monitoring)

## 개요
- 코드 저장소와 컨테이너를 스캔해 보안 이슈를 찾는 **위협 모니터링(Threat Monitoring)**을 정의하고, 저장소 스캐닝과 컨테이너 스캐닝 각각의 동작 방식을 설명.

## 내용
### 위협 모니터링이란
- 코드 저장소와 컨테이너를 스캔해 보안 이슈를 찾는 것 — 비밀번호 오처리(password mishandling), 프로토콜 불안전성, 잘못된 권한 설정이 위협 모니터링으로 발견할 수 있는 이슈의 예.
- 위협 모니터링은 SDLC의 **개발(Develop), 테스트(Test), 배포(Deploy)** 세 단계에 걸쳐 통합됨. IDE와 SCM(소스 코드 관리) 도구에서 코드 스캐닝을 사용하면 개발부터 배포까지 보안 검사를 통합해 SDLC를 지원. 코드 스캐닝 도구는 OWASP Top 10 같은 보안 위협·취약점을 저장하는 데이터베이스를 참조.
- 위협 모니터링을 수행하기 위해 **코드 체커(code checker)** 도구를 사용할 수 있음 — 소스 코드를 스캔해 보안 이슈와 취약점을 찾아 코딩 문제를 알려줌. 코드 체커는 코딩 구문, 스타일, 문서화 같은 속성에서 문제를 찾기 위해 코드를 분석. 코드 체커는 코드에서 무엇을 고쳐야 하는지에 대한 통찰을 제공 — 이를 활용하면 안전한 코드를 개발하고 애플리케이션 품질을 향상시키는 데 도움.

### 저장소 스캐닝(Repository Scanning)
- 코드 저장소는 종종 협업적이고 오픈소스이기 때문에 상당한 보안 위협·취약점 위험을 지님.
- 코드 저장소와 위협 모니터링을 통합하면 GitHub 같은 SCM 도구의 코드 스캐닝이 가능해짐 — 코드 저장소를 스캔하는 동안 자동으로 "수정(fix)" Pull Request를 생성하는 코드 프로젝트 모니터링을 활용 가능.
- 코드 스캐너는 저장소의 코드를 스캔한 뒤 취약점 리포트와 통찰을 제공. 또한 모든 Pull Request를 스캔·테스트해 보안 취약점을 확인하고, 신뢰할 수 있는 소스의 검증으로서 공개 암호화 키(PGP, Pretty Good Privacy)로 커밋에 서명함.

### 컨테이너 스캐닝(Container Scanning)
- 또 다른 위협 모니터링 유형으로, 코드를 담고 있는 컨테이너 이미지를 스캔하는 과정 — 컨테이너는 애플리케이션 코드와 그 패키지 라이브러리 의존성의 묶음.
- 컨테이너는 의존성을 가지기 때문에 외부 소스로부터의 보안 취약점에 노출됨. 컨테이너 스캐닝은 컨테이너에 배포된 코드(취약점과 보안 위협을 포함할 수 있는)를 스캔.
- 컨테이너 이미지는 보통 취약점이 있을 수 있는 다른 컨테이너 이미지로부터 빌드되므로, 컨테이너 스캐닝은 베이스 이미지뿐 아니라 계층화된 다른 모든 컨테이너 이미지도 포함해야 함 — 모든 컨테이너 이미지를 모니터링하면 보안 위험을 줄이는 데 도움.

## 요약
- 위협 모니터링은 SDLC의 개발·테스트·배포 단계에 걸쳐 코드 저장소와 컨테이너를 스캔해 보안 이슈를 찾는 것으로, 코드 체커로 소스 코드의 구문·스타일·문서화 문제를 찾고, GitHub 같은 SCM 도구와 통합해 Pull Request마다 자동으로 취약점을 스캔·수정 제안하고 PGP로 커밋을 검증하는 저장소 스캐닝, 그리고 베이스 이미지부터 계층화된 모든 이미지까지 포함해 스캔하는 컨테이너 스캐닝으로 구성된다.
