# The OSI Model

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/application-security-for-developers-devops/lecture/9AyOV/the-osi-model)

## 개요
- 네트워크 통신을 이해하기 위한 **OSI(Open Systems Interconnection) 모델**의 7개 계층을 소개하고, 개발자가 특히 집중해야 할 상위 3개 계층(Session, Presentation, Application)과 그 보안 함의를 설명.

## 내용
### OSI 모델이란
- 인터넷은 상호 연결된 케이블을 통해 전 세계로 뻗어나가는 복잡한 네트워크의 네트워크 — 이메일, 전화 통화, 스트리밍 등 온갖 종류의 데이터가 인터넷을 오감. 인터넷 개척자들은 현재와 미래의 모든 통신 유형을 전 세계 누구나 사용할 수 있게 하는 시스템을 만들어야 했고, 이를 위해 **OSI 모델**을 고안.
- OSI 모델은 데이터를 주고받기 위한 **7개 계층**으로 구성.

### 7개 계층
1. **Physical Layer(물리 계층)** — 원시 정보 비트를 전송하는 것이 목적. 데이터를 주고받을 때 사용되는 일관된 통신 채널 — 예: 통신 채널의 한쪽 끝에서 전송하면 다른 쪽 끝에서 받아야 함.
2. **Data Link Layer(데이터 링크 계층)** — 전송된 원시 데이터를 감지되지 않은 오류가 없는 라인으로 변환 — **데이터 프레임(data frame)**을 이용해 이 변환이 일어남. 데이터 프레임은 100바이트나 1000바이트 그룹 단위로 순차적으로 전송됨. 데이터 프레임을 받으면 수신자가 올바른 수신을 확인하는 응답 프레임(acknowledgment frame)을 돌려보냄.
3. **Network Layer(네트워크 계층)** — 데이터 전송과 서브넷의 제어를 다룸. 이 계층은 출발지에서 목적지까지 얼마나 많은 패킷이 어떻게 라우팅되는지 결정. 예: 네트워크 관리자라면 네트워크와의 데이터 라우팅을 위한 정적 테이블로 네트워크 경로를 관리할 수 있음.
4. **Transport Layer(전송 계층)** — 상위 계층에서 전송이나 데이터를 받아 네트워크 계층으로 전달하기 위해 더 작은 단위(패킷)로 잘게 나눔. 또한 모든 단위가 종단 간(end-to-end) 올바르게 도착하도록 보장 — 이 계층은 보낸 순서 그대로 데이터를 전달하는 오류 없는 지점 간(point-to-point) 채널을 제공. 연결 시점에 전송 계층은 서비스 유형을 선택 가능(같은 순서 보장, 순서 비보장, 여러 목적지로 데이터 전송 등).
5. **Session Layer(세션 계층)** — 크래시가 발생하더라도 일관된 세션을 확립하면서 서로 다른 머신으로부터 여러 세션을 확립. 대화 통제(dialog control)나 전송 순번 추적, 두 사용자가 동시에 같은 중요한 작업을 시도하는 것을 없애는 토큰 관리(token management) 같은 이점 제공. 긴 전송이 재개될 수 있도록 세션을 재확립하기 위한 동기화도 제공.
6. **Presentation Layer(표현 계층)** — 한 지점에서 다른 지점으로 전송되는 데이터의 구문과 의미론에 초점. 최종 목적지에서 원본 형식을 재구축하기 위해 데이터 스트림에 대해 직렬화·역직렬화 과정을 수행. 예: JPEG, GIF, ASCII 텍스트 같은 포맷/파일 유형이 표현 계층에서 널리 자주 사용됨. 이 계층은 데이터 압축, 암호화·복호화도 제공.
7. **Application Layer(애플리케이션 계층)** — OSI 모델의 최상위 계층. 주로 개발자가 애플리케이션을 만들고 배포하는 데 이 계층을 사용. 브라우저, 웹 페이지, 다른 웹 기반 애플리케이션이 애플리케이션 계층에서 데이터를 전송. 웹 외에도 파일 전송, 이메일, 네트워크 뉴스 같은 다른 애플리케이션들도 7계층을 사용.

### 개발자가 집중해야 할 계층
- 개발자는 OSI 모델의 **상위 3개 계층**을 인지하고 집중해야 함: 5계층(Session), 6계층(Presentation), 7계층(Application).
- 클라이언트가 서버에 리소스를 요청하면, 클라이언트와 서버 사이의 연결이 만들어지는데 이는 **세션 계층**에서 일어남.
- **표현 계층**에서 보안 소켓 암호화(secure socket encryption)를 통합해 사용자가 제출한 데이터를 잠재적인 중간자 공격(man-in-the-middle attack)으로부터 안전하게 지킬 수 있음.
- 애플리케이션을 안전하게 만드는 또 다른 방법은 **443번 포트와 HTTPS**(보안이 적용된 HTTP)를 사용하는 것 — 애플리케이션 수준에서 안전하지 않은 통신을 없앰으로써, 소프트웨어 개발자는 애플리케이션 사용자와 필요한 신뢰를 구축할 수 있음.
- OSI 모델은 네트워크 통신 개념을 이해하고 논하기 위한 효과적인 도구이며, 많은 현대 네트워크 표준과 기술의 기초.

## 요약
- OSI 모델은 Physical → Data Link → Network → Transport → Session → Presentation → Application 순서의 7개 계층으로 네트워크 통신을 구성하며, 개발자는 특히 세션이 확립되는 Session 계층, 데이터 형식·암호화가 이뤄지는 Presentation 계층(보안 소켓 암호화로 중간자 공격 방지), 그리고 브라우저·웹 애플리케이션이 동작하는 Application 계층(포트 443과 HTTPS로 안전한 통신 보장)이라는 상위 3개 계층에 집중해야 한다.
