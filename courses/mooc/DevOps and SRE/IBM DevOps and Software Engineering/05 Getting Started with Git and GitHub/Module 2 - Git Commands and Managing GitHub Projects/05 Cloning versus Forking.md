# Cloning versus Forking

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/getting-started-with-git-and-github/lecture/7zKO3/cloning-versus-forking)

## 개요
- 해당 프로젝트를 작업하는 각 개발자는 자신의 컴퓨터에 로컬 리포지토리라고 하는 자체 리포지토리 복사본과 GitHub.com에 원격 리포지토리라고 하는 자체 리포지토리 사본을 둘 수 있습니다.

## 내용
- 해당 프로젝트를 작업하는 각 개발자는 자신의 컴퓨터에 로컬 리포지토리라고 하는 자체 리포지토리 복사본과 GitHub.com에 원격 리포지토리라고 하는 자체 리포지토리 사본을 둘 수 있습니다.
- Grand Messaging이라는 기존 프로젝트가 있는데 원본 프로젝트에 비해 추가 기능 및 개선 사항을 제공하는 Grand Messaging Plus라는 새 프로젝트 또는 파생 프로젝트를 만들려고 한다고 가정해 보겠습니다.
- 간단히 기존 Grand Messaging 프로젝트를 포크하고 Grand Messaging Plus를 만든 다음 기존 코드 베이스를 기반으로 개발하여 새롭고 향상된 기능을 제공하면 됩니다.
- 의도한 변경이 완료되면 새로 생성된 브랜치에 대해 업스트림 브랜치를 설정하고 변경 내용을 새 브랜치에 푸시한 다음, 검토한 후 새 브랜치의 변경 사항을 메인 브랜치에 병합해 달라고 관리자에게 요청해야 합니다.포킹 워크플로를 다시 살펴보겠습니다.
- 개발자는 로컬 머신에서 클론을 생성하고 변경한 다음, pull 요청을 생성하여 git push를 사용하여 업데이트된 메인 브랜치를 오리진으로 다시 푸시할 수 있습니다.
- 그런 다음 오리진을 사용하여 git clone 명령어를 사용하여 원격 리포지토리의 동일한 복사본을 생성하면 개발자가 컴퓨터에서 사용할 수 있습니다.
- 브랜치를 생성하고 변경 내용을 동기화할 때 사용하는 git 명령어는 브랜치를 생성하는 git branch, 브랜치를 활성화하는 git checkout, 변경 사항을 저장하는 git add 및 git commit, 브랜치를 원격 리포지토리로 푸시하는 git push, 기본 브랜치에 변경 사항을 병합하는 git merge입니다.

## 예시
- 브랜치를 생성하고 변경 내용을 동기화할 때 사용하는 git 명령어는 브랜치를 생성하는 git branch, 브랜치를 활성화하는 git checkout, 변경 사항을 저장하는 git add 및 git commit, 브랜치를 원격 리포지토리로 푸시하는 git push, 기본 브랜치에 변경 사항을 병합하는 git merge입니다.

## 요약
- 그런 다음 오리진을 사용하여 git clone 명령어를 사용하여 원격 리포지토리의 동일한 복사본을 생성하면 개발자가 컴퓨터에서 사용할 수 있습니다. 브랜치를 생성하고 변경 내용을 동기화할 때 사용하는 git 명령어는 브랜치를 생성하는 git branch, 브랜치를 활성화하는 git checkout, 변경 사항을 저장하는 git add 및 git commit, 브랜치를 원격 리포지토리로 푸시하는 git push, 기본 브랜치에 변경 사항을 병합하는 git merge입니다.
