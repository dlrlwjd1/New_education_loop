# GitHub Branches

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/getting-started-with-git-and-github/lecture/Vfgp4/github-branches)

## 개요
- 이 동영상을 시청하고 나면 GitHub에서 브랜치의 용도를 설명하고 변경 사항을 브랜치에 병합하는 방법을 설명할 수 있습니다.

## 내용
- 이 동영상을 시청하고 나면 GitHub에서 브랜치의 용도를 설명하고 변경 사항을 브랜치에 병합하는 방법을 설명할 수 있습니다.
- 기본 브랜치는 기본적으로 생성되지만 모든 브랜치를 배포 가능한 기본 버전의 코드로 사용할 수 있습니다.
- 새 브랜치를 생성하려면 드롭다운 브랜치 Main을 클릭하고 새 브랜치 텍스트에 새 브랜치 이름을 추가한 다음 “Create Branch”를 선택합니다.
- 이 사람은 변경 작성자일 수도 있고 팀 내에서 지정될 수도 있습니다.단, 소유하지 않은 브랜치를 변경하면 GitHub에서 자동으로 풀 리퀘스트를 진행한다는 점에 유의하세요.
- 커밋된 코드 변경 사항을 메인 코드에 병합하려면 “풀 리퀘스트 병합”을 클릭하고 “병합 확인”을 클릭합니다.브랜치에 대한 모든 변경이 완료되면 해당 브랜치는 더 이상 사용되지 않는 것으로 간주되므로 삭제해야 합니다.
- 메인 브랜치에는 배포 가능한 완성된 코드 버전이 포함되어 있습니다.코드를 변경해야 하는 경우 새 브랜치를 생성하세요.
- 변경된 코드를 메인 브랜치에 병합할 준비가 되면 커밋된 코드 변경 사항을 메인 코드에 병합합니다.

## 예시
- 댓글을 작성할 때의 몇 가지 모범 사례는 댓글 메시지 끝에 마침표를 붙이지 말고 댓글 메시지를 50자 미만으로 유지하는 것입니다.

## 요약
- 메인 브랜치에는 배포 가능한 완성된 코드 버전이 포함되어 있습니다.코드를 변경해야 하는 경우 새 브랜치를 생성하세요. 변경된 코드를 메인 브랜치에 병합할 준비가 되면 커밋된 코드 변경 사항을 메인 코드에 병합합니다.
