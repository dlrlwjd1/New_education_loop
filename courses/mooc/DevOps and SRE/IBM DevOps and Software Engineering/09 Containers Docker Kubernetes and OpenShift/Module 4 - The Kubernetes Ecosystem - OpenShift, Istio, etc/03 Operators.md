# Operators

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/ibm-containers-docker-kubernetes-openshift/lecture/KCgf3/operators)

## 개요
- 사용자 지정 컨트롤러, 운영자 패턴, 사용자 지정 리소스 정의 또는 CRD 간의 관계를 보여주고 운영자 허브, 프레임워크 및 성숙도 모델의 목적을 설명하고, 클러스터 작업을 자동화하고, 사용자 지정 컨트롤러 역할을 하여 포드에서 실행되는 Kubernetes API Operator를 확장하고 API 서버와 상호 작용하고, Kubernetes 애플리케이션을 패키징, 배포 및 관리하고, 앱 생성을 자동화합니다.

## 내용
- 사용자 지정 컨트롤러, 운영자 패턴, 사용자 지정 리소스 정의 또는 CRD 간의 관계를 보여주고 운영자 허브, 프레임워크 및 성숙도 모델의 목적을 설명하고, 클러스터 작업을 자동화하고, 사용자 지정 컨트롤러 역할을 하여 포드에서 실행되는 Kubernetes API Operator를 확장하고 API 서버와 상호 작용하고, Kubernetes 애플리케이션을 패키징, 배포 및 관리하고, 앱 생성을 자동화합니다.
- 구성 및 관리 지속적인 실시간 의사 결정을 통해 운영자는 Kubernetes에서 네이티브 앱을 패키징, 배포 및 관리하고, 기타 작업을 자동화하고, 모든 관련 구성 요소가 포함되도록 합니다.
- 운영자가 제공하는 간편한 반복 가능한 설치 및 업그레이드 프로세스 정기적인 전체 시스템 상태 시스템의 각 구성 요소 확인 구성 요소 및 소프트웨어 공급업체의 콘텐츠에 대한 무선 또는 OTA 업데이트 현장 엔지니어로부터 지식을 수집하고 모든 사용자에게 전파하는 방법 및 kubectl 및 OC 명령과 같은 API 및 CLI 도구와의 통합 서비스 브로커가 운영자와 어떻게 비교되는지 살펴보겠습니다.
- 서비스 브로커가 제공하는 업그레이드, 장애 조치 또는 확장과 같은 연속된 작업을 수행할 수 없는 단기 실행 프로세스에서만 사용자 지정 및 파라미터화 설치 시간 및 오프 클러스터 서비스: 오퍼레이터는 업그레이드, 페일오버 또는 확장과 같은 작업을 매일 수행할 수 있는 장기 실행 프로세스를 제공합니다.
- 운영자가 클러스터 및 오프 클러스터 서비스의 현재 상태를 지속적으로 모니터링함에 따른 사용자 지정 리소스 정의 (CRD) 는 Kubernetes API CRD에 오브젝트를 저장하고 검색합니다.
- 커스텀 컨트롤러는 CRD 데이터를 원하는 상태로 해석합니다., 클러스터의 조정 CRD 데이터와 일치하는 실제 상태 Operate Framework는 코딩, 테스트, 전달 및 운영자 업데이트를 포함하는 오픈 소스 도구 집합입니다.
- 전체 애플리케이션을 배포하려면 해당 애플리케이션에 대한 사용자 지정 리소스를 생성하고 그런 다음 사용자 지정 해당 CRD용 컨트롤러 운영자 로직에 따라 실제 상태와 구성된 상태를 조정하는 방법이 결정됩니다.

## 예시
- 전체 애플리케이션을 배포하려면 해당 애플리케이션에 대한 사용자 지정 리소스를 생성하고 그런 다음 사용자 지정 해당 CRD용 컨트롤러 운영자 로직에 따라 실제 상태와 구성된 상태를 조정하는 방법이 결정됩니다.
