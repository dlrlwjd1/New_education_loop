# Builds

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/ibm-containers-docker-kubernetes-openshift/lecture/n1fgh/builds)

## 개요
- 빌드 구성 프로세스에 사용되는 단계를 나열하고 소스 투 이미지 도커 및 사용자 지정 빌드 전략을 설명하세요.

## 내용
- 빌드 구성 프로세스에 사용되는 단계를 나열하고 소스 투 이미지 도커 및 사용자 지정 빌드 전략을 설명하세요.
- 빌드에는 빌드 전략과 입력 소스를 정의하는 빌드 구성 파일 또는 빌드 구성이 필요합니다.
- 우선 순위에 따라 나열된 다음 빌드 입력, 인라인 Dockerfile 정의, 기존 이미지에서 추출한 콘텐츠, Git 리포지토리, 바이너리 또는 로컬 입력, 입력 암호 및 외부 아티팩트를 사용할 수 있습니다.
- 소스 섹션은 빌드의 소스를 정의하고 소스 유형은 git 리포지토리, 인라인 Dockerfile 또는 바이너리 페이로드와 같은 기본 입력을 결정합니다.
- Docker 및 S2I 전략 모두 실행 가능한 이미지를 생성하지만 사용자 지정 빌드 전략은 단위 또는 통합 테스트를 수행하는 JAR 파일 및 CI/CD 배포와 같은 추가 개체를 생성합니다.
- 우선 순위에 따른 빌드 입력에는 인라인 Dockerfile 정의, 기존 이미지에서 추출한 콘텐츠, git 리포지토리, 바이너리 또는 로컬 입력, 입력 암호 및 외부 아티팩트가 포함됩니다.
- 마지막으로, 빌드에는 빌드 전략과 입력 소스를 정의하는 빌드 구성 파일 또는 빌드 구성이 필요합니다.

## 예시
- 예를 들어 노드 JS 기본 이미지를 사용하여 애플리케이션을 빌드하는 경우 보안 수정이 릴리스되고 다른 업데이트가 발생할 때 해당 이미지가 업데이트됩니다.

## 요약
- 우선 순위에 따른 빌드 입력에는 인라인 Dockerfile 정의, 기존 이미지에서 추출한 콘텐츠, git 리포지토리, 바이너리 또는 로컬 입력, 입력 암호 및 외부 아티팩트가 포함됩니다. 마지막으로, 빌드에는 빌드 전략과 입력 소스를 정의하는 빌드 구성 파일 또는 빌드 구성이 필요합니다.
