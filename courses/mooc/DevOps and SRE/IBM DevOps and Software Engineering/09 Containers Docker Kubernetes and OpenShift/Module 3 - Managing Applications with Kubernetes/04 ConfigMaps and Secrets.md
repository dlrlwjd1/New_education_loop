## 내용
- 구성 맵 기능 설명 , 구성 맵을 만드는 세 가지 방법 설명 및 암호를 만드는 세 가지 방법 설명 소프트웨어 개발자의 경우 구성 설정을 변경할 필요가 없도록 구성 변수를 별도로 유지하여 응용 프로그램 코드에 구성 변수를 하드 코딩하지 않는 것이 좋습니다.
- 문자열 리터럴을 사용하거나, 기존 속성 또는 키와 같음 값 파일을 사용하거나, 구성 맵 YAML 디스크립터 파일을 제공하여 구성 맵을 만들 수 있습니다.
- 배포 또는 포드는 구성 맵 키 ref 속성과 함께 환경 변수를 사용하거나 볼륨 플러그인을 사용하여 파일을 마운트하여 구성 맵을 사용합니다.
- 이렇게 하려면 표시된 대로 배포 설명자에 환경 섹션을 추가하고 첫 번째 단계에서 만든 구성 맵을 가리키는 속성 값을 사용합니다.
- 구성 맵에 메시지 변수를 추가하는 또 다른 방법은 key equals value 형식의 모든 환경 변수가 포함된 파일을 사용하는 것입니다.
- 우리의 경우에는 kubectl의 출력을 저장하여 구성 맵을 가져왔습니다.구성 맵을 my-config.yaml이라는 YAML 파일로 가져오려면 첫 번째 명령은 처음부터 구성 맵이 없음을 나타냅니다.
- 암호를 사용하려면 표시된 대로 배포 설명자에 다른 환경을 추가한 다음 응용 프로그램을 Process.env.api_Creds라고 참조하여 응용 프로그램 키를 사용합니다.

## 예시
- 암호를 사용하려면 표시된 대로 배포 설명자에 다른 환경을 추가한 다음 응용 프로그램을 Process.env.api_Creds라고 참조하여 응용 프로그램 키를 사용합니다.
