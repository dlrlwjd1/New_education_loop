# Kubernetes Objects - Part 2

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/ibm-containers-docker-kubernetes-openshift/lecture/e6oIT/kubernetes-objects-part-2)

## 개요
- 이 동영상을 시청한 후에는 서비스의 목적, 속성 및 용도를 설명하고, ClusterIP, NodePort, LoadBalancer 및 외부 이름 서비스의 역할과 용도를 설명하고, 인그레스, 데몬셋, 스테이트풀셋, 작업의 역할과 용도를 설명할 수 있습니다.

## 내용
- 이 동영상을 시청한 후에는 서비스의 목적, 속성 및 용도를 설명하고, ClusterIP, NodePort, LoadBalancer 및 외부 이름 서비스의 역할과 용도를 설명하고, 인그레스, 데몬셋, 스테이트풀셋, 작업의 역할과 용도를 설명할 수 있습니다.
- 서비스 정의 파일에서 클러스터 IP 주소를 설정할 수 있으며, 클러스터 IP 서비스는 클러스터 내에서 서비스 간 통신 ( 예: 앱의 프런트 엔드와 백엔드 구성 요소 간의 통신) 을 제공합니다.
- 외부 이름을 사용하여 외부 스토리지를 나타내는 서비스를 생성하고 서로 다른 네임스페이스의 Pod가 서로 통신할 수 있도록 할 수 있습니다.
- 다음으로, Ingress는 컨트롤러와 결합할 때 Kubernetes 클러스터의 여러 서비스에 대한 외부 사용자 액세스를 관리하는 라우팅 규칙을 제공하는 API 객체입니다.
- 인그레스는 컨트롤러와 결합할 때 쿠버네티스 클러스터의 여러 서비스에 대한 외부 사용자의 액세스를 관리하는 라우팅 규칙을 제공하는 API 객체입니다.
- External Name을 사용하여 외부 스토리지를 나타내는 서비스를 생성하고 서로 다른 네임스페이스의 파드가 서로 통신할 수 있도록 할 수 있다.
- 스테이트풀셋은 스테이트풀 애플리케이션을 관리하고, 파드 배포 및 스케일링을 관리하고, 각 파드 요청에 대한 고정 ID를 유지하고, 워크로드에 영구 스토리지 볼륨을 제공한다.

## 예시
- 스테이트풀셋은 스테이트풀 애플리케이션을 관리하고, 파드 배포 및 스케일링을 관리하고, 각 파드 요청에 대한 고정 ID를 유지하고, 워크로드에 영구 스토리지 볼륨을 제공한다.

## 요약
- External Name을 사용하여 외부 스토리지를 나타내는 서비스를 생성하고 서로 다른 네임스페이스의 파드가 서로 통신할 수 있도록 할 수 있다. 스테이트풀셋은 스테이트풀 애플리케이션을 관리하고, 파드 배포 및 스케일링을 관리하고, 각 파드 요청에 대한 고정 ID를 유지하고, 워크로드에 영구 스토리지 볼륨을 제공한다.
