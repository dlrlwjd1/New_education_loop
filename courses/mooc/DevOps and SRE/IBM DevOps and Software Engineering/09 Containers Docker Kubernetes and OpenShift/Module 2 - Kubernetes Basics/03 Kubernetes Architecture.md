# Kubernetes Architecture

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/ibm-containers-docker-kubernetes-openshift/lecture/Y9KXn/kubernetes-architecture)

## 개요
- 이 아키텍처 다이어그램은 쿠버네티스 시스템의 주요 구성 요소를 강조합니다.쿠버네티스 배포를 쿠버네티스 클러스터라고 합니다.

## 내용
- 이 아키텍처 다이어그램은 쿠버네티스 시스템의 주요 구성 요소를 강조합니다.쿠버네티스 배포를 쿠버네티스 클러스터라고 합니다.
- 컨트롤 플레인은 클러스터에 대한 결정을 내리고 클러스터의 이벤트를 감지하고 이에 응답하여 의도한 클러스터 상태를 유지합니다.
- 컨트롤 플레인에서 내리는 결정의 예로는 워크로드 스케줄링이 있고, 이벤트에 대응하는 예로는 애플리케이션이 배포될 때 새 리소스를 생성하는 경우를 들 수 있습니다.
- Etcd는 쿠버네티스 클러스터의 상태를 정의하며 시스템은 실제 상태를 원하는 상태와 일치하도록 만듭니다.
- Kubernetes 컨트롤러 관리자는 클러스터 상태를 모니터링하고 클러스터의 실제 상태가 원하는 상태와 일치하는지 확인하는 모든 컨트롤러 프로세스를 실행합니다.
- Kubernetes는 오픈 소스이며 다양한 클라우드 제공업체 및 조직에서 이상적으로 채택할 수 있기 때문에 Kubernetes는 가능한 한 클라우드에 구애받지 않도록 노력하고 있습니다.
- 클라우드 컨트롤러 관리자를 사용하면 Kubernetes와 클라우드 제공업체 모두 서로에 대한 종속성을 도입하지 않고도 자유롭게 발전할 수 있습니다.

## 예시
- 예를 들어, Kubernetes API 서버는 클러스터의 상태를 보거나 변경하기 위한 명령을 받아들입니다.

## 요약
- Kubernetes는 오픈 소스이며 다양한 클라우드 제공업체 및 조직에서 이상적으로 채택할 수 있기 때문에 Kubernetes는 가능한 한 클라우드에 구애받지 않도록 노력하고 있습니다. 클라우드 컨트롤러 관리자를 사용하면 Kubernetes와 클라우드 제공업체 모두 서로에 대한 종속성을 도입하지 않고도 자유롭게 발전할 수 있습니다.
