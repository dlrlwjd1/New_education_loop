# Social Coding

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/continuous-integration-and-continuous-delivery-ci-cd/lecture/mqEq5/social-coding)

## 개요
- 소스 코드 관리(SCM)의 중앙집중형·분산형 방식을 소개하고, 오픈소스 커뮤니티의 관행을 기업 내부(inner source)로 가져온 **소셜 코딩(Social Coding)**의 실천 단계를 설명.

## 내용
### 소스 코드 관리(SCM)란
- **SCM(Source Code Management)**은 소스 코드가 개발되면서 그 버전을 추적하는 관행 — 오류가 생기면 이전 버전으로 쉽게 되돌릴 수 있게 함. 또한 여러 사람이 코드의 서로 다른 부분에서 작업하고 이 변경 사항들을 하나의 단일 진실 공급원으로 병합할 수 있게 함.
- 프로그래머는 SCM 도구를 사용해 소스 코드를 관리하며, 이 도구는 **버전 관리 시스템(VCS)**이라고도 불림 — 두 용어는 소프트웨어 시스템을 가리킬 때 같은 의미로 사용 가능.

### 중앙집중형 vs 분산형 SCM
- **중앙집중형(Centralized) SCM**: 코드 저장소와 버전 이력을 중앙에 저장 — 개발자는 코드 일부를 체크아웃해 작업한 뒤 변경 사항을 중앙 저장소에 커밋. 빌드는 반드시 중앙 저장소에서 해야 하는데, 모든 코드가 존재하는 유일한 곳이기 때문.
- **분산형(Distributed) SCM**: 각 개발자가 전체 코드 저장소와 버전 이력의 로컬 복제본을 가짐 — 각 개발자가 코드 전체를 로컬에 가지고 있으므로 로컬 빌드가 가능.

### 소셜 코딩이란
- "이너 소스(inner source)를 위한 오픈소스"라고 부를 수 있음 — 오픈소스 커뮤니티가 수년간 해온 것을 기업 내부의 사내 프로젝트에 커뮤니티처럼 코딩하는 방식으로 가져오는 것.
- 과거에는 개발자들이 제한된 "알 필요(need to know)" 접근 권한과 제한된 소통 속에 프라이빗 저장소에서 작업 — 코드 재사용의 가능성이 없어, 이미 만들어진 것을 아무도 모르기 때문에 기업들이 계속 바퀴를 다시 발명(reinvent the wheel)함.
- 소셜 코딩에서는 저장소가 공개되고, 모두가 코드를 fork해 기여하도록 장려됨 — "이건 내 코드고 아무도 건드릴 수 없다"고 생각하는 개발팀의 습관을 회사의 이익을 위해 극복해야 함.
- 무정부 상태가 될 것 같지만, 실제로는 저장소 소유자가 통제하기 때문에 꽤 잘 작동함 — 저장소 소유자가 기여에 대한 완전한 통제권을 가짐.

### 소셜 코딩의 실천 단계
1. GitHub 이슈를 열고 자신에게 할당해 모두가 자신이 작업 중임을 알게 함.
2. 저장소 소유자와 새 기능에 대해 논의하고, 그들을 위해 개발하기로 합의 — 그들이 이미 해놓은 모든 것을 활용하면서 필요한 기능을 추가할 수 있음.
3. 저장소를 fork하고 브랜치를 만들어 변경 작업을 함.
4. 작업이 끝나고 기여할 것이 있으면 **Pull Request**를 제출 — 리뷰 받을 준비가 되었음을 알리고, 저장소 소유자가 코드를 메인 프로젝트에 병합할지 결정.
- 저장소 소유자는 완전한 통제권을 가짐 — 코드를 병합하는 주체이기 때문에 변경을 요청할 수 있고, 테스트 커버리지가 충분하지 않으면 더 많은 테스트 케이스 작성을 요청할 수 있음.
- 저장소 소유자는 기여자를 동등한 팀원으로 여기며, 이는 서로에게 이득(win-win)인 상황 — 기여자는 다른 팀의 코드와 기능을 활용할 수 있고, 다른 팀은 무료로 새 기능을 얻음.
- 코드가 다시 작성되는 대신 재사용되므로 회사는 비용을 절약하고 모두가 만족함 — 이것이 오픈소스가 작동하는 방식이며, 기업이 자신의 이너 소스를 대해야 하는 방식.

## 요약
- 소셜 코딩은 오픈소스 커뮤니티의 관행을 기업 내부로 가져온 것으로, 프라이빗 저장소에서의 폐쇄적 작업 대신 공개 저장소에서 이슈 할당 → 소유자와 논의 → fork·브랜치 작업 → Pull Request 제출이라는 4단계를 통해 코드 재사용과 협업을 촉진하며, 저장소 소유자가 병합에 대한 완전한 통제권을 유지하기 때문에 무질서 없이 효과적으로 작동한다.
