# Introduction to GitHub Actions

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/continuous-integration-and-continuous-delivery-ci-cd/lecture/9KFWc/introduction-to-github-actions)

## 개요
- GitHub Actions의 기본 개념과 장점을 소개하고, **워크플로우(Workflow) → 작업(Job) → 단계(Step) → 액션(Action)**으로 이어지는 계층 구조를 설명.

## 내용
### GitHub Actions란
- CI/CD 도구 분야의 신참 — 모든 GitHub 저장소에서 사용 가능한 CI/CD 도구. GitHub에 서비스로 통합되어 있어 매력적 — 추가로 설치하거나 가입할 것이 없어 누구나 접근 가능한 CI/CD 도구.
- 다른 CI/CD 도구들처럼 CI 파이프라인을 코드로 다룰 수 있게 해줌 — 필요한 것은 **`.github/workflows`** 폴더 안의 `.yaml` 파일뿐. 파일 이름은 중요하지 않으며, 각 파일이 언제 트리거되어야 하는지를 스스로 기술함. GitHub Actions는 workflows 폴더의 모든 파일을 처리하지만, 워크플로우에 지정된 이벤트가 발생했을 때만 실행.

### 마켓플레이스와 시작 코드
- Jenkins가 풍부한 플러그인 모음을 가진 것처럼, GitHub Actions도 워크플로우에서 사용할 수 있는 액션을 호스팅하는 **마켓플레이스**를 가지고 있음 — 거의 모든 언어와 단계에 대해 매우 다양한 액션을 고를 수 있어 워크플로우 작성을 크게 앞당겨줌. 어떤 작업을 수행하는 스크립트를 직접 짜기 전에 마켓플레이스에 이미 만들어진 액션이 있는지 확인해보는 것이 좋음 — 대부분의 경우 이미 존재함.
- Jenkins, CircleCI, Travis CI 같은 경쟁 도구들과 달리 **수동으로 설정할 웹사이트가 없다**는 것이 장점 — workflows 폴더를 만들고 워크플로우를 나타내는 YAML 파일을 추가하기만 하면 됨. 다른 설정이 필요 없어 시작하기 쉬울 뿐 아니라 수동 단계가 없으므로 CI/CD 워크플로우가 재현 가능함을 보장.
- GitHub 저장소의 **Actions** 탭에서 기능별 워크플로우 템플릿을 선택해 자신의 상황에 맞게 편집할 수 있는 **시작 코드(starter code)**도 제공됨.

### 워크플로우(Workflow)의 기본 개념
- GitHub Actions의 기본 개념은 **워크플로우** — GitHub Actions가 실행하는, job과 step으로 표현된 일련의 자동화된 절차.
- 모든 저장소는 원하는 만큼의 워크플로우를 가질 수 있음 — CI용 워크플로우 하나, CD용 워크플로우 하나, 아티팩트를 게시하는 또 다른 워크플로우처럼 필요한 만큼 workflows 폴더에 넣을 수 있음.

### 워크플로우의 구성 요소 — Event → Runner → Job → Step → Action
- **Event(이벤트)**: 워크플로우가 언제 실행되어야 하는지 알려줌 — 저장소에 push할 때, Pull Request를 만들 때, 릴리스를 만들 때 등.
- **Runner(러너)**: 워크플로우가 job을 실행하는 데 사용 — 다양한 가상 환경을 위한 내장 러너가 있거나, 자신의 환경에서 셀프 호스팅 러너를 사용할 수도 있음.
- **Job(작업)**: 워크플로우는 하나 이상의 job을 포함 — 컴포넌트를 빌드하는 job 하나, 아티팩트 저장소에 게시하는 다른 job, 환경에 배포하는 또 다른 job을 가질 수 있음.
- **Step(단계)**: 각 job은 하나 이상의 step을 포함 — 한 step은 코드를 체크아웃하고, 다른 step은 코드를 컴파일하고, 또 다른 step은 코드에 린터(linter)를 실행하고, 아마도 코드가 제대로 작동하는지 확인하는 테스트 케이스 묶음을 실행하는 step도 있을 것.
- **Action(액션)**: 각 step은 하나 이상의 액션이나 셸 명령을 포함 — 워크플로우의 가장 낮은 수준으로, 코드 체크아웃, 의존성 설치, 코드 컴파일, 테스트 실행 같은 단일 작업을 수행.
- 이 job → step → action의 계층 구조 덕분에 워크플로우가 수행하는 동작들을 논리적으로 그룹화할 수 있음.

## 요약
- GitHub Actions는 모든 GitHub 저장소에 내장된 CI/CD 도구로, `.github/workflows` 폴더의 YAML 파일만으로 웹사이트 수동 설정 없이 재현 가능한 워크플로우를 구성할 수 있고, 마켓플레이스의 기성 액션과 시작 코드로 빠르게 시작할 수 있으며, 워크플로우는 실행 시점을 정하는 이벤트, 실행 환경인 러너, 그리고 job → step → action으로 이어지는 계층 구조를 통해 체크아웃·컴파일·린트·테스트 같은 작업들을 논리적으로 구성한다.
