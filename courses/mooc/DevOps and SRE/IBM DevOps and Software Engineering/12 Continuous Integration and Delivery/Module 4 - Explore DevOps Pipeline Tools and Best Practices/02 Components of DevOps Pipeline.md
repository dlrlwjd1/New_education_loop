# Components of DevOps Pipeline

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/continuous-integration-and-continuous-delivery-ci-cd/lecture/LotP5/components-of-devops-pipeline)

## 개요
- DevOps 파이프라인의 정의와, CI 파이프라인·CD 파이프라인·Continuous Compliance(지속적 컴플라이언스) 파이프라인 각각을 구성하는 다양한 도구·컴포넌트의 역할을 정리.

## 내용
### DevOps 파이프라인이란
- 소프트웨어 전달을 자동화하는 워크플로우 — 빌드, 테스트, 배포, 릴리스 같은 작업을 효율적이고 일관되게 실행하는 일련의 상호 연결된 단계.
- 프로세스를 간소화·표준화함으로써 소프트웨어 전달 생애주기를 자동화 — 코드 변경의 지속적 통합을 가능하게 하고, 저장소와 통합하며, 테스트와 빌드를 자동화하고, 충돌 해결과 버그 발견을 용이하게 함.
- 파이프라인은 DevOps에서 CI/CD 관행을 구현하는 데 필수적.

### CI 파이프라인 vs CD 파이프라인
- **CI 파이프라인**: 패키지를 검증하고 필수 구성 요소를 빌드해 컨테이너 이미지나 Helm 차트 같은 배포 가능한 아티팩트를 만듦 — 버전 관리와 리소스 준비를 보장.
- **CD 파이프라인**: 주로 준비된 아티팩트를 특정 목표 환경에 배포하는 역할 — 개발에서 프로덕션으로의 매끄러운 전환을 보장.

### CI 파이프라인의 구성 요소(예시)
- **PR 파이프라인** — 애플리케이션 저장소의 Pull Request가 트리거함. 자동화된 테스트를 실행해 코드 변경을 검증하고 코드베이스의 무결성을 보장.
- **이슈 트래커(Issue Tracker)** — CI 파이프라인과 통합되어 Pull Request와 연결된 이슈나 작업을 강조해 이슈 해결을 용이하게 함.
- **애플리케이션 저장소** — CI 파이프라인이 빌드·테스트 작업을 위해 가져오는 소스 코드를 저장.
- **Code Risk Analyzer** — 잠재적 위험, 취약점, 코드 품질 이슈를 위해 코드를 분석 — 정적 코드 분석에 기반한 피드백과 권장 사항 제공.
- **Slack 통합** — 개발팀에 알림과 리포트를 보내 효율적인 소통을 가능하게 함.
- **DevOps Insights** — CI 파이프라인에서 데이터를 수집해 병목과 개선 영역을 식별하는 리포트를 생성.
- **SonarQube** — 코드 품질 관리 플랫폼 — 정적 코드 분석 수행, 코드 커버리지 측정, 유지보수성 평가.
- **Secrets Manager** — 민감한 정보를 안전하게 저장하고 CI 파이프라인과 통합되어 빌드·배포 중 승인된 접근을 제공.
- **Evidence 컴포넌트** — 추적성과 감사를 위해 파이프라인 실행 중 수집된 아티팩트와 문서를 저장.
- **Inventory 컴포넌트** — 배포된 애플리케이션, 의존성, 인프라 설정을 추적해 소프트웨어 배포의 일관성과 통제를 보장.
- **아티팩트(binary, 컨테이너 이미지 등)** — CI 파이프라인이 생성하며 소프트웨어 전달 과정의 이후 단계에서 결정적인 역할을 함.
- 전체적으로 CI 파이프라인은 이런 다양한 컴포넌트를 활용해 코드 검증, 테스트, 분석, 협업을 자동화 — 개발자가 품질과 보안 표준을 유지하면서 코드베이스에 변경 사항을 지속적으로 통합할 수 있게 해줌.

### CD 파이프라인의 구성 요소
- CI 파이프라인 이후, CD 파이프라인이 트리거되어 배포 과정을 진행.
- **변경 요청 도구(Change Request Tool)** — 시스템 변경을 관리·추적. 배포 전 변경 사항이 문서화되고 검증되도록 파이프라인과 통합.
- **Key Protect** — 암호화 키와 민감한 정보를 안전하게 저장하며 배포 중 안전한 접근을 제공.
- **Security and Compliance Center** — 정책을 강제하고, 보안 스캔·취약점 평가·컴플라이언스 검사를 수행.
- **DevOps Insights** — 데이터를 수집해 병목과 개선 영역을 식별하는 리포트 생성(CI에서와 동일한 역할).
- **Secrets Manager** — 민감한 정보를 안전하게 저장하며 파이프라인과의 통합을 통해 배포 중 안전한 접근 제공.
- CD 파이프라인은 애플리케이션을 목표 환경에 배포해 정확한 배포와 설정을 보장 — 이 워크플로우는 배포, 변경 추적, 보안 컴플라이언스, 문서화를 자동화해 표준을 유지하면서 효율적이고 신뢰할 수 있는 소프트웨어 전달을 가능하게 함.

### Continuous Compliance(지속적 컴플라이언스) 파이프라인
- CI/CD 파이프라인 외에, 일부 팀은 애플리케이션과 인프라의 개발 생애주기 전반에 걸쳐 보안·컴플라이언스 표준을 유지하도록 보장하는 **지속적 컴플라이언스 파이프라인**을 구현하기도 함.
- 예시 워크플로우:
  - 애플리케이션 코드를 미리 정의된 보안·컴플라이언스 규칙과 대조해 검증.
  - **SonarQube** 같은 정적 코드 분석 도구가 코드베이스를 스캔해 잠재적 보안 취약점과 컴플라이언스 이슈를 식별.
  - 애플리케이션이 업계 특화 또는 규제 컴플라이언스 요구사항을 충족하는지 확인하는 컴플라이언스 검사 포함 — **IBM Cloud Continuous Compliance** 같은 도구가 애플리케이션을 미리 정의된 컴플라이언스 정책과 대조해 평가하고 컴플라이언스 리포트를 생성.
  - **Key Protect** — 암호화 키, 인증서, 기타 민감한 정보를 안전하게 보호·관리.
  - **Security and Compliance Center** — 애플리케이션을 미리 정의된 보안 정책과 컴플라이언스 요구사항에 대해 평가.
  - **DevOps Insights** — 모니터링·분석 도구로 파이프라인의 여러 단계에서 데이터를 수집.
  - **Secrets Manager** — 파이프라인 실행 중 API 키, 비밀번호, 인증서 같은 민감한 정보를 안전하게 저장·관리하고, 보호된 리소스에 접근이 필요한 파이프라인 단계에 필요한 자격 증명을 안전하게 제공.
  - **Slack 알림** — 파이프라인 상태, 컴플라이언스 이슈, 기타 중요한 이벤트에 대해 팀원들에게 지속적으로 알림.
  - 팀은 컴플라이언스를 입증하고 파이프라인 실행을 추적하기 위한 증거를 수집 — 로그, 리포트, 테스트 결과 같은 컴플라이언스와 성공적인 파이프라인 실행의 증거가 되는 아티팩트를 포함.
- 이런 컴포넌트들의 조합은 조직이 보안·컴플라이언스 검증을 자동화하고, 시크릿과 키를 효과적으로 관리하며, 컴플라이언스 목적의 증거를 수집할 수 있게 함 — 애플리케이션과 인프라가 개발·배포 과정 전반에 걸쳐 보안·컴플라이언스 표준에 부합하도록 보장.

## 요약
- DevOps 파이프라인은 소프트웨어 전달을 자동화하는 워크플로우이며, CI 파이프라인(PR 파이프라인·Code Risk Analyzer·SonarQube·Secrets Manager 등으로 코드를 검증하고 아티팩트를 만듦)과 CD 파이프라인(변경 요청 도구·Key Protect·Security and Compliance Center로 프로덕션까지의 매끄러운 배포를 보장)이 이어져 실행되며, 여기에 더해 SonarQube·IBM Cloud Continuous Compliance·Security and Compliance Center 등을 활용해 보안과 컴플라이언스 표준을 자동으로 검증하고 증거를 수집하는 **지속적 컴플라이언스 파이프라인**을 추가로 구축하는 팀도 있다.
