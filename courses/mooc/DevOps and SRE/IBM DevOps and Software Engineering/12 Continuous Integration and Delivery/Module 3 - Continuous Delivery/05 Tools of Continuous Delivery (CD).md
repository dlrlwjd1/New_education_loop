# Tools of Continuous Delivery (CD)

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/continuous-integration-and-continuous-delivery-ci-cd/lecture/GgYtz/tools-of-continuous-delivery-cd)

## 개요
- Jenkins, Spinnaker, Concourse CI, GitLab, Travis CI, Tekton, GoCD, ArgoCD 등 다양한 CD 도구를 개괄하고, CD 도구 선택 시 고려할 요소, 그리고 CD 파이프라인 안에 필요한 보안·배포 작업 도구들을 정리.

## 내용
### 다양한 CD 도구 개괄
- **Jenkins** — 시장에서 가장 오래되고 인기 있는 CI/CD 도구 중 하나로 거대한 커뮤니티와 수많은 플러그인을 지원하지만, CD에는 이상적이지 않음 — 파이프라인 과정에 대한 가시성을 제공하지 않고 많은 설정·유지보수가 필요해 다른 CD 도구 대비 경쟁력이 떨어짐.
- **Spinnaker** — Netflix가 사내에서 만든 클라우드 애그노스틱(cloud-agnostic) 전용 CD 도구. CD 파이프라인을 관리하고 릴리스 롤백을 단순화. 로드밸런서 생성과 클러스터 스케일링을 네이티브로 지원.
- **Concourse CI** — CD 기능도 포함하며 처음부터 컨테이너를 염두에 두고 만들어짐(VM에서도 실행 가능). 컨테이너 우선 접근 덕분에 빌드의 모든 단계가 매우 유연 — Docker 이미지를 가리키기만 하면 됨.
- **GitLab** — CI와 CD를 모두 구현 가능. GitLab이 소스 코드 관리자이기도 해서 프로덕션 배포 과정을 자동화하기 쉬움. 모든 주요 클라우드 플랫폼을 지원해 CI/CD 파이프라인 구성이 매우 유연.
- **Travis CI** — CD 기능도 갖춘 또 다른 CI 도구. 다른 CD 구현만큼 기능이 풍부하지는 않지만 유지보수가 최소한으로 필요.
- **Tekton** — 오픈소스, 벤더 중립적인 프레임워크로 Kubernetes에서 앱을 빌드·테스트·배포할 수 있게 해줌. 핵심 강점은 모듈성 — VM, 서버리스, Kubernetes, 클라우드 제공자 등 여러 환경에 걸쳐 배포 가능.
- **GoCD** — 네이티브 Docker·Kubernetes 지원과 함께 쉬운 파이프라인 설정을 자랑. 커밋과 배포 사이의 모든 단계를 통해 각 파이프라인을 추적하는 데 도움을 주는 자체 Value Stream Map 도구 포함. YAML이나 JSON 파일, 또는 시각적 UI로 파이프라인 구축 가능.
- **ArgoCD** — 원래 Intuit이 Spinnaker보다 가벼운 도구로, 빌드·배포 시간을 개선하고 GitOps 워크플로우를 간소화하기 위해 개발. UI가 잘 만들어져 있고 사용하기 쉬우며 Jenkins, GitHub Actions, CircleCI 등 다양한 CI 도구와 잘 통합됨.

### CD 도구 선택 시 고려할 요소
- **완전한 감사 추적(audit trail)**, **독점적 통합 시크릿(secret) 관리**, **세밀한 역할 기반 접근 제어(RBAC)**를 원할 수 있음 — 이런 기능들은 CD 도구에 부분적으로만 제공되고 어디서나 보편적이지 않을 수 있음(일부 도구는 아주 새롭고 지나치게 단순할 수 있음). 기능이 풍부한 CD 도구를 사용하면 애플리케이션이 더 복잡해지고 움직이는 부분이 많아질 때 이미 필요한 기능을 갖추고 있게 됨.
- **호환성** — CI 파이프라인에 따라 일부 CD 도구는 현재 프로세스와 호환되지 않을 수 있음. 현재 도구 세트와 호환되고 쉽게 통합되는 도구를 고르면 CD 설정이 더 빠르고 골칫거리를 줄여줌.
- **설정과 유지보수 난이도** — 도구마다 구현 방식과 개발자가 프로젝트에서 CD를 설정하는 난이도가 크게 다를 수 있음. Tekton 같은 도구는 설정이 쉽고 파이프라인에 대한 명확한 통찰을 제공. ArgoCD도 설정·유지보수가 쉬운 반면, Jenkins는 설정과 유지보수 모두 손이 많이 감.

### CD 파이프라인 안에 필요한 보안·배포 도구
- CD 도구로 파이프라인을 만드는 것은 첫 단계일 뿐 — 파이프라인 안에서 다음 작업을 수행할 도구도 고려해야 함:
  - **취약점 스캐닝(Vulnerability Scanning)** — 의존성과 구성 요소의 취약점을 식별. 어제는 취약하지 않던 애플리케이션도 기존 코드나 라이브러리에서 발견된 익스플로잇 때문에 갑자기 취약해질 수 있음 — 알려진 취약점이 있는 코드를 배포하지 않도록 CD 파이프라인에 취약점 스캐닝을 추가하는 것이 매우 중요.
  - **시크릿 스캐닝(Secret Scanning)** — API 키와 자격 증명이 실수로 노출되는 것을 방지. 개발자가 실수로 비밀번호나 자격 증명을 소스 관리에 커밋하는 경우가 많음 — 시크릿 스캐닝은 자격 증명이 유출되지 않도록 보장.
  - **SAST(Static Application Security Testing)** — SQL 인젝션, 크로스 사이트 스크립팅 같은 전체 코드베이스의 취약점을 식별. 코드 리뷰 중 일부 실수가 발견될 수도 있지만, 개발자가 잊어버릴 경우를 대비해 CD 파이프라인이 이를 확인하는 것이 중요.
  - **DAST(Dynamic Application Security Testing)** — 소스 코드에 숨겨져 있을 수 있는 잘못된 보안 가정을 스캔. 실행 중인 애플리케이션의 약점을 확인 — 악의적 사용자가 프로덕션에서 발견하기 전에 CD 파이프라인에서 잡아내는 것이 낫음.
  - **배포 도구(Deployment Facilitation)** — 배포를 자동화하면 반복 가능해져서 개발·테스트·스테이징·프로덕션 어디에 배포하든 동일한 결과를 얻을 수 있음.
- 보안은 흔히 나중에 생각하는 것으로 취급되어 애플리케이션 출시 직전에 추가되곤 하는데, 파이프라인에 보안 검사를 추가하면 진행하면서 만드는 모든 변경 사항이 안전하도록 테스트됨.

### ArgoCD 상세
- 인기가 높아지고 있는 비교적 새로운 도구 — **선언적(declarative)** Continuous Delivery 도구로 CD를 자동화·감사·이해하기 쉽게 만들어줌.
- Git 저장소를 원하는 애플리케이션 상태를 정의하는 단일 진실 공급원으로 사용하는 **GitOps 패턴**을 따름.
- Kubernetes 컨트롤러로서, 현재 애플리케이션 상태를 원하는 상태와 비교해 모니터링하고, 차이를 시각화하며, 자동 동기화(sync)로 일치성을 보장.

### Tekton 상세(이 코스에서 사용할 도구)
- 유연하고 오픈소스인 프레임워크로 구현 세부사항을 추상화해, 프로젝트 요구사항에 맞게 빌드·테스트·배포에 집중할 수 있게 해줌.
- CI/CD 도구와 프로세스를 표준화함으로써 Jenkins, Skaffold, Knative 같은 다른 CI/CD 도구들과 잘 작동함.
- Tekton 파이프라인은 완전히 이식 가능(portable) — 한번 만들어지거나 정의되면, 조직 내 다른 개발자가 그 파이프라인을 가져다 구성 요소를 재사용할 수 있음.

## 요약
- CD 도구는 Jenkins(오래되고 설정·유지보수 부담 큼)부터 Spinnaker, Concourse CI, GitLab, Travis CI, GoCD, ArgoCD(선언적 GitOps, Kubernetes 컨트롤러), 그리고 이 코스에서 다룰 Tekton(오픈소스, 완전히 이식 가능한 파이프라인)까지 다양하며, 도구 선택 시에는 기능의 풍부함·호환성·설정과 유지보수 난이도를 고려해야 하고, 파이프라인 안에는 취약점 스캐닝·시크릿 스캐닝·SAST·DAST 같은 보안 검사와 자동화된 배포 도구를 반드시 포함시켜야 한다.
