# What Is Continuous Delivery (CD)?

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/continuous-integration-and-continuous-delivery-ci-cd/lecture/74BOQ/what-is-continuous-delivery-cd)

## 개요
- CI와 CD의 차이를 재확인하고, Martin Fowler의 정의를 바탕으로 Continuous Delivery의 목표("언제든 프로덕션에 릴리스 가능한 상태")와 이점을 정리.

## 내용
### CI와 CD는 별개의 것
- 사람들이 "CI/CD"를 하나처럼 말하지만, 실제로는 순서대로 일어나는 **두 개의 별개**의 것.
- **CI**는 코드를 main/master/trunk 브랜치에 지속적으로 통합하는 것 — 병합 전에 너무 멀리 벗어나지 않도록 해 메인 코드와 지속적으로 통합.
- **CD**는 그렇게 통합된 코드를 어딘가에 배포하는 것 — 통합할 때마다 매번 배포할 수도, 아닐 수도 있음. main 브랜치로 최종 병합되면 CD 부분이 시작됨.

### Continuous Delivery의 정의
- 모든 변경 사항을 **프로덕션과 유사한(production-like) 환경**에 전달함으로써 코드가 빠르고 안전하게 프로덕션에 배포될 수 있도록 보장하는 일련의 관행.
- "production-like"라는 점에 주목 — 반드시 프로덕션 환경일 필요는 없고, 실제로 많은 경우 아님. 실제로 프로덕션에 배포하는 것은 보통 **Continuous Deployment**라고 부름.
- Continuous Delivery는 단지 코드를 개발, 테스트, 또는 스테이징 환경에 배포해 코드가 배포될 수 있음을 확인하는 것을 의미 — 모두에게 코드가 작동하는 것을 볼 기회를 줌.
- 핵심은 이것이 **자동화**되어 있다는 것 — 코드를 배포하는 데 아무도 수동 단계를 수행하지 않음. 자동으로 지속적으로 배포됨.

### Continuous Delivery의 목표 — Martin Fowler의 정의
- Martin Fowler에 따르면 "Continuous Delivery는 소프트웨어를 **언제든 프로덕션에 릴리스**할 수 있는 방식으로 만드는 소프트웨어 개발 규율".
- 언제든 프로덕션에 릴리스할 수 있다는 것은 main/master 브랜치가 **항상 배포 가능해야 함**을 의미 — 나쁜 코드가 제품을 망가뜨릴 수 있는 main/master 브랜치에 들어가지 않도록 하는 일련의 검사가 마련되어 있어야 함. 이것이 절대적으로 핵심.
- 그래서 Pull Request가 있을 때마다 테스트를 실행하는 데 Continuous Integration을 사용하는 것 — 별도의 feature 브랜치에서 작업하고 Pull Request를 사용하면 작성한 코드가 main 브랜치에 다시 병합되기 전에 올바르게 작동하는지 확인 가능.

### Continuous Delivery의 이점
- 개발팀이 소프트웨어를 SDLC(소프트웨어 개발 생애주기)의 여러 단계를 거쳐 이동시키는 단계를 자동화할 수 있게 함 — 자동화는 끊임없는 테스트·배포 사이클로 배포 시간을 줄여줌.
- 배포를 더 많이 할수록 다음 배포가 성공할 것이라는 확신이 커지고, 배포 디버깅에 쓰는 시간이 줄어듦.
- 표준적인 배포 전략에서 흔한 비용(인건비, 인프라 비용, 수동 실패로 인한 시간 손실 비용)을 줄여줌.
- 프로젝트 규모에 따라 소프트웨어 배포를 확장할 수 있게 해줌.
- SDLC의 여러 단계에 코드를 자동으로 배포할 수 있게 해줌 — 개발 환경, 테스트 환경, 스테이징 환경에 모두 문제없이 배포되었다면, 프로덕션에 배포할 때도 문제없을 가능성이 매우 높음.

## 요약
- Continuous Delivery는 CI 다음에 이어지는 별개의 프로세스로서 모든 변경 사항을 프로덕션과 유사한 환경(반드시 실제 프로덕션은 아님)에 자동으로 배포함으로써 main/master 브랜치가 "언제든 프로덕션에 릴리스 가능한" 상태를 유지하도록 보장하며, 개발·테스트·스테이징 단계를 문제없이 거친 코드는 프로덕션 배포도 성공할 가능성이 높다는 확신을 주고 배포 시간·비용·디버깅 부담을 줄여준다.
