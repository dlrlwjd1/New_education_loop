# Software Documentation

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-software-engineering/lecture/Rawez/software-documentation)

## 개요
- 소프트웨어 설명서는 제품의 정의 및 사용 방법을 설명하는 소프트웨어 관련 정보입니다.이러한 자산은 소프트웨어 제품의 개발 및 사용과 관련된 서면, 비디오 또는 그래픽 자산일 수 있습니다.

## 내용
- 소프트웨어 설명서는 제품의 정의 및 사용 방법을 설명하는 소프트웨어 관련 정보입니다.이러한 자산은 소프트웨어 제품의 개발 및 사용과 관련된 서면, 비디오 또는 그래픽 자산일 수 있습니다.
- 소프트웨어 문서는 최종 사용자, 소프트웨어 개발자, QA 엔지니어, 시스템 관리자 및 기타 이해 관계자와 같은 다양한 유형의 사용자를 위해 작성할 수 있습니다.
- 문서에는 여러 유형이 있으며 요구 사항, 설계, 기술, 품질 보증 및 사용자 문서를 포함한 다섯 가지 범주에 대해 설명합니다.
- 기술 문서에는 다른 개발자가 코드를 읽고 동작을 이해하는 데 도움이 되도록 코드에 작성된 주석이 포함되어 있습니다.또한 코드의 작동 방식을 설명하는 작업 문서와 프로젝트 구현 중 엔지니어의 아이디어와 생각을 기록한 문서도 포함될 수 있습니다.
- 테스트 문서 유형에는 테스트 계획, 테스트 데이터, 테스트 시나리오, 테스트 사례, 테스트 전략 및 추적성 매트릭스가 포함됩니다.추적성 매트릭스는 테스트 사례를 요구 사항에 매핑합니다.
- 사용 설명서는 최종 사용자를 대상으로 하며 소프트웨어 작동 방법이나 시스템 설치 또는 문제 해결에 도움을 주는 방법을 설명합니다.
- 프로세스 문서는 프로세스에 대한 개요를 제공하지만 SOP는 훨씬 더 자세히 설명합니다.SOP는 일반적이면서도 복잡한 조직 고유의 작업을 수행하는 방법을 단계별로 설명하는 서면 문서입니다.예를 들어 코드 리포지토리를 사용하여 코드를 체크인하는 것은 소프트웨어 엔지니어에게는 일반적인 지식입니다.

## 예시
- 테스트 문서 유형에는 테스트 계획, 테스트 데이터, 테스트 시나리오, 테스트 사례, 테스트 전략 및 추적성 매트릭스가 포함됩니다.추적성 매트릭스는 테스트 사례를 요구 사항에 매핑합니다.

## 요약
- 사용 설명서는 최종 사용자를 대상으로 하며 소프트웨어 작동 방법이나 시스템 설치 또는 문제 해결에 도움을 주는 방법을 설명합니다. 프로세스 문서는 프로세스에 대한 개요를 제공하지만 SOP는 훨씬 더 자세히 설명합니다.SOP는 일반적이면서도 복잡한 조직 고유의 작업을 수행하는 방법을 단계별로 설명하는 서면 문서입니다.예를 들어 코드 리포지토리를 사용하여 코드를 체크인하는 것은 소프트웨어 엔지니어에게는 일반적인 지식입니다.
