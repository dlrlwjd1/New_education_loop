# Software Development Methodologies

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-software-engineering/lecture/Jr4kU/software-development-methodologies)

## 개요
- 이 동영상을 시청한 후에는 다음을 수행할 수 있습니다 소프트웨어 개발 라이프사이클에 일반적으로 사용되는 몇 가지 접근법을 나열할 수 있습니다, 워터폴, V자형 모델, 애자일 방법을 설명하고 이 세 가지 방법의 장단점을 비교할 수 있습니다.

## 내용
- 이 동영상을 시청한 후에는 다음을 수행할 수 있습니다 소프트웨어 개발 라이프사이클에 일반적으로 사용되는 몇 가지 접근법을 나열할 수 있습니다, 워터폴, V자형 모델, 애자일 방법을 설명하고 이 세 가지 방법의 장단점을 비교할 수 있습니다.
- 애자일 모델은 엄격한 하향식 방식이 아닌 여러 번의 짧은 주기에 걸친 협업적 소프트웨어 개발 프로세스에 중점을 둡니다 여러 번의 짧은 주기에 걸친 협업 소프트웨어 개발 프로세스에 중점을 둡니다.
- 각 스프린트가 끝날 때마다 "스프린트 데모"라는 회의에서 작업 코드 덩어리가 공개되어 이해 관계자들이 볼 수 있습니다 데모'라는 회의에서 작업 코드 덩어리가 공개되어 이해관계자들이 새로운 기능을 보고 피드백을 제공할 수 있습니다.
- "애자일 선언문"으로 알려진 애자일 개발의 네 가지 핵심 가치는 다음과 같습니다 는 다음과 같습니다: 프로세스와 도구보다 개인과 상호 작용 포괄적인 문서보다 작동하는 소프트웨어 계약 협상보다 고객 협업, 그리고 계획에 따른 변화에 대한 대응.
- 워터폴 및 V자형과 같은 전통적인 SDLC 방식은 전체 제품을 중심으로 개발되며 고객 피드백을 요청하기 전에 전체 제품을 개발하는 반면 애자일은 짧고 빠른 개발에 중점을 둡니다.
- 프로젝트에 새로운 기능을 추가할 때 개발은 여전히 기존과 동일한 단계를 거칩니다 SDLC, 하지만 애자일에서는 계획이 각 프로젝트의 시작 단계에서 시작되기 때문에 이 각 스프린트 주기가 시작될 때 시작되기 때문에 새롭고 변화하는 요구 사항을 빠르고 쉽게 처리할 수 있습니다.
- 이 동영상에서 그 점을 배웠습니다: 소프트웨어 개발에 대한 세 가지 일반적인 접근 방식에는 워터폴, V자형 모델, 그리고 애자일 워터폴과 V자형은 순차적이지만 애자일은 반복적이라는 점 워터폴 모델과 V자형 모델 모두 구현하기 쉽지만, 둘 다 변화하는 요구 사항을 잘 수용하지 못합니다 애자일은 변화하는 요구 사항을 수용할 수 있지만 리소스 할당이 어려울 수 있습니다.

## 예시
- 각 스프린트가 끝날 때마다 "스프린트 데모"라는 회의에서 작업 코드 덩어리가 공개되어 이해 관계자들이 볼 수 있습니다 데모'라는 회의에서 작업 코드 덩어리가 공개되어 이해관계자들이 새로운 기능을 보고 피드백을 제공할 수 있습니다.
