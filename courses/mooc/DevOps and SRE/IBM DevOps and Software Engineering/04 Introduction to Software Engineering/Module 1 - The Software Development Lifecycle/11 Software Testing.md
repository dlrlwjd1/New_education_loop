# Software Testing

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-software-engineering/lecture/N7m3H/software-testing)

## 개요
- 테스트 케이스에는 단계, 입력 , 데이터 및 예상 해당 출력이 포함됩니다.테스트 유형이나 개발 방법에 관계없이 테스트 케이스는 항상 요구 사항이 확정된 후에 작성해야 합니다.

## 내용
- 테스트 케이스에는 단계, 입력 , 데이터 및 예상 해당 출력이 포함됩니다.테스트 유형이나 개발 방법에 관계없이 테스트 케이스는 항상 요구 사항이 확정된 후에 작성해야 합니다.
- 소프트웨어 테스트는 소프트웨어를 평가하여 소프트웨어 제품이 요구 사항을 충족하고 오류가 없는지 여부를 식별하는 데 도움이 됩니다.테스트 유형은 크게 기능 테스트 , 비기능 테스트, Regression Testing의 세 가지 범주로 분류할 수 있습니다.
- 목표는 응용 프로그램의 기능을 테스트하여 응용 프로그램을 사용할 수 있고 액세스할 수 있는지 확인하는 것입니다.기능 테스트는 SUT가 기능 요구 사항을 충족하는지 확인하기 위해 SUT를 테스트합니다.
- 회귀 테스트를 수행하려면 전체 또는 일부 테스트 사례를 선택하여 애플리케이션에 대해 테스트해야 합니다.Regression 테스트 사례 선택 및 우선 순위 지정은 어려울 수 있으며 여러 요인에 따라 달라질 수 있습니다.
- 회귀 테스트 사례를 선택하는 일반적인 이유에는 결함이 빈번하거나, 자주 사용되는 기능이 있거나, 최근에 변경된 기능이 포함되어 있거나, 복잡한 테스트 사례, 예외적인 사례, 무작위로 성공하거나 실패한 테스트 사례 등이 있습니다.
- 예를 들어 통합 테스트는 모듈 간의 프로그래밍 로직 차이로 인해 버그가 발생하는 상황을 발견합니다.또한 모듈 개발 중에 요구 사항이 변경되어 모듈이 완전히 단위 테스트되지 않는 경우도 있습니다.
- 시스템 테스트는 스테이징 환경에서 수행되며, 스테이징 환경은 프로덕션 환경과 유사해야 합니다.마지막으로 승인 테스트는 사용자 요구 사항, 요구 사항 및 비즈니스 프로세스에 대한 공식 테스트입니다.시스템이 사용자 , 고객 및 기타 이해 관계자의 요구를 충족하는지 여부를 결정합니다.승인 테스트는 일반적으로 SDLC의 유지 관리 단계에서 고객 또는 이해 관계자가 수행합니다.

## 예시
- 회귀 테스트를 수행하려면 전체 또는 일부 테스트 사례를 선택하여 애플리케이션에 대해 테스트해야 합니다.Regression 테스트 사례 선택 및 우선 순위 지정은 어려울 수 있으며 여러 요인에 따라 달라질 수 있습니다.
