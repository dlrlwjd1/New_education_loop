# Approaches to Application Architecture

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-software-engineering/lecture/RATdN/approaches-to-application-architecture)

## 개요
- 구성 요소는 재사용 가능하고, 교체 가능하고, 독립적이고, 확장 가능하고, 캡슐화되고, 컨텍스트에 국한되지 않아야 합니다.각 원칙에 대해 간단히 설명해 보겠습니다.

## 내용
- 구성 요소는 재사용 가능하고, 교체 가능하고, 독립적이고, 확장 가능하고, 캡슐화되고, 컨텍스트에 국한되지 않아야 합니다.각 원칙에 대해 간단히 설명해 보겠습니다.
- 컨텍스트에 국한되지 않는 구성 요소를 만들려면 다양한 환경에서 작동하도록 구성요소를 설계해야 합니다.내부 상태를 설정하는 데이터는 구성요소에 포함되거나 구성요소에 의해 액세스되지 않고 구성요소에 전달되어야 합니다.
- 컨트롤러는 특정 이벤트에 대해 호출해야 하는 다른 구성 요소를 결정하는 구성 요소 유형입니다.다른 두 구성 요소 간의 데이터 흐름을 제어합니다.
- 구성 요소 기반 아키텍처는 느슨하게 연결된 독립 구성 요소를 정의, 구성 및 구현하여 함께 작동하여 응용 프로그램을 만들 수 있도록 해야 합니다.
- 구성 요소와 서비스의 주요 차이점은 서비스에는 여러 클라이언트가 통신하는 항상 실행되는 고유한 인스턴스가 하나뿐이라는 것입니다.이 다이어그램은 계층 아키텍처의 개체, 구성 요소 및 서비스 간의 관계를 보여줍니다.
- 분산 시스템은 HTTP라고도 하는 하이퍼텍스트 전송 프로토콜과 같은 통신 프로토콜을 통해 메시지를 서로 전달하여 상호 작용을 조정하는 여러 시스템에 여러 서비스가 있는 시스템입니다.분산 시스템의 서비스가 여러 시스템에서 작동하더라도 최종 사용자에게는 분산 시스템이 하나의 일관된 시스템으로 보입니다.
- 분산 시스템의 또 다른 특성은 사용자 수가 증가함에 따라 확장 가능하다는 것입니다.분산 시스템을 실행하는 컴퓨터는 같은 종류의 하드웨어나 운영 체제를 사용할 필요가 없습니다.

## 예시
- 예를 들어 구성 요소는 시스템을 특정 데이터베이스에 연결하는 오픈 소스 API일 수 있습니다.

## 요약
- 분산 시스템은 HTTP라고도 하는 하이퍼텍스트 전송 프로토콜과 같은 통신 프로토콜을 통해 메시지를 서로 전달하여 상호 작용을 조정하는 여러 시스템에 여러 서비스가 있는 시스템입니다.분산 시스템의 서비스가 여러 시스템에서 작동하더라도 최종 사용자에게는 분산 시스템이 하나의 일관된 시스템으로 보입니다. 분산 시스템의 또 다른 특성은 사용자 수가 증가함에 따라 확장 가능하다는 것입니다.분산 시스템을 실행하는 컴퓨터는 같은 종류의 하드웨어나 운영 체제를 사용할 필요가 없습니다.
