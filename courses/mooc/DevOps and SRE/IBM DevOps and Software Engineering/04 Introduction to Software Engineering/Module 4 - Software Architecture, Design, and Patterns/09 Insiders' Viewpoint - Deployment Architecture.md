# Insiders' Viewpoint - Deployment Architecture

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-software-engineering/lecture/4N3Gf/insiders-viewpoint-deployment-architecture)

## 개요
- 일반적으로 시스템이 맞는지, 시스템의 사용자가 몇 명인지 등에 대해서요.이를 통해 얼마나 많은 데이터가 흐를 것으로 예상하십니까?

## 내용
- 일반적으로 시스템이 맞는지, 시스템의 사용자가 몇 명인지 등에 대해서요.이를 통해 얼마나 많은 데이터가 흐를 것으로 예상하십니까?
- 서버리스로 전환할지, 호스팅된 백엔드를 사용할지, 자체 호스팅할지와 같은 인프라 선택 측면에서는 모두 설계 및 아키텍처 관련 결정이므로 처음 몇 가지 작업에 대해서는 이미 결정될 것입니다.
- 시스템 SLO와 가용성은 어떻습니까?서비스 수준 목표, 맞죠?그래서 이런 것들에 대해 생각해 봐야 할 것 같아요.
- 그런 것들을 모니터링해서 시스템이 가동되는 것을 지켜보고, 그 목표와 목표를 달성하고 있는지 확인하고, 목표가 의도한 수준에 못 미칠 경우 이를 완화할 계획을 세우세요?
- 요즘에는 마이크로서비스와 코드를 최대한 모듈화하여 거대하고 부풀어 오른 거대 코드 베이스를 피하는 것이 사람들이 빠르게 움직이고 빠르게 배포할 수 있도록 하는 것이 정말 중요하다고 생각합니다.
- 따라서 저는 여러분 모두가 테스트에 정말, 정말로 주의를 기울이고 테스트 주도 개발, TDD, 테스트 주도 개발을 개발자와 엔지니어로서 삶에서 길러주는 개발 습관으로 삼으실 것을 강력히 권합니다.
- 새 코드를 출시하고 코드가 문제를 일으키거나 망가뜨리는지 테스트하고 싶을 때, 얼마나 빨리 릴리스해야 할지 말지 생각해 봐야 합니다.

## 예시
- 새 코드를 출시하고 코드가 문제를 일으키거나 망가뜨리는지 테스트하고 싶을 때, 얼마나 빨리 릴리스해야 할지 말지 생각해 봐야 합니다.

## 요약
- 따라서 저는 여러분 모두가 테스트에 정말, 정말로 주의를 기울이고 테스트 주도 개발, TDD, 테스트 주도 개발을 개발자와 엔지니어로서 삶에서 길러주는 개발 습관으로 삼으실 것을 강력히 권합니다. 새 코드를 출시하고 코드가 문제를 일으키거나 망가뜨리는지 테스트하고 싶을 때, 얼마나 빨리 릴리스해야 할지 말지 생각해 봐야 합니다.
