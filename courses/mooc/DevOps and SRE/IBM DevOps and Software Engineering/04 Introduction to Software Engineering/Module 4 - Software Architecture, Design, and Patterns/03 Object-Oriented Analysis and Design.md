# Object-Oriented Analysis and Design

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/introduction-to-software-engineering/lecture/amp8x/object-oriented-analysis-and-design)

## 개요
- 클래스 다이어그램의 목적을 설명하고, 객체 지향 설계를 소프트웨어 아키텍처와 연계하여 설명하십시오.

## 내용
- 클래스 다이어그램의 목적을 설명하고, 객체 지향 설계를 소프트웨어 아키텍처와 연계하여 설명하십시오.
- 객체 지향 분석 및 설계 (줄여서 OOAD) 는 시스템이 객체 지향 프로그래밍 언어를 사용하여 소프트웨어 시스템을 개발할 때 소프트웨어 시스템을 분석하고 설계하기 위한 접근 방식입니다.
- 따라서 OOAD에 대해 논의하기 전에 Java, C++ 또는 Python과 같은 언어의 객체 지향 프로그래밍에 대해 좀 더 알아보겠습니다.
- 클래스에는 객체의 일반 특성 (속성 및 메서드) 이 포함되어 있지만 코드 내에서 객체가 생성될 때만 이러한 일반 속성이 특정 값으로 설정됩니다.
- 동작 UML 다이어그램의 몇 가지 예를 이미 살펴보았으므로 이제 클래스가 무엇인지 알았으니 이제 “클래스 다이어그램”이라는 구조적 UML 다이어그램을 살펴보겠습니다.
- 즉, 하위 클래스는 상위 클래스와 동일한 속성과 메서드를 가지만 다른 속성과 메서드를 추가할 수도 있습니다.
- 객체 지향 분석 및 설계는 상호 작용하는 객체의 동작을 기반으로 소프트웨어 시스템을 계획하는 프로세스입니다.

## 예시
- 객체 지향 분석 및 설계는 상호 작용하는 객체의 동작을 기반으로 소프트웨어 시스템을 계획하는 프로세스입니다.

## 요약
- 즉, 하위 클래스는 상위 클래스와 동일한 속성과 메서드를 가지만 다른 속성과 메서드를 추가할 수도 있습니다. 객체 지향 분석 및 설계는 상호 작용하는 객체의 동작을 기반으로 소프트웨어 시스템을 계획하는 프로세스입니다.
