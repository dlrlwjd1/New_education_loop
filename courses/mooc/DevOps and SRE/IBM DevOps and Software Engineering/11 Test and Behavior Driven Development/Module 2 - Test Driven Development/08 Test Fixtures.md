# Test Fixtures

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/test-and-behavior-driven-development-tdd-bdd/lecture/fb8hj/test-fixtures)

## 개요
- 테스트 픽스처를 사용하면 테스트 또는 테스트 세트를 실행하기 전과 테스트 후에 테스트 환경이 어떻게 보이는지 설명할 수 있습니다.

## 내용
- 테스트 픽스처를 사용하면 테스트 또는 테스트 세트를 실행하기 전과 테스트 후에 테스트 환경이 어떻게 보이는지 설명할 수 있습니다.
- 모조품과 모조품에 대해서는 다음 강의에서 더 자세히 다루겠지만, 지금은 “테스트 인형” 또는 “스탠드인”으로 생각하시면 됩니다.테스트 당시에는 사용할 수 없었던 실제 물체를 모방하므로 테스트 픽스처를 사용하여 만들 수 있습니다.
- 다음은 TestCase 클래스입니다.이 메서드에는 해당 클래스의 모든 테스트 전에 한 번 실행되는 setupClass () 라는 클래스 메서드가 있을 수 있습니다.
- 테스트 모듈에서 이러한 픽스처를 모두 사용하는 경우 테스트 러너는 SetupModule, SetupClass, Setup을 차례로 실행한 다음 테스트를 실행합니다.
- 그런 다음 해당 테스트 케이스의 각 추가 테스트에 대해 테스트 러너는 Setup을 실행하고 다음 테스트를 실행한 다음 TearDown을 다시 실행합니다.
- 이것은 PyUnit에서 테스트 픽스처를 사용하여 모든 테스트에 데이터베이스 연결과 테스트를 시작할 깨끗한 테이블 세트가 있는지 확인하는 한 가지 예일뿐입니다.
- 그런 다음 “테스트/픽스처스/계정_데이터.json”이라는 JSON 데이터 파일을 열고 이를 ACCOUNT_DATA 딕셔너리에 로드합니다.

## 예시
- 이렇게 하면 예를 들어 한 테스트에서 고객을 삭제해도 다른 테스트에서 해당 고객을 찾는 데 영향을 주지 않습니다.

## 요약
- 이것은 PyUnit에서 테스트 픽스처를 사용하여 모든 테스트에 데이터베이스 연결과 테스트를 시작할 깨끗한 테이블 세트가 있는지 확인하는 한 가지 예일뿐입니다. 그런 다음 “테스트/픽스처스/계정_데이터.json”이라는 JSON 데이터 파일을 열고 이를 ACCOUNT_DATA 딕셔너리에 로드합니다.
