# Anatomy of a Test Case

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/test-and-behavior-driven-development-tdd-bdd/lecture/6cFQL/anatomy-of-a-test-case)

## 개요
- 이 동영상을 시청한 후에는 테스트에서 테스트 픽스처의 역할을 요약하고, 테스트 프레임워크가 개발자가 어설션을 구축하는 데 어떻게 도움이 되는지 설명하고, 테스트 케이스를 구성하는 방법을 설명할 수 있습니다.예제 테스트 케이스를 살펴보겠습니다.이 예제에서는 스택이라는 일반적인 프로그래밍 구조를 사용할 것입니다.따라서 먼저 스택이 무엇이고 어떻게 작동하는지 이해해야 합니다.

## 내용
- 이 동영상을 시청한 후에는 테스트에서 테스트 픽스처의 역할을 요약하고, 테스트 프레임워크가 개발자가 어설션을 구축하는 데 어떻게 도움이 되는지 설명하고, 테스트 케이스를 구성하는 방법을 설명할 수 있습니다.예제 테스트 케이스를 살펴보겠습니다.이 예제에서는 스택이라는 일반적인 프로그래밍 구조를 사용할 것입니다.따라서 먼저 스택이 무엇이고 어떻게 작동하는지 이해해야 합니다.
- 스택은 라스트 인, 선출 또는 LIFO 동작을 구현하는 데이터 구조입니다.즉, 스택에 무언가를 추가하면 맨 위에 배치되고 스택에서 무언가를 제거하면 맨 위에서 제거됩니다.따라서 마지막으로 추가된 항목이 제거된 첫 번째 항목입니다.스택은 테니스 공이 들어 있는 튜브와 같다고 생각할 수 있습니다.맨 위에 있는 테니스 공을 먼저 꺼내지 않는 한 맨 아래에 있는 테니스 공을 꺼낼 수 없습니다.이 예시에서는 누군가가 이미 A와 B를 추가했는데 스택에 항목을 추가하거나 푸시하는 명령을 푸시라고 합니다.이 예시에서는 항목 C가 스택에 방금 푸시되었습니다.또한 peek 명령을 수행할 수도 있습니다.
- 유닛 테스트에서 가져온 테스트 케이스의 하위 클래스인 클래스를 선언하여 테스트 케이스 작성을 시작합니다.저는 이것을 클래스 스택 테스트 케이스라고 불렀습니다.잠시 후에 살펴보겠지만, 각 테스트는 이 클래스의 메서드가 될 것입니다.다음으로 두 개의 테스트 픽스처를 정의합니다.테스트 픽스처에 대해서는 다른 강의에서 더 자세히 설명하겠지만, 지금은 테스트 픽스처를 사용하면 테스트 케이스를 실행하기 전에 시스템의 초기 상태를 지정할 수 있다는 점을 알아두세요.
- 설치 프로그램에서는 self.stack이라는 인스턴스 변수를 선언하고 이를 새 스택에 할당합니다.이것이 우리가 테스트할 스택이 될 것입니다.Teardown은 self.stack을 none으로 설정하여 재사용되지 않도록 하는 것으로, 이로 인해 부작용이 발생할 수 있습니다.이제 드디어 첫 번째 테스트 케이스를 작성할 준비가 되었습니다.메서드를 정의하고 test_push라고 부릅니다.
- 부모 클래스 테스트 케이스에서 가져온 것입니다.이것이 우리가 어설션을 만드는 데 사용할 수 있는 일련의 메서드를 상속하기 위해 테스트 케이스를 서브클래싱하는 이유입니다.이 메서드는 전달되는 모든 인수가 같다고 주장합니다.이 예제에서는 스택의 맨 위를 들여다보면 9개가 반환된다고 주장합니다.예제에서 9가 실제로 스택의 맨 위에 있다는 것을 알 수 있습니다.
- 테스트 케이스를 저장하고 실행되는 것을 지켜봅시다.당연하게도 테스트를 실행할 때 첫 단계는 setup을 호출하고 새 스택을 생성하여 인스턴스 변수 self.stack에 할당하는 것입니다.다음으로 self.stack.push를 실행하고 숫자 9를 전달하여 9를 스택에 푸시합니다.
- 필요에 따라 몇 가지 테스트 픽스처를 추가하여 각 테스트를 설정하고 분해할 수 있습니다.그런 다음 테스트하려는 코드를 사용하여 예상대로 작동하거나 작동하지 않는지 확인하는 개별 테스트를 작성합니다.이 비디오에서는 테스트 픽스쳐가 개발자가 초기 테스트 상태를 만드는 데 도움이 된다는 것을 배웠습니다.테스트 프레임워크는 테스트 조건을 간소화하는 도구를 제공하며 테스트 사례에는 코드가 예상대로 작동하는지 확인하는 어설션이 포함됩니다.
