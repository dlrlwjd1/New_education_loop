# Writing Feature Files

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/test-and-behavior-driven-development-tdd-bdd/lecture/lDhk5/writing-feature-files)

## 개요
- 이 비디오를 시청한 후에는 기능 파일을 작성하기 위한 필수 팁을 설명하고 Gherkin 구문에서 Background 키워드와 테이블을 사용하는 방법을 설명할 수 있습니다.

## 내용
- 이 비디오를 시청한 후에는 기능 파일을 작성하기 위한 필수 팁을 설명하고 Gherkin 구문에서 Background 키워드와 테이블을 사용하는 방법을 설명할 수 있습니다.
- 하지만 해당 문자열이 동일한 코드를 실행하는 경우 기능 파일에서 사용할 문자열 중 하나를 선택하면 됩니다.
- 저는 개발자들이 customer_id와 같은 변수 이름을 사용할 수 있는 기능 파일을 작성하는 것을 본 적이 있습니다.
- 이 Given 진술은 다른 것과 같습니다.Behave는 모든 Python 스텝 파일에서 Given 데코레이터와 그 뒤에 “the following pets”라는 문자열을 검색합니다.
- 예를 들어 한 시나리오에서 애완동물 중 하나를 삭제하면 Behave는 해당 테이블을 다시 로드하고 해당 애완동물은 다음 시나리오에서 사용할 수 있게 됩니다.
- 이벤트의 두 번째 부분은 “그리고 '검색' 버튼을 클릭합니다.” 이제 개발자는 카테고리 필드 외에도 검색 버튼을 제공해야 한다는 것을 알고 있습니다.
- 다음 두 어설션은 사용자가 찾고 있지 않은 것을 나타냅니다.한 가지 주장은 “하지만 결과에 '키티'가 나오면 안 된다”는 것이고, 다른 하나는 “결과에 '레오'가 나오면 안 된다”는 것입니다.

## 예시
- 예를 들어 사용자가 클릭했을 때 검색/제출 버튼이 작동하는지 확인한다고 가정해 보겠습니다.

## 요약
- 이벤트의 두 번째 부분은 “그리고 '검색' 버튼을 클릭합니다.” 이제 개발자는 카테고리 필드 외에도 검색 버튼을 제공해야 한다는 것을 알고 있습니다. 다음 두 어설션은 사용자가 찾고 있지 않은 것을 나타냅니다.한 가지 주장은 “하지만 결과에 '키티'가 나오면 안 된다”는 것이고, 다른 하나는 “결과에 '레오'가 나오면 안 된다”는 것입니다.
