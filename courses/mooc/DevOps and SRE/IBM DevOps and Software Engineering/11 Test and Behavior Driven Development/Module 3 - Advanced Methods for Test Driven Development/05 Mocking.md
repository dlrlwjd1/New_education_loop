# Mocking

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/test-and-behavior-driven-development-tdd-bdd/lecture/pb1QB/mocking)

## 개요
- 테스트 대상이 시스템이 아니라 코드가 시스템을 호출하고 데이터를 가져온 다음 해당 데이터로 작업을 수행할 수 있는지 여부를 테스트하기 때문에 이를 모방하는 것입니다.

## 내용
- 테스트 대상이 시스템이 아니라 코드가 시스템을 호출하고 데이터를 가져온 다음 해당 데이터로 작업을 수행할 수 있는지 여부를 테스트하기 때문에 이를 모방하는 것입니다.
- 그러면 좋은 리뷰, 나쁜 리뷰, 심지어 리뷰가 없는 리뷰 등 필요한 모든 유형의 리뷰를 다시 보내도록 할 수 있습니다.
- 간단히 말해서 원격 컴포넌트나 외부 시스템에서 테스트를 분리하고 싶을 때 모의 객체를 사용하여 대신 사용할 수 있습니다.
- 다른 방법은 전체 객체를 모킹하여 동작을 변경하는 테스트 프레임워크의 모의 객체를 사용하는 것입니다.
- 이러한 모의 객체의 가장 좋은 용도는 단순한 함수 호출이 아니라 다른 객체처럼 동작하는 전체 객체가 필요할 때입니다.
- 패치와 프레임워크에서 제공하는 모의 객체를 조합하여 사용하면 테스트 조건에서 외부 종속성을 완벽하게 제어하여 반복 가능한 결과를 얻을 수 있습니다.
- 개발자는 원격 구성 요소 또는 외부 시스템에서 테스트를 분리하고 싶을 때마다 모의 작업을 수행해야 합니다.

## 예시
- 예를 들어 코드가 IMDB로 더 잘 알려진 인터넷 영화 데이터베이스의 영화 리뷰를 처리한다고 가정해 보겠습니다.

## 요약
- 패치와 프레임워크에서 제공하는 모의 객체를 조합하여 사용하면 테스트 조건에서 외부 종속성을 완벽하게 제어하여 반복 가능한 결과를 얻을 수 있습니다. 개발자는 원격 구성 요소 또는 외부 시스템에서 테스트를 분리하고 싶을 때마다 모의 작업을 수행해야 합니다.
