# Microservices Patterns

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/applications-development-microservices-serverless-openshift/lecture/hrqIe/microservices-patterns)

## 개요
- 예로는 단일 페이지 애플리케이션 (또는 SPA) 패턴, 프론트엔드용 백엔드 (BFF) 패턴, 스트랭글러 패턴, 서비스 검색 패턴 등이 있습니다.

## 내용
- 예로는 단일 페이지 애플리케이션 (또는 SPA) 패턴, 프론트엔드용 백엔드 (BFF) 패턴, 스트랭글러 패턴, 서비스 검색 패턴 등이 있습니다.
- HTML, CSS 및 JavaScript의 조합을 사용하여 구축된 이러한 애플리케이션은 완전히 새로운 페이지로 리디렉션하는 대신 화면의 일부를 업데이트하는 백엔드 REST 기반 서비스에 대한 동적 서비스 호출을 통해 사용자 입력에 응답합니다.
- 단일 페이지 애플리케이션은 단일 채널 사용자 경험에 적합하지만 모바일 및 웹과 같은 다양한 채널을 통한 사용자 경험 전반에서는 좋지 않은 결과를 제공합니다.
- BFF 패턴을 사용하면 개발자가 모든 인터페이스에서 작동하지만 프론트엔드 성능에 부정적인 영향을 미칠 수 있는 일반 백엔드를 지원하는 대신 해당 인터페이스에 가장 적합한 옵션을 사용하여 사용자 인터페이스당 하나의 백엔드 유형을 만들고 지원할 수 있습니다.
- 필요한 채널을 확인한 다음 해당 채널에 대한 사용자 경험을 준비하기 위한 모든 로직을 포함하는 모놀리식 앱을 사용하는 대신 마이크로서비스 아키텍처를 적용하여 모놀리식 백엔드를 특정 필수 작업을 수행하는 별도의 서비스로 분리합니다.
- 스트랭글러 패턴을 사용하면 웹 애플리케이션의 구조를 사용하여 애플리케이션을 여러 기능 도메인으로 분할하고 해당 도메인을 한 번에 하나의 도메인에 대한 새로운 마이크로서비스 기반 구현으로 대체합니다.
- 이 비디오에서는 마이크로서비스를 통해 백킹 서비스에 의존하는 단일 페이지 애플리케이션이 페이지를 동적으로 업데이트할 수 있고, 프론트엔드용 백엔드 패턴은 마이크로서비스를 사용하여 다양한 사용자 경험을 보다 쉽게 지원하고, 스트랭글러 패턴을 적용하여 모놀리식 앱을 마이크로서비스로 분할할 수 있으며, 서비스 검색 패턴을 통해 애플리케이션과 서비스가 서로를 발견할 수 있다는 것을 배웠습니다.

## 예시
- 예를 들어 데스크톱에서 사용되는 앱의 화면 크기 , 디스플레이 및 성능 제한은 모바일 장치에서 사용되는 앱과 다릅니다.

## 요약
- 스트랭글러 패턴을 사용하면 웹 애플리케이션의 구조를 사용하여 애플리케이션을 여러 기능 도메인으로 분할하고 해당 도메인을 한 번에 하나의 도메인에 대한 새로운 마이크로서비스 기반 구현으로 대체합니다. 이 비디오에서는 마이크로서비스를 통해 백킹 서비스에 의존하는 단일 페이지 애플리케이션이 페이지를 동적으로 업데이트할 수 있고, 프론트엔드용 백엔드 패턴은 마이크로서비스를 사용하여 다양한 사용자 경험을 보다 쉽게 지원하고, 스트랭글러 패턴을 적용하여 모놀리식 앱을 마이크로서비스로 분할할 수 있으며, 서비스 검색 패턴을 통해 애플리케이션과 서비스가 서로를 발견할 수 있다는 것을 배웠습니다.
