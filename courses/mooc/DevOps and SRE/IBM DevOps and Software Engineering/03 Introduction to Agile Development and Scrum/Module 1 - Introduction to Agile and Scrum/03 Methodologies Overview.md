# Methodologies Overview

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/agile-development-and-scrum/lecture/QV5Aa/methodologies-overview)

## 개요
- 워터폴 접근 방식의 문제점을 설명하고, 익스트림 프로그래밍 접근 방식을 설명하고, XP 접근 방식의 가치 목록을 설명하고, 칸반을 정의하고, 핵심 원칙을 나열합니다.

## 내용
- 워터폴 접근 방식의 문제점을 설명하고, 익스트림 프로그래밍 접근 방식을 설명하고, XP 접근 방식의 가치 목록을 설명하고, 칸반을 정의하고, 핵심 원칙을 나열합니다.
- 모든 것은 요구 사항 단계에서 시작됩니다.사람들은 요구 사항을 수집하고, 고객이 원하는 것을 파악하고, 고객이 원하는 것을 제공할 수 있도록 합니다.적어도 그 시점에서는요.
- 따라서 이 단계에서는 시스템에서 고객이 원하는 모든 요구 사항을 문서화하기만 하면 됩니다.그런 다음 설계 단계로 넘어갑니다.
- 그래서 설계 단계에서는 건축가들이 설계를 합니다.그들은 우리가 이러한 요구 사항을 어떻게 받아들이고 제대로 작동하는 소프트웨어로 전환할 수 있는지 알아내고 전체 시스템을 설계합니다.
- 그리고 존중, 모든 사람은 자신이 팀에서 존경을 받고 있고, 제안을 할 수 있는 조언을 줄 수 있고, 자신의 제안이 팀의 다른 사람의 제안과 마찬가지로 가치 있다고 느낍니다.
- 칸반은 또한 진행 중인 작업을 제한한다고 강조합니다.제조 현장에 있을 때 스테이션 중 한 곳에 작업물이 백업되는 것을 원하지 않을 것입니다.
- 그들은 항상 변화를 모색하고 제조 현장에서 더 나은 흐름과 더 빠른 흐름을 얻을 수 있는 방법을 이해하고 모든 사람이 상황이 어떻게 돌아가는지 이해할 수 있도록 정책을 명시합니다.

## 예시
- 그들은 항상 변화를 모색하고 제조 현장에서 더 나은 흐름과 더 빠른 흐름을 얻을 수 있는 방법을 이해하고 모든 사람이 상황이 어떻게 돌아가는지 이해할 수 있도록 정책을 명시합니다.
