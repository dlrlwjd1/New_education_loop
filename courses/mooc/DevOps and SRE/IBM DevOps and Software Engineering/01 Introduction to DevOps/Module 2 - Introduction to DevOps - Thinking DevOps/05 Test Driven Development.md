# Test Driven Development

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/intro-to-devops/lecture/McUML/test-driven-development)

## 개요
- 이 비디오를 시청한 후에는 TDD (테스트 기반 개발) 를 정의하고, TDD가 어떻게 더 높은 품질의 코드를 생성하는지 설명하고, Red, Green, Refactor 워크플로를 설명하고, DevOps에서 TDD의 중요성을 설명할 수 있습니다.

## 내용
- 이 비디오를 시청한 후에는 TDD (테스트 기반 개발) 를 정의하고, TDD가 어떻게 더 높은 품질의 코드를 생성하는지 설명하고, Red, Green, Refactor 워크플로를 설명하고, DevOps에서 TDD의 중요성을 설명할 수 있습니다.
- 테스트할 가치가 없다면 왜 시간을 낭비하는 거죠?” 테스트 케이스를 작성하는 것은 코드가 의도한 대로 작동하는지 증명하는 데 매우 중요합니다.
- 글쎄, 아직 작성하지 않은 코드에 대한 테스트 케이스를 작성하려면 어떻게 해야 할까요?
- 서버에서 업데이트할 수 있나요?” 코드를 테스트하고 해당 라이브러리의 새 버전에서 작동하는지 확인하는 테스트 케이스가 없다면 그렇게 하지 않는 것이 좋습니다.
- 코드를 리팩토링할 때 테스트 케이스가 동작의 모든 변화를 포착한다는 것을 알기 때문에 훨씬 빠르게 진행할 수 있습니다.
- 원하는 동작을 정의하기 위해 먼저 테스트 케이스를 작성하면 테스트를 통과했을 때 해당 동작을 달성했음을 알 수 있습니다.
- 마지막으로 가장 중요한 것은 DevOps 파이프라인 (CI/CD 파이프라인) 을 만들려면 버그를 프로덕션에 더 빨리 푸시하려는 경우가 아니라면 모든 테스트를 자동화해야 한다는 것입니다.

## 예시
- 이제 몇 가지 테스트 사례를 작성하는 데 소요되는 시간을 나중에 디버깅하는 데 드는 시간과 시간을 절약할 수 있습니다.

## 요약
- 원하는 동작을 정의하기 위해 먼저 테스트 케이스를 작성하면 테스트를 통과했을 때 해당 동작을 달성했음을 알 수 있습니다. 마지막으로 가장 중요한 것은 DevOps 파이프라인 (CI/CD 파이프라인) 을 만들려면 버그를 프로덕션에 더 빨리 푸시하려는 경우가 아니라면 모든 테스트를 자동화해야 한다는 것입니다.
