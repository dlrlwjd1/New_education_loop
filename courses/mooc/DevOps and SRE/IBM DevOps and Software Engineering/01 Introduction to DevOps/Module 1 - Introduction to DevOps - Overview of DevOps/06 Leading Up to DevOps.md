# Leading Up to DevOps

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/intro-to-devops/lecture/6Q0Ra/leading-up-to-devops)

## 개요
- 이 비디오를 시청한 후에는 워터폴 방식의 문제점을 설명하고 DevOps 이전의 소프트웨어 개발과 운영 간의 일반적인 관계를 설명할 수 있습니다.DevOps로 해결되는 문제를 충분히 이해하려면 DevOps를 도입한 이유를 이해하는 것이 중요합니다.

## 내용
- 이 비디오를 시청한 후에는 워터폴 방식의 문제점을 설명하고 DevOps 이전의 소프트웨어 개발과 운영 간의 일반적인 관계를 설명할 수 있습니다.DevOps로 해결되는 문제를 충분히 이해하려면 DevOps를 도입한 이유를 이해하는 것이 중요합니다.
- 건축가는 종이로 시스템을 설계하고, 요구 사항 문서를 작성하고, 설계 문서를 작성하고, 상위 설계, 저수준 설계, 시스템 수준 설계를 작성하는 데 몇 달, 몇 달을 소비했습니다.
- 다음 단계에서는 모든 설계를 수행하고 설계를 상위 수준 설계, 하위 수준 설계, 시스템 수준 설계로 문서화한 다음 해당 단계가 종료됩니다.
- 이러한 아티팩트는 다음 단계로 전달되며 개발자가 저수준 설계 문서를 가져와 해당 설계를 구현하는 코드를 작성하는 곳에서 코딩이 시작됩니다.
- 디자이너는 코드에 미치는 영향을 인식하지 못하고, 코더는 모든 코드를 정리하기 전에 코드에 미치는 영향이나 코더가 테스트에 미치는 영향이나 통합에 미치는 영향을 인식하지 못합니다.
- 그리고 가장 무서운 생각은 코드와 가장 멀리 떨어져 있는 사람들, 즉 빈약한 운영 팀이 코드를 배포하고 실행하고 프로덕션 환경에서 관리해야 한다는 것입니다.
- 이 비디오를 통해 알게 된 사실은, 기존의 Waterfall 개발은 지연, 장애, 긴 리드 타임, 비용이 많이 드는 늦은 변경, 익숙하지 않은 코드를 관리하는 작업 등과 같은 문제를 야기한다는 것입니다.

## 예시
- 이 비디오를 통해 알게 된 사실은, 기존의 Waterfall 개발은 지연, 장애, 긴 리드 타임, 비용이 많이 드는 늦은 변경, 익숙하지 않은 코드를 관리하는 작업 등과 같은 문제를 야기한다는 것입니다.

## 요약
- 그리고 가장 무서운 생각은 코드와 가장 멀리 떨어져 있는 사람들, 즉 빈약한 운영 팀이 코드를 배포하고 실행하고 프로덕션 환경에서 관리해야 한다는 것입니다. 이 비디오를 통해 알게 된 사실은, 기존의 Waterfall 개발은 지연, 장애, 긴 리드 타임, 비용이 많이 드는 늦은 변경, 익숙하지 않은 코드를 관리하는 작업 등과 같은 문제를 야기한다는 것입니다.
