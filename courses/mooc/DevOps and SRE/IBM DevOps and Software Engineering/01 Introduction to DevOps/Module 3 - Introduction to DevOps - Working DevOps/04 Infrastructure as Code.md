# Infrastructure as Code

> MOOC 영상 · [원본 강의](https://www.mooc.org/learn/intro-to-devops/lecture/cYYeh/infrastructure-as-code)

## 개요
- 이 비디오를 시청한 후에는 인프라를 코드로 정의하고, 임시 인프라를 설명하고, 컨테이너를 통한 변경 불가능한 전달에 대해 설명할 수 있습니다.

## 내용
- 이 비디오를 시청한 후에는 인프라를 코드로 정의하고, 임시 인프라를 설명하고, 컨테이너를 통한 변경 불가능한 전달에 대해 설명할 수 있습니다.
- Ansible, Puppet, Chef와 같은 도구를 사용하면 인프라를 코드로 설명한 다음 해당 인프라를 생성하고 해당 상태로 유지할 수 있습니다.
- 그런 다음 해당 텍스트 코드를 가져와 버전 관리 시스템에 저장하여 모든 변경 내역을 확인할 수 있습니다.
- Docker, Vagrant, Terraform, 심지어 Kubernetes와 같은 기술을 사용하면 인프라를 코드로 설명할 수 있으며, 이 코드는 버전 제어에 체크인해야 합니다.
- 인프라를 코드 기법으로 사용하여 온디맨드 방식으로 자동화를 통해 서버를 구축하기 때문에 임시 인프라를 사용한 후 폐기할 수 있습니다.
- 애플리케이션을 설치하여 작동하는지 확인한 다음 작동하지 않으면 제거하는 것이 아니라 새 버전과 함께 Docker 컨테이너를 불러오기만 하면 됩니다.
- 불변의 전달은 실행 중인 컨테이너를 패치하는 대신 컨테이너 이미지를 변경한 다음 새 컨테이너를 재배포하는 것입니다.

## 예시
- 예를 들어, 과거에는 테스트 환경을 구축하는 데 몇 주가 걸렸습니다.

## 요약
- 애플리케이션을 설치하여 작동하는지 확인한 다음 작동하지 않으면 제거하는 것이 아니라 새 버전과 함께 Docker 컨테이너를 불러오기만 하면 됩니다. 불변의 전달은 실행 중인 컨테이너를 패치하는 대신 컨테이너 이미지를 변경한 다음 새 컨테이너를 재배포하는 것입니다.
