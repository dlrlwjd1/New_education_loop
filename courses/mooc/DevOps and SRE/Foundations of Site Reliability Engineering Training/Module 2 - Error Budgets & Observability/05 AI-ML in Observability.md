# AI/ML in Observability (관찰 가능성에서의 AI/ML)

> 강좌: Foundations of Site Reliability Engineering Training (Simplilearn) · 모듈 2: Error Budgets & Observability

## 개요
- 시스템이 복잡해지며 전통적 관찰 방법이 부족해지는 상황에서, **AI/ML**이 어떻게 관찰 가능성을 돕는지 다룬다.

## 내용

### 왜 AI/ML인가
- 시스템이 점점 복잡해져 전통적 관찰 방법만으로는 부족 → **AI/ML의 도움** 필요.
- "더 열심히(hard) + 더 똑똑하게(smart)" 일하게 해줌 — 이슈를 **조기에 발견**하고 운영을 **선제적(proactive)**으로.
- 문제가 실제 발생하기 전에 경고를 받아 조치 → **다운타임을 아예 없앰**.

### 핵심 응용
- **이상 탐지(anomaly detection)** — 비정상 패턴 식별.
- **근본 원인 분석(root cause analysis)** — 실패 기원 특정.
- **예측 경고(predictive alerts)** — 이슈 발생 전 경고.
- **노이즈 감소(noise reduction)** — 무관한 데이터 필터링.
- **자동 복구(automated remediation)** — 문제 해결 가속.
  - 예: RAM이 증가하는 패턴을 AI가 감지 → 자동 워크플로로 앱을 **스케일 업/아웃**해 RAM을 낮추거나 늘림.

## 요약
- 복잡한 시스템에서 **AI/ML**은 이슈를 조기 발견해 운영을 반응적에서 **선제적**으로 전환한다.
- 응용: **이상 탐지·근본 원인 분석·예측 경고·노이즈 감소·자동 복구**.
