# Introduction to Site Reliability Engineering (SRE) (SRE 소개)

> 강좌: Foundations of Site Reliability Engineering Training (Simplilearn) · 모듈 1: SRE Foundations

## 개요
- **SRE**의 정의, 목표, 달성 방법, 기원, **DevOps와의 차이**, 그리고 SRE 팀의 역할을 다룬다.

## 내용

### SRE란
- IT 운영의 원리를 소프트웨어로 적용해 **매우 신뢰성 있고 확장 가능한 시스템**을 구축·운영. (소규모는 1명, 대규모는 팀)
- 자동화·모니터링·인시던트 대응으로 소프트웨어 애플리케이션의 신뢰성·효율을 개선 → 비즈니스를 계속 돌아가게.

### 목표
- **시스템 신뢰성(reliability)** — 항상 가용.
- **성능(performance)** — 개발 속도(velocity)와 시스템 안정성(stability)의 sweet spot.
- **확장성(scalability)** — 수요 증가에 맞춰 잘 확장.
- **균형(balance)** — 빠른 배포 + 안정성.

### 달성 방법
- **위험 수용(embracing risk)** — 에러 버짓·실패 분석으로 계산된 위험 감수.
- **명확한 목표** — 측정 가능한 **SLO** 설정.
- **모니터링** — 메트릭·로그로 가시성.
- **협업(collaboration)** — 개발·운영 사일로 제거.
- **자동화(automation)** — 반복 작업 제거(복잡성·안일함 방지), 속도·커버리지 향상.

### 기원
- **구글이 2003년** 대규모 서비스 신뢰성 유지를 위해 도입 → **에러 버짓·수작업 감소·비난 없는 포스트모템** 개념 소개. 이후 많은 기업이 채택, SRE 채용도 증가.

### SRE vs DevOps
| DevOps | SRE |
|--------|-----|
| 문화 중심(culture-focused) | 엔지니어링 중심 |
| 협업 강조 | **자동화·메트릭** 강조 |
| 공식 에러 버짓 없음 | **에러 버짓으로 의사결정** |
| 넓은 조직적 마인드셋 | DevOps 원리의 **구체적 구현** |
| CI/CD 초점 | **신뢰성·가동시간** 초점 |

### SRE 팀 역할
- **인시던트 커맨더(Incident Commander)** — 장애 대응 조율, 팀 노력 조정, 명확한 소통 보장.
- **온콜 엔지니어(On-call Engineer)** — 경고 대응, 트러블슈팅·수정 구현. (커맨더와 협력)
- **신뢰성 아키텍트(Reliability Architect)** — 회복력 있는 시스템 설계, 신뢰성 표준 수립.
- **도구 개발자(Tools Developer)** — 자동화·모니터링 솔루션 제작.

## 요약
- SRE는 IT 운영 원리를 소프트웨어로 구현해 **신뢰성·성능·확장성·균형**을 달성한다.
- **구글(2003)**이 시작했으며 에러 버짓·비난 없는 포스트모템을 도입했다.
- **DevOps는 문화·협업 중심, SRE는 엔지니어링·자동화·메트릭·에러 버짓 중심**이다.
- 팀 역할: 인시던트 커맨더·온콜 엔지니어·신뢰성 아키텍트·도구 개발자.
