# Learning Objectives — 대화정리

## 개요
- 모듈 1은 SRE의 기본 개념부터 신뢰성 측정, 모니터링, 인시던트 관리까지 다룬다.
- 신뢰성을 관리하려면 먼저 서비스가 제대로 동작하는 기준을 정하고 그 상태를 측정할 수 있어야 한다.

## 내용

### 모듈의 학습 목표
- SRE의 핵심 개념과 기원을 이해하고 DevOps와 비교한다.
- SLI·SLO·SLA로 서비스 신뢰성을 측정하고 목표를 정의한다.
- 에러 예산(error budget)으로 신뢰성과 혁신 사이의 균형을 조절한다.
- 모니터링과 관측성(observability)을 적용하여 시스템 가시성을 확보한다.
- 인시던트 관리(incident management)로 장애에 대응하고 경험에서 배운다.

### 신뢰성 기준과 모니터링의 관계
- 모니터링은 데이터를 보여주는 수단이므로, 먼저 무엇을 측정해야 서비스가 신뢰할 만한지 정해야 한다.
- 사용자에게 중요한 행동을 기준으로 SLI를 정의하고, 모니터링으로 그 값을 지속해서 측정한다.
- 아직 측정 수단이 없다면 현재 값을 추측하지 않고 `측정 불가`로 기록한다. 이것이 이후 모니터링 구축의 출발점이 된다.

## 예시
건강보험공단 연동 후 사용자의 몸 상태 결과를 화면에 표시하는 기능을 생각할 수 있다.

- 중요한 사용자 행동: 연동을 시작해 결과 화면까지 정상적으로 확인한다.
- SLI: 전체 연동 시도 중 결과 화면까지 정상 표시된 비율
- 현재 값: 측정 수단이 없으므로 `측정 불가`
- 필요한 가시성: 연동 시작·성공·실패를 구분해 성공률을 계산할 수 있어야 한다.

```text
연동 성공률 = 결과 화면까지 정상 표시된 연동 횟수
             ÷ 전체 연동 시도 횟수 × 100
```

## 요약
- 모듈 1의 흐름은 신뢰성 기준 정의 → 관측과 측정 → 장애 대응 → 학습과 개선이다.
- 모니터링에 앞서 사용자가 중요하게 여기는 성공 행동을 정해야 한다.
- 측정할 수 없는 현재 상태를 확인하는 것도 신뢰성 개선의 중요한 첫 단계다.
