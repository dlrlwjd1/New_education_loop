# Performance Testing in CI/CD (CI/CD의 성능 테스트)

> 강좌: Foundations of Site Reliability Engineering Training (Simplilearn) · 모듈 7: Performance Testing & Advanced SRE

## 개요
- 흔한 **병목(bottleneck)**, CI/CD 성능 테스트 접근·과제·모범 사례와 전자상거래 사례를 다룬다.

## 내용

### 흔한 병목
- **데이터베이스** — 과도한 I/O, 커넥션 풀링, 비효율 쿼리, 인덱싱.
- **메모리** — 메모리 누수, 버퍼 오버런, 가비지 컬렉션.
- **CPU** — 비효율 알고리즘, 스레드 경합(thread contention)·락.
- **디스크 I/O** — 읽기/쓰기 (SSD vs 플래터). → **캐싱**(인메모리 DB) 검토.
- **네트워크** — 대역폭 제약, 높은 지연, 과다한 HTTP 요청.
- **외부 의존성** — 서드파티 API 가용성·응답 시간.

### CI/CD 성능 테스트란
- 성능 테스트를 워크플로에 **내장해 회귀(regression)를 조기에** 잡되, 철저함과 실행 속도를 균형.
- 접근: **성능 테스트 자동화**, **각 빌드를 베이스라인과 비교**해 회귀 탐지, **성능 버짓·임계값 정의**, 코드 변경 기반 **선택적 테스트**.

### 과제
- 긴 테스트 실행 시간, 큰 리소스 요구, **일관성 없는 환경**(스테이징·프로덕션은 최대한 유사하게), 변동적 결과, 오탐(false positive/negative).

### 모범 사례
- **일찍·자주 테스트(test early and often)** — 개발 전반에서.
- **변수 격리** — 한 번에 한 요소만 변경.
- **현실적 데이터** — 프로덕션과 유사한 볼륨·패턴(개인정보 제외).
- **한계를 넘어 테스트(test beyond breaking)** — 시스템 파괴점 탐색.
- **모든 것 모니터링**.

### 사례 — 전자상거래
- 과제: 플래시 세일 중 심각한 속도 저하 → 장바구니 이탈·매출 손실.
- 접근: 과거 세일 데이터 기반 현실적 부하 프로파일로 종합 성능 테스트 → DB 계층·결제 통합에서 병목 발견.
- 결과: 피크 페이지 로드 시간 대폭 감소, **트랜잭션 처리량 50%↑, 장바구니 이탈 75%↓, 세일 매출 35%↑**, 고객 만족 향상.

## 요약
- 병목: **DB·메모리·CPU·디스크 I/O·네트워크·외부 의존성** → 캐싱 등으로 해소.
- CI/CD 성능 테스트: **자동화·베이스라인 비교·성능 버짓·선택적 테스트**로 회귀 조기 탐지.
- 모범 사례: **일찍·자주·변수 격리·현실적 데이터·한계 초과·모니터링**.
