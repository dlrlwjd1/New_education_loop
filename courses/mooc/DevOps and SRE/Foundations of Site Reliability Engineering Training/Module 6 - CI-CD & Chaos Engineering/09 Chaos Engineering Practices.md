# Chaos Engineering Practices (카오스 엔지니어링 실무)

> 강좌: Foundations of Site Reliability Engineering Training (Simplilearn) · 모듈 6: CI/CD & Chaos Engineering

## 개요
- 카오스 엔지니어링의 **프로세스·도구·실험 유형·핵심 원칙·안전 관행·메트릭**을 다룬다.

## 내용

### 프로세스
1. **정상 상태 정의(define steady state)**.
2. **가설 수립**.
3. **실험 실행**.
4. **결과 관찰**.
5. **시스템 개선** — 나쁘면 고치고, 좋아도 지연시간 등 개선.

### 도구
- **Chaos Monkey / Simian Army** (Netflix), **Litmus Chaos**(K8s 클라우드 네이티브), **Gremlin**(상용 플랫폼), **Chaos Toolkit**(오픈소스), **Chaos Mesh**(K8s), **PowerfulSeal**(K8s 파드·노드 종료).

### 실험 유형
- **인프라 카오스** — 서버·전원·RAM·CPU 장애 시뮬레이션.
- **애플리케이션 카오스** — API 오류, DB 손상, 서비스 의존성 장애.
- **네트워크 카오스** — 지연 주입, 패킷 손실, DNS 장애, 연결 종료.
- **상태(state) 카오스** — 시스템 시계 왜곡, 리소스 고갈, 데이터 손상.

### 효과적 실험의 핵심 원칙
- **작게 시작(start small)** — 비핵심 시스템의 단순 실험부터.
- **명확한 메트릭 정의** — 측정 가능한 시스템 건강 지표로 delta(개선/악화) 평가.
- **중단 계획(abort)** — 정지 버튼으로 추가 피해 방지.
- **모든 것 문서화** — AI가 문서·데이터 집계·학습 지원.
- **이해관계자 참여** — 무엇을·어떻게·무엇을 배웠는지 공유.

### 안전 관행
- **오프피크 시간 실행**, **서킷 브레이커(circuit breaker)**, **카나리 실험**(사용자 서브셋), **런북(runbook) 유지**.

### 메트릭
- **실험 메트릭**: 실험 수, 성공/실패율, 실험당 발견 이슈, 이슈 해결 시간.
- **회복력 메트릭**: **MTBF**(평균 고장 간격), **MTTR**(평균 복구 시간), 에러 버짓 소비, **SLO 준수**.

## 요약
- 프로세스: **정상 상태 → 가설 → 실험 → 관찰 → 개선**.
- 도구(Gremlin·Chaos Mesh·Litmus 등)로 인프라·앱·네트워크·상태 실험.
- 원칙: **작게 시작·명확한 메트릭·중단 계획·문서화·이해관계자 참여**. 안전: 오프피크·서킷 브레이커·카나리·런북. 메트릭: MTBF·MTTR·에러 버짓·SLO.
