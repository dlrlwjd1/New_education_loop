# Root Cause Analysis in SRE: Techniques and Implementation (SRE의 근본 원인 분석 기법과 구현)

> 강좌: Foundations of Site Reliability Engineering Training (Simplilearn) · 모듈 5: Alerting, Automation & RCA

## 개요
- RCA **기법**(5 Whys·피시본·결함 트리·타임라인)과 SRE에서의 **구현** 방법을 다룬다.

## 내용

### RCA 기법
| 기법 | 설명 |
|------|------|
| **5 Whys** | "왜?"를 반복해 증상에서 근본 원인으로 파고듦 (Toyota의 Sakichi Toyoda) |
| **피시본 다이어그램(Fishbone / Ishikawa / cause-effect)** | 문제를 물고기 머리로, 원인을 카테고리(사람·프로세스·기술·환경·관리)로 분류 |
| **결함 트리 분석(FTA, Fault Tree Analysis)** | 하향식(top-down) + Boolean 로직(AND/OR 게이트)으로 실패 경로 결합 |
| **타임라인 분석(Timeline)** | 사건을 시간순으로 검토 (시간대가 다르면 무관할 수 있음 → 관계 판단에 중요) |

### 5 Whys 예시
- 웹사이트 다운 → 왜? DB 서버 무응답(메모리 부족 크래시) → 왜? 쿼리가 과도한 자원 소비 → 왜? **인덱스 누락** → 왜? 스키마 변경 프로세스에 **성능 리뷰가 없었음** → **근본 원인**. 해결: 스키마 변경 프로세스에 성능 리뷰 도입.

### 피시본 예시
- 문제: 인증 서비스 실패. 카테고리별 원인 (사람·프로세스·기술 등) 분석 → **만료된 SSL 인증서(로테이션 누락)**가 근본 원인 (사일로·소통·경고 부재).

### 타임라인 예시
- 10:15 프로덕션 배포 → 10:22 첫 오류 로그 → 10:30 지연 스파이크 → 10:42 DB 연결 고갈 → 10:45 서비스 장애 시작. → 사건 순서로 인과 이해.

### 결함 트리 예시 (Boolean 게이트)
- 웹사이트 사용 불가 = 서버 실패(**AND**: 전원+냉각 실패→과열) OR 앱 크래시(**OR**: 미처리 예외/메모리 누수/서드파티 API 타임아웃) OR 네트워크 실패(**OR**: DNS 오설정/방화벽 차단/하드웨어).

### SRE에서 RCA 구현
1. **비난 없는 문화(blameless culture)** 확립.
2. **적절한 RCA 방법 선택**.
3. **발견 문서화·공유**.
4. **예방 조치(preventive measures) 구현**.

## 요약
- RCA 기법: **5 Whys**(반복 질문), **피시본**(카테고리 분류), **FTA**(AND/OR 게이트), **타임라인**(시간순).
- 예: 5 Whys로 "인덱스 누락 → 성능 리뷰 부재"라는 근본 원인 도출.
- 구현: **비난 없는 문화 → 방법 선택 → 문서화·공유 → 예방 조치**.
