# Building an AI-Native Engineering Team with Codex

## 개요
- 원문: [Building an AI-native engineering team](https://developers.openai.com/codex/guides/build-ai-native-engineering-team) (OpenAI Codex Guides)
- 핵심 주제: Codex 같은 AI 코딩 에이전트가 소프트웨어 개발 생명주기(SDLC, Software Development Life Cycle)의 7개 단계를 어떻게 바꾸는지 다룬다. 프런티어 모델은 이제 약 2시간 17분간 지속적으로 추론(sustained reasoning)하며 작업할 수 있어, 기획부터 배포·유지보수까지 전 단계에 의미 있게 기여한다.
- [[01-engineering-management-2026]]가 "조직·채용·역할 재정의"를 다룬다면, 이 글은 "실제 개발 단계별로 에이전트를 어떻게 붙이는가"를 다룬다.

## 내용

### AI 코딩 도구의 진화
단순 자동완성(autocomplete)에서 자율 에이전트로 발전했다.
- 파일 전체와 프로젝트 스캐폴드(scaffold) 생성
- 디버깅·리팩터링 같은 다단계 문제 추론
- 클라우드 기반 멀티 에이전트 환경에서 동작
- 코드·설정·텔레메트리(telemetry)를 동시에 읽음
- 구조화된 도구(컴파일러, 테스트 러너, 보안 스캐너) 실행
- 긴 컨텍스트 윈도로 프로젝트 기억(persistent memory) 유지

### SDLC 7단계별 변화
각 단계마다 **에이전트가 맡는 일**과 **엔지니어의 초점이 옮겨가는 곳**이 나뉜다.

#### 1. 기획(Planning)
- **에이전트**: 명세를 읽고 코드베이스와 교차 참조, 모호한 부분·의존성 식별, 난이도 추정과 작업 분해, 관련 서비스까지 코드 경로 추적
- **엔지니어**: 스코핑 회의 대신 핵심 기능 작업, 우선순위·방향 결정, 에이전트 결과의 정확성 검증
- **시작하기**: 이슈 중복 제거(deduplication), 설명 기반 하위 작업 자동 생성 같은 간단한 워크플로부터

#### 2. 설계(Design)
- **에이전트**: 보일러플레이트·프로젝트 구조 스캐폴딩, 디자인 토큰·스타일 가이드 구현, 목업(mockup)을 코드로 변환, 접근성 개선 제안, 여러 버전 빠르게 프로토타이핑
- **엔지니어**: 핵심 로직·아키텍처 패턴 다듬기, 품질·신뢰성 기준 확보, 사용자 흐름·대안 평가
- **시작하기**: 텍스트+이미지 멀티모달 에이전트 활용, MCP로 디자인 도구 연동, 타입 언어로 유효한 props 정의

#### 3. 빌드(Build)
- **에이전트**: 기능 전체 구현 초안, 여러 파일에 걸친 일관된 수정, 내부 컨벤션에 맞는 보일러플레이트 생성, 빌드 오류 자동 수정, 구현과 함께 테스트 작성, PR 메시지 포함 diff 생성
- **엔지니어**: 제품 동작·엣지 케이스 명확화, 아키텍처 영향 검토, 비즈니스 로직·성능 경로 다듬기, 에이전트 생성 코드용 가드레일(guardrail) 설계
- **시작하기**: 잘 정의된 작업부터, `PLAN.md` 등 계획 도구 사용, 명령 실행 성공 확인, `AGENTS.md` 반복 개선

#### 4. 테스트(Testing)
- **에이전트**: 요구사항 기반 테스트 케이스 제안, 엣지 케이스·실패 모드 식별, 코드 변화에 맞춰 테스트 갱신, 리팩터링 마찰 감소, 구현과 분리된 초기 테스트 생성
- **엔지니어**: 모델 생성 테스트의 품질 검토, 명세와 일치 여부 확인, 엣지 케이스에 적대적 사고(adversarial thinking) 적용
- **시작하기**: 테스트를 기능과 별도 단계로, 기능 구현 전 새 테스트가 실패하는지 확인, `AGENTS.md`에 커버리지 가이드라인 명시

#### 5. 코드 리뷰(Code Review)
- **에이전트**: 코드 실행으로 런타임 동작 해석, 파일·서비스 간 로직 추적, P0/P1급 버그 식별, 고신호(high-signal) 간결한 피드백, 일관된 기본 리뷰를 대규모로 제공
- **엔지니어**: 아키텍처 정합성 강조, 패턴·컨벤션 일관성 검증, 요구사항 충족 확인, 프로덕션 코드의 최종 책임
- **시작하기**: 고품질 PR을 평가셋(evaluation set)으로 큐레이션, 코드 리뷰에 특화 학습된 모델 선택, 품질 지표(PR 댓글 반응 등) 정의, 점진적 롤아웃

#### 6. 문서화(Documentation)
- **에이전트**: 코드베이스 분석으로 기능 요약, Mermaid 등으로 시스템 다이어그램 생성, 기능 빌드 중 문서 자동 갱신, 릴리스 변경 요약, 문서화를 배포의 기본 구성요소로
- **엔지니어**: 문서 구조·조직 결정, 결정의 "왜(why)" 추가, 에이전트용 표준·템플릿 설정, 고객 대면 핵심 문서 검토
- **시작하기**: 에이전트 생성 문서 실험, `AGENTS.md`에 가이드라인 반영, 릴리스 등 자동 생성 워크플로 식별

#### 7. 배포·유지보수(Deploy & Maintain)
- **에이전트**: 로그 파싱·이상 징후 표면화, 의심되는 코드 변경 식별, 핫픽스 제안, 로그·커밋·인프라 변경 상관관계 분석, 장애 분류(incident triage) 간소화
- **엔지니어**: AI 진단 검증, 정확성 확인·수정 승인, 회복력 있는(resilient) 해법 설계, 예방책 수립, 선제적 신뢰성 엔지니어링
- **시작하기**: MCP로 로깅·배포 시스템 연동, 적절한 접근 범위·권한 정의, 재사용 프롬프트 템플릿 구성, 모의 장애 시나리오로 테스트

### AI 네이티브 팀의 핵심 원칙
- **에이전트에 위임**: 기계적·다단계 반복 작업, 구현·테스트·리뷰의 초기 패스, 보일러플레이트 생성, 일상적 문서화·운영 분류
- **사람이 소유**: 전략적 아키텍처 결정, 새롭고 모호한 문제 해결, 최종 코드 리뷰와 프로덕션 책임, 장기 유지보수 트레이드오프, 품질 검증·감독
- **가장 크게 바뀌는 것**: 엔지니어가 라인 단위 구현 → 반복적 감독(iterative oversight)으로 이동, 개발 사이클 가속, 피드백 루프가 지속적 프로세스에 통합

## 예시

### AI 네이티브 팀 도입 체크리스트
- [ ] 라디컬한 전면 개편이 아니라, 잘 정의된 좁은 범위(bounded) 작업부터 시작하는가?
- [ ] `AGENTS.md` / `PLAN.md`로 에이전트에게 컨벤션·커버리지·계획을 명시하고 반복 개선하는가?
- [ ] 테스트를 기능 구현과 분리하고, 기능 전에 테스트가 실패하는지 검증하는가?
- [ ] 코드 리뷰는 고품질 PR 평가셋으로 시작해 신뢰가 쌓인 뒤 점진적으로 확대하는가?
- [ ] 문서화를 "완료"의 일부로 삼고, 릴리스 워크플로에서 자동 생성하는가?
- [ ] MCP로 디자인 도구·로깅·배포 시스템에 안전한 권한 범위로 연동했는가?

### 실제 사례
Cloudwalk, Sansan, Virgin Atlantic 등이 에이전트를 활용해 완전한 마이크로서비스를 수 분 내 배포하고, 경쟁 상태(race condition)·DB 문제를 잡아내며, 개발 도구 안에서 운영 컨텍스트를 통합하고, 배포·유지보수를 강화했다.

## 요약
- 프런티어 모델의 지속 추론 능력 향상으로, AI 에이전트가 기획·설계·빌드·테스트·리뷰·문서화·배포/유지보수 등 SDLC 전 단계에 기여한다.
- 각 단계에서 **기계적 초기 작업은 에이전트가**, **전략·아키텍처·최종 책임은 사람이** 맡는 분업 구조가 핵심이다.
- 엔지니어의 역할은 라인 단위 코딩에서 "반복적 감독(iterative oversight)"으로 이동한다.
- 전면 개편이 아니라 잘 정의된 작업부터 시작해 워크플로·가드레일을 점진적으로 축적하는 방식을 권장한다.
- `AGENTS.md`·`PLAN.md`·MCP 연동이 에이전트를 실무에 붙이는 실질적 지렛대다.
