# New Skills! v1.2 brings /wait-what, /writing-for-agents, and fixes /grill-me

## 개요
- 영상: [New Skills! v1.2 brings /wait-what, /writing-for-agents, and fixes /grill-me](https://www.youtube.com/watch?v=gaDdrDdczO4)
- 채널: Matt Pocock
- 업로드일: 2026-08-05
- 길이: 11:37
- 핵심 주제: Matt Pocock의 skills repo v1.2.0 업데이트. 공식 문서와 설치 경로를 정비하고, 에이전트의 난해한 답변을 다시 설명하게 하는 `/wait-what`, 질문 의존성을 고려해 여러 질문을 묶는 `/grill-me`, 에이전트용 문서를 다듬는 `/writing-for-agents`, 사람이 직접 해야 하는 설정을 안내하는 `/wizard`, 이해관계자와 결정을 공유하는 `/to-questionnaire`를 추가·개선했다.

## 내용

### 1. Skills를 위한 공식 문서 사이트
skills repo가 성숙하면서 각 스킬의 역할과 전체 흐름을 설명하는 문서가 `aihero.dev/skills`에 마련되었다. 메인 페이지에서는 다음 개발 흐름을 한눈에 볼 수 있다.

```text
/grill-with-docs
  -> /to-spec
  -> /to-tickets
  -> /implement
  -> code review
```

왼쪽 패널에서는 모든 스킬의 레퍼런스와 용도를 확인할 수 있다. 자주 묻는 질문은 Matt가 실제 질문을 모아 둔 개인 위키를 바탕으로 작성했으며, `ticket` 같은 용어는 별도의 AI 코딩 사전 정의로 연결된다. 따라서 이 사이트는 스킬 사용법뿐 아니라 Matt가 사용하는 AI 코딩 개념과 용어를 익히는 자료이기도 하다.

### 2. Claude Code와 Codex의 설치·호환성 개선
skills가 Claude Code 공식 플러그인 마켓플레이스에 포함되었다. Claude Code에서 플러그인 검색을 통해 바로 설치할 수 있고, 읽기 전용 번들(read-only bundle)로 제공되어 이후 업데이트도 자동으로 내려받는다.

Codex 사용자를 위해서는 모든 스킬에 `openai.yaml` 사이드카 파일이 추가되었다. 이전에는 Claude Code 등 일부 하니스(harness)에서만 사용자 호출 스킬(user-invoked skill)을 에이전트의 컨텍스트에서 숨겼다가 직접 호출할 수 있었다. 이제 `allow_implicit_invocation: false` 설정이 Codex에도 전달되어, 명시적으로 호출해야 하는 스킬이 Codex UI에서도 의도대로 동작한다.

### 3. `/wait-what` — 이해하기 어려운 답변을 다시 설명시키기
Matt는 최신 Opus가 지나치게 장황하고 낯선 LLM 표현을 사용해 답변을 이해하기 어려운 경우가 많았다고 말한다. 출력 스타일이나 `AGENTS.md` 설정만으로는 충분히 해결되지 않아, 방금 한 말을 더 명확하게 다시 설명하게 하는 `/wait-what`을 만들었다.

이 스킬은 두 가지 방법으로 답변을 개선한다.

- **ASD-STE100 Simplified Technical English**를 기준으로 간단하고 선언적인 문장을 사용하게 한다.
- `/grill-with-docs` 과정에서 만든 `context.md`의 **공통 언어(ubiquitous language)**를 사용하게 한다.

단순히 쉬운 단어를 쓰라고 지시하는 것보다 프로젝트와 사용자가 이미 합의한 언어로 설명하게 하는 것이 핵심이다. 에이전트가 무슨 뜻인지 알 수 없는 답변을 했을 때 “Wait, what?”이라고 호출하면 같은 내용을 더 읽기 쉬운 표현으로 다시 받을 수 있다.

### 4. `/grill-me` — 질문을 의존성 그래프와 라운드로 처리
기존 `/grill-me`는 매 턴 질문을 하나만 했다. 어려운 결정을 모두 끝낸 뒤에도 쉬운 확인 질문에 한 번씩 답해야 해서 세션 후반이 매우 느려지는 문제가 있었다. 반대로 여러 질문을 무조건 한꺼번에 던지면, 앞 질문의 답에 따라 뒤 질문이 달라지는 의존성을 처리할 수 없다.

v1.2에서는 질문을 **의존성 그래프(dependency graph)**로 보고, 지금 답할 수 있는 질문만 라운드(round) 단위로 묶는다.

1. 먼저 다른 질문을 여는 핵심 질문을 묻는다. 이 단계에는 질문이 하나뿐일 수도 있다.
2. 답변으로 새롭게 결정 가능한 질문들을 다음 라운드에 모은다.
3. 현재 질문 프런티어(frontier)를 따라 가능한 한 빠르게 다음 결정을 연다.

각 질문에는 추천 답변이 함께 표시된다. 사용자는 “Q1 동의, Q2 동의, Q3은 변경 필요”처럼 음성 입력(dictation)으로도 여러 항목에 빠르게 답할 수 있다. 즉, 질문의 논리적 순서는 보존하면서 독립적인 쉬운 질문은 한 번에 처리한다.

### 5. `/writing-for-agents` — 에이전트가 읽는 모든 문서를 개선
기존 `writing-great-skills`가 실제로는 스킬뿐 아니라 에이전트가 읽는 여러 문서를 다듬는 데 사용되고 있었기 때문에 범위를 넓혀 `/writing-for-agents`로 바뀌었다.

이 스킬은 다음 문서를 더 간결하게 만들고, 에이전트의 출력과 동작을 예측하기 쉽게 만드는 데 사용한다.

- `AGENTS.md`, `CLAUDE.md` 같은 에이전트 설정 문서
- 새로 만들거나 수정하는 skill 문서
- 에이전트가 작업 지침으로 읽는 기타 문서

또한 너무 많은 지침을 `AGENTS.md`에 처음부터 넣어 컨텍스트를 차지하는 **프런트로딩(frontloading)** 문제를 줄이기 위해, 필요한 내용을 별도 스킬로 분리하는 데도 사용할 수 있다. 이 스킬은 모델 호출 가능(model-invocable)하므로 에이전트가 관련 문서를 수정할 때 자동으로 선택할 수 있다.

### 6. `/wizard` — 사람의 설정 작업을 대화형 스크립트로 안내
클라우드 인프라나 AWS 서비스를 프로비저닝할 때는 로그인, 웹 콘솔 설정, API 키 입력처럼 사람만 수행해야 하거나 사람이 통제해야 하는 단계가 있다. `/wizard`는 이런 과정을 안내하는 **대화형 Bash 마법사(interactive Bash wizard)**를 생성한다.

마법사는 필요한 페이지를 열고, 로그인과 설정 변경을 단계별로 안내하고, 사용자가 API 키를 입력하면 필요한 파일이나 GitHub Secrets에 저장하며, 완료할 때까지 진행 상태를 보여 준다. 생성된 마법사는 결정론적 스크립트(deterministic script)로 실행되므로, 사용자가 입력한 비밀 값이 실행 중 다시 에이전트나 외부 모델로 전송되지 않는다.

Matt는 컴퓨터 사용(computer use)으로 에이전트가 모든 설정을 대신하게 하기보다 자신이 통제권을 유지하면서도 번거로운 절차를 쉽게 진행하기 위해 이 방식을 택했다. `/wizard`의 목적은 자동화할 수 없는 사람의 단계를 없애는 것이 아니라, 정확한 순서와 화면으로 안내해 실수를 줄이는 것이다.

### 7. `/to-questionnaire` — 에이전트 밖의 이해관계자와 결정하기
`/to-questionnaire`는 grilling session에서 내려야 할 결정을 Markdown 설문 문서로 추출한다. 이 문서를 Google Docs 등으로 옮겨 동료나 이해관계자와 함께 답한 뒤, 결과를 다시 에이전트 대화에 가져올 수 있다.

Matt는 뒷마당 사무실을 설계하는 Wayfinder 세션에서 자신이 아니라 공간을 함께 사용할 아내와 논의해야 하는 질문이 있다는 것을 발견했다. 그래서 질문들을 문서로 만들어 함께 검토하고, 답변을 다시 에이전트에 입력했다.

장기적으로는 팀 대화에 에이전트가 직접 참여하는 Slack·Microsoft Teams 방식이 더 자연스러울 수 있다. 하지만 아직 AI 네이티브 협업 환경이 없는 팀에서는 누구나 열고 댓글을 달 수 있는 설문 문서가 실용적인 연결 수단이 된다.

### 8. 나머지 변경 사항과 릴리스 방향
영상에서 다루기에는 작은 수정 사항들은 GitHub의 v1.2.0 전체 변경 로그에서 확인할 수 있다. Matt는 AI 코딩 방식이 이전보다 안정화되고 있다고 보고, 계속 바뀌는 짧은 코호트형 강의 대신 연중 학습할 수 있는 자기 주도형(self-paced) AI 코딩 기초 강좌도 준비하고 있다고 설명한다.

## 예시

### 상황별 스킬 선택
| 상황 | 사용할 스킬 | 기대 결과 |
| --- | --- | --- |
| 에이전트 답변이 장황하고 무슨 뜻인지 알기 어려움 | `/wait-what` | 프로젝트의 공통 언어와 단순한 문장으로 재설명 |
| 요구사항 질문이 많고 질문 사이에 의존성이 있음 | `/grill-me` | 답할 수 있는 질문만 라운드별로 묶어 빠르게 결정 |
| `AGENTS.md`가 길거나 스킬 지침이 모호함 | `/writing-for-agents` | 지침을 간결하게 다듬고 필요한 내용을 스킬로 분리 |
| AWS 설정처럼 사람이 직접 로그인·키 입력을 해야 함 | `/wizard` | 사람이 통제하는 단계별 대화형 Bash 안내 생성 |
| 에이전트를 쓰지 않는 이해관계자와 결정을 내려야 함 | `/to-questionnaire` | 공유·댓글 가능한 설문 문서로 질문을 추출 |

### `/grill-me` 질문 처리 방식
```text
Q1: 핵심 결정
  ├─ 답변 후 Q2, Q3이 열림
  └─ 답변 후 Q4가 열림

Round 1: Q1
Round 2: Q2 + Q3 + Q4
Round 3: 앞선 답변으로 새롭게 열린 질문들
```

### 사람의 통제권을 유지하는 `/wizard` 흐름
```text
에이전트가 대화형 Bash 마법사 생성
  -> 사용자가 스크립트 실행
  -> 정확한 웹 페이지 열기와 로그인 안내
  -> 사용자가 직접 설정 변경·비밀 값 입력
  -> 스크립트가 로컬 파일 또는 GitHub Secrets에 저장
  -> 설정 완료 확인
```

## 요약
- v1.2.0은 `aihero.dev/skills` 문서, Claude Code 공식 마켓플레이스 설치, Codex용 `openai.yaml`을 추가해 스킬을 찾고 설치하고 호출하는 경험을 개선했다.
- `/wait-what`은 Simplified Technical English와 프로젝트의 공통 언어를 사용해 난해한 에이전트 답변을 다시 설명한다.
- `/grill-me`는 질문을 의존성 그래프로 관리하고, 현재 답할 수 있는 질문을 라운드별로 묶어 논리적 순서와 속도를 함께 확보한다.
- `/writing-for-agents`는 스킬뿐 아니라 `AGENTS.md`, `CLAUDE.md` 등 에이전트가 읽는 문서를 간결하고 예측 가능하게 다듬는다.
- `/wizard`는 사람이 직접 해야 하는 인프라 설정을 결정론적 대화형 Bash 스크립트로 안내해 통제권과 편의성을 함께 제공한다.
- `/to-questionnaire`는 에이전트 세션의 결정 질문을 공유 문서로 옮겨, AI 도구를 사용하지 않는 이해관계자도 논의에 참여하게 한다.
