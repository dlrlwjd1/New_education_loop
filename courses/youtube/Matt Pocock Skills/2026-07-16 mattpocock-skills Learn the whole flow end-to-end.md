# mattpocock/skills: Learn the whole flow, end-to-end

## 개요
- 업로드일: 2026-07-16
- 원본: https://www.youtube.com/watch?v=M6mYodf0dJM
- 채널: Matt Pocock
- 핵심 주제: `mattpocock/skills` 저장소를 처음 설치·설정하고, 아이디어에서 배포까지(idea to ship) 이어지는 **메인 플로우(main flow)**를 실제 저장소에서 시연한 튜토리얼
- 배경: 저장소가 스타 162,000개, 다운로드 750만 회에 이르렀지만 정식 튜토리얼이 없었기에, "어떤 순서로 스킬을 쓰는가"라는 반복 질문에 답하기 위해 제작. 고급·신규 기능은 제외하고 **시작에 필요한 기본 흐름**만 다룬다.

## 내용
### 설치: `npx skills@latest add`
- 명령: `npx skills@latest add mattpocock/skills`
  - Node.js가 설치돼 있어야 하며, Vercel의 `skills.sh` CLI 설치기를 실행한다.
  - 신규 프로젝트(greenfield)든 기존 저장소(brownfield)든 방식은 동일하다. 새 프로젝트라면 빈 디렉터리에서 같은 명령을 실행하면 된다.
- 설치 시 38개 스킬 목록이 두 그룹으로 나온다.
  - **mattpocock skills**: 공개해도 좋다고 저자가 "승인(blessed)"한 스킬.
  - **other skills**: 실험 중이며 향후 삭제될 수 있는 스킬.
  - 저자는 공식 스킬 전체 선택을 권장(스페이스로 선택, 리턴으로 확정). *Vercel CLI가 다소 불편해 향후 자체 CLI로 교체 가능성 언급.*
- **에이전트 선택**: 어떤 에이전트에서든 쓰도록 설정된다. Cursor, Codex 등 범용(universal) 대상은 기본 지원되고, Claude Code처럼 Claude 스킬을 쓰는 경우는 직접 선택해 설정한다.
- **설치 범위(scope)**:
  - 팀 작업이면 **project(프로젝트)** 스코프 권장 — 모든 사람이 같은 스킬셋을 쓰고 함께 기여·결정할 수 있다.
  - 솔로 개발이면 **global(홈 디렉터리)**도 무방.
- **설치 방식**: `symlink` 권장. `.agents` 폴더와 `.claude` 폴더로 복사하는 방식보다 심링크가 간단하다. 고민 없이 symlink 선택.

### 스킬은 대부분 "사용자 호출형"이라 컨텍스트 부담이 작다
- 설치 후 Claude Code에서 `/`(슬래시)로 사용 가능한 스킬 목록이 보인다(grill-me, wayfinder, grill-with-docs 등).
- 다른 스킬 저장소와의 차이: 이 스킬들은 **대부분 사용자 호출형(user-invoked)**이다. 설명(description)이 짧고 정확해서 자동으로 컨텍스트에 끼어들지 않는다.
- 결과적으로 전체 스킬을 설치해도 컨텍스트에서 차지하는 양은 **약 660 토큰**에 불과 — 컨텍스트 부하가 매우 가볍다.

### 저장소 설정: `setup mattpocock skills`
스킬은 저장소 내부의 몇 가지 설정에 의존하며, 설정 시 다음을 묻는다.
- **이슈 트래커(issue tracker)**: 스펙과 티켓을 저장할 곳. GitHub, 로컬 마크다운, 그 외 무엇이든 선택 가능.
  - Jira, Linear, Beads 등과의 연동은 **이미 지원된다**. "How do I make it work with Jira?"류 질문이 많은데, `setup mattpocock` 실행 후 "Jira로 설정해줘"라고 말하면 에이전트가 로컬 설정을 보고 알아서 구성한다.
  - 영상에서는 **로컬 마크다운(local markdown)**으로 설정.
- **트리아지 라벨(triage labels)**: 티켓 정보를 전달하는 데 쓰이는 라벨. 크게 중요치 않아 기본값 수용(자세한 내용은 triage 스킬 문서 참고).
- **도메인 문서(domain documentation)**: 저장소에 `context.md`와 ADR을 둔다.
  - **single context**: 대부분(99%)의 경우 권장.
  - **multi-context**: 큰 모노레포에서 여러 bounded context가 필요할 때만.
- 설정 결과: `claude.md`에 이슈 트래커·트리아지 라벨·도메인 문서로 향하는 링크가 추가되고(`docs/agents/domain`, issue tracker 등), 이슈·스펙은 scratch 디렉터리에 저장된다.

### 시작 전 길잡이: `ask-matt` 스킬
- `ask-matt`는 **저자 본인을 스킬로 만든 것**으로, 스킬 저장소에 대해 무엇을 먼저 해야 하는지 안다.
- "어떻게 시작하고, 메인 플로우는 무엇인가?"라고 물으면 다음을 안내한다.
  - 메인 플로우 = **idea to ship**. 코드베이스가 있으면 플로우 맨 위에서 시작해 **하나의 끊기지 않는 컨텍스트 창(one unbroken context window)** 안에서 아래로 내려간다.
  - `grill-with-docs`로 시작 — 아이디어를 다듬는 인터뷰를 하고, 저장소 안에서 상태를 가지므로(stateful) 배운 것을 `context.md`와 ADR에 기록한다. "X를 바꾸고 싶다"를 명확한 계획으로 바꾸는 단계.
  - 대화만으로 모든 질문을 해결할 수 있는가? 실행 가능한 답이 필요하면 `prototype` 스킬 사용(별도 영상 존재), `handoff`로 오갈 수 있다. 아니면 건너뛴다.
- 저자 강조: **자신이 쓰는 컨텍스트 창과 토큰을 의식하는 것이 AI를 잘 쓰는 핵심.**

### 메인 플로우 시연: 인터뷰 → (스펙 → 티켓) → 구현 → 리뷰
시연 대상은 `AI Hero CLI` 저장소. 아이디어: "내부 도구 명령들을 대부분 제거해 공개용만 남기고 싶다."

1. **`grill-with-docs`(인터뷰)**
   - 아이디어는 매우 모호해도 된다. 스킬이 후속 질문으로 무거운 작업(heavy lifting)을 대신한다.
   - 저장소 전체 지도를 만들고 코드를 탐색하며 질문한다(예: 11개 서브커맨드를 가진 internal 네임스페이스 확인).
   - 사용자와 에이전트가 **공유된 이해(shared understanding)**에 도달할 때까지 질문에 답한다. 영상에서는 6개 질문으로 끝났으나, 보통 규모에 따라 20개 정도. → 명령 파일 10개 삭제, 테스트 3개 삭제, 공유 모듈 재배선이라는 계획 도출.
   - *plan mode가 아니라 Claude Code의 auto mode에서 진행.*

2. **갈림길(fork in the road)**
   - 작업이 **한 세션 안에 끝날 정도로 작으면** → 바로 `/implement this`.
   - 여러 세션이 필요할 만큼 크면 → `to-spec` → `to-tickets`로 나눈다.
   - 판단 기준: 저자는 컨텍스트 창이 **약 140k 토큰**을 넘으면 "스마트 존(smart zone)"을 벗어나 주의력이 떨어지고(attention degradation) 환각·품질 저하가 생긴다고 본다. 이 예시는 "100k 예산으로 명령 10개 제거"이므로 충분히 한 세션짜리 → 원래라면 그냥 `implement`.

3. **`to-spec`(스펙 작성)** — *시연을 위해 멀티 세션인 척 진행*
   - 지금까지의 논의(약 46.1k 토큰)를 하나의 문서로 **압축**한다.
   - 이슈 트래커(여기서는 로컬 마크다운)에 스펙이 저장된다.
   - 스펙 = **최종 목적지의 모습**. 문제 정의, 솔루션, 유저 스토리, 구현/테스트 결정 등을 포함. 마지막에 구현 결과와 대조하는 기준이 된다.

4. **`to-tickets`(티켓 분할)**
   - 스펙을 구현 계획으로 바꾼다. **각 티켓 = 컨텍스트 창(스마트 존) 하나 분량의 작업(slice)**.
   - 예시에서는 3개 티켓을 제안했으나, 저자가 "한 slice로 충분"이라 판단해 1개로 조정 → `tickets.md`에 저장.
   - 실제 사례: 며칠 전 구현한 스펙은 하위 티켓 11개(11개 세션). 각 티켓은 짧고, 수용 기준(acceptance criteria) 대부분은 상위 스펙에 있어 티켓엔 "이번 세션에서 무엇을 만드는가"만 담긴다. 큰 작업을 다룰 수 있는 조각으로 쪼개는 방식.

5. **구현(`implement`)**
   - 컨텍스트를 비우고(clear), `implement this @tickets` 형태로 실행. 스펙(어디로 갈지) + 티켓(어떻게 갈지)이 있으므로 에이전트가 필요한 정보를 모두 갖춘다.
   - **티켓을 하나씩** 구현한다. "모든 티켓을 한 번에 해줘"가 아니라, 하나 구현 후 스마트 존에 닿았는지 확인 → 여유 있으면 하나 더, **보통은 티켓마다 컨텍스트를 clear**.
   - `implement` 스크립트가 타입 체크·빌드 등 검증을 실행하고, 이어서 code review 스킬을 자동 로드한다.

6. **코드 리뷰(2축 검증)** — `implement`의 일부로 자동 수행
   - **축 1: 스펙 대조** — 원래 스펙의 모든 수용 기준을 구현 결과와 교차 확인. 큰 작업에서 에이전트가 놓쳤거나 티켓이 불명확했던 부분을 최종 패스로 잡는다.
   - **축 2: 표준 문서 대조** — 저장소의 코딩 표준과 비교. 표준 문서가 없으면 Martin Fowler 류의 고전적 기준(code smells 등)을 사용.
   - **서브에이전트로 리뷰하는 이유**: 메인 에이전트는 자기가 방금 쓴 코드라 "괜찮다"고 여기기 쉽다(에이전트는 자기 코드 수정·개선에 약함). 깨끗한 컨텍스트의 별도 에이전트가 훨씬 잘 리뷰한다.
   - 두 리뷰 통과 후 현재 브랜치에 커밋 → 플로우 완료.

## 예시
### 전체 워크플로 요약
```
npx skills@latest add mattpocock/skills   # 설치 (agent, scope, symlink 선택)
setup mattpocock skills                    # 이슈 트래커 / 트리아지 라벨 / 도메인 문서 설정
ask-matt "how do I get started?"           # 메인 플로우 안내 (선택)

grill-with-docs  <아이디어>                 # 인터뷰 → 공유된 이해 → 계획 (context.md, ADR)
   ├─ 한 세션이면 → /implement this
   └─ 여러 세션이면 → to-spec → to-tickets
to-spec                                    # 논의 압축 → 스펙(목적지) 저장
to-tickets                                 # 스펙 → 티켓(각 티켓 = 컨텍스트 창 1개)
/clear → implement this @tickets           # 티켓 하나씩 구현 (티켓마다 clear 권장)
   └─ implement가 타입체크·빌드·code review 자동 실행 (스펙 대조 + 표준 대조, 서브에이전트)
commit                                     # 통과 시 현재 브랜치에 커밋
```

### 컨텍스트 창을 의식하는 판단 기준
- "스마트 존"은 **약 140k 토큰**까지. 이를 넘으면 주의력 저하·환각이 늘어난다.
- 티켓 하나 = 스마트 존 하나 분량으로 설계 → 큰 작업을 세션 단위로 안전하게 분할.
- 작업이 한 세션에 들어가면 스펙·티켓 단계를 건너뛰고 바로 구현하는 것이 효율적이다.

## 요약
- 설치는 `npx skills@latest add mattpocock/skills`, 이후 `setup mattpocock skills`로 이슈 트래커·라벨·도메인 문서를 구성한다. 팀은 project 스코프, 솔로는 global, 방식은 symlink 권장.
- 스킬 대부분이 **사용자 호출형**이라 전체 설치해도 컨텍스트는 약 660 토큰으로 가볍다.
- 메인 플로우 = **grill-with-docs(인터뷰) → (to-spec → to-tickets) → implement → code review → commit**, 이상적으로는 하나의 끊기지 않는 컨텍스트 창 안에서 진행.
- **스펙 = 목적지, 티켓 = 경로**. 각 티켓은 컨텍스트 창 하나 분량으로, 큰 작업을 세션 단위 조각으로 쪼갠다.
- 작업이 작으면 스펙·티켓을 건너뛰고 바로 `implement`. 컨텍스트는 티켓마다 clear해 "스마트 존(약 140k 토큰)"을 유지한다.
- `implement`가 자동 실행하는 code review는 **스펙 대조 + 표준 대조** 2축이며, 자기 코드에 관대한 메인 에이전트 대신 **서브에이전트**가 수행한다.
- 이슈 트래커는 Jira·Linear·Beads·로컬 마크다운 등 무엇이든 "말로 설정"할 수 있고, `ask-matt`으로 시작 흐름을 물어볼 수 있다.
