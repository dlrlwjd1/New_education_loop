# OpenAI Tibo 인터뷰 - 개인 에이전트와 초고속 추론의 제품 변화

- **업로드일:** 2026-08-27
- **채널:** Tech Bridge
- **발표자·출처:** Tibo / OpenAI 제품·인프라 인터뷰
- **원본:** [YouTube](https://www.youtube.com/watch?v=YRqpmwIDOX0)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 44:24, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 모델의 속도와 도구 사용 능력이 높아질수록 제품은 개인의 의도·주의에 맞추고 인프라 병목을 줄여야 한다.

## 내용

### 연구를 사용자에게 전달하는 문화 (00:40~07:25)

Tibo는 DeepMind의 내부 대화 제품 경험과 OpenAI의 출시 문화를 비교한다. 상향식 아이디어와 빠른 사용자 피드백을 장려하되 기능이 뒤섞이지 않도록 단순성·성능·일관성을 함께 지킨다고 설명한다. 벤치마크만으로 새 모델의 활용법을 모두 알 수 없으므로 직접 사용하며 제품의 방향을 발견해야 한다.

### 개인 파트너와 업무 자동화의 구분 (07:25~14:30)

스킬·메모리·하위 에이전트를 사용자가 일일이 관리하는 부담을 줄이고 목표와 팀의 맥락을 이해하는 파트너를 지향한다. 동시에 로그 분석·성능 개선·회귀 수정처럼 직접 대화할 필요가 적은 자동화 시스템도 별도 유형으로 구분한다. 두 유형은 필요한 인터페이스와 사람의 개입 방식이 다르다.

강한 모델의 작업량은 사람을 기준으로 설계한 노트북의 자원을 넘어설 수 있다. 추론이 빨라지면 네트워크·도구 호출·컴파일 시간이 병목이 되므로 실행 환경과 동시 작업도 개선해야 한다.

### 통합 인터페이스와 사람의 주의 (14:30~26:40)

ChatGPT와 Codex를 개인화된 공통 에이전트로 연결하려는 방향을 설명한다. 개발자·비개발자라는 고정 분류보다 개인의 작업에 맞춰 화면과 도구를 조정하려는 구상이다. 음성·시각·공유 작업 공간처럼 자연스러운 상호작용도 논의한다.

사용 한도 초기화는 초기 제품의 장애와 불편을 보상하려고 시작했다고 설명한다. 이는 당시 운영 경험이며 지속적인 보상 정책을 약속하는 내용은 아니다.

### 모델로 인프라를 개선하는 순환 (26:40~34:16)

선행 컴퓨팅 투자와 모델을 활용한 추론 스택·커널·제품 개선이 처리량과 비용 효율을 높였다고 말한다. 재귀적 자기 개선을 새 모델 연구뿐 아니라 모델을 사용하는 인프라를 개선하는 넓은 의미로 설명한다. 학습의 최전선에서 안전성 점검을 위해 멈추고 시스템을 강화하는 판단도 논의하지만 내부 세부 기준은 공개하지 않는다.

### 초고속 추론이 바꾸는 작업 방식 (34:16~44:24)

장애 대응처럼 시간이 중요한 작업, 빠른 프로토타입, 실시간 창작에서 속도의 가치가 크다. 코드 생성 비중이 크면 효과가 크지만 외부 도구 호출이 많으면 전체 작업의 가속은 추론 배수보다 작다. 여러 작업을 자주 전환하는 사람과 한 작업에 몰입하려는 사람에게도 체감 가치가 다르다.

앞으로 효율 향상으로 더 많은 사람이 강한 모델에 접근할 수 있다는 전망으로 마무리한다. 제품 통합의 도착점과 미래 속도·가격은 인터뷰 시점의 계획과 예측으로 읽어야 한다.

## 예시

| 상황 | 속도 향상의 의미 |
|---|---|
| 많은 코드를 한 번에 생성 | 추론 속도 향상을 크게 체감 |
| 네트워크·도구 호출이 대부분 | 다른 병목 때문에 전체 가속은 제한 |
| 장애 대응 | 몇 초의 단축도 높은 가치 |
| 공동 화면에서 시안 수정 | 기다림을 줄여 창작의 흐름 유지 |

## 요약

- 모델 성능은 직접 사용하고 사용자 피드백을 받아 제품으로 연결한다.
- 개인 파트너와 백그라운드 자동화는 서로 다른 경험을 요구한다.
- 추론 속도뿐 아니라 도구 지연·실행 자원·사람의 주의를 함께 최적화한다.
