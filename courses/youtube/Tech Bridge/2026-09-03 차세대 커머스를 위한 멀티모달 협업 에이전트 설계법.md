# [한영자막] 차세대 커머스를 위한 멀티모달 협업 에이전트 설계법

- 핵심 메시지: 좋은 커머스 에이전트는 검색창을 대화형으로 감싼 도구가 아니다. 사용자의 모호한 의도를 작업 상태로 구조화하고, 정보 획득량이 큰 질문을 골라 선호를 발견한 뒤, 의도에 맞는 형식으로 답하는 전체 루프를 설계·평가해야 한다.

## 내용

### 검색어가 아니라 모호한 의도에서 시작한다
기존 검색형 에이전트는 사용자가 이미 무엇을 원하는지 알고 적절한 키워드까지 가지고 있다고 가정한다. 하지만 실제 쇼핑 사용자는 종종 정확한 상품명 대신 “이런 분위기가 좋다”는 감각이나 참고 이미지만 가지고 온다. 발표자는 이를 **표현 격차(articulation gap)**라고 설명한다.

에이전트는 사용자를 대신해 모든 결정을 내려서는 안 되지만, 다음 행동을 능동적으로 수행해야 한다.

- 현재까지 표현된 요구와 맥락을 이해한다.
- 아직 드러나지 않은 선호를 적절한 방식으로 질문한다.
- 가능한 선택지와 트레이드오프를 조사한다.
- 사용자가 결정을 내리기 쉬운 형태로 결과를 제시한다.

이 프레임워크는 커머스를 예로 들지만 금융, 교육 등 모호한 목표를 구체화해야 하는 다른 소비자 서비스에도 적용할 수 있다.

### 세 단계 루프 — 발견, 조사, 응답
발표자가 제시한 협업 루프는 세 단계로 구성된다.

| 단계 | 에이전트의 역할 | 핵심 질문 |
| --- | --- | --- |
| 발견(Discovery) | 모든 맥락을 작업 상태로 만들고 의도 격차를 찾는다. | 무엇을 알고 있으며, 다음에 무엇을 물어야 하는가? |
| 조사(Research) | 선호를 끌어낼 형식을 고르고 상품·정보를 비교한다. | 텍스트, 이미지, 비교 중 어떤 방식이 가장 효과적인가? |
| 응답(Response) | 목적에 맞는 정보와 표현 형식을 선택한다. | 목록, 표, 요약, 무드보드 중 무엇이 결정을 돕는가? |

한 번 응답하고 끝나는 선형 흐름이 아니라, 사용자 반응으로 작업 상태의 신뢰도를 갱신하며 목표에 가까워지는 반복 루프다.

### 발견 — 멀티모달 맥락을 작업 상태로 바꾼다
에이전트는 현재 질의뿐 아니라 다음 신호를 함께 읽어 **작업 상태(working state)**를 만든다.

- 현재 세션과 과거 대화
- 사용자 개인 맥락
- 참고 이미지와 링크
- 명시된 예산·크기 같은 확정 조건(hard constraints)
- 이미지나 반응에서 추론한 스타일 같은 유연한 선호(soft constraints)
- 재고처럼 실시간으로 다시 확인해야 하는 변수

예를 들어 거실을 꾸미려는 사용자가 예산과 참고 사진을 제공했다면, 에이전트는 예산을 확정 조건으로 보존하고 이미지에서 스타일 단서를 추출한다. 추론된 선호에는 신뢰도 점수를 붙이며, 재고처럼 오래되면 쓸모없는 정보는 실시간으로 갱신한다.

작업 상태는 다음 기준으로 평가한다.

- 원래 맥락의 사실을 빠뜨리지 않았는가?
- 추론한 선호의 신뢰도가 실제 정확성과 잘 보정(calibration)되어 있는가?
- 입력 조건 하나를 바꾸면 관련 상태만 바뀌는가? 즉, 반사실적 민감도(counterfactual sensitivity)가 적절한가?

### 의도 격차 — 가장 가치 있는 질문 하나를 고른다
모르는 항목을 모두 한꺼번에 질문하면 사용자가 지친다. 에이전트는 여러 미확정 변수 중 결과를 가장 크게 바꿀 질문, 즉 **정보 획득량(information gain)**이 가장 큰 질문 하나를 우선해야 한다.

거실 가구 예시에서는 방의 너비와 스타일 선호가 모두 불명확할 수 있다. 이때 방에 들어가지 않는 상품은 다른 조건과 무관하게 탈락하므로, 먼저 너비를 묻는 것이 대화의 방향을 가장 크게 좁힌다.

이 협업 전략은 다음 항목으로 평가할 수 있다.

- 결과를 내기 전에 해결해야 할 차단 조건을 찾았는가?
- 불필요하게 많은 질문을 하지 않았는가?
- 선택한 질문이 실제로 다음 결정을 개선하는가?
- 같은 정보에 여러 차례 질문하지 않는가?

### 조사 — 질문의 내용뿐 아니라 형식을 고른다
객관적인 수치라면 텍스트 질문이 효율적이다. 반면 사용자가 스타일을 말로 설명하지 못한다면 텍스트 질문을 반복하는 대신 시각적 선호 보드(visual preference board)를 보여주는 편이 낫다.

에이전트는 사용자 조건을 상품 카탈로그의 온톨로지(ontology)와 임시로 연결하고, 참고 이미지와 가까운 스타일 후보를 골라 공통 언어를 만든다. 사용자의 클릭이나 호버 같은 미세 반응도 신호로 활용해 선호에 대한 신뢰도를 갱신한다.

이 단계에서는 사용자 시뮬레이터에 숨겨진 선호를 넣어 다음을 측정할 수 있다.

- 숨은 선호를 얼마나 정확히 발견했는가?
- 몇 번의 대화 턴이 필요했는가?
- 질문에 적합한 표현 형식을 선택했는가?

### 응답 — 표현 형식도 모델 지능의 일부다
정답의 내용이 같아도 표현 방식에 따라 사용자가 결정을 내리는 속도가 달라진다.

- 정책이나 리뷰의 핵심을 찾는 요청에는 요약이나 글머리표가 적합하다.
- 두 제품의 장단점을 따지는 요청에는 비교표가 적합하다.
- 공간 스타일과 영감을 찾는 요청에는 이미지와 상품을 함께 배치한 시각 보드가 적합하다.

핵심 정보가 긴 텍스트 안에 묻히면 좋은 응답이 아니다. 발표자는 형식 정확성(format accuracy), 데이터 충실도(data fidelity), 다음 행동으로 이어지는 실행 가능성(user actionability)을 함께 평가해야 한다고 말한다.

### 자동 평가기는 루프와 함께 진화해야 한다
모델의 마지막 답변만 채점해서는 어느 단계에서 문제가 생겼는지 알 수 없다. 작업 상태, 질문 선택, 선호 발견, 응답 형식 등 루프의 각 단계에 자동 평가기(auto-rater)를 둬야 한다.

초기 평가기는 단순할 수 있지만 제품과 사용자 행동이 변하면 평가 기준도 함께 성장해야 한다. 특히 사실 보존, 신뢰도 보정, 반사실적 테스트처럼 결과를 정량적으로 점검할 장치를 마련해야 한다.

### Q&A — 판매자 온톨로지와 에이전트 간 상호작용
판매자 측 도메인 지식은 사용자의 자연어 제약을 상품 메타데이터에 연결하는 데 중요하다. 발표자는 판매자와의 협업 및 UCP 같은 공통 인터페이스가 이 연결에 도움을 준다고 설명한다. 다만 사용자에게 어떤 형식으로 결과를 보여줄지는 여러 판매자에 걸쳐 일관된 경험을 제공하기 위해 에이전트가 결정한다.

다른 에이전트가 구매자를 대신하는 시나리오는 아직 초기 단계다. 에이전트 간 인터페이스로 MCP를 예상할 수 있지만, 사용자 연구에서는 영감과 탐색이 필요한 상단 퍼널(upper funnel)에서는 사람이 직접 참여하기를 원했다. 가격 비교나 협상 같은 하단 퍼널(lower funnel)은 대리 에이전트가 더 잘 맞을 수 있다.

## 예시

### 모호한 거실 꾸미기 요청 처리

```text
입력
- "이런 느낌으로 거실을 바꾸고 싶어요."
- 참고 이미지 1장
- 제한된 예산

1. 작업 상태 생성
   - 예산은 확정 조건으로 보존
   - 이미지에서 스타일 단서를 추출하고 신뢰도를 기록
   - 재고는 실시간 조회 대상으로 분리

2. 의도 격차 계산
   - 방 너비와 스타일 확신도가 부족함
   - 결과를 가장 크게 제한하는 방 너비를 먼저 질문

3. 멀티모달 선호 확인
   - 텍스트로 스타일명을 요구하지 않고 시각 보드를 제시
   - 클릭·호버 반응으로 스타일 신뢰도를 갱신

4. 조사와 응답
   - 조건에 맞는 상품을 비교
   - 설명문 대신 배치 예시와 상품을 묶은 시각 보드로 제시
```

### 설계 점검 질문

```text
1. 사용자가 말한 사실과 모델이 추론한 선호를 구분했는가?
2. 추론에는 신뢰도와 출처가 있는가?
3. 실시간 갱신이 필요한 변수를 따로 관리하는가?
4. 다음 질문은 정보 획득량이 가장 큰 하나인가?
5. 텍스트보다 이미지나 비교가 더 적합한 질문은 없는가?
6. 응답 형식이 사용자의 다음 행동을 쉽게 만드는가?
7. 루프의 각 단계를 독립적으로 평가할 수 있는가?
```

## 요약
- 실제 사용자는 완성된 검색어보다 모호한 분위기와 부분적인 조건을 가지고 오므로, 에이전트는 표현 격차를 해소해야 한다.
- 협업 루프는 발견(맥락과 의도 격차), 조사(선호 획득과 정보 비교), 응답(적응형 표현)의 세 단계로 구성된다.
- 확정 조건, 유연한 선호, 실시간 변수를 분리한 작업 상태가 전체 대화의 기준점이다.
- 모든 미확정 사항을 묻지 말고 결과를 가장 크게 바꾸는 질문 하나를 정보 획득량 기준으로 선택한다.
- 텍스트 질문만 고집하지 말고 시각 보드와 사용자의 미세 반응을 이용해 말로 표현하기 어려운 선호를 찾는다.
- 목록, 비교표, 요약, 무드보드 중 목적에 맞는 형식을 고르는 것 역시 에이전트 지능의 일부다.
- 최종 답변뿐 아니라 작업 상태, 질문 효율, 선호 발견, 형식 선택을 단계별 자동 평가기로 측정해야 한다.
