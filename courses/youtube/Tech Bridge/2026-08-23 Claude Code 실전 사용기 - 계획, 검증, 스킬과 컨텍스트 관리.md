## 내용

### 프로젝트 지침과 필요한 스킬 (00:00~06:33)

발표자는 프로젝트 지침에 짧은 설명과 팀의 스타일·작업 원칙을 두고 유연하게 갱신한다. 반복 절차는 스킬로 표현하며 다른 개발자의 스킬을 읽는 것도 학습에 도움이 된다고 말한다. 요구 구체화, 아키텍처 개선, 코드 단순화 등의 사례를 소개한다. 서로 다른 취향의 스킬을 많이 섞기보다 자신의 작업에 맞는 것을 고른다.

### 큰 작업은 계획, 결과는 검증 (06:33~10:29)

큰 변경은 계획에서 오류를 찾는 편이 수천 줄의 구현을 고치는 것보다 쉽다. 반면 오타 수정 같은 작은 일에는 복잡한 계획이 낭비일 수 있다. 강한 모델로 계획하고 더 저렴한 모델로 구현하는 역할 분담도 제안한다.

검증은 중요한 동작의 테스트, 타입 검사·린트, 브라우저와 스크린샷 확인 등으로 구성한다. 테스트를 먼저 작성해 구현과 독립적인 목표를 주되 모든 줄을 기계적으로 검사하는 과잉 테스트도 피한다. MCP는 외부 도구와 실제로 상호작용할 필요가 있을 때 사용한다.

### 보조 기능과 맥락 비용 (10:29~15:21)

음성 입력, 작업 중 질문, 원격 세션, 명령 출력을 대화에 공유하는 기능을 소개한다. 사용량은 질문 횟수만이 아니라 읽은 파일·도구 결과·출력에 좌우된다. 다른 큰 작업은 새 세션으로 분리하고, 필요한 파일과 자료를 지정하며, 무관한 조사를 줄인다. 압축 시에는 보존할 정보를 명확히 한다. 특정 토큰 수에서 성능이 떨어진다는 수치는 개인 경험이다.

### 반복 실행과 병렬 작업 (15:21~19:35)

정기 이슈 처리, 보안·버그 탐색, 기능 아이디어 조사 등의 자동화를 설명한다. 목표를 만족할 때까지 실행하는 방식과 일정마다 반복하는 방식은 다르다. 하위 에이전트는 별도 맥락으로 조사·리뷰·디버깅을 수행하지만 전체 비용도 늘어난다. 병렬 코드 작업은 워크트리로 분리하는 예를 든다.

### 기본기를 유지하며 도구 선택 (19:35~21:02)

Codex·OpenCode·Pi·Cursor·GitHub Copilot·T3 Code 등 대안을 소개한다. 영상 중간에도 강조하듯 AI가 한도에 도달했을 때 자기 프로젝트를 이해하지 못하는 상태를 피해야 한다. 변경의 이유를 설명받고 소프트웨어 기본기를 함께 익히자는 메시지다. 기능·요금제·제공 상태는 촬영 당시 설명이며 일부는 영상 내에서도 변경되었다고 정정한다.

## 예시

| 작업 | 적용할 방식 |
|---|---|
| 작은 오타·이름 변경 | 간단한 요청과 필요한 확인 |
| 여러 파일의 큰 기능 | 계획과 인수 기준을 먼저 검토 |
| 화면 변경 | 브라우저 동작·스크린샷 검증 |
| 외부 데이터 필요 | 필요한 MCP만 연결 |
| 독립적인 조사·리뷰 | 비용을 고려한 별도 에이전트 |
| 새로운 큰 주제 | 관련 맥락을 정리해 세션 분리 |

## 요약

- 필요한 만큼만 계획하고 중요한 결과를 검증한다.
- 스킬·MCP·하위 에이전트는 효용과 맥락 비용을 함께 본다.
- AI의 변경을 이해하며 자신의 개발 기본기도 유지한다.
