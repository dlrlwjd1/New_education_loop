# Jeff Dean의 AI 창업 강의 - 추론 병목과 실험 자동화

## 개요

- **업로드일:** 2026-08-09
- **채널:** Tech Bridge
- **발표자·출처:** Jeff Dean (Y Combinator Startup School 대담)
- **원본:** [YouTube](https://www.youtube.com/watch?v=W7hJVj1yb34)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 56:38, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** AI의 기회는 모델 크기뿐 아니라 데이터 이동·추론 지연·컨텍스트·평가 루프에서 생기며, 사람은 중요한 문제를 고르고 명세하는 능력을 길러야 한다.

## 내용

### 1. 더 긴 작업과 자동화된 연구에 대한 전망 (0:00~5:30)

Jeff Dean은 코딩 에이전트가 더 복잡하고 오래 걸리는 작업을 수행하는 방향으로 발전했다고 평가한다. 다음 단계로 문제를 나누고 실험을 수행한 뒤 결과를 결합하는 연구 자동화를 전망한다. 측정 가능한 목표가 있는 과학·공학 문제도 그 대상이다.

또 하나의 변화는 추론 지연이다. 응답을 훨씬 빨리 받을 수 있다면 가능한 제품 경험 자체가 달라진다. 장기간의 언어 간 소프트웨어 재구현은 오래 실행되는 에이전트의 활용 예로 든다.

### 2. TPU의 출발 - 수요를 곱해 병목 계산하기 (5:34~10:01)

신경망 음성 인식의 품질이 좋아지자 사용량 증가에 필요한 계산량이 문제가 됐다. 사용자가 하루 몇 분씩 더 사용하는 경우를 계산한 결과, 기존 CPU 방식으로는 큰 인프라 확장이 필요했다고 회고한다.

TPU는 저정밀도 밀집 선형대수에 특화하되 특정 모델 하나에만 묶이지 않는 선택이었다. 발표자가 제시하는 당시 대비 효율·지연 개선 수치는 초기 세대의 회고이지 현재 모든 하드웨어의 비교값이 아니다.

창업자에게는 지금의 해결법을 조금 개선하는 것뿐 아니라, 병목을 처음부터 다르게 풀면 한두 자릿수 배율의 차이를 낼 수 있는지 계산해 보라고 조언한다.

### 3. AI 시스템에서 알아야 할 수치 (10:03~15:42)

중요한 값으로 가속기 메모리 대역폭, 연산 에너지, 칩 간 연결 대역폭, 더 큰 클러스터로 확장할 때의 통신 성능 변화를 든다.

데이터를 이동하는 에너지가 계산 자체보다 훨씬 크면 배치로 이동 비용을 나눠 부담하게 된다. 하지만 배치를 모으는 것은 낮은 지연을 원하는 추론과 충돌할 수 있다. 데이터 이동을 줄이고 필요한 정밀도에 집중하는 하드웨어 설계가 그래서 중요하다. 강의의 에너지 비율은 이 관계를 설명하기 위한 예시다.

### 4. 컨텍스트 엔지니어링은 실제 실패에서 시작한다 (15:50~21:48)

모델은 전체 시스템의 한 부분이다. 검색, 도구, 과거 작업 정보, 여러 접근의 평가와 조율이 합쳐져 문제 해결 능력이 된다. 학습된 파라미터에 묻힌 정보와 달리 현재 문제의 맥락은 직접 제공할 수 있다.

사용 중 모델이 실패하는 부분을 보고 필요한 정보와 도구 사용 지침을 스킬로 만든다. 기반 모델을 다시 학습하지 않고도 작업 환경을 개선하는 접근이다.

Dean과 Sanjay의 성능 최적화 사례에서는 다음 절차를 스킬로 전달했다.

1. 현재 구현의 마이크로벤치마크를 측정한다.
2. 코드 변경으로 성능 개선을 시도한다.
3. 벤치마크를 다시 실행한다.
4. 더 넓은 벤치마크와 캐시 사용 특성도 확인한다.
5. 결과에 따라 반복한다.

발표 중 소개한 `Performance Hints` 문서는 이런 성능 판단 지식을 전달하는 사례다.

### 5. 긴 에이전트 실행의 신뢰성 (21:49~24:53)

모델이 익숙하지 않은 작업 영역으로 벗어나면 실패 가능성이 커진다. 스킬은 도구를 사용하는 검증된 경로를 안내할 수 있다.

여러 에이전트가 다른 접근을 탐색하고 별도 평가자가 유망한 결과를 선택하는 방법도 설명한다. 추론 시점의 계산을 탐색과 평가에 써서 실패한 경로를 버리는 방식이며, 에이전트 수만 늘리는 것과는 다르다.

### 6. 작은 팀이 선택할 문제 (24:57~30:59)

범용 모델이 놓치는 분야의 사용자 경험, 특정 데이터에 대한 접근, 전문 모델의 높은 정확도가 작은 팀의 기회라고 설명한다. 개인 정보를 정리하는 제품과 AlphaFold 같은 전문 모델을 예로 든다.

다만 범용 모델이 곧 잘하게 될 일을 임시 보완하는 사업인지 판단해야 한다. 현재 모델이 어느 정도 수행하는 문제보다 거의 못 하는 문제를 살펴보라는 조언은 기회 탐색의 휴리스틱이다. 성공률 하나로 사업성을 결정하라는 공식은 아니다.

### 7. 명세와 문제 선택의 안목 (31:02~36:08)

에이전트가 코드를 작성할수록 사람이 원하는 동작을 명확히 적는 일이 중요해진다. 기존 프로그램을 다른 언어로 옮기는 작업은 원본 구현과 테스트가 상세한 명세 역할을 하므로 유리하다.

실행 능력이 풍부해지면 무엇을 만들게 할지가 희소한 능력이 된다. 안목을 기르는 방법으로 다양한 문제를 풀고, 앞으로 중요할 주제를 적어 두었다가 12개월 뒤 예측을 돌아보는 연습을 제안한다.

### 8. 오래된 가정을 뒤집는 사고실험 (36:12~41:42)

모든 트랜지스터가 극도로 신뢰성 있어야 한다는 가정을 완화하고 상위 수준의 중복성으로 보완한다면 어떨지 질문한다. 이는 실제 제품 계획 발표가 아니라 설계 가정을 의심해 보는 사고실험이다. 기존 방식에는 좋은 이유가 있을 수 있으므로 실험 결과가 채택으로 이어진다고 보장하지 않는다.

MapReduce는 단순한 데이터 처리 목적과 복잡한 병렬화·장애 복구 코드를 분리한 사례다. 공통의 복구 작업을 하위 구현으로 옮기고 상위에서는 계산의 의도에 집중하게 했다.

### 9. 과학적 방법의 자동화와 빠른 평가자 (41:46~47:19)

가설 제안 → 실험 구현 → 평가 → 다음 실험이라는 순환을 자동화하고 지연을 줄이면 훨씬 많은 후보를 탐색할 수 있다. 상위 문제를 하위 실험으로 나누고 결과를 통합하는 조율도 필요하다.

양자화학 시뮬레이터의 입출력으로 학습한 근사 모델이 평가를 크게 가속한 사례를 소개한다. 빠른 평가자는 탐색 범위를 넓히지만 정답을 완전히 대신하는 것으로 취급하지 않는다. 목표는 토큰이나 실험 횟수가 아니라 계산량당 유용한 발견을 늘리는 것이다.

### 10. 거절, 동료, 다음 연구 기회 (47:22~56:38)

지식 증류 논문이 처음 거절됐어도 공개 후 널리 사용됐다는 회고를 통해, 중요한 문제라는 근거가 있다면 외부 평가 하나로 포기하지 말라고 말한다.

진로 선택에서는 의미 있는 문제, 함께 일하기 좋은 동료, 성공했을 때의 긍정적 영향을 기준으로 삼는다. 팀에는 상호 보완적인 능력과 낮은 자의식, 서로 배우려는 태도가 중요하다.

마지막으로 효율적인 추론 하드웨어, 더 적은 데이터로 배우는 알고리즘, 지속 학습, 다중 에이전트 상호작용, 사람 사이의 더 나은 대화와 연결을 앞으로의 관심 분야로 제시한다.

## 예시

강의의 언어 이전 사례를 작업 명세로 정리하면 다음과 같다.

| 단계 | 검증 기준 |
| --- | --- |
| 원본 분석 | 기존 프로그램이 수행하는 기능과 예외 동작을 파악 |
| 새 언어 구현 | 같은 입력에 요구되는 동작을 구현 |
| 테스트 이전 | 기존 테스트가 새 구현에서도 통과하는지 확인 |
| 차이 비교 | 두 구현의 결과 차이를 찾아 수정 |
| 성능 평가 | 기능 동일성과 성능 개선을 각각 확인 |

원본 구현과 테스트가 상세한 요구사항을 제공하므로, 막연한 새 제품 요청보다 완료 여부를 판단하기 쉽다는 예다.

## 요약

- 추론 지연·데이터 이동·평가 속도는 제품과 연구의 가능성을 바꾸는 병목이다.
- 모델의 실패를 관찰하고 도구·스킬·평가 루프를 개선한다.
- 명확한 명세와 중요한 문제를 고르는 안목이 에이전트 활용의 핵심이다.
- 실험 자동화의 성과는 계산량당 유용한 발견으로 본다.
