# Boris Cherny와 AMD가 말하는 에이전트 조직의 병목과 자율성

## 개요

- **업로드일:** 2026-08-12
- **채널:** Tech Bridge
- **발표자·출처:** Boris Cherny × Mark Papermaster (AMD 대담)
- **원본:** [YouTube](https://www.youtube.com/watch?v=nfUKLULchXE)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 39:39, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 에이전트를 쓰는 조직은 코드 생성뿐 아니라 검토·출시·권한 관리까지 이어지는 병목을 계속 개선해야 한다.

## 내용

### 1. 미래 모델의 능력을 전제로 제품을 설계하기 (0:00~7:46)

Boris Cherny는 엔지니어링·제품·디자인 등 여러 역할을 경험한 것이 도구 자체보다 사용자가 달성할 결과를 보게 했다고 설명한다. 채용에서도 다양한 배경과 호기심을 중시한다.

Claude Code는 당시 모델에 맞춘 자동완성을 넘어, 앞으로 더 유능해질 모델이 도구를 사용하며 일을 수행하는 제품으로 출발했다. 초기에는 능력이 충분하지 않았지만 모델 개선과 함께 제품의 가치가 커졌다는 회고다. 미래 능력을 예상해 투자하되 실제 사용에서 가설을 확인하는 접근이다.

### 2. 고정된 호출 순서에서 목표 중심 실행으로 (7:51~10:05)

처음에는 사람이 LLM 호출 순서를 미리 정하는 방식이 많았다. 이후에는 목표·도구·맥락을 제공하고 모델이 다음 행동을 결정하게 하는 구조가 중요해졌다고 말한다. 모든 지식을 시작부터 넣기보다 스킬과 도구를 통해 필요한 정보를 그때 가져오는 방식도 함께 설명한다.

### 3. 생산성 향상은 다음 병목을 드러낸다 (10:11~17:58)

Anthropic 내부 활용 사례로 온보딩 질문, 코딩, 리뷰, 보안, 사용자 피드백 분류, 제품·마케팅 업무를 든다. 엔지니어당 코드 출력량이 연초 대비 8배라는 내부 수치를 소개하지만, 이는 사업 성과나 전체 업무 생산성이 8배라는 의미는 아니다.

코드 작성이 빨라지면 검토와 출시 같은 다음 단계가 제약이 된다. 조직은 자율적으로 아이디어를 실험하고 사용자 반응을 확인하는 사람에게 맥락과 시간을 제공해야 한다. 실험을 허용한다면서 실패를 인사상 불이익으로 돌리면 학습이 일어나기 어렵다는 취지다.

### 4. 병렬 에이전트와 회귀 검증 (18:00~23:29)

하나의 에이전트에서 여러 에이전트, 중첩된 위임과 장시간 실행으로 작업 규모가 커지는 흐름을 설명한다. 마이그레이션이나 앱 개발 사례에서도 결과가 나왔다는 사실과 실제 배포할 준비가 됐다는 사실은 구분된다. 회귀 검증이 필요하다.

추론 시 여러 접근을 시도하는 것은 성공 가능성을 높일 수 있지만, 에이전트 수나 토큰 사용량 자체가 목표는 아니다. 작업을 어떻게 나누고 결과를 어떻게 검증하느냐가 중요하다.

### 5. 비용보다 먼저 성과를 찾고, 반복 작업은 평가한다 (23:33~29:39)

ROI를 논할 때 지출만 줄이기보다 새로 얻을 수 있는 성과를 먼저 탐색하라고 조언한다. 유효한 사용처를 찾은 뒤 저렴한 모델·추론 수준·평가를 활용해 비용을 조정한다. 과거 모델에서 실패했다는 기억 때문에 새 모델의 능력을 과소평가하지 말고 다시 실험할 필요도 있다.

수천 번 반복하는 업무에는 회귀 평가와 모델 비교가 유용하다. 일회성 제품 탐색에서는 평가를 만드는 비용도 고려하며 사람의 판단과 사용 경험을 함께 활용한다.

### 6. 장시간 자율 실행과 승인 피로 (29:42~34:08)

신뢰에는 정렬 학습, 부적절한 요청에 대한 이견 제시, 프롬프트 인젝션 방어, 실행 시점의 분류 등 여러 층이 필요하다고 설명한다. 발표자의 낮은 공격 성공률 언급은 완전한 안전 보장을 뜻하지 않는다.

사람이 Bash 명령을 읽지 않고 승인만 반복하는 문제도 다룬다. Anthropic은 분류기를 통한 승인 판단을 평가·레드팀·침투 테스트로 검증했다고 소개한다. 핵심은 승인 횟수를 늘리는 것이 아니라 실제 위험을 판별할 수 있는 통제다.

### 7. 하드웨어 확장과 향후 전망 (34:13~39:39)

Papermaster는 반도체 미세화만으로 과거의 비용·전력 개선 속도를 유지하기 어려워졌으며, 에이전트가 칩 설계의 많은 변수와 상태를 탐색하는 데 도움이 된다고 설명한다.

Cherny는 더 오래 실행되고 더 적은 감독을 필요로 하는 에이전트를 전망한다. 제품·스타트업 전체를 만드는 미래에 대한 발언은 당시의 예측이며, 이미 일반적으로 가능한 결과로 단정하지 않는다.

## 요약

- 제품과 조직을 현재의 코드 작성 속도에만 맞추지 말고 변화하는 모델 능력에 맞춰 재검토한다.
- 병렬 실행의 가치는 검증 가능한 결과와 전체 업무 흐름의 개선으로 평가한다.
- 장시간 자율성에는 맥락 제공, 회귀 평가, 실효성 있는 권한 판단이 함께 필요하다.
