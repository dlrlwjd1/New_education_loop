# Claude Code 세션의 컨텍스트와 토큰 낭비를 줄이는 습관

## 개요

- **업로드일:** 2026-08-20
- **채널:** Tech Bridge
- **발표자·출처:** Tech Bridge 소개 영상의 Claude Code 활용 해설
- **원본:** [YouTube](https://www.youtube.com/watch?v=-QwaaSwQIhE)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 12:18, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 작업 전환, 초기 컨텍스트 점검, 파일 지정과 출력 필터링으로 불필요한 모델 입력을 줄인다.

## 내용

### 작업 전환과 컨텍스트 점검 (00:00–05:39)

서로 무관한 작업으로 넘어갈 때는 필요한 내용을 파일로 남기고 세션을 비우는 습관을 제안한다. 이어서 수행할 일이 있다면 압축을 고려하되, 압축도 기존 내용을 읽고 요약하는 작업이라 비용이 든다는 점을 설명한다.

영상은 캐시 만료와 압축 시점을 연결해 비용을 해설한다. 여기서 제시한 한 시간 기준 등은 영상 당시 설명이며 모든 모델·요금제의 일반 규칙으로 확대하지 않는다.

`/context`로 메시지 입력 전부터 차지하는 컨텍스트를 확인하고, 메모리·전역 스킬·MCP·에이전트 설정에 불필요한 항목이 쌓이지 않았는지 살핀다. 시연에서는 시작 전 수만 토큰이 들어간 사례를 보여 준다. 설치한 도구를 잊은 채 계속 추가하면 매 세션의 기본 비용이 커진다는 지적이다.

### 작업에 맞는 자원과 명확한 파일 지정 (05:43–08:23)

모델과 추론 수준을 작업에 맞게 정하고 세션 중 불필요한 변경을 줄이라고 권한다. 발표자는 변경에 따른 캐시 재사용 영향을 강조하며, 성격이 다른 작업은 별도 하위 에이전트로 분리하는 방식을 소개한다. 구체적인 캐시 동작은 해당 제품 설정에 따른 설명으로 읽는다.

이미 위치를 아는 파일은 `@`로 지정한다. 막연히 파일을 찾으라고 시키면 디렉터리 검색과 검색 결과를 읽는 호출이 늘어난다. 필요한 문서를 직접 전달하면 탐색 단계와 관련 없는 출력이 줄어든다.

### 시끄러운 출력의 비용 (08:27–10:33)

CLI의 전체 출력을 무조건 넘기지 말고 필요한 범위와 정보를 필터링한다. 큰 상태 출력이나 로그는 컨텍스트를 채우고 실제 작업과 무관한 정보를 남긴다.

많은 원본 출력을 살펴야 하는 작업은 하위 에이전트가 읽고 필요한 결과만 반환하게 할 수 있다. 다만 영상에서도 단순한 Git 상태 확인 하나에 하위 에이전트를 쓰는 것은 과할 수 있음을 인정한다.

### 완료 비용을 의식하는 개발 (10:36–12:18)

정액 구독 환경에서는 토큰 사용량을 무시하기 쉽지만, API 기반 에이전트를 만들면 불필요한 입력이 운영 비용으로 이어진다. 목표는 단순히 프롬프트를 짧게 하는 것이 아니라, 과제를 완료하는 데 필요한 호출과 정보의 양을 관리하는 것이다.

## 예시

영상의 제안을 작업 상황별로 정리하면 다음과 같다.

| 상황 | 적용할 습관 |
|---|---|
| 앞 작업과 무관한 새 과제 | 필요한 결과를 파일에 남기고 컨텍스트 초기화 |
| 시작부터 컨텍스트 사용량이 큼 | 메모리와 전역 도구·스킬 설정 점검 |
| 수정할 파일을 이미 앎 | 파일을 직접 지정 |
| 로그가 길고 결론만 필요함 | 출력 필터링 또는 별도 작업에서 요약 |

## 요약

- 세션에 무엇이 들어가는지 먼저 확인한다.
- 파일 지정과 출력 범위 조절로 불필요한 탐색을 줄인다.
- 캐시·모델 설정은 영상 당시 설명과 실제 사용하는 환경을 구분한다.
