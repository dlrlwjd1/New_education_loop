# 토큰 사용량보다 중요한 신뢰할 수 있는 처리량

## 개요

- **업로드일:** 2026-09-02
- **채널:** Tech Bridge
- **발표자·출처:** Mingsheng Hong / Ironclad 엔지니어링 강연
- **원본:** [YouTube](https://www.youtube.com/watch?v=fOsLTMhjyMM)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 22:19, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 토큰을 많이 쓰거나 적게 쓰는 것보다 검증되어 고객에게 전달되는 결과의 가치를 높이는 데 집중한다.

## 내용

### 사용량 대시보드는 순위표가 아니다 (00:00–06:17)

토큰 사용량을 경쟁 지표로 만들면 소비 자체를 늘리는 잘못된 유인이 생긴다. 대시보드는 미도입 영역과 급격한 비용 증가를 찾는 연기 감지기처럼 사용한다. 도입 초기에는 접근성과 수용을 먼저 해결하고, 이후 비용과 가치의 관계를 측정한다.

### Trusted Throughput의 정의 (06:17–13:33)

코드 생성량이나 열린 PR 수보다 실제 병합된 결과를 본다. 작은 동시성 버그 수정과 많은 상용구 생성의 가치는 다르므로 PR 복잡도를 가중하는 시도를 소개하되, 아직 발전 중인 대리 지표라고 말한다.

신뢰는 세 층으로 확인한다. 테스트·보안·안전한 배포 같은 객관적 검사, 아키텍처·가독성·유지보수에 대한 사람의 판단, 장애·롤백·고객 문의 같은 운영 피드백이다.

### 새 병목은 리뷰와 CI (13:43–17:40)

코드 생성이 쉬워지면 리뷰와 병합 대기가 늘어난다. 느린 CI를 피하려고 PR을 크게 합치는 것은 리뷰 품질을 떨어뜨리는 역효과를 낸다. AI로 기본 결함을 먼저 거르고 사람은 중요한 설계 판단에 집중한다.

플레이키 테스트를 줄이고, 준비된 PR이 병합되기까지 걸리는 시간과 재시도 횟수를 측정해 플랫폼 차원에서 개선한다. 불안정한 CI를 에이전트가 계속 재실행하게 하는 것은 근본 해결이 아니다.

### 비용·학습·구매 판단 (17:49–22:19)

예산과 할당량, 이상 사용 알림, 팀별 검토를 결합한다. 자동 수정 루프는 횟수를 제한하고, 고정 프롬프트를 앞에 두어 캐시를 활용하며 불필요한 컨텍스트를 줄인다. 차별화되지 않는 도구는 구매하고 조직별 고품질 작업 절차는 내부 플레이북으로 축적하는 관점을 제시한다.

## 예시

10줄의 동시성 버그 수정은 1,000줄의 상용구보다 가치가 클 수 있다. 따라서 코드 줄 수나 토큰 소비량이 아니라 검증·병합·고객 효과를 함께 측정한다.

## 요약

- 비용 측정에서 바로 비용 삭감으로 뛰어넘지 않는다.
- 코드가 늘어난 만큼 리뷰와 CI 역량도 키워야 한다.
- 객관적 검사, 사람의 판단, 운영 결과를 합쳐 신뢰를 평가한다.
