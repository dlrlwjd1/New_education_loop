# 로컬 연구 에이전트의 기억 검색 정책 평가

## 개요

- **업로드일:** 2026-08-14
- **채널:** Tech Bridge
- **발표자·출처:** Stefania Druga / Sakana AI
- **원본:** [YouTube](https://www.youtube.com/watch?v=yUjTWl7tOYc)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 11:50, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 기억을 저장소가 아닌 쓰기·관리·읽기의 제어 루프로 보고 장기 작업에서 검색 정책을 비교한다.

## 내용

### 긴 작업의 컨텍스트 손실 (00:00–03:52)

이전 결정을 잊거나 일을 반복하고 질문에서 벗어나는 현상을 문제로 제시한다. 로컬 모델에서는 RAM·실행 시간 제약도 있어 필요한 맥락을 효율적으로 전달해야 한다.

발표자는 로컬 Mac에서 연구 에이전트의 모델은 고정하고 기억 하네스만 바꾸어 실험한다. 핵심 맥락, 검색 블록, 세션 간 아카이브를 구분한다. 기억은 단순 DB가 아니라 무엇을 기록·유지·조회할지 결정하는 루프다.

### 네 가지 비교 조건 (03:58–05:58)

기억 없음, 벡터 유사도 검색, 결정 기록을 활용한 검색, 정답 기억을 제공하는 oracle 조건을 비교한다. 첫 문헌 조사 과제에서는 큰 연구 주장과 이를 수정하는 작은 단서를 함께 넣는다.

모든 정보가 컨텍스트에 들어가는 경우에는 기억을 추가해도 성능은 같고 비용만 늘었다고 보고한다. 기억 시스템이 항상 유리하다는 가정부터 검증한 것이다.

### 과거 단계의 정보가 필요한 장기 과제 (06:03–09:21)

500번째 단계에서 124번째 단계의 정보가 필요한 식으로, 현재 컨텍스트 밖의 기록을 찾아야 하는 과제를 평가한다. 발표자는 68개 질문과 여러 조건·seed에서 순위를 매긴 검색 정책이 유리했다고 보고한다. 68은 질문 수이며 성능이 68배라는 뜻이 아니다.

Oracle도 최대 성능을 보장하지 않았다. 올바른 기억을 전달해도 모델이 무시하거나 잘못 사용할 수 있기 때문이다. 임의 기록·잘못된 단계·최근 단계 등을 주는 ablation과 다른 모델·벤치마크의 결과도 소개한다.

### 검색 정책을 별도 평가 대상으로 (09:28–11:50)

무슨 기억을 남기는지, 우선순위를 어떻게 정하는지, 여러 세션 뒤에도 무엇이 유지되는지 평가해야 한다. 나쁜 검색은 잘못된 방향으로 추론하게 만들어 비용을 늘리고, 적절한 구조는 토큰을 절약할 수 있다.

로컬 실험은 데이터·연산·평가를 통제하는 장점이 있지만 발표 환경에서는 직렬 실행과 배치 처리 제한 때문에 평가가 오래 걸렸다. 초기 실험의 결과와 더 넓은 기억 연구의 가능성을 구분한다.

## 예시

| 조건 | 확인하려는 질문 |
|---|---|
| 기억 없음 | 현재 컨텍스트만으로 충분한가? |
| 벡터 검색 | 의미적으로 비슷한 정보가 도움이 되는가? |
| 결정 중심·순위 검색 | 과제에 필요한 과거 결정을 우선할 수 있는가? |
| Oracle | 올바른 기억을 줘도 모델이 활용하는가? |

## 요약

- 기억의 필요성부터 현재 컨텍스트 기준으로 확인한다.
- 검색 성공과 검색한 정보의 올바른 활용은 별개다.
- 품질·토큰·실행 시간으로 검색 정책을 비교한다.
