# Flutter 개발자의 AI 워크플로와 스킬 5가지

## 개요

- **업로드일:** 2026-09-02
- **채널:** Tech Bridge
- **발표자·출처:** Ivanna Kaceviča / Flutter 개발자 대담
- **원본:** [YouTube](https://www.youtube.com/watch?v=4hfmNiQDt1g)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 15:22, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 반복되는 프로젝트 지식을 필요한 순간에만 읽는 스킬로 만들고, 코드 리뷰와 실제 화면 검증을 함께 수행한다.

## 내용

### 규칙과 스킬의 차이 (00:00–02:29)

상시 읽는 프로젝트 규칙과 달리 스킬은 특정 과제에 필요한 절차를 선택적으로 불러오는 방식이다. 반복 작업을 템플릿화할 때 유용하며, 광고 SDK 설치처럼 일회성 복잡한 절차를 자동화한 뒤 제거하는 경우도 있다.

### 외부 스킬의 보안과 유지보수 (02:29–05:37)

Markdown 파일도 에이전트의 행동을 바꾸므로 프롬프트 인젝션 경로가 될 수 있다고 지적한다. 공식 출처를 우선하고 내용을 검토하며, 생성기로 만든 스킬도 사람이 조정해야 한다고 말한다. 공식 출처라는 사실 자체가 무위험을 보장하는 것으로 해석하지 않는다.

### 권하는 다섯 가지 (05:37–11:22)

| 스킬 | 역할 |
| --- | --- |
| Skill Creator | 지침뿐 아니라 스크립트·참고자료·자산까지 구성 |
| 코드 리뷰 | 리뷰와 PR 실행 검증을 나누고 결과를 교차 확인 |
| 새 기능·엔드포인트 추가 | 기존 내비게이션·데이터 계층·디자인 시스템에 맞춘 반복 골격 생성 |
| Flutter 기본 레이아웃 | Row·Column·Wrap·Stack과 유연한 배치를 적절히 사용 |
| 시각적 QA | 앱을 웹에서 실행하고 실제 화면을 캡처해 오류 확인 |

스킬 설명에는 언제 사용할지 명확히 적는다. 코드가 그럴듯한지를 평가하는 것과 그 코드가 필요한지를 판단하는 것은 다르므로, 후자에는 업무 맥락이 중요하다고 말한다. Golden test의 회귀 검증과 실제 스크린샷 검토도 역할이 다르다.

### 여러 도구를 관리하는 개발자 (11:25–15:22)

Claude·Codex·Antigravity를 함께 사용하며 에이전트에게 업무를 배분하는 개인 경험을 소개한다. Flutter의 단일 코드베이스로 여러 플랫폼에 배포하는 이점을 강조하지만, 남은 토큰을 모두 쓰려는 심리가 과도한 작업으로 이어질 수 있다는 자기 관찰도 덧붙인다.

## 예시

왼쪽 텍스트와 오른쪽 이미지를 배치할 때 절대 위치와 중첩 컨테이너를 남발하는 대신 Row와 Flexible·Expanded 같은 적절한 레이아웃을 쓰게 한다. 화면을 실제로 캡처해 반응형 동작까지 확인한다.

## 요약

- 반복되는 구조와 사용 조건을 스킬에 담는다.
- 좋은 코드와 필요한 코드를 구분하고 시각적 QA를 더한다.
- 스킬 생성 자동화 이후에도 내용 검토와 유지보수는 필요하다.
