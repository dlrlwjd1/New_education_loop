## 내용

### 자체 AI를 만드는 네 동기 (00:00–06:21)

발표자는 sovereign AI를 기업이 모델 가중치까지 포함해 자체 지능을 통제하는 방향으로 설명한다. 모든 기성 모델 사용을 중단하라는 뜻은 아니며 제품 일부부터 통합 범위를 넓히는 접근이다.

동기는 비용, 지연 시간, 도메인 성능, 공급자에 대한 의존성 통제다. 애플리케이션 기업도 평가·하네스·후속 학습 연구를 통해 지능 자체를 개선하는 조직이 될 수 있다는 관점이다.

### 1. 소유와 임대의 경계 (06:26–09:19)

자체 구축 여부는 이분법이 아니다. 원가에서의 비중, 속도의 중요성, 도메인 성능 개선 가능성, 고유 데이터의 가치를 기준으로 기능마다 판단한다.

영상은 즉시 응답과 호출량이 중요한 자동완성, 특수 보안 업무, 독점 데이터가 중요한 생물학 모델을 예로 든다. 특정 회사의 당시 선택을 모든 기업에 적용하는 규칙으로 삼지는 않는다.

### 2~3. 팀과 성과의 가시성 (09:23–12:00)

연구 중심 또는 엔지니어링 중심 리더 등 필요한 인재는 연구 성격에 따라 다르다. 기존 플랫폼 지원팀에 추가 업무를 얹기보다 작고 집중된 팀을 고려하라고 제안한다.

'Legibility'는 내부 성과를 구매자와 생태계가 이해할 수 있도록 드러내는 것이다. 실질적인 연구 결과, 공개 평가와 기술 설명을 통해 차별성을 증명하는 활동을 포함한다.

### 4. 평가에서 운영 학습까지 (12:05–13:50)

전략 → 평가 기준 → 모델 라우팅·하네스 실험 → 필요하면 후속 학습 → 운영 피드백 루프의 순서를 제시한다. 중간·사전 학습까지 필요한 경우는 더 제한적이라고 설명한다.

오픈 가중치 기반 모델을 자신의 분야에 맞게 바꾸어 성능을 개선할 가능성을 강조하지만, 모든 자체 모델이 상용 모델보다 우수해진다는 보장은 아니다.

### 운영 스택과 개발 스택 (13:55–17:21)

운영 스택에는 모델, 하네스, 도구와 컨텍스트가 있다. 자체 통제 범위가 커지면 이를 설정·운영하는 부담도 커진다.

개발 스택에는 평가·관측, 전문가 실행 경로·합성 데이터·RL 환경, 후속 학습과 운영 경험의 반영이 포함된다. 발표자는 기억과 데이터 접근도 성능에 중요한 요소로 강조한다. 매 상호작용이 저절로 개선이 되는 것이 아니라 데이터를 선별·평가하는 학습 체계를 설계해야 한다.

## 예시

| 판단 축 | 자체 구축을 검토할 질문 |

| 비용 | 해당 호출이 제품 원가에서 큰 비중인가? |
| 속도 | 지연 시간이 핵심 사용자 경험을 제한하는가? |
| 성능 | 고유 평가에서 특화 개선의 여지가 있는가? |
| 데이터·통제 | 기업 고유 지식과 운영 조건을 직접 관리해야 하는가? |

## 요약

- 기능별로 외부 사용과 자체 통제의 경계를 정한다.
- 평가 기준을 먼저 만들고 하네스·라우팅·학습을 실험한다.
- 모델 소유에는 데이터·관측·팀·운영 책임이 함께 따른다.
