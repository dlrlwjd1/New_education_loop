# 에이전트 설계 안티패턴 - Claude 아키텍처 시나리오로 배우기

## 개요

- **업로드일:** 2026-08-10
- **채널:** Tech Bridge
- **발표자·출처:** Frank Coyle (Berkeley)
- **원본:** [YouTube](https://www.youtube.com/watch?v=eAm9kuLmGDA)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 19:33, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 도구 실행의 종료 조건, 역할 분리, 컨텍스트 격리, 비대화형 CI를 실패 패턴과 함께 설명한다.

## 내용

### 1. 시험보다 중요한 것은 설계 판단 (0:00~5:48)

발표자는 Claude Certified Architect의 시나리오를 학습 틀로 소개한다. 강의의 목적은 시험 정보 암기보다 실제 제약 아래에서 잘못된 설계 선택을 알아보는 데 있다. 시험 가격·응시 조건 등은 이 노트에서 현재 안내로 제공하지 않는다.

다루는 영역은 에이전트 아키텍처, Claude Code 작업 환경, 프롬프트와 구조화 출력, 도구·MCP, 컨텍스트와 신뢰성이다. 고객 지원, 코드 생성, 다중 에이전트 연구, 개발 생산성, CI, 구조화 추출의 여섯 시나리오를 예고한다. 다만 마지막 구조화 추출은 시간 관계상 별도 상세 설명 없이 끝난다.

### 2. 고객 지원 - 반환된 텍스트를 곧바로 최종 답으로 쓰지 않기 (5:53~10:55)

에이전트 루프를 순차 실행·조건 분기·반복이라는 프로그래밍 개념과 연결한다. 모델이 도구 호출의 이름과 인자를 제안하면 실제 실행은 호스트 프로그램이 담당한다.

응답의 `stop_reason`에 따라 도구 실행을 이어갈지, 정상 완료로 처리할지, 출력 한도에 걸린 결과를 복구할지 판단해야 한다. 출력이 있다는 이유만으로 완전한 답이라고 취급하는 것이 안티패턴이다. 불확실한 결과는 사람이 검토할 수 있어야 한다.

### 3. 코드 생성 - 적용 범위에 맞는 지침 (11:00~11:41)

`CLAUDE.md`를 계층적으로 두어 공통 규칙과 특정 프로젝트·디렉터리의 규칙을 구분하는 방식을 설명한다. 모든 상황을 하나의 거대한 지침으로 다루기보다 해당 작업에 필요한 규칙을 전달하는 취지다.

### 4. 연구 에이전트 - 도구와 맥락을 과잉 제공하지 않기 (11:48~14:52)

하나의 에이전트에 모든 도구와 모든 역할을 맡기면 선택이 복잡해진다. 역할을 전문화하고 필요한 도구만 주는 방식을 제안한다.

검토 에이전트에는 주장과 근거를 제공하되, 생성 과정의 모든 논의를 그대로 전달하지 않는 사례를 든다. 앞선 결론에 끌려가는 집단 동조를 줄이고 독립 검토를 돕기 위한 설계다.

### 5. 개발 생산성 - 하위 작업의 전체 출력을 합치지 않기 (15:02~17:48)

로그를 분석하는 하위 작업은 별도 컨텍스트에서 수행하고, 부모에는 문제 요약을 돌려준다. 로그 원문과 중간 출력을 전부 합치는 것은 비용과 혼란을 키우는 안티패턴이다.

긴 세션에는 컨텍스트 크기 관리와 압축이 필요하다. 발표자가 예시로 든 임계값은 모든 모델에 적용할 고정 기준이 아니다. 작업에 필요한 정보를 남기는 압축 로직을 별도로 설계할 수도 있다고 설명한다.

### 6. CI - 사람의 답을 기다리는 파이프라인 피하기 (17:56~19:33)

자동 파이프라인에서 대화형 질문이 발생하면 실행이 멈출 수 있다. 비대화형 실행에 필요한 설정을 갖추고, 즉시 결과가 필요하지 않은 작업에는 배치 처리를 검토하는 방식이다.

배치의 구체적인 가격과 처리 시간은 서비스 조건에 따르므로, 강의의 요지는 지연을 허용할 수 있는 업무를 구분하는 데 있다. 마무리에서는 직접 실험하고 실패에서 설계 패턴을 배우라고 강조한다.

## 예시

강의의 안티패턴을 점검표로 정리하면 다음과 같다.

| 상황 | 피할 선택 | 대안 |
| --- | --- | --- |
| 도구 사용 응답 | 텍스트를 곧바로 완료 결과로 처리 | 종료 이유에 따라 실행·완료·복구 분기 |
| 연구 작업 | 모든 도구를 한 에이전트에 제공 | 역할과 도구 범위 제한 |
| 결과 검토 | 앞선 논의를 통째로 전달 | 주장과 근거 중심의 독립 검토 |
| 로그 분석 | 모든 로그를 부모 대화에 합침 | 별도 분석 후 필요한 요약 반환 |
| CI | 대화형 확인을 기다림 | 비대화형 실행 설정 |

## 요약

- 모델의 도구 요청과 실제 도구 실행을 구분하고 종료 조건을 확인한다.
- 역할·도구·컨텍스트의 경계를 설계해 과잉 정보와 동조를 줄인다.
- 자동 파이프라인의 대기 지점과 긴 세션의 컨텍스트 누적을 관리한다.
