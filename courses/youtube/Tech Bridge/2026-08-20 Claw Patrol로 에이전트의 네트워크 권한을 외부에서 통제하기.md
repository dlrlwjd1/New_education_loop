# Claw Patrol로 에이전트의 네트워크 권한을 외부에서 통제하기

## 개요

- **업로드일:** 2026-08-20
- **채널:** Tech Bridge
- **발표자·출처:** Ryan Dahl / Deno
- **원본:** [YouTube](https://www.youtube.com/watch?v=w0e6vBjYq3U)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 18:32, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 에이전트를 신뢰하지 않는 소프트웨어로 보고, 프로토콜을 이해하는 외부 프록시에서 자격 증명과 실행 권한을 통제한다.

## 내용

### 장애 대응 에이전트와 신뢰 경계 (00:00–06:56)

Deno는 서비스 장애 대응에 에이전트를 활용하며 Postgres, Kubernetes, ClickHouse, AWS, GitHub, Slack의 맥락을 함께 제공한다. 쓰기 권한까지 있으면 복구할 수 있는 일이 늘지만, 지원 요청을 통한 프롬프트 주입이나 잘못된 판단으로 파괴적인 작업을 할 수도 있다.

발표자는 모델의 정렬이나 에이전트 내부 보호 기능만으로 보안을 보장해서는 안 된다고 주장한다. VM은 로컬 파일과 프로세스를 격리하지만, 실제 운영 시스템에 영향을 주는 네트워크 동작은 별도 경계가 필요하다. 여러 시스템을 경유하는 연결에서는 각 서비스의 권한이 합쳐져 예상하지 못한 접근 경로가 생길 수 있다.

### 프로토콜을 이해하는 외부 프록시 (06:56–12:53)

MCP 도구의 권한 제어만으로는 에이전트가 직접 실행하는 CLI 하위 프로세스를 모두 통제하기 어렵다. LLM 게이트웨이는 모델 호출을, HTTP 프록시는 HTTP 요청을 다루지만 Postgres 같은 다른 프로토콜도 고려해야 한다.

Claw Patrol은 에이전트 외부에서 요청을 중계하고 프로토콜별 규칙을 적용한다. 실제 자격 증명은 프록시가 보관·주입하고 에이전트에는 노출하지 않는 방식이다. 권한 규칙은 HCL 파일로 Git에서 관리하며, 지원 프로토콜은 플러그인으로 확장한다고 설명한다. 데모에서는 에이전트가 실행한 Postgres 삭제 요청을 프록시가 해석해 차단한다.

### 승인·관측·자격 증명 관리 (13:03–16:54)

대시보드는 개별 동작의 허용·거부·승인 대기와 세부 정보를 보여 준다. 규칙은 즉시 거부 외에도 LLM 판정, Slack에서의 사람 승인 또는 두 단계의 조합을 지정할 수 있다. 보호 경계는 에이전트 소프트웨어를 수정하지 않고 유지한다.

발표 당시 쿠키, Postgres, OAuth, AWS 서명 등 여러 인증 방식을 지원한다고 소개한다. Deno에서는 Tailscale의 exit node로 운용하며 대시보드 인증에도 Tailscale 신원을 쓴다. WireGuard 경로도 제공한다. 운영 자격 증명이 집중되는 프록시 자체는 엄격히 관리해야 한다.

### 정책을 테스트하는 방법 (17:10–18:32)

규칙 파일에 요청 fixture를 넣어 특정 요청이 항상 차단되는지 단위 테스트할 수 있다고 설명한다. 더 똑똑한 모델이 잘못된 동작을 줄일 수는 있어도 외부의 보안 경계는 계속 필요하다는 것이 발표자의 결론이다.

## 예시

영상의 차단 데모를 실행 흐름으로 표현하면 다음과 같다.

`에이전트 → psql 하위 프로세스 → Claw Patrol의 Postgres 해석 → 삭제 금지 규칙 → 요청 차단`

에이전트가 명령을 실행하기로 결정했더라도, 운영 DB로 전달되는 동작은 별도의 정책으로 제한한다.

## 요약

- 에이전트의 자체 판단과 실제 실행 권한의 경계를 분리한다.
- CLI·터널·비HTTP 프로토콜까지 포함한 네트워크 경로를 통제한다.
- 정책 파일, 승인 기록, fixture 테스트로 권한을 검토한다.
