# Theo가 에이전트 작업을 터미널에서 GUI로 옮긴 이유

## 개요

- **업로드일:** 2026-08-19
- **채널:** Tech Bridge
- **발표자·출처:** Theo / T3 Code
- **원본:** [YouTube](https://www.youtube.com/watch?v=ggOlrPsT5_c)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 30:11, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 여러 프로젝트와 장시간 에이전트 실행을 관리할 때 시각적 작업 목록과 원격 실행의 지속성이 인지 부담을 줄인다고 설명한다.

## 내용

### 터미널 중심 작업의 한계 (00:00–08:05)

오랫동안 터미널·tmux·SSH를 사용한 Theo는 여러 에이전트를 동시에 관리하면서 습관이 바뀌었다고 말한다. Antigravity의 에이전트 관리 화면과 Codex 앱에서 프로젝트별 스레드와 작업 트리를 한눈에 보는 경험이 계기였다.

터미널 패널마다 작업을 기억하는 방식은 병렬 작업 수가 계속 달라질 때 부담이 된다. 이미지 붙여넣기, 읽기 좋은 텍스트, 클릭으로 스레드 전환하기 같은 작은 편의가 누적되어 작업 방식에 영향을 준다고 설명한다.

### 모델 선택과 인터페이스를 분리하려는 요구 (08:08–13:30)

발표자는 공급자별 앱과 CLI의 기능 차이 때문에 모델의 적합성보다 편한 UI에 따라 선택하게 된 경험을 말한다. 원하는 기능이나 회귀를 직접 고치기 어려운 폐쇄형 도구도 불만이었다.

이미지 전달과 원격 세션 관리에 별도 설정을 많이 들이는 대신, 여러 모델을 일관된 화면에서 사용하고 싶었다는 것이 T3 Code 개발 배경이다. 제품 지원과 구독 관련 발언은 영상 당시 상태를 설명한 것이다.

### 원격 실행을 노트북 연결에서 독립시키기 (13:34–17:50)

불안정한 SSH 연결, 모바일 터미널 조작, 노트북 발열과 배터리, 이동 중 실행 중단이 문제였다. 필요한 조건으로 이미지 입력, 기존 구독 활용, Linux와 모바일 지원, 낮은 자원 사용량, 여러 작업 관리를 제시한다.

### T3 Code의 설계와 사용 경험 (17:55–25:54)

네이티브 UI 실험 뒤 긴 텍스트 렌더링 문제로 Electron을 사용하게 되었다고 설명한다. 통신을 Electron 전용 RPC 대신 WebSocket 중심으로 구성해 원격 제어를 연결했다.

공동 개발자 Julius는 작업 트리와 여러 에이전트 통합을 개선했다. 실행할 컴퓨터를 고르고 작업을 보내면 로컬 앱을 종료한 뒤에도 다른 컴퓨터·웹·모바일에서 같은 진행 상황에 다시 연결하는 흐름을 시연한다. Tailscale을 이용한 연결과 백그라운드 서비스 방식도 소개한다.

### 개발 도구를 직접 바꿀 수 있는가 (25:58–30:11)

소스에 접근할 수 있어야 에이전트로 자신의 도구를 고칠 수 있다는 것이 오픈소스 선택의 이유다. 발표자는 GUI 전환 후 처리한 PR이 늘었다는 개인 경험을 말하지만, 일반적인 생산성 비교 실험은 아니다. 결론은 자신이 다루는 작업 규모에 맞춰 에이전트 관리 인터페이스를 다시 평가하라는 제안이다.

## 예시

발표자가 강조한 원격 작업 흐름:

`노트북에서 원격 컴퓨터 선택 → 장시간 작업 요청 → 노트북 앱 종료 → 휴대폰이나 웹에서 같은 스레드 확인`

실행 장소와 사람이 보는 화면을 분리하면 이동 중에도 작업을 이어 볼 수 있다는 사례다.

## 요약

- 병렬 에이전트 작업에서는 세션을 찾고 전환하는 비용도 중요하다.
- 실행의 지속성과 모바일 접근이 장시간 작업 방식을 바꾼다.
- 영상은 T3 Code 개발자의 제품 경험과 주장을 담는다.
