# Anthropic Managed Agents - 지속 실행과 신뢰를 위한 플랫폼 설계

## 개요

- **업로드일:** 2026-09-01
- **채널:** Tech Bridge
- **발표자·출처:** Angela Jiang · Katelyn Lesse / Kleiner Perkins Builders 대담
- **원본:** [YouTube](https://www.youtube.com/watch?v=TQqa0B_pNGE)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 43:55, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 장시간 작업하는 에이전트에는 모델 외에도 복구 가능한 실행 환경, 관측 가능성, 도메인별 검증이 필요하다.

## 내용

### 짧은 호출에서 지속적인 업무로 (00:00~10:05)

에이전트가 개별 명령을 수행하는 수준을 넘어 분석 전체를 맡게 되면 오류 복구와 실행 인프라가 병목이 된다. DCF 분석 사례처럼 여러 단계의 계산과 확인을 이어 가려면 작업 상태가 유지되어야 한다. 두 발표자는 Stripe에서 API 제품을 만들었던 경험을 플랫폼 추상화와 연결한다.

### 모델의 상태와 실행 샌드박스 분리 (10:05~16:17)

Managed Agents는 공통 분산 시스템 문제를 플랫폼에 맡기고 고객이 도메인 지식·시스템 프롬프트·스킬·MCP 도구에 집중하도록 설계한다. 지속되는 에이전트 상태와 위험한 코드를 실행하는 일시적인 샌드박스를 분리해, 실행 환경이 실패해도 작업 전체가 사라지지 않게 한다.

처음에는 높은 수준의 추상화를 사용하고 필요할 때 자체 샌드박스나 낮은 수준의 제어를 선택하는 방향이다.

### 신뢰와 비용을 평가하는 단위 (16:17~23:31)

신뢰에는 실행 범위를 가두는 통제와, 결과가 올바른지 확인하는 관측 가능성이 모두 필요하다. 운영 데이터 접근 경계, 감사 가능한 실행 기록, 사내 시스템 연결을 제품의 일부로 다룬다.

비용은 토큰 단가보다 성공적으로 끝낸 업무당 비용으로 비교한다. 강한 모델이 재시도와 오류를 줄이면 전체 비용이 낮아질 수 있다. 실행 모델과 상위 모델의 자문을 조합하거나, 실행자와 평가자를 분리하는 방식도 논의한다. 과거 세션에서 메모리와 스킬을 개선하는 설명은 발표 당시의 제품·내부 평가 맥락이다.

### 하네스와 업무 설계 (23:31~33:31)

하네스에는 모델·도구 반복 호출 외에도 상태 지속, 안전한 환경, 자격 증명 처리가 들어간다. 그 위의 업무 전략은 도메인에 따라 달라진다. 은행의 KYC 전체를 한 번에 자동화하기보다 작은 작업으로 나누고 자기 검증과 예외 보고 지점을 설계하라고 제안한다.

사용자 경험도 기존 Slack 등에서 결과를 받고 필요할 때 감독하는 동료 형태로 이동할 수 있다. 실제 기업 도입에는 맞춤 시스템 연결과 엔지니어링이 여전히 필요하다.

### 팀 운영과 피드백 (33:31~43:55)

구현 속도가 빨라질수록 무엇을 누구를 위해 만들지 결정하고 팀을 조율하는 일이 중요해진다. 제품은 여러 가설을 실험하되 인프라와 보안은 엄격하게 관리한다. 내부에서도 외부와 같은 API를 사용하고, 고객 제품을 에이전트로 시험하며 얻은 피드백을 플랫폼에 반영한다.

## 예시

DCF 분석을 에이전트에 맡기는 경우를 영상의 논의에 맞춰 나누면 다음과 같다.

| 층 | 책임 |
|---|---|
| 도메인 작업 | 자료 해석, 계산 규칙, 결과 확인 |
| 에이전트 전략 | 작업 분해, 실행·평가 반복, 예외 보고 |
| 플랫폼 | 상태 보존, 샌드박스 복구, 도구 연결과 실행 기록 |
| 사람 | 업무 범위와 접근 권한 설정, 중요한 결과 판단 |

## 요약

- 장시간 에이전트의 신뢰성은 지속 상태와 복구 가능한 실행 환경에 달려 있다.
- 실행 통제와 결과 검증을 함께 설계하고 업무당 비용을 측정한다.
- 플랫폼은 공통 인프라를 맡고 고객은 도메인 판단과 검증 기준을 제공한다.
