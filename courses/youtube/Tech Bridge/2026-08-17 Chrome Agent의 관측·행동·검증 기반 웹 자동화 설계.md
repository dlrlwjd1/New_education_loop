# Chrome Agent의 관측·행동·검증 기반 웹 자동화 설계

## 개요

- **업로드일:** 2026-08-17
- **채널:** Tech Bridge
- **발표자·출처:** Chrome Agent 개발자의 웹 자동화 발표
- **원본:** [YouTube](https://www.youtube.com/watch?v=mxsJo_Jjdi8)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 21:01, 자동 자막 언어 `es-US`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 브라우저의 여러 관측 채널로 결과를 검증하고, 반복 가능한 조작은 코드로 고정해 모델 호출을 줄인다.

## 내용

### CLI와 브라우저 제어의 역할 (00:00–05:26)

발표자는 개인 업무를 브라우저 에이전트에 맡기는 과정에서 겪은 제약을 소개한다. Chrome DevTools Protocol(CDP)을 사용하는 Chrome Agent와 CLI 기반 자동화가 발표 주제다.

한 번 해결한 조작을 스크립트로 반복하면 매 클릭마다 모델을 호출하는 비용을 줄일 수 있다고 설명한다. 영상의 CLI·MCP 비교 수치는 특정 비교 사례이며, 프로토콜 자체가 모든 구현의 성능을 결정하는 것은 아니다.

브라우저를 관찰하는 채널로 DOM, 접근성 트리, 스크린샷, 네트워크와 콘솔 로그를 소개한다. 입력과 탐색은 행동 수단이다.

### 관측 → 행동 → 독립적인 검증 (05:31–08:12)

현재 상태를 관측하고 한 동작을 수행한 뒤, 다른 채널로 결과를 확인한다. 클릭 명령이 성공했다는 응답만 보지 않고 화면 변화나 네트워크 응답을 확인하는 것이 예다.

페이지 특성에 맞는 상호작용 수단을 선택하고, 탐색으로 찾은 동작 경로를 코드와 스킬로 남기는 방식을 제안한다. 이로써 불확실한 탐색과 반복 실행을 분리한다.

### 사례가 보여 주는 구현상의 차이 (08:17–19:33)

발표자는 자신이 소유한 인프라와 운영 계정에서 시연한다고 전제한다. 메일 작성 화면에서는 반복적인 입력을 코드로 처리하고 내용만 상황에 맞게 생성하는 예를 든다. 이후 합성 이벤트와 브라우저 입력의 차이, 시각적 판단이 필요한 페이지, 자동화 방어 장치에 관한 실험을 보여 준다.

이 구간에는 CAPTCHA 관련 시연도 포함된다. 학습상 핵심은 반복 제어를 코드가 맡고 시각적 해석이 필요한 순간에만 모델을 부르는 역할 분담이다. 입력 이벤트 하나의 속성이 자동화를 전혀 탐지할 수 없다는 보장을 뜻하지는 않는다.

### 재사용 가능한 자동화로 마무리 (19:37–21:01)

발표자는 모델 능력만으로 해결하려 하지 말고 관측 도구·제어 루프·재사용 코드의 조합을 설계하라고 강조한다. 실시간 제약이 있는 흐름에서는 모델 호출의 지연도 시스템 성공 여부에 영향을 준다.

## 예시

일반적인 웹 폼 자동화에 적용할 수 있는 영상의 설계 원칙:

`화면 구조 확인 → 필요한 입력 수행 → 화면·응답에서 저장 결과 확인 → 성공한 조작 순서를 재사용 코드로 보존`

내용을 판단하는 부분과 반복 입력을 실행하는 부분을 분리하고, 실행 성공 여부는 별도로 관측한다.

## 요약

- 행동 요청의 성공과 실제 페이지 결과를 구분한다.
- 반복 제어는 코드로, 필요한 해석은 모델로 나눈다.
- 탐색으로 얻은 작업 경로를 기록해야 자동화가 재사용 가능해진다.
