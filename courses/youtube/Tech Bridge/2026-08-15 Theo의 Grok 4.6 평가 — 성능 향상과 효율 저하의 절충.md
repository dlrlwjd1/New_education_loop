# Theo의 Grok 4.6 평가 — 성능 향상과 효율 저하의 절충

## 개요

- **업로드일:** 2026-08-15
- **채널:** Tech Bridge
- **발표자·출처:** Theo / T3 Code
- **원본:** [YouTube](https://www.youtube.com/watch?v=NwstOgsxstQ)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 23:49, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 벤치마크 상승과 실제 개발 경험을 나누어 보고, 토큰 효율 저하가 속도와 완료 비용에 미치는 영향을 평가한다.

## 내용

### 발표 성능과 실제 체감 (00:00–07:48)

Theo는 Grok 4.6의 장기 작업·코딩·지식 업무 개선을 소개한다. 추가 학습, 이전 모델로 만든 학습 경로, SFT와 강화학습이 개선 배경으로 설명된다. 종합 지표와 특정 코딩 벤치마크가 올라도 개인 작업에서의 유용성을 완전히 설명하지는 못한다고 강조한다.

### 단가는 같아도 완료 비용은 증가 (07:53–10:34)

당시 비교에서 주요 입력·출력 단가보다 토큰 사용량 증가가 눈에 띈다. 이전 버전의 빠르고 저렴한 특성이 약해졌다는 평가다. 더 많이 추론하면 일부 성능은 올라갈 수 있지만 응답 대기와 과제당 비용도 늘어난다.

영상의 요금·평가 점수는 당시 비교 결과다. 모델 선택에서 품질 하나로 순위를 매기기보다 비용·속도·꼼꼼함·여러 작업 조율을 구분한다.

### UI·게임 생성에서 발견한 문제 (10:38–16:13)

여러 웹 디자인에서는 오래된 템플릿 같은 배치와 일관되지 않은 시각 요소를 지적한다. 디자인 스킬을 넣어도 결과 편차가 있었다.

기존 수족관 게임을 다시 만드는 실험에서는 요소 크기, 조작, 성장 속도가 어색했다. 3D 전환은 처음에 검은 화면이 나왔고 스크린샷 피드백 뒤에도 좌우 반전과 배치 문제가 남았다. 이는 해당 프롬프트와 실행 사례의 결과이며 모델 전체의 보편적 실패율은 아니다.

### 실제 저장소 분석과 장기 변경 (16:16–20:46)

보안 감사에서는 Git의 이전 감사와 연결해 여러 실질적인 문제를 찾았으나 더 깊은 문제 일부는 놓쳤다고 평가한다. T3 Code의 Cursor 통합 방식 분석과 Grok 지원 보완 작업도 보여 준다.

큰 PR을 만든 뒤 리뷰 피드백을 처리하고, 실행 기록에서 빠진 이벤트를 찾아 후속 PR로 연결하는 흐름에서는 긴 맥락을 유지하는 능력을 긍정적으로 본다. 동시에 계획 모드나 이벤트 표시 문제 중 일부는 모델 자체와 별개인 하네스 통합의 문제로 드러난다.

### 최종 판단 (20:50–23:49)

지능·검토·조율은 개선됐지만 이전 버전의 차별점이던 속도와 비용은 약해졌다는 것이 결론이다. 후속 모델에 대한 기대는 남기지만 영상 당시 자신의 기본 모델로 채택할 정도는 아니라고 말한다.

## 예시

| 평가 축 | 영상에서의 관찰 |
|---|---|
| 벤치마크 | 이전 버전 대비 상승 |
| 작업당 비용·속도 | 토큰 사용 증가로 효율 약화 |
| 시각·게임 제작 | 배치와 동작 오류 발생 |
| 저장소 분석·후속 PR | 긴 작업과 피드백 처리는 비교적 양호 |

서로 다른 축을 하나의 '최고 모델' 점수로 합치지 않는 것이 평가의 요지다.

## 요약

- 높은 벤치마크 점수와 선호하는 작업 경험은 다를 수 있다.
- 토큰 사용량은 완료 비용과 지연 시간을 함께 바꾼다.
- 모델 오류와 하네스 통합 문제를 구분해 진단한다.
