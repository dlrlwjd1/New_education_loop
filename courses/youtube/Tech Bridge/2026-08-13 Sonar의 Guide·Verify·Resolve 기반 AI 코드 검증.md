## 개요

- **업로드일:** 2026-08-13
- **채널:** Tech Bridge
- **발표자·출처:** Anirban Chatterjee / Sonar
- **원본:** [YouTube](https://www.youtube.com/watch?v=2Xkq2twywp4)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 21:57, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 코드 생성 속도에 맞춰 독립적인 검증과 수정 루프를 개발 과정과 CI/CD에 넣는 방법을 설명한다.

## 내용

### 생성 속도와 검증 부채 (00:00–08:58)

발표자는 AI 도입 뒤 코드 생산량이 늘어도 복잡성과 정적 분석 경고가 누적되면 장기 생산성을 해칠 수 있다는 연구를 소개한다. 필요한 품질과 기본 생성 결과의 차이를 검증 부채로 설명한다. 개인 실험과 대규모 운영 서비스는 요구 품질이 다르다.

모델별로 정확성·유지보수성·신뢰성·보안의 강점이 다르며, 사람이 AI의 자신 있는 설명을 그대로 받아들이는 것도 문제라고 말한다. 소개한 연구에서 코드 리뷰로 확장한 부분은 발표자의 해석이다.

### 독립적이고 다층적인 검증 (09:02–11:45)

코드가 사람과 어느 모델 중 어디서 나왔든 같은 기준을 적용한다. 생성에 사용한 방식과 다른 분석 기법, 반복 가능하고 설명할 수 있는 검사, 여러 층의 도구를 조합하자는 제안이다. 정적 분석과 AI 검토 어느 하나로 모든 문제를 찾을 수는 없다.

AC/DC(Agent-Centric Development Cycle)는 **Guide → Verify → Resolve**의 반복이다. 필요한 맥락과 제약을 제공하고, 결과를 검증하고, 발견한 문제를 에이전트가 수정해 다시 검사한다.

### 조직의 기준과 제품 구성 (11:51–16:42)

팀과 도구가 달라도 일관된 기준을 적용하고, 보안 문제를 일찍 찾으며 검증 기록을 남기는 필요성을 설명한다. SonarQube, AI 리뷰·CI 자동화, Sonar Vortex, 기존 결함을 처리하는 remediation agent를 소개한다.

기준에는 아키텍처, 허용 의존성, 코딩 패턴, 로그·관측 방식, 품질 통과 조건이 포함된다. 자동 수정·승인·병합은 신뢰와 설정에 따라 단계적으로 활성화하는 기능으로 설명하며 처음부터 무조건 수행한다고 하지 않는다.

### 내부 개발 루프와 외부 CI/CD 루프 (16:46–21:57)

작업 시작에는 전체 저장소를 무조건 넣기보다 관련 맥락을 전달한다. 에이전트가 초안을 작성한 즉시 분석해 결함이 다음 작업에 전파되기 전에 고친다. 이후 PR에서는 다시 전체 변경의 품질·보안·유지보수성을 검증하고 테스트·빌드·배포로 이어진다.

시연에서는 Cursor가 맥락 도구와 검증 도구를 호출하고 지적을 수정한 뒤 재분석한다. 결론은 생성의 자율성과 공통 검증 체계를 함께 설계하자는 것이다. 제품 도입 효과와 지원 범위는 공급자의 발표 내용으로 기록한다.

## 예시

| 단계 | 내부 에이전트 루프 | 외부 CI/CD 루프 |
|---|---|---|
| Guide | 관련 코드 맥락과 작성 기준 | 조직의 품질·아키텍처 기준 |
| Verify | 초안 직후 문제 분석 | PR 전체의 다층 검사 |
| Resolve | 에이전트가 수정·재검사 | 발견한 결함을 고친 뒤 통과 확인 |

## 요약

- 생산량 증가에 맞춰 검증 역량도 확장해야 한다.
- 생성 도구와 독립적인 다층 검사를 조합한다.
- 초안 단계와 PR 단계 모두에서 기준·검증·수정을 반복한다.
