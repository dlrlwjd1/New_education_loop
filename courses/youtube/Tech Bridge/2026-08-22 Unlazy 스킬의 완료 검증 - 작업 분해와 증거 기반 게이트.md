# Unlazy 스킬의 완료 검증 - 작업 분해와 증거 기반 게이트

## 개요

- **업로드일:** 2026-08-22
- **채널:** Tech Bridge
- **발표자·출처:** AI Labs / Unlazy 스킬 분석·수정 시연
- **원본:** [YouTube](https://www.youtube.com/watch?v=Hnm18BesInM)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 11:29, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 완료했다는 문장 대신 작업별 검증 명령과 실제 결과를 남기고 상위 단계에서 다시 확인하는 접근이다.

## 내용

### 조기 종료와 숨은 범위 축소 (00:00~04:24)

여러 파일 중 일부만 확인하거나 어려운 요구를 빼고도 완료했다고 말하는 문제를 다룬다. 단순한 완료 문구나 대화 내용만 읽는 판정은 실제 산출물의 상태와 다를 수 있다. 영상의 “게으름 해결” 표현은 홍보적인 이름이며 실패가 완전히 제거되었다는 실증 결과는 아니다.

### 작업 트리와 파일로 남기는 기준 (04:24~07:25)

큰 요구를 의미 있는 작업으로 나누고 각 작업에 완료 조건을 둔다. 영상에서 소개한 버전은 깊이에 따라 같은 세션에서 처리하거나 별도 에이전트로 위임한다. 너무 작은 단위로 쪼개지 않도록 조절한다.

게이트 파일에는 기대 결과, 이를 검사할 명령, 기대 출력, 실제 증거를 둔다. 체크박스가 선택되어 있어도 증거가 대기 상태이면 통과로 보지 않는다. 파일에 기준을 남겨 긴 대화에서 요구가 사라지는 문제를 줄인다.

### 재검증과 미완료 보고 (07:25~09:23)

하위 작업이 끝났다고 보고하면 상위 실행자가 실제 검사를 다시 수행한다. 충족할 수 없는 조건은 이름과 이유를 남겨 최종 보고에 포함한다. 확인된 통과와 미완료를 구분하는 것이 핵심이다. 스킬 설치와 프로젝트 범위 설정도 시연한다.

### 순차 실행의 병목 개선 (09:23~11:29)

초기 테스트에서는 하위 에이전트를 쓰더라도 한 작업씩 기다려 오래 걸렸다고 설명한다. 발표자는 독립 작업을 병렬로 실행하도록 수정하고, 계획에 파일별 작업 범위를 적어 덮어쓰기를 줄인다. 쉬운 작업과 어려운 작업을 다른 모델에 배정하는 방안도 제시한다. 제시된 소요 시간은 특정 데모 앱의 결과이며 병렬 수를 늘리면 항상 빨라진다는 의미는 아니다.

## 예시

게이트 기록의 구성:

| 항목 | 역할 |
|---|---|
| 기대 결과 | 무엇이 되어야 완료인가 |
| 검사 명령 | 산출물에서 어떻게 확인하는가 |
| 기대 출력 | 어떤 결과를 통과로 보는가 |
| 실제 증거 | 실행해서 무엇을 확인했는가 |
| 미충족 이유 | 남은 조건과 해결하지 못한 이유 |

검사가 요구의 의미를 잘 대변해야 하며 단순한 문자열 일치만으로 모든 제품 품질을 증명할 수는 없다.

## 요약

- 완료 주장과 실제 검증 증거를 구분한다.
- 요구·기준을 파일로 남기고 위임 결과를 다시 확인한다.
- 병렬화는 독립성과 파일 충돌을 고려해 적용한다.
