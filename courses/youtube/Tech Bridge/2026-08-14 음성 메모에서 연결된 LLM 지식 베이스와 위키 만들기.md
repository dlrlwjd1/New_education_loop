# 음성 메모에서 연결된 LLM 지식 베이스와 위키 만들기

## 개요

- **업로드일:** 2026-08-14
- **채널:** Tech Bridge
- **발표자·출처:** Hubble·Warp·Oz를 활용한 지식 관리 발표
- **원본:** [YouTube](https://www.youtube.com/watch?v=IpyEKxGlibI)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 19:17, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 원시 메모를 쉽게 모으고 태그·출처·관련 링크를 보강한 뒤 위키와 시각화로 탐색한다.

## 내용

### 원시 생각을 먼저 남기기 (00:00–04:49)

흩어진 메모를 완벽히 정리하려다 기록 자체를 놓치는 문제에서 출발한다. Markdown 폴더를 원자료로 삼고 원하는 뷰어를 사용한다. 발표자는 Hubble 앱을 보여 주지만 특정 뷰어가 필수는 아니다.

음성 입력으로 독서·팟캐스트·회의 후 생각을 빠르게 남긴다. Handy와 VoiceInk 같은 로컬 전사 도구를 소개하며 처음부터 문장을 완벽히 다듬기보다 원재료를 확보하는 것을 강조한다.

### Enrich Note — 메타데이터와 연결 보강 (04:53–08:19)

스킬이 기존 메모에 주제 태그, 원본 출처, 보강 시각, 관련 메모 링크를 더한다. 미리 관리하는 태그 목록을 사용해 비슷한 새 태그가 무한히 늘지 않게 한다.

처리 시각은 다음 실행에서 아직 보강하지 않은 메모를 찾는 표시가 된다. 키워드 검색으로 관련 메모를 연결하면 과거에 어디에 적었는지 기억하지 않아도 링크를 따라갈 수 있다.

### 원자료 위에 주제별 위키 구축 (08:26–12:47)

관심 분야를 정하고 원자료에서 인물·조직·개념·출처 페이지를 구성한다. AI와 음악의 교차 주제, 독서 속 인물처럼 원래 메모의 연결을 다시 발견하는 예를 든다.

합성된 위키에서 원시 메모와 출처로 돌아갈 수 있게 한다. 업무에서는 사람별 회의와 고객 관련 내용을 찾아보는 방식으로 응용할 수 있다고 설명한다.

### 주기적인 보강과 동기화 (12:50–17:08)

수동 실행에서 시작한 스킬을 일간·주간 작업으로 옮긴다. 발표의 클라우드 구성은 Markdown을 샌드박스로 동기화 → 미처리 메모 보강·위키 갱신 → 다시 동기화하는 흐름이다. Obsidian headless CLI를 사용하며 Git으로도 같은 기본 구조를 만들 수 있다고 말한다.

로컬 예약 작업은 실행 컴퓨터의 가용성에 의존한다. 클라우드에서는 별도 실행 환경과 자료 동기화가 필요하다.

### 시각화로 연결과 빈틈 보기 (17:12–19:17)

에이전트에게 HTML 기반 그래프를 만들어 메모를 주제별로 묶고 클릭하면 원문을 열게 한다. 작성 습관을 보는 달력형 차트도 소개한다. 시각화는 장식뿐 아니라 관심의 집중과 생각의 빈틈을 발견하는 탐색 도구다.

## 예시

`음성 메모 → Markdown 원자료 → 기존 태그·출처·관련 링크 보강 → 관심 분야 위키 → 클릭 가능한 관계 그래프`

반복 실행에서는 보강 시각을 확인해 새로 들어온 메모를 처리한다.

## 요약

- 기록의 진입 장벽을 낮추고 정리는 후속 작업으로 분리한다.
- 태그 규칙과 처리 표시로 반복 작업의 일관성을 유지한다.
- 위키와 그래프에서 원자료로 돌아가는 연결을 남긴다.
