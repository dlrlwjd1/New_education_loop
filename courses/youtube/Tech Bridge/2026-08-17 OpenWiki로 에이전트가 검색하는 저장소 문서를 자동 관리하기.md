# OpenWiki로 에이전트가 검색하는 저장소 문서를 자동 관리하기

## 개요

- **업로드일:** 2026-08-17
- **채널:** Tech Bridge
- **발표자·출처:** Brace Sproul / LangChain
- **원본:** [YouTube](https://www.youtube.com/watch?v=S_PeI8JUqMg)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 16:32, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 에이전트가 필요한 문서 조각을 빠르게 찾도록 구조화하고 Git 변경에 따라 위키를 갱신한다.

## 내용

### 생성보다 유지와 검색 (00:00–03:55)

OpenWiki는 저장소 문서를 생성·유지하는 CLI다. 범용 기억이라는 큰 문제에서 코드베이스 문서처럼 범위가 분명한 영역부터 시작했다. 에이전트가 소비하기 좋은 문서, 쉬운 설치, 자동 갱신을 주요 목표로 둔다.

에이전트는 문서 전체보다 일부 조각을 검색하므로 각 내용은 독립적으로 이해할 수 있어야 한다. 정확하고 예측 가능한 제목, 한 파일의 명확한 주제, 불필요하게 큰 문자열을 배제한 구성이 중요하다.

### Markdown과 OKF 메타데이터 (04:09–08:44)

초기 설정은 모델·키·저장소 설명을 받고 위키, 에이전트 지침, GitHub Actions를 만든다. `quickstart.md`는 전체 지도를, 디렉터리별 인덱스는 해당 범위를, 변경 로그는 최근 갱신 내용을 제공한다.

발표 당시 OKF(Open Knowledge Format)의 유형·제목·설명·리소스·태그·타임스탬프 같은 frontmatter를 적용한다. 구조화된 필드는 필터와 검색을 돕고, 문서 간 링크는 관련 맥락으로 이동하게 한다.

### 초기 평가와 사람을 위한 수정 (08:47–11:21)

약 20개 코드 작업에서 위키 사용 전후를 비교했으며 도구 호출·검색·토큰이 줄고 성공 과제가 소폭 늘었다고 보고한다. 초기 소규모 결과로 제시하며 일반적인 효과를 확정하지 않는다.

처음에는 에이전트만 읽는다고 가정했지만 사람도 문서를 원했다. 이에 흐름도와 상태도 등을 추가했다. 사람의 이해에 도움이 되었으나 에이전트 성능 개선은 별도로 검증하지 않았다고 말한다.

### 초기화와 증분 갱신 (11:25–16:32)

초기화 에이전트는 현재 코드뿐 아니라 Git 기록을 보고 문서를 작성한다. 후처리는 형식을 검증하고 인덱스·로그·메타데이터를 정리한다.

정기 갱신은 마지막 실행 이후 변경이 없으면 생략한다. 변경이 있으면 커밋 기록을 읽어 위키를 수정하고 PR을 연다. 사람은 변경을 검토해 병합한다. 향후 과제로 큰 저장소 평가, 더 나은 프롬프트, 전용 검색·필터 도구를 제시한다.

## 예시

`Git 변경 감지 → 마지막 갱신 이후 커밋 분석 → 관련 문서 수정 → OKF 형식 검사·인덱스 갱신 → PR → 검토·병합`

문서가 자동 생성된다는 것과 변경이 자동 병합된다는 것은 다른 단계다.

## 요약

- 문서 조각이 독립적으로 이해되고 검색될 수 있어야 한다.
- 메타데이터와 링크는 생성된 지식을 찾는 비용을 줄인다.
- 변경 감지와 PR을 통해 문서 유지 작업을 반복 가능하게 만든다.
