# Warp Oz의 클라우드 에이전트 플랫폼 - 실행 환경과 협업 구조

- **업로드일:** 2026-08-28
- **채널:** Tech Bridge
- **발표자·출처:** Sophia / Warp 개발자 도구 강연
- **원본:** [YouTube](https://www.youtube.com/watch?v=6SBCO0vg1UM)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 20:17, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 클라우드 에이전트 플랫폼은 실행 환경·하네스·결과물을 연결해 사용자의 의도를 검토 가능한 소프트웨어로 바꾼다.

## 내용

### 로컬 도구에서 클라우드 작업으로 (00:00~04:47)

Warp 터미널에서 로컬 AI 작업을 거쳐 장시간 클라우드 작업으로 이동한 배경을 설명한다. 플랫폼은 클라우드 인프라의 복잡성을 사용자에게 그대로 노출하지 않아야 한다. 관리형 샌드박스는 진입을 쉽게 하지만 실제 기업의 보안·개발 환경에는 고객 소유 인프라도 필요하므로 자체 호스팅 실행을 함께 지원하는 방향이다.

### 여러 하네스와 일관된 결과물 (04:47~09:58)

Claude Code·Codex·자체 하네스 등 선택의 자유를 주면서 대화 상태 저장·복원, PR·이슈·파일 같은 산출물의 표현은 일관되게 유지한다. 조사·계획, 구현, 검증을 다른 에이전트에 맡길 수 있다. 프롬프트를 통한 위임뿐 아니라 에이전트·하위 에이전트·환경·산출물을 다루는 API를 제공해 자체 업무 도구를 만들게 한다.

내부에서는 이 SDK로 소셜 미디어 언급을 분석하고 답변을 제안하는 봇, 제품 질문과 경쟁 분석 도구 등을 만들었다고 소개한다.

### 오픈소스 기여를 처리하는 구조 (10:02~14:17)

이슈가 들어오면 에이전트가 코드와 맥락을 조사하고 필요한 정보를 질문한다. 초기 명세·작업·구현·리뷰를 지원하며 여러 검토 반복을 거친 PR을 사람에게 전달한다. 목적은 PR 수만 늘리는 것이 아니라 기여자의 의도를 구체화하고 사람의 검토 부담을 줄이는 것이다. 실제 사례와 피드백으로 이 과정도 개선한다.

### 공장보다 작업장의 관점 (14:23~20:17)

도예가가 손잡이·유약·검사 절차와 작업장 배치를 함께 설계한 이야기를 들려준다. 소프트웨어 개발도 사람의 세부적인 의도를 반복 가능한 체계로 옮기는 일이라고 본다. 사건에 반응하는 자동화, 관측 가능성, 지속적인 개선, 실패와 토큰 비용의 절감이 필요하다. 비개발자의 도메인 지식도 이런 구조를 통해 소프트웨어로 구현할 수 있다는 결론이다.

## 예시

영상의 오픈소스 처리 흐름:

`새 이슈 → 저장소 조사·추가 질문 → 명세와 작업 구체화 → 구현 → 에이전트 검토 반복 → 사람의 리뷰`

각 단계의 실행 환경과 하네스는 달라도 상태와 산출물을 조회하는 방식은 플랫폼 차원에서 통일한다.

## 요약

- 관리형 실행과 고객 인프라를 모두 고려해야 실제 팀에 맞출 수 있다.
- 여러 하네스의 유연성과 플랫폼 경험의 일관성을 함께 설계한다.
- 자동화의 가치는 사람의 의도를 구현하고 반복적인 부담을 줄이는 데 있다.
