# Exa의 AI 기반 GTM - 고객 데이터, Jeffbot, FDE

## 개요

- **업로드일:** 2026-08-28
- **채널:** Tech Bridge
- **발표자·출처:** Jeffrey Wang / Exa 공동 창업자
- **원본:** [YouTube](https://www.youtube.com/watch?v=GBg-fY82y84)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 18:16, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 시장 진출 업무를 고객과 제품에 대한 데이터 문제로 보고 API·화면·에이전트를 함께 구축한다.

## 내용

### 제품과 유통을 함께 만들기 (00:00~05:10)

좋은 제품과 고객에게 전달하는 GTM(go-to-market)은 모두 필요하다. 잠재 고객 조사, 담당자 탐색, 사용 사례 파악, POC 제작은 내부 사용 데이터와 외부 기업·인물·뉴스 데이터를 연결하는 문제다. 에이전트가 행동할 수 있도록 계속 갱신되는 시장의 모델을 만들자는 접근이다.

### 두 화면과 두 에이전트 (05:10~09:58)

- **ICP 대시보드:** 이상적 고객군과 시장을 분류하고 기업별 정보·잠재 지출 등을 탐색한다.
- **Request Lens:** 가입, 사용 급증·중단, 중요한 고객의 등장 같은 신호를 알린다.
- **코딩 에이전트:** 영업팀이 고객을 조사하고 데모를 만들 때 이용한다.
- **Jeffbot:** 창업자의 문체와 과거 판단을 참고해 답변·의사결정 초안을 만든다.

Jeffbot은 약 760개 이메일에서 문체를 분석하고 Slack·이메일에 남은 과거 결정으로 평가 자료를 구성했다. 단순히 말투를 흉내 내는 것과 의사결정을 평가하는 것을 구분한다.

### API와 고정 화면의 공존 (09:58~13:07)

에이전트가 데이터를 사용할 프로그램 인터페이스가 필요하다. API·MCP·CLI 중 이름보다 접근 가능성이 중요하다. 반복 작업에는 익숙한 고정 GUI가 유용하고, 탐색적인 질문에는 유연한 대화형 에이전트가 유용하다.

직접 개발과 SaaS 구매를 양자택일로 보지 않는다. Exa는 Salesforce의 데이터 구조를 활용하면서 MCP로 에이전트를 연결한다. 핵심은 업무에 맞게 확장할 수 있는가다.

### 운영 조직과 권한 구분 (13:07~18:16)

영업 담당자는 도구 사용 교육을 받고, FDE는 고객 거래 지원과 내부 AI 시스템의 기능 개발·유지보수를 함께 맡는다. 발표자는 당시 조직 규모에서 효과적인 모델이라고 설명하며 영구히 모든 역할이 합쳐질 것이라고 단정하지 않는다.

질의응답에서는 Jeffbot의 권한을 구분한다. 창업자가 호출할 때와 다른 직원이 호출할 때 접근 가능한 도구가 다르며, 다른 직원에게는 메시지 초안 작성 등으로 제한한다. 창업자의 모든 권한을 전 직원에게 그대로 제공하는 구조가 아니다.

## 예시

고객의 검색 사용량이 급감한 경우:

`Request Lens 신호 → ICP·사용 이력 확인 → 에이전트로 계정 조사 → 대응 메시지 또는 데모 초안 → 영업 담당자의 판단`

Jeffbot 평가 자료는 과거 Slack·이메일의 결정 사례에서 만들고, 호출자별로 실행 가능한 도구를 구분한다.

## 요약

- GTM은 내부·외부 데이터를 연결해 고객 행동을 이해하는 문제다.
- 고정 GUI와 유연한 에이전트는 서로 다른 역할을 한다.
- 과거 결정 기반 평가, 사용자별 권한, FDE의 유지보수가 실제 운영을 뒷받침한다.
