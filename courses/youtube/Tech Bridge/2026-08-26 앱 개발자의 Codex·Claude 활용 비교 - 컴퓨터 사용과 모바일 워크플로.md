# 앱 개발자의 Codex·Claude 활용 비교 - 컴퓨터 사용과 모바일 워크플로

## 개요

- **업로드일:** 2026-08-26
- **채널:** Tech Bridge
- **발표자·출처:** Chris / 생산성 앱 개발자 개인 사용기
- **원본:** [YouTube](https://www.youtube.com/watch?v=uogfQG6JZwA)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 20:40, 자동 자막 언어 `de-DE`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 코드 품질 외에도 실제 화면 검증, 모바일 접근, 업무 연결성이 도구 선택에 큰 영향을 준다는 경험담이다.

## 내용

### 전환의 이유는 사용자 경험 (00:00~03:38)

발표자는 상위 모델의 코딩 결과가 전반적으로 비슷했다고 평가하면서 컴퓨터 사용과 모바일 경험 때문에 Codex를 주 도구로 바꿨다고 설명한다. Claude도 디자인과 어려운 문제에 계속 사용한다. 점수와 모델 순위는 개인 평가다.

### 실제 화면을 다루는 사례 (03:38~09:04)

iOS 시뮬레이터의 길게 누르기·드래그, iPhone과 Watch의 동기화 확인, 서비스 대시보드 설정 등을 소개한다. 빌드 도구와 화면 조작을 조합해 코드 변경 후 실제 동작까지 확인하는 방식이다.

항공권 사례에서는 검색 결과에 있는 가격만 믿지 않고 자신의 조건에서 실제 이용 가능한지 확인한 점을 강조한다. 컴퓨터 사용은 많은 토큰을 소비했고 별도의 정량 벤치마크는 하지 않았다고 밝힌다.

### 모바일에서 업무를 이어 가기 (09:04~12:19)

휴대전화에서 새 작업을 시작하고 이메일·코드·시뮬레이터를 연결하는 흐름을 설명한다. 고객의 버그 신고를 읽고 수정·테스트한 뒤 답장 초안까지 만드는 것이 예다. 개발과 일반 업무가 섞이는 개인 개발자에게 통합된 경험이 유용했다고 말한다.

### 모델별 역할과 비용 판단 (12:19~20:40)

일상 구현, 디자인, 해결되지 않는 복잡한 문제에 서로 다른 모델을 사용한다. 큰 작업에는 다른 모델의 두 번째 검토를 받아 새로운 관점을 찾는다. 가장 높은 추론 설정이 모두에게 필요한 것은 아니며 작은 설정·요금제에서 시작해 필요할 때 올리라고 제안한다.

발표자는 당시 여러 구독에 월 600달러를 지출했다고 설명한다. 구독이 보조금으로 유지되며 향후 비싸질 수 있다는 논의는 본인의 추정이고, 기업의 실제 원가나 미래 가격을 입증한 자료는 제시하지 않는다. 노트의 요점은 가격 예측보다 자신의 사용량과 얻는 가치를 비교하는 데 있다.

## 예시

영상의 모바일 버그 대응 사례:

`사용자 이메일 확인 → 저장소에서 원인 조사 → 수정 → 빌드 도구·시뮬레이터로 확인 → 결과와 답장 초안`

모델 비교는 같은 업무를 수행한 결과와 검토 부담을 기준으로 하고, 개인의 선호 점수를 일반적인 성능 순위로 바꾸지 않는다.

## 요약

- 도구 선택에는 코딩 외의 업무 연결성과 실제 검증 경험도 중요하다.
- 모델을 역할별로 쓰고 필요한 경우 서로 다른 모델로 검토한다.
- 구독·설정은 실제 사용량과 가치에 맞추며 가격 전망과 확인된 사실을 구분한다.
