# [한글자막] 1,000시간 넘게 배운 Claude를 15분 만에 익혀보세요 (초보부터 프로까지)

## 개요
- 업로드일: 2026-06-30
- 원본: https://www.youtube.com/watch?v=DQbpvuVN0SI
- 채널: Tech Bridge (해외 기술 강연/노하우 영상에 한글자막을 붙여 소개하는 채널)
- 발표자: Dan Martell (Claude를 1,000시간 넘게 사용하며 툴 제작·워크플로 자동화·자율 시스템 구축에 활용해 온 사업가)
- 핵심 주제: Claude 사용자를 아마추어부터 에이전트 오케스트레이터(agent orchestrator)까지 **6단계 레벨**로 나누고, 각 레벨에서 바로 써먹을 수 있는 구체적인 프롬프트·기능·워크플로를 소개한다.

## 내용
### 레벨 1 — 아마추어(the amateur): 챗봇처럼 쓰는 단계
- Claude를 "고급 구글 검색창"처럼 쓴다. 질문 하나, 답 하나 받고 탭을 닫는다. 메모리도, 프로젝트(projects)도 없어서 Claude가 지금 무슨 작업을 하고 있는지 전혀 모른다. 발표자는 이를 "NASA 슈퍼컴퓨터로 2+2를 계산하는 것"에 비유하며, Claude 기능의 5% 정도만 쓰는 셈이라고 말한다.
- 레벨업 팁 두 가지
  1. **먼저 인터뷰하게 만들기** — "답하기 전에, 이 작업을 제대로 수행하는 데 필요한 질문을 나에게 먼저 해줘"라고 요청하면, Claude가 필요한 맥락을 확보하기 위한 질문을 던진다.
  2. **스스로 검토하게 만들기** — "네 작업을 검토해줘(check your work)"라고 요청하면 Claude가 자기 실수를 스스로 잡아내며 더 나은 결과물을 준다.

### 레벨 2 — 레귤러(the regular): 프로젝트로 기억을 만드는 단계
- Claude를 하나의 **작업 공간(workspace)**처럼 쓴다. 그냥 채팅하는 게 아니라 **프로젝트(Projects)** 기능을 자신의 역할·이니셔티브·클라이언트·워크플로 단위로 만들어 쓴다. 그러면 Claude가 다시 돌아올 때마다 "내가 누구인지" 기억하기 때문에 결과물의 질이 올라간다.
- 설정 절차
  1. 왼쪽 메뉴에서 새 프로젝트(create a new project)를 만들고, 이름을 자신이 맡은 **역할**로 짓는다(예: "마케팅").
  2. 그 역할을 위한 **마스터 프롬프트(master prompt)**를 만든다. Claude에게 "내 역할(마케터)을 위한 마스터 프롬프트를 만들기 위해 나를 인터뷰해줘"라고 요청하면, Claude가 질문을 던지고 답변을 바탕으로 파일 하나를 만들어 준다. 마스터 프롬프트는 일하는 방식, 팀 구성, 사용 도구 등 나에 대한 모든 맥락을 담은 지침 문서다.
  3. 이 마스터 프롬프트와 관련 자료(샘플 데이터, 예시, 프로세스 문서 등)를 프로젝트의 파일(files) 디렉터리에 추가한다. 이렇게 하면 기억과 맥락, 고유한 워크플로를 가진 전용 공간이 완성된다.
  - 발표자는 유튜브 영상을 만들 때마다 쓰는 프로젝트 폴더를 예로 든다. 파일에는 자신의 목소리(voice) 문서, 브랜딩 문서, 좋아하는 과거 스크립트 예시를 넣어두어, 별도 설명 없이도 자신의 과거 방식대로 개요(outline)를 뽑아준다고 한다.
- 심화 팁: **시스템 프롬프트(system prompt)** — "이 워크플로를 위한 시스템 프롬프트를 만들기 위해 나를 인터뷰해줘"라고 요청한다. 마스터 프롬프트가 "재료(나에 대한 모든 맥락)"라면, 시스템 프롬프트는 "레시피(과정·지침)"에 해당한다. 이미 갖고 있지만 문서화하지 않았던 프로세스를 Claude가 인터뷰로 끄집어내 문서로 만들어주면, 이를 프로젝트의 커스텀 지침(custom instructions)에 붙여넣어 매번 같은 품질·같은 형식으로 작동하게 만든다.

### 레벨 3 — 인티그레이터(the integrator): 도구를 연결하는 단계
- Claude를 실제 업무가 이루어지는 도구들에 연결한다. 이메일을 복사해서 Claude에 붙여넣는 대신, Claude가 직접 가서 이메일을 가져오게 하는 식이다.
- 운영 방법
  1. **커넥터(connectors)** 사용 — Gmail, Drive, Slack, Notion 등 연결 가능한 데이터 시스템을 모두 연결해, 채팅 중 필요할 때 Claude가 해당 자료를 검색하게 한다.
  2. **시각화(visualizations) 만들기** — 그래프, 막대그래프, 목업 등을 채팅 안에서 바로 생성한다.
  3. **인터랙티브 아티팩트(artifacts)** 만들기 — 클릭·슬라이더·버튼 같은 상호작용이 가능한 작은 미니 앱 형태의 결과물을 만들어, 학습이나 데이터 시각화를 훨씬 쉽게 한다.
  - 잘 알려지지 않은 고급 활용: 텍스트를 채팅에 붙여넣고 이를 **컴포저(composer)**(채팅 안의 구글 독스 같은 편집 공간)에 넣어달라고 하면, 그 안에서 직접 편집하며 원하는 결과물을 만들 수 있다.
- 발표자의 실제 사용 예: Drive·Slack·캘린더·이메일에 Claude를 연결해두고, "내 캘린더 봐줘, 뭘 놓치고 있는지 알려줘", "이메일 봐줘, 내가 알아야 할 걸 알려줘", "나는 회사 CEO야. 지난 1주일 Slack을 훑어서 회사 전반에 대한 CEO 수준의 이해를 정리해줘" 같은 요청을 거의 매일 한다.
- 심화 팁: 크롬(Chrome)에 Claude를 설치해 쓴다. 채팅에서 "지시사항을 써줘"라고 받은 다음, 그 지시사항을 Chrome 안의 Claude에 붙여넣으면 해당 사이트에서 실제 작업을 대신 수행한다.

### 레벨 4 — 오퍼레이터(the operator): 방향을 지시하는 단계
- 직접 실행자(doer)에서 벗어나 **감독자(director)**가 되는 단계다. 인간이 루프 안에 있는(human in the loop) 구조로, 오퍼레이터는 스스로 작업을 실행하는 대신 자동으로 돌아가는 작업을 설정해두고 검토·승인만 한다.
- 오퍼레이터가 Claude를 배치하는 세 가지 방법
  1. **시스템 프롬프트** — Claude의 인터뷰를 통해 각 산출물 유형에 맞는 시스템 프롬프트를 만들어 둔다. 발표자는 앞으로 팀·회사의 지적 재산(IP)과 가치는 "자신들이 만드는 것들에 대해 정의된 시스템 프롬프트를 얼마나 갖고 있는가"에서 나온다고 말한다.
  2. **스킬(skills)** — 반복하는 워크플로를 스킬로 저장해둔다. Claude에는 재무·마케팅 등 다양한 기성 스킬이 이미 많이 있지만, 회사 고유의 작업은 슬래시 명령을 만들고 이름을 붙여 실행한 뒤 스킬로 만든다. 발표자의 원칙은 "일주일에 3번 이상 하는 일이면 스킬로 만든다"는 것. 예: 회사의 각종 분석·지표·보고서·업데이트를 종합해 간결한 현황 요약을 주는 "company status" 스킬을 만들어 `/company status`만 입력하면 매번 실행되게 했다.
  3. **스케줄링·Co-work 작업** — Co-work는 컴퓨터에서 작업을 대신 실행할 수 있는 앱으로, 예를 들어 한 시스템에서 다른 시스템으로 마이그레이션하는 작업을 실행시켜 놓고 자리를 비웠다가 돌아와서 완료된 것을 확인할 수 있다. 좋은 오퍼레이터는 자신의 시스템 프롬프트와 스킬을 살펴보며 "이 중 반복 가능한 산출물을 Co-work로 매일 자동 실행할 수 있을까?"를 점검한다. 발표자는 매일 밤 8시에 다음 날 이메일·캘린더를 정리한 메시지를 받도록 설정해, 비서가 있어도 필요 없을 만큼 자동화했다고 한다.
  - 심화 팁: **스킬 체이닝(chaining skills)** — 예를 들어 자신의 목소리로 글을 쓰는 카피라이팅 스킬과 이메일 작성 스킬이 각각 존재하고, 이 두 스킬을 다시 인박스 자동화라는 또 다른 스킬이 호출하는 식으로, 독립적으로 패키징된 여러 스킬(작은 에이전트처럼)이 서로 연결되어 하나의 파이프라인을 이룬다.

### 레벨 5 — 빌더(the builder): Claude Code로 직접 만드는 단계
- Claude로 코드를 작성해 커스텀 앱, 대시보드, 내부 툴을 직접 만드는 단계. 발표자는 회사를 이틀간 멈추고 전 직원이 참여하는 AI 해커톤을 열어 모두가 코딩하는 법을 배우게 했고, 그 결과 팀 전체가 빌더가 되었다고 소개한다.
- **Claude Code** 안에서 만들 수 있는 세 범주
  1. **루프(loops)** — 서버 위에서 계속 실행되며 다른 에이전트·시스템·API와 통신하는 반복 작업. Co-work보다 더 고급이며 항상 실행 중이라는 의미에서 루프라 부른다.
  2. **툴(tools)** — 특정 프로젝트나 일회성 상황을 위해 만드는 것으로, 계속 쓸 것이 아니기 때문에 발표자는 이를 "소모품(disposable)"으로 간주한다.
  3. **앱(apps)** — 실제로 프로덕션에서 쓰이는 소프트웨어. 발표자 회사의 하우스 매니저(house manager)인 Betty는 프로그래머가 아니지만, 자동차·부동산·투자·예산 등 개인 삶의 모든 워크플로를 관리하는 시스템을 직접 만들었다. 발표자는 "AI 시대에 영어가 새로운 프로그래밍 언어"라고 표현한다.
- 심화 팁
  - **플랜 모드(plan mode)** — 무언가를 만들기 전 항상 `/plan`을 입력하고 아이디어를 던진다. Claude가 필요하면 질문을 하고, 코드를 작성하기 전에 승인받을 완성된 계획을 먼저 작성해준다. 사전 계획 없이 바로 코딩을 시키면 비용이 많이 든다는 불만이 흔한데, 플랜 모드를 쓰면 비용을 크게 아낄 수 있다.
  - **Claude Code 리모트(remote)** — 노트북을 떠날 때마다 사용. 터미널에서 `/remote control`을 입력하면 휴대폰의 Claude 앱과 연결되어, 계속 코드를 작성할 수 있다. 발표자는 산악자전거를 타다가도 이 기능으로 코딩을 했다고 소개한다.

### 레벨 6 — 에이전트 오케스트레이터(the agent orchestrator): 팀원을 만드는 단계
- 오케스트레이터는 실제로 무언가를 계속 실행하는 에이전트를 설계하는 사람이다. 지금까지의 모든 요소(스킬, 시스템 프롬프트, 툴 등)를 하나의 에이전트에 연결해, 부서나 프로세스, 워크플로를 계속 돌아가는 루프로 만들고 더 이상 직접 관여하지 않는다. 발표자는 이를 "루프 안의 인간(human in the loop)"에서 **"루프를 감독하는 인간(human on the loop)"**으로의 전환이라고 표현한다.
- 에이전트를 설계하는 프레임워크(하나의 정답이 아니라 사고방식)
  1. **메인 에이전트(main agent)** 하나를 만든다 — 총괄자/오케스트레이터 역할(비서 에이전트, 관리자 에이전트 등). 발표자의 메인 에이전트 이름은 "Kai"이며, 그 자체로는 별다른 일을 하지 않고 다른 에이전트들을 지휘하는 역할만 한다.
  2. **전문화된 서브 에이전트(sub agents)**를 만든다 — 각 서브 에이전트는 하나의 워크플로를 전담하며, 메인 에이전트가 이들과 소통하며 지시를 내린다. 발표자의 부동산 에이전트 이름은 "Reese"이며 투자 매물을 찾고, Kai가 매일 Reese와 확인해 결과를 발표자에게 보고한다.
  3. **텔레그램(Telegram) 연결** — 휴대폰으로 에이전트와 대화할 수 있게 연결해둔다.
  - 심화 팁: **크리틱 에이전트(critique agent)** — 메인 에이전트가 카피라이팅이나 리서치 같은 결과물을 크리틱 에이전트에게 검토를 요청하면, 개선할 점을 목록으로 만들어 다시 메인 에이전트에 돌려주고 재작업시켜, 항상 최상의 결과물을 얻는 구조다.
  - 발표자는 자신의 플랫폼 "Apex"(apex.host)를 언급하며, 내부적으로 Claude를 메인 에이전트 모델로 쓰고 Apex는 이를 더 안전하고 다루기 쉽게 만든 레이어라고 설명한다. 다만 이 구조는 Claude만으로도 직접 구현할 수 있다고 강조한다.

## 예시
### 레벨별로 바로 써먹을 수 있는 프롬프트 패턴
```
[레벨1] 답하기 전에, 이 작업을 제대로 수행하는 데 필요한 질문을 나에게 먼저 해줘.
[레벨1] 네 작업을 검토해줘.
[레벨2] 내 역할(예: 마케터)을 위한 마스터 프롬프트를 만들기 위해 나를 인터뷰해줘.
[레벨2] 이 워크플로를 위한 시스템 프롬프트를 만들기 위해 나를 인터뷰해줘.
[레벨3] 내 캘린더 봐줘. 내가 뭘 놓치고 있는지 알려줘.
[레벨3] 지난 1주일 Slack을 훑어서 회사 전반에 대한 CEO 수준의 이해를 정리해줘.
[레벨5] /plan  ← 코드를 짜기 전, 아이디어를 던지고 완성된 계획을 먼저 승인받는다.
[레벨5] /remote control  ← 휴대폰의 Claude 앱과 연결해 자리를 비운 상태에서도 코딩을 이어간다.
```

### 마스터 프롬프트 vs 시스템 프롬프트
| 구분 | 역할 | 내용 |
| --- | --- | --- |
| 마스터 프롬프트(master prompt) | 재료(ingredients) | 나에 대한 모든 맥락 — 일하는 방식, 팀 구성, 도구, 역할 |
| 시스템 프롬프트(system prompt) | 레시피(recipe) | 특정 워크플로의 절차·지침, 이미 하고 있지만 문서화하지 않았던 프로세스 |

### 6단계 레벨 요약표
| 레벨 | 이름 | 핵심 행동 |
| --- | --- | --- |
| 1 | 아마추어 | 질문-답 한 번, 메모리·프로젝트 없음 |
| 2 | 레귤러 | 프로젝트 + 마스터 프롬프트로 기억·맥락 확보 |
| 3 | 인티그레이터 | 커넥터(Gmail/Drive/Slack/Notion) + 시각화 + 아티팩트 |
| 4 | 오퍼레이터 | 시스템 프롬프트 + 스킬 + Co-work 스케줄링 |
| 5 | 빌더 | Claude Code로 루프/툴/앱 직접 제작, 플랜 모드 활용 |
| 6 | 에이전트 오케스트레이터 | 메인 에이전트 + 서브 에이전트 조합, 인간은 "루프 위(on the loop)"에서 감독 |

## 요약
- Claude 사용 성숙도를 6단계(아마추어 → 레귤러 → 인티그레이터 → 오퍼레이터 → 빌더 → 에이전트 오케스트레이터)로 구분하며, 각 단계는 이전 단계 위에 새로운 기능(프로젝트, 커넥터, 스킬/스케줄링, Claude Code, 에이전트)을 쌓아 올리는 구조다.
- 레벨 1~2에서는 "인터뷰 요청 → 검토 요청"과 "프로젝트 + 마스터 프롬프트"로 Claude에게 지속적인 맥락(기억)을 만들어주는 것이 핵심이다.
- 레벨 3에서는 Gmail·Drive·Slack·Notion 등 커넥터로 Claude를 실제 업무 도구에 연결하고, 시각화와 인터랙티브 아티팩트로 결과물을 직접 만든다.
- 레벨 4에서는 시스템 프롬프트·스킬·Co-work 스케줄링으로 반복 작업을 자동화하며, "일주일 3회 이상 하는 일은 스킬로 만든다"는 기준과 스킬을 서로 연결하는 "스킬 체이닝"을 제시한다.
- 레벨 5에서는 Claude Code 안에서 루프·툴·앱을 직접 만들며, 코딩 전 반드시 플랜 모드로 계획을 승인받고 Claude Code 리모트로 어디서든 작업을 이어간다.
- 레벨 6에서는 메인 에이전트(오케스트레이터)와 전문화된 서브 에이전트, 크리틱 에이전트를 조합해 인간이 직접 실행하지 않아도 돌아가는 자율 시스템을 구축한다 — "루프 안의 인간"에서 "루프를 감독하는 인간"으로의 전환.
- 발표자는 마지막으로, 기능을 단순히 수집하지 말고 그중 하나를 골라 30일 연속 실천할 것을 권한다.
