# 백그라운드 에이전트 런타임 - 이벤트 로그와 재현 가능한 프롬프트

## 개요

- **업로드일:** 2026-08-24
- **채널:** Tech Bridge
- **발표자·출처:** Rémi Louf / .txt 강연
- **원본:** [YouTube](https://www.youtube.com/watch?v=Nt2aeDlzk4U)
- **정리 범위:** 전체 제공 스크립트(마지막 발화 19:59, 자동 자막 언어 `en`). 수치·제품 상태·전망은 영상 당시 발표자의 설명을 기준으로 한다.
- **핵심:** 자동 브리핑의 실제 실패를 해결하며 이벤트·큐·내용 기반 주소·타입 경계를 갖춘 작은 런타임을 만든 사례다.

## 내용

### 계속 조종하지 않아도 되는 에이전트 (00:00~05:39)

발표자는 산책 중에도 휴대전화로 에이전트를 계속 조종하는 대신 아침에 결과만 받고 싶었다. 시장 뉴스·업무 도구·음성 메모를 모아 브리핑을 만드는 개인적인 필요에서 시작했다. Markdown과 YAML로 에이전트를 정의하고 cron으로 정기 작업을 실행한다. 코드 속 프롬프트보다 파일 정의가 버전 관리와 리뷰에 편했다고 설명한다.

### 시간뿐 아니라 사건에 반응하기 (05:39~08:07)

음성 메모가 들어오면 전사·정리 에이전트가 처리하고 완료 이벤트를 발행한다. 브리핑 에이전트는 정기 시장 분석과 메모 처리 결과를 받아 최종 메시지를 만든다. 각 에이전트가 받아들이고 반환하는 이벤트를 선언하면 이 사례에서는 명시적인 워크플로 간선을 모두 관리하지 않아도 연결이 형성된다.

### 세 가지 실패에서 생긴 기반 기능 (08:07~10:23)

브리핑의 중복 발송, 사라진 메모, 바뀐 프롬프트를 추적할 수 없는 문제가 발생했다. 이에 각각 시도 횟수를 관리하는 큐, 추가 전용 이벤트 로그, 내용 기반 주소(content addressing)를 도입했다. 에이전트가 있어도 익숙한 분산 시스템 문제가 사라지지 않는다는 교훈이다.

### 모델 입력을 추적하고 비교하기 (10:23~15:59)

이벤트는 원인 관계로 연결한다. 시스템 프롬프트·스킬·도구 설명·사용자 메시지를 해시로 식별하고 조합해 실제 요청을 재구성한다. 실행 간 어떤 요소가 바뀌었는지 비교하고, 같은 입력을 다른 모델에 재생해 결과를 평가한다. 기록하는 것은 시스템이 구성한 입력과 출력이며 모델의 비공개 내부 사고 전체를 복원한다는 의미는 아니다.

### 타입 경계와 실제 사용 (15:59~19:59)

외부 도구 호출과 에이전트 사이 이벤트에 타입 경계를 둬 잘못된 구조가 시스템에 들어오는 것을 막는다. 구조화된 출력은 형식 오류를 줄이지만 업무 의미의 정확성까지 자동 보장하지는 않는다. 발표자는 당시 회사에서 약 20개 에이전트로 확장했고 자신의 브리핑 업무에는 공개 모델도 충분했다고 설명한다. 도구를 직접 사용하며 요구와 실패를 이해한 경험을 강조한다.

## 예시

`음성 메모 등록 → 전사·정리 → 처리 완료 이벤트 → 시장 분석 결과와 결합 → 브리핑 → Slack 메시지 요청`

| 실패 | 추가한 기반 |
|---|---|
| 메모 유실 | 원인 관계를 가진 추가 전용 로그 |
| 중복 처리 | 큐와 재시도 추적 |
| 프롬프트 회귀 원인 불명 | 해시 기반 입력 보관·비교·재생 |

## 요약

- 지속 실행에는 일정 외에 이벤트 기반 반응이 필요하다.
- 로그·큐·재시도·타입 경계는 에이전트에서도 기본이다.
- 실제 입력을 보존하면 디버깅과 모델 교체 평가가 쉬워진다.
