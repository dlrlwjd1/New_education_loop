# How to evaluate agents in practice

## 개요
- 업로드일: 2025-12-12
- 채널: Google Cloud Tech
- 재생목록: AI agent crash course (agent evaluation 시리즈 2편/완결편, [1편 - The agent evaluation revolution](2025-12-03%20The%20agent%20evaluation%20revolution.md) 후속)
- 1편에서 다룬 이론(왜 기존 테스트가 에이전트에 안 통하는지, 무엇을 측정해야 하는지)을 실전으로 옮긴다. 3단계 테스트 피라미드(three-tier testing pyramid)와 ADK를 이용한 실제 테스트 작성법을 다룬다.

## 내용

### 1. 3단계 테스트 피라미드 (three-tier testing pyramid)
- **1단계 — 컴포넌트 레벨 단위 테스트(component-level unit test)**: 에이전트 테스트의 기초. 가장 작은 구성요소를 독립적으로 테스트한다. 예: 간단한 프롬프트에서 에이전트가 올바른 도구를 골랐는가? 올바른 형식의 응답(JSON 필드 등)을 만들었는가? 빠르고 저렴하며 자동화되어 있어 CI(지속적 통합)에서 회귀(regression)를 조기에 잡기에 적합하다.
- **2단계 — 궤적 레벨 통합 테스트(trajectory-level integration test)**: 여러 단계로 이뤄진 작업 전체를 엔드투엔드로 테스트한다. 에이전트가 논리적으로 계획했는가? 도구를 올바른 순서로 사용했는가? 무언가 실패했을 때 적응했는가? 이전 정보를 기억하고 목표에 도달했는가?
- **3단계 — 엔드투엔드 인간 검토(end-to-end human review)**: 사람이 직접 전체 경험(도움이 되었는지, 안전한지, 상식적인지)을 검토한다. 느리고 비용이 크지만 최종 품질 게이트(quality gate) 역할을 한다.

| 단계 | 확인 대상 | 특징 |
| --- | --- | --- |
| 1단계: 컴포넌트 단위 테스트 | 도구·매개변수의 정확성 | 빠르고 저렴, CI에 적합 |
| 2단계: 궤적 레벨 통합 테스트 | 능력과 추론 | 다단계 작업 전체를 검증 |
| 3단계: 엔드투엔드 인간 검토 | 사용자 경험과 신뢰 | 느리고 비쌈, 최종 게이트 |

### 2. ADK로 실제 평가하기: Book Finder 에이전트 예시
- 예시 에이전트: Gemini 2.5 Pro를 두뇌로 사용하고, `search local library`(도서관 검색), `find local bookstore`(서점 검색), `order online`(온라인 주문) 세 도구를 가진 책 찾기 에이전트.
- 사용자가 "해리포터 책 주문해줘"라고 하면, 먼저 지역 도서관을 확인하고, 없으면 서점을 확인하며, 그래도 없으면 온라인으로 주문한다.
- 이런 에이전트를 평가하려면 책을 찾는 전체 여정(journey) 전체를 평가해야 하므로, **기대 궤적(expected trajectory)**을 설정하고 실제 과정과 비교해야 한다.
- **궤적(trajectory)**이란 에이전트가 작업을 해결하기 위해 거치는 전체 여정으로, (1) 인자를 포함한 도구 호출의 순서, (2) 중간 단계와 추론, (3) 최종 응답을 포함한다.
- Book Finder 예시의 바람직한 궤적: 도서관 검색 → 서점 검색 → 온라인 주문. 궤적 외에도 최종 답변(예: 지역 옵션이 실패했을 때 온라인 소매점을 추천했는가)을 비교해야 한다.

### 3. ADK의 두 가지 핵심 평가 지표(metric)
- **도구 궤적 평균 점수(tool trajectory average score)**: 실제 도구 호출이 기대한 순서와 얼마나 가까운지를 측정. 점수를 1로 설정하면 100% 일치해야 통과하고, 0으로 설정하면 완전히 달라도 통과한다. 사용 시 0~1 사이의 임계값(threshold)을 설정해야 한다.
- **응답 일치 점수(response match score)**: 최종 답변이 기대 답변과 얼마나 유사한지를 측정. 내부적으로 Rouge-1을 사용해 단어 중복도를 확인하며, 정밀도(precision)와 재현율(recall)을 결합한 0~1 점수를 낸다. 예: 0.5는 "충분히 비슷함", 0.8은 "매우 엄격한 일치"를 의미. 에이전트는 비결정적(non-deterministic)이므로, temperature를 0에 가깝게 설정하지 않는 한 1.0을 요구하는 것은 피해야 한다.

### 피라미드에 맞춘 테스트 설계
- **1단계 (컴포넌트 테스트)**: 단순한 프롬프트와 기대 도구 호출로 도구 선택 정확도, 매개변수 정확성 등을 테스트.
- **2단계 (궤적 테스트)**: ADK Eval을 사용해 다단계 작업과 기대 도구 순서를 테스트하고, 도구 궤적 평균 점수·응답 일치 점수 같은 지표로 능력과 추론을 평가.
- **3단계 (인간 검토)**: ADK가 제공하는 트레이스(trace)를 바탕으로 사람이 전체 품질을 판단.

### 데모 요약
- 1단계 데모: 단일 도구 호출이 올바르게 선택·채워지는지 확인하는 도구 정확성(tool correctness) 단위 테스트. `search local library` 도구가 선택되었는지, `title=Harry Potter` 같은 매개변수가 올바르게 전달되었는지 확인. 여기서 실패하면 다음 단계로 넘어가기 전에 반드시 고쳐야 한다(기초에 해당하므로).
- 2단계 데모: 다단계 계획과 최종 답변을 함께 테스트. 도구 궤적 평균 점수와 응답 일치 점수로 통과 기준을 설정 (예: 궤적은 0.8로 엄격하게, 응답은 0.5로 자연어 변형을 허용).

## 예시
개념 요약 코드 (ADK Eval 사용):
```python
# 1단계: 컴포넌트(도구 정확성) 단위 테스트
def test_tool_selection():
    response = book_finder_agent.run("해리포터 책 주문해줘")
    assert response.tool_calls[0].name == "search_local_library"
    assert response.tool_calls[0].args["title"] == "Harry Potter"

# 2단계: ADK Eval을 이용한 궤적 테스트
eval_config = {
    "tool_trajectory_avg_score": 0.8,   # 엄격한 궤적 일치 요구
    "response_match_score": 0.5,        # 자연어 변형 허용
}
eval_result = adk_eval.evaluate(
    agent=book_finder_agent,
    eval_set="book_finder_eval_set.json",
    criteria=eval_config,
)
```

## 요약
- 3단계 테스트 피라미드: 1단계(컴포넌트 단위 테스트, 빠르고 저렴) → 2단계(궤적 레벨 통합 테스트, ADK Eval 사용) → 3단계(엔드투엔드 인간 검토, 최종 품질 게이트).
- **궤적(trajectory)** = 도구 호출 순서 + 중간 추론 + 최종 응답을 포함한 에이전트의 전체 여정이며, 이를 기대 궤적과 비교해 평가한다.
- 핵심 지표 두 가지: **도구 궤적 평균 점수**(도구 호출 순서 일치도)와 **응답 일치 점수**(Rouge-1 기반 최종 답변 유사도). 둘 다 0~1 임계값을 설정해 사용하며, 에이전트의 비결정성 때문에 지나치게 엄격한 기준(예: 1.0)은 피해야 한다.
- 이 시리즈로 "이 에이전트가 작동하는 것 같다"는 느낌에서 "이 에이전트가 신뢰할 수 있다는 것을 안다"로 나아가는 방법을 배웠다.
