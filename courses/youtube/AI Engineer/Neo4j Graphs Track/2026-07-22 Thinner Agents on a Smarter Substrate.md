# Thinner Agents on a Smarter Substrate

## 개요
- 업로드일: 2026-07-22
- 원본: https://www.youtube.com/watch?v=VGN22pPpb-8
- 재생목록: Neo4j Graphs Track @ AI Engineer
- 발표자: Emil Eifrem, Neo4j
- 핵심 주제: 에이전트마다 데이터 연결 지식을 중복 구현하지 않고, 온톨로지 기반 시맨틱 레이어(ontology-based semantic layer)에 공통 지능을 축적하는 구조

## 내용
### 에이전트가 두꺼워지는 이유
은행 계좌 개설 에이전트는 신원 확인을 위해 차량 등록 기관, 여권 서비스, 내부 고객 데이터 등 여러 소스를 찾아야 한다. 한 팀이 이 연결을 완성해도 다음 팀은 새 에이전트를 만들 때 데이터의 위치, 최신성, 신뢰도, 접근 권한을 다시 조사한다.

이 방식에는 네 가지 문제가 있다.

- **발견(discovery)**: 필요한 데이터가 어느 시스템에 있는지 에이전트마다 다시 찾는다.
- **신뢰(trust)**: 동일한 정보의 여러 버전 중 무엇을 믿어야 하는지 알기 어렵다.
- **중복(DRY 위반)**: 모든 팀이 같은 연결과 변환 로직을 반복한다.
- **학습 부재**: 한 에이전트의 성공과 실패가 다음 에이전트의 성능을 높이지 못한다.

### 얇은 에이전트와 똑똑한 기반
발표자는 개별 에이전트를 얇게(thin) 유지하고, 공통 지능을 공유 기반(shared substrate)에 넣자고 제안한다. 이 기반은 세 층으로 구성된다.

1. **비즈니스 온톨로지(business ontology)**  
   `f_name` 같은 물리 스키마의 이름이 아니라 고객, 계좌, 신원 확인처럼 조직이 실제로 사용하는 개념과 관계를 정의한다.
2. **기술 온톨로지(technical ontology)**  
   데이터베이스, Snowflake, Databricks, S3 등 데이터 소스와 스키마를 카탈로그화하고 비즈니스 개념과 연결한다.
3. **실행 추적(execution traces)**  
   에이전트가 어떤 소스를 선택하고 어떤 절차를 시도했으며 결과가 성공했는지 기록한다.

비즈니스 개념과 물리 데이터의 매핑 덕분에 데이터가 이동해도 모든 에이전트를 직접 수정할 필요가 없다. 실행 기록까지 그래프에 쌓이면 과거에 성공한 경로를 이후 에이전트가 재사용할 수 있다.

### 위에서 정의하고 아래에서 학습하기
온톨로지는 조직의 의미 체계를 위에서 아래로(top-down) 제공한다. 실행 추적은 실제 에이전트 행동에서 아래로부터(bottom-up) 학습 신호를 만든다. 두 방향을 결합해야 시맨틱 레이어가 정적인 카탈로그에 머물지 않고 사용 경험에 따라 개선된다.

## 예시
```text
계좌 개설 요청
  → 비즈니스 개념: 고객의 신원 확인 필요
  → 기술 매핑: DMV 조회 + 여권 서비스
  → 정책 확인: 해당 에이전트의 접근 권한
  → 실행 결과 기록: 어떤 경로가 성공했는가
  → 다음 에이전트가 성공 경로를 우선 재사용
```

데이터 소스가 바뀌면 비즈니스 개념은 그대로 두고 기술 온톨로지의 매핑을 갱신한다. 이 변경이 시맨틱 레이어를 사용하는 여러 에이전트에 공통으로 반영된다.

## 요약
- 에이전트별 데이터 연결은 발견·신뢰·중복·학습 문제를 반복해서 만든다.
- 비즈니스 온톨로지는 조직의 언어를, 기술 온톨로지는 실제 데이터 위치와 스키마를 표현한다.
- 실행 추적을 함께 저장하면 성공과 실패가 공유 자산이 되어 기반 자체가 개선된다.
- 장기적으로 차별화되는 지능은 개별 에이전트보다 공통 시맨틱 레이어에 축적된다.
