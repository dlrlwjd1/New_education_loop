# Learned Execution Graphs for Anomaly Detection & Drift in APIs

## 개요
- 업로드일: 2026-07-23
- 원본: https://www.youtube.com/watch?v=u1yaOeEX4e8
- 재생목록: Neo4j Graphs Track @ AI Engineer
- 발표자: Ritvik Pandya, JP Morgan Chase
- 핵심 주제: API 요청의 실제 실행 단계를 단기 실행 그래프(short-lived execution graph)로 학습해 구조적 이상과 드리프트를 탐지하는 방법

## 내용
### 평균 지표가 숨기는 실패
전통적인 모니터링은 엔드포인트 전체의 지연 시간, 오류율, 처리량을 본다. 하지만 필수 처리 단계가 조용히 생략되면 요청은 더 빨리 끝나고 오류도 발생하지 않아 지표상 오히려 정상으로 보일 수 있다.

실행 그래프는 API 요청 한 건이 통과한 미들웨어와 처리 단계를 방향성 비순환 그래프(DAG)로 표현한다. 정상 실행에서 학습한 그래프와 실제 요청의 그래프를 비교하면 단계의 누락, 순서 변경, 예상치 못한 삽입을 구조적 차이로 찾을 수 있다.

### 기준선을 학습하고 차이를 국소화하기
파이프라인은 초당 1,600개가 넘는 요청의 텔레메트리에서 실행 경로를 구성한다. 전체 요청에 하나의 임계값을 적용하지 않고 클라이언트나 경로별 기준선과 노드별 성능 분포를 학습한다.

처리 흐름은 다음과 같다.

1. 정상 실행 그래프와 노드별 기준선을 학습한다.
2. 새 요청의 실제 그래프를 기준선과 비교한다.
3. 구조 또는 분포의 편차를 찾는다.
4. 문제를 엔드포인트 전체가 아니라 특정 노드에 국소화한다.
5. 저비용 1차 검사에서 변화가 확인된 경우에만 더 비싼 분석으로 승격한다.

운영 사례에서는 한 노드의 41배 편차를 기존 서비스 수준 모니터링이 놓쳤지만 그래프가 포착했다. 근본 원인 탐색 시간이 수 시간에서 30초 미만으로 줄었다.

### 이상과 드리프트 구분
**이상(anomaly)**은 한 번의 비정상 실행이고, **드리프트(drift)**는 시스템 행동의 기준 자체가 서서히 이동하는 현상이다.

- **구조적 드리프트(structural drift)**: 노드나 엣지가 추가·삭제·재배열된다.
- **볼륨 드리프트(volume drift)**: 특정 경로의 호출량이 변한다.
- **행동·공변량 드리프트(behavioral/covariate drift)**: 노드의 지연 등 분포가 변한다.

분포 변화에는 KL divergence 같은 측정을 사용한다. 드리프트가 확정되면 계속 경고하는 대신 검토 후 새로운 기준선으로 전환해야 한다.

### 운영 고려 사항
지연 도착 이벤트, 샘플링, 신규 클라이언트의 콜드 스타트(cold start), 점진 배포를 고려해야 한다. 실시간 핫 패스(hot path)는 가벼운 검사만 수행하고, 재구성·상세 분석은 별도 경로에서 처리한다.

## 예시
```text
학습된 정상 경로: 인증 → 권한 확인 → 필수 검증 → 비즈니스 로직 → 응답
실제 실행 경로:   인증 → 권한 확인 →             비즈니스 로직 → 응답

평균 지표: 지연 감소, 오류 0
실행 그래프: 필수 검증 노드 누락 탐지
```

## 요약
- 엔드포인트 평균은 단계 누락이나 순서 변화를 숨길 수 있다.
- 요청별 실행 DAG는 “얼마나 느린가”뿐 아니라 “무엇이 실제로 실행됐는가”를 보여준다.
- 노드별 기준선은 문제를 정확한 처리 단계에 국소화한다.
- 일회성 이상과 지속적 드리프트를 구분해야 경보와 기준선 갱신을 올바르게 처리할 수 있다.
