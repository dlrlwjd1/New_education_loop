# Active Graph Agent Runtime (BabyAGI 4)

## 개요
- 업로드일: 2026-07-22
- 원본: https://www.youtube.com/watch?v=khVX_BUnEwU
- 재생목록: Neo4j Graphs Track @ AI Engineer
- 발표자: Yohei Nakajima, Untapped Capital
- 핵심 주제: LLM이 아니라 불변 이벤트 로그(immutable event log)를 중심에 둔 ActiveGraph 에이전트 런타임

## 내용
### “에이전트에 로그를 붙이기”를 뒤집기
일반적인 에이전트는 LLM 호출 루프를 중심으로 만들고 메모리, 로깅, 복구 기능을 나중에 덧붙인다. ActiveGraph는 반대로 모든 행동과 상태 변경을 타입이 있는 불변 이벤트 로그에 먼저 기록한다. 이 로그를 투영(project)해 현재 상태 그래프를 만든다.

따라서 로그는 단순한 관찰 기록이 아니라 에이전트 자체의 원본(source of truth)이다. 특정 시점까지 이벤트를 재생하면 상태를 복구할 수 있고, 과거 지점에서 분기하면 다른 실험을 수행할 수 있다.

### 런타임의 구성 요소
- **행동(behaviors)**: 그래프의 변화를 감지하고 새 이벤트를 발생시킨다.
- **정책(policies)**: 에이전트가 스스로 바꿀 수 있는 것, 사람의 승인이 필요한 것, 모순 검사가 필요한 것을 결정한다.
- **뷰(views)**: 동일한 이벤트 로그에서 목적별 상태 표현을 만든다.
- **팩(packs)**: 메모리, 도구, 채팅 같은 기능을 교체 가능한 단위로 제공한다.

여러 LLM이 직접 메시지를 주고받는 대신 공유 상태를 읽고 이벤트를 남긴다. 발표자는 이를 과거의 블랙보드 시스템(blackboard system)과 Kafka식 이벤트 아키텍처의 계보로 설명한다.

### 복구·분기·자기 개선
500문항 평가 중 350번째에서 API 키가 실패한 사례에서 런타임은 전체 작업을 다시 시작하지 않았다. 이벤트 로그의 직전 상태로 롤백한 뒤 작업을 이어갔다. 장기 실행 작업에서 재시작 비용을 줄이는 핵심 효과다.

자기 개선(self-improvement)도 무제한 코드 수정이 아니라 통제된 실험으로 만든다.

1. 현재 에이전트를 분기한다.
2. 변경 패치를 제안한다.
3. 샌드박스 테스트와 평가를 실행한다.
4. 정확도가 실제로 오른 경우에만 변경을 유지한다.

정책과 평가가 자기 변경을 둘러싼 안전 경계가 된다. ActiveGraph Lab은 자료를 읽고 실험을 만들며, 자신의 코드 버그를 찾아 PR까지 만든 사례를 보여준다.

## 예시
```text
Event 350: evaluation_started
Event 351: question_loaded
Event 352: api_call_failed
              ↓
정책이 재시도 가능 실패로 판정
              ↓
Event 353: state_restored
Event 354: evaluation_resumed
```

이벤트를 삭제하거나 현재 상태를 억지로 수정하는 대신, 복구와 재시도 역시 새 이벤트로 남긴다. 그래서 사후에 무슨 일이 있었는지 재현할 수 있다.

## 요약
- ActiveGraph에서는 “로그가 에이전트”이며 현재 상태는 이벤트 로그의 투영 결과다.
- 이벤트 소싱(event sourcing)은 재생, 롤백, 분기, 장기 작업 재개를 자연스럽게 만든다.
- 여러 모델은 서로 직접 대화하지 않고 공유 그래프 상태를 통해 협력한다.
- 자기 개선은 분기, 샌드박스, 평가, 정책을 거친 통제된 변경으로 구현한다.
