## 내용
### 사람의 조직도를 복제한 첫 설계
첫 시스템은 인간 분석가의 업무 단계를 에이전트로 각각 분리했다.

1. 성과 변화 신호를 탐지한다.
2. 문제가 발생한 지역이나 세그먼트를 찾는다.
3. 원인을 분석한다.
4. 결론과 행동 제안을 종합한다.

각 에이전트는 오케스트레이터를 통해 결과를 다음 단계로 넘겼다. 구조는 깔끔해 보였지만 전체 문제를 끝까지 소유하는 주체가 없었다. 핸드오프마다 맥락이 축약되고 단계별 결론이 서로 어긋났다.

실제 출력에서는 특정 지역의 처방이 18% 감소한 원인을 보험자의 의약품 등급 변경으로 올바르게 찾고도 “영업 담당자를 더 투입하라”는 잘못된 조치를 제안했다. 원인과 행동 사이에 필요한 제약 도메인 지식이 파이프라인 전체에서 보존되지 않았기 때문이다.

### 에이전트가 할 일과 코드가 할 일 분리
팀은 빈 디렉터리에서 Claude Code에 셸과 데이터베이스를 주고 문제를 어떻게 푸는지 관찰했다. 재설계 결과는 더 복잡한 다중 에이전트 토폴로지가 아니라 더 작은 시스템이었다.

- 수치 변화의 **신호 탐지**는 에이전트가 깨어나기 전에 결정적 파이프라인이 수행한다.
- 에이전트는 신호가 있는지 추측하지 않고 이미 확인된 신호를 조사한다.
- 하나의 주 에이전트가 전체 추론과 최종 답을 소유한다.
- 제한된 정보 조회가 필요할 때만 집중된 서브에이전트를 동적으로 생성한다.

확실한 계산은 코드에 맡기고, 모호한 조사와 가설 검증에 에이전트를 사용한 것이다.

### 지식 그래프를 제어면으로 사용하기
제약 산업 지식 그래프는 단순 조회 테이블이 아니라 에이전트의 탐색 범위를 제한하는 제어면(control plane)이다. 그래프의 각 엣지는 가능한 인과 관계를 나타내는 가설이다.

예를 들어 처방 감소와 보험 등급 변경이 연결되어 있다면 에이전트는 이를 정답으로 받아들이지 않고 실제 데이터에 대해 검증한다. 가능한 원인 경로를 도메인 그래프로 제한하므로 무한한 탐색과 무관한 행동 제안을 줄인다.

재설계한 시스템은 인간 분석가가 한 달 동안 수행하던 분석을 약 20분에 처리했다.

## 예시
```text
결정적 파이프라인:
처방량 18% 감소 신호를 계산하고 위치를 확정

지식 그래프의 후보 가설:
처방 감소 ← 보험 등급 변경
처방 감소 ← 공급 문제
처방 감소 ← 경쟁 약품 출시

단일 에이전트:
각 엣지를 실제 데이터로 검증
→ 입증된 원인과 도메인에 맞는 행동을 함께 종합
```

## 요약
- 인간 조직의 역할 분리를 그대로 다중 에이전트 구조로 옮기면 핸드오프에서 전체 맥락과 책임이 사라질 수 있다.
- 결정적으로 계산할 수 있는 신호 탐지는 일반 코드가 먼저 수행하는 편이 안정적이다.
- 하나의 에이전트가 전체 추론을 소유하고 필요할 때만 제한된 서브에이전트를 쓰면 일관성이 높아진다.
- 지식 그래프의 엣지를 검증할 가설로 사용하면 에이전트의 탐색을 도메인 안에 묶을 수 있다.
