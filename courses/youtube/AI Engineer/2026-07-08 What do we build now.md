# What do we build now

## 개요
- 원본: https://www.youtube.com/watch?v=xUnRQ9vLXxo
- 채널: AI Engineer
- 발표자: Theo Browne
- 핵심 주제: 모델 능력이 빠르게 커지면서, 개발자는 기존 도구와 사고방식에 갇히지 말고 더 넓고 큰 제품 범위를 상상해야 한다.

## 내용
### 모델 세대가 개발 방식의 기준을 바꾼다
발표자는 Sonnet 3.5, Opus 4.5, Mythos/Fable 계열 모델을 각각 다른 개발 시대의 전환점처럼 설명한다. 초기에는 tool call을 안정적으로 수행하는 것이 중요했고, 다음에는 장기 작업을 잃지 않는 능력이 중요해졌으며, 이후에는 모델이 스스로 하위 작업을 분해하고 추가 agent를 활용하는 orchestration 능력이 중요해졌다고 본다.

### 개발자는 아직 skeuomorphic phase에 있다
Theo는 iOS 초기 디자인이 실제 물건을 닮아야 사용자를 설득할 수 있었던 것처럼, 개발자들도 지금 터미널, Git, 언어 정체성 같은 과거의 도구 모양에 갇혀 있다고 말한다.

터미널은 친숙하지만 자연어 agent를 위한 최종 인터페이스는 아닐 수 있다. Git, env 파일 공유, 언어별 정체성, 삭제를 두려워하는 습관도 다시 검토해야 할 대상으로 제시된다.

### 아이디어의 크기 기준이 내려갔다
예전에는 스타트업 규모였던 일이 이제는 side project가 될 수 있고, side project였던 일은 markdown 파일 하나로도 충분할 수 있다. agent를 cron으로 실행하고, markdown 지시문이 PR triage, 우선순위 정리, 정적 HTML 배포까지 수행하는 사례를 통해 "실행 가능한 문서"의 위력을 강조한다.

### 크게가 아니라 넓게 생각하기
발표자는 breadth와 depth의 구분을 사용한다. 과거에는 스타트업이 AWS 같은 거대 플랫폼과 breadth로 경쟁하기 어려웠기 때문에 특정 vertical을 깊게 파는 전략이 합리적이었다. 하지만 agent의 도움으로 훨씬 넓은 범위를 빠르게 구축할 수 있게 되면서, 더 넓은 제품 범위를 시도할 수 있다고 주장한다.

## 예시
### markdown file as product
발표자는 매일 아침 markdown 지시문을 실행해 여러 GitHub repo의 PR 상태를 확인하고, 우선순위를 정리하고, 정적 HTML 페이지를 만들어 S3에 올리는 자동화를 예로 든다. 과거에는 서비스로 만들었을 일이 지금은 markdown 파일과 agent 실행으로 대체될 수 있다는 것이다.

### breadth-first product thinking
- 기존 사고: AWS 전체와 경쟁할 수 없으니 좁은 영역을 깊게 파자.
- 새 사고: agent로 여러 영역의 충분한 시작점을 만들고, 부족한 vertical 기능은 사용자와 agent가 확장하게 만들자.

## 요약
- 모델이 좋아질수록 기존 Jira ticket 수준의 일만 자동화해서는 새 능력을 체감하기 어렵다.
- 개발자는 터미널, 언어, Git 관습 같은 기존 정체성을 절대화하지 말아야 한다.
- 많은 자동화와 제품 실험은 이제 markdown 파일 하나로 시작할 수 있다.
- 좋은 AI 시대의 제품은 더 넓은 표면적을 제공하고, 사용자가 스스로 확장할 수 있게 설계된다.
