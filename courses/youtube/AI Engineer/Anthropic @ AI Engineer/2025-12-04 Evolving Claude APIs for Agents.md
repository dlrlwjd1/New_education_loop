## 내용
### 에이전트 API에 필요한 세 축
에이전트는 한 번의 응답을 생성하는 애플리케이션보다 오랫동안 도구를 사용하고 많은 중간 상태를 유지한다. 발표는 모델 능력을 실제 시스템에서 활용하려면 API가 다음 문제를 함께 풀어야 한다고 설명한다.

- 모델이 외부 환경에서 행동할 수 있는 **도구**
- 긴 실행에서 중요한 정보를 유지하는 **컨텍스트 관리**
- 세션과 작업을 넘어 유용한 상태를 보존하는 **메모리**

### 도구와 실행 피드백
모델이 계획만 세우는 것으로는 에이전트가 되지 않는다. API는 도구의 입력·출력 구조를 명확히 하고, 실행 성공과 실패를 다시 모델에 전달해야 한다. 긴 작업에서는 일시적 실패, 잘못된 인수, 권한 부족을 복구할 수 있는 반복 루프가 필요하다.

도구 수가 늘수록 모델에 모든 정의를 매번 제공하는 비용도 커진다. 따라서 관련 도구를 선택적으로 노출하고 도구 결과를 압축하는 설계가 중요하다.

### 컨텍스트 윈도우 관리
장기 실행에서는 대화와 도구 출력이 계속 쌓인다. 무작정 전체 기록을 유지하면 비용이 증가하고 중요한 목표가 오래된 로그에 묻힌다.

관리 전략은 다음과 같다.

- 원래 목표와 결정 사항을 보존한다.
- 큰 도구 출력은 요약하거나 외부 저장소에 둔다.
- 현재 단계에 필요한 정보만 다시 불러온다.
- 컨텍스트를 줄인 뒤에도 완료 조건과 금지 사항이 사라지지 않았는지 확인한다.

### 메모리의 역할
컨텍스트 윈도우는 현재 실행의 작업 공간이고, 메모리는 실행을 넘어 남길 정보를 선택하는 층이다. 사용자 선호, 검증된 사실, 성공한 절차를 모두 같은 방식으로 저장할 수는 없다. 정보 종류별 갱신·만료·신뢰 정책이 필요하다.

플랫폼 API는 이런 기반 기능을 제공하되 애플리케이션이 도메인에 맞는 정책과 평가를 설계할 여지를 남겨야 한다.

## 예시
장기 고객 조사 에이전트는 검색 결과 전문을 계속 대화에 보존하는 대신 다음처럼 상태를 나눈다.

```text
활성 컨텍스트: 현재 조사 질문, 다음 행동, 완료 조건
외부 작업 상태: 원본 문서와 전체 도구 출력
메모리: 검증된 고객 선호와 이전 조사에서 재사용할 절차
```

## 요약
- 장기 에이전트용 API는 모델 호출뿐 아니라 도구 실행, 컨텍스트 축약, 메모리 정책을 지원해야 한다.
- 도구 결과와 오류는 모델이 복구할 수 있는 구조화된 관찰로 돌아가야 한다.
- 컨텍스트는 현재 작업 공간이며 모든 기록을 영구 보존하는 저장소가 아니다.
- 메모리는 무엇을 남기고 갱신하거나 만료할지에 대한 애플리케이션 정책이 필요하다.
