## 내용
### MCP가 해결하는 연결 문제
AI 애플리케이션마다 데이터베이스, 파일, SaaS 통합을 별도 구현하면 연결이 파편화된다. MCP는 AI 호스트가 여러 데이터·도구 서버와 공통 방식으로 통신하도록 하는 공개 표준이다.

구조는 세 역할로 나뉜다.

- **호스트(host)**: 사용자 경험과 모델 실행을 관리한다.
- **클라이언트(client)**: 특정 MCP 서버와 프로토콜 연결을 유지한다.
- **서버(server)**: 데이터와 행동 기능을 표준 인터페이스로 제공한다.

### 세 가지 서버 인터페이스
- **Prompts**: 서버가 제공하는 재사용 가능한 상호작용 템플릿
- **Resources**: 파일·문서·스키마처럼 읽을 수 있는 맥락
- **Tools**: 검색, 계산, 쓰기처럼 모델이 호출할 수 있는 행동

리소스는 참고할 정보를, 도구는 부작용이 있을 수 있는 실행을 나타낸다. 이 구분은 사용자에게 읽기와 행동 권한을 다르게 보여주는 데도 중요하다.

### 에이전트 루프와 MCP
에이전트는 서버의 도구를 발견하고, 현재 목표에 맞는 기능을 선택하며, 결과를 관찰해 다음 행동을 결정한다. MCP는 연결 경계를 제공하지만 계획, 권한, 오류 복구, 완료 판단은 호스트의 에이전트 하니스가 담당한다.

워크숍에서는 여러 서버의 맥락을 조합해 조사 작업을 수행하고 결과를 생성하는 과정을 다룬다.

### Sampling
Sampling은 서버가 클라이언트를 통해 모델 생성을 요청하는 기능이다. 서버가 자체 모델 API 키와 별도 모델 스택을 갖지 않고도 호스트가 선택한 모델과 사용자 권한 아래에서 지능적 처리를 요청할 수 있다.

이 역방향 요청에는 사용자가 무엇을 승인하는지, 어떤 컨텍스트가 모델에 전달되는지 명확한 통제가 필요하다.

### 생태계와 향후 과제
MCP의 가치는 단일 서버보다 여러 클라이언트와 서버가 상호운용될 때 커진다. 인증, 원격 전송, 서버 발견, 도구 품질, 보안 UX가 생태계 확장의 핵심 과제로 제시된다.

## 예시
```text
사용자 → AI 호스트
           ├─ MCP 클라이언트 → 문서 서버(resources)
           ├─ MCP 클라이언트 → 검색 서버(tools)
           └─ MCP 클라이언트 → 업무 서버(tools)

에이전트:
문서 읽기 → 검색 → 결과 종합 → 쓰기 작업 전 승인
```

## 요약
- MCP는 AI 호스트와 외부 데이터·도구 사이의 공통 연결 경계를 제공한다.
- prompts, resources, tools는 템플릿·읽기 맥락·행동을 각각 구분한다.
- 에이전트의 계획과 안전 정책은 MCP 자체가 아니라 호스트 하니스의 책임이다.
- Sampling은 서버가 호스트의 모델 능력을 요청하게 하지만 컨텍스트와 승인 경계를 명확히 해야 한다.
