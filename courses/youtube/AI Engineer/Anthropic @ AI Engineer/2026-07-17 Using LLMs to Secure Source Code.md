# Using LLMs to Secure Source Code

## 개요
- 업로드일: 2026-07-17
- 원본: https://www.youtube.com/watch?v=imFedndyXYQ
- 재생목록: Anthropic @ AI Engineer
- 발표자: Eugene Yan, Anthropic
- 핵심 주제: LLM을 이용한 취약점 탐지에서 검증·분류·패치까지 이어지는 여섯 단계 보안 워크플로

## 내용
### 병목은 취약점 발견 이후로 이동했다
프런티어 모델은 실제 코드에서 많은 보안 후보를 찾을 수 있게 됐다. Anthropic이 1,000개가 넘는 오픈 소스 저장소를 스캔한 사례에서는 23,000개 후보 중 고위험 또는 치명적 후보 6,200개를 찾고, 1,600개를 관리자에게 보고했으며 약 100개가 실제 패치로 이어졌다.

후보 수가 늘면서 문제는 “더 많이 찾기”보다 진짜 취약점을 검증하고, 중요한 순서대로 엔지니어에게 전달하며, 안전한 패치를 만드는 일로 이동한다.

### 여섯 단계
1. **위협 모델(threat model)**  
   시스템의 신뢰 경계, 공격자 능력, 중요한 자산과 설계 결정을 문서화한다. 모델은 코드 문맥은 잘 보지만 사람 머릿속의 시스템 문맥은 알지 못한다.
2. **샌드박스(sandbox)**  
   공격 재현과 패치 검증을 격리된 컨테이너에서 수행한다.
3. **발견(discovery)**  
   놓치지 않는 재현율(recall)을 우선해 폭넓게 후보를 찾는다.
4. **독립 검증(verification)**  
   발견 에이전트의 추론을 보지 않은 별도 에이전트가 새 환경에서 실제 익스플로잇을 재현한다.
5. **분류(triage)**  
   심각도, 악용 가능성, 영향 범위를 기준으로 사람의 제한된 관심을 배분한다.
6. **패치(patching)**  
   수정과 회귀 테스트까지 완료해 같은 버그가 다시 들어오지 않게 한다.

### 발견과 검증의 목적 함수 분리
발견 단계는 머신러닝 분류기의 높은 재현율처럼 의심스러운 것을 넓게 수집한다. 검증 단계는 높은 정밀도(precision)를 목표로 실제 악용 가능성을 입증한다. 한 에이전트가 자신의 발견을 검증하면 기존 결론을 합리화할 수 있으므로, 두 단계는 독립적이고 적대적으로 구성한다.

### 기술보다 어려운 조직 병목
실제 운영에서는 보고 경로, 심각도 합의, 담당자 배정, 유지관리자의 처리 능력이 병목이 된다. 자동 스캐너의 후보가 사람의 검토 용량을 압도하면 시스템 전체의 가치는 낮아진다. 따라서 처음부터 완전 자동화를 시도하기보다 오픈 소스 의존성 등 좁은 범위에서 사람이 통제하며 시작하는 것이 권장된다.

## 예시
문자열 결합으로 주문 ID를 SQL에 넣는 5줄짜리 조회 코드에서 발견 에이전트가 SQL 주입 가능성을 제기한다.

```text
발견: 입력값이 SQL 문자열에 직접 결합됨
검증: 새 컨테이너에서 공격 입력으로 데이터 노출 재현
분류: 외부 접근 가능 여부와 노출 범위 확인
패치: 매개변수화 쿼리로 변경
회귀 테스트: 동일 공격 입력이 더 이상 성공하지 않음
```

## 요약
- 모델의 보안 탐지 능력이 높아지면서 검증·분류·패치가 새 병목이 됐다.
- 위협 모델은 코드만으로 알 수 없는 시스템 맥락을 제공한다.
- 발견은 재현율, 독립 검증은 정밀도를 각각 최적화해야 한다.
- 사람의 관심은 확장되지 않으므로 후보 라우팅과 우선순위 설계가 자동 스캔만큼 중요하다.
