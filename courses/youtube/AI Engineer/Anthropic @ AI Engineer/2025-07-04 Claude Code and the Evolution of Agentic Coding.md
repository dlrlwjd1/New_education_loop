## 내용
### 코딩 UX는 계속 추상화됐다
초기 텍스트 편집기는 입력 기능이 매우 제한적이었고, 이후 IDE는 자동 완성, 탐색, 리팩터링과 디버깅을 통합했다. 에이전틱 코딩은 또 하나의 추상화 변화로, 사용자가 구체적인 편집 동작보다 원하는 결과를 설명하고 모델이 코드베이스를 탐색·수정·검증하게 한다.

발표의 핵심 전제는 모델 능력이 제품 UI보다 빠르게 발전한다는 점이다. 특정 모델의 현재 약점에 맞춰 복잡한 UI와 워크플로를 고정하면 새 모델의 능력을 활용하기 어려워질 수 있다.

### 터미널에서 시작한 이유
Claude Code는 별도의 무거운 IDE를 먼저 만들기보다 터미널을 출발점으로 삼았다. 터미널에는 개발자가 이미 사용하는 파일 시스템, 셸 명령, Git, 테스트, 빌드 도구가 있다. 모델은 이 범용 인터페이스를 통해 코드베이스를 검색하고 실제 개발 루프에 참여할 수 있다.

단순한 텍스트 인터페이스는 다음 장점이 있다.

- 기존 개발 환경과 쉽게 결합된다.
- 원격 서버와 다양한 저장소에서 동일하게 작동한다.
- 모델과 사용자의 행동 기록이 투명하게 보인다.
- 새 기능을 전용 UI보다 도구와 명령으로 빠르게 실험할 수 있다.

### 모델을 제품의 중심에 두기
Claude Code 팀의 접근은 가능한 한 모델이 문제를 풀게 하고, 제품은 필요한 도구·권한·피드백 루프를 제공하는 것이다. 사람이 모든 분기를 하드코딩하면 모델 능력이 향상돼도 제품 성능이 함께 오르지 않는다.

동시에 단순함은 기능 부재가 아니라 설계 선택이다. 실행 전 승인, 변경 검토, 테스트 결과처럼 사용자가 신뢰를 형성하는 정보는 명확하게 보여줘야 한다.

### 빠른 모델 변화에 맞춘 개발
제품 팀은 모델 변화에 맞춰 프롬프트와 하니스를 계속 재평가한다. 사용자 피드백과 실제 작업 데이터를 통해 모델이 어디서 막히는지 찾고, 필요한 최소 도구를 추가한다.

## 예시
```text
사용자: 인증 모듈의 실패 원인을 찾아 수정해 줘.

Claude Code:
저장소 검색 → 관련 파일 읽기 → Git 이력 확인
→ 수정 → 테스트 실행 → 실패 관찰 → 재수정
→ 변경 사항과 검증 결과 제시
```

별도의 “인증 디버깅 UI”를 만드는 대신 터미널의 범용 도구를 모델이 조합한다.

## 요약
- 에이전틱 코딩은 편집 동작보다 목표와 검증에 집중하게 만드는 인터페이스 변화다.
- 터미널은 기존 개발 도구와 원격 환경을 포괄하는 범용 에이전트 인터페이스다.
- 제품 로직을 과도하게 고정하기보다 모델이 도구를 사용해 문제를 풀 수 있게 해야 능력 향상의 혜택을 얻는다.
- 단순한 UI 안에서도 권한, 실행 기록, 테스트 결과는 신뢰를 위해 명확해야 한다.
