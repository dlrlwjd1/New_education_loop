# Don't Build Agents, Build Skills Instead

## 개요
- 업로드일: 2025-12-08
- 원본: https://www.youtube.com/watch?v=CEvIs9y1uog
- 재생목록: Anthropic @ AI Engineer
- 발표자: Barry Zhang, Mahesh Murag, Anthropic
- 핵심 주제: 에이전트를 도메인별로 새로 만드는 대신 절차적 전문 지식을 이식 가능한 스킬(skill)로 패키징하는 방법

## 내용
### 하니스의 평준화와 전문성의 빈칸
모델 지능이 빠르게 높아지고 도구 호출, 반복 루프, 메모리 같은 에이전트 기반 구조는 서로 비슷해지고 있다. 그러나 범용 에이전트는 조직 고유의 업무 절차와 도메인 전문성을 자동으로 알지 못한다.

프롬프트에 모든 규칙을 넣으면 컨텍스트가 커지고, 특정 에이전트 코드에 지식을 박아 넣으면 다른 환경으로 옮기기 어렵다. 또한 대화에서 배운 절차가 다음 작업에 자동으로 남지 않는다.

### 스킬의 최소 형식
스킬은 조합 가능한 절차적 지식(procedural knowledge)을 파일 묶음으로 구성한다. 일반적으로 다음 요소를 담는다.

- 스킬의 목적과 사용 시점을 설명하는 메타데이터
- 단계별 작업 지침
- 필요할 때 읽을 참고 자료
- 반복 작업을 실행하는 스크립트나 템플릿

핵심은 새 에이전트 개체를 하나 더 만드는 것이 아니라 같은 에이전트가 필요에 따라 새로운 전문성을 불러오게 하는 것이다.

### 점진적 공개
모든 스킬 전문을 항상 컨텍스트에 넣지 않는다. 런타임에는 짧은 설명만 보여주고, 에이전트가 관련성을 판단한 스킬의 세부 지침과 자료만 단계적으로 읽는다. 이 점진적 공개(progressive disclosure)는 많은 스킬을 보유해도 컨텍스트 비용을 제한한다.

```text
스킬 목록과 짧은 설명
        ↓ 관련 스킬 선택
SKILL.md 세부 지침
        ↓ 필요한 경우
참고 자료·스크립트·템플릿
```

### 이식성과 네트워크 효과
스킬은 특정 모델 호출 코드보다 파일과 문서에 가까워 도구와 환경 사이에서 옮기기 쉽다. 하나의 좋은 스킬이 여러 에이전트의 성능을 높이고, 여러 사용자의 개선이 다시 스킬 품질에 반영될 수 있다.

장기 비전은 에이전트가 성공 경험에서 반복 가능한 절차를 추출해 자신의 스킬을 쓰고, 평가를 통해 유지할 전문성을 선택하는 것이다.

## 예시
재무 보고 스킬은 단순히 “보고서를 작성하라”는 프롬프트가 아니다.

```text
목적: 월간 재무 보고서 생성
절차: 데이터 검증 → 계정 매핑 → 이상 항목 확인 → 보고서 작성
참고: 조직의 계정과목 정의
스크립트: 원장 합계 검증
템플릿: 승인된 보고서 형식
```

같은 범용 에이전트가 이 스킬을 필요할 때만 불러와 조직의 절차대로 작업한다.

## 요약
- 에이전트 기반 구조보다 실제 업무에 필요한 도메인 전문성이 더 큰 병목이 되고 있다.
- 스킬은 절차, 참고 자료, 스크립트와 템플릿을 조합 가능한 파일 묶음으로 패키징한다.
- 점진적 공개는 많은 전문성을 제공하면서 컨텍스트 사용량을 통제한다.
- 범용 에이전트에 이식 가능한 스킬을 더하는 구조가 도메인별 에이전트를 반복 제작하는 것보다 재사용성이 높다.
