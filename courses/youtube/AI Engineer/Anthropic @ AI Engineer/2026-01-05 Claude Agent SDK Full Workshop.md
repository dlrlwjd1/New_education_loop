## 내용
### 기능·워크플로·에이전트
단일 LLM 기능은 한 번의 분류나 생성을 수행한다. 워크플로는 RAG처럼 사람이 정한 여러 단계를 따른다. 에이전트는 필요한 컨텍스트를 스스로 만들고 다음 행동 경로를 선택하며 더 자율적으로 작업한다.

에이전트의 핵심은 모델만이 아니라 도구, 프롬프트, 파일 시스템, 스킬, 서브에이전트, 메모리를 묶는 하니스다. Agent SDK는 Claude Code를 만들며 반복 구현한 이 구성 요소를 재사용하기 위해 Claude Code 위에 구축됐다.

### 기본 에이전트 루프
워크숍은 하니스를 직접 만들며 다음 순환을 구현한다.

```text
컨텍스트 수집 → 생각 → 행동 → 관찰 → 검증
                         ↑           ↓
                         └── 수정 ───┘
```

모델의 도구 요청을 파싱하고 실행 결과를 다시 관찰로 넣는다. 실패하거나 막힌 상태에서는 오류를 숨기지 않고 다음 시도에 필요한 피드백으로 제공한다.

### Bash를 범용 도구로 사용하기
작업마다 전용 도구를 만드는 대신 Bash를 제공하면 에이전트가 `git`, 검색 도구, 변환기 등 기존 소프트웨어를 조합할 수 있다. 이는 사람이 컴퓨터를 사용하는 방식과 비슷하고 새 작업에 대한 유연성이 높다.

반면 셸은 강력하므로 읽기 전용과 쓰기 권한, 실행 디렉터리, 샌드박스를 구분해야 한다. 범용성은 권한 통제와 함께 설계되어야 한다.

### 파일 시스템을 컨텍스트와 메모리로
에이전트는 `ls`와 검색으로 필요한 정보를 찾고, 파일에 계획이나 발견 사항을 기록해 긴 작업의 상태를 외부화한다. `CLAUDE.md` 같은 컨텍스트 파일은 저장소의 규칙과 구조를 알려준다.

거대한 코드베이스를 모두 임베딩하거나 컨텍스트에 넣기보다 좋은 안내 파일을 제공하고 관련 하위 디렉터리에서 시작해 범위를 좁히는 접근을 제안한다.

### 훅으로 결정적 규칙 넣기
모델이 필수 단계를 건너뛰면 훅이 행동을 가로채 추가 피드백을 넣을 수 있다. 예를 들어 “추측하지 말고 스크립트로 데이터를 확인하라”거나 “쓰기 전에 파일을 읽어라”는 규칙을 런타임에서 강제한다.

## 예시
연구 에이전트는 관련 파일을 검색하고, 조사 결과를 작업 파일에 저장하고, 다음 질의를 스스로 결정한다. 완료 전에는 결과 파일이 실제로 생성됐는지와 요구 항목을 충족했는지 다시 확인한다.

```text
if write_requested && !target_was_read:
    block_action()
    return_feedback("대상 파일을 먼저 읽으세요.")
```

## 요약
- 에이전트는 자신의 컨텍스트와 경로를 구성하는 반복 실행 시스템이다.
- Agent SDK는 Claude Code의 도구·권한·메모리·서브에이전트 경험을 재사용한다.
- Bash와 파일 시스템은 범용 행동, 상태 외부화, 결과 검증을 가능하게 한다.
- 강력한 범용 도구에는 샌드박스와 권한이 필요하며, 결정적 요구 사항은 훅으로 보완할 수 있다.
