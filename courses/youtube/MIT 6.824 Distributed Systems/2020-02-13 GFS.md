# Lecture 3: GFS

## 개요
- 업로드일: 2020-02-13
- 원본: https://www.youtube.com/watch?v=EpIgvowZr00
- 강좌: MIT 6.824 Distributed Systems (Spring 2020)
- 핵심 주제: Google File System(GFS)의 중앙 메타데이터, 청크 복제, primary lease, 장애 복구와 완화된 일관성

## 내용
### 목표와 워크로드
GFS는 수백·수천 대의 저가 서버에서 매우 큰 파일을 저장하고 높은 집계 처리량을 내도록 설계됐다. 작은 랜덤 쓰기보다 대형 순차 읽기와 파일 끝 추가(append)가 흔하고, 서버 장애는 예외가 아니라 정상 상황으로 가정한다.

### 구조
- **Master**: 파일 이름, 청크 번호, 청크 위치와 버전 같은 메타데이터를 관리한다.
- **Chunkserver**: 큰 고정 크기 청크를 로컬 디스크에 저장하고 여러 서버에 복제한다.
- **Client**: master에서 위치를 받은 뒤 데이터는 chunkserver와 직접 주고받는다.

master가 데이터 경로에서 빠지므로 병목을 줄일 수 있다. 클라이언트는 메타데이터를 캐시해 master 요청 횟수를 줄인다.

### 쓰기 순서와 primary
master는 한 복제본에 제한 시간 lease를 주어 primary로 지정한다. 데이터는 먼저 모든 복제본에 전달되고, primary가 mutation의 순서를 정하면 secondary가 같은 순서로 적용한다. 제어 흐름과 데이터 흐름을 분리한 것이다.

동시 append나 실패 때문에 일부 복제본에는 중복되거나 정의되지 않은 영역이 생길 수 있다. GFS는 엄격한 POSIX 의미보다 애플리케이션이 감당할 수 있는 단순한 일관성 모델과 높은 처리량을 선택한다.

### 장애 처리
master는 heartbeat로 chunkserver 상태를 확인하고 부족한 복제본을 다시 만든다. 청크 버전 번호로 오래된 stale 복제본을 식별한다. master 상태는 operation log와 체크포인트로 복구하며, 삭제 파일은 즉시 제거하지 않고 지연 수거한다.

## 예시
클라이언트가 `(파일, 오프셋)`을 master에 보내면 청크 핸들과 복제본 주소를 받는다. 이후 데이터를 복제본들에 전송하고 primary에 쓰기를 요청한다. primary가 정한 일련번호가 모든 복제본의 적용 순서를 통일한다.

## 요약
- GFS는 대형 파일·순차 처리·빈번한 서버 장애라는 Google 워크로드에 맞춘 시스템이다.
- master는 메타데이터만 관리하고 실제 데이터 전송에서는 빠진다.
- primary lease가 복제본 사이의 mutation 순서를 정한다.
- 엄격한 범용 파일 의미 일부를 포기하고 높은 처리량과 단순한 장애 복구를 얻는다.
