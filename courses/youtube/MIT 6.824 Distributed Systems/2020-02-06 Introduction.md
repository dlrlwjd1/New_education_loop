## 내용
### 분산 시스템이란
분산 시스템(distributed system)은 네트워크로 통신하는 여러 컴퓨터가 하나의 일관된 작업을 수행하는 시스템이다. 대형 웹사이트의 저장소, 대규모 데이터 처리, P2P 파일 공유 등이 대표적이다.

여러 컴퓨터를 쓰는 주요 이유는 다음과 같다.

- 처리량을 늘리기 위한 병렬 실행
- 복제로 장애를 견디는 고가용성(high availability)
- 은행 간 송금처럼 본질적으로 떨어져 있는 주체의 협력
- 신뢰하지 않는 코드를 격리하는 보안

단일 컴퓨터로 해결할 수 있다면 그것이 더 단순하다. 분산 시스템은 동시 실행, 부분 장애(partial failure), 네트워크 지연 때문에 설계와 디버깅이 훨씬 어렵다.

### 강좌의 세 축
- **장애 허용(fault tolerance)**: 복제본 중 일부가 실패해도 서비스를 계속한다.
- **일관성(consistency)**: 여러 복제본이 애플리케이션에 어떤 읽기·쓰기 의미를 제공할지 정한다.
- **성능(performance)**: 서버 수를 늘릴 때 처리량도 함께 증가하도록 확장한다.

이 목표들은 충돌한다. 강한 일관성과 복제는 통신을 요구하고, 통신은 지연과 확장성 문제를 만든다.

### MapReduce 사례
MapReduce는 프로그래머가 `Map`과 `Reduce` 함수만 작성하면 작업 분배, 셔플(shuffle), 부하 균형, 작업자 장애 복구를 프레임워크가 담당한다.

```text
입력 조각 → 병렬 Map → (key, value) 중간 결과
          → key별 shuffle → 병렬 Reduce → 결과 파일
```

코디네이터는 완료되지 않은 작업을 다른 작업자에게 다시 할당한다. 재실행 결과가 같아야 하므로 Map과 Reduce는 외부 상태에 의존하지 않는 결정적 함수여야 한다. 많은 작은 작업을 동적으로 배정하고 느린 작업은 중복 실행해 straggler의 영향을 줄인다.

## 예시
단어 수 세기에서는 Map이 각 단어를 `(word, 1)`로 내보내고, Reduce가 같은 단어의 값 개수를 합친다. GFS에 입력을 저장하고 데이터가 있는 서버에서 Map을 실행하면 네트워크 전송을 줄일 수 있다.

## 요약
- 분산 시스템은 성능·장애 허용·물리적 분산·보안을 위해 필요하지만 단일 시스템보다 훨씬 복잡하다.
- 핵심 설계 문제는 장애 허용, 일관성, 확장 가능한 성능 사이의 균형이다.
- MapReduce는 제한된 프로그래밍 모델을 제공하는 대신 분산 실행의 복잡성을 숨긴다.
- 결정적 작업, 동적 작업 배정, 실패한 작업의 재실행이 단순한 장애 복구를 가능하게 한다.
