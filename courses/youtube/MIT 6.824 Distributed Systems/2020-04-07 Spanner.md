## 내용
### 목표
Spanner는 여러 데이터센터에 shard와 replica를 두면서도 shard를 넘는 트랜잭션을 제공한다. 데이터 근접성과 데이터센터 장애 허용을 얻으면서 애플리케이션에 강한 트랜잭션 의미를 주는 것이 목표다.

### Paxos와 2PC
각 shard는 Paxos group으로 복제되며 leader가 읽기·쓰기를 조정한다. 한 shard의 트랜잭션은 해당 group에서 처리하고, 여러 shard를 건드리면 각 Paxos leader가 2PC participant가 된다. participant와 coordinator의 결정 자체가 복제되므로 단일 coordinator crash 때문에 영구히 멈추는 위험을 줄인다.

### TrueTime
TrueTime은 현재 시각 하나가 아니라 실제 시간이 존재한다고 보장되는 구간 `[earliest, latest]`를 반환한다. GPS와 원자시계에서 시간을 받아 clock uncertainty의 상한을 관리한다.

commit timestamp를 선택한 뒤 불확실성 구간이 지나갈 때까지 기다리는 commit wait를 수행하면, 먼저 완료된 트랜잭션의 timestamp가 나중에 시작한 트랜잭션보다 작다는 external consistency를 보장할 수 있다.

### Read-only transaction
읽기 전용 트랜잭션은 과거의 안전한 timestamp에서 snapshot을 읽는다. lock이나 2PC 없이 여러 shard에서 일관된 snapshot을 병렬로 읽을 수 있어 읽기 중심 workload에 효과적이다.

## 예시
서울 client의 트랜잭션이 미국과 유럽 shard를 함께 갱신하면 각 shard의 Paxos leader가 prepare하고 2PC로 commit한다. 분석 query는 과거 timestamp를 골라 replica에서 읽어 현재 쓰기를 막지 않는다.

## 요약
- Spanner는 지리적 복제와 shard 간 ACID 트랜잭션을 동시에 제공한다.
- Paxos로 복제된 participant 위에서 2PC를 실행해 장애 허용성을 높인다.
- TrueTime의 bounded uncertainty와 commit wait가 실제 시간 순서와 commit 순서를 맞춘다.
- timestamp 기반 읽기 전용 트랜잭션은 lock 없이 일관된 분산 snapshot을 읽는다.
