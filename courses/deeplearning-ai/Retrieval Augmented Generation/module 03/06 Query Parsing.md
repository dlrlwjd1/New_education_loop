# Query Parsing

## 개요
- 사용자는 RAG 시스템에 **사람과 대화하듯** 프롬프트를 쓰므로, 그 프롬프트는 **검색 쿼리로는 부적합**하다. 리트리버는 프롬프트를 **파싱해 의도를 파악하고 검색에 최적화**하도록 편집·재작성·변환한다.
- 가장 널리 쓰이고 대부분의 경우 충분한 기법은 **LLM 쿼리 재작성(query rewriting)** 이다.
- 고급 기법으로 **개체명 인식(NER)**, **가상 문서 임베딩(HyDE)** 등이 있으나, 더 복잡하고 항상 더 나은 것은 아니므로 실험으로 판단한다.

## 내용

### 왜 쿼리 파싱이 필요한가
- 사용자는 대화형으로 질문해 불필요한 정보·모호함이 많다. 이를 벡터 DB에 그대로 넣지 말고, 리트리버가 **의도를 파악해 최적화**해야 한다.

### ① LLM 쿼리 재작성(query rewriting) — 가장 널리 쓰임
- LLM을 **쿼리 재작성기**로 세팅. 예(의료 지식 베이스) 지시: "모호한 표현 명확화, 적절한 **의료 용어** 사용, 매칭 확률을 높일 **동의어** 추가, 불필요·산만한 정보 제거."
- 예시:
  - **원본**: "블랙 랩 강아지 Poppy와 산책하다 목줄을 세게 당겼는데, 3일째 어깨가 저리고 손가락이 찌릿해요. 뭘까요?"
  - **재작성**: "어깨에 갑작스러운 강한 당김 → 3일간 지속되는 어깨·손가락 저림. **신경병증(neuropathy)·신경 압박(nerve impingement)** 등 잠재적 원인·진단은?"
- 불필요 정보 제거, 모호함 해소, 의료 용어 사용으로 매칭 확률↑. 각 프롬프트 정제를 위한 추가 LLM 호출 비용이 들지만, **이점이 충분히 정당화**된다. 프롬프트는 반복 개선 가능.

### ② 개체명 인식(Named Entity Recognition, NER) — 고급
- 쿼리에서 장소·사람·날짜·가상 인물 등 **정보 범주**를 인식. 이 정보로 벡터 검색이나 이후 **메타데이터 필터링**을 개선.
- 예: **GLiNER**(범용 NER 모델)에 텍스트와 원하는 개체 유형 목록(사람·책·장소·날짜·배우·캐릭터 등)을 주면, 해당 개체가 라벨링된 쿼리를 반환.
- 매우 효율적이라 쿼리마다 실행 가능. 약간의 지연이 추가되지만 검색 품질을 크게 높일 수 있다.

### ③ 가상 문서 임베딩(Hypothetical Document Embeddings, HyDE) — 고급
- 검색의 **이상적 결과가 될 가상 문서**를 생성해 쿼리를 정제. 예: 앞의 의료 질문이라면 LLM이 "빠른 당김으로 인한 어깨·손 저림"에 대한 **가상 문서**를 생성 → 그 문서를 임베딩해 **그 벡터로 검색**.
- 핵심: 리트리버가 질문의 의도뿐 아니라 **좋은 결과가 어떤 모습일지**를 이해하게 한다.
- 보통 리트리버는 **프롬프트↔문서**(사과↔오렌지)를 매칭하지만, HyDE는 **가상의 완벽한 문서↔실제 문서**(더 유사한 텍스트)를 비교한다.
- 실제로 성능이 향상되나, 검색 지연과 가상 문서 생성 LLM 연산 비용이 든다.

### 실무 권장
- 어떤 형태의 쿼리 파싱이든 RAG의 핵심 구성 요소다.
- 거의 모든 경우 **기본 쿼리 재작성**(잘 프롬프트한 LLM으로 사용자 프롬프트를 다듬기)이 정답.
- NER·HyDE 등 고급 기법은 추가 이점이 있을 수 있으나 **더 복잡하고 항상 더 낫지는 않다** → 실험해 프로젝트가 어떻게 발전해야 할지 결과로 판단하라.

## 예시

### 쿼리 재작성 전/후
| 구분 | 내용 |
|------|------|
| 원본 | 강아지 산책 중 목줄을 당김, 3일째 어깨·손가락 저림 (잡담 섞임) |
| 재작성 | 어깨 강한 당김 → 지속 저림, neuropathy/nerve impingement 원인? (용어·간결) |

### 쿼리 파싱 기법
| 기법 | 하는 일 | 위치 |
|------|---------|------|
| 쿼리 재작성 | LLM이 프롬프트 정제 | 기본·권장 |
| NER(GLiNER) | 개체 범주 인식 | 벡터 검색/메타데이터 필터 개선 |
| HyDE | 가상 문서 생성 후 그 벡터로 검색 | 문서↔문서 비교 |

## 요약
- 사용자 프롬프트는 검색 쿼리로 부적합하므로, **쿼리 파싱**으로 의도를 파악해 검색에 최적화한다.
- **LLM 쿼리 재작성**이 가장 널리 쓰이고 대부분 충분하며, 추가 LLM 호출 비용을 정당화할 만큼 이점이 크다.
- 고급 기법인 **NER**(개체 인식 → 필터/검색 개선)와 **HyDE**(가상 문서 벡터로 검색)는 성능을 높일 수 있으나 더 복잡하고 항상 낫지는 않다.
- 기본 재작성을 표준으로 삼고, 고급 기법은 **실험으로 효과를 검증**해 도입하라.
