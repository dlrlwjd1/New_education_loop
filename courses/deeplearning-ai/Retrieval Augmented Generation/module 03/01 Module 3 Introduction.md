# Module 3 Introduction

## 개요
- 모듈 3은 정보 검색 이론을 **프로덕션(production)** 으로 옮긴다. 관계형 DB로도 대부분의 검색을 구현할 수 있지만, 수백만~수십억 문서를 검색하면 특히 **시맨틱 검색의 벡터 연산**이 크게 느려진다.
- 이때 **벡터 데이터베이스(vector database)** 로 전환한다 — 대량의 벡터 데이터를 저장·검색하도록 최적화되어 RAG와 거의 동의어가 됐다.
- 청킹(chunking)·쿼리 파싱(query parsing)·리랭킹(reranking) 등 프로덕션 RAG 성능을 높이는 기법들도 다룬다.

## 내용

### 이 모듈에서 배우는 것
- **벡터 데이터베이스**가 벡터 검색에 왜 그렇게 최적화되어 있는지, 그리고 직접 사용해 다양한 검색을 실행하는 실습.
- 프로덕션 RAG 시스템에서 리트리버 성능을 더 끌어올리는 기법들:
  - **문서 청킹(document chunking)**
  - **쿼리 파싱(query parsing)**
  - **리랭킹(re-ranking)**
- 모듈 끝에 개념을 적용하는 프로그래밍 과제.

## 요약
- 대규모(수백만~수십억 문서)에서는 벡터 연산이 느려지므로 **벡터 데이터베이스**로 전환하며, 이는 RAG의 표준 구성 요소가 됐다.
- 모듈 3은 벡터 DB의 최적화 원리와 사용법, 그리고 **청킹·쿼리 파싱·리랭킹** 같은 프로덕션 성능 향상 기법을 다룬다.
