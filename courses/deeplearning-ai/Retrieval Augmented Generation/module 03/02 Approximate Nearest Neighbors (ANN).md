# Approximate Nearest Neighbors Algorithms (ANN)

## 개요
- 벡터 검색을 소박하게 구현한 **k-최근접 이웃(k-nearest neighbor, KNN)** 은 이해·구현이 쉽지만, 문서 수에 **선형(linear)** 으로 느려져 대규모에서 확장성이 나쁘다.
- 이를 개선한 것이 **근사 최근접 이웃(Approximate Nearest Neighbors, ANN)** 알고리즘군으로, 약간의 정확도를 희생해 훨씬 빠르게 검색한다.
- 대표 알고리즘 **NSW(Navigable Small World)** 와 그 계층화 버전 **HNSW** 는 **근접 그래프(proximity graph)** 를 활용해, 검색을 대략 **로그(logarithmic)** 시간으로 만들어 수십억 벡터도 수백 밀리초에 검색한다.

## 내용

### k-최근접 이웃(KNN)의 한계
- 절차: 모든 문서와 프롬프트를 임베딩 → 프롬프트 벡터와 **모든 문서 벡터의 거리 계산** → 거리순 정렬 → 상위 **k개** 반환.
- 이해·구현은 쉽지만 **확장성이 최악**: 검색당 계산량이 문서 수에 **선형 비례**. 문서 1,000개면 1,000번, 10억 개면 10억 번 거리 계산 → 후자가 100만 배 느림.

### ANN — 속도를 위해 정확도를 약간 희생
- ANN 알고리즘군은 영리한 자료구조로 검색을 크게 빠르게 한다. 대신 **절대적으로 가장 가까운** 문서를 찾는다는 보장은 없고(약간의 품질 희생), 매우 가까운 문서는 찾아낸다.

### NSW(Navigable Small World)
- **근접 그래프(proximity graph) 사전 구축**:
  1. 각 벡터와 다른 모든 벡터의 거리 계산.
  2. 문서마다 노드 하나 추가.
  3. 각 문서를 **가장 가까운 몇 개 문서와 간선(edge)** 으로 연결 → 거미줄 같은 구조.
- **검색 과정**:
  1. 프롬프트를 벡터화(쿼리 벡터).
  2. **무작위 진입점(candidate vector)** 선택(프롬프트와 가깝다는 가정 없음).
  3. 현재 후보의 **이웃들 중 프롬프트에 가장 가까운 것**을 계산(이웃이 몇 개뿐이라 빠름) → 새 후보로.
  4. 더 가까운 이웃이 없을 때까지 반복 → 후보 반환.
- 최적 경로가 아니라 **매 순간 최선의 이웃**을 고르므로 절대 최적 벡터는 못 찾을 수 있으나, 실제로 매우 가까운 벡터를 KNN보다 훨씬 빠르게 찾는다.

### HNSW(Hierarchical NSW)
- 여러 층(layer)을 가진 **계층적 근접 그래프**로 초반 검색을 크게 가속. 예(문서 1,000개):
  - **층 1**: 전체 1,000개 벡터로 정상 근접 그래프.
  - **층 2**: 무작위로 100개만 남겨 근접 그래프.
  - **층 3**: 무작위로 10개만 남겨 근접 그래프.
- **검색**: 최상위 **층 3**에서 무작위 진입점으로 최적 후보를 찾음 → 그 후보에서 **층 2**로 내려가 더 탐색 → **층 1(전체)** 로 내려가 최종 후보를 찾아 반환.
- 원리: 상위 층에서 **큰 점프**로 프롬프트 벡터의 대략적 이웃에 도달하고, 층 1에 도달할 무렵엔 이미 매우 가까운 상태.
- 상위 층으로 갈수록 벡터가 **기하급수적으로 적어** 실행 시간이 대략 **로그(logarithmic)** — KNN의 선형과 대비. 덕분에 수십억 벡터도 수백 ms 지연으로 검색 가능.

### 알아둘 핵심 (직접 구현할 필요는 없음)
1. ANN은 KNN보다 **훨씬 빨라** 대규모 벡터 검색을 가능케 한다.
2. 프롬프트에 가까운 문서를 찾지만 **절대 최적 매치는 보장하지 않는다**.
3. 전 과정이 좋은 **근접 그래프** 구축에 의존하며, 이는 연산 부담이 크지만 **프롬프트 수신 전 미리 계산**할 수 있다.

## 예시

### KNN vs HNSW
| 항목 | KNN | HNSW |
|------|-----|------|
| 방식 | 모든 벡터와 거리 계산 | 계층적 근접 그래프 탐색 |
| 시간 복잡도 | 선형(linear) | 로그(logarithmic) |
| 정확도 | 정확(exact) | 근사(approximate) |
| 대규모 적합성 | 나쁨 | 우수(수십억 벡터, 수백 ms) |

## 요약
- 소박한 **KNN** 벡터 검색은 문서 수에 **선형**으로 느려져 대규모에 부적합하다.
- **ANN** 은 약간의 정확도를 희생해 훨씬 빠르게 검색하며, **NSW** 는 근접 그래프를 이웃 따라 탐색한다.
- **HNSW** 는 계층적 그래프로 상위 층에서 큰 점프를 해 **로그 시간**을 달성 — 수십억 벡터도 수백 ms에 검색.
- 직접 구현하진 않지만, ANN은 **빠르되 최적 보장은 없고**, 사전 계산된 **근접 그래프**에 의존한다는 점을 기억하라.
- 다음 강의에서 이 알고리즘들을 실제로 구현하는 도구(벡터 데이터베이스)를 다룬다.
