# Chunking

## 개요
- **청킹(chunking)** 은 지식 베이스의 긴 문서를 **더 작은 텍스트 조각(chunk)** 으로 나누는 것이다.
- 이유 세 가지: ① 임베딩 모델의 **입력 길이 한계**, ② 검색 **관련성(relevancy) 향상**, ③ LLM에 **가장 관련 있는 부분만** 전달(컨텍스트 윈도 절약).
- **청크 크기**가 핵심 — 너무 크면 의미가 뭉개지고 컨텍스트를 채우며, 너무 작으면 맥락을 잃는다. 대표 전략은 **고정 크기 청킹(+오버랩)** 과 **재귀적 문자 분할**이다.

## 내용

### 왜 청킹하는가 (책 1,000권 예시)
- 책 1,000권을 그대로 인덱싱하면 각 책이 **하나의 벡터**로 압축된다 → 특정 챕터·페이지의 주제를 선명히 표현 못 하고 전체를 **평균**해버려 검색 관련성이 나쁘다. 검색해도 **책 한 권 전체**를 가져와 LLM 컨텍스트를 금방 채운다.
- 그래서 책을 페이지·문단·문장 수준으로 쪼갠다. 책 1,000권이 문단 100만 개가 되어도 벡터 DB는 쉽게 저장·검색한다.

### 청크 크기(chunk size)의 트레이드오프
- **너무 크면**(예: 챕터 단위): 책 전체를 벡터화할 때와 같은 문제 — 하나의 벡터로 미묘한 의미를 담기 어렵고 컨텍스트 윈도를 빠르게 채움.
- **너무 작으면**(극단: 단어 단위): 주변 문장·문단의 맥락을 모두 잃어 관련성이 떨어짐. 문장 단위조차 지나치게 세분화될 수 있다.
- 만능 정답은 없고, 벡터가 **너무 많거나 너무 적은 맥락**을 담는 것 사이에서 균형을 찾는다.

### 전략 ① 고정 크기 청킹(fixed-size)
- 모든 청크를 같은 크기로(예: 250자). 1~250=청크1, 251~500=청크2, …
- 문제: 분할이 단어 중간이나 하나의 응집된 생각을 끊을 수 있음.
- 해결: **오버랩(overlap)** 허용. 예) 250자 청크가 앞뒤 청크와 25자씩 겹침 → 청크1=1~250, 청크2=226~475, 청크3=451~700 … (보통 청크 대비 백분율로 표현, 여기선 10% 오버랩).
- 오버랩은 단어가 맥락에서 잘리는 경우를 최소화(경계 단어가 두 청크에 등장). 오버랩이 클수록 관련성은 좋아지지만 **중복 정보로 벡터 수가 늘어난다**.

### 전략 ② 재귀적 문자 분할(recursive character text splitting)
- 특정 문자를 기준으로 분할(예: 문단 사이의 **줄바꿈(newline)**). 청크 크기가 가변적이라 매우 크거나 작은 청크가 생길 수 있지만, **문서 구조를 반영**해 관련 개념이 한 청크에 유지될 가능성이 높다.
- 문서 유형별로 다르게 분할 가능: HTML은 문단·헤더 태그, Python 코드는 함수 정의, 텍스트는 줄바꿈 등.

### 실무 팁
- 고정 크기+오버랩이나 특정 문자 기준 분할은 직접 구현할 만큼 단순하지만, 이를 돕는 외부 라이브러리도 있다.
- 문서에 메타데이터가 있으면 청크가 **원본 문서의 메타데이터를 상속**하게 하고, 위치 정보를 추가할 수 있다.
- **좋은 출발점**: 약 **500자 고정 청크 + 50~100자 오버랩**.

## 예시

### 고정 크기 청킹 (250자, 25자 오버랩)
| 청크 | 문자 범위 |
|------|-----------|
| 1 | 1 ~ 250 |
| 2 | 226 ~ 475 |
| 3 | 451 ~ 700 |

### 청크 크기 트레이드오프
| 크기 | 문제 |
|------|------|
| 너무 큼(챕터) | 의미 뭉개짐, 컨텍스트 낭비 |
| 너무 작음(단어/문장) | 맥락 상실, 관련성 하락 |
| 적정 | 균형(권장: 500자 + 50~100자 오버랩) |

## 요약
- **청킹**은 긴 문서를 작은 조각으로 나누는 것으로, **임베딩 길이 한계 대응·검색 관련성 향상·컨텍스트 윈도 절약**을 위해 필요하다.
- 청크가 너무 크면 의미가 뭉개지고, 너무 작으면 맥락을 잃으므로 **적절한 크기**가 관건이다.
- 대표 전략은 **고정 크기 청킹(+오버랩)** 과 문서 구조를 반영하는 **재귀적 문자 분할**이며, 청크는 원본 메타데이터를 상속해야 한다.
- 권장 출발점은 **500자 청크 + 50~100자 오버랩**이며, 더 정교한 기법은 다음 강의에서 다룬다.
