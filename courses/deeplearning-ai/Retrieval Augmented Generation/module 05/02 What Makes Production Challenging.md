# What Makes Production Challenging

## 개요
- 프로덕션 환경은 프로토타이핑과 다른 새로운 부담을 준다: **트래픽 확장**, **프롬프트의 다양성·예측 불가능성**, **지저분한 실세계 데이터**, **보안·프라이버시**, 그리고 무엇보다 **실수의 실제 비즈니스 영향**.
- 따라서 문제를 **사전 예측·발생 시 추적·변경의 실제 개선 여부 검증**하는 시스템이 필수다.

## 내용

### 프로덕션의 새로운 도전
1. **트래픽 확장(scaling)**: 사용자가 늘면 처리량(throughput)·지연(latency) 제약, 메모리·연산 사용 증가 → 결국 **비용 증가**. 대규모에서 성능 유지가 어렵다.
2. **프롬프트의 다양성·예측 불가능성**: 철저히 테스트해도 모든 요청 유형을 예측하기 어렵다. 출시 전엔 잘 되던 시스템이 새로운 요청에 취약할 수 있다.
3. **지저분한 실세계 데이터**: 데이터가 파편화·형식 불량·메타데이터 누락 등이 흔하고, 많은 데이터가 텍스트가 아니라 **이미지·PDF·슬라이드**에 있다 → 지식 베이스에 넣으려면 접근 방법이 필요.
4. **보안·프라이버시**: 많은 RAG가 **비공개·독점 데이터** 때문에 배포된다. 권한 있는 사용자만 접근하도록 하면서 데이터를 비공개로 유지하는 기능이 중요.
5. **실수의 실제 영향**: 재정·평판 손상으로 이어질 수 있다.

### 실제 사고 사례
- **Google AI 검색 요약**: 출시 초기 "돌을 먹으면 영양상 이롭다"고 답. 원인은 "돌을 몇 개 먹어야 하나?"라는 (엉뚱하고 예측 어려운) 질문에 대해, 검색된 코믹한 포럼 글을 **시스템이 유머임을 인식하지 못한** 것. Google은 수정하고 원인을 블로그로 설명.
- **항공사 챗봇**: 실제로 없는 할인을 선의로 약속.
- **악의적 사용자**: RAG를 속여 제품을 공짜로 팔게 하거나 비밀 정보를 노출시키려 시도.

### 필요한 대비
- 프로덕션은 어려운 환경이므로, **문제를 사전 예측**하고, 발생 시 **추적(track down)** 하며, 변경이 **실제 개선으로 이어지는지 검증**하는 체계가 결정적이다.

## 예시

### 프로덕션 도전 요약
| 도전 | 내용 |
|------|------|
| 트래픽 확장 | 처리량·지연·비용 증가 |
| 프롬프트 다양성 | 예측 못 한 요청에 취약 |
| 지저분한 데이터 | 파편화·비텍스트(이미지·PDF) |
| 보안·프라이버시 | 권한 관리하며 비공개 유지 |
| 실수 영향 | 재정·평판 손상 |

## 요약
- 프로덕션은 **트래픽 확장, 예측 불가한 프롬프트, 지저분한 실세계 데이터, 보안·프라이버시, 실수의 실제 영향**이라는 새 도전을 준다.
- Google "돌 먹기" 요약, 항공사 챗봇의 가짜 할인 등은 프로덕션 실수의 실제 비용을 보여준다.
- 대응의 핵심은 문제를 **예측·추적·검증**하는 체계이며, 다음 강의부터 그 첫 번째인 **관측성(observability)** 을 다룬다.
