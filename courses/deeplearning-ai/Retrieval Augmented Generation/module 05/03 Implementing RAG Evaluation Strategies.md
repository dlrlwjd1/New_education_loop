# Implementing RAG Evaluation Strategies

## 개요
- 프로덕션 대응의 첫 단계는 견고한 **관측성(observability) 시스템** 구축이다. 이 시스템은 **소프트웨어 성능 지표**(지연·처리량·메모리·연산)와 **품질 지표**(사용자 만족·리트리버 recall 등)를 추적해야 한다.
- 정보 수집은 **집계 통계(추세·회귀 탐지)** 와 **상세 로그(개별 프롬프트 추적)** 로 나뉘고, **실험(A/B 테스트)** 도 가능해야 한다.
- 평가 설계 프레임워크는 **범위(scope: 구성 요소 vs 전체)** × **평가자 유형(evaluator type: 코드 / LLM 심사 / 인간)** 의 격자다.

## 내용

### 관측성 시스템이 추적할 것
1. **소프트웨어 성능 지표**: 지연(latency), 처리량(throughput), 메모리·연산 사용.
2. **품질 지표**: 최종 응답에 대한 사용자 만족부터 리트리버의 recall까지.
3. **수집·보고 방식**:
   - **집계 통계(aggregate)**: 시간에 따른 고수준 추세 추적, **회귀(regression)** 빠른 식별.
   - **상세 로그(detailed logs)**: 개별 프롬프트의 파이프라인 여정 추적 → 저품질 응답 원인 파악.
   - **실험(experimentation)**: 새 모델·시스템 프롬프트·리트리버 설정 변경을 안전 환경에서 실험하거나 프로덕션에서 A/B 테스트해, 지표 영향을 보고 반영 여부 결정.

### 평가 프레임워크 — 범위 × 평가자 유형 격자
- **범위(scope)**:
  - **시스템 수준(system-level)**: 전체 성능 요약·고수준 시각.
  - **구성 요소 수준(component-level)**: 개별 문제 디버깅. 예: 전체 지연이 높다면, 원인이 리트리버인지 LLM인지 다른 요소인지 구성 요소 평가로 추적.
- **평가자 유형(evaluator type)**:
  - **코드 기반(code-based)**: 가장 저렴·단순·자동·결정론적. 예: 초당 처리 프롬프트 수 기록, LLM이 유효 JSON을 내는지 유닛 테스트. 거의 무료.
  - **인간 피드백(human)**: 가장 비싸지만 코드가 못 잡는 정보 포착. 예: 👍/👎, 상세 피드백 텍스트박스. 또는 인간이 **테스트 데이터셋(프롬프트+정답 문서)을 사전 구축**하면 이후 precision·recall을 빠르게 계산(초기 구축엔 사람 필요).
  - **LLM 심사(LLM-as-a-judge)**: 절충 — 코드보다 유연, 인간보다 저렴. 예: 검색된 문서가 프롬프트에 관련 있는지 LLM이 판단. 단, **자기 계열 편향**이 있고, 명확한 루브릭과 **이산적 기준(관련/무관)** 이 0~100점 척도보다 잘 작동.

### 실무 시작용 지표 세트
- 각 주요 구성 요소와 전체 시스템에 대해 **성능 + 품질** 지표를 함께 수집:
  - **성능 지표**(지연·처리량·메모리·tokens/sec): **코드 기반** → 저렴, 구성 요소·시스템 양쪽에서 수집.
  - **품질 지표**: 인간 주석 또는 LLM 심사에 의존.
    - **시스템 품질**: 사용자 👍/👎 로 전체 응답 품질 피드백.
    - **리트리버 평가**: 인간 주석 테스트셋(프롬프트+기대 문서) → recall·precision 계산.
    - **LLM 품질**: RAGAS 같은 LLM 기반 평가로 응답 관련성·인용 품질·무관 정보 무시 정도 평가.
- 이렇게 하면 전체·구성 요소의 성능·품질 가시성을 확보하고, 저렴한 지표(지연)와 비싼 지표(인간·LLM)의 균형을 잡는다.

## 예시

### 평가 격자 (범위 × 평가자 유형)
| | 코드 기반 | LLM 심사 | 인간 |
|---|-----------|----------|------|
| 시스템 수준 | 지연·처리량 | 전체 응답 품질 | 👍/👎 |
| 구성 요소 수준 | 컴포넌트별 지연·JSON 검증 | 리트리버 문서 관련성, RAGAS | 리트리버 recall/precision(주석 테스트셋) |

### 평가자 유형 비교
| 유형 | 비용 | 특징 |
|------|------|------|
| 코드 기반 | 거의 무료 | 자동·결정론적 |
| LLM 심사 | 중간 | 유연, 편향·루브릭 주의 |
| 인간 | 높음 | 코드가 못 잡는 정보 포착 |

## 요약
- 프로덕션 대응의 시작은 **관측성 시스템** — **성능 지표(코드 기반)** 와 **품질 지표(인간·LLM 기반)** 를, **집계 통계 + 상세 로그 + 실험** 형태로 수집한다.
- 평가는 **범위(구성 요소 vs 전체)** × **평가자 유형(코드/LLM 심사/인간)** 격자로 설계한다.
- 시작 세트: 성능은 코드로 저렴하게, 시스템 품질은 👍/👎, 리트리버는 주석 테스트셋(recall/precision), LLM은 RAGAS로 평가.
- 다음 강의는 이 시스템 구현 시 고려사항(로깅·모니터링·관측성)을 더 자세히 다룬다.
