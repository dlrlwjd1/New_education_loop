# Security

## 개요
- RAG는 흔히 **비공개·독점 정보** 때문에 구축되므로, 배포 후에도 그 데이터를 비공개로 유지하는 것이 핵심 과제다. 이 강의는 RAG 고유의 **지식 베이스 보안**에 초점을 둔다.
- 유출 경로: ① 사용자가 프롬프트로 **직접 요청**, ② **LLM 제공사로 전송**되는 증강 프롬프트, ③ 데이터베이스 **직접 해킹**.
- 대응: **인증 + 역할 기반 접근(RBAC) 멀티테넌시**, 필요 시 **온프레미스(on-prem)** 로 전체 실행, **암호화**(단, 벡터 DB 고유의 한계 존재).

## 내용

### 유출 경로 ① — 프롬프트로 직접 요청
- 잘 짜인 프롬프트로 LLM이 검색된 청크의 정보를 그대로 인용하게 만들 수 있다. 안전장치가 있어도 사용자가 지식 베이스 내용에 **간접 접근** 가능하다고 가정하는 게 합리적.
- **대응**:
  - **인증(authentication)**: 접근 허용 정보에 맞게 사용자 인증(예: 사내 데이터면 로그인한 직원만 프롬프트 가능).
  - **역할 기반 접근(RBAC) 멀티테넌시**: 데이터를 역할·접근 수준별 **여러 테넌트로 분리 저장**. 사용자 프롬프트가 검색을 유발하면, 그 사용자의 역할·권한에 해당하는 문서에만 접근.
  - 주의: 단일 테넌트에 다 넣고 **메타데이터 필터로 접근 제어**하는 것은 실패 위험이 커 **부적절**. 메타데이터 필터링은 **개인화용**이지 **보안용이 아니다**. 보안에는 **별도 저장된 다수 테넌트**가 훨씬 신뢰할 만하다.

### 유출 경로 ② — LLM 제공사로 전송
- 증강 프롬프트에는 지식 베이스에서 검색된 문서·청크가 들어 있고, 이를 LLM 제공사로 보내는 순간 **보안 통제권을 잃는다**. 정보 민감도에 따라 감내 못 할 위험일 수 있다.
- **대응 — 온프레미스(on-premises)**: LLM과 벡터 DB를 **자체 하드웨어**에서 실행하면, 전 파이프라인에 걸쳐 지식 베이스 내용을 통제할 수 있다. 복잡성·비용이 늘지만, 높은 보안이 필요하면 그만한 가치가 있다.

### 유출 경로 ③ — 직접 해킹과 암호화
- 전통적 DB처럼 벡터 DB도 해킹될 수 있다. 전통적 DB는 **암호화**로 방어(해커가 접근해도 내용을 못 읽음).
- **벡터 DB의 고유 과제**: ANN 알고리즘이 작동하려면 최소한 문서의 **조밀 벡터(dense vector)** 는 **복호화된 상태로 메모리에** 있어야 한다. 청크 텍스트 자체는 암호화 저장·검색 후 증강 프롬프트 구성 시 복호화할 수 있다(일부 벡터 DB가 제공, 또는 직접 구현). 복잡성·지연이 늘지만 보안 계층이 추가됨.
- **암호화되지 않는 조밀 벡터의 위험**: 최근 연구에서 **조밀 벡터로부터 원문을 재구성**할 수 있음이 드러남. 즉 청크를 암호화해도 **암호화되지 않은 벡터에서 재구성**될 수 있다.
  - 대응 연구: 벡터에 **노이즈 추가**, **변환 적용**, 거리는 보존하되 의미를 가리는 **차원 축소** 등. 다만 각각 리트리버 복잡성↑·성능↓. 이 취약점은 해커가 DB에 직접 접근 + 실험적 재구성 기법을 써야 하는 진행 중인 연구 주제지만, 인지할 가치가 있다.

## 예시

### 유출 경로별 대응
| 유출 경로 | 대응 |
|-----------|------|
| 프롬프트로 직접 요청 | 인증 + RBAC 멀티테넌시(메타데이터 필터는 보안용 아님) |
| LLM 제공사로 전송 | 온프레미스 호스팅 |
| DB 직접 해킹 | 청크 암호화(벡터는 복호화 필요), 벡터 노이즈·변환·차원축소 |

## 요약
- RAG 지식 베이스는 대개 **비공개 정보**를 담으므로, 그 정보에 **어떻게 접근되는지 이해하고 통제**하는 것이 핵심이다.
- 프롬프트 직접 요청은 **인증 + RBAC 멀티테넌시**로 막고(메타데이터 필터는 보안용이 아님), LLM 제공사 전송 위험은 **온프레미스**로 통제한다.
- **암호화**는 도움되나, 벡터 DB는 ANN을 위해 **조밀 벡터를 복호화 상태로** 둬야 하고 그 벡터에서 **원문 재구성**이 가능하다는 고유 위험이 있다(노이즈·변환 등 연구 중).
- 이 기법들을 broader 사이버보안 조치와 결합해 프로덕션 RAG 보안을 높여라. 마지막 강의는 **멀티모달 RAG**다.
