# Multimodal RAG

## 개요
- 정보는 텍스트뿐 아니라 **슬라이드·PDF·이미지** 등 다양한 형식에 담겨 있다. **멀티모달 모델(multimodal model)** 덕분에 이런 데이터도 RAG 지식 베이스에 넣을 수 있다.
- 전형적 멀티모달 RAG는 텍스트·이미지를 프롬프트로 받고, 지식 베이스에 텍스트·이미지를 저장하며, 텍스트 응답을 생성한다. 이를 위해 **멀티모달 임베딩 모델**과 **언어-비전 모델(language vision model)** 이 필요하다.
- PDF·슬라이드는 정보 밀도가 높아 **이미지 청킹**이 필요하며, 최신 **PDF RAG**(페이지를 격자로 분할해 ColBERT처럼 검색) 방식이 유망하다.

## 내용

### 멀티모달 모델이란
- 여러 데이터 타입을 다루도록 설계된 모델. 가장 흔한 조합은 **텍스트+이미지**이며 오디오·비디오도 가능. 멀티모달 RAG를 위해 **리트리버와 LLM 둘 다** 멀티모달로 업그레이드해야 한다.

### ① 멀티모달 임베딩 모델
- 여러 형식의 데이터를 **같은 벡터 공간**에 임베딩. 예: "dog"과 "puppy"가 가깝듯, **개 이미지**도 그 근처에 배치. "tree"와 나무 이미지도 서로 가깝되 다른 영역에.
- 즉 텍스트 임베딩 모델처럼 **유사 의미를 가깝게** 두되, 여러 **모달리티**에 대해 이를 수행.
- 검색은 익숙한 방식: 지식 베이스의 이미지·텍스트를 같은 공간에 임베딩 → 프롬프트(이미지든 텍스트든)를 같은 모델로 임베딩 → 벡터 검색으로 가까운 이미지/문서 반환 → 증강 프롬프트에 추가.

### ② 언어-비전 모델(language vision model)
- 텍스트+이미지를 처리하는 LLM. 텍스트 전용 LLM과 유사하되 **토큰화된 이미지**를 처리.
- **이미지 토큰화**: 이미지를 여러 **패치(patch)** 로 나눠 각각 토큰으로 표현. 해상도에 따라 이미지당 약 100~1,000 토큰. 중요한 건 토큰 수가 아니라, 이미지·텍스트 모두 **토큰 시퀀스로 변환**된다는 점.
- 이후 텍스트 전용 LLM처럼 멀티모달 토큰 시퀀스를 트랜스포머에 통과시켜 텍스트·이미지와 그 관계를 이해하고 보통 **텍스트 토큰**을 출력.

### 아키텍처 업그레이드
- 멀티모달 임베딩 모델 + 언어-비전 모델을 갖추면, 이미지·텍스트를 함께 저장하도록 RAG를 올리는 건 간단하다. 고수준 아키텍처는 사실상 동일하되 이미지·텍스트를 모두 다룬다.
- 이점: **이미지로 쉽게 변환되는** 많은 파일 형식(슬라이드·PDF)을 수집할 수 있다.

### PDF·슬라이드 청킹 문제
- 슬라이드·PDF는 한 페이지에 텍스트·차트·캡션·이미지가 뒤섞여 **정보 밀도가 높다**. 하나의 벡터로 한 페이지의 뉘앙스를 담기 어려워 → **이미지도 텍스트처럼 청킹**해야 한다.
- **초기 방식**: 페이지의 어느 부분이 차트·이미지·텍스트인지 감지하는 정교한 기법. 그러나 여전히 **오류가 많고 까다롭다**.
- **최신 방식 — PDF RAG**: 경계가 합리적인지 신경 쓰지 않고 페이지를 그냥 **정사각형 격자(grid)** 로 분할. 각 사각형을 멀티모달 임베딩 모델로 조밀 벡터로 임베딩 → 페이지가 벡터 1개가 아니라 예를 들어 1,000개로 표현.
  - 검색은 **ColBERT와 유사**: 프롬프트의 각 단어가 페이지에서 **가장 잘 맞는 사각형**을 찾고, 그 점수들을 합산해 페이지 전체를 채점.
  - 장점: 어떤 이미지든 격자로 분할 가능해 **유연**하고 검색 성능도 좋음 → 유망한 방향.
  - 단점: 벡터 DB에 **엄청난 수의 벡터**를 저장해야 함. (벡터 DB들이 관련 도구를 점차 지원)

### 현황
- 멀티모달 RAG는 빠르게 발전 중인 최첨단 기술. 대부분의 LLM 제공사가 **언어-비전 모델**을 제공하는 반면, **멀티모달 임베딩 모델**은 상대적으로 실험적이다.

## 예시

### 멀티모달 RAG 구성 요소 업그레이드
| 구성 요소 | 변경 |
|-----------|------|
| 임베딩 모델 | 멀티모달(텍스트·이미지를 같은 공간에) |
| LLM | 언어-비전 모델(토큰화된 이미지 처리) |
| 지식 베이스 | 텍스트+이미지 저장 |

### PDF 청킹 방식
| 방식 | 특징 |
|------|------|
| 요소 감지(초기) | 차트·이미지·텍스트 구분 시도, 오류 많음 |
| PDF RAG(격자) | 페이지를 사각형 격자로 분할, ColBERT식 검색, 유연·고성능, 벡터 다량 |

## 요약
- **멀티모달 RAG** 는 텍스트뿐 아니라 이미지·PDF·슬라이드를 지식 베이스에 담아, **멀티모달 임베딩 모델**(여러 형식을 같은 벡터 공간에)과 **언어-비전 모델**(토큰화된 이미지 처리)로 구현한다.
- 검색·아키텍처는 기존과 유사하되, PDF·슬라이드는 정보 밀도가 높아 **이미지 청킹**이 필요하다.
- 최신 **PDF RAG** 는 페이지를 **격자로 분할**해 각 칸을 임베딩하고 **ColBERT식**으로 검색 — 유연·고성능이나 벡터 저장량이 크다.
- 언어-비전 모델은 널리 제공되지만 멀티모달 임베딩 모델은 아직 실험적이며, 이 분야는 빠르게 발전 중이다. 이로써 코스 전체가 마무리된다.
