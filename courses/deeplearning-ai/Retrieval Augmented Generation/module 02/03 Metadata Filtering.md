# Metadata Filtering

## 개요
- **메타데이터 필터링(metadata filtering)** 은 리트리버에서 가장 단순·친숙한 기법으로, 문서의 **메타데이터**(제목·저자·작성일·접근 권한 등)를 **엄격한 기준(rigid criteria)** 으로 걸러 결과를 좁힌다.
- 스프레드시트의 표 필터링과 같은 개념이며, SQL 쿼리처럼 작동한다.
- 그 자체로는 검색 기법이 아니라 **다른 검색 기법의 결과를 정제(refine)하는 도구**다. 단독으로는 쓸모없고 반드시 다른 기법과 짝지어야 한다.

## 내용

### 작동 방식 (신문사 예시)
- 신문사가 과거 기사 리트리버를 만든다고 하자. 지식 베이스에는 수천 개 기사가 있고, 각 기사는 **제목·발행일·저자·섹션** 등 여러 메타데이터로 태깅된다.
- 전체 본문은 지식 베이스에 있지만, 시스템은 **메타데이터 기준으로만** 검색한다 — SQL 쿼리와 비슷하다.
  - 단일 조건: 특정 날짜에 발행된 모든 기사, 특정 저자의 모든 기사.
  - 복합 조건: "2024년 6~7월 사이 오피니언 섹션에 특정 기자가 쓴 기사" → **모든 조건을 만족하는 기사만** 반환.

### 필터는 프롬프트가 아니라 "사용자 속성"으로 결정
- 전형적 RAG에서 메타데이터 필터링은 검색 자체가 아니라 **다른 기법의 결과를 좁히는 데** 쓴다.
- 필터는 보통 **프롬프트 내용**이 아니라 **요청하는 사용자의 속성**으로 정해진다.
  - **접근 권한**: 무료/유료 기사 메타데이터 → 유료 구독자가 아니면 유료 기사를 제외.
  - **지역(region)**: 기사 발행 지역 메타데이터 → 독자의 위치를 감지해 해당 지역 기사만 반환.

### 장점
1. **개념적으로 단순** → 이해·디버깅이 쉽다.
2. **빠르고 성숙하며 잘 최적화**된 접근.
3. (가장 중요) **엄격한 기준으로 문서 포함 여부를 결정**할 수 있는 **유일한** 방법. 어떤 문서를 반드시 포함/제외할지 엄격히 정의하려면 이 방법뿐이다.

### 한계
- 진정한 검색 기법이 아니라 **다른 두 기법(키워드·시맨틱)의 결과를 정제하는 도구**에 가깝다.
- **지나치게 경직**되고, 문서의 **내용(content)을 무시**하며, 필터를 통과한 문서를 **랭킹할 방법이 없다**.
- 메타데이터 필터링만으로 만든 리트리버는 사실상 쓸모없다 → 반드시 다른 검색 기법과 결합해야 실질적 가치를 낸다. 특히 문서 **내용이 프롬프트와 실제로 관련 있는지** 판단할 방법이 필요하다.

## 예시

### 메타데이터 필터링 활용
| 목적 | 필터 기준(메타데이터) | 결정 근거 |
|------|----------------------|-----------|
| 복합 검색 | 섹션 + 기간 + 저자 | 프롬프트/요구사항 |
| 접근 제어 | 무료/유료 | 사용자 구독 상태 |
| 지역 제한 | 발행 지역 | 사용자 위치 |

## 요약
- **메타데이터 필터링**은 문서의 메타데이터(제목·저자·날짜·권한·지역 등)를 **엄격한 기준**으로 걸러 결과를 좁히는, SQL/스프레드시트 필터와 같은 단순한 기법이다.
- 필터는 대개 프롬프트가 아니라 **사용자 속성**(구독 상태·지역 등)으로 결정되며, **엄격한 포함/제외**를 할 수 있는 유일한 방법이다.
- 단, 내용을 무시하고 랭킹이 없어 **단독으로는 무용**하며, 키워드·시맨틱 검색과 결합해야 한다.
- 다음 강의에서 문서 내용의 관련성을 판단하는 **키워드 검색**을 다룬다.
