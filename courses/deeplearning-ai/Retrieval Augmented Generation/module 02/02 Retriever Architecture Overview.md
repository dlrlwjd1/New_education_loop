# Retriever Architecture Overview

## 개요
- 리트리버는 지식 베이스에서 프롬프트에 가장 관련 있는 문서를 빠르게 골라 LLM에 넘긴다. 대부분의 현대 리트리버는 **두 가지 검색 기법**을 함께 쓴다.
- **키워드 검색(keyword search)** = 프롬프트의 정확한 단어를 포함한 문서 찾기, **시맨틱 검색(semantic search)** = 프롬프트와 의미가 유사한 문서 찾기.
- 두 결과를 **메타데이터 필터링(metadata filtering)** 으로 거른 뒤 결합해 최종 랭킹을 만드는 방식을 **하이브리드 검색(hybrid search)** 이라 한다.

## 내용

### 전체 흐름
1. 프롬프트가 리트리버로 전달된다. 리트리버는 지식 베이스(DB에 있는 텍스트 파일 묶음)에 접근한다.
2. **두 가지 검색**을 병행:
   - **키워드 검색**: 프롬프트의 **정확한 단어**를 포함한 문서를 찾는다. 수십 년간 정보 검색을 이끈 검증된 전통적 방식.
   - **시맨틱 검색**: 프롬프트와 **의미가 유사한** 문서를 찾는다. 같은 단어가 없어도 관련 문서를 찾아 더 유연하다.
3. 각 기법이 문서 컬렉션(예: 각 20~50개)을 반환. 두 목록에 겹치는 문서가 많지만, 검색 방식이 달라 **한쪽에서 더 높게 랭킹**될 수 있다.
4. 각 목록을 **메타데이터로 필터링**한다. 예: 어떤 문서는 엔지니어링 팀용, 어떤 문서는 HR용 → 사용자가 속한 팀을 알아 해당 부서 문서만 통과시킨다.
5. 필터링된 두 목록(키워드 + 시맨틱)을 **결합**해 최종 관련도 랭킹을 만든다.
6. 최종 목록의 **상위 문서**를 반환 → 증강 프롬프트에 추가. 검색 완료.

### 세 기법의 역할
- **키워드 검색**: 사용자가 쓴 **정확한 단어**에 민감하게 반응.
- **시맨틱 검색**: 같은 단어가 없어도 **의미가 유사한** 문서를 찾는 유연성.
- **메타데이터 필터링**: 다른 두 방식으론 불가능한 **엄격한 기준**으로 문서를 배제.

### 하이브리드 검색(hybrid search)
- 여러 기법을 조합해 최종 랭킹을 내는 방식. 각 기법이 상호 보완적 이점을 제공한다.
- 고성능 리트리버 설계 = 각 기법의 **상대적 강점**을 이해하고, 프로젝트 필요에 맞게 **기법 간 균형(balance)** 을 튜닝하는 것.

## 예시

### 세 기법 비교
| 기법 | 하는 일 | 강점 |
|------|---------|------|
| 키워드 검색 | 정확한 단어 포함 문서 | 정확한 용어에 민감 |
| 시맨틱 검색 | 의미가 유사한 문서 | 다른 단어여도 관련 문서 발견 |
| 메타데이터 필터링 | 기준으로 문서 배제 | 엄격한 조건 적용(권한·부서 등) |

## 요약
- 현대 리트리버는 **키워드 검색 + 시맨틱 검색**을 병행하고, **메타데이터 필터링**으로 거른 두 목록을 **결합해 최종 랭킹**을 만든다 — 이를 **하이브리드 검색**이라 한다.
- 키워드는 정확한 단어에, 시맨틱은 의미 유사성에 강하며, 메타데이터 필터링은 엄격한 기준으로 배제한다.
- 좋은 리트리버 설계는 각 기법의 강점을 이해해 **균형을 튜닝**하는 것이다.
- 다음 강의부터 가장 단순한 **메타데이터 필터링**을 시작으로 세 기법을 하나씩 다룬다.
