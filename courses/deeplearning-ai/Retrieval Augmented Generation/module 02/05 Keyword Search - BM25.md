# Keyword Search - BM25

## 개요
- **BM25(Best Matching 25)** 는 대부분의 리트리버가 쓰는 키워드 검색 알고리즘으로, 창안자들이 제안한 25번째 점수 함수 변형이라 이 이름이 붙었다.
- TF-IDF를 두 가지로 개선한다: ① **용어 빈도 포화(term frequency saturation)** — 키워드 반복의 **수확 체감**, ② **문서 길이 정규화(document length normalization)** — 긴 문서 페널티를 **체감** 방식으로.
- 두 개의 **튜닝 가능한 하이퍼파라미터**를 제공해 데이터셋에 맞출 수 있어, TF-IDF보다 성능이 좋으면서 연산 비용은 비슷하고 더 유연하다.

## 내용

### BM25가 TF-IDF를 개선하는 점
- 공식은 TF-IDF와 유사하되, 단일 키워드에 대한 단일 문서의 관련 점수를 계산하고, 모든 키워드에 대해 합산해 문서의 총 관련 점수(랭킹용)를 낸다.

1. **용어 빈도 포화(term frequency saturation)**
   - 키워드가 더 많이 나올수록 **수확 체감(diminishing returns)**. 예: "pizza"를 20번 포함한 문서가 10번 포함한 문서보다 정확히 2배 관련 있는 건 아니다 → 추가 등장을 할인.

2. **문서 길이 정규화 (체감 페널티)**
   - TF-IDF처럼 긴 문서를 여전히 페널티하되, **체감 방식**으로 적용. TF-IDF는 긴 문서를 **지나치게 공격적으로** 할인할 수 있다.
   - BM25는 문서가 길어질수록 **추가 페널티를 점점 줄여**, 긴 문서라도 키워드 빈도가 충분히 높으면 여전히 높은 점수를 받는다.

3. **튜닝 가능한 하이퍼파라미터 2개**
   - **용어 빈도 포화**의 정도와 **문서 길이 정규화**의 정도를 조절 — 즉 반복 키워드에 대한 보상이 얼마나 빨리 멈추는지, 길이에 대한 페널티가 얼마나 빨리 붙는지.
   - 프로덕션에서는 지식 베이스 데이터에 가장 잘 맞도록 이 값들을 튜닝한다.

### 왜 BM25가 표준인가
- 관련 문서를 찾는 성능이 **TF-IDF보다 유의미하게 우수**하고, 연산 자원은 대략 동등하며, 데이터셋에 맞춘 튜닝이 가능해 훨씬 유연하다.

### 키워드 검색 정리
- 핵심 아이디어: 프롬프트의 키워드가 각 문서에 **얼마나 자주 나오는지**로 문서를 매칭.
- 이 과정에서 프롬프트·문서를 **희소 벡터(sparse vector)** 로 변환하고, TF-IDF나 BM25는 그 희소 벡터를 처리해 점수·랭킹하는 서로 다른 방식이다.
- 키워드 희소성, 문서 내 등장 빈도, 문서 길이 같은 요소를 반영한다.

### 강점과 약점
- **강점**:
  - **단순함** — 실전에서 잘 작동하며, 단독으로도 꽤 좋은 성능을 내 더 고급 기법이 넘기 힘든 경쟁적 벤치마크를 종종 세운다.
  - 검색된 문서가 사용자 프롬프트의 **키워드를 확실히 포함**한다. 특히 사용자가 **전문 용어·정확한 제품명**을 쓸 것으로 예상될 때 정확한 키워드 매칭이 중요하다.
- **약점**:
  - 쿼리가 문서의 단어와 **정확히 일치하는 키워드**를 포함해야 한다. 의미는 비슷하지만 단어가 다르면 매칭하지 못한다 → **시맨틱 검색**이 이 문제를 해결.

## 예시

### TF-IDF vs BM25
| 항목 | TF-IDF | BM25 |
|------|--------|------|
| 키워드 반복 | 선형 증가 | **수확 체감**(포화) |
| 긴 문서 페널티 | 공격적일 수 있음 | **체감** 페널티 |
| 하이퍼파라미터 | 없음 | 2개(튜닝 가능) |
| 위치 | 기준선 | 프로덕션 표준 |

## 요약
- **BM25** 는 TF-IDF를 개선한 프로덕션 표준 키워드 검색 알고리즘으로, **용어 빈도 포화**(반복 수확 체감)와 **체감식 문서 길이 정규화**를 적용한다.
- **2개의 튜닝 가능한 하이퍼파라미터**로 데이터셋에 맞출 수 있어, TF-IDF보다 성능이 좋고 비용은 비슷하며 더 유연하다.
- 키워드 검색은 단순하고 강력하며 **정확한 용어·제품명 매칭**에 특히 유용하지만, **단어가 정확히 일치**해야 하는 한계가 있다.
