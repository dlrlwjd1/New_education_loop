# Agentic RAG

## 개요
- **에이전틱 워크플로(agentic workflow)** 는 RAG 전반에 **여러 LLM** 을 두고 각자 한 단계를 맡기는 방식이다(쿼리 확장·프롬프트 재작성·인용 생성 등에서 이미 본 아이디어).
- 두 가지 변화: ① 작업을 **여러 단계·결정**으로 나누어 각기 다른 LLM 호출로 처리, ② LLM에 **도구(tool)**(코드 인터프리터·웹 브라우저·벡터 DB) 접근 제공.
- **순차·조건·반복·병렬** 워크플로 패턴이 있으며, 각 단계에 **서로 다른(작고 빠른/특화된) 모델**을 쓸 수 있다 — LLM을 독립 해법이 아니라 **모듈**로 보는 사고 전환.

## 내용

### 에이전틱 시스템의 두 변화
- 일반: 프롬프트 → 응답(단순).
- 에이전틱:
  1. 작업을 **일련의 단계·결정**으로 다루고, 각 단계를 **다른 LLM 호출**로 완료.
  2. LLM에 **더 넓은 도구**(코드 인터프리터, 웹 브라우저, RAG의 경우 벡터 DB) 접근 제공.

### 예시 에이전틱 RAG 워크플로
1. 사용자 프롬프트를 작은 **라우터 LLM(router)** 이 먼저 처리 — 벡터 DB 호출이 필요한지 판단, **yes/no** 만 출력(이 작업에 특화).
2. **no**면 검색을 건너뛰고 별도 LLM이 바로 응답 생성. **yes**면 벡터 DB에서 검색.
3. 검색했으면 **평가 LLM(evaluator)** 이 문서가 답하기에 충분한지 판단 → 부족하면 **추가 검색** 요청.
4. 충분하면 증강 프롬프트를 구성해 LLM이 응답 생성.
5. 마지막 LLM이 응답에 **인용(citation)** 추가.

### 핵심 원리
- 에이전틱 시스템 설계는 **플로차트 그리기**와 같다. 각 LLM은 여전히 텍스트 입력→텍스트 출력이지만, 프롬프트의 여정에서 **하나의 작업**만 맡는다.
- 모든 단계에 **같은 LLM을 쓸 필요 없다**. 라우터·평가는 단순 작업이라 **가볍고 빠르고 싼** 모델, 초안 생성은 **큰** 모델, 인용은 **인용 특화** 모델을 쓸 수 있다.

### 에이전틱 워크플로 패턴
- **순차(sequential)**: 출력을 여러 LLM에 선형으로 통과(예: 쿼리 파서 → 쿼리 재작성 → 인용 생성). 각 LLM이 한 단계에 특화.
- **조건(conditional)**: 라우터 LLM이 여러 경로 중 하나를 선택(검색 필요 여부, 또는 강점이 다른 여러 LLM 중 선택).
- **반복(iterative)**: 조건과 유사하되 프롬프트를 앞 단계로 되돌려 **루프** 형성. 예: 기존 코드베이스와 통합되는 코드 생성 — 평가 LLM이 (코드 인터프리터 도움으로) 각 초안을 평가·피드백하며 적합할 때까지 반복.
- **병렬(parallel)**: **오케스트레이터(orchestrator) LLM** 이 프롬프트를 여러 작업으로 쪼개 각각 다른 LLM에 할당, **신서사이저(synthesizer) LLM** 이 결과를 재결합. 예: 두 논문의 핵심 통찰 비교 — 각 논문을 다른 LLM이 요약·평가하고 오케스트레이터가 종합.

### 구현과 사고 전환
- 단순한 에이전틱 시스템은 로직을 직접 구현하면 되고, 복잡해지면 이를 돕는 다양한 도구·라이브러리·플랫폼이 있다.
- 사고 전환: LLM이 **독립 해법**이 아니라 더 큰 워크플로 안의 **모듈**로 보이기 시작한다. 그러면 각 단계에 잘 맞는 **작은 모델이나 몇몇 작업만 뛰어난 모델**을 기꺼이 쓰게 되어, 더 유능한 RAG를 유연하게 만들 수 있다.

## 예시

### 에이전틱 워크플로 패턴
| 패턴 | 설명 | 예 |
|------|------|-----|
| 순차 | 여러 LLM 선형 통과 | 파서→재작성→인용 |
| 조건 | 라우터가 경로 선택 | 검색 필요 여부 판단 |
| 반복 | 앞 단계로 루프 | 코드 생성 재시도 |
| 병렬 | 오케스트레이터 분할→신서사이저 종합 | 두 논문 비교 |

### 예시 워크플로의 LLM 역할
| LLM | 역할 | 모델 크기 |
|-----|------|-----------|
| 라우터 | 검색 필요 여부(yes/no) | 작고 빠름 |
| 평가 | 문서 충분성 판단 | 작고 빠름 |
| 생성 | 응답 초안 | 큼 |
| 인용 | 출처 추가 | 인용 특화 |

## 요약
- **에이전틱 RAG** 는 여러 LLM에 각각 한 단계(라우팅·검색 평가·생성·인용 등)를 맡기고 **도구** 접근을 주는 방식으로, 설계는 **플로차트 그리기**와 같다.
- 단계마다 **다른 모델**(가벼운 라우터/평가, 큰 생성, 특화 인용)을 쓸 수 있다.
- 패턴은 **순차·조건·반복·병렬**이 있으며, 조합해 더 유능한 시스템을 만든다.
- LLM을 독립 해법이 아니라 **모듈**로 보는 사고 전환이 핵심이다. 다음 강의는 **RAG vs 파인튜닝**이다.
