# Handling Hallucinations

## 개요
- 잘 설계된 RAG도 여전히 **환각(hallucination)** 을 일으킬 수 있어, 탐지·감소·정확한 출처 인용이 RAG 파이프라인의 가장 중요한 부분이다.
- LLM은 진위가 아니라 **개연성 있는 텍스트**를 생성하도록 설계됐기에 환각이 생기며, 환각은 **그럴듯하게 들려** 탐지가 어렵고 신뢰를 잃게 한다.
- 완벽한 해법은 없지만, RAG 자체가 최선의 접근 중 하나다. 핵심 대책은 **검색 정보에 근거(grounding)** 시키기, **출처 인용**(+ ContextCite 같은 외부 검증), **환각 중심 벤치마크(ALCE 등)** 로 테스트하기다.

## 내용

### 환각 예시와 원인
- 예: 온라인 상점 챗봇에 "학생 할인 있나요?"라고 물음. 리트리버는 시니어·신규 고객 10% 할인 정보를 찾았고, 시스템 프롬프트는 "친절하라"고 함 → LLM이 **"물론이죠, 학생증으로 10% 할인 가능"** 이라 답하지만 **학생 할인은 실제로 없음**(지어냄).
- 원인: LLM은 약간의 무작위성과 함께 **개연성 있는 텍스트 시퀀스**를 생성하도록 설계됐다. 개연성 있는 것이 대개 사실이지만 항상은 아니며, LLM은 **참/거짓이 아니라 개연/비개연**을 구분한다.

### 환각이 문제인 이유
1. 사용자에게 **부정확한 정보** 제공.
2. 환각은 정의상 **그럴듯해서** 완전한 헛소리보다 **탐지가 어렵다**.
3. 대부분이 정확해도 가끔의 환각이 **신뢰를 잃게** 한다.

### 환각의 다양한 유형(할인 예)
- 실제 시니어 할인을 정확히 설명하되 **수치를 오기**(10%를 5%로).
- 존재하는 시니어 할인을 **없다고** 잘못 진술.
- 존재하지 않는 할인을 **완전히 지어냄**.
- → 정확성에 확신을 가지려면 **여러 수준에서** 생성 텍스트를 평가해야 한다.

### 냉정한 진실 — 완벽한 해법은 없다
- 현재로선 환각의 완벽한 해법이 없다. 다만 **RAG가 가장 좋은 접근 중 하나**이며, RAG를 다듬어 빈도를 더 줄일 수 있다.

### 대책
- **지식 베이스가 없다면**: 신뢰할 외부 진실이 없어 선택지가 제한적. 한 방법은 **자기일관성 검사(self-consistency checking)** — 같은 프롬프트로 여러 번 생성해 사실 정보가 일관되는지 확인(환각은 비일관적일 것이라는 전제). 그러나 비용이 크고 불안정.
- **지식 베이스가 있다면(=RAG)**: 최선은 응답을 **검색 정보에 근거(ground)** 시키는 것.
  - **시스템 프롬프트 수정**: "검색된 정보에 기반해서만 사실 주장을 하라".
  - **출처 인용(cite sources)**: 문장/문단 끝마다 출처를 인용하게 하면 근거화 가능성↑, 사람이 검증하기도 쉬움.
    - 위험: LLM이 **인용 자체를 환각**할 수 있음. 출처 인용에 파인튜닝된 모델은 더 신뢰할 만하나, 더 확신하려면 **외부 시스템** 필요.
    - **ContextCite**: 응답을 **문장 단위**로 처리해 각 문장을 검색된 문맥 문서 중 하나에 귀속(attribute). 근거 없는 문장은 **"no source"** 태그, 일부는 유사도 점수 제공. 이 태그로 최종 출처 인용을 만들거나, LLM이 얼마나 자주 근거화하는지 **평가**에 사용.

### 환각 중심 벤치마크 — ALCE
- **ALCE 벤치마크**: 시스템이 응답 생성 시 얼마나 잘 출처를 참조·인용하는지 측정. 사전 구성된 지식 베이스·샘플 질문을 제공 → 내 RAG로 응답 생성 → ALCE가 평가.
- 세 지표: **유창성(fluency)**, **정확성(correctness)**, **인용 품질(citation quality)** — 텍스트가 얼마나 명료한지, 사실적으로 정확한지, 인용이 올바른 출처와 얼마나 정렬되는지.
- 이 벤치마크가 프로덕션 환각을 통제하진 않지만, 시스템이 환각을 얼마나 잘 피하고 출처를 인용하는지 **감을 준다**.

## 예시

### 환각 대책 정리
| 상황 | 접근 |
|------|------|
| 지식 베이스 없음 | 자기일관성 검사(비용·불안정) |
| 지식 베이스 있음(RAG) | 검색 정보에 근거 + 출처 인용 |
| 인용 검증 | ContextCite(문장별 출처 귀속) |
| 시스템 테스트 | ALCE(유창성·정확성·인용 품질) |

## 요약
- RAG도 여전히 환각하며, 환각은 LLM이 **개연성 있는 텍스트**를 생성하기 때문에 발생하고 **그럴듯해서 위험**하다.
- 완벽한 해법은 없지만 RAG 자체가 최선의 대책 중 하나이며, 핵심은 응답을 **검색 정보에 근거화**하는 것이다.
- **시스템 프롬프트로 근거화 강제 + 출처 인용**(+ ContextCite 같은 외부 문장별 검증)으로 환각을 줄이고, **ALCE** 등 벤치마크로 유창성·정확성·인용 품질을 테스트한다.
- 다음 강의에서 **LLM 성능 평가**를 다룬다.
