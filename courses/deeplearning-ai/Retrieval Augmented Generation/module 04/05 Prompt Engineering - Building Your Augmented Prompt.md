# Prompt Engineering: Building Your Augmented Prompt

## 개요
- **프롬프트 엔지니어링(prompt engineering)** 은 더 나은 결과를 내는 다양한 프롬프트 기법의 총칭이다.
- 코드에서 프롬프트는 흔히 OpenAI의 **메시지 형식(messages format)** — `content` + `role`(system/user/assistant)의 JSON — 으로 구성되며, 멀티턴 대화는 전체 대화를 매번 함께 전송한다.
- RAG 프롬프트 구성의 핵심은 **시스템 프롬프트(system prompt)** 작성과, 시스템 프롬프트·대화 기록·검색된 청크·최신 사용자 질문을 담는 **프롬프트 템플릿(prompt template)** 이다.

## 내용

### 메시지 형식(messages format)
- 프롬프트를 메시지 시퀀스로 구조화. 각 메시지 = **content**(텍스트) + **role**:
  - **system**: LLM의 전반적 행동에 영향을 주는 고수준 지침.
  - **user**: 사용자가 보낸 프롬프트 기록.
  - **assistant**: LLM이 이전에 생성한 응답 기록.
- **멀티턴 대화(multi-turn conversation)**: LLM은 이전 발화를 기억하는 게 아니라, **전체 대화가 매번 메시지 형식으로 변환**되어 새 user 메시지와 함께 통째로 제출된다.
- 이 JSON은 하나의 텍스트 문자열(**chat template**)로 변환되며, 화살표·수직바 같은 **특수 태그**로 각 메시지의 시작/끝을 표시한다. LLM은 이 태그로 system/user/assistant를 구분하도록 훈련됐다.

### 시스템 프롬프트(system prompt) 작성
- LLM에게 **어떻게 행동할지** 고수준 지침을 준다. 항상 특정 톤으로 말하거나 특정 절차를 따르게 하려면 여기에 넣는다.
- 인기 챗봇의 시스템 프롬프트 예에서 관찰되는 것:
  - **길이가 매우 길다**(수 페이지도 가능) — 항상 길 필요는 없지만 그럴 유연성이 있음.
  - 초반에 **지식 컷오프·현재 날짜** → 정보가 얼마나 오래됐는지, 답할 위치인지 판단에 도움.
  - 후반에 **절차·톤** 지시 — 단계적 추론, 유해 요청 거부, 마크다운 응답 등. "지적 호기심이 있고 토론을 즐긴다" 같은 **성격(personality)** 부여도.
- RAG용 시스템 프롬프트 예: "검색된 문서만 사용해 답하라", "문서가 관련 있는지 판단하라", "응답에 출처를 인용하라", 상세히/간결히 답하기 등.
- 시스템 프롬프트는 보통 **모든 프롬프트에 추가**되므로, 이를 다듬는 데 시간을 쓰면 결과 스타일·품질이 크게 개선된다.

### 증강 프롬프트(augmented prompt)와 템플릿
- 증강 프롬프트는 여러 정보를 담으므로 **잘 설계된 프롬프트 템플릿**이 유용하다. 템플릿은 프롬프트의 고수준 구조와 각 콘텐츠가 주입될 위치를 정한다. 전형적 구성:
  1. **시스템 프롬프트**(행동 지침).
  2. (멀티턴이면) **이전 대화 메시지**.
  3. 리트리버가 반환한 **상위 5~10개 청크** + 처리 방법 안내.
  4. LLM이 답해야 할 **최신 사용자 프롬프트**.
- 템플릿의 장점: 개별 구성 요소를 바꿔 **프롬프트 구조를 쉽게 실험**하고 응답 변화를 확인할 수 있다.

## 예시

### 메시지 role
| role | 역할 |
|------|------|
| system | 전반적 행동·톤·절차 지침 |
| user | 사용자 프롬프트 |
| assistant | LLM의 이전 응답 |

### RAG 프롬프트 템플릿 구조
```
[system]   시스템 프롬프트(검색 문서만 사용, 출처 인용 등)
[history]  이전 user/assistant 메시지 (멀티턴)
[context]  검색된 상위 5~10개 청크 + 처리 안내
[user]     최신 사용자 질문
```

## 요약
- **프롬프트 엔지니어링**은 더 나은 결과를 위한 기법의 총칭이며, 코드에서는 **메시지 형식**(content+role: system/user/assistant)으로 프롬프트를 구성한다.
- 멀티턴 대화는 LLM이 기억하는 게 아니라 **전체 대화를 매번 함께 전송**하는 것이다.
- **시스템 프롬프트**는 모든 프롬프트에 붙는 고수준 지침으로(RAG에선 "검색 문서만 사용·출처 인용" 등), 다듬을 가치가 크다.
- **증강 프롬프트**는 시스템 프롬프트·대화 기록·검색 청크·최신 질문을 담는 **템플릿**으로 구성하면 실험·개선이 쉽다.
- 다음 강의에서 LLM 성능을 더 높이는 **고급 프롬프트 기법**을 다룬다.
