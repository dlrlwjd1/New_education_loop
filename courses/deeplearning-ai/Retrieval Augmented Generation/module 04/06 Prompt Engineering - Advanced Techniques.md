# Prompt Engineering: Advanced Techniques

## 개요
- 기본 프롬프트 템플릿 이후 시도할 고급 기법: **인컨텍스트 러닝(in-context learning, few-shot/one-shot)**, **단계적 추론 유도(scratchpad, chain-of-thought)**, 그리고 이를 내장한 **추론 모델(reasoning model)**.
- 이런 기법과 멀티턴 대화는 프롬프트·응답 길이를 늘려 **컨텍스트 윈도를 빠르게 소진**하므로 **컨텍스트 프루닝(context pruning)** 관리가 중요하다.
- 고급 기법은 **필요하다고 확인된 뒤에만** 도입하고, 프롬프팅은 과학이자 예술이므로 실험으로 최적을 찾는다.

## 내용

### 인컨텍스트 러닝(in-context learning)
- 원하는 출력의 **예시를 프롬프트에 추가**해 LLM이 구조·톤을 학습하게 한다(응답을 근거화하는 RAG와 같은 원리). 예: 고객 서비스 챗봇에 과거 요청+고품질 응답 예시를 넣기.
- 예시 여러 개 = **few-shot**, 하나 = **one-shot**.
- 구현:
  - 예시를 프롬프트에 **하드코딩**(안정적 행동이 필요할 때).
  - 매번 바꾸려면 **RAG로 예시를 검색**(성공한 고객 대화를 벡터 DB에 인덱싱 → 새 문의 시 유사 주제 대화를 검색해 주입). 사실상 일반 RAG지만 **예시 응답을 검색**한다는 점이 품질을 높인다.

### 단계적 추론 유도
- **스크래치패드(scratchpad)**: 최종 답 전에 "소리 내어 생각하라/단계적으로 접근하라"고 지시. scratchpad 태그 사이 토큰은 **사고·브레인스토밍 공간**이며 최종 답에 포함되지 않는다고 알린다.
- **생각의 사슬(chain-of-thought)**: 즉답 대신 단계적으로 풀게 함(먼저 필요한 단계를 생성한 뒤 그 단계를 따름). 계획·점진 접근이 **정확도를 높이고**, 과정을 보여줘 **오류 추적**도 쉽다.

### 추론 모델(reasoning model)
- 위 추론 전략이 성공적이라 많은 LLM이 **기본적으로 추론 모델**로 설계됨. 코딩·수학·계획·퍼즐·멀티스텝 워크플로에 강함.
- 내부적으로 **추론 토큰(reasoning tokens)** 을 먼저 생성(계획·옵션 검토, 스크래치패드처럼)한 뒤 **응답 토큰(response tokens)** 을 출력. 제공사에 따라 추론 토큰 접근 가능 여부가 다름.
- 추론 토큰이 정확도를 높이지만 **일반 토큰과 같은 비용**이 들어, 추론 모델은 **더 느리고 비싸다**. 그래도 문서 관련성 평가·복잡한 응답 통합에 강해, RAG에서 값어치를 할 수 있다.
- 주의: 많은 프롬프트 기법이 추론 모델엔 **잘 안 맞는다**.
  - "step-by-step으로 생각해"는 이미 훈련되어 **불필요**.
  - **인컨텍스트 러닝**도 예시 응답을 현재 질문에 섞어버려 잘 안 될 수 있음.
  - 대신 **구체적 목표**와 **원하는 출력 형식**을 명확히 주는 것이 낫다. 고수준 지침·취해야/피해야 할 접근을 준 뒤 검색된 문서를 **통째로(context dump)** 넘겨도 된다. (제공사 프롬프트 가이드 참고)

### 컨텍스트 윈도 관리
- 초기 프롬프트와 생성 토큰 모두 컨텍스트 윈도를 쓴다. 문서 주입·인컨텍스트 예시·추론 계획 등 고급 기법은 프롬프트·응답 길이를 늘려 윈도를 **빠르게 채운다**.
- **싱글턴**: 그 기법이 실제로 가치를 주는지 검증하고, chain-of-thought·인컨텍스트 러닝이 성능을 못 높이면 **제거**.
- **멀티턴 — 컨텍스트 프루닝(context pruning)**:
  - 단순: **최근 N개 메시지만** 유지(예: 마지막 5개).
  - 정교: 별도 LLM으로 **오래된 메시지를 요약**해 크기를 줄이되 핵심 보존.
  - 추론 모델은 대화 기록에서 **추론 토큰을 버리고 응답 토큰만** 유지.
  - RAG에선 보통 **최신 질문을 뒷받침하는 청크만** 포함(이전 질문의 청크 제외).
- 필요하면 **더 긴 컨텍스트 윈도 모델**로 전환할 수 있으나, 긴 프롬프트는 여전히 느리고 비싸므로 신중히 설계.

### 실무 권장
- RAG가 반드시 고급 기법을 써야 하는 건 아니다 — **간단한 템플릿 + 잘 쓴 시스템 프롬프트**로 충분할 수 있다.
- 고급 기법은 **필요하다고 명확해진 뒤에만** 추가하고, 프롬프팅은 예술에 가까우니 다양한 프롬프트를 **실험**하라.

## 예시

### 고급 기법 요약
| 기법 | 하는 일 | 주의 |
|------|---------|------|
| in-context learning | 예시로 구조·톤 학습(few/one-shot) | 추론 모델엔 잘 안 맞을 수 있음 |
| scratchpad / CoT | 단계적 사고 유도 | 추론 모델엔 불필요 |
| 추론 모델 | 추론 토큰 후 응답 | 느리고 비쌈, 형식 명확히 |
| 컨텍스트 프루닝 | 오래된 메시지 제거·요약 | 멀티턴 필수 |

## 요약
- 고급 프롬프트 기법: **인컨텍스트 러닝(few/one-shot)**, **스크래치패드·생각의 사슬**, 그리고 이를 내장한 **추론 모델**(느리고 비싸지만 복잡한 작업·관련성 평가에 강함).
- 추론 모델에는 "step-by-step"·인컨텍스트 러닝이 잘 안 맞고, **구체적 목표·출력 형식**을 주고 문서를 통째로 넘기는 편이 낫다.
- 이런 기법과 멀티턴은 컨텍스트 윈도를 빠르게 채우므로 **컨텍스트 프루닝**(최근 N개 유지, 요약, 추론 토큰 제거, 최신 청크만)이 중요하다.
- 고급 기법은 **필요할 때만** 도입하고 실험으로 최적을 찾아라. 다음 강의는 **환각 처리**다.
