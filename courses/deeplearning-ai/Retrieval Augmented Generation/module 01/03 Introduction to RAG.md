# Introduction to RAG

## 개요
- RAG는 LLM에게 **학습 데이터에 없는 정보에 대한 접근**을 제공해 성능을 개선하는 접근법이다.
- 사람이 질문에 답하는 과정을 **① 정보 수집(retrieval) → ② 그 정보로 추론·응답(generation)** 의 두 단계로 볼 수 있듯, LLM도 검색 단계의 이점을 누린다 — 이것이 RAG의 핵심 아이디어다.
- 구현의 핵심: LLM에 보내기 전 **프롬프트를 수정**해 검색된 정보를 덧붙인다(augmented prompt). 이 검색을 담당하는 구성 요소가 **리트리버(retriever)** 다.

## 내용

### 세 가지 질문 예시 — 정보의 필요 정도
1. "호텔은 왜 주말에 비싼가?" → 이미 아는 상식으로 **즉답 가능**(주말 여행 수요 증가).
2. "이번 주말 밴쿠버 호텔은 왜 유독 비싼가?" → **약간의 추가 정보** 필요(예: Taylor Swift 2일 공연 검색).
3. "밴쿠버는 왜 다운타운 근처 호텔 수용력이 더 많지 않은가?" → 도시 개발사·도시계획 등 **많은 전문 정보에 대한 심층 조사** 필요.

### 두 단계: Retrieval + Generation
- 응답 과정 = **필요한 정보 수집 → 그 정보로 추론해 응답**.
- 첫 질문처럼 수집이 불필요할 때도 있고, 조금 또는 많이 필요할 때도 있다.
- RAG에서 유용한 정보를 모으는 과정을 **검색(retrieval)**, 그 정보로 추론해 답하는 과정을 **생성(generation)** 이라 한다.

### LLM도 사람과 같은 이유로 검색이 필요하다
- LLM은 인터넷의 방대한 텍스트를 읽은 사람과 비슷하다고 볼 수 있다. 프롬프트를 주면 이 지식에 기대 응답한다.
- 하지만 LLM이 정확히 답하는 데 필요한 정보를 **모를 때**가 있다: 최신 사건이거나, 학습한 적 없는 전문 정보일 때.
- 사람에게 모든 주제의 전문가이길 기대할 수 없듯 LLM도 마찬가지며, **더 나은 정보에 접근할수록 더 나은 응답**을 낸다. LLM도 검색 단계의 이점을 본다는 인식이 RAG의 핵심이다.

### LLM은 수학 모델 — 학습에 없는 정보의 문제
- LLM은 개방 인터넷의 대규모 데이터로 훈련된 수학 모델로, **훈련 데이터에 담긴 정보를 학습**한다. 프롬프트를 보낼 때, 관련 정보가 (이상적으로는 여러 번) 훈련 데이터에 포함됐길 바라는 것이다.
- 그러나 많은 정보가 포함되지 않는다: 기업의 **비공개 데이터베이스**, 숨겨지거나 접근이 어려운 정보, 매 순간 새로 발행되는 뉴스 등.

### 해결책 — 프롬프트에 넣어라 (augmented prompt)
- 핵심 아이디어: LLM에 보내기 전 **프롬프트를 수정**해, 사용자의 원 질문에 **응답에 도움 되는 정보를 추가**한다.
- 흐름(예: "이번 주말 밴쿠버 호텔은 왜 비싼가?"):
  1. **검색(retrieval)** 단계로 관련 정보를 수집.
  2. 원 질문 + 검색된 정보를 합친 **증강 프롬프트(augmented prompt)** 를 LLM에 제공.
  3. 이제 LLM은 정확히 답할 정보를 갖는다.

### 리트리버(retriever)와 지식 베이스
- 이 정보는 어딘가에서 검색되어야 한다. 이를 담당하는 구성 요소가 **리트리버(retriever)** 다.
- 리트리버는 **신뢰할 수 있고 관련 있으며 때로 비공개인 정보의 지식 베이스(knowledge base)** 를 관리한다.
- 프롬프트를 받으면 리트리버가 지식 베이스에서 **가장 관련 있는 정보**를 찾아 LLM에 전달하고, 모델은 그 정보를 활용해 응답한다.
- 이름 그대로 **Retrieval(검색)** 로 **Augmented(증강)** 된 **Generation(생성)** — 지식 베이스에서 관련 정보를 먼저 검색해 LLM의 생성을 개선하는 것이다.

## 예시

### 질문별 필요 정보와 RAG 처리
| 질문 | 필요 정보 | 처리 |
|------|-----------|------|
| 호텔은 왜 주말에 비싼가? | 없음(상식) | 즉답(generation만) |
| 이번 주말 밴쿠버 호텔은 왜 비싼가? | 소량(최신 이벤트) | retrieval + generation |
| 밴쿠버는 왜 호텔 수용력이 적은가? | 다량(전문·역사) | 심층 retrieval + generation |

## 요약
- RAG는 LLM에 **학습하지 않은 정보에 대한 접근**을 주어 성능을 높인다 — 사람처럼 LLM도 **정보 수집(retrieval) → 추론·응답(generation)** 의 이점을 본다.
- LLM은 훈련 데이터에 없는 비공개·최신·전문 정보를 모르므로, **프롬프트에 검색된 정보를 덧붙인 증강 프롬프트**로 이를 보완한다.
- 검색을 담당하는 **리트리버**가 신뢰할 수 있는 **지식 베이스**에서 가장 관련 있는 정보를 찾아 LLM에 전달한다.
- 다음 강의에서는 RAG가 실제로 쓰이는 활용 사례를 살펴본다.
