# Introduction to Information Retrieval

## 개요
- **리트리버(retriever)** 는 LLM이 학습 때 접하지 못했을 유용한 정보를 제공하는 구성 요소다. 도서관 비유로 그 작동을 이해할 수 있다.
- 리트리버는 지식 베이스 문서를 **인덱스(index)** 로 정리하고, 프롬프트의 의미를 파악해 문서를 **관련도 점수(relevance score)** 로 **랭킹**한 뒤 상위 문서를 반환한다.
- 관련 문서는 포함하되 무관한 문서는 제외해야 하며, **몇 개를 반환할지**가 핵심 과제다. 대규모에서는 보통 **벡터 데이터베이스(vector database)** 위에 구축된다.

## 내용

### 도서관 비유
- "집에서 뉴욕 스타일 피자 만드는 법?"을 답하러 도서관에 갔다고 하자.
  - 도서관의 **책 컬렉션** ↔ 리트리버의 **문서 지식 베이스**.
  - 책이 주제·장르·저자별로 **섹션·선반**에 정리됨 ↔ 리트리버가 문서를 **인덱스**로 정리(검색 용이).
  - **사서(librarian)** 가 질문의 의미를 이해해 요리·이탈리아 요리·뉴욕 섹션을 찾아줌 ↔ 리트리버가 프롬프트 의미를 파악해 인덱스를 검색.

### 리트리버의 작동 흐름
1. 프롬프트를 처리해 **근본 의미**를 이해한다.
2. 그 이해로 문서 인덱스를 검색한다.
3. 프롬프트에 가장 관련 있다고 판단한 문서를 지식 베이스에서 반환한다.

### 관련도 랭킹(ranking)
- 검색 시 리트리버는 각 문서에 관련도를 정량화한 **수치 점수**를 매긴다. 보통 **프롬프트 텍스트와 문서 텍스트 간 유사도(similarity)** 의 측정치다.
- 점수가 가장 높은 문서를 반환한다. 유사도 점수 계산 방식은 여러 가지가 있으며 코스 뒤에서 배운다.

### 핵심 과제 — 몇 개를 반환할까
- 잘 설계된 리트리버는 관련 문서를 반환하되 **무관한 문서는 보류(withhold)** 해야 한다.
  - 모든 문서를 반환하면: 관련 문서는 다 포함되지만 무관 정보의 산에 묻히고, **프롬프트 비용이 커지거나 컨텍스트 윈도를 소진**한다.
  - 최상위 1개만 반환하면: 2·3·4위의 가치 있는 관련 정보를 놓친다.
- 이상적으로는 완벽히 랭킹해 정확한 개수를 반환하지만, 실제로는 관련 문서를 너무 낮게, 무관 문서를 너무 높게 매기기도 해 **반환 개수 결정이 어렵다**.
- 성능 최적화를 위해 시간에 걸쳐 **모니터링하고 다양한 설정을 실험**해야 한다(코스에서 광범위하게 다룸).

### 정보 검색(information retrieval)이라는 분야
- 익숙한 소프트웨어들이 리트리버와 유사한 일을 한다: **웹 검색엔진**(검색어 → 관련 웹페이지), **관계형 데이터베이스**(SQL 쿼리 → 일치하는 행/테이블).
- **정보 검색(information retrieval)** 분야는 LLM 등장 전에 이미 성숙했으며, 그 아이디어가 리트리버·RAG 설계의 바탕이 된다.

### 구현 — 벡터 데이터베이스
- 리트리버 구현 방법은 이론상 다양하다. 대부분의 회사가 데이터를 전통적 관계형 DB에 두고 있어 거기서 검색하면 좋겠지만…
- **대규모에서는** 대부분의 리트리버가 **벡터 데이터베이스(vector database)** 위에 구축된다 — 프롬프트에 가장 근접한 문서를 **빠르게 찾도록 최적화된** 특수 데이터베이스다(필수는 아님).
- 코스에서는 여러 검색 기술의 바탕인 **정보 검색의 일반 원리**와, 프로덕션 규모 RAG의 리트리버로 흔히 쓰이는 **벡터 데이터베이스**를 모두 배운다.

## 예시

### 도서관 ↔ 리트리버 대응
| 도서관 | 리트리버 |
|--------|----------|
| 책 컬렉션 | 문서 지식 베이스 |
| 섹션·선반 정리 | 인덱스(index) |
| 사서의 질문 이해 | 프롬프트 의미 처리 |
| 관련 책 찾기 | 관련도 점수로 랭킹·반환 |

### 유사한 소프트웨어
- 웹 검색엔진: 검색어 → 관련 웹페이지
- 관계형 DB: SQL 쿼리 → 일치 행/테이블

## 요약
- 리트리버는 도서관의 사서처럼 프롬프트의 **의미를 이해**해, **인덱스**로 정리된 지식 베이스에서 문서를 **관련도 점수로 랭킹**해 상위를 반환한다.
- 핵심 과제는 관련 문서는 포함하되 무관 문서는 제외하고 **적절한 개수**를 반환하는 것으로, 완벽하지 않기에 지속적 모니터링·실험이 필요하다.
- 리트리버는 성숙한 **정보 검색** 분야에 뿌리를 두며(웹 검색·관계형 DB와 유사), 대규모에서는 보통 **벡터 데이터베이스** 위에 구축된다.
