# RAG Architecture Overview

## 개요
- RAG의 세 핵심 구성 요소는 **LLM, 지식 베이스(knowledge base), 리트리버(retriever)** 이며, 이 강의는 이들이 어떻게 함께 작동하는지 전체 아키텍처를 다룬다.
- 사용자 경험은 일반 LLM과 **동일**하다(프롬프트 입력 → 응답). 내부적으로 프롬프트가 먼저 리트리버로 우회(side route)해 관련 문서를 가져와 **증강 프롬프트(augmented prompt)** 를 만드는 단계가 추가될 뿐이다.
- 리트리버 추가만으로 정보 접근성·환각 감소·최신성·출처 인용·역할 분담 등 여러 이점이 생긴다.

## 내용

### 동작 흐름 (일반 LLM vs RAG)
- **일반 LLM**: 프롬프트 입력 → LLM이 처리·응답.
- **RAG (사용자 경험은 동일, 내부 단계 추가)**:
  1. 프롬프트를 받으면 먼저 **리트리버로 라우팅**.
  2. 리트리버가 **지식 베이스(실질적으로는 유용한 문서들의 데이터베이스)** 를 쿼리해 가장 관련 있는 문서를 반환.
  3. 원 프롬프트에 관련 문서 정보를 결합한 **증강 프롬프트** 생성. (예: "다음 질문에 답하라: 이번 주말 밴쿠버 호텔은 왜 비싼가? 도움이 될 관련 기사 5개는 다음과 같다: …")
  4. 증강 프롬프트를 LLM에 보내 응답 생성 — LLM은 **학습 지식 + 검색된 맥락** 모두를 바탕으로 답한다.
- 결과: 약간의 지연(latency)이 추가되지만, 응답이 **정확·최신·맥락 인식적**일 가능성이 높아진다.

### 리트리버 추가의 이점
1. **정보 접근성**: 회사 정책, 개인 정보, 오늘 아침 헤드라인 등 원래 접근 불가능했을 정보를 LLM에 제공 — RAG가 유일한 방법일 때가 많다.
2. **환각(hallucination) 감소**: 환각은 학습에서 제외됐거나 드물게 언급된 주제에 대해 생성할 때 흔히 발생한다. 관련 정보를 프롬프트에 직접 넣어 응답을 **근거(ground)** 시키면 일반적·오해성 텍스트 생성이 줄어든다.
3. **최신성 유지**: 모델 재훈련(retraining)은 비싸고 오래 걸린다. RAG는 다른 DB처럼 **지식 베이스만 업데이트**하면 되고, 변경 사항이 인덱싱되는 즉시 새 정보로 응답할 수 있다.
4. **출처 인용(cite sources)**: 증강 프롬프트에 인용 정보를 넣으면 LLM이 응답에 포함할 수 있어, 근거 제공은 물론 독자가 더 깊이 파고들어 검증할 수 있다.
5. **역할 분담(각자 강점에 집중)**: 리트리버가 방대한 정보를 필터링해 가장 중요·관련 있는 것을 간결히 제시하고, LLM은 **텍스트 생성**에 집중한다. 사실 탐색·필터링을 LLM에 의존하지 않는다.

### 간단한 코드 데모 (개념)
```python
# retrieve: 리트리버 래퍼 — 텍스트 쿼리를 받아 지식 베이스의 관련 문서 반환
# generate: LLM 래퍼 — 텍스트 프롬프트를 받아 LLM 응답 반환

prompt = "why are hotel prices in Vancouver super expensive this weekend?"

# 1) 직접 LLM에 → 부정확할 수 있음
generate(prompt)

# 2) 리트리버로 관련 정보 검색
docs = retrieve(prompt)

# 3) 증강 프롬프트 구성
augmented = f"respond to the following prompt: {prompt}\nusing the following information retrieved to help you answer:\n{docs}"

# 4) 증강 프롬프트를 LLM에 → 정확한 응답
generate(augmented)
```
- 핵심: **프롬프트에 추가 맥락을 더해 LLM이 더 정확히 답하게 하는 것** — 그게 RAG의 전부다.

## 예시

### RAG의 이점 요약
| 이점 | 설명 |
|------|------|
| 정보 접근성 | 비공개·개인·최신 정보를 LLM에 제공 |
| 환각 감소 | 관련 정보로 응답을 근거화 |
| 최신성 | 지식 베이스만 갱신하면 즉시 반영(재훈련 불필요) |
| 출처 인용 | 응답에 인용 포함 → 검증 가능 |
| 역할 분담 | 리트리버=필터링, LLM=생성 |

## 요약
- RAG 아키텍처는 일반 LLM 흐름에 **리트리버를 통한 우회(검색 → 증강 프롬프트)** 단계를 더한 것이며, 사용자 경험은 동일하되 약간의 지연이 추가된다.
- 세 구성 요소 **LLM·지식 베이스·리트리버**가 협력해, LLM은 학습 지식과 검색된 맥락을 함께 활용해 응답한다.
- 리트리버 추가의 핵심 이점: 정보 접근성, 환각 감소, 최신성(지식 베이스만 갱신), 출처 인용, 역할 분담(리트리버=필터링/LLM=생성).
- 다음 강의부터 각 구성 요소를 더 자세히 살펴본다.
