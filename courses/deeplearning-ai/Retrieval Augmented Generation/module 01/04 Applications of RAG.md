# Applications of RAG

## 개요
- RAG의 핵심은 **기성(off-the-shelf) LLM** 을, 학습 시 접근하지 못했을 정보의 **지식 베이스(knowledge base)** 와 짝짓는 것이다.
- 코드 생성, 기업 맞춤 챗봇, 헬스케어·법률, AI 웹 검색 요약, 개인화 비서 등 다양한 맥락에 적용된다.
- **LLM 학습에 쓰이지 않았을 정보에 접근할 수 있을 때마다** 유용한 RAG 애플리케이션을 만들 잠재력이 있다.

## 내용

### ① 코드 생성(code generation)
- LLM은 방대한 공개 코드(사실상 모든 공개 Git 저장소)를 학습했지만, **특정 프로젝트에 맞는 정확한 코드**를 생성하려면 그 프로젝트의 클래스·함수·정의, 전반적 코딩 스타일 등 **전문 정보**가 필요하다.
- 자신의 **코드베이스를 지식 베이스로** 쓰는 RAG를 만들면, 관련 클래스·정의·파일을 검색해 프로젝트에 맞는 코드 생성·질문 응답이 훨씬 좋아진다.

### ② 기업 맞춤 챗봇
- 모든 회사는 고유한 제품·정책·커뮤니케이션 지침을 갖는다. 이런 **사내 문서를 지식 베이스로** 삼는다.
  - **고객 서비스 챗봇**: 제품 정보, 현재 재고, 흔한 문제 해결 단계를 아는 챗봇.
  - **사내 챗봇**: 회사 정책을 정확히 답하거나 유용한 문서로 안내.
- 지식 베이스가 LLM 응답을 회사의 **구체적 제품·정책에 근거(ground)** 시켜, 일반적이거나 오해를 부르는 응답을 최소화한다.

### ③ 헬스케어·법률
- 지식 베이스에 특정 사건의 법률 문서, 최근 발행된 의학 저널 텍스트 등을 담는다.
- **정밀성이 필수이고 틈새·비공개 정보가 방대한** 분야에서는, RAG 방식이 **충분히 정확하고 비공개 정보를 활용하는** LLM 기반 제품을 배포하는 유일한 길일 수 있다.

### ④ AI 지원 웹 검색
- 검색엔진은 역사적으로 리트리버처럼 작동해 왔다(쿼리 → 관련 웹사이트 반환).
- 오늘날 검색엔진은 결과에 대한 **AI 요약**을 제공해 유용한 정보를 훑어보기 쉽게 준다. 이 AI 웹 요약은 사실상 **지식 베이스가 인터넷 전체**인 RAG 시스템이다.

### ⑤ 개인화 비서(personalized assistant)
- 대규모 RAG뿐 아니라 **고도로 개인화된 소규모** RAG도 강력하다.
- 문자·이메일·워드프로세서·캘린더의 비서가 메시지 전송, 일정 정리, 문서 초안 작성 등을 돕는다.
- 이때 지식 베이스는 상대적으로 작다(내 문자·연락처·이메일·문서 폴더 등). 이런 문서는 **중요한 맥락이 밀도 높게** 담겨 있어, 소규모 개인 정보에 접근하는 RAG가 내 작업에 훨씬 관련성 높은 결과를 낸다.

### 공통 원리
- RAG는 매우 다양한 맥락에 적용된다. 기업·조직·개인 모두 LLM 생성 품질을 높일 정보 모음을 갖고 있다.
- **LLM 학습에 쓰이지 않았을 정보에 접근할 수 있을 때마다** RAG 애플리케이션의 잠재력이 있으며, 원래 불가능했던 맥락에서도 LLM을 쓸 수 있게 해준다.

## 예시

### 애플리케이션별 지식 베이스
| 애플리케이션 | 지식 베이스 |
|--------------|-------------|
| 코드 생성 | 자체 코드베이스(클래스·정의·파일) |
| 기업 챗봇 | 사내 문서(제품·정책·재고) |
| 헬스케어·법률 | 의학 저널·사건 법률 문서 |
| AI 웹 검색 요약 | 인터넷 전체 |
| 개인화 비서 | 내 문자·이메일·문서 폴더 |

## 요약
- RAG는 기성 LLM에 **지식 베이스**를 결합하는 방식으로, 코드 생성·기업 챗봇·헬스케어/법률·AI 웹 검색·개인화 비서 등 폭넓게 적용된다.
- 공통 원리는 응답을 특정 정보에 **근거(ground)** 시켜 정확성을 높이는 것이며, 지식 베이스는 대규모(인터넷)부터 소규모(개인 이메일)까지 다양하다.
- **LLM이 학습하지 않았을 정보에 접근할 수 있으면** 언제나 RAG를 적용할 기회가 있다.
