# Choosing a model

## 개요
- LLM으로 소프트웨어 애플리케이션을 만들 때는 모델 크기, 성능, 비용, 배포 방식, 오픈소스 여부를 고려해야 한다.
- 모델 크기는 대략적인 능력의 힌트가 되지만, 실제 성능은 애플리케이션에서 직접 테스트해보는 것이 중요하다.
- 폐쇄형(closed-source) 모델은 사용이 쉽고 강력한 경우가 많고, 오픈소스(open-source) 모델은 통제권과 데이터 프라이버시 측면에서 장점이 있다.

## 내용

### 모델 크기와 능력
LLM에는 다양한 선택지가 있다. 큰 모델과 작은 모델, 오픈소스 모델과 폐쇄형 모델이 있으며, 애플리케이션 목적에 따라 적절한 모델을 선택해야 한다.

모델의 능력을 가늠하는 한 가지 방법은 모델 크기, 즉 파라미터(parameter) 수를 보는 것이다.

**약 10억 파라미터 규모 모델**은 패턴 매칭과 기본적인 세계 지식이 필요한 작업에 적합할 수 있다. 예를 들어 식당 리뷰를 긍정 또는 부정 감성으로 분류하는 작업은 음식 관련 기본 표현을 이해하고 패턴을 찾는 작업이므로, 10억 파라미터 모델로도 충분할 수 있다.

**약 100억 파라미터 규모 모델**은 더 많은 세계 지식을 갖고 있으며, 기본적인 지시를 더 잘 따른다. 음식 주문 챗봇처럼 여러 지시를 따라야 하는 애플리케이션에서는 100억 파라미터 모델이 적합할 수 있고, 필요하면 파인튜닝으로 특정 지시 수행 능력을 더 개선할 수 있다.

**1,000억 파라미터 이상 모델**은 풍부한 세계 지식과 복잡한 추론 능력이 필요한 작업에 더 적합하다. 물리, 철학, 역사, 과학 같은 다양한 영역의 깊은 지식과 복잡한 사고가 필요한 작업에서는 큰 모델이 유리할 수 있다. 브레인스토밍 파트너처럼 복잡한 아이디어를 함께 생각해야 하는 작업에서도 큰 모델을 사용할 수 있다.

### 실험적 선택의 중요성
LLM 애플리케이션 개발은 매우 실험적(empirical)이다. 일반적인 가이드라인은 도움이 되지만, 어떤 모델이 특정 애플리케이션에서 실제로 잘 동작할지는 미리 정확히 알기 어렵다.

따라서 몇 가지 모델을 직접 테스트해보고, 실제 결과를 비교한 뒤 애플리케이션에 가장 잘 맞는 모델을 선택하는 것이 좋다.

### 폐쇄형 모델
폐쇄형(closed-source) 모델은 보통 클라우드 프로그래밍 인터페이스(API)를 통해 사용할 수 있다.

장점:
- 애플리케이션에 통합하기 쉽다.
- 몇 줄의 코드로 호출할 수 있다.
- 가장 크고 강력한 모델 중 상당수가 폐쇄형 API로 제공된다.
- 대형 제공업체가 API 호출 비용을 낮추기 위해 많은 최적화를 해두었기 때문에 비교적 저렴하게 사용할 수 있다.

단점:
- 특정 제공업체에 종속되는 벤더 락인(vendor lock-in) 위험이 있다.
- 다른 LLM으로 바꿀 때 모든 프롬프트와 기능을 다시 테스트해야 한다.

현재는 한 LLM에서 다른 LLM으로 바꾸는 전환 비용이 아주 높지는 않지만, 재테스트와 품질 검증 비용은 존재한다.

### 오픈소스 모델
오픈소스(open-source) 모델도 많이 공개되고 있다. 오픈소스 모델의 가장 큰 장점은 통제권이다.

장점:
- 모델에 대한 완전한 통제권을 가질 수 있다.
- 제공업체가 모델을 중단하거나 폐기(deprecate)할 위험을 줄일 수 있다.
- 자체 서버, PC, 노트북, 모바일 기기 등에서 직접 실행할 수 있다.
- 데이터 프라이버시와 접근 제어를 직접 관리할 수 있다.

예를 들어 전자 건강 기록(electronic health records)을 다루는 애플리케이션에서는 환자 프라이버시 때문에 데이터를 클라우드 제공업체에 업로드할 수 없을 수 있다. 이런 경우 오픈소스 모델을 자체 컴퓨터에서 실행해 민감한 데이터를 외부로 보내지 않는 방식이 필요할 수 있다.

## 예시

### 모델 크기별 대략적 특징
| 모델 크기 | 특징 | 적합한 예시 |
|------|------|------|
| 약 10억 파라미터 | 패턴 매칭, 기본 세계 지식 | 식당 리뷰 감성 분류 |
| 약 100억 파라미터 | 더 많은 세계 지식, 기본 지시 수행 | 음식 주문 챗봇 |
| 1,000억+ 파라미터 | 풍부한 세계 지식, 복잡한 추론 | 브레인스토밍, 깊은 지식이 필요한 작업 |

### 폐쇄형 모델과 오픈소스 모델 비교
| 항목 | 폐쇄형 모델 | 오픈소스 모델 |
|------|------|------|
| 접근 방식 | 클라우드 API | 직접 실행 가능 |
| 장점 | 통합이 쉽고 강력한 모델 접근 가능 | 통제권, 프라이버시, 자체 배포 |
| 단점 | 벤더 락인 가능성 | 운영과 배포 책임 필요 |
| 적합한 상황 | 빠르게 강력한 모델을 쓰고 싶을 때 | 데이터 프라이버시나 온프레미스 실행이 중요할 때 |

## 요약
- 모델 크기는 LLM의 능력을 가늠하는 힌트가 되지만, 실제 애플리케이션에서는 직접 테스트해야 한다.
- 작은 모델은 단순한 패턴 매칭에, 큰 모델은 복잡한 추론과 풍부한 지식이 필요한 작업에 더 적합할 수 있다.
- 폐쇄형 모델은 사용이 쉽고 강력한 경우가 많지만, 벤더 락인 위험이 있다.
- 오픈소스 모델은 통제권과 프라이버시 측면에서 유리하며, 민감한 데이터를 다루는 애플리케이션에 적합할 수 있다.
