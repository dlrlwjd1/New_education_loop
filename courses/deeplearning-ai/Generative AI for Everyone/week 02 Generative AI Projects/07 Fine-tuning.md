# Fine-tuning

## 개요
- 파인튜닝(fine-tuning)은 RAG와 함께 LLM의 능력을 확장하는 기술이다.
- RAG가 프롬프트에 추가 정보를 넣는 방식이라면, 파인튜닝은 모델이 추가 데이터로 조금 더 학습하게 해 출력 방식이나 도메인 지식을 조정한다.
- 파인튜닝은 특정 스타일 출력, 프롬프트로 정의하기 어려운 작업, 특정 도메인 지식 습득, 작은 모델 성능 향상에 유용하다.

## 내용

### RAG와 파인튜닝의 차이
RAG는 LLM에 추가 정보를 제공하는 한 가지 방법이다. 질문과 관련된 문서나 문서 일부를 찾아 프롬프트에 넣고, LLM이 그 맥락을 바탕으로 답하도록 한다.

파인튜닝(fine-tuning)은 다른 방식으로 LLM에 더 많은 정보를 반영한다. 특히 LLM의 입력 길이나 컨텍스트 창(context window)에 들어가기 어려울 만큼 큰 맥락이 있거나, 모델이 특정 스타일로 출력하도록 만들고 싶을 때 유용하다.

다만 실제 구현은 RAG보다 조금 더 어렵다.

### 사전학습과 파인튜닝
LLM은 처음에 인터넷에서 수집한 수천억 개 또는 1조 개 이상의 단어를 이용해 다음 단어를 예측하도록 학습된다. 예를 들어 "my favorite food is a bagel with cream cheese" 같은 문장에서 다음 단어를 예측하는 방식이다.

이처럼 많은 데이터로 대규모 언어 모델을 처음 학습시키는 과정을 **사전학습(pre-training)** 이라고 한다.

파인튜닝은 이미 사전학습된 LLM에 추가 데이터를 조금 더 학습시켜 원하는 방향으로 출력을 바꾸는 과정이다.

예를 들어 모든 것에 대해 매우 긍정적이고 낙관적인 태도로 답하는 모델을 만들고 싶다면, 다음과 같은 긍정적인 문장들을 추가 데이터로 준비할 수 있다.

- "what a wonderful chocolate cake"
- "the novel was thrilling"

이런 문장들로 추가 학습을 시키면, 모델의 출력이 더 긍정적이고 낙관적인 방향으로 이동할 수 있다. 사전학습에는 수천억 단어가 필요하지만, 파인튜닝은 10,000단어, 100,000단어, 또는 더 많으면 1,000,000단어 같은 훨씬 작은 데이터셋으로도 효과를 낼 수 있다.

### 프롬프트로 정의하기 어려운 작업
파인튜닝이 유용한 첫 번째 경우는 작업을 프롬프트로 명확히 정의하기 어려울 때다.

예를 들어 고객 서비스 통화를 요약하는 작업을 생각해보자. 일반 LLM은 "고객이 모니터 문제를 상담원에게 설명했다"처럼 일반적인 요약을 만들 수 있다. 하지만 콜센터 관리자는 제품 모델명, 고객 ID, 문제 상황 같은 구체적인 정보를 포함한 특정 형식의 요약을 원할 수 있다.

이 경우 사람이 직접 작성한 수백 개의 고품질 요약 예시를 만들어 LLM을 파인튜닝하면, 모델이 원하는 스타일과 세부 수준의 요약을 더 잘 생성할 수 있다.

### 특정 말투나 글쓰기 스타일 모방
파인튜닝은 특정 사람이나 캐릭터의 말투를 흉내 내는 데도 유용하다.

특정 사람의 말투는 프롬프트로 설명하기 어렵다. "Andrew Ng처럼 말해줘"라고 해도, 어떤 표현 습관과 문장 구조를 따라야 하는지 정확히 설명하기 쉽지 않다.

하지만 실제 발화 transcript를 많이 모아 파인튜닝하면, 모델이 해당 사람의 실제 단어 사용과 말투를 학습해 더 비슷한 문장을 만들 수 있다. 인공 캐릭터나 만화 캐릭터가 특정 스타일로 말하게 만드는 데도 같은 접근을 사용할 수 있다.

### 특정 도메인 지식 습득
파인튜닝이 유용한 두 번째 큰 영역은 특정 도메인의 지식을 습득하게 하는 것이다.

예를 들어 의료 노트는 일반 영어와 매우 다르다.

- `Pt`: patient
- `c/o`: complaining of
- `SOB`: shortness of breath
- `DOE`: dyspnea on exertion
- `PE`: physical examination

일반 영어로 학습된 LLM은 이런 의료 노트를 잘 처리하지 못할 수 있다. 하지만 의료 기록 모음으로 파인튜닝하면, 모델이 의료 노트의 표현 방식과 약어를 더 잘 이해하게 된다.

비슷하게 법률 문서도 일반적인 일상 언어와 다르다. 법률 문서에는 `hereof` 같은 표현이나 복잡한 조항 구조가 자주 등장한다. 법률 문서로 파인튜닝하면 LLM이 법률 문서를 읽고 처리하는 데 더 적합해질 수 있다.

금융 문서도 마찬가지다. 대량의 금융 문서로 파인튜닝하면, 금융 문서를 처리하는 애플리케이션에서 성능을 높일 수 있다.

### 작은 모델을 특정 작업에 맞게 개선
파인튜닝의 또 다른 활용은 작은 모델이 큰 모델이 필요했던 작업을 수행하게 만드는 것이다.

매우 큰 모델, 예를 들어 1,000억 개 이상의 파라미터를 가진 모델은 복잡한 추론이나 많은 지식이 필요한 작업에 강할 수 있다. 하지만 응답 지연(latency)이 길고, 자체 컴퓨터에서 운영하면 비용이 높을 수 있다. 이런 모델은 GPU 서버 같은 특수한 고성능 컴퓨터가 필요할 수 있으며, 일반 노트북이나 스마트폰에서 실행하기 어렵다.

반면 10억 개 파라미터 규모의 작은 모델은 노트북, PC, 모바일 기기에서 훨씬 쉽게 실행될 수 있다. 작은 모델은 큰 모델만큼 똑똑하지 않을 수 있지만, 특정 작업에 맞게 파인튜닝하면 충분히 좋은 성능을 낼 수 있다.

예를 들어 식당 리뷰를 긍정 또는 부정 감성으로 분류하는 작업은 1,000억 개 파라미터 모델이 꼭 필요하지 않을 수 있다. 수백 개 또는 1,000개 정도의 예시로 작은 모델을 파인튜닝하면 이 작업을 잘 수행할 수 있다.

### 비용 관점
RAG와 파인튜닝은 모두 상대적으로 저렴하게 시작할 수 있다.

- RAG는 주로 프롬프트 구성 방식을 바꾸는 작업이다.
- 파인튜닝은 데이터 양에 따라 수십 달러 또는 수백 달러 수준에서 시작할 수 있다.

반면 자체 모델을 처음부터 사전학습하는 것은 현재 매우 비싸다. 보통 대형 기술 기업처럼 충분한 자원이 있는 조직만 시도한다.

## 예시

### 파인튜닝이 유용한 경우
| 경우 | 설명 |
|------|------|
| 특정 스타일 출력 | 긍정적 말투, 특정 사람의 말투, 캐릭터 말투 |
| 프롬프트로 정의하기 어려운 작업 | 콜센터 통화의 특정 형식 요약 |
| 도메인 지식 습득 | 의료 노트, 법률 문서, 금융 문서 처리 |
| 작은 모델 성능 향상 | 작은 모델을 특정 작업에 맞게 조정 |

### RAG와 파인튜닝 비교
| 항목 | RAG | 파인튜닝 |
|------|------|------|
| 방식 | 관련 정보를 검색해 프롬프트에 추가 | 추가 데이터로 모델을 더 학습 |
| 강점 | 최신/외부 문서 기반 답변 | 특정 스타일, 형식, 도메인 적응 |
| 구현 난이도 | 비교적 쉬움 | RAG보다 어려움 |
| 비용 | 주로 프롬프트/검색 시스템 비용 | 데이터 양에 따라 수십~수백 달러부터 가능 |

## 요약
- 파인튜닝은 사전학습된 LLM을 추가 데이터로 더 학습시켜 원하는 출력 방식이나 도메인 지식을 반영하는 기술이다.
- 프롬프트로 설명하기 어려운 스타일, 형식, 도메인 지식에는 파인튜닝이 효과적일 수 있다.
- 작은 모델을 특정 작업에 맞게 파인튜닝하면 큰 모델보다 낮은 비용과 짧은 지연 시간으로 충분한 성능을 얻을 수 있다.
- 자체 사전학습은 매우 비싸지만, RAG와 파인튜닝은 많은 프로젝트에서 현실적인 개선 수단이다.
