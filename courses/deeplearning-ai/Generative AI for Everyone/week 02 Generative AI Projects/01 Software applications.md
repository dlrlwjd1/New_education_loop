# Software applications

## 개요
- Week 2는 생성형 AI를 소프트웨어 애플리케이션에 통합하는 방법과, 단순 프롬프팅을 넘어서는 기술 옵션을 다룬다.
- 생성형 AI는 기존에 수개월이 걸리던 일부 AI 애플리케이션 개발을 며칠 또는 일주일 수준으로 단축할 수 있다.
- 특히 텍스트, 이미지, 오디오 같은 비정형 데이터(unstructured data)를 다루는 애플리케이션에서 효과가 크다.

## 내용

### Week 2의 초점
지난주에는 생성형 AI를 사용하는 두 가지 방식, 즉 웹 사용자 인터페이스(web user interface)를 통한 사용과 소프트웨어 애플리케이션에 통합하는 방식을 살펴보았다.

이번 주에는 생성형 AI로 만들어지는 소프트웨어 애플리케이션과, 단순히 프롬프트를 입력하는 것보다 더 강력한 기술 옵션을 살펴본다. 예를 들어 공개 인터넷 데이터에서 학습한 지식만 사용하는 것이 아니라, 회사가 보유한 독점 문서(proprietary documents)를 기반으로 동작하게 만드는 방법도 다룬다.

### 생성형 AI 애플리케이션 예시
지난주에 다룬 생성형 AI 애플리케이션 예시는 다음과 같다.

- 회사 주차 정책에 대한 질문에 답하기
- 인터넷의 식당 리뷰를 읽고 평판 모니터링하기
- 음식 주문을 받는 챗봇 만들기

이런 애플리케이션 중 일부는 생성형 AI 이전에도 존재했다. 하지만 생성형 AI는 이런 애플리케이션을 훨씬 쉽게 만들 수 있게 했고, 많은 경우 성능도 더 좋게 만들었다.

### 기존 지도 학습 방식의 개발 과정
식당 리뷰를 읽고 긍정/부정 감성을 분류하는 평판 모니터링 시스템을 예로 들면, 기존 방식은 지도 학습(supervised learning)을 사용했다.

지도 학습 기반 시스템을 만들려면 보통 다음 과정이 필요했다.

1. 식당 리뷰와 감성 라벨을 수집한다.
2. 수백 개 또는 수천 개의 라벨링된 데이터 포인트를 준비한다.
3. 머신러닝 엔지니어가 데이터를 사용해 모델을 학습시킨다.
4. AWS, Google Cloud, Azure 같은 클라우드 서비스에 모델을 배포한다.
5. 운영 환경에서 안정적으로 동작하는지 확인한다.

예를 들어 다음과 같은 데이터가 필요했다.

- "best soup dumplings I've ever eaten" → 긍정
- "the colorful table cloths made me smile" → 긍정
- "not worth the three month wait" → 부정

이 방식은 가치 있는 AI 시스템을 만들 수 있었지만, 좋은 머신러닝 팀이 있어도 6~12개월이 걸리는 경우가 많았다.

### 프롬프트 기반 개발 방식
생성형 AI를 사용하면 같은 감성 분류 시스템을 훨씬 간단하게 만들 수 있다.

프롬프트 기반 개발(prompt-based development)에서는 코드 안에서 다음과 같은 프롬프트를 정의한다.

- 지시문: "다음 리뷰를 긍정 또는 부정 감성으로 분류하라."
- 리뷰 텍스트: 분류할 실제 리뷰

그다음 한 줄의 코드로 LLM을 호출해 응답을 받고, 결과를 출력하면 된다. 기존 방식처럼 라벨링 데이터 수집, 모델 학습, 별도 배포 과정을 길게 거치지 않고도 빠르게 동작하는 프로토타입을 만들 수 있다.

### 개발 속도의 변화
기존 지도 학습 기반 접근은 다음과 같은 시간이 걸릴 수 있었다.

- 라벨링 데이터 수집: 약 1개월
- 모델 학습: 약 3개월
- 배포 및 안정화: 약 3개월

반면 프롬프트 기반 AI는 다음과 같은 속도로 진행될 수 있다.

- 프롬프트 작성: 몇 분 또는 몇 시간
- 배포: 몇 시간 또는 며칠

예전에는 훌륭한 머신러닝 팀이 6~12개월에 걸쳐 만들던 애플리케이션을, 이제는 훨씬 더 많은 사람들이 며칠 또는 일주일 안에 만들 수 있게 되었다. 이는 AI 애플리케이션 개발의 진입 장벽을 크게 낮추고 있다.

### 중요한 단서
생성형 AI가 모든 문제에 적합한 것은 아니다. 지난주에 본 것처럼 생성형 AI는 텍스트, 이미지, 오디오 같은 비정형 데이터에 특히 잘 작동한다.

따라서 생성형 AI 기반 애플리케이션을 고려할 때는 다루는 데이터가 비정형 데이터인지, 그리고 LLM이 잘 수행할 수 있는 작업인지 판단해야 한다.

## 예시

### 기존 지도 학습 방식과 프롬프트 기반 방식 비교
| 항목 | 기존 지도 학습 방식 | 프롬프트 기반 생성형 AI |
|------|------|------|
| 데이터 준비 | 수백~수천 개 라벨링 데이터 필요 | 프롬프트와 입력 텍스트로 시작 가능 |
| 모델 개발 | AI 팀이 모델 학습 | LLM 호출 |
| 배포 | 별도 모델 배포와 안정화 필요 | 기존 LLM API 또는 서비스 활용 |
| 시간 | 보통 수개월 | 몇 시간~며칠 가능 |
| 적합한 데이터 | 구조화/비정형 모두 가능하나 작업별 모델 필요 | 텍스트, 이미지, 오디오 등 비정형 데이터에 강함 |

### 감성 분류 프롬프트 예시
```text
Classify the following review as having either a positive or negative sentiment.

Review: Best bubble tea I've ever had.
```

예상 출력:

```text
Positive sentiment
```

## 요약
- Week 2는 생성형 AI를 소프트웨어 애플리케이션으로 구축하는 방법과 더 강력한 기술 옵션을 다룬다.
- 기존 지도 학습 방식은 라벨링 데이터 수집, 모델 학습, 배포에 많은 시간이 필요했다.
- 프롬프트 기반 생성형 AI는 간단한 프롬프트와 LLM 호출만으로 빠르게 애플리케이션을 만들 수 있게 한다.
- 이 변화는 AI 애플리케이션 개발의 진입 장벽을 낮추지만, 생성형 AI가 특히 비정형 데이터에 강하다는 한계를 함께 고려해야 한다.
