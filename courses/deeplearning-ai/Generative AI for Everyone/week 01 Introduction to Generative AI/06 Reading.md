# Reading

## 개요
- 읽기(reading) 작업은 긴 텍스트를 입력하고, 그보다 짧거나 비슷한 길이의 결과를 생성하는 작업이다.
- LLM은 교정, 요약, 이메일 라우팅, 감성 분석 같은 읽기 작업에 유용하다.
- 조직 업무에서는 읽기 작업을 웹 인터페이스에 수작업으로 붙여넣기보다 소프트웨어 기반 LLM 애플리케이션으로 자동화하는 경우가 많다.

## 내용

### 읽기 작업의 기본 형태
쓰기 작업이 짧은 프롬프트로 긴 텍스트를 생성하는 것이라면, 읽기 작업은 상대적으로 긴 입력을 읽고 짧은 출력이나 판단을 생성하는 작업이다.

예시:
- 긴 글을 읽고 요약 생성
- 문법 및 철자 오류 교정
- 고객 이메일을 읽고 불만 여부 판단
- 리뷰를 읽고 긍정/부정 감성 분류
- 대화 기록을 읽고 핵심 내용 요약

### 교정(proofreading)
LLM은 작성한 텍스트에서 철자 오류, 문법 오류, 어색한 문장을 찾아 고치는 데 유용하다.

예를 들어 "다음 텍스트를 교정해줘"라고 요청할 수 있다. 더 좋은 결과를 얻으려면 텍스트의 목적과 대상도 함께 알려주는 것이 좋다.

예시:
- "이 문장은 어린이용 봉제 인형을 판매하는 웹사이트에 들어갈 텍스트야."
- "철자와 문법 오류, 어색한 문장을 확인하고 수정해줘."

사람이 여러 번 읽어도 놓치는 오류를 LLM이 찾아낼 수 있기 때문에, 중요한 글을 작성할 때 보조 검토 도구로 활용할 수 있다.

### 긴 글 요약
LLM은 긴 기사나 논문을 빠르게 요약하는 데 사용할 수 있다.

강의에서는 Erik Brynjolfsson의 "The Turing Trap"이라는 긴 글을 읽을 시간이 없었을 때, 전체 글을 LLM 웹 인터페이스에 붙여넣고 요약을 생성한 사례를 소개한다.

요약을 통해 핵심 논지를 빠르게 파악할 수 있었다. 이 글의 핵심은 인간과 비슷한 AI를 만드는 것만이 중요한 것이 아니라, AI가 인간을 대체(automate)하기보다 보완하고 증강(augment)하도록 만드는 데 더 많은 노력이 필요하다는 점이었다.

LLM 요약은 긴 글을 완전히 대체하는 것은 아니지만, 시간이 부족할 때 빠르게 전체 흐름을 이해하는 데 도움이 된다.

### 고객 서비스 통화 요약
기업 환경에서는 고객 서비스 통화 기록을 요약하는 소프트웨어 기반 LLM 애플리케이션을 만들 수 있다.

흐름은 다음과 같다.

1. 고객 서비스 통화를 녹음한다.
2. 음성 인식 시스템으로 통화 내용을 텍스트 대본으로 변환한다.
3. LLM이 각 대본을 읽고 짧은 요약을 생성한다.
4. 관리자는 많은 통화 내용을 직접 읽지 않고도 요약을 통해 문제나 추세를 파악한다.

이런 작업은 대량의 대본을 사람이 하나씩 웹 인터페이스에 붙여넣기 어렵기 때문에, LLM을 포함한 소프트웨어 애플리케이션으로 구현하는 것이 적합하다.

### 고객 이메일 라우팅
LLM은 고객 이메일을 읽고 어떤 부서로 보낼지 결정하는 데 사용할 수 있다.

처음에는 "이 이메일을 읽고 적절한 부서로 라우팅해줘"라고만 프롬프트를 작성할 수 있다. 하지만 이 경우 LLM이 실제 조직에 존재하지 않는 "불만 부서" 같은 부서를 만들어낼 수 있다.

더 나은 프롬프트는 선택 가능한 부서 목록을 명시하는 것이다.

예시:
- "다음 이메일을 읽고 가장 적절한 부서를 선택해줘."
- "반드시 다음 목록 중 하나만 선택해: 의류, 배송, 결제, 반품."

이처럼 프롬프트에 충분한 맥락과 제약을 제공하면 더 일관된 결과를 얻을 수 있다.

### 평판 모니터링과 감성 분석
LLM은 리뷰나 고객 이메일을 읽고 긍정/부정 감성을 분류할 수 있다.

예를 들어 식당 리뷰에 "음식이 훌륭했고 서비스가 친절했다"는 내용이 있다면 긍정으로 분류할 수 있다. 소프트웨어가 매일 긍정 리뷰와 부정 리뷰 수를 집계하면, 시간에 따른 고객 감성 추세를 보여주는 대시보드를 만들 수 있다.

부정 리뷰가 갑자기 늘어나면, 식당 운영자가 문제를 빨리 알아차리고 대응할 수 있다.

## 예시

### 읽기 작업 예시
| 작업 | 입력 | 출력 |
|------|------|------|
| 교정 | 웹사이트 문구 | 수정된 문장 |
| 요약 | 긴 기사나 논문 | 핵심 요약 |
| 통화 요약 | 고객 서비스 대화 대본 | 짧은 통화 요약 |
| 이메일 라우팅 | 고객 이메일 | 담당 부서 |
| 감성 분석 | 고객 리뷰 | 긍정/부정 |

### 이메일 라우팅 프롬프트 개선
| 프롬프트 | 문제/효과 |
|------|------|
| 이 이메일을 읽고 적절한 부서로 보내줘 | 존재하지 않는 부서를 만들 수 있음 |
| 다음 부서 목록 중 하나만 선택해 이메일을 라우팅해줘 | 실제 조직 구조에 맞는 결과를 얻기 쉬움 |

## 요약
- 읽기 작업은 긴 텍스트를 읽고 짧은 판단, 요약, 분류를 생성하는 작업이다.
- LLM은 교정, 요약, 고객 서비스 통화 요약, 이메일 라우팅, 감성 분석에 활용할 수 있다.
- 업무에서 대량의 텍스트를 처리해야 하는 경우에는 웹 인터페이스보다 소프트웨어 기반 LLM 애플리케이션이 적합하다.
- 좋은 읽기 작업을 만들려면 LLM이 선택해야 할 범위와 필요한 맥락을 프롬프트에 명확히 제공해야 한다.
