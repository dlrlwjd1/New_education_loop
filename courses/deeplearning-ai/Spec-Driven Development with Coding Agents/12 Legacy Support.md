# Legacy Support

## 개요
- SDD·AI가 그린필드(신규)에만 좋다는 통념과 달리, **기존 레거시(legacy) 프로젝트에도 유효**하다 — 이 레슨은 기존 프로젝트에 SDD를 도입한다.

## 내용

### 레거시 설정
- 예제로 이미 아는 **AgentClinic MVP**를 사용하되, **specs 폴더 없이** main에서, **새 Claude Code 세션**·다른 디렉터리로 시작해 레거시처럼 만듦.
- 배경은 `README.md`, 미완 작업은 `TODO.md`에. (실제 레거시는 이슈 트래커·스프레드시트·워드 문서 등에 계획이 흩어져 있을 수 있음.)

### 헌법부터 (역공학)
- 워크플로대로 **헌법 단계**부터 — 레슨 5와 거의 같은 프롬프트에 **기존 산출물(여기선 to-do 파일)에서 로드맵 항목을 찾도록** 지시.
- 에이전트가 기존 코드베이스에서 SDD 산출물을 **발견·역공학(reverse engineer)** → 헌법이 향후 코드 변경을 **과거 개발자들의 결과물과 정렬**.
- 맥락이 있으면 더 추가 가능(예: 효율 개선 + 인기 기능 구현 임무). 프로세스는 같지만 산출물(코드·커밋·문서)이 많아 **대화가 더 풍부**하고 코드 탐색 **툴 콜**이 많이 보임.
- 생성된 헌법: 미션(청중·아이디어·부가 정보), 기술 스택(파일 구조·프레임워크 버전·확인 사항 추출), 로드맵(to-do에 맞춘 단계) → **커밋**. SDD에서 명세는 **버전 관리 전략의 일부**.

### 이후 워크플로 (동일)
- 레거시가 **SDD 기반** 위에 올려짐 → 이제부터는 이전 레슨과 완전히 동일.
- 다음 로드맵 기능(Phase 1 feedback form)을 대화로 계획 → 브랜치·명세 생성 → 기능 명세(계획·요구사항·검증) 검토·커밋 → 수정 후 구현 → 검증 → 커밋 → main 머지.
- **재계획** 시간 확보 — 방금 SDD를 도입해 튜닝할 것이 많을 수 있음.

## 요약
- SDD는 레거시에도 적용된다 — 에이전트가 기존 코드·문서에서 **헌법을 역공학**해 SDD 기반을 놓는다.
- 기반이 놓이면 **이후 워크플로는 그린필드와 동일**(계획·구현·검증·재계획).
- 수작업 없이 잘 문서화된 단계적 흐름을 얻고, **명세가 프로젝트의 기억(memory)** 이 되어 바래지 않는다.
