# Creating the Constitution

## 개요
- 에이전트에게 프로젝트의 **미션·청중·주요 결정**을 알려야 한다 — 이 레슨은 에이전트와 **함께 대화하며 헌법(Constitution)** 을 작성한다.
- 헌법 = **미션·기술 스택·로드맵** 세 기둥으로 이뤄진 전역 고수준 요구사항.

## 내용

### 헌법의 3대 기둥
- 프로젝트의 핵심 아이디어, 회사 선호 기술 스택과의 적합성, 계획된 기능을 담아 향후 기능 개발을 안내하고 이해관계자에게 프로젝트 형태를 설명.
- **혼자 쓰지 않고 에이전트와 대화하며** 작성 — 에이전트가 좋은 질문(고려 못 한 아키텍처 패턴, 이미 존재하는 외부 패키지, 속도 vs 데이터 충실도 같은 트레이드오프)을 던짐.
- 이 세 기둥은 그린필드뿐 아니라 **기존 코드베이스(brownfield)** 에도 적용.

### 예제 프로젝트: AgentClinic
- AI 에이전트가 인간으로부터 받는 스트레스(환각·컨텍스트 부패·메모리 문제·서브에이전트 조율)를 치료하는 클리닉 — Pet Clinic 패러디.
- **풀스택 웹앱**: Next.js 백엔드 + React 프런트엔드. 예약(appointments)·질환(ailments, 예: hallucination)·치료(treatments, 예: context infusion) 관리.

### 헌법 작성 대화 흐름
1. **프로젝트 설명 제공** + 이해관계자 의견이 `README.md`에 있음을 알림. (Claude Code의 `AskUserQuestion` 툴을 선택적으로 활용 — UI가 보기 좋아서.)
2. 에이전트에게 **미션·기술 스택·로드맵을 함께** 작성하도록 지시. SDD는 **휴먼 인 더 루프(human-in-the-loop)** 로 작은 변경을 검토하는 방식이 최선 → 로드맵을 **작은 단계**로 구성하라 지시.
3. 에이전트의 인터뷰 질문에 답변 (예: 미션 톤 = playful, 백엔드 = TypeScript, 로드맵 세분성 선택) → **Submit answers**.
4. 에이전트가 **쓰기 권한** 요청 → 변경을 통제 하에 둠. (보안 트레이드오프가 괜찮으면 세션 동안 특정 명령 일괄 승인 가능.)
5. 결과: `specs` 디렉터리에 **mission.md·tech-stack.md·roadmap.md** 생성.

### 휴먼 인 더 루프 검토
- 예: 미션에 타깃 청중이 빠짐(비즈니스를 에이전트가 알 리 없음) → **직접 편집 대신 대화를 이어** 수정. 관련 문서 일관성을 위해 **에이전트에게 변경을 맡기는** 것이 모범 사례(직접 수정 시 연관 문서 갱신을 놓칠 수 있음).
- 빠른 프로토타입이라 SQLite 사용 — 언급 안 했지만 에이전트가 추천에서 알아내 기술 스택에 포함.
- 최종 검토 후 **헌법을 커밋** → 프로젝트의 살아있는 문서(living document).

## 요약
- 헌법은 **미션·기술 스택·로드맵**이며 에이전트와 **대화하며** 작성한다.
- **휴먼 인 더 루프**로 작은 단계·검토를 유지하고, 문서 일관성을 위해 수정도 에이전트에게 맡긴다.
- 예제 AgentClinic(Next.js+React)의 헌법을 완성해 커밋하고 첫 기능으로 넘어간다.
