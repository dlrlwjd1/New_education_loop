# The Second Feature Phase

## 개요
- 개선된 헌법·워크플로로 **두 번째 기능(agents and ailments)** 을 진행하며, 흔한 고통점인 **AI 피로(AI fatigue)** 대처 전략을 다룬다.

## 내용

### AI 피로와 깨끗한 구획
- 에이전트가 많은 코드·변경을 생성 → 휴먼 인 더 루프 검증이 지침. 이를 줄이려면 **기능 단계마다 깨끗한 구분(clean division)**.
- 각 기능을 올바른 흐름 상태(flow state)에서 시작하기 위한 체크: 미완 작업 없나? **지난 브랜치를 main에 머지했나?** 다음 로드맵 항목이 맞나? **에이전트 컨텍스트를 비웠나?**(명세가 기억 스냅샷이 아닌 의도를 담게, 그리고 제한된 컨텍스트 예산을 다음 작업에 집중).

### 기능 명세 (반복 프로세스)
- 컨텍스트 비우고 시작. (반복되는 프롬프트는 이후 레슨에서 **커스텀 워크플로**로 간소화.)
- 에이전트 질문에 답: 기능들 한 단계 유지=Yes, 마이그레이션=plain SQL, 검증=1·2·3 → Submit.
- 에이전트 **추론 과정 관찰**이 유용(verbose 모드면 중간 아이디어까지). 의도 반영을 위해 **PicoCSS** 프레임워크로 소폭 변경 → 요구사항 수정 시 다른 파일도 반영하게 지시 → 커밋(메시지는 에이전트가 작성).

### 구현
- 계획/기능 단계 구분이 컨텍스트·시간·에이전트 과부하를 막음. 기능이 너무 크면 **계획 일부만 먼저 구현**해 변경 크기를 관리.

### 심층 검토
- 진행을 봤어도 부족 → **속도를 늦추고** 심층 리뷰. AI 피로를 줄이려 **고수준 요구사항**에 집중, 변수명 트집 금지 — 내 이름으로 커밋할 수 있는 코드인지만 확인.
- 예: props에 인라인 타입 사용 → **독립 TypeScript 타입**으로 바꾸도록 전역 수정 지시. 이런 누락(추출된 prop 타입)은 실패가 아니라 **명세를 진화**시키는 과정 — 포착하면 향후 결과가 좋아짐 → 소단계 커밋.

### 검증 + 서브에이전트 심층 리뷰
- 앱 실행으로 확인 + **이해했는지 검증**해 인지 부채 방지. 테스트를 **디버거로 실행**하며 흐름 탐색.
- "속았는지" 검증하려 에이전트에 **여러 서브에이전트(sub-agents)** 를 띄워 이 변경으로 프로젝트 전체 심층 리뷰 지시 → 생각할 공간 확보 + **메인 에이전트 컨텍스트 보존**(오염 방지). 서브에이전트가 이슈·권고 반환 → 수정·테스트로 좋은 상태로. **두 번째 점검에서 중요한 이슈를 자주 발견** — 도구함에 넣어둘 것.
- 검증 완료 → 커밋 → 이전 레슨의 **체인지로그 스킬**로 변경 문서화 → 커밋 → 머지.

### 빠른 재계획
- 로드맵을 보며 다음 기능이 여전히 맞는지 확인. 기능 간 **깨끗한 단절**이 AI 피로를 관리(커피 브레이크 가능).

## 요약
- 각 기능은 **컨텍스트 클리어·머지 확인** 등 깨끗한 구획으로 시작해 **AI 피로**를 관리한다.
- 검토는 **고수준**에 집중하고 누락은 **명세 진화**로 포착하며, **서브에이전트 심층 리뷰**로 놓친 이슈를 잡는다.
- 반복 가능한 SDD 프로세스가 자리잡음 → 다음은 **MVP**를 만들 수 있는지 검증.
