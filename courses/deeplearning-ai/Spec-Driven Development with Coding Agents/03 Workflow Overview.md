# Workflow Overview

## 개요
- SDD는 프로젝트 전체에 대해, 그리고 각 기능(feature)마다 에이전트에게 **무엇을 어떻게 만들지 미리** 알려준다 — 진행할수록 개선된다.
- 핵심 스킬은 **적절한 상세 수준(right level of detail)** 을 아는 것 — 에이전트를 유능한 페어 프로그래머로 대하면 대개 맞다.

## 내용

### 상세 수준
- **많이**: 목표·미션·타깃 청중·제약 등 맥락.
- **적게**: 에이전트가 스스로 알아낼 수 있는 저수준 결정.

### 워크플로 단계
1. **헌법(Constitution) 명세** — 미션·기술 스택·로드맵 정의.
   - 헌법은 프로젝트 수준 세부를 형식화하는 한 방법. 많은 개발자는 최상위 `agents.md`를 쓰지만, 헌법은 **에이전트 비종속적(agent-agnostic)** 이고 더 **구조적**.
   - 인간-에이전트, 그리고 **인간-인간** 간의 핵심 결정 합의를 담음.
   - **미션(mission)**: 왜(why) — 비전·청중·범위. 사전 정의가 진행 중 결정을 안내.
   - **기술 스택(tech stack)**: 개발·배포 기술과 제약에 대한 팀 공통 이해.
   - **로드맵(roadmap)**: 단계(phase) 시퀀스를 담은 **살아있는 문서(living document)** — 각 단계는 자체 기능 명세 프로세스로 구현.
2. **기능 개발(반복 프로세스)** — **계획(plan) → 구현(implement) → 검증(validate)**.
3. **재계획(Replanning) 단계** — 기능 사이에 헌법 수정·로드맵 업데이트·프로세스 자체 개선.

### 아키텍트 비유
- 건축가가 건물 상세 도면을 시공자에게 주듯 — 인간은 **설계·감독·검토/수락(또는 변경 요청)**. 시공자에게 일하는 법을 지시하지 말고, **그들이 모르는 맥락**에 집중.

## 요약
- SDD 워크플로: **헌법(미션·기술 스택·로드맵) → 기능 루프(계획·구현·검증) → 재계획**.
- 헌법은 `agents.md`보다 구조적·에이전트 비종속적이며 인간·에이전트 간 합의를 담는다.
- 핵심은 **적절한 상세 수준**으로 에이전트를 조종(steer)하는 것. (다음 setup 영상은 선택 사항)
