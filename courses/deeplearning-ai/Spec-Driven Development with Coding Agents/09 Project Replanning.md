# Project Replanning

## 개요
- 첫 기능 구현 후 곧장 다음으로 달려가지 말고, **한 걸음 물러나 재계획(replanning)** 하며 성찰한다 — "빨리 가려면 천천히 가라(run slow to run fast)".

## 내용

### 헌법 업데이트 (테스트 정책)
- 검증에 테스트가 좋지만 에이전트에 테스트 선호를 다 주지 않았음 → **재계획 브랜치**를 만들어 헌법의 기술 스택 갱신.
- 헌법은 **살아있는 문서** — 어떤 버전이 어떤 코드를 만들었는지 추적하려 **별도 브랜치**에서 수정하는 것이 모범 사례.
- 프롬프트로 정책을 명시 → 에이전트가 package.json에 스크립트 추가(의존성은 아직). 이 변경을 **기존 기능 명세·구현에도 반영**하도록 지시. 이후 에이전트에 **테스트 작성**을 요청 → 에디터에서 **디버거로 실행**(휴먼 인 더 루프로 코드 단계 실행 확인) → 커밋.

### 제품 계획 변경 (반응형 디자인)
- PM 업데이트: 사용자 40%가 모바일 → **반응형 디자인(responsive design)** 강조. 에이전트에 반응형을 원하며 **제품 명세·기능 명세·코드**를 모두 수정하라 지시.
- 개발 초기라 작은 변경이므로 **재계획 중 직접 구현** 타당. 큰 작업이면 재계획에서 처리하지 말고 **로드맵에 별도 기능 단계로 예약** — 판단에 맡김.
- 명세는 코드뿐 아니라 **결정을 포착**해야 하며 둘을 **동기화**해 팀 커뮤니케이션을 도움. 작은 단계·잦은 커밋이 리뷰 과부하를 막음.

### 프로젝트 정리 (로드맵)
- 로드맵의 다음 작업이 여전히 타당한지 재검토 → 기능 2·3·4·5가 서로 묶여 있어 **한 단계로 통합**하도록 로드맵 갱신 후 커밋.

### 재계획 = 워크플로 개선 + 스킬(skills)
- 재계획은 기능·프로젝트뿐 아니라 **조직 전반의 SDD 워크플로 개선**도 포함.
- 예: 비기술 이해관계자가 진행 상황을 보려면 main 머지마다 **체인지로그(changelog)** 갱신 → **스킬(skill)** 로 자동화.
- **스킬** = 에이전트에 새 능력·전문성을 주는 지시·리소스 묶음. **정의 가능·반복적이며 프로젝트/조직 특유 맥락**이 필요한 워크플로에 적합. 직접 쓸 수도 있지만 **에이전트가 스킬 작성을 돕는 스킬**도 있음.
- 이 스킬은 **글로벌 스킬 영역**에 생성돼 모든 프로젝트에서 사용 가능(프로젝트 전용 vs 표준화는 스타일 선택). Claude Code가 이 스킬로 프로젝트 CHANGELOG 생성 → 수동 검토.
- 검증 단계(README 갱신·린팅·포매팅·테스트 작성 등)를 **검증 스킬(validation skill)** 로 묶으면 반복 프로세스·수작업 감소.

## 요약
- **재계획**은 기능 사이에 헌법·로드맵·제품 계획을 갱신하며 성찰하는 단계다.
- 명세와 코드를 **동기화**하고, 작은 변경은 직접·큰 변경은 로드맵 기능으로 예약한다.
- 반복 워크플로(체인지로그·검증)는 **스킬**로 자동화한다. 이제 개발자 일은 대부분 **계획·검증**이므로 재계획 시간을 확보하라.
