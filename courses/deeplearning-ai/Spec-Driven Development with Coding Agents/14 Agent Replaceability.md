# Agent Replaceability

## 개요
- SDD는 작업을 **어떻게(how)** 에서 **무엇을·왜(what·why)** 로 옮기므로, 모델·에이전트가 빠르게 발전해도 워크플로를 **한 선택에 묶지 않는다**.
- **표준(standards)** 덕분에 워크플로·도구를 유지하며 에이전트를 교체할 수 있다.

## 내용

### 에이전트 표준
- **MCP**: 외부 도구 연결.
- **AGENTS.md**: 규칙(rules).
- **Agent Skills**: 부가 맥락과 함께 반복 워크플로 포착.
- **ACP(Agent Client Protocol)**: 에이전트를 클라이언트(에디터)에 연결.

### 에이전트 교체 예시
- 레슨 12의 기능 명세 스킬을 **Codex**(OpenAI 에이전트, 데스크톱·에디터·터미널 구동)로 복사 → 다른 경로에 저장되지만 마이그레이션 후 **정상 작동** → 같은 프로젝트에서 에이전트를 오가며 SDD 워크플로 유지.

### ACP와 레지스트리
- **ACP**로 서로 다른 에디터·에이전트 조합 가능 — 양쪽이 ACP를 지원하면 완벽한 매치.
- **ACP 레지스트리**가 에이전트-클라이언트의 발견·설치·연결을 자동화(전체 라이프사이클 커버). 예: JetBrains IDE의 AI Chat → 레지스트리에서 호환 에이전트 목록 → **OpenCode**(인기 오픈소스 에이전트) 설치 클릭 시 설치+IDE 통합 자동화 → 같은 에디터에서 여러 에이전트를 SDD에 활용.
- **ACP 아키텍처**는 **LSP**가 쓰는 방식과 일치하도록 설계 — Next Edit Suggestion·플랜 모드까지 커버. 나아가 **커스텀 에이전트**를 만들어 로컬 설치도 가능.

### 에이전트 선택
- 업계가 빠르게 변하고 **벤치마크 리더보드**가 등장 — 자주 바뀌니 **자신에게 중요한 기준**으로 최신 정보를 반영해 결정.

## 요약
- SDD 명세는 고수준이라 **특정 에이전트·IDE에 종속되지 않는다**.
- **MCP·AGENTS.md·Skills·ACP** 표준이 에이전트 교체·조합을 가능하게 한다.
- 워크플로·도구를 에이전트 독립적으로 구축했으며, 표준이 늘수록 이 유연성은 커진다.
