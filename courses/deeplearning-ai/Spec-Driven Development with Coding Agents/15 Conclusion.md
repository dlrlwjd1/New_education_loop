# Conclusion

## 개요
- 코스 마무리 — 바이브 코딩(에이전트가 원하는 대로 해주길 바람)에서 **SDD(실제 필요에 가까워짐)** 로의 전환을 배웠다.

## 내용

### 배운 것
- **헌법(constitution)** 작성, **대화를 통한 기능 계획**, **휴먼 인 더 루프 검증**, **스킬·표준을 통한 워크플로 자동화**.
- 오늘 쓰는 명세는 내일 프로젝트의 **기억(memory)** 이 된다 — 날카롭게 유지하고 프로세스를 계속 개선.

### 마지막 메시지
- **최고의 코드는 훌륭한 명세에서 시작한다.**
- 너무 빨리 가는 것의 대가를 겪은 엔지니어가 많다 → **엔지니어링을 되살리고**, 사용자가 소프트웨어의 **운전자(driver)** 로 남자.

## 요약
- SDD는 **헌법 → 대화형 기능 계획 → 휴먼 인 더 루프 검증 → 스킬·표준 자동화**의 흐름이다.
- 명세는 프로젝트의 지속되는 기억이며, **좋은 코드는 좋은 명세에서 출발**한다.
- 속도보다 엔지니어링과 통제를 지키며 개발자가 주도권을 유지하는 것이 핵심이다.
