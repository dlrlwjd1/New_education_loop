# Feature Implementation

## 개요
- 완성된 기능 명세(Hello Hono)를 바탕으로 **전체 구현(implementation)** 을 수행한다.

## 내용

### 구현 시작
- 먼저 기능 명세 계획을 빠르게 재검토.
- 구현 전 **`/clear` 명령으로 컨텍스트를 비움** — 명세 문서에 필요한 내용이 담겨 있음.
- 프롬프트로 **모든 태스크 그룹(task groups)** 을 구현하게 함.
- 때로는 태스크 그룹을 **하나씩** 처리해 더 작은 단계·커밋으로 진행 — 특히 **보안·데이터베이스 관리**처럼 작은 실수가 나중에 복리로 커지는 영역에 유용.

### 진행 관찰과 감독
- Claude 실행 중 콘솔에서 변경을 **실시간 관찰**, 이후 커밋 창에서 최종 변경을 확인 → 작업 리뷰를 조기에 시작.
- 이 패러다임에서 개발자의 핵심 역할은 **아키텍트·감독자(supervisor)** 로서 에이전트에 **명확한 계약(contract)** 을 제공하는 것.
- 에이전트는 각 태스크 그룹별 수행 내용의 요약·세부를 제공.

### 실행 확인
- `package.json`에서 앱 실행 → 콘솔에서 서버 시작 → 브라우저에서 결과 확인(nano 규모라 화면은 소박하지만 픽셀 확인).
- 기능 구현 완료. 에이전트가 **자체 검증(validation)** 수행 → 다음 레슨에서 **사용자 검증**.

## 요약
- 구현 전 `/clear`로 컨텍스트를 비우고 명세 기반으로 태스크 그룹을 구현한다.
- 민감 영역은 **태스크 그룹 단위**로 쪼개 진행하고, 개발자는 **감독자**로서 계약을 명확히 유지한다.
- 실행으로 결과를 확인하며, 다음은 **기능 검증(feature validation)**.
