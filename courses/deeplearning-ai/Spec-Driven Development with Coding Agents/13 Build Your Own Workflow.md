# Build Your Own Workflow

## 개요
- SDD 워크플로를 더 빠르고 가볍게 **자기 방식대로 자동화**한다 — 스킬·MCP·플러그인·SDD 프레임워크를 활용.

## 내용

### 스킬로 반복 자동화
- **에이전트 스킬(Agent Skills)** = 에이전트에 새 능력·전문성을 주는 **오픈 표준**. 기능 명세 시작 시 반복하는 프롬프트("이거 해라, 세 파일 써라")를 스킬로 자동화.
- 에이전트의 **스킬 생성기(skill creator)** 로 함께 작성(커뮤니티의 "스킬 만드는 스킬"도 설치 가능). 작동 중 출력이 원하는 선택을 하는지 관찰. 스킬은 **프로젝트별 또는 글로벌**.

### 스킬 호출과 점진적 공개
- 호출법: 프롬프트에서 **할 일 앞에 스킬을 언급**, 또는 다른 스킬에서 스킬 호출.
- 오픈 표준상 에이전트는 스킬 **설명(description)** 으로 호출 시점을 판단 — **점진적 공개(progressive disclosure)**. 다만 컨텍스트가 커지면 판단이 부정확 → 파일 태깅처럼 **원하는 스킬은 이름으로 지정**해 사고 토큰 절약.
- 에이전트의 내장 `/clear` 같은 **/커맨드**도 있으나, 많은 에이전트가 커스텀 /커맨드에서 **스킬로 이동** 중.

### MCP vs CLI + 스킬
- 에이전트에 API·비공개 지식베이스·DB 접근을 주는 보편적 방법은 **MCP(Model Context Protocol)**. 예: **Context7** — 최신 패키지 문서를 컨텍스트에 주입(React 9.0 대신 9.2+ 인지).
- 하지만 **CLI를 쓰는 스킬**이 같은 목적을 더 우아하게 달성하는 추세 — Context7도 이제 **CLI 호출 스킬**을 제안. 설치 시 **MCP 서버 vs CLI+Skills** 선택 → 후자 사용(더 적은 셋업·컨텍스트로 액션 가능해 MCP를 재고하는 흐름).

### 공유: 플러그인
- 워크플로(스킬 등)를 여러 기기·팀·외부와 공유하려면 **플러그인(plugins)** — Claude Code의 설치·업데이트 가능한 확장 모음(무료 커뮤니티 성장 중). 단 **크로스 에이전트 표준은 아직 아님**, 코드를 실행하므로 **신뢰**하고 설치·업데이트.

### SDD 프레임워크
- **GitHub Spec Kit**: 에이전트에 `/constitution·/plan·/tasks·/implement` 커맨드 제공(이 코스 워크플로와 유사).
- **OpenSpec(Fission AI)**: propose·explore(=plan) → apply(=implement) → archive(=replanning) 워크플로, 빠른 기능용 표준 패턴 포함.
- 둘 다 **브랜치 관리·검증 스크립트·명세 문서 포맷** 제공 → 실험해 자기 워크플로를 다듬을 것.

### 리서치 백로그(backlog)
- 기능 도중 떠오른 아이디어(예: DB 선택)를 브랜치 작업을 멈추지 않고 에이전트와 리서치하되 로드맵엔 아직 안 올리고 싶을 때 → 에이전트에 **알려진 위치에 리포트 작성**을 지시해 **리서치 백로그**로 보관. 나중에 백로그 파일 링크와 함께 로드맵에 예약. 커지면 리서치 자동화 **스킬**로.

## 요약
- 반복 프롬프트는 **스킬**로 자동화하고, 원하는 스킬은 **이름으로 지정**한다.
- **MCP → CLI+스킬** 전환 추세이며, 워크플로는 **플러그인**으로 공유(신뢰 후 설치)한다.
- **Spec Kit·OpenSpec** 같은 프레임워크를 채택·커스터마이즈하고, 아이디어는 **리서치 백로그**로 관리한다.
