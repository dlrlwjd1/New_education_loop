# Legacy Support — 대화정리

## 개요
- 이 강의의 결론을 한 문장으로 요약하면: **레거시(legacy)도 헌법 단계부터 시작하면 되고, 기반이 놓인 뒤 워크플로는 그린필드와 동일하다.**
- 대화에서 확인한 초점: 헌법과 로드맵을 "기존 것에서 뽑아낸다"는 말의 정확한 의미, 그리고 헌법이 없으면 무엇이 문제인지.

## 내용

### 1. "헌법도 기존 것에서, 로드맵도 기존 것에서, 이후는 동일" — 대체로 맞다

**맞는 부분: "그 이후는 동일"이 이 레슨의 결론이다.**

헌법이 한 번 놓이면 레거시가 SDD 기반 위에 올라간 상태가 되고, 그다음은 레슨 6~11과 완전히 같은 흐름이다.

다음 로드맵 기능(Phase 1 feedback form) 계획 → 브랜치·명세 생성 → 명세 검토·커밋 → 구현 → 검증 → 커밋 → main 머지.

**결이 다른 부분 ①: 로드맵의 출처는 "기존 코드"가 아니라 "기존 산출물(artifacts)"이다.**

헌법 구성 요소별로 출처가 갈린다.

| 헌법 구성 요소 | 출처 |
|---|---|
| 미션 | `README.md` (청중·아이디어·부가 정보) |
| 기술 스택 | **코드베이스** (파일 구조, 프레임워크 버전) |
| 로드맵 | **`TODO.md`** — 미완 작업 목록 |

코드에서 뽑는 건 주로 기술 스택이고, 로드맵은 "아직 안 한 일" 문서에서 나온다. 코드는 이미 **한** 일이므로 로드맵의 재료가 아니다.

실제 레거시 프로젝트라면 이 to-do가 이슈 트래커·스프레드시트·워드 문서 등에 흩어져 있을 수 있다.

**결이 다른 부분 ②: 순수 역공학(reverse engineer)만은 아니다.**

맥락이 있으면 사람이 추가로 넣는다. 레슨에서는 "효율 개선 + 인기 기능 구현"이라는 임무를 덧붙였다. 기존 것을 발굴하는 게 기본이지만, 앞으로의 방향은 사람이 얹는다.

**결이 다른 부분 ③: 재계획(replanning)에 시간을 더 써야 한다.**

워크플로는 같지만, SDD를 방금 도입했으니 튜닝할 것이 많을 수 있다는 단서가 붙는다.

### 2. 헌법이 없으면 무엇이 문제인가 — "할 때마다 달라진다"

대화에서 나온 답: 헌법이 없으면 할 때마다 결과가 달라진다. 정확하고, 레거시에서는 이 "달라짐"이 두 방향으로 나타난다.

**시간축으로 달라짐 (일관성)**

같은 요청을 두 번 해도 결과가 다르다. 세션이 바뀌면 에이전트는 이전 대화를 기억하지 못한다. 그래서 레슨 요약에 **명세가 프로젝트의 기억(memory)** 이라는 표현이 나온다. 헌법이 기억을 파일로 고정해두면 세션이 몇 번 바뀌어도 같은 기준으로 판단한다.

**코드베이스 안에서 달라짐 (정렬)**

레거시 특유의 문제다. 기술 스택이 헌법에 없으면 에이전트는 기존 코드가 어떤 프레임워크·어떤 패턴을 쓰는지 모르고 자기 취향대로 만든다. 결과적으로 한 프로젝트 안에 서로 이질적인 구역이 생긴다.

레슨의 "헌법이 향후 코드 변경을 **과거 개발자들의 결과물과 정렬**한다"가 바로 이것을 막는 장치이며, 헌법의 기술 스택 항목이 파일 구조·프레임워크 버전을 코드에서 추출하는 이유다.

### 3. 그린필드와의 차이

그린필드에서는 정렬 문제가 약하다. 정렬 대상인 과거 코드 자체가 없으니 헌법은 "앞으로 이렇게 하자"만 정하면 된다.

레거시 헌법은 "이미 이렇게 되어 있다"를 먼저 읽어내야 한다. 그래서 레슨에서 **코드 탐색 툴 콜이 많이 보이고 대화가 더 풍부**했다.

## 예시

레슨의 레거시 설정 방식 — 이미 아는 AgentClinic MVP를 레거시처럼 만들기:

- `specs` 폴더 **없이** main에서 시작
- **새 Claude Code 세션** + 다른 디렉터리 (이전 대화 기억이 없는 상태)
- 배경은 `README.md`, 미완 작업은 `TODO.md`에만 존재

헌법 단계 프롬프트는 레슨 5와 거의 같고, 여기에 **기존 산출물(to-do 파일)에서 로드맵 항목을 찾도록** 지시하는 부분만 추가된다.

생성된 헌법(미션 / 기술 스택 / 로드맵)은 **커밋**한다. SDD에서 명세는 버전 관리 전략의 일부다.

## 요약

- 레거시도 SDD 적용 가능 — 워크플로대로 **헌법 단계부터** 시작한다.
- 출처가 갈린다: 미션은 `README.md`, 기술 스택은 **코드**, 로드맵은 **TODO 문서**. 여기에 사람이 앞으로의 임무를 얹는다.
- 헌법이 없으면 결과가 **매번 달라지고**(세션 기억 없음), **코드베이스 안에서 이질적으로 갈라진다**(스택 정렬 실패).
- 기반이 놓이면 이후 워크플로는 **그린필드와 동일**. 단 갓 도입한 상태라 **재계획에 시간을 더 쓴다**.
- 명세가 프로젝트의 기억이 되어 바래지 않는다.
