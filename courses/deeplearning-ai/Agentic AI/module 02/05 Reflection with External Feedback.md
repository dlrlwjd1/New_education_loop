# Reflection with External Feedback

## 핵심 명제

> 외부 피드백(external feedback)이 있는 Reflection은 LLM 혼자 하는 Reflection보다 훨씬 강력하다.

## 성능 향상 곡선

프롬프트 튜닝의 한계와 Reflection의 역할:

```
성능
 ↑
 │                              ← 외부 피드백 + Reflection 튜닝
 │                    ·····················
 │          ← Reflection 추가 후 튜닝
 │    ·············
 │←── 프롬프트만 튜닝
 │·············
 └──────────────────────────────→ 시간 / 노력
```

- **프롬프트 단독 튜닝**: 초기엔 개선되다가 plateau(정체) 발생
- **Reflection 추가**: plateau를 한 단계 올릴 수 있음
- **외부 피드백 추가**: 더 높은 성능 궤도로 점프 가능

→ 프롬프트 튜닝의 수익 감소(diminishing returns)를 느낀다면, Reflection 또는 외부 피드백을 도입할 시점

## 외부 피드백이란

LLM이 이전과 **동일한 정보**를 다시 보는 게 아니라, **새로운 외부 정보**를 추가로 주입하는 것.

기존 Reflection: LLM → 결과 → 같은 LLM이 재검토 → 개선 시도
외부 피드백: LLM → 결과 → [외부 도구/코드가 새 정보 생성] → LLM이 그 정보를 바탕으로 개선

## 외부 피드백 예시 3가지

### 1. 코드 실행 결과 피드백
코드를 생성했다면 → 직접 실행 → 출력값 또는 에러 메시지를 LLM에 다시 전달
- 새 정보: 실제 실행 결과 / 에러 스택트레이스
- 효과: "내가 상상한 결과"가 아닌 "실제 결과"를 보고 수정 가능

### 2. 패턴 매칭 피드백 (이메일 예시)
이메일 초안에 경쟁사 이름이 포함되면 안 될 때:
- 정규식(regex) 패턴 매칭으로 경쟁사 이름 탐색
- 발견 시 → LLM에 "이 이름이 포함되었으니 제거하고 다시 작성하라" 전달
- 새 정보: 경쟁사 이름이 몇 개, 어디에 있는지

### 3. 웹 검색으로 팩트체크 피드백
에세이에서 "타지마할은 1648년에 지어졌다"고 썼을 때:
- 웹 검색으로 실제 역사 조회
- 정확한 사실(1631년 착공 ~ 1648년 완공)을 LLM에 제공
- LLM이 더 정확한 텍스트로 개선
- 새 정보: 신뢰할 수 있는 출처의 사실 정보

### 4. 단어 수 카운터 피드백
LLM은 정확한 단어 수 제한을 잘 못 지킴:
- 코드로 단어 수를 정확히 계산
- 제한 초과 시 → "현재 N단어, M단어로 줄여라" 전달
- 새 정보: 정확한 단어 수치

## 공통 패턴

```
[LLM 생성] → [외부 코드/툴이 새 정보 추출] → [새 정보를 Reflection LLM에 입력] → [개선된 결과]
```

세 예시 모두 동일한 구조:
1. 초기 출력을 코드로 분석
2. 새로운 사실(에러, 패턴, 검색 결과, 단어 수)을 추출
3. 그 사실을 LLM에 피드백으로 전달

## 건강 고도화 적용 아이디어

| 현재 LLM 출력 | 외부 피드백 가능한 것 |
|--------------|---------------------|
| 코칭 텍스트 | "의학적 진단" 문구 regex 감지 → 재생성 요청 |
| 노화속도 설명 | 실제 계산값과 텍스트 수치 일치 여부 코드 검증 |
| 추천 이유 | 금칙어(경쟁사, 특정 의약품명) 패턴 매칭 |
