# Tool Use Introduction

## 핵심 개념

> LLM에게 함수(function)를 제공하여, LLM이 필요하다고 판단할 때 스스로 호출을 요청하게 하는 것

사람이 도구 없이 맨손보다 도구를 쓸 때 더 많은 것을 할 수 있듯, LLM도 툴이 있으면 훨씬 더 많은 것을 할 수 있다.

## Tool Use 동작 방식

```
[사용자 입력]
     ↓
[LLM] ← 툴 목록 제공 (dashed box)
     ↓ 툴 호출 결정
[함수 실행] → 결과 반환
     ↓
[LLM] → 최종 출력 생성
```

예시: `getCurrentTime` 함수 제공 시

1. 사용자: "지금 몇 시야?"
2. LLM: `getCurrentTime()` 호출 요청
3. 함수 실행 → `"3:20 PM"` 반환
4. LLM: "현재 시각은 오후 3시 20분입니다"

## LLM이 툴 사용 여부를 스스로 결정

같은 툴 목록이 있어도, 필요 없으면 호출하지 않음:

| 질문 | `getCurrentTime` 호출 여부 | 이유 |
|------|--------------------------|------|
| "지금 몇 시야?" | O | 시간 정보 필요 |
| "녹차에 카페인이 얼마나 있어?" | X | 시간 정보 불필요 |

→ 하드코딩 방식(항상 웹 검색)과의 차이: **LLM이 판단하여 호출**

## 슬라이드 표기 규칙

LLM 위에 **dashed box(점선 박스)** = 해당 LLM에 툴이 제공됨을 의미
- LLM이 제공된 툴 중 무엇을, 언제 호출할지 자율적으로 결정

## Tool Use 활용 예시

| 상황 | 사용 툴 | LLM 행동 |
|------|---------|---------|
| 이탈리아 레스토랑 찾기 | 웹 검색 | "Mountain View 근처 레스토랑" 검색 후 결과 요약 |
| 흰 선글라스 구매 고객 조회 | DB 쿼리 | 판매 테이블 조회 후 결과 반환 |
| 이자 계산 ($500, 10년, 5%) | 계산 함수 or 코드 실행 | 수식 계산 후 정확한 값 반환 |

## 멀티 툴 예시: 캘린더 어시스턴트

제공 툴:
- `check_calendar()` — 빈 시간 확인
- `make_appointment()` — 일정 추가 / 초대 전송
- `delete_appointment()` — 일정 삭제

요청: "목요일에 Alice와 회의 잡아줘"

```
LLM → check_calendar(목요일) → 오후 3시 빈 시간 확인
LLM → make_appointment(Alice, 목요일 3pm) → 초대 전송 완료
LLM → "Alice와 목요일 오후 3시 회의가 잡혔습니다"
```

## 개발자의 역할

- 앱이 해야 할 작업 유형을 파악
- 필요한 함수(툴)를 직접 구현
- LLM에 툴 목록을 제공
- LLM이 언제 무엇을 호출할지는 LLM에게 위임
