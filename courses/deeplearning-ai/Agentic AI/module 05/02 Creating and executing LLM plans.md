# Creating and executing LLM plans

## 개요
- 앞 영상에서는 계획을 **단순 텍스트**로 표현했지만, 실무에서는 다운스트림 코드가 안정적으로 파싱·실행할 수 있도록 **구조화된 형식**으로 계획을 작성하게 한다.
- 권장 형식: **JSON**(또는 XML).

## 내용

### 왜 JSON으로 계획을 쓰게 하는가
- 영어 문장으로 된 계획은 코드가 파싱하기 모호하다.
- **JSON 형식**이면 각 단계를 명확·비모호하게 파싱해 **한 단계씩 신뢰성 있게 실행**할 수 있다.
- 요즘 주요 LLM들은 JSON 출력을 잘 생성한다.

### JSON 계획 예시 구조
시스템 프롬프트: "다음 도구들에 접근할 수 있다. **JSON 형식으로 단계별 계획을 만들어라**" + JSON 스키마를 충분히 설명.

```json
[
  {
    "step": 1,
    "description": "둥근 선글라스를 찾는다",
    "tool": "get_item_descriptions",
    "arguments": { ... }
  },
  {
    "step": 2,
    "description": "재고를 확인한다",
    "tool": "check_inventory",
    "arguments": { ... }
  }
]
```
- 각 리스트 항목이 **step 번호 / 설명(description) / 사용할 도구(tool) / 인자(arguments)** 를 키-값으로 명확히 담는다.

### 형식별 신뢰도 비교
| 형식 | 파싱 신뢰도 | 비고 |
|---|---|---|
| **JSON** | 높음 (권장) | 주요 LLM이 잘 생성 |
| **XML** | 높음 (권장) | XML 태그로 단계·번호 명시 |
| Markdown | 중간 | 파싱이 다소 모호 |
| Plain text | 낮음 | 가장 비신뢰적 |

## 요약
- 계획을 **JSON(또는 XML)** 으로 출력하게 하면, 코드가 단계를 명확히 파싱해 체계적으로 실행할 수 있다.
- 마크다운·평문은 파싱이 모호해 덜 권장.
