# Communication patterns for multi-agent systems

## 개요
- 사람 팀의 조직도(org chart)를 설계하는 것이 복잡하듯, 다중 에이전트의 **통신 패턴(communication pattern)** 설계도 복잡하다.
- 오늘날 자주 쓰이는 대표 패턴들을 정리한다.

## 가장 흔한 두 패턴

### 1) 선형(linear)
```
[리서처] → [그래픽 디자이너] → [작가]
```
- 각 에이전트가 순차적으로 다음 에이전트에게 출력을 전달.

### 2) 계층형(hierarchical) — 매니저 조율
```
        [마케팅 매니저]
       ↙     ↓      ↘
 [리서처] [그래픽 디자이너] [작가]
```
- 매니저가 각 에이전트에게 작업을 시키고 **결과를 다시 매니저가 받아** 다음 에이전트에게 전달.
- 구현 팁: 리서처가 그래픽 디자이너·작가에게 직접 넘기기보다, **매니저에게 되돌려 주는 편이 더 단순**.

## 고급/덜 흔한 패턴

### 3) 깊은 계층(deeper hierarchy)
- 일부 에이전트가 **자기 하위 에이전트(sub-agent)** 를 호출.
- 예: 리서처가 웹 리서처 + 팩트 체커를 두고, 작가가 스타일 작가 + 인용 검사기를 둠.
- 1단계 계층보다 훨씬 복잡해 사용 빈도는 낮음.

### 4) 전체-대-전체(all-to-all)
- **누구든 아무 때나 서로에게 메시지**를 보낼 수 있음.
- 구현: 모든 에이전트에게 "호출 가능한 다른 에이전트들"을 알려주고, 한 에이전트가 메시지를 보내면 수신자의 컨텍스트(inbox)에 추가됨. 수신자는 숙고 후 응답.
- 모두가 협업하다 각자 "끝났다"고 선언하거나 작가가 충분하다고 판단하면 최종 출력 생성.
- 결과가 **예측하기 어려움**. 높은 제어가 필요 없고 약간의 혼돈·불확실성을 감수할 수 있는 애플리케이션에서 실험적으로 사용(안 좋으면 다시 실행).

## 요약
| 패턴 | 특징 | 사용 빈도 |
|---|---|---|
| 선형(linear) | 순차 전달 | 매우 흔함 |
| 계층형(hierarchical) | 매니저가 조율 | 매우 흔함 |
| 깊은 계층 | sub-agent 호출 | 덜 흔함 |
| all-to-all | 자유 통신, 예측 어려움 | 실험적 |

- 다중 에이전트 구축을 쉽게 해주는 **소프트웨어 프레임워크**가 많고, 이 통신 패턴들의 구현도 도와준다.
