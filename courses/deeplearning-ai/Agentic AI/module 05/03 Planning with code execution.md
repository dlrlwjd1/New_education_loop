# Planning with code execution

## 개요
- JSON 계획을 한 단계씩 실행하는 대신, **LLM이 코드를 직접 작성**하게 하면 그 코드 한 편이 여러 단계를 담아 복잡한 계획을 실행할 수 있다.
- 작업을 코드로 풀 수 있는 애플리케이션에서 매우 강력한 방법.

## 내용

### 커스텀 도구 방식의 한계
예: 커피 머신 판매 스프레드시트에 대한 질의응답 시스템.
제공 도구: `get column max`, `get column mean`, `filter rows`, `get column min`, `get column median`, `sum rows` 등.

문제점:
- "핫초코 판매가 가장 높은 달은?" → filter rows로 1월 추출→통계, 2월 반복, …12월 반복 후 max. **매우 복잡**.
- "지난주 고유 거래 수는?" → 기존 도구로는 **불가능** → `get unique entries` 도구를 새로 만들어야 함.
- "마지막 5건 거래 금액은?" → 또 새 도구 필요.
- → 질의가 늘수록 **도구를 계속 추가**하게 되어 취약(brittle)하고 비효율적, 엣지 케이스에 시달림.

### 코드 실행으로 계획 표현하기
프롬프트: "사용자 질의를 해결하는 **코드를 작성**하고, 답을 Python 코드로 반환하라" (예: `<execute_python>` XML 태그로 구분).

- LLM이 pandas 같은 **데이터 처리 라이브러리**로 CSV를 불러와 계획을 코드로 표현.
- 예("마지막 5건 거래 금액"): ①CSV 로드 → ②날짜 컬럼 파싱 → ③날짜 정렬 → ④마지막 5건 선택 → ⑤price 컬럼 표시. 각 단계가 곧 코드.

### 왜 코드가 강력한가
- Python + pandas 같은 라이브러리에는 **수백~수천 개의 내장 함수**가 있다.
- LLM은 이 함수들을 **언제 어떻게 호출하는지 방대한 데이터로 학습**했다.
- 따라서 거대한 라이브러리에서 적절한 함수들을 골라 이어붙여 복잡한 질의의 계획을 스스로 구성할 수 있다.

### 주의: 안전한 실행 환경
- 코드를 실행하므로 **샌드박스(sandbox)** 같은 안전한 실행 환경이 필요(Tool use 모듈에서 언급한 주의점).
- (강사: 모범 사례는 아니지만 샌드박스 없이 쓰는 개발자도 많다고 언급.)

### 연구 근거
- Xingyao Wang 등의 논문에서 인용한 그래프: 여러 모델·작업에서 **"CodeAct"(코드로 행동)** 방식이 JSON→행동 변환이나 텍스트보다 우수.
- 성능 경향: **코드 > JSON 계획 > 평문 계획**.
- 단, 커스텀 도구를 줘야 하는 애플리케이션도 있으므로 코드가 만능은 아니다. 적용 가능할 때 매우 강력.

## Planning 정리
- 오늘날 가장 강력한 활용처: **고도로 에이전틱한 소프트웨어 코딩 도구**. 복잡한 SW를 컴포넌트별 계획(체크리스트)으로 세우고, 테스트까지 계획하며 한 단계씩 실행.
- 다른 분야는 아직 성장 중. 단점은 **제어 어려움**(런타임 동작을 미리 모름)이지만, 제어를 일부 포기하는 대신 **시도 가능한 작업 범위가 크게 넓어진다**.

## 요약
- 코드로 계획을 표현하면 라이브러리의 방대한 함수를 활용해 풍부한 계획을 실행 가능.
- 성능: 코드 > JSON > 평문. 안전한 실행 환경(샌드박스) 유의.
