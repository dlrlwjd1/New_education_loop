# Multi-agentic workflows

## 개요
- **다중 에이전트(multi-agent) 워크플로** = 여러 에이전트가 협업해 하나의 작업을 수행.
- "같은 LLM을 반복 호출하는데 왜 여러 에이전트가 필요한가?"에 대한 답: **복잡한 작업을 역할별로 분해**하면 개발이 쉬워지기 때문.

## 내용

### 왜 여러 에이전트인가 (비유)
- **컴퓨터**: CPU 하나여도 작업을 여러 프로세스/스레드로 나누면 프로그래밍이 쉬워진다.
- **팀 고용**: 복잡한 일을 한 사람에게 맡기기보다, **서로 다른 역할의 몇 명**에게 나눠 맡긴다.
- 멘탈 모델: "이 일을 할 사람 한 명"이 아니라 "역할이 다른 3~4명을 고용한다면?"으로 생각 → 하위 작업(sub-task)으로 분해해 하나씩 구축.

### 복잡한 작업의 자연스러운 역할 분해 예
| 작업 | 역할(에이전트)들 |
|---|---|
| 마케팅 자료 제작 | 리서처, 그래픽 디자이너, 작가(writer) |
| 리서치 기사 작성 | 리서처, 통계가, 수석 작가, 편집자 |
| 법률 사건 준비 | 어소시에이트, 패러리걸, 조사관 |

### 에이전트별 도구 설계 (마케팅 예)
| 에이전트 | 역할 | 필요한 도구 |
|---|---|---|
| 리서처 | 시장 트렌드·경쟁사 분석 | 웹 검색 |
| 그래픽 디자이너 | 시각화·아트워크 생성 | 이미지 생성/편집 API, 코드 실행(차트) |
| 작가 | 리서치+그래픽을 브로슈어로 | (추가 도구 불필요, LLM 텍스트 생성) |

- 각 에이전트는 **LLM에게 해당 역할을 부여하는 프롬프트**로 만든다.
  - 예: "너는 리서치 에이전트다. 시장 트렌드·경쟁사 분석 전문가다. 선글라스 제품의 시장 트렌드를 온라인 리서치하고 경쟁사 동향을 요약하라."

## 두 가지 통신 패턴(communication pattern)

### 1) 선형(linear) 워크플로
```
[리서처] → 리서치 리포트
    ↓
[그래픽 디자이너] → 데이터 시각화/아트워크
    ↓
[작가] → 최종 마케팅 브로슈어
```
- 장점: 각 에이전트를 **한 번에 하나씩 집중해서** 개발 가능(협업자끼리 분담). 마지막에 이어붙임.
- **재사용**: 마케팅용 그래픽 디자이너를 더 일반화해 소셜 미디어 포스트·웹페이지 삽화에도 재사용 가능.

### 2) 매니저(coordinator)가 조율하는 계획 기반
- Planning 패턴과 동일하되, **도구(초록 박스)를 에이전트(보라 박스)로 대체**.
- 프롬프트: "너는 마케팅 매니저다. 다음 팀 에이전트들과 일한다 [에이전트 설명]. 단계별 계획을 반환하라."
- LLM(매니저)이 계획 수립: 리서처에게 조사 요청 → 그래픽 디자이너에게 이미지 요청 → 작가에게 리포트 요청 → 마지막으로 리포트 리플렉션/개선.
- 이 구조는 **매니저 에이전트 1 + 실무 에이전트 3 = 총 4개 에이전트** 협업으로 볼 수 있다. 매니저가 방향을 정하고 작업을 위임(delegate).

## 요약
- 다중 에이전트 = 복잡한 작업을 **역할별 에이전트로 분해**해 협업. 각각을 독립적으로 개발·재사용 가능.
- 각 에이전트는 역할 프롬프트 + 필요한 도구로 구성.
- 핵심 설계 결정: **에이전트 간 통신 패턴** (선형 vs 매니저 조율 등). 활발히 연구되는 영역.
