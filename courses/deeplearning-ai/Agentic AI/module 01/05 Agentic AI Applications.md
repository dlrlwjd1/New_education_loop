# Agentic AI Applications

## 개요

Agentic AI 애플리케이션은 비즈니스 프로세스, 고객 응대, 웹 브라우저 사용 등 다양한 작업에 적용될 수 있습니다.

이 강의의 핵심:
- 단계가 명확한 업무는 Agentic 워크플로우로 구현하기 쉬움
- 단계가 사전에 정해지지 않은 업무는 LLM이 계획을 세워야 하므로 더 어려움
- 텍스트 중심 작업이 멀티모달 작업보다 일반적으로 더 안정적임

## 예시 1: 인보이스 처리

### 목표

인보이스 PDF에서 중요한 필드를 추출해 데이터베이스에 기록합니다.

추출 대상 예시:
- 청구자: Tech Flow Solutions
- 청구자 주소
- 결제 금액: $3,000
- 결제 기한: August 20th, 2025

### Agentic 워크플로우

1. 인보이스 PDF 입력
2. PDF-to-text 변환 API 호출
3. 변환된 텍스트를 LLM에 입력
4. 문서가 실제 인보이스인지 판별
5. 필요한 필드 추출
6. 데이터베이스 업데이트 API 또는 툴 호출

### 특징

이 작업은 비교적 구현하기 쉽습니다.

이유:
- 따라야 할 프로세스가 명확함
- 필요한 필드가 사전에 정의되어 있음
- 데이터베이스에 기록하는 최종 행동도 분명함

## 예시 2: 고객 주문 문의 응답

### 목표

고객이 보낸 주문 관련 이메일을 분석하고, 관련 정보를 조회한 뒤 응답 초안을 작성합니다.

### Agentic 워크플로우

1. 고객 이메일 입력
2. LLM이 주문 관련 문의인지 확인
3. 고객 이름, 주문 정보 등 핵심 정보 추출
4. 주문 데이터베이스 조회
5. 조회 결과를 바탕으로 LLM이 답변 초안 작성
6. 사람이 검토할 수 있도록 리뷰 큐에 등록
7. 사람 승인 후 고객에게 발송

### Human-in-the-loop

이 예시는 LLM이 바로 고객에게 답장을 보내지 않고, 사람의 검토를 거치도록 설계됩니다.

장점:
- 잘못된 응답 발송 위험 감소
- 고객 커뮤니케이션 품질 관리 가능
- 업무 자동화와 사람 검토를 균형 있게 결합

## 예시 3: 더 복잡한 고객 서비스 에이전트

단순 주문 문의보다 더 어려운 경우는 고객이 다양한 질문을 자유롭게 던지는 상황입니다.

### 재고 문의 예시

고객 질문:
> 검은색 청바지나 파란색 청바지가 있나요?

필요한 단계:
1. 검은색 청바지 재고 조회
2. 파란색 청바지 재고 조회
3. 결과를 종합해 고객에게 응답

### 반품 요청 예시

고객 질문:
> 제가 산 비치 타월을 반품하고 싶어요.

필요한 단계:
1. 고객이 실제로 비치 타월을 구매했는지 확인
2. 구매일과 반품 가능 기간 확인
3. 상품이 사용되지 않았다는 조건 등 반품 정책 확인
4. 반품 가능하면 반품 배송 라벨 발급
5. 데이터베이스 상태를 `return pending`으로 업데이트

### 왜 더 어려운가

이 경우에는 필요한 단계가 미리 고정되어 있지 않습니다.

- 사용자 입력에 따라 필요한 데이터베이스 쿼리가 달라짐
- LLM이 스스로 어떤 절차가 필요한지 계획해야 함
- 계획 오류가 발생하면 잘못된 답변이나 잘못된 액션으로 이어질 수 있음

## 예시 4: 컴퓨터 사용 에이전트

컴퓨터 사용 에이전트(computer use agent)는 웹 브라우저를 직접 조작해 복잡한 작업을 수행하려는 에이전트입니다.

### 항공편 좌석 확인 예시

사용자 요청:
- 샌프란시스코에서 워싱턴 DC DCA 공항으로 가는 특정 United Airlines 항공편의 좌석 가능 여부 확인

에이전트 행동:
1. 웹 브라우저 열기
2. United 웹사이트 접속
3. 페이지 요소 클릭
4. 텍스트 필드 입력
5. 검색 결과 해석
6. 필요 시 Google Flights로 이동
7. 다시 United 웹사이트로 돌아와 좌석 가능 여부 확인

### 현재 한계

컴퓨터 사용 에이전트는 매우 흥미로운 연구 분야이지만, 아직 미션 크리티컬한 업무에 충분히 안정적이지는 않습니다.

어려운 점:
- 웹페이지 로딩이 느리면 상황을 잘못 판단할 수 있음
- 복잡한 웹 UI를 정확히 읽거나 조작하기 어려움
- 페이지 구조 변화에 취약함
- 예측 가능성과 신뢰성이 아직 낮음

## 구현 난이도에 영향을 주는 요소

### 더 쉬운 작업

- 명확한 단계별 프로세스가 있음
- 회사에 이미 표준 운영 절차(SOP)가 있음
- 입력과 출력이 주로 텍스트 기반임
- 필요한 툴 호출과 데이터베이스 업데이트가 사전에 정의되어 있음

### 더 어려운 작업

- 필요한 단계가 사전에 알려져 있지 않음
- 에이전트가 실행 중에 계획을 세워야 함
- 다양한 사용자 요청에 따라 서로 다른 절차를 선택해야 함
- 이미지, 음성, 오디오 등 멀티모달 입력을 처리해야 함
- 웹 브라우저처럼 불안정하고 복잡한 환경을 직접 조작해야 함

## 핵심 스킬: Task Decomposition

Agentic 워크플로우를 구현할 때 가장 중요한 역량 중 하나는 복잡한 작업을 개별 단계로 나누는 능력입니다.

예:
- 리서치 보고서 작성 → 검색어 생성, 웹 검색, 페이지 다운로드, 요약, 초안 작성, 검토
- 고객 응대 → 의도 파악, 정보 추출, 데이터베이스 조회, 정책 확인, 답변 생성, 리뷰 요청

복잡한 업무를 작은 단계로 나누면 각 단계를 LLM, API, 데이터베이스, 사람 검토 등 적절한 컴포넌트에 맡길 수 있습니다.

## 요약

- Agentic AI는 인보이스 처리, 고객 주문 문의, 일반 고객 서비스, 컴퓨터 사용 등 다양한 업무에 적용 가능
- 명확한 절차가 있는 작업은 구현이 비교적 쉬움
- 단계가 고정되어 있지 않은 작업은 LLM의 계획 능력이 필요해 더 어렵고 예측하기 어려움
- 텍스트 기반 작업이 멀티모달 또는 브라우저 조작 작업보다 일반적으로 더 안정적임
- 복잡한 워크플로우를 개별 단계로 나누는 Task Decomposition이 핵심 역량
