# Design Patterns

## 개요

Agentic 워크플로우는 LLM, 툴, API, 데이터베이스, 코드 실행 같은 빌딩 블록을 조합해 복잡한 작업을 수행하도록 구성합니다.

이 강의에서 소개하는 네 가지 핵심 디자인 패턴:
- Reflection
- Tool Use
- Planning
- Multi-Agent Collaboration

이 패턴들은 빌딩 블록을 어떻게 연결해 더 복잡한 워크플로우를 만들지 생각하는 데 도움을 줍니다.

## 1. Reflection

Reflection은 LLM이 자신의 출력물을 다시 검토하고, 피드백을 바탕으로 더 나은 결과를 생성하도록 하는 패턴입니다.

### 코드 작성 예시

1. LLM에게 특정 작업을 수행하는 코드를 작성하게 함
2. 생성된 코드를 다시 LLM에 입력
3. LLM에게 정확성, 스타일, 효율성을 기준으로 검토 요청
4. 발견된 문제를 바탕으로 코드 수정 요청
5. 더 나은 버전의 코드 생성

### 외부 피드백 활용

Reflection은 LLM의 자기 검토뿐 아니라 외부 정보를 피드백으로 사용할 수도 있습니다.

예:
- 코드를 실제로 실행
- 에러 메시지 확인
- 단위 테스트 결과 확인
- 실패 원인을 LLM에 다시 입력
- 수정된 코드 생성

### 특징

- 항상 100% 성공을 보장하지는 않음
- 하지만 시스템 성능을 의미 있게 끌어올리는 경우가 많음
- 구현이 비교적 단순한 편
- 다음 모듈에서 더 깊게 다룰 핵심 패턴

### Critique Agent

같은 LLM이 자기 출력을 비판할 수도 있지만, 별도의 critique agent를 둘 수도 있습니다.

예:
- 작성 에이전트: 코드 생성
- 비평 에이전트: 코드 검토, 오류 지적, 테스트 실행
- 작성 에이전트: 피드백을 반영해 코드 수정

이처럼 각 LLM에 서로 다른 역할을 부여하면 두 에이전트가 대화하듯 반복 개선할 수 있습니다.

## 2. Tool Use

Tool Use는 LLM이 함수나 API 같은 외부 도구를 호출해 작업을 수행하는 패턴입니다.

### 예시

| 사용자 요청 | 사용할 수 있는 툴 |
|------------|------------------|
| 리뷰어들이 추천하는 최고의 커피메이커는? | 웹 검색 툴 |
| 복리로 $100를 투자하면 얼마가 되는가? | 코드 실행 툴 |
| 고객 주문 상태는? | 주문 데이터베이스 조회 |
| 회의 일정을 잡아줘 | 캘린더 API |
| 이메일을 보내줘 | 이메일 API |

### 왜 중요한가

LLM은 텍스트 생성에는 강하지만, 외부 세계의 최신 정보나 실제 액션 수행에는 한계가 있습니다.

Tool Use를 통해 LLM은 다음을 수행할 수 있습니다.
- 웹에서 정보 검색
- 데이터베이스 조회
- 코드 실행
- 이메일 및 캘린더 같은 생산성 앱 조작
- 이미지 처리
- 수학 및 데이터 분석

핵심은 LLM이 어떤 툴을 언제 호출할지 결정할 수 있다는 점입니다.

## 3. Planning

Planning은 LLM이 목표를 달성하기 위해 필요한 단계의 순서를 스스로 결정하는 패턴입니다.

### HuggingGPT 예시

요청:
> 남자아이 이미지의 포즈와 같은 포즈로 책을 읽는 여자아이 이미지를 생성하고, 생성된 이미지를 음성으로 설명해줘.

LLM이 계획할 수 있는 단계:
1. 포즈 추정 모델로 남자아이의 포즈 파악
2. 해당 포즈를 사용해 여자아이 이미지 생성
3. 생성된 이미지를 설명하는 텍스트 생성
4. 텍스트를 음성으로 변환

### 특징

- 개발자가 모든 단계를 미리 하드코딩하지 않음
- LLM이 필요한 작업 순서와 API 호출 순서를 결정
- 복잡하고 유연한 작업에 유용
- 하지만 제어하기 어렵고 더 실험적인 영역

Planning은 더 높은 자율성을 가진 Agentic 워크플로우와 밀접하게 연결됩니다.

## 4. Multi-Agent Collaboration

Multi-Agent Collaboration은 여러 에이전트가 서로 다른 역할을 맡아 함께 복잡한 작업을 수행하는 패턴입니다.

### ChatDev 예시

ChatDev는 여러 역할의 에이전트가 가상의 소프트웨어 회사처럼 협업하는 프레임워크입니다.

역할 예시:
- CEO
- Programmer
- Tester
- Designer

각 에이전트는 특정 역할을 맡고, 함께 소프트웨어 개발 작업을 수행합니다.

### 마케팅 브로셔 작성 예시

사람 팀을 구성한다면 다음과 같은 역할이 필요할 수 있습니다.

| 역할 | 수행 작업 |
|------|----------|
| Researcher | 온라인 리서치 |
| Marketer | 마케팅 문구 작성 |
| Editor | 문장 다듬기 및 최종 편집 |

이를 Agentic 워크플로우로 구현하면:
1. Research Agent가 자료 조사
2. Marketer Agent가 브로셔 문구 작성
3. Editor Agent가 문구를 검토하고 다듬음

### 특징

- 복잡한 작업에서 더 좋은 결과를 낼 수 있음
- 역할 분담을 통해 전문성을 흉내 낼 수 있음
- 글쓰기, 전기 작성, 체스 수 결정 같은 작업에서 연구적으로 좋은 결과가 보고됨
- 여러 에이전트가 무엇을 할지 사전에 완전히 예측하기 어려워 제어가 더 어려움

## 네 가지 패턴 비교

| 패턴 | 핵심 아이디어 | 장점 | 주의점 |
|------|--------------|------|--------|
| Reflection | 출력물을 검토하고 반복 개선 | 구현이 단순하고 성능 개선 가능 | 항상 성공하지는 않음 |
| Tool Use | LLM이 외부 툴 호출 | 최신 정보, 계산, 실제 액션 가능 | 툴 선택과 인자 오류 관리 필요 |
| Planning | LLM이 단계 순서를 결정 | 유연한 문제 해결 가능 | 제어와 예측이 어려움 |
| Multi-Agent Collaboration | 여러 역할의 에이전트 협업 | 복잡한 작업에서 품질 향상 가능 | 조율과 통제가 어려움 |

## Agentic 워크플로우 구축 관점

Agentic 워크플로우를 만들 때 필요한 역량:
- 사용 가능한 빌딩 블록 이해
- 작업을 개별 단계로 분해
- 적절한 디자인 패턴 선택
- 필요한 툴과 모델 연결
- eval을 통해 성능 측정
- error analysis로 개선 지점 발견
- 반복적으로 워크플로우 개선

## 요약

- Agentic 워크플로우는 빌딩 블록을 조합해 복잡한 작업을 수행하도록 만드는 방식
- 대표 디자인 패턴은 Reflection, Tool Use, Planning, Multi-Agent Collaboration
- Reflection은 출력물을 검토하고 개선하는 패턴
- Tool Use는 LLM이 함수, API, 데이터베이스, 코드 실행 같은 툴을 사용하는 패턴
- Planning은 LLM이 필요한 단계의 순서를 스스로 결정하는 패턴
- Multi-Agent Collaboration은 여러 역할의 에이전트가 협력하는 패턴
- 좋은 Agentic 시스템을 만들려면 디자인 패턴뿐 아니라 eval과 error analysis도 함께 필요함
