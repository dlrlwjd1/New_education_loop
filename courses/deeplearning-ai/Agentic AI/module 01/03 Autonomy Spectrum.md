# Autonomy Spectrum (자율성 스펙트럼)

## 핵심 개념: "Agent"가 아닌 "Agentic"

앤드류 응이 "Agentic"이라는 형용사를 의도적으로 만든 이유:
- "에이전트인가 아닌가"의 이분법적 논쟁을 피하기 위해
- 자율성(autonomy)은 **정도(degree)의 문제**이지 이진(binary)이 아님
- 용어 논쟁보다 실제 시스템 구축에 집중하자는 취지

## 자율성 스펙트럼

```
낮은 자율성 ←————————————————————→ 높은 자율성
  (Less Autonomous)              (Highly Autonomous)
```

### 낮은 자율성 (Less Autonomous)
- 모든 단계가 **사전에 결정**됨 (프로그래머가 하드코딩)
- 툴 호출 순서 고정 (예: 항상 web search → fetch → write)
- LLM의 자율성 = 생성하는 **텍스트 내용**에만 있음
- 완전 결정론적(fully deterministic) 흐름

예시:
```
[사용자 입력] → LLM(검색어 생성) → 웹 검색 → 웹 페이지 fetch → LLM(에세이 작성)
```

### 반자율 (Semi-Autonomous)
- 일부 결정은 LLM이 내림 (어떤 툴을 쓸지 등)
- 툴 목록 자체는 사람이 사전 정의
- 예: 웹 검색 vs 뉴스 검색 vs arxiv 중 LLM이 선택

### 높은 자율성 (Highly Autonomous)
- 실행 단계의 **순서 자체**를 LLM이 결정
- 더 많은 웹페이지가 필요한지, 반성(reflection)이 필요한지 LLM이 판단
- 극단: 새 함수나 툴을 **직접 생성**해서 실행
- 덜 통제 가능하고, 예측하기 어려움, 활발히 연구 중

## 시각 표기 규칙 (강의 전체 공통)

| 색상 | 의미 |
|------|------|
| 빨간색 | 사용자 입력 (user query, 입력 문서 등) |
| 회색 박스 | LLM 호출 |
| 초록색 박스 | 외부 소프트웨어 실행 (웹 검색 API, 코드 실행 등) |

## 실용적 관점

- 낮은 자율성 시스템도 **비즈니스에서 충분히 가치 있음** — 수많은 기업이 이 영역에서 구축 중
- 높은 자율성 시스템은 강력하지만 **예측 불가능성**이 높아 연구 과제가 많음
- 어디에 위치할지는 **사용 목적과 허용 가능한 리스크**에 따라 결정
