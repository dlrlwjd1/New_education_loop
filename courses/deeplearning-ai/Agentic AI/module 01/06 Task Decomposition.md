# Task Decomposition

## 개요

Task Decomposition은 사람이 하거나 비즈니스가 수행하는 복잡한 작업을 Agentic 워크플로우가 따를 수 있는 개별 단계로 나누는 과정입니다.

핵심 질문:
> 이 단계를 LLM, 짧은 코드, 함수 호출, API, 또는 다른 툴로 구현할 수 있는가?

만약 답이 아니라면:
- 사람이 이 단계를 어떻게 수행하는지 생각해보기
- 더 작은 단계로 다시 분해하기
- 각 작은 단계가 LLM 또는 툴로 구현 가능한지 재검토하기

## 예시 1: Research Agent

### 직접 생성의 한계

주제 X에 대한 에세이를 작성할 때 LLM에 한 번만 프롬프트를 주면 결과는 빠르게 나오지만, 깊이 있는 리서치가 필요한 주제에서는 한계가 있습니다.

가능한 문제:
- 표면적인 내용만 다룸
- obvious facts 위주로 작성됨
- 깊이 있는 분석이나 자료 기반 논의가 부족함

### 1차 분해

사람이 에세이를 쓴다면 보통 바로 최종본을 쓰지 않고 여러 단계를 거칩니다.

초기 Agentic 워크플로우:
1. 에세이 아웃라인 작성
2. 웹 검색 수행
3. 검색 결과를 바탕으로 에세이 작성

각 단계의 구현 가능성:
- 아웃라인 작성: LLM이 수행 가능
- 웹 검색: LLM이 검색어를 생성하고 검색 API 또는 툴 호출
- 에세이 작성: 검색 결과를 입력으로 받아 LLM이 초안 생성

이 방식은 단일 프롬프트 직접 생성보다 더 깊이 있는 결과를 만들 수 있는 합리적인 첫 시도입니다.

### 추가 분해와 개선

초기 워크플로우 결과가 여전히 부족할 수 있습니다.

예:
- 글의 시작, 중간, 끝이 일관되지 않음
- 내용이 연결되지 않고 산만함
- 충분히 깊이 있거나 thoughtful하지 않음

이 경우 `에세이 작성` 단계를 더 작은 단계로 나눌 수 있습니다.

개선된 워크플로우:
1. 에세이 아웃라인 작성
2. 웹 검색 수행
3. 첫 번째 초안 작성
4. 초안에서 수정이 필요한 부분 검토
5. 검토 결과를 바탕으로 초안 수정

이 접근은 사람이 글을 쓸 때 초안을 작성하고, 읽어보고, 다시 고치는 과정과 유사합니다.

## 예시 2: 고객 주문 문의 응답

고객 주문 문의 이메일에 응답하는 작업도 여러 단계로 나눌 수 있습니다.

### Agentic 워크플로우

1. 핵심 정보 추출
   - 이메일을 보낸 사람
   - 주문한 상품
   - 주문 번호
2. 관련 고객 기록 조회
   - 주문 데이터베이스 쿼리 생성
   - 배송 상태, 주문 일자 등 조회
3. 고객에게 보낼 응답 작성 및 전송
   - 조회된 정보를 바탕으로 답변 생성
   - 필요하면 이메일 전송 API 호출

### 구현 가능성 판단

각 단계는 LLM 또는 툴로 구현 가능합니다.

- 정보 추출: LLM
- 데이터베이스 조회: LLM + 함수 호출 또는 API
- 응답 작성: LLM
- 이메일 전송: API 또는 툴 호출

중요한 점은 전체 작업을 한 번에 해결하려고 하기보다, 각 단계가 어떤 컴포넌트로 구현 가능한지 따져보는 것입니다.

## 예시 3: 인보이스 처리

PDF 인보이스가 텍스트로 변환된 이후의 작업은 비교적 명확하게 분해할 수 있습니다.

### Agentic 워크플로우

1. 필요한 정보 추출
   - 청구자 이름
   - 주소
   - 결제 기한
   - 결제 금액
2. 추출 정보 확인 및 데이터베이스 저장
   - 정보가 올바르게 추출되었는지 검토
   - 새 데이터베이스 레코드 생성 또는 업데이트

### 구현 가능성 판단

- 필드 추출: LLM이 수행 가능
- 데이터베이스 업데이트: LLM이 함수 호출 또는 API 호출로 수행 가능

이처럼 프로세스가 명확한 업무는 Agentic 워크플로우로 구현하기 쉽습니다.

## Agentic 워크플로우의 빌딩 블록

Agentic 워크플로우를 설계할 때 사용할 수 있는 대표적인 빌딩 블록은 다음과 같습니다.

### AI 모델

| 빌딩 블록 | 역할 |
|-----------|------|
| LLM | 텍스트 생성, 정보 추출, 다음 호출 결정 |
| Large Multimodal Model | 이미지, 오디오 등 멀티모달 입력 처리 |
| 특수 AI 모델 | PDF-to-text, text-to-speech, 이미지 분석 등 |

### 소프트웨어 툴

| 툴 | 역할 |
|----|------|
| API 호출 | 웹 검색, 날씨 조회, 이메일 전송, 캘린더 확인 등 |
| 데이터베이스 조회 | 고객 정보, 주문 정보, 내부 데이터 검색 |
| RAG | 큰 텍스트 데이터베이스에서 관련 문서 검색 |
| 코드 실행 | LLM이 코드를 작성하고 실행해 다양한 작업 수행 |

Agentic 워크플로우 설계는 사람이 수행하는 업무를 관찰한 뒤, 위와 같은 빌딩 블록을 어떤 순서로 연결할지 결정하는 과정입니다.

## 반복 개선

Task Decomposition은 한 번에 완성되는 경우가 많지 않습니다.

일반적인 과정:
1. 초기 단계 분해 설계
2. Agentic 워크플로우 구현
3. 결과 확인
4. 부족한 부분 분석
5. 특정 단계를 더 세분화하거나 교체
6. 원하는 성능이 나올 때까지 반복

예:
- 직접 생성이 부족하면 아웃라인과 검색 단계를 추가
- 글이 산만하면 초안 검토와 수정 단계를 추가
- 특정 API 호출이 불안정하면 검증 단계나 fallback 경로 추가

## 요약

- Task Decomposition은 복잡한 작업을 Agentic 워크플로우가 실행 가능한 작은 단계로 나누는 기술
- 각 단계마다 LLM, API, 함수 호출, 코드 실행, RAG 등으로 구현 가능한지 확인해야 함
- 구현이 어렵다면 사람이 그 단계를 어떻게 수행하는지 보고 더 작은 단계로 분해
- Research Agent, 고객 주문 문의, 인보이스 처리 모두 이 방식으로 설계 가능
- 초기 분해 후 결과를 평가하고 반복적으로 개선하는 과정이 중요함
