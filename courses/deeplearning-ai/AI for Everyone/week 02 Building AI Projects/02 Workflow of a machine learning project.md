# Workflow of a machine learning project

## 개요
- 머신러닝 프로젝트는 입력 A를 출력 B로 바꾸는 매핑을 학습하는 시스템을 만드는 과정이다.
- 핵심 단계는 **데이터 수집 → 모델 훈련 → 모델 배포**다.
- 실제 프로젝트에서는 한 번에 완성되지 않으며, 여러 번 반복하면서 모델을 개선한다.

## 내용

### 머신러닝 프로젝트의 기본 흐름
머신러닝 프로젝트는 보통 다음 세 단계로 진행된다.

| 단계 | 설명 |
|------|------|
| 1. 데이터 수집 | 입력 A와 원하는 출력 B가 포함된 데이터를 모은다. |
| 2. 모델 훈련 | 머신러닝 알고리즘이 A to B 매핑을 학습한다. |
| 3. 모델 배포 | 학습된 모델을 실제 제품이나 사용자 환경에 적용한다. |

각 단계에서는 반복(iteration)이 필요하다. 첫 번째 모델은 거의 항상 충분히 잘 작동하지 않기 때문에, 데이터를 더 모으거나 모델을 조정하면서 성능을 개선한다.

### 예시 1: 음성 인식
스마트 스피커가 "Alexa", "Hey Google", "Hey Siri" 같은 호출어를 인식하려면 먼저 오디오 데이터를 수집해야 한다.

| 입력 A | 출력 B |
|--------|--------|
| 사용자의 오디오 클립 | 사용자가 말한 단어 또는 호출어 여부 |

첫 단계에서는 여러 사람이 "Alexa"라고 말한 오디오와, "hello" 같은 다른 단어를 말한 오디오를 녹음한다. 이후 모델은 오디오 클립을 입력받아 어떤 단어가 말해졌는지 학습한다.

모델을 스마트 스피커에 배포하면 실제 사용자 환경에서 새로운 문제가 나타날 수 있다. 예를 들어 미국식 억양으로 학습한 시스템을 영국에 배포하면 영국식 억양을 잘 인식하지 못할 수 있다. 이 경우 새 데이터를 다시 수집해 모델을 유지보수하고 업데이트해야 한다.

### 예시 2: 자율주행차의 차량 감지
자율주행차의 핵심 구성 요소 중 하나는 전방 이미지를 보고 다른 차량의 위치를 찾는 시스템이다.

| 입력 A | 출력 B |
|--------|--------|
| 전방 카메라 이미지 | 이미지 속 다른 차량의 위치 |

이 프로젝트에서도 첫 단계는 데이터 수집이다. 전방 이미지와 함께, 이미지 안의 차량 위치를 표시한 라벨이 필요하다. 보통 차량 주위에 사각형을 그려 출력 B를 정의한다.

두 번째 단계에서는 이 데이터를 사용해 모델을 훈련한다. 초기 모델은 잘못된 위치를 차량으로 인식할 수 있으므로 여러 번 반복하면서 개선해야 한다.

세 번째 단계는 배포다. 자율주행 분야에서는 안전이 최우선이므로, 모델은 안전을 보장할 수 있는 방식으로 테스트되고 배포되어야 한다. 배포 후에는 골프 카트처럼 기존 데이터에 적게 포함된 새로운 유형의 차량을 잘 감지하지 못할 수 있고, 이런 데이터를 다시 수집해 모델을 개선한다.

### 반복의 중요성
머신러닝 프로젝트는 선형적으로 한 번에 끝나지 않는다. 배포 이후에도 새 데이터를 통해 모델을 업데이트할 수 있다면 제품이 계속 좋아질 수 있다.

반복은 다음과 같은 이유로 필요하다.

- 첫 번째 모델의 성능이 충분하지 않을 수 있다.
- 실제 사용자 환경의 데이터가 훈련 데이터와 다를 수 있다.
- 새로운 유형의 입력이 등장할 수 있다.
- 배포 후 수집한 데이터가 모델 개선에 도움을 줄 수 있다.

## 예시

### 머신러닝 프로젝트 체크리스트
| 질문 | 확인 내용 |
|------|-----------|
| 입력 A는 무엇인가? | 오디오, 이미지, 센서 데이터 등 |
| 출력 B는 무엇인가? | 단어, 차량 위치, 결함 여부 등 |
| 데이터가 충분한가? | A와 B가 함께 있는 데이터 필요 |
| 배포 환경은 어떤가? | 실제 사용자, 공장, 차량 등 |
| 배포 후 데이터를 받을 수 있는가? | 유지보수와 업데이트 가능성 |

## 요약
- 머신러닝 프로젝트의 핵심 단계는 데이터 수집, 모델 훈련, 모델 배포다.
- 음성 인식은 오디오를 입력으로 받아 단어 또는 호출어를 출력하는 A to B 문제다.
- 자율주행 차량 감지는 이미지를 입력으로 받아 차량 위치를 출력하는 문제다.
- 실제 환경에서는 새 데이터와 예상치 못한 사례가 생기므로 반복과 유지보수가 중요하다.
