# 03 Basic Recipe for Machine Learning

## 개요
- bias/variance 진단 결과에 따라 **체계적으로** 성능을 개선하는 기본 레시피.

---

## 내용

### 기본 레시피 (순서대로)
```
1) High bias? (훈련 세트 성능 확인)
   → YES: - 더 큰 네트워크 (층/유닛 ↑)   ← 거의 항상 도움
          - 더 오래 훈련                 ← 손해는 없음
          - (다른 네트워크 구조)          ← 될 수도, 안 될 수도
   훈련 세트를 잘 맞출 때까지 반복.

2) High variance? (dev 세트 성능 확인)
   → YES: - 더 많은 데이터              ← 가능하면 최선
          - 정규화(regularization)
          - (다른 네트워크 구조)
   low bias & low variance가 될 때까지 반복 → 완료.
```

### 핵심 포인트
1. **진단에 따라 시도할 것이 다르다.**
   - 예: high bias인데 데이터를 더 모아도 소용없음.
   - 먼저 bias/variance를 진단해 **효율적인 대응**을 고른다.
2. **딥러닝 시대엔 bias-variance 트레이드오프가 약하다.**
   - 과거엔 도구가 부족해 한쪽을 줄이면 다른 쪽이 커졌다.
   - 지금은:
     - **더 큰 네트워크** → bias를 줄이면서 (적절히 정규화하면) variance를 크게 해치지 않음.
     - **더 많은 데이터** → variance를 줄이면서 bias를 거의 해치지 않음.
   - → 한쪽만 줄이는 도구가 생김 → 딥러닝이 지도학습에서 강력한 이유 중 하나.
3. **잘 정규화된** 큰 네트워크는 거의 손해가 없다 (비용은 계산 시간뿐).

---

## 요약
- 레시피: high bias 해결(큰 망/더 오래) → high variance 해결(더 많은 데이터/정규화) → 반복.
- bias/variance를 먼저 진단해 맞는 처방을 선택.
- 큰 망 + 더 많은 데이터로 트레이드오프 없이 개선 가능 (정규화 전제).
