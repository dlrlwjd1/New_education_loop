# 06 Inception Network Motivation

## 개요
- **Inception 모듈**: 필터 크기(1×1/3×3/5×5)나 pooling을 고르지 말고 **다 해서 출력을 이어붙인다(concatenate)**.
- 연산량 문제는 **1×1 conv 병목(bottleneck)** 으로 해결.

---

## 내용

### Inception 모듈
- 입력 28×28×192에 대해:
  - 1×1 conv → 28×28×64
  - 3×3 same conv → 28×28×128
  - 5×5 same conv → 28×28×32
  - max pool(same, stride 1) → 28×28×32
- 모두 **채널 방향으로 쌓음** → 28×28×**256**.
- 네트워크가 어떤 필터 조합을 쓸지 스스로 학습. (Szegedy 등)
- pooling도 차원을 맞추려면 **same padding + stride 1** 사용(비정상적 형태).

### 연산량 문제와 병목 층 ⭐
- 5×5 conv 직접: 출력 28×28×32, 각 값에 5×5×192 곱 → **약 1억 2천만 곱셈**.
- **1×1 병목**으로 개선:
  ```
  28×28×192 → (1×1 conv, 16필터) → 28×28×16  → (5×5 conv) → 28×28×32
  ```
  - 1×1 단계: 28×28×16 × (1×1×192) ≈ **240만**.
  - 5×5 단계: 28×28×32 × (5×5×16) ≈ **1,000만**.
  - 합계 ≈ **1,240만** → **약 1/10로 감소**.
- **bottleneck layer** = 표현을 잠깐 줄였다가 다시 늘리는 가장 작은 부분.
- 병목을 합리적으로 쓰면 **성능 손실 없이 연산량 대폭 절약**.

---

## 요약
- Inception 모듈 = 1×1/3×3/5×5/pool을 모두 적용해 채널 방향 concat.
- 1×1 conv 병목으로 연산량을 ~1/10로 줄임(성능 손실 거의 없음).
