# 06 Addressing Data Mismatch

## 개요
- 데이터 불일치(data mismatch)에는 **체계적 해법은 없지만** 시도할 만한 방법들이 있다.

---

## 내용

### 접근
1. **수동 오류 분석** — train과 dev의 차이를 이해 (dev만 보고 test는 보지 말 것 — 과적합 방지).
   - 예: dev에 자동차 소음이 많음, 거리 번호(street number) 오인식이 잦음.
2. train 데이터를 dev와 **더 비슷하게** 만들거나, dev와 비슷한 데이터를 **더 수집**.
   - 예: 차량 소음 시뮬레이션, 숫자 발화 데이터 추가 수집.

### 인공 데이터 합성 (artificial data synthesis)
- 예: 깨끗한 음성 + 자동차 소음을 **더해** 차 안에서 말한 것처럼 합성.
- 음성 인식에서 이미 좋은 시스템의 성능을 크게 올린 사례 있음.

### ⚠️ 주의: 작은 부분공간에 과적합
- 깨끗한 음성 10,000시간 + **1시간짜리 소음을 10,000번 반복**하면, 사람 귀엔 괜찮아도 신경망이 **그 1시간 소음에 과적합**할 수 있음.
  - 가능한 모든 소음 공간의 극히 일부만 합성하는 셈.
- 자율주행: **컴퓨터 그래픽/비디오 게임**으로 차 이미지 합성 — 게임에 차종이 20개뿐이면 그 20개에 과적합. 실제 세계 차종은 훨씬 많음.
- 사람 눈/귀엔 사실적이어도 **전체 공간의 작은 부분집합**만 다루고 있을 수 있음.

---

## 요약
- data mismatch: 오류 분석으로 train/dev 차이를 파악 → train을 dev와 비슷하게 만들거나 유사 데이터 수집.
- 인공 데이터 합성은 효과적이나, **전체 공간의 작은 부분에 과적합**하지 않도록 주의.
