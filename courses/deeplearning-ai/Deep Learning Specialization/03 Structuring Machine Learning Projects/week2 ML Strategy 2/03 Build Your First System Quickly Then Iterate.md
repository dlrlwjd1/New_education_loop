# 03 Build Your First System Quickly, Then Iterate

## 개요
- 새 ML 애플리케이션은 **빠르게 첫 시스템을 만들고 반복(iterate)** 하라.

---

## 내용

### 문제: 방향이 너무 많다
- 예: 음성 인식 — 잡음(카페/자동차) 강건성, 억양, 원거리(far-field), 아동 음성, 말더듬/필러(uh, um) 등 **50개 방향**이 모두 그럴듯하다. 무엇에 집중할지 고르기 어렵다.

### 권장 절차
1. **dev/test 세트 + 지표를 빠르게 설정** (과녁 놓기 — 틀리면 나중에 옮김).
2. **초기 시스템을 빠르게 구축** (quick and dirty, 과하게 고민 X). 훈련 세트로 학습해 성능 확인.
3. **bias/variance 분석 + 오류 분석**으로 다음 단계 우선순위 결정.
   - 예: 오류 분석에서 far-field(원거리) 문제가 크면 → 그쪽에 집중.

### 초기 시스템의 가치
- 학습된 시스템이 있어야 bias/variance·오류 분석을 할 수 있고, 이것이 **어디로 갈지 우선순위**를 정해준다.

### 예외
- 해당 분야 **경험이 많거나**, 거의 동일한 문제의 **탄탄한 학술 문헌**이 있으면(예: 얼굴 인식) 처음부터 더 복잡하게 시작해도 됨.
- 새 문제라면 과설계하지 말 것.

### 관찰
- 팀들은 **과소설계보다 과설계(overthink)** 하는 경우가 훨씬 많다.
- 목표가 "잘 작동하는 것을 만드는 것"이면(새 알고리즘 발명이 아니라), quick and dirty로 시작해 분석으로 우선순위를 정하라.

---

## 요약
- dev/test·지표 빠르게 설정 → 초기 시스템 빠르게 구축 → bias/variance·오류 분석으로 반복.
- 과설계를 경계. 경험/문헌이 풍부한 분야는 예외.
