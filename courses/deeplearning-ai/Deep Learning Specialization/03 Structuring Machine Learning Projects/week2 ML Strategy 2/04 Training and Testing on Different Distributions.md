# 04 Training and Testing on Different Distributions

## 개요
- 딥러닝은 데이터 갈증이 커, **훈련 세트가 dev/test와 다른 분포**에서 오는 경우가 많다. 이를 잘 다루는 법.

---

## 내용

### 예 1: 고양이 앱 (웹 20만 + 앱 1만)
- **원하는 분포**: 사용자가 앱에 올린 이미지(흐림/비전문, 1만 개).
- **여분 데이터**: 웹에서 크롤링한 고화질 고양이(20만 개).

**옵션 1 (❌ 비권장)**: 21만 개를 섞어 무작위로 train/dev/test 분할.
- 장점: 모두 같은 분포.
- 치명적 단점: dev 2,500개 중 **약 2,381개가 웹 이미지**, 앱은 ~119개뿐 → **과녁이 엉뚱한 분포**를 향함.

**옵션 2 (✅ 권장)**:
- train = 웹 20만 + 앱 5천
- dev = 앱 2,500, test = 앱 2,500 (dev/test는 **전부 앱 이미지**)
- 장점: **과녁을 원하는 분포(앱)에 정확히** 둠.
- 단점: train과 dev/test 분포가 다름 → 하지만 장기적으로 더 나은 성능 (대처법은 후속 영상).

### 예 2: 음성 인식 백미러
- train = 기존 여러 음성 데이터 50만 발화(구매/스마트 스피커/키보드 등).
- dev/test = 실제 백미러 발화(주소·내비 질의 등, 원하는 분포).
- 20,000개 백미러 발화 중 10,000은 train에 넣고 dev/test 각 5,000씩으로 나눠도 됨.

---

## 요약
- train은 다른 분포(대량 데이터)에서 와도 되지만, **dev/test는 반드시 원하는 분포**로.
- 데이터를 그냥 섞지 말 것 — 과녁이 잘못된 분포를 향하게 됨.
