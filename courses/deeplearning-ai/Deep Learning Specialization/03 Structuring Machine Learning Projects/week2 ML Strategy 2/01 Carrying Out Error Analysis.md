# 01 Carrying Out Error Analysis

## 개요
- **오류 분석(error analysis)**: 알고리즘이 틀린 예제를 **직접(수동으로) 살펴** 다음에 무엇을 개선할지 정하는 것.

---

## 내용

### 예: 개를 고양이로 오분류
- 고양이 분류기 오류 10%. 개 사진을 고양이로 오인. "개 문제"에 몇 달을 써야 할까?
- **오류 분석 절차**:
  1. 오분류된 dev 예제 **~100개**를 뽑는다.
  2. 그중 몇 개가 개인지 **센다**.
  - 개가 **5%** → 개 문제를 다 풀어도 10% → 9.5%로만 개선 (상한/ceiling이 낮음) → 안 할 수도.
  - 개가 **50%** → 10% → 5%로 개선 가능 → 할 만함.
- 100개 세는 데 **5~10분** → 몇 달 방향을 결정. "성능 상한(ceiling)"을 빠르게 추정.

### 여러 아이디어 병렬 평가 (스프레드시트)
| 이미지 | 개(dog) | 큰 고양이(great cat) | 흐림(blurry) | 코멘트 |
|---|---|---|---|---|
| 1 | ✓ | | | 핏불 |
| 2 | | | ✓ | |
| 3 | | ✓ | ✓ | 비 오는 날 동물원 |
| ... | | | | |
| **비율** | 8% | 43% | 61% | |

- 각 열의 체크 비율 = 그 범주의 오류 비중.
- 진행 중 **새 범주**(예: Instagram 필터) 발견 시 열 추가 가능.
- → 흐림·큰 고양이의 개선 상한이 훨씬 높음 → 우선순위 결정. (엄밀한 공식이 아니라 방향 감각 제공)

---

## 요약
- 오분류 예제 ~100개를 수동으로 범주별로 세면(수 시간 이내), 각 방향의 개선 상한을 알아 우선순위를 정할 수 있다.
- false positive/negative 모두 보고, 필요하면 새 오류 범주를 추가.
