# 06 Size of the Dev and Test Sets

## 개요
- 딥러닝 시대에는 dev/test 세트 **크기 규칙**이 바뀌었다.

---

## 내용

### 과거 규칙
- 70/30 (train/test) 또는 60/20/20 (train/dev/test).
- 총 100~10,000개 수준이면 합리적.

### 빅데이터 시대
- 예: 100만 개 → **98% train / 1% dev / 1% test** (dev·test 각 1만 개면 충분).
- 딥러닝은 데이터 갈증이 커 **train 비율을 크게**.

### dev/test 크기 결정 원칙 ⭐
- **dev 세트**: 아이디어/알고리즘 A·B를 **평가·선택**하기에 충분한 크기.
- **test 세트**: 최종 시스템 성능을 **확신할 만큼**의 크기 (수백만 개까지 필요 없을 수도, 1만~10만이면 충분한 경우 많음).
- 둘 다 30%보다 훨씬 작아도 됨.

### test 세트 생략
- 최종 성능의 편향 없는 추정이 꼭 필요 없다면 train + dev만 둘 수도 있음.
- 이때 dev를 "test set"이라 부르는 관행이 있으나, 실제론 튜닝에 쓰므로 **train-dev set**이라 부르는 게 정직.
- (강사는 test 세트를 두는 걸 권장 — 배포 전 편향 없는 추정에 안심.)

---

## 요약
- 70/30 규칙은 빅데이터에 안 맞음 → train 비율↑, dev/test는 목적에 맞는 크기면 충분.
- dev = A/B 평가에 충분, test = 최종 성능 확신에 충분.
