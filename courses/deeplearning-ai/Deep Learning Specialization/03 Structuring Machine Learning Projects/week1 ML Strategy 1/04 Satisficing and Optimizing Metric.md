# 04 Satisficing and Optimizing Metric

## 개요
- 여러 지표를 하나로 합치기 어려울 때: **최적화 지표(optimizing)** 1개 + **만족 지표(satisficing)** 여러 개로 나눈다.

---

## 내용

### 정의
- **Optimizing metric(최적화 지표)**: 최대한 잘 하고 싶은 지표 (예: 정확도).
- **Satisficing metric(만족 지표)**: **임계값(threshold)만 넘으면** 그 이상은 신경 안 씀 (예: 실행 시간 ≤ 100ms).

### 예시 1: 정확도 + 실행 시간
| 분류기 | 정확도 | 실행 시간 |
|---|---|---|
| A | 90% | 80ms |
| B | 92% | 95ms |
| C | 95% | 1500ms |
- 규칙: **실행 시간 ≤ 100ms(만족) 하에서 정확도 최대화(최적화)**.
- → C는 시간 초과로 탈락, A·B 중 정확도 높은 **B 선택**.

### 예시 2: 웨이크 워드(trigger word) 탐지
- (Alexa, OK Google, Hey Siri, 你好百度 등)
- **정확도 최대화(최적화)** + **24시간당 오탐(false positive) ≤ 1회(만족)**.

### 일반 규칙
- n개 지표가 있으면: **1개는 optimizing**, 나머지 **n−1개는 satisficing**(임계값 통과만 요구).
- → 여러 분류기 중 "최선"을 거의 자동으로 선택 가능.

---

## 요약
- 최적화 지표 1개 + 만족 지표 여러 개 → 자동으로 최선 분류기 선택.
- 만족 지표는 임계값만 넘으면 됨(예: 시간, 오탐 횟수), 최적화 지표는 최대화(예: 정확도).
