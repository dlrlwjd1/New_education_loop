# 02 Orthogonalization

## 개요
- **직교화(orthogonalization)**: 각 "손잡이(knob)"가 **한 가지만** 제어하도록 하면 시스템 튜닝이 쉬워진다.
- 효과적인 ML 엔지니어는 "무엇을 조정하면 어떤 효과가 나는지"를 명확히 안다.

---

## 내용

### 비유
- **옛날 TV**: 높이/너비/사다리꼴/위치/회전 각각을 조정하는 **별도 손잡이** → 튜닝 쉬움. 하나가 여러 개를 섞어 바꾸면 조정 불가능.
- **자동차**: 조향(steering)과 속도(가속/브레이크)가 **분리된 제어** → 원하는 대로 운전 가능.
- **직교(orthogonal)** = 서로 90도, 즉 독립적으로 하나씩 제어.

### ML의 4단계 사슬(chain of assumptions)과 각 손잡이 ⭐
지도학습이 잘 되려면 순서대로 만족해야 하고, 각 단계마다 **전용 손잡이**가 있다:

| 단계 | 문제 | 조정할 손잡이(knob) |
|---|---|---|
| 1. **훈련 세트** 성능 | train 부적합 | 더 큰 네트워크, 더 나은 옵티마이저(Adam) |
| 2. **dev 세트** 성능 | train OK, dev 나쁨 | 정규화, 더 큰 훈련 세트 |
| 3. **test 세트** 성능 | dev OK, test 나쁨 | 더 큰 dev 세트 |
| 4. **실제 세계** 성능 | test OK, 실사용 나쁨 | dev/test 분포 또는 비용 함수 변경 |

- 각 문제를 **정확히 진단**하고 그에 맞는 손잡이만 돌린다.

### Early stopping은 덜 직교적
- early stopping은 **훈련 세트 적합도와 dev 성능을 동시에** 바꿈 → 두 가지를 섞는 손잡이(TV 너비+높이를 동시에 바꾸는 것과 유사).
- 나쁜 건 아니지만, Andrew Ng은 **덜 직교적이라 잘 안 씀** — 더 직교적인 손잡이가 튜닝을 쉽게 함.

---

## 요약
- 직교화 = 문제를 정확히 진단하고 그것만 고치는 전용 손잡이를 사용.
- 4단계: train → dev → test → 실세계, 각 단계별 전용 개선책.
- early stopping은 두 효과를 섞어 덜 직교적.
