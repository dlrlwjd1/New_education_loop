# 05 Train / Dev / Test Distributions

## 개요
- dev/test 세트 설정은 팀 진행 속도에 큰 영향. 핵심 규칙: **dev와 test는 반드시 같은 분포에서.**

---

## 내용

### 비유: 과녁(target)
- dev 세트 + 단일 숫자 지표 = 팀이 조준할 **과녁의 정중앙(bullseye)** 을 정하는 것.
- 팀은 dev 세트에 맞춰 빠르게 반복하며 조준을 좁혀감.

### 나쁜 예 ⚠️
- 8개 지역 데이터에서 **4개 지역은 dev, 다른 4개 지역은 test** 로 나눔 → dev와 test **분포가 다름**.
- 결과: 몇 달간 dev에 최적화했는데 test에서 전혀 다른 성능 → **과녁을 옮긴 셈**, 노력 낭비.
- 실화: 중간 소득 지역 대출 데이터로 dev 최적화 → 저소득 지역 test에서 실패 → **3개월 낭비**.

### 올바른 방법
- 모든 데이터를 **무작위로 섞어** dev와 test에 배분 → 둘 다 8개 지역을 모두 포함, **같은 분포**.
- **dev/test는 "미래에 얻을, 잘하고 싶은 데이터"를 반영**하도록 선택하고, 같은 분포에서.

### 참고
- 훈련 세트 설정은 별도(후속 영상). dev/test 분포가 과녁을, 훈련 세트 선택이 그 과녁을 얼마나 잘 맞추는지를 좌우.

---

## 요약
- dev와 test는 **같은 분포**에서, 미래에 마주칠 중요한 데이터를 반영해 선택.
- 다른 분포로 나누면 과녁을 옮기는 격 → 몇 달 낭비 가능.
