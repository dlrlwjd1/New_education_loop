# Creating a Memo

## 개요
- **메모(memo, memorandum)** 는 내부 소통용 간결·구조화 문서 — 보고서보다 **간결·유연·협업적**.
- 목적: 간결성(brevity)·행동 지향(action-oriented)·협업(collaborative).

## 내용

### 배경
- 데이터 스토리텔링 혁신: Toyota **A3 리포트**, Intel **원페이저**, Amazon·Netflix **내부 메모**(Bezos는 PowerPoint 금지, 회의 시작 6페이지 메모 묵독). "명확한 글쓰기는 명확한 사고".

### 메모 구조
1. **헤더**: To(주요 청중)·From(이름/팀)·Date·Subject(핵심 인사이트 1줄 요약).
2. **주요 결론**: 2~3문장, 왜 중요한지 즉시(예: "지난 분기 이탈률 10%↑, 낮은 초기 참여·가격 민감성 때문").
3. **핵심 발견**: 과한 세부 없이 **불릿 리스트**(예: "참여 중요 — 첫 3개월 주 2시간 미만 시청자는 이탈 3배", "가격 요인 — 이탈자 50%가 가격 언급").
4. **권고**: 구체적 next step 옵션(예: 개인화 온보딩·A/B 테스트, 가격 티어 재검토). 결정은 안 하되 각 옵션이 왜 타당한지.
5. **행동 촉구(call to action)**: 피드백 초대(예: "금요일까지 의견 공유").

### 활용
- 보고서처럼 LLM·동료 피드백. 덜 형식적이라 **초안을 일찍·덜 다듬어** 보내도 됨.
- **덜 형식적·더 인터랙티브** 할 때 메모 선택.

## 요약
- **메모**는 간결·행동 지향·협업적 내부 소통 문서로, **헤더 → 주요 결론 → 핵심 발견(불릿) → 권고 → 행동 촉구** 구조다.
- 보고서보다 덜 형식적이라 초안을 일찍 공유하고 피드백을 받는다.
- 다음 강의는 기술적 청중용 **노트북**이다.
