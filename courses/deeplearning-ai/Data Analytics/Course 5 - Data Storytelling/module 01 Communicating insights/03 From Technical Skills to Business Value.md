# From Technical Skills to Business Value

## 개요
- 기술 역량을 **비즈니스 임팩트**로 바꾸려면 "무엇이 일어났나"를 넘어 "왜, 그래서 무엇을 할까"의 **스토리**가 필요하다.
- 데이터 스토리텔링은 라이프사이클 **첫 단계(문제 정의)** 에서 시작되며, **청중별로 맞춤**해야 한다.

## 내용

### 스토리는 문제 정의에서 시작
- 예: "참여도 5% 증가"(사실)는 부족. 매니저가 원하는 건 **왜 증가했나, 얼마나 이례적인가, 유지하려면?** = 스토리.
- 문제 정의 단계부터 "무엇이·왜"의 내러티브 개발.

### 청중별 맞춤
- **경영진(executives)**: 매출·전략·성장 영향, 큰 그림, 시간 부족 → 짧은 슬라이드.
- **제품 매니저(product managers)**: 사용자 행동·기능 개선 → 세분화·사용자 페르소나.
- **데이터팀**: 어떤 분석을 왜 택했나 → 접근법 피드백·상세 인사이트.
- 같은 "활성 사용자 5% 증가"도 청중별 다른 스토리(경영진엔 추세·원인·이익, PM엔 세분화, 데이터팀엔 접근 피드백).

### 형식 선택
- 청중에 따라 형식 결정 — 데이터 표엔 핵심이 묻힐 수 있음. 인사이트는 명확·실행 가능해야.
- 예 경영진: 핵심 지표(5% 증가) + 원인(basic 티어 가격 인하) + 시점 표시 라인 차트 + 매출 영향 시각화의 짧은 슬라이드.

## 요약
- 기술을 **비즈니스 가치**로 바꾸려면 "왜·그래서 무엇"의 **스토리**가 필요하며, 문제 정의 단계부터 시작한다.
- **청중(경영진·PM·데이터팀)** 의 관심·의사결정에 맞춰 내용·형식을 맞춘다.
- 목표는 데이터와 실행에 대한 **공통 이해** 형성이다. 다음 강의는 데이터 스토리텔링 자체다.
