# Selecting Insights for a Dashboard

## 개요
- 대시보드 설계는 **청중**에서 시작한다 — 청중이 큐레이션 수준·데이터 양·해석 복잡성을 결정.
- 대시보드는 명확한 **목적(질문)** 을 가진 데이터 스토리이자 **의사결정 지원 도구**다.

## 내용

### 청중별 요구
- **기술 사용자**: 복잡한 시각화·필터, 드릴다운.
- **경영진**: 고수준 지표·큐레이션된 스토리(핵심 KPI).
- **동료 애널리스트**: 상세 운영 지표.
- **자신**: 기능 우선(미학 덜 중요).

### 청중 평가
1. **데이터 리터러시**(통계 검정·다차원 차트 익숙?).
2. **필요한 결정**.
3. **시간 제약**(30초 vs 30분, 첫 사용 시 안내 가능?).

### 목적 중심 선택
- 명확한 목적 없으면 어수선. 문제·청중에 맞는 큐레이션 선택(병원 개선=큐레이션 스토리, 콘텐츠 투자=탐색 샌드박스).
- 각 요소 평가: "이 차트가 행동을 유도하나? 문제를 다루나? 필수인가 있으면 좋은 것인가?" → **차트 추가 유혹 억제**.
- 각 시각화가 답하는 질문을 적어 목적과 정렬 확인. **less is more**.
- **정보 계층**: 핵심 지표를 가장 두드러지게, 보조 정보는 덜 강조·검색 시 제공.

## 요약
- 대시보드는 **청중**(리터러시·결정·시간)에 맞춰 큐레이션·복잡성을 정하는 **의사결정 지원 도구**다.
- **명확한 목적**에 따라 인사이트를 선택하고, 각 요소가 행동을 유도하는지 평가해 **less is more** 를 지킨다.
- **정보 계층**으로 핵심을 강조한다. 다음 강의는 대시보드 좋은 예·더 나은 예다.
