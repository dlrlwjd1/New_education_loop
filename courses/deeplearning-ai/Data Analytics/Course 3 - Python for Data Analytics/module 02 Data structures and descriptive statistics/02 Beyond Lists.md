# Beyond Lists

## 개요
- **자료 구조(data structure)** 는 데이터를 배열·조직하는 방식. 리스트는 그중 하나일 뿐이다.
- 리스트의 한계(1차원·과도한 유연성·대규모 비효율)를 이해하면 **데이터프레임·시리즈** 같은 다른 구조를 선택할 수 있다.

## 내용

### 리스트의 3가지 한계
1. **1차원(one-dimensional)**: 사실상 한 열만 저장. 점수 리스트만으론 "Melrose Shrimp 점수?"에 답 불가(이름 없음). 이름·점수 두 리스트를 따로 두는 건 조직화가 없어 clunky. 데이터는 대개 **2차원(행·열)**.
2. **과도한 유연성(too flexible)**: 리스트는 여러 타입 혼재 가능(숫자+문자열). `sum`하면 오류 — Python은 int와 string을 더할 수 없음. 분석에선 **각 열이 한 타입**이어야 함.
3. **대규모 비효율**: for 루프는 항목을 **하나씩** 처리(컨베이어 벨트에서 하나씩 도장). 대규모에선 비효율.

### 벡터화 (vectorization)
- 특수 자료 구조(**데이터프레임·시리즈**)는 항목 개별이 아니라 **전체에 한 번에** 연산(넓은 도장으로 5개 동시에).
- 5개 작업이 각 1초면 for 루프 5초 vs 벡터화 1초 — 대규모일수록 큰 차이.
- 이 "전체 동시 연산"이 **벡터화(vectorization)** — 코딩할 필요 없이 자료 구조의 내장 기능.

## 요약
- **자료 구조**는 데이터 조직 방식이며, 리스트는 1차원·과유연·대규모 비효율의 한계가 있다.
- **데이터프레임·시리즈**는 2차원이고 열별 타입을 지키며 **벡터화**로 전체를 한 번에 효율 연산한다.
- 다음 강의는 남이 만든 자료 구조를 쓰기 위한 **모듈 가져오기(importing)** 다.
