# Debugging with Variables

## 개요
- **디버깅(debugging)** = 코드의 오류를 찾아 고치는 것. 변수는 강력하지만 오류(대소문자·순서 등)를 유발할 수 있다.
- 핵심 전략: 코드 변경 테스트, LLM 활용, 커뮤니티 검색.

## 내용

### 변수 이름 규칙
- 문자(대/소문자)·숫자·**밑줄(_)** 사용, **문자로 시작**. 
- **대소문자 구분(case sensitive)**: `income2023` ≠ `Income2023`(컴퓨터에겐 i와 I가 완전히 다른 글자).
- **서술적 이름** 권장: `x`보다 `total_library_visits` — 컴퓨터는 무관하나 사람에게 큰 도움.

### 흔한 오류
- **대소문자 불일치**: `Total_library_visits` 출력 시 오류 → 소문자로 수정.
- **덮어쓰기로 값 손실**: 같은 변수에 2022·2023 값을 순서대로 할당하면 마지막 값만 남음 → 둘 다 필요하면 `_2022`·`_2023`처럼 **별도 변수**.
- **정의 전 사용**: 변수를 정의하기 전에 쓰면 오류 → **정의가 사용보다 먼저** 와야 함(다른 셀이어도 순서 논리적으로).

### 디버깅 3전략
1. **코드 변경 테스트**: Shift+Enter로 무료. 일부러 깨뜨려 보며(따옴표·괄호 누락 시?) 예측 확인.
2. **LLM 활용**: "이 오류가 무슨 뜻?" + 오류 붙여넣기. 인터넷 코드로 학습해 훌륭한 Python 버디.
3. **커뮤니티**: deeplearning.ai 커뮤니티에서 질문 스레드.
- 오류는 코딩의 정상적 부분 — 에세이도 백스페이스 없이 쓰지 않듯, 회복력 있게 대하기.

## 예시

### 변수 디버깅
```python
total_library_visits = 3.8 * 17479
print(Total_library_visits)   # 오류: 대소문자 불일치
# 둘 다 필요하면 별도 변수
visits_2023 = 3.8 * 17479
visits_2022 = 3.3 * 17445
print(total_expenses)  # 오류: 정의 전 사용
```

## 요약
- 변수는 **대소문자 구분**, 문자 시작, 밑줄 허용이며 **서술적 이름**을 권장한다.
- 흔한 오류: 대소문자 불일치, 덮어쓰기 값 손실, **정의 전 사용**(정의를 먼저).
- 디버깅은 **테스트·LLM·커뮤니티**로 하며 오류는 정상이다. 다음 강의는 **리스트(lists)** 다.
