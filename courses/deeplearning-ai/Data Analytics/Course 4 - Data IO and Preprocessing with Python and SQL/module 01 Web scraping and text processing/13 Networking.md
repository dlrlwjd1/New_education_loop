# Networking

## 개요
- **네트워킹(networking)** 은 **클라이언트(내 컴퓨터)** 와 **서버**의 대화 — 요청·응답(**request-response cycle**).
- 웹 스크래핑의 핵심 프로토콜은 **HTTP(Hypertext Transfer Protocol)**.

## 내용

### 요청-응답 주기
- 클라이언트가 서버에 요청 → 서버가 응답. 예: `pd.read_html(URL)` 은 요청, 서버가 표를 응답. 브라우저도 동일(MOOC.org 접속 = 요청).

### HTTP 요청
- **프로토콜(protocol)** = 통신 표준 규칙. HTTP는 요청·응답 형식을 정함.
- 요청 두 부분:
  - **동사(verb)**: 동작. 스크래핑은 대개 **GET**(데이터 가져오기). 그 외 POST·PATCH·DELETE.
  - **경로(path)**: 요청 목적지(예: read_html의 URL).

### 네트워킹의 도전
- 지금까진 모든 변수·함수가 통제 하에 있었으나, 웹 스크래핑은 **외부 요인**에 의존(친구에게 자전거 빌리기 비유).
- 문제: 웹사이트 **느림**, 응답 보장 없음(스크래핑 방지 조치), 페이지 없음 등.

### 상태 코드 (status code)
- 3자리 숫자로 요청 결과 표시:
  - **200**: 성공.
  - **4xx**(400·404): **내 쪽 문제**(서버가 경로 인식 못 함 등).
  - **5xx**(500·503): **서버 쪽 문제**(유지보수·다운 등).

## 요약
- **네트워킹**은 클라이언트-서버의 요청-응답 주기이며 **HTTP**가 형식을 정한다.
- HTTP 요청은 **동사(GET 등)** 와 **경로(URL)** 로 이뤄지고, 스크래핑은 외부 요인에 의존한다.
- **상태 코드**: 200(성공)·4xx(내 문제)·5xx(서버 문제). 다음 강의는 더 복잡한 스크래핑이다.
