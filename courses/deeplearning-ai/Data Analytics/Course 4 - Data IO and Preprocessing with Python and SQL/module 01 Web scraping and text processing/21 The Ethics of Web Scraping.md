# The Ethics of Web Scraping

## 개요
- 웹 스크래핑에는 **윤리·법적 고려**가 따른다: 저작권·이용약관, 서버 부담.
- **robots.txt** 파일로 사이트가 허용·금지하는 스크래핑을 확인한다.

## 내용

### 저작권·접근 문제
- 온라인이라고 사용 허가된 건 아님. 재사용 제한(특히 상업적) 있을 수 있음.
- **합법(현지법)** vs **계약·이용약관 위반** 구분. 경쟁사 사이트 전 페이지 스크래핑은 법적 조치 없이도 **차단**될 수 있음. **이용약관·라이선스 확인**. (법률 자문 아님)

### 서버 부담
- 요청마다 서버가 처리(거부해도) → 시간·에너지 소모. 과도한 요청은 서버 과부하·다운 유발.
- 좋은 관행: **페이지를 한 번만 스크래핑**하고 처리는 내 컴퓨터에서. **요청 코드와 처리 코드 분리**(재요청 방지). 데모에서도 페이지당 요청 1회.
- 과도한 요청은 **CAPTCHA·차단** 유발 → 여러 페이지 시 **요청 제한**. Python **time 모듈**: `time.sleep(1)` 로 요청 간 1초 대기.

### robots.txt
- 웹 개발자가 경계를 설정하는 파일. **루트 도메인 + /robots.txt** 로 접근(예: deeplearning.ai/robots.txt).
- deeplearning.ai는 짧음(자유 스크래핑 허용). wikipedia는 길고 복잡 → **LLM으로 요약**("이 robots.txt에서 허용되는 스크래핑을 요약").
  - 예: 위키 — 문서 페이지·API는 허용, admin·토론·특수 페이지 금지, **빠르고 공격적인 크롤링 금지**(차단 경고) → `time.sleep` 필요.

## 요약
- 웹 스크래핑은 **저작권·이용약관**을 확인하고 **서버 부담을 최소화**(페이지 1회 요청, 처리 분리, time.sleep)해야 한다.
- **robots.txt**(루트 도메인/robots.txt)로 허용·금지 규칙을 확인하며 LLM으로 요약할 수 있다.
- 이로써 Module 1(웹 스크래핑·텍스트 처리)을 마친다. 다음 모듈은 **API로 데이터 수집·전처리**다.
