# ETL and ELT

## 개요
- 전처리는 저장 **전** 또는 **후**에 할 수 있다: **ETL(Extract-Transform-Load)** 은 저장 전, **ELT(Extract-Load-Transform)** 는 저장 후.
- ETL은 모두에게 필요한 전처리, ELT는 다운스트림별 요구가 다를 때 쓴다.

## 내용

### ETL (Extract → Transform → Load)
- 저장 **전** 처리. **Extract**=수집, **Transform**=전처리, **Load**=분석 준비 형식(DB·CSV) 저장.
- "모두에게 필요한 전처리" — 예: 데이터팀이 날짜 형식 표준화·고객명 정리·명백한 중복 제거.
- 단계 상세:
  - **추출(extraction)**: CSV·API·웹에서 데이터 가져옴, 원본 무결성 유지(수정·덮어쓰기 방지).
  - **변환(transform)**: 날짜 형식 통일·중복 제거 등.
  - **적재(load)**: 분석 준비 형식(플랫 파일·DB)으로 저장 → Python 노트북에서 바로 분석.

### ELT (Extract → Load → Transform)
- 저장 **후** 처리. 원시 데이터를 먼저 저장하고 나중에(Python 등에서) 변환. 덜 흔함.
- 비정형·빠르게 변하는 데이터(소셜 미디어)나 다운스트림 애널리스트마다 다른 분석을 할 때. 단 사용 전 추가 변환 필요.

### 연속선
- 실무는 ETL~ELT 연속선 — 일부는 적재 전, 일부는 개인이 수행.
- 적재 전 변환은 무결성·일관성 보장하되 후속 분석을 막지 않아야 함(예: 지역별 날짜 표준화는 하되 타임스탬프 밀리초는 만약을 위해 보존).
- 데이터가 ETL/ELT 중 무엇을 거쳤는지 알면 한계 이해·활용에 도움. 데이터 엔지니어와 협업.

## 요약
- **ETL**(저장 전 변환)은 공통 전처리, **ELT**(저장 후 변환)는 요구가 다양할 때 쓴다.
- ETL은 **추출→변환→적재**로 분석 준비 형식을 만들고, ELT는 원시 저장 후 나중에 변환한다.
- 실무는 연속선이며, 어느 과정을 거쳤는지 알면 데이터 한계를 이해할 수 있다. 다음 레슨은 웹 스크래핑 실습이다.
