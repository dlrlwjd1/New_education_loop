# Gathering Stakeholder Requirements

## 개요
- 효과적 인사이트는 이해관계자의 일을 **이해**하는 데서 나온다. **이해관계자 소통**과 **도메인 지식**은 쌍방향 — 나는 비즈니스를, 비즈니스는 내 역량을 배운다.
- 요구사항 수집 구조: **준비 → 경청 → 열린 질문 → 이해 확인·요약**, 그리고 **겸손(humility)**.

## 내용

### 도메인 지식은 현장에서
- (강사 Netflix 경험) 프로덕션 현장 사람들과 만나 그들의 일·도전을 배우며 분석 아이디어가 생겼고, **도메인 지식**을 쌓아 협업을 제안할 자신감을 얻음. 초기 성공이 신뢰를 쌓아 생산적 파트너십으로.
- 조언: 도메인 지식은 **일하는 사람에게서 직접 흡수**. 독서·컨퍼런스는 보조일 뿐, **양질의 시간(관찰·경청·질문)** 을 대체할 수 없다.

### 미팅 구조
- **준비(prepare)**: 그들의 일과 풀려는 문제를 미리 학습 → 정보에 기반한 질문.
- **적극 경청(active listening)**: 목표·페인 포인트에 집중. **말하기보다 듣기**, 좋은 노트(나중에 잊는다).
- **열린 질문(open-ended)**: 예/아니오 대신 상세히 이끌어냄. "개입이 효과적인가?"보다 "이 결과에 기여하는 요인이 뭐라고 보나?".
- **이해 확인·요약**: 대화 끝에 들은 것을 요약해 동일 이해 확인.
- **겸손**: 그들은 전문가라는 전제에서 시작. "내가 구원하러 왔다"는 태도 금물.

### 핵심 질문
- **비즈니스 목표는?**(때로 애매 — 존중하며 도전해 명료화).
- **성공을 어떻게 보나? 지표가 있나?**(없다면 비전을 정의하게 돕고 지표 개발 기회로).
- **가장 큰 도전은?**(반복 작업에 시간 낭비 등 → 그 도전을 **비즈니스 목표와 연결** 가능한지).
- **이 분석으로 어떤 결정을 하나?**(분석 유형·출력 설계 결정).
- **예상 리스크는? 무엇이면 이 분석을 안 쓰겠나?**(잘 안 묻지만 시간을 잘 쓰기 위해 중요).

### 지속적 정렬
- 정렬은 **일회성이 아니라 지속적** 과정. 이해관계자 니즈를 이해하면 작업이 기대에 부합한다.

## 예시

### 미팅 구조
```
준비 → 적극 경청(말하기<듣기) → 열린 질문 → 요약·확인 → 겸손
```

### 핵심 질문
| 질문 | 목적 |
|------|------|
| 비즈니스 목표? | 명료화 |
| 성공·지표? | 지표 정의 |
| 최대 도전? | 목표와 연결 |
| 어떤 결정? | 분석 유형·출력 설계 |
| 리스크? | 시간 낭비 방지 |

## 요약
- 효과적 분석은 이해관계자의 일을 이해하는 데서 나오며, **도메인 지식은 현장에서 직접** 흡수한다(쌍방향).
- 요구사항 수집은 **준비→경청→열린 질문→요약·확인 + 겸손**의 구조로, 목표·성공지표·도전·결정·리스크를 묻는다.
- 정렬은 지속적 과정이다. 다음 강의는 이해관계자 입력을 **종합(synthesizing)** 하는 법이다.
