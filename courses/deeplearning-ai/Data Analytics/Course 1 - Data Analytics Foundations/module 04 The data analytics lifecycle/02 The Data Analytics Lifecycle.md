# The Data Analytics Lifecycle

## 개요
- **데이터 애널리틱스 라이프사이클** 은 서로 다른 프로젝트를 같은 핵심 접근으로 구조화하는 **엔드투엔드·반복적** 프레임워크다.
- **5단계**: ① 문제 정의 → ② 데이터 수집·전처리 → ③ 데이터 분석·인사이트 도출 → ④ 결과 공유 → ⑤ 결과(성과) 평가.
- 프로젝트 성공은 분석 자체만큼 그 **주변 단계**에 달려 있고, 각 단계 소요 시간은 프로젝트마다 다르다(적응 필요). 반복적이다.

## 내용

### 5단계
1. **문제 정의(define the problem)**: 무엇을 풀 것인가. 의사결정 공간을 좁히고 **성공의 정의**를 명확히. 질문: 비즈니스 목표? 어떤 결정이 필요한가? 이해관계자와 그 니즈? 성공이란? (아인슈타인: "1시간이 있다면 55분은 문제를, 5분은 해결책을 생각한다" — 문제 정의에 시간을 들여라.)
2. **수집·전처리(collect & preprocess)**: 원시 데이터를 쓸 수 있는 정보로 변환. 비정형은 노력이 큼, 결측·형식 불량이 분석을 어렵게 하고, 원하는 데이터가 없으면 가진 것으로 타협. **인사이트 품질은 데이터 품질에 직결**.
3. **분석·인사이트 도출(analyze & identify insights)**: 통계·시각화·ML로 패턴을 찾고, 문제 맥락에서 의미(인사이트)를 도출. 인사이트 도출은 **번역**과 비슷 — 데이터 언어를 이해관계자가 쓸 수 있는 이야기로.
4. **결과 공유(share results)**: 분석은 컴퓨터에 갇혀 있으면 무용. **적절한 발견을 적절한 사람에게 적절한 상세 수준으로** 전달해 영향 창출.
5. **성과 평가(evaluate outcomes)**: 결정의 실제 영향 평가(코치의 게임 플랜이 승리로 이어졌나). 질문: 1단계에서 정의한 성공을 달성했나? 이해관계자가 만족하나? 장기 영향은? — 목표는 인사이트가 아니라 **긍정적 변화로 이어지는 행동**.

### 반복성
- 라이프사이클은 **반복적** — 한 결정의 평가에서 얻은 인사이트가 다음 분석에 반영되어 선순환. 노련한 애널리스트도 새 과제엔 이 기본으로 돌아간다.

## 예시

### 5단계
| 단계 | 핵심 질문 |
|------|-----------|
| ① 문제 정의 | 무엇을 풀고 성공이란? |
| ② 수집·전처리 | 데이터는 어디에, 어떻게 준비? |
| ③ 분석·인사이트 | 패턴은? 무엇을 의미하나? |
| ④ 공유 | 누구에게 어떻게 전달? |
| ⑤ 평가 | 문제를 얼마나 잘 풀었나? |

## 요약
- **데이터 애널리틱스 라이프사이클**은 **문제 정의 → 수집·전처리 → 분석·인사이트 → 공유 → 평가**의 5단계 반복 프레임워크다.
- 분석 자체만큼 **주변 단계**가 성공을 좌우하며, 문제 정의에 시간을 들이고(아인슈타인) 데이터 품질이 인사이트 품질을 결정한다.
- 목표는 인사이트가 아니라 **긍정적 변화로 이어지는 행동**이며, 평가 결과가 다음 분석에 반영되는 선순환이다.
- 다음 강의부터 각 단계를 자세히 다룬다(문제 정의부터).
