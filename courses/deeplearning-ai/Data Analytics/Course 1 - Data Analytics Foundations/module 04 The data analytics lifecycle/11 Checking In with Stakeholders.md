# Checking In with Stakeholders

## 개요
- 문제 정의 후 혼자 밀어붙이지 말고 **정기적으로 이해관계자와 점검(check-in)** 해야 한다.
- 이점: **정렬 확인·재작업 방지·신뢰 구축·장애물 극복·지속적 가치 가시화**.
- 점검 빈도·방식은 **프로젝트 복잡도·이해관계자 가용성·소통 선호**에 따라 정한다.

## 내용

### 점검의 이점
- **정렬(alignment)**: 같은 페이지에 있는지 확인, 조기 피드백으로 **재작업 방지**.
- **신뢰 구축**: 정기 소통이 이해관계자 입력을 존중함을 보여줌.
- **장애물 극복**: 이해관계자 입력이 문제를 빠르게 해결(두 뇌가 하나보다 낫다).
- **지속적 가치 가시화**: 끝까지 기다리지 않고 진행을 계속 보여줌.

### 점검 방법
- 각 점검마다 **간결한 진행 요약 + 다루고 싶은 구체적 질문** 준비 → 집중된 논의.
- **방어적이지 않게 적극 경청**으로 피드백 수용, **다음 단계 식별**로 협업 분위기.
- 빈도·방식: **복잡한 프로젝트**는 더 자주, **가용성** 존중(시간 요청 남발 금지), **소통 선호**(공식 미팅 vs 이메일·짧은 통화).

### 예시 — 반려동물 가게 로열티 프로그램 (단계별 점검)
- **문제 정의**: 사장과 초기 미팅(로열티 프로그램 브레인스토밍 + 목표·타깃·예산) → 후속으로 문제 정의 정제(고객 유지·LTV↑).
- **수집·전처리**: 고객서비스팀 점검(정성 피드백·페인 포인트·제안), 사장·마케팅과 가용 데이터 확인.
- **분석·인사이트**: 사장·마케팅과 예비 결과(로열티 프로그램 ROI 등) 공유·문제 해결.
- **결과 공유**: 종합 발표(프로그램 구조·보상·소통 전략) + 피드백.
- **성과 평가**: 사장·마케팅과 구현 계획·리스크 논의, 출시 후 전 이해관계자와 성과 모니터·개선.
- → 이해관계자가 **든든한 파트너**가 있다고 느낌.

## 예시

### 점검 빈도·방식 결정
| 요인 | 고려 |
|------|------|
| 프로젝트 복잡도 | 복잡할수록 자주 |
| 가용성 | 시간 존중 |
| 소통 선호 | 미팅 vs 이메일/통화 |

## 요약
- 분석 내내 **정기 점검**으로 정렬·신뢰·재작업 방지·장애물 극복·가치 가시화를 얻는다.
- 각 점검은 **진행 요약 + 구체 질문** 준비, 방어 없는 경청, 다음 단계 식별로 진행하고, 빈도·방식은 복잡도·가용성·선호로 정한다.
- 라이프사이클 각 단계에서 적절한 이해관계자와 점검하면 인사이트가 실행 가능해진다. 다음 강의는 **도메인 지식**이다.
