# Demo: LLMs for Stakeholder Analysis

## 개요
- LLM은 **문제 정의**와 **이해관계자 협업**에서 훌륭한 사고 파트너다. 하이킹/바이킹 앱 회사 예시로 두 활용을 보여준다.
- ① 상충하는 이해관계자 이메일 **종합·공통점 도출·의사결정 우선순위**, ② 회의록으로 **럼스펠드 매트릭스** 생성 후 **분석 우선순위** 제안.

## 내용

### ① 이해관계자 입력 종합
- 상황: 엔지니어링 리드 vs 영업 부사장(Sanjana)이 앱 방향에 대한 이메일. 목표는 입력을 종합해 분석이 비즈니스 임팩트에 기여할 접근 제안.
- ChatGPT에 **회사 맥락 + 이해관계자 설명 + 두 이메일 텍스트** 제공, 각자의 관점 요약·공통점 강조 요청.
  - 엔지니어링 리드: **사용자 경험 향상**(리더보드·위치 기반 추천·웨어러블 연동) → **기존 사용자 유지(retention)** 초점.
  - 영업 부사장: **시장 확장**(아웃도어 소매 제휴·기업 웰니스) → **신규 확보(acquisition)** 초점.
  - **공통점**: 둘 다 데이터 기반 인사이트·사용자 참여를 원함.
- 후속 질문: "이해관계자 목표 기반으로 내려야 할 비즈니스 결정 목록을, 둘이 동의할 만한 것 우선으로." → 데이터 기반 제품 개선(둘 다 동의) → 참여·시장 확장·기술 통합·모니터링 순. **상위 2개 우선순위 제안서를 쓰고 이해관계자 피드백**을 받는 전략.

### ② 럼스펠드 매트릭스 + 분석 우선순위
- 사용자 경험 향상을 핵심 문제로 결정. 리더십 회의록을 업로드해 LLM에 **럼스펠드 매트릭스** 생성 요청 → 회의록 문장을 4분면으로 분류.
- **known unknowns**(분석 잠재력 큼): 획득 채널이 유지에 미치는 영향, 초기 다운로드 이후 사용자 동기, 시장 트렌드·경쟁 인사이트 → 실행 가능한 분석들.
- 마지막 후속: "내가 가진 데이터로 가능한 분석을 제안해줘" → 3가지 분석 제안(획득 채널별 유지·참여 영향 등), 각 **목적·관심 이해관계자·권장 접근**(사용자 세그멘테이션·지표 비교 등, 코스에서 배운 것)·UX 개선 연결까지.

### 결론
- LLM으로 방대한 읽기·쓰기를 줄이고 작업에 대한 **제2의 의견**을 얻는다. 데이터 애널리틱스에서 이를 활용해 삶을 편하게 만들라.

## 예시

### LLM 이해관계자 분석 흐름
```
1) 회사 맥락 + 이해관계자 + 이메일 → 관점 요약·공통점
2) 동의 가능한 것 우선으로 의사결정 목록
3) 회의록 → 럼스펠드 매트릭스(known unknowns 집중)
4) 보유 데이터로 가능한 분석 제안(목적·이해관계자·접근)
```

## 요약
- LLM은 **문제 정의·이해관계자 협업**의 사고 파트너로, 상충 이메일을 종합해 관점·공통점·의사결정 우선순위를 도출한다.
- 회의록으로 **럼스펠드 매트릭스**를 만들어 **known unknowns**를 분석 기회로 식별하고, 보유 데이터에 맞는 분석을 제안받는다.
- 방대한 읽기·쓰기를 줄이고 **제2의 의견**을 얻는 것이 핵심. 이로써 모듈 4가 마무리되며, 다음은 캡스톤·마무리 강의다.
