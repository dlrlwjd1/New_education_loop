# Sharing Results

## 개요
- 인사이트는 공유해야 영향을 낸다. 공유 방식 선택 시 **① 인사이트를 요약할 최선의 접근**과 **② 이해관계자 니즈** 두 가지를 고려한다.
- 형식: **리포트·대시보드·프레젠테이션·ML 모델 배포**(+스크롤 리텔링 등). 그리고 **명확성·관련성·실행 가능성** 원칙을 지킨다.

## 내용

### 두 고려 요인
- **인사이트에 맞는 접근**: 복잡한 데이터=시각화, 여러 인사이트=요약, 숫자=의미로 맥락화, 새 데이터=과거와 대비.
- **이해관계자 니즈**: 기술 수준(전문가는 디테일, 비전문가는 전문용어 줄인 설명), 시간 제약·선호 방식, 의사결정 통제권.

### 공유 형식
- **리포트(report)** (과소평가됨): 시각화 포함 서면 요약. **철저한 설명·방법론 문서화·기술 청중**에 유용. 빠른 소통·비전문가엔 부적합.
- **대시보드(dashboard)**: 인터랙티브 시각화. 스스로 탐색·최신 정보 접근·성과 추적에 유용. 상세 설명·방법론엔 부적합.
- **프레젠테이션(presentation)**: 라이브 발표(스토리텔링 기회). 설득·토론·대규모 청중에 유용. 나중에 재열람하거나 청중별 깊이가 다를 땐 부적합.
- **ML 모델 배포**: 결정 자동화. 들어오는 데이터로 잦은 결정에 유용. 근거 설명·인터랙티브 탐색·비전문가 소통엔 부적합.
- 그 외 **스크롤 리텔링(scrollytelling)**(리포트의 인터랙티브 버전, 예: Pudding.cool) 등.

### 세 원칙
- **명확성(clarity)**: 이해하기 쉽게. 전문용어 피하고 시각 활용, 청중이 아는 것/모르는 것 인지.
- **관련성(relevance)**: 이해관계자 목표에 가장 관련된 인사이트에 집중. 아는 걸 다 말하려는 충동을 참고 **필요한 것**을 이해시킴.
- **실행 가능성(actionability)**: 내려야 할 **결정**에 집중, 가능하면 근거 기반 권고 제공.

### 핵심
- 분석을 "울타리 너머로 던지고" 떠나지 말고, 인사이트에 대한 **가장 효과적인 이야기**를 만들어 최종 결정이 당신의 작업에 근거하도록 하라.

## 예시

### 공유 형식 선택
| 형식 | 유용 | 부적합 |
|------|------|--------|
| 리포트 | 철저 설명·방법론·기술 청중 | 빠른 소통·비전문가 |
| 대시보드 | 자율 탐색·최신 추적 | 상세 설명 |
| 프레젠테이션 | 설득·토론·대규모 | 재열람·깊이 차이 |
| ML 모델 | 잦은 자동 결정 | 근거 설명·비전문가 |

## 요약
- 결과 공유는 **인사이트 요약 방식 + 이해관계자 니즈**를 고려해 형식(리포트·대시보드·프레젠테이션·ML 모델 등)을 선택한다.
- 각 형식은 장단이 뚜렷하며, 공통 원칙은 **명확성·관련성·실행 가능성**이다.
- 분석을 던져두지 말고 **효과적 이야기**로 만들어 결정에 반영되게 한다. 다음 강의는 **성과 평가**다.
