# Collecting & Preprocessing Data

## 개요
- **데이터 수집(collection)** 은 문제 해결에 도움 될 정보원을 찾는 것(DB 쿼리·설문·웹 스크래핑), **전처리(preprocessing)** 는 원시 데이터를 분석 가능한 형태로 변환하는 것.
- 인사이트 품질은 데이터 품질에 직결되므로 이 단계가 **기초(foundational)** 다.

## 내용

### 데이터 수집
- **문제 정의 재검토** → **1차 관심 결과**(매출·리뷰·비용) 식별 → 그 결과에 **맥락을 주는 데이터** 브레인스토밍(예: 고객 유지 → 해지율 + 인구통계·구매 이력·참여 지표).
- 필요한 데이터를 정했으면 **잠재적 출처**(내부 DB·공개 데이터셋·직접 설문/실험) 브레인스토밍.
- 출처 평가: **접근성**(권한 있나?)·**품질**(정확·최신?). 모두 못 모을 수 있으니 **가치 높은 출처 우선**, 예산·일정 내 유지. 확신 없으면 **도메인 전문가**에게 유사 질문에 쓰이는 데이터 유형을 문의.

### 전처리 (흔한 단계)
1. **형식 정리(formatting)**: 일관된 형식으로.
2. **정제(cleaning)**: 오류·중복·이상치 제거.
3. **결측값 처리(handling missing values)**: 채우거나 불완전 데이터 제거.
4. **변환(transformation)**: 데이터 타입 변환·집계·새 특성 생성.

### 실전 예 — 매니저 급여 설문(askamanager.org 2019)
- Google Form 자기보고. 나이·경력은 선택지지만 직함·산업·급여·위치는 **자유 텍스트** → 열 안에서 **불일치**: 급여에 통화 기호 위치가 제각각($ 앞/뒤/없음), 위치 표기가 도시/주/국가~지역까지 다양.
- **비정상 행**: 급여 $3·경력 1년 이하, "연 1+" 등 → 정당하지 않은 제출.
- 위치별 분석하려면 급여·위치 표준화 + 비정상 행 제거 작업이 큼. 이상적으로는 **미리 폼에 제약**을 설계(이후 버전은 미국 주 선택·통화 옵션 추가).
- 전처리는 지저분→깔끔의 극적 변화라 만족스럽다(파워워싱 영상이 인기인 이유처럼).

## 예시

### 전처리 4단계
| 단계 | 내용 |
|------|------|
| 형식 정리 | 일관된 형식 |
| 정제 | 오류·중복·이상치 제거 |
| 결측값 처리 | 채우기/제거 |
| 변환 | 타입·집계·새 특성 |

## 요약
- **수집**은 문제에 맞는 정보원을 찾는 것(접근성·품질로 우선순위, 도메인 전문가 활용), **전처리**는 원시 데이터를 분석 가능하게 만드는 것.
- 전처리 흔한 단계는 **형식 정리·정제·결측값 처리·변환**이며, 급여 설문 예처럼 자유 텍스트는 불일치·비정상 행이 많다.
- 이상적으로는 수집 단계(폼 설계)에서 문제를 미리 방지한다. 다음 강의는 **데이터 분석**이다.
