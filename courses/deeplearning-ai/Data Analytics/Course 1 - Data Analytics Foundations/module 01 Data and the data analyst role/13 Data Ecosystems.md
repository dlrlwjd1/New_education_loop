# Data Ecosystems

## 개요
- 데이터는 전기처럼 생성된 곳에 머물지 않고 여러 시스템을 거쳐 인사이트로 이어진다 — 이 흐름을 **데이터 생태계(data ecosystem)** 라 한다.
- 흐름 단계: **수집(collection) → 저장(storage) → 처리(processing) → 분석(analysis) → 전달(delivery)**.
- 데이터 애널리스트(당신)는 이 단계를 소유하며, **상류의 데이터 엔지니어**와 **하류의 비즈니스 이해관계자**에게 가장 책임이 있다.

## 내용

### 데이터 생태계 단계
- **수집(collection)**: 데이터를 포착(센서, 웹 상호작용 추적, 설문 등).
- **저장(storage)**: 안전하게 보관. 저장 방식이 분석 난이도를 좌우하며 보통 **데이터 엔지니어**가 담당.
- **처리(processing)**: 수집된 원형은 저장·분석에 이상적이지 않을 수 있어, **수집↔저장** 사이와 **저장↔분석** 사이에서 처리가 일어난다.
- **분석(analysis)**: 데이터를 조사해 의사결정에 도움 될 인사이트를 찾음.
- **전달(delivery)**: 결과를 효과적으로 소통(리포트·대시보드 등).
- 핵심 데이터 팀(애널리스트 포함)이 이 단계를 소유하고, 데이터를 생성하는 사용자와 PM·엔지니어 등 이해관계자가 그 결과에 의존한다. **상류(데이터 엔지니어)·하류(비즈니스 이해관계자)** 에 가장 책임이 있다.

### 예시 — 병원
- 각 환자가 많은 건강 데이터를 생성: 간호사가 체온(디지털 체온계)·호흡(청진기) 측정, 혈액/소변 검사(실험실 처리), 영상(X-ray·초음파·MRI, 전문가 해석) → **전자의무기록(EMR)** 에 신원·수집 시점·수집자와 함께 저장.
- **저장·처리는 데이터 유형에 따라 다름**: 정형(인구통계·바이탈)은 전통 DB에 쉽게, 비정형(손글씨 노트)은 AI 필기 인식·수기 입력 등 추가 처리 후 저장.
- 의사가 EMR 데이터 + 전문성으로 진단(진단 자체도 EMR에 기록되는 데이터).
- **애널리스트의 역할**: 개별 환자를 진단하는 게 아니라, 수천 건의 유사 환자 기록에서 **패턴**을 분석해 의사의 더 나은 결정을 돕는 인사이트(더 나은 치료 프로토콜, 간과된 위험 요인 등)를 드러낸다.

## 예시

### 데이터 생태계 흐름
| 단계 | 내용 | 담당 |
|------|------|------|
| 수집 | 데이터 포착 | 사용자·시스템 |
| 저장 | 안전 보관 | 데이터 엔지니어 |
| 처리 | 형식 변환 | (수집↔저장, 저장↔분석 사이) |
| 분석 | 인사이트 도출 | 데이터 애널리스트 |
| 전달 | 결과 소통 | 데이터 애널리스트 |

## 요약
- **데이터 생태계**는 데이터가 생성부터 의사결정까지 거치는 **수집→저장→처리→분석→전달** 의 흐름이다.
- 저장은 데이터 엔지니어가, 분석·전달은 애널리스트가 소유하며, 애널리스트는 **상류(엔지니어)·하류(이해관계자)** 에 가장 책임이 있다.
- 병원 예시처럼 데이터는 유형에 따라 다르게 저장·처리되고, 애널리스트는 개별이 아니라 **패턴 분석**으로 가치를 낸다.
- 다음 두 강의에서 핵심 협업자(이해관계자, 데이터 엔지니어)를 만난다.
