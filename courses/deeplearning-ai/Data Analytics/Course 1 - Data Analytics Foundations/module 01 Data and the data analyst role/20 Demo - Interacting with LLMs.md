# Demo: Interacting with LLMs

## 개요
- LLM과 실제로 상호작용하는 데모. 앞서 배운 **한계**(수학 오류, 검증 불가한 사실)와 **강점**(검증 가능한 개념 설명, 브레인스토밍)을 직접 확인한다.
- 핵심 습관: 대화를 **진짜 주고받기(back and forth)** 로 만들고 후속 질문을 하며, **회의적 마인드셋**을 유지한다.

## 내용

### 수학은 부정확 — 다른 도구 사용
- "1~888의 합?" → LLM이 공식(n/2 × (첫항+끝항))은 주지만 계산 결과가 **틀림**(LLM 394,116 vs 실제 394,716). **수학엔 계산기·스프레드시트·프로그래밍**을 쓰는 게 낫다.

### 시사·행동 한계
- "지금 핫도그(7-Eleven 배달) 원해" → Claude는 지역에 따라 다르다고 안내, **Gemini는 웹 검색**으로 더 구체적 답(계정 위치 감지 — 팔로알토는 배달 가능). 단, **주문 대신 실행은 불가** — 오늘날 LLM이 못 하는 일도 있다.

### 검증 불가한 사실 — 권위 있는 출처로
- "백색왜성·쌍성계 사실?" → 정보를 주지만 **참인지 알 수 없어** 이 주제는 LLM에 묻지 않고 검색엔진·교과서 같은 **권위 있는 출처**를 쓰는 게 낫다.

### 검증 가능한 개념 — 학습에 활용
- "연속형 vs 이산형 수치 특성 차이?" → 이미 배운 내용이라 **정답 검증 가능**하고, 예시(연속: 나이·키·몸무게 / 이산: 자녀 수)도 유용. 인터넷에 흔한 주제라 사실 확인 부담이 적다.

### 복잡한 브레인스토밍 — 후속 질문으로 심화
- "이색 반려동물 가게 매출 증대 3옵션 결정 프로세스 브레인스토밍" → 각 옵션의 장단점을 나열(일부 중복·모호). "다른 가게를 방문하라"처럼 모호하면, **후속 질문**("다른 이색 반려동물 가게를 어떻게 평가할까?")으로 위치·상품군·가격 등 구체적 기준을 끌어낸다.

### 요약 습관
- 채팅을 **진짜 주고받기**로 만들고 질문·후속 질문을 하며, **회의적 마인드셋**을 유지 — LLM의 말을 진실로 받아들이지 말 것.

## 예시

### 작업별 LLM 적합성
| 작업 | LLM 적합성 | 대안/조치 |
|------|-----------|-----------|
| 수학 계산 | 부적합(틀림) | 계산기·스프레드시트 |
| 검증 불가 전문 사실 | 부적합 | 검색엔진·교과서 |
| 시사 | 웹 검색 모델이 유리 | Gemini 등 |
| 검증 가능한 개념 | 적합 | 알고 있으면 검증 |
| 브레인스토밍 | 적합 | 후속 질문으로 심화 |

## 요약
- 데모는 LLM이 **수학·검증 불가 사실에 부적합**하고, **검증 가능한 개념 설명·브레인스토밍**에 유용함을 보여준다.
- 시사는 **웹 검색 모델**(Gemini 등)이 유리하나, LLM이 대신 주문을 실행하는 등의 **행동 한계**도 있다.
- 핵심은 대화를 **주고받기 + 후속 질문**으로 만들고 **회의적 마인드셋**을 유지하는 것.
- 이로써 모듈 1이 마무리되고, 다음 모듈은 **스프레드시트로 데이터 다루기**다.
