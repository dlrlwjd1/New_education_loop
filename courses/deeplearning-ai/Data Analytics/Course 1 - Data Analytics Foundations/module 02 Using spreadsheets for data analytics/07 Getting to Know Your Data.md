# Getting to Know Your Data

## 개요
- 의미 있는 분석 전에 데이터를 **알아가야** 한다 — 새 사람을 만나는 것처럼 데이터셋도 역사와 성격이 있다.
- **메타데이터(metadata, 데이터에 대한 데이터)** 를 통해 파일명·작성자·설명·형식·생성일·접근 권한 등을 파악한다.
- 데이터의 **출처(source)·수집 방식·품질**을 이해하면 잠재적 문제를 예측할 수 있다.

## 내용

### 메타데이터(metadata)
- 이미 배운 것(정형/비정형 여부, 관측치·특성 수, 수치형/범주형 구분)도 메타데이터. 흔히 마주치는 메타데이터:
  - **파일명**: 검색·발견 방법.
  - **원저자**: 후속 질문 대상.
  - **설명**: 데이터 내용의 맥락.
  - **파일 형식**(CSV·TXT·JSON 등): 상호작용 방법.
  - **생성/최종 수정일**: 데이터의 최신성.
  - **접근 권한**: 누가 어떻게 접근·조작하는가.

### 출처(source) — 데이터의 기원 이야기
- 어떻게 수집·생성됐는가? **사람** 생성인가 **소프트웨어** 생성인가.
  - 설문이면 **미응답** 가능성 고려. 소프트웨어면 **체계적 오류(systematic errors)** 를 살핌.
- **품질**: 정확한가, 결함이 있는가(대개 후자). 출처를 알면 발생 가능한 문제를 파악하기 쉽다.

### 예시 — 호텔 예약 데이터 기원
- **나이(최신성)**: 2019년 2월 발표 → 그 이후 예약은 기대하지 말 것.
- **출처**: 두 호텔 모두 포르투갈 — H1은 리조트 지역 Algarve, H2는 수도 Lisbon(서로 멀어 특성이 다를 수 있음).
- **수집 방식**: 호텔 **자산 관리 시스템(property management system) DB에서 직접 쿼리** 추출 → **신뢰성 높음**(자동 생성, 인적 오류 최소), 호텔 소유 데이터, 자동 추출이라 **대규모**(2년간 36,000건 = 하루 50건 이상).

## 예시

### 흔한 메타데이터
| 메타데이터 | 알려주는 것 |
|-----------|-------------|
| 파일명 | 검색·발견 |
| 원저자 | 후속 질문 |
| 설명 | 내용 맥락 |
| 파일 형식 | 상호작용 방법 |
| 생성/수정일 | 최신성 |
| 접근 권한 | 누가·어떻게 |

## 요약
- 분석 전 **데이터 알아가기**가 필수이며, **메타데이터**(파일명·작성자·설명·형식·날짜·권한)로 데이터를 파악한다.
- 데이터의 **출처·수집 방식(사람 vs 소프트웨어)·품질**을 이해하면 미응답·체계적 오류 등 문제를 예측할 수 있다.
- 호텔 데이터는 관리 시스템에서 자동 추출되어 신뢰성 높고 대규모다. 다음 강의에서 **요약 통계(summary statistics)** 를 다룬다.
