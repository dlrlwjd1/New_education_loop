# Data Encoding

## 개요
- 명확성·효율성·맥락을 실제 차트로 구현하는 **디자인 위계**: **① 축(스케일·라벨)을 완벽히 → ② 색을 신중히 → ③ 그 밖의 것은 아주 신중히** 추가.
- **데이터 인코딩(data encoding)**(색·크기·모양·위치로 데이터를 직접 표현) vs **차트 요소(chart elements)**(라벨·격자선·축·주석·제목)를 구분한다.

## 내용

### 축(axes)
- x·y축을 읽기 쉽고 라벨링되고 직관적으로. 수치형은 **0 포함** 고려, **스케일을 적절히**(과장·압축하면 메시지 왜곡). 라벨은 명확·간결(격자선으로 정확한 값을 읽기 어려울 때 특히 유용).

### 색(color)
- 명확성·맥락을 위한 가장 강력한 도구 — 핵심 강조(경쟁사 대비 자사 성과), 맥락 제공(과거 데이터 회색 처리로 현재 강조).
- **색맹 고려**: 전 세계 약 4.5%가 색맹(주로 적록). 가능하면 색 + 다른 요소(고유 마커)의 **이중 인코딩(double encoding)**.

### 차원 수 관리
- 일반적으로 **2차원(x, y)** 유지가 해석에 좋다. 3+차원이 꼭 필요하면 **여러 플롯을 나란히**.
- 예: 온도·관찰된 새 수·종(로빈/블루제이) 3차원. 한 차트에 색으로 종을 넣으면 관측이 많아 구분이 어려움 → **종별 산점도 2개로 분리**하면 각 패턴이 명확해지고 비교도 가능.

### 신중히 쓸 요소
- **마커(markers)**: 산점도에서 3번째 차원. 색 대신 마커로 종 구분 시 작아서 구분이 어려움 → 대개 색이 낫고, **2종 이상**이면 접근을 재고(색 또는 분리).
- **크기(size, 버블 차트)**: 3번째 차원. 인구·금액처럼 **크기 유추가 자연스러울 때** 유용. 예: x=부(富), y=기대수명, 버블=인구, 색=지역(4번째 차원) — 정보가 많으니 과하지 않게.
- 원칙: **효율성** — 시각 요소를 남발하지 말고, 각 추가는 이해에 명확히 기여해야 한다.

## 예시

### 데이터 인코딩 vs 차트 요소
| 구분 | 예 |
|------|-----|
| 데이터 인코딩 | 색·크기·모양·위치(데이터 직접 표현) |
| 차트 요소 | 라벨·격자선·축·주석·제목 |

### 디자인 위계
```
① 축(스케일·라벨) 완벽히
② 색 신중히(강조·맥락, 색맹 고려)
③ 마커·크기 등은 아주 신중히
```

## 요약
- 시각화는 **축 → 색 → 그 외** 순으로 신중히 만든다. **데이터 인코딩**(색·크기·모양·위치)이 백본, **차트 요소**(라벨·축·주석)는 명확성·맥락 보조다.
- 색은 강력하나 **색맹을 위해 이중 인코딩**을 쓰고, 대개 **2차원 유지**하며 3+차원은 여러 플롯으로 분리한다.
- 마커·버블 크기는 자연스러운 경우에만, **효율성**을 지켜 과하지 않게 쓴다. 다음 강의는 **차트 요소**다.
