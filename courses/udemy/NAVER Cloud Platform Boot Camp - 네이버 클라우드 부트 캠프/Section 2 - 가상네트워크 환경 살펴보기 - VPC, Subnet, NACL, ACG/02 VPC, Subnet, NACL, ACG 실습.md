# VPC, Subnet, NACL, ACG 실습

## 개요

- NAVER Cloud Platform 콘솔에서 VPC와 서브넷을 생성한다.
- NACL 인바운드·아웃바운드 규칙과 라우팅 테이블을 확인한다.
- 퍼블릭·프라이빗·로드밸런서용 주소 범위를 구분해 네트워크를 구성한다.

## 내용

### 콘솔과 플랫폼 선택

콘솔의 Services 메뉴에서 필요한 서비스를 선택하고, 작업할 리전과 플랫폼을 정한다. 강의는 이전 방식인 Classic보다 독립적인 네트워크 도메인을 제공하는 VPC 환경을 기준으로 진행한다.

### VPC 생성

VPC 메뉴에서 이름과 사설 IP 주소 범위를 입력해 VPC를 만든다. VPC를 생성해도 서브넷은 자동 생성되지 않으므로 별도로 구성해야 한다.

VPC를 만들면 기본 NACL이 함께 생성되지만 인바운드·아웃바운드 접근 규칙은 직접 설정해야 한다.

### NACL 규칙 설정

강의 실습에서는 외부에서 사용할 서비스를 고려해 인바운드에 다음 포트를 허용한다.

- SSH: TCP 22
- HTTP: TCP 80
- HTTPS: TCP 443

아웃바운드는 서버가 외부로 통신할 수 있도록 필요한 프로토콜과 포트 범위를 허용한다. 실제 운영 환경에서는 모든 출발지를 무조건 허용하기보다 관리 IP와 서비스 요구사항에 맞춰 범위를 좁혀야 한다.

### 서브넷 생성

Subnet Management에서 VPC, IP 주소 범위, 가용 존(zone), NACL, 인터넷 게이트웨이 사용 여부와 용도를 선택한다.

강의는 주소만 보고도 역할을 알 수 있도록 범위를 구분한다.

```text
VPC
├─ Public Subnet: 외부 공개 서버
├─ Private Subnet: 내부 서버
└─ Load Balancer Subnet: 로드밸런서 전용
```

서브넷 이름과 주소의 숫자를 대응시키면 운영 중 어느 서브넷인지 빠르게 식별할 수 있다.

### 라우팅 테이블 확인

퍼블릭 서브넷의 라우팅 테이블에는 인터넷 게이트웨이로 향하는 기본 경로가 추가된다. 프라이빗 서브넷은 로컬 경로만 가지므로 외부 통신을 위해 NAT Gateway 등의 라우팅 대상을 추가해야 한다.

Virtual Private Gateway는 NAVER Cloud와 사내 네트워크·데이터센터를 전용회선 또는 IPsec VPN으로 연결할 때 사용한다.

## 예시

```text
1. VPC 이름과 사설 IP 범위 입력
2. 기본 NACL의 인바운드·아웃바운드 규칙 설정
3. Public Subnet 생성
4. Private Subnet 생성
5. Load Balancer용 Subnet 생성
6. 각 서브넷의 라우팅 테이블 확인
```

## 요약

- VPC와 서브넷은 각각 따로 생성한다.
- 기본 NACL은 생성되지만 접근 규칙은 직접 정의한다.
- 서브넷마다 가용 존, NACL, 인터넷 연결 여부와 용도를 선택한다.
- 퍼블릭 서브넷에는 인터넷 게이트웨이 경로가 있고 프라이빗 서브넷에는 기본적으로 로컬 경로만 있다.
- 일관된 이름과 주소 계획은 네트워크 운영의 가독성을 높인다.
