# VPC, Subnet, NACL, ACG

## 개요

- VPC와 서브넷(subnet)으로 격리된 가상 네트워크를 설계한다.
- 퍼블릭·프라이빗 서브넷의 통신 방식과 용도를 구분한다.
- NACL과 ACG의 적용 범위 및 상태 저장 여부를 비교한다.

## 내용

### VPC

VPC(Virtual Private Cloud)는 다른 사용자의 네트워크와 논리적으로 격리된 전용 네트워크 공간이다. 가상의 데이터센터 또는 네트워크 센터처럼 이해할 수 있으며, 서브넷·게이트웨이·라우팅 테이블을 이용해 내부 트래픽 흐름을 제어한다.

강의 시점에는 계정당 VPC를 최대 3개까지 만들 수 있다고 설명한다.

### 서브넷

서브넷은 하나의 IP 주소 범위를 더 작은 네트워크로 나눈 것이다. 시스템의 용도나 보안 수준에 따라 장비를 그룹화해 관리성을 높인다.

- 퍼블릭 서브넷: 공인 IP와 인터넷 게이트웨이를 통해 외부와 직접 통신
- 프라이빗 서브넷: 사설 IP만 사용하며 외부와 직접 통신하지 않음

프라이빗 서브넷의 서버가 인터넷에 접근하려면 NAT Gateway와 같은 별도 경로가 필요하다. 사내 데이터센터·사무실과 연결할 때는 Virtual Private Gateway와 전용회선 또는 IPsec VPN을 사용할 수 있다.

### 주소 계획

서브넷을 만들기 전 필요한 장비 수와 IP 범위를 파악하고, 호스트 수에 맞는 서브넷 마스크를 선택한다. 건물·층·업무·환경 등 의미 있는 기준을 주소 체계에 반영하면 운영 중 네트워크를 식별하기 쉽다.

### NACL과 ACG 비교

| 항목 | NACL(Network ACL) | ACG(Access Control Group) |
|---|---|---|
| 적용 대상 | 서브넷 | 서버의 네트워크 인터페이스 |
| 규칙 | 허용·거부 | 허용 |
| 상태 | 상태 비저장(stateless) | 상태 저장(stateful) |
| 응답 트래픽 | 명시적 규칙 필요 | 연결 상태에 따라 자동 허용 |

NACL은 네트워크 경계에서 서브넷 전체를 제어하고, ACG는 개별 서버 단위의 접근을 제어한다. 두 계층을 함께 사용해 네트워크 보안을 구성한다.

## 예시

```text
VPC: 10.0.0.0/16
├─ Public Subnet: 외부 공개 웹 서버
│  └─ Internet Gateway를 통한 외부 통신
└─ Private Subnet: 내부 애플리케이션·데이터베이스
   └─ 필요할 때 NAT Gateway를 통한 외부 접근
```

## 요약

- VPC는 계정 전용으로 격리된 가상 네트워크다.
- 서브넷은 역할과 보안 요구에 따라 IP 범위를 나누는 단위다.
- 퍼블릭 서브넷은 외부와 직접 통신하고 프라이빗 서브넷은 별도 게이트웨이가 필요하다.
- NACL은 서브넷 단위의 상태 비저장 필터이고 ACG는 서버 단위의 상태 저장 필터다.
- 구축 전에 주소 범위와 필요한 호스트 수를 계획해야 한다.
