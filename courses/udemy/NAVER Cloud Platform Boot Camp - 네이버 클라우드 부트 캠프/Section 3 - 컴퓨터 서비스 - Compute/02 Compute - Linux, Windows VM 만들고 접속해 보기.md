# Compute - Linux, Windows VM 만들고 접속해 보기

## 개요

- 퍼블릭·프라이빗 서브넷에 Linux와 Windows VM을 생성한다.
- 인증 키로 관리자 비밀번호를 확인하고 SSH·RDP로 접속한다.
- ACG 포트, 공인 IP, 반납 보호와 요금제 설정을 확인한다.

## 내용

### 서버 생성

Server 메뉴에서 OS 또는 애플리케이션 이미지를 선택하고 VPC·서브넷·서버 사양·이름을 지정한다. 퍼블릭 서브넷에서는 공인 IP를 할당할 수 있지만 프라이빗 서브넷에서는 직접 할당할 수 없다.

새 인증 키를 만들었다면 반드시 안전한 위치에 저장한다. 인증 키는 콘솔에서 Linux의 `root` 비밀번호나 Windows의 `Administrator` 비밀번호를 확인할 때 사용한다.

### ACG 포트

| 용도 | 프로토콜·포트 |
|---|---|
| Linux SSH | TCP 22 |
| Windows RDP | TCP 3389 |

서버의 ACG에 접속에 필요한 인바운드 규칙이 있어야 한다. 실제 운영에서는 접속 출발지 IP를 관리자의 네트워크로 제한하는 것이 좋다.

### Linux와 Windows 접속

Linux VM은 공인 IP와 확인한 관리자 비밀번호를 사용해 SSH로 접속한다. Windows VM은 공인 IP, `Administrator` 계정과 관리자 비밀번호를 이용해 원격 데스크톱(RDP)으로 접속한다.

프라이빗 서브넷의 VM은 공인 IP가 없으므로 퍼블릭 서브넷의 서버를 경유해야 한다. Windows도 같은 방식으로 퍼블릭 Windows 서버를 거쳐 내부 RDP 연결을 만들 수 있다.

### 비용과 반납 보호

서버는 월 요금제 또는 시간 요금제로 만들 수 있다. 특정 시간에만 사용하는 실습 서버는 시간 요금제로 생성하고 사용하지 않을 때 정지하면 CPU·메모리 비용을 줄일 수 있다. 단, 디스크 비용은 계속 발생한다.

반납 보호를 켜면 실수로 운영 서버를 삭제하는 것을 방지할 수 있다.

## 예시

```text
Linux VM
→ Ubuntu 이미지 선택
→ Public Subnet 선택
→ 공인 IP 할당
→ 인증 키 선택·저장
→ ACG에서 TCP 22 허용
→ 관리자 비밀번호 확인
→ SSH 접속
```

## 요약

- 퍼블릭 서브넷의 VM은 공인 IP를 할당할 수 있다.
- 프라이빗 VM은 퍼블릭 서버 같은 중간 접속 지점이 필요하다.
- Linux는 SSH 22번, Windows는 RDP 3389번 포트를 사용한다.
- 인증 키는 관리자 비밀번호 확인에 필요하므로 안전하게 보관한다.
- 실습 서버에는 시간 요금제와 반납 보호를 적절히 사용한다.
