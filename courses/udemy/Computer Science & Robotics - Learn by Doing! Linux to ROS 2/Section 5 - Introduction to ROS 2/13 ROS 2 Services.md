# ROS 2 Services

## 개요
1. **서비스의 개념**: 서비스는 Ros 노드가 다른 노드에게 기능을 제공하는 요청-응답 통신 프로토콜을 사용하는 노드입니다.
2. **주요 차이점**: 주제 대신 발행자-구독자 모델을 사용하지 않습니다.
3. **복잡한 시나리오**: 한 노드에서 얼굴 인식 기능을 구현하고, 다른 노드에서는 해당 기능을 재사용하여 새로운 기능을 추가할 수 있습니다.

- 원본: [Udemy 강의](https://www.udemy.com/course/computer-science-robotics-learn-by-doing-linux-to-ros-2/learn/lecture/49933317#overview)

## 내용
### 서비스의 기본 원칙
1. **요청-응답 모델**: 클라이언트가 서버에게 요청을 보내고, 서버는 이를 처리한 후 응답을 반환합니다.
2. **메시지 타입**: 클라이언트와 서버 간에 전달할 수 있는 데이터를 정의하는 중요한 역할을 합니다.

### 적용 시나리오
1. **노드 구현**: 카메라 스트림에서 인체 얼굴을 감지하고, 로봇이 해당 움직임을 따라가는 ROS 2 애플리케이션입니다.
2. **새로운 노드 추가**: 새로운 노드를 추가하여 로봇이 가까운 사람에게 말할 수 있도록 합니다.
3. **서비스의 활용**: 얼굴 인식 기능을 중앙화하여 여러 노드에서 재사용합니다.

### 메시지 타입
1. **요청 메시지**: 클라이언트가 서버에 보내는 데이터입니다. 예를 들어, 현재 이미지 프레임이 포함됩니다.
2. **응답 메시지**: 서버가 클라이언트에게 반환하는 데이터입니다. 예를 들어, 감지된 얼굴의 3D 포즈가 포함될 수 있습니다.

## 예시
- 얼굴 감지 기능을 서비스 서버에 두고, 다른 노드가 서비스 클라이언트로 요청해 감지 결과를 재사용한다.
- 요청에는 현재 이미지 프레임을, 응답에는 감지된 얼굴의 3D 포즈를 담는 구성을 예로 든다.
