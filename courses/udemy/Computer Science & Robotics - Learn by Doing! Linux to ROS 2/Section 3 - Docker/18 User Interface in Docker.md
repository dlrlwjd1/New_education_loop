# User Interface in Docker

## 개요
1. **Docker의 기본적인 사용 방식**: 현재까지는 터미널을 통해 Docker 컨테이너에서 명령어를 실행해 왔다. 그래픽 사용자 인터페이스나 친화적인 그래픽 애플리케이션은 없었다.
2. **Docker의 초기 목적**: 그래픽 사용자 인터페이스가 필요하지 않은 기술자와 컴퓨터 과학자들을 위한 도구로 설계되었다.
3. **컨테이너의 격리성**: 컨테이너는 기본적으로 호스트 머신의 파일 시스템과 네트워크, 그래픽 디스플레이로부터 격리되어 있다.
4. **그래픽 사용자 인터페이스의 처리**: Linux 시스템에서 Docker 내부에서 그래픽 사용자 인터페이스를 처리하는 것은 display server라는 구성 요소가 담당한다.

## 내용
### X Window System (X11)
1. **클래식 디스플레이 서버 모델**: X 서버는 화면을 제어하고, GUI 애플리케이션은 X 서버에 연결하여 창을 표시해야 한다.
2. **환경 변수 `DISPLAY`**: Linux에서 `DISPLAY`라는 환경 변수가 있으며, X11 애플리케이션이 어떤 디스플레이 서버와 화면에 연결해야 하는지 알려준다.
3. **디스플레이 서버의 역할**: X 서버는 화면에 창을 표시하고 키보드 및 마우스 입력을 관리한다.

### Wayland
1. **현대 디스플레이 프로토콜**: X11을 대체하기 위해 개발된 모던한 디스플레이 프로토콜이다.
