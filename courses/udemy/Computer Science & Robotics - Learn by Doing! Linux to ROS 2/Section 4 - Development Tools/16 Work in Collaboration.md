# Work in Collaboration

## 개요
이 섹션의 이전 강의에서는 리포지토리 관리, 브랜치와 병합, 그리고 역사 탐색에 대해 배웠습니다. 이를 통해 우리는 git을 시간 여행기처럼 사용할 수 있었습니다. 그러나 개인적으로 일할 때도 유용하지만, 다른 사람들과 협업할 때는 그 진정한 힘을 발휘합니다. 프로젝트의 발전을 추적하거나 개발자 커뮤니티와 함께 작업하는 경우에도 git은 협업 도구로서 가장 효과적입니다.

- 원본: [Udemy 강의](https://www.udemy.com/course/computer-science-robotics-learn-by-doing-linux-to-ros-2/learn/lecture/51268701#overview)

## 내용
### Forking a Repository
Forking은 개인의 GitHub 계정 아래에서 원래의 GitHub 리포지토리의 복사본을 만드는 것입니다. 이는 개발자 커뮤니티에 기여하거나 특정 프로젝트를 사용자 정의하려고 할 때 유용합니다.

### Making Changes in a Fork
개인의 fork에서 변경 사항을 완료한 후, 오픈 소스 커뮤니티의 좋은 기여자가 되면 실제 모든 사람이 당신의 기능이나 버그 수정으로 이점을 얻을 수 있도록 변경 사항을 주요 리포지토리에 병합하려고 합니다.

### Creating a Pull Request
이 소절의 본문은 수집되지 않았다. Udemy 자막 원문을 확보한 뒤 보완해야 한다.

## 요약
1. Forking은 개인의 GitHub 계정 아래에서 원래의 리포지토리의 복사본을 만듭니다.
2. 변경 사항을 완료한 후, 오픈 소스 커뮤니티의 좋은 기여자가 되면 pull request를 생성하여 주요 리포지토리에 변경 사항을 통합합니다.
3. Pull request는 공용 패키지의 유지 관리자를 기본 개발 브랜치에 변경 사항 통합을 요청하는 것입니다.
