# Day 3 - Build Guardrails for AI Agents Plus Sandboxes and MCP

## 개요
- 출력 가드레일을 구현하고 샌드박스·Context7 MCP를 선택 실습으로 살펴본다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49820725#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 이메일 출력 가드레일
`@output_guardrail` 함수에서 Checker를 실행해 구조화된 평가를 받는다. 자리표시자가 있거나 전문적이지 않으면 `GuardrailFunctionOutput`의 `tripwire_triggered`를 참으로 반환한다. 카우보이 말투로 이메일을 쓰게 하여 예외 발생과 trace의 검사 결과를 확인한다.

### 명시적인 코드 검사 대안
별도 `Runner.run`으로 초안을 만든 뒤 Checker를 실행하고 조건문으로 전달 여부를 정할 수도 있다. 강사는 검사 시점과 제어가 잘 보인다는 이유로 이 방식을 선호한다. SDK 가드레일과 직접 검사 중 어느 것을 쓰든 실제 부수 효과 이전에 필요한 검사가 끝나는지 살펴야 한다.

### 샌드박스 선택 실습
영상의 베타 기능은 manifest로 작업 공간을, capabilities로 기능을, sandbox run config로 실행 환경을 지정한다. 입력 코드의 복사본을 검토하고 지정한 출력 폴더에 수정본을 쓰게 한다. `orders.py`의 고객별 주문 그룹에서 하나의 리스트를 여러 고객이 공유하던 버그를 찾아 고객마다 별도 리스트를 만들도록 수정한다. 베타 API와 지원 환경은 이후 바뀔 수 있으므로 영상의 설정을 현재 호환성 보장으로 읽지 않는다.

### Context7 MCP 비교
오래된 모델에 최신 SDK의 manifest 역할을 물어 모른다는 응답을 기준선으로 확인한다. 같은 모델에 Context7 MCP를 연결한 뒤 다시 묻는다. trace에서는 라이브러리 ID 확인 도구와 문서 질의 도구가 호출된다. 최신 정보를 모델 재학습 없이 검색 도구로 공급하는 사례다.

## 예시
```text
가드레일: 초안 → Checker → 문제 여부 → 중단 또는 다음 단계
샌드박스: 코드 복사본 → 버그 분석 → 허용된 출력 폴더의 수정본
MCP: 라이브러리 이름 → 라이브러리 ID → 문서 질의 → 근거를 포함한 응답
```

과제는 추가 입력·출력 검사를 만들고 이메일 자체도 제목·본문·서명으로 구조화하는 것이다.

## 요약
- 가드레일은 실제 검사 결과와 실행 시점까지 확인한다.
- 샌드박스는 작업 공간과 실행 권한을 함께 정의한다.
- MCP는 다른 사람이 만든 도구를 에이전트에 연결하는 통로다.
