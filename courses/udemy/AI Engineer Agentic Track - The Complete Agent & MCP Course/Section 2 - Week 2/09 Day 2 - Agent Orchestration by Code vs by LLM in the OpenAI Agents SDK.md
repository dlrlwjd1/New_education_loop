# Day 2 - Agent Orchestration by Code vs by LLM in the OpenAI Agents SDK

## 개요
- 실행 경로를 코드가 정하는 방식과 LLM이 도구를 통해 정하는 방식을 비교한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49820447#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 코드에 의한 오케스트레이션
Python이 여러 `Runner.run` 호출을 순서대로 배치하고 결과를 다음 입력으로 변환한다. 실행 경로와 데이터 전달을 명시하므로 추적·테스트·실패 분석이 쉽다. 구조화 출력을 읽어 분기하는 방식도 포함한다.

### LLM에 의한 오케스트레이션
상위에서 하나의 Agent를 실행하고, 그 Agent에 다른 Agent를 실행하는 도구를 준다. 모델이 작업에 맞는 도구와 인자를 선택하면서 협업 경로가 정해진다. SDK의 agents as tools와 handoffs를 후속 실습에서 비교한다.

### 경계와 선택 기준
구조화 출력을 코드가 읽어 분기하면 모델 판단과 코드 제어가 섞이므로 둘은 완전히 분리된 범주가 아니다. 강사는 업무 경로를 통제해야 하는 시스템에는 코드 중심 방식이, 자율적인 탐색이 제품의 핵심인 경우에는 LLM 중심 방식이 적합할 수 있다고 설명한다. 코드 제어라고 모델 출력 자체가 결정적이 되는 것은 아니다.

## 예시
| 비교 | 코드 중심 | LLM 중심 |
|---|---|---|
| 다음 호출 결정 | 명시적인 Python 흐름 | 모델의 도구 선택 |
| 결과 전달 | 코드가 변환해 다음 입력 생성 | 도구 결과 또는 제어 이관 |
| 주요 특성 | 경로 추적·검증이 쉬움 | 작업에 따라 경로를 유연하게 선택 |

실습에서는 같은 영업 프로젝트를 양쪽 방식으로 만든다.

## 요약
- 제어 흐름을 누가 결정하는지로 두 방식을 비교한다.
- 두 방식을 한 시스템에서 섞어 쓸 수 있다.
- 자율성과 경로 통제의 필요를 기준으로 선택한다.
