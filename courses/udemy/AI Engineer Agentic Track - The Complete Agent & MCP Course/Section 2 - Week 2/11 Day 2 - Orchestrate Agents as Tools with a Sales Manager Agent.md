# Day 2 - Orchestrate Agents as Tools with a Sales Manager Agent

## 개요
- 다른 에이전트를 도구로 바꾸어 Sales Manager가 초안 생성·선택·전달을 조율하게 한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49820479#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### as_tool의 역할
각 영업 에이전트에 `as_tool`을 적용해 호출 가능한 도구로 만든다. 도구가 받은 입력은 하위 에이전트의 요청이 되고, 실행 결과는 상위 에이전트로 돌아온다. 직접 작성해야 할 래퍼 코드를 SDK가 제공하는 셈이다.

### 관리자에 네 도구 제공
세 초안 작성 도구와 한 전달 도구를 Sales Manager에 준다. 지시는 각 작성 도구를 사용하고 후보들을 평가한 뒤 최선의 이메일 하나만 전달하라는 순서다. 중복 전달 같은 실제 실패를 줄이기 위해 “한 개만”이라는 조건을 명확히 한다.

### 한 번의 상위 실행
상위 코드는 Sales Manager를 대상으로 `Runner.run`을 한 번 호출한다. 이후 모델이 도구와 입력을 선택한다. 영상의 trace에서는 세 작성 도구가 병렬로 실행되고, 관리자가 결과를 검토한 뒤 전달 도구를 호출한다.

### 검증
도식은 관리자가 어떤 도구를 사용할 수 있는지 보여줄 뿐 실제 경로를 보장하지 않는다. trace에서 도구 입력·출력과 실행 순서를 확인하고 받은 메일도 확인한다. 하위 작업 후 상위가 결과를 받아 이어서 판단하는 흐름에 적합한 방식이다.

## 예시
```text
Sales Manager → 초안 작성 에이전트 도구들
              ← 각 초안
Sales Manager → 최선의 후보 선택 → 메시지 전달 도구
              ← 전달 결과 → 최종 응답
```

## 요약
- as_tool은 에이전트 실행을 도구 호출 형태로 감싼다.
- 하위 결과는 다시 관리자의 판단에 사용된다.
- 자연어로 요구한 순서는 trace로 실제 수행 여부를 확인한다.
