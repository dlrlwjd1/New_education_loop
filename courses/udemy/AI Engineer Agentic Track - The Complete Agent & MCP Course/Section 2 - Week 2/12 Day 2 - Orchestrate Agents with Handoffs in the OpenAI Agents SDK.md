# Day 2 - Orchestrate Agents with Handoffs in the OpenAI Agents SDK

## 개요
- Sales Manager가 초안을 모은 뒤 Sales Sender에 제어를 넘기는 핸드오프를 구현한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49820485#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 반환과 제어 이관의 차이
agents as tools는 A가 B를 호출해 결과를 받아 이어가는 구조다. handoff는 A에서 B로 현재 작업의 제어를 넘긴다. B의 결과를 A가 도구 결과처럼 받아 재개하는 방식과 다르다. 강사는 자신의 경험상 도구형 협업을 선호하지만 이번에는 두 방식을 비교한다.

### 관리자와 발송 담당 구성
관리자는 세 초안 작성 도구를 사용한다. 초안을 모으면 `handoffs`에 지정한 Sales Sender로 넘겨 최선의 초안을 선택하고 전달하게 한다. Sender는 전달 도구를 갖고 있으며 도구 사용을 요구하는 설정도 적용한다.

### trace로 이관 확인
한 번의 `Runner.run` 후 추적에서 작성 도구들, 핸드오프 이벤트, Sender 실행, 전달 도구를 확인한다. 실제 메일 도착과 선택 본문을 비교한다. 영상에서는 이름의 공백이 도구 이름으로 변환되는 과정의 경고도 확인하고 명시적으로 정돈된 이름을 쓰도록 안내한다.

### 확장 과제
내용을 개선하는 후속 단계를 세 방식 각각으로 구현해 본다. 더 어려운 과제로는 회신을 받아 대화를 이어가는 영업 흐름을 제시한다. 실무 성과는 그럴듯한 문장이 아니라 실제 반응·매출 등으로 평가해야 한다는 원칙을 다시 강조한다.

## 예시
```text
Manager ──초안 도구 호출·결과 수집──→ Manager
Manager ──handoff──→ Sales Sender ──전달 도구──→ 최종 응답
```

도구형 협업에서의 B → A 반환과 핸드오프의 제어 이동을 비교한다.

## 요약
- handoff는 다른 에이전트로 제어를 넘기는 구성이다.
- 등록된 핸드오프 대상과 실제 이관 발생은 구분해 추적으로 확인한다.
- 강사의 선호와 프레임워크의 일반적 우열을 동일시하지 않는다.
