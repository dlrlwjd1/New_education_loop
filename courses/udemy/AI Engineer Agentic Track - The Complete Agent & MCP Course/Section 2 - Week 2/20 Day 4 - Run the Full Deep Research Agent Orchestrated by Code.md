# Day 4 - Run the Full Deep Research Agent Orchestrated by Code

## 개요
- 계획·동시 검색·보고서 작성·전달을 하나의 추적 아래 실행한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49820805#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 검색 계획과 동시 실행
Planner의 결과를 받아 항목마다 검색 코루틴을 만든다. 각 검색 입력에는 검색어와 이유를 함께 전달한다. `asyncio.gather`로 검색들을 함께 진행하고 완료된 요약들을 모은다.

### 보고서와 전달
원래 질문과 검색 결과를 Writer에 넣어 구조화된 보고서를 받는다. 이어서 Emailer에 보고서를 넘긴다. 주요 단계별 `Runner.run`과 상태 출력은 작은 함수들로 분리된다. 검사 단계를 추가하려면 별도 함수와 호출을 같은 흐름에 넣을 수 있다.

### 첫 실행 확인
다섯 검색을 수행한 뒤 받은 이메일과 trace를 본다. 계획 이후 여러 검색의 실행 시간이 겹치고, 검색 완료 뒤 작성·전달이 이어지는지 확인한다. 단계가 각각 다른 실행이어도 `with trace`로 전체를 묶어 볼 수 있다.

### 모델·검색 수 변경 실험
더 큰 모델과 스무 검색으로 다시 실행한다. 모델 상수를 바꾸는 데 그치지 않고 Agent 정의도 다시 실행한다. 강사는 더 자세한 결과를 비교하면서 시간·비용 증가와 일부 분류의 한계도 짚는다. 검색 수를 늘렸다는 사실만으로 보고서 품질을 확정하지 않는다.

## 예시
```text
trace("research")
  계획 생성
  → gather(검색 1, 검색 2, ..., 검색 N)
  → 질문 + 요약 모음으로 보고서 작성
  → 보고서 전달
```

비교 항목: 검색 수, 소요 시간, 보고서의 근거·내용, 실제 전달 결과.

## 요약
- 독립적인 검색은 함께 실행하고 후속 단계는 결과를 기다린다.
- 추적에서 코드로 설계한 순서가 실제로 지켜졌는지 본다.
- 설정 변경 후 관련 Agent 객체도 다시 만들어야 한다.
