# Day 2 - Build a Multi-Agent Sales Team and Orchestrate Agents Three Ways

## 개요
- 영업 이메일 초안을 만들고 선택·전달하는 프로젝트로 세 가지 오케스트레이션을 비교한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49820431#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 프로젝트의 작업
여러 SDR(sales development representative) 에이전트가 영업 이메일 초안을 만든다. 후보 중 하나를 선택하고 전달하는 흐름을 구축한다. 목적은 에이전트들이 정보를 주고받는 방식을 경험하는 것이다.

### 세 가지 구현
먼저 Python 코드가 각 에이전트를 호출하고 결과를 연결한다. 다음은 관리 에이전트가 다른 에이전트를 도구로 호출하는 agents as tools, 마지막은 다른 에이전트로 제어를 넘기는 handoffs다. 자율성을 높이면 동작 경로를 예상하고 검증하기가 어려워질 수 있다.

### 학습 예제의 한계
강사는 이번에는 비교를 위해 처음부터 여러 역할을 나누며, 실제 영업 성과를 정량 평가하지 않는다고 명시한다. 실무에서는 단순한 구성부터 시작하고 열람·응답 등 사업 지표로 구조의 효과를 확인해야 한다. 생성 문장이 그럴듯하다는 사실만으로 효과적인 영업이라고 결론 내리지 않는다.

## 예시
```text
여러 초안 생성 → 후보 비교·선택 → 선택한 메시지 전달

같은 작업을 코드 제어 / 도구형 협업 / 핸드오프로 각각 구현
```

## 요약
- 비교의 대상은 영업 문장의 우열보다 협업 제어 방식이다.
- agents as tools와 handoffs는 모두 LLM이 다음 작업 선택에 관여한다.
- 실습 결과와 실제 사업 성과 검증을 구분한다.
