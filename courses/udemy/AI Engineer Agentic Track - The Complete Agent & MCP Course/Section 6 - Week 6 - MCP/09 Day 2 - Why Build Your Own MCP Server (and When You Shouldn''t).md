# Day 2 - Why Build Your Own MCP Server (and When You Shouldn''t)

## 개요
- 자체 MCP 서버를 만들 이유와 직접 함수 도구를 쓸 상황을 구분한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/50767635#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 서버가 유용한 경우
다른 사용자에게 도구를 배포하거나, 조직의 여러 언어·팀이 같은 도구를 일관되게 사용하도록 할 때 표준 인터페이스가 유용하다. 연결 구조를 이해하기 위한 학습 실습도 정당한 목적이다.

### 직접 호출로 충분한 경우
자기 애플리케이션 안의 Python 함수를 자기 에이전트만 사용한다면 함수 도구로 바로 연결할 수 있다. MCP를 추가하면 별도 프로세스와 통신 경계를 관리해야 한다. 도구를 만들었다는 이유만으로 서버가 필요한 것은 아니다.

### 이번 실습의 목적
강의는 계좌 도구를 MCP로 감싸며 구조를 배우려는 목적임을 명시한다. 기술 유행보다 재사용·배포 요구를 먼저 확인한다.

## 예시
```text
앱 내부 함수 한 곳에서 사용 → 직접 함수 도구
다른 앱·언어·팀에 공통 제공 → MCP 서버 검토
```

## 요약
- MCP의 가치는 도구의 재사용과 공통 연결에 있다.
- 불필요한 프로세스 경계를 추가하지 않는다.
