# Day 5 - Choosing an Agent Framework and 10 Things That Really Matter

## 개요
- 프레임워크 선택보다 중요한 문제 정의·평가·단순한 시작과 반복 개선 원칙을 정리한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/50769785#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 프레임워크 선택
팀의 언어·개발 방식·필요한 기능에 맞춰 고른다. 기본 에이전트 프레임워크의 공통점이 크므로 선택 자체보다 해결할 문제와 결과 평가가 중요하다는 것이 강사의 결론이다.

### 강의가 강조하는 열 가지
1. 기술보다 실제 업무 문제를 먼저 정의한다.
2. 성공을 측정할 지표를 찾는다.
3. 코드 기반 workflow를 초기 기준선으로 만든다.
4. 작은 하위 문제에서 시작해 범위를 넓힌다.
5. LLM 호출 하나로 시작하고 효과가 있을 때 분리한다.
6. 예산이 허용하면 강한 모델로 먼저 안정화한 뒤 비용을 낮춘다.
7. 기억만이 아니라 입력 문맥 전체를 설계한다.
8. 프롬프트를 실험·수정하며 개선한다.
9. trace를 확인하고 필요한 관측 정보를 화면에 드러낸다.
10. 엔지니어이자 실험자로서 가설을 검증한다.

### 적용 방식
자율성·에이전트 수·작은 모델 전환이 실제 지표를 개선하는지 기준선과 비교한다. 마지막에는 이런 실험 과정을 즐기는 태도도 덧붙인다.

## 예시
```text
업무 문제·지표 → 단순한 기준선 → trace 분석
→ 한 가지 변경 → 측정 → 유지 또는 되돌리기
```

## 요약
- 프레임워크 이름보다 문제와 지표가 우선이다.
- 복잡성은 측정된 개선을 근거로 추가한다.
