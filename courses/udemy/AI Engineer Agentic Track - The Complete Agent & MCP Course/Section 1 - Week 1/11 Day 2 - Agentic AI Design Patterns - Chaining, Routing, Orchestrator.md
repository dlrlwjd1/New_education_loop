# Day 2 - Agentic AI Design Patterns: Chaining, Routing, Orchestrator

## 개요
- 다섯 워크플로 패턴과 개방형 에이전트 루프를 비교한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49770901#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 프롬프트 체이닝과 라우팅
프롬프트 체이닝(prompt chaining)은 큰 일을 순차적인 작은 호출로 나누고 이전 결과를 전달한다. 단계 사이에 코드로 검사하는 게이트를 둘 수도 있다. 라우팅(routing)은 입력을 분류해 전문 프롬프트나 모델로 보낸다. 고객 지원 질문을 기술·업무·기타로 나누는 사례를 든다.

### 병렬화와 오케스트레이터–워커
병렬화(parallelization)는 코드가 독립 작업을 나눠 실행하고 결과를 모으는 구조다. 오케스트레이터–워커(orchestrator–worker)는 LLM이 작업을 동적으로 나누고 다른 호출들의 결과를 합성한다. 도식이 비슷해도 **분해·합성을 코드와 LLM 중 누가 결정하는지**가 다르다.

### 평가자–최적화기
평가자–최적화기(evaluator–optimizer)는 생성 결과를 평가해 통과시키거나 피드백과 함께 다시 생성하도록 돌려보낸다. 강사는 이와 관련해 LLM as a judge라는 표현도 설명한다.

### 개방형 에이전트
에이전트는 고정 경로보다 환경의 피드백에 따라 행동하고, 목표를 달성할 때까지 루프를 반복하는 구조다. 패턴 이름을 암기하거나 모든 문제를 하나의 패턴에 맞추기보다는 실제 프로젝트에서 여러 패턴의 요소가 섞이는 것을 이해하라고 강조한다.

## 예시
```text
병렬화: 코드가 작업 A/B/C 지정 → 개별 LLM 호출 → 코드가 결과 취합
오케스트레이터–워커: LLM이 하위 작업 결정 → 개별 호출 → LLM이 결과 합성
평가자–최적화기: 생성 → 평가 → 통과 또는 피드백 후 재생성
```

## 요약
- 설계 패턴은 조합 가능한 아이디어다.
- 병렬화와 오케스트레이터–워커는 작업 분해의 결정 주체가 다르다.
- 평가 루프와 개방형 행동 루프의 목적을 구분한다.
