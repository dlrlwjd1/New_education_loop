# Day 5 - Build a Visible Agent Loop with Checklist Tools Like Claude Code

## 개요
- 체크리스트 생성·완료 도구와 터미널 출력을 이용해 에이전트 진행을 눈에 보이게 만든다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/54173707#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 더 잘 보이는 루프
`1_foundations`의 추가 실습에서 채팅 뒤에 숨은 루프를 터미널 UI로 드러낸다. `rich`로 완료 항목을 색과 취소선으로 표시한다. 모델 내부 사고를 직접 읽는 기능이 아니라 도구 호출과 상태 변화를 표시하는 기능이다.

### 상태와 두 도구
`checklist`는 작업 설명 리스트, `completed`는 완료 여부 리스트다. `create_checklist`는 설명들을 저장하고 상태를 미완료로 초기화한다. `mark_complete`는 1부터 시작하는 항목 번호와 완료 메모를 받아 상태를 바꾸고 전체 목록을 출력한다. 먼저 일반 Python 호출로 확인한 뒤 두 도구의 JSON 스키마를 만든다.

### 기존 루프 재사용
도구 요청을 해석하고 실행 결과를 이력에 추가하는 구조는 디지털 트윈과 같다. 시스템 프롬프트에서 먼저 계획을 세우고 각 단계를 수행하라고 지시한다. 도구 요청이 계속되는 동안 모델을 재호출한다.

### 문제 풀이 시연과 한계
서로 마주 오는 두 열차 문제를 주자 모델이 다섯 단계의 계획을 만들고 하나씩 완료 표시한다. 강사의 프롬프트는 추가 질문을 하지 않도록 했으므로, 빠진 조건이 있으면 모델이 가정할 수 있다. 영상에 나온 시각은 시연 출력이며 출발지 사이 거리 등 전제가 없으면 유일한 정답으로 볼 수 없다. 과제는 다른 문제로 실험하고 같은 루프를 직접 구현하는 것이다.

## 예시
```text
create_checklist([조건 정리, 필요한 계산, 결과 확인])
→ mark_complete(1, 조건 정리 결과)
→ mark_complete(2, 계산 결과)
→ mark_complete(3, 확인 결과)
→ 최종 응답
```

완료 표시는 도구가 바꾼 상태이므로 실제 결과의 정확성은 별도로 확인한다.

## 요약
- 체크리스트 도구만으로 계획과 진행 상황을 표시할 수 있다.
- 작업 목록과 완료 상태를 모델 외부의 코드가 관리한다.
- 잘 보이는 진행과 정답의 정확성은 구분한다.
