# Day 4 - Build the Agent Loop From Scratch: Tool Calling with a While Loop

## 개요
- 단일 도구 호출의 한계를 확인하고 두 종류의 루프로 에이전트를 완성한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49771205#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### tools 전달과 응답 판별
Chat Completions 호출에 `tools`를 전달하고 `response.choices[0].finish_reason`이 `tool_calls`인지 확인한다. 모델이 요청한 함수 인자를 읽어 애플리케이션이 이메일 기록 함수를 실행한다.

### 도구 요청과 결과를 이력에 추가
모델의 도구 요청 메시지를 저장한 뒤 실행 결과를 도구 메시지로 넣는다. 결과의 `tool_call_id`는 어느 요청에 대한 응답인지 연결한다. 이 이력으로 모델을 다시 호출해야 기록 결과를 반영한 사용자 답변을 만들 수 있다.

### 단일 호출 구현의 실패
첫 버전은 첫 번째 도구 요청만 처리하고 한 번만 재호출한다. 이메일 세 개를 기록해 달라고 요청하자 일부 도구 요청에 응답하지 못해 오류가 발생한다. Gradio의 간단한 오류 표시 뒤 실제 스택 추적을 확인한다.

### for와 while의 역할
내부 `for`는 한 응답에 포함된 모든 도구 요청을 처리한다. 외부 `while`은 재호출된 모델이 추가 도구를 요청하면 계속 실행한다. 더 이상 도구 요청이 없을 때 최종 텍스트를 반환한다. 수정 후 세 이메일 모두 파일에 기록됐는지 확인한다.

### 확장 과제
출력이 경력에 관한 내용인지 별도 LLM으로 평가하고 필요하면 다시 생성하는 가드레일을 추가한다. 자신의 업무에 맞는 도구를 연결하는 것도 과제다.

## 예시
```text
모델 호출
└─ 도구 요청이 있는 동안 반복 (while)
   ├─ 모델의 도구 요청 메시지 저장
   ├─ 요청 각각 실행 (for)
   ├─ 각 tool_call_id와 실행 결과 저장
   └─ 갱신된 이력으로 모델 재호출
최종 텍스트를 UI에 반환
```

## 요약
- 한 응답의 다중 도구 요청과 여러 번의 모델 호출을 모두 처리한다.
- 도구 요청 메시지와 연결된 결과 메시지를 빠짐없이 보존한다.
- 최종 출력만 보지 말고 실제 파일 기록 결과를 확인한다.
