# Day 4 - The Agent Landscape: Frameworks, Runtimes, Tools and Builders

## 개요
- 빌더·제품·런타임·프레임워크를 나누고 에이전트 프레임워크가 대신 처리하는 일을 설명한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49771159#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 네 종류의 도구
빌더(builder)는 n8n처럼 화면에서 에이전트 흐름을 조립하는 도구다. 에이전트 제품(product)은 사용자의 일을 처리하는 완성된 애플리케이션이다. 런타임(runtime)은 에이전트를 배포하고 실행하는 환경이며 일반적인 클라우드 실행 환경도 여기에 해당할 수 있다. 프레임워크(framework)는 개발자가 에이전트를 만들 때 쓰는 라이브러리다. 강사는 이 구분이 자신의 설명용 관점이며 제품 사이에 겹치는 부분이 있다고 말한다.

### 프레임워크의 공통 역할
주요 기능은 호출 간 오케스트레이션, 도구 호출과 MCP 연결, 입력 구성·구조화 출력 처리다. 구조화 출력도 모델이 생성한 JSON을 코드가 파이썬 객체로 바꾸는 과정으로 이해한다. 프레임워크는 반복되는 연결·변환 코드를 줄여 준다.

### 가벼운 추상화와 정해진 개발 방식
OpenAI Agents SDK·Google ADK·Strands는 상대적으로 가벼운 방식, CrewAI와 LangGraph는 더 정해진 구조를 따르는 방식으로 소개한다. 정해진 방식은 빠른 구현을 돕지만 다른 방식이 필요하면 제약이 될 수 있다. 이는 강사의 비교 관점이며 절대적인 우열은 아니다.

### 프레임워크 없이 시작하는 이유
Week 1에서는 도구 호출과 루프를 직접 만들어 실제 동작을 익힌다. 프레임워크가 에이전트의 필수 조건은 아니다. 선택할 때는 팀의 경험과 필요한 유연성도 고려하며, 특정 프로젝트마다 유일한 정답 프레임워크가 있다고 보지 않는다.

## 예시
```text
사용자가 조립: 빌더
사용자가 바로 사용: 에이전트 제품
개발자가 구현: 프레임워크
구현한 코드를 실행·배포: 런타임
```

이번 주 실습은 프레임워크 없이 호출 → 도구 실행 → 재호출을 직접 연결한다.

## 요약
- 에이전트 프레임워크는 반복 작업을 줄이는 라이브러리다.
- 오케스트레이션·도구 호출·입출력 처리가 주요 공통 기능이다.
- 직접 구현해 본 루프가 이후 프레임워크를 이해하는 기준이 된다.
