# Day 2 - What Is an AI Agent? Definitions, Workflows vs Agents Explained

## 개요
- AI 에이전트의 세 가지 설명과 워크플로·에이전트의 차이를 구분한다.
- 출처: [원본 강의](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/learn/lecture/49770897#overview)의 실제 자막 확인·정리 (2026-09-07).

## 내용
### 에이전트의 세 가지 설명
강사는 에이전트를 독립적으로 일을 하는 AI 시스템, LLM이 작업 흐름을 제어하는 시스템, **목표를 이루기 위해 도구와 함께 루프에서 호출되는 LLM**이라는 세 관점으로 소개한다. 마지막 설명을 이후 과정의 기준으로 사용한다.

### 모델과 실행 코드를 분리해서 이해하기
LLM은 입력 토큰에서 출력 토큰을 생성한다. 그 출력이 다음 행동이나 도구 호출을 지시할 수 있지만 실제 실행은 출력의 의미를 해석하는 애플리케이션 코드가 맡는다. 모델 자체가 브라우저나 파일을 직접 조작하는 것으로 이해하면 안 된다.

### 워크플로와 에이전트
Anthropic의 구분을 빌려 워크플로는 사전에 정한 경로를 따라 여러 호출을 연결하는 구조, 에이전트는 다음 행동을 반복해서 결정하는 개방적인 구조로 설명한다. 워크플로 안에서도 LLM이 분기를 선택할 수 있다. 따라서 LLM이 의사결정에 참여한다고 모두 개방형 에이전트가 되는 것은 아니다.

### 프로젝트와 연결
질문 구체화 → 검색 → 보고서 작성 같은 Deep Research는 워크플로 예시다. 브라우저에서 목표를 달성할 때까지 행동하는 Sidekick은 에이전트 예시다. 실무 시스템은 둘의 중간에 놓일 수 있으며, 반복 가능성과 테스트 가능성이 중요할 때는 정해진 경로가 유리하다고 설명한다.

## 예시
```text
워크플로: 질문 정리 → 웹 검색 → 보고서 작성
에이전트: 목표 → LLM 판단 → 도구 실행 → 결과 관찰 → 다시 판단
```

n8n 데모에서도 모델의 반복 호출, 시트·시장 데이터 도구, 목표 달성 여부가 결합된다.

## 요약
- 에이전트는 모델과 도구 실행·반복 제어 코드가 결합된 시스템이다.
- 워크플로에도 LLM이 선택하는 분기가 있을 수 있다.
- 두 구분은 설계 설명을 위한 관점이며 엄격한 이분법은 아니다.
