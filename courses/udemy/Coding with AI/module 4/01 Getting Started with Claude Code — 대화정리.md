# Getting Started with Claude Code — 대화정리

## 개요

- Claude Code의 기본 작업 흐름은 프롬프트, 변경 제안, 권한 승인, 실행과 diff 검토로 이어진다.
- 처음에는 작업마다 승인하여 AI가 무엇을 하는지 이해하고 위험 범위를 익힌다.
- 숙련의 기준은 모든 것을 자동 승인하는 것이 아니라 안전한 작업만 선택적으로 자동화하는 능력이다.

## 내용

### 기본 승인 모드로 행동을 이해하기

Claude Code는 파일 생성과 명령 실행 전에 사용자에게 권한을 요청한다. 처음부터 auto-run 또는 YOLO 모드를 사용하면 어떤 명령과 변경이 실행되는지 배우기 어렵다. 기본 모드에서 단계마다 확인하면 AI의 행동 방식과 작업별 위험을 파악할 수 있다.

숙련된 사용자도 모든 작업을 무조건 자동 승인할 필요는 없다. 반복적이고 되돌리기 쉬우며 위험 범위가 명확한 작업만 제한적으로 승인하고, 파일 삭제·광범위한 수정·Git 작업·처음 보는 명령은 직접 확인하는 편이 안전하다.

### 파일 컨텍스트를 명확하게 지정하기

`@joke.py`처럼 파일을 명시하면 에이전트가 작업 대상을 추측하거나 코드베이스에서 검색하는 과정을 줄일 수 있다. 파일을 컨텍스트에 넣는 것 자체는 토큰을 사용하므로 무조건 토큰 사용량이 감소하는 것은 아니다. 하지만 불필요한 탐색과 잘못된 파일 읽기를 줄여 전체 작업 비용과 오해 가능성을 낮춘다.

### diff는 의도를 검증하는 지점이다

변경을 적용하기 전에 diff에서 제거된 코드와 추가된 코드를 확인한다. 이를 통해 다음을 점검한다.

- 요청한 코드만 변경했는가
- 기존의 필요한 코드를 실수로 제거하지 않았는가
- 관련 없는 리팩터링을 추가하지 않았는가
- 파일명과 구현 방식이 사용자의 의도에 맞는가

### 잘못된 제안은 적용 전에 수정하기

파일명이나 구현 방향이 틀렸다면 먼저 승인한 뒤 다시 고치기보다 `Tab to add additional instructions`로 거부하면서 올바른 지시를 추가한다. 원하지 않는 변경이 작업 공간에 들어오는 것을 막고, 하나의 의도를 하나의 깔끔한 변경으로 유지할 수 있다.

```text
승인 후 수정
잘못된 변경 → 적용 → 추가 수정 → 다시 검토

거부 + 추가 지시
잘못된 제안 → 미적용 → 올바른 제안 → 검토
```

### 선택적 자동 승인

`python3` 실행처럼 반복적이고 명확한 특정 액션만 “다시 묻지 않기”로 허용하면 승인 피로(review fatigue)를 줄일 수 있다. 동시에 파일 삭제나 Git 작업처럼 중요한 변경에는 검토 단계를 유지한다.

## 예시

특정 파일을 명시적으로 컨텍스트에 포함한다.

```text
@joke.py에 사용자가 계속할지 묻는 반복 기능을 추가해 줘.
```

bash 모드에서는 `!` 뒤에 명령을 입력한다.

```bash
!python joke.py
```

작업 흐름은 다음과 같다.

```text
프롬프트 입력
→ AI의 작업·코드 제안
→ 권한 확인
→ 파일 생성 또는 명령 실행
→ diff 검토
→ 승인 또는 추가 지시
```

## 요약

- 처음에는 기본 승인 모드에서 AI가 실제로 무엇을 하는지 확인한다.
- 안전하고 반복적인 특정 액션만 선택적으로 자동 승인한다.
- `@파일명`으로 작업 대상을 명확히 하여 탐색과 오해를 줄인다.
- diff로 변경 의도, 범위와 삭제 내용을 검토한다.
- 잘못된 변경은 적용 후 고치기보다 승인 전에 거부하고 추가 지시한다.
