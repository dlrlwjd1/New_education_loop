# Plan Mode — 대화정리

## 개요

- Plan mode는 코드를 수정하지 않고 프로젝트를 읽어 마크다운 계획을 만드는 모드다.
- 계획 문서는 사용자와 AI가 함께 작성하는 작은 명세이자 구현 계약으로 사용할 수 있다.
- 계획 승인과 실제 코드 변경 승인은 별개이며 구현 단계의 권한 상태를 다시 확인해야 한다.

## 내용

### 계획과 실행 분리

Plan mode에서는 프로젝트 파일을 탐색하고 개선 아이디어와 구현 단계를 계획 문서에 기록하지만 코드는 변경하지 않는다. 코드가 바뀌기 전에 계획을 검토하므로 빠진 요구사항, 불필요한 기능과 잘못된 구현 순서를 먼저 수정할 수 있다.

```text
프로젝트 탐색
→ 개선 아이디어 제안
→ 사용자가 범위 선택
→ 계획 문서 작성·검토
→ 별도 구현 승인
→ 코드 작성과 결과 검증
```

이 계획 문서는 대화가 사라져도 구현 의도와 단계를 복구할 수 있게 한다. 다만 `.claude/Plans/`가 글로벌 경로인지 프로젝트 경로인지에 따라 프로젝트와 함께 버전 관리되지 않을 수 있으므로 저장 위치를 확인한다.

### 작은 기능만 선택하기

프로젝트 스캔 결과로 제안된 기능을 한꺼번에 모두 선택하면 작업 범위와 diff가 커진다. AI가 일부 요구사항을 놓치거나 사용자가 변경을 충분히 리뷰하기 어려워지고, 테스트 실패의 원인도 찾기 힘들어진다. 따라서 작은 기능 단위로 계획·구현·테스트·검토 사이클을 닫는다.

### 읽기 전용도 컨텍스트 비용이 든다

Plan mode가 코드를 수정하지 않는다고 해서 비용이 없는 것은 아니다. 계획을 세우려면 관련 파일과 구조를 읽고 관계를 분석해야 한다. 프로젝트가 크거나 탐색 범위가 넓으면 시간과 토큰 사용량도 증가한다. 대상 기능과 디렉터리를 명시하면 불필요한 탐색을 줄일 수 있다.

### 계획 승인과 구현 승인 분리

강의 시점의 Claude Code에서는 Plan mode의 계획에 `yes`라고 답해 구현 단계로 넘어가면 일반 에이전트 모드와 함께 Accept Edits가 켜진다. 사용자는 계획만 승인했다고 생각했지만 이후 파일 변경까지 자동 승인된 상태가 될 수 있다.

사용자가 선호하는 흐름에서는 두 승인을 분리한다.

1. 사용자와 AI가 계획 문서를 함께 작성한다.
2. 사용자가 계획의 범위와 단계를 승인한다.
3. Plan mode를 종료하고 Accept Edits가 꺼진 기본 모드인지 확인한다.
4. AI가 승인된 계획을 기준으로 구현한다.
5. 사용자가 실제 diff와 실행 결과를 검토한다.

검토 시점은 파일 변경마다 승인하거나 구현 완료 후 전체 diff를 검토하는 방식으로 정할 수 있지만, **계획 동의가 자동 편집 동의를 의미하지 않는다**는 경계는 유지한다.

## 예시

AI 상호작용 규칙에 승인 경계를 명시할 수 있다.

```md
- 계획 승인은 구현 승인을 의미하지 않는다.
- 계획이 승인된 후에도 코드를 변경하기 전에 별도로 확인한다.
- 구현 결과는 diff와 테스트 결과를 기준으로 검토한다.
```

Plan mode의 개념적 흐름:

```text
Plan mode: 읽기 + 공동 계획 작성
                 ↓ 계획 승인
기본 모드: 구현 + diff 제시
                 ↓ 구현 검토
변경 수락
```

## 요약

- Plan mode는 실행 전에 검토 가능한 마크다운 계획을 만든다.
- 계획은 사용자와 AI가 함께 작성하는 작은 명세이자 구현 계약이다.
- 기능 제안은 작은 범위로 선택해 AI의 혼란과 사용자의 리뷰 부담을 줄인다.
- 읽기 전용 계획도 프로젝트 탐색에 시간과 토큰을 사용한다.
- 계획 승인과 구현 승인을 분리하고 구현 단계의 Accept Edits 상태를 확인한다.
