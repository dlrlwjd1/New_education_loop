# Reviewing Generated Code

## 개요
- 프로토타입 코드는 **보관·사용하지 않지만**, 이런 도구가 어떤 코드를 만드는지 살펴본다.
- "끔찍하다"가 아니라, **바꾸고 싶은 지점들**이 있다는 게 핵심 — 생성물을 무비판적으로 쓰면 안 되는 이유.
- 교훈: AI가 다 하게 두면 **내가 아키텍트가 아니다**. Claude Code/Cursor에선 컨텍스트 파일로 이 문제를 해결.

## 내용

### 생성 코드에서 봐야 할 것 (체크리스트)
- **보안 우려(security concerns)** — 사실상 가장 중요 (맨 위에 둬야 함).
- **파일·컴포넌트 구조** — 파일 배치, 컴포넌트 분리 여부 (분리하라고 지시했었음).
- **상태 관리(state management)** 방식.
- **미사용 import / 죽은 코드(dead code)**.
- **의존성(dependencies)** — 안 쓰는 패키지를 잔뜩 설치하는 경우 많음.
- **과잉 엔지니어링(over-engineering)** — AI가 자주 함, 불필요하게 복잡하게 만듦.
- **에러 처리** 방식.
- 무엇을 맞고 무엇을 틀렸는지.

### V0 결과에서 발견한 것

**의존성**
- 지시한 것: React, Tailwind → 반영됨 (React 19, Tailwind + tailwind-animate, react-markdown).
- **지시 안 했는데 추가된 것**: React Hook Form + Zod(검증), Sonner(토스트), shadcn/ui(Radix UI 컴포넌트들), Recharts(어디 쓰는지 불명).
- → **안 써도 되는 것들을 설치** — 이 방식으로 코딩하면 흔한 현상. 그래서 **tech stack을 매우 구체적으로** 지정해야.

**프레임워크 선택**
- React만 시켰는데 **Next.js 16을 사용** (최신 버전). AI는 지정 안 하면 대개 **Next.js + Tailwind**를 좋아함(인기 있으니 합리적).

**코드 구조 문제 (강사 기준)**
- 페이지를 통째로 `use client`로 만듦 → 강사는 **페이지는 서버(server) 렌더링**, 상호작용 필요한 **별도 컴포넌트만 `use client`** 선호.
  - 훅(useState/useEffect 등)을 쓰면 client여야 하므로 그 부분만 분리.
- `page.tsx`에 **너무 많은 것**이 들어감:
  - 샘플 마크다운(더미 노트)을 페이지에 그대로 넣음 → `starterNote.ts` 같은 파일로 빼서 import 해야.
  - 노트 상태 전부가 페이지에 → 별도 notes 컴포넌트(client)로 분리해야.
  - 테마·디바운스·useEffect도 페이지에.
- `useCallback` 사용 → **React 19 + 컴파일러**에선 대부분 불필요.
- 이상적으로는 페이지엔 **return(렌더링될 부분)만** 두고 나머지는 분리·import.

### 핵심 교훈
- **무엇이 일어나는지 모른 채 앱을 생성하면 안 된다.**
- Claude Code/Cursor에선 **컨텍스트 파일 + 내 코딩 선호**를 설정 →
  - 예: "Next.js 사용 시 모든 페이지는 서버 렌더링하고, 상호작용은 client 컴포넌트로 가져와라"를 컨텍스트에 넣으면 **매번 지시할 필요 없음**.
  - 무엇이든 지정 가능(클래스 쓰라고 하면 기본으로 그렇게 함).
- V0/Bolt에선 이걸 매번 프롬프트로 지정해야 하고, 대부분은 안 함.
- 프로토타입에선 분리 지시 덕에 컴포넌트로 나뉘긴 함(안 했으면 다 `page.tsx`에 들어갔을 것). 하지만 **프로덕션 코드는 아님** → 사용 안 함.

## 요약
- 생성 코드 리뷰 포인트: **보안 · 파일/컴포넌트 구조 · 상태관리 · 미사용/죽은 코드 · 의존성 · 과잉 엔지니어링 · 에러 처리**.
- V0는 시키지 않은 패키지(Zod·Sonner·shadcn·Recharts)와 **Next.js**를 추가 → tech stack은 구체적으로 지정할 것.
- 강사 선호: **페이지=서버, 상호작용 컴포넌트만 client**, `page.tsx`에 로직·더미데이터 몰아넣지 않기, React 19에선 `useCallback` 불필요.
- 진짜 해법은 **컨텍스트 파일에 코딩 선호를 설정**해 매번 지시 없이 일관성 확보 (Claude Code/Cursor). 프로토타입 코드는 프로덕션용 아님.
