# Iterating on the Prototype

## 개요
- **반복(iteration)** = 이미 있는 것 위에 점진적 개선·조정·다듬기를 쌓는 과정.
- AI를 효과적으로 쓰는 데 **핵심적인 부분**.
- 프로토타입(노트 앱)에 여러 변경을 채팅으로 요청하며 룩앤필을 다듬는다. (코드는 여전히 보관 안 함.)

## 내용

### 반복으로 추가한 변경들 (V0 채팅으로 요청)
1. **삭제 확인(delete confirmation)** — 기존엔 삭제 시 바로 사라짐 → "노트 삭제 시 확인 추가" 요청.
   - → shadcn **alert dialog** 컴포넌트로 확인 팝업 생성.
2. **색상 스킴 변경** — "더 어두운 블루/퍼플 색으로 변경" → 배경까지 짙은 청보라로.
3. **단어 수·글자 수(word/character count)** — "에디터 패널 하단에 **subtle·비방해적으로** 표시, 타이핑 시 **실시간 업데이트**" → 하단에 표시, 입력하는 대로 갱신.
4. **마크다운 내보내기(export)** — "현재 노트를 `.md` 파일로 내보내는 다운로드 버튼 추가.
   - 파일명 = 노트 제목, **소문자 + 공백을 대시(-)로 치환** + `.md`, 다른 노트 액션 근처에 배치."
   - → 다운로드 버튼 생성, `test note` → `test-note.md`로 저장.
5. **패널 폭 조절(resizable panes)** — "에디터/프리뷰 패널의 **폭을 조절 가능**하게" → 가운데 핸들로 드래그해 폭 조절.

### 프롬프트 디테일 관찰
- 요청 시에도 구체적으로: 표시 위치("하단"), 스타일("subtle, non-distracting"), 동작("실시간"), 파일명 규칙(소문자·대시·확장자) 등을 명시.

### 이게 바로 바이브 코딩
- 강사: "이것이 **바이브 코딩의 정의** — 코드에서 무슨 일이 벌어지는지 모른다."
- 코드를 열어보면 AI가 알아서 추가한 것들: `sidebarOpen`/`editorWidth` 상태, `isResizing` useRef, container ref, alert dialog + `handleConfirmDelete` 등.
- 프로토타입이라 괜찮지만 — **모른 채 진행한다는 점**이 핵심 차이.

### 위치
- 이 노트 앱은 메인 프로젝트가 아님 — **프롬프팅 감을 익히는 워밍업**.
- 다음: **프로토타이핑/바이브 코딩 vs 프로덕션 코드의 현실**을 정리하며 이 섹션 마무리.

## 요약
- **반복(iteration)** = 점진 개선의 연속, AI 활용의 핵심.
- 채팅으로 삭제 확인·색상·단어수·`.md` 내보내기·패널 폭 조절을 추가 — 요청도 **구체적으로**.
- 이 방식은 코드 내부를 모른 채 진행하는 **바이브 코딩** — 프로토타입엔 OK.
- 다음은 **프로토타이핑/바이브 코딩 vs 프로덕션 코드**의 현실.
