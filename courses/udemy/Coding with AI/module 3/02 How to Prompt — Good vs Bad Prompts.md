# How to Prompt — Good vs Bad Prompts

## 개요
- AI 도구의 결과물 품질은 **프롬프트 품질에 직결**된다.
- 개발자들이 AI로 고전하는 가장 큰 이유는 모델이 나빠서가 아니라 **정보를 충분히 주지 않아서**다.
- 원칙: **나는 아키텍트(architect), AI는 빌더(builder)** — 구체적으로 무엇을·어떻게 만들지 지시한다.

## 내용

### 중요한 프롬프트는 "문서"로
- 이 코스에서 강사는 매우 상세한 프롬프트를 준다.
- 메인 프로젝트의 중요한 기능 프롬프트는 대부분 **마크다운 문서**로 작성 → AI에 전달.
- 장점: **통제 유지**, 아주 구체적인 요청 가능, **나중에 참조**할 기록으로 남음.

### 원샷(one-shotting) 주의
- 실제 애플리케이션을 한 번에(one-shot) 만드는 건 비추천.
- 프로토타이핑에서도 **화면 하나씩(one screen at a time)**.
  - 예: to-do 앱 → 대시보드부터. 대시보드+랜딩+인증을 한 번에 X.
- 단, 아주 단순한 것(로컬 스토리지, 단일 페이지)은 원샷 OK.

### 예시 1 — React To-Do 앱

**❌ 나쁜 프롬프트**
> "Build me a to-do app in React."
- 너무 모호함. 원하는 기능·기술 요구사항·UI/UX 방향이 전혀 없음 → AI가 전부 추측.

**✅ 좋은 프롬프트** (features + tech stack + UI/UX 포함)
- **Features**: 추가/편집/삭제/완료 표시, all·active·completed 필터, **로컬 스토리지 저장**, 드래그앤드롭 정렬.
  - (프로토타이핑 시엔 DB 대신 로컬 스토리지 사용 → 메인 프로젝트에서 DB 구현.)
- **Tech stack**: React 함수형 컴포넌트 + 훅, Tailwind CSS, 반응형(responsive).
- **UI/UX**: Todoist 같은 깔끔·미니멀 인터페이스, 완료엔 체크박스, 이름은 인라인 편집.
  - 💡 **좋아하는 다른 인터페이스를 예시로 제시**(복사 아님, 영감용) — 매우 중요.

→ 좋은 이유: 기능·기술 스택·UI 기대치 나열 + **디자인 레퍼런스 제공**.

### 예시 2 — API 통합 (Weather API)

**❌ 나쁜 프롬프트**
> "Add a weather API to my app."
- 어떤 weather API? 어떤 데이터? 앱 어디에? 에러 처리 언급 없음.

**✅ 좋은 프롬프트** (아키텍트로서 구체 지시)
- OpenWeatherMap API를 React 앱에 통합, **`weatherService.js`** 파일 생성해 API 호출 담당(파일명까지 지정).
- 현재 날씨 + 5일 예보 fetch.
- **적절한 에러 처리**(failed requests) 포함.
- **로딩 상태(loading states)** 추가.
- 온도·상태·날씨 아이콘 표시(무엇을 가져와 어떻게 보여줄지 명시).
- **API details**: 어떤 API인지, (필요 시 키), 필요한 엔드포인트(current weather / forecast), 성공·에러 응답 모두 처리.
- **단계 지시**: "먼저 service 파일을 보여주고, 그다음 컴포넌트에 통합해라."

→ 좋은 이유: API 명시, 정확한 데이터 나열, 에러·로딩 언급, **모듈화된 코드(service 파일)** 요청, **단계로 분해**.

### 핵심 프롬프트 체크리스트
1. **Features** — 무슨 기능인지
2. **Tech stack** — 어떤 기술로
3. **UI/UX** — 어떤 룩앤필 (+ 레퍼런스 예시)
4. **구현 세부** — 파일명, 에러 처리, 로딩 상태 등
5. **단계 분해** — 한 번에 다 X, 순서대로

## 요약
- 결과 품질 = **프롬프트(=정보량) 품질**. 최대 문제는 "정보 부족".
- 좋은 프롬프트는 **features + tech stack + UI/UX + 구현 세부 + 단계 분해**를 담는다.
- 중요한 프롬프트는 **문서(마크다운)** 로 작성해 통제·재사용.
- **원샷 지양**, 화면/기능 하나씩. UI엔 **레퍼런스 예시** 제공.
- 항상 **나는 아키텍트, AI는 빌더** — 무엇을 어떻게 만들지 내가 지시.
