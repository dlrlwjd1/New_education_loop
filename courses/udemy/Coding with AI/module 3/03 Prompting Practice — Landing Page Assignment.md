# Prompting Practice — Landing Page Assignment

## 개요
- 지난 강의의 프롬프팅 원칙을 **직접 실습**하는 (선택) 과제.
- **claude.ai**(브라우저)로 진행 — 아직 Claude Code는 사용하지 않음. **HTML·CSS·JS만** 사용(브라우저에서 렌더링).
- 좋은 프롬프트 구조가 실제로 원하는 결과를 만들어내는지 검증한다.

## 내용

### 과제 (선택)
지난 강의 원칙으로 **랜딩 페이지 생성 프롬프트**를 작성:
- 관심 있는 **SaaS 제품 아이디어** 아무거나 (생산성 도구, 개발자 도구 등).
- 프롬프트 구조/원칙 적용:
  - **어떤 섹션·콘텐츠**가 필요한지 (단일 랜딩 페이지이므로): hero 섹션, features 카드+아이콘, testimonials, footer 등.
  - **기술 요구사항**: 여기선 중요치 않음 → HTML·CSS·JS 권장.
  - **디자인 방향/레퍼런스**: 좋아하는 예시 사이트.
  - **충분히 구체적인가?** AI가 추측할 게 많지 않은가?
- 팁: 텍스트 에디터에 **따로 작성 후** claude.ai에 붙여넣기. 결과가 별로면 수정·재프롬프트.

### 강사 예시 프롬프트 — "CodeSnap" (개발자용 스크린샷 도구)
**섹션(Sections)**
- Hero: 헤드라인 + 서브헤딩 + CTA + 예시 스크린샷
- 아이콘 있는 features 3개
- Pricing: free / pro 티어
- 링크 있는 footer

**기술(Technical)**
- HTML + 바닐라 CSS + JS
- 부드러운 스크롤 내비게이션(smooth scroll)
- 모바일 반응형
- hero에 그라디언트 배경

**디자인(Design)**
- 개발자 지향 미학 — **GitHub, VS Code 참고**(레퍼런스 제공)
- 다크모드 친화, 퍼플·블루 그라디언트 액센트
- 깔끔·모던 타이포그래피
- 샘플 콘텐츠 포함, **모든 버튼 동작**(섹션 스크롤)

### 결과 검증 (요구사항 대조)
생성 후, 프롬프트에 쓴 것이 실제로 반영됐는지 하나씩 점검.
- 섹션 전부 생성됨: hero(헤딩/서브헤딩/CTA/스크린샷), features 3개+아이콘, pricing(pro에 "most popular" 아웃라인), footer.
- 기술: 스무스 스크롤·내비 동작, 버튼 클릭 시 해당 섹션 이동, 모바일에서 스택+콜아웃 메뉴 → 반응형 OK.
- 디자인: hero 그라디언트, 개발자 스타일, 퍼플·블루, 모던 타이포 → 요청 전부 반영.
- 결론: **요청한 걸 전부 줬다 → 좋은 프롬프트의 증거**이자 따라 쓸 좋은 템플릿.

### 모델 참고
- 강사는 **Opus 4.5**(당시 최신 Claude 모델) 사용. 코스 전반에서 사용.
- 시청 시점엔 더 새 모델이 있을 수 있음 → **최신 또는 권장 모델** 사용.
- 단일 프롬프트 생성에 3~4분 소요.

### 다음 순서
- 프로토타이핑을 더 깊게 — 강사는 **V0** 사용(단, Lovable 등 원샷 바이브 코딩 플랫폼 아무거나 가능).

## 요약
- claude.ai에서 **HTML/CSS/JS 랜딩 페이지**를 좋은 프롬프트로 생성해보는 실습.
- 프롬프트 템플릿 = **섹션/콘텐츠 + 기술 + 디자인(레퍼런스) + 구체성 점검**.
- 생성 후 **요구사항을 하나씩 대조**해 반영 여부 확인하는 습관.
- 다음은 V0(또는 Lovable/Bolt 등)로 더 깊은 프로토타이핑.
