# CLAUDE.md and Project Context — 대화정리

## 개요

- `CLAUDE.md`나 `AGENTS.md`는 에이전트가 프로젝트에 들어올 때 읽는 지속 컨텍스트의 진입점이다.
- 상세 정보는 역할과 변경 주기에 따라 별도 파일로 분리하면 읽고 수정하기 쉽다.
- 중요한 프로젝트 합의는 휘발되는 대화가 아니라 파일에 기록해야 다음 세션에도 적용된다.

## 내용

### 대화 기억 대신 파일에 외부화하기

AI의 대화 컨텍스트는 토큰 제한이 있으며 `/clear`나 compact가 발생하면 이전 대화 내용이 사라질 수 있다. 따라서 프로젝트 목적, 구현 규칙, 협업 방식처럼 다음 세션에도 유지되어야 하는 정보는 대화 기록에만 두지 않고 프로젝트 파일에 남긴다.

### 진입점과 상세 문서 분리

루트의 `CLAUDE.md` 또는 `AGENTS.md`에 모든 정보를 몰아넣으면 중요한 규칙이 긴 설명에 묻히고 문서를 관리하기 어려워진다. 루트 파일에는 핵심 규칙과 상세 문서의 위치를 두고, 상세 정보는 다음과 같이 역할별로 분리한다.

- `project-overview.md`: 무엇을 만드는지 설명하는 프로젝트 목적, 기능, 데이터 구조, 기술 스택
- `coding-standards.md`: 코드를 어떻게 작성하는지 정하는 구현 규칙
- `ai-interaction.md`: AI가 언제 질문하고 언제 실행하는지 정하는 협업 규칙
- `current-feature.md`: 지금 어떤 기능을 작업하는지 나타내는 현재 상태

### 변경 주기에 따른 분리

`project-overview.md`는 프로젝트 목적과 핵심 구조처럼 비교적 안정적인 정보를 담는다. 반면 `current-feature.md`는 기능이 끝날 때마다 갱신된다. 둘을 분리하면 자주 바뀌는 작업 상태 때문에 안정적인 프로젝트 설명을 계속 수정하지 않아도 되고, 에이전트도 프로젝트 전체와 현재 작업을 구별할 수 있다.

### 컨텍스트 라우팅과 토큰 비용

파일을 여러 개로 나누는 것만으로 토큰 비용이 줄어드는 것은 아니다. 루트 파일이 매번 모든 문서를 읽으라고 지시하면 전체 토큰 사용량은 그대로다. 각 파일의 목적과 읽어야 하는 조건을 명시하여 항상 필요한 정보와 작업에 따라 필요한 정보를 구분해야 한다. 이때 루트 파일은 상세 정보를 전부 담는 문서가 아니라 필요한 컨텍스트로 안내하는 **컨텍스트 라우터(context router)** 역할을 한다.

강의에서는 `project-overview.md`를 추가하면서 약 6,000토큰이 늘었지만, 프로젝트의 핵심 개념과 데이터 모델을 이해한 상태로 기능을 구현하면 잘못된 가정과 재작업을 줄일 수 있으므로 가치 있는 비용으로 판단했다.

### 자동 생성 문서는 초안이다

`/init`으로 만든 `CLAUDE.md`에는 불필요한 아키텍처 설명, 코드만 보면 알 수 있는 내용, 자동 분석 과정에서 생긴 잘못된 추측이 들어갈 수 있다. 자동 생성 결과는 완성된 규칙이 아니라 초안으로 취급하고, 유용한 명령어는 남기되 중복되거나 부정확한 내용은 사람이 검토하여 제거한다.

## 예시

```text
project/
  AGENTS.md
  context/
    project-overview.md
    coding-standards.md
    ai-interaction.md
    current-feature.md
```

```md
## Context routing

- `context/project-overview.md`: 프로젝트 구조나 데이터 모델을 파악해야 할 때 읽는다.
- `context/coding-standards.md`: 코드를 작성하거나 수정하기 전에 읽는다.
- `context/ai-interaction.md`: 핵심 협업 규칙을 확인할 때 읽는다.
- `context/current-feature.md`: 현재 기능을 구현하거나 진행 상태를 갱신할 때 읽는다.
```

반드시 지켜야 하는 짧은 규칙까지 선택적으로 두면 누락될 수 있으므로, 그런 규칙은 루트 파일에 직접 두는 편이 안전하다.

## 요약

- 대화 컨텍스트는 휘발되므로 중요한 합의는 파일에 기록한다.
- 상세 컨텍스트는 목적과 변경 주기에 따라 분리한다.
- 루트 파일은 핵심 규칙과 상세 문서의 읽기 조건을 제공하는 진입점이다.
- 파일 분리만으로 토큰이 절약되지는 않으며 선택적 로딩 기준이 필요하다.
- 자동 생성된 컨텍스트 문서는 반드시 사람이 검토한다.
