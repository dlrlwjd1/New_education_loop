# Coding Standards and AI Interaction Rules — 대화정리

## 개요

- `coding-standards.md`는 만들어지는 코드의 형태와 기술적 품질 기준을 정한다.
- `ai-interaction.md`는 AI의 행동, 판단, 승인 범위와 중단 조건을 정한다.
- 기능 명세가 동작을 정의한다면 코딩 표준은 그 동작을 프로젝트에서 반복 가능하고 일관된 방식으로 구현하게 한다.

## 내용

### 명세에서 구현 규칙으로

프로젝트 명세는 무엇을 왜 만드는지, 기능 명세는 기능이 어떤 동작을 해야 하는지 설명한다. 그러나 같은 동작도 여러 기술로 구현할 수 있다. 반복적으로 발생하는 구현 선택을 기능마다 다시 결정하면 코드베이스에 서로 다른 패턴이 섞이므로, 프로젝트 공통 선택은 코딩 표준으로 고정한다.

```text
프로젝트 명세       무엇을 왜 만드는가
기능 명세           어떤 동작을 해야 하는가
코딩 표준           그 동작을 어떤 방식으로 구현하는가
AI 상호작용 규칙    구현 중 AI가 어디까지 스스로 결정하는가
```

### 코딩 표준과 AI 상호작용 규칙의 구분

분류 기준은 규칙이 적용되는 파일 범위가 아니라 **규칙의 대상**이다.

- `coding-standards.md`: TypeScript, React, Next.js, Prisma, Tailwind 등 산출되는 코드의 구조와 구현 방식
- `ai-interaction.md`: 삭제 전 확인, 큰 리팩터링 전 질문, 최소 변경, 커밋 승인 등 에이전트의 행동과 권한 경계

따라서 “파일을 삭제하기 전에 확인한다”는 코딩 스타일이 아니라 AI가 실행 전에 승인을 받아야 하는 행동 규칙이므로 `ai-interaction.md`에 속한다.

### 서버 액션과 API route

기능 명세에 “사용자가 아이템 생성 폼을 제출한다”고만 적혀 있으면 AI는 여러 구현 방식 중 하나를 임의로 고를 수 있다. 이 프로젝트의 코딩 표준은 앱 내부의 일반적인 폼 제출과 단순 mutation에는 서버 액션(server action)을 사용하고, 외부 서비스가 HTTP 요청을 보내는 웹훅이나 파일 업로드 진행, 장시간 작업, 외부 통합에는 API route를 사용하도록 선택을 고정한다.

Stripe 웹훅은 앱 내부 폼이 호출하는 기능이 아니라 외부 Stripe 서버가 특정 URL로 HTTP 요청을 보내므로 API route가 필요하다. 반면 일반 폼 제출은 서버 액션으로 처리할 수 있다. 중요한 것은 기술 하나를 깊게 파는 것이 아니라, 반복되는 기술 선택을 프로젝트 수준의 표준으로 끌어올려 기능마다 다시 논쟁하지 않는 것이다.

### 기존 코드와 최신 표준

에이전트는 기존 코드에서 비슷한 구현을 찾아 모방할 수 있다. 하지만 기존 코드는 임시 구현이거나 서로 다른 패턴이 섞인 상태일 수 있고, 새 프로젝트에는 참고할 코드가 없을 수도 있다. 따라서 코딩 표준으로 방향을 정하고 기존 코드는 구체적인 적용 사례로 참고한다.

기존 코드가 API route를 사용하지만 최신 표준이 신규 폼에 서버 액션을 요구한다면, 신규 기능에는 최신 표준을 적용하고 요청 범위 밖의 기존 코드는 그대로 둔다. 두 방식의 공존이 문제가 되면 몰래 리팩터링하지 않고 충돌을 설명한 뒤 사용자에게 결정받는다.

### 예시가 있는 규칙

추상적인 문장만으로는 규칙의 해석이 달라질 수 있다. “이렇게 쓴다 / 이렇게 쓰지 않는다” 예시를 함께 제공하면 예시 기반 학습(few-shot prompting)처럼 원하는 코드 형태와 허용·금지 경계를 구체적으로 전달할 수 있다.

### 중단 조건과 커밋 승인

같은 문제를 2~3번 해결하지 못했다면 계속 수정할수록 임시 변경이 쌓이고 원래 문제와 새 문제가 섞일 위험이 커진다. 이때는 멈춰서 현재 문제, 시도한 접근, 실패 이유와 다음 선택지를 설명한다.

빌드 성공과 사용자 승인은 서로 다른 검증이다. 빌드 성공은 코드가 기술적으로 컴파일되는지를 보여 주지만, 사용자의 의도와 변경 범위가 맞는지는 보장하지 않는다. 따라서 빌드가 성공해도 사용자가 변경을 검토하고 허락한 뒤 커밋한다.

## 예시

일반적인 폼 제출은 서버 액션을 기본값으로 둔다.

```ts
"use server";

export async function createItem(formData: FormData) {
  // Zod로 입력을 검증하고 Prisma로 저장한다.
}
```

외부 서비스가 호출해야 하는 웹훅은 API route를 사용한다.

```text
Stripe 서버
  → HTTP POST /api/webhooks/stripe
  → 결제 상태 처리
```

## 요약

- 기능 명세는 동작을, 코딩 표준은 반복되는 구현 방식을 정한다.
- 코딩 표준은 코드의 형태를, AI 상호작용 규칙은 에이전트의 행동과 권한을 제한한다.
- 표준이 방향을 제시하고 기존 코드는 그 표준의 구체적인 적용 사례가 된다.
- 규칙에는 좋은 예와 나쁜 예를 함께 넣어 해석 차이를 줄인다.
- 반복 실패 시 멈추는 조건과 사용자 승인 절차가 코드베이스를 불필요한 변경으로부터 보호한다.
