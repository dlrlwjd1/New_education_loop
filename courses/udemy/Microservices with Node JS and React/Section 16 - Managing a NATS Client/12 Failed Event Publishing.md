# Failed Event Publishing

## 개요
- 유효성 검사를 하죠 티켓 문서를 생성하고 저장하고 이벤트를 게시하죠 하지만 이 두 개의 라우트 처리기는 아주 작은 차이가 있어요 게시자에 await 키워드가 각각 있다는 거죠

## 내용
### 자막·본문 기반 핵심 내용
- 유효성 검사를 하죠 티켓 문서를 생성하고 저장하고 이벤트를 게시하죠 하지만 이 두 개의 라우트 처리기는 아주 작은 차이가 있어요 게시자에 await 키워드가 각각 있다는 거죠
- 새 라우트 처리기 안에 티켓 생성 게시자에 대한 대기 키워드 표시가 있어요 근데 업데이트 내부에 await 키워드 안 넣었어요
- 요청이 들어오면 유효성 검사를 하고 티켓 문서에 변화를 주고 저장하죠 그런 다음 업데이트 안에 있는 이벤트를 게시해요 New 내부와 아주 유사하죠
- 새로운 티켓 경로 처리기와 업데이트 경로 처리기를 살펴보고 있어요 이 둘은 논리가 비슷해요

### 구현 요소
- 강의에서 직접 언급하거나 사용하는 요소: `await`
