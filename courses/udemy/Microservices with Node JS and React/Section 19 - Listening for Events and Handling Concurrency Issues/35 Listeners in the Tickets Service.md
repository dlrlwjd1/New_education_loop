# Listeners in the Tickets Service

- Order Service는 이러한 이벤트들을 잘 처리하고 있어요. 주문 서비스도 두 가지 이벤트를 방출하죠

## 내용
### 자막·본문 기반 핵심 내용
- Order Service는 이러한 이벤트들을 잘 처리하고 있어요. 주문 서비스도 두 가지 이벤트를 방출하죠
- 예를 들어 주문 서비스는 명령을 게시하고 명령을 취소하죠 티켓 서비스에 주문 생성 이벤트와 주문 취소 이벤트를 볼 수신기가 있는지 확인해야 해요
- 이걸 하는 이유는 주문이 생성된 후에 티켓을 확실히 잠가야 하기 일단 표가 예약되면 표 서비스는 확실히 해야 합니다 이 표를 소유한 사람 표를 만든 사람이 돌아와서 수정을 못 하도록요 사용자가 표 구매 과정을 거쳐 갑자기 가격이 이유 없이 변경되거나 설명이 변경되는 걸 봐선 안 되니까요
- 그걸 구현하기 위해 티켓 서비스로 돌아갈게요 서로 다른 청취자를 구현할 거예요 티켓 서비스가 목록이나 주문 이벤트가 생성된 것을 볼 때마다 우리는 티켓 서비스 안에서 적절한 티켓을 찾을 것입니다 그리고 거기에 무언가를 설정하여 티켓을 잠가버리고 더 이상의 변경을 막는 것이죠
