## 내용
### 자막·본문 기반 핵심 내용
- 하지만 NATS로 보내지는 않습니다 NATS는 고객 이벤트 버스로 가지만 본질적으로 그 이벤트가 사용된 쿼리 서비스와 관련이 있죠
- 여기가 트랜잭션 서비스의 정말 더 나은 디자인을 거쳤기 때문에 이런 동시성 문제들이 생기기 시작하는 걸 보시게 될 겁니다 NATS 서버의 어떤 화려한 기능에 의존하지 않고도 동시성 문제가 생길 거예요
- 왜냐하면 여기에 숫자 필드가 있고 클라이언트 데이터베이스 내의 마지막 트랜잭션 번호를 기록하고 있기 때문입니다 두 번째 트랜잭션은 처리하지 않아도 된다는 것을 알고 있었습니다 트랜잭션을 거부한 1번 서비스와는 완전히 다른 서비스인데도 우리는 앉아서 30초간 기다렸다가 이 두 개가 타임아웃을 거쳐 NATS가 다시 재생할 거라고 상상해 봤죠
- 지금까지 살펴본 모든 해결책에서 NAT를 어떻게 사용하면 이 동시성 문제를 해결하거나 고칠 수 있을지 연구했어요
