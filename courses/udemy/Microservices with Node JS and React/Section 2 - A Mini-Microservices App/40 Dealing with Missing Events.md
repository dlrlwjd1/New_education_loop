# Dealing with Missing Events

## 개요
- 모든 데이터를 다시 한 번 동기화한 후 쿼리 서비스는 여러 이벤트를 수신하기 이 접근 방식의 단점은 동기화 요청을 하게 된다는 겁니다 이 말은 쿼리 안에서 코드를 구현해야 한다는 거죠 이 데이터베이스와 직접적으로 작업하기 여기 포스트 데이터 저장소가 제 SQL이고 코멘트 데이터스토어는 MongoDB라고 는 MySQL 데이터베이스와 MongoDB 데이터베이스의 인터페이스를 위해 쿼리 안에 코드를 작성해야 하죠

## 내용
### 자막·본문 기반 핵심 내용
- 모든 데이터를 다시 한 번 동기화한 후 쿼리 서비스는 여러 이벤트를 수신하기 이 접근 방식의 단점은 동기화 요청을 하게 된다는 겁니다 이 말은 쿼리 안에서 코드를 구현해야 한다는 거죠 이 데이터베이스와 직접적으로 작업하기 여기 포스트 데이터 저장소가 제 SQL이고 코멘트 데이터스토어는 MongoDB라고 는 MySQL 데이터베이스와 MongoDB 데이터베이스의 인터페이스를 위해 쿼리 안에 코드를 작성해야 하죠
- 포스트들을 모두 저장하면 Common Service로 방향을 돌려 동기화 요청을 직접 할 수 있어요 모든 코멘트를 달라고 하는 거죠
- 쿼리가 신경 쓰는 이벤트들이죠 Query가 이벤트에 접근할 수 있다면요 잘 될 수도 있어요 그런 것에 전략이 달려 있죠
- 이론상으로는 과거에 발산된 모든 사건에 접근할 수 있다면 쿼리가 가능해요 예를 들어 POST 서비스는 1, 2, 3개의 이벤트를 내보내는데 각각은 POST 생성 이벤트죠

### 구현 요소
- 강의에서 직접 언급하거나 사용하는 요소: `Service`, `MongoDB`, `Query`
