# Feature Specification: 정교화·청킹·인터리빙

**Feature Branch**: `[007-elaboration-interleaving]`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "007 — 정교화·청킹·인터리빙 (F05). 006은 '근거 포함 정답 → 정교화 단계로 전이'만 구현. 이 기능: 근거 포함 정답 후 이유 질문(왜 이렇게 설계했는가), 사용자가 직접 관련 개념에 이름 붙이기(청킹 — AI가 먼저 완성하지 않음), 세션 중간/끝에 오늘 예정인 다른 주제 복습 항목 1~2개 섞기(연체 제외, 없으면 생략, 7장 확정), 그 답변도 채점해 해당 복습 항목 이력에만 반영, 한 화면에 여러 질문 동시 제출 금지, 기초 지식 없는 사용자에게 이유 질문 반복 금지, 조기 복습 자동 편성 안 함. 복습 단계 계산(1→3→7→16→35일)은 008 소관, 이 기능은 인터리빙 결과를 복습 이벤트로 기록하고 단계 계산은 008 규칙에 위임."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 맞힌 개념에 "왜?"를 묻고 자기 말로 설명하기 (Priority: P1) 🎯 MVP

사용자가 인출 질문에 근거까지 포함해 맞히면(006에서 "맞음" 판정 후 정교화 단계로 전이된 상태), 시스템은 바로 다음 질문으로 넘어가지 않고 "왜 이렇게 설계했을까요?"와 같은 이유 질문 하나를 던진다. 사용자는 자기 말로 이유를 설명하고, 시스템은 그 설명을 채점해 맞은 부분과 보완할 부분을 알려준다.

**Why this priority**: 006은 정답을 맞힌 뒤 "정교화 단계"라는 상태로 옮겨 놓기만 하고 그 뒤에 아무것도 하지 않는다. 이유 질문이 없으면 이 앱은 낱개 사실을 맞히는 퀴즈에서 멈춘다. `/study` 스킬이 말하는 "정교화는 청킹의 공장"이라는 흐름의 출발점이므로 가장 먼저 필요하다.

**Independent Test**: 근거 포함 정답으로 "맞음" 판정을 받은 질문에서, 다음 화면이 이유 질문 하나인지, 이유 질문에 대한 답을 제출하기 전에는 모범 설명이 어디에도 노출되지 않는지, 제출 후 채점 피드백이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 인출 질문이 근거를 포함한 "맞음"으로 판정되어 정교화 단계에 있을 때, **When** 사용자가 다음 화면을 열면, **Then** 그 개념에 대한 이유 질문 하나만 표시되고 답변 입력을 기다린다.
2. **Given** 이유 질문이 표시된 상태에서, **When** 사용자가 아직 답을 제출하지 않았으면, **Then** 모범 설명·힌트·예시 답이 화면과 응답 어디에도 포함되지 않는다.
3. **Given** 이유 질문에 설명을 제출했을 때, **When** 채점이 완료되면, **Then** 설명의 맞은 부분과 보완할 부분이 사용자 답변의 표현을 인용해 구분되어 표시된다.
4. **Given** 이유 질문에 대한 설명이 부정확하게 판정됐을 때, **When** 결과를 확인하면, **Then** 원래 인출 질문의 "맞음" 판정은 바뀌지 않고, 이 판정만으로 신규 복습 항목이 생기지 않는다.
5. **Given** 이유 질문 채점 호출이 실패하거나 시간 초과됐을 때, **When** 결과를 확인하면, **Then** 제출한 설명은 보존되고 "채점 대기/재시도 가능" 상태로 남는다.

### User Story 2 - 방금 다룬 개념들에 내가 직접 이름 붙이기(청킹) (Priority: P1)

이유 질문에 대한 설명을 마친 뒤, 시스템은 "방금 나온 것들에 이름을 하나 붙여 보세요."라고 요청한다. 사용자가 이름과(선택적으로) 한두 줄 설명을 직접 적어 제출하면, 그 이름이 이 세션의 개념 묶음으로 저장된다. 시스템은 사용자가 쓰기 전에 이름이나 설명을 먼저 제안하지 않는다.

**Why this priority**: 청킹은 낱개 넷이 한 덩어리가 되는 순간이며, AI가 먼저 이름을 붙여 버리면 사용자가 읽고 익숙해진 느낌만 남는다(CLAUDE.md "읽어서 익숙해진 느낌은 이해가 아니다"). 정교화와 한 쌍이라 같은 우선순위다.

**Independent Test**: 이유 질문을 마친 세션에서 청킹 요청 화면이 뜨는지, 제출 전 화면·응답에 이름 후보가 없는지, 제출한 이름·설명이 그대로 저장되어 새로고침 후에도 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이유 질문 단계가 끝났을 때, **When** 다음 화면이 열리면, **Then** "방금 나온 것들에 이름을 하나 붙여 보세요."와 함께 이 묶음에 포함된 개념 목록(이번 세션에서 사용자가 다룬 개념명)만 보여주고 이름 입력을 기다린다.
2. **Given** 청킹 요청 화면에서, **When** 사용자가 아직 제출하지 않았으면, **Then** 시스템이 만든 이름 후보·설명 예시가 화면과 응답 어디에도 포함되지 않는다.
3. **Given** 사용자가 이름(필수)과 설명(선택)을 제출했을 때, **When** 저장이 완료되면, **Then** 사용자가 쓴 문장이 수정 없이 그대로 저장되고 새로고침 후에도 표시된다.
4. **Given** 사용자가 이름을 제출한 뒤, **When** 피드백을 받으면, **Then** 피드백은 사용자가 쓴 이름을 대체하지 않으며, 저장된 이름은 사용자가 직접 고치기 전에는 바뀌지 않는다.
5. **Given** 사용자가 이름 붙이기를 원하지 않을 때, **When** 건너뛰기를 선택하면, **Then** 청킹이 "건너뜀"으로 기록되고 다음 단계로 진행되며, 오답·복습 항목으로 취급되지 않는다.

### User Story 3 - 세션 중간·끝에 다른 주제의 오늘 복습 항목 섞어 풀기(인터리빙) (Priority: P2)

현재 주제를 공부하는 도중이나 끝에, 시스템은 복습큐에서 **오늘이 다음 복습일인, 현재 주제와 다른 주제의 항목** 1~2개를 한 번에 하나씩 질문으로 낸다. 연체된 항목과 아직 날짜가 오지 않은 항목은 섞지 않으며, 대상이 없으면 조용히 생략한다. 사용자가 "왜 갑자기 이걸 묻느냐"고 궁금해하면 섞는 이유를 짧게 보여준다.

**Why this priority**: 인터리빙은 다섯 전략 중 하나지만, 정교화·청킹(US1·2) 흐름이 먼저 있어야 "세션 중간·끝"이라는 끼워 넣을 지점이 생긴다. 또한 결과 반영이 008(간격 반복 일정)과 맞물리므로 P2로 둔다.

**Independent Test**: 오늘 예정 항목·연체 항목·내일 예정 항목·현재 주제와 같은 주제의 항목을 섞어 둔 복습큐로 세션을 진행해, 오늘 예정인 다른 주제 항목만 최대 2개 출제되는지, 대상이 없을 때 인터리빙 단계 없이 진행되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 복습큐에 오늘이 다음 복습일인 다른 주제 항목이 3개 있을 때, **When** 인터리빙 시점이 되면, **Then** 그중 최대 2개만 선택되고, 한 화면에 하나씩 순서대로 출제된다.
2. **Given** 복습큐에 연체된(다음 복습일이 오늘보다 이전인) 다른 주제 항목만 있을 때, **When** 인터리빙 시점이 되면, **Then** 어떤 항목도 출제되지 않고 인터리빙 단계가 생략된다.
3. **Given** 다음 복습일이 내일 이후인 항목만 있을 때, **When** 인터리빙 시점이 되면, **Then** 그 항목들은 앞당겨 출제되지 않는다(조기 복습 자동 편성 없음).
4. **Given** 오늘 예정 항목이 모두 현재 세션과 같은 주제일 때, **When** 인터리빙 시점이 되면, **Then** 출제되지 않고 생략된다.
5. **Given** 인터리빙 질문이 표시됐을 때, **When** 사용자가 섞는 이유를 확인하려 하면, **Then** "섞으면 연습 중 성적이 떨어지지만, 시험에서는 문제가 유형별로 나오지 않는다"는 취지의 짧은 설명을 볼 수 있다.
6. **Given** 인터리빙 질문이 표시됐을 때, **When** 사용자가 그 질문을 건너뛰면, **Then** 복습 사건이 기록되지 않고 그 항목은 여전히 오늘 복습 대상으로 남는다.

### User Story 4 - 섞어 푼 복습 답변이 그 복습 항목의 이력에만 반영되기 (Priority: P2)

인터리빙으로 낸 질문의 답변도 006과 같은 기준(맞음·유창하지만 틀림·모름)으로 채점되며, 그 결과는 **출제된 그 복습 항목**의 복습 사건(성공/실패)으로만 기록된다. 현재 세션 주제의 진도나 다른 복습 항목에는 영향을 주지 않고, 다음 복습일·단계 계산은 008의 규칙을 따른다.

**Why this priority**: US3의 결과 처리다. 결과가 엉뚱한 항목이나 현재 주제 진도에 섞여 들어가면 복습 일정 전체가 오염되므로 US3과 같은 우선순위로 반드시 함께 검증한다(웹전환 명세 T09).

**Independent Test**: 서로 다른 주제의 복습 항목 두 개를 인터리빙으로 풀어 하나는 맞히고 하나는 틀린 뒤, 각 항목에 정확히 하나씩의 성공/실패 사건만 기록되고 현재 세션 주제의 진도·다른 항목은 변하지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 인터리빙 질문에 답을 제출했을 때, **When** 채점이 완료되면, **Then** 판정은 006과 같은 세 가지 중 하나이며 맞은 부분·틀린 부분이 구분되어 표시된다.
2. **Given** 인터리빙 질문이 "맞음"으로 판정됐을 때, **When** 결과가 반영되면, **Then** 출제된 복습 항목에만 "복습 성공" 사건 하나가 기록되고 다른 복습 항목과 현재 주제 진도는 변하지 않는다.
3. **Given** 인터리빙 질문이 "유창하지만 틀림" 또는 "모름"으로 판정됐을 때, **When** 결과가 반영되면, **Then** 출제된 복습 항목에 "복습 실패" 사건 하나가 기록되고, 같은 개념으로 새 복습 항목이 중복 생성되지 않는다.
4. **Given** 같은 인터리빙 답변이 중복 전송됐을 때, **When** 서버가 처리하면, **Then** 복습 사건은 한 번만 기록된다.
5. **Given** 인터리빙 질문이 첫 답에서 틀려 힌트나 설명 후 다시 맞혔을 때, **When** 결과가 반영되면, **Then** 그 항목의 복습 사건은 최초 판정(실패) 하나로만 기록되고, 이후 재답변은 같은 날 교정 성공으로 따로 남되 복습 단계를 올리지 않는다.
6. **Given** 인터리빙 채점이 실패하거나 시간 초과됐을 때, **When** 결과를 확인하면, **Then** 복습 사건은 기록되지 않고 답변은 "채점 대기/재시도 가능" 상태로 보존된다.

### User Story 5 - 기초가 없는 개념에는 "왜?"를 억지로 반복하지 않기 (Priority: P3)

사용자가 부품 개념을 아직 갖추지 못한 상태(사전 지식 확인에서 재료 없음 판정, 힌트 세 번 후 설명 전환, 또는 이유 질문에 "모름")라면, 시스템은 이유 질문을 계속 던지지 않고 인출 확인 단계에 머문다.

**Why this priority**: "불발하는 왜?"는 소설을 부른다(`/study` 4절). 안전장치이지만, US1이 먼저 있어야 억제할 대상이 생기므로 P3로 둔다.

**Independent Test**: 설명 전환을 거쳐 맞힌 질문, 이유 질문에 "모르겠습니다"를 제출한 질문 각각에서 이유 질문이 다시 나오지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사전 지식 확인에서 재료가 없다고 판정되었거나 힌트 세 번 후 설명으로 전환된 뒤 맞힌 질문일 때, **When** 다음 단계가 결정되면, **Then** 이유 질문 없이 청킹 또는 다음 질문으로 넘어간다.
2. **Given** 이유 질문에 "모르겠습니다"를 제출했거나 부품 개념이 없다고 판정됐을 때, **When** 다음 단계가 결정되면, **Then** 같은 개념에 이유 질문을 다시 던지지 않는다.
3. **Given** 한 세션에서 이유 질문이 연속 두 번 "모름"으로 끝났을 때, **When** 이후 질문이 맞음으로 판정되면, **Then** 그 세션의 남은 부분에서는 이유 질문을 생략하고 사용자에게 그 사실을 알린다.

---

### Edge Cases

- 이유 질문 단계에서 사용자가 여러 개념을 한 번에 설명하려 하거나 여러 질문에 한꺼번에 답하려 하는 경우 → 한 화면에는 질문 하나의 입력만 있으며, 여러 질문을 한 번에 제출하는 경로 자체가 없다.
- 청킹 이름에 빈 문자열만 제출하는 경우 → 제출을 받지 않고 이름을 적거나 건너뛰도록 안내한다.
- 청킹 대상 개념이 하나뿐인 경우(세션에서 맞힌 개념이 하나) → 청킹 요청은 그대로 할 수 있으나 묶음에는 그 개념 하나만 연결된다.
- 인터리빙 대상 선택 도중 자정이 지나 "오늘"이 바뀌는 경우 → 인터리빙 대상을 고른 시점의 사용자 달력 날짜 기준으로 판정하며, 이미 출제된 질문은 그대로 진행한다.
- 인터리빙으로 출제한 복습 항목이 그 사이 파일에서 삭제되거나 마스터 완료로 옮겨진 경우 → 결과를 다른 항목에 대신 기록하지 않고, 반영할 수 없음을 알리며 답변 기록만 보존한다.
- 이번 세션에서 방금 오답으로 새로 등록된 항목 → 다음 복습일이 내일이므로 인터리빙 대상이 아니다.
- 같은 날 이미 복습 사건이 기록된 항목(다른 세션에서 인터리빙으로 풀었거나 복습한 항목) → 같은 날 다시 인터리빙 대상으로 고르지 않는다.
- 복습 항목의 날짜가 깨져 "형식 확인 필요"로 분리된 항목 → 인터리빙 대상에서 제외한다.
- 세션 도중 서버 재시작이나 새로고침 → 정교화·청킹·인터리빙 중 어느 단계였는지와 이미 고른 인터리빙 항목이 유지되어 그 지점부터 이어간다.

## Requirements *(mandatory)*

### Functional Requirements

**정교화(이유 질문)**

- **FR-001**: 인출 질문이 근거를 포함한 "맞음"으로 판정되어 정교화 단계로 전이된 경우, 시스템은 그 개념에 대한 이유 질문("왜 이렇게 설계했는가" 형식) 하나를 생성해 표시해야 한다.
- **FR-002**: 이유 질문은 한 개념당 최대 한 번만 제시해야 한다.
- **FR-003**: 이유 질문에 대한 답변을 제출하기 전에는 모범 설명·힌트·예시 답이 어떤 형태의 응답에도 포함되지 않아야 한다.
- **FR-004**: 시스템은 이유 질문에 대한 답변을 채점 요청 전에 저장하고, 채점 결과로 맞은 부분과 보완할 부분을 사용자 답변 표현을 인용해 구분해 보여줘야 한다.
- **FR-005**: 이유 질문의 채점 결과는 원래 인출 질문의 판정을 바꾸지 않아야 하며, 그 결과만으로 신규 복습 항목을 등록하지 않아야 한다.
- **FR-006**: 해당 질문이 사전 지식 "재료 없음" 판정이나 힌트 세 번 후 설명 전환을 거쳐 맞힌 경우, 시스템은 이유 질문을 생략해야 한다.
- **FR-007**: 이유 질문에 "모르겠습니다"가 제출되었거나 부품 개념이 없다고 판정되면, 시스템은 같은 개념에 이유 질문을 다시 제시하지 않아야 한다.
- **FR-008**: 한 세션에서 이유 질문이 연속 두 번 "모름"으로 끝나면, 시스템은 그 세션의 남은 부분에서 이유 질문을 생략하고 사용자에게 생략 사실을 알려야 한다.

**청킹(개념 묶기)**

- **FR-009**: 이유 질문 단계가 끝나거나 생략된 뒤, 시스템은 "방금 나온 것들에 이름을 하나 붙여 보세요."라는 청킹 요청과 함께 묶음 대상 개념 목록(이번 세션에서 다룬 개념명)을 보여줘야 한다.
- **FR-010**: 청킹 요청 시 시스템은 이름 후보·설명 예시를 먼저 생성하거나 노출하지 않아야 한다 — 이름과 설명은 사용자가 작성한다.
- **FR-011**: 시스템은 사용자가 제출한 청킹 이름(필수)과 설명(선택)을 수정 없이 그대로 저장해야 하며, 사용자가 직접 고치기 전에는 바꾸지 않아야 한다.
- **FR-012**: 사용자는 청킹을 건너뛸 수 있어야 하며, 건너뛴 경우 "건너뜀"으로 기록하고 오답이나 복습 항목으로 취급하지 않아야 한다.
- **FR-013**: 청킹 제출 후 피드백을 줄 수 있으나, 피드백은 사용자가 쓴 이름·설명을 대체하거나 덮어쓰지 않아야 한다.

**인터리빙(다른 주제 복습 섞기)**

- **FR-014**: 시스템은 한 개념의 정교화·청킹 흐름이 끝난 시점(세션 중간) 또는 사용자가 세션 마무리를 요청한 시점(세션 끝)에 인터리빙 대상을 판정해야 한다.
- **FR-015**: 인터리빙 대상은 사용자 시간대의 오늘 날짜가 다음 복습일과 정확히 같은, 활성 상태의 복습 항목 중 현재 세션 주제와 다른 주제의 항목으로 한정해야 한다.
- **FR-016**: 연체 항목(다음 복습일이 오늘보다 이전), 미래 항목(다음 복습일이 오늘 이후), 날짜 형식 확인 필요 항목, 마스터 완료 항목, 오늘 이미 복습 사건이 기록된 항목은 인터리빙 대상에서 제외해야 한다.
- **FR-017**: 한 세션에서 인터리빙으로 출제하는 항목은 합계 최대 2개여야 하며, 대상이 없으면 인터리빙 단계를 생략하고 다음 단계로 진행해야 한다.
- **FR-018**: 시스템은 미래 복습 항목을 앞당겨 출제하는 조기 복습을 자동으로 편성하지 않아야 한다.
- **FR-019**: 인터리빙 질문은 한 화면에 하나씩만 표시해야 하며, 여러 질문을 한 번에 제출하게 하지 않아야 한다(정교화·청킹 단계에도 동일하게 적용된다).
- **FR-020**: 인터리빙 질문 화면에서 사용자는 섞는 이유에 대한 짧은 설명을 확인할 수 있어야 한다.
- **FR-021**: 사용자는 인터리빙 질문을 건너뛸 수 있어야 하며, 건너뛴 항목에는 복습 사건을 기록하지 않고 오늘 복습 대상으로 그대로 남겨야 한다.

**인터리빙 결과 반영**

- **FR-022**: 인터리빙 답변은 006과 같은 기준("맞음"/"유창하지만 틀림"/"모름")으로 채점되어야 하며, 채점 실패·시간 초과 시 "채점 대기/재시도 가능" 상태로 남고 복습 사건을 기록하지 않아야 한다.
- **FR-023**: 인터리빙 답변의 최초 판정은 출제된 그 복습 항목 하나에만 복습 사건(맞음 → 성공, 유창하지만 틀림·모름 → 실패)으로 기록되어야 하며, 다른 복습 항목이나 현재 세션 주제의 진도를 변경하지 않아야 한다.
- **FR-024**: 인터리빙 답변이 틀려도 같은 개념으로 새 복습 항목을 생성하지 않아야 한다(이미 존재하는 항목의 실패 사건으로만 남긴다).
- **FR-025**: 최초 판정 이후 힌트·설명을 거친 재답변은 최초 판정과 분리해 저장하되, 그 항목의 복습 사건을 추가로 만들거나 복습 단계를 올리지 않아야 한다.
- **FR-026**: 복습 사건의 기록에 따른 다음 복습일·반복 단계 계산은 008(간격 반복 복습 일정)의 규칙을 따라야 하며, 이 기능은 단계를 직접 계산하지 않아야 한다.
- **FR-027**: 동일한 인터리빙 답변 제출이 중복 전송되면 복습 사건은 한 번만 기록되어야 한다.
- **FR-028**: 출제된 복습 항목이 결과 반영 시점에 더 이상 활성 상태가 아니면, 시스템은 결과를 다른 항목에 대신 기록하지 않고 반영 불가를 알리며 답변 기록만 보존해야 한다.

**공통**

- **FR-029**: 정교화·청킹·인터리빙 단계의 전이는 서버가 결정해야 하며, 클라이언트가 주장하는 단계·판정을 그대로 받아들이지 않아야 한다. AI가 반환한 문장을 그대로 데이터 갱신 명령으로 쓰지 않아야 한다.
- **FR-030**: 현재 단계(이유 질문/청킹/인터리빙), 선택된 인터리빙 항목, 제출된 답변·청킹 내용은 영속 저장되어 새로고침이나 서버 재시작 후에도 같은 지점에서 이어갈 수 있어야 한다.

### Key Entities *(include if feature involves data)*

- **이유 질문(정교화 질문)**: 006의 "맞음" 질문 하나에 딸린 후속 질문. 원 질문 참조, 질문 내용, 생략 여부와 생략 사유(재료 없음/설명 전환/연속 모름)를 담는다.
- **정교화 답변 시도**: 이유 질문에 대한 제출 텍스트, 시도 순번, 채점 상태, 맞은 부분·보완할 부분을 담는다. 006의 답변 시도와 같이 덮어쓰지 않고 쌓는다.
- **개념 묶음(청크)**: 세션에 속하며, 사용자가 작성한 이름·설명(원문 그대로), 묶인 개념 목록, 상태(제출됨/건너뜀), 작성 시각을 담는다.
- **인터리빙 출제**: 세션에 속하며, 출제된 복습 항목 참조, 출제 순서(1~2), 선정 기준 날짜(사용자 달력 날짜), 상태(출제됨/답변됨/건너뜀/반영 불가)를 담는다.
- **복습 사건**: 복습 항목 하나에 대한 한 번의 복습 결과. 복습 항목 참조, 결과(성공/실패), 실제 복습일, 발생 경로(인터리빙), 근거 답변 참조, 중복 방지 식별자를 담는다. 이 사건을 받아 다음 복습일·단계를 계산하는 일은 008이 맡는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 근거 포함 정답으로 판정된 질문(설명 전환을 거치지 않은 것)의 100%에서 이유 질문이 정확히 한 번 제시된다.
- **SC-002**: 이유 질문·청킹 요청 화면에서 사용자가 제출하기 전 모범 설명·이름 후보가 노출되는 사례가 0건이다.
- **SC-003**: 저장된 청킹 이름·설명이 사용자가 제출한 원문과 다른 사례가 0건이다.
- **SC-004**: 오늘·어제·내일 예정 항목과 같은 주제·다른 주제 항목을 섞은 시험 데이터에서, 출제된 인터리빙 항목의 100%가 "오늘 예정·다른 주제" 조건을 만족하고, 세션당 출제 수가 2개를 넘는 사례가 0건이다.
- **SC-005**: 서로 다른 주제의 복습 항목을 섞어 풀었을 때, 복습 사건이 출제된 항목이 아닌 다른 항목이나 현재 주제 진도에 반영되는 사례가 0건이다(웹전환 명세 T09).
- **SC-006**: 동일 인터리빙 답변의 중복 전송이나 같은 날 재답변으로 복습 사건이 두 번 이상 기록되는 사례가 0건이다.
- **SC-007**: 설명 전환을 거쳐 맞혔거나 이유 질문에 "모름"을 낸 개념에 이유 질문이 다시 제시되는 사례가 0건이다.
- **SC-008**: 정교화·청킹·인터리빙 각 단계에서 새로고침 또는 재개를 했을 때 100% 같은 단계·같은 인터리빙 항목에서 이어진다.

## Assumptions

- **006 위에 얹는 기능이다.** 질문 생성·채점·힌트·설명·채점 실패 처리·AI 호출 방식은 006이 정한 것을 그대로 재사용한다. 이 기능은 006의 "정교화 단계로 전이" 이후 흐름과, 세션 중간·끝의 인터리빙 삽입 지점만 추가한다.
- **008 의존성**: 복습 사건을 받아 다음 복습일·반복 단계(1→3→7→16→35일, 실패 시 1일 복귀, 같은 날 재정답은 단계 증가 없음)를 계산하는 규칙은 008 소관이다. 이 기능은 복습 사건을 기록하고 계산을 008에 위임한다. 008이 아직 적용되지 않은 상태에서는 사건만 기록되고 항목의 다음 복습일은 바뀌지 않으며, "오늘 이미 복습 사건이 있는 항목은 다시 고르지 않는다"(FR-016) 규칙으로 같은 날 중복 출제를 막는다.
- **"다른 주제" 판정**: 004가 보존한 복습 항목의 "주제" 칸은 자유 서술형 텍스트다. 기본값으로, 현재 세션의 주제명(주제 경로) 또는 로드맵 이름(자료·로드맵 경로)이 항목의 주제 텍스트에 포함되어 있으면 "같은 주제"로 보고 제외한다. 애매하면 제외하는 쪽(보수적)을 택한다 — 섞지 않는 쪽의 손해가 잘못 섞는 쪽보다 작다. 정확한 비교 방식은 계획 단계에서 정한다.
- **인터리빙 시점**: `/study` 5절의 "세션 중간이나 끝"을 "한 개념의 정교화·청킹이 끝난 뒤" 또는 "세션 마무리 요청 시점(009가 제공하는 마무리 흐름 직전)"으로 해석했다. 009가 아직 없으면 세션 중간 시점만 동작한다. 세션당 합계 최대 2개(7장 "1~2개")로 해석했다.
- **이유 질문 결과는 복습 등록 대상이 아니다.** 1.2절 "틀린 답만 신규 복습 항목으로 등록"의 틀린 답은 인출 질문의 오답을 뜻한다고 보고, 이미 맞힌 개념의 심화 설명이 부정확하다는 이유로 복습 항목을 만들지 않는다. 채점 이력은 남아 010(학습 이력)에서 볼 수 있다.
- **"기초 지식 없음"의 판정**: 006에서 사전 지식 "재료 없음" 판정 또는 힌트 세 번 후 설명 전환을 거친 경우, 그리고 이유 질문에 "모름"이 나온 경우를 기초가 없는 신호로 본다. 연속 두 번 "모름"이면 세션 전체에서 이유 질문을 멈춘다는 기준은 "계속하지 않는다"를 검증 가능하게 만들기 위한 기본값이다.
- **인터리빙 결과의 복습 사건은 최초 판정 하나**: 7장 확정 "최초 판정과 재시도 분리", "같은 날 재정답은 교정 성공으로 기록하되 단계 증가 없음"을 따른다.
- **청킹 피드백**: 제출 후 AI 피드백은 허용하되 사용자의 이름을 바꾸지 않는다. 피드백 제공 여부·형식은 계획 단계에서 정한다.
- 청킹 결과(개념 묶음)를 복습큐나 로드맵 체크박스에 반영하지 않는다. 세션 기록의 일부로만 보존하며, 파일(`내학습/진행상황.md` 등) 반영은 009(세션 마무리) 범위다.
- 배포 형태는 개인용 로컬 단일 사용자 앱이다(웹전환 명세 7장 확정) — 다중 사용자 권한은 범위 밖이다.
- 실제 AI가 만든 이유 질문·피드백의 품질은 성공 기준에 포함하지 않는다. 결정적으로 검증 가능한 것(단계 전이, 노출 금지, 대상 선정, 사건 반영 범위, 중복 방지)만 성공 기준으로 삼는다.
