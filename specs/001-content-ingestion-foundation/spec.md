- Q: 이 기능이 만든 로드맵·트랙·Phase·자료 매핑과 색인을, 3단계(사용자·읽기 화면)가 곧바로 읽어서 쓸 수 있도록 실제 저장소에 써서 남겨야 하나요, 아니면 이번 단계는 파싱·식별자 규칙과 원본 대조 검증까지만 하나요? → A: 이번 단계는 파싱·식별자 부여 규칙의 정의와 원본 대비 정확성 검증까지만 다룬다. 그 규칙을 적용해 실제로 조회 가능한 영속 저장소(7.1의 SQLite 파생 캐시)를 만드는 작업은 3단계(사용자·읽기 화면)에서 이 기능이 정의한 규칙을 그대로 적용해 수행한다.
- Q: 재가져오기 시 "동일한 원본"으로 판단해서 기존 식별자를 재사용하는 기준은 무엇인가요 — 파일이 이동/이름 변경됐지만 내용은 그대로인 경우 같은 항목으로 봐야 하나요? → A: 경로를 1차 키로 매칭하고, 경로가 안 맞으면 내용 해시로 재확인한다. 이동·이름 변경은 내용 해시 재확인으로 같은 항목으로 인식하고, 경로가 같은데 내용이 달라지면 새 버전으로 처리한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기존 로드맵·진도를 그대로 가져오기 (Priority: P1)

사용자가 웹앱에 처음 접속했을 때, 기존에 `study-progress/`에 쌓아둔 로드맵·Phase·학습 항목과 체크박스 완료 상태가 그대로 반영되어 있어야 한다. 이 기반이 없으면 브리핑·로드맵 탐색·학습 이력 등 다른 어떤 화면도 신뢰할 수 있는 숫자를 보여줄 수 없다.

**Why this priority**: 이후 모든 기능(브리핑 집계, 로드맵 탐색, 학습 이력)이 이 데이터 위에서 동작한다. 이 기능 없이는 다른 어떤 화면도 검증 가능한 상태로 만들 수 없다.

**Independent Test**: 실제 저장소의 로드맵 디렉터리를 가져오기 실행 한 번으로 처리한 뒤, 각 로드맵의 "완료/전체" 수치를 원본 Markdown 파일의 체크박스를 직접 센 값과 대조해서 완전히 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `study-progress/`에 8개의 로드맵 디렉터리가 있는 상태, **When** 가져오기를 실행하면, **Then** 8개 로드맵 모두가 인식되고 각 로드맵의 완료/전체 항목 수가 원본 체크박스 수와 일치한다.
2. **Given** 이미 한 번 가져온 로드맵을 다시 가져오기, **When** 두 번째 가져오기를 실행하면, **Then** 동일한 항목이 중복 생성되지 않고 기존 식별자가 그대로 유지된다.

---

### User Story 2 - 트랙 아래 중첩된 Phase 구조 인식 (Priority: P1)

인공지능융합공학부 로드맵처럼 트랙(대분류) 아래에 여러 Phase가 중첩된 구조도, 로드맵 최상위 폴더만 읽어서는 하위 항목을 놓칠 수 있다. 이 구조를 빠짐없이 인식해야 진행률과 탐색이 정확하다.

**Why this priority**: 중첩 구조를 놓치면 진행률이 실제보다 낮게 계산되고, 사용자가 이미 끝낸 Phase를 못 찾는 문제로 바로 이어진다. User Story 1과 동급으로 중요하다.

**Independent Test**: 트랙-Phase 중첩 구조를 가진 로드맵 하나를 가져와서, 그 로드맵의 모든 트랙과 각 트랙 아래 모든 Phase·학습 항목이 결과에 나타나는지 원본 폴더 구조와 대조한다.

**Acceptance Scenarios**:

1. **Given** 트랙 3개, 트랙마다 Phase가 2~4개씩 있는 로드맵, **When** 가져오기를 실행하면, **Then** 모든 트랙과 그 아래 모든 Phase·학습 항목이 결과에 나타나고 누락이 0건이다.
2. **Given** 같은 로드맵, **When** 원본 폴더의 Phase 순서(파일명 문자열 정렬과 다른 논리적 순서)를 확인하면, **Then** 결과의 트랙·Phase·항목 순서가 원문의 논리적 순서와 일치한다(문자열 정렬에 의존하지 않는다).

---

### User Story 3 - 강의 자료 색인 (Priority: P2)

`courses/`에는 7,865개의 Markdown 자료가 있다. 사용자가 자료를 찾거나 로드맵이 자료를 연결할 때, 매번 전체 폴더를 순회하거나 본문 전체를 옮기지 않고 제목·경로·분류·연결된 로드맵으로 빠르게 찾을 수 있어야 한다.

**Why this priority**: 자료 탐색(F09)과 로드맵의 자료 연결(F02, F08)이 이 색인 위에서 동작한다. 다만 진행률·학습 흐름 자체보다는 지원 기능이라 P1보다 한 단계 낮다.

**Independent Test**: 색인이 만들어진 뒤, 알고 있는 자료 제목·경로로 검색해 정확히 그 자료가 나오는지, 전체 자료 수가 원본 파일 수와 일치하는지, 그리고 로드맵의 학습 항목이 가리키는 자료 연결이 실제로 해석되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `courses/` 안의 7,865개 자료, **When** 색인을 만들면, **Then** 색인에 포함된 자료 수가 원본 파일 수와 정확히 일치한다.
2. **Given** 한글, 공백, URL 인코딩이 섞인 경로를 가진 자료, **When** 그 자료를 제목으로 검색하면, **Then** 경로 해석 오류 없이 정확히 그 자료 하나가 나온다.
3. **Given** 학습 항목이 실제로 존재하는 자료를 가리키는 경우와, 존재하지 않는 자료를 가리키는 경우가 섞인 로드맵, **When** 가져오기를 실행하면, **Then** 존재하는 자료는 `linkedMaterialId`로 정확히 연결되고, 존재하지 않는 참조는 `ImportError(kind="link_broken")`로 보고되며 나머지 처리를 막지 않는다.

### User Story 4 - 예시 데이터와 실제 기록 분리 (Priority: P2)

현재 저장소의 일부 학습 기록은 과제 제출용 예시(가상) 데이터다. 실제 신규 사용자의 진도로 잘못 섞이면 "내가 이미 다 배운 것처럼" 보이는 심각한 오류가 된다. 사용자가 가져올 범위(예시 체험용 / 실제 기록)를 명확히 선택할 수 있어야 한다.

**Why this priority**: 잘못 섞이면 신뢰가 깨지는 치명적 오류지만, 정상적인 단일 가져오기 흐름(P1)이 먼저 동작해야 분리 로직을 검증할 수 있다.

**Independent Test**: 예시 데이터와 실제 기록이 함께 있는 저장소 상태에서 "실제 기록만" 범위로 가져오기를 실행한 뒤, 결과에 예시로 표시된 항목이 하나도 포함되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 예시 데이터와 실제 기록이 함께 있는 저장소, **When** 사용자가 "실제 기록만" 가져오기를 선택하면, **Then** 결과의 예시 데이터 항목 수는 0이다.
2. **Given** 같은 저장소, **When** 사용자가 "예시 체험" 범위를 선택하면, **Then** 예시 데이터는 별도 공간에 표시되고 실제 기록 공간의 진도에 영향을 주지 않는다.

---

### Edge Cases

- Phase 문서 자체가 없는 로드맵은 어떻게 처리하는가? → "진행 자료 없음"으로 구분해 보고하고, 다른 로드맵의 처리를 막지 않는다.
- Phase 문서는 있지만 체크박스 형식이 깨져 있어 집계할 수 없으면? → "형식 확인 필요"로 구분해 보류 목록에 남기고, 나머지 정상 항목은 계속 처리한다.
- Markdown 코드 블록 안에 예시로 적힌 체크박스는 어떻게 구분하는가? → 실제 목록 구조가 아닌 코드 블록 내용은 학습 항목으로 세지 않는다.
- 같은 자료가 두 로드맵에 동시에 연결되어 있을 때, 한쪽에서 완료 처리하면 다른 쪽도 완료로 바뀌는가? → 아니다, 각 로드맵의 학습 항목 완료 상태는 독립적으로 유지된다.
- 파일명 정규화 과정에서 서로 다른 두 원본이 같은 식별자로 충돌하면? → 자동으로 하나를 덮어쓰지 않고 보류 목록에 남겨 사용자에게 알린다.
- 날짜가 잘못 기록된 완료 항목(예: 미래 날짜, 파싱 불가한 형식)은 어떻게 처리하는가? → 오늘 날짜로 임의 변환하지 않고, 별도 오류 항목으로 분리해서 보고하며 나머지 정상 항목의 처리는 계속한다.
- 동일한 자료·로드맵 원본을 다시 가져올 때 이전 식별자를 못 찾으면? → 새 항목으로 만들기 전에 원본 경로·내용 해시로 기존 매핑을 다시 확인하고, 그래도 못 찾으면 신규로 처리한 뒤 그 사실을 보고한다.
- 학습 항목이 가리키는 자료 식별자가 실제 자료 목록에 없으면(예: 원문 링크가 깨졌거나 자료가 삭제됨)? → 그 학습 항목의 `linkedMaterialId`는 비워두고 `ImportError(kind="link_broken")`로 보고하며, 나머지 정상 항목의 처리는 계속한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 로드맵 디렉터리를 읽어 각 로드맵의 트랙·Phase·학습 항목을 원문의 순서를 보존한 채로 추출해야 한다(문자열 정렬에 의존하지 않는다).
- **FR-002**: 시스템은 트랙 아래에 하위 Phase가 있는 중첩 구조를 빠짐없이 인식해야 한다. 로드맵 최상위 폴더만 읽어 하위 트랙의 Phase를 누락해서는 안 된다.
- **FR-003**: 시스템은 로드맵·트랙·Phase·학습 항목 각각에 안정적인 고유 식별자를 부여해야 하며, 동일한 원본을 다시 가져와도 같은 항목은 같은 식별자를 유지해야 한다. "동일한 원본" 판정은 경로를 1차 키로 사용하고, 경로가 일치하지 않으면 내용 해시로 재확인한다(이동·이름 변경 감지).
- **FR-004**: 시스템은 파일명에 "Phase"가 포함된 문서의 체크박스만 진행률 집계 대상으로 인식하고, 부록·인덱스 문서의 체크박스는 집계 대상에서 제외해야 한다.
- **FR-005**: 시스템은 Markdown 코드 블록 안에 있는 예시 체크박스를 실제 학습 항목으로 집계하지 않아야 한다.
- **FR-006**: 시스템은 `[x]`, `[X]`, 공백이 포함된 변형 등 통상적인 체크박스 표기를 완료 상태로 해석해야 하며, 해석할 수 없는 표기는 오류 목록에 남기고 나머지 항목의 처리를 막지 않아야 한다.
- **FR-007**: 시스템은 `courses/` 안의 자료 각각에 안정적인 식별자를 부여하고, 제공처·강좌·제목·분류로 조회할 수 있는 색인을 만들어야 한다. 제공처·강좌는 경로 구조에서 추론 가능한 경우에 채우며, 추론할 수 없으면 null로 남긴다(주제 기반 검색은 이 기능의 범위가 아니다 — Assumptions 참고).
- **FR-008**: 시스템이 만드는 자료 색인은 식별자·제목·경로로 직접 접근할 수 있는 구조여야 하며, 특정 자료를 찾기 위해 매번 전체 목록을 순차 비교해야만 하는 구조로 설계하지 않아야 한다(3단계에서 이 구조를 그대로 저장소에 옮겨 쓴다).
- **FR-009**: 시스템은 상대 경로, 공백, 한글, URL 인코딩, 중첩 디렉터리, 앵커가 포함된 원본 경로를 오류 없이 해석해야 한다.
- **FR-010**: 시스템은 파일명 정규화로 서로 다른 두 원본이 같은 식별자로 충돌하는 경우를 감지해 보류 목록에 남겨야 하며, FR-003의 매칭 규칙(경로 우선·해시 재확인)으로 같은 원본임이 확인되지 않는 한 임의로 하나를 덮어써서는 안 된다.
- **FR-011**: 시스템은 예시(데모) 데이터와 실제 학습 기록을 구분해서 가져올 수 있게 하고, 사용자가 범위를 선택하기 전까지는 기본적으로 분리된 상태를 유지해야 한다.
- **FR-012**: 시스템은 동일한 원본을 다시 가져올 때 기존에 생성된 식별자와 매핑을 재사용해 같은 항목을 중복 생성하지 않아야 한다. 매칭은 FR-003의 규칙을 따른다. 경로가 같은데 내용 해시가 다르면 같은 항목의 새 버전으로 처리한다.
- **FR-013**: 시스템은 같은 자료가 여러 로드맵에 연결되어 있어도 각 로드맵의 학습 항목 완료 상태를 서로 독립적으로 유지해야 한다.
- **FR-014**: 시스템은 가져오기 처리 중 발견한 오류(날짜 오류, 깨진 링크, 해석 불가 체크박스, 식별자 충돌 후보)를 목록으로 보고하고, 오류가 있는 항목을 제외한 나머지 정상 항목의 처리는 계속해야 한다.
- **FR-015**: 시스템은 Phase 문서가 전혀 없는 로드맵과, Phase 문서는 있으나 집계 가능한 항목이 없는 로드맵을 구분해서 보고해야 한다.
- **FR-016**: 이 기능의 범위는 파싱·식별자 부여·색인 규칙의 정의와 원본 대비 정확성 검증까지다. 그 결과를 화면·API가 실시간으로 조회할 수 있는 영속 저장소에 실제로 적재하는 작업은 이 기능의 범위가 아니며, 3단계(사용자·읽기 화면)에서 이 기능이 정의한 규칙을 그대로 적용해 수행한다.

### Key Entities *(include if feature involves data)*

- **로드맵(및 버전)**: 학습 목표를 가진 독립 과목 하나. 트랙·Phase 계층을 포함하며, 수정될 때마다 버전이 남는다.
- **트랙**: 로드맵 내부의 대분류(예: 특정 학부 로드맵의 세부 전공 트랙). 하위에 여러 Phase를 포함할 수 있다.
- **Phase / 학습 항목**: Phase는 순서가 있는 학습 단계이며, 그 아래 체크박스 단위의 학습 항목을 포함한다. 각 항목은 완료 여부, 도착점, 연결된 자료 또는 산출물 과제를 가진다.
- **자료(및 자료 버전)**: `courses/`의 강의·문서 정리본 한 건. 제목, 원본 경로, 분류, 출처, 내용 해시를 가진다.
- **가져오기 배치·매핑**: 한 번의 가져오기 실행 단위. 원본 경로·내용 해시와 생성된 식별자의 연결, 발견된 오류 목록, 각 항목의 반영 상태(생성/갱신/보류)를 담는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 가져오기 실행 후 모든 로드맵의 "완료/전체" 항목 수가 원본 Markdown 체크박스 수와 100% 일치한다.
- **SC-002**: 트랙-Phase 중첩 구조를 가진 로드맵에서 하위 Phase·학습 항목의 누락이 0건이다.
- **SC-003**: `courses/`의 자료 전체(현재 7,865개)에 대해 색인에 포함된 수와 원본 파일 수가 정확히 일치한다.
- **SC-004**: 동일한 원본으로 가져오기를 두 번 실행해도 새로 생성되는 중복 항목이 0건이다.
- **SC-005**: "실제 기록만" 범위로 가져오면 결과에 포함된 예시 데이터 항목 수가 0건이다.
- **SC-006**: 한글·공백·URL 인코딩이 섞인 경로를 가진 자료 100건을 표본 검사했을 때 경로 해석 오류가 0건이다.

## Assumptions

- 로드맵·자료의 원본은 계속 파일(Markdown, `study-progress/*`, `courses/*`)이며, 이 기능은 그 파일을 읽기만 하고 원본을 고치지 않는다(구현전_결정사항.md 7.1 원칙).
- 화면에서의 진행률 표시나 브리핑 집계(F01) 자체는 이 기능 위에서 이후 단계로 구현되며, 이 기능은 그 기반이 되는 파싱·식별자 부여·색인 규칙·데이터 분리 규칙의 정의와 검증까지만 다룬다. 그 규칙을 실제 영속 저장소(SQLite 파생 캐시)에 적재하는 구현은 3단계(사용자·읽기 화면)의 범위다.
- `courses/` 자료 분류는 현재 `articles`, `deeplearning-ai`, `mooc`, `udemy`, `youtube` 5종이며, 새 분류가 추가되어도 이 기능이 동작해야 한다.
- 개인용 로컬 웹앱(단일 사용자)이므로 다중 사용자 간 데이터 격리는 이 기능의 범위 밖이다.
- "예시 데이터"의 판별 기준(어떤 파일·폴더가 과제용 가상 데이터인지)은 `사용과개선.md`에 명시된 고지를 근거로 하며, 명확히 표시되지 않은 항목은 실제 기록으로 간주한다. **구현 중 확정**: `사용과개선.md`의 고지는 산문 설명일 뿐, 실제 저장소 어떤 파일에도 기계가 읽을 수 있는 표시가 없었다. 이 규칙을 실제로 판별 가능하게 하기 위해 최소한의 표시 규약(로드맵 `README.md` 또는 특정 Phase 파일에 `<!-- scope: example -->` 주석)을 도입했다 — 지금 저장소에는 이 표시가 있는 파일이 하나도 없으므로, 현재는 `scope: "real"`이 전체를 포함하고 `scope: "example"`은 빈 결과를 반환하는 것이 정상이다(버그 아님). 실제로 예시로 구분할 로드맵이 생기면 그 파일에 이 주석을 추가하면 된다.
- 주제(topic) 기반 자료 검색은 이 기능에서 다루지 않는다. 파일 경로 구조만으로는 신뢰할 수 있는 주제 분류를 만들 수 없고, 콘텐츠 태깅 같은 별도 인프라가 필요하므로 이후 단계로 미룬다(FR-007).
