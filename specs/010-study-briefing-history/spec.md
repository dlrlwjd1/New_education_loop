## 범위와 기존 기능과의 경계

- **이미 있는 것(005 User Story 3, 다시 명세하지 않음)**: 웹에서 실행한 브리핑 스냅샷의 날짜별 목록(기준 날짜·범위·생성 시각·평균 진행률·복습 건수)과, 스냅샷 하나를 저장된 값 그대로 보여주는 상세 화면("생성 당시 값" 안내 포함), 스냅샷 불변 보장(005 FR-014·FR-015).
- **이 기능이 더하는 것**:
  1. 학습 기록(세션) 목록·조회 화면과 세션 상세 화면 — 현재 웹에는 없다.
  2. 파일에만 있는 **이전한 요약 기록** — `내학습/진행상황.md`의 기존 표 행, `내학습/브리핑로그.md`의 기존 요약 표 행 — 을 웹 기록과 구분해 열람하는 경로. 005의 브리핑 기록 목록은 웹 스냅샷만 보여주고 기존 요약 표 행은 보여주지 않는다.
  3. 브리핑 기록 목록·상세의 보강 — 이전한 요약 행의 날짜별 상세, 당시 복습 대상 수·진행 중 로드맵 수·로드맵별 진행률을 기록된 값에서 보여주기, 현재 값과의 구분 표시.
  4. 중단·마무리 대기 세션에서 009의 재개 경로로 들어가는 진입 연결.
- **이 기능이 하지 않는 것**: 세션 재개·마무리 동작(009), 복습 일정 계산(008), 브리핑 생성(005), 기록 내보내기·백업(013), 기록 수정·삭제. 이 기능은 **읽기 전용**이며 진도·복습 일정·원본 파일을 변경하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 지난 학습 기록을 날짜·로드맵·주제로 찾아보기 (Priority: P1) 🎯 MVP

사용자는 여러 로드맵(=독립된 과목)을 따로 공부하기 때문에, "지난주에 네트워크 서비스에서 뭘 했더라"를 파일을 열지 않고 확인하고 싶다. 학습 기록 화면을 열면 세션이 최신 날짜부터 나열되고, 날짜(또는 기간)·로드맵·주제로 좁혀 볼 수 있다. 각 행에는 날짜, 로드맵·주제, 상태(완료 / 중단됨 / 마무리 대기), 최초 판정 기준 정답·오답 수, 사용자 세 줄 요약의 앞부분, 그리고 이 기록이 **웹에서 생성한 상세 기록**인지 **이전한 요약 기록**인지가 표시된다.

**Why this priority**: 학습 기록이 대화가 아니라 저장소에 남는다는 것을 사용자가 처음 확인하는 화면이다. 목록이 없으면 세션 상세(US2)나 이어하기(US5)로 들어갈 입구 자체가 없다.

**Independent Test**: 웹 세션 몇 개(완료·중단됨 섞임)와 이전한 요약 행 몇 개가 있는 상태에서 목록을 열고, 날짜·로드맵·주제 조건을 각각 걸어 결과가 조건에 맞게 줄어드는지, 두 종류의 기록이 구분 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 웹 세션 3개와 이전한 요약 행 6개가 있을 때, **When** 학습 기록 목록을 열면, **Then** 9개가 날짜 최신순으로 나열되고 각 행에 "웹 상세 기록" 또는 "이전한 요약 기록" 구분이 표시된다.
2. **Given** 여러 로드맵의 기록이 섞여 있을 때, **When** 로드맵 하나를 조건으로 고르면, **Then** 그 로드맵에 연결된 기록만 남고, 로드맵을 판정할 수 없는 이전 요약 행은 "로드맵 미상"으로 따로 모아 볼 수 있다.
3. **Given** 주제 검색어 "NAT"를 입력했을 때, **When** 조회하면, **Then** 세션 주제·대상 이름 또는 이전 요약 행의 "무엇을"·"메모" 원문에 그 글자가 포함된 기록만 남는다.
4. **Given** 특정 기간을 조건으로 줬을 때, **When** 조회하면, **Then** 기록 날짜가 그 기간에 속하는 기록만 남고, 가져온 시각이나 수정 시각이 그 기간에 속하는 것만으로는 포함되지 않는다.
5. **Given** 기록이 하나도 없을 때, **When** 목록을 열면, **Then** "아직 학습 기록이 없습니다" 안내와 학습 시작으로 가는 경로가 표시되고 오류로 취급되지 않는다.
6. **Given** 조건에 맞는 기록이 없을 때, **When** 조회하면, **Then** "조건에 맞는 기록 없음"이 표시되고 기록이 아예 없는 상태와 구분된다.

### User Story 2 - 웹 세션 하나를 열어 질문·답변·판정과 그 결과를 되짚기 (Priority: P1)

사용자는 목록에서 웹 세션 하나를 열어, 그날 받은 질문과 자신이 제출한 답변, 각 답변의 판정(맞음 / 유창하지만 틀림 / 모름 / 채점 대기 / 보류)과 맞은 부분·틀린 부분을 순서대로 본다. 이어서 자신이 직접 쓴 세 줄 요약, 그 세션을 근거로 완료 처리된 학습 항목, 그 세션에서 생긴 복습 일정 변경(신규 등록, 단계 이동, 다음 복습일)을 확인한다.

**Why this priority**: F10의 핵심 사용 단계 2번이며 `design/화면-현황.md`가 "남은 과제"로 적은 "학습 기록 상세보기"다. 틀린 답을 다시 보는 것이 복습의 재료가 된다.

**Independent Test**: 정답·오답·힌트 사용·채점 재시도가 섞인 세션 하나를 끝까지 진행·마무리한 뒤, 상세 화면에 모든 질문·시도가 순서대로, 기록된 판정 그대로 나오는지, 요약·완료 항목·복습 변경이 그 세션 것만 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 질문 3개, 그중 하나는 힌트 2회 후 정답인 세션이 있을 때, **When** 상세를 열면, **Then** 질문이 제시된 순서대로, 각 질문 아래 시도가 시도 순번대로 표시되고, 받은 힌트 횟수가 함께 보인다.
2. **Given** 한 질문에 첫 시도는 "유창하지만 틀림", 재시도는 "맞음"인 기록이 있을 때, **When** 상세를 열면, **Then** 두 시도가 각각의 판정으로 따로 보이고, 세션 집계는 최초 판정(오답 1)과 재시도 결과(재시도 정답 1)를 나눠 보여준다.
3. **Given** 채점 호출 실패로 "채점 대기/재시도 가능" 상태로 남은 시도가 있을 때, **When** 상세를 열면, **Then** 그 시도는 오답이나 모름이 아니라 "채점 대기"로 표시되고 정답·오답 집계에 들어가지 않는다.
4. **Given** 세션을 마무리하며 세 줄 요약을 썼을 때, **When** 상세를 열면, **Then** 사용자가 쓴 원문 그대로 보인다. 요약 없이 끝난 세션은 "요약 없음(마무리 대기)"으로 표시되고 대신 생성된 요약이 보이지 않는다.
5. **Given** 그 세션에서 오답 1건이 복습 대상으로 신규 등록되고 기존 복습 항목 1건이 다음 단계로 이동했을 때, **When** 상세를 열면, **Then** 두 변경이 변경 전·후 단계와 다음 복습일과 함께 표시되고, 다른 세션에서 생긴 변경은 보이지 않는다.
6. **Given** 세션 이후 그 복습 항목이 다른 세션에서 또 이동했을 때, **When** 이 세션 상세를 다시 열면, **Then** 이 세션에서 일어난 당시 변경이 그대로 보이며, 현재 복습 일정을 보여준다면 "현재"로 따로 표시된다.
7. **Given** 존재하지 않는 세션 식별자로 접근했을 때, **When** 상세를 요청하면, **Then** "해당 학습 기록을 찾을 수 없습니다"로 안내하고 다른 세션을 대신 보여주지 않는다.

### User Story 3 - 이전한 요약 기록을 있는 그대로 열람하기 (Priority: P2)

웹 전환 전에 CLI에서 쌓은 학습 기록은 `내학습/진행상황.md`의 표 한 줄(날짜·무엇을·맞음/틀림·시간·메모)뿐이고 질문·답변 원문은 없다. 사용자가 이런 기록을 열면 원문 칸이 그대로 보이고, "이전한 요약 기록 — 질문·답변 원문 없음"이 분명히 표시된다. 맞음/틀림 칸처럼 숫자로 읽을 수 있는 부분만 구조화된 수치로 함께 보인다.

**Why this priority**: F10 완료 확인 기준("이전한 요약 기록과 웹에서 생성한 상세 기록을 구분해 열람")의 절반이다. 다만 사용자 데이터 대부분이 앞으로는 웹 세션으로 쌓이므로 P1 다음에 둔다.

**Independent Test**: 실제 `내학습/진행상황.md`의 현재 행(예: `1맞음(NAT) / 4틀림(초회)` 같은 섞인 표기 포함)으로 목록과 상세를 열어, 원문이 한 글자도 바뀌지 않고 보이는지, 질문·답변 칸이 비어 있다고 표시되는지, 숫자만 따로 구조화되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `| 2026-09-14 | 네트워크 서비스 로드맵 Phase 1 1-A (계층과 캡슐화) | 3맞음 / 2틀림 | 25분 | ... |` 행이 있을 때, **When** 그 기록을 열면, **Then** 다섯 칸의 원문이 그대로 보이고, 맞음 3·틀림 2·기록된 시간 25분이 구조화된 값으로 함께 보인다.
2. **Given** `1맞음(NAT) / 4틀림(초회)`처럼 괄호 설명이 섞인 칸이 있을 때, **When** 그 기록을 열면, **Then** 원문은 그대로 보존되고, 읽어낼 수 있는 숫자(맞음 1, 틀림 4)만 구조화되며, 괄호 속 설명은 원문으로만 남는다.
3. **Given** 숫자로 읽을 수 없는 칸이 있을 때, **When** 그 기록을 열면, **Then** 그 칸은 원문만 보이고 구조화 값은 "해석 불가"로 표시되며, 추정한 숫자로 채워지지 않는다.
4. **Given** 이전한 요약 기록을 열었을 때, **When** 질문·답변·판정·사용자 요약 영역을 보면, **Then** "원문 없음(이전한 요약 기록)"으로 표시되고, AI가 생성한 질문·답변·요약이 어떤 형태로도 채워져 있지 않다.
5. **Given** 이전한 요약 기록을 열었을 때, **When** 날짜 정보를 보면, **Then** 기록 날짜(표의 날짜 칸)와 가져온 시각이 따로 보이고, 가져온 시각을 학습한 날로 표시하지 않는다.

### User Story 4 - 날짜별 브리핑 기록을 당시 값 그대로 열어보기 (Priority: P2)

사용자는 브리핑 기록 목록에서 날짜를 골라, 그날 브리핑 시점의 복습 대상 수, 진행 중 로드맵 수, 로드맵별 진행률을 본다. 웹에서 실행한 브리핑(005 스냅샷)뿐 아니라 웹 전환 전에 `내학습/브리핑로그.md` 요약 표에 쌓인 기록도 같은 목록에 "이전한 요약 기록"으로 구분되어 나타나고, 그 행의 `평균 진행률` 칸은 원문 그대로 보존된 채, 로드맵별 비율처럼 읽어낼 수 있는 수치만 따로 정리돼 보인다.

**Why this priority**: 005가 웹 스냅샷 상세는 이미 제공하므로 공백은 이전한 요약 행과 날짜별 비교 보강이다. 학습 기록(US1~3)보다 판단 재료로서의 가치가 한 단계 낮다.

**Independent Test**: 실제 `내학습/브리핑로그.md`(요약 표 5행 + 웹 상세 기록 섹션)가 있는 상태에서 목록을 열어, 요약 표 행은 이전 기록으로, 웹 스냅샷은 웹 기록으로 각각 한 번씩만 나오는지, 이전 행 상세에서 `평균 진행률` 원문과 구조화 수치가 함께 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `내학습/브리핑로그.md` 요약 표에 5행이 있고 웹 스냅샷이 3건 있을 때, **When** 브리핑 기록 목록을 열면, **Then** 8건이 날짜 최신순으로 나오고 각 건에 "웹 스냅샷" 또는 "이전한 요약 기록"이 표시된다. 파일의 "상세 기록 (웹)" 섹션에 이미 적힌 웹 스냅샷은 이전 기록으로 한 번 더 나타나지 않는다.
2. **Given** `평균 진행률` 칸이 `ADsP 3.0%(4/134), 네트워크서비스 0.8%(2/251), 데브옵스 0.6%(5/799)`인 이전 행이 있을 때, **When** 상세를 열면, **Then** 원문 전체가 그대로 보이고, 로드맵 이름·비율·완료/전체 세 묶음이 구조화된 값으로 따로 보인다.
3. **Given** `평균 진행률` 칸이 `0% (학기 초)`인 이전 행이 있을 때, **When** 상세를 열면, **Then** 원문이 그대로 보이고, 로드맵 이름 없는 비율 하나는 "원문에 적힌 전체 비율"로만 구조화되며 로드맵별 값으로 꾸며지지 않는다.
4. **Given** 같은 날짜(2026-09-23)에 이전 요약 행이 2개 있을 때, **When** 목록을 열면, **Then** 두 행이 파일에 적힌 순서대로 각각 별개 기록으로 나오고, 시각 정보가 없는 행에 임의의 시각을 만들어 붙이지 않는다.
5. **Given** 이전 행의 `진행 중 로드맵 수` 칸이 `1(ADsP)`일 때, **When** 상세를 열면, **Then** 원문과 구조화 값(1)이 함께 보인다.
6. **Given** 브리핑 기록 이후 로드맵 진도가 바뀌었을 때, **When** 기록 상세를 열면, **Then** 기록된 당시 값이 그대로 보이고, 현재 값을 함께 보여준다면 "현재"라는 표시와 함께 당시 값과 분리된 영역에만 나타난다.
7. **Given** 웹 스냅샷의 범위가 특정 로드맵일 때, **When** 목록·상세를 열면, **Then** 범위가 식별자 문자열이 아니라 스냅샷에 기록된 로드맵 이름으로 표시된다.

### User Story 5 - 중단된 세션에서 이어하기로 들어가기 (Priority: P3)

사용자는 학습 기록 목록이나 세션 상세에서 "중단됨" 또는 "마무리 대기" 상태의 세션을 발견하면, "이어하기"를 눌러 그 세션이 멈춘 지점으로 돌아간다. 재개 자체(마지막 질문·답변 상태 불러오기, 요약 작성)는 009가 맡고, 이 기능은 그 입구를 제공한다.

**Why this priority**: 편의 경로다. 009의 재개 기능이 없으면 의미가 없고, 목록·상세(US1·US2)가 먼저 있어야 붙일 곳이 생긴다.

**Independent Test**: 중단된 세션 하나와 완료된 세션 하나를 준비해, 중단된 세션에만 이어하기 진입이 보이고 그것을 누르면 009의 재개 화면으로 같은 세션 식별자를 들고 이동하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "중단됨" 또는 "마무리 대기" 상태의 웹 세션이 있을 때, **When** 목록이나 상세를 보면, **Then** 그 세션에 "이어하기" 진입이 표시되고, 누르면 009의 재개 경로로 그 세션이 열린다.
2. **Given** "완료" 상태의 세션이나 이전한 요약 기록일 때, **When** 목록이나 상세를 보면, **Then** "이어하기" 진입이 표시되지 않는다.
3. **Given** 목록을 연 뒤 다른 탭에서 그 세션을 이미 마무리했을 때, **When** 이어하기를 누르면, **Then** 이 기능은 세션 상태를 직접 바꾸지 않고 009의 판단에 따르며, 이미 완료됐다는 안내 후 최신 상태의 상세로 돌아갈 수 있다.
4. **Given** 이어하기 진입을 누르기만 했을 때, **When** 기록을 확인하면, **Then** 이 기능은 세션 상태·답변·진도를 한 건도 변경하지 않았다.

### Edge Cases

- `내학습/진행상황.md` 또는 `내학습/브리핑로그.md`의 표에서 칸 수가 맞지 않거나 날짜 칸이 날짜로 읽히지 않는 행 → 그 행만 원문과 함께 "형식 확인 필요"로 분리 표시하고, 나머지 정상 행의 열람은 계속된다. 날짜를 추정해 채우지 않고 "날짜 미상"으로 둔다.
- 원본 파일 자체가 없거나 표가 없는 경우 → 이전 기록 0건으로 취급하고 웹 기록 열람은 정상 동작한다. 파일을 읽을 수 없는 오류(권한·인코딩 등)는 "이전 기록을 불러올 수 없음"으로 따로 알리고 웹 기록은 계속 보여준다.
- 사용자가 원본 파일의 이전 행을 직접 고친 경우 → 파일이 원본이므로(웹전환 명세 7.1) 다음 열람 때 고친 내용이 보이고, 그 행의 수정 시각이 갱신된다. 기록 날짜와 가져온 시각은 수정 시각과 섞이지 않는다.
- 같은 이전 행을 여러 번 다시 읽어도(서버 재시작, 파생 저장소 재생성) → 같은 기록 하나로 보이고 중복되지 않는다.
- 009가 웹 세션 마무리 때 `내학습/진행상황.md`에 남기는 한 줄 → 그 세션의 웹 상세 기록과 연결된 파일 기록으로 취급해, 이전한 요약 기록으로 한 번 더 나타나지 않는다.
- 이전 행의 "무엇을" 칸에 로드맵 이름이 여러 개 들어 있거나(예: 복습 + 다른 로드맵 진도) 로드맵 이름이 전혀 없는 경우 → 등록된 로드맵 이름과 결정적으로 일치하는 것만 연결하고(여러 개면 모두), 하나도 없으면 "로드맵 미상"으로 둔다. AI로 추정해 연결하지 않는다.
- 세션이 참조하던 로드맵·학습 항목이 이후 로드맵 수정(012)으로 사라지거나 이름이 바뀐 경우 → 세션 상세는 기록 당시의 이름을 그대로 보여주고, 현재 존재하지 않는다는 사실만 따로 표시한다. 기록이 사라지지 않는다.
- 진행 중(아직 중단·완료가 아닌) 세션 → 목록에 "진행 중"으로 표시하되 상세에는 확정된 답변·판정까지만 보여주고, 서버에 제출되지 않은 입력 초안은 보여주지 않는다.
- 판정 "보류" 또는 "채점 대기" 시도만 있는 질문 → 정답·오답 어느 쪽 집계에도 넣지 않고 따로 셈한다.
- 매우 긴 답변·요약 → 목록에서는 앞부분만 보이고 상세에서 전체가 보인다. 원문을 잘라 저장하지 않는다.
- 답변·자료 원문에 스크립트나 지시문처럼 보이는 문자열이 들어 있는 경우 → 글자 그대로 표시만 하고 실행하거나 명령으로 해석하지 않는다.
- 시간대를 바꾼 뒤 과거 기록을 보는 경우 → 기록 날짜는 기록 당시 저장된 날짜 그대로 보여주고, 새 시간대로 다시 계산해 날짜를 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**학습 기록 목록**

- **FR-001**: 시스템은 웹 학습 세션과 이전한 요약 기록을 한 목록에서 기록 날짜 최신순으로 보여줘야 한다. 같은 날짜 안에서는 웹 세션은 시작 시각 최신순, 이전 요약 행은 원본 파일에 적힌 순서를 따른다.
- **FR-002**: 시스템은 목록의 모든 기록에 출처 구분("웹 상세 기록" / "이전한 요약 기록")을 표시해야 한다.
- **FR-003**: 사용자는 기록 날짜(하루 또는 기간), 로드맵, 주제 검색어, 상태(완료 / 중단됨 / 마무리 대기 / 진행 중) 조건을 조합해 목록을 좁힐 수 있어야 한다. 날짜 조건은 기록 날짜에만 적용되고 수정 시각·가져온 시각에는 적용되지 않는다.
- **FR-004**: 주제 검색은 웹 세션의 주제·대상 이름과, 이전 요약 행의 "무엇을"·"메모" 원문을 대상으로 해야 한다.
- **FR-005**: 시스템은 이전 요약 행을 등록된 로드맵 이름과의 결정적 일치로만 로드맵에 연결해야 하며, 일치가 없으면 "로드맵 미상"으로 두고 로드맵 조건에서 따로 고를 수 있게 해야 한다. AI 추정으로 로드맵을 연결하지 않아야 한다.
- **FR-006**: 시스템은 기록이 전혀 없는 상태와, 기록은 있으나 조건에 맞는 것이 없는 상태를 구분해 안내해야 한다.
- **FR-007**: 목록의 각 웹 세션 행은 기록 날짜, 로드맵·주제, 상태, 최초 판정 기준 정답·오답 수, 사용자 요약 앞부분을 보여줘야 한다. 이전 요약 행은 기록 날짜, "무엇을" 원문, "맞음 / 틀림" 원문을 보여줘야 한다.

**세션 상세(웹 상세 기록)**

- **FR-008**: 시스템은 세션 상세에서 질문을 제시된 순서대로, 각 질문의 답변 시도를 시도 순번대로 보여줘야 하며, 각 시도에 제출 원문, 판정(맞음 / 유창하지만 틀림 / 모름 / 채점 대기 / 보류), 맞은 부분·틀린 부분, 받은 힌트 횟수를 표시해야 한다.
- **FR-009**: 시스템은 "채점 대기" 또는 "보류" 상태의 시도를 오답·모름으로 표시하거나 정답·오답 집계에 넣지 않아야 한다.
- **FR-010**: 시스템은 사용자가 작성한 세 줄 요약을 원문 그대로 보여줘야 하며, 요약이 없으면 "요약 없음"과 세션 상태를 표시하고 어떤 대체 요약도 생성·표시하지 않아야 한다.
- **FR-011**: 시스템은 그 세션을 근거로 완료 처리된 학습 항목(로드맵·Phase·항목 이름과 완료 날짜)을 보여줘야 하며, 다른 세션이나 수동 체크로 완료된 항목을 이 세션의 성과로 표시하지 않아야 한다.
- **FR-012**: 시스템은 그 세션에서 발생한 복습 일정 변경(신규 등록, 단계 이동, 교정 성공 기록, 다음 복습일 변경)을 변경 전·후 값과 함께 발생 순서대로 보여줘야 하며, 다른 세션에서 발생한 변경은 포함하지 않아야 한다.
- **FR-013**: 시스템은 세션 상세의 모든 값(판정, 집계, 완료 항목, 복습 변경, 로드맵·항목 이름)을 기록 당시 값으로 보여줘야 하며, 현재 진도·복습 일정·로드맵 구성으로 다시 계산해 바꾸어 보여주지 않아야 한다.
- **FR-014**: 시스템은 세션의 학습 시간을 보여줄 경우 009가 기록한 활동 시간을 그대로 쓰고, 그 값의 의미(활동 시간)를 함께 표시해야 한다. 기록된 값이 없으면 "기록 없음"으로 둔다.
- **FR-015**: 존재하지 않는 세션 식별자로 상세를 요청하면, 시스템은 찾을 수 없다고 안내하고 다른 세션 데이터를 대신 보여주지 않아야 한다.

**이전한 요약 기록**

- **FR-016**: 시스템은 `내학습/진행상황.md`와 `내학습/브리핑로그.md`의 기존 요약 표 행을 이전한 요약 기록으로 열람할 수 있게 해야 하며, 각 칸의 원문을 한 글자도 바꾸지 않고 보존·표시해야 한다.
- **FR-017**: 시스템은 원문 칸에서 결정적 규칙으로 읽어낼 수 있는 수치만 구조화해야 한다 — 학습 기록의 맞음 수·틀림 수·기록된 시간(분), 브리핑 기록의 밀린 복습 개수·진행 중 로드맵 수·로드맵별 비율과 완료/전체, 로드맵 이름 없이 적힌 전체 비율. 읽어낼 수 없는 부분은 "해석 불가"로 표시하고 추정값으로 채우지 않아야 한다.
- **FR-018**: 시스템은 이전한 요약 기록에 없는 상세 데이터(질문, 답변, 판정, 사용자 요약, 복습 변경, 완료 항목)를 AI나 다른 추정으로 만들어 채우지 않아야 하며, 그 영역에 "원문 없음(이전한 요약 기록)"을 표시해야 한다.
- **FR-019**: 시스템은 이전한 브리핑 요약 행의 로드맵별 비율로부터 평균 진행률을 새로 계산해 원문의 `평균 진행률` 값인 것처럼 표시하지 않아야 한다.
- **FR-020**: 시스템은 칸 수·날짜 형식이 맞지 않는 행을 그 행만 "형식 확인 필요"로 원문과 함께 분리 표시하고, 나머지 행 열람을 계속해야 한다.
- **FR-021**: 시스템은 같은 원본 행을 여러 번 읽어도 기록 하나로 식별해야 하며(서버 재시작·파생 저장소 재생성 포함), 웹 기능이 파일에 남긴 행(005의 "상세 기록 (웹)" 섹션, 009의 세션 마무리 한 줄)을 이전한 요약 기록으로 중복 표시하지 않아야 한다.
- **FR-022**: 원본 파일이 파일 쪽에서 수정되면, 시스템은 다음 열람 때 수정된 원문을 보여주고 그 기록의 수정 시각을 갱신해야 한다(웹전환 명세 7.1 "파일 우선").

**브리핑 기록 보강**

- **FR-023**: 시스템은 005의 브리핑 기록 목록에 이전한 브리핑 요약 행을 함께 보여주고, 각 건에 "웹 스냅샷" / "이전한 요약 기록" 구분을 표시해야 한다.
- **FR-024**: 시스템은 이전한 브리핑 요약 행의 날짜별 상세를 제공해야 하며, 날짜·밀린 복습 개수·진행 중 로드맵 수·평균 진행률·메모 원문과 FR-017의 구조화 수치를 함께 보여줘야 한다.
- **FR-025**: 시스템은 브리핑 기록 목록과 웹 스냅샷 상세에서 당시 복습 대상 수, 진행 중 로드맵 수, 로드맵별 진행률을 스냅샷에 저장된 값에서만 보여줘야 한다. 진행 중 로드맵 수처럼 스냅샷에 직접 없는 값은 스냅샷에 저장된 로드맵별 값에서만 도출하고 현재 진도에서 도출하지 않아야 한다.
- **FR-026**: 시스템은 웹 스냅샷의 범위가 특정 로드맵이면 식별자가 아니라 스냅샷에 기록된 로드맵 이름으로 표시해야 한다.
- **FR-027**: 이전 요약 행처럼 시각 정보가 없는 기록에 시스템은 임의의 시각을 만들어 붙이지 않아야 하며, 같은 날짜의 여러 행은 파일 순서대로 별개 기록으로 보여줘야 한다.

**현재 값과 당시 값, 이름 붙이기, 시각 필드**

- **FR-028**: 학습·브리핑 기록 상세에 현재 값(현재 진행률, 현재 복습 일정 등)을 함께 보여줄 경우, 시스템은 그것을 "현재"로 표시해 당시 값과 분리된 영역에 두어야 하며, 어떤 경우에도 저장된 과거 기록 값을 현재 값으로 덮어쓰지 않아야 한다.
- **FR-029**: 시스템은 정답 수·정답 비율을 "숙련도", "점수", "실력", "이해도"처럼 객관적 역량 지표로 읽히는 이름으로 표시하지 않아야 하며, 집계를 보여줄 때는 그 기준(예: "최초 판정 기준 · 재시도 제외", 대상 세션 범위)을 함께 표시해야 한다. 최초 판정과 재시도 결과는 분리해 집계해야 한다.
- **FR-030**: 시스템은 모든 기록에 기록 날짜(학습·브리핑이 일어난 사용자 달력 날짜), 수정 시각(기록 내용이 마지막으로 바뀐 시각), 가져온 시각(이전한 요약 기록을 처음 읽어 들인 시각, 웹 기록은 해당 없음)을 서로 다른 필드로 관리하고 상세에서 구분해 보여줘야 한다. 가져온 시각을 기록 날짜로 대신 쓰지 않아야 한다.
- **FR-031**: 시스템은 과거 기록의 기록 날짜를 사용자의 현재 시간대로 다시 계산해 바꾸지 않아야 한다.

**이어하기 진입과 읽기 전용**

- **FR-032**: 시스템은 상태가 "중단됨" 또는 "마무리 대기"인 웹 세션에만 이어하기 진입을 표시해야 하며, 그 진입은 009의 재개 경로로 해당 세션 식별자를 넘겨야 한다. 재개 가능 여부의 최종 판단은 009에 맡긴다.
- **FR-033**: 이 기능은 진도, 복습 일정, 세션 상태, 브리핑 스냅샷, 원본 파일(`내학습/*.md`, `study-progress/`)을 변경하지 않아야 한다(읽기 전용). 이전 기록의 구조화 결과는 원본에서 다시 만들 수 있는 파생 정보로만 둔다.
- **FR-034**: 시스템은 답변·요약·메모 원문을 글자 그대로 표시만 하고, 그 안의 마크업이나 지시문을 실행·해석하지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **학습 기록 항목(목록용 보기)**: 목록 한 행에 해당하는 읽기 전용 보기. 출처 구분(웹 / 이전), 기록 날짜, 로드맵 연결(여러 개 또는 미상), 주제·대상 이름, 상태, 최초 판정 정답·오답 수, 요약 앞부분, 수정 시각, 가져온 시각을 담는다. 웹 세션이면 006·009의 세션을, 이전 기록이면 이전 학습 요약 행을 가리킨다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 실제 `내학습/진행상황.md`와 `내학습/브리핑로그.md`의 기존 요약 표 행 100%가 목록에 정확히 한 번씩 나타나고, 표시되는 원문이 파일과 글자 단위로 100% 일치한다.
- **SC-002**: 이전한 요약 기록 상세에서 AI나 추정으로 만들어진 질문·답변·판정·요약·수치가 표시되는 사례가 0건이다.
- **SC-003**: 웹 스냅샷과 파일에 이미 적힌 웹 기록이 이전한 요약 기록으로 중복 표시되는 사례가 0건이다.
- **SC-004**: 기록 생성 이후 진도·복습 일정·로드맵 구성이 바뀌어도, 과거 학습·브리핑 기록 상세의 당시 값은 100% 그대로이며, 현재 값은 "현재" 표시 없이 당시 값 자리에 나타나는 사례가 0건이다.
- **SC-005**: 세션 상세에 표시되는 질문·시도·판정·힌트 횟수·복습 변경이 해당 세션에서 실제 확정된 기록과 100% 일치하고, 다른 세션의 기록이 섞이는 사례가 0건이다.
- **SC-006**: 날짜·로드맵·주제·상태 조건 조합으로 조회했을 때 조건에 맞는 기록은 빠짐없이, 맞지 않는 기록은 하나도 나오지 않는다.
- **SC-007**: 형식이 깨진 행이 섞여 있어도 정상 행의 열람 성공률은 100%이며, 깨진 행은 100% "형식 확인 필요"로 원문과 함께 표시된다.
- **SC-008**: 화면에 정답 수·정답 비율을 "숙련도·점수·실력·이해도"로 표기한 곳이 0곳이고, 집계가 보이는 모든 곳에 기준이 함께 표시된다.
- **SC-009**: 이어하기 진입이 "중단됨·마무리 대기" 세션에는 100% 표시되고 그 외 기록에는 0건 표시되며, 이 기능을 쓰는 동안 진도·복습 일정·원본 파일이 변경되는 사례가 0건이다.
- **SC-010**: 사용자는 학습 기록 화면을 연 뒤 원하는 날짜의 세션 상세에 30초 안에 도달할 수 있다.

## Assumptions

- 배포 형태는 개인용 로컬 단일 사용자 앱이다(웹전환 명세 7장 확정). F10 완료 확인의 "새로 로그인해도 기록이 남는다"는 이 환경에서 "서버 재시작·파생 저장소 재생성 뒤에도 기록이 그대로 열람된다"로 해석한다.
- 데이터 원본은 파일이고 보조 저장소는 파일에서 파생된다(웹전환 명세 7.1). 이전한 요약 기록은 원본 파일에서 읽어 구조화하며, 파생 결과는 언제든 원본에서 다시 만들 수 있다. 여기서 "가져온 시각"은 그 행을 처음 읽어 들인 시각을 뜻하고, 재생성 때는 가능한 한 최초 값을 유지하되 유지할 수 없으면 "가져온 시각 재설정됨"이 드러나도록 계획 단계에서 정한다.
- 이 기능은 별도의 "가져오기 실행" 절차(가져오기 배치 확정·오류 보고서)를 만들지 않는다. 대량 가져오기·백업·복원(013)과는 독립적으로, 열람 시점에 원본 파일을 읽는다.
- 웹 세션 데이터는 006(질문·답변·채점), 007(정교화 기록), 008(복습 사건), 009(세션 상태·요약·완료 항목·활동 시간)가 만든다. 이 기능은 그 기능들이 기록한 값을 읽기만 한다. 선행 기능 중 일부가 아직 없으면 해당 영역은 "기록 없음"으로 표시하고 나머지 영역은 정상 동작한다(예: 008 이전에는 복습 변경이 006의 신규 등록만 보인다).
- 세션 상태 이름(완료 / 중단됨 / 마무리 대기 / 진행 중)은 웹전환 명세 F07과 `design/canvas/StudyHistory.dc.html` 시안의 표기를 따른다. 정확한 상태값 정의는 009가 소유한다.
- 009가 세션 마무리 때 `내학습/진행상황.md`에 남기는 한 줄은 그 세션과 연결할 수 있는 식별 정보를 갖는다고 가정한다(CLAUDE.md "세션이 끝나면 진행상황.md에 한 줄" 규칙의 웹 버전). 연결 방식은 009와 계획 단계에서 맞춘다. 그 정보가 없는 행은 이전한 요약 기록으로 취급한다.
- 005는 웹 스냅샷을 `내학습/브리핑로그.md`의 "상세 기록 (웹)" 섹션에 적고 요약 표에는 적지 않는다(현재 파일 기준). 따라서 요약 표 행은 모두 이전한 요약 기록으로, "상세 기록 (웹)" 섹션은 이미 005 스냅샷으로 열람 가능한 것으로 본다.
- 이전 요약 행의 로드맵 연결은 등록된 로드맵 제목과, 공백을 무시한 일치 또는 "로드맵" 접미어 유무 정도의 결정적 규칙으로만 한다(예: `네트워크서비스` ↔ `네트워크 서비스 로드맵`). 구체 규칙은 계획 단계에서 정하되 AI 판단은 쓰지 않는다.
- "정답 비율" 같은 요약 집계를 목록 상단에 보여줄지는 선택 사항이다. 보여줄 경우 웹 세션의 최초 판정만 대상으로 하고(웹전환 명세 7장 "최초 판정과 재시도 분리"), 이전 요약 행의 맞음/틀림은 판정 기준이 다르므로 섞지 않는다.
- 학습 기록 내보내기(2.3절 표의 "내보내기")는 013의 범위이며 이 기능에 포함하지 않는다. 기록의 수정·삭제 기능도 두지 않는다.
- 화면 경로, 메뉴 이름, 정확한 문구는 구현 단계에서 정한다(웹전환 명세 2.3절). 기존 005 브리핑 기록 화면은 경로를 유지한 채 보강하는 것을 기본으로 한다.
