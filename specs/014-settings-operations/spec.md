## User Scenarios & Testing *(mandatory)*

### User Story 1 - AI나 저장이 실패해도 내가 쓴 답과 진행 상태가 남아 있고, 한곳에서 확인·복구하기 (Priority: P1) 🎯 MVP

학습 중에 AI 호출이 시간 초과되거나, 구독 한도에 걸리거나, 파일 저장이 실패해도 사용자가 적은 답변과 세션의 현재 단계는 사라지지 않는다. 사용자는 "운영 상태" 화면 하나에서 최근에 무엇이 실패했는지(자료 가져오기 실패, AI 오류, 저장 실패)를 보고, 각 항목에서 바로 안전한 재시도를 실행할 수 있다. 재시도는 이미 확정된 학습 기록을 덮어쓰거나 두 번 반영하지 않는다.

**Why this priority**: F12의 완료 확인 기준 자체가 "AI 또는 저장 장애가 발생해도 제출된 답변을 복구할 수 있다"이다. 006이 채점 실패를 "재시도 가능"으로 남기는 것까지는 만들었지만, 저장 실패·한도 초과·서버 재시작 중 끊긴 호출을 한곳에서 확인하고 되살리는 경로는 없다. 이것이 없으면 장애가 날 때마다 사용자는 무엇이 사라졌는지 알 수 없다.

**Independent Test**: AI 호출 실패·한도 초과·파일 쓰기 실패·AI 호출 도중 서버 재시작을 각각 인위적으로 재현한 뒤, 답변과 세션 단계가 보존되는지, 운영 상태 화면에 해당 항목이 나타나는지, 재시도 후 기록이 한 번만 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 답변을 제출했을 때, **When** AI 호출이 시간 초과·형식 오류·구독 한도 초과로 실패하면, **Then** 답변 원문과 세션 단계가 그대로 보존되고, 화면에는 실패 종류(예: "AI 응답 시간 초과", "구독 사용 한도에 도달")와 재시도 방법이 텍스트로 안내되며, 답변은 오답·모름으로 기록되지 않는다.
2. **Given** AI 호출이 진행 중일 때, **When** 서버가 재시작되면, **Then** 재시작 후 그 답변은 "재시도 가능" 상태로 표시되고 오답 처리되거나 사라지지 않는다.
3. **Given** 채점은 끝났지만 원본 파일(예: `내학습/복습큐.md`) 반영이 실패했을 때, **When** 사용자가 운영 상태 화면을 열면, **Then** 그 항목이 "저장 실패 — 파일 반영 대기"로 표시되고, 재시도를 누르면 원본 파일에 한 번만 반영된다(같은 행이 두 번 생기지 않는다).
4. **Given** 재적재(자료 가져오기) 중 일부 파일에서 오류가 났을 때, **When** 운영 상태 화면을 열면, **Then** 오류가 난 파일 위치와 오류 종류가 목록으로 보이고, 정상 파일은 그대로 조회 가능하다.
5. **Given** 운영 상태 화면에 실패 항목이 없을 때, **When** 화면을 열면, **Then** "최근 실패 없음"과 마지막 재적재 시각·AI 실행 가능 여부가 표시된다.
6. **Given** 이미 확정된 채점 결과가 있는 질문에 대해, **When** 복구 작업(재시도·재반영)이 실행되면, **Then** 확정된 판정·복습 항목·진도는 변경되지 않는다.

### User Story 2 - 시간대를 확인·변경하고, 지금 적용 중인 학습 설정 보기 (Priority: P1)

사용자는 설정 화면에서 오늘 날짜와 복습 기한을 계산하는 기준 시간대(기본 `Asia/Seoul`)를 확인하고 바꿀 수 있다. 바꾼 시간대는 저장한 뒤의 판정(오늘 날짜 계산, 새 세션, 새 브리핑)부터 적용되고, 이미 기록된 날짜(최초 오답일, 다음 복습일, 완료일, 과거 브리핑 기준 날짜)는 다시 쓰이지 않는다. 같은 화면에서 힌트 한도·복습 간격·한 세션의 신규 주제 한도처럼 지금 적용 중인 학습 규칙과 그 정책 버전을 읽기 전용으로 볼 수 있다.

**Why this priority**: 2.1절 첫 이용 순서의 2단계가 "시간대 확인"이고, 브리핑(005)·학습(006)·복습 일정(008)이 모두 "사용자 시간대의 오늘"에 의존한다. 지금은 코드 곳곳에 `Asia/Seoul`이 고정값으로 박혀 있어 사용자가 확인하거나 바꿀 방법이 없다.

**Independent Test**: 시간대를 `UTC`로 바꾼 뒤, 기존 복습 항목의 날짜 표기가 하나도 바뀌지 않았는지, 새로 연 브리핑의 기준 날짜가 `UTC` 기준 오늘로 계산되는지, 서버 재시작·재적재 후에도 설정이 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 설정을 한 번도 바꾸지 않은 상태에서, **When** 설정 화면을 열면, **Then** 시간대가 `Asia/Seoul`로 표시되고 "오늘 날짜와 복습 기한을 이 시간대 기준으로 계산합니다"라는 설명이 보인다.
2. **Given** 시간대를 `Asia/Seoul`에서 `UTC`로 바꿔 저장했을 때, **When** 복습큐·학습 기록·브리핑 기록을 열면, **Then** 이미 저장된 모든 날짜 값이 변경 전과 동일하다.
3. **Given** 시간대를 바꿔 저장한 뒤, **When** 새 브리핑을 실행하거나 새 학습 세션을 시작하면, **Then** 그 판정의 "오늘"은 새 시간대 기준으로 계산되고 그 기록에 적용된 시간대가 함께 남는다.
4. **Given** 시간대를 바꾸기 전에 시작한 학습 세션이 진행 중일 때, **When** 그 세션을 이어가면, **Then** 그 세션은 시작 시점의 시간대로 계속 판정된다.
5. **Given** 목록에 없는 문자열(예: `Seoul`, `UTC+9`)을 시간대로 입력했을 때, **When** 저장하면, **Then** 저장이 거부되고 올바른 시간대를 고르라는 안내와 함께 기존 값이 유지된다.
6. **Given** 설정 화면에서, **When** 학습 규칙 영역을 보면, **Then** 힌트 최대 횟수, 복습 간격(1·3·7·16·35일), 한 세션 신규 주제 한도, 현재 프롬프트·채점·복습 정책 버전이 표시되며 이 값들은 화면에서 편집할 수 없다.

### User Story 3 - 원본 파일을 고친 뒤 버튼 하나로, 또는 서버를 켤 때 자동으로 최신 상태 반영하기 (Priority: P2)

사용자가 텍스트 에디터나 터미널의 `/study`·`/브리핑`으로 원본 Markdown(Phase 체크박스, 복습큐)을 고친 뒤, 웹 화면에서 "원본 다시 읽기"를 누르면 최신 파일 내용이 화면에 반영된다. 서버를 켤 때 저장소가 비어 있거나, 구조 버전이 맞지 않거나, 원본 파일이 저장소보다 최신이면 자동으로 다시 읽는다. 다시 읽는 동안에도 화면은 마지막으로 성공한 상태를 보여주고, 진행 중이라는 사실을 알린다.

**Why this priority**: 002·004가 "재적재를 언제 트리거할지는 화면·운영 기능을 만들 때 정한다"고 미뤄 둔 결정이다. 지금은 적재되지 않은 상태에서 화면을 열면 "서버 관리자가 먼저 데이터 적재를 실행해야 합니다"라는 안내만 나오고, 사용자가 웹에서 할 수 있는 일이 없다. 다만 US1·US2가 없어도 명령줄 재적재로 우회할 수 있으므로 P2다.

**Independent Test**: 저장소 파일을 지우고 서버를 시작해 자동 재적재가 일어나는지, Phase 파일의 체크박스 하나를 고치고 "원본 다시 읽기"를 눌러 진행률이 정확히 바뀌는지, 재적재 중 화면이 깨진 반쪽 상태를 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 저장소가 한 번도 적재되지 않은 상태에서, **When** 서버를 시작하면, **Then** 자동으로 재적재가 시작되고, 완료 전 화면을 열면 "학습 데이터를 읽는 중" 안내가 보이며, 완료 후에는 정상 화면이 보인다.
2. **Given** 원본 Phase 파일이 저장소의 마지막 적재 이후 수정됐을 때, **When** 서버를 시작하면, **Then** 자동 재적재가 실행되어 수정 내용이 반영된다.
3. **Given** 원본 파일이 마지막 적재 이후 바뀌지 않았을 때, **When** 서버를 시작하면, **Then** 전체 재적재를 다시 실행하지 않고 기존 저장소를 그대로 쓴다.
4. **Given** 사용자가 Phase 파일의 체크박스 하나를 완료로 고쳤을 때, **When** 운영 상태(또는 설정) 화면에서 "원본 다시 읽기"를 누르면, **Then** 완료 후 해당 로드맵의 완료 수가 정확히 1 늘어나고, 마지막 재적재 시각이 갱신된다.
5. **Given** 재적재가 진행 중일 때, **When** 사용자가 "원본 다시 읽기"를 다시 누르면, **Then** 두 번째 재적재가 겹쳐 실행되지 않고 "이미 진행 중"이라고 안내된다.
6. **Given** 재적재가 오류로 중단됐을 때, **When** 화면을 열면, **Then** 재적재 전의 마지막 성공 상태가 계속 보이고, 운영 상태 화면에 실패가 기록된다.
7. **Given** 학습 세션·브리핑 기록·설정이 있을 때, **When** 재적재가 실행되면, **Then** 그 기록들은 하나도 삭제·변경되지 않는다.

### User Story 4 - 휴대전화 화면과 키보드만으로 학습 한 세션 끝내기, 어디서든 원하는 화면으로 이동하기 (Priority: P2)

사용자는 마우스 없이 키보드만으로, 또는 휴대전화 크기 화면에서 학습 세션 하나를 시작부터 결과 확인까지 끝낼 수 있다. 새 질문이 나오면 커서가 답변 입력창으로 가고, 채점 결과는 색깔만이 아니라 "맞음/틀림/모름" 글자와 기호로도 구분된다. AI가 채점하는 동안에도 입력창의 내용이 지워지거나 포커스를 빼앗기지 않는다. 모든 화면에는 같은 내비게이션이 있어 브리핑·학습·로드맵·복습큐·자료실·기록·설정으로 이동할 수 있고, 휴대전화에서는 화면 하단의 내비게이션으로 주요 화면에 닿는다.

**Why this priority**: 출시 전 확인 T21이며 5장 8단계의 통과 기준("실제 브라우저 확인")에 들어간다. 지금 공통 내비게이션에는 "로드맵"과 "자료실" 두 개만 있어, 브리핑·학습실·학습 기록으로는 주소를 직접 쳐야 갈 수 있다.

**Independent Test**: 폭 390px 화면과 키보드만(Tab/Shift+Tab/Enter/Space)으로 브리핑 → 학습 시작 → 답변 제출 → 채점 결과 확인 → 다음 질문까지 진행하고, 각 단계에서 포커스 위치·가로 스크롤·정오답 표기를 확인한다.

**Acceptance Scenarios**:

1. **Given** 키보드만 쓰는 사용자가, **When** 학습 세션 하나를 시작해 답변 제출·채점 결과 확인·다음 질문까지 진행하면, **Then** 마우스 없이 모든 단계를 완료할 수 있고, 현재 포커스된 요소가 항상 눈에 보이는 테두리로 표시된다.
2. **Given** 새 질문이 표시됐을 때, **When** 화면이 갱신되면, **Then** 포커스가 답변 입력창에 놓인다.
3. **Given** 채점 결과가 표시됐을 때, **When** 사용자가 결과를 보면, **Then** 판정은 색상 외에 판정 글자("맞음", "유창하지만 틀림", "모름")와 모양이 다른 표시로도 구분되고, 화면 낭독기에도 판정이 읽힌다.
4. **Given** 답변을 제출해 AI가 처리 중일 때, **When** 처리 중 안내가 표시되면, **Then** 입력창의 내용이 지워지지 않고, 안내가 포커스를 가로채지 않으며, 같은 버튼을 다시 눌러 중복 제출되지 않는다.
5. **Given** 폭 390px 휴대전화 화면에서, **When** 브리핑·학습실·로드맵·복습큐·자료실·설정 화면을 열면, **Then** 가로 스크롤이 생기지 않고, 터치 대상은 충분히 크며, 하단 내비게이션이 답변 입력창이나 제출 버튼을 가리지 않는다.
6. **Given** 어느 화면에 있든, **When** 내비게이션을 보면, **Then** 이미 구현된 모든 주요 화면으로 가는 링크가 같은 순서로 있고 현재 화면이 표시되며, 아직 없는 화면으로 가는 링크는 보이지 않는다.
7. **Given** 키보드 사용자가 페이지를 열었을 때, **When** 첫 Tab을 누르면, **Then** "본문으로 건너뛰기" 링크가 나타나 내비게이션을 건너뛸 수 있다.

### User Story 5 - 무엇이 언제 어떤 정책으로 실행됐는지 로그로 남기고, AI 사용량이 한도를 넘지 않게 하기 (Priority: P3)

모든 요청과 AI 호출은 요청 ID·오류 종류·소요 시간·적용된 정책 버전과 함께 운영 로그에 남는다. AI 요청·응답 원문은 로그 파일에 전량 보관되어, 채점이 이상했을 때 나중에 그대로 다시 볼 수 있다. 서버는 AI 동시 호출 수·세션당 호출 횟수·입력 크기에 상한을 두어 구독 한도를 한 번에 소진하지 않게 하고, 상한에 걸리면 입력을 보존한 채 이유를 알려준다. 인증 정보·서버 비밀정보는 브라우저 응답이나 로그 어디에도 나오지 않는다.

**Why this priority**: 장애의 원인을 나중에 찾고(헌법 원칙 V), 채점 품질을 정책 버전별로 비교하기 위한 기반이다. 단일 사용자 앱이라 즉시 사용자 가치는 US1~US4보다 작다.

**Independent Test**: 학습 세션 하나를 진행한 뒤 로그 파일에서 각 AI 호출의 요청 ID·소요 시간·정책 버전·요청/응답 원문을 찾을 수 있는지, 입력 상한을 넘는 답변과 동시 호출 상한을 넘는 요청을 보냈을 때 입력이 보존된 채 안내되는지, 브라우저가 받는 모든 응답과 로그에 인증 정보가 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 답변을 제출해 채점이 끝났을 때, **When** 운영 로그를 확인하면, **Then** 그 요청의 요청 ID, 결과(성공/오류 종류), 소요 시간, 적용된 프롬프트·채점 정책 버전이 한 항목으로 남아 있다.
2. **Given** AI 호출이 한 번 실행됐을 때, **When** AI 원문 로그를 확인하면, **Then** 그 호출에 보낸 요청 원문과 받은 응답 원문(실패 시 실패 출력)이 요청 ID로 연결되어 전량 남아 있다.
3. **Given** 채점 기록 하나가 있을 때, **When** 그 기록을 조회하면, **Then** 채점 당시의 정책 버전을 알 수 있고, 이후 정책이 바뀌어도 그 값은 바뀌지 않는다.
4. **Given** 입력 크기 상한을 넘는 답변을 제출하려 할 때, **When** 제출하면, **Then** AI를 호출하지 않고 상한과 현재 길이를 알려주며 입력 내용은 그대로 남는다.
5. **Given** 같은 세션에서 이미 AI 호출이 진행 중일 때, **When** 다른 탭에서 같은 세션에 답변을 또 제출하면, **Then** 두 번째 호출은 시작되지 않고 "처리 중인 요청이 있다"는 안내와 함께 입력이 보존된다.
6. **Given** 한 세션의 AI 호출 횟수가 상한에 도달했을 때, **When** 추가 AI 호출이 필요한 행동을 하면, **Then** 호출하지 않고 세션을 마무리하거나 새 세션으로 이어가라고 안내하며 지금까지의 진행 상태는 보존된다.
7. **Given** 어떤 화면이든, **When** 브라우저가 받은 응답과 운영 로그를 검사하면, **Then** 구독 인증 정보·토큰·서버 환경 변수 값이 포함되어 있지 않다.

### User Story 6 - 핵심 이용 순서 전체가 실제 브라우저에서 이어지는지 확인하기 (Priority: P3)

브리핑 → 학습 → 오답 → 재접속 → 복습으로 이어지는 핵심 이용 순서가 실제 브라우저에서 끊김 없이 연결된다. 단일 사용자 로컬 앱이므로 T22의 "로그인" 단계는 해당 없음으로 처리하고, 대신 "서버를 켜고 첫 화면에 들어온다"로 시작한다.

**Why this priority**: 5장 8단계의 통과 기준이자 웹 전환 완료의 마지막 확인이다. 다른 기능(005~009)이 모두 갖춰져야 끝까지 확인할 수 있으므로 가장 나중에 둔다.

**Independent Test**: 실제 브라우저(데스크톱·모바일 폭 각각)로 첫 화면 진입부터 다음 날 복습 반영까지 사람이 거치는 순서 그대로 진행하고 각 단계의 화면 상태를 기록한다.

**Acceptance Scenarios**:

1. **Given** 서버를 켜고 첫 화면에 들어왔을 때, **When** 브리핑을 실행하고 학습을 시작해 한 질문에 오답을 제출하면, **Then** 그 항목이 복습 대상으로 등록된 것이 화면에서 확인된다.
2. **Given** 오답을 남긴 뒤 브라우저를 닫았다가, **When** 다시 접속하면, **Then** 진행 중이던 세션·등록된 복습 항목이 그대로 남아 있다.
3. **Given** 그 복습 항목의 다음 복습일이 된 뒤, **When** 브리핑을 열고 복습을 시작해 정답을 제출하면, **Then** 복습 결과가 그 항목에만 반영되고 다음 복습일이 갱신된 것이 화면에서 확인된다.
4. **Given** 위 전 과정을, **When** 키보드만 쓰는 방식과 휴대전화 폭 화면에서 각각 반복하면, **Then** 두 방식 모두 같은 결과로 끝난다.

### Edge Cases

- 시간대를 바꿔 "오늘"이 하루 앞당겨지거나 늦춰지는 경우(자정 전후) → 이미 저장된 날짜는 그대로 두고, 오늘 복습 대상 여부는 새 시간대의 오늘과 저장된 날짜를 비교해 판단한다(T05). 같은 날 이미 반영한 복습이 시간대 변경만으로 다시 "오늘 대상"이 되더라도 중복 반영되지 않는다.
- 설정 저장 파일(또는 저장 위치)이 손상되거나 없는 경우 → 기본값(`Asia/Seoul`)으로 동작하고 운영 상태 화면에 "설정을 읽지 못해 기본값 사용 중"을 표시한다. 손상된 원본을 조용히 덮어쓰지 않는다.
- 재적재 도중 사용자가 학습 중이어서 원본 파일에 새 복습 항목이 쓰이는 경우 → 파일 쓰기와 재적재가 서로의 결과를 깨뜨리지 않아야 하며, 재적재 이후에도 방금 등록한 복습 항목이 조회된다.
- 재적재가 18초 이상 걸리는 동안 서버를 켜자마자 화면을 여는 경우 → 서버 시작은 재적재 완료를 기다리지 않고, 화면은 "읽는 중" 상태를 보인다.
- 구독 인증이 만료되었거나 AI 실행 도구가 설치되어 있지 않은 경우 → 학습 시작 전에 이를 알 수 있어야 하며(운영 상태 화면의 "AI 실행 가능 여부"), 학습 중에 발생하면 US1과 같이 입력을 보존한다. 읽기 전용 화면(로드맵·자료실·브리핑)은 계속 쓸 수 있다.
- 로그 파일이 매우 커지거나 디스크가 가득 찬 경우 → 로그 기록 실패가 학습 요청 자체를 실패시키지 않는다. 학습 기록 저장이 우선이며, 로그 기록 실패는 운영 상태 화면에 표시한다.
- 같은 복구 재시도를 두 번 누르거나 두 탭에서 동시에 누르는 경우 → 한 번만 반영된다.
- 운영 상태 화면의 실패 항목이 가리키는 세션·자료가 이미 삭제되었거나 이후 정상 처리된 경우 → 해당 항목을 "이미 해결됨" 또는 "대상 없음"으로 표시하고 재시도 버튼을 비활성화한다.
- 휴대전화에서 가상 키보드가 올라와 화면 높이가 줄어드는 경우 → 답변 입력창과 제출 버튼이 가상 키보드나 하단 내비게이션에 가려지지 않는다.
- 사용자가 브라우저 글자 크기를 200%로 키운 경우 → 내용이 잘리거나 겹치지 않고, 가로 스크롤 없이 읽을 수 있다.
- 같은 기기의 다른 네트워크 장치(같은 와이파이의 다른 기기)에서 접속을 시도하는 경우 → 기본 설정에서는 접속되지 않는다(인증이 없으므로 이 기기에서만 열리게 한다).

## Requirements *(mandatory)*

### Functional Requirements

**배포 형태와 범위 (T18)**

- **FR-001**: 시스템은 개인용 로컬 단일 사용자 앱으로 동작해야 하며, 로그인·계정·다중 사용자 인증·인가·사용자 간 데이터 격리 기능을 제공하지 않는다. 출시 전 확인 T18("다른 사용자의 세션·내보내기 ID 요청 시 접근 거부")은 "사용자"라는 구분 자체가 없으므로 해당 없음으로 처리하고, 그 근거(웹전환 명세 7장 배포 형태 확정)를 검증 기록에 남겨야 한다.
- **FR-002**: 인증이 없는 대신, 시스템은 기본 설정에서 이 기기 자신에게서 온 접속만 받아야 한다. 같은 네트워크의 다른 기기에서 접속을 허용하는 것은 이 기능의 범위 밖이다.

**설정 — 시간대와 학습 설정**

- **FR-003**: 시스템은 설정 화면에서 현재 시간대를 보여주고 변경할 수 있게 해야 하며, 설정을 한 번도 저장하지 않았으면 `Asia/Seoul`을 기본값으로 사용해야 한다.
- **FR-004**: 시스템은 표준 시간대 이름(IANA 시간대 목록)에 있는 값만 저장해야 하며, 그 외의 값은 거부하고 기존 값을 유지해야 한다.
- **FR-005**: 시간대를 변경해도 시스템은 이미 저장된 어떤 날짜 값(최초 오답일, 다음 복습일, 항목 완료일, 브리핑 기준 날짜, 세션 시작 시각의 표시 기준)도 다시 계산하거나 다시 쓰지 않아야 한다.
- **FR-006**: 변경된 시간대는 저장 이후 새로 시작하는 판정(새 브리핑, 새 학습 세션, 새로 계산하는 오늘 날짜)부터 적용되어야 하며, 변경 전에 시작된 학습 세션은 시작 시점의 시간대로 계속 판정되어야 한다.
- **FR-007**: 브리핑·학습 세션·복습 반영 등 "오늘"에 의존하는 모든 기능은 코드에 고정된 시간대가 아니라 이 설정 값을 사용해야 하며, 각 기록에는 그 판정에 적용된 시간대가 함께 남아야 한다.
- **FR-008**: 설정 화면은 현재 적용 중인 학습 규칙(힌트 최대 횟수, 복습 간격 단계, 한 세션 신규 주제 한도, 인터리빙 대상 수)과 현재 학습 정책 버전을 읽기 전용으로 보여줘야 한다. 이 값들은 학습 원칙(웹전환 명세 1.2)에 해당하므로 설정 화면에서 편집할 수 없어야 한다.
- **FR-009**: 설정 값은 파일에서 파생되는 캐시와 분리해 보관되어야 하며, 재적재·캐시 재생성·서버 재시작 후에도 유지되어야 한다.

**캐시 재적재 트리거**

- **FR-010**: 시스템은 서버 시작 시, 파생 저장소(002 로드맵·자료 캐시, 004 복습큐 캐시)가 비어 있거나, 구조 버전이 맞지 않거나, 원본 파일이 마지막 적재 이후 변경된 경우에만 자동으로 재적재를 실행해야 한다. 원본이 변경되지 않았으면 전체 재적재를 생략해야 한다.
- **FR-011**: 서버 시작 시의 자동 재적재는 서버가 요청을 받기 시작하는 것을 막지 않아야 하며, 재적재가 끝나기 전 요청에는 마지막 성공 상태 또는(한 번도 적재된 적이 없으면) "학습 데이터를 읽는 중" 안내를 보여줘야 한다.
- **FR-012**: 시스템은 운영 상태 화면에 "원본 다시 읽기" 수동 실행 수단을 제공해야 하며, 실행 결과(성공/실패, 처리한 로드맵·자료·복습 항목 수, 오류 목록, 완료 시각)를 보여줘야 한다.
- **FR-013**: 재적재는 한 번에 하나만 실행되어야 하며, 진행 중에 추가 요청이 오면 새로 시작하지 않고 진행 중임을 알려야 한다.
- **FR-014**: 재적재는 파일에서 파생되는 캐시만 다시 만들어야 하며, 파일에서 파생되지 않는 기록(학습 세션·답변·채점, 브리핑 기록, 설정, 운영 로그)을 삭제하거나 변경하지 않아야 한다.
- **FR-015**: 주기적 자동 재적재와 실시간 파일 변경 감시는 제공하지 않는다(002 가정 유지). 저장소가 적재되지 않았을 때 보이는 안내는 "관리자가 적재를 실행해야 한다" 대신 운영 상태 화면의 "원본 다시 읽기"로 안내해야 한다.

**운영 상태와 오류 복구**

- **FR-016**: 시스템은 운영 상태 화면에서 다음을 보여줘야 한다: 마지막 재적재 시각과 결과, 재적재(자료 가져오기) 오류 목록(파일 위치·오류 종류), 재시도 가능 상태로 남은 AI 호출(대상 세션·질문·실패 종류·발생 시각), 원본 파일 반영에 실패한 기록(대상 파일·내용 요약·발생 시각), AI 실행 가능 여부(실행 도구 존재·구독 인증 상태).
- **FR-017**: 운영 상태 화면의 각 실패 항목은 해당 항목에만 적용되는 재시도 수단을 제공해야 한다(재적재 재실행, 해당 세션으로 이동해 채점 재시도, 원본 파일 재반영).
- **FR-018**: AI 호출이 시간 초과·형식 오류·실행 불가·구독 한도 초과·서버 재시작으로 중단된 경우, 시스템은 사용자 입력과 세션의 현재 단계를 보존하고 그 답변을 오답·모름으로 기록하지 않아야 한다. 사용자에게는 실패 종류를 구분해 알려야 한다(구독 한도 초과는 "나중에 다시 시도"로, 일시적 실패는 "지금 다시 시도"로).
- **FR-019**: 서버 재시작 시, 시스템은 재시작 전에 "채점 중"이었던 답변을 모두 "재시도 가능" 상태로 전환해야 한다.
- **FR-020**: 학습 기록이 확정됐지만 원본 파일 반영이 실패한 경우, 시스템은 반영할 내용을 잃지 않고 보관해 두었다가 재시도 시 원본 파일에 한 번만 반영해야 한다.
- **FR-021**: 모든 복구 작업(채점 재시도, 원본 재반영, 재적재)은 이미 확정된 판정·복습 항목·진도·브리핑 기록을 덮어쓰지 않아야 하며, 같은 복구 요청이 중복으로 실행돼도 한 번만 반영되어야 한다.
- **FR-022**: 운영 상태 화면의 실패 항목이 이미 해결됐거나 대상이 없어진 경우, 그 상태를 표시하고 재시도를 막아야 한다.

**운영 로그**

- **FR-023**: 시스템은 모든 화면 요청과 AI 호출에 요청 ID를 부여하고, 운영 로그에 요청 ID·시각·요청 종류·결과(성공 또는 오류 종류)·소요 시간·적용된 학습 정책 버전을 한 항목으로 남겨야 한다.
- **FR-024**: 시스템은 AI 호출마다 보낸 요청 원문과 받은 응답 원문(실패 시 실패 출력 포함)을 요청 ID로 연결해 로컬 로그 파일에 전량 보관해야 한다. 이는 F12의 "개인 답변 전문을 무조건 기록하지 않는다"를 웹전환 명세 7장 확정("요청·응답 원문은 로그 파일에 전량 보관, 개인 단일 사용자라 허용")이 대체한 것이다.
- **FR-025**: 운영 로그와 AI 원문 로그에는 구독 인증 정보·토큰·서버 환경 변수 값이 기록되지 않아야 한다.
- **FR-026**: 로그 기록 실패는 학습 요청 자체를 실패시키지 않아야 하며, 운영 상태 화면에 로그 기록 실패로 표시되어야 한다.
- **FR-027**: 운영 상태 화면은 로그 요약(최근 오류 건수·종류)만 보여주고, AI 원문은 브라우저에 표시하지 않는다(원문은 로컬 로그 파일로 확인한다).

**비밀정보와 사용량 제한**

- **FR-028**: 시스템은 AI 실행에 쓰이는 구독 인증 정보와 서버 비밀정보(환경 변수, 로컬 설정 파일 경로의 민감 값)를 어떤 브라우저 응답에도 포함하지 않아야 한다. 오류 메시지에 내부 실패 출력·스택을 그대로 노출하지 않아야 한다.
- **FR-029**: 시스템은 AI 동시 호출 수에 상한을 두어야 한다 — 한 학습 세션에서는 동시에 하나만, 앱 전체에서는 기본 2건까지. 상한을 넘는 요청은 AI를 호출하지 않고 입력을 보존한 채 "처리 중인 요청이 있다"고 알려야 한다.
- **FR-030**: 시스템은 한 학습 세션의 AI 호출 횟수에 상한(기본 100회)을 두어야 하며, 상한에 도달하면 진행 상태를 보존한 채 세션을 마무리하거나 새 세션으로 이어가도록 안내해야 한다.
- **FR-031**: 시스템은 사용자 답변 1건의 길이에 상한(기본 4,000자)을 두고 이를 입력 화면에 미리 표시해야 하며, 상한을 넘으면 AI를 호출하지 않고 입력 내용을 그대로 둔 채 현재 길이와 상한을 알려야 한다. AI에 함께 보내는 학습 자료 본문에도 상한을 두어, 넘는 경우 잘라서 보냈다는 사실을 기록해야 한다.
- **FR-032**: 사용량 상한 값은 서버 설정으로 조정할 수 있어야 하며, 설정 화면에는 현재 상한 값이 읽기 전용으로 표시되어야 한다.

**학습 정책 버전**

- **FR-033**: 시스템은 프롬프트·채점·복습 정책 각각에 버전을 부여해야 하며, 정책 내용이 바뀌면 버전이 바뀌어야 한다.
- **FR-034**: 모든 채점 시도·복습 반영 기록에는 그 시점에 적용된 정책 버전이 함께 저장되어야 하며, 이후 정책이 바뀌어도 기존 기록의 버전 값은 바뀌지 않아야 한다.

**접근성·모바일**

- **FR-035**: 학습 세션 한 개(시작 → 답변 제출 → 채점 결과 확인 → 다음 질문 또는 마무리)는 키보드만으로 완료할 수 있어야 하며, 포커스된 요소는 항상 눈에 보이게 표시되어야 한다.
- **FR-036**: 새 질문이 표시되면 포커스는 답변 입력창으로 이동해야 하고, 채점 결과가 표시되면 결과가 화면 낭독기에 읽혀야 한다.
- **FR-037**: 정답·오답·모름·재시도 가능 상태는 색상 외에 글자와 모양이 다른 표시로도 구분되어야 한다.
- **FR-038**: AI 처리 중 표시는 입력창의 내용을 지우거나 포커스를 가로채지 않아야 하며, 처리 중에는 같은 제출이 반복 실행되지 않아야 한다. 이후 실시간 출력(스트리밍)을 도입하더라도 이 조건을 지켜야 한다.
- **FR-039**: 모든 화면은 폭 360px 이상의 휴대전화 화면에서 가로 스크롤 없이 이용 가능해야 하며, 터치 대상은 최소 44×44px이어야 하고, 브라우저 글자 크기 200%에서도 내용이 잘리거나 겹치지 않아야 한다.
- **FR-040**: 모든 화면은 첫 초점 이동 시 나타나는 "본문으로 건너뛰기" 링크를 제공해야 한다.

**내비게이션 정보구조**

- **FR-041**: 모든 화면은 같은 공통 내비게이션을 가져야 하며, 그 구성은 시안(`design/canvas/`)의 그룹을 따른다 — 학습 공간(브리핑, AI 학습실, 로드맵, 복습큐, 자료실), 기록(학습 기록, 브리핑 기록), 관리(설정, 운영 상태). 현재 화면은 시각적 표시와 함께 보조 기술에도 "현재 페이지"로 알려져야 한다.
- **FR-042**: 내비게이션에는 실제로 구현된 화면으로 가는 링크만 표시해야 하며, 아직 없는 화면의 링크나 안내 문구만 뜨는 링크를 두지 않아야 한다.
- **FR-043**: 휴대전화 폭에서는 주요 화면(브리핑, AI 학습실, 로드맵, 복습큐)을 하단 내비게이션으로 제공하고, 나머지 화면은 하단 내비게이션의 "더보기"로 접근할 수 있어야 한다. 하단 내비게이션은 답변 입력창·제출 버튼·페이지 마지막 내용을 가리지 않아야 한다.

**전체 흐름 확인 (T22)**

- **FR-044**: 출시 전 확인으로, 실제 브라우저에서 "서버 시작 후 첫 화면 → 브리핑 → 학습 → 오답 → 브라우저 종료 후 재접속 → 복습일에 복습"의 순서가 데스크톱 폭과 휴대전화 폭, 그리고 키보드만 쓰는 방식에서 각각 끊김 없이 이어져야 한다. T22의 로그인 단계는 FR-001에 따라 해당 없음으로 기록한다.
- **FR-045**: 이 확인은 사용자의 실제 학습 기록(`내학습/`, `study-progress/`)을 변경하지 않는 분리된 데이터로 수행해야 하며, 날짜가 지나야 하는 단계(다음 날 복습)는 기준 날짜를 조정할 수 있는 방식으로 재현해야 한다.

### Key Entities *(include if feature involves data)*

- **사용자 설정**: 시간대(기본 `Asia/Seoul`), 마지막 변경 시각. 파일에서 파생되지 않는 진짜 데이터이며 재적재로 지워지지 않는다. 단일 사용자이므로 한 벌만 존재한다.
- **학습 정책 버전**: 프롬프트·채점·복습 정책의 종류, 버전 식별자, 적용 시작 시각. 채점 시도·복습 반영 기록이 이 값을 참조한다.
- **재적재 실행 기록**: 002가 정의한 적재 실행 기록을 확장한 것으로, 실행 계기(서버 시작/수동), 시작·완료 시각, 결과, 처리 수치, 오류 목록을 담는다.
- **운영 이벤트(실패 항목)**: 종류(재적재 오류/AI 호출 실패/원본 반영 실패/로그 기록 실패/설정 읽기 실패), 대상(세션·질문·파일 위치), 발생 시각, 해결 상태(미해결/해결됨/대상 없음), 재시도에 필요한 보관 내용.
- **운영 로그 항목**: 요청 ID, 시각, 요청 종류, 결과·오류 종류, 소요 시간, 정책 버전.
- **AI 호출 원문 기록**: 요청 ID, 보낸 요청 원문, 받은 응답 원문 또는 실패 출력, 소요 시간, 자료 본문 잘림 여부.
- **사용량 상한**: 앱 전체 동시 AI 호출 상한, 세션당 동시 호출 상한, 세션당 AI 호출 횟수 상한, 답변 길이 상한, 자료 본문 상한.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: AI 시간 초과·형식 오류·구독 한도 초과·서버 재시작·원본 파일 쓰기 실패를 각각 재현한 경우 100%에서 제출된 답변 원문과 세션 단계가 보존되고, 오답·모름으로 잘못 기록되는 사례가 0건이다.
- **SC-002**: 운영 상태 화면의 재시도를 같은 항목에 두 번 이상 실행해도 원본 파일·기록에 중복 반영되는 사례가 0건이며, 이미 확정된 판정·복습 항목·진도가 바뀌는 사례가 0건이다.
- **SC-003**: 시간대를 변경한 전후로 저장된 모든 날짜 값을 비교했을 때 달라진 값이 0건이고, 변경 후 새로 만든 브리핑·세션의 기준 날짜는 100% 새 시간대의 오늘과 일치한다.
- **SC-004**: 원본 Phase 파일을 고친 뒤 "원본 다시 읽기"를 실행하면 화면의 완료 수가 실제 파일 변경과 100% 일치하고, 재적재 전후로 학습 세션·브리핑 기록·설정의 건수와 내용 변화가 0건이다.
- **SC-005**: 원본이 변경되지 않은 상태로 서버를 시작하면 전체 재적재가 실행되지 않고, 서버는 재적재 완료를 기다리지 않고 5초 안에 첫 화면 요청에 응답한다.
- **SC-006**: 키보드만으로, 그리고 폭 390px 화면에서 학습 한 세션을 마우스·가로 스크롤 없이 100% 완료할 수 있다(T21).
- **SC-007**: 정오답 표시를 흑백(색 제거)으로 보았을 때도 판정 4종(맞음·유창하지만 틀림·모름·재시도 가능)을 모두 구분할 수 있다.
- **SC-008**: 모든 구현된 화면에서 공통 내비게이션으로 다른 모든 구현된 화면에 2번 이하의 선택으로 도달할 수 있고, 존재하지 않는 화면으로 가는 링크는 0개다.
- **SC-009**: 학습 세션 하나를 진행한 뒤, 그 세션의 모든 AI 호출에 대해 요청 ID로 운영 로그 항목과 요청·응답 원문을 100% 찾을 수 있고, 브라우저 응답과 로그 어디에서도 인증 정보가 발견되는 사례가 0건이다.
- **SC-010**: 사용량 상한(동시 호출·세션당 호출 수·답변 길이)을 넘는 요청 100%가 AI를 호출하지 않고 거부되며, 그 경우 입력 내용이 사라지는 사례가 0건이다.
- **SC-011**: T22 흐름(첫 화면 → 브리핑 → 학습 → 오답 → 재접속 → 복습)이 데스크톱·휴대전화 폭·키보드 전용 세 방식 모두에서 끝까지 이어지며, 이 확인 후 사용자의 실제 학습 기록 변화는 0건이다.

## Assumptions

- **배포 형태**: 웹전환 명세 7장이 개인용 로컬 웹앱으로 확정했으므로 F12의 1·3단계(작업공간 접근, 자신의 데이터 범위)와 "다중 사용자 배포에서는 인증과 서버 측 소유권 검사가 필수", 출시 전 확인 T18은 해당 없음으로 처리한다. 인증이 없으므로 대신 "이 기기에서만 접속"(FR-002)을 최소 안전장치로 둔다. 휴대전화 화면 요구사항(FR-039·FR-043)은 실제 휴대전화 접속이 아니라 휴대전화 폭 화면에서의 이용을 뜻하며, 실제 휴대전화에서 같은 네트워크로 접속하는 기능은 인증 없이 데이터가 노출되므로 이번 범위에서 제외한다.
- **AI 원문 전량 보관**: F12의 "개인 답변 전문이나 비밀정보를 무조건 기록하지 않는다"는 7장 확정("요청·응답 원문은 로그 파일에 전량 보관한다, 개인 단일 사용자라 허용")이 대체한다. 단 "비밀정보를 기록하지 않는다"는 부분은 그대로 유지한다(FR-025). 로그 보관 기간 제한·자동 삭제는 두지 않는다(데이터량 문제 없음, 7장). 로그 파일은 개인 답변 원문을 담으므로 저장소 버전 관리(git) 대상에서 기본 제외한다.
- **비밀정보**: 7장 확정에 따라 별도 AI 제공자 API 키가 없고 로그인된 구독 인증을 그대로 쓴다. 따라서 "AI 제공자 키를 브라우저에 전달하지 않는다"는 "구독 인증 정보·서버 환경 값을 브라우저·로그에 노출하지 않는다"로 해석한다.
- **비용 제어**: 비용은 곧 기존 구독 한도(7장)이므로 금액 예산이 아니라 호출 수·동시성·입력 크기 상한으로 제어한다. 기본 상한 값(앱 전체 동시 2건, 세션당 동시 1건, 세션당 100회, 답변 4,000자)은 006의 실측(채점 1회 9~17초)과 한 세션 규모(질문 수 개 × 힌트 최대 3회 + 설명·정교화)를 고려한 초기값이며, 계획 단계에서 조정할 수 있다. 구독 자체의 한도 도달은 AI 실행 도구의 오류로만 알 수 있으므로 이를 별도 실패 종류로 구분해 안내한다.
- **기본 학습 설정**: F12 2단계의 "기본 학습 설정"은 학습 원칙(1.2)을 약화시키지 않는 범위로 한정한다. 힌트 한도·복습 간격·신규 주제 한도·인터리빙 대상 수는 7장에서 확정된 정책이므로 읽기 전용으로만 보여주고, 이번 기능에서 사용자가 편집할 수 있는 값은 시간대 하나다. 편집 가능한 학습 설정을 늘리는 것은 별도 결정이 필요하다.
- **시간대 변경 적용 시점**: 006이 이미 세션마다 시작 시점 시간대를 저장하므로, 진행 중 세션은 그 값을 유지하고 새 판정부터 새 시간대를 쓴다. 저장된 날짜는 달력 날짜 문자열 그대로 보존하고 변환하지 않는다(T05).
- **재적재 트리거**: 002·004가 미룬 재적재 시점은 "서버 시작 시(필요할 때만) + 수동 버튼"으로 정한다. 주기적 실행과 실시간 파일 감시는 제외한다 — 7.1절의 "세션 시작 시 파일을 읽어 반영"은 앱을 켤 때의 적재로 해석한다. 전체 재적재가 실측 약 18초 걸리므로(006 개발결과) 서버 시작을 막지 않고 뒤에서 실행한다. 006이 복습 항목을 쓸 때 캐시에 직접 반영하는 방식은 그대로 두며, 재적재 트리거가 이를 대체하지 않는다.
- **운영 상태 화면의 위치**: 시안 `Settings.dc.html`은 시간대·가져오기·내보내기·백업을 한 화면에 둔다. 이 기능은 시간대·학습 규칙 표시를 설정 화면에, 재적재·실패 항목·AI 실행 가능 여부를 운영 상태 화면(또는 설정 화면의 한 영역)에 두며, 정확한 화면 분할은 계획 단계에서 정한다. 시안의 "가져오기(미리보기 후 반영)"와 "내보내기·백업"은 013(데이터 내보내기·백업·복구)의 범위이며, 이 기능은 그 영역을 만들지 않는다. 013의 백업 복원도 FR-021(기존 기록 덮어쓰기 금지)을 지켜야 하지만 복원 절차 자체는 013이 정한다.
- **저장 실패의 대상**: 원본 파일 반영(복습큐·Phase 체크박스·진행상황·브리핑로그)을 다루는 기능은 006·008·009·005이다. 이 기능은 그 기능들이 실패를 운영 이벤트로 남기고 재반영할 수 있게 하는 공통 경로와 화면을 정하며, 각 파일 쓰기 규칙 자체는 해당 기능이 정한다.
- **정책 버전**: 006까지의 채점 기록에는 정책 버전이 없으므로, 이 기능 이전 기록은 "버전 기록 이전"으로 표시하고 소급해서 값을 채우지 않는다.
- **내비게이션**: 시안의 사이드바(WORKSPACE 5개 + RECORDS 2개 + 설정)를 기준으로 하고, 첫 화면을 브리핑(시안 `Main.dc.html`)으로 둘지와 각 화면의 경로 이름은 계획 단계에서 정한다. 하단 내비게이션 항목 4개 + "더보기"는 휴대전화 폭의 일반적인 수용 개수를 따른 초기값이다. 아직 구현되지 않은 화면(예: 로드맵 만들기 011)은 해당 기능이 완료될 때 내비게이션에 추가한다.
- **T22 확인 방식**: 브리핑(005)·학습(006)·복습 일정(008)·재개(009)가 완료된 뒤에 수행한다. 헌법 원칙 I·IV에 따라 실제 브라우저로 확인하며, 이전 기능 검증에서 실제 `내학습/` 파일이 오염됐던 사례(005·006 개발결과)를 고려해 분리된 데이터로 수행한다(FR-045).
- **접근성 수준**: 명시적 인증 기준 등급을 요구하지 않고, F12가 열거한 항목(휴대전화 화면, 키보드 조작, 입력창 포커스, 색상 외 정오답 표현, 출력이 입력을 방해하지 않음)과 시안이 이미 갖춘 요소(초점 테두리, 본문 건너뛰기)를 확인 가능한 조건으로 옮겼다. 터치 대상 44px, 글자 크기 200%는 일반적인 웹 접근성 관행을 따른 값이다.
