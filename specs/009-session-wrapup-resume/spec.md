# Feature Specification: 세션 마무리·진도 저장·중단 후 재개

**Feature Branch**: `[009-session-wrapup-resume]`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "009 — 세션 마무리·진도 저장·중단 후 재개 (F07). 006은 세션·질문·답변 시도를 `내학습/study-sessions.sqlite`에 저장하지만 세션을 끝내는 절차가 없다. 사용자가 세션 마무리를 선택하면 자료 없이 세 줄 요약을 직접 작성(AI가 대신 작성 금지)하고, 자료 기반 학습이면 평가를 통과한 항목만 Phase 문서 체크박스를 완료·날짜 반영한다(주제 모드가 비슷한 제목의 로드맵을 자동 체크 금지, 같은 자료가 두 로드맵에 연결돼도 한쪽 완료가 다른 쪽 진도를 자동 변경 금지 — T15). 정답·오답 집계, 주제, 로드맵·Phase, 요약, 학습 시간(긴 비활성 제외한 활동 시간)을 저장하고 `내학습/진행상황.md`에 한 줄 기록한다(파일이 원본 — 7.1, CLAUDE.md 기록 규칙). 요약 없이 나가면 '중단됨/마무리 대기' 상태, 일시 중단·새로고침·재접속 시 마지막 질문·답변 상태로 재개, 입력 초안과 제출된 답변 구분, 브라우저 종료 이벤트에만 의존 금지, 종료 요청 중복 반영 금지(T13), 종료 중 저장 실패 시 확정 기록 유지, 이미 반영한 복습 재적용 금지, 날짜 미상 가져오기 항목 보존. 항목 통과 기준(7장 확정): 근거 있는 확인 답변·산출물 검토, 최초 판정과 재시도 분리."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 세 줄 요약으로 세션을 마무리하고 기록을 남기기 (Priority: P1) 🎯 MVP

사용자가 질문 몇 개를 풀고 "세션 마무리"를 선택하면, 자료·질문·답변이 보이지 않는 화면에서 오늘 배운 것을 자기 말로 세 줄 적는다. 제출하면 이 세션의 정답·오답 집계, 주제(또는 로드맵·Phase), 요약, 학습 시간이 저장되고 `내학습/진행상황.md`에 한 줄이 추가된다. 마지막으로 저장 결과와 이번 세션에 복습큐에 등록된 항목·다음 복습일을 확인하고 끝낸다.

**Why this priority**: 006까지는 세션이 시작만 되고 끝나지 않는다. 세 줄 요약은 이 저장소 `/study` 7절이 정한 "오늘의 마지막 인출 연습"이며, `내학습/진행상황.md` 한 줄은 CLAUDE.md가 모든 세션에 요구하는 기록 규칙이다. 이것 없이는 웹에서 한 공부가 원본 파일 어디에도 남지 않는다.

**Independent Test**: 주제 모드 세션에서 정답 2개·오답 1개를 만든 뒤 마무리를 선택해 세 줄을 제출하고, 세션 상태가 "완료"로 바뀌는지, `내학습/진행상황.md` 표 맨 끝에 날짜·주제·"2맞음 / 1틀림"·활동 시간·요약이 담긴 한 줄이 정확히 하나 추가되는지, 기존 행이 한 글자도 바뀌지 않았는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 진행 중인 세션에서, **When** 사용자가 세션 마무리를 선택하면, **Then** 세 줄 요약 입력 화면이 나타나고 그 화면에는 학습 자료 본문·질문·사용자 답변·채점 결과·AI가 만든 요약 초안이 어떤 형태로도 표시되지 않는다.
2. **Given** 요약 입력 화면에서, **When** 세 줄 중 하나라도 비어 있는 채로 제출하면, **Then** 저장되지 않고 어느 줄이 비었는지 안내한다.
3. **Given** 세 줄을 모두 채워 제출했을 때, **When** 마무리가 확정되면, **Then** 세션에 정답·오답 집계, 대상(주제명 또는 로드맵·Phase·항목), 사용자 요약 원문, 활동 시간, 시작·종료 시각이 저장되고 세션 상태가 "완료"가 된다.
4. **Given** 마무리가 확정됐을 때, **When** `내학습/진행상황.md`를 열면, **Then** 표의 마지막 행 다음에 `| 날짜 | 무엇을 | N맞음 / M틀림 | K분 | 메모 |` 형식의 행이 정확히 하나 추가되어 있고, 기존 행은 변경되지 않았다.
5. **Given** 마무리가 확정됐을 때, **When** 결과 화면을 보면, **Then** 저장 완료 표시, 이번 세션의 집계, 이번 세션에서 복습큐에 새로 등록된 항목과 각 항목의 다음 복습일, 변경된 원본 파일 목록과 "커밋은 직접 수행" 안내가 보인다.
6. **Given** 요약 입력 화면에서, **When** 사용자가 요약 자동 작성·요약 제안을 요청할 수 있는 수단을 찾으면, **Then** 그런 수단은 존재하지 않는다.

### User Story 2 - 평가를 통과한 학습 항목만 Phase 체크박스에 반영하기 (Priority: P1)

로드맵 이어하기나 자료로 공부 경로로 학습한 세션을 마무리하면, 이번 세션에서 근거 있는 확인 답변(또는 산출물 검토)을 통과한 학습 항목만 해당 로드맵의 Phase 문서에서 `[x]`와 날짜로 바뀐다. 자료를 열어보기만 했거나 통과하지 못한 항목, 주제 모드 세션, 같은 자료를 공유하는 다른 로드맵의 항목은 절대 바뀌지 않는다.

**Why this priority**: Phase 문서의 체크박스는 모든 진행률(001·003·005)의 원본이다. 여기에 잘못된 완료가 한 번이라도 쓰이면 브리핑과 로드맵 화면의 숫자 전체가 거짓이 된다. User Story 1과 함께 "진도를 만드는" 핵심이라 같은 우선순위다.

**Independent Test**: 같은 자료가 연결된 로드맵 두 개를 준비하고, 한 로드맵의 Phase 항목 3개로 세션을 진행해 1개는 첫 시도에 정답, 1개는 오답 후 재인출로 정답, 1개는 오답으로 끝낸 뒤 마무리한다. 앞의 두 항목만 `[x] (날짜)`로 바뀌고, 세 번째 항목과 다른 로드맵의 같은 제목 항목, 그리고 이미 `[x]`였던 날짜 없는 항목은 그대로인지 파일 diff로 확인한다.

**Acceptance Scenarios**:

1. **Given** 로드맵 경로 세션에서 어떤 학습 항목의 확인 질문에 근거를 포함한 정답 판정을 받았을 때, **When** 세션을 마무리하면, **Then** 그 로드맵의 해당 Phase 문서에서 그 항목 한 줄만 `[x]`로 바뀌고 줄 끝에 통과한 날짜가 `(YYYY-MM-DD)` 형식으로 붙는다.
2. **Given** 첫 시도는 오답이었지만 설명 후 재인출에서 근거 있는 정답을 받은 항목이 있을 때, **When** 마무리하면, **Then** 그 항목은 통과로 반영되고, 집계에는 최초 판정(틀림)과 재시도 통과가 분리되어 기록된다.
3. **Given** 자료를 열어 읽기만 하고 확인 답변이 없거나, 확인 답변이 끝내 오답·모름으로 끝난 항목이 있을 때, **When** 마무리하면, **Then** 그 항목의 체크박스는 바뀌지 않는다.
4. **Given** 주제 모드 세션이 어떤 로드맵 항목과 제목이 같거나 비슷할 때, **When** 마무리하면, **Then** 어떤 로드맵의 어떤 체크박스도 바뀌지 않는다.
5. **Given** 같은 자료가 로드맵 A와 로드맵 B에 연결되어 있고 세션이 로드맵 A의 항목으로 시작됐을 때, **When** 마무리하면, **Then** 로드맵 A의 항목만 바뀌고 로드맵 B의 진도는 변하지 않는다.
6. **Given** 마무리 화면에서 체크박스에 반영될 항목 목록이 제시됐을 때, **When** 사용자가 그중 일부를 반영에서 제외하면, **Then** 제외한 항목은 반영되지 않는다. 통과하지 않은 항목을 사용자가 목록에 추가할 수단은 없다.
7. **Given** 이미 `[x]`인 항목(날짜가 있든 날짜 미상이든)이 이번 세션에서 다시 통과했을 때, **When** 마무리하면, **Then** 그 줄은 바뀌지 않는다 — 기존 날짜를 덮어쓰거나, 날짜 미상 항목에 오늘 날짜를 새로 붙이지 않는다.

### User Story 3 - 중단했다가 마지막 질문·답변 상태로 이어가기 (Priority: P2)

사용자가 세션 도중 일시 중단하거나, 새로고침하거나, 브라우저를 닫았다가 나중에(다른 기기에서라도) 다시 들어오면, 끝내지 않은 세션 목록에서 그 세션을 골라 마지막으로 보던 질문과 그 질문의 답변·힌트·채점 상태에서 그대로 이어간다. 제출하지 않고 쓰던 답변 초안도 초안으로 되살아난다.

**Why this priority**: 한 번에 끝까지 공부하지 못하는 것은 흔한 상황이다. 다만 006이 이미 질문·힌트·답변 시도를 서버에 저장하고 있어 "상태 보존" 자체는 상당 부분 갖춰져 있으므로, 마무리(US1·US2) 다음 순위로 둔다.

**Independent Test**: 질문 하나에 힌트를 1개 받은 상태에서 답변란에 초안을 입력하고 몇 초 기다린 뒤 창을 강제로 닫는다(종료 이벤트가 발생하지 않는 방식). 다시 접속해 미완료 세션 목록에서 세션을 열었을 때 같은 질문·힌트 1개·초안 텍스트가 복원되고, 초안이 제출된 답변이나 채점 이력으로 집계되지 않았는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 진행 중인 세션에서, **When** 사용자가 일시 중단을 선택하면, **Then** 세션 상태가 "중단됨"으로 바뀌고 학습 시작 화면의 미완료 세션 목록에 나타난다.
2. **Given** 새로고침하거나 다른 기기에서 같은 세션을 열었을 때, **When** 화면이 표시되면, **Then** 마지막 질문, 그 질문의 제출된 답변 시도·판정·힌트 횟수·채점 대기 여부가 서버에 저장된 그대로 표시된다.
3. **Given** 답변란에 제출하지 않은 초안을 입력하고 입력을 멈췄을 때, **When** 창이 종료 이벤트 없이 닫힌 뒤 다시 열면, **Then** 초안이 "제출 전 초안"으로 복원되고, 제출된 답변 목록·채점·집계에는 포함되지 않는다.
4. **Given** 사용자가 세션 도중 아무 조치 없이 떠나 일정 시간 이상 활동이 없을 때, **When** 다음에 접속하면, **Then** 그 세션은 "중단됨"으로 표시되며, 이 판단은 브라우저가 보내는 종료 신호 없이도 이루어진다.
5. **Given** 중단된 세션을 재개했을 때, **When** 이어서 답하면, **Then** 힌트 횟수·시도 순번은 이어서 증가하고 중단 전 기록이 초기화되거나 중복되지 않는다.

### User Story 4 - 요약 없이 나가도 마무리 대기로 남고, 나중에 마무리하기 (Priority: P2)

사용자가 마무리를 선택했지만 세 줄 요약을 쓰지 않고 떠나거나, "요약 없이 나가기"를 고르면 세션은 "마무리 대기"로 남는다. 체크박스 반영과 진행상황 기록은 일어나지 않는다. 나중에 돌아와 세 줄을 쓰면 그때 마무리가 확정된다.

**Why this priority**: T14(요약 없이 종료 시 항목 자동 완료 없음)를 지키는 안전장치이면서, 요약을 AI가 대신 채워 넣는 지름길을 막는 규칙이다.

**Independent Test**: 로드맵 경로 세션에서 항목 하나를 통과시킨 뒤 마무리를 선택하고 요약을 쓰지 않은 채 나간다. Phase 문서와 `내학습/진행상황.md`가 바뀌지 않았고 세션이 "마무리 대기"로 표시되는지 확인한 뒤, 다음 날 돌아와 요약을 제출했을 때 체크박스 날짜가 제출일이 아니라 통과한 날로 기록되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 마무리를 선택한 뒤 요약을 제출하지 않았을 때, **When** 사용자가 떠나거나 "요약 없이 나가기"를 고르면, **Then** 세션 상태는 "마무리 대기"이고 어떤 Phase 문서 체크박스도, `내학습/진행상황.md`도 바뀌지 않는다.
2. **Given** "마무리 대기" 세션이 있을 때, **When** 사용자가 나중에 그 세션을 열어 세 줄 요약을 제출하면, **Then** 그 시점에 마무리가 확정되고 US1·US2의 저장·반영이 한 번 수행된다.
3. **Given** 요약 없이 남은 세션이 있을 때, **When** 어떤 시간이 지나더라도, **Then** 시스템이 요약을 자동 생성하거나 세션을 자동으로 "완료" 처리하지 않는다.
4. **Given** "마무리 대기" 세션을 다른 날 확정했을 때, **When** 체크박스 날짜를 보면, **Then** 각 항목의 날짜는 그 항목이 평가를 통과한 날이며 확정한 날이 아니다.

---

### User Story 5 - 종료 도중 통신이 끊기거나 저장이 실패해도 기록이 유실·중복되지 않기 (Priority: P3)

마무리 제출 중 네트워크가 끊기거나, 두 탭에서 동시에 마무리를 누르거나, 원본 파일 쓰기 중 하나가 실패해도, 이미 확정된 답변·채점·복습 등록은 그대로 남고, 같은 마무리가 두 번 반영되어 진행상황 줄이 두 개 생기거나 복습이 두 번 적용되지 않는다.

**Why this priority**: T13 시나리오다. 드물게 일어나지만 한 번 일어나면 원본 파일이 오염되어 수작업 정리가 필요해진다. 핵심 흐름(US1~US4)이 먼저 있어야 검증할 대상이 생기므로 P3로 둔다.

**Independent Test**: 마무리 제출 요청을 같은 식별자로 두 번 보내고, 또 다른 탭에서 한 번 더 보낸 뒤 `내학습/진행상황.md`의 추가 행이 1개인지, 체크박스 변경이 1회분인지 확인한다. 이어서 Phase 문서 쓰기를 인위적으로 실패시킨 상태에서 마무리하고, 세션이 "마무리 저장 실패(재시도 가능)"로 남으며 답변·채점 기록은 그대로인지, 재시도하면 빠진 부분만 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 마무리 요청이 서버에 반영된 뒤 응답이 도착하기 전에 통신이 끊겼을 때, **When** 사용자가 재접속하거나 같은 요청을 다시 보내면, **Then** 이미 확정된 마무리 결과를 그대로 보여주고 아무것도 다시 반영하지 않는다.
2. **Given** 두 탭에서 같은 세션의 마무리를 거의 동시에 제출했을 때, **When** 둘 다 처리되면, **Then** 마무리는 한 번만 반영되고 늦은 쪽은 "이미 마무리된 세션"임을 안내받는다.
3. **Given** 마무리 중 원본 파일(Phase 문서 또는 `내학습/진행상황.md`) 쓰기가 실패했을 때, **When** 결과를 확인하면, **Then** 세션은 "마무리 저장 실패(재시도 가능)"로 표시되고, 제출된 요약·답변·채점·복습 등록은 유실되지 않으며, 어느 파일에 무엇이 반영되지 않았는지 알려준다.
4. **Given** "마무리 저장 실패" 상태에서 재시도했을 때, **When** 처리가 끝나면, **Then** 이미 반영된 부분은 다시 쓰지 않고 빠진 부분만 반영되어, 결과적으로 진행상황 행 1개·항목별 체크박스 변경 1회만 남는다.
5. **Given** 세션 도중 복습 대상 항목의 결과가 이미 복습 기록에 반영됐을 때, **When** 마무리하면, **Then** 그 복습 결과를 다시 적용하지 않고(단계가 한 번 더 오르거나 내려가지 않고), 이미 등록된 신규 오답을 다시 등록하지 않는다.
6. **Given** 이미 "완료"된 세션에, **When** 다른 탭에서 답변 제출·힌트 요청이 들어오면, **Then** 거부되고 최신 상태(완료)를 다시 조회하도록 안내한다.

### Edge Cases

- 마무리를 선택한 시점에 채점 대기/재시도 필요 상태의 답변이 남아 있으면? → 그 사실을 알리고 "먼저 재시도" 또는 "그대로 마무리"를 고르게 한다. 그대로 마무리하면 그 답변은 집계(맞음·틀림)와 항목 통과 판단에서 모두 제외되며, 오답으로 계산되지 않는다.
- 질문에 하나도 답하지 않고 마무리하면? → 요약은 작성할 수 있고 진행상황 행은 "0맞음 / 0틀림"으로 남는다. 체크박스는 어떤 것도 바뀌지 않는다.
- 사용자가 세션 도중 Phase 문서를 직접 고쳐 대상 항목 줄의 문구가 바뀌었거나 줄이 사라졌다면? → 파일을 우선한다(7.1). 해당 항목을 찾을 수 없으면 비슷한 다른 줄을 대신 체크하지 않고, "반영하지 못한 항목"으로 결과 화면에 보고한다. 나머지 항목과 진행상황 기록은 계속 처리한다.
- 대상 항목이 이미 사용자에 의해 파일에서 `[x]`로 바뀌어 있다면? → 그대로 두고 덮어쓰지 않는다.
- 자료실에서 자료만 골라 시작해 세션에 특정 로드맵 항목이 연결되지 않았다면? → 자동으로 체크하지 않는다. 마무리 화면에서 그 자료가 연결된 로드맵 항목 중 반영할 곳을 사용자가 명시적으로 고를 수 있고, 고르지 않으면 어떤 체크박스도 바뀌지 않는다. 고른 경우에도 그 로드맵 하나에만 반영된다.
- "틀린 문제는 복습큐에 등록"처럼 확인 질문이나 산출물 검토로 평가할 수 없는 안내성 항목은? → 자동 통과 대상이 아니다. 사용자가 파일에서 직접 체크할 수 있다.
- 세션이 자정을 넘기거나 여러 날에 걸쳐 재개됐다면? → 항목 완료 날짜는 각 항목이 통과한 사용자 달력 날짜(설정된 시간대, 기본 `Asia/Seoul`)이고, 진행상황 행의 날짜는 세션을 시작한 날이며, 다른 날 확정했으면 메모에 확정일을 덧붙인다.
- 긴 비활성 구간(예: 한 시간 자리 비움)이 섞인 세션은? → 그 구간은 학습 시간에서 제외된다. 화면과 기록에는 "활동 시간"으로 표시하고, 시작~종료 체류 시간을 학습 시간이라고 부르지 않는다.
- 요약 세 줄에 표 구분자(`|`)나 줄바꿈이 들어 있으면? → 진행상황 표의 행 구조가 깨지지 않도록 안전하게 변환해 기록하고, 원문은 세션 기록에 그대로 보관한다.
- 요약 한 줄이 지나치게 길면? → 줄당 길이 제한을 입력 화면에서 미리 알리고, 넘으면 제출 전에 안내한다.
- `내학습/진행상황.md`가 없거나 표 형식이 깨져 있으면? → 기존 내용을 지우거나 재작성하지 않는다. 파일이 없으면 기존 머리글 형식으로 새로 만들고, 표를 찾을 수 없으면 "마무리 저장 실패(재시도 가능)"로 두고 원인을 알린다.
- 과거에 날짜 없이 완료로 가져온 항목, 날짜 칸이 비정상인 기존 진행상황 행은? → 그대로 보존한다. 가져온 날이나 오늘 날짜로 채우지 않는다.
- 존재하지 않는 세션 식별자로 재개·마무리를 요청하면? → 오류로 안내하고 다른 세션을 대신 열지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**마무리와 세 줄 요약**

- **FR-001**: 시스템은 진행 중이거나 중단된 세션에서 사용자가 언제든 "세션 마무리"를 선택할 수 있게 해야 한다. 마무리는 사용자의 명시적 선택으로만 시작되며, 시스템이 스스로 세션을 마무리하지 않아야 한다.
- **FR-002**: 마무리를 선택하면 시스템은 세 줄 요약 입력 화면을 보여줘야 하며, 그 화면과 그 화면의 응답에는 학습 자료 본문, 이번 세션의 질문·답변·채점·힌트·설명 내용이 포함되지 않아야 한다("자료 없이" 작성).
- **FR-003**: 요약은 사용자가 직접 입력한 세 줄이어야 한다. 세 줄 모두 비어 있지 않아야 제출되며, 줄당 길이 제한은 입력 전에 안내되어야 한다.
- **FR-004**: 시스템은 사용자 요약을 AI로 생성·보완·제안하지 않아야 하며, 요약 입력란을 어떤 내용으로도 미리 채우지 않아야 한다. 제출된 요약 원문은 수정 없이 저장되어야 한다.
- **FR-005**: 세 줄 요약이 제출되어야만 세션이 "완료"로 확정되며, 체크박스 반영(FR-009~FR-016)과 진행상황 기록(FR-019~FR-021)은 이 확정 시점에만 수행되어야 한다.

**세션 상태**

- **FR-006**: 세션은 서버가 관리하는 다음 상태 중 하나를 가져야 한다: 진행 중, 중단됨, 마무리 대기(마무리를 선택했으나 요약 미제출), 마무리 저장 실패(재시도 가능), 완료. 상태 전환은 서버가 결정하며 클라이언트가 주장하는 "완료"를 그대로 받아들이지 않아야 한다.
- **FR-007**: 사용자가 요약 없이 나가거나 "요약 없이 나가기"를 선택하면 세션은 "마무리 대기"로 남아야 하며, 시간이 지나도 자동으로 "완료"가 되거나 요약이 생성되지 않아야 한다.
- **FR-008**: 활동 없이 일정 시간(비활성 기준 시간)이 지난 "진행 중" 세션은, 브라우저의 종료 신호 없이도, 다음 조회 시점에 "중단됨"으로 표시되어야 한다.

**평가 통과 항목의 진도 반영**

- **FR-009**: 시스템은 자료 기반 세션(로드맵 이어하기 또는 자료로 공부)에서만 Phase 문서 체크박스를 변경할 수 있다. 주제 모드 세션의 마무리는 어떤 로드맵의 어떤 체크박스도 변경하지 않아야 하며, 제목 유사도에 근거한 자동 매칭을 하지 않아야 한다.
- **FR-010**: 학습 항목은 이번 세션에서 그 항목에 연결된 확인 질문에 대해 근거를 포함한 "맞음" 판정을 받았거나, 산출물 항목의 경우 제출한 산출물이 검토에서 통과 판정을 받았을 때만 "통과"로 간주되어야 한다. 자료를 열람한 것, 설명을 본 것, 판정이 보류되었거나 재시도 대기인 것은 통과가 아니다.
- **FR-011**: 최초 판정이 오답·모름이었더라도 같은 세션 안에서 힌트나 설명 이후 재인출에서 근거 있는 "맞음"을 받으면 그 항목은 통과로 간주하되, 시스템은 항목별로 최초 판정과 최종(재시도) 판정을 분리해 저장해야 한다.
- **FR-012**: 체크박스 반영은 세션이 시작될 때 지정된(또는 마무리 시 사용자가 명시적으로 고른) 단 하나의 로드맵의 학습 항목에만 수행되어야 한다. 같은 자료가 다른 로드맵에도 연결되어 있어도 다른 로드맵의 진도는 변경되지 않아야 한다.
- **FR-013**: 마무리 화면은 반영 예정 항목 목록을 보여주고, 사용자는 그중 일부를 반영에서 제외할 수 있어야 한다. 통과하지 않은 항목을 반영 목록에 추가하는 수단은 제공하지 않아야 한다.
- **FR-014**: 통과 항목의 반영은 해당 Phase 문서에서 그 항목의 줄 하나만 `[ ]`에서 `[x]`로 바꾸고 줄 끝에 통과한 날(사용자 시간대 기준 달력 날짜)을 `(YYYY-MM-DD)` 형식으로 덧붙이는 것이어야 하며, 문서의 다른 부분은 바이트 단위로 보존되어야 한다.
- **FR-015**: 이미 완료(`[x]`) 상태인 항목은 날짜가 있든 없든 변경하지 않아야 한다 — 기존 날짜를 덮어쓰거나, 날짜 미상으로 가져온 항목에 오늘 날짜나 가져온 날짜를 채워 넣지 않아야 한다.
- **FR-016**: 반영 직전 원본 Phase 문서를 다시 읽어야 하며(파일이 원본 — 7.1), 대상 항목 줄을 찾을 수 없거나 문구가 바뀌었으면 다른 줄을 대신 변경하지 않고 "반영하지 못한 항목"으로 사용자에게 보고해야 한다.
- **FR-017**: 반영된 각 항목에 대해 시스템은 개인 진도 기록(항목, 완료 날짜, 근거가 된 세션·질문·판정)을 보조 저장소에 남겨야 하며, 같은 항목에 대한 진도 기록은 하나만 존재해야 한다.

**세션 기록 저장**

- **FR-018**: 마무리 확정 시 시스템은 세션별로 다음을 저장해야 한다: 경로(주제/자료/로드맵), 주제명 또는 로드맵·Phase·항목, 최초 판정 기준 맞음 수·틀림 수(모름 포함), 재시도 후 통과 수, 채점 제외(재시도 필요·보류) 수, 사용자 요약 원문, 활동 시간, 시작·종료·확정 시각, 반영된 항목 목록.
- **FR-019**: 활동 시간은 사용자의 활동(질문 표시, 입력, 제출, 결과 확인 등) 사이 간격 중 비활성 기준 시간을 넘는 구간을 제외하고 합산해야 하며, 분 단위로 기록·표시되어야 한다. 화면과 기록에서는 이를 "활동 시간"으로 부르고 체류 시간과 구분해야 한다.
- **FR-020**: 마무리 확정 시 시스템은 `내학습/진행상황.md`의 진행 표 끝에 기존 열 구성(날짜 · 무엇을 · 맞음 / 틀림 · 시간 · 메모)을 따르는 행을 정확히 하나 추가해야 한다. "무엇을"에는 주제명, 또는 자료 기반이면 로드맵명·Phase·학습한 항목을 담아야 하고, "맞음 / 틀림"은 `N맞음 / M틀림` 형식이어야 한다.
- **FR-021**: 진행상황 행의 메모에는 사용자 요약(세 줄을 한 칸에 이어 붙인 형태)과 서버가 확정한 사실(복습큐 신규 등록 수, 반영한 체크박스 수, 확정일이 시작일과 다를 때의 확정일)만 담겨야 하며, AI가 생성한 문장을 넣지 않아야 한다. 기존 행은 수정·재정렬·삭제하지 않아야 한다.
- **FR-022**: 마무리 결과 화면은 저장 완료 여부, 이번 세션 집계, 이번 세션에서 복습큐에 새로 등록된 항목과 다음 복습일, 변경된 원본 파일 목록, 반영하지 못한 항목을 보여줘야 하며, 커밋은 사용자가 직접 수행하라는 안내를 포함해야 한다(자동 커밋·푸시는 하지 않는다).

**중단 후 재개와 초안**

- **FR-023**: 시스템은 끝나지 않은 세션(진행 중·중단됨·마무리 대기·마무리 저장 실패)을 학습 시작 화면에 목록으로 보여주고, 사용자가 그중 하나를 골라 재개하거나 마무리할 수 있게 해야 한다.
- **FR-024**: 재개하면 시스템은 마지막 질문과 그 질문의 제출된 답변 시도, 판정, 힌트 횟수, 설명 표시 여부, 채점 대기 여부를 서버에 저장된 상태 그대로 복원해야 한다. 새로고침·재접속·다른 기기 접속 모두 같은 결과여야 한다.
- **FR-025**: 시스템은 제출 전 입력 초안(답변 초안, 요약 초안)을 제출된 답변과 구분해 저장해야 한다. 초안은 채점·집계·항목 통과·진행상황 기록 어디에도 포함되지 않아야 하며, 재개 시 초안으로 표시되어야 한다.
- **FR-026**: 초안과 진행 상태의 저장은 브라우저 종료 이벤트에 의존하지 않아야 한다. 초안은 입력이 멈춘 뒤 짧은 시간 안에 자동으로 저장되어, 종료 신호 없이 창이 닫혀도 마지막 자동 저장 시점까지 복원되어야 한다.

**중복 방지와 실패 처리**

- **FR-027**: 마무리 요청에는 요청 식별자가 있어야 하며, 같은 식별자의 재전송은 이미 확정된 결과를 그대로 반환하고 아무것도 다시 반영하지 않아야 한다. 같은 세션에 대한 서로 다른 마무리 요청이 경합하면 하나만 반영되고 나머지는 "이미 마무리됨"으로 안내되어야 한다.
- **FR-028**: 마무리 처리 중 일부 단계(세션 기록, 체크박스 반영, 진행상황 기록)가 실패하면, 이미 확정된 답변·채점·복습 등록·제출된 요약은 유지되어야 하고, 세션은 "마무리 저장 실패(재시도 가능)"로 남아 실패한 단계와 파일을 보고해야 한다.
- **FR-029**: 마무리 재시도는 단계별로 이미 반영된 것을 다시 반영하지 않아야 한다 — 최종적으로 진행상황 행은 세션당 하나, 체크박스 변경은 항목당 한 번이어야 한다.
- **FR-030**: 마무리 단계는 세션 도중 이미 반영된 복습 결과(복습 항목의 성공·실패 반영)를 다시 적용하지 않아야 하고, 이미 등록된 신규 오답 항목을 다시 등록하지 않아야 한다. 마무리는 복습 일정 계산 자체를 수행하지 않는다.
- **FR-031**: "완료"된 세션에 대한 답변 제출·힌트 요청·재시도 요청은 거부되어야 하며, 사용자에게 최신 상태를 다시 조회하도록 안내해야 한다.
- **FR-032**: 마무리 시점에 채점 대기·재시도 필요·판정 보류 상태의 답변이 있으면 시스템은 이를 알리고 재시도 또는 그대로 마무리를 선택하게 해야 하며, 그대로 마무리하면 그 답변은 맞음·틀림 집계와 항목 통과 판단에서 제외해야 한다.
- **FR-033**: 존재하지 않는 세션 식별자로 재개·마무리를 요청하면 오류로 안내해야 하며, 다른 세션의 데이터를 대신 보여주지 않아야 한다.
- **FR-034**: 시스템은 마무리 때 `내학습/진행상황.md`에 추가한 행의 원문을 그 세션의 마무리 처리 기록에 함께 저장해, 이후 기능(010 학습 이력)이 그 행을 해당 웹 세션과 결정적으로 연결하고 이전한 요약 기록으로 중복 표시하지 않을 수 있게 해야 한다. 행 자체의 형식(`| 날짜 | 무엇을 | N맞음 / M틀림 | K분 | 메모 |`)에는 사람이 읽기 어려운 식별 문자열을 넣지 않는다.

### Key Entities *(include if feature involves data)*

- **학습 세션(확장)**: 006의 세션에 상태(진행 중/중단됨/마무리 대기/마무리 저장 실패/완료), 마지막 활동 시각, 활동 시간, 마무리 요청 식별자, 확정 시각, 체크박스 반영 대상 로드맵(하나)이 더해진다.
- **세션 요약**: 세션에 하나. 사용자가 입력한 세 줄 원문과 제출 시각. AI가 만든 값은 들어가지 않는다.
- **세션 집계**: 최초 판정 기준 맞음·틀림 수, 재시도 통과 수, 채점 제외 수, 이번 세션 신규 복습 등록 목록.
- **항목 평가 결과**: 세션·학습 항목별로 연결된 확인 질문(또는 산출물 검토), 최초 판정, 최종 판정, 통과 여부, 통과한 날짜.
- **개인 진도 기록**: 학습 항목별 하나. 완료 상태, 완료 날짜(날짜 미상 허용), 근거 세션·판정. 가져오기로 들어온 날짜 미상 기록을 그대로 보존한다.
- **입력 초안**: 세션·질문(또는 요약) 단위의 제출 전 텍스트와 마지막 저장 시각. 제출된 답변 시도와 별개다.
- **마무리 처리 기록**: 마무리 요청 식별자, 단계별(세션 기록·체크박스 반영·진행상황 기록) 반영 여부와 실패 사유. 진행상황 기록이 반영됐다면 추가한 행의 원문(FR-034). 재시도 시 빠진 단계만 수행하는 근거가 된다.

## Assumptions

- **의존 기능**: 006(학습 핵심 루프)의 세션·질문·답변 시도·힌트 저장과 신규 오답의 복습큐 즉시 등록을 그대로 사용한다. 신규 오답 등록은 006이 채점 시점에 이미 수행하므로 이 기능은 다시 등록하지 않는다. 복습 결과의 단계 이동(1→3→7→16→35일)은 008(간격 반복 복습 일정)의 책임이며, 이 기능은 008이 세션 도중 반영한 결과를 재적용하지 않는 것만 보장한다. Phase 문서의 항목 식별과 체크박스 해석은 001(자료 이전 기반)의 규칙(Phase 파일만 대상, 코드 블록 제외, `[x]`/`[X]` 해석, 로드맵별 독립 완료 상태 — 001 FR-013)을 따르며, 반영 후 진행률 캐시 갱신은 002(영속 저장소)의 재동기화 경로를 따른다.
- **항목 통과 기준**: 웹전환 명세 7장 확정("근거 있는 확인 답변·산출물 검토, 최초 판정과 재시도 분리")을 따른다. 기존 CLI 기록(2026-09-22 "4개 모두 첫 시도는 … 재인출로 통과")처럼 같은 세션 안의 재인출 통과는 통과로 인정하되, 통계에서는 최초 판정을 기준으로 맞음·틀림을 센다. 오답으로 시작해 재인출로 통과한 항목은 체크되면서 동시에 복습큐에도 남아 있을 수 있다(기존 CLI 관행과 동일).
- **질문과 학습 항목의 연결**: 자료 기반 세션의 확인 질문은 어떤 학습 항목을 확인하는지 참조를 가져야 한다. 006의 질문에는 항목 참조가 없거나 세션 단위 대상 하나뿐이므로, 질문 단위 항목 참조를 추가하는 것은 이 기능의 범위다. 항목 참조가 없는 질문은 어떤 항목도 통과시키지 않는다.
- **산출물 항목**: `산출물:`로 시작하는 항목은 사용자가 산출물(텍스트·요약·풀이 결과 등)을 제출하고 그 검토 판정이 통과일 때만 통과한다. 산출물 제출·검토는 확인 질문과 같은 답변·채점 절차를 재사용하는 것으로 가정하며, 서버에서 코드를 실행하지 않는다(006 FR-025).
- **자료실 진입 세션**: 특정 로드맵 항목 없이 자료만으로 시작한 세션은 기본적으로 체크박스를 바꾸지 않는다. 마무리 화면에서 사용자가 그 자료가 연결된 로드맵 중 하나를 명시적으로 고를 때만 그 로드맵 항목에 반영한다(T15, "무엇을 할지는 사용자가 결정" 원칙).
- **비활성 기준 시간**: 명세에 수치가 없어 기본값을 **10분**으로 둔다. 활동 사이 간격이 10분을 넘으면 그 간격 전체를 활동 시간에서 제외한다. 같은 10분을 "진행 중 → 중단됨" 표시 판단(FR-008)에도 쓴다. AI 채점을 기다리는 시간(수십 초)은 활동으로 본다. 설정 화면에서 바꿀 수 있게 할지는 014(설정·운영·접근성)에서 다룬다.
- **초안 자동 저장 주기**: 입력이 멈춘 뒤 약 5초 이내에 서버에 저장하는 것을 기본으로 한다. 초안은 사용자 본인만 보는 로컬 기록이며, 제출 시 초안은 제출된 답변으로 대체된다.
- **요약 형식**: 세 줄 모두 필수, 줄당 최대 200자를 기본값으로 둔다. 요약의 내용 평가(AI 채점)는 하지 않는다 — 요약은 마지막 인출 연습이지 채점 대상이 아니다.
- **진행상황 행의 날짜·형식**: 날짜는 세션 시작일(사용자 시간대, 기본 `Asia/Seoul`), 시간은 `K분`, 맞음/틀림은 최초 판정 기준 `N맞음 / M틀림`이다. 재시도 통과가 있으면 메모에 "재시도 통과 N"처럼 서버가 계산한 사실로 덧붙인다. 메모에는 사용자 요약을 " / "로 이어 붙여 넣고 표 구분자는 안전하게 변환한다. 기존 CLI 행의 메모처럼 AI가 쓴 서술은 넣지 않는다.
- **체크박스 날짜**: 항목이 평가를 통과한 날(사용자 시간대 달력 날짜)이다. 마무리 확정일이 아니다. 형식은 기존 Phase 문서의 `- [x] 항목명 (YYYY-MM-DD)`를 따른다.
- **파일과 보조 저장소의 관계**: 웹전환 명세 7.1에 따라 원본은 Phase 문서와 `내학습/진행상황.md`이고, 세션·요약·초안·마무리 처리 기록은 006의 전용 보조 저장소에 둔다. 확정 전 이벤트는 보조 저장소에 먼저 기록하고 확정 시 파일에 써낸다. 파일이 더 최신이면(사용자 직접 수정) 파일을 우선한다.
- **브리핑 로그**: 이 기능은 `내학습/브리핑로그.md`를 쓰지 않는다(005 브리핑의 책임). 학습 이력 화면에서 세션 기록을 상세 조회하는 것은 010(학습 이력·브리핑 이력 상세)의 범위다.
- **자동 커밋 없음**: CLAUDE.md는 세션 후 커밋을 권하지만, 웹전환 명세 7장 확정(GitHub 자동 동기화 제외)에 따라 웹앱은 변경 파일 목록과 안내만 보여주고 커밋·푸시는 하지 않는다.
- **세션 폐기·삭제**: 끝나지 않은 세션을 삭제하는 기능은 이 범위에 넣지 않는다. 원치 않는 세션은 "마무리 대기"로 남겨 둘 수 있다.
- **배포 형태**: 개인용 로컬 단일 사용자 앱(웹전환 명세 7장 확정). 다른 기기 접속은 같은 로컬 서버에 다른 브라우저로 접속하는 경우를 뜻하며, 다중 사용자 인증·권한은 범위 밖이다.
