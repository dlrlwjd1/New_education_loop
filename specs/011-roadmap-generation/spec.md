**Status**: Draft

AI 실행: Claude Code 헤드리스(`claude -p`)를 도구 차단 상태로 — 006과 동일, 자료 속 지시문은 데이터로 취급. 로드맵을 새로 만드는 결정은 사용자가 한다(CLAUDE.md). 미결정: AI 자동 처리 구간(3~4단계) 진행 중 이탈 시 처음부터 다시 시작 vs 이어서 완료 알림."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가진 자료를 넣고 로드맵을 끝까지 만들어 받기 (Priority: P1) 🎯 MVP

사용자가 강의 노트 파일을 올리거나 강의 페이지 링크를 붙여 넣으면, 서버가 그 자료를 읽어 자료마다 "정리된 학습 포인트"를 보여준다. 사용자가 "로드맵 만들기 시작"을 누르면 그 뒤로는 화면마다 멈춰 승인을 받지 않고, 진행률(%)만 보여주면서 필요 지식 정리 → Phase 구성과 Phase별 도착점 → 자료 연결 → 자료 없는 항목의 산출물 과제 제안까지 이어서 처리한다. 끝나면 목표·Phase·학습 항목·연결 자료·진행률 0%가 담긴 완성 로드맵이 표시되고, 이 시점에 저장이 최종 확정된다.

**Why this priority**: F08의 기본 경로이자 이 기능의 존재 이유다. 지금까지 새 로드맵은 터미널의 `/roadmap` 스킬로만 만들 수 있었다 — 이 경로가 웹에서 동작해야 5장 7단계("로드맵 작성")가 성립한다.

**Independent Test**: 실제 파일 하나와 접근 가능한 URL 하나를 넣어 학습 포인트가 표시되는지 확인하고, "로드맵 만들기 시작" 이후 추가 입력 없이 진행률이 0%에서 100%까지 올라가 완성 로드맵이 표시되는지, 그리고 `study-progress/` 아래에 새 로드맵 폴더가 생겼는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로드맵 만들기 화면에서, **When** 사용자가 파일을 올리거나 URL을 추가하면, **Then** "추가된 자료" 목록에 그 자료가 나타나고 자료별 상태(추가됨 / 읽는 중 / 정리 완료 / 실패)가 표시된다.
2. **Given** 자료 하나가 "정리 완료" 상태가 되면, **When** 사용자가 그 자료를 보면, **Then** 그 자료에서 뽑은 학습 포인트 목록이 자료별로 구분되어 표시된다.
3. **Given** 정리 완료된 자료가 하나 이상 있을 때, **When** 사용자가 "로드맵 만들기 시작"을 누르면, **Then** 생성 중 화면으로 바뀌고 진행률(%)만 표시되며, 필요 지식·Phase·자료 연결 결과를 중간에 하나씩 보여주며 승인을 요구하는 화면은 나타나지 않는다.
4. **Given** 자동 처리가 끝났을 때, **When** 완성 화면이 표시되면, **Then** 로드맵 이름, 도착점(한 문장), Phase 목록(각 Phase의 도착점 포함), Phase별 학습 항목(연결된 자료 또는 산출물 과제), 진행률 0%, "N개 Phase · N개 항목" 요약이 함께 보인다.
5. **Given** 완성 화면이 표시됐을 때, **When** 사용자가 결과를 확인하면, **Then** 그 로드맵은 이미 저장된 상태이며, 결과가 마음에 들지 않을 때 생성 과정을 다시 여는 대신 로드맵 수정(012)으로 이동할 수 있는 경로가 안내된다.
6. **Given** 사용자가 "로드맵 만들기 시작"을 누르지 않았을 때, **When** 자료만 추가하고 화면을 떠나면, **Then** 어떤 로드맵도 `study-progress/`에 만들어지지 않는다(로드맵을 새로 만드는 결정은 사용자가 한다).

### User Story 2 - 저장된 로드맵이 기존 로드맵과 똑같이 학습·브리핑에 쓰이고, 가짜 자료는 저장되지 않기 (Priority: P1)

완성된 로드맵은 기존 로드맵과 같은 형식의 파일로 `study-progress/<새 로드맵>/`에 저장되어, 로드맵 목록·상세(003), 브리핑(005), 학습 시작(006)에서 기존 로드맵과 구분 없이 쓰인다. 저장 직전 서버는 모든 자료 연결이 실제로 존재하는 자료를 가리키는지 확인하고, AI가 지어낸 경로나 존재하지 않는 자료는 저장하지 않는다.

**Why this priority**: 파일로 저장되지 않거나 기존 파싱 규칙(001)을 통과하지 못하면, 만든 로드맵으로 공부도 브리핑도 할 수 없다 — User Story 1의 결과가 쓸모 있으려면 이 보장이 함께 있어야 한다. 가짜 경로 차단은 F08이 "검증 없이 그대로 저장하지 않는다"로 명시한 안전장치다.

**Independent Test**: AI 응답을 모킹해 실제 자료 경로·존재하지 않는 자료 경로·저장소 밖을 가리키는 경로를 섞은 결과로 저장을 시도하고, 존재하지 않는 참조가 하나도 파일에 남지 않는지 확인한다. 이어 저장된 로드맵을 다시 적재했을 때 오류 0건으로 인식되고, 로드맵 목록·브리핑·학습 시작에서 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 완성 로드맵이 저장됐을 때, **When** 로드맵 목록을 열면, **Then** 새 로드맵이 진행률 0%(미시작)로 나타나고, 상세 화면에서 Phase와 학습 항목이 생성 결과와 같은 순서로 보인다.
2. **Given** 새 로드맵이 저장된 뒤, **When** 브리핑을 실행하면, **Then** 새 로드맵이 다른 로드맵과 같은 방식으로 진행률 집계에 포함된다.
3. **Given** 새 로드맵이 저장된 뒤, **When** 학습 시작에서 "로드맵 이어하기"로 그 로드맵을 고르면, **Then** 첫 번째 미완료 학습 항목으로 학습이 시작된다.
4. **Given** AI가 자료 연결 후보로 존재하지 않는 자료 경로를 제안했을 때, **When** 서버가 저장 전 검증을 하면, **Then** 그 경로는 파일에 쓰이지 않고 해당 학습 항목은 산출물 과제로 대체되며, 대체된 개수가 완성 화면에 표시된다.
5. **Given** 저장된 로드맵 파일, **When** 기존 가져오기 규칙(001)으로 다시 읽으면, **Then** 그 로드맵에 대해 깨진 링크·해석 불가 체크박스 등 오류가 0건이다.
6. **Given** 생성된 로드맵 이름이 이미 있는 로드맵 폴더와 같을 때, **When** 저장하면, **Then** 기존 폴더를 덮어쓰지 않고 구분되는 새 이름으로 저장되며 그 이름이 사용자에게 표시된다.

### User Story 3 - 자료 없이 목표만 적어서 로드맵 만들기 (Priority: P2)

넣을 자료가 없거나 원치 않는 사용자는 "자료 없이 목표만 적을게요"로 전환해, 완주 후 직접 만들 수 있어야 하는 결과물을 한 문장으로 적고, 이미 아는 것·처음인 것·주당 학습 시간·목표 기한을 입력한다. "로드맵 만들기 시작" 이후는 User Story 1과 같은 자동 처리 구간으로 합류한다.

**Why this priority**: 보조 경로다. 자동 처리·저장 구간은 User Story 1과 공유하므로, 기본 경로가 동작한 뒤 입력 단계만 추가하면 된다.

**Independent Test**: 자료를 하나도 넣지 않고 목표 경로로 전환해 네 항목을 입력한 뒤 생성을 시작하고, 자료 경로와 같은 진행률 화면·완성 화면·저장 결과가 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로드맵 만들기 화면에서, **When** 사용자가 "자료 없이 목표만 적을게요"를 누르면, **Then** 결과물 한 문장, 이미 아는 것, 처음인 것, 주당 학습 시간, 목표 기한을 입력하는 폼으로 전환된다.
2. **Given** 목표 입력 폼에서, **When** 결과물 문장을 비워 두고 시작하려 하면, **Then** 시작이 막히고 결과물 문장이 필요하다는 안내가 표시된다.
3. **Given** 결과물 문장 입력란, **When** 사용자가 입력을 시작하기 전에, **Then** "이해한다"가 아니라 직접 만들 수 있는 결과물로 적으라는 안내와 좋은 예·나쁜 예가 보인다.
4. **Given** 네 항목을 입력하고 "로드맵 만들기 시작"을 누르면, **When** 자동 처리가 끝나면, **Then** 자료 경로와 동일한 형식의 완성 로드맵이 표시·저장되고, 로드맵 README의 도착점·출발점·제약·기한에 사용자가 입력한 값이 반영된다.
5. **Given** 목표 경로로 전환한 뒤, **When** 사용자가 다시 자료 경로로 돌아가면, **Then** 앞서 추가했던 자료 목록은 사라지지 않고 그대로 남아 있다.

### User Story 4 - 이미 있는 자료를 빠짐없이 찾아 연결하고, 없으면 산출물 과제로 채우기 (Priority: P2)

자동 처리 중 자료 연결 단계는 사용자가 넣은 자료를 우선 후보로 포함하고, 기존 로드맵들에 이미 매핑된 같은 항목을 재사용하며, 자료실 전체 카탈로그를 확인한 뒤에야 "적합한 자료 없음"으로 판단한다. 적합한 자료가 없는 항목은 비워 두지 않고 사용자가 직접 만들 산출물 과제로 채운다.

**Why this priority**: 기존 `/roadmap` 스킬이 "전체 목록 훑기를 건너뛰면 이미 있는 자료를 없음으로 처리하게 된다"고 경고한 실패를 막는 규칙이다. 로드맵이 만들어지는 것(P1) 자체보다는 품질 규칙이라 한 단계 낮다.

**Independent Test**: 자료실에 특정 항목과 정확히 맞는 자료가 있지만 단순 키워드 검색의 상위 결과에는 나오지 않는 픽스처를 준비하고, 생성 결과에서 그 자료가 연결되는지 확인한다. 기존 로드맵에 이미 매핑된 항목이 새 로드맵에서도 같은 자료로 연결되는지, 어떤 자료와도 맞지 않는 항목이 빈칸이 아니라 산출물 과제로 채워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 자료 경로에서 넣은 자료, **When** 자료 연결이 수행되면, **Then** 그 자료는 자동으로 연결 후보에 포함되고, 그 자료에서 나온 학습 포인트에 해당하는 항목에는 그 자료가 연결된다.
2. **Given** 기존 로드맵에서 같은 학습 항목이 이미 특정 자료에 연결돼 있을 때, **When** 새 로드맵에 같은 항목이 생기면, **Then** 그 기존 매핑이 재사용된다.
3. **Given** 적합한 자료가 자료실에 있지만 키워드 검색 상위 몇 개 안에는 나오지 않을 때, **When** 자료 연결이 수행되면, **Then** 시스템은 전체 카탈로그를 확인한 뒤 판단하며 상위 결과만 보고 "자료 없음"으로 처리하지 않는다.
4. **Given** 어떤 자료와도 맞지 않는 학습 항목, **When** 완성 로드맵이 만들어지면, **Then** 그 항목은 "산출물:"로 시작하는 직접 만들 결과물 과제로 채워지고 빈 항목으로 남지 않는다.
5. **Given** 산출물 과제, **When** 내용을 보면, **Then** 과제는 사용자가 직접 만들어 볼 것을 제시할 뿐 과제의 정답·완성 코드를 담고 있지 않다.

### User Story 5 - 잘못된 URL·파일은 넣는 순간 이유와 함께 거절되기 (Priority: P2)

사용자가 넣은 URL이 허용되지 않는 형식이거나, 접근할 수 없거나, 너무 크거나, 응답이 너무 느리면 시스템은 그 자료를 조용히 건너뛰지 않고 이유를 알려준다. 파일도 지원하지 않는 형식이거나 너무 크면 같은 방식으로 안내한다. 실패한 자료가 있어도 나머지 자료로 계속 진행할 수 있다.

**Why this priority**: 등록되지 않은 임의 URL을 서버가 대신 읽는 기능이라 입력 검증이 없으면 안전하지 않다(F08 개발 시 주의점). 다만 정상 경로가 먼저 동작해야 검증할 대상이 생긴다.

**Independent Test**: 허용되지 않는 프로토콜, 존재하지 않는 호스트, 크기 제한을 넘는 응답, 시간 제한을 넘는 응답, 로그인이 필요한 페이지, 지원하지 않는 파일 형식을 각각 넣어 보고, 모두 자료별 "실패" 상태와 구체적인 이유로 표시되며 나머지 자료의 처리는 계속되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `http`·`https`가 아닌 주소(예: `file://`, `ftp://`, `javascript:`), **When** 사용자가 추가하면, **Then** 서버에 요청을 보내기 전에 거절되고 허용 형식이 안내된다.
2. **Given** 접근할 수 없는 URL(존재하지 않는 주소, 오류 응답, 로그인 필요), **When** 서버가 읽기를 시도하면, **Then** 그 자료는 "실패"로 표시되고 원인과 함께 "파일로 올려 주세요" 같은 대안이 안내된다.
3. **Given** 크기 제한을 넘거나 시간 제한 안에 응답하지 않는 URL, **When** 서버가 읽기를 시도하면, **Then** 제한을 넘은 시점에 읽기를 중단하고 어떤 제한에 걸렸는지 알린다.
4. **Given** 지원하지 않는 형식이거나 크기 제한을 넘는 파일, **When** 사용자가 올리면, **Then** 업로드가 거절되고 지원 형식·크기 제한이 안내된다.
5. **Given** 자료 세 개 중 하나가 실패했을 때, **When** 나머지 두 개가 정리 완료되면, **Then** 사용자는 실패한 자료를 빼거나 다시 시도하거나 그대로 둔 채 "로드맵 만들기 시작"을 누를 수 있고, 실패한 자료는 생성 입력에 포함되지 않는다.
6. **Given** 정리 완료된 자료가 하나도 없을 때(목표 경로도 아님), **When** 사용자가 시작하려 하면, **Then** 시작이 막히고 자료를 추가하거나 목표 경로로 전환하라는 안내가 표시된다.

### User Story 6 - 중간에 떠나거나 AI가 실패해도 입력이 사라지지 않기 (Priority: P3)

자료를 넣다가 브라우저를 닫거나 서버가 재시작돼도, 다음에 로드맵 만들기 화면에 들어오면 이미 추가한 자료 목록과 정리된 학습 포인트(목표 경로라면 입력한 값)가 그대로 남아 있어 이어서 할 수 있다. 자동 처리 중 AI 호출이 실패하면 반쯤 만든 로드맵을 저장하지 않고, 입력을 보존한 채 다시 시도할 수 있게 한다.

**Why this priority**: 편의·안정성 기능이다. 한 번에 끝나는 정상 흐름(P1)이 먼저 있어야 이어가기가 의미 있다.

**Independent Test**: 자료 두 개를 추가한 뒤 서버를 재시작하고 화면을 다시 열어 자료 목록이 보존되는지 확인한다. 자동 처리 중 AI 호출이 실패하도록 재현해 `study-progress/`에 불완전한 폴더가 생기지 않는지, 입력 초안이 남아 재시도할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 자료를 두 개 추가하고 하나가 정리 완료된 상태, **When** 사용자가 화면을 떠났다가(또는 서버 재시작 후) 다시 로드맵 만들기에 들어오면, **Then** 작성 중인 초안이 있다는 안내와 함께 두 자료와 정리된 학습 포인트가 그대로 복원된다.
2. **Given** 작성 중인 초안이 있을 때, **When** 사용자가 "새로 시작"을 고르면, **Then** 기존 초안은 사용자 확인 없이 지워지지 않는다.
3. **Given** 자동 처리 중 AI 호출이 실패하거나 시간 초과·형식 오류가 났을 때, **When** 처리가 멈추면, **Then** `study-progress/`에는 아무것도 저장되지 않고, 사용자에게 실패 사실과 "다시 시도"가 안내되며, 입력(자료 목록·학습 포인트·목표 값)은 보존된다.
4. **Given** 자동 처리 구간이 진행 중일 때, **When** 사용자가 화면을 떠났다가 돌아오면, **Then** [NEEDS CLARIFICATION: 자동 처리(3~4단계) 진행 중 이탈 시 처음부터 다시 시작하는지, 서버가 이어서 완료하고 돌아왔을 때 완료를 알리는지 — 명세서 F08이 "구현 전 확정"으로 남겨 둠. 권장 기본값: 서버가 브라우저와 무관하게 이어서 처리하고, 돌아오면 현재 진행률 또는 완성 결과를 보여준다. 단 서버 자체가 재시작돼 처리가 끊긴 경우에는 입력을 보존한 채 자동 처리 구간을 처음부터 다시 시작한다.]
5. **Given** "로드맵 만들기 시작"이 중복으로 눌렸을 때(이중 클릭, 재전송), **When** 서버가 요청을 받으면, **Then** 같은 초안에 대해 자동 처리가 두 번 실행되거나 로드맵이 두 개 저장되지 않는다.

### Edge Cases

- 자료 속에 "이전 지시를 무시하라", "파일을 삭제하라" 같은 문장이 있는 경우 → 학습 자료의 일부로만 다루고 시스템 지시로 실행하지 않는다. AI는 도구·파일·명령 실행 권한이 없는 상태로 호출되므로 실행할 수단 자체가 없다.
- 같은 URL이나 같은 내용의 파일을 두 번 넣는 경우 → 중복임을 알리고 목록에 한 번만 남긴다.
- 자료가 매우 커서 학습 포인트가 지나치게 많이 나오는 경우 → 가이드 범위(지식 20~40개, Phase 4~8개, Phase당 5~15시간)를 벗어나도 저장을 막지 않되, 완성 화면에서 가이드 범위를 벗어났다는 사실을 알리고 수정(012)으로 묶거나 줄일 수 있음을 안내한다.
- 자료가 너무 적어 지식 항목이 몇 개 안 나오는 경우 → 강제로 부풀리지 않고 그대로 만들며, 가이드 범위보다 적다는 사실만 알린다.
- 자료 본문에서 텍스트를 뽑을 수 없는 경우(스캔 이미지 PDF, 빈 문서) → 그 자료를 "실패(내용을 읽을 수 없음)"로 표시하고 다른 자료 처리를 막지 않는다.
- AI가 정해진 결과 형식에 맞지 않는 응답을 반환한 경우 → 그 응답을 파일로 쓰지 않고 해당 단계를 실패로 처리해 재시도 가능 상태로 둔다.
- AI가 Phase 간 순환 선행 관계(A→B→A)나 존재하지 않는 Phase를 참조하는 결과를 낸 경우 → 서버 검증에서 걸러 저장하지 않고 재시도 대상으로 처리한다.
- 로드맵 이름에 파일 이름으로 쓸 수 없는 문자(`/`, `\`, `:` 등)나 상위 경로(`..`)가 들어간 경우 → 안전한 폴더명으로 바꿔 `study-progress/` 밖이나 기존 폴더에 쓰이지 않게 한다.
- 저장 도중 디스크 오류 등으로 일부 파일만 쓰인 경우 → 반쪽짜리 로드맵 폴더를 남기지 않는다(전부 저장되거나 전혀 저장되지 않는다).
- 사용자가 입력한 목표 기한이 오늘보다 과거이거나 주당 학습 시간이 0 이하인 경우 → 입력 단계에서 안내하고 시작을 막는다.
- 사용자가 넣은 자료가 자료실에 이미 등록된 자료와 같은 경우 → 새 자료로 중복 보관하지 않고 기존 자료에 연결한다.
- 생성이 끝난 뒤 저장 직전에 사용자가 `study-progress/`를 직접 고쳐 같은 이름의 폴더가 생긴 경우 → 덮어쓰지 않고 구분되는 이름으로 저장한다(파일이 원본이라는 7.1 원칙).

## Requirements *(mandatory)*

### Functional Requirements

**입력 단계 — 자료 경로(기본)**

- **FR-001**: 시스템은 로드맵 만들기의 기본 입력으로 파일 업로드와 URL 입력을 제공해야 하며, 두 방식으로 추가한 자료를 하나의 "추가된 자료" 목록으로 보여줘야 한다.
- **FR-002**: 시스템은 자료별로 처리 상태(추가됨 / 읽는 중 / 정리 완료 / 실패)와 실패 이유를 표시해야 한다.
- **FR-003**: 시스템은 정리 완료된 자료마다 그 자료에서 뽑은 학습 포인트 목록을 자료별로 구분해 보여줘야 한다. 학습 포인트는 자료에 담긴 주제·개념의 목록이며, 문제의 정답이나 과제 풀이를 포함하지 않는다.
- **FR-004**: 사용자는 선택 사항으로 "정리 방향"(예: 특정 범위에 집중)을 한 줄 입력할 수 있어야 하며, 비워 두면 자료 전체 내용을 기준으로 정리한다.
- **FR-005**: 사용자는 추가된 자료를 목록에서 제거하거나, 실패한 자료를 다시 시도할 수 있어야 한다.
- **FR-006**: 시스템은 같은 URL 또는 같은 내용의 파일이 다시 추가되면 중복임을 알리고 목록에 한 번만 남겨야 한다.

**입력 단계 — 목표 경로(보조)**

- **FR-007**: 시스템은 "자료 없이 목표만 적을게요" 전환을 제공해야 하며, 이 경로에서 완주 후 직접 만들 수 있어야 하는 결과물 한 문장(필수), 이미 아는 것, 처음인 것, 주당 학습 시간, 목표 기한을 입력받아야 한다.
- **FR-008**: 시스템은 결과물 문장 입력란에 "이해한다"가 아닌 결과물로 적으라는 안내와 좋은 예·나쁜 예를 표시해야 한다. 이 안내는 입력을 막는 검사가 아니다.
- **FR-009**: 시스템은 결과물 문장이 비어 있거나, 주당 학습 시간이 0 이하이거나, 목표 기한이 오늘(사용자 시간대 기준)보다 과거이면 시작을 막고 이유를 안내해야 한다.
- **FR-010**: 자료 경로와 목표 경로를 오가도 각 경로에서 이미 입력한 내용(자료 목록, 목표 값)은 사라지지 않아야 한다.

**입력 검증**

- **FR-011**: 시스템은 `http`·`https` 이외의 프로토콜을 가진 URL을 서버 요청 전에 거절해야 한다. 이 웹앱 자신을 가리키는 주소(로컬 루프백)도 거절한다.
- **FR-012**: 시스템은 URL 읽기에 크기 제한과 시간 제한을 적용해야 하며, 제한을 넘으면 읽기를 중단하고 어떤 제한에 걸렸는지 사용자에게 알려야 한다.
- **FR-013**: 시스템은 접근할 수 없는 URL(주소 해석 실패, 오류 응답, 로그인 필요 등)을 조용히 건너뛰지 않고 그 자료를 실패로 표시하며, 원인과 대안(파일로 올리기 등)을 안내해야 한다.
- **FR-014**: 시스템은 지원 형식(PDF·DOCX·TXT·MD)이 아니거나 크기 제한을 넘는 파일을 거절하고 지원 형식·제한을 안내해야 한다.
- **FR-015**: 시스템은 본문 텍스트를 뽑을 수 없는 자료를 실패로 표시하고, 그 실패가 다른 자료의 처리를 막지 않게 해야 한다.
- **FR-016**: 시스템은 정리 완료된 자료가 하나 이상 있거나(자료 경로) 목표 경로의 필수값이 채워졌을 때만 "로드맵 만들기 시작"을 허용해야 하며, 실패한 자료는 생성 입력에 포함하지 않아야 한다.

**시작 확정과 자동 처리**

- **FR-017**: 새 로드맵은 사용자가 "로드맵 만들기 시작"을 명시적으로 누른 경우에만 만들어져야 한다. 자료 추가나 학습 포인트 정리만으로는 `study-progress/`에 아무것도 생기지 않아야 한다.
- **FR-018**: 시작이 확정되면 시스템은 사용자 승인 없이 다음 순서로 이어서 처리해야 한다: (1) 필요 지식 목록 작성 → (2) 선행 관계에 따른 Phase 구성과 Phase별 도착점 → (3) 자료 연결 → (4) 자료 없는 항목의 산출물 과제 제안. 이 구간에서 단계별 결과를 보여주며 승인을 요구하는 화면을 두지 않는다.
- **FR-019**: 필요 지식 목록은 자료 연결보다 먼저, 자료 경로에서는 정리된 학습 포인트를 근거로, 목표 경로에서는 목표 달성에 필요한 것을 근거로 만들어야 한다. 지식 항목은 도구명·강좌명이 아니라 "할 줄 알아야 하는 것"으로 표현한다.
- **FR-020**: 시스템은 자동 처리 중 진행률(%)을 표시해야 하며, 진행률은 서버가 완료된 처리 단계를 기준으로 계산해야 한다(AI의 자연어 응답으로 진행률을 정하지 않는다). 진행률은 처리 중에 줄어들지 않아야 한다.
- **FR-021**: 지식 20~40개, Phase 4~8개, Phase당 5~15시간은 생성의 가이드로만 사용하며, 이 범위를 벗어난 결과의 저장을 막지 않아야 한다. 범위를 벗어나면 완성 화면에서 그 사실을 알린다.
- **FR-022**: 같은 초안에 대한 "로드맵 만들기 시작" 요청이 중복 전송되면, 시스템은 자동 처리를 한 번만 실행하고 로드맵을 한 번만 저장해야 한다.

**자료 연결**

- **FR-023**: 자료 연결 단계는 자료 경로에서 사용자가 넣은 자료를 자동으로 연결 후보에 포함해야 한다.
- **FR-024**: 자료 연결 단계는 기존 로드맵들에 같은 학습 항목이 이미 자료와 연결돼 있으면 그 매핑을 재사용해야 한다.
- **FR-025**: 시스템은 어떤 학습 항목에 적합한 자료가 없다고 판단하기 전에 자료실 전체 카탈로그와 기존 매핑을 확인해야 하며, 검색 결과 상위 몇 개만 보고 "자료 없음"으로 단정하지 않아야 한다.
- **FR-026**: 적합한 자료가 없는 학습 항목은 비워 두지 않고, 사용자가 직접 만들 산출물 과제로 채워야 한다. 산출물 과제는 만들 것을 제시할 뿐 정답·완성 코드·풀이를 포함하지 않아야 한다(CLAUDE.md: 사용자 대신 과제를 풀지 않는다).

**완성·저장·검증**

- **FR-027**: 자동 처리가 끝나면 시스템은 로드맵 이름, 도착점 한 문장, 출발점·제약·기한(입력된 경우), Phase 목록과 Phase별 도착점·예상 시간, Phase별 학습 항목(연결 자료 또는 산출물 과제), 진행률 0%를 담은 완성 로드맵을 표시하고 저장해야 한다. 이 저장이 최종 확정이며, 저장 전 별도 승인 단계를 두지 않는다.
- **FR-028**: 시스템은 저장 직전에 모든 자료 연결이 실제로 존재하는 자료를 가리키는지 확인해야 한다. 존재하지 않는 자료, 저장소 밖 경로, AI가 지어낸 경로는 파일에 쓰지 않고 해당 항목을 산출물 과제로 대체해야 하며, 대체한 개수를 완성 화면에 표시해야 한다.
- **FR-029**: 시스템은 AI 결과의 형식(필수 항목 누락, Phase 순서·선행 관계의 순환, 존재하지 않는 Phase 참조 등)을 저장 전에 검증해야 하며, 검증을 통과하지 못한 결과는 저장하지 않고 재시도 가능한 실패로 처리해야 한다.
- **FR-030**: 완성 로드맵은 `study-progress/<새 로드맵 폴더>/`에 기존 로드맵과 같은 구조(도착점·Phase 표·순서를 담은 README, 파일명에 순번과 "Phase"를 포함한 Phase 문서, 체크박스 형식의 학습 항목, 모두 미완료)로 저장되어야 하며, 기존 가져오기 규칙(001)으로 다시 읽었을 때 그 로드맵에 대한 오류가 0건이어야 한다.
- **FR-031**: 시스템은 기존 로드맵 폴더를 덮어쓰지 않아야 한다. 이름이 겹치면 구분되는 새 이름으로 저장하고 그 이름을 사용자에게 알린다. 폴더·파일명은 `study-progress/` 밖을 가리키거나 파일 이름으로 쓸 수 없는 문자를 포함하지 않도록 정리되어야 한다.
- **FR-032**: 로드맵 저장은 전부 성공하거나 전혀 반영되지 않아야 한다. 일부 파일만 쓰인 반쪽 로드맵 폴더를 남기지 않는다.
- **FR-033**: 저장 직후 새 로드맵은 추가 조작 없이 로드맵 목록·상세(003), 브리핑 진행률 집계(005), 학습 시작의 로드맵 이어하기(006)에 기존 로드맵과 같은 방식으로 나타나야 한다.
- **FR-034**: 사용자가 파일·URL로 넣은 자료 중 연결에 쓰인 것은 이후에도 열람·학습에 쓸 수 있도록 식별 가능한 자료로 보관되어야 하며, 새 로드맵의 학습 항목은 그 자료를 존재하는 자료로 가리켜야 한다. 자료실에 이미 같은 자료가 있으면 중복 보관하지 않고 기존 자료를 연결한다.
- **FR-035**: 완성 화면은 "로드맵 확인하기"(003 상세), "바로 학습 시작"(006 로드맵 이어하기), 결과를 고치려면 로드맵 수정(012)으로 가는 경로를 제공해야 한다. 생성 과정을 다시 여는 "되돌려서 재검토" 경로는 두지 않는다.

**중단·재개·실패**

- **FR-036**: 입력 단계의 초안(추가된 자료 목록, 자료별 상태와 학습 포인트, 정리 방향, 목표 경로 입력값)은 서버에 영속 보관되어야 하며, 브라우저를 닫거나 서버가 재시작된 뒤에도 복원되어야 한다.
- **FR-037**: 작성 중인 초안이 있을 때 로드맵 만들기에 들어오면 이어서 할지 새로 시작할지 고를 수 있어야 하며, 새로 시작해도 기존 초안은 사용자 확인 없이 지워지지 않아야 한다.
- **FR-038**: 자동 처리 중 AI 호출이 실패·시간 초과·형식 오류로 끝나면, 시스템은 `study-progress/`에 아무것도 저장하지 않고 입력 초안을 보존한 채 실패를 알리고 재시도할 수 있게 해야 한다.
- **FR-039**: 자동 처리 진행 중 사용자가 화면을 떠났다가 돌아왔을 때의 동작은 [NEEDS CLARIFICATION: 처음부터 다시 시작 vs 서버가 이어서 완료하고 완료 알림 — F08 "구현 전 확정" 항목. 권장: 이어서 완료(서버 재시작으로 끊긴 경우만 입력 보존 후 자동 처리 구간 재시작)]를 따른다.

**AI 실행과 안전**

- **FR-040**: 자료 정리와 자동 처리의 AI 호출은 006과 같은 방식(별도 API 키 없이 로컬 Claude Code 헤드리스 호출, 도구·파일·셸·외부 연결 접근 차단)으로 수행해야 한다.
- **FR-041**: 시스템은 자료 본문과 사용자 입력을 AI에게 데이터로만 전달해야 하며, 그 안의 지시문을 시스템 지시로 따르지 않아야 한다. AI가 반환한 내용을 그대로 파일 쓰기·명령으로 실행하지 않고, 서버가 검증한 구조화된 결과만 저장에 사용한다.
- **FR-042**: 시스템은 자료 정리·자동 처리의 AI 요청·응답 원문을 로그로 보관해야 한다(7장 확정: 요청·응답 원문 전량 보관).
- **FR-043**: 이 기능은 git 커밋·푸시를 자동으로 수행하지 않아야 한다(7장 확정: GitHub 연동 없음).

### Key Entities *(include if feature involves data)*

- **로드맵 생성 초안**: 로드맵 하나를 만들기 위한 입력 묶음. 입력 경로(자료/목표), 정리 방향, 목표 경로 입력값(결과물 문장·이미 아는 것·처음인 것·주당 시간·기한), 상태(입력 중 / 자동 처리 중 / 실패 / 완료), 진행률, 실패 이유, 완료 시 저장된 로드맵 참조를 가진다.
- **입력 자료**: 초안에 추가된 파일 또는 URL 하나. 종류, 원래 이름·주소, 처리 상태, 실패 이유, 내용 식별값(중복 판정용), 정리된 학습 포인트 목록, 보관된 자료 참조(연결에 쓰일 때)를 가진다.
- **학습 포인트**: 입력 자료 하나에서 뽑은 주제·개념 한 줄. 출처 자료를 가리킨다.
- **생성 결과(검증 전)**: 자동 처리가 만든 로드맵 구조 — 로드맵 이름, 도착점, 필요 지식 목록, Phase(순서·이름·도착점·예상 시간·선행 관계), 학습 항목(연결 자료 후보 또는 산출물 과제). 서버 검증을 통과해야만 파일로 저장된다.
- **완성 로드맵**: `study-progress/` 아래에 저장된 새 로드맵 폴더. 001의 로드맵·Phase·학습 항목과 같은 성격이며 저장 후에는 기존 로드맵과 구분하지 않는다.
- **자료 연결**: 학습 항목과 실제 존재하는 자료(자료실 자료 또는 보관된 입력 자료)의 연결. 기존 매핑 재사용 여부, 대체(가짜 경로 → 산출물 과제) 여부를 기록한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 자료 경로와 목표 경로 각각에서, "로드맵 만들기 시작" 이후 사용자가 추가 입력·승인을 한 번도 하지 않고 완성 로드맵 화면까지 도달한다(중간 승인 화면 0개).
- **SC-002**: 생성·저장된 로드맵을 기존 가져오기 규칙으로 다시 읽었을 때 그 로드맵에 대한 오류가 0건이고, 저장 직후 로드맵 목록·브리핑·학습 시작 세 곳 모두에서 진행률 0%로 나타난다.
- **SC-003**: 존재하지 않는 자료 경로를 섞은 AI 결과로 저장을 시도했을 때, 저장된 파일에 존재하지 않는 자료 참조가 0건이다.
- **SC-004**: "로드맵 만들기 시작"을 누르지 않은 초안 100건 중 `study-progress/`에 로드맵이 생긴 경우가 0건이며, 기존 로드맵 폴더가 덮어써진 경우가 0건이다.
- **SC-005**: 허용되지 않는 프로토콜·접근 불가·크기 초과·시간 초과·지원하지 않는 형식의 입력 각각이 100% 실패 이유와 함께 표시되고, 이로 인해 다른 자료의 처리가 중단되는 사례가 0건이다.
- **SC-006**: 입력 단계에서 브라우저를 닫거나 서버를 재시작한 뒤 돌아왔을 때 추가된 자료 목록과 학습 포인트가 100% 복원된다.
- **SC-007**: 자동 처리 중 AI 실패를 재현했을 때 반쪽짜리 로드맵 폴더가 생긴 사례가 0건이고, 입력 초안은 100% 보존되어 재시도할 수 있다.
- **SC-008**: 자료실 전체 카탈로그에 정확히 맞는 자료가 있지만 키워드 검색 상위 결과에는 없는 검증용 사례에서, 그 자료가 연결되지 않고 산출물 과제로 대체되는 사례가 0건이다.
- **SC-009**: 자료 속에 지시문을 심은 입력으로 생성했을 때, 파일 삭제·명령 실행·`study-progress/` 밖 쓰기 등 지시문에 따른 동작이 0건이다.
- **SC-010**: 완성 로드맵에서 빈 학습 항목(자료도 산출물 과제도 없는 항목)이 0건이다.

## Assumptions

- 이 기능의 범위는 F08의 1~5단계(입력 → 자동 처리 → 완성 로드맵 표시·저장 → 학습·브리핑 연결)까지다. 6~7단계(결과 교정, 변경 내용 먼저 보여주기, 유지·추가·삭제 확인, 새 버전 저장)는 012(로드맵 수정·버전)의 범위이며, 이 기능은 완성 화면에서 012로 가는 경로만 제공한다.
- 7장 확정 사항("로드맵 생성 중 검증 방식": 화면별 승인 없음, 교정은 완성 후 수정 절차로)을 그대로 따른다. F08이 요구하는 "검증 없이 그대로 저장하지 않는다"는 저장 시점의 서버 검증(FR-028·FR-029)으로 충족한다.
- "로드맵을 새로 만드는 결정은 사용자가 한다"(CLAUDE.md)는 "로드맵 만들기 시작" 버튼의 명시적 클릭으로 충족한다. 그 이후 이름·구성은 AI가 정하고 사용자는 012로 고친다.
- 파일이 원본이라는 7.1 원칙에 따라, 완성 로드맵의 원본은 `study-progress/` 아래 Markdown 파일이다. 로드맵 목록·브리핑에 나타나게 하는 파생 저장소 반영(002의 재적재 또는 그에 준하는 즉시 반영)은 저장 직후 서버가 수행한다 — 정확한 반영 방식은 계획 단계에서 정한다.
- 생성 파일의 구조는 기존 `/roadmap` 스킬의 4절 형식(README: 도착점·출발점/제약/기한·Phase 표·순서 / Phase 문서: `# Phase N — 이름`, `**이 Phase의 도착점**`, `## N-A. 소주제`, `- [ ] 자료 링크` 또는 `- [ ] 산출물: …`)과 실제 로드맵(`study-progress/ADsP 로드맵/`)을 기준으로 한다. 폴더명은 기존 관례대로 `<주제> 로드맵`을 기본으로 한다.
- 입력 초안·자동 처리 상태 같은 "파일에서 파생되지 않는 데이터"는 005·006이 확립한 원칙대로 002/004의 공유 캐시가 아닌 이 기능 전용 저장소에 둔다. 초안은 로드맵이 완성된 뒤에도 생성 근거로 남겨 두되, 삭제·보관 정책은 이 기능에서 정하지 않는다.
- 사용자가 올린 파일·URL에서 읽은 자료를 보관하는 정확한 위치(예: 새 로드맵 폴더 안, 또는 사용자 자료 전용 폴더)와 그 자료에 식별자를 부여해 자료실(003)·학습(006)에서 열 수 있게 하는 방식은 계획 단계에서 정한다. 이 스펙은 "연결에 쓰인 입력 자료는 존재하는 자료로 검증 가능해야 한다"(FR-034)는 성질만 요구한다. `courses/`는 읽기 전용으로 취급하므로(CLAUDE.md) 입력 자료를 `courses/` 아래에 쓰지 않는다.
- 입력 제한 기본값(계획 단계에서 조정 가능): 파일 형식은 디자인 시안과 같은 PDF·DOCX·TXT·MD, 파일당 20MB, URL 응답 본문 5MB, URL 읽기 시간 30초, 리다이렉트는 최대 5회까지 따라가되 매 단계마다 FR-011의 프로토콜 검사를 다시 적용한다. 설정 화면에서 조정하는 기능은 014의 범위다.
- 개인용 로컬 단일 사용자 앱이며 디자인 시안이 "사내 위키" URL을 예로 들고 있으므로, 사설 네트워크 주소는 허용하되 이 웹앱 자신(로컬 루프백)은 거절한다. 로그인이 필요한 페이지의 인증 처리(쿠키 전달 등)는 지원하지 않고 "접근 불가"로 안내한다.
- 자료실 전체 카탈로그(현재 7,865개)를 확인한다는 요구(FR-025)는 "상위 몇 개만 보고 단정하지 않는다"는 판단 규칙이다. 전체 목록을 AI에게 한 번에 넘길지, 서버가 전체 카탈로그에서 후보를 추린 뒤 넘길지 등 구체적 방법은 계획 단계에서 정한다. 단 어떤 방법이든 판단 전에 카탈로그 전체가 검토 대상이어야 한다.
- 자동 처리 구간의 진행률은 서버가 아는 단계 완료(필요 지식 → Phase 구성 → 자료 연결 → 산출물 과제 → 검증·저장)를 기준으로 계산하며, 단계 안의 세밀한 퍼센트는 요구하지 않는다. 화면 갱신 방식(주기적 확인 등)은 계획 단계에서 정한다 — 006은 실시간 프로토콜 없이 서버 렌더링을 유지했다.
- 자료 경로에서 학습 포인트를 보여주는 것은 1.2의 "답변 전에 정답을 보여주지 않는다" 원칙과 충돌하지 않는다고 본다 — 학습 포인트는 주제 목록이지 질문의 정답이 아니며, 이 화면에서는 학습(질문·채점)이 일어나지 않는다.
- 생성된 로드맵은 다른 로드맵의 선행 과정으로 강제되지 않는 독립 과목이다(1.2, CLAUDE.md).
- 실제 AI 생성 결과의 품질(지식 목록의 적절성, Phase 구성의 타당성, 자료 연결의 정확성)은 성공 기준에 포함하지 않는다. 결정적으로 검증 가능한 것(승인 화면 없음, 저장 검증, 파일 구조, 원자적 저장, 초안 보존, 입력 검증)만 성공 기준으로 삼고, 품질은 012의 수정 절차로 교정한다. 단 SC-008(전체 카탈로그 확인)은 모킹된 AI 결과가 아니라 후보 제공 방식 자체를 검증하는 사례로 확인한다.
- 이 기능은 `내학습/진행상황.md`에 자동으로 기록을 남기지 않는다. 학습 세션 기록은 009·010의 범위다.
