# Feature Specification: 로드맵 탐색·자료실 화면 (Roadmap & Materials Screens)

**Feature Branch**: `003-roadmap-materials-screens`

**Created**: 2026-09-22

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 로드맵 목록에서 진행 상황 한눈에 보기 (Priority: P1)

사용자가 웹앱을 열면, 자신이 만든 모든 로드맵의 목록을 제목·완료/전체·진행률과 함께 본다. 로드맵이 몇 개든(현재 8개, 앞으로 늘어남) 목록에 누락 없이 나타난다.

**Why this priority**: 이것이 없으면 사용자는 어떤 로드맵이 있는지, 어디까지 했는지조차 알 수 없다 — 이 기능 전체의 진입점.

**Independent Test**: 002의 실제 저장소로 목록 화면을 열어, 로드맵 8개 전부가 제목·완료/전체·진행률과 함께 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로드맵이 여러 개 적재된 저장소, **When** 목록 화면을 열면, **Then** 모든 로드맵이 제목·완료/전체 개수·진행률과 함께 나타난다.
2. **Given** 진행 자료(Phase 문서)가 없는 로드맵, **When** 목록을 보면, **Then** 그 로드맵은 "진행 자료 없음"으로 구분되어 표시되고 0%로 잘못 표시되지 않는다.
3. **Given** "확인 필요" 항목이 있는 로드맵, **When** 목록을 보면, **Then** 그 로드맵에 확인이 필요한 항목이 있다는 표시가 함께 나타난다.

---

### User Story 2 - 로드맵 상세에서 트랙·Phase·학습 항목 탐색 (Priority: P1)

사용자가 목록에서 로드맵 하나를 선택하면, 트랙(있는 경우)과 그 아래 Phase, 각 Phase의 학습 항목을 원문에 기록된 순서 그대로 본다. 트랙 없이 Phase만 있는 로드맵도 동일하게 탐색할 수 있다.

**Why this priority**: 목록에서 진행률만 보고 실제로 무엇을 배웠고 무엇이 남았는지 들여다볼 수 없다면 목록은 반쪽짜리다. US1과 짝을 이루는 핵심 화면.

**Independent Test**: 트랙이 있는 로드맵과 없는 로드맵을 각각 열어, 트랙·Phase·학습 항목이 누락 없이, 파일명 문자열 정렬이 아닌 원문 순서로 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 트랙 여러 개를 가진 로드맵, **When** 상세 화면을 열면, **Then** 모든 트랙과 그 아래 Phase·학습 항목이 원문 순서로, 누락 없이 나타난다.
2. **Given** 트랙 없이 Phase만 있는 로드맵, **When** 상세 화면을 열면, **Then** 트랙 단계 없이 Phase 목록이 바로 나타난다.
3. **Given** 체크박스 형식이 깨져 집계 불가능한 Phase, **When** 그 Phase를 보면, **Then** 학습 항목 목록 대신 "형식 확인 필요" 같은 안내가 나타나고 빈 목록으로 조용히 처리되지 않는다.
4. **Given** 학습 항목이 자료와 연결된 경우, **When** 그 항목을 보면, **Then** 연결된 자료로 이동할 수 있는 경로가 함께 나타난다.

---

### User Story 3 - "이어서 공부"로 다음 위치 안내받기 (Priority: P2)

사용자가 로드맵 상세에서 "이어서 공부"를 선택하면, 그 로드맵의 첫 번째 미완료 학습 항목의 위치(트랙/Phase/항목)로 바로 이동한다. 특정 Phase나 항목을 직접 선택해 그 위치에서 시작할 수도 있다.

**Why this priority**: US1·US2로 이미 탐색은 가능하지만, 매번 처음부터 어디까지 했는지 눈으로 찾아야 한다면 반복 이용에 불편하다. 탐색이 갖춰진 다음에 얹는 편의 기능이라 P1보다 한 단계 낮다.

**Independent Test**: 완료/미완료가 섞인 로드맵에서 "이어서 공부"를 선택해, 원문 순서상 가장 먼저 나오는 미완료 항목의 위치로 정확히 이동하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 일부만 완료된 로드맵, **When** "이어서 공부"를 선택하면, **Then** 원문 순서상 가장 먼저 나오는 미완료 항목의 위치가 제시된다.
2. **Given** 모든 항목이 완료된 로드맵, **When** "이어서 공부"를 선택하면, **Then** 더 이상 남은 항목이 없다는 것을 알리고 임의의 항목을 잘못 제안하지 않는다.
3. **Given** 로드맵 상세 화면, **When** 사용자가 특정 Phase나 항목을 직접 선택하면, **Then** "이어서 공부"의 제안과 무관하게 그 위치로 이동한다.

---

### User Story 4 - 자료실에서 조건으로 자료 찾기 (Priority: P2)

사용자가 자료실에서 제공처·강좌·분류·경로·제목 조건으로 자료 7,865개 중 원하는 것을 찾는다. 검색 결과에는 제목·경로·분류·연결된 로드맵이 함께 나타난다.

**Why this priority**: 로드맵 탐색(US1·US2)과 독립적으로 그 자체로 가치가 있는 별개 화면(F09)이지만, 이 기능 전체의 핵심 가치인 "로드맵 진행"보다는 보조적이라 P2.

**Independent Test**: 분류·제공처·강좌·경로·제목 조건을 각각(및 조합해) 검색해, 002 `searchMaterials`가 반환하는 결과와 화면에 나타나는 결과가 정확히 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 자료 7,865개가 색인된 저장소, **When** 분류나 제공처로 검색하면, **Then** 전체 목록을 다시 순회하지 않고 조건에 맞는 자료만 즉시 나타난다.
2. **Given** 검색 조건에 맞는 자료가 없음, **When** 검색하면, **Then** 결과 없음이 명확히 표시되고 오류로 보이지 않는다.
3. **Given** 같은 자료가 두 로드맵에 연결된 경우, **When** 그 자료를 검색 결과에서 보면, **Then** 연결된 로드맵 모두가 함께 나타난다.

---

### User Story 5 - 자료 본문을 안전하게 열람하기 (Priority: P2)

사용자가 검색 결과나 로드맵 상세에서 자료 하나를 선택하면, 그 자료의 본문(표, 코드 블록, 내부 링크, 원본 출처 링크 포함)을 화면에서 바로 읽는다.

**Why this priority**: 검색(US4)이나 탐색(US2)으로 자료를 찾아도 내용을 못 보면 소용없다 — 두 진입 경로 모두가 최종적으로 의존하는 화면.

**Independent Test**: 표·코드 블록·내부 링크·한글/공백/URL 인코딩 경로가 섞인 실제 자료를 열어, 원본과 같은 내용으로 정상 표시되고 스크립트가 실행되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 표와 코드 블록이 있는 자료, **When** 열람하면, **Then** 원본 서식 그대로 표와 코드 블록이 표시된다.
2. **Given** 원본 출처를 가리키는 링크가 있는 자료, **When** 열람하면, **Then** 그 링크가 그대로 보존되어 나타난다.
3. **Given** 악성 스크립트나 위험한 URL이 섞인 Markdown, **When** 열람하면, **Then** 스크립트는 실행되지 않고 텍스트로만 무해하게 표시된다.
4. **Given** 사용자가 화면에서 자료를 열람, **When** 열람이 끝나면, **Then** 그 사실만으로 연결된 학습 항목이 자동으로 완료 처리되지 않는다(완료 판정은 이 기능 밖의 별도 학습 절차가 담당).

---

### Edge Cases

- 로드맵이 하나도 없는 신규 사용자가 목록 화면을 열면? → 빈 목록과 "아직 로드맵이 없다"는 안내가 나타나고, 오류나 빈 화면으로 보이지 않는다.
- 002의 저장소가 아직 한 번도 적재되지 않았거나 최신이 아니면? → 화면은 오래된/빈 데이터를 사용자에게 그대로 보여주기보다, 적재가 필요하다는 것을 알 수 있는 상태를 보인다(적재를 언제 어떻게 트리거할지는 이 기능 밖, 002 spec.md Assumptions 참고).
- 검색 결과나 자료 목록이 매우 많으면? → 한 번에 전부 렌더링해 화면을 느리게 만들지 않고, 페이지 단위 또는 더 보기 방식으로 나눠 보여준다.
- 자료 본문의 전사·요약 품질이 낮거나 불충분하면? → 출처와 관련 주의 문구를 그대로 보존해 사용자가 신뢰도를 스스로 판단할 수 있게 한다.
- 표시 제목이 실제 자료 식별자(경로)와 다르면? → 화면은 사람이 읽는 제목과 내부 식별자를 분리해서 다루고, 제목이 같은 서로 다른 자료를 혼동하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 로드맵 목록을 제목·완료/전체 개수·진행률과 함께 보여줘야 하며, 로드맵 개수를 고정된 값으로 가정하지 않아야 한다.
- **FR-002**: 시스템은 트랙 유무와 관계없이 모든 트랙·Phase·학습 항목을 원문에 기록된 순서로 보여줘야 한다(파일명 문자열 정렬에 의존하지 않는다).
- **FR-003**: 시스템은 "진행 자료 없음"(Phase 문서가 없는 로드맵)과 "형식 확인 필요"(체크박스 형식이 깨져 집계 불가능한 Phase)를 서로 다른 상태로 구분해 보여줘야 하며, 둘 다 조용히 빈 화면이나 0%로 처리하지 않아야 한다.
- **FR-004**: 시스템은 "확인 필요"로 표시된 항목(001/002가 보고한 오류)이 있는 로드맵을 목록과 상세 화면 모두에서 사용자가 알아볼 수 있게 표시해야 한다.
- **FR-005**: 사용자는 로드맵 상세에서 "이어서 공부"를 선택해 그 로드맵의 원문 순서상 가장 먼저 나오는 미완료 항목의 위치로 이동할 수 있어야 하며, 모든 항목이 완료된 경우 그 사실을 알리고 임의의 항목을 제안하지 않아야 한다.
- **FR-006**: 사용자는 "이어서 공부"의 제안과 무관하게 특정 Phase나 학습 항목을 직접 선택해 그 위치에서 볼 수 있어야 한다.
- **FR-007**: 시스템은 제공처·강좌·분류·경로·제목 조건(개별 또는 조합)으로 자료를 검색할 수 있어야 하며, 검색마다 전체 자료 목록을 다시 순회하지 않아야 한다.
- **FR-008**: 검색 결과는 자료의 제목·경로·분류·연결된 로드맵 목록을 포함해야 한다.
- **FR-009**: 시스템은 선택한 자료의 본문(표, 코드 블록, 내부 링크, 원본 출처 링크 포함)을 원본과 같은 내용으로 표시해야 한다.
- **FR-010**: 시스템은 자료 본문에 포함된 스크립트나 위험한 URL을 실행하지 않고 안전하게 렌더링해야 한다.
- **FR-011**: 시스템은 학습 항목이 연결된 자료를 가리킬 때, 그 자료로 이동할 수 있는 경로를 제공해야 한다.
- **FR-012**: 시스템은 사용자가 자료를 열람했다는 사실만으로 연결된 학습 항목을 자동으로 완료 처리하지 않아야 한다(완료 판정은 별도 학습 절차의 책임).
- **FR-013**: 시스템은 같은 자료가 여러 로드맵에 연결되어 있어도, 각 로드맵의 학습 항목별 완료 상태를 서로 독립적으로 유지해야 한다(002가 이미 보장하는 값을 그대로 반영하고 화면에서 재계산하지 않는다).
- **FR-014**: 시스템은 자료의 표시 제목과 내부 식별자(경로 기반 id)를 분리해서 다뤄야 하며, 제목이 같은 서로 다른 자료를 하나로 혼동해 보여주지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **로드맵 목록 항목**: 002 `listRoadmaps()`가 반환하는 값(제목, 완료/전체, 진행률, 확인 필요 개수)을 그대로 화면에 옮긴 것 — 이 기능이 새로 계산하지 않는다.
- **로드맵 상세**: 002 `getRoadmapDetail()`이 반환하는 트랙·Phase·학습 항목 트리 — 화면은 이 구조를 순서대로 펼쳐 보여주는 역할만 한다.
- **이어서 공부 위치**: 로드맵 상세 트리에서 "완료되지 않은 첫 항목"을 가리키는, 이 화면이 계산해 사용하는 뷰 전용 상태(002가 미리 계산해 제공하지 않음).
- **자료 검색 결과 항목**: 002 `searchMaterials()`가 반환하는 값(제목, 경로, 분류, 제공처, 강좌, 연결된 로드맵) — 이 기능이 새로 계산하지 않는다.
- **자료 본문**: 자료 원본 파일의 렌더링된 내용 — 002는 자료의 메타데이터만 제공하므로, 본문 자체를 읽어오는 방법은 계획 단계에서 정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 웹앱을 연 뒤 3번의 선택(목록 → 로드맵 선택 → 이어서 공부) 이내로 자신이 다음에 공부할 위치에 도달할 수 있다.
- **SC-002**: 실제 저장소의 로드맵 8개, 트랙·Phase·학습 항목 전부가 목록·상세 화면에서 누락 없이 나타난다(002가 보고하는 수치와 100% 일치).
- **SC-003**: 자료 7,865개 중 조건에 맞는 자료를 검색하면 1초 이내에 결과가 화면에 나타난다.
- **SC-004**: 표·코드 블록·한글/공백/URL 인코딩 경로가 섞인 자료 100건을 열람했을 때, 원본과 다르게 표시되거나 깨지는 사례가 0건이다.
- **SC-005**: 악성 스크립트가 포함된 자료를 열람해도 스크립트 실행이 0건이다.

## Assumptions

- 이 기능은 `웹전환_기능명세_및_개발가이드.md` 5장의 3단계("사용자·읽기 화면") 중 로드맵 탐색(F02)과 자료실(F09) 화면까지만 다룬다. "이어서 공부"나 항목 선택은 학습 위치로 **이동/안내**하는 데까지이며, 실제 질문·답변 세션(F03/F04, 5단계 "학습 핵심 루프")을 시작하는 것은 이 기능 밖이다 — 5장 development 순서표가 이미 3단계와 5단계를 별도 단계로 구분해 두었다.
- 이 기능은 002-persistence-layer의 다섯 조회 함수(`listRoadmaps`, `getRoadmapDetail`, `searchMaterials`, `listReviewNeededItems`, 그리고 자료 본문 자체를 읽기 위한 추가 접근 방법)를 유일한 데이터 원천으로 삼는다 — 001/002가 이미 계산한 진행률·식별자·연결 관계를 이 기능이 다시 계산하지 않는다.
- 002가 저장소를 언제 재적재하는지(수동/서버 시작 시/주기적)는 002 spec.md Assumptions가 이미 범위 밖으로 정한 대로, 이 기능도 재논의하지 않는다 — 다만 저장소가 오래됐거나 비어 있을 때 사용자에게 그 상태를 알리는 것(Edge Cases)까지는 이 기능이 다룬다.
- 단일 사용자 로컬 웹앱(구현전_결정사항.md 7.1)이므로 다중 사용자 인증·인가, 접근 권한 분리는 범위 밖이다.
- 자료 본문 렌더링의 구체적 방식(어떤 라이브러리·서버 경유 여부 등)은 기술 스택 선택이므로 계획(`/speckit-plan`) 단계에서 정하고, 이 스펙은 "원본과 같게, 안전하게 보여야 한다"는 사용자 관점의 결과만 규정한다.
- 검색·목록 결과가 많을 때의 구체적인 나눠보기 방식(페이지 번호, 무한 스크롤, 더보기 버튼 등)은 화면 설계 단계의 세부사항으로 남겨두고, 이 스펙은 "전체를 한 번에 렌더링해 느려지지 않아야 한다"는 결과만 규정한다.
