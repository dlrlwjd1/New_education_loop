# Learning Loop 웹 화면 시안

기존 `/브리핑`, `/study`, `/roadmap`을 웹 화면으로 옮기는 디자인 작업이다.

## 로컬 시안

[`learning-loop-preview.html`](learning-loop-preview.html)을 브라우저에서 열면 세 화면을 확인할 수 있다. 별도 설치나 서버 실행은 필요하지 않다.

1. **오늘의 브리핑**: 복습할 내용, 로드맵 진행률, 이어서 학습하기.
2. **AI 학습실**: 사전 인출 질문 하나, 답변 입력, 모름·중단 동작, 학습 단계.
3. **로드맵 만들기**: 결과물 목표, 현재 수준, 학습 시간·기한 입력.

예시 작업공간의 디자인 시안이다. 화면 전환과 입력 상태를 확인할 수 있으며, 실제 AI 채점·로드맵 생성·계정·DB 저장은 연결하지 않았다. 학습실은 답변 전에 정답이나 힌트를 보여주지 않는다.

### 확인한 범위

로컬 Chromium에서 1440px와 390px 폭으로 세 화면의 전환·가로 넘침을 확인했다. 빈 답변과 공백 답변 제출 방지, 데모 안내, 중단 후 화면 복귀, 목표 입력 검증, 본문 건너뛰기 포커스 동작도 확인했다. 콘솔·실행 오류와 외부 네트워크 요청은 없었다. 이 결과는 로컬 HTML 시안에 대한 검증이며 Figma 검증 결과는 아니다.

## 클로드 디자인 캔버스

Figma 대신 [Claude Design 캔버스](https://claude.ai/artifact/Sj3Y3ED1ed3BuKnpJKz2jy)로 시안을 옮겼다. 13개 실제 화면 아트보드가 배치되어 있으며, 화면 구성·카피·톤은 이 로컬 HTML 시안(`learning-loop-preview.html`)을 그대로 따른다.

**맨 위 — 화면 흐름도**: `FlowMap` — Main에서 각 버튼이 어디로 이어지는지 화살표로 정리한 다이어그램. 실선은 실제로 만든 버튼의 목적지, 점선은 아직 화면이 없어 가정한 흐름이다. 사이드바 내비게이션으로 가는 이동은 "언제든 갈 수 있어" 별도로 표시하지 않는다.
**1행 — 진입 화면**: 오늘의 브리핑(`Main`)
**2행 — 대화형 화면**: 학습 시작 선택(`StudyLaunch`) · AI 학습실(`Study`, 로드맵 모드 토글 포함) · 로드맵 만들기(`Roadmap`) · 복습하기(`Review`, 큐에서 고른 항목의 진행 중인 대화)
**3행 — 목록·기록 화면**: 자료실(`Library`) · 학습 기록(`StudyHistory`) · 브리핑 기록(`BriefingHistory`) · 복습 큐(`ReviewQueue`, 목록형)
**4행 — 개요·관리 화면**: 로드맵 목록·상세(`RoadmapOverview`) · 로드맵 수정(`RoadmapEdit`) · 설정·데이터 관리(`Settings`)

사이드바는 이제 WORKSPACE(오늘의 브리핑·AI 학습실·로드맵·복습 큐·자료실) / RECORDS(학습 기록·브리핑 기록) 두 그룹과, 우측 상단 톱니바퀴 아이콘의 설정으로 구성된다. "AI 학습실" 메뉴는 곧장 대화창으로 가지 않고 `StudyLaunch`(무엇을 공부할지 고르는 화면)로 먼저 간다 — 대상이 이미 정해진 진입(로드맵 개요의 "이어서 공부" 등)만 예외로 바로 `Study`로 간다. "로드맵" 내비게이션은 개요(`RoadmapOverview`)로 가고, 로드맵 만들기(`Roadmap`)는 브리핑·개요 화면의 "새 로드맵" 버튼으로 바로 진입한다. 이 배선 규칙과 그렇게 정한 근거는 [`사용흐름-리뷰.md`](사용흐름-리뷰.md)에 있다.

각 화면 아트보드 바로 아래에는 그 화면이 뭘 하는 곳인지 두세 문장으로 적은 설명 박스(`*Note.dc.html`, 예: `MainNote.dc.html`)가 별도 아트보드로 붙어 있다. 캔버스 확대·축소로 훑어볼 때 화면끼리 헷갈리지 않도록 하는 용도이며, 명세서의 어느 F0x 절에 대응하는지도 함께 적었다.

`RoadmapStudy.dc.html`은 `Study.dc.html`에 합쳐졌다. 화면 상단 "로드맵 모드" 스위치를 클릭하면(실제로 동작하는 토글) 왼쪽에 로드맵 목차 사이드바가 나타나거나 사라진다 — 켜짐이 기본값. 로드맵 만들기 완료 버튼과 브리핑의 "이어서 학습" 링크는 모두 `#study`로 연결된다.

화면별 구현 현황·미구현 목록은 [`화면-현황.md`](화면-현황.md)에 정리했다.

- 정적 목업이다. 화면 전환·폼 검증 등 실제 동작은 로컬 HTML 시안 쪽에만 있다.
- 캔버스 링크를 열면 각 아트보드를 클릭해 요소 단위로 편집하고, 저장하면 모두에게 새 버전으로 반영된다.
- 소스 아트보드 파일은 [`canvas/`](canvas/)에 있다. 내용을 바꾸려면 이 파일들을 고친 뒤 다시 시딩·게시한다.
- `Roadmap.dc.html`은 목표 직접 입력형이 아니라 **자료(파일·URL) 입력형**이다: URL을 넣으면 읽어서 정리하고, 파일은 올리면 바로 추가된 것으로 표시한다. `웹전환_기능명세_및_개발가이드.md` F08을 이 흐름에 맞춰 갱신했다 — 자료 입력이 기본 경로, 목표 직접 입력은 폼 안의 보조 경로("자료 없이 목표만 적을게요")다. 로컬 HTML 시안의 로드맵 화면은 아직 이전 버전(목표 직접 입력)이라 캔버스와 내용이 다르다.
- **AI 학습실·복습하기는 페이지를 넘기는 방식에서 대화(채팅) 방식으로 바꿨다.** 기존에는 "먼저 떠올리기 → 답변 확인하기 → 부족한 부분 채우기 → 세 줄로 정리하기" 4단계를 화면 4개로 나눠 페이지를 넘겨야 했는데, 지금은 질문·답변·피드백·설명·정리가 VSCode의 대화창처럼 말풍선으로 쌓이고 아래 입력창에서 계속 답하는 한 화면으로 합쳤다. `Study.dc.html`은 8턴짜리 완료된 대화 전체를, `Review.dc.html`은 진행 중인 3턴짜리 대화를 보여준다.
- `Study.dc.html`의 "로드맵 모드" 토글(위 참고)이 예전 `RoadmapStudy.dc.html`의 역할을 대신한다 — 켜면 왼쪽에 로드맵 목록 + 그 로드맵 파일의 학습 항목 제목으로 만든 목차가 나타나고, 목차 항목을 누르면 해당 항목으로 이동하는 구조다.
- 복습은 `Review.dc.html`로 화면을 분리했다. 제목을 "복습할 시간이에요"로 따로 지어 학습 화면("기억을 꺼내는 시간")과 헷갈리지 않게 했고, 오른쪽 사이드바는 오늘의 복습 큐(진행중/대기)와 간격 반복 안내를 보여준다. `ReviewQueue.dc.html`이 복습 대상 전체를 훑어보는 목록 화면이고, 여기서 항목을 고르면 `Review.dc.html`의 대화로 들어간다 — 사이드바 "복습 큐" 메뉴는 목록으로, 브리핑의 "첫 번째 복습 시작"은 곧바로 대화로 연결된다.
- 자료실(`Library`)·학습 기록(`StudyHistory`)·브리핑 기록(`BriefingHistory`)·설정(`Settings`)은 이번에 새로 추가한 아트보드다. 자료 검색·세션 상세·브리핑 상세·실제 가져오기/내보내기 동작은 아직 정적 목업이며, 남은 과제는 `화면-현황.md`에 정리했다.

제품 기능 요구사항은 루트의 [`웹전환_기능명세_및_개발가이드.md`](../웹전환_기능명세_및_개발가이드.md)를 따른다.
