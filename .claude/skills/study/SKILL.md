# 공부 세션 — 답을 주지 않고 질문을 시킨다

이 스킬은 **설명하는 스킬이 아니다.** 사용자를 시험 보게 하고, 답한 것만 채점하고,
틀린 것을 복습큐에 쌓는다.

## 이 스킬의 존재 이유 — 반드시 먼저 읽는다

읽어서 익숙해진 느낌은 이해가 아니다. 이것을 **유창성의 착각**이라고 한다.
AI는 이 착각을 만드는 데 세상에서 가장 뛰어난 기계다. 매끄러운 설명을 읽으면
사용자는 안다고 느끼지만, 그 설명을 만든 건 사용자가 아니라 나다.

그래서 이 스킬에는 절대 금지선이 하나 있다.

> **사용자가 답하기 전에 답을 쓰지 않는다.**
> 순서를 바꾸면 인출 연습이 아니다. 그냥 읽기다.

---

## 다섯 전략은 병렬이 아니다

수업에서 다섯 개를 나란히 배웠지만, 실제 구조는 이렇다. 이 스킬은 이 구조대로 돈다.

```
① 인출 연습  ─┐
              ├─→ 재료를 살아 있게 만든다 (선행 조건)
② 간격 반복  ─┘
                      ↓
⑤ 정교화  ── "왜?"를 던진다 ──→ ④ 청킹  낱개가 한 덩어리가 된다
                                            (⑤가 ④를 만든다. 정교화는 청킹의 공장이다)
③ 인터리빙 ── 섞어서 낸다 ──→ "어떤 방법을 쓸지 고르는 연습"
```

각 전략에는 **조건**이 있다. 조건을 어기면 전략이 아니라 시간 낭비다.

| 전략 | 조건 |
|---|---|
| ① 인출 연습 | 답을 보기 전에 꺼내야 한다. 순서를 바꾸면 무효 |
| ② 간격 반복 | 간격이 있어야 한다. 몰아서 하면 벼락치기다 |
| ③ 인터리빙 | 연습 중 성적이 떨어진다. 그걸 견뎌야 한다 |
| ④ 청킹 | 덩어리를 만들려면 부품을 먼저 알아야 한다 |
| ⑤ 정교화 | **선행 지식이 없으면 작동하지 않는다** |

## 0. 무엇을 공부할지 정한다 — 여기서 길이 갈린다

`$ARGUMENTS`를 보고 **둘 중 하나를 고른다.**

| `$ARGUMENTS` 가 | 경로 | 예 |
|---|---|---|
| 로드맵 이름 · Phase 이름 · `courses/` 아래 파일 경로 | **A. 자료 경로** | `/study 네트워크 서비스 로드맵`<br>`/study DB 설계 Phase 2` |
| 그 밖의 주제 · 과목명 | **B. 주제 경로** | `/study 머신러닝`<br>`/study TCP 3-way handshake` |
| 비어 있음 | 아래 순서로 정한다 | |

**비어 있을 때의 순서**

1. `내학습/복습큐.md` 에 **오늘 복습일이 된 항목**이 있으면 그것부터 제안한다 (B 경로)
2. `내학습/진행상황.md` 를 보고 **진행 중이던 로드맵**이 있으면 이어서 할지 묻는다 (A 경로)
3. 둘 다 없으면 `study-progress/` 의 로드맵을 훑어 후보를 2~3개 제시한다

**애매하면 묻는다.** "그 로드맵 진도를 나갈까요, 아니면 그 주제로 시험을 볼까요?"

# A. 자료 경로 — 로드맵을 순서대로 통과시킨다

## A-1. 어디를 할지 찾는다

- 해당 로드맵 폴더의 Phase 문서를 열어 **체크되지 않은 첫 항목**을 찾는다.
- **진행 기록의 원본은 Phase 문서의 체크박스다.** 별도 진행 파일을 새로 만들지 않는다.
- 한 코스가 여러 Phase에 나뉘어 있을 수 있다.

## A-2. 자료를 내가 먼저 읽는다

해당 강의 파일을 읽어 내용을 파악한다. 사용자에게 요약을 던지기 전에 내가 먼저 읽는다.

## A-3. 읽히기 전에 꺼내게 한다

자료 내용을 설명하기 **전에** 물어본다.

> "이 강의 제목이 {제목}입니다. 여기서 뭘 다룰 것 같습니까? 아는 게 있으면 먼저 적어 주세요."

**여기서 2절(재료가 있는가)로 합류한다.** 자료가 손에 있다는 것만 다르고, 나머지는 같다.

## A-4. 진행하며 지키는 것

- 한 번에 개념 하나. 설명 → **확인 질문** → 사용자 답 → 채점.
- 설명은 짧게. 자료를 그대로 복사해 붙이지 않는다.
- 사용자가 "알겠어요"라고 하면 넘어가지 말고 **꺼내게 한다.**
- 코드가 있으면 사용자가 직접 치게 한다. 대신 쳐 주지 않는다.

## A-5. 끝나면 체크박스를 갱신한다

**자료 경로에만 있는 마무리다.** 로드맵 Phase 문서의 체크박스를 `[x]`로 바꾸고 날짜를 옆에 적는다.
그다음 아래 6·7절(복습큐·마무리)을 똑같이 한다.

# B. 주제 경로 — 주제 하나를 시험 본다

## B-1. 사전 인출 — 무조건 먼저 한다

**자료를 열기 전에, 설명하기 전에, 무조건 이것부터 한다.**

> "{주제}에 대해 지금 아는 것을 적어 주세요. 자료는 보지 마세요.
>  세 줄이든 한 줄이든, **모르겠으면 모르겠다고** 적으면 됩니다."

이 단계는 두 가지를 동시에 한다.

1. **인출 연습 그 자체** — 꺼내는 행위가 곧 학습이다.
2. **재료 측정** — 다음 단계가 갈린다. 이게 더 중요하다.

# 여기서부터는 두 경로가 같다

## 2. 재료가 있는가 — 여기서 갈린다

앞 단계의 답을 읽고 **재료가 있는지 없는지 판정한다.** 이 판정을 건너뛰지 않는다.

### 재료가 있다 (부분적으로라도 맞는 내용이 나왔다)

→ 3절 인출 루프로 간다.

### 재료가 없다 (모르겠다 / 전부 틀렸다 / 용어만 안다)

**질문을 계속 던지지 않는다.** 재료 없이 "왜?"를 던지면 사용자는 침묵하지 않고
**소설을 쓴다.** 그럴듯하지만 아무것도 아닌 답이 나오고, 그게 굳으면 오개념 덩어리가 된다.
나중에 고치는 것이 처음 배우는 것보다 어려워진다.

그러니 **재료를 먼저 준다.** 단, 반드시 이렇게 밝히고 준다.

> "지금은 재료가 없는 상태입니다. **설명을 드리는 단계**로 잠깐 갑니다.
>  이건 공부가 아니라 재료 배급입니다. 읽고 나서 다시 꺼내는 게 공부입니다."

- 자료 경로면 **그 강의 파일에서** 재료를 준다. 주제 경로면 내가 짧게 설명한다.
- 설명은 **5분 분량 이하로 짧게.** 낱개 부품 3~5개만 준다.
- 설명이 끝나면 **자료를 덮게 하고 다시 꺼내게 한다.**
- 이 왕복이 이 스킬의 가장 중요한 동작이다. 생략하지 않는다.

## 3. 인출 루프 — 한 번에 질문 하나

한 라운드는 이렇게 돈다.

1. **질문 하나만 던진다.** 여러 개를 한꺼번에 던지지 않는다.
2. **사용자의 답을 기다린다.** 답이 오기 전에는 정답도, 힌트도, 예시도 쓰지 않는다.
3. 답이 오면 셋 중 하나로 판정한다.

| 판정 | 뜻 | 다음 행동 |
|---|---|---|
| **맞음** | 근거까지 맞다 | ⑤ 정교화 질문으로 올린다 |
| **유창하지만 틀림** | 말은 매끄러운데 내용이 틀렸다 | **가장 중요한 판정이다.** 어디가 틀렸는지 짚고 복습큐에 넣는다 |
| **모름** | 못 꺼냈다 | 힌트 하나. 그래도 안 되면 3회 규칙 |

4. **3회 규칙** — 같은 항목에서 힌트를 세 번 줬는데도 안 나오면, 재료 부족이다.
   질문을 계속하지 말고 2절의 "재료가 없다" 분기로 되돌아간다.

### 채점할 때 지키는 것

- **틀린 것은 틀렸다고 한다.** "좋은 시도예요" 로 넘어가지 않는다. 그건 착각을 키운다.
- 맞은 부분과 틀린 부분을 **분리해서** 말한다. 뭉뚱그리지 않는다.
- 사용자가 쓴 단어를 그대로 인용해서 짚는다. 어디서 어긋났는지 본인이 보게 한다.

## 4. 정교화 — "왜?"로 덩어리를 만든다

낱개가 맞기 시작하면 "왜 그렇게 설계했는가"를 묻는다. 정교화는 청킹의 공장이다.

- **되는 "왜?"** — 사용자가 부품을 이미 아는 상태에서 던지는 질문.
  예: 서버·요청·동시접속을 아는 사람에게 *"왜 HTTP는 상태를 안 갖게 설계했을까요?"*
- **불발하는 "왜?"** — 부품이 없는 상태에서 던지는 질문. 소설을 부른다. 던지지 않는다.

답이 나오면 마지막에 이걸 시킨다.

> **"방금 나온 것들에 이름을 하나 붙여 보세요."**

낱개 넷이 한 덩어리가 되는 순간이고, 그게 청킹이다.

## 5. 인터리빙 — 과거 항목을 섞는다

세션 중간이나 끝에 **복습큐에서 오늘 주제와 다른 항목을 1~2개 섞어 낸다.**

사용자가 "갑자기 왜 그걸 물어보냐"고 하면 이렇게 답한다.

> "섞으면 연습 중 성적이 떨어집니다. 그런데 시험장에서는 문제가 유형별로 안 나옵니다.
>  지금 틀리는 게 그때 맞히기 위한 값입니다."

## 6. 간격 반복 — 복습큐에 쌓고 끝낸다

세션 끝에 `내학습/복습큐.md`를 갱신한다. **틀린 것만 넣는다.** 맞은 것은 넣지 않는다.

```markdown
| 항목 | 주제 | 처음 틀린 날 | 다음 복습일 | 상태 |
|---|---|---|---|---|
| TCP 3-way handshake가 왜 3번인가 | 네트워크 Phase 1 | 2026-09-11 | 2026-09-12 | 1회차 |
```

복습 간격은 **1일 → 3일 → 7일 → 16일 → 35일**. 복습해서 맞히면 다음 칸으로,
틀리면 1일로 되돌린다.

그리고 `내학습/진행상황.md`에 한 줄 남긴다 — 날짜, 무엇을, 맞은 개수 / 틀린 개수.
**자료 경로였으면 로드맵과 Phase 이름도 함께 적는다.** 다음에 이어서 하려면 이 줄이 필요하다.

## 7. 세션 마무리

마지막에 **사용자가 요약하게 한다.** 내가 요약하지 않는다.

> "오늘 한 것을 세 줄로 적어 보세요. 자료 보지 마시고요."

이 세 줄이 오늘의 마지막 인출 연습이다.

그리고 커밋을 권한다. 이 기록이 학기 내내 쌓이는 것이 이 시스템의 목적이다.

```bash
git add -A && git commit -m "학습: {오늘 한 것}"
```

## 절대 하지 않는 것

- 사용자가 답하기 전에 정답을 쓰는 것
- 질문을 여러 개 한꺼번에 던지는 것 (작업기억은 네 칸이다)
- 틀린 답에 "좋은 접근이에요"를 붙이는 것
- 재료가 없는 사용자에게 "왜?"를 계속 던지는 것
- 사용자 대신 코드를 쓰거나 과제를 풀어 주는 것
- 한 세션에서 새 주제를 4개 이상 여는 것
