# 오늘의 브리핑 — 흩어진 진행 상황을 한 화면으로

## 이 스킬의 존재 이유

사용자는 `study-progress/` 안의 로드맵을 **각각 독립된 과목으로** 따로 공부한다. 인공지능융합공학부
로드맵도 통합 커리큘럼을 순서대로 밟으라는 뜻이 아니라 여러 과목 중 하나일 뿐이다. 로드맵이 늘어날수록
어디까지 했는지, 오늘 뭐부터 복습해야 하는지가 폴더마다 흩어져서 안 보이게 된다.

이 스킬은 **판단 재료를 모아 보여주는 것까지만** 한다. 무엇을 공부할지 고르는 것은 사용자의 일이고,
실제로 공부를 진행하는 것은 `/study`의 일이다. 이 스킬은 둘 다 하지 않는다.

## 0. 무엇을 모을지 정한다

`$ARGUMENTS`가 비어 있으면 `study-progress/` 아래 모든 로드맵을 대상으로 한다.
로드맵 이름이 주어지면 그 로드맵 하나만 본다.

```bash
find study-progress -maxdepth 1 -type d -not -path study-progress | sort
```

## 1. 로드맵별 진행률을 센다

대상 로드맵마다, 그 폴더 아래 **모든 깊이**에서 파일명에 "Phase"가 들어간 `.md` 파일을 찾는다
(인공지능융합공학부 로드맵처럼 트랙 하위 폴더에 Phase 문서가 한 단계 더 들어간 경우가 있어서,
`-maxdepth`를 주지 않는다).

```bash
find "study-progress/{로드맵}" -iname "*Phase*.md"
```

찾은 각 파일에서 체크박스를 센다.

```bash
grep -c '^\s*- \[ \]' "{Phase파일}"   # 안 한 것
grep -c '^\s*- \[x\]' "{Phase파일}"   # 한 것 (대소문자 X도 포함해서 센다)
```

로드맵 안의 모든 Phase 문서 합계로 "완료/전체"와 %를 계산한다.

- Phase 문서를 한 개도 못 찾은 로드맵은 **건너뛰지 말고** "진행 자료 없음"으로 따로 표시한다.
  임의로 로드맵을 새로 만들거나 지우지 않는다 — 그건 `/roadmap`의 일이다.
- 체크박스가 0/0인(문서는 있는데 체크박스가 없는) 경우도 "형식을 확인할 것"으로 따로 표시한다.

> **% 표시에서 정수 반올림(버림)을 쓰지 않는다.** 로드맵 하나에 수백 개의 항목이 있으면
> 몇 개 체크해도 정수 %로는 `0%`로 버려져서, "시작 안 함"과 "시작했지만 아직 적음"이
> 화면에서 구별되지 않는다 (1차 사용에서 실제로 발견된 문제 — 데브옵스가 2/799를 채웠는데도
> `0%`로 나와 진행 여부를 알 수 없었다). 그래서:
> - `완료 == 0` → **"0% (미시작)"**
> - `완료 > 0` 이지만 소수 첫째 자리까지도 0.0이 되는 경우 → **"<0.1% (진행 중, {완료}/{전체})"**
> - 그 외 → 소수 첫째 자리까지 표시, 예: **"1.2% (3/251)"**
> 항상 "완료/전체" 원래 숫자를 %와 나란히 적어서, 반올림으로 정보가 사라지지 않게 한다.

## 2. 복습 우선순위를 뽑는다

`내학습/복습큐.md`를 읽는다. 표의 "다음 복습일" 열을 오늘 날짜와 비교해서,
**오늘이거나 이미 지난** 행만 모두 뽑는다.

- 가장 많이 지난 것부터 먼저 보여준다 (밀린 지 오래된 것이 우선순위가 높다).
- 아직 복습일이 안 된 항목은 보여주지 않는다 — 간격 반복의 조건은 간격이다.
- 날짜 형식이 깨져서 판단할 수 없는 행이 있으면, 그 행만 "형식 확인 필요"로 따로 표시하고
  나머지는 정상 처리한다. 조용히 무시하지 않는다.
- 복습큐 표에 행이 아예 없으면 "아직 쌓인 오답이 없습니다"라고 명시한다. 빈 상태를 오류처럼 다루지 않는다.

## 3. 화면에 보여준다

다음 순서로, 간결하게 보여준다.

1. 오늘 날짜
2. **복습 우선순위** — 표(항목 · 로드맵/주제 · 다음 복습일 · 며칠 지남). 없으면 "밀린 복습 없음"
3. **로드맵별 진행률** — 표(로드맵 · 완료/전체 · %, 위 표시 규칙대로). "진행 자료 없음" 로드맵은 표 아래 한 줄로 따로 묶는다
4. 진행률 0%인 로드맵이 4개를 넘으면 이름만 나열하고 하나씩 펼치지 않는다 (화면이 길어지는 것을 막는다)

이 단계에서 "다음에 뭘 하세요"라고 지시하지 않는다. 재료만 보여주고 판단은 사용자가 한다.

## 4. 기록한다

`내학습/브리핑로그.md`에 표 형식으로 한 줄 추가한다 (파일이 없으면 헤더부터 만든다).

```markdown
| 날짜 | 밀린 복습 개수 | 진행 중 로드맵 수 | 평균 진행률 | 메모 |
|---|---|---|---|---|
| 2026-09-16 | 3 | 2 | 41% | DB 설계가 가장 밀려 있음 |
```

그리고 커밋을 권한다.

```bash
git add -A && git commit -m "브리핑: {날짜}"
```

## 정보가 부족할 때

| 상황 | 행동 |
|---|---|
| 로드맵 폴더에 Phase 문서가 없음 | "진행 자료 없음"으로 표시하고 건너뜀. 새로 안 만듦 |
| 체크박스 표기가 표준과 다름(`[X]`, `[ x]` 등) | 대소문자·공백 변형을 인식하되, 셀 수 없는 형식이면 "형식 확인 필요"로 표시 |
| 복습큐 행의 날짜가 깨짐 | 그 행만 "형식 확인 필요"로 분리, 나머지는 정상 진행 |
| 복습큐·진행 로드맵이 모두 비어 있음 | 오류가 아니라 정상 초기 상태로 안내 |

## 사용자에게 물어볼 것

- 브리핑 결과가 실제 상황과 다르게 보이면(예: 분명히 진행했는데 0%로 나옴), 임의로 파일 구조를
  바꾸지 않고 원인을 사용자와 함께 확인한다.
- 로드맵을 브리핑 대상에서 빼고 싶다는 말이 나오면, 파일을 지우지 말고 제외 방법을 사용자에게 먼저 묻는다.

## 절대 하지 않는 것

- 오늘 무엇을 공부하라고 대신 결정하는 것 (재료만 준다)
- 체크박스를 대신 체크하는 것 (그건 `/study`의 일)
- 진행 자료가 없다고 로드맵 폴더를 새로 만들거나 지우는 것 (그건 `/roadmap`의 일)
- 복습큐 행을 이 스킬이 직접 추가·삭제하는 것 (그건 `/study`의 일)
