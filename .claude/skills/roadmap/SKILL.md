# 내 로드맵 만들기

**이 스킬은 받은 시스템을 내 것으로 바꾸는 스킬이다.**

## 순서가 전부다

> **필요 지식을 먼저 다 적는다 → 그 다음에 강의를 붙인다.**

거꾸로 하면 안 된다. `courses/` 를 먼저 뒤지고 목차를 짜면
"가진 자료로 만들 수 있는 로드맵"이 나오지, "그 주제를 배우는 데 실제로 필요한 로드맵"이 나오지 않는다.

## 0. 도착점을 한 문장으로

가장 먼저, 그리고 반드시 사용자에게 묻는다.

> **"이 로드맵이 끝났을 때 당신이 직접 만들 수 있어야 하는 것 하나는 뭡니까?"**

- "이해한다"는 도착점이 아니다. **결과물**로 적는다.
- 나쁨: `네트워크를 이해한다`
- 좋음: `내 서버에 도메인을 붙이고 HTTPS로 열어서 한 달간 죽지 않게 운영한다`

도착점이 뒤의 모든 판단(무엇을 넣고 뺄지)의 기준이 된다. 여기서 대충 넘어가면 로드맵이 무너진다.

이어서 세 가지를 짧게 확정한다. 길게 인터뷰하지 않는다.

| 항목 | 묻는 것 |
|---|---|
| 출발점 | 이미 아는 것 / 처음인 것 |
| 제약 | 주당 몇 시간 쓸 수 있나 |
| 기한 | 언제까지 |

## 1. 필요 지식 리스트업 — 강의를 보기 전에 한다

**아직 `courses/` 를 뒤지지 않는다.** 도착점에 도달하려면 무엇을 알아야 하는지만 적는다.

- 도착점에서 **거꾸로 내려온다.** "이걸 하려면 그 직전에 무엇을 할 줄 알아야 하는가"를 반복한다.
- 항목은 **할 줄 알아야 하는 것**으로 적는다. 도구명이나 강좌명으로 적지 않는다.
  - 나쁨: `Docker`
  - 좋음: `앱을 이미지로 빌드해서 서버에서 실행한다`
- 20~40개면 보통이다. 너무 적으면 얕고, 너무 많으면 묶어야 한다.

리스트를 만들면 **사용자에게 먼저 보여주고 확인받는다.** 여기가 뼈대라서, 빠진 것을 여기서 잡는 게 가장 싸다.

## 2. 순서 정하기 — 의존 관계로 묶는다

- 항목들을 **선행 관계**로 정렬한다. A를 모르면 B가 안 되는 것을 찾는다.
- 4~8개의 Phase로 묶는다. 한 Phase는 5~15시간 정도가 적당하다.
- 각 Phase에 **그 Phase의 도착점**을 한 문장씩 붙인다.

## 3. 강의 붙이기 — 이제야 `courses/` 를 본다

매칭 우선순위는 **저장소 자료 → 없으면 산출물 과제**다.

```bash
find courses -maxdepth 3 -type d | sort            # 전체 목록을 눈으로 훑는다
grep -ril "키워드" courses --include="*.md" | head  # 본문 매칭
```

- 키워드 검색만 하고 끝내지 않는다. **전체 목록 훑기를 건너뛰면 이미 있는 자료를 "없음"으로 처리하게 된다.**
- 기존 로드맵(`study-progress/*/`)에 같은 항목이 이미 매칭돼 있으면 **그걸 재사용한다.** 다시 찾지 않는다.
- 자료가 없는 항목은 **비워 두지 말고 "산출물 과제"로 채운다.** 직접 만들어 보는 것으로 대체한다.

## 4. 파일로 남긴다

`study-progress/{주제} 로드맵/` 폴더를 만들고 아래를 쓴다.

```
study-progress/{주제} 로드맵/
  README.md                  ← 도착점 · Phase 표 · 총 시간 · 순서
  01 Phase 1 - {이름}.md      ← 체크박스가 있는 실제 진행 문서
  02 Phase 2 - {이름}.md
  ...
```

Phase 문서의 형식:

```markdown
# Phase 1 — {이름}

**이 Phase의 도착점**: {한 문장}

## 1-A. {소주제}

- [ ] `courses/.../{강의}.md`
- [ ] 산출물: {직접 만들 것}
```

체크박스는 `/study` 스킬이 갱신한다 — 로드맵 이름을 주고 돌리면 된다.

## 5. 커밋

```bash
git add -A && git commit -m "로드맵: {주제} 신설"
```

## 흔한 실패

| 실패 | 왜 문제인가 |
|---|---|
| 도착점을 "이해한다"로 적었다 | 끝났는지 판정할 수 없다 |
| `courses/` 를 먼저 훑고 목차를 짰다 | 가진 자료의 모양대로 로드맵이 휜다 |
| 항목을 도구명으로 적었다 | 뭘 할 줄 알게 되는지가 안 보인다 |
| Phase가 12개다 | 완주 못 한다. 묶어라 |
