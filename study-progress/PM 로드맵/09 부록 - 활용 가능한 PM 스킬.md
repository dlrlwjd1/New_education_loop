# 부록 — 활용 가능한 PM 스킬

이 작업 환경에는 **PM 실무용 스킬(skill) 9개 묶음**이 이미 설치되어 있다. 강의는 아니지만, Phase별 산출물 과제를 만들 때 초안 생성 도구로 쓸 수 있다.

호출 방법: `/스킬명` (예: `/pm-execution:write-prd`)

## 중요 — 쓰는 순서

스킬은 **강의를 대체하지 않는다.** 순서를 지켜야 실력이 남는다.

1. 강의로 프레임워크를 이해한다
2. **먼저 직접 써 본다** (10분이라도)
3. 스킬로 초안을 만든다
4. 내가 쓴 것과 비교해서 빠진 관점을 찾는다

3번부터 시작하면 문서는 나오지만 판단력이 늘지 않는다. 특히 기획을 처음 맡은 상황이라면, 첫 두 달은 2번을 반드시 거치는 게 낫다.

## Phase별 대응 스킬

### Phase 1 — 전략과 목표

| 산출물 | 스킬 |
|---|---|
| 제품 전략 캔버스(9섹션) | `pm-product-strategy:strategy` |
| 제품 비전 | `pm-product-strategy:product-vision` |
| OKR | `pm-execution:plan-okrs` |
| 비즈니스 모델 (Lean Canvas / BMC / Startup Canvas) | `pm-product-strategy:business-model` |
| 가치 제안 (JTBD 6부 템플릿) | `pm-product-strategy:value-proposition` |
| 이해관계자 매핑 (Power × Interest) | `pm-execution:stakeholder-map` |

### Phase 2 — 문제 발견

| 산출물 | 스킬 |
|---|---|
| 거시 환경 분석 (SWOT · PESTLE · Five Forces · Ansoff 한 번에) | `pm-product-strategy:market-scan` |
| 시장 규모 (TAM/SAM/SOM) | `pm-market-research:market-sizing` |
| 경쟁 분석 | `pm-market-research:competitive-analysis` |
| 인터뷰 스크립트 / 인터뷰 요약 | `pm-product-discovery:interview` |
| 페르소나 · 세그먼트 · 고객 여정 | `pm-market-research:research-users` |
| 사용자 피드백 대량 분석 | `pm-market-research:analyze-feedback` |
| 기회 솔루션 트리 (Teresa Torres) | `pm-product-discovery:opportunity-solution-tree` |

### Phase 3 — 솔루션과 검증

| 산출물 | 스킬 |
|---|---|
| 발산→가정→실험 전 과정 | `pm-product-discovery:discover` |
| 아이디에이션 (PM·디자이너·엔지니어 3관점) | `pm-product-discovery:brainstorm` |
| 가정 우선순위 (Impact × Risk) | `pm-product-discovery:prioritize-assumptions` |
| 기능 우선순위 | `pm-product-discovery:prioritize-features` |
| 프레임워크 비교 (RICE·ICE·Kano·MoSCoW 등 9개) | `pm-execution:prioritization-frameworks` |
| 요청 트리아지 | `pm-product-discovery:triage-requests` |
| 사전 부검 (만들기 전 실패 시나리오) | `pm-execution:pre-mortem` |

### Phase 4 — 실행

| 산출물 | 스킬 |
|---|---|
| PRD | `pm-execution:write-prd` |
| **PRD 레드팀 (가정 공격)** | `pm-execution:red-team-prd` ← **PRD 쓴 다음 반드시 이걸 돌린다** |
| 사용자 스토리 / 잡 스토리 / WWA | `pm-execution:write-stories` |
| 스프린트 계획 · 회고 · 릴리스 노트 | `pm-execution:sprint` |
| 테스트 시나리오 | `pm-execution:test-scenarios` |
| 회의록 | `pm-execution:meeting-notes` |

### Phase 5 — 출시와 성장

| 산출물 | 스킬 |
|---|---|
| GTM 전략 (비치헤드·ICP·메시징·채널·출시 계획) | `pm-go-to-market:plan-launch` |
| 성장 루프 · GTM 모션 | `pm-go-to-market:growth-strategy` |
| 노스 스타 지표 | `pm-marketing-growth:north-star` |
| 지표 대시보드 설계 | `pm-product-discovery:setup-metrics` |
| 성과 중심 로드맵 전환 | `pm-execution:transform-roadmap` |
| 가격 전략 | `pm-product-strategy:pricing` |
| 경쟁 배틀카드 (영업용) | `pm-go-to-market:battlecard` |
| 코호트 분석 · A/B 테스트 분석 | `pm-data-analytics:analyze-cohorts` · `pm-data-analytics:analyze-test` |
| 마케팅 아이디어 · 포지셔닝 · 제품명 | `pm-marketing-growth:market-product` |

### Phase 6 — AI 제품

| 산출물 | 스킬 |
|---|---|
| AI로 만든 앱을 리뷰 가능 상태로 (전체 패킷) | `pm-ai-shipping:ship-check` |
| 코드베이스를 문서로 역설계 | `pm-ai-shipping:document-app` |
| 정적 보안 감사 | `pm-ai-shipping:security-audit-static` |
| 정적 성능 감사 | `pm-ai-shipping:performance-audit-static` |
| 테스트 커버리지 맵 | `pm-ai-shipping:derive-tests` |
| **의도 vs 구현 간극 찾기** | `pm-ai-shipping:intended-vs-implemented` |
| 출시 전 필요한 문서 세트 정의 | `pm-ai-shipping:shipping-artifacts` |

> `pm-ai-shipping` 묶음은 이 상황에 특히 값이 있다. **엔지니어 출신 기획자가 가진 고유한 강점**이 여기다. AI로 빠르게 만든 것을 실제로 내보낼 수 있는 상태인지 판단하는 일은 기획과 엔지니어링을 둘 다 아는 사람만 할 수 있다.

## 추천 조합 (파이프라인)

**신규 기능 하나를 기획할 때**
```
pm-product-discovery:discover        문제·가정·실험 정리
  → pm-execution:write-prd           PRD 초안
  → pm-execution:red-team-prd        내 PRD의 가정을 공격
  → pm-execution:write-stories       스토리로 분해
  → pm-execution:test-scenarios      테스트 시나리오
```

**새 시장/제품을 검토할 때**
```
pm-product-strategy:market-scan      거시 환경
  → pm-market-research:market-sizing TAM/SAM/SOM
  → pm-market-research:competitive-analysis
  → pm-product-strategy:business-model
  → pm-go-to-market:plan-launch
```

**AI로 만든 것을 출시할 때**
```
pm-ai-shipping:ship-check            전체 점검 패킷 (하위 스킬들을 자동 호출)
```

## 이 저장소의 학습용 스킬

- `study` — 강의를 Q&A로 함께 공부하고 진행 기록과 정리본을 자동 생성한다. **이 로드맵을 진행할 때 기본으로 쓸 스킬이다.** 정의: `.claude/skills/study/SKILL.md`

사용 예:
```
/study courses/udemy/Become a Better Engineer by Understanding Product Management/Section 2 - Setting up Product strategic directions/04 Product goals. OKRs framework.md
```
