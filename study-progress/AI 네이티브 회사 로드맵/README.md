# AI 네이티브 회사 학습 로드맵 — 회사 운영 OS를 직접 만든다

회사의 실제 업무를 **역할이 나뉜 AI 에이전트가 돌리는 사내 운영 시스템(Company OS)** 을 만드는 로드맵이다. "AI를 잘 쓰는 법"이 아니라 "회사가 돌아가는 방식 자체를 에이전트 위에 다시 올리는 법"을 다룬다. 45개 필요 지식 중 41개는 저장소에 이미 정리된 강의로 채워져 있었고, 2026-09-02에 남은 공백 4개(업무 측정·인력 판단·전략과 해자·가격 구조)를 채우는 MOOC 강좌 4개를 모두 등록·정리했다 — **Process Mining**(TU/e · 60강), **AI Applications in People Management**(Wharton · 38강), **AI Strategy and Governance**(Wharton · 34강), **Customer Value in Pricing Strategy**(UVA Darden × BCG · 54강). **2026-09-03에 필요 지식 리스트 자체를 웹 리서치로 다시 검증했고, 그때 새로 드러난 공백 8개를 각 Phase에 반영했다.** 무엇이 달라졌는지는 아래 「갱신 기록」에 있다.

- 작성일: 2026-09-02 · **마지막 갱신: 2026-09-03**
- 웹 리서치 기준일: 2026-09-03
- 대상: 프로그래밍 경험 있음. Claude Code·에이전트 프레임워크를 이미 쓰지만, 그것을 **회사 운영 단위로 조립해 본 적은 없는** 상태
- 원칙: 저장소 자료 우선. 2026-09-02의 공백 4개는 MOOC Plus 포함 강좌 4개로 채워 정리 완료. 2026-09-03 재탐색에서 나온 **미확보 추천 강좌 4개**는 [부록 B](13%20부록%20-%20추천%20강의%20종합.md)에
- 도착점: **내 회사(또는 인수한 사업)의 실제 업무를 역할별 AI 에이전트가 돌리는 사내 운영 시스템을 만들어, 업무 하나를 사람 개입 없이 끝까지 돌리고 그 결과를 지표로 확인한다.**

## 순서를 이렇게 잡은 이유

**Phase 1을 프로세스 지도로 시작한다.** 에이전트를 먼저 만들면 "만들 수 있는 것"을 자동화하게 되지, "자동화해야 하는 것"을 자동화하지 않는다. 빌더 조쉬 인터뷰가 인수 직후 제품이 아니라 계기판을 먼저 만든 이유와 같다. BPMN으로 업무를 그려 두면 Phase 5에서 에이전트 역할을 나눌 때 그 그림이 그대로 조직도가 된다.

**Phase 2(능력의 경계)를 Phase 3(만들기) 앞에 둔다.** 모델이 무엇을 못 하는지 모르면 자율성 등급을 정할 수 없고, 자율성 등급이 없으면 Phase 5의 사람 승인 지점을 어디에 둘지 근거가 없다.

**Phase 3에서 프레임워크 없이 에이전트 루프를 직접 짠다.** CrewAI·LangGraph·ADK를 먼저 배우면 프레임워크가 감춘 것을 못 본다. 루프를 손으로 짜 본 뒤에 Phase 5에서 프레임워크를 고른다.

**Phase 4를 Phase 5 앞에 둔다.** 에이전트 여러 개를 붙이기 전에 **조회 가능한 환경**이 먼저 있어야 한다. 회사 지식과 사내 시스템에 접근하지 못하는 에이전트를 여러 개 만들면 잡담하는 챗봇 무리가 된다.

**Phase 6·7(평가·보안)을 Phase 8(배포) 앞에 둔다.** eval 없이 배포한 에이전트는 조용히 틀린다. 실패가 눈에 보이는 상태를 만들고 나서 프로덕션에 올린다.

**Phase 10(사람)을 마지막 직전에 둔다.** 무엇을 자동화할 수 있는지 실제로 만들어 본 뒤에야 "그럼 사람은 무엇을 하는가"에 근거 있는 답을 낼 수 있다. 순서를 뒤집으면 추측으로 조직을 설계하게 된다.

## 추천 진행 방식

- **주 5시간 기준 약 27주** 코스다.
- 강의 하나를 볼 때마다 `study` 스킬로 Q&A 학습을 하면 정리본이 자동 생성된다.
- **대상 회사를 Phase 1 시작 전에 하나 정한다.** 실제 회사가 없으면 인수 후보 SaaS나 본인이 하는 부업 하나를 가정으로 잡는다. 대상 없이 진행하면 Phase 1·9·11의 산출물이 전부 공허해진다. 정할 것이 없으면 [12 부록](12%20부록%20-%20사업%20확보와%20수익%20구조.md)을 먼저 본다.
- **API 비용이 든다.** Phase 3부터 유료 LLM API 키가 필요하고, Phase 5의 멀티 에이전트와 Phase 6의 eval은 호출 수가 빠르게 늘어난다. 로컬 모델(Ollama) 대안이 Phase 2에 있으니 실습 단계에서는 그쪽을 섞는다.
- **Phase 4 이후로는 사내 실제 데이터를 다루게 된다.** Phase 7의 보안을 다 보기 전에는 민감 데이터를 외부 API에 넣지 않는다.

## 이 로드맵에 없는 것

- **모델을 직접 학습·파인튜닝하는 법** — Phase 2에서 "언제 파인튜닝을 고르는가"까지만 다룬다. 실제 학습 파이프라인은 **MLOps 로드맵**이 다룬다.
- **운영 관측 인프라를 처음부터 구축하는 법** — Phase 7·8은 에이전트를 관측하는 데 필요한 만큼만 다룬다. Prometheus·Grafana·로그 파이프라인을 제대로 세우는 것은 **개발운영 로드맵**이다.
- **제품 기획 방법론 전체** — Phase 1의 자동화 후보 판단까지만 다룬다. 문제 발견·검증·출시는 [PM 로드맵](../PM%20로드맵/)이다.
- **스펙 주도 개발의 세부 워크플로** — Phase 8에서 코드 생산 수단으로만 쓴다. 헌법·명세·재계획의 전체 흐름은 [스펙 주도 개발 로드맵](../스펙%20주도%20개발%20로드맵/)이다.
- **고객 확보와 판매** — 회사를 *운영*하는 로드맵이지 *성장*시키는 로드맵이 아니다. **마케팅 로드맵**이 다룬다.

로드맵을 만든 다음 날, **필요 지식 리스트가 그 분야의 실제 요구와 맞는지**를 병렬 웹 리서치(표준 커리큘럼 · 커뮤니티 로드맵 · 실무 요구 스킬 · 최신 동향) 네 갈래로 다시 검증했다. 문서에 넣은 사실은 모두 원문을 직접 열어 확인했다.

**가장 큰 발견 — 저장소의 MCP 강의가 현행 스펙과 어긋난다.** 개념(호스트·클라이언트·서버 분리, 도구 명세, 왜 사내 API를 그대로 붙이면 안 되는가)은 그대로 유효하지만 **직접 서버를 만드는 실습은 코드 수준에서 달라졌다.** [Phase 4의 4-C](04%20Phase%204%20-%20회사%20지식과%20시스템%20연결.md)에 **현행 스펙 기준으로 지켜야 할 것**을 정리해 넣었고, 프로토콜 세부는 강의가 아니라 공식 스펙에서 가져오도록 안내를 바꿨다.

**필요 지식 리스트에 없던 항목 8개를 추가했다.** 각 Phase의 "이 단계가 끝나면 할 수 있어야 하는 것"과 `2026-09-03 보강` 블록에 들어가 있다.

**강좌를 재탐색해 미확보 추천 4개를 [부록 B](13%20부록%20-%20추천%20강의%20종합.md)에 추가했다.** Phase 6·9는 저장소 자료가 이미 두터워 대부분의 후보가 밀렸다. 남은 것은 **Evaluating AI Agents**(DeepLearning.AI × Arize · 무료 2h36m · 1순위), **AI Security Masterclass**(Udemy · 실습형), **Change Management for Generative AI**(Vanderbilt · 2h), **MLOps and LLMOps M3·M4**(Board Infinity)다. 넣지 않기로 한 것과 그 이유도 같은 문서에 적어 두었다.

**곁가지로 확인한 것** — LangChain v1(2025-10-22)에서 `initialize_agent`·`AgentExecutor`·`create_react_agent`가 폐기되고 `create_agent`로 통합됐다([Phase 5](05%20Phase%205%20-%20에이전트%20조직%20만들기.md)에 주의 추가). A2A는 v1.0 정식 릴리스와 Linux Foundation 편입(2026-08-17)으로 실험 단계를 벗어났지만, **단일 조직 내부에서 MCP 대비 실익이 있는지는 확인하지 못해** 로드맵에 넣지 않았다.

**바뀌지 않은 것** — Phase 구조(11개 + 부록 2개)와 순서, 기존 체크리스트와 학습일은 그대로다.

## 주의 사항

- **각 Phase 문서의 체크리스트가 이 로드맵이 다루는 코스들의 진행 기록 원본이다.** 별도의 코스 단위 진행 기록 파일은 두지 않는다.
- **다른 로드맵과 강의가 겹친다.** SDD·개발운영·PM·MLOps 로드맵이 같은 강의를 일부 공유한다. 이 로드맵은 **자체 체크박스를 둔다** — 같은 강의를 두 로드맵에서 각각 체크하게 되므로, 한쪽을 이미 봤다면 여기서도 바로 `[x]` 처리하고 학습일을 옮겨 적는다.
- **YouTube 노트는 강의가 아니라 사례다.** Phase 1·10에 들어간 영상 노트는 체계적 커리큘럼이 아니라 실제 사례와 주장이다. 여기서 배운 것을 그대로 따르지 말고 Phase 1의 판단 기준으로 걸러 쓴다.
- **공백 4개는 2026-09-02에 모두 채워졌고, 2026-09-03 재탐색에서 새 추천 4개가 나왔다(미확보).** 어떤 강좌가 어느 Phase의 무엇을 채웠는지는 [부록 B](13%20부록%20-%20추천%20강의%20종합.md)의 표 두 개로 볼 수 있다.
- **각 Phase 문서의 `2026-09-03 보강` 블록은 강의가 아니라 웹 리서치에서 나온 것이다.** 저장소 강의가 다루지 않는 내용이므로, 체크리스트가 아니라 산출물을 만들 때 참고하는 기준으로 쓴다. 출처 링크를 함께 달아 두었으니 판단이 필요하면 원문을 연다.
