# 부록 — L2와 라우터 내부

- 목표: Phase 1에서 "그렇게 동작한다"고 받아들인 것들의 **속을 연다.**
- 분량: 약 8시간
- 마지막 학습일: (미학습)

## 언제 보는가

도착점(클라우드 VPC 구축과 진단)에 **직접 필요하지는 않다.** 그래서 Phase가 아니라 부록이다. 다만 아래 질문이 걸리기 시작하면 그때 온다.

- 스위치는 어느 포트로 보낼지 어떻게 아는가? (MAC 학습)
- VPC의 "가상 네트워크"는 물리적으로 무엇 위에 얹혀 있는가? (네트워크 가상화·VLAN)
- 라우터 안에서 패킷은 입력 포트에서 출력 포트로 어떻게 옮겨지는가? (스위칭 패브릭)
- 왜 어떤 스위치는 부하가 걸리면 특정 포트만 느려지는가? (head-of-line blocking)
- 클라우드 콘솔에서 규칙을 바꾸면 왜 즉시 반영되지 않을 때가 있는가? (제어 평면 vs 데이터 평면)

특히 **제어 평면과 데이터 평면의 구분**은 클라우드 네트워크를 다룰 때 실용적이다 — 콘솔 조작(제어 평면)과 실제 패킷 전달(데이터 평면)이 별개의 시스템이라는 것을 알면, "설정은 바꿨는데 아직 안 통한다"를 당황하지 않고 기다릴 수 있다.

> **노트 품질**: 이 부록의 자료는 전부 `Hands-on Internet of Things`다. Phase 1과 같은 이유로 **자동 전사 수준이라 문장이 거칠다.** 각 노트 상단의 원본 강의 링크를 함께 쓴다.

## 이 부록에서 뺀 것

같은 강좌의 나머지는 이 로드맵의 범위 밖이다.

- **Course 2 (IoT Communications) 전체** — RF·안테나·변조·메시 라우팅. 무선 IoT 고유 주제라 **IoT 로드맵**에 맡긴다
- **Course 4 Module 3~4 (물리 배선)** — 도선·EMI 차폐·케이블 등급·해양 응용. 물리 시공 영역이다
- **Course 1 Module 2~4 (IoT 회로·마이크로컨트롤러·아두이노)** — 하드웨어. **IoT 로드맵**과 **로보틱스 로드맵**이 다룬다
- **Course 3의 병원 IoT 사례(`08 Lecture 15`)와 Course 4의 `01 Lecture 1`** — 도메인 사례라 네트워크 원리 학습에는 불필요

## 산출물

부록에는 필수 산출물을 두지 않는다. 굳이 하나 만든다면:

**"내 VPC를 물리 장비로 그려 보기"** — Phase 7에서 만든 VPC를 온프레미스 장비(스위치·라우터·방화벽)로 구현한다면 어떤 그림이 되는지 그린다. VPC의 각 요소가 어느 물리 장비에 대응하는지 표로 정리한다. 클라우드가 추상화한 것이 정확히 무엇인지 드러난다.
