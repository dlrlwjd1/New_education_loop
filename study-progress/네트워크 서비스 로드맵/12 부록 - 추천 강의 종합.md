## 최소 세트 — 완료됨

**The Bits and Bytes of Computer Networking (Google)** — 2026-09-02 수강·정리 완료. 6모듈 91강(약 19시간), Google IT Support 인증 과정의 2번째 강좌다. MOOC Plus에 포함되어 추가 비용은 들지 않았다.

이 강좌 하나가 덮은 것:

- **Phase 1**의 CIDR·서브네팅·NAT 공백 → [1-D](01%20Phase%201%20-%20%ED%8C%A8%ED%82%B7%EC%9D%B4%20%EC%96%B4%EB%96%BB%EA%B2%8C%20%EC%98%A4%EA%B0%80%EB%8A%94%EA%B0%80.md) (Module 2·4, 9강)
- **Phase 2**의 DNS 전체 — 저장소 자료가 0이던 유일한 Phase → [2-A~2-C](02%20Phase%202%20-%20%EC%9D%B4%EB%A6%84%20%EB%B6%99%EC%9D%B4%EA%B8%B0%20DNS.md) (Module 4·6, 11강)
- **Phase 9**의 진단 도구 → [9-A](09%20Phase%209%20-%20%EA%B4%80%EC%B8%A1%EA%B3%BC%20%EC%9E%A5%EC%95%A0%20%EC%A7%84%EB%8B%A8.md) (Module 6, 8강)

정리본 전체는 [저장소 README](../../courses/mooc/Computer%20Science%20Fundamentals/The%20Bits%20and%20Bytes%20of%20Computer%20Networking/README.md) 참조.

**남은 공백 두 가지** — 이 강좌로도 채워지지 않았다.

- **`dig`** — 강의는 `nslookup` 기준이다. `dig +trace`·`dig @권한NS`는 Phase 2의 산출물 과제로 익힌다
- **경로 MTU 탐색** — 단편화의 원리는 다루지만 Path MTU Discovery는 없다. Phase 1의 보조 과제 3번으로

## 두 번째 세트 — 실습이 아쉬울 때

1. **TLS & HTTPS Explained** (MOOC·Packt) — Phase 4. 3모듈 6시간으로 짧고, `openssl` 로 CA를 직접 만들어 서명하는 실습이 있다. **인증서 장애는 실무에서 가장 자주 만나는 네트워크 장애**라 투자 대비 회수가 빠르다
2. **Implement NGINX Web Servers and Reverse Proxy Solutions** (MOOC·EDUCBA) — Phase 5. 저장소의 로드밸런서 학습이 전부 클라우드 콘솔 클릭이라, **설정 파일을 직접 쓰는 경험**이 통째로 빠져 있다. 4모듈 8시간

## 세 번째 세트 — 클라우드를 넓힐 때

**Hands-on AWS VPC Labs** (MOOC·Pearson) — Phase 7·8. 11개 실습 랩. NCP로 배운 VPC를 AWS로 옮기면서 **피어링·VPN·흐름 로그**까지 확장한다.

다만 **NCP 실습을 이미 끝냈다면 겹치는 부분이 크다.** 순수하게 공백만 노린다면 흐름 로그 랩 2개와 피어링 랩 2개가 목적인데, 그 정도는 AWS 공식 문서와 직접 실습으로도 가능하다. **AWS를 실무에서 쓸 계획이 있을 때만** 우선순위를 올린다.

같은 이유로 **AWS Cloud Technical Essentials**는 위 랩 강좌와 상당히 겹친다. **둘 중 하나만** 고른다 — 개념부터면 Essentials, 손으로 만들 거면 Labs.

## 스페셜라이제이션을 통으로 살지 말지

이 로드맵의 추천 강의는 **전부 단일 강좌**라 전문과정을 통으로 살 이유가 없다.

- **Google IT Support Professional Certificate** — 6강좌짜리 인증 과정이지만, 이 로드맵에 필요한 건 2번째 강좌 하나다. 나머지(운영체제·시스템 관리·보안·고객 응대)는 저장소의 IBM DevOps·Linux 자료와 겹치거나 범위 밖이다. **MOOC Plus 구독 중이라면 개별 수강으로 충분하다.**
- **Packt 강좌들** — 각각 독립 강좌다. 묶음이 없다.

## 사지 않아도 되는 것 / 신중해야 하는 것

| 강의 | 이유 |
|---|---|
| DNS (MOOC·Packt) | 커리큘럼이 **네임서버 운영(BIND·Unbound·NSD 설치·설정)** 쪽에 무게가 실려 있다. 이 로드맵의 도착점은 "클라우드 관리형 DNS를 쓸 줄 아는 것"이라 오버스펙이다. Google 강좌 Module 4로 충분하다. 직접 네임서버를 세울 계획이 생기면 그때 산다 |
| AWS Cloud Technical Essentials | Hands-on AWS VPC Labs와 범위가 겹친다. **둘 다 사지 않는다** |
| WebSockets Protocol Explained | HTTP/2·3와 WebSocket이 도착점에 직접 필요하진 않다. **실시간 기능이 있는 서비스를 다룰 때** 우선순위를 올린다. 다만 Module 2의 TCP 핸드셰이크·4계층 모델은 Phase 1 복습으로 값이 있다 |
| Udemy의 Nginx·DNS·TLS 강좌들 | 검색에는 잡히지만 **강좌 페이지를 열어 확인하지 못했다**(Udemy가 자동 접근을 차단한다). 위 MOOC 강좌들로 같은 공백이 덮이므로 표에 넣지 않았다. Udemy 쪽을 보고 싶다면 직접 페이지를 열어 커리큘럼을 확인한 뒤 고른다 |

## 강의 없이 버티는 경로

**추천 강의를 하나도 사지 않아도 이 로드맵은 완주할 수 있다.** 각 Phase의 공백 절에 「산출물 과제 (강의 없이도 가능)」를 두었다. 다만 아래 둘은 과제만으로는 얕아진다.

- ~~**Phase 2(DNS)**~~ — **2026-09-02 해소.** Google 강좌 Module 4·6으로 재귀 조회 구조·레코드·TTL·존이 전부 채워졌다
- ~~**Phase 1의 CIDR·NAT**~~ — **2026-09-02 해소.** Module 2의 Subnet Masks·Basic Binary Math가 AND 연산까지 설명한다

이 두 곳이 Google 강좌 하나로 동시에 해결된 것이 **★★★★★를 준 이유**였고, 실제로 그렇게 됐다. 남은 추천 강의 6개는 여전히 미확보이며 **없어도 로드맵 완주에는 지장이 없다.**

## 새 강의를 추가할 때

`AGENTS.md`의 플랫폼별 폴더 규칙을 따른다.

- MOOC 강좌는 카테고리 폴더 아래 — Bits and Bytes는 **`courses/mooc/Computer Science Fundamentals/`** 에 두었다(네트워킹 전용 카테고리가 없어 Nand to Tetris·Software Design과 같은 층위로 판단). 남은 강좌들은 **`courses/mooc/Web and APIs/`** 가 어울린다. 네트워크 전용 카테고리를 새로 만들지는 사용자와 상의한다
- Udemy 강좌는 `courses/udemy/{코스명}/` 에 섹션 구조로

강의를 정리하고 나면 **해당 Phase 문서의 「공백」 절을 실제 체크리스트로 교체**하고, 이 표의 상태 칸과 [README](README.md)의 진행 현황 표를 함께 갱신한다.
