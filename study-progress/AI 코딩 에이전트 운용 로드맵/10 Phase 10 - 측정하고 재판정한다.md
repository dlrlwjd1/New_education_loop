# Phase 10 — 측정하고 재판정한다

- 목표: 지금까지 만든 운용 방식이 실제로 효과가 있었는지 자기기만 없이 판정하고, 낡은 설정을 지운다.
- 상태: **강의 미확보.** MOOC·Udemy 어디에도 이 주제 전용 강좌가 없다(2026-09-10 조사).

## 왜 필요한가

앞의 아홉 Phase는 전부 "더 잘 쓰는 법"이었다. 이 Phase는 **"정말 나아졌는가"**를 묻는다. 이게 왜 별도 Phase인지는 한 가지 연구가 설명한다.

> METR의 무작위 대조 실험에서 숙련 오픈소스 개발자 16명이 실제 태스크 246건을 수행했다. AI를 쓸 때 **실제로는 19% 느려졌는데, 본인들은 20% 빨라졌다고 추정했다.**

**39%p의 인식 격차다.** 이 격차를 의식하지 않으면 [Phase 11](11%20Phase%2011%20-%20캡스톤%20운용%20표준.md)에서 굳히는 운용 표준이 "효과 있다고 느꼈던 것"의 모음이 된다.

⚠️ **그렇다고 "19% 느려진다"를 현재값으로 인용해서도 안 된다.** METR은 2026-02-24에 **실험 설계 자체를 변경**했다고 공지했다 — AI 없이 일하기를 거부하는 개발자가 늘어 선택 편향이 커졌기 때문이다. 즉 "19% 감속"도, 후속 설문의 "1.4~2배 향상"도 지금 시점의 측정치로 쓸 수 없다. **남는 교훈은 숫자가 아니라 "체감을 믿지 말고 재라"는 것이다.**

비용 쪽도 마찬가지로 실측이 필요하다. 어느 대형 기술 회사는 엔지니어 약 5,000명에게 코딩 에이전트를 배포한 뒤 **연간 AI 예산을 4개월 만에 소진**했다.

## 이 단계가 끝나면 할 수 있어야 하는 것

- **PR당 비용** 단위로 생각한다 — 총액이 아니라
- 폭주 루프를 감지하고 차단한다
- **재작업률(rework rate)**을 추적한다 — 처리량은 오르는데 안정성이 나빠지는 패턴을 잡는다
- 모델 선택을 **작업별 정책**으로 고정하고, 데이터로 갱신한다
- 설정 자산을 **3~6개월마다 재검토**하고 낡은 것을 지운다
- AI 생성 출처를 기록해 감사 추적을 만든다

## 산출물 과제 (강의 없이도 가능)

이 Phase는 **전적으로 산출물로 완료를 판정한다.**

### 1. 비용 기록 4주치

- **PR 1건당 비용**을 기록한다. 월 총액이 아니다
- 작업 유형별로 나눈다 — 버그 수정 · 새 기능 · 리팩터링 · 조사
- [Phase 1](01%20Phase%201%20-%20하네스를%20이해한다.md)에서 만든 모델 선택 기준표를 **이 데이터로 갱신한다.** 그때는 추측이었고 지금은 실측이다

### 2. 재작업률 기록

- 에이전트가 만든 변경 중 **일주일 안에 다시 손댄 비율**
- 리뷰에서 되돌려진 PR 비율
- 처리량(머지된 PR 수)과 나란히 놓는다. **처리량만 오르고 재작업률도 오르면 그건 개선이 아니다**

### 3. 체감 대 실측 비교 1회

가장 중요한 과제다.

1. 작업 하나를 시작하기 **전에** 예상 소요 시간을 적는다
2. 실제 소요 시간을 잰다 — 에이전트를 기다린 시간, 결과를 읽고 고친 시간을 모두 포함한다
3. 10건쯤 모아 차이를 본다

**"에이전트가 3분 만에 짜 줬다"와 "그 결과를 이해하고 고치는 데 40분 걸렸다"는 다른 이야기다.** 후자를 안 재면 자기기만이 된다.

### 4. 설정 자산 재검토 1회

모델이 좋아지면 설정이 오히려 족쇄가 된다. 아래를 점검한다.

- [ ] 규칙 파일에서 **최신 모델이 이미 알아서 하는 것**을 지운다
- [ ] 한 번도 안 불린 스킬을 지운다
- [ ] 한 번도 안 막은 훅을 재평가한다 — 필요 없는 것인지, 잘못 걸린 것인지
- [ ] MCP 서버 중 안 쓰는 것을 뗀다 (도구 정의만으로도 컨텍스트를 먹는다)

**앞으로 3~6개월마다 반복한다.** 재검토 주기를 캘린더에 넣는 것까지가 이 과제다.

### 5. 출처 기록 방식 결정

- AI가 생성한 변경에 **출처를 남기는 방식**을 정한다 (커밋 트레일러 · PR 라벨 등)
- 인시던트가 났을 때 "이건 누가/무엇이 만들었나"에 답할 수 있어야 한다
- 이 저장소가 커밋에 `Co-Authored-By`를 남기는 방식이 최소 사례다
